# EXECUTE 执行预处理语句

`EXECUTE` 语句执行一个已由 `PREPARE` 准备好的预处理语句，通过 `USING` 子句按顺序传入对应 `?` 占位符的参数值。参数必须使用用户变量（`@var`）传递，不能直接传字面量。同一个预处理语句可以用不同参数多次 `EXECUTE`。

---

## 语法

```sql
EXECUTE stmt_name [USING @var_name [, @var_name ...]]
-- @var_name 的数量和顺序必须与 ? 占位符的数量和顺序完全一致
-- 无参数时 USING 子句可省略
```

---

## 基本示例

```sql
-- 准备语句
PREPARE stmt FROM 'SELECT id, username FROM users WHERE dept_id = ? AND status = ?';

-- 设置参数变量
SET @dept = 3;
SET @status = 1;

-- 执行
EXECUTE stmt USING @dept, @status;
-- 等价于执行：SELECT id, username FROM users WHERE dept_id = 3 AND status = 1

-- 修改参数，再次执行（复用编译结果）
SET @dept = 5;
EXECUTE stmt USING @dept, @status;
-- 等价于执行：SELECT id, username FROM users WHERE dept_id = 5 AND status = 1

DEALLOCATE PREPARE stmt;
```

---

## 无参数语句的 EXECUTE

```sql
-- 准备没有 ? 占位符的语句
PREPARE stmt_no_params FROM 'SELECT COUNT(*) AS total FROM users WHERE is_active = 1';

-- EXECUTE 时不需要 USING 子句
EXECUTE stmt_no_params;

DEALLOCATE PREPARE stmt_no_params;
```

---

## 在存储过程中多次 EXECUTE

```sql
DELIMITER //

CREATE PROCEDURE sp_batch_insert_demo()
BEGIN
    DECLARE i INT DEFAULT 1;
    
    PREPARE stmt FROM 'INSERT INTO test_table (name, created_at) VALUES (?, NOW())';
    
    WHILE i <= 5 DO
        SET @name = CONCAT('item_', i);
        EXECUTE stmt USING @name;
        SET i = i + 1;
    END WHILE;
    
    DEALLOCATE PREPARE stmt;
END //

DELIMITER ;
```

---

## EXECUTE 后获取影响行数

```sql
PREPARE stmt_update FROM 'UPDATE products SET stock = stock - ? WHERE id = ?';

SET @qty = 3;
SET @prod_id = 101;
EXECUTE stmt_update USING @qty, @prod_id;

-- ROW_COUNT() 返回 EXECUTE 影响的行数
SELECT ROW_COUNT() AS affected;

DEALLOCATE PREPARE stmt_update;
```

---

## 参数类型的自动转换

```sql
PREPARE stmt FROM 'SELECT * FROM orders WHERE amount > ? LIMIT ?';

-- MySQL 会自动将用户变量的值转换为合适的类型
SET @min_amount = '100.50';   -- 字符串，但会被自动转为 DECIMAL
SET @limit = 10;
EXECUTE stmt USING @min_amount, @limit;

-- 注意：NULL 参数
SET @dept = NULL;
PREPARE stmt_null FROM 'SELECT * FROM users WHERE dept_id = ?';
EXECUTE stmt_null USING @dept;
-- 等价于：WHERE dept_id = NULL（不是 WHERE dept_id IS NULL！）
-- 如果要匹配 NULL，需要在 SQL 中写 WHERE dept_id <=> ?（NULL安全比较）

DEALLOCATE PREPARE stmt_null;
```

## EXECUTE 的结果处理

```sql
-- EXECUTE 返回的结果集与普通 SELECT 相同，客户端正常处理
PREPARE stmt FROM 'SELECT id, username, email FROM users WHERE id > ? LIMIT 5';
SET @min_id = 10;
EXECUTE stmt USING @min_id;
-- 客户端（或 MySQL 命令行）收到一个普通的结果集

-- 在存储过程中，EXECUTE 的 SELECT 结果集直接返回给客户端
-- 无法在存储过程内部通过 SELECT INTO 捕获 EXECUTE 的结果集
-- 如需捕获，应使用 SELECT ... INTO 的普通 SQL 方式，而非 EXECUTE

DEALLOCATE PREPARE stmt;
```

---

## 适用场景

- **循环批量操作**：在存储过程循环中重复 EXECUTE 相同的预处理语句，避免每次解析
- **相同查询结构，不同参数**：按不同条件查询时复用同一预处理语句
- **动态 SQL 执行**：通过 SET @sql = ... 构建的动态 SQL，PREPARE 后 EXECUTE

---

## 常见问题

**EXECUTE 的 USING 子句能直接传字面量吗（如 USING 5, 'active'）？**

不能，`USING` 子句只接受用户变量（`@var`），不能直接传字面量。必须先 `SET @var = value`，再 `EXECUTE ... USING @var`。这是 MySQL 的规定，不同于一些其他数据库的预处理接口。

---

## 注意事项

- EXECUTE 的参数数量必须与 `?` 占位符数量完全一致，多一个或少一个都会报错：`ERROR 1210 (HY000): Incorrect arguments to EXECUTE`。
- EXECUTE 后，被替换参数的用户变量值不会被修改——EXECUTE 是只读地读取变量值，不会改变变量本身。

---

## 总结

`EXECUTE stmt_name [USING @var1, @var2, ...]` 执行已 PREPARE 的语句，按顺序用用户变量替换 `?` 占位符。参数只能是用户变量，不能是字面量。同一语句可以用不同参数值多次 EXECUTE，复用编译结果。EXECUTE 无参数时省略 USING 子句。执行后用 ROW_COUNT() 获取 DML 影响行数。使用完毕后 DEALLOCATE PREPARE 释放。
