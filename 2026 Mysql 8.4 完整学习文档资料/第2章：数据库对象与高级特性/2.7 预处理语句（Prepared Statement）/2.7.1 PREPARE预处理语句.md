# PREPARE 预处理语句

`PREPARE` 语句将一个 SQL 模板发送给 MySQL 服务器进行解析和编译，生成一个可重复执行的预编译语句对象。参数位置用 `?` 占位符表示，执行时通过 `EXECUTE` 传入实际参数值。预处理语句既能提升重复执行的性能，也是防止 SQL 注入的有效手段。

---

## 语法

```sql
PREPARE stmt_name FROM preparable_stmt;
-- preparable_stmt 可以是字符串字面量，也可以是用户变量（@var）
```

---

## 基本示例

```sql
-- 准备一条带参数的 SELECT 语句
PREPARE stmt_get_user FROM 'SELECT id, username, email FROM users WHERE id = ?';

-- 准备一条带多个参数的语句
PREPARE stmt_search_users FROM 
    'SELECT id, username FROM users WHERE status = ? AND created_at > ? LIMIT ?';

-- 准备 INSERT 语句
PREPARE stmt_insert FROM 
    'INSERT INTO products (name, price, stock) VALUES (?, ?, ?)';

-- 通过用户变量传入 SQL 字符串（常用于动态 SQL）
SET @sql = 'SELECT * FROM users WHERE dept_id = ?';
PREPARE stmt_dept_users FROM @sql;
```

---

## 执行预处理语句

```sql
-- 设置参数值（使用用户变量）
SET @user_id = 5;
EXECUTE stmt_get_user USING @user_id;

-- 多个参数
SET @status = 1;
SET @start_date = '2026-01-01';
SET @limit = 20;
EXECUTE stmt_search_users USING @status, @start_date, @limit;

-- INSERT 参数
SET @name = '笔记本电脑';
SET @price = 4999.00;
SET @stock = 50;
EXECUTE stmt_insert USING @name, @price, @stock;
```

---

## 完整生命周期示例

```sql
-- 1. 准备（PREPARE）
PREPARE stmt_update_status FROM 
    'UPDATE orders SET status = ?, updated_at = NOW() WHERE id = ? AND user_id = ?';

-- 2. 多次执行（EXECUTE）
SET @new_status = 2;
SET @order_id = 100;
SET @uid = 5;
EXECUTE stmt_update_status USING @new_status, @order_id, @uid;

SET @order_id = 101;
EXECUTE stmt_update_status USING @new_status, @order_id, @uid;

-- 3. 释放（DEALLOCATE PREPARE）
DEALLOCATE PREPARE stmt_update_status;
```

## 在存储过程中使用 PREPARE

```sql
DELIMITER //

CREATE PROCEDURE sp_dynamic_query(
    IN  p_table_name VARCHAR(64),
    IN  p_limit      INT
)
BEGIN
    SET @sql = CONCAT('SELECT * FROM `', p_table_name, '` LIMIT ?');
    PREPARE dynamic_stmt FROM @sql;
    SET @p_limit = p_limit;
    EXECUTE dynamic_stmt USING @p_limit;
    DEALLOCATE PREPARE dynamic_stmt;
END //

DELIMITER ;

CALL sp_dynamic_query('users', 10);
```

## PREPARE 支持的语句类型

```sql
-- 支持的语句类型（主要 DML 和部分 DDL）
PREPARE s FROM 'SELECT ...';
PREPARE s FROM 'INSERT ...';
PREPARE s FROM 'UPDATE ...';
PREPARE s FROM 'DELETE ...';
PREPARE s FROM 'CALL sp_name(?, ?)';
PREPARE s FROM 'CREATE TABLE ...';
PREPARE s FROM 'ALTER TABLE ...';
PREPARE s FROM 'DROP TABLE ...';

-- 不支持多语句（不能在一个 PREPARE 中包含多条以分号分隔的 SQL）
-- 不支持嵌套 PREPARE
-- 不支持 PREPARE 本身作为预处理语句
```

## 预处理语句与普通语句对比

| 对比维度 | 普通语句 | 预处理语句 |
|---------|---------|----------|
| 解析编译 | 每次执行都解析 | 只解析一次 |
| 参数传入 | 字符串拼接 | `?` 占位符 |
| SQL 注入风险 | 有（字符串拼接）| 无（参数与 SQL 分离）|
| 重复执行性能 | 较低 | 较高（复用编译结果）|
| 适用场景 | 一次性 SQL | 重复执行、动态 SQL |

---

## 适用场景

- **重复执行相同结构的 SQL**：批量插入、循环查询，减少每次解析编译开销
- **动态表名/列名**：无法用 `?` 占位的表名需要字符串拼接后 PREPARE（注意校验合法性）
- **防 SQL 注入**：让用户输入的值通过 `?` 而非字符串拼接传入

---

## 常见问题

**预处理语句的 `?` 占位符能用于表名、列名吗？**

不能，`?` 只能作为**值**的占位符（替换 WHERE 条件中的值、INSERT 的值、LIMIT 的数量等）。表名、列名、关键字不能用 `?` 占位。如果需要动态表名，只能用字符串拼接构建 SQL，然后通过 PREPARE 执行，但必须严格验证表名来源（白名单校验）防止注入。

---

## 注意事项

- 预处理语句是会话级的（Session-scoped），在当前连接中 PREPARE 后，其他连接无法使用。连接断开后，所有未 DEALLOCATE 的预处理语句自动被释放。
- 同一会话中，用相同 stmt_name 再次 PREPARE，会覆盖之前的预处理语句（不需要先 DEALLOCATE）。

---

## 总结

`PREPARE stmt_name FROM 'SQL with ? placeholders'` 将 SQL 模板预编译，用 `?` 作为参数占位符。参数值通过 `EXECUTE stmt_name USING @var1, @var2` 传入。预处理语句只解析一次可多次执行（性能优势），参数与 SQL 结构分离（防止 SQL 注入）。使用完毕应 `DEALLOCATE PREPARE stmt_name` 释放资源。
