# ALTER VIEW 修改视图

`ALTER VIEW` 语句修改已存在的视图定义，相当于重新定义视图背后的 SELECT 语句及其选项。与 `CREATE OR REPLACE VIEW` 相比，`ALTER VIEW` 要求视图必须已经存在，而 `CREATE OR REPLACE VIEW` 在视图不存在时会创建，存在时会替换。

---

## 语法

```sql
ALTER
    [ALGORITHM = {UNDEFINED | MERGE | TEMPTABLE}]
    [DEFINER = user]
    [SQL SECURITY { DEFINER | INVOKER }]
    VIEW view_name [(column_list)]
    AS select_statement
    [WITH [CASCADED | LOCAL] CHECK OPTION]
```

---

## 基本示例

```sql
-- 原视图
CREATE VIEW active_users AS
SELECT id, username, email FROM users WHERE is_active = 1;

-- 修改视图：添加 created_at 列，并加上 WITH CHECK OPTION
ALTER VIEW active_users AS
SELECT id, username, email, created_at
FROM users
WHERE is_active = 1 AND is_deleted = 0
WITH CHECK OPTION;

-- 修改视图算法
ALTER ALGORITHM = MERGE VIEW active_users AS
SELECT id, username, email FROM users WHERE is_active = 1;

-- 修改 SQL SECURITY
ALTER SQL SECURITY INVOKER VIEW active_users AS
SELECT id, username, email FROM users WHERE is_active = 1;
```

---

## ALTER VIEW 与 CREATE OR REPLACE VIEW 的对比

```sql
-- ALTER VIEW：视图不存在时报错
ALTER VIEW nonexistent_view AS SELECT 1;
-- ERROR 1146 (42S02): Table 'mydb.nonexistent_view' doesn't exist

-- CREATE OR REPLACE VIEW：视图不存在时创建，存在时替换
CREATE OR REPLACE VIEW active_users AS
SELECT id, username FROM users WHERE is_active = 1;
-- 视图不存在：创建；存在：用新定义替换
```

| 对比 | ALTER VIEW | CREATE OR REPLACE VIEW |
|------|-----------|----------------------|
| 视图不存在 | 报错 | 创建新视图 |
| 视图存在 | 替换定义 | 替换定义 |
| 实际使用偏好 | 明确知道视图存在时 | 更通用，推荐 |
| 权限要求 | 需要 ALTER VIEW 或 CREATE VIEW 权限 | 需要 CREATE VIEW 权限 |

## 修改视图需要的权限

```sql
-- 查看当前用户是否有 ALTER VIEW 权限
SHOW GRANTS FOR CURRENT_USER();

-- 授予 ALTER VIEW 权限
GRANT ALTER VIEW ON mydb.* TO 'dev_user'@'%';

-- 注意：ALTER VIEW 操作会以 DEFINER 用户的身份重写视图
-- 如果原视图有 DEFINER = 'admin'@'%'，只有 admin 或 SUPER 权限的用户能修改 DEFINER
```

## 查看视图修改前后的定义

```sql
-- 修改前备份视图定义
SELECT VIEW_DEFINITION FROM information_schema.VIEWS
WHERE TABLE_SCHEMA = 'mydb' AND TABLE_NAME = 'active_users';

-- 修改视图
ALTER VIEW active_users AS
SELECT id, username, email, phone
FROM users WHERE is_active = 1;

-- 确认修改后的定义
SHOW CREATE VIEW active_users\G
```

## 适用场景

- **业务逻辑变更**：底层表结构变化后，修改视图定义以适配新结构（如表新增了列，更新视图以包含该列）
- **性能优化**：根据执行计划将视图算法从 UNDEFINED 调整为 MERGE（减少临时表使用）
- **安全策略调整**：从 DEFINER 模式改为 INVOKER 模式，要求调用者自己有底层表权限

---

## 常见问题

**ALTER VIEW 会影响依赖该视图的存储过程或其他视图吗？**

不会立即报错，但依赖该视图的存储过程和其他视图在下次调用时可能因为视图列名或结构变化而失败。修改视图前应当检查所有依赖关系：

```sql
SELECT * FROM information_schema.VIEWS
WHERE VIEW_DEFINITION LIKE '%active_users%' AND TABLE_SCHEMA = 'mydb';
-- 查找引用了 active_users 的其他视图
```

---

## 注意事项

- `ALTER VIEW` 完整替换视图定义，不能只修改某个字段或某个属性——必须重新写完整的 SELECT 语句。如果只想加一个列，也必须把原来的列都写进去。
- `ALTER VIEW` 不保留原视图的 `WITH CHECK OPTION`；如果原视图有 CHECK OPTION，`ALTER VIEW` 时不写就会丢失。每次修改视图时都要检查是否需要保留 CHECK OPTION。

---

## 总结

`ALTER VIEW view_name AS select_statement` 替换已存在视图的定义，语法与 CREATE VIEW 几乎相同。与 `CREATE OR REPLACE VIEW` 的主要区别是：ALTER VIEW 要求视图已存在，而 CREATE OR REPLACE 更通用（不存在时创建，存在时替换）。修改时必须完整重写 SELECT 语句，不能局部修改，且原有的 WITH CHECK OPTION 不会自动保留。
