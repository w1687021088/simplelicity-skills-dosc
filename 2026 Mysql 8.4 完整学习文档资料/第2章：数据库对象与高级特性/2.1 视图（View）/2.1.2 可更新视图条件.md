# 可更新视图条件

可更新视图（Updatable View）允许通过 INSERT、UPDATE、DELETE 操作修改底层表的数据。并非所有视图都是可更新的，MySQL 要求视图的行与底层表的行之间存在一对一关系，才能将对视图的修改映射到底层表。

---

## 可更新视图的核心要求

视图与底层表必须存在一对一的行对应关系。视图中的每一行必须能唯一对应底层表中的一行，以便 MySQL 知道更新视图中某行时应该更新底层表的哪一行。

---

## 使视图不可更新的构造

以下任何一种构造出现在视图定义中，该视图就变为不可更新（只读视图）：

```sql
-- 1. 聚合函数或窗口函数
CREATE VIEW v1 AS SELECT dept_id, COUNT(*) AS cnt FROM employees GROUP BY dept_id;
-- COUNT(*) 使视图不可更新

-- 2. DISTINCT
CREATE VIEW v2 AS SELECT DISTINCT dept_id FROM employees;
-- 不可更新

-- 3. GROUP BY / HAVING
CREATE VIEW v3 AS SELECT dept_id, SUM(salary) FROM employees GROUP BY dept_id;
-- 不可更新

-- 4. UNION 或 UNION ALL
CREATE VIEW v4 AS SELECT id FROM t1 UNION SELECT id FROM t2;
-- 不可更新

-- 5. SELECT 列表中的子查询
CREATE VIEW v5 AS
SELECT id, (SELECT COUNT(*) FROM orders WHERE user_id = users.id) AS order_cnt
FROM users;
-- 不可更新（SELECT 列表中的相关子查询）

-- 6. ALGORITHM = TEMPTABLE（强制临时表算法）
CREATE ALGORITHM = TEMPTABLE VIEW v6 AS SELECT id, name FROM users;
-- 不可更新

-- 7. 对基础表某列的多次引用（INSERT 受限）
CREATE VIEW v7 AS SELECT id, salary, salary * 1.1 AS bonus FROM employees;
-- salary 被引用两次，INSERT 失败，但 UPDATE/DELETE 可以
```

## 可更新视图示例

```sql
-- 可更新视图：简单过滤，底层表行一一对应
CREATE VIEW active_users AS
SELECT id, username, email, is_active
FROM users
WHERE is_active = 1;

-- 通过视图 UPDATE（会修改底层 users 表）
UPDATE active_users SET email = 'new@example.com' WHERE id = 5;
-- 等价于：UPDATE users SET email = 'new@example.com' WHERE id = 5 AND is_active = 1;

-- 通过视图 DELETE
DELETE FROM active_users WHERE id = 5;
-- 等价于：DELETE FROM users WHERE id = 5 AND is_active = 1;

-- 通过视图 INSERT（注意：不满足 WHERE 条件的行会被插入底层表但从视图中不可见）
INSERT INTO active_users (id, username, email, is_active)
VALUES (100, 'bob', 'bob@example.com', 1);
-- is_active = 1，满足视图条件，可以从视图查到
INSERT INTO active_users (id, username, email, is_active)
VALUES (101, 'charlie', 'charlie@example.com', 0);
-- is_active = 0，不满足视图 WHERE，插入成功但从视图查不到（如需禁止此行为，用 WITH CHECK OPTION）
```

## 查看视图是否可更新

```sql
-- 通过 information_schema 查看视图的可更新性
SELECT TABLE_NAME, IS_UPDATABLE
FROM information_schema.VIEWS
WHERE TABLE_SCHEMA = 'your_db_name';

-- IS_UPDATABLE 列：YES = 可更新，NO = 只读视图
```

## 可更新性与可插入性的区别

```sql
-- 可更新（UPDATE/DELETE）和可插入（INSERT）的条件略有不同
-- 可插入的要求更严格：
-- 视图中必须包含底层表的所有 NOT NULL 且无默认值的列
-- 不能有以下：DISTINCT、GROUP BY、聚合函数、UNION、
--             SELECT 列表子查询、通过多个表的 JOIN、
--             对同一列的多次引用

-- 简单 JOIN 视图：UPDATE/DELETE 可以（针对可唯一标识底层表行的情况），但通常 INSERT 不行
CREATE VIEW emp_dept_view AS
SELECT e.id, e.name, e.salary, d.name AS dept_name
FROM employees e
INNER JOIN departments d ON d.id = e.dept_id;
-- 可以 UPDATE e.salary（只修改 employees 表的列）
-- 不能 INSERT（因为跨越两个基础表）
```

## 可更新的多表连接视图（特殊情况）

```sql
-- MySQL 允许对 JOIN 视图做有限制的更新（只更新"驱动表"一侧的列）
CREATE VIEW emp_view AS
SELECT e.id, e.name, e.salary, e.dept_id, d.name AS dept_name
FROM employees e
INNER JOIN departments d ON d.id = e.dept_id;

-- 只更新 employees 表的列（可以）
UPDATE emp_view SET salary = 15000 WHERE id = 1;

-- 同时更新两个表的列（不行，MySQL 不支持单个 UPDATE 修改多个基础表）
UPDATE emp_view SET salary = 15000, dept_name = '新名称' WHERE id = 1;
-- ERROR: Can not modify more than one base table through a join view
```

## 适用场景

- **行级别访问控制**：只让用户通过可更新视图操作满足条件的行（配合 WITH CHECK OPTION 防止逃逸）
- **隐藏列的更新接口**：通过视图只暴露允许修改的列，隐藏不应被修改的列
- **数据封装**：为不同业务角色提供不同的视图更新接口

---

## 常见问题

**为什么通过视图 INSERT 后，从视图里查不到刚插入的行？**

因为视图有 WHERE 过滤，插入的行不满足 WHERE 条件时，数据确实写入了底层表，但不符合视图的过滤条件，所以视图查不到。要防止这种行为，在视图上加 `WITH CHECK OPTION`——它会拒绝任何不满足视图 WHERE 条件的 INSERT 或 UPDATE。

---

## 注意事项

- 对 JOIN 视图做 UPDATE 时，每个 DML 语句只能修改**一个**基础表的列，不能同时修改两个表的列。
- 带计算列（如 `salary * 1.1`）的视图，该计算列不可用于 INSERT 或 UPDATE（因为无法反向推算底层值）。

---

## 总结

可更新视图要求视图行与底层表行一对一对应，不包含聚合函数、DISTINCT、GROUP BY、HAVING、UNION、TEMPTABLE 算法等构造。通过可更新视图的 UPDATE/DELETE/INSERT 操作实际上修改的是底层表。JOIN 视图通常只支持对单个基础表列的修改，不能同时修改两个表。通过 `information_schema.VIEWS` 的 `IS_UPDATABLE` 列可以确认视图的可更新性。
