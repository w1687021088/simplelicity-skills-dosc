# 视图算法 MERGE 与 TEMPTABLE

视图算法（ALGORITHM）决定 MySQL 如何处理对视图的查询。它有三个可选值：`MERGE`、`TEMPTABLE`、`UNDEFINED`。算法的选择直接影响视图的执行效率和是否可以更新。

---

## 三种算法含义

```sql
CREATE [ALGORITHM = {UNDEFINED | MERGE | TEMPTABLE}] VIEW view_name AS ...;
```

- **MERGE**：将引用视图的查询与视图定义合并，生成一个统一的查询语句执行。视图不产生中间临时表，优化器可以将外层 WHERE 条件下推到视图内部，索引可以被充分利用。
- **TEMPTABLE**：先执行视图的 SELECT，把结果存入临时表，再在临时表上执行外部查询。无法使用底层表的索引，外层 WHERE 无法下推，通常性能较差，且视图变为不可更新。
- **UNDEFINED**（默认）：MySQL 自动选择，优先使用 MERGE，如果视图含有聚合、DISTINCT、UNION 等不支持 MERGE 的构造，则退化为 TEMPTABLE。

---

## MERGE 算法工作原理

```sql
-- 视图定义
CREATE ALGORITHM = MERGE VIEW active_users AS
SELECT id, username, email FROM users WHERE is_active = 1;

-- 外部查询
SELECT * FROM active_users WHERE id = 5;

-- MySQL 将其合并（MERGE）为：
SELECT id, username, email FROM users WHERE is_active = 1 AND id = 5;
-- 外层的 WHERE id = 5 被下推进视图内，底层 users.id 的索引可以被使用
```

---

## TEMPTABLE 算法工作原理

```sql
-- 视图定义（聚合查询，只能使用 TEMPTABLE）
CREATE VIEW dept_stats AS
SELECT dept_id, COUNT(*) AS cnt, AVG(salary) AS avg_sal
FROM employees
GROUP BY dept_id;

-- 外部查询
SELECT * FROM dept_stats WHERE dept_id = 3;

-- TEMPTABLE 处理过程：
-- 步骤1：执行视图内的 SELECT（全表聚合，临时表存结果）
--   临时表：[(1, 10, 8000), (2, 5, 12000), (3, 8, 9500), ...]
-- 步骤2：在临时表上过滤 WHERE dept_id = 3
-- 外层过滤是在临时表上做的，无法利用 employees 表的索引
```

---

## MERGE 与 TEMPTABLE 的对比

| 对比维度 | MERGE | TEMPTABLE |
|---------|-------|-----------|
| 执行方式 | 合并为单一 SQL 执行 | 先建临时表，再查临时表 |
| 索引使用 | 可使用底层表索引 | 临时表无索引 |
| WHERE 下推 | 支持（外层条件下推到底层）| 不支持 |
| 视图可更新性 | 可更新（满足其他条件时）| 不可更新 |
| 适用场景 | 简单过滤、JOIN 视图 | 含聚合/DISTINCT/UNION 的视图 |
| 性能 | 通常更好 | 通常较差（大结果集时尤其明显）|

## UNDEFINED 的实际行为

```sql
-- UNDEFINED（默认）：MySQL 优先尝试 MERGE
CREATE VIEW user_orders AS
SELECT u.id, u.username, o.amount
FROM users u
LEFT JOIN orders o ON o.user_id = u.id;
-- 没有聚合等限制，MySQL 选择 MERGE

CREATE VIEW dept_stats AS
SELECT dept_id, COUNT(*) AS cnt FROM employees GROUP BY dept_id;
-- 有 GROUP BY + 聚合，MySQL 不得不使用 TEMPTABLE

-- 查看实际使用了哪个算法（通过 EXPLAIN 或 information_schema）
SELECT TABLE_NAME, ALGORITHM
FROM information_schema.VIEWS
WHERE TABLE_SCHEMA = 'mydb';
-- ALGORITHM 列显示 UNDEFINED/MERGE/TEMPTABLE
```

## 何时强制指定算法

```sql
-- 强制 MERGE：优化性能（确保索引可用）
CREATE ALGORITHM = MERGE VIEW recent_orders AS
SELECT * FROM orders WHERE created_at >= CURDATE() - INTERVAL 7 DAY;
-- 强制 MERGE 使外层 WHERE 能与内部条件合并，充分利用 created_at 索引

-- 强制 TEMPTABLE：确保视图结果一致性（极少场景）
-- 某些特殊情况（如视图包含 SQL_CALC_FOUND_ROWS）需要强制 TEMPTABLE
-- 通常不需要手动指定 TEMPTABLE
```

---

## 通过 EXPLAIN 验证算法效果

```sql
-- 查看视图查询的执行计划
EXPLAIN SELECT * FROM active_users WHERE id = 5;

-- MERGE 算法：会显示底层 users 表，type = const/ref（使用了索引）
-- TEMPTABLE 算法：会出现 "DERIVED" 或临时表的特征，type = ALL（全扫描临时表）
```

---

## 适用场景

- **MERGE**：绝大多数业务视图（简单过滤、JOIN）都应优先使用或让 MySQL 默认选择 MERGE，以获得最佳索引利用率
- **TEMPTABLE**：聚合统计视图（含 GROUP BY、DISTINCT、UNION）无法使用 MERGE，MySQL 会自动使用 TEMPTABLE，不需要手动指定

---

## 常见问题

**指定了 MERGE，但 MySQL 实际使用了 TEMPTABLE，原因是什么？**

如果视图定义包含聚合函数、DISTINCT、GROUP BY、HAVING、UNION 等构造，即使指定 `ALGORITHM = MERGE`，MySQL 也无法使用 MERGE，会忽略指定并退化为 TEMPTABLE，同时记录一个警告。

---

## 注意事项

- 不要对含有聚合、DISTINCT 或 UNION 的视图强制指定 `ALGORITHM = MERGE`，MySQL 会忽略该设置并产生不必要的警告，实际执行时仍然使用 TEMPTABLE。
- 指定了 `ALGORITHM = TEMPTABLE` 的视图**一定不可更新**，因为临时表与底层表之间没有行级别的映射关系。

---

## 总结

视图算法决定 MySQL 如何执行视图查询。`MERGE` 将外部查询与视图定义合并执行，支持索引下推，性能好，视图可更新；`TEMPTABLE` 先将视图结果物化为临时表，不支持索引，性能较差，视图不可更新；`UNDEFINED`（默认）让 MySQL 自动选择，优先 MERGE。含聚合、DISTINCT、UNION 的视图只能使用 TEMPTABLE。绝大多数情况下不需要手动指定算法，让 MySQL 自动选择即可。
