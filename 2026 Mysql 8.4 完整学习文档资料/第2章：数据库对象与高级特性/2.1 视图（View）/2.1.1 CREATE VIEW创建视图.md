# CREATE VIEW 创建视图

视图（View）是一个命名的 SQL 查询，存储在数据库中，可以像普通表一样被引用。它本身不存储数据（STORED 生成列除外），每次查询视图时，MySQL 会执行视图背后的 SELECT 语句。视图的主要价值在于封装复杂查询逻辑、简化访问、控制数据暴露范围。

---

## 语法

```sql
CREATE
    [OR REPLACE]
    [ALGORITHM = {UNDEFINED | MERGE | TEMPTABLE}]
    [DEFINER = user]
    [SQL SECURITY { DEFINER | INVOKER }]
    VIEW view_name [(column_list)]
    AS select_statement
    [WITH [CASCADED | LOCAL] CHECK OPTION]
```

---

## 基本示例

```sql
-- 最简单的视图：封装 SELECT 语句
CREATE VIEW active_users AS
SELECT id, username, email, created_at
FROM users
WHERE is_active = 1;

-- 使用视图（和普通表一样）
SELECT * FROM active_users;
SELECT id, username FROM active_users WHERE username LIKE 'alice%';

-- OR REPLACE：视图已存在时替换，不存在时创建（避免先 DROP 再 CREATE）
CREATE OR REPLACE VIEW active_users AS
SELECT id, username, email, created_at
FROM users
WHERE is_active = 1 AND is_deleted = 0;
```

## 多表连接视图

```sql
-- 封装复杂 JOIN 查询
CREATE VIEW order_summary AS
SELECT 
    o.id          AS order_id,
    o.created_at  AS order_date,
    o.status,
    o.amount,
    u.username    AS customer_name,
    u.email       AS customer_email,
    p.name        AS product_name
FROM orders o
INNER JOIN users u ON u.id = o.user_id
INNER JOIN order_items oi ON oi.order_id = o.id
INNER JOIN products p ON p.id = oi.product_id;

-- 使用时只需简单的 SELECT
SELECT customer_name, SUM(amount) AS total
FROM order_summary
WHERE status = 2
GROUP BY customer_name;
```

## 带聚合的统计视图

```sql
-- 部门薪资统计视图
CREATE VIEW dept_salary_stats AS
SELECT 
    d.id           AS dept_id,
    d.name         AS dept_name,
    COUNT(e.id)    AS employee_count,
    AVG(e.salary)  AS avg_salary,
    MAX(e.salary)  AS max_salary,
    MIN(e.salary)  AS min_salary,
    SUM(e.salary)  AS total_salary
FROM departments d
LEFT JOIN employees e ON e.dept_id = d.id
GROUP BY d.id, d.name;
```

## 自定义视图列名

```sql
-- 方法1：AS 别名
CREATE VIEW user_contacts AS
SELECT id, CONCAT(first_name, ' ', last_name) AS full_name, email
FROM users;

-- 方法2：视图列列表（在视图名后指定）
CREATE VIEW user_contacts (user_id, full_name, contact_email) AS
SELECT id, CONCAT(first_name, ' ', last_name), email
FROM users;
```

```sql
-- 查看视图列表

SELECT TABLE_NAME, VIEW_DEFINITION, ALGORITHM, SECURITY_TYPE

WHERE TABLE_SCHEMA = DATABASE();
```

## SQL SECURITY 子句

```sql
-- DEFINER（默认）：以视图创建者的权限执行
-- INVOKER：以当前调用者的权限执行

-- 创建者有权限查 users 表，调用者可能没有
-- DEFINER 安全上下文：调用者只要有 SELECT 权限查视图即可，无需有查底层表的权限
CREATE DEFINER = 'admin'@'%' 
SQL SECURITY DEFINER
VIEW secure_user_info AS
SELECT id, username FROM users WHERE is_active = 1;

-- INVOKER：调用者必须自己有底层表的查询权限
CREATE SQL SECURITY INVOKER
VIEW user_info AS
SELECT id, username FROM users;
```

## 适用场景

- **简化复杂查询**：将频繁使用的多表 JOIN、聚合统计封装为视图，方便引用
- **权限控制**：通过视图只暴露特定列（如隐藏 password、salary），限制直接访问底层表
- **业务接口隔离**：底层表结构变化时，只需修改视图定义，不影响上层 SQL
- **数据脱敏展示**：在视图中对敏感字段做处理（如 SUBSTRING 隐藏手机号中间4位）

## 常见问题

**视图和临时表有什么区别？**

视图是持久化的数据库对象，不存储数据，每次查询时动态执行背后的 SELECT。临时表只在当前会话存在，存储真实数据，查询时无需重复计算。频繁访问且计算复杂的视图（特别是 TEMPTABLE 算法的视图），考虑改用物化的临时表或 CTE 替代。

---

## 注意事项

- 视图名和表名在同一数据库中不能重复。如果在有同名表的情况下创建同名视图，表会被视图覆盖（不推荐，容易造成混淆）。
- 视图中使用了 `ORDER BY`，但外部查询没有 `ORDER BY` 时，结果的顺序是不确定的。MySQL 不保证视图内的 ORDER BY 影响最终结果顺序，如需排序应在最外层查询中指定。
- 视图不能包含 `TEMPORARY` 表，也不能在视图中定义触发器，但可以在视图上建立触发器（前提是视图是可更新的）。

---

## 总结

`CREATE [OR REPLACE] VIEW view_name AS select_statement` 创建一个命名视图，将 SELECT 查询持久化为数据库对象。视图可以像普通表一样 SELECT，但不存储数据。`OR REPLACE` 省去先 DROP 的步骤。`SQL SECURITY DEFINER/INVOKER` 控制权限上下文。视图最核心的价值是封装查询逻辑、隔离底层表结构变化、实现列级权限控制。
