# 函数与存储过程的区别

存储函数（Function）和存储过程（Procedure）都是存储在数据库中的可复用 SQL 程序，但它们在调用方式、参数类型、返回值、使用场景上有明显不同。理解这些差异是选择使用哪种对象的基础。

---

## 核心对比

| 对比维度 | 存储函数（Function）| 存储过程（Procedure）|
|---------|-----------------|-------------------|
| 调用方式 | 嵌入 SQL 表达式（SELECT/WHERE/SET）| 独立 CALL 语句 |
| 返回方式 | RETURN 返回单个标量值 | 无 RETURN，通过 OUT/INOUT 参数或结果集返回 |
| 参数类型 | 只有 IN 参数 | IN、OUT、INOUT 三种 |
| 结果集 | 不能返回结果集（行列数据）| 可以返回多个结果集 |
| RETURNS 声明 | 必须有 RETURNS type | 不需要 |
| DML 操作 | 不建议（会引发复制和事务问题）| 可以 |
| 事务控制 | 不能显式提交/回滚事务 | 可以 START TRANSACTION/COMMIT/ROLLBACK |
| 创建语法 | CREATE FUNCTION ... RETURNS type | CREATE PROCEDURE ... |
| 调用语法 | SELECT fn_name() / SET v = fn_name() | CALL sp_name() |

---

## 调用方式差异

```sql
-- 函数：嵌入 SQL 中使用
SELECT id, fn_get_username(user_id) AS username FROM orders;
SELECT * FROM orders WHERE fn_calc_discount(user_id, amount) > 100;
SET @result = fn_add(3, 5);

-- 存储过程：独立 CALL 调用，不能嵌入表达式
CALL sp_get_active_users();
CALL sp_process_order(100, @result);
-- SELECT sp_process_order(100);  -- 错误！过程不能在 SELECT 中调用
```

## 返回值差异

```sql
DELIMITER //

-- 函数：单个 RETURN 值
CREATE FUNCTION fn_order_total(p_user_id INT) RETURNS DECIMAL(12,2)
READS SQL DATA
BEGIN
    DECLARE v_total DECIMAL(12,2);
    SELECT COALESCE(SUM(amount), 0) INTO v_total
    FROM orders WHERE user_id = p_user_id AND status = 2;
    RETURN v_total;    -- 只能返回一个值
END //

-- 存储过程：可以返回多个 OUT 参数和多个结果集
CREATE PROCEDURE sp_user_summary(
    IN  p_user_id  INT,
    OUT p_count    INT,
    OUT p_total    DECIMAL(12,2),
    OUT p_vip      TINYINT
)
BEGIN
    SELECT COUNT(*), SUM(amount) INTO p_count, p_total
    FROM orders WHERE user_id = p_user_id AND status = 2;
    
    SELECT is_vip INTO p_vip FROM users WHERE id = p_user_id;
    
    -- 还可以额外返回结果集
    SELECT id, amount, created_at FROM orders WHERE user_id = p_user_id LIMIT 10;
END //

DELIMITER ;

-- 函数调用
SELECT fn_order_total(5);

-- 过程调用（返回3个OUT参数+1个结果集）
CALL sp_user_summary(5, @cnt, @total, @vip);
SELECT @cnt, @total, @vip;
```

## 事务控制差异

```sql
DELIMITER //

-- 函数：不能使用事务控制语句
CREATE FUNCTION fn_bad_transaction(p_id INT) RETURNS INT
MODIFIES SQL DATA
BEGIN
    START TRANSACTION;    -- 语法上允许，但行为不可预期（函数嵌入在事务中时）
    UPDATE accounts SET balance = balance - 100 WHERE id = p_id;
    COMMIT;               -- 会提交外层调用者的事务！极危险
    RETURN 1;
END //

-- 存储过程：可以安全使用事务控制
CREATE PROCEDURE sp_transfer(IN p_from INT, IN p_to INT, IN p_amount DECIMAL)
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION ROLLBACK;
    START TRANSACTION;
    UPDATE accounts SET balance = balance - p_amount WHERE id = p_from;
    UPDATE accounts SET balance = balance + p_amount WHERE id = p_to;
    COMMIT;
END //

DELIMITER ;
```

## 何时用函数，何时用存储过程

| 场景 | 选择 | 原因 |
|------|------|------|
| SELECT 中计算字段 | Function | 可嵌入 SELECT 列表 |
| WHERE 条件中的逻辑判断 | Function | 可嵌入 WHERE 子句 |
| 数据脱敏、格式转换 | Function | 在多个查询中复用 |
| 多步骤业务操作（下单/支付）| Procedure | 需要多个 OUT 参数和事务控制 |
| 返回多行结果集 | Procedure | 函数不能返回结果集 |
| 批量数据处理 | Procedure | 需要游标、循环、事务 |

---

## 适用场景

- **函数**：业务规则计算（折扣、积分、评级）、字段格式化（脱敏、单位换算）、辅助列生成（生成列中调用函数），这些都需要嵌入 SQL 表达式。
- **存储过程**：完整的业务流程（下单+扣库存+写日志）、需要事务保证的操作、返回多个数据集的报表类查询。

---

## 常见问题

**函数能不能返回一个表（结果集）？**

不能。MySQL 的存储函数只能通过 RETURN 返回单个标量值，不能返回行列结果集。如果需要返回表数据，应使用存储过程（内部的 SELECT 直接返回结果集）。如果需要在 FROM 子句中"展开"函数的表结果，需要考虑使用视图或表值函数（MySQL 8.4 不原生支持表值函数，可用 JSON_TABLE 变通）。

---

## 注意事项

- 函数中如果包含 DML 语句（INSERT/UPDATE/DELETE），在调用者存在事务时可能引发隐式提交外层事务或其他并发问题，应将 DML 逻辑放在存储过程中。
- 选择函数还是存储过程时，首要判断标准是"是否需要嵌入 SQL 表达式中调用"——能嵌入 SQL 中使用的用函数，独立执行的业务流程用存储过程。

---

## 总结

存储函数通过 RETURN 返回单值，可以嵌入 SQL 表达式（SELECT/WHERE/SET）中使用；存储过程通过 CALL 独立调用，支持 OUT/INOUT 参数和多结果集返回，可以包含事务控制。选择原则：需要在 SQL 表达式中使用 → 函数；独立的业务逻辑流程（尤其包含 DML 和事务）→ 存储过程。
