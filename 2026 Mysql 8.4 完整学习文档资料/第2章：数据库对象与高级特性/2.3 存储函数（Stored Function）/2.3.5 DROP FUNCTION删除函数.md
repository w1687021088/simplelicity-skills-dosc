# DROP FUNCTION 删除函数

`DROP FUNCTION` 语句从数据库中删除一个已存在的存储函数定义。删除函数不影响底层表数据，但调用该函数的 SQL 语句、视图、存储过程和触发器在执行时会报错。`IF EXISTS` 选项防止函数不存在时报错。

---

## 语法

```sql
DROP FUNCTION [IF EXISTS] func_name;
```

---

## 基本示例

```sql
-- 删除存储函数
DROP FUNCTION fn_get_username;

-- IF EXISTS：函数不存在时不报错，只发出警告
DROP FUNCTION IF EXISTS fn_get_username;

-- 在部署脚本中的标准写法
DROP FUNCTION IF EXISTS fn_calc_discount;
DELIMITER //
CREATE FUNCTION fn_calc_discount(p_amount DECIMAL(10,2), p_rate DECIMAL(5,2))
RETURNS DECIMAL(10,2)
DETERMINISTIC
BEGIN
    RETURN ROUND(p_amount * p_rate, 2);
END //
DELIMITER ;
```

---

## 删除前查看依赖

```sql
-- 查看引用该函数的视图
SELECT TABLE_NAME, VIEW_DEFINITION
FROM information_schema.VIEWS
WHERE TABLE_SCHEMA = DATABASE()
  AND VIEW_DEFINITION LIKE '%fn_calc_discount%';

-- 查看引用该函数的存储过程/函数
SELECT ROUTINE_NAME, ROUTINE_TYPE
FROM information_schema.ROUTINES
WHERE ROUTINE_SCHEMA = DATABASE()
  AND ROUTINE_DEFINITION LIKE '%fn_calc_discount%';

-- 确认无依赖后删除
DROP FUNCTION IF EXISTS fn_calc_discount;
```

---

## 修改函数的标准流程

```sql
-- MySQL 不支持 ALTER FUNCTION 修改函数体（只能改特性声明）
-- 修改函数体必须先 DROP 再 CREATE

-- 步骤1：备份旧定义
SHOW CREATE FUNCTION fn_mask_name\G

-- 步骤2：删除旧函数
DROP FUNCTION IF EXISTS fn_mask_name;

-- 步骤3：创建新版本
DELIMITER //
CREATE FUNCTION fn_mask_name(p_name VARCHAR(100)) RETURNS VARCHAR(100)
DETERMINISTIC
BEGIN
    -- 新版本逻辑
    DECLARE v_len INT DEFAULT CHAR_LENGTH(p_name);
    IF v_len <= 1 THEN RETURN p_name; END IF;
    RETURN CONCAT(LEFT(p_name, 1), REPEAT('*', v_len - 1));
END //
DELIMITER ;
```

## DROP FUNCTION vs DROP PROCEDURE

```sql
-- 函数和存储过程是不同类型的对象，有各自的 DROP 语句
DROP FUNCTION fn_calc;       -- 删除存储函数
DROP PROCEDURE sp_process;   -- 删除存储过程

-- 不能混用：对函数执行 DROP PROCEDURE 会报错
DROP PROCEDURE fn_calc;
-- ERROR 1305 (42000): PROCEDURE mydb.fn_calc does not exist

-- 查询时也要区分 ROUTINE_TYPE
SELECT ROUTINE_NAME, ROUTINE_TYPE FROM information_schema.ROUTINES
WHERE ROUTINE_SCHEMA = DATABASE();
-- ROUTINE_TYPE 列：'FUNCTION' 或 'PROCEDURE'
```

## 需要的权限

```sql
-- 删除函数需要 ALTER ROUTINE 权限（或是函数的 DEFINER）
SHOW GRANTS FOR CURRENT_USER();

-- 授予 ALTER ROUTINE 权限
GRANT ALTER ROUTINE ON mydb.* TO 'dev_user'@'%';

-- 撤销权限后无法删除函数
-- ERROR 1370 (42000): alter routine command denied to user 'dev'@'localhost' for routine 'mydb.fn_calc'
```

---

## 适用场景

- **版本迭代**：更新函数逻辑时先 `DROP IF EXISTS` 再重新 `CREATE`
- **清理废弃函数**：删除不再使用的旧版本或测试函数
- **数据库重置**：开发/测试环境中清空所有自定义函数

---

## 常见问题

**删除函数后，用到该函数的视图还能查询吗？**

视图定义本身不会改变，但查询视图时 MySQL 会执行视图定义中的 SQL，尝试调用已删除的函数时报错 `ERROR 1305: FUNCTION does not exist`。如果视图使用了该函数，需要在删除函数前先修改或删除视图，或者在重建函数后视图自动恢复可用。

---

## 注意事项

- 与存储过程一样，MySQL 没有"重命名函数"的语法，重命名只能通过 DROP + CREATE 完成。
- 生产环境执行 DROP FUNCTION 前，确认没有正在执行的 SQL 语句调用了该函数，避免运行时错误。

---

## 总结

`DROP FUNCTION [IF EXISTS] func_name` 删除存储函数定义，不影响底层数据。`IF EXISTS` 防止函数不存在时报错。修改函数体必须先 DROP 再 CREATE（ALTER FUNCTION 无法修改函数体代码）。删除函数前检查 `information_schema.VIEWS` 和 `ROUTINES` 中的依赖关系，避免导致其他对象失效。
