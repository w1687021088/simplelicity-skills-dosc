# 确定性函数 DETERMINISTIC 声明

`DETERMINISTIC` 是存储函数（和存储过程）的特性声明，表示相同的输入参数永远产生相同的返回值。这个声明对 MySQL 的二进制日志（binlog）行为、查询优化器以及数据复制有直接影响。声明是否准确至关重要，错误声明会导致数据不一致。

---

## 语法

```sql
CREATE FUNCTION func_name(params) RETURNS type
DETERMINISTIC          -- 或 NOT DETERMINISTIC
BEGIN
    ...
END;
```

---

## 什么是确定性函数

```sql
-- DETERMINISTIC（确定性）：相同输入 → 永远相同输出
-- 例如：数学计算、字符串处理

DELIMITER //

CREATE FUNCTION fn_circle_area(r DOUBLE) RETURNS DOUBLE
DETERMINISTIC            -- 相同的 r 永远得到相同的面积
RETURN PI() * r * r //

CREATE FUNCTION fn_mask_phone(p_phone VARCHAR(20)) RETURNS VARCHAR(20)
DETERMINISTIC            -- 相同的手机号永远得到相同的脱敏结果
RETURN CONCAT(LEFT(p_phone, 3), '****', RIGHT(p_phone, 4)) //

-- NOT DETERMINISTIC（非确定性）：相同输入 → 可能产生不同输出
-- 例如：依赖 NOW()、RAND()、外部表数据

CREATE FUNCTION fn_current_time_str() RETURNS VARCHAR(30)
NOT DETERMINISTIC        -- 每次调用返回不同的时间
RETURN DATE_FORMAT(NOW(), '%Y-%m-%d %H:%i:%s') //

CREATE FUNCTION fn_get_username(p_id INT) RETURNS VARCHAR(100)
READS SQL DATA           -- 查询数据库（表数据可能变化，非确定性）
NOT DETERMINISTIC
BEGIN
    DECLARE v_name VARCHAR(100);
    SELECT username INTO v_name FROM users WHERE id = p_id;
    RETURN COALESCE(v_name, 'Unknown');
END //

DELIMITER ;
```

## DETERMINISTIC 与 binlog 的关系

```sql
-- 当 MySQL 开启二进制日志（log_bin = ON）时：
-- 如果函数既没有 DETERMINISTIC，也没有 NO SQL 或 READS SQL DATA 声明：
-- 创建函数会报错：
-- ERROR 1418 (HY000): This function has none of DETERMINISTIC, NO SQL, or 
-- READS SQL DATA in its declaration and binary logging is enabled
-- (you *might* want to use the less safe log_bin_trust_function_creators variable)

-- 解决方案1：给函数加正确的特性声明
CREATE FUNCTION fn_calc(a INT, b INT) RETURNS INT
DETERMINISTIC              -- 声明为确定性
RETURN a + b;

-- 解决方案2（临时/不推荐）：设置 log_bin_trust_function_creators = ON
-- 此设置允许创建没有声明的函数，但可能导致主从数据不一致
SET GLOBAL log_bin_trust_function_creators = ON;
```

---

## 特性声明速查

| 特性 | 含义 | 与 binlog 的关系 |
|------|------|----------------|
| `DETERMINISTIC` | 相同输入总是相同输出 | 可以安全基于语句记录日志 |
| `NOT DETERMINISTIC` | 相同输入可能不同输出（默认）| 需要以行级格式记录 |
| `NO SQL` | 函数不包含 SQL | 可以安全基于语句记录 |
| `READS SQL DATA` | 函数只读取数据 | 可以允许创建（MySQL 内部判断是否安全）|
| `MODIFIES SQL DATA` | 函数修改数据 | 需要格外小心，复制可能不安全 |
| `CONTAINS SQL` | 包含 SQL 但不读写数据（默认）| 未明确声明时 binlog 可能报错 |

## 错误声明的后果

```sql
-- 将非确定性函数错误声明为 DETERMINISTIC（危险）
CREATE FUNCTION fn_wrong(p_id INT) RETURNS VARCHAR(100)
DETERMINISTIC            -- 声明了确定性
READS SQL DATA           -- 但实际查询数据库（数据可能变化）
BEGIN
    DECLARE v_name VARCHAR(100);
    SELECT username INTO v_name FROM users WHERE id = p_id;
    RETURN v_name;
END;

-- 危害：
-- 优化器可能缓存该函数的结果，导致查询拿到旧数据
-- 在基于语句的 binlog 中，从库可能看到不同的表数据，导致主从数据不一致
```

## 实际项目中的推荐声明

```sql
DELIMITER //

-- 纯计算：DETERMINISTIC
CREATE FUNCTION fn_discount_price(price DECIMAL, rate DECIMAL) 
RETURNS DECIMAL(10,2)
DETERMINISTIC
RETURN ROUND(price * rate, 2) //

-- 只查数据库：NOT DETERMINISTIC + READS SQL DATA
CREATE FUNCTION fn_user_level(p_id INT) RETURNS VARCHAR(20)
NOT DETERMINISTIC
READS SQL DATA
BEGIN
    DECLARE v_orders INT;
    SELECT COUNT(*) INTO v_orders FROM orders WHERE user_id = p_id AND status = 2;
    RETURN CASE WHEN v_orders > 100 THEN 'Gold'
                WHEN v_orders > 20  THEN 'Silver'
                ELSE 'Bronze' END;
END //

DELIMITER ;
```

## 适用场景

- **纯数学/字符串计算**：必须声明 DETERMINISTIC（面积计算、字符串处理）
- **查询数据库的函数**：声明 NOT DETERMINISTIC + READS SQL DATA（用户等级、最新状态）
- **依赖当前时间/随机数**：声明 NOT DETERMINISTIC（任何使用 NOW()、RAND()、UUID() 的函数）

---

## 常见问题

**能同时声明 DETERMINISTIC 和 READS SQL DATA 吗？**

语法上允许，但语义上矛盾——查询数据库的函数通常不是确定性的（表数据会变化）。同时声明时 MySQL 以 DETERMINISTIC 为准。建议不要同时声明，选择最能准确描述函数行为的那一个。

---

## 注意事项

- `DETERMINISTIC` 声明是程序员的承诺，MySQL 不会验证函数是否真的具有确定性。错误的声明（把非确定性函数声明为 DETERMINISTIC）不会报错，但会导致数据不一致问题，特别是在主从复制环境中。
- 默认不声明任何特性时，MySQL 使用 `NOT DETERMINISTIC` 和 `CONTAINS SQL`。在 binlog 开启的情况下，`CONTAINS SQL + NOT DETERMINISTIC` 组合会导致创建失败（需要 `log_bin_trust_function_creators = ON` 才能绕过）。

---

## 总结

`DETERMINISTIC` 声明表示函数对相同输入始终返回相同值，是存储函数特性声明中与 binlog 和复制安全最相关的部分。纯计算函数必须声明 DETERMINISTIC；访问数据库的函数应声明 NOT DETERMINISTIC + READS SQL DATA；依赖时间或随机数的函数是 NOT DETERMINISTIC。错误声明会导致优化器缓存错误结果或主从复制数据不一致。
