# CREATE FUNCTION 创建函数

存储函数（Stored Function）是一种特殊的存储程序，接收参数（只有 IN 类型）并通过 `RETURN` 返回单个值。与存储过程不同，存储函数可以直接嵌入 SQL 表达式中使用（如 `SELECT my_func(id)` 或 `WHERE my_func(col) > 10`），类似于 MySQL 内置函数。

---

## 语法

```sql
CREATE
    [DEFINER = user]
    FUNCTION [IF NOT EXISTS] func_name ([func_parameter[,...]])
    RETURNS type
    [characteristic ...]
    routine_body

func_parameter:
    param_name type      -- 注意：函数参数没有 IN/OUT/INOUT 修饰，默认都是 IN

characteristic:
    COMMENT 'string'
  | LANGUAGE SQL
  | [NOT] DETERMINISTIC
  | { CONTAINS SQL | NO SQL | READS SQL DATA | MODIFIES SQL DATA }
  | SQL SECURITY { DEFINER | INVOKER }
```

---

## 基本示例

```sql
DELIMITER //

-- 最简单的函数：计算两数之和
CREATE FUNCTION fn_add(a INT, b INT) RETURNS INT
DETERMINISTIC
BEGIN
    RETURN a + b;
END //

-- 字符串处理函数：姓名脱敏
CREATE FUNCTION fn_mask_name(p_name VARCHAR(50)) RETURNS VARCHAR(50)
DETERMINISTIC
BEGIN
    DECLARE v_len INT;
    SET v_len = CHAR_LENGTH(p_name);
    IF v_len <= 1 THEN
        RETURN p_name;
    ELSEIF v_len = 2 THEN
        RETURN CONCAT(LEFT(p_name, 1), '*');
    ELSE
        RETURN CONCAT(LEFT(p_name, 1), REPEAT('*', v_len - 2), RIGHT(p_name, 1));
    END IF;
END //

-- 查询函数：根据用户 ID 获取用户名（READS SQL DATA）
CREATE FUNCTION fn_get_username(p_user_id INT) RETURNS VARCHAR(100)
READS SQL DATA
BEGIN
    DECLARE v_name VARCHAR(100);
    SELECT username INTO v_name FROM users WHERE id = p_user_id;
    RETURN COALESCE(v_name, 'Unknown');
END //

DELIMITER ;

-- 在 SQL 中直接使用
SELECT fn_add(3, 4);                              -- 7
SELECT fn_mask_name('张三丰');                    -- 张*丰
SELECT id, fn_get_username(id) AS username FROM orders LIMIT 5;
```

## IF NOT EXISTS（MySQL 8.0+）

```sql
DELIMITER //

-- 函数已存在时不报错，保留原有定义
CREATE FUNCTION IF NOT EXISTS fn_add(a INT, b INT) RETURNS INT
DETERMINISTIC
RETURN a + b;    -- 单语句函数可以省略 BEGIN...END

DELIMITER ;
```

---

## 单语句函数（省略 BEGIN...END）

```sql
DELIMITER //

-- 简单到只需一个 RETURN 的函数可以省略 BEGIN...END
CREATE FUNCTION fn_square(n DOUBLE) RETURNS DOUBLE
DETERMINISTIC
RETURN n * n //

CREATE FUNCTION fn_is_vip(p_user_id INT) RETURNS TINYINT
READS SQL DATA
RETURN (SELECT is_vip FROM users WHERE id = p_user_id) //

DELIMITER ;

SELECT fn_square(5.0);       -- 25
SELECT fn_is_vip(3);         -- 1 或 0
```

## 查看函数定义

```sql
-- 列出当前数据库的存储函数
SHOW FUNCTION STATUS WHERE Db = DATABASE();

-- 查看函数定义
SHOW CREATE FUNCTION fn_mask_name\G

-- 从 information_schema 查询
SELECT ROUTINE_NAME, DATA_TYPE, IS_DETERMINISTIC, DTD_IDENTIFIER
FROM information_schema.ROUTINES
WHERE ROUTINE_SCHEMA = DATABASE()
  AND ROUTINE_TYPE = 'FUNCTION';
```

## 函数在 SQL 中的使用方式

```sql
-- SELECT 列表中
SELECT id, fn_mask_name(full_name) AS masked_name FROM users;

-- WHERE 条件中
SELECT * FROM orders WHERE fn_get_username(user_id) = 'alice';

-- GROUP BY 中
SELECT fn_get_username(user_id) AS uname, COUNT(*) AS cnt
FROM orders GROUP BY fn_get_username(user_id);

-- UPDATE 的 SET 中
UPDATE users SET display_name = fn_mask_name(full_name);

-- 其他函数中嵌套
SELECT CONCAT('用户：', fn_get_username(1)) AS info;
```

## 适用场景

- **数据脱敏**：姓名、手机号、身份证号的脱敏处理（封装为函数，在多个查询中复用）
- **业务计算**：折扣计算、佣金计算、评分换算等（封装为函数在 SELECT 中使用）
- **代码复用**：多个查询需要相同的复杂计算逻辑，封装为函数避免重复
- **数据转换**：状态码转文字、单位换算等简单映射

## 常见问题

**函数能执行 INSERT/UPDATE/DELETE 吗？**

技术上在声明了 `MODIFIES SQL DATA` 特性的函数中可以执行 DML，但 MySQL 强烈不建议这样做。在事务中调用含 DML 的函数会引发各种复杂问题（事务一致性、复制等），且默认情况下非确定性函数在开启二进制日志时还需要特殊配置。函数应保持"只读"或"纯计算"的特性。

---

## 注意事项

- 函数必须有 `RETURNS type` 声明（声明返回类型），并且函数体内所有执行路径都必须到达 `RETURN` 语句。如果函数在某个 IF 分支没有 RETURN，MySQL 会报警告，并在该路径执行时返回 NULL。
- 在 MySQL 开启二进制日志（`log_bin = ON`）时，创建非 DETERMINISTIC 函数会报错 `ERROR 1418: This function has none of DETERMINISTIC, NO SQL, or READS SQL DATA in its declaration`，必须声明恰当的特性（`DETERMINISTIC` 或 `READS SQL DATA`）。

---

## 总结

`CREATE FUNCTION func_name(params) RETURNS type characteristic BEGIN ... RETURN value; END` 创建存储函数。函数的核心特点是可以直接嵌入 SQL 表达式中使用（SELECT/WHERE/UPDATE SET 等）。函数只有 IN 参数，必须通过 RETURN 返回单个值。开启 binlog 时必须声明 DETERMINISTIC 或 READS SQL DATA。函数适合封装计算逻辑和数据转换，不适合包含复杂事务的 DML 操作。
