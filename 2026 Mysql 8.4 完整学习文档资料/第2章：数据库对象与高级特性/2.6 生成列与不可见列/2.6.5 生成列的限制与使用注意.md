# 生成列的限制与使用注意

生成列（Generated Column）功能强大，但有一系列严格限制和使用注意点。了解这些限制有助于在设计阶段避免踩坑，在出现报错时快速定位问题根源。

---

## 表达式限制

```sql
-- 限制1：不能引用其他表或使用子查询
-- 以下写法报错：
CREATE TABLE orders (
    id         INT AUTO_INCREMENT PRIMARY KEY,
    user_id    INT,
    -- 错误：不能在生成列中查询其他表
    user_name  VARCHAR(100) AS (SELECT username FROM users WHERE id = user_id) VIRTUAL
    -- ERROR 3107: Expression of generated column 'user_name' contains a disallowed function.
);

-- 限制2：不能使用非确定性函数（NOW(), RAND(), UUID(), CURDATE() 等）
CREATE TABLE items (
    id         INT AUTO_INCREMENT PRIMARY KEY,
    name       VARCHAR(100),
    -- 错误：NOW() 是非确定性函数
    created_ts VARCHAR(30) AS (DATE_FORMAT(NOW(), '%Y-%m-%d')) VIRTUAL
    -- ERROR 3637: Expression of generated column 'created_ts' contains a disallowed function.
);

-- 正确：只能引用同表的其他列或常量/确定性函数
CREATE TABLE products (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    price       DECIMAL(10,2),
    tax_rate    DECIMAL(5,4) DEFAULT 0.13,
    -- 合法：引用同表其他列
    price_inc_tax DECIMAL(12,2) AS (ROUND(price * (1 + tax_rate), 2)) VIRTUAL
);
```

---

## 列引用限制

```sql
-- 限制3：生成列只能引用在它之前定义的列（或在 ALTER TABLE 时已存在的列）
-- 正确：subtotal 在 quantity 和 unit_price 之后定义
CREATE TABLE order_items (
    quantity   INT,
    unit_price DECIMAL(10,2),
    subtotal   DECIMAL(12,2) AS (quantity * unit_price) VIRTUAL  -- 合法
);

-- 限制4：生成列不能引用另一个生成列（在同一表的 DDL 中）
-- 注：MySQL 8.0.19 之前不允许，8.0.19+ 允许在有限条件下引用
CREATE TABLE demo (
    a INT,
    b INT AS (a * 2) VIRTUAL,
    -- 在 8.0.19 之前此处不允许引用 b：
    c INT AS (b + 1) VIRTUAL   -- 可能不被支持，取决于版本
);
```

---

## DML 限制

```sql
-- 限制5：不能在 INSERT/UPDATE 中为生成列指定值
CREATE TABLE items (
    id       INT AUTO_INCREMENT PRIMARY KEY,
    price    DECIMAL(10,2),
    tax      DECIMAL(10,2) AS (price * 0.13) VIRTUAL
);

-- 报错：不能给生成列赋值
INSERT INTO items (id, price, tax) VALUES (1, 100, 13);
-- ERROR 3105: The value specified for generated column 'tax' in table 'items' is not allowed.

-- 正确：不要在 DML 中包含生成列
INSERT INTO items (price) VALUES (100);   -- tax 自动计算
UPDATE items SET price = 200 WHERE id = 1;  -- tax 自动重新计算
```

---

## 存储引擎限制

```sql
-- 虚拟生成列（VIRTUAL）：仅 InnoDB 和 NDB 支持索引，MyISAM 不支持
-- 存储生成列（STORED）：InnoDB, MyISAM 等主要引擎均支持

-- 外键：
-- VIRTUAL 生成列不能作为外键的被引用列（没有实际存储）
-- STORED 生成列可以作为外键的被引用列

-- 分区：
-- 生成列可以用于分区键，但表达式必须满足分区函数的要求
```

## 数据类型与隐式转换

```sql
-- 生成列的数据类型必须与表达式的返回类型兼容
-- 类型不兼容时 MySQL 进行隐式截断（不报错，但可能丢失精度）

CREATE TABLE demo_types (
    a DECIMAL(10,5),
    -- 声明为 INT，但 a 是小数，发生截断
    b INT AS (a * 100) VIRTUAL   -- 如果 a=1.12345，b 计算结果 112.345 会被截断为 112
);

-- 建议：声明类型时与表达式的精确输出匹配
CREATE TABLE demo_types_correct (
    a       DECIMAL(10,5),
    b_exact DECIMAL(12,3) AS (a * 100) VIRTUAL   -- 类型与计算结果匹配
);
```

## ALTER TABLE 添加存储生成列的性能影响

```sql
-- 添加 STORED 生成列会触发全表重建（重新计算并写入每一行）
-- 对于大表（数百万行），这个操作可能非常慢，且会锁表

-- 检查表大小
SELECT table_name, ROUND(data_length/1024/1024, 2) AS data_mb
FROM information_schema.TABLES
WHERE table_schema = DATABASE() AND table_name = 'orders';

-- 对大表，考虑：
-- 1. 在低峰期执行
-- 2. 使用 pt-online-schema-change 工具（避免长时间锁表）
-- 3. 先添加 VIRTUAL 列（无重建开销），再考虑是否改为 STORED

-- 添加 VIRTUAL 生成列无需全表重建（仅更新表定义）
ALTER TABLE orders ADD COLUMN order_year SMALLINT AS (YEAR(created_at)) VIRTUAL;
-- 对大表也很快（不重建数据）

-- 添加 STORED 生成列会全表重建
ALTER TABLE orders ADD COLUMN order_ym CHAR(7) AS (DATE_FORMAT(created_at, '%Y-%m')) STORED;
-- 大表上可能需要很长时间
```

## 生成列与触发器的关系

```sql
-- 触发器中可以读取生成列（VIRTUAL 或 STORED）的值
-- 但不能在触发器中修改生成列的值

CREATE TABLE items (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    price DECIMAL(10,2),
    tax   DECIMAL(10,2) AS (price * 0.13) VIRTUAL
);

CREATE TRIGGER trg_items_after_insert
AFTER INSERT ON items
FOR EACH ROW
BEGIN
    -- 可以读取生成列的值
    INSERT INTO item_audit (item_id, tax_amount) VALUES (NEW.id, NEW.tax);
    
    -- 不能修改生成列
    -- SET NEW.tax = 15;  -- 报错
END;
```

## 适用场景

- **规避陷阱**：了解不能用 NOW()/子查询，在设计阶段选择合适的方案
- **大表操作预规划**：添加 STORED 列前评估表大小，决定是否需要在低峰期操作
- **版本兼容性检查**：跨生成列引用（`c AS (b + 1)`）需要确认 MySQL 版本支持

---

## 常见问题

**为什么不能在生成列中用 NOW()？**

生成列的值必须具有确定性，即在任意时间读取都能通过表达式重现相同的值。`NOW()` 每次调用返回不同时间，无法保证重现性。更深层原因是 InnoDB 的 MVCC 机制需要能在任何时间点重新计算生成列的值。

---

## 注意事项

- 生成列不能有 `DEFAULT` 值（因为值由表达式决定，不需要也不允许有默认值）。
- 生成列上的约束（NOT NULL、UNIQUE 等）在 MySQL 层面才能检查，底层引擎层的约束（如外键）对 VIRTUAL 列不适用。

---

## 总结

生成列的关键限制：表达式只能引用同表其他列（不能子查询或跨表）；不能使用非确定性函数（NOW/RAND/UUID）；不能在 INSERT/UPDATE 中赋值；VIRTUAL 列不能作为外键引用。性能注意：添加 STORED 列会全表重建，大表应在低峰期操作；添加 VIRTUAL 列无此问题。设计时先确认版本和引擎支持，再选择 VIRTUAL 还是 STORED。
