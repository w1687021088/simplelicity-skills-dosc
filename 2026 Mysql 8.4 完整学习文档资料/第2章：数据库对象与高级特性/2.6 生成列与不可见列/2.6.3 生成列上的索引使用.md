# 生成列上的索引使用

在生成列上创建索引是 MySQL 实现**函数索引**（Functional Index）的核心机制。普通列上无法直接对函数结果建索引，但通过生成列配合索引，可以让 `WHERE LOWER(email) = ?` 或 `WHERE YEAR(created_at) = ?` 这类函数过滤查询走索引，大幅提升查询性能。

---

## 函数索引的传统问题

```sql
-- 没有生成列索引时，函数过滤无法使用索引
CREATE TABLE users (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(255),
    INDEX idx_email (email)   -- 普通索引
);

-- 以下查询无法使用 idx_email（函数破坏了索引可用性）
SELECT * FROM users WHERE LOWER(email) = 'alice@example.com';
-- type: ALL（全表扫描），即使 email 有索引也无法使用
```

---

## 通过生成列实现函数索引

```sql
-- 方式1：虚拟生成列 + 索引（推荐，不占额外存储）
CREATE TABLE users (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    email       VARCHAR(255),
    email_lower VARCHAR(255) AS (LOWER(email)) VIRTUAL,
    INDEX idx_email_lower (email_lower)
);

-- 现在可以走索引
SELECT * FROM users WHERE email_lower = 'alice@example.com';
-- type: ref（走索引）

-- 优化器也可以自动转换（有些版本支持）
EXPLAIN SELECT * FROM users WHERE LOWER(email) = 'alice@example.com';
-- MySQL 优化器可以识别这是对 email_lower 列的查询，自动使用 idx_email_lower
```

## 日期函数索引

```sql
CREATE TABLE orders (
    id         INT AUTO_INCREMENT PRIMARY KEY,
    user_id    INT,
    amount     DECIMAL(10,2),
    created_at DATETIME,
    -- 存储生成列：提取日期部分用于按天统计
    order_date DATE GENERATED ALWAYS AS (DATE(created_at)) STORED,
    -- 存储生成列：提取年月用于按月统计
    order_ym   CHAR(7) GENERATED ALWAYS AS (DATE_FORMAT(created_at, '%Y-%m')) STORED,
    INDEX idx_order_date (order_date),
    INDEX idx_order_ym   (order_ym)
);

-- 走 idx_order_date 索引
SELECT * FROM orders WHERE order_date = '2026-03-15';

-- 走 idx_order_ym 索引  
SELECT SUM(amount) FROM orders WHERE order_ym = '2026-03';

-- 对比：以下写法无法走索引
-- SELECT * FROM orders WHERE DATE(created_at) = '2026-03-15';  -- 全表扫描
```

## JSON 字段的提取索引

```sql
CREATE TABLE user_profiles (
    id         INT AUTO_INCREMENT PRIMARY KEY,
    user_id    INT UNIQUE,
    meta       JSON,
    -- 从 JSON 提取城市字段，用于城市过滤查询
    city       VARCHAR(100) AS (JSON_UNQUOTE(JSON_EXTRACT(meta, '$.address.city'))) VIRTUAL,
    -- 从 JSON 提取年龄段，用于用户分层查询
    age_group  VARCHAR(20) AS (
        CASE
            WHEN JSON_EXTRACT(meta, '$.age') < 18 THEN 'minor'
            WHEN JSON_EXTRACT(meta, '$.age') < 30 THEN 'young'
            WHEN JSON_EXTRACT(meta, '$.age') < 50 THEN 'middle'
            ELSE 'senior'
        END
    ) VIRTUAL,
    INDEX idx_city      (city),
    INDEX idx_age_group (age_group)
);

-- 走索引的 JSON 过滤查询
SELECT * FROM user_profiles WHERE city = 'Beijing';
SELECT COUNT(*) FROM user_profiles GROUP BY age_group;
```

## 唯一约束与生成列

```sql
-- 用生成列实现大小写不敏感的邮箱唯一约束
CREATE TABLE users (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    email       VARCHAR(255) NOT NULL,
    email_lower VARCHAR(255) AS (LOWER(email)) VIRTUAL,
    UNIQUE KEY uk_email_lower (email_lower)   -- 唯一约束加在生成列上
);

-- 大小写不同但实际相同的邮箱被拦截
INSERT INTO users (email) VALUES ('Alice@Example.com');   -- 成功
INSERT INTO users (email) VALUES ('alice@example.com');   -- ERROR 1062：唯一键冲突
INSERT INTO users (email) VALUES ('ALICE@EXAMPLE.COM');   -- ERROR 1062：唯一键冲突
```

## MySQL 8.0+ 直接语法函数索引

```sql
-- MySQL 8.0.13+ 支持直接在 CREATE TABLE 中使用函数索引（语法糖）
-- 底层实现原理与生成列索引相同，只是语法更简洁
CREATE TABLE users (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(255),
    INDEX idx_email_lower ((LOWER(email)))  -- 注意双括号
);

-- 等价于（MySQL 内部会自动创建一个隐藏的虚拟生成列）
-- 查询效果相同：WHERE LOWER(email) = 'alice@example.com' 走索引
```

## 适用场景

- **大小写不敏感查询**：`LOWER(col)` 生成列 + 唯一索引，实现邮箱/用户名不区分大小写
- **日期范围查询优化**：`DATE(datetime_col)` 或 `DATE_FORMAT(...)` 提取日期部分加索引
- **JSON 字段快速过滤**：从 JSON 中提取常用查询字段，加索引避免全表扫描
- **表达式唯一约束**：`TRIM(col)` 去空格后的唯一约束

---

## 常见问题

**直接函数索引（双括号语法）和生成列索引有区别吗？**

功能上没有区别，MySQL 8.0.13+ 的函数索引语法底层实际就是创建一个隐藏的虚拟生成列再加索引。函数索引语法更简洁，不需要显式定义生成列；生成列方式更灵活，生成列本身可以在 SELECT 中直接引用。

---

## 注意事项

- 在生成列上建索引后，查询时使用的函数表达式必须与生成列的表达式完全一致，优化器才能识别并使用索引。`LOWER(email)` 有索引，但查询用 `LCASE(email)` 不会被识别（虽然功能相同，但函数名不同）。
- 生成列的表达式不能引用其他表，也不能使用非确定性函数（NOW()、RAND()），否则无法创建索引。

---

## 总结

生成列索引是 MySQL 实现函数索引的机制：定义虚拟/存储生成列 `col AS (expr)`，再在该列上 `CREATE INDEX`，之后涉及相同表达式的查询就能走索引。常用于 `LOWER(email)` 邮箱大小写不敏感、`DATE(created_at)` 日期过滤、JSON 字段提取等场景。MySQL 8.0.13+ 提供了更简洁的函数索引语法 `((expr))`，底层与生成列索引完全相同。
