# 虚拟生成列 VIRTUAL

虚拟生成列（Virtual Generated Column）是根据表达式计算得出的列，**不占用实际的存储空间**，每次查询时实时计算。适合频繁查询但不需要持久化存储的派生字段。MySQL 5.7 引入，8.x 持续完善。

---

## 语法

```sql
col_name data_type [GENERATED ALWAYS] AS (expression) VIRTUAL
-- VIRTUAL 是默认值，可以省略
-- expression 中只能引用同一行的其他列，不能引用其他表或子查询
```

---

## 基本示例

```sql
-- 创建表时定义虚拟生成列
CREATE TABLE order_items (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    product_id  INT NOT NULL,
    quantity    INT NOT NULL DEFAULT 1,
    unit_price  DECIMAL(10,2) NOT NULL,
    -- 虚拟生成列：小计 = 数量 × 单价（查询时实时计算，不存储）
    subtotal    DECIMAL(12,2) GENERATED ALWAYS AS (quantity * unit_price) VIRTUAL,
    -- 虚拟生成列：含税价（税率 10%）
    price_with_tax DECIMAL(12,2) AS (unit_price * 1.10) VIRTUAL,
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 查询时虚拟列实时计算
SELECT id, quantity, unit_price, subtotal, price_with_tax FROM order_items;
-- subtotal 和 price_with_tax 在查询时实时计算，不存储在磁盘上
```

## 在已有表上添加虚拟生成列

```sql
-- 给现有表添加虚拟生成列
ALTER TABLE users
ADD COLUMN full_name_upper VARCHAR(200)
    GENERATED ALWAYS AS (UPPER(CONCAT(first_name, ' ', last_name))) VIRTUAL;

ALTER TABLE products
ADD COLUMN price_category VARCHAR(20)
    GENERATED ALWAYS AS (
        CASE
            WHEN price < 100  THEN 'low'
            WHEN price < 1000 THEN 'medium'
            ELSE 'high'
        END
    ) VIRTUAL;
```

## 虚拟生成列支持的表达式

```sql
CREATE TABLE demo_virtual (
    id        INT AUTO_INCREMENT PRIMARY KEY,
    first     VARCHAR(50),
    last      VARCHAR(50),
    birthdate DATE,
    score     DECIMAL(5,2),
    json_data JSON,
    
    -- 字符串拼接
    full_name  VARCHAR(110) AS (CONCAT(first, ' ', last)) VIRTUAL,
    
    -- 日期计算
    age        INT AS (TIMESTAMPDIFF(YEAR, birthdate, CURDATE())) VIRTUAL,
    
    -- 数学计算
    grade      VARCHAR(2) AS (
        CASE WHEN score >= 90 THEN 'A'
             WHEN score >= 80 THEN 'B'
             WHEN score >= 70 THEN 'C'
             ELSE 'D' END
    ) VIRTUAL,
    
    -- JSON 提取
    city       VARCHAR(100) AS (JSON_UNQUOTE(JSON_EXTRACT(json_data, '$.city'))) VIRTUAL
);
```

## 虚拟生成列与索引

```sql
-- 可以在虚拟生成列上创建索引（常用于函数索引）
CREATE TABLE users (
    id       INT AUTO_INCREMENT PRIMARY KEY,
    email    VARCHAR(255),
    -- 邮箱小写虚拟列 + 索引 = 实现大小写不敏感的邮箱唯一约束
    email_lower VARCHAR(255) AS (LOWER(email)) VIRTUAL,
    INDEX idx_email_lower (email_lower)
);

-- 查询时自动利用虚拟列索引
SELECT * FROM users WHERE LOWER(email) = 'user@example.com';
-- 优化器可以利用 idx_email_lower 索引加速查询
```

## 虚拟列 vs 存储生成列

| 对比维度 | 虚拟生成列（VIRTUAL）| 存储生成列（STORED）|
|---------|--------------------|--------------------|
| 存储空间 | 不占用（实时计算）| 占用（持久化存储）|
| 计算时机 | 查询时计算 | INSERT/UPDATE 时计算一次 |
| 查询性能 | 每次查询都计算（复杂表达式影响性能）| 读取存储值，无需计算 |
| 写入性能 | 不影响写入 | INSERT/UPDATE 有额外计算 |
| 支持索引 | 是（会为索引存储计算结果）| 是 |
| 适用场景 | 简单派生字段、函数索引 | 复杂计算、频繁查询的派生字段 |

---

## 适用场景

- **函数索引**：对 `LOWER(email)` / `YEAR(created_at)` 等函数应用加速查询
- **简单派生字段**：小计、全名拼接、JSON 字段提取，在查询列表中使用
- **分类标签**：根据数值范围计算类别标签（价格档次、评分级别）

---

## 常见问题

**虚拟生成列可以更新吗？**

不能直接更新生成列（INSERT/UPDATE 中不能给生成列赋值）。其值由 MySQL 根据表达式自动计算，修改引用的基础列后，虚拟列的查询结果自动跟着变化。

---

## 注意事项

- 生成列的表达式中不能使用不确定性函数（`NOW()`、`RAND()`、`UUID()`），也不能引用其他表或子查询，只能基于同行的其他列或常量。
- 虚拟生成列虽然不存储数据，但在创建索引时 InnoDB 会在索引记录中存储该列的计算值，所以有索引的虚拟列不是"完全零开销"的。

---

## 总结

虚拟生成列（`col AS (expr) VIRTUAL`）在查询时实时计算，不占额外存储空间。适合简单的派生字段和函数索引场景。表达式只能引用同行其他列，不支持不确定性函数和子查询。可以在虚拟生成列上建索引，是 MySQL 实现函数索引（如 `LOWER(email)` 加速查询）的标准方式。
