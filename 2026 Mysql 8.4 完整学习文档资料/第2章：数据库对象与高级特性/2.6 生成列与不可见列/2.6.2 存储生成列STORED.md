# 存储生成列 STORED

存储生成列（Stored Generated Column）是在 INSERT 或 UPDATE 时计算并**持久化到磁盘**的派生列。与虚拟生成列不同，存储列在查询时直接读取已存好的值，不需要实时计算。适合计算代价高、查询频繁的派生字段。

---

## 语法

```sql
col_name data_type [GENERATED ALWAYS] AS (expression) STORED
-- STORED 关键字必须显式写出（与 VIRTUAL 的默认不同）
```

---

## 基本示例

```sql
-- 存储生成列：小计持久化存储
CREATE TABLE order_items (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    product_id  INT NOT NULL,
    quantity    INT NOT NULL DEFAULT 1,
    unit_price  DECIMAL(10,2) NOT NULL,
    discount    DECIMAL(5,4) NOT NULL DEFAULT 0,
    -- 存储生成列：折后小计，INSERT/UPDATE 时计算并存储
    subtotal    DECIMAL(12,2) GENERATED ALWAYS AS
                    (ROUND(quantity * unit_price * (1 - discount), 2)) STORED,
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- INSERT 时 MySQL 自动计算 subtotal 并存储
INSERT INTO order_items (product_id, quantity, unit_price, discount)
VALUES (101, 3, 199.00, 0.1);
-- subtotal 自动计算：3 * 199 * (1 - 0.1) = 537.30，并持久化存储

-- 查询时直接读取存储值，无计算开销
SELECT id, quantity, unit_price, discount, subtotal FROM order_items;
```

## 在已有表上添加存储生成列

```sql
-- 给现有表添加存储生成列
ALTER TABLE users
ADD COLUMN full_name VARCHAR(200)
    GENERATED ALWAYS AS (CONCAT(COALESCE(first_name, ''), ' ', COALESCE(last_name, ''))) STORED;

-- 添加后，MySQL 会对现有行计算并填充 full_name 的值（可能需要较长时间，视数据量而定）

-- 添加 JSON 提取的存储列
ALTER TABLE events
ADD COLUMN event_city VARCHAR(100)
    GENERATED ALWAYS AS (JSON_UNQUOTE(JSON_EXTRACT(event_data, '$.location.city'))) STORED,
ADD INDEX idx_event_city (event_city);  -- 同时添加索引
```

## 存储生成列上的索引

```sql
CREATE TABLE articles (
    id           INT AUTO_INCREMENT PRIMARY KEY,
    title        VARCHAR(500),
    content      LONGTEXT,
    author_id    INT,
    published_at DATETIME,
    -- 存储生成列：发布年月（用于按月份统计和过滤）
    pub_yearmonth CHAR(7) GENERATED ALWAYS AS (DATE_FORMAT(published_at, '%Y-%m')) STORED,
    INDEX idx_pub_yearmonth (pub_yearmonth),    -- 存储列可建索引
    UNIQUE KEY uk_title_author (title(100), author_id)
);

-- 查询时可以利用存储列索引
SELECT COUNT(*) FROM articles WHERE pub_yearmonth = '2026-03';
-- 比 WHERE DATE_FORMAT(published_at, '%Y-%m') = '2026-03' 快（有索引）
```

## 存储生成列的约束

```sql
-- 存储生成列可以作为外键的被引用列
-- 存储生成列可以有 NOT NULL 约束（如果表达式不可能为 NULL）
-- 存储生成列不能有 DEFAULT 值
-- 存储生成列不能通过 INSERT/UPDATE 显式赋值

-- 以下会报错：
INSERT INTO order_items (product_id, quantity, unit_price, subtotal)
VALUES (1, 2, 100, 200.00);
-- ERROR 3105: The value specified for generated column 'subtotal' in table
-- 'order_items' is not allowed.

-- 正确写法：不要在 INSERT 中包含生成列
INSERT INTO order_items (product_id, quantity, unit_price)
VALUES (1, 2, 100);   -- subtotal 由 MySQL 自动计算
```

## VIRTUAL vs STORED 的完整对比

| 对比维度 | VIRTUAL | STORED |
|---------|---------|--------|
| 关键字 | `VIRTUAL`（默认可省略）| `STORED`（必须写）|
| 存储 | 不存储 | 持久化存储 |
| 计算时机 | 每次查询时 | INSERT/UPDATE 时 |
| 查询开销 | 有（实时计算）| 无（读存储值）|
| 写入开销 | 无 | 有（计算并写入）|
| 磁盘空间 | 无额外占用 | 占用额外存储 |
| 支持索引 | 是（索引记录计算值）| 是 |
| 支持外键引用 | 否 | 是 |
| 适用 | 简单计算/函数索引 | 复杂计算/高频查询 |

---

## 适用场景

- **高频查询的派生字段**：订单小计、含税价格、全名等每次查询都用到的派生值
- **基于 JSON 字段的提取列**：从 JSON 中提取关键字段并索引，提升 JSON 数据的查询性能
- **日期派生列**：从 DATETIME 提取 YEAR/MONTH/DATE 等，配合索引加速按日期范围的查询

---

## 常见问题

**存储生成列的数据与基础列不一致怎么处理？**

正常情况下不会出现不一致，因为每次 INSERT/UPDATE 时 MySQL 自动重新计算。只有在通过不常规方式（直接修改 ibdata 文件等）绕过 MySQL 写入才可能造成不一致，这属于数据损坏的情况，可以通过 `ALTER TABLE ... FORCE` 重建触发重新计算。

---

## 注意事项

- 给大表添加存储生成列（ALTER TABLE ADD COLUMN ... STORED）会触发全表重建，过程中会锁表（如果不使用 Online DDL）。对大表操作应在低峰期执行，或使用 pt-online-schema-change 等工具。
- 存储生成列占用额外的磁盘空间，在空间敏感的场景中，简单的派生字段优先考虑 VIRTUAL（如果查询频率不高）。

---

## 总结

存储生成列（`col AS (expr) STORED`）在 INSERT/UPDATE 时计算并持久化存储，查询时直接读取，适合高频查询的复杂派生字段。相比 VIRTUAL，STORED 查询更快但占用额外存储和写入计算开销。存储生成列支持索引，常用于 JSON 字段提取、日期派生列等需要频繁过滤和排序的场景。INSERT/UPDATE 不能显式为生成列赋值。
