# 不可见列 INVISIBLE

不可见列（Invisible Column）是 MySQL 8.0.23 引入的特性，允许将某列设置为"隐藏"状态。`SELECT *` 不会返回不可见列，`INSERT` 时也不需要显式指定列名来排除它。只有在查询/插入时**明确指定列名**，才会访问不可见列。

---

## 语法

```sql
-- 创建表时定义不可见列
col_name data_type ... INVISIBLE

-- 将已有列改为不可见
ALTER TABLE tbl MODIFY COLUMN col_name data_type ... INVISIBLE;

-- 将不可见列改回可见
ALTER TABLE tbl MODIFY COLUMN col_name data_type ... VISIBLE;
```

---

## 基本示例

```sql
-- 创建含不可见列的表
CREATE TABLE users (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    username    VARCHAR(100) NOT NULL,
    email       VARCHAR(255) NOT NULL,
    -- 不可见列：内部追踪字段，不希望暴露给普通查询
    internal_id VARCHAR(36)  INVISIBLE DEFAULT (UUID()),
    password_hash VARCHAR(255) INVISIBLE,
    created_at  DATETIME     DEFAULT CURRENT_TIMESTAMP
);

-- SELECT * 不包含不可见列
SELECT * FROM users;
-- 结果只有：id, username, email, created_at
-- internal_id 和 password_hash 不在结果中

-- 必须显式指定才能查询不可见列
SELECT id, username, internal_id FROM users;
SELECT id, password_hash FROM users WHERE id = 1;
```

---

## INSERT 时的行为

```sql
-- 无列名的 INSERT 不需要考虑不可见列（不可见列使用默认值）
INSERT INTO users (username, email) VALUES ('alice', 'alice@example.com');
-- internal_id 自动使用 DEFAULT (UUID())
-- password_hash 使用 DEFAULT（如果有的话），否则为 NULL

-- 不带列名的 INSERT VALUES（无法插入不可见列）
INSERT INTO users VALUES (DEFAULT, 'bob', 'bob@example.com', NOW());
-- 这个 INSERT 只对应4个可见列（id, username, email, created_at）
-- 不可见列不参与位置匹配

-- 要插入不可见列的值，必须显式指定列名
INSERT INTO users (username, email, internal_id, password_hash)
VALUES ('charlie', 'charlie@example.com', UUID(), SHA2('password123', 256));
```

## 修改列的可见性

```sql
-- 将已有列设为不可见（不影响数据，只影响 SELECT * 和无列名 INSERT 的行为）
ALTER TABLE users MODIFY COLUMN password_hash VARCHAR(255) INVISIBLE;

-- 将不可见列改回可见
ALTER TABLE users MODIFY COLUMN password_hash VARCHAR(255) VISIBLE;

-- 查看表结构（不可见列有标注）
SHOW CREATE TABLE users\G
-- 不可见列在 CREATE TABLE 语句中显示为：`internal_id` varchar(36) /*!80023 INVISIBLE */

DESC users;
-- 不可见列也会在 DESCRIBE 结果中显示，Null 列旁有 "YES/INVISIBLE" 标注
```

---

## 查看不可见列

```sql
-- DESCRIBE 会显示不可见列（列在结果中，但标注为不可见）
DESC users;
-- Field       | Type         | Null | Key | Default | Extra
-- id          | int          | NO   | PRI | NULL    | auto_increment
-- username    | varchar(100) | NO   |     | NULL    |
-- email       | varchar(255) | NO   |     | NULL    |
-- internal_id | varchar(36)  | YES  |     | NULL    | INVISIBLE
-- ...

-- 从 information_schema 查询不可见列
SELECT COLUMN_NAME, IS_NULLABLE, EXTRA
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_NAME = 'users'
  AND EXTRA LIKE '%INVISIBLE%';
```

## 实际应用场景

```sql
-- 场景1：向旧表添加新列，不破坏使用 SELECT * 的旧代码
-- 旧代码：SELECT * FROM orders WHERE id = ?（依赖列顺序处理结果集）
-- 新增一个内部字段，加 INVISIBLE 不影响旧代码

ALTER TABLE orders
ADD COLUMN processing_node VARCHAR(50) INVISIBLE DEFAULT (@@hostname);
-- 旧代码 SELECT * 不受影响，新代码可以显式查询 processing_node

-- 场景2：隐藏敏感字段（密码、内部编号）
-- 防止 SELECT * 意外泄露敏感信息
ALTER TABLE users MODIFY COLUMN password_hash VARCHAR(255) INVISIBLE;
-- SELECT * FROM users 不会返回 password_hash，需要显式 SELECT password_hash 才能读取
```

---

## 适用场景

- **平滑添加新列**：给被旧代码通过 `SELECT *` 或无列名 INSERT 操作的表添加新列，用 INVISIBLE 避免破坏旧代码
- **隐藏内部字段**：把数据库内部追踪字段（分片键、版本号、处理节点）设为不可见，不暴露给业务层
- **审计/追踪列**：对应用层完全透明的元数据字段

---

## 常见问题

**不可见列真的无法被 SELECT * 返回吗？**

是的，`SELECT *` 不包含不可见列。但注意，这是一种"隐藏"而不是"安全保护"——任何有 SELECT 权限的用户只要知道列名，仍然可以通过 `SELECT internal_id FROM users` 读取该列。不可见列不是权限控制机制。

---

## 注意事项

- 表中至少有一个可见列。如果尝试将表中最后一个可见列设为 INVISIBLE，会报错。
- 不可见列与生成列（VIRTUAL/STORED）可以结合使用：`col AS (expr) VIRTUAL INVISIBLE`，这样生成的列既不占存储，也不出现在 `SELECT *` 结果中。

---

## 总结

不可见列（`col type INVISIBLE`）使 `SELECT *` 不返回该列，无列名 INSERT 也不需要提供该列的值。必须显式指定列名才能读写不可见列。主要用途：平滑添加新列（不破坏旧代码）、隐藏内部追踪字段。通过 `ALTER TABLE MODIFY ... INVISIBLE/VISIBLE` 随时切换可见性，不影响数据。
