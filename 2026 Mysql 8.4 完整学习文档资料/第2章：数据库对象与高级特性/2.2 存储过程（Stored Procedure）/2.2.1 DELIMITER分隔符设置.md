# DELIMITER 分隔符设置

MySQL 客户端默认使用分号 `;` 作为语句结束符。存储过程、函数、触发器等多语句块内部也使用分号，这会导致客户端在读到第一个 `;` 时就提交语句，而不是等完整的存储过程定义结束后再提交。`DELIMITER` 命令用于临时更改语句结束符，解决这个冲突。

---

## 语法

```sql
DELIMITER delimiter_string
```

- `delimiter_string`：新的结束符，可以是任意字符串，常用 `//` 或 `$$`
- 这是 MySQL 客户端命令，**不是** SQL 语句（不能在编程语言的 SQL 驱动中使用，如 JDBC、pymysql）

---

## 为什么需要 DELIMITER

```sql
-- 没有 DELIMITER 时的问题：
CREATE PROCEDURE get_users()
BEGIN
    SELECT * FROM users;  -- 这里的分号让客户端以为语句结束了
    SELECT COUNT(*) FROM users;  -- 这行会作为独立语句发送，出错
END;

-- 客户端在读到第一个 ; 就尝试执行 CREATE PROCEDURE ... BEGIN SELECT * FROM users，
-- 这是不完整的语句，会报语法错误
```

---

## 正确使用方式

```sql
-- 第一步：将结束符改为 //
DELIMITER //

-- 第二步：定义存储过程（内部的 ; 不再触发提交）
CREATE PROCEDURE get_user_stats()
BEGIN
    SELECT COUNT(*) AS total_users FROM users;
    SELECT COUNT(*) AS active_users FROM users WHERE is_active = 1;
    SELECT DATE(MAX(created_at)) AS latest_register FROM users;
END //
-- 这里的 // 才是真正的语句结束符，客户端把完整的 CREATE PROCEDURE ... END 作为一个语句发送

-- 第三步：恢复分号为结束符
DELIMITER ;

-- 之后可以正常调用
CALL get_user_stats();
```

---

## 常见分隔符选择

```sql
-- 最常用的分隔符（避免与 SQL 语法冲突）
DELIMITER //      -- 最常见
DELIMITER $$      -- 也很常见
DELIMITER @@      -- 偶尔用
DELIMITER |       -- 不推荐（与 OR 操作符 || 混淆风险）
DELIMITER ;       -- 恢复默认

-- 注意：DELIMITER 命令和新分隔符之间需要有空格
-- DELIMITER//  -- 错误写法（无空格）
-- DELIMITER // -- 正确写法
```

---

## DELIMITER 只在命令行客户端中有效

```sql
-- DELIMITER 是 mysql 命令行客户端的特殊命令，不是 SQL 语言的一部分
-- 在以下工具中有效：
-- mysql 命令行客户端
-- MySQL Workbench（GUI 工具）
-- Navicat（GUI 工具）

-- 在以下环境中【无效】或不需要：
-- JDBC（Java）
-- pymysql / MySQLdb（Python）
-- node-mysql（Node.js）
-- 这些驱动可以直接发送完整的 CREATE PROCEDURE ... END; 语句，不需要 DELIMITER

-- PHP/PDO 示例（不需要 DELIMITER）：
-- $pdo->exec("CREATE PROCEDURE get_users() BEGIN SELECT * FROM users; END");
```

---

## 在 SQL 脚本文件中使用

```sql
-- 文件 deploy.sql
DELIMITER //

CREATE PROCEDURE sp_get_order(IN order_id INT)
BEGIN
    SELECT * FROM orders WHERE id = order_id;
END //

CREATE PROCEDURE sp_cancel_order(IN order_id INT)
BEGIN
    UPDATE orders SET status = 3 WHERE id = order_id;
END //

DELIMITER ;

-- 执行脚本文件：
-- mysql -u root -p mydb < deploy.sql
```

---

## 适用场景

- **定义存储过程**：多语句 BEGIN...END 块中需要 DELIMITER 保护内部分号
- **定义函数和触发器**：同样需要 DELIMITER（触发器体中有多条语句时）
- **批量 SQL 脚本部署**：在 `.sql` 文件中批量创建存储过程时，必须用 DELIMITER 包裹

---

## 常见问题

**在 Java JDBC 或 Python 中创建存储过程需要 DELIMITER 吗？**

不需要。程序语言的数据库驱动可以将完整的多行 SQL 作为一个字符串发送给 MySQL 服务器，MySQL 服务器端接受完整的 `CREATE PROCEDURE ... END` 语句，不需要 DELIMITER 来帮助客户端识别语句边界。DELIMITER 是 `mysql` 命令行客户端工具的功能，不属于 SQL 语言本身。

---

## 注意事项

- 使用完 DELIMITER 后，务必用 `DELIMITER ;` 恢复默认分隔符，否则后续所有语句都需要用新分隔符结尾，容易引起混乱。
- DELIMITER 不支持空格作为分隔符（`DELIMITER  ` 不合法），也不支持反斜线 `\`（有特殊含义）。

---

## 总结

`DELIMITER` 命令临时更改 MySQL 命令行客户端的语句结束符，使客户端能正确识别包含内部分号的多语句存储过程定义。标准用法是在创建存储过程前执行 `DELIMITER //`，定义完成后执行 `DELIMITER ;` 恢复。这是命令行客户端特有的机制，不适用于编程语言驱动（JDBC、pymysql 等）。
