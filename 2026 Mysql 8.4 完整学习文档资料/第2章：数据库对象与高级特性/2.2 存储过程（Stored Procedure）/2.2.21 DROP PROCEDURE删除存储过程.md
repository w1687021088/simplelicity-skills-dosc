# DROP PROCEDURE 删除存储过程

`DROP PROCEDURE` 语句从数据库中删除一个已存在的存储过程定义。删除存储过程不影响底层表的数据，但依赖该过程的其他过程在调用时会报错。MySQL 8.0 起支持 `IF EXISTS`，避免过程不存在时报错。

---

## 语法

```sql
DROP PROCEDURE [IF EXISTS] sp_name;
```

---

## 基本示例

```sql
-- 删除存储过程
DROP PROCEDURE sp_get_users;

-- IF EXISTS：过程不存在时不报错，只发出警告
DROP PROCEDURE IF EXISTS sp_get_users;
-- Query OK, 0 rows affected, 1 warning (0.00 sec)

-- 在部署脚本中的标准写法（先删后建）
DROP PROCEDURE IF EXISTS sp_process_orders;
DELIMITER //
CREATE PROCEDURE sp_process_orders()
BEGIN
    -- ...
END //
DELIMITER ;
```

---

## 查看存储过程后再删除

```sql
-- 确认存在后再删除
SELECT ROUTINE_NAME, CREATED, LAST_ALTERED
FROM information_schema.ROUTINES
WHERE ROUTINE_SCHEMA = DATABASE()
  AND ROUTINE_TYPE = 'PROCEDURE'
  AND ROUTINE_NAME = 'sp_process_orders';

-- 确认后删除
DROP PROCEDURE IF EXISTS sp_process_orders;
```

---

## 批量删除存储过程

```sql
-- 生成批量删除语句
SELECT CONCAT('DROP PROCEDURE IF EXISTS `', ROUTINE_NAME, '`;') AS drop_stmt
FROM information_schema.ROUTINES
WHERE ROUTINE_SCHEMA = 'mydb'
  AND ROUTINE_TYPE = 'PROCEDURE'
  AND ROUTINE_NAME LIKE 'sp_old_%';

-- 执行生成的语句删除所有以 sp_old_ 开头的过程
```

---

## 修改存储过程的常见模式

```sql
-- MySQL 不支持修改过程体（ALTER PROCEDURE 只能修改特性声明，不能改代码）
-- 要修改过程体，必须先 DROP 再重建

-- 正确做法：
DROP PROCEDURE IF EXISTS sp_get_user;
DELIMITER //
CREATE PROCEDURE sp_get_user(IN p_id INT)
BEGIN
    SELECT id, username, email, created_at FROM users WHERE id = p_id;
END //
DELIMITER ;

-- 错误认知：以为 ALTER PROCEDURE 可以改代码
-- ALTER PROCEDURE sp_get_user MODIFIES SQL DATA;  -- 只能改特性，不能改 BEGIN...END 里的内容
```

---

## DROP PROCEDURE vs ALTER PROCEDURE 对比

| 操作 | 用途 |
|------|------|
| `DROP PROCEDURE` | 完全删除存储过程定义 |
| `ALTER PROCEDURE` | 只能修改特性声明（COMMENT/安全性/数据访问类型），不能修改过程体 |
| `DROP + CREATE` | 实际上修改过程体的唯一方式 |

## 删除权限

```sql
-- 删除存储过程需要以下权限之一：
-- 1. ALTER ROUTINE 权限（在该数据库上）
-- 2. 是该过程的 DEFINER 用户

SHOW GRANTS FOR 'dev_user'@'%';
-- 如果缺少 ALTER ROUTINE 权限，执行 DROP PROCEDURE 会报 ERROR 1370 (42000)

-- 授予 ALTER ROUTINE 权限
GRANT ALTER ROUTINE ON mydb.* TO 'dev_user'@'%';
```

---

## 适用场景

- **数据库部署/更新**：更新存储过程前先删除旧版本（在 CI/CD 管道中）
- **清理废弃过程**：删除不再使用的老版本存储过程，减少数据库对象杂乱
- **开发重置**：在开发环境中快速重建存储过程（`DROP IF EXISTS` + `CREATE`）

---

## 常见问题

**删除存储过程会影响调用它的其他存储过程吗？**

不会立即报错，MySQL 存储过程采用运行时解析（不是编译时）。删除后，依赖它的存储过程的定义仍然保留，但在被调用时执行到 `CALL sp_deleted_proc()` 的语句时，会抛出运行时错误 `ERROR 1305: PROCEDURE does not exist`。

---

## 注意事项

- MySQL 没有"重命名存储过程"的语法，如果需要重命名，只能先 `DROP` 再用新名称 `CREATE`。
- 在生产环境执行 `DROP PROCEDURE` 前，确认该过程不在任何活跃事务或定时任务中被调用，避免正在执行的过程被删除引发运行错误。

---

## 总结

`DROP PROCEDURE [IF EXISTS] sp_name` 删除存储过程定义，不影响底层数据。`IF EXISTS` 避免过程不存在时的报错，推荐在脚本中始终使用。修改存储过程体（BEGIN...END 内的代码）必须先 DROP 再 CREATE，因为 ALTER PROCEDURE 只能修改特性声明，无法修改过程体代码。
