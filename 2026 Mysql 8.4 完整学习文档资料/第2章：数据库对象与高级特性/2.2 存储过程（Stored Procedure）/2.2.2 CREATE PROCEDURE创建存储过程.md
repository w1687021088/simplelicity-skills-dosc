# CREATE PROCEDURE 创建存储过程

存储过程是保存在数据库中的一组预编译 SQL 语句，可以通过名称调用执行。与在应用层拼接和发送 SQL 相比，存储过程减少网络往返、封装业务逻辑、支持参数传递和事务控制。MySQL 8.4 中存储过程支持 `IF NOT EXISTS` 子句，避免重复创建时报错。

---

## 语法

```sql
CREATE
    [DEFINER = user]
    PROCEDURE [IF NOT EXISTS] sp_name ([proc_parameter[,...]])
    [characteristic ...]
    routine_body

proc_parameter:
    [IN | OUT | INOUT] param_name type

characteristic:
    COMMENT 'string'
  | LANGUAGE SQL
  | [NOT] DETERMINISTIC
  | { CONTAINS SQL | NO SQL | READS SQL DATA | MODIFIES SQL DATA }
  | SQL SECURITY { DEFINER | INVOKER }

routine_body:
    有效的 SQL 语句或 BEGIN...END 块
```

---

## 基本示例

```sql
DELIMITER //

-- 最简单的存储过程（无参数）
CREATE PROCEDURE sp_hello()
BEGIN
    SELECT 'Hello, MySQL 8.4!' AS greeting;
END //

-- 含注释和特性描述的存储过程
CREATE PROCEDURE sp_get_active_users()
COMMENT '获取所有活跃用户列表'
READS SQL DATA
BEGIN
    SELECT id, username, email, created_at
    FROM users
    WHERE is_active = 1
    ORDER BY created_at DESC;
END //

DELIMITER ;

-- 调用存储过程
CALL sp_hello();
CALL sp_get_active_users();
```

## IF NOT EXISTS（MySQL 8.4 新增）

```sql
DELIMITER //

-- MySQL 8.4 支持 IF NOT EXISTS，存储过程已存在时不报错
CREATE PROCEDURE IF NOT EXISTS sp_get_users()
BEGIN
    SELECT * FROM users;
END //

DELIMITER ;
-- 若 sp_get_users 已存在：不报错，发出警告，保留原有定义
-- 若不存在：创建新存储过程
```

## 存储过程的特性声明

```sql
DELIMITER //

CREATE PROCEDURE sp_process_order(IN order_id INT)
COMMENT '处理订单：更新状态并写入日志'
MODIFIES SQL DATA        -- 声明过程会修改数据（影响复制行为）
SQL SECURITY DEFINER     -- 以创建者的权限执行
BEGIN
    DECLARE v_status INT;
    
    -- 获取当前状态
    SELECT status INTO v_status FROM orders WHERE id = order_id;
    
    -- 根据状态处理
    IF v_status = 1 THEN
        UPDATE orders SET status = 2, processed_at = NOW() WHERE id = order_id;
        INSERT INTO order_logs (order_id, action, created_at)
        VALUES (order_id, 'processed', NOW());
    END IF;
END //

DELIMITER ;
```

---

## 特性声明对比

| 特性 | 含义 |
|------|------|
| `CONTAINS SQL` | 过程包含 SQL，但不读写数据（默认）|
| `NO SQL` | 过程不包含 SQL 语句 |
| `READS SQL DATA` | 过程只读取数据（SELECT）|
| `MODIFIES SQL DATA` | 过程修改数据（INSERT/UPDATE/DELETE）|
| `[NOT] DETERMINISTIC` | 相同输入是否总返回相同结果（影响二进制日志）|
| `SQL SECURITY DEFINER` | 以创建者权限执行（默认）|
| `SQL SECURITY INVOKER` | 以调用者权限执行 |

## 查看存储过程

```sql
-- 列出当前数据库的所有存储过程
SHOW PROCEDURE STATUS WHERE Db = DATABASE();

-- 查看存储过程定义
SHOW CREATE PROCEDURE sp_get_active_users\G

-- 从 information_schema 查询
SELECT ROUTINE_NAME, ROUTINE_TYPE, CREATED, LAST_ALTERED,
       ROUTINE_COMMENT, SECURITY_TYPE, SQL_DATA_ACCESS
FROM information_schema.ROUTINES
WHERE ROUTINE_SCHEMA = DATABASE()
  AND ROUTINE_TYPE = 'PROCEDURE';
```

## 在事务中使用存储过程

```sql
DELIMITER //

CREATE PROCEDURE sp_transfer_funds(
    IN from_account INT,
    IN to_account   INT,
    IN amount       DECIMAL(10,2)
)
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        RESIGNAL;  -- 重新抛出异常给调用者
    END;
    
    START TRANSACTION;
    
    UPDATE accounts SET balance = balance - amount WHERE id = from_account;
    UPDATE accounts SET balance = balance + amount WHERE id = to_account;
    
    COMMIT;
END //

DELIMITER ;

-- 调用
CALL sp_transfer_funds(1, 2, 500.00);
```

## 适用场景

- **封装复杂业务逻辑**：多步骤操作（下单→扣库存→写日志→发通知）封装为一个存储过程
- **减少网络往返**：将多条 SQL 操作整合为一次 CALL，减少客户端与服务器之间的交互
- **权限控制**：通过 DEFINER 安全上下文，让没有底层表权限的用户执行特定操作
- **代码复用**：多个应用或不同语言的客户端共享同一套数据库处理逻辑

## 常见问题

**存储过程能返回结果集吗？**

可以。存储过程中的 `SELECT` 语句会将结果集直接发送给客户端（和普通 SELECT 一样）。一个存储过程可以包含多个 `SELECT`，客户端会收到多个结果集。但函数（`CREATE FUNCTION`）不能返回结果集，只能通过 `RETURN` 返回单个值。

---

## 注意事项

- 存储过程的调试比普通 SQL 难，MySQL 没有内置的存储过程调试器（需借助第三方工具如 MySQL Workbench 的调试功能）。生产环境中复杂存储过程建议添加详细的注释和日志表。
- 修改存储过程必须用 `DROP PROCEDURE` 后再 `CREATE PROCEDURE`，MySQL 不支持 `ALTER PROCEDURE` 修改过程体（只能改特性声明不能改过程体）。

---

## 总结

`CREATE PROCEDURE sp_name([params]) BEGIN ... END` 创建存储过程。MySQL 8.4 新增 `IF NOT EXISTS` 防止重复创建报错。存储过程可以通过 `CALL` 调用，可包含参数（IN/OUT/INOUT）、局部变量、条件判断、循环、游标和事务控制。特性声明（`READS SQL DATA` / `MODIFIES SQL DATA` / `DETERMINISTIC`）影响二进制日志和复制行为，建议根据实际情况准确声明。
