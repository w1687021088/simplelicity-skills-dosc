# IN 参数传递

`IN` 是存储过程参数的默认方向，表示调用者将值传入存储过程，过程内部可以读取该值，但对该参数的任何修改不会影响外部调用者的变量。`IN` 参数相当于按值传递（pass by value）。

---

## 语法

```sql
CREATE PROCEDURE sp_name(IN param_name data_type)
BEGIN
    -- param_name 可以在这里读取，但修改不影响外部
END;
```

不写方向关键字时，默认就是 `IN`：

```sql
-- 以下两种写法等价
CREATE PROCEDURE sp_demo(IN user_id INT)  ...
CREATE PROCEDURE sp_demo(user_id INT)     ...  -- 默认 IN
```

---

## 基本示例

```sql
DELIMITER //

-- 按 ID 查询用户
CREATE PROCEDURE sp_get_user(IN p_user_id INT)
BEGIN
    SELECT id, username, email, created_at
    FROM users
    WHERE id = p_user_id;
END //

-- 按状态和时间范围查询订单
CREATE PROCEDURE sp_get_orders_by_status(
    IN p_status     INT,
    IN p_start_date DATE,
    IN p_end_date   DATE
)
BEGIN
    SELECT id, user_id, amount, status, created_at
    FROM orders
    WHERE status = p_status
      AND DATE(created_at) BETWEEN p_start_date AND p_end_date
    ORDER BY created_at DESC;
END //

DELIMITER ;

-- 调用
CALL sp_get_user(5);
CALL sp_get_orders_by_status(2, '2026-03-01', '2026-03-31');
```

## IN 参数不影响外部变量

```sql
DELIMITER //

CREATE PROCEDURE sp_double(IN p_num INT)
BEGIN
    SET p_num = p_num * 2;  -- 修改 IN 参数（只在过程内有效）
    SELECT p_num AS result_inside;  -- 显示 20
END //

DELIMITER ;

-- 调用
SET @my_num = 10;
CALL sp_double(@my_num);          -- 过程内显示 20
SELECT @my_num;                    -- 结果仍是 10（未受影响）
-- IN 参数是值传递，内部修改不会传回外部
```

## 在过程内使用 IN 参数

```sql
DELIMITER //

CREATE PROCEDURE sp_batch_update_status(
    IN p_dept_id INT,
    IN p_new_status TINYINT
)
BEGIN
    -- IN 参数可以出现在 SQL 语句的任何位置
    UPDATE employees
    SET status = p_new_status
    WHERE dept_id = p_dept_id;
    
    -- 也可以用于条件判断
    IF p_new_status = 0 THEN
        INSERT INTO audit_log (action, target, created_at)
        VALUES (CONCAT('deactivate dept ', p_dept_id), 'employees', NOW());
    END IF;
    
    SELECT ROW_COUNT() AS affected_rows;
END //

DELIMITER ;

CALL sp_batch_update_status(3, 0);
```

## IN 参数接受 NULL

```sql
DELIMITER //

CREATE PROCEDURE sp_search_users(
    IN p_username VARCHAR(100),
    IN p_status   TINYINT
)
BEGIN
    SELECT * FROM users
    WHERE (p_username IS NULL OR username LIKE CONCAT('%', p_username, '%'))
      AND (p_status IS NULL OR is_active = p_status);
    -- 利用 NULL 表示"不过滤该条件"，实现可选过滤参数
END //

DELIMITER ;

-- 只按用户名搜索，不限状态
CALL sp_search_users('alice', NULL);
-- 只按状态过滤，不限用户名
CALL sp_search_users(NULL, 1);
-- 同时过滤两个条件
CALL sp_search_users('alice', 1);
```

## 适用场景

- **查询条件传入**：将 WHERE 条件的值通过 IN 参数传递（用户 ID、状态码、日期范围等）
- **操作目标指定**：通过 IN 参数指定要操作的记录（批量更新某部门的数据）
- **可选过滤参数**：传入 NULL 表示该过滤条件不生效，实现灵活的动态查询

---

## 常见问题

**IN 参数有长度限制吗？**

IN 参数的数据类型遵循 MySQL 的普通类型限制（如 VARCHAR 最大 65535 字节，TEXT 型不能直接用作存储过程参数类型）。传递大文本时需要注意参数类型的选择。

---

## 注意事项

- 调用存储过程时，实参数量和类型必须与定义匹配。MySQL 会做隐式类型转换，但类型不兼容时会报错或产生意外结果。
- IN 参数命名建议加前缀（如 `p_` 或 `in_`）与局部变量和列名区分，避免因同名导致的歧义（过程体中 SQL 引用同名的列时，参数和列名可能混淆）。

---

## 总结

`IN` 参数是存储过程的输入参数，调用者将值传入，过程内可读取但无法将修改反馈给调用者（按值传递）。不写方向关键字时默认是 `IN`。支持 NULL 值，常用于实现可选过滤条件。命名时建议使用统一前缀避免与列名冲突。
