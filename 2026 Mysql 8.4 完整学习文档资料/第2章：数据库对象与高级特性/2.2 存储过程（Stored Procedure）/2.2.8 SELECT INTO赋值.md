# SELECT ... INTO 赋值

`SELECT ... INTO` 是存储过程中从查询结果给变量赋值的标准方式。它执行一个 SELECT 查询，并将查询结果的列值依次赋给指定的变量，要求查询结果**恰好返回一行**。

---

## 语法

```sql
SELECT col1 [, col2 ...]
INTO var1 [, var2 ...]
FROM table_name
[WHERE ...];
```

---

## 基本示例

```sql
DELIMITER //

CREATE PROCEDURE sp_get_user_info(IN p_user_id INT)
BEGIN
    DECLARE v_username  VARCHAR(100);
    DECLARE v_email     VARCHAR(255);
    DECLARE v_is_active TINYINT;
    
    -- 将查询结果赋值给多个局部变量
    SELECT username, email, is_active
    INTO v_username, v_email, v_is_active
    FROM users
    WHERE id = p_user_id;
    
    SELECT v_username AS username,
           v_email    AS email,
           v_is_active AS is_active;
END //

DELIMITER ;

CALL sp_get_user_info(5);
```

## 结合聚合函数

```sql
DELIMITER //

CREATE PROCEDURE sp_dept_salary(IN p_dept_id INT)
BEGIN
    DECLARE v_total   DECIMAL(12,2);
    DECLARE v_avg     DECIMAL(10,2);
    DECLARE v_count   INT;
    
    -- 聚合查询结果赋值（聚合结果永远是一行，安全）
    SELECT COUNT(*), SUM(salary), ROUND(AVG(salary), 2)
    INTO v_count, v_total, v_avg
    FROM employees
    WHERE dept_id = p_dept_id;
    
    SELECT p_dept_id AS dept_id, v_count AS emp_count,
           v_total AS total_salary, v_avg AS avg_salary;
END //

DELIMITER ;
```

## 零行与多行的处理

```sql
DELIMITER //

CREATE PROCEDURE sp_safe_get_user(IN p_user_id INT)
BEGIN
    DECLARE v_name   VARCHAR(100);
    DECLARE v_found  TINYINT DEFAULT 0;
    
    -- 处理零行情况（NOT FOUND 条件处理程序）
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_found = 0;
    SET v_found = 1;  -- 假设能找到
    
    SELECT username INTO v_name FROM users WHERE id = p_user_id;
    -- 如果没有匹配行：触发 NOT FOUND 处理程序，v_found = 0，v_name 保持原值（不变）
    -- 如果有一行：v_name 被赋值，v_found = 1
    -- 如果有多行：报错 ERROR 1172: Result consisted of more than one row
    
    IF v_found = 1 THEN
        SELECT v_name AS found_user;
    ELSE
        SELECT '用户不存在' AS message;
    END IF;
END //

DELIMITER ;
```

## 多行情况的处理

```sql
-- SELECT INTO 要求结果恰好一行
-- 如果查询可能返回多行，需要加 LIMIT 1 或用聚合

DELIMITER //

CREATE PROCEDURE sp_get_latest_order(IN p_user_id INT)
BEGIN
    DECLARE v_order_id INT;
    DECLARE v_amount   DECIMAL(10,2);
    
    -- 可能有多个订单，用 LIMIT 1 确保只返回一行
    SELECT id, amount
    INTO v_order_id, v_amount
    FROM orders
    WHERE user_id = p_user_id
    ORDER BY created_at DESC
    LIMIT 1;
    
    IF v_order_id IS NOT NULL THEN
        SELECT v_order_id, v_amount;
    ELSE
        SELECT '无订单记录' AS message;
    END IF;
END //

DELIMITER ;
```

## SELECT INTO 与 INTO OUTFILE 的区别

```sql
-- SELECT INTO var：给变量赋值（存储过程内使用）
SELECT username INTO v_name FROM users WHERE id = 1;

-- SELECT INTO OUTFILE：将查询结果写入服务器端文件（不是给变量赋值）
SELECT * FROM users INTO OUTFILE '/tmp/users_export.csv'
FIELDS TERMINATED BY ',' LINES TERMINATED BY '\n';
```

## 适用场景

- **按主键查单行数据**：根据 ID 查用户/订单的详细信息并赋给多个变量
- **聚合计算结果**：COUNT、SUM、AVG 等聚合查询结果赋给变量
- **获取最新记录**：配合 ORDER BY ... LIMIT 1 获取最新/最大值记录

---

## 常见问题

**SELECT INTO 查到多行会怎样？**

会报 `ERROR 1172 (42000): Result consisted of more than one row`。必须确保查询只返回一行：加 `LIMIT 1`、使用聚合函数、或通过主键/唯一键查询。

**查询结果为零行会怎样？**

`v_name` 变量保持原来的值（不会被清空），同时触发 `NOT FOUND` 条件（SQLSTATE '02000'）。如果没有相应的 HANDLER，语句会静默继续（变量值不确定），因此重要场景应添加 `DECLARE CONTINUE HANDLER FOR NOT FOUND` 来明确处理。

---

## 注意事项

- `INTO` 子句中变量的数量和顺序必须与 `SELECT` 列表中的列数量和顺序完全对应，否则报错。
- 对于关键业务逻辑中的 `SELECT INTO`，建议总是添加 NOT FOUND 处理程序，并在处理程序中设置标志变量，在后续逻辑中明确检查是否查到了数据。

---

## 总结

`SELECT col1, col2 INTO var1, var2 FROM table WHERE ...` 将查询结果赋值给局部变量，要求查询恰好返回一行。零行时变量值不变并触发 NOT FOUND 条件，多行时直接报错。聚合函数（COUNT/SUM/AVG）的查询天然只返回一行，是安全的 SELECT INTO 场景。可能返回多行时要加 LIMIT 1 或用聚合保证单行结果。
