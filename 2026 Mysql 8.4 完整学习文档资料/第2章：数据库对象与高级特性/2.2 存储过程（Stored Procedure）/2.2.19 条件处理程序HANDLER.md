# 条件处理程序 HANDLER

`DECLARE ... HANDLER` 是存储过程中的异常处理机制，相当于其他语言的 try-catch。当 SQL 语句触发特定条件（错误码、SQLSTATE、命名条件）时，HANDLER 捕获并处理它，决定过程是继续执行（CONTINUE）还是退出（EXIT）。

---

## 语法

```sql
DECLARE handler_type HANDLER FOR condition_value [, condition_value ...]
    statement;

handler_type:
    CONTINUE   -- 执行处理语句后，继续执行触发条件的语句的下一条
  | EXIT       -- 执行处理语句后，退出当前 BEGIN...END 块

condition_value:
    SQLSTATE [VALUE] sqlstate_value   -- 5位 SQLSTATE 值
  | condition_name                    -- 用 DECLARE CONDITION 定义的命名条件
  | SQLWARNING                        -- 所有以 '01' 开头的 SQLSTATE
  | NOT FOUND                         -- 所有以 '02' 开头的 SQLSTATE（如游标到末尾）
  | SQLEXCEPTION                      -- 所有非 '00'/'01'/'02' 的 SQLSTATE（运行时错误）
  | mysql_error_code                  -- MySQL 特定错误号（整数）
```

---

## 常用 HANDLER 模式

```sql
DELIMITER //

CREATE PROCEDURE sp_handler_demo()
BEGIN
    -- 1. NOT FOUND：游标末尾、SELECT INTO 无结果
    DECLARE v_done   TINYINT DEFAULT FALSE;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    -- 2. SQLEXCEPTION：捕获所有运行时错误
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SELECT '发生错误，事务已回滚' AS error_message;
    END;
    
    -- 3. 特定 MySQL 错误号：1062 = 唯一键冲突
    DECLARE CONTINUE HANDLER FOR 1062
    BEGIN
        SELECT '检测到重复记录，已跳过' AS warning_message;
    END;
    
    -- 4. 特定 SQLSTATE：'23000' = 完整性约束违反（包含 1062）
    DECLARE CONTINUE HANDLER FOR SQLSTATE '23000'
    BEGIN
        SELECT '约束违反' AS msg;
    END;
END //

DELIMITER ;
```

## CONTINUE vs EXIT HANDLER

```sql
DELIMITER //

-- CONTINUE HANDLER：处理后继续执行下一条语句
CREATE PROCEDURE sp_continue_handler()
BEGIN
    DECLARE CONTINUE HANDLER FOR 1062
        SELECT '重复记录，跳过' AS msg;
    
    INSERT INTO users (id, username) VALUES (1, 'alice');  -- 假设 id=1 已存在，触发 1062
    -- HANDLER 处理（输出消息）后，继续执行下面的语句
    INSERT INTO users (id, username) VALUES (2, 'bob');    -- 继续执行，成功插入
    SELECT '两条 INSERT 都尝试完毕' AS result;
END //

-- EXIT HANDLER：处理后退出当前 BEGIN...END 块
CREATE PROCEDURE sp_exit_handler()
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SELECT '错误退出，已回滚' AS result;
    END;
    
    START TRANSACTION;
    INSERT INTO users (id, username) VALUES (1, 'alice');  -- 触发错误
    -- EXIT HANDLER 执行后，退出 BEGIN...END 块
    -- 下面的 COMMIT 不会执行
    COMMIT;
END //

DELIMITER ;
```

## 事务中的错误处理（最佳实践）

```sql
DELIMITER //

CREATE PROCEDURE sp_transaction_with_handler(
    IN  p_from_id  INT,
    IN  p_to_id    INT,
    IN  p_amount   DECIMAL(10,2),
    OUT p_result   VARCHAR(100)
)
BEGIN
    DECLARE v_error TINYINT DEFAULT 0;
    
    -- 错误时设置标志位，但不立即退出（CONTINUE）
    DECLARE CONTINUE HANDLER FOR SQLEXCEPTION SET v_error = 1;
    
    START TRANSACTION;
    
    UPDATE accounts SET balance = balance - p_amount WHERE id = p_from_id;
    UPDATE accounts SET balance = balance + p_amount WHERE id = p_to_id;
    
    IF v_error = 1 THEN
        ROLLBACK;
        SET p_result = '转账失败：数据库错误';
    ELSE
        COMMIT;
        SET p_result = '转账成功';
    END IF;
END //

DELIMITER ;
```

## 命名条件（DECLARE CONDITION）

```sql
DELIMITER //

CREATE PROCEDURE sp_named_condition()
BEGIN
    -- 给错误码起一个有意义的名字
    DECLARE duplicate_key CONDITION FOR 1062;
    DECLARE foreign_key_fail CONDITION FOR 1452;
    
    DECLARE CONTINUE HANDLER FOR duplicate_key
        SELECT '主键或唯一键冲突' AS error;
    
    DECLARE CONTINUE HANDLER FOR foreign_key_fail
        SELECT '外键约束违反' AS error;
    
    INSERT INTO categories (id, name) VALUES (1, 'Tech');    -- 可能触发 1062
    INSERT INTO products (category_id, name) VALUES (999, 'Widget'); -- 可能触发 1452
END //

DELIMITER ;
```

## 常见 SQLSTATE 和错误码对照

| 错误码 | SQLSTATE | 含义 |
|--------|---------|------|
| 1062 | 23000 | 唯一键/主键重复 |
| 1048 | 23000 | 列不能为 NULL |
| 1452 | 23000 | 外键约束违反 |
| 1264 | 22003 | 数值超出范围 |
| 1292 | 22007 | 日期格式错误 |
| NOT FOUND | 02000 | 游标末尾/无结果行 |

---

## 适用场景

- **游标遍历**：`DECLARE CONTINUE HANDLER FOR NOT FOUND` 检测游标末尾
- **事务错误回滚**：`DECLARE EXIT HANDLER FOR SQLEXCEPTION` 捕获错误并 ROLLBACK
- **批量操作跳过错误**：`DECLARE CONTINUE HANDLER FOR 1062` 忽略重复记录继续处理
- **精细化错误信息**：针对不同错误码返回不同提示信息

---

## 常见问题

**CONTINUE HANDLER 和 EXIT HANDLER 能同时声明吗？**

可以，但如果同一条件同时有 CONTINUE 和 EXIT HANDLER，MySQL 优先使用更具体（更靠近触发位置）的那个。一般不建议对同一条件声明两个 HANDLER，容易造成行为混乱。

---

## 注意事项

- HANDLER 声明必须在游标声明之后、其他可执行语句之前（DECLARE 顺序：变量 → 游标 → 条件 CONDITION → HANDLER）。
- EXIT HANDLER 退出的是声明该 HANDLER 的 `BEGIN...END` 块，不是整个存储过程。如需退出整个过程，HANDLER 应声明在最外层的 BEGIN...END 中，或配合 LEAVE 标签实现。

---

## 总结

`DECLARE {CONTINUE|EXIT} HANDLER FOR condition statement` 是 MySQL 存储过程的异常处理机制。CONTINUE 处理后继续执行，EXIT 处理后退出当前块。常用条件有 NOT FOUND（游标末尾/无结果）、SQLEXCEPTION（运行时错误）、特定错误码（如 1062 唯一键冲突）。在事务存储过程中配合 ROLLBACK 使用是保证数据一致性的标准模式。
