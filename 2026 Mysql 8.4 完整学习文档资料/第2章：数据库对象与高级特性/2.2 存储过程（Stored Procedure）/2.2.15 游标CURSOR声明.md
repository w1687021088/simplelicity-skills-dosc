# 游标 CURSOR 声明

游标（Cursor）是一个数据库对象，允许在存储过程中逐行处理 SELECT 查询的结果集。当业务逻辑需要对查询结果中的每一行做独立处理（如每行调用不同的函数、写入不同的目标）时，游标是解决方案。MySQL 中的游标是只读的、不可滚动的（只能向前遍历）。

---

## 语法

```sql
DECLARE cursor_name CURSOR FOR select_statement;
```

- `cursor_name`：游标名称
- `select_statement`：定义游标数据集的 SELECT 语句（此时不执行，只是定义）
- 游标声明必须在局部变量声明之后、HANDLER 声明之前

---

## 声明顺序规则

```sql
DELIMITER //

CREATE PROCEDURE sp_cursor_demo()
BEGIN
    -- 第1步：声明局部变量
    DECLARE v_user_id   INT;
    DECLARE v_username  VARCHAR(100);
    DECLARE v_done      TINYINT DEFAULT FALSE;
    
    -- 第2步：声明游标（在变量之后）
    DECLARE user_cursor CURSOR FOR
        SELECT id, username FROM users WHERE is_active = 1;
    
    -- 第3步：声明处理程序（在游标之后）
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    -- 第4步：后续使用游标的逻辑（OPEN/FETCH/CLOSE）
    OPEN user_cursor;
    -- ...
    CLOSE user_cursor;
END //

DELIMITER ;
```

## 游标的数据快照特性

```sql
DELIMITER //

CREATE PROCEDURE sp_cursor_snapshot_demo()
BEGIN
    DECLARE v_id    INT;
    DECLARE v_name  VARCHAR(100);
    DECLARE v_done  TINYINT DEFAULT FALSE;
    
    -- 游标的 SELECT 在 OPEN 时执行，产生数据快照
    -- 此后对底层表的修改不影响游标已经打开的数据集
    DECLARE cur CURSOR FOR
        SELECT id, username FROM users WHERE is_active = 1
        ORDER BY id;
    
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    OPEN cur;   -- 此时执行 SELECT，数据集固定
    
    fetch_loop: LOOP
        FETCH cur INTO v_id, v_name;
        IF v_done THEN LEAVE fetch_loop; END IF;
        
        -- 即使在循环中修改 users 表，游标数据集也不变
        UPDATE users SET last_processed = NOW() WHERE id = v_id;
        
    END LOOP;
    
    CLOSE cur;
END //

DELIMITER ;
```

## 带参数的游标（使用过程参数或变量）

```sql
DELIMITER //

-- 游标的 SELECT 语句可以引用过程的参数（IN 参数）或已声明的局部变量
CREATE PROCEDURE sp_dept_user_cursor(IN p_dept_id INT)
BEGIN
    DECLARE v_user_id   INT;
    DECLARE v_username  VARCHAR(100);
    DECLARE v_done      TINYINT DEFAULT FALSE;
    
    -- 游标 SELECT 引用了 IN 参数 p_dept_id
    DECLARE dept_cursor CURSOR FOR
        SELECT id, username 
        FROM users 
        WHERE dept_id = p_dept_id AND is_active = 1
        ORDER BY username;
    
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    OPEN dept_cursor;
    
    read_loop: LOOP
        FETCH dept_cursor INTO v_user_id, v_username;
        IF v_done THEN LEAVE read_loop; END IF;
        SELECT v_user_id, v_username;
    END LOOP read_loop;
    
    CLOSE dept_cursor;
END //

DELIMITER ;
```

## 多游标同时使用

```sql
DELIMITER //

-- 同时使用两个游标（需要分别使用不同的 NOT FOUND 处理）
CREATE PROCEDURE sp_two_cursors()
BEGIN
    DECLARE v_id1   INT;
    DECLARE v_id2   INT;
    DECLARE v_done1 TINYINT DEFAULT FALSE;
    DECLARE v_done2 TINYINT DEFAULT FALSE;
    
    DECLARE cur1 CURSOR FOR SELECT id FROM table1;
    DECLARE cur2 CURSOR FOR SELECT id FROM table2;
    
    -- 注意：两个游标共用 NOT FOUND 处理程序很复杂
    -- 建议分别在嵌套 BEGIN...END 块中使用不同的 HANDLER
    
    BEGIN
        DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done1 = TRUE;
        OPEN cur1;
        loop1: LOOP
            FETCH cur1 INTO v_id1;
            IF v_done1 THEN LEAVE loop1; END IF;
            -- 处理 v_id1
        END LOOP loop1;
        CLOSE cur1;
    END;
    
    BEGIN
        DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done2 = TRUE;
        OPEN cur2;
        loop2: LOOP
            FETCH cur2 INTO v_id2;
            IF v_done2 THEN LEAVE loop2; END IF;
            -- 处理 v_id2
        END LOOP loop2;
        CLOSE cur2;
    END;
END //

DELIMITER ;
```

## 适用场景

- **逐行处理复杂业务逻辑**：每行数据需要执行复杂的条件判断、调用其他过程
- **跨表数据同步**：遍历源表每行数据，按行写入目标表（需要行级别的计算）
- **批量数据转换**：需要为每行生成特定格式的数据（如生成唯一编号）

---

## 常见问题

**游标能修改底层表的数据吗？**

MySQL 游标是只读的，不支持 `UPDATE ... WHERE CURRENT OF cursor` 语法（PostgreSQL 支持）。如果需要修改游标指向的行，可以在 FETCH 后记录主键，然后用独立的 UPDATE 语句按主键修改。

---

## 注意事项

- 游标声明顺序固定：**局部变量 → 游标声明 → HANDLER 声明**，顺序错误会报语法错误。
- MySQL 游标不可滚动（Forward Only），只能从第一行向最后一行单向遍历，不能后退或跳转到任意行。
- 游标数据量大时，FETCH 逐行处理性能远不如基于集合的 SQL 操作（如 UPDATE ... JOIN），非必要不使用游标，优先用集合操作。

---

## 总结

`DECLARE cursor_name CURSOR FOR select_statement` 声明游标，定义数据集但不执行查询。游标声明必须放在局部变量之后、HANDLER 之前。MySQL 游标是只读、不可滚动的，只能向前逐行读取。游标打开（OPEN）时才真正执行查询并产生数据快照，此后底层表变化不影响已打开的游标。游标性能不及集合操作，应优先用集合操作，仅在需要逐行独立处理时使用游标。
