# REPEAT 循环结构

`REPEAT` 是存储过程中的后置条件循环，先执行循环体，再检查退出条件。与 `WHILE`（先检查后执行）不同，`REPEAT` 的循环体至少执行一次，即使条件一开始就满足。当退出条件为 TRUE 时停止循环（注意：是满足条件时退出，与 WHILE 相反）。

---

## 语法

```sql
[label:] REPEAT
    statements;
UNTIL condition
END REPEAT [label];
```

- 先执行 `statements`，然后检查 `UNTIL condition`
- 条件为 **TRUE** 时**退出**（与 WHILE 相反：WHILE 是条件为 TRUE 时继续）
- 循环体至少执行一次

---

## 基本示例

```sql
DELIMITER //

-- 简单计数（至少执行一次）
CREATE PROCEDURE sp_repeat_demo(IN p_limit INT)
BEGIN
    DECLARE v_i   INT DEFAULT 1;
    DECLARE v_sum INT DEFAULT 0;
    
    REPEAT
        SET v_sum = v_sum + v_i;
        SET v_i   = v_i + 1;
    UNTIL v_i > p_limit
    END REPEAT;
    
    SELECT p_limit AS limit_val, v_sum AS sum_result;
END //

DELIMITER ;

CALL sp_repeat_demo(5);   -- sum = 15 (1+2+3+4+5)
CALL sp_repeat_demo(0);   -- v_i 从 1 开始，第一次执行后 v_i=2，2 > 0 为 TRUE，退出
                           -- sum = 1（至少执行一次）
```

## 与 WHILE 的行为对比

```sql
DELIMITER //

-- WHILE：p_limit = 0 时，一次都不执行
CREATE PROCEDURE sp_while_zero(IN p_limit INT)
BEGIN
    DECLARE v_i INT DEFAULT 1;
    DECLARE v_sum INT DEFAULT 0;
    
    WHILE v_i <= p_limit DO
        SET v_sum = v_sum + v_i;
        SET v_i = v_i + 1;
    END WHILE;
    
    SELECT 'WHILE', p_limit, v_sum;
END //

-- REPEAT：p_limit = 0 时，执行一次后退出（v_sum = 1）
CREATE PROCEDURE sp_repeat_zero(IN p_limit INT)
BEGIN
    DECLARE v_i INT DEFAULT 1;
    DECLARE v_sum INT DEFAULT 0;
    
    REPEAT
        SET v_sum = v_sum + v_i;
        SET v_i = v_i + 1;
    UNTIL v_i > p_limit
    END REPEAT;
    
    SELECT 'REPEAT', p_limit, v_sum;
END //

DELIMITER ;

CALL sp_while_zero(0);    -- v_sum = 0（一次未执行）
CALL sp_repeat_zero(0);   -- v_sum = 1（执行了一次）
```

## 实际业务应用：重试逻辑

```sql
DELIMITER //

-- 带重试的操作（如获取分布式锁）
CREATE PROCEDURE sp_acquire_lock_with_retry(
    IN  p_resource_key VARCHAR(100),
    IN  p_max_retries  INT,
    OUT p_success      TINYINT
)
BEGIN
    DECLARE v_retry INT DEFAULT 0;
    DECLARE v_lock  TINYINT DEFAULT 0;
    SET p_success = 0;
    
    REPEAT
        -- 尝试获取锁（INSERT IGNORE 插入成功说明获取锁成功）
        INSERT IGNORE INTO resource_locks (resource_key, locked_at, expires_at)
        VALUES (p_resource_key, NOW(), NOW() + INTERVAL 30 SECOND);
        
        IF ROW_COUNT() > 0 THEN
            SET v_lock = 1;    -- 获取成功
            SET p_success = 1;
        ELSE
            SET v_retry = v_retry + 1;
            DO SLEEP(0.5);     -- 等待 500ms 后重试
        END IF;
        
    UNTIL v_lock = 1 OR v_retry >= p_max_retries
    END REPEAT;
END //

DELIMITER ;
```

## WHILE vs REPEAT vs LOOP 对比

| 循环类型 | 条件检查时机 | 最少执行次数 | 条件语义 |
|---------|------------|------------|---------|
| WHILE | 循环前检查 | 0 次 | 条件为 TRUE 继续 |
| REPEAT | 循环后检查 | 1 次 | 条件为 TRUE 退出 |
| LOOP | 无自动条件 | 1 次（需 LEAVE 退出）| 靠 LEAVE 手动退出 |

---

## 适用场景

- **至少执行一次的操作**：用户交互提示（至少提示一次）、初始化操作
- **重试逻辑**：操作失败时重试，成功或达到最大重试次数退出
- **先执行后验证**：先产生一个结果，然后检查结果是否满足要求（类似 do-while）

---

## 常见问题

**REPEAT 的 UNTIL 条件可以用 NULL 吗？**

NULL 在 MySQL 中被视为 FALSE（不是 TRUE），所以 `UNTIL NULL` 不会退出循环，相当于无限循环，必须确保 UNTIL 条件最终会变为 TRUE（非 NULL 非 0）。

---

## 注意事项

- `UNTIL` 关键字后的条件中，不能直接声明变量（DECLARE 只能在 BEGIN 块顶部）。退出条件用到的变量必须在 BEGIN 块顶部已声明。
- REPEAT 循环体至少执行一次的特性，使其不适合那些"条件一开始就可能不满足，应该一次都不执行"的场景，这种情况应用 WHILE。

---

## 总结

`REPEAT ... UNTIL condition END REPEAT` 是后置条件循环，先执行循环体再检查退出条件，保证至少执行一次。`UNTIL condition` 中条件为 TRUE 时**退出**（注意与 WHILE 的语义相反）。适用于重试逻辑、至少执行一次的场景。与 WHILE 的核心区别：WHILE 条件 TRUE 时继续，REPEAT UNTIL 条件 TRUE 时停止。
