# 游标 FETCH 提取数据

`FETCH` 从已打开的游标中读取当前行的数据，并将各列值依次赋给指定变量，同时将游标指针向后移动一行。每次 FETCH 只读取一行，通常放在循环中逐行处理所有数据。当所有行读完后，再次 FETCH 会触发 `NOT FOUND` 条件。

---

## 语法

```sql
FETCH [[NEXT] FROM] cursor_name INTO var_name [, var_name ...];
```

- `NEXT FROM` 是可选的（符合 SQL 标准的写法），MySQL 默认就是读取下一行
- `var_name` 的数量和顺序必须与游标定义中的 SELECT 列完全匹配

---

## 标准游标遍历模式

```sql
DELIMITER //

CREATE PROCEDURE sp_fetch_demo()
BEGIN
    DECLARE v_id       INT;
    DECLARE v_username VARCHAR(100);
    DECLARE v_email    VARCHAR(255);
    DECLARE v_done     TINYINT DEFAULT FALSE;
    
    -- 游标定义：SELECT 3 列
    DECLARE user_cur CURSOR FOR
        SELECT id, username, email FROM users WHERE is_active = 1;
    
    -- NOT FOUND 处理程序（FETCH 超出末行时触发）
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    OPEN user_cur;
    
    read_loop: LOOP
        -- FETCH：读取一行，3 个列依次赋给 3 个变量
        FETCH user_cur INTO v_id, v_username, v_email;
        
        -- 检查是否已到末行
        IF v_done THEN
            LEAVE read_loop;
        END IF;
        
        -- 处理当前行的数据
        INSERT INTO user_audit(user_id, username, checked_at)
        VALUES (v_id, v_username, NOW());
        
    END LOOP read_loop;
    
    CLOSE user_cur;
    SELECT ROW_COUNT() AS processed_rows;
END //

DELIMITER ;
```

## FETCH 后立即检查 NOT FOUND 的重要性

```sql
DELIMITER //

-- 常见错误写法：FETCH 和 IF 之间有其他处理语句
CREATE PROCEDURE sp_wrong_pattern()
BEGIN
    DECLARE v_id   INT;
    DECLARE v_done TINYINT DEFAULT FALSE;
    DECLARE cur CURSOR FOR SELECT id FROM users;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    OPEN cur;
    read_loop: LOOP
        FETCH cur INTO v_id;
        
        -- 错误：FETCH 后没有立即检查 v_done
        -- 如果这是最后一行，v_done 已被设为 TRUE
        -- 但 v_id 的值是上一次 FETCH 的值（NOT FOUND 时变量不被清空）
        UPDATE users SET last_check = NOW() WHERE id = v_id;  -- 会重复处理最后一行！
        
        IF v_done THEN LEAVE read_loop; END IF;
    END LOOP read_loop;
    CLOSE cur;
END //

-- 正确写法：FETCH 后立即检查 v_done
CREATE PROCEDURE sp_correct_pattern()
BEGIN
    DECLARE v_id   INT;
    DECLARE v_done TINYINT DEFAULT FALSE;
    DECLARE cur CURSOR FOR SELECT id FROM users;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    OPEN cur;
    read_loop: LOOP
        FETCH cur INTO v_id;
        IF v_done THEN LEAVE read_loop; END IF;  -- 立即检查！
        
        UPDATE users SET last_check = NOW() WHERE id = v_id;
    END LOOP read_loop;
    CLOSE cur;
END //

DELIMITER ;
```

## 使用 FETCH 处理复杂业务

```sql
DELIMITER //

CREATE PROCEDURE sp_process_orders()
BEGIN
    DECLARE v_order_id  INT;
    DECLARE v_user_id   INT;
    DECLARE v_amount    DECIMAL(10,2);
    DECLARE v_created   DATETIME;
    DECLARE v_done      TINYINT DEFAULT FALSE;
    DECLARE v_processed INT DEFAULT 0;
    DECLARE v_skipped   INT DEFAULT 0;
    
    DECLARE order_cur CURSOR FOR
        SELECT id, user_id, amount, created_at
        FROM orders
        WHERE status = 0
          AND created_at < NOW() - INTERVAL 24 HOUR
        ORDER BY id;
    
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    OPEN order_cur;
    
    proc_loop: LOOP
        FETCH order_cur INTO v_order_id, v_user_id, v_amount, v_created;
        IF v_done THEN LEAVE proc_loop; END IF;
        
        -- 超过 7 天未支付：自动取消
        IF v_created < NOW() - INTERVAL 7 DAY THEN
            UPDATE orders SET status = 4, cancelled_at = NOW() WHERE id = v_order_id;
            SET v_processed = v_processed + 1;
        ELSE
            -- 1-7 天：发提醒（假设调用通知服务存储过程）
            CALL sp_send_payment_reminder(v_user_id, v_order_id, v_amount);
            SET v_skipped = v_skipped + 1;
        END IF;
        
    END LOOP proc_loop;
    
    CLOSE order_cur;
    SELECT v_processed AS cancelled, v_skipped AS reminded;
END //

DELIMITER ;
```

## 适用场景

- **逐行数据处理**：每行数据需要进行独立的业务判断和操作
- **跨行累计计算**：需要访问上一行数据进行比较或累加（纯 SQL 难以表达的逻辑）
- **行级别调用子程序**：对每行数据调用另一个存储过程（CALL）或函数

---

## 常见问题

**FETCH 超出末行后，变量的值是什么？**

NOT FOUND 触发时，已声明的变量**保持上一次 FETCH 的值**，不会被清空或置为 NULL。这正是"FETCH 后必须立即检查 v_done"的原因——如果在检查前使用了变量，会使用最后一行的旧数据再次处理，产生重复操作。

---

## 注意事项

- FETCH 变量的数量、顺序和类型必须与游标定义中 SELECT 列完全一致，数量不匹配会报 `ERROR 1328: Incorrect number of FETCH variables`。
- 每次 FETCH 移动游标指针到下一行，MySQL 游标不支持回退（backward）或随机访问（如 FETCH 第 5 行），只能单向向前读取。

---

## 总结

`FETCH cursor_name INTO var1, var2, ...` 从已打开的游标读取当前行并赋给变量，然后将指针移到下一行。最后一行之后的 FETCH 触发 NOT FOUND 条件（`v_done = TRUE`）。**FETCH 后必须立即检查退出标志**，否则会在最后一行重复处理。变量数量和顺序必须与游标 SELECT 列完全对应。
