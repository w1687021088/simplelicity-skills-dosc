# 游标 OPEN 打开

`OPEN cursor_name` 执行游标定义中的 SELECT 语句，将查询结果集加载到游标中，并将游标指针定位到第一行之前。游标必须先 `DECLARE` 声明，然后 `OPEN` 才能使用 `FETCH` 读取数据。

---

## 语法

```sql
OPEN cursor_name;
```

---

## 基本示例

```sql
DELIMITER //

CREATE PROCEDURE sp_open_demo()
BEGIN
    DECLARE v_id       INT;
    DECLARE v_username VARCHAR(100);
    DECLARE v_done     TINYINT DEFAULT FALSE;
    
    -- 声明游标（此时不执行 SELECT）
    DECLARE user_cur CURSOR FOR
        SELECT id, username FROM users WHERE is_active = 1 ORDER BY id;
    
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    -- OPEN：执行 SELECT，游标就绪
    OPEN user_cur;
    
    -- FETCH 读取数据
    read_loop: LOOP
        FETCH user_cur INTO v_id, v_username;
        IF v_done THEN LEAVE read_loop; END IF;
        SELECT v_id, v_username;
    END LOOP read_loop;
    
    -- 使用完毕后 CLOSE
    CLOSE user_cur;
END //

DELIMITER ;
```

## OPEN 的时机与数据快照

```sql
DELIMITER //

CREATE PROCEDURE sp_open_timing_demo()
BEGIN
    DECLARE v_id   INT;
    DECLARE v_done TINYINT DEFAULT FALSE;
    
    DECLARE cur CURSOR FOR
        SELECT id FROM users WHERE is_active = 1;
    
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    -- 此时 users 表有 100 个活跃用户
    
    -- 另一个连接在 OPEN 之前插入了 1 个新用户
    -- 如果 OPEN 之前插入：新用户会出现在游标数据集中（MySQL InnoDB，已提交事务可见）
    -- 如果 OPEN 之后插入：新用户不会出现（数据已快照）
    
    OPEN cur;   -- 此刻执行 SELECT，产生数据快照
    -- 快照后，即使 users 表数据变化，已打开的游标不受影响
    
    read_loop: LOOP
        FETCH cur INTO v_id;
        IF v_done THEN LEAVE read_loop; END IF;
        -- 对 users 表的修改不会影响游标遍历
        UPDATE users SET last_processed = NOW() WHERE id = v_id;
    END LOOP read_loop;
    
    CLOSE cur;
END //

DELIMITER ;
```

## 重复 OPEN 的处理

```sql
DELIMITER //

CREATE PROCEDURE sp_reopen_demo()
BEGIN
    DECLARE v_id   INT;
    DECLARE v_done TINYINT DEFAULT FALSE;
    
    DECLARE cur CURSOR FOR SELECT id FROM users LIMIT 5;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    -- 第一次打开
    OPEN cur;
    FETCH cur INTO v_id;
    SELECT v_id AS first_id;
    CLOSE cur;
    
    -- 重置标志（重新打开前必须重置 v_done）
    SET v_done = FALSE;
    
    -- 第二次打开（游标重新从头开始）
    OPEN cur;
    FETCH cur INTO v_id;
    SELECT v_id AS first_id_again;  -- 与第一次相同（重新从头读）
    CLOSE cur;
END //

DELIMITER ;
```

## 对已打开游标再次 OPEN 的行为

```sql
-- 对同一个游标第二次调用 OPEN（不先 CLOSE）
OPEN cur;
FETCH cur INTO v_id;
-- 不 CLOSE，直接再次 OPEN
OPEN cur;
-- MySQL 8.0+：报警告，游标被重新打开（等同于先 CLOSE 再 OPEN）
-- 不同版本行为可能略有差异，建议始终先 CLOSE 再 OPEN
```

## 游标完整生命周期

```sql
DELIMITER //

CREATE PROCEDURE sp_cursor_lifecycle()
BEGIN
    DECLARE v_id   INT;
    DECLARE v_done TINYINT DEFAULT FALSE;
    
    -- 1. 声明（定义 SELECT，不执行）
    DECLARE my_cur CURSOR FOR SELECT id FROM users WHERE is_active = 1;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;
    
    -- 2. 打开（执行 SELECT，数据就绪）
    OPEN my_cur;
    
    -- 3. 读取数据（FETCH 循环）
    my_loop: LOOP
        FETCH my_cur INTO v_id;           -- 4. 逐行提取
        IF v_done THEN LEAVE my_loop; END IF;
        -- 处理 v_id...
    END LOOP my_loop;
    
    -- 5. 关闭（释放资源）
    CLOSE my_cur;
    -- 游标声明隐式释放（过程结束时）
END //

DELIMITER ;
```

## 适用场景

- **游标遍历前的准备**：所有游标使用模式（DECLARE → OPEN → FETCH 循环 → CLOSE）都必须有 OPEN 步骤
- **重新遍历数据集**：CLOSE 后再次 OPEN 相同游标，从头重新遍历（但会重新执行 SELECT，性能有消耗）

---

## 常见问题

**不 OPEN 直接 FETCH 会怎样？**

会报错 `ERROR 1326 (24000): Cursor is not open`，游标在 FETCH 前必须通过 OPEN 打开。

---

## 注意事项

- OPEN 会执行游标定义中的 SELECT 语句，对于复杂查询或大结果集，OPEN 本身可能消耗较多时间和内存。在大结果集情况下，考虑为 SELECT 添加适当的 LIMIT 或先过滤数据减小结果集。
- 游标使用完毕后必须调用 CLOSE，释放游标占用的资源。存储过程结束时 MySQL 会自动关闭所有未关闭的游标，但显式 CLOSE 是良好实践，也便于游标的重用。

---

## 总结

`OPEN cursor_name` 执行游标定义的 SELECT 语句，产生数据快照并将游标指针置于第一行之前，之后可以通过 FETCH 逐行读取。游标打开后底层表的变化不影响已打开的数据集。每次 OPEN 都会重新执行查询（重置到第一行），CLOSE 后可以再次 OPEN 重新遍历。游标使用完毕应显式 CLOSE。
