# SHOW EVENTS 查看事件

`SHOW EVENTS` 显示当前数据库或指定数据库中定义的事件列表及其基本信息。配合 `information_schema.EVENTS` 视图可以进行更灵活的查询，包括事件的下次执行时间、最近一次执行时间和当前状态。

---

## 语法

```sql
SHOW EVENTS [FROM db_name] [LIKE 'pattern' | WHERE expr];

-- 查看事件完整定义
SHOW CREATE EVENT event_name;
```

---

## 基本示例

```sql
-- 查看当前数据库的所有事件
SHOW EVENTS;

-- 查看指定数据库的事件
SHOW EVENTS FROM mydb;

-- 按事件名称模式过滤
SHOW EVENTS LIKE 'evt_daily%';

-- WHERE 条件过滤
SHOW EVENTS WHERE Status = 'ENABLED';

-- 查看事件的完整 DDL 定义
SHOW CREATE EVENT evt_daily_cleanup\G
```

## SHOW EVENTS 输出列说明

| 列名 | 含义 |
|------|------|
| Db | 事件所在的数据库 |
| Name | 事件名称 |
| Definer | 创建者（user@host）|
| Time zone | 事件使用的时区 |
| Type | 事件类型（ONE TIME 或 RECURRING）|
| Execute at | 一次性事件的执行时间（RECURRING 为空）|
| Interval value | 周期间隔值（ONE TIME 为空）|
| Interval field | 间隔单位（MINUTE/HOUR/DAY 等）|
| Starts | 周期事件的开始时间 |
| Ends | 周期事件的结束时间（未设则为空）|
| Status | 状态（ENABLED/DISABLED/SLAVESIDE_DISABLED）|
| Originator | 创建事件的服务器 ID（复制相关）|
| character_set_client | 字符集 |

## 使用 information_schema.EVENTS 深度查询

```sql
-- 查看所有事件的详细信息（包含 LAST_EXECUTED 和 NEXT_EXECUTION_AT）
SELECT 
    EVENT_NAME,
    EVENT_TYPE,
    STATUS,
    INTERVAL_VALUE,
    INTERVAL_FIELD,
    DATE_FORMAT(LAST_EXECUTED, '%Y-%m-%d %H:%i:%s')      AS last_run,
    DATE_FORMAT(NEXT_EXECUTION_AT, '%Y-%m-%d %H:%i:%s')  AS next_run,
    EVENT_COMMENT
FROM information_schema.EVENTS
WHERE EVENT_SCHEMA = DATABASE()
ORDER BY NEXT_EXECUTION_AT;

-- 查找长时间未执行的事件（可能是执行失败了）
SELECT EVENT_NAME, STATUS, LAST_EXECUTED
FROM information_schema.EVENTS
WHERE EVENT_SCHEMA = DATABASE()
  AND STATUS = 'ENABLED'
  AND (LAST_EXECUTED IS NULL OR LAST_EXECUTED < NOW() - INTERVAL 2 DAY);

-- 只查看处于启用状态的周期性事件
SELECT EVENT_NAME, INTERVAL_VALUE, INTERVAL_FIELD, NEXT_EXECUTION_AT
FROM information_schema.EVENTS
WHERE EVENT_SCHEMA = DATABASE()
  AND EVENT_TYPE = 'RECURRING'
  AND STATUS = 'ENABLED'
ORDER BY NEXT_EXECUTION_AT;
```

## 查看下次执行时间

```sql
-- 查看所有已启用事件的下次执行时间
SELECT 
    EVENT_NAME,
    NEXT_EXECUTION_AT,
    TIMESTAMPDIFF(MINUTE, NOW(), NEXT_EXECUTION_AT) AS minutes_until_next
FROM information_schema.EVENTS
WHERE EVENT_SCHEMA = DATABASE()
  AND STATUS = 'ENABLED'
  AND NEXT_EXECUTION_AT IS NOT NULL
ORDER BY NEXT_EXECUTION_AT
LIMIT 10;
```

## 查看事件执行历史（借助日志表）

```sql
-- MySQL 没有内置的事件执行历史记录
-- 需要在事件体中手动记录执行日志

-- 示例：在事件中记录执行日志
CREATE EVENT evt_with_log
ON SCHEDULE EVERY 1 HOUR
ON COMPLETION PRESERVE
DO
BEGIN
    -- 业务逻辑
    DELETE FROM temp_data WHERE created_at < NOW() - INTERVAL 1 DAY;
    
    -- 手动记录执行日志
    INSERT INTO event_exec_log (event_name, exec_time, rows_affected)
    VALUES ('evt_with_log', NOW(), ROW_COUNT());
END;

-- 查询执行日志
SELECT * FROM event_exec_log WHERE event_name = 'evt_with_log'
ORDER BY exec_time DESC LIMIT 20;
```

## 适用场景

- **日常运维监控**：定期检查事件状态和下次执行时间，发现异常（DISABLED 事件、长时间未执行）
- **上线前核查**：确认生产环境的事件配置符合预期
- **文档生成**：从 information_schema.EVENTS 提取所有事件信息生成数据库文档

---

## 常见问题

**SHOW EVENTS 看不到 LAST_EXECUTED 列怎么办？**

`SHOW EVENTS` 默认不显示 `LAST_EXECUTED`，需要通过 `information_schema.EVENTS` 视图查询该字段。执行 `SELECT EVENT_NAME, LAST_EXECUTED FROM information_schema.EVENTS WHERE EVENT_SCHEMA = DATABASE()` 可以查到上次执行时间。

---

## 注意事项

- `SHOW EVENTS LIKE 'pattern'` 中的 pattern 匹配的是**事件名称**（Event Name），与 `SHOW TRIGGERS` 不同（SHOW TRIGGERS LIKE 匹配表名）。
- 只有拥有 `EVENT` 权限的用户才能查看其他用户创建的事件。普通用户只能查看自己创建的事件（或拥有 `SUPER` 权限的用户可查看所有事件）。

---

## 总结

`SHOW EVENTS [FROM db]` 显示事件基本信息；`SHOW CREATE EVENT name` 显示完整 DDL；`information_schema.EVENTS` 提供 LAST_EXECUTED（上次执行时间）和 NEXT_EXECUTION_AT（下次执行时间）等额外字段，是监控事件状态的主要工具。MySQL 没有内置的事件执行历史，需在事件体中手动写入日志表。
