# 事件与存储过程结合使用

事件体中可以直接写 SQL 语句，也可以调用存储过程（`CALL sp_name()`）。将复杂的定时任务逻辑封装在存储过程中，由事件负责调度触发，是生产环境中最推荐的模式。这种分离设计让任务逻辑可以独立测试、修改，而不需要重建事件。

---

## 基础结合模式

```sql
DELIMITER //

-- 第一步：创建包含业务逻辑的存储过程
CREATE PROCEDURE sp_daily_maintenance()
BEGIN
    DECLARE v_deleted_sessions INT DEFAULT 0;
    DECLARE v_deleted_logs     INT DEFAULT 0;
    
    -- 清理过期会话
    DELETE FROM user_sessions WHERE expired_at < NOW() - INTERVAL 1 DAY;
    SET v_deleted_sessions = ROW_COUNT();
    
    -- 清理操作日志（保留30天）
    DELETE FROM operation_logs WHERE created_at < NOW() - INTERVAL 30 DAY;
    SET v_deleted_logs = ROW_COUNT();
    
    -- 记录本次维护结果
    INSERT INTO maintenance_log (
        task_name, deleted_sessions, deleted_logs, run_at
    ) VALUES (
        'daily_maintenance', v_deleted_sessions, v_deleted_logs, NOW()
    );
END //

-- 第二步：创建事件调用存储过程
CREATE EVENT IF NOT EXISTS evt_daily_maintenance
ON SCHEDULE EVERY 1 DAY
    STARTS CURDATE() + INTERVAL 1 DAY + INTERVAL 2 HOUR   -- 明天凌晨2点开始
ON COMPLETION PRESERVE
ENABLE
COMMENT '每日凌晨2点执行维护任务'
DO CALL sp_daily_maintenance() //

DELIMITER ;

-- 手动测试存储过程（不需要等到事件触发）
CALL sp_daily_maintenance();
```

## 带错误处理的结合模式

```sql
DELIMITER //

-- 存储过程内含错误处理，事件体保持简洁
CREATE PROCEDURE sp_hourly_stats()
BEGIN
    DECLARE v_error TINYINT DEFAULT 0;
    DECLARE CONTINUE HANDLER FOR SQLEXCEPTION SET v_error = 1;
    
    -- 生成小时统计
    INSERT INTO hourly_order_stats (hour_time, order_count, revenue)
    SELECT 
        DATE_FORMAT(NOW() - INTERVAL 1 HOUR, '%Y-%m-%d %H:00:00'),
        COUNT(*),
        COALESCE(SUM(amount), 0)
    FROM orders
    WHERE created_at >= NOW() - INTERVAL 1 HOUR
      AND created_at < DATE_FORMAT(NOW(), '%Y-%m-%d %H:00:00')
      AND status = 2
    ON DUPLICATE KEY UPDATE
        order_count = VALUES(order_count),
        revenue     = VALUES(revenue);
    
    -- 记录执行结果（无论成功失败）
    INSERT INTO event_exec_log (event_name, exec_time, success, error_flag)
    VALUES ('evt_hourly_stats', NOW(), IF(v_error = 0, 1, 0), v_error);
END //

CREATE EVENT IF NOT EXISTS evt_hourly_stats
ON SCHEDULE EVERY 1 HOUR
    STARTS CURDATE() + INTERVAL 1 HOUR
ON COMPLETION PRESERVE
DO CALL sp_hourly_stats() //

DELIMITER ;
```

## 动态参数传入事件

```sql
DELIMITER //

-- 事件不能直接传参给存储过程（事件没有参数），
-- 可以通过系统表或配置表读取参数

CREATE PROCEDURE sp_configurable_cleanup()
BEGIN
    DECLARE v_keep_days INT DEFAULT 30;
    
    -- 从配置表读取保留天数（动态配置，无需修改代码）
    SELECT config_value INTO v_keep_days
    FROM app_configs
    WHERE config_key = 'log_retention_days';
    
    SET v_keep_days = COALESCE(v_keep_days, 30);
    
    DELETE FROM access_logs
    WHERE created_at < NOW() - INTERVAL v_keep_days DAY;
    
    SELECT CONCAT('清理了 ', ROW_COUNT(), ' 条日志（保留天数：', v_keep_days, '）') AS result;
END //

CREATE EVENT IF NOT EXISTS evt_configurable_cleanup
ON SCHEDULE EVERY 1 DAY
    STARTS CURDATE() + INTERVAL 1 DAY + INTERVAL 3 HOUR
ON COMPLETION PRESERVE
DO CALL sp_configurable_cleanup() //

DELIMITER ;
```

## 分离设计的优势

```sql
-- 存储过程可以独立于事件被手动调用（测试/补跑）
CALL sp_daily_maintenance();

-- 修改业务逻辑时只需重建存储过程，事件不需要改动
DROP PROCEDURE IF EXISTS sp_daily_maintenance;
DELIMITER //
CREATE PROCEDURE sp_daily_maintenance()
BEGIN
    -- 更新后的逻辑
    -- ...
END //
DELIMITER ;
-- evt_daily_maintenance 事件不需要任何修改，下次触发自动调用新逻辑

-- 与直接在事件体中写 SQL 的对比：
-- 如果逻辑写在事件体中，修改逻辑需要 DROP EVENT + CREATE EVENT，有空档期
-- 使用 CALL sp_xxx() 模式：修改只需重建存储过程，事件连续运行
```

---

## 适用场景

- **生产环境定时任务**：推荐始终使用事件 + 存储过程的组合，逻辑放存储过程，调度放事件
- **需要手动补跑的任务**：存储过程可以手动 CALL，事件自动调度，两者互不干扰
- **复杂的定时处理**：涉及游标、循环、多步骤事务的逻辑，必须放在存储过程中

## 常见问题

**事件能调用有 OUT 参数的存储过程吗？**

技术上可以，但需要用户变量接收：`CALL sp_xxx(@out_param)`。不过 OUT 参数的值在事件执行完后没有地方被读取，因此事件通常调用的是没有 OUT 参数（或参数无关紧要）的存储过程，返回值通过写日志表的方式保留。

---

## 注意事项

- 事件调用存储过程时，存储过程以事件的 DEFINER 身份执行（不是调度器线程），因此存储过程需要在 DEFINER 用户的权限范围内可以执行所有操作。
- 存储过程中不要使用 `SELECT` 语句直接输出结果（在事件上下文中输出结果没有意义，结果不会发送给任何客户端），改为将结果写入日志表。

---

## 总结

事件体中用 `CALL sp_name()` 调用存储过程是生产环境中定时任务的最佳实践。这种分离设计让任务逻辑可以独立测试（手动 CALL）、独立修改（只需重建存储过程），而事件只负责定时触发，不需要在修改业务逻辑时停止或重建事件。存储过程内应包含错误处理和执行日志记录，方便运维监控。
