# ALTER EVENT 修改事件

`ALTER EVENT` 语句用于修改已存在事件的调度计划、状态、事件体和其他属性，无需删除后重建。这是维护定时任务的主要手段，可以临时禁用、修改执行时间或更改事件的 SQL 逻辑。

---

## 语法

```sql
ALTER
    [DEFINER = user]
    EVENT event_name
    [ON SCHEDULE schedule]
    [ON COMPLETION [NOT] PRESERVE]
    [RENAME TO new_event_name]
    [ENABLE | DISABLE | DISABLE ON SLAVE]
    [COMMENT 'string']
    [DO event_body];
```

所有子句均为可选，可以只修改需要改变的部分。

---

## 启用和禁用事件

```sql
-- 临时禁用事件（暂停执行，保留定义）
ALTER EVENT evt_daily_cleanup DISABLE;

-- 重新启用
ALTER EVENT evt_daily_cleanup ENABLE;

-- 在从库禁用（主从复制中，避免从库也执行事件）
ALTER EVENT evt_daily_cleanup DISABLE ON SLAVE;
```

---

## 修改执行计划

```sql
-- 将一次性事件的执行时间推迟
ALTER EVENT evt_midnight_archive
ON SCHEDULE AT '2026-06-30 23:59:00';  -- 修改执行时间

-- 修改周期性事件的间隔
ALTER EVENT evt_every_minute
ON SCHEDULE EVERY 5 MINUTE             -- 从每分钟改为每5分钟
    STARTS NOW()
ON COMPLETION PRESERVE;

-- 修改每日任务的执行时刻（从 2 点改为 3 点）
ALTER EVENT evt_daily_cleanup
ON SCHEDULE EVERY 1 DAY
    STARTS CURDATE() + INTERVAL 1 DAY + INTERVAL 3 HOUR;  -- 明天凌晨3点开始
```

---

## 修改事件体（DO 子句）

```sql
-- 修改事件执行的 SQL（更新业务逻辑）
ALTER EVENT evt_daily_cleanup
DO
BEGIN
    -- 新增：清理更多类型的过期数据
    DELETE FROM session_logs WHERE expired_at < NOW() - INTERVAL 30 DAY;
    DELETE FROM temp_files WHERE created_at < NOW() - INTERVAL 7 DAY;
    DELETE FROM notification_queue WHERE status = 2 AND created_at < NOW() - INTERVAL 90 DAY;
    -- 记录执行日志
    INSERT INTO event_run_log (event_name, run_at)
    VALUES ('evt_daily_cleanup', NOW());
END;
```

## 重命名事件

```sql
-- 重命名事件
ALTER EVENT evt_daily_cleanup
RENAME TO evt_daily_data_cleanup;

-- 将事件迁移到另一个数据库（通过指定 schema）
ALTER EVENT old_db.evt_daily_cleanup
RENAME TO new_db.evt_daily_cleanup;
```

---

## 修改注释和保留选项

```sql
-- 修改注释
ALTER EVENT evt_daily_cleanup
COMMENT '每日凌晨3点清理过期数据、临时文件和通知队列';

-- 修改 ON COMPLETION 行为
-- 将"执行后自动删除"改为"执行后保留"
ALTER EVENT evt_one_time_task
ON COMPLETION PRESERVE;
```

## 综合修改示例

```sql
-- 同时修改多个属性
ALTER EVENT evt_stats_hourly
ON SCHEDULE EVERY 30 MINUTE           -- 从每小时改为每30分钟
    STARTS NOW()
ON COMPLETION PRESERVE
ENABLE
COMMENT '每30分钟统计一次实时数据'
DO
BEGIN
    INSERT INTO realtime_stats (stat_time, order_count, revenue)
    SELECT NOW(), COUNT(*), SUM(amount)
    FROM orders
    WHERE created_at >= NOW() - INTERVAL 30 MINUTE AND status = 2;
END;
```

## 修改与删除重建的对比

| 操作 | ALTER EVENT | DROP + CREATE |
|------|-------------|---------------|
| 语法复杂度 | 只写需要修改的部分 | 需要写完整的 CREATE 语句 |
| 是否中断执行 | 修改期间不中断（调度器继续工作）| 删除后新建之间有空档 |
| 重命名 | 支持（RENAME TO）| 不支持（只能用新名字创建）|
| 是否保留执行历史 | 保留（LAST_EXECUTED 不变）| 重新创建后历史丢失 |

---

## 适用场景

- **临时暂停任务**：维护期间 DISABLE，维护结束后 ENABLE
- **调整执行时间**：节假日调整定时任务执行时刻
- **升级任务逻辑**：更新事件体中的 SQL 逻辑（不需要删除重建）
- **主从切换后调整**：从库提升为主库后，从 DISABLE ON SLAVE 改为 ENABLE

---

## 常见问题

**修改正在执行中的事件会怎样？**

如果事件正在被调度器执行，ALTER EVENT 的修改会等执行完毕后生效（不会打断正在运行的任务）。下次触发时使用新的配置。

---

## 注意事项

- `ALTER EVENT` 只修改指定的子句，未指定的属性保持原值不变。与 `CREATE EVENT` 不同，不需要写出所有属性。
- 修改事件需要在该事件所在的数据库上拥有 `EVENT` 权限。修改其他用户创建的事件还需要 `SUPER` 权限（或 `SYSTEM_VARIABLES_ADMIN`）。

---

## 总结

`ALTER EVENT event_name [ON SCHEDULE ...] [ENABLE|DISABLE] [COMMENT ...] [DO ...]` 修改事件的任意属性，只需指定要改变的部分。常用于临时禁用/启用（DISABLE/ENABLE）、调整执行时间（ON SCHEDULE）、更新执行逻辑（DO 新代码）。相比删除重建，ALTER EVENT 不会造成执行空档，且保留 LAST_EXECUTED 等历史信息。
