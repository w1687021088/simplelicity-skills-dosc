# 周期性事件 EVERY 子句

`ON SCHEDULE EVERY interval` 创建按固定周期重复执行的事件。可以通过 `STARTS` 指定第一次执行的时间，通过 `ENDS` 指定停止执行的时间。这是事件调度器中最常用的模式，用于实现各种定期自动化任务。

---

## 语法

```sql
ON SCHEDULE EVERY interval
    [STARTS {timestamp | NOW() [+ INTERVAL interval] ...}]
    [ENDS   {timestamp | NOW() [+ INTERVAL interval] ...}]
```

---

## 支持的间隔单位

| 间隔单位 | 示例 |
|---------|------|
| SECOND | EVERY 30 SECOND |
| MINUTE | EVERY 5 MINUTE |
| HOUR | EVERY 1 HOUR |
| DAY | EVERY 1 DAY |
| WEEK | EVERY 1 WEEK |
| MONTH | EVERY 1 MONTH |
| QUARTER | EVERY 1 QUARTER |
| YEAR | EVERY 1 YEAR |
| HOUR_MINUTE | EVERY '1:30' HOUR_MINUTE |
| DAY_HOUR | EVERY '2:12' DAY_HOUR |
| MINUTE_SECOND | EVERY '5:30' MINUTE_SECOND |

## 基本示例

```sql
-- 每分钟执行一次（从现在开始，不设结束时间）
CREATE EVENT IF NOT EXISTS evt_every_minute
ON SCHEDULE EVERY 1 MINUTE
STARTS NOW()
ON COMPLETION PRESERVE
DO
    UPDATE queue_status SET last_check = NOW();

-- 每天凌晨 2 点执行（STARTS 指定首次执行时间）
CREATE EVENT IF NOT EXISTS evt_daily_cleanup
ON SCHEDULE EVERY 1 DAY
    STARTS '2026-01-01 02:00:00'   -- 每天凌晨 2:00
ON COMPLETION PRESERVE
COMMENT '每日数据清理'
DO
BEGIN
    DELETE FROM session_logs WHERE expired_at < NOW() - INTERVAL 30 DAY;
    DELETE FROM temp_uploads WHERE created_at < NOW() - INTERVAL 3 DAY;
END;

-- 每周一凌晨 3 点执行（STARTS 设置为下周一）
CREATE EVENT IF NOT EXISTS evt_weekly_report
ON SCHEDULE EVERY 1 WEEK
    STARTS '2026-03-04 03:00:00'   -- 2026-03-04 是一个周一
ON COMPLETION PRESERVE
DO CALL sp_generate_weekly_report();

-- 每月1日凌晨执行
CREATE EVENT IF NOT EXISTS evt_monthly_archive
ON SCHEDULE EVERY 1 MONTH
    STARTS '2026-03-01 01:00:00'
ON COMPLETION PRESERVE
DO CALL sp_monthly_data_archive();
```

## 带 ENDS 的有时限周期事件

```sql
-- 促销期间（3 天内）每 30 分钟检查一次库存预警
CREATE EVENT IF NOT EXISTS evt_promo_stock_check
ON SCHEDULE EVERY 30 MINUTE
    STARTS NOW()
    ENDS NOW() + INTERVAL 3 DAY
ON COMPLETION NOT PRESERVE   -- 促销期结束后自动删除事件
DO
    INSERT INTO stock_alerts (product_id, alert_level, created_at)
    SELECT id, 'LOW', NOW() FROM products
    WHERE stock < 10 AND is_active = 1
    ON DUPLICATE KEY UPDATE created_at = NOW();

-- 特定时间段内的高频统计（A/B测试期间每 5 分钟统计一次转化率）
CREATE EVENT IF NOT EXISTS evt_ab_test_stats
ON SCHEDULE EVERY 5 MINUTE
    STARTS '2026-03-01 00:00:00'
    ENDS   '2026-03-15 23:59:59'
ON COMPLETION PRESERVE
DO
    INSERT INTO ab_test_metrics (experiment_id, check_time, conversions, impressions)
    SELECT 42, NOW(), COUNT(*), SUM(impressions)
    FROM ab_test_log WHERE check_time >= NOW() - INTERVAL 5 MINUTE;
```

## STARTS 的作用

```sql
-- 不设 STARTS：从调度器下次检查时立即开始执行
CREATE EVENT evt_no_starts
ON SCHEDULE EVERY 1 HOUR
DO SELECT 1;

-- 设 STARTS（未来时间）：从 STARTS 时刻开始，按 EVERY 间隔执行
CREATE EVENT evt_future_start
ON SCHEDULE EVERY 1 HOUR
    STARTS '2026-06-01 08:00:00'  -- 6月1日8点开始，之后每小时执行一次
DO SELECT 1;

-- 设 STARTS（过去时间）：相当于调整执行的"基准时间点"
-- MySQL 会从 STARTS 开始，按 EVERY 计算下一个满足条件的时间点
CREATE EVENT evt_past_start
ON SCHEDULE EVERY 1 DAY
    STARTS '2026-01-01 02:00:00'  -- 基准时间：每天凌晨2点执行
DO CALL sp_daily_task();
-- 即使当前是 2026-03-15，调度器也会在今天的 02:00:00 执行（如果还没执行过的话）
```

## 适用场景

- **每日定时任务**：数据清理、日志归档、统计汇总（EVERY 1 DAY + STARTS 设在凌晨）
- **每小时统计**：业务指标实时汇总（EVERY 1 HOUR）
- **高频监控**：队列积压检测、超时订单处理（EVERY 1 MINUTE 或 EVERY 30 SECOND）
- **有时限的临时任务**：活动期间的特殊逻辑（EVERY + ENDS 结合使用）

---

## 常见问题

**EVERY 1 DAY 和 EVERY 24 HOUR 有区别吗？**

行为上基本相同，但涉及夏令时（DST）调整时会有差异。`EVERY 1 DAY` 按日历天计算（受 DST 影响时某天可能是 23 或 25 小时），`EVERY 24 HOUR` 按精确 24 小时间隔计算（不受 DST 影响）。在没有 DST 的地区两者完全等价。

---

## 注意事项

- 如果事件的执行时间超过了 EVERY 的间隔（如 EVERY 1 MINUTE 但任务需要执行 90 秒），MySQL 不会并发触发新的执行，而是等上一次执行完毕后，在下一个到期点触发。中间被跳过的执行不会补执行。
- 在主从复制环境中，事件执行的 DML 会通过 binlog 复制到从库，应避免在从库也开启事件调度器导致双重执行。

---

## 总结

`ON SCHEDULE EVERY interval [STARTS start_time] [ENDS end_time]` 创建周期性事件。STARTS 设置第一次执行的基准时间（用于控制每天的执行时刻），ENDS 设置停止时间（过期后根据 ON COMPLETION 决定是否保留定义）。任务执行超时时不并发触发，等上次完成后再按周期执行。生产环境建议配合 `ON COMPLETION PRESERVE` 保留事件定义，方便监控和管理。
