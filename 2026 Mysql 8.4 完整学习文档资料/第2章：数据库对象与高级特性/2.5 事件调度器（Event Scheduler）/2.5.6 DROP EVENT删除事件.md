# DROP EVENT 删除事件

`DROP EVENT` 语句从数据库中删除一个已定义的事件。删除事件后，该事件不会再被调度器触发执行。`IF EXISTS` 选项防止事件不存在时报错。

---

## 语法

```sql
DROP EVENT [IF EXISTS] event_name;
```

---

## 基本示例

```sql
-- 删除事件
DROP EVENT evt_daily_cleanup;

-- IF EXISTS：事件不存在时不报错，只发出警告
DROP EVENT IF EXISTS evt_daily_cleanup;

-- 部署脚本中的标准写法（先删后建）
DROP EVENT IF EXISTS evt_hourly_stats;
CREATE EVENT IF NOT EXISTS evt_hourly_stats
ON SCHEDULE EVERY 1 HOUR
STARTS NOW()
ON COMPLETION PRESERVE
DO
    CALL sp_hourly_statistics();
```

---

## 删除前查看事件状态

```sql
-- 先查看事件的状态和最近执行时间
SELECT EVENT_NAME, STATUS, LAST_EXECUTED, NEXT_EXECUTION_AT
FROM information_schema.EVENTS
WHERE EVENT_SCHEMA = DATABASE()
  AND EVENT_NAME = 'evt_daily_cleanup';

-- 确认可以删除后执行删除
DROP EVENT IF EXISTS evt_daily_cleanup;

-- 验证已删除
SHOW EVENTS;
```

## 批量删除事件

```sql
-- 生成批量删除语句（删除所有以 evt_old_ 开头的事件）
SELECT CONCAT('DROP EVENT IF EXISTS `', EVENT_NAME, '`;') AS drop_stmt
FROM information_schema.EVENTS
WHERE EVENT_SCHEMA = DATABASE()
  AND EVENT_NAME LIKE 'evt_old_%';

-- 查询生成后手动执行，或通过存储过程执行
```

## DROP EVENT vs DISABLE EVENT

```sql
-- DROP EVENT：彻底删除，不可恢复（除非重新 CREATE）
DROP EVENT evt_daily_cleanup;

-- ALTER EVENT ... DISABLE：暂停执行，保留定义，可以随时重新启用
ALTER EVENT evt_daily_cleanup DISABLE;

-- 选择建议：
-- 临时不需要执行 → DISABLE（保留定义，以后可以 ENABLE）
-- 永久不再需要 → DROP EVENT
```

---

## ON COMPLETION NOT PRESERVE 的自动删除

```sql
-- 事件体中设置了 ON COMPLETION NOT PRESERVE（默认）的事件，
-- 在执行完毕（AT 时间过了或 ENDS 时间到了）后，会被 MySQL 自动删除
-- 不需要手动 DROP

CREATE EVENT evt_auto_cleanup
ON SCHEDULE AT NOW() + INTERVAL 1 HOUR
ON COMPLETION NOT PRESERVE    -- 默认：执行后自动删除
DO DELETE FROM temp_data WHERE created_at < NOW() - INTERVAL 1 DAY;
-- 1 小时后自动执行并删除，无需手动 DROP
```

## 删除需要的权限

```sql
-- 删除事件需要在该事件所在数据库上拥有 EVENT 权限
SHOW GRANTS FOR CURRENT_USER();

-- 授予 EVENT 权限
GRANT EVENT ON mydb.* TO 'dev_user'@'%';

-- 撤销权限后无法删除他人创建的事件
-- ERROR 1142 (42000): EVENT command denied to user 'dev'@'localhost' for table 'mydb'
```

## 适用场景

- **清理废弃任务**：删除不再需要的历史定时任务
- **环境重置**：开发/测试环境重置时清空所有事件
- **版本迭代**：更新事件逻辑时先 DROP IF EXISTS 再重新创建

---

## 常见问题

**删除事件后，已经通过该事件执行的历史数据会丢失吗？**

不会，事件执行的 SQL 语句产生的数据变更（INSERT/UPDATE/DELETE）是永久的，删除事件定义只是移除了调度计划，不会影响已经写入的历史数据。

---

## 注意事项

- 如果事件正在执行中，`DROP EVENT` 不会中断正在运行的任务，会等待当前执行完成后再删除事件定义（实际上删除发生得很快，调度器不会再次触发该事件）。
- 数据库被删除（`DROP DATABASE`）时，其中定义的所有事件也会一并删除。

---

## 总结

`DROP EVENT [IF EXISTS] event_name` 永久删除事件定义。推荐使用 `IF EXISTS` 避免不存在时报错。临时不需要执行但未来可能需要的事件应使用 `ALTER EVENT ... DISABLE` 而非 DROP。设置了 `ON COMPLETION NOT PRESERVE` 的事件在执行完毕后由 MySQL 自动删除，无需手动 DROP。
