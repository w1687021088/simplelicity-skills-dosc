# 事件调度器开启与配置

MySQL 事件调度器（Event Scheduler）是 MySQL 内置的定时任务引擎，可以在指定时间或按周期自动执行 SQL 语句或存储过程，类似操作系统的 cron 任务但完全在数据库内运行。默认情况下事件调度器处于关闭状态，需要手动开启。

---

## 查看调度器状态

```sql
-- 查看事件调度器当前状态
SHOW VARIABLES LIKE 'event_scheduler';
-- 输出：
-- +------------------+-------+
-- | Variable_name    | Value |
-- +------------------+-------+
-- | event_scheduler  | OFF   |
-- +------------------+-------+

-- 通过 SHOW PROCESSLIST 也能看到调度器线程
SHOW PROCESSLIST;
-- 如果调度器开启，会看到一个 User=event_scheduler 的系统线程
```

---

## 开启事件调度器

```sql
-- 方式1：动态设置（立即生效，服务器重启后恢复默认）
SET GLOBAL event_scheduler = ON;
SET GLOBAL event_scheduler = 1;    -- 等价写法

-- 关闭
SET GLOBAL event_scheduler = OFF;
SET GLOBAL event_scheduler = 0;

-- DISABLED 状态：完全禁止（需要重启才能改变，通常用于配置文件）
-- SET GLOBAL event_scheduler = DISABLED;  -- 不能在运行时设置为 DISABLED
```

---

## 持久化配置（my.cnf / my.ini）

```ini
# 在 MySQL 配置文件中设置，服务器重启后永久生效
[mysqld]
event_scheduler = ON       # 开启
# event_scheduler = OFF    # 关闭
# event_scheduler = DISABLED  # 完全禁用（不能通过 SET GLOBAL 开启）
```

---

## 三种状态的区别

| 状态 | 含义 | 事件能否创建 | 事件能否执行 |
|------|------|------------|------------|
| ON | 已开启 | 是 | 是 |
| OFF | 已关闭（默认）| 是 | 否（等待开启后执行）|
| DISABLED | 完全禁用 | 是 | 否（SET GLOBAL 也无法开启）|

---

## 确认调度器开启

```sql
-- 开启后验证
SET GLOBAL event_scheduler = ON;
SHOW VARIABLES LIKE 'event_scheduler';
-- +------------------+-------+
-- | Variable_name    | Value |
-- +------------------+-------+
-- | event_scheduler  | ON    |
-- +------------------+-------+

-- 查看调度器线程
SHOW PROCESSLIST;
-- 会看到类似：
-- Id: 1  User: event_scheduler  Command: Daemon  Info: Waiting for next activation
```

## 需要的权限

```sql
-- 开启/关闭调度器需要 SYSTEM_VARIABLES_ADMIN 权限（或 SUPER）
SET GLOBAL event_scheduler = ON;
-- ERROR 1227 (42000): Access denied; you need (at least one of) 
-- the SUPER or SYSTEM_VARIABLES_ADMIN privilege(s) for this operation

-- 创建/管理事件需要 EVENT 权限
GRANT EVENT ON mydb.* TO 'dev_user'@'%';
```

## 适用场景

- **定时数据清理**：每天凌晨清理过期日志、过期会话
- **定时统计汇总**：每小时汇总订单数据到报表表
- **定时缓存刷新**：周期性更新汇总统计数据
- **定时任务通知**：检查超时未支付订单并自动取消

---

## 常见问题

**为什么事件调度器默认关闭？**

默认关闭是因为事件调度器作为后台线程持续消耗系统资源，不是所有 MySQL 实例都需要定时任务功能，让用户按需开启可以减少不必要的资源占用。在需要使用事件功能的生产环境中，通过配置文件持久化开启是推荐做法。

---

## 注意事项

- 在主从复制架构中，事件调度器通常只在主库开启，从库关闭（`SET GLOBAL event_scheduler = OFF`），避免事件在从库重复执行（主库的事件执行会通过 binlog 同步到从库）。
- 事件调度器的时区以 MySQL 服务器的系统时区（`@@global.time_zone`）为准，创建事件前确认时区设置正确，避免定时任务在错误的时间执行。

---

## 总结

`SET GLOBAL event_scheduler = ON` 开启 MySQL 事件调度器，默认状态为 OFF。持久化开启应在配置文件的 `[mysqld]` 段添加 `event_scheduler = ON`。三种状态：ON（运行）、OFF（停止，可以 SET GLOBAL 开启）、DISABLED（完全禁用，不能运行时修改）。主从复制环境中通常只在主库开启。
