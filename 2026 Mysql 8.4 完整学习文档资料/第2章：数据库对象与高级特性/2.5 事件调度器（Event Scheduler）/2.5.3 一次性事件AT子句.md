# 一次性事件 AT 子句

`ON SCHEDULE AT timestamp` 指定事件只在某个特定时刻执行一次。时间可以是一个具体的日期时间字面量，也可以是 `NOW()` 加上时间间隔的表达式。默认情况下，一次性事件执行完后会自动被删除（`ON COMPLETION NOT PRESERVE`）。

---

## 语法

```sql
CREATE EVENT event_name
ON SCHEDULE AT {timestamp | NOW() [+ INTERVAL interval [+ INTERVAL interval ...]]}
[ON COMPLETION [NOT] PRESERVE]
DO event_body;
```

---

## 基本示例

```sql
-- 1 小时后执行一次
CREATE EVENT evt_one_hour_later
ON SCHEDULE AT NOW() + INTERVAL 1 HOUR
DO
    DELETE FROM temp_cache WHERE created_at < NOW() - INTERVAL 1 HOUR;

-- 明天凌晨 3 点执行一次（指定精确时刻）
CREATE EVENT evt_tomorrow_3am
ON SCHEDULE AT CURDATE() + INTERVAL 1 DAY + INTERVAL 3 HOUR
DO
    CALL sp_daily_data_archive();

-- 在指定日期时间执行
CREATE EVENT evt_on_specific_time
ON SCHEDULE AT '2026-12-31 23:59:00'
ON COMPLETION NOT PRESERVE   -- 执行后自动删除（这是默认值）
COMMENT '2026年最后一秒的任务'
DO
    INSERT INTO year_end_reports (report_date, total_revenue)
    SELECT '2026-12-31', SUM(amount) FROM orders
    WHERE YEAR(created_at) = 2026 AND status = 2;
```

---

## 多个 INTERVAL 叠加

```sql
-- AT 子句中可以叠加多个 INTERVAL 来精确指定时间
-- 下周三上午 9 点
CREATE EVENT evt_next_wednesday_9am
ON SCHEDULE AT
    CURDATE()
    + INTERVAL (7 - WEEKDAY(CURDATE()) + 2) % 7 + 1 DAY   -- 下一个周三
    + INTERVAL 9 HOUR
ON COMPLETION NOT PRESERVE
DO CALL sp_weekly_report();

-- 30 天 6 小时 30 分钟后
CREATE EVENT evt_complex_interval
ON SCHEDULE AT NOW() + INTERVAL 30 DAY + INTERVAL 6 HOUR + INTERVAL 30 MINUTE
DO SELECT 1;
```

## ON COMPLETION 对一次性事件的影响

```sql
-- ON COMPLETION NOT PRESERVE（默认）：执行后自动删除事件
CREATE EVENT evt_auto_delete
ON SCHEDULE AT NOW() + INTERVAL 5 MINUTE
ON COMPLETION NOT PRESERVE
DO DELETE FROM temp_table WHERE id < 100;
-- 5 分钟后执行，执行完成后事件自动从数据库中删除

-- ON COMPLETION PRESERVE：执行后保留事件（状态变为 DISABLE）
CREATE EVENT evt_keep_after_run
ON SCHEDULE AT NOW() + INTERVAL 5 MINUTE
ON COMPLETION PRESERVE   -- 执行后不删除
DO DELETE FROM temp_table WHERE id < 100;
-- 5 分钟后执行，执行完后事件定义保留，状态变为 DISABLE
-- 可以通过 ALTER EVENT 修改 AT 时间后重新启用
```

## 创建处于过去时间的事件

```sql
-- 如果 AT 时间已经过去（当前时间 > AT 时间），事件会立即触发一次
CREATE EVENT evt_past_time
ON SCHEDULE AT '2024-01-01 00:00:00'   -- 这是一个过去的时间
ON COMPLETION NOT PRESERVE
DO SELECT 'Executed immediately since AT time is in the past';
-- 调度器会立即触发一次，然后删除事件（ON COMPLETION NOT PRESERVE）
```

## 查看和追踪一次性事件

```sql
-- 查看待执行的一次性事件
SELECT EVENT_NAME, EXECUTE_AT, STATUS, LAST_EXECUTED
FROM information_schema.EVENTS
WHERE EVENT_SCHEMA = DATABASE()
  AND EVENT_TYPE = 'ONE TIME'
ORDER BY EXECUTE_AT;

-- 取消尚未执行的一次性事件
DROP EVENT IF EXISTS evt_one_hour_later;
-- 或者暂时禁用
ALTER EVENT evt_one_hour_later DISABLE;
```

## 适用场景

- **延迟执行**：某个操作需要延迟一段时间后执行（如 30 分钟后发送推送）
- **预定任务**：在特定日期时刻执行的任务（年末归档、促销活动启动）
- **数据库层面的定时操作**：不依赖应用层实现的一次性数据处理

---

## 常见问题

**如果调度器关闭期间，一次性事件的 AT 时间到了，调度器开启后还会执行吗？**

不会。MySQL 的事件调度器不会补执行错过的触发时间。如果调度器关闭时事件的 AT 时间已经过去，开启调度器后该事件不会再被触发（状态变为 DISABLE，如果是 ON COMPLETION NOT PRESERVE 则可能已被删除或标记过期）。

---

## 注意事项

- AT 时间为过去时刻时，事件会立即触发（而不是等到相同时刻的明天或下周），这与 EVERY 的行为不同。注意不要误创建立即触发的生产事件。
- 一次性事件执行完毕后（ON COMPLETION NOT PRESERVE），会从 `information_schema.EVENTS` 中消失，无法通过 `SHOW EVENTS` 查看。如需追踪执行记录，应在事件体中将执行结果写入日志表。

---

## 总结

`ON SCHEDULE AT timestamp` 创建只在指定时刻执行一次的事件。时间支持字面量或 `NOW() + INTERVAL` 表达式，可叠加多个 INTERVAL。过去时间的 AT 会立即触发。默认 `ON COMPLETION NOT PRESERVE`（执行后自动删除），加 `ON COMPLETION PRESERVE` 则保留事件定义（状态变 DISABLE）供后续重用。调度器关闭期间错过的执行不会补执行。
