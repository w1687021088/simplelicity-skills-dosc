# DROP TRIGGER 删除触发器

`DROP TRIGGER` 语句从数据库中删除一个已存在的触发器定义。删除触发器不影响触发器所附属的表及其数据，但触发器的自动执行逻辑将不再存在。`IF EXISTS` 选项防止触发器不存在时报错。

---

## 语法

```sql
DROP TRIGGER [IF EXISTS] [schema_name.]trigger_name;
```

---

## 基本示例

```sql
-- 删除触发器
DROP TRIGGER trg_users_before_insert;

-- IF EXISTS：触发器不存在时不报错，只发出警告
DROP TRIGGER IF EXISTS trg_users_before_insert;

-- 指定数据库名（跨库管理时使用）
DROP TRIGGER IF EXISTS mydb.trg_users_before_insert;

-- 在部署脚本中的标准写法（先删后建）
DROP TRIGGER IF EXISTS trg_orders_before_update;
DELIMITER //
CREATE TRIGGER trg_orders_before_update
BEFORE UPDATE ON orders
FOR EACH ROW
BEGIN
    SET NEW.updated_at = NOW();
END //
DELIMITER ;
```

---

## 查看后再删除

```sql
-- 先确认触发器存在和内容
SHOW TRIGGERS WHERE `Trigger` = 'trg_orders_before_update'\G

-- 确认后删除
DROP TRIGGER IF EXISTS trg_orders_before_update;

-- 验证已删除
SHOW TRIGGERS WHERE `Table` = 'orders';
-- 输出为空，说明删除成功
```

## 批量删除触发器

```sql
-- 生成批量删除语句
SELECT CONCAT('DROP TRIGGER IF EXISTS `', TRIGGER_SCHEMA, '`.`', TRIGGER_NAME, '`;') AS drop_stmt
FROM information_schema.TRIGGERS
WHERE TRIGGER_SCHEMA = 'mydb'
  AND TRIGGER_NAME LIKE 'trg_old_%';

-- 删除整张表上的所有触发器（可以通过脚本执行生成的语句）
SELECT CONCAT('DROP TRIGGER IF EXISTS `', TRIGGER_NAME, '`;') AS drop_stmt
FROM information_schema.TRIGGERS
WHERE TRIGGER_SCHEMA = DATABASE()
  AND EVENT_OBJECT_TABLE = 'legacy_table';
```

## 删除触发器所需权限

```sql
-- 删除触发器需要在该表上拥有 TRIGGER 权限
SHOW GRANTS FOR CURRENT_USER();

-- 授予 TRIGGER 权限
GRANT TRIGGER ON mydb.orders TO 'dev_user'@'%';

-- 撤销 TRIGGER 权限后无法删除触发器
-- ERROR 1142 (42000): TRIGGER command denied to user 'dev'@'localhost' for table 'orders'
```

## 修改触发器的完整流程

```sql
-- MySQL 没有 ALTER TRIGGER 语句，修改触发器必须先 DROP 再 CREATE

-- 步骤1：查看旧定义（保存备份）
SHOW CREATE TRIGGER trg_orders_before_update\G

-- 步骤2：删除旧触发器
DROP TRIGGER IF EXISTS trg_orders_before_update;

-- 步骤3：创建新版本
DELIMITER //
CREATE TRIGGER trg_orders_before_update
BEFORE UPDATE ON orders
FOR EACH ROW
BEGIN
    SET NEW.updated_at = NOW();
    IF NEW.status < OLD.status THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '状态不能回退';
    END IF;
END //
DELIMITER ;

-- 步骤4：验证新触发器
SHOW TRIGGERS WHERE `Table` = 'orders';
```

## 适用场景

- **版本迭代**：触发器逻辑需要修改时，先 DROP IF EXISTS 再重新 CREATE
- **清理废弃触发器**：删除不再需要的审计触发器或测试触发器
- **性能优化**：通过删除性能影响大的触发器改用异步方案
- **数据库迁移**：迁移前清除源库触发器，在目标库重建

---

## 常见问题

**删除触发器后，已经写入的数据会受影响吗？**

不会，触发器只影响删除后的新 DML 操作。删除触发器之前通过触发器写入的历史数据完全不受影响。

---

## 注意事项

- MySQL 没有禁用/暂停触发器的语法（类似 SQL Server 的 DISABLE TRIGGER）。如果临时不想触发器生效（如批量导入数据时绕过触发器），只能 DROP 再重建，或使用 `SET @trigger_disabled = 1` 配合触发器内的条件判断来模拟禁用效果。
- 删除整个表（DROP TABLE）时，表上的所有触发器会被自动一起删除。

---

## 总结

`DROP TRIGGER [IF EXISTS] trigger_name` 删除触发器定义，不影响表数据。MySQL 没有 ALTER TRIGGER 语法，修改触发器必须 DROP + CREATE。也没有禁用/暂停触发器的语法，临时绕过触发器只能先删后建或在触发器内加条件判断。DROP TABLE 会自动删除表上所有触发器。
