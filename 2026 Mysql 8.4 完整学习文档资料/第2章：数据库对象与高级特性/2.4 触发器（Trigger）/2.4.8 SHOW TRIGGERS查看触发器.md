# SHOW TRIGGERS 查看触发器

`SHOW TRIGGERS` 语句显示当前数据库或指定数据库中的触发器信息，包括触发器名称、事件、所属表、执行时机、触发器体和创建时间等。结合 `information_schema.TRIGGERS` 视图可以进行更灵活的查询。

---

## 语法

```sql
SHOW TRIGGERS [FROM db_name] [LIKE 'pattern' | WHERE expr];

-- 查看触发器完整定义
SHOW CREATE TRIGGER trigger_name;
```

---

## 基本示例

```sql
-- 查看当前数据库的所有触发器
SHOW TRIGGERS;

-- 查看指定数据库的触发器
SHOW TRIGGERS FROM mydb;

-- 按表名过滤（LIKE 匹配 Table 列）
SHOW TRIGGERS LIKE 'users';
SHOW TRIGGERS LIKE 'order%';

-- 按触发事件过滤（WHERE 过滤 Event 列）
SHOW TRIGGERS WHERE `Event` = 'INSERT';

-- 查看触发器的完整定义（DDL）
SHOW CREATE TRIGGER trg_users_before_insert\G
```

---

## SHOW TRIGGERS 的输出列说明

| 列名 | 含义 |
|------|------|
| Trigger | 触发器名称 |
| Event | 触发事件（INSERT/UPDATE/DELETE）|
| Table | 触发器所属的表名 |
| Statement | 触发器体（BEGIN...END 内的 SQL）|
| Timing | 执行时机（BEFORE/AFTER）|
| Created | 创建时间 |
| sql_mode | 创建时的 SQL 模式 |
| Definer | 创建者（user@host）|
| character_set_client | 字符集 |
| collation_connection | 排序规则 |
| Database Collation | 数据库排序规则 |

## 使用 information_schema.TRIGGERS 查询

```sql
-- 更灵活的触发器查询（可以按任意条件过滤）
SELECT 
    TRIGGER_NAME,
    EVENT_MANIPULATION AS event,
    EVENT_OBJECT_TABLE AS table_name,
    ACTION_TIMING AS timing,
    ACTION_STATEMENT AS body,
    CREATED,
    DEFINER
FROM information_schema.TRIGGERS
WHERE TRIGGER_SCHEMA = DATABASE()
ORDER BY EVENT_OBJECT_TABLE, ACTION_TIMING, EVENT_MANIPULATION;

-- 查询特定表上的所有触发器
SELECT TRIGGER_NAME, EVENT_MANIPULATION, ACTION_TIMING
FROM information_schema.TRIGGERS
WHERE TRIGGER_SCHEMA = DATABASE()
  AND EVENT_OBJECT_TABLE = 'orders';

-- 统计每张表的触发器数量
SELECT EVENT_OBJECT_TABLE AS table_name, COUNT(*) AS trigger_count
FROM information_schema.TRIGGERS
WHERE TRIGGER_SCHEMA = DATABASE()
GROUP BY EVENT_OBJECT_TABLE
ORDER BY trigger_count DESC;
```

## 批量查看所有表的触发器状态

```sql
-- 生成所有触发器的汇总报告
SELECT 
    TRIGGER_NAME,
    CONCAT(ACTION_TIMING, ' ', EVENT_MANIPULATION) AS event_type,
    EVENT_OBJECT_TABLE AS on_table,
    DEFINER,
    DATE_FORMAT(CREATED, '%Y-%m-%d %H:%i:%s') AS created_at
FROM information_schema.TRIGGERS
WHERE TRIGGER_SCHEMA = DATABASE()
ORDER BY EVENT_OBJECT_TABLE, ACTION_TIMING, EVENT_MANIPULATION;
```

## 适用场景

- **数据库审查**：列出所有触发器，了解隐藏的自动化逻辑，防止"幽灵操作"
- **触发器调试**：查看触发器定义，确认逻辑是否正确
- **上线前检查**：部署前确认哪些表有触发器，评估 DML 操作的实际代价
- **文档生成**：从 information_schema.TRIGGERS 提取触发器信息生成数据库文档

---

## 常见问题

**查看触发器定义需要什么权限？**

普通用户可以查看 `SHOW TRIGGERS` 中自己有权限访问的表上的触发器。查看 `information_schema.TRIGGERS` 需要对应表的 `TRIGGER` 权限（或 `SUPER` 权限）。DBA 或有 TRIGGER 权限的用户可以查看所有触发器。

---

## 注意事项

- `SHOW TRIGGERS LIKE 'pattern'` 中的 pattern 匹配的是触发器所在的**表名**（Table 列），不是触发器名称本身。要按触发器名称过滤，用 `WHERE` 子句：`SHOW TRIGGERS WHERE Trigger LIKE 'trg_orders%'`。
- 在维护或排查问题时，要养成先用 `SHOW TRIGGERS` 检查表上是否有触发器的习惯，避免因为忘记触发器导致 DML 操作产生意外的副作用。

---

## 总结

`SHOW TRIGGERS [FROM db] [LIKE table_pattern | WHERE condition]` 列出触发器基本信息；`SHOW CREATE TRIGGER name` 显示完整 DDL 定义；`information_schema.TRIGGERS` 提供最灵活的查询能力（可按任意字段过滤和排序）。维护数据库时建议定期检查触发器列表，避免遗忘隐藏的自动化逻辑造成预期外的数据变更。
