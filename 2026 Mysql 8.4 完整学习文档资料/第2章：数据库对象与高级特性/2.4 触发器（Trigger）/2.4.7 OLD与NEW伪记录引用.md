# OLD 与 NEW 伪记录引用

在触发器中，`OLD` 和 `NEW` 是两个特殊的伪记录（pseudo-record），分别代表操作前的旧行数据和操作后的新行数据。不同的触发器事件（INSERT/UPDATE/DELETE）和时机（BEFORE/AFTER）决定了 OLD 和 NEW 的可用性及是否可以修改。

---

## OLD 与 NEW 的可用性

| 触发器类型 | OLD 可读 | NEW 可读 | NEW 可写（BEFORE）|
|-----------|---------|---------|-----------------|
| BEFORE INSERT | 否 | 是 | 是 |
| AFTER INSERT | 否 | 是 | 否 |
| BEFORE UPDATE | 是 | 是 | 是 |
| AFTER UPDATE | 是 | 是 | 否 |
| BEFORE DELETE | 是 | 否 | — |
| AFTER DELETE | 是 | 否 | — |

---

## 基本使用方式

```sql
DELIMITER //

-- UPDATE 触发器中同时使用 OLD 和 NEW
CREATE TRIGGER trg_demo_old_new
BEFORE UPDATE ON employees
FOR EACH ROW
BEGIN
    -- 读取旧值
    DECLARE v_old_salary DECIMAL(10,2);
    DECLARE v_new_salary DECIMAL(10,2);
    SET v_old_salary = OLD.salary;   -- 更新前的薪资
    SET v_new_salary = NEW.salary;   -- 即将写入的薪资
    
    -- 检测是否涨薪超过 50%
    IF v_new_salary > v_old_salary * 1.5 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '单次涨薪不能超过50%';
    END IF;
    
    -- 修改 NEW 值（BEFORE 触发器可以）
    IF NEW.updated_at IS NULL THEN
        SET NEW.updated_at = NOW();
    END IF;
END //

DELIMITER ;
```

## INSERT 触发器中的 NEW

```sql
DELIMITER //

-- BEFORE INSERT：NEW 有初始值（应用层传入的值），可以修改
CREATE TRIGGER trg_insert_new
BEFORE INSERT ON users
FOR EACH ROW
BEGIN
    -- 读取应用层传入的值
    SELECT NEW.username, NEW.email;  -- 可以读
    
    -- 修改即将插入的值
    SET NEW.username = LOWER(TRIM(NEW.username));
    SET NEW.created_at = IFNULL(NEW.created_at, NOW());
    
    -- OLD 不可用（INSERT 没有旧行）
    -- SELECT OLD.username;  -- 错误：INSERT 触发器中 OLD 不存在
END //

-- AFTER INSERT：NEW 是已写入的值（包含 AUTO_INCREMENT ID），不可修改
CREATE TRIGGER trg_after_insert_new
AFTER INSERT ON users
FOR EACH ROW
BEGIN
    -- NEW.id 此时有值（AUTO_INCREMENT 已生成）
    INSERT INTO user_profiles (user_id) VALUES (NEW.id);
    
    -- 不能修改 NEW
    -- SET NEW.username = 'modified';  -- 语法错误：AFTER 触发器中 NEW 不可写
END //

DELIMITER ;
```

## DELETE 触发器中的 OLD

```sql
DELIMITER //

-- BEFORE/AFTER DELETE：只有 OLD，没有 NEW
CREATE TRIGGER trg_delete_old
AFTER DELETE ON orders
FOR EACH ROW
BEGIN
    -- 通过 OLD 访问已删除行的所有字段
    INSERT INTO orders_archive (
        original_id, user_id, amount, status, deleted_at
    ) VALUES (
        OLD.id, OLD.user_id, OLD.amount, OLD.status, NOW()
    );
    
    -- NEW 不可用（DELETE 没有新行）
    -- SELECT NEW.id;  -- 错误：DELETE 触发器中 NEW 不存在
END //

DELIMITER ;
```

## 比较字段是否变化

```sql
DELIMITER //

-- UPDATE 触发器中，通过比较 OLD 和 NEW 检测字段变化
CREATE TRIGGER trg_check_changes
AFTER UPDATE ON products
FOR EACH ROW
BEGIN
    -- 价格变化
    IF OLD.price != NEW.price THEN
        INSERT INTO change_log (table_name, record_id, field, old_val, new_val, changed_at)
        VALUES ('products', OLD.id, 'price', OLD.price, NEW.price, NOW());
    END IF;
    
    -- 库存变化
    IF OLD.stock != NEW.stock THEN
        INSERT INTO change_log (table_name, record_id, field, old_val, new_val, changed_at)
        VALUES ('products', OLD.id, 'stock', OLD.stock, NEW.stock, NOW());
    END IF;
    
    -- 名称变化（字符串比较）
    IF OLD.name != NEW.name OR (OLD.name IS NULL AND NEW.name IS NOT NULL) THEN
        INSERT INTO change_log (table_name, record_id, field, old_val, new_val, changed_at)
        VALUES ('products', OLD.id, 'name', OLD.name, NEW.name, NOW());
    END IF;
END //

DELIMITER ;
```

## 适用场景

- **校验新值与旧值的关系**：薪资变化幅度、状态推进方向（UPDATE 触发器中同时使用 OLD 和 NEW）
- **记录变更前后的对比数据**：历史表中同时记录 old_value 和 new_value
- **根据新值自动填充关联字段**：状态变为"已发货"时自动设置 shipped_at（`SET NEW.shipped_at = NOW()`）

---

## 常见问题

**比较 NULL 时 `OLD.col != NEW.col` 够用吗？**

不够用。NULL 参与比较时结果是 NULL（不是 TRUE 也不是 FALSE），所以 `NULL != NULL` 结果是 NULL，不会进入 IF 分支。正确写法是：`IF (OLD.col != NEW.col) OR (OLD.col IS NULL AND NEW.col IS NOT NULL) OR (OLD.col IS NOT NULL AND NEW.col IS NULL)`，或者用 `NOT (OLD.col <=> NEW.col)`（`<=>` 是 NULL 安全的相等比较）。

---

## 注意事项

- 在 BEFORE 触发器中通过 `SET NEW.col = val` 修改值时，这个新值会实际写入数据库，而不会再次触发该触发器（不会无限递归）。
- OLD 和 NEW 不是真实的表，不能对它们执行 `SELECT * FROM OLD`，只能用 `OLD.col_name` 或 `NEW.col_name` 逐列访问。

---

## 总结

`OLD` 和 `NEW` 是触发器中的伪记录，分别代表操作前旧值和操作后新值。INSERT 只有 NEW（无 OLD），DELETE 只有 OLD（无 NEW），UPDATE 两者都有。BEFORE 触发器中可以通过 `SET NEW.col = val` 修改新值，AFTER 触发器中 NEW 只读。NULL 值比较应使用 `<=>` 安全等于操作符，避免漏检 NULL 值变化。
