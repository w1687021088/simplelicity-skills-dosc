# BEFORE DELETE 触发器

`BEFORE DELETE` 触发器在行数据被删除之前自动执行。可以通过 `OLD` 读取即将被删除的行数据，常用于阻止非法删除（通过 SIGNAL）、归档数据到历史表、级联处理关联数据等场景。`NEW` 在 DELETE 触发器中不可用。

---

## 语法

```sql
CREATE TRIGGER trigger_name
BEFORE DELETE ON table_name
FOR EACH ROW
BEGIN
    -- OLD.col_name：即将被删除的行数据（只读）
    -- NEW 不可用
END;
```

- `OLD`：代表即将被删除的行，只读
- BEFORE DELETE 中用 `SIGNAL` 抛出错误可以阻止删除操作

---

## 基本示例：阻止非法删除

```sql
DELIMITER //

-- 阻止删除有关联订单的用户
CREATE TRIGGER trg_users_before_delete
BEFORE DELETE ON users
FOR EACH ROW
BEGIN
    DECLARE v_order_count INT;
    
    SELECT COUNT(*) INTO v_order_count
    FROM orders
    WHERE user_id = OLD.id AND status NOT IN (3, 4);  -- 有未完成的订单
    
    IF v_order_count > 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '该用户存在未完成的订单，不能删除';
    END IF;
END //

-- 阻止删除超级管理员
CREATE TRIGGER trg_admins_before_delete
BEFORE DELETE ON users
FOR EACH ROW
BEGIN
    IF OLD.role = 'super_admin' THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '超级管理员账号不允许删除';
    END IF;
END //

DELIMITER ;
```

## 删除前归档数据

```sql
DELIMITER //

-- 删除订单前，将数据归档到历史表
CREATE TRIGGER trg_orders_before_delete
BEFORE DELETE ON orders
FOR EACH ROW
BEGIN
    INSERT INTO orders_archive (
        original_id,
        user_id,
        order_no,
        amount,
        status,
        created_at,
        archived_at,
        archive_reason
    ) VALUES (
        OLD.id,
        OLD.user_id,
        OLD.order_no,
        OLD.amount,
        OLD.status,
        OLD.created_at,
        NOW(),
        '手动删除'
    );
END //

DELIMITER ;
```

## 级联清理关联数据

```sql
DELIMITER //

-- 删除部门前，自动清理或重新分配关联员工
CREATE TRIGGER trg_departments_before_delete
BEFORE DELETE ON departments
FOR EACH ROW
BEGIN
    DECLARE v_employee_count INT;
    
    SELECT COUNT(*) INTO v_employee_count
    FROM employees WHERE dept_id = OLD.id AND status = 1;
    
    -- 有在职员工则阻止删除
    IF v_employee_count > 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '该部门有在职员工，请先将员工转移到其他部门';
    END IF;
    
    -- 将已离职员工的 dept_id 设为 NULL（清理关联）
    UPDATE employees SET dept_id = NULL
    WHERE dept_id = OLD.id AND status = 0;
END //

DELIMITER ;
```

## BEFORE DELETE 与软删除的关系

```sql
DELIMITER //

-- 实现"假删除变软删除"：拦截真正的 DELETE，改为设置 deleted_at
-- 注意：这种方式会把 DELETE 转为 UPDATE，然后 SIGNAL 取消真正的删除
-- 更常见的做法是在应用层用 UPDATE 代替 DELETE

CREATE TRIGGER trg_products_before_delete
BEFORE DELETE ON products
FOR EACH ROW
BEGIN
    -- 将删除操作转为软删除
    UPDATE products SET deleted_at = NOW() WHERE id = OLD.id;
    
    -- 取消真正的删除（DATA 已通过 UPDATE 标记为软删除）
    SIGNAL SQLSTATE '45000'
    SET MESSAGE_TEXT = '使用软删除，数据已标记为已删除状态';
    -- 注意：这种模式在实际中不推荐，会让调用者收到错误
    -- 推荐在应用层直接执行 UPDATE ... SET deleted_at = NOW() 代替 DELETE
END //

DELIMITER ;
```

## 适用场景

- **删除前校验**：确认没有关联的活跃记录才允许删除（外键约束的补充）
- **数据归档**：删除前将数据备份到历史表，保留操作痕迹
- **清理关联数据**：删除主记录前处理相关联的从属记录（而不依赖数据库外键级联）
- **审计记录**：记录谁删除了哪条数据（DELETE 前记录 OLD 行数据）

---

## 常见问题

**BEFORE DELETE 触发器执行完毕后，DELETE 一定会发生吗？**

只要触发器没有 SIGNAL 抛出错误，DELETE 就会正常执行。如果需要条件性阻止删除，必须在触发器中显式使用 SIGNAL。

---

## 注意事项

- `TRUNCATE TABLE` 不会触发行级触发器（包括 BEFORE DELETE），因为 TRUNCATE 是 DDL 操作，不是逐行删除。如果需要在清空表时触发操作，只能用 `DELETE FROM table`（有触发器）而不是 TRUNCATE。
- BEFORE DELETE 触发器中对 `OLD` 数据所做的 UPDATE 操作（如修改 OLD.status）没有意义——UPDATE 触发的是 UPDATE 触发器，且即将删除的行修改后也会被删除，没有持久效果。

---

## 总结

`BEFORE DELETE` 触发器在行删除前执行，通过 `OLD` 读取即将删除的数据，通过 `SIGNAL` 可以阻止删除。常用于删除前校验（有关联记录则拒绝）、删除前归档（写入历史表）、级联清理关联数据。`NEW` 在 DELETE 触发器中不可用。TRUNCATE TABLE 不触发行级触发器。
