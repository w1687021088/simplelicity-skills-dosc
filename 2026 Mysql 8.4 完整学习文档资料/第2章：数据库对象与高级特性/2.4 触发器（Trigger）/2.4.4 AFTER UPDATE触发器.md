# AFTER UPDATE 触发器

`AFTER UPDATE` 触发器在行数据成功更新之后自动执行。此时可以通过 `OLD` 读取更新前的值，通过 `NEW` 读取更新后的值（只读，不能再修改）。常用于记录变更历史、同步关联表数据、发送通知等场景。

---

## 语法

```sql
CREATE TRIGGER trigger_name
AFTER UPDATE ON table_name
FOR EACH ROW
BEGIN
    -- OLD.col_name：更新前的旧值（只读）
    -- NEW.col_name：更新后的新值（只读）
END;
```

- `OLD` 和 `NEW` 都是只读的（数据已更新，不能再改）
- AFTER UPDATE 中抛出异常会回滚整个 UPDATE 操作

---

## 基本示例：记录变更历史

```sql
DELIMITER //

-- 员工薪资变更后，记录变更历史
CREATE TRIGGER trg_employees_after_update
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
    -- 只在薪资发生变化时记录
    IF NEW.salary != OLD.salary THEN
        INSERT INTO salary_change_log (
            employee_id,
            old_salary,
            new_salary,
            change_amount,
            change_pct,
            changed_at,
            changed_by
        ) VALUES (
            OLD.id,
            OLD.salary,
            NEW.salary,
            NEW.salary - OLD.salary,
            ROUND((NEW.salary - OLD.salary) / OLD.salary * 100, 2),
            NOW(),
            USER()  -- 记录操作者（当前 MySQL 连接用户）
        );
    END IF;
END //

DELIMITER ;
```

## 状态变化触发联动

```sql
DELIMITER //

-- 订单状态更新后，根据新状态执行对应的联动操作
CREATE TRIGGER trg_orders_after_update
AFTER UPDATE ON orders
FOR EACH ROW
BEGIN
    -- 订单状态从"待发货"变为"已发货"
    IF OLD.status = 1 AND NEW.status = 2 THEN
        -- 更新用户的最近购买时间
        UPDATE users SET last_purchase_at = NOW() WHERE id = NEW.user_id;
        
        -- 插入发货通知
        INSERT INTO notifications (user_id, type, content, created_at)
        VALUES (NEW.user_id, 'SHIPPING', 
                CONCAT('您的订单 ', NEW.order_no, ' 已发货'),
                NOW());
    END IF;
    
    -- 订单状态变为"已完成"
    IF OLD.status != 3 AND NEW.status = 3 THEN
        -- 增加用户完成订单数
        UPDATE user_stats SET completed_orders = completed_orders + 1
        WHERE user_id = NEW.user_id;
    END IF;
    
    -- 订单状态变为"已取消"
    IF OLD.status != 4 AND NEW.status = 4 THEN
        -- 恢复库存
        UPDATE inventory SET quantity = quantity + 1
        WHERE product_id = NEW.product_id;
    END IF;
END //

DELIMITER ;
```

## 同步汇总表

```sql
DELIMITER //

-- 账户余额更新后，同步更新今日汇总统计
CREATE TRIGGER trg_accounts_after_update
AFTER UPDATE ON accounts
FOR EACH ROW
BEGIN
    DECLARE v_diff DECIMAL(12,2);
    SET v_diff = NEW.balance - OLD.balance;
    
    IF v_diff > 0 THEN
        -- 充值：增加当日充值总额
        INSERT INTO daily_stats (stat_date, total_recharge)
        VALUES (CURDATE(), v_diff)
        ON DUPLICATE KEY UPDATE total_recharge = total_recharge + v_diff;
    ELSEIF v_diff < 0 THEN
        -- 消费：增加当日消费总额
        INSERT INTO daily_stats (stat_date, total_spend)
        VALUES (CURDATE(), ABS(v_diff))
        ON DUPLICATE KEY UPDATE total_spend = total_spend + ABS(v_diff);
    END IF;
END //

DELIMITER ;
```

## 使用 IF 检测字段变化

```sql
DELIMITER //

CREATE TRIGGER trg_products_after_update
AFTER UPDATE ON products
FOR EACH ROW
BEGIN
    -- 只检测关心的字段是否变化
    -- 价格变化：记录价格历史
    IF NEW.price != OLD.price THEN
        INSERT INTO price_history (product_id, old_price, new_price, changed_at)
        VALUES (OLD.id, OLD.price, NEW.price, NOW());
    END IF;
    
    -- 库存降至 0：触发缺货提醒
    IF NEW.stock = 0 AND OLD.stock > 0 THEN
        INSERT INTO stock_alerts (product_id, alert_type, created_at)
        VALUES (NEW.id, 'OUT_OF_STOCK', NOW());
    END IF;
    
    -- 库存从 0 恢复：清除缺货提醒
    IF NEW.stock > 0 AND OLD.stock = 0 THEN
        DELETE FROM stock_alerts
        WHERE product_id = NEW.id AND alert_type = 'OUT_OF_STOCK';
    END IF;
END //

DELIMITER ;
```

## 适用场景

- **变更历史追踪**：记录字段修改前后的值（价格历史、薪资变更日志）
- **状态机联动**：根据状态的具体变化方向，触发不同的后续业务操作
- **统计数据同步**：余额变化后同步更新统计汇总表
- **事件通知**：状态变更后插入通知记录，供消费队列推送

---

## 常见问题

**AFTER UPDATE 触发器每次只处理一行吗？**

是的，MySQL 触发器是行级的（FOR EACH ROW），每个被 UPDATE 影响的行都会触发一次。`UPDATE orders SET status = 2 WHERE status = 1` 影响 100 行，触发器就执行 100 次，每次 OLD 和 NEW 都是当前行的数据。

---

## 注意事项

- AFTER UPDATE 触发器中不能修改 NEW 的值（数据已写入），如果需要修改，应在 BEFORE UPDATE 中处理。
- AFTER UPDATE 触发器中对其他表的 DML 操作（INSERT/UPDATE）也会触发那些表的触发器，注意避免触发器链的循环。

---

## 总结

`AFTER UPDATE` 触发器在行成功更新后执行，OLD 和 NEW 均为只读。适合记录变更历史（通过 `OLD.salary != NEW.salary` 检测字段变化）、状态机联动（根据 OLD.status → NEW.status 的变化执行不同操作）、同步统计汇总表。与 BEFORE UPDATE 的区别：BEFORE 可以修改 NEW/拦截更新，AFTER 适合事后联动。
