# BEFORE UPDATE 触发器

`BEFORE UPDATE` 触发器在行数据被修改之前自动执行。可以通过 `OLD` 读取更新前的值，通过 `NEW` 读取或修改即将写入的新值。常用于数据校验、自动维护时间戳、防止特定字段被修改等场景。如果在触发器中 `SIGNAL` 抛出错误，UPDATE 操作会被取消。

---

## 语法

```sql
CREATE TRIGGER trigger_name
BEFORE UPDATE ON table_name
FOR EACH ROW
BEGIN
    -- OLD.col_name：更新前的旧值（只读）
    -- NEW.col_name：即将写入的新值（可读可写）
    SET NEW.col_name = expression;
END;
```

- `OLD`：更新前的行，只读
- `NEW`：即将写入的新行，可以修改（修改 NEW 会影响实际写入的值）

---

## 基本示例：自动维护 updated_at

```sql
DELIMITER //

-- 任何字段更新时，自动更新 updated_at 时间戳
CREATE TRIGGER trg_users_before_update
BEFORE UPDATE ON users
FOR EACH ROW
BEGIN
    SET NEW.updated_at = NOW();
END //

DELIMITER ;

-- 更新用户邮箱，updated_at 自动更新
UPDATE users SET email = 'new@example.com' WHERE id = 5;
-- updated_at 被自动设置为当前时间
```

## 数据校验：防止非法更新

```sql
DELIMITER //

-- 订单状态只能向前推进，不能回退
CREATE TRIGGER trg_orders_before_update
BEFORE UPDATE ON orders
FOR EACH ROW
BEGIN
    -- 已完成或已取消的订单不能修改状态
    IF OLD.status IN (3, 4) AND NEW.status != OLD.status THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '已完成或已取消的订单不能修改状态';
    END IF;
    
    -- 状态只能向前推进（不能回退）
    IF NEW.status < OLD.status THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '订单状态不能回退';
    END IF;
    
    -- 自动更新处理时间
    SET NEW.updated_at = NOW();
    
    -- 如果状态变为已发货（2），自动设置发货时间
    IF NEW.status = 2 AND OLD.status = 1 THEN
        SET NEW.shipped_at = NOW();
    END IF;
END //

DELIMITER ;
```

## 保护关键字段不被修改

```sql
DELIMITER //

-- 防止 user_id（创建者）被修改
CREATE TRIGGER trg_orders_protect_fields
BEFORE UPDATE ON orders
FOR EACH ROW
BEGIN
    -- 强制 user_id 不变（即使应用层传了新值，也保持旧值）
    SET NEW.user_id = OLD.user_id;
    
    -- 防止 created_at 被修改
    SET NEW.created_at = OLD.created_at;
END //

DELIMITER ;
```

## 检测字段是否被修改

```sql
DELIMITER //

CREATE TRIGGER trg_employees_salary_audit
BEFORE UPDATE ON employees
FOR EACH ROW
BEGIN
    -- 检测薪资是否发生变化
    IF NEW.salary != OLD.salary THEN
        -- 薪资变化前的校验：降薪不能超过 20%
        IF NEW.salary < OLD.salary * 0.8 THEN
            SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = '单次降薪不能超过20%';
        END IF;
        
        -- 记录薪资变更（到变更历史表）
        INSERT INTO salary_history (
            employee_id, old_salary, new_salary, changed_at
        ) VALUES (
            OLD.id, OLD.salary, NEW.salary, NOW()
        );
    END IF;
    
    SET NEW.updated_at = NOW();
END //

DELIMITER ;
```

## OLD 与 NEW 的可用性

| 操作 | OLD 可用 | NEW 可用 | NEW 可修改 |
|------|---------|---------|----------|
| BEFORE INSERT | 否 | 是 | 是 |
| AFTER INSERT | 否 | 是 | 否 |
| BEFORE UPDATE | 是 | 是 | 是 |
| AFTER UPDATE | 是 | 是 | 否 |
| BEFORE DELETE | 是 | 否 | 否 |
| AFTER DELETE | 是 | 否 | 否 |

---

## 适用场景

- **自动维护时间戳**：`SET NEW.updated_at = NOW()` 是最常见的 BEFORE UPDATE 用途
- **状态机保护**：确保状态码只能按合法顺序推进，不能跳跃或回退
- **只读字段保护**：通过 `SET NEW.created_at = OLD.created_at` 防止关键字段被修改
- **条件式时间记录**：根据新旧状态差异，自动设置特定事件的时间戳（如 shipped_at）

---

## 常见问题

**BEFORE UPDATE 如果抛出错误，UPDATE 一定会被取消吗？**

是的，如果触发器中调用 `SIGNAL` 抛出错误，当前 UPDATE 操作会被立即中止并回滚，数据不会发生任何变化。

---

## 注意事项

- `BEFORE UPDATE` 触发器对每个被 UPDATE 影响的**行**触发一次。`UPDATE users SET status = 1 WHERE dept_id = 3` 影响了 50 行，触发器就执行 50 次，每次有独立的 OLD 和 NEW。
- 在 BEFORE UPDATE 中修改了 NEW 值，这个修改会实际写入数据库，但不会触发再次执行触发器（不会递归触发）。

---

## 总结

`BEFORE UPDATE` 触发器在行更新前执行，可以读取 `OLD`（旧值）和 `NEW`（新值），并通过 `SET NEW.col = val` 修改即将写入的值。常用于自动维护 `updated_at`、状态机校验（防止状态回退）、保护只读字段（强制 `SET NEW.created_at = OLD.created_at`）。通过 `SIGNAL` 可以取消整个 UPDATE 操作。
