# AFTER INSERT 触发器

`AFTER INSERT` 触发器在行数据成功插入到表之后自动执行。此时可以通过 `NEW` 伪记录读取已插入的所有列值（包括 AUTO_INCREMENT 生成的 ID），常用于写入审计日志、同步统计数据、更新关联表等场景。

---

## 语法

```sql
CREATE TRIGGER trigger_name
AFTER INSERT ON table_name
FOR EACH ROW
BEGIN
    -- 通过 NEW.col_name 读取已插入的值（不能修改）
END;
```

- `NEW`：代表已插入的行，只读（不能再修改，数据已写入磁盘）
- `NEW.id` 此时有值（AUTO_INCREMENT 已生成）
- AFTER INSERT 中抛出异常会回滚整个 INSERT 操作

---

## 基本示例：写入审计日志

```sql
DELIMITER //

-- 记录用户注册日志
CREATE TRIGGER trg_users_after_insert
AFTER INSERT ON users
FOR EACH ROW
BEGIN
    INSERT INTO user_audit_log (
        user_id,
        action,
        details,
        created_at
    ) VALUES (
        NEW.id,                           -- AUTO_INCREMENT ID，此时已生成
        'REGISTER',
        CONCAT('用户注册：', NEW.username, ' (', NEW.email, ')'),
        NOW()
    );
END //

DELIMITER ;

-- 注册用户后自动写入日志
INSERT INTO users (username, email, is_active) VALUES ('bob', 'bob@example.com', 1);
-- 触发器自动在 user_audit_log 插入一条审计记录
```

## 同步统计数据

```sql
DELIMITER //

-- 订单插入后，更新用户的订单统计
CREATE TRIGGER trg_orders_after_insert
AFTER INSERT ON orders
FOR EACH ROW
BEGIN
    -- 更新用户订单计数和累计消费
    INSERT INTO user_stats (user_id, order_count, total_spent)
    VALUES (NEW.user_id, 1, NEW.amount)
    ON DUPLICATE KEY UPDATE
        order_count = order_count + 1,
        total_spent = total_spent + NEW.amount,
        updated_at  = NOW();
END //

-- 产品表插入后，初始化库存记录
CREATE TRIGGER trg_products_after_insert
AFTER INSERT ON products
FOR EACH ROW
BEGIN
    INSERT INTO inventory (product_id, quantity, reserved, updated_at)
    VALUES (NEW.id, NEW.initial_stock, 0, NOW());
END //

DELIMITER ;
```

## 级联创建关联数据

```sql
DELIMITER //

-- 公司注册后，自动创建超级管理员账户
CREATE TRIGGER trg_companies_after_insert
AFTER INSERT ON companies
FOR EACH ROW
BEGIN
    INSERT INTO company_admins (company_id, role, is_owner, created_at)
    VALUES (NEW.id, 'super_admin', 1, NOW());
    
    INSERT INTO company_settings (company_id, max_users, created_at)
    VALUES (NEW.id, 10, NOW());  -- 默认10个用户名额
END //

DELIMITER ;
```

## AFTER INSERT 中抛出错误

```sql
DELIMITER //

-- AFTER INSERT 中的错误会导致整个 INSERT 回滚
CREATE TRIGGER trg_orders_after_insert_check
AFTER INSERT ON orders
FOR EACH ROW
BEGIN
    -- 检查用户是否被封禁（理论上 BEFORE INSERT 更合适，这里仅演示）
    DECLARE v_is_banned TINYINT;
    SELECT is_banned INTO v_is_banned FROM users WHERE id = NEW.user_id;
    
    IF v_is_banned = 1 THEN
        -- AFTER INSERT 中抛出异常：整个 INSERT 事务回滚
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '封禁用户不能下单';
    END IF;
END //

DELIMITER ;
```

## BEFORE vs AFTER INSERT 选择指南

| 需求 | 推荐时机 |
|------|---------|
| 修改即将插入的值 | BEFORE INSERT |
| 数据校验（阻止插入）| BEFORE INSERT |
| 自动填充字段（created_at 等）| BEFORE INSERT |
| 获取自增 ID | AFTER INSERT |
| 写入审计日志 | AFTER INSERT |
| 同步统计/汇总表 | AFTER INSERT |
| 级联创建关联数据 | AFTER INSERT |

---

## 适用场景

- **审计日志**：记录谁在何时创建了哪条数据（用于安全审计和历史追踪）
- **统计汇总**：INSERT 后同步更新计数器、累计值（如用户订单数、销售额）
- **初始化关联数据**：新记录插入后，在关联表中创建默认的从属记录

---

## 常见问题

**AFTER INSERT 触发器中能修改刚插入的行吗？**

不能通过修改 `NEW` 来改变已插入的值（NEW 在 AFTER 中是只读的）。如果需要修改，可以在触发器中用 `UPDATE table SET ... WHERE id = NEW.id` 来更新刚插入的行，但这会增加额外的 UPDATE 操作，性能有影响。更好的做法是用 BEFORE INSERT 触发器在写入前修改数据。

---

## 注意事项

- AFTER INSERT 触发器中执行的 INSERT/UPDATE 操作也会触发那些表上的触发器（级联触发），需要确保不会造成触发器链的无限递归。
- 在高并发写入场景中，触发器带来的额外 INSERT/UPDATE 操作会增加延迟。对于极高 QPS 的表，考虑是否能用批量异步任务替代触发器做统计汇总。

---

## 总结

`AFTER INSERT` 触发器在行成功插入后执行，可以读取 `NEW` 的所有列值（包括 AUTO_INCREMENT 生成的 ID），但不能修改 NEW。常用于写审计日志、更新统计汇总、级联初始化关联数据。AFTER 中抛出异常会回滚整个 INSERT 操作。选择 BEFORE 还是 AFTER：需要修改或阻止数据用 BEFORE，需要 AUTO_INCREMENT ID 或在成功插入后做关联操作用 AFTER。
