# BEFORE INSERT 触发器

`BEFORE INSERT` 触发器在行数据插入到表之前自动执行。此时可以通过 `NEW` 伪记录读取和修改即将插入的列值，从而实现数据校验、自动填充字段、格式化输入等功能。如果触发器中调用 `SIGNAL` 抛出错误，INSERT 操作会被终止。

---

## 语法

```sql
CREATE TRIGGER trigger_name
BEFORE INSERT ON table_name
FOR EACH ROW
BEGIN
    -- 通过 NEW.col_name 读取或修改即将插入的值
    SET NEW.col_name = expression;
END;
```

- `NEW`：代表即将插入的行，可以读取（`NEW.col`）和修改（`SET NEW.col = val`）
- `FOR EACH ROW`：每插入一行触发一次（MySQL 只支持行级触发器）
- BEFORE INSERT 的修改在实际写入磁盘之前发生，新值会被持久化

---

## 基本示例：自动填充字段

```sql
DELIMITER //

-- 自动填充 created_at 和 updated_at（即使应用层没有传入）
CREATE TRIGGER trg_users_before_insert
BEFORE INSERT ON users
FOR EACH ROW
BEGIN
    IF NEW.created_at IS NULL THEN
        SET NEW.created_at = NOW();
    END IF;
    SET NEW.updated_at = NOW();
    -- 用户名转小写处理
    SET NEW.username = LOWER(TRIM(NEW.username));
END //

DELIMITER ;

-- 验证
INSERT INTO users (username, email) VALUES ('  Alice  ', 'alice@example.com');
-- username 实际存储为 'alice'（去空格+转小写）
-- created_at 和 updated_at 自动填充
```

## 数据验证：阻止非法输入

```sql
DELIMITER //

-- 在插入前验证数据合法性，不合法则用 SIGNAL 阻止插入
CREATE TRIGGER trg_products_validate_before_insert
BEFORE INSERT ON products
FOR EACH ROW
BEGIN
    -- 校验价格非负
    IF NEW.price < 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '商品价格不能为负数';
    END IF;
    
    -- 校验库存非负
    IF NEW.stock < 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '初始库存不能为负数';
    END IF;
    
    -- 自动处理名称：去除首尾空格
    SET NEW.name = TRIM(NEW.name);
    
    -- 如果没有传入创建时间，自动设置
    IF NEW.created_at IS NULL THEN
        SET NEW.created_at = NOW();
    END IF;
END //

DELIMITER ;

-- 测试验证
INSERT INTO products (name, price, stock) VALUES ('手机', -100, 10);
-- ERROR 1644 (45000): 商品价格不能为负数（INSERT 被阻止）

INSERT INTO products (name, price, stock) VALUES ('手机', 2999, 100);
-- 成功插入（name='手机', price=2999, stock=100）
```

## 生成衍生字段

```sql
DELIMITER //

-- 订单表插入时自动生成订单编号
CREATE TRIGGER trg_orders_gen_order_no
BEFORE INSERT ON orders
FOR EACH ROW
BEGIN
    -- 生成格式：ORD + 年月日 + 6位随机数
    IF NEW.order_no IS NULL OR NEW.order_no = '' THEN
        SET NEW.order_no = CONCAT(
            'ORD',
            DATE_FORMAT(NOW(), '%Y%m%d'),
            LPAD(FLOOR(RAND() * 1000000), 6, '0')
        );
    END IF;
    
    -- 计算总金额（如果没传）
    IF NEW.total_amount IS NULL THEN
        SET NEW.total_amount = NEW.quantity * NEW.unit_price;
    END IF;
END //

DELIMITER ;
```

## BEFORE INSERT 与 AFTER INSERT 的对比

| 对比 | BEFORE INSERT | AFTER INSERT |
|------|--------------|-------------|
| 执行时机 | 行写入前 | 行写入后 |
| 修改 NEW 值 | 可以（影响实际存储的值）| 不可以（数据已写入）|
| 获取自增 ID | 不能（还未生成）| 可以（NEW.id 有值）|
| 阻止插入 | 可以（用 SIGNAL）| 不能（数据已写入）|
| 适用场景 | 数据校验、自动填充、格式化 | 写操作日志、同步统计数据 |

---

## 适用场景

- **数据校验**：在插入前验证字段合法性（价格非负、日期合理），不合法则 SIGNAL 阻止
- **自动填充字段**：插入时自动设置 `created_at`、`created_by`、`uuid`、`order_no` 等字段
- **数据格式化**：用户名转小写、手机号去空格、状态码默认值

---

## 常见问题

**BEFORE INSERT 触发器能修改所有列的值吗？**

可以，包括主键（如果不是 AUTO_INCREMENT 或者插入了显式值）。但不能修改 AUTO_INCREMENT 生成的 ID（它在 BEFORE INSERT 时还没有生成）。修改 AUTO_INCREMENT 列的 NEW 值没有意义（即使设置也会被覆盖）。需要获取自增 ID 应在 AFTER INSERT 触发器中使用 `NEW.id`。

---

## 注意事项

- 一个表只能有一个 BEFORE INSERT 触发器（MySQL 每个事件/时机只允许一个触发器）。如果需要多个操作，将所有逻辑写在同一个触发器的 BEGIN...END 中。
- BEFORE INSERT 触发器中的修改（`SET NEW.col = val`）会影响实际写入的值，修改正确与否直接影响数据质量，务必测试覆盖所有字段修改逻辑。

---

## 总结

`BEFORE INSERT` 触发器在行数据写入前执行，可以通过 `SET NEW.col = val` 修改即将插入的值，通过 `SIGNAL` 阻止非法插入。常用于数据校验、自动填充时间戳/编号、格式化输入。与 AFTER INSERT 的核心区别：BEFORE 可以修改数据和阻止插入，AFTER 可以获取自增 ID 但无法修改数据。
