# 连接控制插件 Connection-Control

Connection-Control 插件是 MySQL 提供的防暴力破解安全组件，通过监控连接失败次数，在达到阈值后对后续连接尝试施加递增延迟，从而减缓暴力破解攻击的速度。该插件包含两个组件：`CONNECTION_CONTROL`（核心逻辑，实施连接延迟）和 `CONNECTION_CONTROL_FAILED_LOGIN_ATTEMPTS`（信息表，提供失败登录的监控数据）。在面向公网的数据库或安全合规要求较高的环境中，Connection-Control 插件是一道重要的防御层。

---

## 安装 Connection-Control 插件

```sql
-- 方法1：运行时安装
INSTALL PLUGIN CONNECTION_CONTROL SONAME 'connection_control.so';
INSTALL PLUGIN CONNECTION_CONTROL_FAILED_LOGIN_ATTEMPTS
    SONAME 'connection_control.so';
-- Windows 上使用 .dll 后缀

-- 方法2：my.cnf 配置文件方式（推荐，每次启动自动加载）
-- [mysqld]
-- plugin-load-add=connection_control.so
-- connection-control-failed-connections-threshold=3
-- connection-control-min-connection-delay=1000
-- connection-control-max-connection-delay=86400000

-- 验证安装：
SELECT PLUGIN_NAME, PLUGIN_STATUS FROM information_schema.PLUGINS
WHERE PLUGIN_NAME LIKE 'CONNECTION_CONTROL%';
-- CONNECTION_CONTROL: ACTIVE
-- CONNECTION_CONTROL_FAILED_LOGIN_ATTEMPTS: ACTIVE
```

## 核心参数配置

```sql
-- 查看当前配置：
SHOW VARIABLES LIKE 'connection_control%';

-- 1. connection_control_failed_connections_threshold
-- 连续失败登录次数阈值（超过后开始施加延迟）
-- 默认值：3
-- 范围：0 到 2147483647（0 表示禁用延迟功能）
SET GLOBAL connection_control_failed_connections_threshold = 3;
-- 连续失败 3 次后，第 4 次开始延迟

-- 2. connection_control_min_connection_delay
-- 最小延迟时间（毫秒）
-- 默认值：1000（1秒）
-- 范围：1000 到 2147483647
SET GLOBAL connection_control_min_connection_delay = 2000;  -- 2秒

-- 3. connection_control_max_connection_delay
-- 最大延迟时间（毫秒）
-- 默认值：2147483647（约 24.8 天）
-- 实际使用中通常设置为合理上限
SET GLOBAL connection_control_max_connection_delay = 86400000;  -- 24小时
```

## 延迟计算规则

```
延迟递增公式：
delay = min_delay × (failed_attempts - threshold)

示例（threshold=3, min_delay=2000ms）：
第1次失败：无延迟（未超过阈值）
第2次失败：无延迟
第3次失败：无延迟（刚好等于阈值，不延迟）
第4次失败：延迟 2000ms × (4-3) = 2秒
第5次失败：延迟 2000ms × (5-3) = 4秒
第6次失败：延迟 2000ms × (6-3) = 6秒
第10次失败：延迟 2000ms × (10-3) = 14秒
第50次失败：延迟 2000ms × (50-3) = 94秒

延迟上限受 max_connection_delay 限制：
如果 max_connection_delay = 60000（60秒），
第50次计算出 94秒 → 实际延迟 = 60秒（取上限值）

延迟的含义：
- 延迟发生在连接建立阶段（认证之前）
- 在延迟期间，该连接线程被阻塞，不占用 CPU 但占用一个连接名额
- 攻击者每次尝试都需要等待更长时间，大幅降低暴力破解效率
```

## 监控失败登录尝试

```sql
-- 通过 CONNECTION_CONTROL_FAILED_LOGIN_ATTEMPTS 表监控：
SELECT * FROM information_schema.CONNECTION_CONTROL_FAILED_LOGIN_ATTEMPTS;
-- 输出：
-- USERHOST                    | FAILED_ATTEMPTS
-- 'hacker'@'192.168.1.100'   | 15
-- 'admin'@'10.0.0.50'        | 5
-- 'root'@'203.0.113.1'       | 47

-- 该表只记录超过阈值的失败尝试
-- 成功登录后，该用户的计数器重置为 0

-- 结合 Performance Schema 查看连接延迟的状态变量：
SHOW GLOBAL STATUS LIKE 'Connection_control%';
-- Connection_control_delay_generated: 123
-- → 已经产生了 123 次连接延迟（有 123 次连接因失败次数超过阈值而被延迟）
```

## 生产环境推荐配置

```ini
[mysqld]
# 加载连接控制插件
plugin-load-add=connection_control.so

# 连续失败 5 次后开始延迟（允许用户有几次输错密码的机会）
connection-control-failed-connections-threshold=5

# 最小延迟 2 秒（第 6 次失败延迟 2 秒）
connection-control-min-connection-delay=2000

# 最大延迟 5 分钟（防止单个连接被无限期阻塞）
connection-control-max-connection-delay=300000

# 配合 max_connect_errors 使用：
# max_connect_errors 控制主机级别的连接错误上限
# 超过后直接封锁该主机（需要 FLUSH HOSTS 解除）
max_connect_errors=100
```

## 适用场景

- **面向公网的 MySQL 服务器**：当 MySQL 端口（3306）暴露在公网时，暴力破解攻击会频繁尝试常见用户名/密码组合。Connection-Control 插件对超过阈值的失败连接施加递增延迟，使攻击者每秒只能尝试极少次数，从根本上降低暴力破解的可行性
- **多租户 SaaS 平台的数据库安全**：多个租户共用一个 MySQL 实例，某个租户的凭据可能被泄露或攻击。Connection-Control 插件可以限制针对单个用户的暴力破解，同时不影响其他用户的正常连接

## 常见问题

**Connection-Control 延迟会不会影响正常用户的连接？**

正常用户（密码正确）的连接不受 Connection-Control 影响。延迟只在连续失败次数超过阈值后才触发，且一旦成功登录，该用户的失败计数器立即重置为 0。需要注意的是，延迟是按"用户+来源主机"维度计算的（如 `'app'@'10.0.0.1'` 和 `'app'@'10.0.0.2'` 是两个独立的计数器），某个来源 IP 的失败不会影响其他 IP 的正常连接。如果正常用户偶尔输错密码（如 2~3 次），只要不超过阈值就不会有延迟。

---

## 注意事项

- Connection-Control 的延迟是在**服务端连接线程中阻塞**实现的，延迟期间该线程占用一个 `max_connections` 连接名额但不消耗 CPU。如果攻击者大量并发连接（每个都触发长延迟），可能耗尽 `max_connections` 连接数，导致正常用户无法连接。建议配合防火墙规则（`iptables`）或 `max_connect_errors` 在网络层限制恶意 IP，而不是仅依赖 Connection-Control。
- Connection-Control 插件的失败计数器存储在内存中，MySQL 重启后清零。如果攻击者在 MySQL 重启后立即发起攻击，计数器从零开始，需要再次达到阈值才会触发延迟。

## 总结

Connection-Control 插件通过对连续失败登录施加递增延迟来防御暴力破解攻击。安装：`INSTALL PLUGIN CONNECTION_CONTROL SONAME 'connection_control.so'`。核心参数：`connection_control_failed_connections_threshold`（失败次数阈值，默认 3）、`connection_control_min_connection_delay`（最小延迟，默认 1000ms）、`connection_control_max_connection_delay`（最大延迟上限）。延迟公式：`min_delay × (失败次数 - 阈值)`，递增至上限。监控：`information_schema.CONNECTION_CONTROL_FAILED_LOGIN_ATTEMPTS` 表查看各用户的失败次数。成功登录后计数器重置。建议配合防火墙和 `max_connect_errors` 使用，形成多层防御体系。
