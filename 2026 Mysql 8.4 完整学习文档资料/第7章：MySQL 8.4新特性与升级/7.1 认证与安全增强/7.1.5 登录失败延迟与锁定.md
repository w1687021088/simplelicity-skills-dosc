# 登录失败延迟与锁定

MySQL 提供了多层次的登录失败防护机制，从连接级别的延迟（Connection-Control 插件）到账户级别的锁定（`FAILED_LOGIN_ATTEMPTS` 和 `PASSWORD_LOCK_TIME`），再到主机级别的封锁（`max_connect_errors`）。MySQL 8.0.19 引入的**账户级别登录失败锁定**是其中最精细的控制方式，可以为每个用户单独设置"连续失败 N 次后锁定 M 天"的策略，是企业安全合规的重要工具。

---

## 账户级别的失败锁定（MySQL 8.0.19+）

```sql
-- CREATE USER 或 ALTER USER 时指定失败锁定策略：

-- 连续失败 5 次后，锁定账户 1 天（24小时）
CREATE USER 'app_user'@'%'
    IDENTIFIED BY 'secure_password'
    FAILED_LOGIN_ATTEMPTS 5
    PASSWORD_LOCK_TIME 1;

-- 连续失败 3 次后，锁定账户 3 天
ALTER USER 'admin'@'localhost'
    FAILED_LOGIN_ATTEMPTS 3
    PASSWORD_LOCK_TIME 3;

-- 连续失败 10 次后，永久锁定（需要 DBA 手动解锁）
CREATE USER 'sensitive_user'@'%'
    IDENTIFIED BY 'password'
    FAILED_LOGIN_ATTEMPTS 10
    PASSWORD_LOCK_TIME UNBOUNDED;

-- 禁用失败锁定（默认行为）
ALTER USER 'app_user'@'%'
    FAILED_LOGIN_ATTEMPTS 0
    PASSWORD_LOCK_TIME 0;

-- 查看用户的锁定策略：
SELECT User, Host,
       User_attributes->>'$.Password_locking.failed_login_attempts' AS max_failures,
       User_attributes->>'$.Password_locking.password_lock_time_days' AS lock_days
FROM mysql.user
WHERE User = 'app_user';
```

## 锁定状态查看与手动解锁

```sql
-- 查看当前被锁定的账户：
SELECT User, Host, account_locked,
       User_attributes->>'$.Password_locking.failed_login_attempts' AS max_failures,
       User_attributes->>'$.Password_locking.password_lock_time_days' AS lock_days
FROM mysql.user
WHERE account_locked = 'Y';

-- 当用户被锁定时，尝试登录会收到错误：
-- ERROR 3955 (HY000): Access denied for user 'app_user'@'%'.
-- Account is blocked for ... day(s) ... due to ... consecutive failed logins.

-- 手动解锁账户（DBA 操作）：
ALTER USER 'app_user'@'%' ACCOUNT UNLOCK;

-- 解锁后，失败计数器重置为 0
-- 用户可以重新尝试登录

-- 主动锁定账户（不依赖失败次数）：
ALTER USER 'app_user'@'%' ACCOUNT LOCK;
-- 直接锁定，无需等待失败次数达到阈值
-- 适用于：离职员工账户、可疑活动账户
```

## max_connect_errors 主机级别封锁

```sql
-- max_connect_errors 是更粗粒度的防护（主机级别）
-- 当来自某个主机的连续连接错误（不仅仅是密码错误，还包括连接超时等）
-- 超过 max_connect_errors 时，MySQL 直接拒绝该主机的所有连接

SHOW VARIABLES LIKE 'max_connect_errors';
-- max_connect_errors: 100（默认值）

-- 被封锁的主机尝试连接时会收到：
-- ERROR 1129 (HY000): Host '192.168.1.100' is blocked because of many connection errors

-- 解除主机封锁：
FLUSH HOSTS;
-- 或在 MySQL 8.0.31+ 中使用：
TRUNCATE TABLE performance_schema.host_cache;

-- 查看主机连接错误统计：
SELECT IP, COUNT_HANDSHAKE_ERRORS, COUNT_AUTHENTICATION_ERRORS
FROM performance_schema.host_cache
WHERE COUNT_HANDSHAKE_ERRORS > 0 OR COUNT_AUTHENTICATION_ERRORS > 0;
```

## 三层防护体系对比

| 防护层次 | 机制 | 粒度 | 触发条件 | 恢复方式 |
|---------|------|:----:|---------|---------|
| Connection-Control 插件 | 递增延迟 | 用户+主机 | 连续失败超过阈值 | 成功登录后自动重置 |
| FAILED_LOGIN_ATTEMPTS | 账户锁定 | 用户账户 | 连续失败超过设定次数 | 自动（到期解锁）或手动 UNLOCK |
| max_connect_errors | 主机封锁 | 来源 IP | 连接错误超过限制 | FLUSH HOSTS 手动解除 |

## 生产环境综合配置方案

```ini
[mysqld]
# 第一层：Connection-Control 插件（连接延迟）
plugin-load-add=connection_control.so
connection-control-failed-connections-threshold=5
connection-control-min-connection-delay=2000
connection-control-max-connection-delay=300000

# 第三层：主机级别封锁
max_connect_errors=200
```

```sql
-- 第二层：账户级别锁定
-- 普通应用账户：连续失败 10 次锁定 1 天
ALTER USER 'app'@'%'
    FAILED_LOGIN_ATTEMPTS 10
    PASSWORD_LOCK_TIME 1;

-- DBA 管理账户：连续失败 5 次锁定 7 天（更严格）
ALTER USER 'dba_admin'@'localhost'
    FAILED_LOGIN_ATTEMPTS 5
    PASSWORD_LOCK_TIME 7;

-- 监控账户（只读，安全要求较低）：连续失败 20 次锁定 1 天
ALTER USER 'monitor'@'%'
    FAILED_LOGIN_ATTEMPTS 20
    PASSWORD_LOCK_TIME 1;
```

## 监控与告警

```sql
-- 监控登录失败趋势（Performance Schema）：
SELECT * FROM performance_schema.host_cache
WHERE COUNT_AUTHENTICATION_ERRORS > 10
ORDER BY COUNT_AUTHENTICATION_ERRORS DESC;

-- Connection-Control 延迟统计：
SHOW GLOBAL STATUS LIKE 'Connection_control_delay_generated';
-- 如果该值快速增长，说明正在遭受暴力破解

-- 被锁定的账户列表：
SELECT User, Host FROM mysql.user WHERE account_locked = 'Y';

-- 建议告警规则：
-- 1. Connection_control_delay_generated 5分钟内增长超过 50 → 触发告警
-- 2. 任何 DBA 账户被锁定 → 立即告警
-- 3. performance_schema.host_cache 中某 IP 的错误数超过 50 → 告警
```

## 适用场景

- **合规审计要求的账户锁定策略**：金融行业（如 PCI-DSS 要求）或政企系统通常要求"连续 N 次登录失败后锁定账户 M 分钟/小时"。MySQL 8.0.19+ 的 `FAILED_LOGIN_ATTEMPTS` 和 `PASSWORD_LOCK_TIME` 直接在数据库层满足此要求，无需额外应用层实现
- **多租户环境中防止凭据爆破蔓延**：在多租户 SaaS 系统中，某个租户的凭据可能被泄露后遭到暴力破解。账户级别的锁定策略可以隔离影响，确保单个账户被攻击时不影响其他租户的正常访问

## 常见问题

**FAILED_LOGIN_ATTEMPTS 的计数器在什么时候重置？**

计数器在以下情况下重置为 0：①用户成功登录（密码正确）后，失败计数器立即清零；②DBA 执行 `ALTER USER ... ACCOUNT UNLOCK` 手动解锁后，计数器清零；③密码到期后重新设置密码（`ALTER USER ... IDENTIFIED BY ...`），计数器清零。注意：MySQL 服务重启后，内存中的失败计数器也会清零（计数器不持久化到磁盘），但账户的锁定状态（`account_locked`）是持久化的，重启后仍然有效。

---

## 注意事项

- `FAILED_LOGIN_ATTEMPTS` 和 `PASSWORD_LOCK_TIME` 是**账户属性**（存储在 `mysql.user` 表的 `User_attributes` JSON 列中），持久化到磁盘，MySQL 重启后设置不会丢失。但失败计数器（当前连续失败的次数）存储在内存中，重启后会清零。这意味着攻击者理论上可以通过触发 MySQL 重启来重置计数器，因此应结合 Connection-Control 插件和防火墙规则提供额外保护。
- `PASSWORD_LOCK_TIME UNBOUNDED` 表示永久锁定，只能通过 DBA 手动 `ALTER USER ... ACCOUNT UNLOCK` 解除。在设置此策略前，确保有至少一个不受此限制的超级管理员账户（如 `root`），否则可能出现所有管理员账户都被锁定的"死锁"情况。

## 总结

MySQL 提供三层登录失败防护：Connection-Control 插件（递增延迟，按用户+主机粒度）→ `FAILED_LOGIN_ATTEMPTS` + `PASSWORD_LOCK_TIME`（账户级锁定，MySQL 8.0.19+）→ `max_connect_errors`（主机级封锁）。账户锁定设置：`CREATE/ALTER USER ... FAILED_LOGIN_ATTEMPTS N PASSWORD_LOCK_TIME M`（N 次失败后锁定 M 天），`PASSWORD_LOCK_TIME UNBOUNDED`（永久锁定）。解锁：`ALTER USER ... ACCOUNT UNLOCK`。监控：`mysql.user` 表（锁定状态）、`performance_schema.host_cache`（主机错误统计）、`Connection_control_delay_generated`（延迟统计）。生产建议：三层防护结合使用，按账户重要性设置不同严格程度的锁定策略。
