# mysql_native_password 默认禁用影响

`mysql_native_password` 是 MySQL 最古老的认证插件，从 MySQL 4.1 一直沿用至今，基于 SHA-1 哈希算法进行密码验证。从 MySQL 8.0.34 开始，该插件被标记为**废弃（deprecated）**；从 MySQL 8.4.0 开始，该插件**默认禁用（disabled by default）**；在 MySQL 9.0.0 中被**完全移除（removed）**。MySQL 8.4 LTS 作为长期支持版本，默认禁用 `mysql_native_password` 是一个影响广泛的变更，直接影响老客户端连接、旧版 ORM 框架、遗留系统迁移等场景。

---

## mysql_native_password 的历史地位

在 MySQL 8.0 之前，`mysql_native_password` 是默认认证插件。MySQL 8.0 将默认认证插件改为 `caching_sha2_password`，但仍然保留了 `mysql_native_password` 的支持。大量旧系统和客户端驱动（特别是 PHP 5.x 的 mysqlnd、旧版 Python mysql-connector、早期 Java JDBC 驱动等）仅支持 `mysql_native_password`，不支持 `caching_sha2_password`。

MySQL 8.4 将 `mysql_native_password` 默认禁用后，这些旧客户端在未做任何修改的情况下将**无法连接**到 MySQL 8.4 服务器。

---

## 默认禁用的具体表现

```sql
-- 在 MySQL 8.4 中，mysql_native_password 插件默认不加载
-- 尝试使用该插件创建用户会报错：

CREATE USER 'old_app'@'%' IDENTIFIED WITH mysql_native_password BY 'password123';
-- ERROR 1524 (HY000): Plugin 'mysql_native_password' is not loaded

-- 尝试将已有用户的认证插件改为 mysql_native_password 也会报错：
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'password123';
-- ERROR 1524 (HY000): Plugin 'mysql_native_password' is not loaded

-- 查看当前已加载的认证插件：
SELECT PLUGIN_NAME, PLUGIN_STATUS FROM information_schema.PLUGINS
WHERE PLUGIN_NAME LIKE '%password%' OR PLUGIN_NAME LIKE '%auth%';
-- caching_sha2_password: ACTIVE
-- sha256_password: ACTIVE（也已废弃，但仍可用）
-- mysql_native_password: 不在列表中（未加载）
```

## 临时重新启用 mysql_native_password

```ini
# 如果升级到 MySQL 8.4 后，短期内仍需兼容旧客户端
# 可以在 my.cnf（或 my.ini）中重新启用该插件：

[mysqld]
# 重新加载 mysql_native_password 插件
mysql_native_password=ON

# 注意：这只是临时过渡措施
# mysql_native_password 在 MySQL 9.0 中将被完全移除
# 应尽快将所有客户端和用户迁移到 caching_sha2_password
```

```sql
-- 也可以通过启动参数启用（不修改配置文件）
-- mysqld --mysql-native-password=ON

-- 启用后验证插件状态：
SELECT PLUGIN_NAME, PLUGIN_STATUS FROM information_schema.PLUGINS
WHERE PLUGIN_NAME = 'mysql_native_password';
-- mysql_native_password: ACTIVE
```

## 迁移用户到 caching_sha2_password

```sql
-- 查找仍在使用 mysql_native_password 的用户：
SELECT User, Host, plugin FROM mysql.user WHERE plugin = 'mysql_native_password';

-- 将用户迁移到 caching_sha2_password：
ALTER USER 'old_app'@'%' IDENTIFIED WITH caching_sha2_password BY 'new_secure_password';

-- 批量迁移脚本（生成 ALTER USER 语句）：
SELECT CONCAT('ALTER USER ''', User, '''@''', Host,
              ''' IDENTIFIED WITH caching_sha2_password BY ''CHANGE_ME'';')
FROM mysql.user
WHERE plugin = 'mysql_native_password';
-- 将输出的语句逐条执行，替换 CHANGE_ME 为实际密码

-- 迁移后验证：
SELECT User, Host, plugin FROM mysql.user WHERE plugin = 'mysql_native_password';
-- 确认没有用户仍使用旧插件
```

## 适用场景

- **MySQL 5.7/8.0 升级到 8.4 的兼容性评估**：在升级前，通过 `SELECT User, Host, plugin FROM mysql.user WHERE plugin='mysql_native_password'` 盘点所有使用旧认证插件的用户，逐一确认对应的客户端驱动版本是否支持 `caching_sha2_password`，制定迁移计划
- **多语言微服务系统的统一认证迁移**：对于使用多种编程语言（Java、Python、PHP、Go）的微服务系统，需要逐个检查各服务的数据库驱动版本，确保所有服务都支持 `caching_sha2_password` 后再统一切换

## 常见问题

**升级到 MySQL 8.4 后，旧应用突然无法连接数据库，报错 "Plugin 'mysql_native_password' is not loaded"，如何快速恢复？**

这是因为 MySQL 8.4 默认禁用了 `mysql_native_password` 插件，而应用的数据库用户仍使用该插件认证。快速恢复步骤：①在 `my.cnf` 的 `[mysqld]` 段添加 `mysql_native_password=ON`；②重启 MySQL 服务（`systemctl restart mysqld`）；③应用恢复连接后，立即开始将用户迁移到 `caching_sha2_password`（`ALTER USER ... IDENTIFIED WITH caching_sha2_password BY ...`）；④更新所有客户端驱动到支持 `caching_sha2_password` 的版本；⑤全部迁移完成后，移除 `mysql_native_password=ON` 配置，重启 MySQL。

---

## 注意事项

- `caching_sha2_password` 在首次认证时需要安全连接（SSL/TLS 或 RSA 密钥交换）。如果客户端通过非加密连接（`--ssl-mode=DISABLED`），首次连接可能失败。解决方法：确保 MySQL 服务器启用了 SSL（MySQL 8.0+ 默认生成自签名证书），客户端不要显式禁用 SSL；或者在服务端配置 `REQUIRE NONE` 并让客户端获取 RSA 公钥（`--get-server-public-key`）。
- 在主从复制环境中，如果从库的复制用户（`CHANGE REPLICATION SOURCE TO ... USER='repl'`）使用 `mysql_native_password`，升级主库到 8.4 后复制会中断。需要先在主库上将复制用户迁移到 `caching_sha2_password`，并确认从库的 MySQL 版本和驱动支持该插件。

## 总结

MySQL 8.4 LTS 默认禁用了 `mysql_native_password` 认证插件（8.0.34 废弃 → 8.4 默认禁用 → 9.0 完全移除）。直接影响：使用旧认证插件的用户无法登录，报错 `Plugin 'mysql_native_password' is not loaded`。临时恢复：`my.cnf` 中添加 `mysql_native_password=ON` 并重启。长期方案：将所有用户迁移到 `caching_sha2_password`（`ALTER USER ... IDENTIFIED WITH caching_sha2_password BY ...`），同时升级客户端驱动到支持新认证插件的版本。迁移前通过 `SELECT User, Host, plugin FROM mysql.user WHERE plugin='mysql_native_password'` 盘点受影响用户。注意 `caching_sha2_password` 首次连接需要安全连接（SSL 或 RSA 公钥交换）。
