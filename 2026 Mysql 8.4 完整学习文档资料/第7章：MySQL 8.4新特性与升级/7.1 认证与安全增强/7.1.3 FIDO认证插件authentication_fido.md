# FIDO 认证插件 authentication_fido

FIDO（Fast Identity Online）认证插件 `authentication_fido` 是 MySQL 8.0.27 引入的认证方式，支持基于硬件安全密钥（如 YubiKey）或平台认证器（如指纹识别、Windows Hello）的多因素认证（MFA）和无密码认证（Passwordless Authentication）。FIDO 基于 WebAuthn 标准，使用公钥密码学替代传统密码，用户无需记忆密码，认证过程依赖物理设备或生物特征，从根本上消除了密码泄露和暴力破解的风险。

## FIDO 认证的工作原理

```
FIDO 认证流程：

注册阶段（一次性操作）：
1. DBA 创建用户并指定 authentication_fido 认证方式
2. 用户首次连接时，MySQL 服务端生成一个挑战（Challenge）
3. 客户端将挑战转发给 FIDO 设备（如 YubiKey）
4. 用户触摸安全密钥或进行生物识别（指纹/面部）
5. FIDO 设备生成公私钥对，将公钥发送给服务端
6. 服务端保存公钥，注册完成

认证阶段（每次登录）：
1. 用户连接 MySQL 服务端
2. 服务端生成随机挑战发送给客户端
3. 客户端将挑战转发给 FIDO 设备
4. 用户触摸安全密钥或进行生物识别
5. FIDO 设备用私钥对挑战签名，返回签名
6. 服务端用保存的公钥验证签名
7. 签名验证通过 → 认证成功

安全优势：
- 私钥永远不离开 FIDO 设备（无法被窃取）
- 每次认证使用随机挑战（防重放攻击）
- 无密码传输（消除中间人攻击风险）
```

## 安装与启用 FIDO 插件

```sql
-- 方法1：运行时安装（立即生效并注册到 mysql.plugins 表）
INSTALL PLUGIN authentication_fido SONAME 'authentication_fido.so';
-- Windows 上使用 .dll：
-- INSTALL PLUGIN authentication_fido SONAME 'authentication_fido.dll';

-- 方法2：在 my.cnf 中配置（每次启动自动加载）
-- [mysqld]
-- plugin-load-add=authentication_fido.so

-- 验证插件已加载：
SELECT PLUGIN_NAME, PLUGIN_STATUS FROM information_schema.PLUGINS
WHERE PLUGIN_NAME = 'authentication_fido';
-- authentication_fido: ACTIVE

-- 客户端也需要对应的插件（authentication_fido_client）
-- MySQL 8.0.27+ 的 mysql 命令行客户端自带
-- 第三方客户端需确认是否支持 FIDO 协议
```

## 创建 FIDO 用户

```sql
-- 场景1：FIDO 作为第二因素（多因素认证 MFA）
-- 第一因素：传统密码（caching_sha2_password）
-- 第二因素：FIDO 设备
CREATE USER 'secure_admin'@'localhost'
    IDENTIFIED WITH caching_sha2_password BY 'first_factor_password'
    AND IDENTIFIED WITH authentication_fido;

-- 场景2：FIDO 无密码认证（Passwordless）
-- 仅使用 FIDO 设备，无需输入任何密码
CREATE USER 'keyonly_user'@'localhost'
    IDENTIFIED WITH authentication_fido
    INITIAL AUTHENTICATION IDENTIFIED BY 'temp_setup_password';
-- INITIAL AUTHENTICATION：用于首次注册 FIDO 设备的临时密码
-- 注册完成后，后续登录仅需 FIDO 设备，无需密码

-- 注册 FIDO 设备（用户首次连接时执行）：
-- mysql --user=secure_admin --password1 --fido-register-factor=2
-- 输入第一因素密码后，系统提示触摸 FIDO 设备完成注册
```

## FIDO 认证的实际登录流程

```bash
# 多因素认证登录（密码 + FIDO）：
mysql --user=secure_admin --password1 --password2
# Enter password: （输入第一因素密码）
# Please insert FIDO device and perform gesture action for sign. （触摸安全密钥）
# Welcome to the MySQL monitor.

# 无密码认证登录（仅 FIDO）：
mysql --user=keyonly_user
# Please insert FIDO device and perform gesture action for sign. （触摸安全密钥）
# Welcome to the MySQL monitor.

# --password1：第一因素密码提示
# --password2：第二因素（FIDO 设备交互）
# --fido-register-factor=N：注册第 N 个因素的 FIDO 设备
```

## FIDO 与传统认证方式对比

| 对比维度 | mysql_native_password | caching_sha2_password | authentication_fido |
|---------|:--------------------:|:--------------------:|:------------------:|
| 安全强度 | SHA-1（弱）| SHA-256（强）| 公钥密码学（极强）|
| 密码存储 | 服务端哈希 | 服务端哈希 | 公钥（私钥在设备）|
| 暴力破解风险 | 有 | 有（SHA-256 更耐暴力）| 无（无密码可破解）|
| 中间人攻击 | 有风险 | SSL 保护 | 无风险（公钥验证）|
| 多因素认证 | 不支持 | 不支持（单因素）| 支持（2FA/3FA）|
| 用户体验 | 输入密码 | 输入密码 | 触摸/指纹（无密码）|
| 硬件要求 | 无 | 无 | 需要 FIDO 设备 |
| MySQL 8.4 状态 | 默认禁用 | 默认启用 | 可选安装 |

## 适用场景

- **高安全要求的数据库管理员（DBA）账户**：对于有权限执行 DDL、GRANT、数据导出等敏感操作的 DBA 账户，使用 FIDO 多因素认证（密码 + 硬件密钥），即使密码泄露也无法登录（需要物理设备）
- **金融/医疗等合规行业的访问控制**：PCI-DSS、HIPAA 等合规标准要求对敏感数据的访问实施多因素认证，`authentication_fido` 直接在数据库层面满足这些合规要求，无需额外中间层

## 常见问题

**FIDO 设备丢失或损坏后，如何恢复用户的数据库访问权限？**

FIDO 设备丢失是一个严重的安全事件，需要通过 DBA 权限重置用户认证。步骤：①DBA 使用自己的账户登录 MySQL；②取消该用户的 FIDO 认证（`ALTER USER 'user'@'host' DISCARD OLD PASSWORD`）或重新设置认证方式（`ALTER USER 'user'@'host' IDENTIFIED WITH caching_sha2_password BY 'temp_password'`）；③用户使用临时密码登录后，注册新的 FIDO 设备；④建议为关键用户注册备用 FIDO 设备（如第二个 YubiKey），存放在安全位置。

## 注意事项

- `authentication_fido` 在 MySQL 8.2 中被标记为废弃，替代方案是 `authentication_webauthn`（基于更新的 WebAuthn 标准）。MySQL 8.4 LTS 仍支持 `authentication_fido`，但新部署建议评估 `authentication_webauthn`。两者的核心原理相同（都基于 FIDO2/WebAuthn），但 `authentication_webauthn` 提供了更好的平台兼容性。
- FIDO 认证目前只支持通过 MySQL 命令行客户端（`mysql`）和部分 Connector 库进行。图形化工具（如 Navicat、DBeaver、MySQL Workbench）的 FIDO 支持取决于各工具的更新进度，部署前需要确认所有使用的工具是否支持。

`authentication_fido` 是 MySQL 8.0.27 引入的 FIDO 认证插件，支持基于硬件安全密钥或生物识别的多因素认证（MFA）和无密码认证。安装：`INSTALL PLUGIN authentication_fido SONAME 'authentication_fido.so'`。使用：`CREATE USER ... IDENTIFIED WITH caching_sha2_password BY '...' AND IDENTIFIED WITH authentication_fido`（MFA 模式）。注册设备：`mysql --user=... --fido-register-factor=2`。安全优势：私钥不离开设备、无密码传输、防重放攻击。适合 DBA 高权限账户和合规要求场景。注意 MySQL 8.2 起 `authentication_fido` 已废弃，推荐关注 `authentication_webauthn` 作为替代。
