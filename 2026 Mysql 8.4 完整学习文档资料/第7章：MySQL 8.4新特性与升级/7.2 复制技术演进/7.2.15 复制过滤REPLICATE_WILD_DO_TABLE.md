# 复制过滤 REPLICATE_WILD_DO_TABLE

`REPLICATE_WILD_DO_TABLE` 是 MySQL 复制过滤中支持**通配符匹配**的表级别白名单过滤器。与 `REPLICATE_DO_TABLE`（需要精确指定每张表）不同，`REPLICATE_WILD_DO_TABLE` 允许使用 `%`（匹配任意多个字符）和 `_`（匹配单个字符）通配符来匹配表名模式，适合表名有规律的场景（如按日期分表 `order_202401`、`order_202402`）。

---

## 配置方式

```ini
# 方式1：my.cnf 启动参数（持久化）
[mysqld]
# 只复制 mydb 数据库中所有以 order 开头的表
replicate-wild-do-table = mydb.order%

# 复制 mydb 数据库的所有表
replicate-wild-do-table = mydb.%

# 复制所有数据库中以 user 开头的表
replicate-wild-do-table = %.user%

# 多个规则需要写多行
replicate-wild-do-table = mydb.order%
replicate-wild-do-table = mydb.product%
```

```sql
-- 方式2：CHANGE REPLICATION FILTER（在线设置，不持久化）
STOP REPLICA SQL_THREAD;

CHANGE REPLICATION FILTER
    REPLICATE_WILD_DO_TABLE = ('mydb.order%', 'mydb.product%');

START REPLICA SQL_THREAD;

-- 注意：通配符模式需要用单引号包裹

-- 指定通道：
CHANGE REPLICATION FILTER
    REPLICATE_WILD_DO_TABLE = ('mydb.order%')
    FOR CHANNEL 'channel_1';

-- 清除规则：
CHANGE REPLICATION FILTER REPLICATE_WILD_DO_TABLE = ();

-- 查看当前配置：
SHOW REPLICA STATUS \G
-- Replicate_Wild_Do_Table: mydb.order%,mydb.product%
```

---

## 通配符规则

```sql
-- % ：匹配零个或多个任意字符
-- _ ：匹配恰好一个任意字符

-- 模式示例：

-- mydb.order%
-- 匹配：mydb.orders, mydb.order_2024, mydb.order_items, mydb.order_detail_202401
-- 不匹配：mydb.products, otherdb.orders

-- mydb.order_____
-- 匹配：mydb.order_2024（恰好 5 个字符的后缀）
-- 不匹配：mydb.order_202401（后缀超过 5 个字符）

-- mydb.%
-- 匹配：mydb 数据库中的所有表
-- 等效于 REPLICATE_DO_DB = (mydb)

-- %.orders
-- 匹配：所有数据库中名为 orders 的表
-- 如：mydb.orders, shop.orders, test.orders

-- 转义特殊字符（% 和 _）：
-- 如果表名本身包含 % 或 _，需要用反斜杠转义
-- replicate-wild-do-table = mydb.my\_table%
-- 匹配 mydb.my_table 开头的表（_ 是表名的一部分，不是通配符）
```

## 过滤评估优先级

```
从库 SQL 线程的过滤评估顺序：

1. REPLICATE_DO_DB / REPLICATE_IGNORE_DB（数据库级别）
2. REPLICATE_DO_TABLE / REPLICATE_IGNORE_TABLE（精确表名）
3. REPLICATE_WILD_DO_TABLE / REPLICATE_WILD_IGNORE_TABLE（通配符）

各过滤器的关系：
- 如果设置了 REPLICATE_DO_TABLE 且事件的表名匹配 → 通过（不再检查通配符）
- 如果 REPLICATE_DO_TABLE 未设置或不匹配 → 继续检查 REPLICATE_WILD_DO_TABLE
- 如果两者都未设置 → 事件通过（不过滤）

实际使用中，通常只使用一种表级别过滤器：
- 需要精确指定少数表 → REPLICATE_DO_TABLE
- 需要通配符匹配一批表 → REPLICATE_WILD_DO_TABLE
- 很少同时使用两者
```

---

## 四种过滤器对比

| 过滤器 | 粒度 | 通配符 | 匹配依据 | 适用场景 |
|-------|:----:|:-----:|---------|---------|
| REPLICATE_DO_DB | 数据库 | 不支持 | 数据库名 | 复制少数数据库 |
| REPLICATE_IGNORE_DB | 数据库 | 不支持 | 数据库名 | 排除少数数据库 |
| REPLICATE_DO_TABLE | 表 | 不支持 | db.table 精确匹配 | 复制少数固定表 |
| REPLICATE_WILD_DO_TABLE | 表 | 支持 %/_ | db.table 模式匹配 | 复制一批命名规律的表 |

---

## 适用场景

- **分表环境的复制过滤**：按日期或 ID 范围分表的业务（如 `order_202401`、`order_202402`、...），使用 `REPLICATE_WILD_DO_TABLE = ('mydb.order_%')` 可以自动匹配所有分表，新增分表无需修改过滤规则
- **多租户系统的按租户复制**：如果每个租户有独立的数据库（如 `tenant_001`、`tenant_002`），使用 `REPLICATE_WILD_DO_TABLE = ('tenant_00%.%')` 可以匹配特定前缀的租户数据

## 常见问题

**REPLICATE_WILD_DO_TABLE 对 DDL 语句（CREATE TABLE、ALTER TABLE）的过滤行为是什么？**

DDL 语句的过滤行为比较复杂。在 ROW 格式下，DDL 语句本身是以 STATEMENT 方式记录在 binlog 中的（即使 `binlog_format=ROW`，DDL 仍以语句形式记录）。DDL 的过滤首先检查数据库级别规则（`REPLICATE_DO_DB`/`REPLICATE_IGNORE_DB`），如果通过，再检查表级别规则。`REPLICATE_WILD_DO_TABLE` 会检查 DDL 涉及的表名是否匹配通配符模式。例如，`CREATE TABLE mydb.order_202501` 在 `REPLICATE_WILD_DO_TABLE=('mydb.order_%')` 下会被复制。但 `DROP DATABASE mydb` 这样的数据库级 DDL 不受表级别过滤器影响。

---

## 注意事项

- `REPLICATE_WILD_DO_TABLE` 的通配符模式字符串在 `my.cnf` 中不需要引号，但在 `CHANGE REPLICATION FILTER` SQL 语句中必须用单引号包裹：`CHANGE REPLICATION FILTER REPLICATE_WILD_DO_TABLE = ('mydb.order%')`。漏掉引号会导致语法错误。
- 通配符 `%` 可以匹配零个字符，所以 `mydb.order%` 也会匹配 `mydb.order`（不带任何后缀的表名）。如果只想匹配带后缀的分表（如 `order_2024` 但不匹配 `order` 本身），应使用 `mydb.order_%`（至少有一个 `_` 后缀字符）。

## 总结

`REPLICATE_WILD_DO_TABLE` 是支持通配符（`%` 匹配任意多字符，`_` 匹配单字符）的表级别白名单过滤器。配置：`my.cnf` 中 `replicate-wild-do-table=db.table%`（持久化）或 `CHANGE REPLICATION FILTER REPLICATE_WILD_DO_TABLE=('db.table%')`（在线，不持久化，需引号）。评估优先级：数据库级别 → 精确表级别 → 通配符表级别。适合分表场景（`order_%`）和命名规律的表批量过滤。新增符合模式的表自动被匹配，无需修改规则。注意 `%` 匹配零个字符，`mydb.order%` 也匹配 `mydb.order` 本身。
