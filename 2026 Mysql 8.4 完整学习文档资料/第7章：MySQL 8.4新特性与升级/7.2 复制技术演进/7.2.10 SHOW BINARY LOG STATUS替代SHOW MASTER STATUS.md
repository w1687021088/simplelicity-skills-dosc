# SHOW BINARY LOG STATUS 替代 SHOW MASTER STATUS

MySQL 8.2 开始引入 `SHOW BINARY LOG STATUS` 语句，替代传统的 `SHOW MASTER STATUS`。这一变更是 MySQL 术语标准化的一部分——将复制相关命令中的"Master/Slave"术语逐步替换为"Source/Replica"及更准确的描述性术语。`SHOW MASTER STATUS` 在 MySQL 8.2 中被标记为废弃（deprecated），在 MySQL 8.4 LTS 中仍可使用但会产生废弃警告，预计在未来版本中移除。

---

## 语法变更

```sql
-- 旧语法（已废弃，MySQL 8.2 起产生警告）：
SHOW MASTER STATUS;
-- Warning (Code 1287): 'SHOW MASTER STATUS' is deprecated 
-- and will be removed in a future release. 
-- Please use SHOW BINARY LOG STATUS instead.

-- 新语法（MySQL 8.2+，推荐使用）：
SHOW BINARY LOG STATUS;

-- 两者输出完全一致：
+------------------+----------+--------------+------------------+-------------------+
| File             | Position | Binlog_Do_DB | Binlog_Ignore_DB | Executed_Gtid_Set |
+------------------+----------+--------------+------------------+-------------------+
| mysql-bin.000015 |      836 |              |                  | uuid:1-150        |
+------------------+----------+--------------+------------------+-------------------+
```

```sql
SHOW BINARY LOG STATUS \G

```

## 适用场景

- **MySQL 8.4 LTS 环境的标准化**：在所有新编写的运维脚本、监控工具、备份脚本中统一使用 `SHOW BINARY LOG STATUS`，避免废弃警告
- **跨版本兼容的运维工具开发**：如果运维工具需要同时支持 MySQL 5.7/8.0/8.4，建议实现版本检测逻辑，根据服务器版本选择新旧语法

## 常见问题

**旧版本的 MySQL（如 5.7 或 8.0.x）不支持 SHOW BINARY LOG STATUS，如何编写兼容新旧版本的脚本？**

可以通过先查询 MySQL 版本号（`SELECT VERSION()`），然后根据版本选择语法。MySQL 8.2 及以上使用 `SHOW BINARY LOG STATUS`，8.2 以下使用 `SHOW MASTER STATUS`。另一种方式是直接执行新语法，如果报语法错误则捕获异常并回退到旧语法。对于 shell 脚本，可以用 `mysql -e "SHOW BINARY LOG STATUS" 2>/dev/null || mysql -e "SHOW MASTER STATUS"` 实现简单的回退。

## 注意事项

- `SHOW BINARY LOG STATUS` 需要 `REPLICATION CLIENT` 或 `SUPER` 权限，与 `SHOW MASTER STATUS` 的权限要求一致。
- 术语变更是渐进式的，旧语法在 MySQL 8.4 LTS 中仍然可以正常工作（只产生废弃警告），但在编写新代码和脚本时应优先使用新语法，为将来的版本升级做准备。

---

## 总结

`SHOW BINARY LOG STATUS` 是 MySQL 8.2 引入的新语法，替代已废弃的 `SHOW MASTER STATUS`。两者功能和输出完全一致（File、Position、Binlog_Do_DB、Binlog_Ignore_DB、Executed_Gtid_Set），区别仅在于命令名称的术语标准化（去除 Master/Slave 术语）。MySQL 8.4 LTS 中旧语法仍可用但产生废弃警告。建议在所有新脚本中使用新语法，跨版本工具通过版本检测或异常回退实现兼容。
