# SHOW REPLICA STATUS 语法变更

`SHOW REPLICA STATUS` 是 MySQL 8.0.22 引入的新语法，替代传统的 `SHOW SLAVE STATUS`。这是 MySQL 术语标准化的重要一环——将所有复制相关命令中的"Slave"替换为"Replica"。`SHOW REPLICA STATUS` 是从库管理中最常用的命令之一，用于查看从库的复制状态、延迟、错误信息等关键指标。在 MySQL 8.4 LTS 中，旧语法 `SHOW SLAVE STATUS` 仍然可用但已废弃，会产生警告。

---

## 语法对照

```sql
-- 旧语法（已废弃）：
SHOW SLAVE STATUS \G
-- Warning: 'SHOW SLAVE STATUS' is deprecated...

-- 新语法（MySQL 8.0.22+，推荐）：
SHOW REPLICA STATUS \G

-- 指定复制通道（多源复制时使用）：
SHOW REPLICA STATUS FOR CHANNEL 'channel_name' \G

-- 权限要求：REPLICATION CLIENT 或 SUPER
```

## 脚本迁移示例

```sql
-- 监控脚本中常用的延迟检查：

-- 旧写法：
-- SELECT * FROM SHOW SLAVE STATUS 中获取 Seconds_Behind_Master

-- 新写法（MySQL 8.0.22+）：
-- 方式1：直接使用 SHOW REPLICA STATUS
SHOW REPLICA STATUS \G
-- 获取 Seconds_Behind_Source 字段值

-- 方式2：使用 Performance Schema（更精确的延迟监控）
SELECT CHANNEL_NAME,
    LAST_APPLIED_TRANSACTION_ORIGINAL_COMMIT_TIMESTAMP AS source_commit,
    LAST_APPLIED_TRANSACTION_END_APPLY_TIMESTAMP AS replica_apply,
    TIMESTAMPDIFF(SECOND,
        LAST_APPLIED_TRANSACTION_ORIGINAL_COMMIT_TIMESTAMP,
        LAST_APPLIED_TRANSACTION_END_APPLY_TIMESTAMP) AS replication_lag
FROM performance_schema.replication_applier_status_by_worker
WHERE CHANNEL_NAME = ''
ORDER BY LAST_APPLIED_TRANSACTION_END_APPLY_TIMESTAMP DESC
LIMIT 1;
-- Performance Schema 提供的延迟信息更精确（基于事务时间戳）
-- Seconds_Behind_Source 基于事件时间，在 MTS 环境下可能不准确
```

## 相关命令的完整术语变更

```sql
-- 复制管理命令的新旧对照（MySQL 8.0.22+ 推荐使用新语法）：

-- 启动复制：
START REPLICA;                    -- 替代 START SLAVE
START REPLICA IO_THREAD;          -- 替代 START SLAVE IO_THREAD
START REPLICA SQL_THREAD;         -- 替代 START SLAVE SQL_THREAD

-- 停止复制：
STOP REPLICA;                     -- 替代 STOP SLAVE
STOP REPLICA IO_THREAD;
STOP REPLICA SQL_THREAD;

-- 重置复制：
RESET REPLICA;                    -- 替代 RESET SLAVE
RESET REPLICA ALL;                -- 替代 RESET SLAVE ALL

-- 配置复制源：
CHANGE REPLICATION SOURCE TO ...;  -- 替代 CHANGE MASTER TO

-- 查看从库列表（在主库上执行）：
SHOW REPLICAS;                    -- 替代 SHOW SLAVE HOSTS
```

## 常见问题

**使用 SHOW REPLICA STATUS 输出的字段名是否与 SHOW SLAVE STATUS 完全不同？需要修改所有解析逻辑吗？**

字段名的变化遵循统一规则：`Master` → `Source`、`Slave` → `Replica`。不包含这两个词的字段名保持不变（如 `Last_IO_Error`、`Last_SQL_Error`、`Retrieved_Gtid_Set` 等）。修改解析逻辑时只需要批量替换字段名中的 `Master` → `Source` 和 `Slave` → `Replica` 即可。建议通过正则替换一次性完成。

---

## 注意事项

- `SHOW REPLICA STATUS` 和 `SHOW SLAVE STATUS` 返回的数据内容完全一致，只是字段名不同。不会因为使用新语法而获得额外信息或缺少信息。
- 在多源复制（Multi-Source Replication）环境中，不指定 `FOR CHANNEL` 时，如果只有一个通道则返回该通道的状态；如果有多个通道则返回所有通道的状态（每个通道一行）。建议在多通道环境中始终指定 `FOR CHANNEL 'channel_name'` 以避免歧义。

## 总结

`SHOW REPLICA STATUS` 是 MySQL 8.0.22 引入的新语法，替代已废弃的 `SHOW SLAVE STATUS`。功能完全一致，输出字段名中的 `Master` 替换为 `Source`、`Slave` 替换为 `Replica`（如 `Seconds_Behind_Master` → `Seconds_Behind_Source`）。MySQL 8.4 LTS 中旧语法仍可用但产生警告。相关命令同样更新：`START/STOP REPLICA`、`RESET REPLICA`、`CHANGE REPLICATION SOURCE TO`、`SHOW REPLICAS`。建议所有新脚本使用新语法，对更精确的延迟监控推荐使用 `performance_schema.replication_applier_status_by_worker`。
