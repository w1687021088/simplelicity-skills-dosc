# 克隆插件本地克隆

Clone Plugin 除了支持远程克隆（通过网络从另一个 MySQL 实例克隆数据），还支持**本地克隆**（在同一台服务器上将数据复制到指定目录）。本地克隆不需要网络传输，直接在本地文件系统上复制 InnoDB 数据文件，速度取决于磁盘 I/O 性能。本地克隆的典型用途包括：快速创建数据库副本用于测试、在同一台服务器上搭建多个 MySQL 实例、创建一致性快照用于备份。

---

## 本地克隆的语法与执行

```sql
-- 本地克隆将当前实例的 InnoDB 数据复制到指定目录
-- 前提：已安装 Clone Plugin
INSTALL PLUGIN clone SONAME 'mysql_clone.so';

-- 执行本地克隆：
CLONE LOCAL DATA DIRECTORY = '/data/mysql_clone';

-- 克隆过程：
-- 1. 在 /data/mysql_clone 目录下创建完整的 MySQL 数据目录结构
-- 2. 复制所有 InnoDB 数据文件（.ibd、系统表空间、undo 日志等）
-- 3. 复制过程中当前实例正常提供服务（在线操作）
-- 4. 克隆完成后，目标目录包含一份一致性数据快照

-- 目标目录的要求：
-- 1. 目录必须不存在或为空目录（MySQL 会自动创建）
-- 2. MySQL 进程用户（如 mysql）必须有写入权限
-- 3. 目标路径不能是当前数据目录或其子目录
```

---

## 使用克隆数据启动新实例

```bash
# 本地克隆完成后，可以使用克隆的数据启动一个新的 MySQL 实例

# 1. 修改克隆目录的所有权（确保 mysql 用户可读写）
chown -R mysql:mysql /data/mysql_clone

# 2. 使用克隆的数据目录启动新实例（指定不同的端口和 socket）
mysqld --datadir=/data/mysql_clone \
       --port=3307 \
       --socket=/tmp/mysql_clone.sock \
       --server-id=2 &

# 3. 连接新实例
mysql -S /tmp/mysql_clone.sock -u root -p

# 注意：
# - 新实例的 server_id 必须与原实例不同（如果要建立复制）
# - 新实例的 auto.cnf（server_uuid）会自动重新生成
# - 新实例的端口、socket 必须与原实例不同
```

## 本地克隆的权限要求

```sql
-- 执行本地克隆的用户需要 BACKUP_ADMIN 权限：
GRANT BACKUP_ADMIN ON *.* TO 'admin'@'localhost';

-- 查看当前用户是否有克隆权限：
SHOW GRANTS FOR CURRENT_USER;

-- 与远程克隆的权限对比：
-- 本地克隆：当前实例用户需要 BACKUP_ADMIN
-- 远程克隆：接收者用户需要 CLONE_ADMIN，捐赠者用户需要 BACKUP_ADMIN
```

## 监控本地克隆进度

```sql
-- 本地克隆的进度监控与远程克隆使用相同的 Performance Schema 表：

-- 克隆状态：
SELECT STATE, BEGIN_TIME, END_TIME, SOURCE, DESTINATION
FROM performance_schema.clone_status \G

-- 各阶段进度：
SELECT STAGE, STATE, DATA, DATA_SPEED
FROM performance_schema.clone_progress;

-- STAGE 阶段说明：
-- DROP DATA: 准备目标目录
-- FILE COPY: 复制数据文件（最耗时的阶段）
-- PAGE COPY: 复制克隆期间修改的数据页
-- REDO COPY: 复制 redo log
-- FILE SYNC: 将所有文件同步到磁盘

-- 注意：本地克隆没有 RESTART 和 RECOVERY 阶段
-- 因为本地克隆不会重启当前实例
```

## 本地克隆 vs 远程克隆 vs mysqldump 对比

| 对比维度 | 本地克隆 | 远程克隆 | mysqldump |
|---------|:------:|:------:|:--------:|
| 数据传输 | 本地磁盘复制 | 网络传输 | 网络传输（SQL 文本）|
| 速度 | 快（受磁盘 I/O 限制）| 中（受网络带宽限制）| 慢（逻辑导出+导入）|
| 在线操作 | 是 | 是 | 是（--single-transaction）|
| 数据格式 | InnoDB 物理文件 | InnoDB 物理文件 | SQL 语句 |
| 引擎支持 | 仅 InnoDB | 仅 InnoDB | 所有引擎 |
| 包含 GTID 信息 | 是 | 是 | 是（--set-gtid-purged）|
| 是否需要重启 | 否（只是复制文件）| 接收者自动重启 | 否 |
| 增量能力 | 不支持 | 不支持 | 不支持 |

## 适用场景

- **快速创建测试/开发环境的数据副本**：在同一台服务器上将生产数据（或 staging 数据）本地克隆到另一个目录，启动一个独立的 MySQL 实例用于测试或开发，比 `mysqldump` 导出再导入快得多
- **数据库版本升级前的数据备份**：在执行 MySQL 版本升级前，通过本地克隆创建一份当前数据的完整副本，如果升级失败可以快速回退到克隆的数据

## 常见问题

**本地克隆期间对当前运行的 MySQL 实例有多大性能影响？**

本地克隆的性能影响主要来自磁盘 I/O——克隆过程需要读取所有 InnoDB 数据文件并写入目标目录。如果源目录和目标目录在同一块物理磁盘上，I/O 竞争会比较明显（读写都在同一磁盘）。建议将目标目录放在不同的物理磁盘或 SSD 上，减少 I/O 竞争。可以通过 `clone_max_data_bandwidth`（单位 MB/s）限制克隆的数据读取速率，降低对生产查询的影响。CPU 和内存的影响可以忽略。

---

## 注意事项

- 本地克隆的目标目录必须是**不存在或空的目录**，不能是已有数据的目录。如果指定的目录已存在且非空，克隆命令会报错。这是一个安全措施，防止误覆盖现有数据。
- 本地克隆只复制 InnoDB 引擎的数据。如果数据库中有 MyISAM 表、CSV 表或其他非 InnoDB 引擎的表，这些表的数据不会出现在克隆的目录中。使用克隆数据启动新实例后，这些表会显示为空或不存在。

---

## 总结

Clone Plugin 本地克隆通过 `CLONE LOCAL DATA DIRECTORY = '/path/to/dir'` 将当前实例的 InnoDB 数据复制到本地指定目录，无需网络传输，速度取决于磁盘 I/O。执行权限：BACKUP_ADMIN。克隆完成后得到一份一致性数据快照，可用于启动新实例（指定不同 `--datadir`、`--port`、`--server-id`）。监控：`performance_schema.clone_status` 和 `clone_progress`。适合：快速创建测试副本、升级前数据备份、同服务器多实例部署。限制：仅克隆 InnoDB 数据，目标目录必须为空，不支持增量克隆。
