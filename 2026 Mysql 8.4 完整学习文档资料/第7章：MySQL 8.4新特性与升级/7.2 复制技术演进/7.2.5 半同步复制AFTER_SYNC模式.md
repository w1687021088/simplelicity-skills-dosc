# 半同步复制 AFTER_SYNC 模式

半同步复制（Semi-Synchronous Replication）是介于异步复制和全同步复制之间的折衷方案：主库在提交事务时，等待**至少一个从库**确认已经接收并写入 relay log 后，才向客户端返回提交成功。这保证了提交成功的事务至少在一个从库上有副本，降低了主库故障时数据丢失的风险。MySQL 5.7 引入了 `AFTER_SYNC`（无损半同步）模式，相比早期的 `AFTER_COMMIT` 模式提供了更强的数据一致性保证，是 MySQL 8.4 LTS 推荐的半同步模式。

---

## AFTER_SYNC 的工作流程

```
AFTER_SYNC（无损半同步）的事务提交流程：

1. 主库执行事务（InnoDB 引擎层）
2. 主库将事务写入 binlog（sync binlog）
3. 主库将 binlog 事件发送给从库           ← 在 engine commit 之前！
4. 等待从库 ACK（确认已写入 relay log）    ← 阻塞等待
5. 主库执行 engine commit（InnoDB commit）
6. 向客户端返回提交成功

关键点：步骤 3-4 发生在 engine commit 之前
- 如果主库在步骤 4 之前崩溃 → 事务未提交到 InnoDB → 数据未丢失
- 如果主库在步骤 4 和 5 之间崩溃 → 从库已有数据，主库恢复后可补齐
- 如果从库在超时内未返回 ACK → 退化为异步复制（rpl_semi_sync_source_timeout）

为什么叫"无损"（Lossless）：
- 所有已向客户端确认提交的事务，至少在一个从库上有副本
- 主库崩溃后切换到从库，不会丢失任何已提交的事务
```

## 安装与配置

```sql
-- 安装半同步复制插件
-- 主库：
INSTALL PLUGIN rpl_semi_sync_source SONAME 'semisync_source.so';
-- 从库：
INSTALL PLUGIN rpl_semi_sync_replica SONAME 'semisync_replica.so';

-- MySQL 8.0.26 之前的插件名：
-- INSTALL PLUGIN rpl_semi_sync_master SONAME 'semisync_master.so';
-- INSTALL PLUGIN rpl_semi_sync_slave SONAME 'semisync_slave.so';

-- 主库启用半同步（AFTER_SYNC 模式）：
SET GLOBAL rpl_semi_sync_source_enabled = ON;
SET GLOBAL rpl_semi_sync_source_wait_point = 'AFTER_SYNC';  -- 默认值

-- 从库启用半同步：
SET GLOBAL rpl_semi_sync_replica_enabled = ON;

-- 重启从库 IO 线程使配置生效：
STOP REPLICA IO_THREAD;
START REPLICA IO_THREAD;
```

```ini
# my.cnf 主库配置
[mysqld]
plugin-load-add = semisync_source.so
rpl_semi_sync_source_enabled = ON
rpl_semi_sync_source_wait_point = AFTER_SYNC
rpl_semi_sync_source_timeout = 5000    # 等待 ACK 超时（毫秒），默认 10000

# my.cnf 从库配置
[mysqld]
plugin-load-add = semisync_replica.so
rpl_semi_sync_replica_enabled = ON
```

## 核心参数

```sql
-- 查看半同步相关参数：
SHOW VARIABLES LIKE 'rpl_semi_sync%';

-- rpl_semi_sync_source_wait_point
-- AFTER_SYNC（默认，无损模式）：engine commit 之前等待 ACK
-- AFTER_COMMIT：engine commit 之后等待 ACK（有数据丢失风险）

-- rpl_semi_sync_source_timeout（毫秒）
-- 等待从库 ACK 的超时时间，超时后退化为异步复制
-- 默认 10000（10 秒）
SET GLOBAL rpl_semi_sync_source_timeout = 5000;  -- 5 秒

-- rpl_semi_sync_source_wait_for_replica_count
-- 需要多少个从库返回 ACK 后才继续提交
-- 默认 1（至少一个从库确认）
-- 设为 2 表示需要两个从库确认（更安全，但延迟更高）
SET GLOBAL rpl_semi_sync_source_wait_for_replica_count = 1;
```

## 监控半同步状态

```sql
-- 主库状态监控：
SHOW GLOBAL STATUS LIKE 'Rpl_semi_sync_source%';

-- 关键状态变量：
-- Rpl_semi_sync_source_status: ON
--   当前是否处于半同步模式（OFF 表示已退化为异步）
-- Rpl_semi_sync_source_yes_tx: 1500
--   通过半同步确认的事务数
-- Rpl_semi_sync_source_no_tx: 10
--   退化为异步提交的事务数（从库 ACK 超时）
-- Rpl_semi_sync_source_clients: 2
--   当前连接的半同步从库数量
-- Rpl_semi_sync_source_tx_avg_wait_time: 500
--   平均等待 ACK 时间（微秒）

-- 从库状态监控：
SHOW GLOBAL STATUS LIKE 'Rpl_semi_sync_replica%';
-- Rpl_semi_sync_replica_status: ON

-- 计算半同步成功率：
-- 成功率 = yes_tx / (yes_tx + no_tx) × 100%
-- 低于 99% 时需要关注网络延迟或从库性能
```

## 超时退化与恢复

```
超时退化机制：

1. 主库提交事务，发送 binlog 给从库
2. 等待 ACK，超过 rpl_semi_sync_source_timeout（如 5 秒）
3. 超时！主库自动退化为异步复制
4. Rpl_semi_sync_source_status 变为 OFF
5. 后续事务不再等待 ACK，直接提交（异步模式）

自动恢复：
6. 从库恢复正常，发送 ACK 给主库
7. 主库检测到有活跃的半同步从库
8. 自动恢复为半同步模式
9. Rpl_semi_sync_source_status 变为 ON

退化的影响：
- 退化期间的事务可能只在主库有副本（如果主库此时崩溃，可能丢数据）
- 退化是暂时的，从库恢复后自动恢复半同步
- 通过 Rpl_semi_sync_source_no_tx 监控退化频率
```

## 适用场景

- **金融交易等数据零丢失要求的场景**：银行转账、支付清算等业务要求每一笔已确认的交易都不能丢失。AFTER_SYNC 模式保证了已返回成功的事务至少在一个从库有副本，主库故障后切换到从库不会丢失数据
- **主从切换高可用架构的数据一致性保障**：配合 MHA、Orchestrator 等故障转移工具，使用 AFTER_SYNC 半同步可以确保切换后新主库的数据与旧主库完全一致，不需要额外的数据补偿操作

## 常见问题

**半同步复制会增加多少延迟？**

半同步复制的额外延迟 = 主库到从库的网络往返时间（RTT）。在同一数据中心内（RTT 通常 < 1ms），增加的延迟可以忽略（每个事务增加约 0.5~1ms）。在跨机房环境中（RTT 可能 5~50ms），延迟影响显著，每个事务提交时间增加 5~50ms。因此半同步复制适合同机房部署，跨机房建议使用异步复制或 MGR。可以通过 `Rpl_semi_sync_source_tx_avg_wait_time` 状态变量监控实际的平均等待时间。

---

## 注意事项

- `rpl_semi_sync_source_timeout` 设置过短（如 1 秒）会导致频繁退化为异步模式（网络抖动就可能超时），设置过长（如 60 秒）会导致从库故障时主库事务长时间阻塞。建议根据主从之间的网络 RTT 设置为 RTT 的 5~10 倍（同机房 2~5 秒，跨机房 10~30 秒）。
- 半同步复制只保证从库**接收**了 binlog（写入 relay log），不保证从库**执行**了事务。从库可能接收了事务但尚未回放。因此故障转移后，新主库可能需要等待 relay log 中的事务全部回放完成后才能对外提供服务。

## 总结

AFTER_SYNC（无损半同步）是 MySQL 8.4 推荐的半同步模式，在 engine commit 之前等待从库 ACK，保证已向客户端确认的事务至少在一个从库有副本（零数据丢失）。安装：`INSTALL PLUGIN rpl_semi_sync_source SONAME 'semisync_source.so'`。核心配置：`rpl_semi_sync_source_enabled=ON`、`rpl_semi_sync_source_wait_point=AFTER_SYNC`、`rpl_semi_sync_source_timeout`（ACK 超时时间）。超时后自动退化为异步，从库恢复后自动回到半同步。监控：`Rpl_semi_sync_source_status`（当前模式）、`Rpl_semi_sync_source_yes_tx/no_tx`（成功/退化事务数）。适合同机房高可用架构，跨机房延迟影响较大。
