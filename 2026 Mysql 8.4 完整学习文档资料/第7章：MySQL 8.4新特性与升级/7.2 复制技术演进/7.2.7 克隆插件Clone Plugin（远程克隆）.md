# 克隆插件 Clone Plugin（远程克隆）

Clone Plugin 是 MySQL 8.0.17 引入的数据克隆工具，允许从一个运行中的 MySQL 实例（捐赠者/Donor）通过网络将 InnoDB 数据完整复制到另一个实例（接收者/Recipient），无需停机、无需手动导出导入。远程克隆是 Clone Plugin 最核心的功能，它可以在几分钟到几十分钟内完成 GB 到 TB 级别数据的传输（取决于网络带宽），比传统的 `mysqldump` 逻辑备份快数倍甚至数十倍。克隆完成后，接收者自动获得捐赠者的 GTID 执行集合和 binlog 位置信息，可以直接建立复制关系。

---

## 安装 Clone Plugin

```sql
-- 在捐赠者（Donor）和接收者（Recipient）上都需要安装：
INSTALL PLUGIN clone SONAME 'mysql_clone.so';

-- 验证安装：
SELECT PLUGIN_NAME, PLUGIN_STATUS FROM information_schema.PLUGINS
WHERE PLUGIN_NAME = 'clone';
-- clone: ACTIVE

-- 也可以在 my.cnf 中配置自动加载：
-- [mysqld]
-- plugin-load-add = mysql_clone.so
```

## 远程克隆的前提条件

```sql
-- 1. 捐赠者和接收者的 MySQL 版本必须相同（主版本号一致）
-- 例如：两边都是 8.4.x

-- 2. 捐赠者和接收者的操作系统和架构相同

-- 3. 两边都安装了 Clone Plugin

-- 4. 捐赠者上创建具有 BACKUP_ADMIN 权限的克隆用户：
CREATE USER 'clone_user'@'%' IDENTIFIED BY 'clone_password';
GRANT BACKUP_ADMIN ON *.* TO 'clone_user'@'%';

-- 5. 接收者上需要 CLONE_ADMIN 权限：
-- 执行 CLONE 命令的用户需要 CLONE_ADMIN 权限
GRANT CLONE_ADMIN ON *.* TO 'admin'@'localhost';

-- 6. 接收者设置允许的捐赠者列表：
SET GLOBAL clone_valid_donor_list = '192.168.1.100:3306';
-- 多个捐赠者用逗号分隔：
-- SET GLOBAL clone_valid_donor_list = '192.168.1.100:3306,192.168.1.101:3306';
```

## 执行远程克隆

```sql
-- 在接收者（Recipient）上执行：
CLONE INSTANCE FROM 'clone_user'@'192.168.1.100':3306
    IDENTIFIED BY 'clone_password';

-- 克隆过程：
-- 1. 接收者连接到捐赠者
-- 2. 捐赠者开始传输 InnoDB 数据文件
-- 3. 传输过程中捐赠者正常提供服务（在线热克隆）
-- 4. 传输完成后，接收者自动重启 MySQL 服务
-- 5. 重启后接收者拥有捐赠者的完整数据副本

-- 指定数据目录（不替换当前数据，克隆到指定目录）：
CLONE INSTANCE FROM 'clone_user'@'192.168.1.100':3306
    IDENTIFIED BY 'clone_password'
    DATA DIRECTORY = '/data/clone_backup';
-- 不会自动重启，数据保存在指定目录

-- 使用 SSL 加密传输（安全要求高的环境）：
CLONE INSTANCE FROM 'clone_user'@'192.168.1.100':3306
    IDENTIFIED BY 'clone_password'
    REQUIRE SSL;
```

## 监控克隆进度

```sql
-- 通过 Performance Schema 监控克隆状态：
SELECT STATE, BEGIN_TIME, END_TIME,
       SOURCE, DESTINATION,
       BINLOG_FILE, BINLOG_POSITION,
       GTID_EXECUTED
FROM performance_schema.clone_status \G

-- STATE 的可能值：
-- Not Started: 未开始
-- In Progress: 进行中
-- Completed: 完成
-- Failed: 失败

-- 查看克隆各阶段进度：
SELECT STAGE, STATE, 
       CAST(BEGIN_TIME AS DATETIME) AS start_time,
       CAST(END_TIME AS DATETIME) AS end_time,
       DATA, NETWORK, DATA_SPEED
FROM performance_schema.clone_progress;

-- STAGE 阶段：
-- DROP DATA: 清理接收者的旧数据
-- FILE COPY: 传输数据文件（最耗时）
-- PAGE COPY: 传输克隆期间修改的页面
-- REDO COPY: 传输 redo log
-- FILE SYNC: 文件同步到磁盘
-- RESTART: 重启 MySQL
-- RECOVERY: 崩溃恢复
```

## 克隆后建立复制关系

```sql
-- 克隆完成后，接收者自动获得捐赠者的 GTID 和 binlog 位置
-- 可以直接建立主从复制：

-- 1. 查看克隆获取的复制坐标：
SELECT BINLOG_FILE, BINLOG_POSITION, GTID_EXECUTED
FROM performance_schema.clone_status;

-- 2. 使用 GTID AUTO_POSITION 建立复制（推荐）：
CHANGE REPLICATION SOURCE TO
    SOURCE_HOST = '192.168.1.100',
    SOURCE_PORT = 3306,
    SOURCE_USER = 'repl_user',
    SOURCE_PASSWORD = 'repl_password',
    SOURCE_AUTO_POSITION = 1;

START REPLICA;

-- 克隆 + GTID AUTO_POSITION = 快速搭建从库
-- 比 mysqldump + 手动恢复 + 配置复制 快得多
```

## 适用场景

- **快速搭建新的从库**：当需要为现有主库添加新的从库时，远程克隆比 `mysqldump` 逻辑备份恢复快得多（100GB 数据，克隆可能只需要 10~20 分钟，而 mysqldump 可能需要数小时），且不影响主库性能
- **Group Replication 新成员加入**：MGR 可以配置自动使用 Clone Plugin 进行分布式恢复（`group_replication_clone_threshold`），新成员加入时自动从现有成员克隆数据，无需手动备份恢复

## 常见问题

**远程克隆过程中，捐赠者（Donor）的性能会受到多大影响？**

克隆过程中捐赠者需要额外的 I/O 来读取数据文件并通过网络发送，主要影响磁盘 I/O 和网络带宽。CPU 影响较小。实际性能影响取决于磁盘 I/O 余量和网络带宽：如果捐赠者的 I/O 利用率已经很高（>80%），克隆期间可能导致查询响应时间增加。可以通过 `clone_max_data_bandwidth`（限制克隆数据传输速率，MB/s）和 `clone_max_network_bandwidth`（限制网络传输速率）参数限制克隆对捐赠者的影响。

## 注意事项

- 远程克隆在接收者上执行时，**会删除接收者上所有现有的 InnoDB 数据**（除非指定了 `DATA DIRECTORY`），然后用捐赠者的数据替换。这是一个破坏性操作，执行前必须确认接收者上没有需要保留的数据。
- Clone Plugin 只克隆 InnoDB 引擎的数据。MyISAM 表、CSV 表等非 InnoDB 引擎的数据不会被克隆。如果数据库中有非 InnoDB 表，需要通过其他方式（如 `mysqldump`）单独迁移这些表。

## 总结

Clone Plugin 远程克隆允许从运行中的 MySQL 实例（Donor）通过网络复制完整的 InnoDB 数据到另一个实例（Recipient），无需停机。安装：`INSTALL PLUGIN clone SONAME 'mysql_clone.so'`（两端都需要）。执行：`CLONE INSTANCE FROM 'user'@'host':port IDENTIFIED BY 'password'`。前提：版本相同、Donor 有 BACKUP_ADMIN 权限、Recipient 设置 `clone_valid_donor_list`。克隆完成后自动获得 GTID 和 binlog 位置，可直接建立复制。监控：`performance_schema.clone_status` 和 `clone_progress`。适合快速搭建从库和 MGR 新成员加入。注意：会删除接收者现有数据，只克隆 InnoDB 引擎数据。
