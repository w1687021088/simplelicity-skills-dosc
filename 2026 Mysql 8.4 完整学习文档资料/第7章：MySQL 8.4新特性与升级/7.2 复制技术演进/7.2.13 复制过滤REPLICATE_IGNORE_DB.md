# 复制过滤 REPLICATE_IGNORE_DB

`REPLICATE_IGNORE_DB` 是 MySQL 复制过滤机制中的"排除型"过滤器，用于在从库端**忽略指定数据库**的变更事件，其余数据库的事件正常复制。它与 `REPLICATE_DO_DB`（只复制指定数据库）互为反向操作。实际使用中，如果需要排除少数几个数据库，用 `REPLICATE_IGNORE_DB` 更方便；如果只需要保留少数几个数据库，用 `REPLICATE_DO_DB` 更合适。

---

## 配置方式

```ini
# 方式1：my.cnf 启动参数（持久化）
[mysqld]
# 忽略 test 和 tmp 数据库的复制事件
replicate-ignore-db = test
replicate-ignore-db = tmp
```

```sql
-- 方式2：CHANGE REPLICATION FILTER（在线设置，不持久化）
STOP REPLICA SQL_THREAD;

CHANGE REPLICATION FILTER REPLICATE_IGNORE_DB = (test, tmp);

START REPLICA SQL_THREAD;

-- 指定通道：
CHANGE REPLICATION FILTER REPLICATE_IGNORE_DB = (test)
    FOR CHANNEL 'channel_1';

-- 清除规则：
CHANGE REPLICATION FILTER REPLICATE_IGNORE_DB = ();

-- 查看当前配置：
SHOW REPLICA STATUS \G
-- Replicate_Ignore_DB: test,tmp
```

---

## 过滤行为（SBR vs RBR）

```sql
-- 与 REPLICATE_DO_DB 相同，过滤行为取决于复制格式

-- STATEMENT 格式：基于当前默认数据库（USE 指定）过滤
USE test;           -- 默认数据库 = test
INSERT INTO mydb.t1 VALUES (1);
-- REPLICATE_IGNORE_DB = (test) → 这条语句会被忽略！
-- 因为默认数据库是 test（即使操作的是 mydb 的表）

-- ROW 格式：基于被修改表实际所属的数据库过滤
USE test;           -- 默认数据库 = test
INSERT INTO mydb.t1 VALUES (1);
-- REPLICATE_IGNORE_DB = (test) → 这条语句会被复制
-- 因为 mydb.t1 属于 mydb，不在忽略列表中

-- 推荐使用 ROW 格式（MySQL 8.0 默认），过滤行为更准确
```

## REPLICATE_DO_DB 与 REPLICATE_IGNORE_DB 的交互

```sql
-- 两者可以同时设置，但不建议对同一数据库同时设置

-- 规则优先级（从库 SQL 线程的评估顺序）：
-- 1. 如果设置了 REPLICATE_DO_DB：
--    → 只有在列表中的数据库才通过，其他全部忽略
--    → REPLICATE_IGNORE_DB 对不在 DO_DB 中的数据库无意义
-- 2. 如果只设置了 REPLICATE_IGNORE_DB：
--    → 在列表中的数据库被忽略，其他全部通过

-- 同时设置的行为（不推荐）：
CHANGE REPLICATION FILTER
    REPLICATE_DO_DB = (db1, db2, db3),
    REPLICATE_IGNORE_DB = (db2);
-- 评估流程：
-- db1 的事件 → 在 DO_DB 中 → 通过（不看 IGNORE_DB）
-- db2 的事件 → 在 DO_DB 中 → 通过 → 然后被 IGNORE_DB 忽略
-- db3 的事件 → 在 DO_DB 中 → 通过
-- db4 的事件 → 不在 DO_DB 中 → 直接忽略
-- 实际效果：只复制 db1 和 db3（db2 被排除，db4 不在白名单）
```

## 典型使用场景对比

| 场景 | 推荐过滤器 | 原因 |
|-----|:---------:|------|
| 从库只需要 2 个数据库（共 20 个）| REPLICATE_DO_DB | 白名单短，配置简单 |
| 从库不需要 2 个数据库（共 20 个）| REPLICATE_IGNORE_DB | 黑名单短，配置简单 |
| 排除测试/临时数据库 | REPLICATE_IGNORE_DB | 只排除少数数据库 |
| 多源复制隔离不同数据库 | REPLICATE_DO_DB | 明确每个通道的数据 |

---

## 适用场景

- **排除测试或临时数据库的复制**：主库上有 `test`、`tmp`、`staging` 等不需要在从库出现的数据库，通过 `REPLICATE_IGNORE_DB` 排除，减少从库的存储和回放负载
- **排除大日志表所在的数据库**：如果有专门的日志数据库（如 `log_db`）存放大量操作日志，从库不需要这些日志时可以忽略该数据库

---

## 常见问题

**REPLICATE_IGNORE_DB 会影响系统数据库（mysql、performance_schema、sys）的复制吗？**

可以设置忽略系统数据库，但通常不建议忽略 `mysql` 数据库。`mysql` 数据库包含用户权限表（`mysql.user`、`mysql.db` 等），如果忽略 `mysql` 数据库的复制，主库上的 `CREATE USER`、`GRANT` 等权限变更不会同步到从库，导致从库的权限与主库不一致。`performance_schema` 和 `information_schema` 本身不参与 binlog 复制（它们是虚拟数据库），不需要设置忽略规则。`sys` 数据库是视图集合，通常也不需要过滤。

---

## 注意事项

- `REPLICATE_IGNORE_DB` 同样存在 SBR 模式下基于默认数据库过滤的问题（跨库操作可能被误忽略或误通过）。MySQL 8.0+ 默认使用 ROW 格式（`binlog_format=ROW`），ROW 格式基于表的实际数据库过滤，建议确保使用 ROW 格式。
- `CHANGE REPLICATION FILTER` 设置的过滤规则在 MySQL 重启后丢失，需要在 `my.cnf` 中同时配置 `--replicate-ignore-db` 才能持久化。运维中容易出现"在线设置了过滤规则但忘记写入配置文件，重启后过滤规则消失"的问题。

---

## 总结

`REPLICATE_IGNORE_DB` 在从库端忽略指定数据库的复制事件，其余数据库正常复制。配置：`my.cnf` 中 `replicate-ignore-db=dbname`（持久化）或 `CHANGE REPLICATION FILTER REPLICATE_IGNORE_DB=(db1,db2)`（在线，不持久化）。与 `REPLICATE_DO_DB` 互为反向：DO_DB 是白名单，IGNORE_DB 是黑名单。SBR 模式基于默认数据库过滤，RBR 模式基于表实际数据库过滤（推荐 ROW 格式）。适合排除少数不需要的数据库（如 test、tmp、log_db）。不建议忽略 `mysql` 系统数据库，以免权限不同步。
