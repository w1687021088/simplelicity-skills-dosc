# myisam_repair_threads 移除

`myisam_repair_threads` 是一个控制 MyISAM 表修复操作并行线程数的系统变量。在 MySQL 8.0 中被标记为废弃，在 MySQL 8.4 LTS 中已被移除。该变量允许在 `REPAIR TABLE` 修复 MyISAM 表时使用多个线程并行重建索引，但由于 MyISAM 引擎本身在 MySQL 8.0+ 中已不推荐使用（InnoDB 是默认和推荐的引擎），且多线程修复功能存在稳定性问题，最终被移除。

---

## 变量的历史作用

```sql
-- myisam_repair_threads 的作用（MySQL 5.7 及之前）：
SHOW VARIABLES LIKE 'myisam_repair_threads';
-- myisam_repair_threads: 1（默认值，单线程修复）

-- 设置为 > 1 时启用多线程修复：
SET SESSION myisam_repair_threads = 4;
-- 修复 MyISAM 表时使用 4 个线程并行重建索引

-- 使用场景：
REPAIR TABLE myisam_table;
-- 当 myisam_repair_threads > 1 时
-- MyISAM 的多个索引可以由不同线程并行重建
-- 理论上可以加速大表的修复操作

-- 实际问题：
-- 1. 多线程修复存在已知的稳定性问题
-- 2. 可能导致索引损坏
-- 3. 在 SSD 等现代存储上并行优势不明显
-- 4. MyISAM 引擎本身已不推荐使用
```

## 移除后的影响

```sql
-- MySQL 8.0 中的废弃警告：
SET SESSION myisam_repair_threads = 4;
-- Warning: '@@myisam_repair_threads' is deprecated and will be removed
-- in a future release.

-- MySQL 8.4 中该变量已不存在：
SHOW VARIABLES LIKE 'myisam_repair_threads';
-- Empty set

SET SESSION myisam_repair_threads = 4;
-- ERROR 1193 (HY000): Unknown system variable 'myisam_repair_threads'

-- 如果 my.cnf 中包含此变量：
-- [mysqld]
-- myisam_repair_threads = 4
-- MySQL 8.4 启动时会报错：
-- [ERROR] unknown variable 'myisam_repair_threads=4'

-- 修复方法：从 my.cnf 中移除该配置行
```

## MyISAM 到 InnoDB 的迁移

```sql
-- 如果仍有 MyISAM 表，建议迁移到 InnoDB

-- 查找所有 MyISAM 表：
SELECT TABLE_SCHEMA, TABLE_NAME, ENGINE, TABLE_ROWS,
       ROUND(DATA_LENGTH/1024/1024, 2) AS data_mb,
       ROUND(INDEX_LENGTH/1024/1024, 2) AS index_mb
FROM information_schema.TABLES
WHERE ENGINE = 'MyISAM'
    AND TABLE_SCHEMA NOT IN ('mysql', 'information_schema', 'performance_schema', 'sys')
ORDER BY DATA_LENGTH DESC;

-- 将 MyISAM 表转换为 InnoDB：
ALTER TABLE mydb.mytable ENGINE = InnoDB;

-- 批量转换脚本（生成转换语句）：
SELECT CONCAT('ALTER TABLE `', TABLE_SCHEMA, '`.`', TABLE_NAME, '` ENGINE=InnoDB;')
FROM information_schema.TABLES
WHERE ENGINE = 'MyISAM'
    AND TABLE_SCHEMA NOT IN ('mysql', 'information_schema', 'performance_schema', 'sys');

-- 转换后验证：
SELECT TABLE_NAME, ENGINE FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'mydb' AND TABLE_NAME = 'mytable';
-- ENGINE: InnoDB
```

## 适用场景

- **MySQL 8.0 到 8.4 的升级准备**：在升级前检查 `my.cnf` 中是否包含 `myisam_repair_threads` 参数，如果有则移除，避免 MySQL 8.4 启动失败
- **MyISAM 到 InnoDB 的迁移规划**：随着 MyISAM 相关功能的逐步移除，应尽早将所有 MyISAM 表迁移到 InnoDB，利用 InnoDB 的事务支持、崩溃恢复、行级锁等优势

---

## 常见问题

**移除 myisam_repair_threads 后，MyISAM 表的 REPAIR TABLE 还能用吗？**

可以。`REPAIR TABLE` 命令本身没有被移除，仍然可以用于修复 MyISAM 表。只是修复操作固定为单线程执行（无法指定多线程并行重建索引）。对于大型 MyISAM 表，单线程修复可能需要更长时间。但考虑到多线程修复本身存在稳定性问题，单线程修复实际上更安全可靠。如果 MyISAM 表的修复性能是关键需求，更好的方案是将表迁移到 InnoDB——InnoDB 具有崩溃恢复能力，正常情况下不需要 `REPAIR TABLE`。

---

## 注意事项

- MySQL 8.0 的系统数据库（`mysql`）中仍有部分表使用 MyISAM 或 CSV 等非 InnoDB 引擎（如 `mysql.general_log`、`mysql.slow_log`），这些系统表不应手动转换为 InnoDB。`key_buffer_size` 参数仍然需要保留一个较小的值（如 8MB）以支持这些系统表的索引缓存。
- 在清理 `my.cnf` 中的废弃变量时，建议使用 MySQL Shell 的 `util.checkForServerUpgrade()` 工具自动检测所有需要修改的配置项，而不是手动逐一检查。该工具会列出所有已废弃和已移除的变量及其在配置文件中的位置。

---

## 总结

`myisam_repair_threads` 在 MySQL 8.0 中废弃，MySQL 8.4 中移除。该变量控制 MyISAM 表修复的并行线程数，因 MyISAM 引擎不推荐使用且多线程修复存在稳定性问题而被移除。升级处理：从 `my.cnf` 中移除 `myisam_repair_threads` 配置。`REPAIR TABLE` 仍可用（单线程）。建议将所有 MyISAM 表迁移到 InnoDB（`ALTER TABLE t ENGINE=InnoDB`）。同时检查其他 MyISAM 相关变量是否在后续版本中被移除。使用 `util.checkForServerUpgrade()` 自动检测废弃配置。
