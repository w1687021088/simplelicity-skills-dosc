# 旧 SSL 系统变量移除（ssl, have_ssl 等）

MySQL 8.0 及后续版本对 SSL/TLS 相关的系统变量进行了清理和重命名，部分旧的 SSL 状态变量和系统变量被废弃或移除。MySQL 8.4 LTS 中进一步强化了 TLS 加密连接的默认行为，并清理了遗留的变量命名。了解这些变化对于从旧版本升级到 MySQL 8.0+/8.4 非常重要，可以避免配置文件中的废弃参数导致启动失败或功能异常。

---

## 被移除或废弃的 SSL 变量

```sql
-- MySQL 8.0+ 中被废弃或移除的旧 SSL 相关变量：

-- 1. have_ssl（废弃）
-- MySQL 5.7：用于检查服务器是否支持 SSL
SHOW VARIABLES LIKE 'have_ssl';
-- have_ssl: YES / DISABLED
-- MySQL 8.0+：仍然存在但标记为废弃
-- MySQL 8.4+：可能被移除，建议使用替代方式

-- 替代方式：检查 TLS 是否启用
SHOW VARIABLES LIKE 'ssl_%';
-- 查看 ssl_ca, ssl_cert, ssl_key 等变量
-- 或者通过 Performance Schema：
SELECT * FROM performance_schema.tls_channel_status \G

-- 2. have_openssl（废弃）
-- MySQL 5.7：检查是否使用 OpenSSL 库
SHOW VARIABLES LIKE 'have_openssl';
-- MySQL 8.0+：废弃，MySQL 8.0 统一使用 OpenSSL
-- MySQL 8.0 之前支持 yaSSL 和 OpenSSL 两种 SSL 库
-- MySQL 8.0 起只支持 OpenSSL

-- 3. Ssl_* 状态变量的变化
-- 部分旧的 Ssl_ 状态变量在 MySQL 8.0+ 中被调整或移除
SHOW STATUS LIKE 'Ssl_%';
-- Ssl_cipher：当前连接使用的加密套件（仍然存在）
-- Ssl_version：当前连接的 TLS 版本（仍然存在）
```

## SSL/TLS 配置的变化

```ini
# MySQL 5.7 的 SSL 配置：
[mysqld]
ssl-ca = /etc/mysql/ca.pem
ssl-cert = /etc/mysql/server-cert.pem
ssl-key = /etc/mysql/server-key.pem

# MySQL 8.0+ 的配置（变量名相同，但行为有变化）：
[mysqld]
ssl_ca = /etc/mysql/ca.pem
ssl_cert = /etc/mysql/server-cert.pem
ssl_key = /etc/mysql/server-key.pem

# MySQL 8.0+ 的重要变化：
# 1. 默认启用 SSL
#    MySQL 8.0 在安装时自动生成 SSL 证书
#    默认启用 SSL 加密连接（不需要手动配置）

# 2. require_secure_transport（MySQL 8.0+）
#    强制所有连接必须使用 SSL
require_secure_transport = ON

# 3. tls_version 控制允许的 TLS 版本
tls_version = TLSv1.2,TLSv1.3
# MySQL 8.0.16+ 支持 TLSv1.3
# MySQL 8.0.28+ 默认禁用 TLSv1 和 TLSv1.1
```

## MySQL 8.0+ 的 TLS 版本控制

```sql
-- 查看当前允许的 TLS 版本：
SHOW VARIABLES LIKE 'tls_version';
-- tls_version: TLSv1.2,TLSv1.3

-- MySQL 8.0.28+ 默认禁用了不安全的 TLS 版本：
-- TLSv1 和 TLSv1.1 默认不再支持
-- 如果客户端只支持 TLSv1 或 TLSv1.1，连接会被拒绝

-- 查看当前连接的 TLS 信息：
SHOW STATUS LIKE 'Ssl_version';
-- Ssl_version: TLSv1.3

SHOW STATUS LIKE 'Ssl_cipher';
-- Ssl_cipher: TLS_AES_256_GCM_SHA384

-- MySQL 8.0.16+ 支持在线更换 SSL 证书：
ALTER INSTANCE RELOAD TLS;
-- 不需要重启 MySQL 即可加载新的 SSL 证书
-- 已有连接不受影响，新连接使用新证书

-- 查看 TLS 通道状态（MySQL 8.0.21+）：
SELECT * FROM performance_schema.tls_channel_status \G
-- 显示 TLS 证书信息、协议版本等
```

## 升级时的配置调整

```ini
# 从 MySQL 5.7 升级到 8.0+/8.4 时需要检查的 SSL 配置：

# 1. 移除已废弃的变量引用
# 不要在配置文件中使用：
# have_ssl（只读变量，不应出现在配置文件中）
# have_openssl（只读变量）

# 2. 更新 TLS 版本配置
# 旧配置（可能包含不安全版本）：
# tls_version = TLSv1,TLSv1.1,TLSv1.2
# 新配置（只保留安全版本）：
tls_version = TLSv1.2,TLSv1.3

# 3. 如果使用自签名证书
# MySQL 8.0 安装时自动生成自签名证书
# 位于 datadir 下：
# ca.pem, server-cert.pem, server-key.pem
# client-cert.pem, client-key.pem

# 4. 加密套件配置
# MySQL 8.0.16+ 新增 tls_ciphersuites（用于 TLSv1.3）：
tls_ciphersuites = TLS_AES_128_GCM_SHA256:TLS_AES_256_GCM_SHA384
# 旧的 ssl_cipher 仍用于 TLSv1.2：
ssl_cipher = ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384
```

## 适用场景

- **MySQL 5.7 到 8.0+/8.4 的升级准备**：在升级前检查配置文件中是否引用了已废弃的 SSL 变量，确保升级后 MySQL 能正常启动且 SSL 功能正常
- **SSL/TLS 安全加固**：利用 MySQL 8.0+ 的 TLS 版本控制功能，禁用不安全的 TLS 版本（TLSv1、TLSv1.1），强制使用 TLSv1.2 或 TLSv1.3

## 常见问题

**升级到 MySQL 8.0 后，旧的客户端无法通过 SSL 连接是什么原因？**

最可能的原因是 MySQL 8.0.28+ 默认禁用了 TLSv1 和 TLSv1.1。如果旧客户端（如很老版本的 MySQL Connector、JDBC 驱动、PHP 的 mysqlnd 等）只支持 TLSv1 或 TLSv1.1，连接会被拒绝。解决方案：①升级客户端库到支持 TLSv1.2+ 的版本（推荐）；②临时在 MySQL 配置中重新启用旧 TLS 版本（不推荐，安全风险）：`tls_version=TLSv1.1,TLSv1.2,TLSv1.3`；③使用非 SSL 连接（`--ssl-mode=DISABLED`），但这会降低安全性。

---

## 注意事项

- MySQL 8.0 默认在安装时自动生成自签名 SSL 证书并启用 SSL。如果之前的 MySQL 5.7 没有配置 SSL，升级到 8.0 后 SSL 会自动启用。这可能影响某些不支持 SSL 的旧客户端或监控工具的连接。可以通过 `--ssl-mode=DISABLED` 在客户端禁用 SSL，或在服务端设置特定用户不要求 SSL：`ALTER USER 'monitor'@'%' REQUIRE NONE`。
- `ALTER INSTANCE RELOAD TLS`（MySQL 8.0.16+）允许在不重启服务器的情况下更换 SSL 证书。这在证书轮换场景中非常有用，但需要注意新证书文件的路径必须与 `ssl_ca`、`ssl_cert`、`ssl_key` 变量中配置的路径一致。

## 总结

MySQL 8.0 废弃了 `have_ssl`、`have_openssl` 等旧变量，统一使用 OpenSSL 库。默认自动生成 SSL 证书并启用加密连接。MySQL 8.0.28+ 默认禁用 TLSv1 和 TLSv1.1，只允许 TLSv1.2 和 TLSv1.3。新增 `tls_ciphersuites`（TLSv1.3 加密套件）、`ALTER INSTANCE RELOAD TLS`（在线更换证书）、`performance_schema.tls_channel_status`（TLS 状态查看）。升级时需从配置文件移除废弃变量、更新 TLS 版本设置、确认客户端支持 TLSv1.2+。
