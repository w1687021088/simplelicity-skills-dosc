# 从 8.0 升级到 8.4 检查清单

MySQL 8.4 LTS（Long-Term Support）是 MySQL 8.0 之后的第一个 LTS 版本，提供长期支持和稳定性保证。从 MySQL 8.0 升级到 8.4 是一个大版本升级，需要仔细检查兼容性、配置变更、废弃特性移除等多方面因素。本文提供一份系统化的升级检查清单，帮助 DBA 在升级前全面评估风险并做好准备。

---

## 升级前的环境检查

```sql
-- 1. 确认当前 MySQL 版本
SELECT VERSION();
-- 必须是 MySQL 8.0.x 才能直接升级到 8.4
-- 如果是 MySQL 5.7，必须先升级到 8.0 再升级到 8.4

-- 2. 确认操作系统兼容性
-- MySQL 8.4 对操作系统版本有最低要求
-- 例如：CentOS 7+、Ubuntu 18.04+、Windows Server 2016+
-- 确认当前操作系统在 MySQL 8.4 的支持列表中

-- 3. 确认磁盘空间
-- 升级过程中可能需要额外的磁盘空间
-- 建议预留当前数据目录大小的 20% 作为缓冲
SELECT ROUND(SUM(DATA_LENGTH + INDEX_LENGTH) / 1024 / 1024 / 1024, 2) AS total_gb
FROM information_schema.TABLES;

-- 4. 确认备份
-- 升级前必须完成完整备份
-- 包括数据目录、配置文件、binlog 等
-- 建议使用物理备份（如 Percona XtraBackup）
```

```sql
-- 6. 外键引用非唯一键

-- 8. 空间数据类型兼容性
-- 9. 表名和列名的长度限制
-- 10. 其他已知的不兼容项

-- 检查结果分为三个级别：
-- Error（必须修复）：不修复将导致升级失败
-- Warning（建议修复）：可能影响升级后的功能
-- Notice（信息提示）：行为变化的提醒
```

## 数据兼容性检查

```sql
-- 1. 检查表的存储引擎
-- 确认是否有 MyISAM 用户表需要转换为 InnoDB
SELECT TABLE_SCHEMA, TABLE_NAME, ENGINE
FROM information_schema.TABLES
WHERE ENGINE != 'InnoDB'
    AND TABLE_SCHEMA NOT IN ('mysql', 'information_schema', 'performance_schema', 'sys')
ORDER BY TABLE_SCHEMA, TABLE_NAME;

-- 2. 检查字符集和排序规则
-- MySQL 8.0 默认字符集为 utf8mb4，排序规则为 utf8mb4_0900_ai_ci
-- 检查是否有使用旧字符集的表
SELECT TABLE_SCHEMA, TABLE_NAME, TABLE_COLLATION
FROM information_schema.TABLES
WHERE TABLE_COLLATION NOT LIKE 'utf8mb4%'
    AND TABLE_SCHEMA NOT IN ('mysql', 'information_schema', 'performance_schema', 'sys');

-- 3. 检查外键引用非唯一键
SELECT tc.TABLE_SCHEMA, tc.TABLE_NAME, tc.CONSTRAINT_NAME,
       kcu.REFERENCED_TABLE_NAME, kcu.REFERENCED_COLUMN_NAME
FROM information_schema.TABLE_CONSTRAINTS tc
JOIN information_schema.KEY_COLUMN_USAGE kcu
    ON tc.CONSTRAINT_NAME = kcu.CONSTRAINT_NAME
    AND tc.TABLE_SCHEMA = kcu.TABLE_SCHEMA
WHERE tc.CONSTRAINT_TYPE = 'FOREIGN KEY';

-- 4. 检查是否有使用废弃认证插件的用户
SELECT User, Host, plugin FROM mysql.user
WHERE plugin IN ('mysql_native_password', 'sha256_password');
-- mysql_native_password 在 8.4 中已废弃
-- 建议迁移到 caching_sha2_password

-- 5. 检查分区表
SELECT TABLE_SCHEMA, TABLE_NAME, PARTITION_METHOD
FROM information_schema.PARTITIONS
WHERE PARTITION_METHOD IS NOT NULL
GROUP BY TABLE_SCHEMA, TABLE_NAME, PARTITION_METHOD;
```

## 复制环境的升级注意事项

```sql
-- 如果使用主从复制或 Group Replication：

-- 1. 升级顺序：先升级从库，最后升级主库
-- 从库先升级到 8.4 → 验证复制正常 → 再升级主库
-- 高版本的从库可以从低版本的主库复制（反过来不行）

-- 2. 检查复制相关的术语变更
-- SHOW SLAVE STATUS → SHOW REPLICA STATUS
-- CHANGE MASTER TO → CHANGE REPLICATION SOURCE TO
-- START SLAVE → START REPLICA
-- 旧语法在 8.4 中可能被移除

-- 3. 检查 GTID 配置
SHOW VARIABLES LIKE 'gtid_mode';
-- 建议使用 GTID 复制（gtid_mode=ON）

-- 4. 检查 binlog 格式
SHOW VARIABLES LIKE 'binlog_format';
-- MySQL 8.4 可能移除 STATEMENT 和 MIXED 格式
-- 建议使用 ROW 格式

-- 5. Group Replication 的升级
-- MGR 集群的升级需要滚动升级
-- 确保所有成员使用兼容的通信协议版本
SELECT @@group_replication_communication_stack;
```

## 升级执行步骤

```
完整的升级执行步骤：

升级前（提前数天/数周）：
  □ 运行 checkForServerUpgrade 检查工具
  □ 修复所有 Error 级别的问题
  □ 评估所有 Warning 级别的问题
  □ 更新 my.cnf（移除废弃变量、更新重命名变量）
  □ 测试环境中完成升级测试
  □ 验证应用兼容性（SQL 语法、连接参数等）
  □ 更新客户端驱动（JDBC、Python Connector 等）

升级当天：
  □ 完成完整备份（物理备份 + binlog）
  □ 通知相关团队进入维护窗口
  □ 停止应用写入（或切换到只读模式）
  □ 确认复制同步完成（如果有从库）
  □ 停止 MySQL 服务
  □ 替换二进制文件为 8.4 版本
  □ 启动 MySQL 8.4（自动执行数据字典升级）
  □ 检查 Error Log 确认无错误
  □ 验证核心功能（连接、查询、写入）
  □ 恢复应用流量
  □ 持续监控性能和错误日志

升级后（数天内）：
  □ 监控慢查询日志（执行计划可能变化）
  □ 监控应用层错误日志
  □ 确认备份策略在新版本上正常工作
  □ 更新运维脚本和监控工具
```

## 常见问题

**MySQL 8.0 到 8.4 可以原地升级（in-place upgrade）吗？**

可以。MySQL 支持从 8.0 到 8.4 的原地升级——直接替换二进制文件并启动即可，服务器会自动升级数据字典和系统表。也支持逻辑升级（logical upgrade）——从 8.0 导出数据，在 8.4 中重新导入。原地升级速度更快（不需要导出导入数据），但回滚困难（需要从备份恢复）。逻辑升级回滚容易（保留旧的数据目录），但大数据量时耗时很长。对于生产环境，推荐原地升级 + 完整备份作为回滚手段。

---

## 注意事项

- MySQL 不支持跨大版本直接升级（如 5.7 → 8.4）。必须按照 5.7 → 8.0 → 8.4 的路径逐步升级。每次升级后都应验证功能正常后再进行下一步。
- 升级到 MySQL 8.4 后，不能降级回 MySQL 8.0。如果升级后发现严重问题需要回退，只能通过升级前的备份恢复到 MySQL 8.0。因此升级前的完整备份是必须的，不能省略。

## 总结

从 MySQL 8.0 升级到 8.4 的核心检查项：①运行 `checkForServerUpgrade` 检查工具；②清理 `my.cnf` 中的废弃/移除变量；③检查认证插件（迁移 `mysql_native_password` 到 `caching_sha2_password`）；④检查复制配置（术语变更、binlog 格式、GTID）；⑤检查存储引擎（MyISAM → InnoDB）；⑥更新客户端驱动；⑦完成完整备份。升级路径：8.0 → 8.4（原地升级）。复制环境先升级从库后升级主库。不支持降级，必须有备份。支持原地升级和逻辑升级两种方式。
