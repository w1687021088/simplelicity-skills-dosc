# mysql_upgrade 工具移除

`mysql_upgrade` 是 MySQL 5.x 和部分 8.0 早期版本中用于升级后检查和修复系统表的命令行工具。MySQL 8.0.16 开始，`mysql_upgrade` 的功能被整合到 MySQL 服务器（`mysqld`）的启动过程中——服务器在启动时自动检测是否需要升级系统表，并自动完成升级操作。从 MySQL 8.0.16 起，`mysql_upgrade` 工具被标记为废弃；在 MySQL 8.4 LTS 中，该工具已被完全移除。

---

## mysql_upgrade 的历史作用

```
mysql_upgrade 的传统用途：

1. 升级系统表（mysql 数据库中的表）
   - 检查系统表的结构是否与当前版本匹配
   - 添加新版本引入的系统表或列
   - 修复系统表的字符集和排序规则

2. 检查和修复用户表
   - 对所有用户表执行 CHECK TABLE
   - 检查表结构与当前版本的兼容性
   - 标记需要重建的表

3. 更新权限表
   - 添加新版本引入的权限列
   - 更新 grant tables 的结构

传统升级流程（MySQL 5.7 → 8.0 早期）：
  1. 停止旧版本 MySQL
  2. 替换二进制文件为新版本
  3. 启动新版本 MySQL
  4. 运行 mysql_upgrade   ← 必须步骤
  5. 重启 MySQL（使升级生效）

如果忘记运行 mysql_upgrade：
  - 系统表结构不正确
  - 新功能可能无法使用
  - 权限表可能缺少新列
  - 可能出现各种奇怪的错误
```

## MySQL 8.0.16+ 的自动升级机制

```sql
-- MySQL 8.0.16+ 中，升级检查和修复由 mysqld 在启动时自动完成

-- 启动时的自动升级行为由 --upgrade 参数控制：

-- 1. --upgrade=AUTO（默认值）
-- 启动时自动检查数据字典和系统表是否需要升级
-- 如果需要，自动执行升级操作
-- 升级完成后正常启动服务

-- 2. --upgrade=NONE
-- 跳过所有升级检查
-- 如果系统表需要升级但未执行，可能导致功能异常
-- 仅在特殊情况下使用（如紧急启动）

-- 3. --upgrade=MINIMAL
-- 只升级数据字典（DD）表
-- 不升级系统表（Performance Schema、sys schema 等）
-- 用于快速启动，稍后手动完成剩余升级

-- 4. --upgrade=FORCE
-- 强制执行所有升级操作，即使版本号未变化
-- 用于修复可能损坏的系统表

-- 查看升级状态：
SELECT * FROM performance_schema.error_log
WHERE DATA LIKE '%upgrade%'
ORDER BY LOGGED DESC LIMIT 20;
```

```ini
# my.cnf 配置示例：
[mysqld]
# 默认行为（自动升级）：
upgrade = AUTO

# 跳过升级（紧急启动）：
# upgrade = NONE

# 强制升级：
# upgrade = FORCE
```

## 新的升级流程

```
MySQL 8.0.16+ / 8.4 的升级流程（不再需要 mysql_upgrade）：

1. 停止旧版本 MySQL
   systemctl stop mysqld

2. 替换二进制文件为新版本
   （通过包管理器升级或替换二进制文件）

3. 启动新版本 MySQL
   systemctl start mysqld
   → mysqld 自动检测数据字典版本
   → 自动执行必要的升级操作
   → 在 Error Log 中记录升级过程
   → 升级完成后正常提供服务

4. 验证升级完成
   查看 Error Log 确认无错误
   检查系统表版本
```

```sql
-- 验证升级是否完成：

-- 检查 Error Log 中的升级信息：
SELECT LOGGED, PRIO, DATA FROM performance_schema.error_log
WHERE DATA LIKE '%upgrad%' OR DATA LIKE '%Data Dictionary%'
ORDER BY LOGGED DESC LIMIT 10;

-- 检查数据字典版本：
SELECT * FROM mysql.dd_properties
WHERE properties LIKE '%dd_version%';

-- 检查服务器版本：
SELECT VERSION();
```

## 从旧版本升级的注意事项

```sql
-- 从 MySQL 5.7 升级到 8.0/8.4 的特殊考虑：

-- 1. MySQL 5.7 → 8.0 仍然需要 mysql_upgrade（如果是 8.0.16 之前的版本）
-- MySQL 5.7 → 8.0.16+ 不需要 mysql_upgrade（自动升级）

-- 2. 不支持跨大版本直接升级
-- MySQL 5.7 → 8.4 不支持直接升级
-- 必须先升级到 8.0，再从 8.0 升级到 8.4
-- 路径：5.7 → 8.0 → 8.4

-- 3. 升级前检查
-- 使用 MySQL Shell 的升级检查工具：
-- mysqlsh -- util checkForServerUpgrade root@localhost:3306

-- 4. 旧的 mysql_upgrade 命令在 8.4 中不存在
-- 如果脚本中还在调用 mysql_upgrade：
-- mysql_upgrade -u root -p
-- → 命令不存在，报错
-- → 从脚本中移除此步骤
```

## 适用场景

- **MySQL 升级流程的简化**：从 MySQL 8.0.16+ 开始，升级后不再需要单独运行 `mysql_upgrade`，服务器启动时自动完成升级操作，减少了运维步骤和人为遗忘的风险
- **自动化部署脚本的更新**：如果现有的自动化部署或升级脚本中包含 `mysql_upgrade` 步骤，升级到 MySQL 8.0.16+/8.4 后需要从脚本中移除该步骤

## 常见问题

**如果自动升级失败（--upgrade=AUTO），MySQL 还能启动吗？**

如果自动升级过程中遇到错误，MySQL 服务器可能无法正常启动。Error Log 中会记录详细的错误信息。常见的升级失败原因：①磁盘空间不足（升级过程需要修改系统表）；②数据字典损坏；③权限不足（MySQL 进程无法修改系统表文件）。处理方法：使用 `--upgrade=NONE` 启动 MySQL（跳过升级），分析 Error Log 定位问题，修复后使用 `--upgrade=FORCE` 重新启动执行升级。如果问题严重，可能需要从备份恢复。

## 注意事项

- 在 MySQL 8.4 中，`mysql_upgrade` 二进制文件已被完全移除。如果运维脚本、CI/CD 流水线、或监控工具中仍然调用 `mysql_upgrade`，会因为命令不存在而报错。升级到 8.4 前应全面检查所有相关脚本和工具。
- 自动升级（`--upgrade=AUTO`）在大型数据库中可能需要较长时间（几分钟到几十分钟），因为需要检查和修改系统表。在此期间 MySQL 服务不可用。建议在维护窗口进行升级，并预留足够的启动时间。可以通过 Error Log 实时监控升级进度。

## 总结

MySQL 8.0.16 起，`mysql_upgrade` 的功能被整合到 `mysqld` 启动过程中（`--upgrade=AUTO` 默认自动升级）。MySQL 8.4 LTS 中 `mysql_upgrade` 工具已被完全移除。升级流程简化为：停止旧版本 → 替换二进制 → 启动新版本（自动完成升级）。`--upgrade` 参数：`AUTO`（默认自动）、`NONE`（跳过）、`MINIMAL`（仅数据字典）、`FORCE`（强制全部）。升级前使用 MySQL Shell 的 `checkForServerUpgrade()` 检查兼容性。从脚本中移除 `mysql_upgrade` 调用。不支持跨大版本直接升级（5.7→8.0→8.4）。
