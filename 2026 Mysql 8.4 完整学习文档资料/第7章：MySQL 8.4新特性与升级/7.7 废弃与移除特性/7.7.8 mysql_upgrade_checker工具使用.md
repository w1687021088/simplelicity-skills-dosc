# mysql_upgrade_checker 工具使用

MySQL Shell 提供了 `util.checkForServerUpgrade()` 升级检查工具（也被称为 Upgrade Checker），用于在升级 MySQL 之前自动检测当前实例中存在的兼容性问题。该工具会分析系统变量、用户权限、表结构、SQL 语法等多个维度，输出详细的检查报告，标明哪些问题必须在升级前修复（Error）、哪些建议修复（Warning）、哪些仅作提醒（Notice）。这是 MySQL 官方推荐的升级前必备步骤。

---

## 工具的安装与调用

```bash
# mysql_upgrade_checker 是 MySQL Shell 的内置功能
# 首先确保安装了 MySQL Shell

# Linux 安装 MySQL Shell：
# yum install mysql-shell    （RHEL/CentOS）
# apt install mysql-shell    （Ubuntu/Debian）

# Windows 安装：
# 从 MySQL 官网下载 MySQL Shell 安装包

# 启动 MySQL Shell：
mysqlsh

# 在 MySQL Shell 中调用升级检查：
# 方法1：交互模式
mysqlsh root@localhost:3306
util.checkForServerUpgrade()

# 方法2：指定目标版本
util.checkForServerUpgrade({"targetVersion": "8.4.0"})

# 方法3：命令行直接调用
mysqlsh -- util checkForServerUpgrade root@localhost:3306 --target-version=8.4.0

# 方法4：输出到文件
util.checkForServerUpgrade({"targetVersion": "8.4.0", "outputFormat": "JSON"})
```

## 检查项目详解

```
Upgrade Checker 会执行以下类别的检查：

1. 已移除的系统变量
   检查 my.cnf 和运行时配置中是否使用了目标版本已移除的变量
   例如：query_cache_type, myisam_repair_threads 等
   级别：Error（必须修复）

2. 已废弃的系统变量
   检查是否使用了目标版本中标记为废弃的变量
   例如：log_bin_use_v1_row_events 等
   级别：Warning（建议修复）

3. 认证插件兼容性
   检查用户是否使用了废弃的认证插件
   例如：mysql_native_password
   级别：Warning

4. 废弃的 SQL 语法
   检查存储过程、触发器、事件中是否使用了废弃语法
   例如：GROUP BY ... ASC/DESC, SQL_CALC_FOUND_ROWS 等
   级别：Warning

5. 表结构兼容性
   - 外键引用非唯一键
   - 分区表的兼容性
   - 数据类型的变化
   - 字符集和排序规则
   级别：Warning 或 Error

6. 存储引擎
   检查是否有使用非 InnoDB 引擎的用户表
   级别：Notice

7. Schema 和表名
   检查表名、列名是否与新版本的保留字冲突
   级别：Warning

8. 复制配置
   检查复制相关参数的兼容性
   级别：Warning

9. 空间数据类型
   检查 GIS 数据类型的兼容性变化
   级别：Notice

10. 默认值变化
    提醒目标版本中默认值发生变化的参数
    级别：Notice
```

## 检查报告解读

```
检查报告的输出格式：

=== 检查报告示例 ===

1) Removed system variables
   检查已移除的系统变量...
   
   Error: 以下系统变量在目标版本中已被移除：
   - query_cache_type（当前值：1）
   - myisam_repair_threads（当前值：4）
   
   修复建议：从 my.cnf 中移除这些变量

2) Users using deprecated authentication plugins
   检查用户认证插件...
   
   Warning: 以下用户使用了废弃的认证插件：
   - 'app_user'@'%' 使用 mysql_native_password
   - 'monitor'@'localhost' 使用 mysql_native_password
   
   修复建议：ALTER USER 'app_user'@'%' IDENTIFIED WITH caching_sha2_password BY 'password';

3) Tables using non-InnoDB storage engines
   检查存储引擎...
   
   Notice: 以下用户表使用非 InnoDB 引擎：
   - mydb.legacy_table (MyISAM)
   
   建议：ALTER TABLE mydb.legacy_table ENGINE=InnoDB;

=== 检查总结 ===
Errors:   2（必须修复）
Warnings: 5（建议修复）
Notices:  3（信息提示）
```

## 常用参数

```bash
# util.checkForServerUpgrade() 的参数选项：

# targetVersion：目标升级版本
util.checkForServerUpgrade({"targetVersion": "8.4.0"})

# outputFormat：输出格式
# "TEXT"（默认，人类可读）
# "JSON"（结构化，适合脚本解析）
util.checkForServerUpgrade({"outputFormat": "JSON"})

# configPath：指定 my.cnf 路径（检查配置文件中的废弃变量）
util.checkForServerUpgrade({"configPath": "/etc/my.cnf"})

# 组合使用：
util.checkForServerUpgrade({
    "targetVersion": "8.4.0",
    "outputFormat": "TEXT",
    "configPath": "/etc/my.cnf"
})

# 命令行模式：
mysqlsh -- util checkForServerUpgrade root@localhost:3306 \
    --target-version=8.4.0 \
    --output-format=JSON \
    --config-path=/etc/my.cnf
```

## 修复常见问题的示例

```sql
-- 根据检查报告修复常见问题：

-- 1. 修复废弃认证插件
ALTER USER 'app_user'@'%' IDENTIFIED WITH caching_sha2_password BY 'new_password';

-- 2. 转换 MyISAM 表为 InnoDB
ALTER TABLE mydb.legacy_table ENGINE = InnoDB;

-- 3. 修复外键引用非唯一键
-- 先删除旧外键
ALTER TABLE child_table DROP FOREIGN KEY fk_name;
-- 在父表上添加唯一索引
ALTER TABLE parent_table ADD UNIQUE INDEX uniq_col (referenced_col);
-- 重新创建外键
ALTER TABLE child_table ADD FOREIGN KEY (col) REFERENCES parent_table(referenced_col);

-- 4. 修复废弃 SQL 语法（存储过程/触发器/事件中）
-- 旧语法：SELECT SQL_CALC_FOUND_ROWS * FROM t; SELECT FOUND_ROWS();
-- 新语法：SELECT COUNT(*) FROM t; SELECT * FROM t LIMIT ...;

-- 5. 修复保留字冲突
-- 如果表名或列名与新版本保留字冲突
-- 使用反引号包裹：`groups`, `rank` 等
```

## 适用场景

- **升级前的全面兼容性检查**：在计划升级到 MySQL 8.0+/8.4 之前，运行该工具对当前实例进行全面检查，获取需要修复的问题清单和修复建议
- **持续集成中的升级就绪检查**：在 CI/CD 流水线中定期运行升级检查（JSON 输出 + 脚本解析），持续监控代码和配置中的兼容性问题，确保随时可以升级

## 常见问题

**checkForServerUpgrade 需要什么权限？**

该工具需要连接到 MySQL 服务器并读取系统表和元数据，建议使用具有以下权限的用户：`SELECT` 权限（用于读取 `information_schema`、`performance_schema`、`mysql` 等系统数据库）、`PROCESS` 权限（用于查看服务器状态）、`RELOAD` 权限（用于某些检查项）。最简单的方式是使用 `root` 用户运行。如果不使用 `root`，至少需要 `SELECT ON *.*` 和 `PROCESS` 权限。该工具是只读的，不会修改任何数据或配置。

---

## 注意事项

- `util.checkForServerUpgrade()` 只进行检查和报告，不会自动修复任何问题。所有修复操作需要 DBA 手动执行。建议先在测试环境中验证修复方案，确认无副作用后再在生产环境执行。
- 检查工具的结果可能随 MySQL Shell 版本更新而变化（新版本可能添加更多检查项）。建议使用与目标 MySQL 版本匹配的最新 MySQL Shell 版本运行检查，以获取最完整的检查结果。例如升级到 MySQL 8.4，建议使用 MySQL Shell 8.4 版本。

## 总结

`util.checkForServerUpgrade()` 是 MySQL Shell 的内置升级检查工具，在升级前自动检测兼容性问题。检查项包括：已移除/废弃的系统变量、认证插件、SQL 语法、表结构、存储引擎、保留字冲突、复制配置等。结果分三级：Error（必须修复）、Warning（建议修复）、Notice（信息提示）。参数：`targetVersion`（目标版本）、`outputFormat`（TEXT/JSON）、`configPath`（my.cnf 路径）。工具只读不修改数据。建议使用与目标版本匹配的 MySQL Shell 版本运行。是 MySQL 官方推荐的升级前必备步骤。
