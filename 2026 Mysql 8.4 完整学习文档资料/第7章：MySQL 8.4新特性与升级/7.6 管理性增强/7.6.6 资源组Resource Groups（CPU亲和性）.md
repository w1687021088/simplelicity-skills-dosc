# 资源组 Resource Groups（CPU 亲和性）

MySQL 8.0 引入了资源组（Resource Groups）功能，允许 DBA 将 MySQL 内部线程绑定到特定的 CPU 核心上运行，实现 CPU 资源的隔离和分配。通过资源组，可以将不同类型的工作负载（如 OLTP 查询、后台批量任务、备份操作）分配到不同的 CPU 核心，避免它们互相争抢 CPU 资源。这是操作系统级别 CPU 亲和性（CPU Affinity）在 MySQL 层面的实现。

---

## 资源组的核心概念

```
资源组的两种类型：

1. SYSTEM 类型（系统资源组）
   - 用于 MySQL 内部系统线程
   - 如 InnoDB 后台线程、Purge 线程、Page Cleaner 线程等
   - 优先级范围：-20 到 0（数值越小优先级越高）
   - 默认系统资源组：SYS_default

2. USER 类型（用户资源组）
   - 用于用户连接线程（处理 SQL 查询的线程）
   - 优先级范围：0 到 19（数值越小优先级越高）
   - 默认用户资源组：USR_default

线程优先级的含义：
  优先级通过 Linux 的 nice 值实现
  -20（最高优先级）→ 0（默认）→ 19（最低优先级）
  SYSTEM 类型可以设置 -20~0（高于或等于默认优先级）
  USER 类型只能设置 0~19（等于或低于默认优先级）

注意：设置线程优先级需要 MySQL 进程有 CAP_SYS_NICE 权限
```

## 查看默认资源组

```sql
-- 查看所有资源组：
SELECT * FROM information_schema.RESOURCE_GROUPS \G

-- 默认存在两个资源组：

-- 1. USR_default（用户线程默认组）
-- RESOURCE_GROUP_NAME: USR_default
-- RESOURCE_GROUP_TYPE: USER
-- RESOURCE_GROUP_ENABLED: 1
-- VCPU_IDS: 0-N（所有 CPU 核心）
-- THREAD_PRIORITY: 0

-- 2. SYS_default（系统线程默认组）
-- RESOURCE_GROUP_NAME: SYS_default
-- RESOURCE_GROUP_TYPE: SYSTEM
-- RESOURCE_GROUP_ENABLED: 1
-- VCPU_IDS: 0-N（所有 CPU 核心）
-- THREAD_PRIORITY: 0

-- 查看当前线程所属的资源组：
SELECT RESOURCE_GROUP FROM performance_schema.threads
WHERE PROCESSLIST_ID = CONNECTION_ID();
```

## 创建自定义资源组

```sql
-- 创建用于 OLTP 查询的高优先级资源组（绑定到 CPU 0-3）：
CREATE RESOURCE GROUP oltp_group
    TYPE = USER
    VCPU = 0-3
    THREAD_PRIORITY = 0
    ENABLE;

-- 创建用于批量任务的低优先级资源组（绑定到 CPU 4-7）：
CREATE RESOURCE GROUP batch_group
    TYPE = USER
    VCPU = 4-7
    THREAD_PRIORITY = 10
    ENABLE;

-- 创建用于报表查询的资源组（绑定到 CPU 6-7）：
CREATE RESOURCE GROUP report_group
    TYPE = USER
    VCPU = 6-7
    THREAD_PRIORITY = 15
    ENABLE;

-- 创建系统线程资源组（如 InnoDB 后台线程）：
CREATE RESOURCE GROUP innodb_bg
    TYPE = SYSTEM
    VCPU = 0-1
    THREAD_PRIORITY = -10
    ENABLE;

-- 查看创建的资源组：
SELECT RESOURCE_GROUP_NAME, RESOURCE_GROUP_TYPE, 
       RESOURCE_GROUP_ENABLED, VCPU_IDS, THREAD_PRIORITY
FROM information_schema.RESOURCE_GROUPS;
```

## 将线程分配到资源组

```sql
-- 方法1：通过 Hint 指定当前查询使用的资源组
SELECT /*+ RESOURCE_GROUP(batch_group) */ *
FROM large_table WHERE created_at > '2024-01-01';

-- 方法2：通过 SET RESOURCE GROUP 设置当前会话
SET RESOURCE GROUP batch_group;
-- 当前会话后续的所有查询都在 batch_group 中执行

-- 方法3：将指定线程分配到资源组
SET RESOURCE GROUP batch_group FOR thread_id;
-- thread_id 从 performance_schema.threads 获取

-- 查看线程的资源组分配：
SELECT THREAD_ID, PROCESSLIST_ID, PROCESSLIST_USER, 
       PROCESSLIST_COMMAND, RESOURCE_GROUP
FROM performance_schema.threads
WHERE PROCESSLIST_USER IS NOT NULL;
```

## 管理资源组

```sql
-- 修改资源组：
ALTER RESOURCE GROUP batch_group
    VCPU = 4-5
    THREAD_PRIORITY = 15;

-- 禁用资源组（不影响已分配的线程）：
ALTER RESOURCE GROUP batch_group DISABLE;

-- 强制移动已分配线程并禁用：
ALTER RESOURCE GROUP batch_group DISABLE FORCE;
-- FORCE 会将该组的线程移回默认组

-- 启用资源组：
ALTER RESOURCE GROUP batch_group ENABLE;

-- 删除资源组：
DROP RESOURCE GROUP batch_group;

-- 强制删除（移走线程后删除）：
DROP RESOURCE GROUP batch_group FORCE;

-- 权限要求：
-- CREATE/ALTER/DROP RESOURCE GROUP 需要 RESOURCE_GROUP_ADMIN 权限
-- SET RESOURCE GROUP 需要 RESOURCE_GROUP_ADMIN 或 RESOURCE_GROUP_USER 权限
GRANT RESOURCE_GROUP_ADMIN ON *.* TO 'dba'@'%';
GRANT RESOURCE_GROUP_USER ON *.* TO 'app_user'@'%';
```

## 适用场景

- **OLTP 与批量任务的 CPU 隔离**：在同一台服务器上运行 OLTP 实时查询和批量数据处理任务时，通过资源组将它们绑定到不同的 CPU 核心，防止批量任务抢占 OLTP 查询的 CPU 资源
- **多租户环境的资源分配**：在多个应用共享同一个 MySQL 实例时，为每个应用创建独立的资源组并分配不同的 CPU 核心，实现租户间的资源隔离

## 常见问题

**资源组在所有操作系统上都有效吗？**

资源组的 CPU 亲和性（VCPU 绑定）在 Linux 和 FreeBSD 上有效，在 Windows 和 macOS 上不支持 CPU 绑定（VCPU 设置会被忽略）。线程优先级（THREAD_PRIORITY）在 Linux 上需要 MySQL 进程具有 `CAP_SYS_NICE` 权限，否则只能设置优先级为 0。可以通过以下命令授予权限：`sudo setcap cap_sys_nice+ep /usr/sbin/mysqld`。如果没有 `CAP_SYS_NICE` 权限，创建非 0 优先级的资源组会成功，但实际分配线程时优先级设置不生效。

---

## 注意事项

- 资源组只控制 CPU 资源（核心绑定和优先级），不控制内存、磁盘 I/O 或网络带宽。如果需要更全面的资源隔离，需要配合操作系统级别的 cgroup 或容器化方案。
- VCPU 设置中的 CPU 编号必须在服务器实际拥有的 CPU 核心范围内。如果指定了不存在的 CPU 编号（如服务器只有 8 核但指定了 VCPU=0-15），`CREATE RESOURCE GROUP` 会报错。可以通过 `SELECT @@thread_pool_size` 或操作系统命令（`nproc`）确认可用的 CPU 核心数。

## 总结

资源组（Resource Groups）是 MySQL 8.0 的 CPU 资源管理功能，通过 CPU 亲和性（VCPU 绑定）和线程优先级实现 CPU 资源隔离。两种类型：SYSTEM（系统线程，优先级 -20~0）和 USER（用户线程，优先级 0~19）。创建：`CREATE RESOURCE GROUP name TYPE=USER VCPU=0-3 THREAD_PRIORITY=0`。分配：`SET RESOURCE GROUP name` 或 `/*+ RESOURCE_GROUP(name) */` Hint。权限：`RESOURCE_GROUP_ADMIN` / `RESOURCE_GROUP_USER`。Linux 上需要 `CAP_SYS_NICE` 权限才能设置非 0 优先级。只控制 CPU，不控制内存和 I/O。
