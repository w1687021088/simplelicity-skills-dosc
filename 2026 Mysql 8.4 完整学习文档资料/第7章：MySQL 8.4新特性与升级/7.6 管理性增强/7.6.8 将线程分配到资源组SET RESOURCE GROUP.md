# 将线程分配到资源组 SET RESOURCE GROUP

`SET RESOURCE GROUP` 是 MySQL 8.0 引入的命令，用于将当前会话的线程或指定线程分配到某个资源组中执行。分配后，该线程将受到资源组定义的 CPU 核心绑定和线程优先级约束。MySQL 还支持通过查询 Hint `/*+ RESOURCE_GROUP(name) */` 在单条 SQL 语句级别指定资源组，提供了更细粒度的资源控制能力。

---

## 基本语法

```sql
-- 语法1：将当前会话分配到资源组
SET RESOURCE GROUP group_name;

-- 语法2：将指定线程分配到资源组
SET RESOURCE GROUP group_name FOR thread_id;
-- thread_id 是 performance_schema.threads 中的 THREAD_ID

-- 示例：将当前会话分配到批量任务资源组
SET RESOURCE GROUP rg_batch;
-- 当前会话后续的所有 SQL 都在 rg_batch 中执行
-- 直到会话结束或重新分配到其他资源组

-- 恢复到默认资源组：
SET RESOURCE GROUP USR_default;
```

---

## 通过 Hint 指定资源组

```sql
-- 使用 RESOURCE_GROUP Hint 在单条查询级别指定资源组
-- 只影响当前查询，不影响会话的后续查询

-- 批量导入时使用低优先级资源组：
INSERT /*+ RESOURCE_GROUP(rg_batch) */ INTO target_table
SELECT * FROM source_table WHERE created_at > '2024-01-01';

-- 报表查询使用报表资源组：
SELECT /*+ RESOURCE_GROUP(rg_report) */
    department, COUNT(*), SUM(salary)
FROM employees
GROUP BY department;

-- 备份查询使用备份资源组：
SELECT /*+ RESOURCE_GROUP(rg_backup) */ *
FROM large_table INTO OUTFILE '/tmp/backup.csv';

-- Hint 的优先级高于 SET RESOURCE GROUP
-- 即使当前会话已 SET RESOURCE GROUP rg_oltp
-- 带有 RESOURCE_GROUP(rg_batch) Hint 的查询仍在 rg_batch 中执行
```

## 将指定线程分配到资源组

```sql
-- 查看当前所有用户线程及其资源组：
SELECT THREAD_ID, PROCESSLIST_ID, PROCESSLIST_USER,
       PROCESSLIST_HOST, PROCESSLIST_COMMAND, RESOURCE_GROUP
FROM performance_schema.threads
WHERE TYPE = 'FOREGROUND' AND PROCESSLIST_USER IS NOT NULL;

-- 将特定线程分配到资源组：
-- 假设线程 THREAD_ID = 50 是一个正在执行大查询的连接
SET RESOURCE GROUP rg_batch FOR 50;
-- 该线程立即被移到 rg_batch 资源组

-- 将多个线程分配到同一个资源组（需要逐一执行）：
SET RESOURCE GROUP rg_batch FOR 50;
SET RESOURCE GROUP rg_batch FOR 51;
SET RESOURCE GROUP rg_batch FOR 52;

-- 将系统线程分配到系统资源组：
-- 先找到 InnoDB 后台线程的 THREAD_ID：
SELECT THREAD_ID, NAME, RESOURCE_GROUP
FROM performance_schema.threads
WHERE NAME LIKE 'thread/innodb/%';

-- 分配到系统资源组：
SET RESOURCE GROUP rg_innodb FOR 35;
-- 注意：系统线程只能分配到 SYSTEM 类型的资源组
-- 用户线程只能分配到 USER 类型的资源组
```

## 权限要求

```sql
-- SET RESOURCE GROUP 需要以下权限之一：
-- RESOURCE_GROUP_ADMIN：完全管理权限
-- RESOURCE_GROUP_USER：只允许分配线程到资源组

-- 授予应用用户切换资源组的权限：
GRANT RESOURCE_GROUP_USER ON *.* TO 'app_user'@'%';
-- app_user 可以 SET RESOURCE GROUP 和使用 RESOURCE_GROUP Hint
-- 但不能 CREATE/ALTER/DROP RESOURCE GROUP

-- 将其他用户的线程分配到资源组（FOR thread_id）：
-- 需要 RESOURCE_GROUP_ADMIN 权限
-- RESOURCE_GROUP_USER 只能分配自己的线程

-- 安全的权限模型：
-- DBA：RESOURCE_GROUP_ADMIN（完全管理）
-- 应用用户：RESOURCE_GROUP_USER（只能切换自己的资源组）
-- 普通用户：无权限（始终使用默认资源组）
```

## 资源组分配的生效与持续

```sql
-- SET RESOURCE GROUP 的生效时机：
-- 立即生效，当前正在执行的查询完成后，下一个查询开始时应用新的资源组设置

-- 持续时间：
-- SET RESOURCE GROUP：持续到会话结束或重新分配
-- RESOURCE_GROUP Hint：仅当前查询

-- 会话断开后：
-- 资源组分配随会话消失
-- 新连接使用默认资源组（USR_default）
-- 没有"自动分配"机制

-- 自动分配的替代方案：
-- 1. 在应用的连接初始化代码中执行 SET RESOURCE GROUP
-- 2. 使用 init_connect 系统变量（对非 SUPER 用户的每个新连接自动执行）
SET GLOBAL init_connect = 'SET RESOURCE GROUP rg_oltp';
-- 注意：init_connect 对具有 CONNECTION_ADMIN 权限的用户不执行

-- 3. 在连接池的初始化 SQL 中配置
-- HikariCP：connectionInitSql = "SET RESOURCE GROUP rg_oltp"
-- Druid：initConnectionSqls = ["SET RESOURCE GROUP rg_oltp"]
```

## 适用场景

- **在线批量操作的资源限制**：当需要在生产环境执行大批量数据清洗、迁移或统计任务时，通过 `SET RESOURCE GROUP rg_batch` 将当前会话限制在低优先级资源组，减少对在线业务的影响
- **慢查询的紧急降级**：DBA 发现某个连接正在执行资源密集型查询影响了其他业务时，可以通过 `SET RESOURCE GROUP rg_low FOR thread_id` 将该线程移到低优先级组，立即降低其对 CPU 的占用

## 常见问题

**SET RESOURCE GROUP 对当前正在执行的查询有效吗？**

`SET RESOURCE GROUP` 对当前正在执行的查询没有即时效果。资源组的切换在下一个查询开始执行时才生效。如果需要立即影响正在执行的查询，可以使用 `SET RESOURCE GROUP group_name FOR thread_id` 将目标线程从外部切换——这种方式会在操作系统层面立即调整线程的 CPU 亲和性和优先级，但正在执行的查询可能需要等到下次 CPU 调度时才能感受到变化。对于 `RESOURCE_GROUP` Hint，它在查询开始执行时就确定了资源组，因此是即时生效的。

## 注意事项

- USER 类型的资源组只能分配给用户线程（前台线程），SYSTEM 类型的资源组只能分配给系统线程（后台线程）。如果尝试将用户线程分配到 SYSTEM 资源组，会报错：`ERROR 3654: Incorrect resource group type for the thread`。通过 `performance_schema.threads` 的 `TYPE` 列可以区分线程类型（FOREGROUND 或 BACKGROUND）。
- `init_connect` 变量可以用于自动分配资源组，但它不对具有 `CONNECTION_ADMIN`（或旧版的 `SUPER`）权限的用户执行。这意味着 DBA 用户的连接不会被自动分配到 `init_connect` 中指定的资源组。如果 `init_connect` 中的 SQL 有语法错误，普通用户将无法连接到 MySQL，需要由有 `CONNECTION_ADMIN` 权限的用户修复。

## 总结

`SET RESOURCE GROUP name` 将当前会话分配到指定资源组，`SET RESOURCE GROUP name FOR thread_id` 分配指定线程。`/*+ RESOURCE_GROUP(name) */` Hint 在单条查询级别指定。权限：`RESOURCE_GROUP_USER`（分配自己的线程）或 `RESOURCE_GROUP_ADMIN`（分配任意线程）。分配在下一个查询生效，持续到会话结束或重新分配。USER 资源组只能分配用户线程，SYSTEM 资源组只能分配系统线程。自动分配方案：`init_connect` 系统变量或连接池初始化 SQL。查看线程资源组：`performance_schema.threads` 的 `RESOURCE_GROUP` 列。
