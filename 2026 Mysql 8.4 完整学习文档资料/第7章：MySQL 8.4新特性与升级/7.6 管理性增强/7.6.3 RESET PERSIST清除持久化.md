# RESET PERSIST 清除持久化

`RESET PERSIST` 是 MySQL 8.0 引入的命令，用于清除通过 `SET PERSIST` 或 `SET PERSIST_ONLY` 写入 `mysqld-auto.cnf` 文件的持久化变量。当持久化的变量值有误、不再需要、或需要让 `my.cnf` 中的配置重新生效时，可以使用 `RESET PERSIST` 将其从持久化配置中移除。

---

## 基本语法

```sql
-- 清除单个持久化变量：
RESET PERSIST max_connections;
-- 从 mysqld-auto.cnf 中移除 max_connections 的持久化记录
-- 当前运行值不受影响
-- 下次重启时，max_connections 将使用 my.cnf 或默认值

-- 清除所有持久化变量：
RESET PERSIST;
-- 清空 mysqld-auto.cnf 中的所有持久化记录
-- 等效于清空整个 mysqld-auto.cnf 文件

-- 清除可能不存在的变量（MySQL 8.0.16+）：
RESET PERSIST IF EXISTS max_connections;
-- 如果 max_connections 没有被持久化，不报错（静默忽略）
-- 没有 IF EXISTS 时，如果变量不存在会报错

-- 验证清除结果：
SELECT * FROM performance_schema.persisted_variables;
-- 确认目标变量已不在列表中
```

---

## 使用场景示例

```sql
-- 场景1：撤销错误的持久化配置
-- 误操作：将 max_connections 设为了 10（太小了）
SET PERSIST max_connections = 10;
-- 发现问题后撤销：
RESET PERSIST max_connections;
-- 同时恢复运行值：
SET GLOBAL max_connections = 500;

-- 场景2：让 my.cnf 的配置重新生效
-- my.cnf 中 innodb_io_capacity = 200
-- 之前 SET PERSIST innodb_io_capacity = 2000
-- 现在想恢复为 my.cnf 中的 200：
RESET PERSIST innodb_io_capacity;
-- 下次重启后 innodb_io_capacity 回到 my.cnf 的 200

-- 场景3：清理遗留的持久化配置
-- 查看有哪些持久化变量：
SELECT VARIABLE_NAME, VARIABLE_VALUE FROM performance_schema.persisted_variables;
-- 发现一些不需要的旧配置：
RESET PERSIST IF EXISTS old_variable_1;
RESET PERSIST IF EXISTS old_variable_2;

-- 场景4：全部重置（重新开始）
RESET PERSIST;
-- 清空所有持久化配置
-- 下次重启时完全使用 my.cnf 和默认值
```

## RESET PERSIST 的行为细节

```sql
-- 1. RESET PERSIST 不修改当前运行值
SHOW VARIABLES LIKE 'max_connections';
-- max_connections: 500（通过 SET PERSIST 设置的）

RESET PERSIST max_connections;
-- 从 mysqld-auto.cnf 移除

SHOW VARIABLES LIKE 'max_connections';
-- max_connections: 500（当前运行值不变！）

-- 下次重启后：
-- max_connections 将使用 my.cnf 的值或默认值

-- 2. RESET PERSIST 对只读变量同样有效
RESET PERSIST innodb_buffer_pool_instances;
-- 清除只读变量的持久化记录

-- 3. RESET PERSIST 会更新 mysqld-auto.cnf 文件
-- 清除单个变量：从 JSON 文件中移除该键值对
-- 清除所有变量：文件内容变为空的 JSON 对象 {}

-- 4. 权限要求
-- RESET PERSIST 需要 SYSTEM_VARIABLES_ADMIN 权限
-- 对只读变量还需要 PERSIST_RO_VARIABLES_ADMIN 权限
```

## 持久化变量的管理流程

```
完整的持久化变量管理流程：

1. 查看当前持久化变量
   SELECT * FROM performance_schema.persisted_variables;

2. 持久化新变量
   SET PERSIST variable_name = value;
   SET PERSIST_ONLY readonly_var = value;

3. 验证持久化成功
   SELECT * FROM performance_schema.persisted_variables
   WHERE VARIABLE_NAME = 'variable_name';

4. 需要修改持久化值
   SET PERSIST variable_name = new_value;
   （直接覆盖旧的持久化值）

5. 需要撤销持久化
   RESET PERSIST variable_name;
   RESET PERSIST IF EXISTS variable_name;

6. 需要全部清除
   RESET PERSIST;

7. 重启后验证
   SHOW VARIABLES LIKE 'variable_name';
   SELECT VARIABLE_NAME, VARIABLE_SOURCE
   FROM performance_schema.variables_info
   WHERE VARIABLE_NAME = 'variable_name';
```

## 适用场景

- **撤销误操作的持久化配置**：当通过 `SET PERSIST` 误设了某个参数值（如将 `max_connections` 设为过小的值），可以通过 `RESET PERSIST` 撤销，防止下次重启时应用错误配置
- **服务器迁移或环境初始化**：在将 MySQL 实例迁移到新环境，或初始化标准配置时，使用 `RESET PERSIST`（无参数）清除所有历史持久化配置，然后重新按照新环境的标准设置

---

## 常见问题

**RESET PERSIST 后，当前运行值会恢复吗？**

不会。`RESET PERSIST` 只影响 `mysqld-auto.cnf` 文件中的持久化记录，不修改当前运行中的变量值。如果需要同时恢复当前运行值，需要额外执行 `SET GLOBAL variable_name = original_value`。例如：先 `RESET PERSIST max_connections` 清除持久化，再 `SET GLOBAL max_connections = 151` 恢复运行值。如果只执行了 `RESET PERSIST`，当前运行值在本次服务器运行期间保持不变，只有在下次重启时才会使用 `my.cnf` 或默认值。

---

## 注意事项

- `RESET PERSIST` 不带参数时会清除**所有**持久化变量，操作前应通过 `SELECT * FROM performance_schema.persisted_variables` 确认当前有哪些持久化变量，避免误清除重要配置。建议在执行 `RESET PERSIST`（无参数）前备份 `mysqld-auto.cnf` 文件。
- `RESET PERSIST variable_name`（不带 `IF EXISTS`）在目标变量没有被持久化时会报错：`ERROR 3615: Variable 'xxx' was not found in the persisted variables table`。在脚本中建议使用 `RESET PERSIST IF EXISTS variable_name` 避免报错中断脚本执行。

---

## 总结

`RESET PERSIST` 用于清除 `mysqld-auto.cnf` 中的持久化变量。`RESET PERSIST var_name` 清除单个变量，`RESET PERSIST` 清除所有变量，`RESET PERSIST IF EXISTS var_name`（8.0.16+）安全清除（不报错）。RESET PERSIST 不修改当前运行值，只影响下次重启时的配置。需要 `SYSTEM_VARIABLES_ADMIN` 权限。使用场景：撤销误操作、让 `my.cnf` 配置重新生效、环境初始化。操作前建议查看 `performance_schema.persisted_variables` 确认。
