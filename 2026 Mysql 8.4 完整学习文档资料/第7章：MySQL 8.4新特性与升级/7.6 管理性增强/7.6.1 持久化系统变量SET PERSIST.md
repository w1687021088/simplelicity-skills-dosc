# 持久化系统变量 SET PERSIST

MySQL 8.0 引入了 `SET PERSIST` 语法，允许在运行时修改系统变量的同时将其持久化到配置文件中，服务器重启后修改仍然生效。在此之前，`SET GLOBAL` 修改的变量只在内存中生效，重启后恢复为 `my.cnf` 中的配置值。运维人员经常遇到"SET GLOBAL 修改了参数但忘记同步到 my.cnf，重启后配置丢失"的问题，`SET PERSIST` 彻底解决了这个痛点。

---

## 基本语法

```sql
-- SET PERSIST 语法：
SET PERSIST variable_name = value;

-- 示例：修改最大连接数并持久化
SET PERSIST max_connections = 500;
-- 效果：
-- 1. 立即将 max_connections 修改为 500（等同于 SET GLOBAL）
-- 2. 将修改写入 mysqld-auto.cnf 文件（重启后仍生效）

-- 更多示例：
SET PERSIST innodb_buffer_pool_size = 4294967296;  -- 4GB
SET PERSIST slow_query_log = ON;
SET PERSIST long_query_time = 1.0;
SET PERSIST innodb_io_capacity = 2000;

-- 同时修改多个变量：
SET PERSIST max_connections = 500, wait_timeout = 28800;

-- 查看持久化的变量：
SELECT * FROM performance_schema.persisted_variables;
-- 显示所有通过 SET PERSIST 持久化的变量及其值
```

---

## SET PERSIST vs SET GLOBAL

```sql
-- SET GLOBAL：只在运行时生效，重启后丢失
SET GLOBAL max_connections = 500;
-- max_connections 变为 500
-- 重启后恢复为 my.cnf 中的值（如 151）

-- SET PERSIST：运行时生效 + 持久化，重启后仍生效
SET PERSIST max_connections = 500;
-- max_connections 变为 500
-- 写入 mysqld-auto.cnf
-- 重启后 max_connections 仍为 500

-- SET PERSIST_ONLY：只持久化，不立即生效
SET PERSIST_ONLY max_connections = 500;
-- max_connections 当前不变
-- 写入 mysqld-auto.cnf
-- 下次重启后生效
-- 适用于只读变量（如 innodb_buffer_pool_instances）
```

| 命令 | 立即生效 | 持久化 | 适用场景 |
|-----|:------:|:-----:|---------|
| SET GLOBAL | 是 | 否 | 临时测试、排查问题 |
| SET PERSIST | 是 | 是 | 生产环境参数调整 |
| SET PERSIST_ONLY | 否 | 是 | 只读变量、计划重启 |

## mysqld-auto.cnf 文件

```sql
-- SET PERSIST 将变量写入 mysqld-auto.cnf
-- 文件位置：数据目录（datadir）下
SHOW VARIABLES LIKE 'datadir';
-- 例如：/var/lib/mysql/

-- mysqld-auto.cnf 是 JSON 格式文件：
-- {
--   "Version": 2,
--   "mysql_server": {
--     "max_connections": {
--       "Value": "500",
--       "Metadata": {
--         "Host": "localhost",
--         "User": "root",
--         "Timestamp": 1703123456
--       }
--     }
--   }
-- }

-- 加载优先级（从低到高）：
-- 1. 编译时默认值
-- 2. /etc/my.cnf → /etc/mysql/my.cnf → ~/.my.cnf 等
-- 3. mysqld-auto.cnf（最高优先级）
-- 如果 my.cnf 中 max_connections=151
-- 但 mysqld-auto.cnf 中 max_connections=500
-- 启动后 max_connections = 500（mysqld-auto.cnf 优先）
```

## 权限要求

```sql
-- SET PERSIST 需要以下权限之一：
-- SYSTEM_VARIABLES_ADMIN + PERSIST_RO_VARIABLES_ADMIN
-- 或 SUPER 权限

-- 查看当前用户权限：
SHOW GRANTS FOR CURRENT_USER();

-- 授予持久化权限：
GRANT SYSTEM_VARIABLES_ADMIN, PERSIST_RO_VARIABLES_ADMIN ON *.* TO 'dba'@'%';

-- SYSTEM_VARIABLES_ADMIN：允许 SET GLOBAL 和 SET PERSIST
-- PERSIST_RO_VARIABLES_ADMIN：允许对只读变量执行 SET PERSIST_ONLY

-- 安全建议：
-- 只将 SET PERSIST 权限授予 DBA 用户
-- 应用账户不应有此权限（防止应用意外修改服务器配置）
```

## 适用场景

- **生产环境的参数调优**：在性能调优过程中需要修改系统参数（如 `innodb_buffer_pool_size`、`max_connections`），使用 `SET PERSIST` 确保修改在重启后仍然生效，避免手动编辑 `my.cnf` 遗漏
- **自动化运维脚本**：在自动化部署或运维脚本中，使用 `SET PERSIST` 通过 SQL 完成参数配置，无需操作系统层面的文件编辑权限

---

## 常见问题

**SET PERSIST 和手动编辑 my.cnf 哪个优先级更高？**

`mysqld-auto.cnf` 的优先级高于 `my.cnf`。MySQL 启动时的配置加载顺序为：编译默认值 → 命令行选项文件（`my.cnf` 等）→ `mysqld-auto.cnf`。后加载的覆盖先加载的。因此如果在 `my.cnf` 中设置了 `max_connections=200`，又通过 `SET PERSIST max_connections=500` 持久化了 500，重启后 `max_connections` 为 500。如果需要让 `my.cnf` 的值生效，需要先清除持久化：`RESET PERSIST max_connections`。

---

## 注意事项

- `mysqld-auto.cnf` 是 MySQL 自动管理的文件，**不应手动编辑**。手动编辑可能导致 JSON 格式错误，MySQL 启动时会报错并拒绝启动。如果需要清除持久化的变量，应使用 `RESET PERSIST` 命令。
- `SET PERSIST` 会记录修改者的用户名、主机名和时间戳到 `mysqld-auto.cnf` 中。这提供了审计追踪能力，可以知道是谁在什么时间修改了参数。通过 `performance_schema.persisted_variables` 和 `performance_schema.variables_info` 查看详细信息。

---

## 总结

`SET PERSIST` 是 MySQL 8.0 引入的持久化系统变量机制，修改立即生效并写入 `mysqld-auto.cnf`（数据目录下的 JSON 文件），重启后仍然有效。三种方式：`SET GLOBAL`（临时）、`SET PERSIST`（立即 + 持久化）、`SET PERSIST_ONLY`（仅持久化，下次重启生效）。`mysqld-auto.cnf` 优先级高于 `my.cnf`。需要 `SYSTEM_VARIABLES_ADMIN` 权限。查看持久化变量：`performance_schema.persisted_variables`。清除持久化：`RESET PERSIST [variable_name]`。不要手动编辑 `mysqld-auto.cnf`。
