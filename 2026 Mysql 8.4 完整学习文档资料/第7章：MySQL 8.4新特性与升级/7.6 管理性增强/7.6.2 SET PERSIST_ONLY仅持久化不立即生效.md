# SET PERSIST_ONLY 仅持久化不立即生效

`SET PERSIST_ONLY` 是 MySQL 8.0 引入的系统变量持久化命令，与 `SET PERSIST` 不同的是，它**只将变量值写入 `mysqld-auto.cnf` 文件，不修改当前运行中的变量值**。修改在下次 MySQL 重启时才生效。这个命令的主要用途是修改那些只能在启动时设置的只读系统变量（read-only variables），如 `innodb_buffer_pool_instances`、`innodb_log_file_size`（MySQL 8.0.30 之前）、`lower_case_table_names` 等。

---

## 基本语法

```sql
-- SET PERSIST_ONLY 语法：
SET PERSIST_ONLY variable_name = value;

-- 修改只读变量（运行时不可更改的变量）：
SET PERSIST_ONLY innodb_buffer_pool_instances = 8;
-- 当前值不变
-- 写入 mysqld-auto.cnf
-- 下次重启后生效

SET PERSIST_ONLY innodb_dedicated_server = ON;
-- 当前值不变，重启后生效

-- 也可以用于动态变量（但不会立即生效）：
SET PERSIST_ONLY max_connections = 1000;
-- max_connections 当前不变
-- 下次重启后变为 1000
-- 适用场景：计划在下次维护窗口重启时生效

-- 查看持久化的变量：
SELECT * FROM performance_schema.persisted_variables
WHERE VARIABLE_NAME = 'innodb_buffer_pool_instances';
```

---

## SET PERSIST_ONLY vs SET PERSIST vs SET GLOBAL

```sql
-- 三种命令的行为对比：

-- 场景：当前 max_connections = 151

-- SET GLOBAL：
SET GLOBAL max_connections = 500;
-- 当前值：500（立即生效）
-- 重启后：151（回到 my.cnf 的值，不持久化）

-- SET PERSIST：
SET PERSIST max_connections = 500;
-- 当前值：500（立即生效）
-- 重启后：500（已持久化到 mysqld-auto.cnf）

-- SET PERSIST_ONLY：
SET PERSIST_ONLY max_connections = 500;
-- 当前值：151（不立即生效）
-- 重启后：500（已持久化到 mysqld-auto.cnf）
```

| 命令 | 立即生效 | 持久化 | 支持只读变量 |
|-----|:------:|:-----:|:----------:|
| SET GLOBAL | 是 | 否 | 否 |
| SET PERSIST | 是 | 是 | 否 |
| SET PERSIST_ONLY | 否 | 是 | 是 |

## 只读变量的修改

```sql
-- 以下变量只能通过 SET PERSIST_ONLY 持久化（运行时不可更改）：

-- InnoDB 相关只读变量：
SET PERSIST_ONLY innodb_buffer_pool_instances = 8;
SET PERSIST_ONLY innodb_page_size = 16384;
SET PERSIST_ONLY innodb_dedicated_server = ON;

-- 服务器相关只读变量：
SET PERSIST_ONLY lower_case_table_names = 1;
SET PERSIST_ONLY default_authentication_plugin = 'caching_sha2_password';

-- 如果尝试对只读变量使用 SET PERSIST：
SET PERSIST innodb_buffer_pool_instances = 8;
-- ERROR 1238 (HY000): Variable 'innodb_buffer_pool_instances' is a read only variable
-- 必须使用 SET PERSIST_ONLY

-- 如果尝试对只读变量使用 SET GLOBAL：
SET GLOBAL innodb_buffer_pool_instances = 8;
-- ERROR 1238 (HY000): Variable 'innodb_buffer_pool_instances' is a read only variable
```

## 权限要求

```sql
-- SET PERSIST_ONLY 对只读变量需要特殊权限：
-- PERSIST_RO_VARIABLES_ADMIN + SYSTEM_VARIABLES_ADMIN

-- 查看权限：
SHOW GRANTS FOR 'dba'@'localhost';

-- 授予权限：
GRANT SYSTEM_VARIABLES_ADMIN, PERSIST_RO_VARIABLES_ADMIN
    ON *.* TO 'dba'@'localhost';

-- 权限层级：
-- SET GLOBAL → 需要 SYSTEM_VARIABLES_ADMIN 或 SUPER
-- SET PERSIST → 需要 SYSTEM_VARIABLES_ADMIN 或 SUPER
-- SET PERSIST_ONLY（动态变量）→ 需要 SYSTEM_VARIABLES_ADMIN
-- SET PERSIST_ONLY（只读变量）→ 需要 PERSIST_RO_VARIABLES_ADMIN

-- 安全建议：
-- PERSIST_RO_VARIABLES_ADMIN 权限应严格控制
-- 因为它允许修改影响服务器启动行为的关键参数
```

## 验证持久化结果

```sql
-- 查看所有持久化变量：
SELECT VARIABLE_NAME, VARIABLE_VALUE
FROM performance_schema.persisted_variables;

-- 查看变量的详细信息（包括来源）：
SELECT VARIABLE_NAME, VARIABLE_SOURCE, SET_TIME, SET_USER, SET_HOST
FROM performance_schema.variables_info
WHERE VARIABLE_SOURCE = 'PERSISTED';

-- VARIABLE_SOURCE 的值：
-- COMPILED: 编译默认值
-- GLOBAL: my.cnf 中的值
-- PERSISTED: mysqld-auto.cnf 中的值
-- DYNAMIC: 通过 SET GLOBAL 修改的值

-- 对比当前值和持久化值：
SELECT v.VARIABLE_NAME, 
       v.VARIABLE_VALUE AS current_value,
       p.VARIABLE_VALUE AS persisted_value
FROM performance_schema.global_variables v
JOIN performance_schema.persisted_variables p
    ON v.VARIABLE_NAME = p.VARIABLE_NAME
WHERE v.VARIABLE_VALUE != p.VARIABLE_VALUE;
-- 列出当前值与持久化值不同的变量
-- 这些变量将在下次重启时变为持久化值
```

## 适用场景

- **修改只能在启动时设置的参数**：如 `innodb_buffer_pool_instances`、`innodb_page_size` 等只读变量，只能通过 `SET PERSIST_ONLY` 持久化，在下次重启时生效
- **计划性的配置变更**：在维护窗口之前预先配置好参数（使用 `SET PERSIST_ONLY`），到维护窗口时只需重启 MySQL 即可应用所有配置变更，减少维护窗口的操作步骤和风险

---

## 常见问题

**SET PERSIST_ONLY 持久化的值什么时候生效？必须重启 MySQL 吗？**

对于只读变量，必须重启 MySQL 才能生效——这是因为只读变量在服务器启动时初始化，运行期间无法修改。对于动态变量（如 `max_connections`），`SET PERSIST_ONLY` 持久化后也需要重启才生效（因为 `PERSIST_ONLY` 不修改当前运行值）。如果希望动态变量立即生效且持久化，应使用 `SET PERSIST` 而不是 `SET PERSIST_ONLY`。可以通过 `RESTART` 命令（MySQL 8.0.4+）在 SQL 层面触发 MySQL 重启。

---

## 注意事项

- 使用 `SET PERSIST_ONLY` 修改只读变量后，建议通过 `SELECT * FROM performance_schema.persisted_variables` 确认持久化成功，并在下次重启后通过 `SHOW VARIABLES LIKE 'var_name'` 确认新值已生效。如果持久化值有误，可以在重启前通过 `RESET PERSIST var_name` 撤销。
- 某些只读变量之间存在依赖关系。例如 `innodb_buffer_pool_instances` 要求 `innodb_buffer_pool_size` 至少为 1GB（每个实例至少 128MB）。如果只持久化了 `innodb_buffer_pool_instances=16` 但 `innodb_buffer_pool_size` 仍为默认的 128MB，重启时可能导致配置冲突或被自动调整。建议同时持久化相关的变量。

## 总结

`SET PERSIST_ONLY` 只将变量值写入 `mysqld-auto.cnf`，不修改当前运行值，下次重启时生效。主要用途：修改只读变量（如 `innodb_buffer_pool_instances`、`innodb_page_size`）和计划性的配置变更。权限：只读变量需要 `PERSIST_RO_VARIABLES_ADMIN`。验证：`performance_schema.persisted_variables` 查看持久化值，`performance_schema.variables_info` 查看变量来源（`VARIABLE_SOURCE='PERSISTED'`）。对比当前值和持久化值可以预知重启后的配置变化。撤销：`RESET PERSIST var_name`。
