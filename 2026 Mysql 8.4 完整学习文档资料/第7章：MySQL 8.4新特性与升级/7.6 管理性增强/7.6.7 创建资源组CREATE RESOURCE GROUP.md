# 创建资源组 CREATE RESOURCE GROUP

`CREATE RESOURCE GROUP` 是 MySQL 8.0 引入的 DDL 语句，用于创建自定义资源组。资源组定义了 CPU 核心绑定范围（VCPU）和线程优先级（THREAD_PRIORITY），创建后可以将用户线程或系统线程分配到该资源组中，实现 CPU 资源的隔离与分配。

---

## 完整语法

```sql
CREATE RESOURCE GROUP group_name
    TYPE = {SYSTEM | USER}
    [VCPU [=] vcpu_spec [, vcpu_spec] ...]
    [THREAD_PRIORITY [=] N]
    [ENABLE | DISABLE]

-- 参数说明：
-- group_name：资源组名称（唯一标识符，大小写不敏感）
-- TYPE：SYSTEM（系统线程）或 USER（用户线程）
-- VCPU：绑定的 CPU 核心范围
--   格式：单个核心（如 0）、范围（如 0-3）、列表（如 0,2,4,6）
--   混合格式：0-3, 6, 8-11
-- THREAD_PRIORITY：线程优先级
--   SYSTEM 类型：-20 到 0
--   USER 类型：0 到 19
-- ENABLE/DISABLE：创建后是否启用（默认 ENABLE）
```

---

## 创建示例

```sql
-- 1. 创建 OLTP 高优先级资源组
-- 绑定到 CPU 0-3，优先级 0（最高用户优先级）
CREATE RESOURCE GROUP rg_oltp
    TYPE = USER
    VCPU = 0-3
    THREAD_PRIORITY = 0
    ENABLE;

-- 2. 创建批量任务低优先级资源组
-- 绑定到 CPU 4-7，优先级 10（较低）
CREATE RESOURCE GROUP rg_batch
    TYPE = USER
    VCPU = 4-7
    THREAD_PRIORITY = 10
    ENABLE;

-- 3. 创建报表查询资源组
-- 绑定到 CPU 6-7，优先级 15（低）
CREATE RESOURCE GROUP rg_report
    TYPE = USER
    VCPU = 6,7
    THREAD_PRIORITY = 15
    ENABLE;

-- 4. 创建 InnoDB 后台线程资源组
-- 绑定到 CPU 0-1，优先级 -10（较高系统优先级）
CREATE RESOURCE GROUP rg_innodb_bg
    TYPE = SYSTEM
    VCPU = 0-1
    THREAD_PRIORITY = -10
    ENABLE;

-- 5. 创建暂时禁用的资源组（稍后启用）
CREATE RESOURCE GROUP rg_maintenance
    TYPE = USER
    VCPU = 0-7
    THREAD_PRIORITY = 19
    DISABLE;
```

## 权限要求

```sql
-- 创建资源组需要 RESOURCE_GROUP_ADMIN 权限
GRANT RESOURCE_GROUP_ADMIN ON *.* TO 'dba'@'%';

-- 验证权限：
SHOW GRANTS FOR 'dba'@'%';
-- 应包含 RESOURCE_GROUP_ADMIN

-- 权限层级：
-- RESOURCE_GROUP_ADMIN：CREATE/ALTER/DROP RESOURCE GROUP + SET RESOURCE GROUP
-- RESOURCE_GROUP_USER：只能 SET RESOURCE GROUP（不能创建/修改/删除）

-- 建议权限分配：
-- DBA 用户：RESOURCE_GROUP_ADMIN（完全管理）
-- 应用用户：RESOURCE_GROUP_USER（只能切换资源组）
-- 普通用户：不授予（使用默认资源组）
```

## VCPU 规格详解

```sql
-- VCPU 支持多种指定方式：

-- 单个 CPU 核心：
CREATE RESOURCE GROUP rg1 TYPE = USER VCPU = 0;

-- CPU 范围：
CREATE RESOURCE GROUP rg2 TYPE = USER VCPU = 0-3;
-- 包含 CPU 0, 1, 2, 3

-- 多个不连续的 CPU：
CREATE RESOURCE GROUP rg3 TYPE = USER VCPU = 0, 2, 4, 6;

-- 混合格式（范围 + 单个）：
CREATE RESOURCE GROUP rg4 TYPE = USER VCPU = 0-3, 6, 8-11;
-- 包含 CPU 0,1,2,3,6,8,9,10,11

-- 不指定 VCPU（使用所有可用 CPU）：
CREATE RESOURCE GROUP rg5 TYPE = USER;
-- 等效于 VCPU = 0-N（N 为最大 CPU 编号）

-- 查看系统可用的 CPU 核心数：
-- 在 Linux 上：nproc 或 cat /proc/cpuinfo | grep processor | wc -l
-- 在 MySQL 中可以参考：
SELECT @@thread_handling;

-- 注意：VCPU 编号不能超过系统实际拥有的 CPU 核心数
-- 例如 8 核系统只能使用 VCPU = 0-7
```

## 创建后的验证与管理

```sql
-- 查看所有资源组：
SELECT RESOURCE_GROUP_NAME, RESOURCE_GROUP_TYPE,
       RESOURCE_GROUP_ENABLED, VCPU_IDS, THREAD_PRIORITY
FROM information_schema.RESOURCE_GROUPS;

-- 查看特定资源组的详情：
SELECT * FROM information_schema.RESOURCE_GROUPS
WHERE RESOURCE_GROUP_NAME = 'rg_oltp' \G

-- 修改资源组：
ALTER RESOURCE GROUP rg_batch VCPU = 4-5 THREAD_PRIORITY = 12;

-- 启用/禁用资源组：
ALTER RESOURCE GROUP rg_maintenance ENABLE;
ALTER RESOURCE GROUP rg_batch DISABLE;

-- 删除资源组：
DROP RESOURCE GROUP rg_report;
-- 如果有线程正在使用该资源组：
DROP RESOURCE GROUP rg_report FORCE;
-- FORCE 会将线程移回默认组后再删除
```

## 生产环境的资源组规划示例

```sql
-- 假设服务器有 16 个 CPU 核心（0-15）

-- OLTP 核心业务（CPU 0-7，8 核心，最高优先级）
CREATE RESOURCE GROUP rg_oltp
    TYPE = USER VCPU = 0-7 THREAD_PRIORITY = 0;

-- 批量导入/ETL（CPU 8-11，4 核心，低优先级）
CREATE RESOURCE GROUP rg_etl
    TYPE = USER VCPU = 8-11 THREAD_PRIORITY = 10;

-- 报表/分析查询（CPU 12-13，2 核心，较低优先级）
CREATE RESOURCE GROUP rg_analytics
    TYPE = USER VCPU = 12-13 THREAD_PRIORITY = 15;

-- 备份任务（CPU 14-15，2 核心，最低优先级）
CREATE RESOURCE GROUP rg_backup
    TYPE = USER VCPU = 14-15 THREAD_PRIORITY = 19;

-- InnoDB 后台线程（CPU 0-3，高优先级）
CREATE RESOURCE GROUP rg_innodb
    TYPE = SYSTEM VCPU = 0-3 THREAD_PRIORITY = -5;
```

## 适用场景

- **混合工作负载的 CPU 资源隔离**：同一台 MySQL 服务器同时处理 OLTP 查询和批量分析任务时，通过创建不同的资源组将它们绑定到不同的 CPU 核心，确保 OLTP 查询的响应时间不受批量任务影响
- **备份操作的资源限制**：通过将备份线程分配到低优先级、少量 CPU 核心的资源组，限制备份操作对在线业务的影响

## 常见问题

**多个资源组的 VCPU 范围可以重叠吗？**

可以。MySQL 允许不同资源组的 VCPU 范围重叠。例如 `rg_oltp` 绑定 CPU 0-7，`rg_analytics` 也绑定 CPU 6-7，两个资源组的线程可以同时在 CPU 6-7 上运行。重叠意味着这些 CPU 核心被多个资源组共享，不是独占。如果需要严格的 CPU 隔离（不同工作负载不共享任何 CPU 核心），应确保资源组的 VCPU 范围没有交集。在实际生产中，适度的重叠是可以接受的（如系统线程和用户线程共享部分 CPU），但关键的 OLTP 资源组建议不与低优先级任务组重叠。

---

## 注意事项

- 资源组的 THREAD_PRIORITY 设置依赖操作系统的线程优先级机制（Linux 上是 nice 值）。MySQL 进程需要 `CAP_SYS_NICE` 权限才能设置非 0 优先级。如果没有此权限，创建资源组不会报错，但分配线程时优先级设置不会生效（线程仍以默认优先级运行）。可以通过 `setcap cap_sys_nice+ep /usr/sbin/mysqld` 授予权限。
- 资源组信息存储在 `mysql.resource_groups` 系统表中，属于数据字典的一部分。`CREATE RESOURCE GROUP` 是 DDL 操作，会写入 binlog 并在复制环境中传播到从库。如果主从库的 CPU 核心数不同，从库上可能因为 VCPU 范围超出实际核心数而报错。

## 总结

`CREATE RESOURCE GROUP name TYPE={SYSTEM|USER} [VCPU=spec] [THREAD_PRIORITY=N] [ENABLE|DISABLE]` 创建自定义资源组。VCPU 支持单核、范围、列表和混合格式。USER 类型优先级 0~19，SYSTEM 类型优先级 -20~0。需要 `RESOURCE_GROUP_ADMIN` 权限。创建后通过 `SET RESOURCE GROUP` 或 `/*+ RESOURCE_GROUP() */` Hint 分配线程。多个资源组的 VCPU 可以重叠（共享 CPU）。线程优先级需要 `CAP_SYS_NICE` 权限。查看：`information_schema.RESOURCE_GROUPS`。修改：`ALTER RESOURCE GROUP`。删除：`DROP RESOURCE GROUP [FORCE]`。
