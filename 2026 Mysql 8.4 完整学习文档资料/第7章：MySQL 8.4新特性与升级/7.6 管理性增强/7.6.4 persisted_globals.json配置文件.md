# persisted_globals.json 配置文件

`mysqld-auto.cnf`（早期文档中也称为 `persisted_globals.json`）是 MySQL 8.0 引入的持久化配置文件，存储通过 `SET PERSIST` 和 `SET PERSIST_ONLY` 持久化的系统变量。该文件位于 MySQL 数据目录（`datadir`）下，采用 JSON 格式存储，由 MySQL 服务器自动管理。它在配置加载顺序中优先级最高——高于 `my.cnf` 和命令行参数，是 MySQL 8.0 持久化系统变量机制的核心存储载体。

## JSON 结构说明

```
mysqld-auto.cnf 的 JSON 结构：

{
  "Version": 2,                     ← 文件格式版本
  "mysql_server": {                  ← 服务器配置命名空间
    "variable_name": {               ← 动态变量（SET PERSIST）
      "Value": "value",             ← 变量值（字符串形式）
      "Metadata": {
        "Host": "hostname",          ← 修改者的主机
        "User": "username",          ← 修改者的用户名
        "Timestamp": 1703123456      ← 修改的 Unix 时间戳
      }
    },
    "mysql_server_static_options": { ← 只读变量（SET PERSIST_ONLY）
      "readonly_var": {
        "Value": "value",
        "Metadata": { ... }
      }
    }
  }
}

关键点：
- 动态变量存储在 "mysql_server" 直接子级
- 只读变量存储在 "mysql_server_static_options" 子级
- Metadata 记录了修改者和修改时间（审计信息）
- Value 始终是字符串类型（即使原始值是数字或布尔值）
```

## 配置加载优先级

```
MySQL 启动时的配置加载顺序（从低到高）：

1. 编译时默认值（Compiled-in defaults）
   → 最低优先级

2. 系统级配置文件
   → /etc/my.cnf（Linux）
   → /etc/mysql/my.cnf
   → C:\ProgramData\MySQL\MySQL Server 8.4\my.ini（Windows）

3. 用户级配置文件
   → ~/.my.cnf

4. 命令行参数
   → mysqld --max-connections=500

5. mysqld-auto.cnf（最高优先级）
   → SET PERSIST / SET PERSIST_ONLY 写入的值

冲突解决规则：
  后加载的覆盖先加载的
  mysqld-auto.cnf 中的值始终优先

示例：
  my.cnf: max_connections = 200
  mysqld-auto.cnf: max_connections = 500
  → 启动后 max_connections = 500
```

## 通过 Performance Schema 查看

```sql
-- 查看所有持久化变量：
SELECT VARIABLE_NAME, VARIABLE_VALUE
FROM performance_schema.persisted_variables
ORDER BY VARIABLE_NAME;

-- 查看变量的来源和修改信息：
SELECT VARIABLE_NAME, VARIABLE_SOURCE, SET_TIME, SET_USER, SET_HOST
FROM performance_schema.variables_info
WHERE VARIABLE_SOURCE = 'PERSISTED'
ORDER BY SET_TIME DESC;

-- VARIABLE_SOURCE 的可能值：
-- COMPILED: 编译默认值
-- GLOBAL: 配置文件（my.cnf）
-- SERVER: 服务器启动参数
-- PERSISTED: mysqld-auto.cnf
-- DYNAMIC: 运行时 SET GLOBAL 修改
-- COMMAND_LINE: 命令行参数

-- 查看所有非默认值的变量及其来源：
SELECT VARIABLE_NAME, VARIABLE_SOURCE, VARIABLE_VALUE
FROM performance_schema.variables_info vi
JOIN performance_schema.global_variables gv USING (VARIABLE_NAME)
WHERE VARIABLE_SOURCE NOT IN ('COMPILED')
ORDER BY VARIABLE_SOURCE, VARIABLE_NAME;
```

```sql
-- 将文件内容替换为 {}（空 JSON 对象）
-- 重启 MySQL

-- 永远不要手动编辑 mysqld-auto.cnf
-- 只通过 SET PERSIST / SET PERSIST_ONLY / RESET PERSIST 管理

```

## 适用场景

- **配置审计与变更追踪**：`mysqld-auto.cnf` 中的 Metadata 记录了每次修改的用户、主机和时间戳，配合 `performance_schema.variables_info` 可以追踪"谁在什么时间修改了哪个参数"
- **多实例配置管理**：在管理多个 MySQL 实例时，可以通过比较各实例的 `mysqld-auto.cnf` 文件，快速发现实例间的配置差异

## 常见问题

**可以通过拷贝 mysqld-auto.cnf 来复制一个实例的持久化配置到另一个实例吗？**

技术上可以，但不推荐。直接拷贝 `mysqld-auto.cnf` 到另一个实例的数据目录，另一个实例重启后会加载这些持久化配置。但有以下风险：①不同实例的硬件配置不同，参数值可能不适用（如 `innodb_buffer_pool_size`）；②Metadata 中的用户和时间信息会误导审计；③文件版本或格式可能不兼容。推荐做法：从 `performance_schema.persisted_variables` 导出需要的变量，在目标实例上通过 `SET PERSIST` 逐一设置。

---

## 注意事项

- `mysqld-auto.cnf` 文件的权限应限制为 MySQL 服务器进程的运行用户可读写（通常是 `mysql:mysql`，权限 `600`）。如果文件权限被修改导致 MySQL 无法读写，`SET PERSIST` 会报错，且启动时可能无法加载持久化配置。
- 在使用 MySQL Shell 的 `dba.configureInstance()` 配置 InnoDB Cluster 时，它也会使用 `SET PERSIST` 持久化 MGR 相关参数到 `mysqld-auto.cnf`。因此在 InnoDB Cluster 环境中，`RESET PERSIST`（清除所有）可能会破坏集群配置，应谨慎使用。

## 总结

`mysqld-auto.cnf` 是 MySQL 8.0 的持久化配置文件，位于 `datadir` 下，JSON 格式，存储 `SET PERSIST` / `SET PERSIST_ONLY` 的变量值。结构：动态变量在 `mysql_server` 下，只读变量在 `mysql_server_static_options` 下，每个变量包含 Value 和 Metadata（User、Host、Timestamp）。加载优先级最高（高于 `my.cnf` 和命令行参数）。查看：`performance_schema.persisted_variables` 和 `variables_info`（`VARIABLE_SOURCE='PERSISTED'`）。不要手动编辑，通过 `SET PERSIST` / `RESET PERSIST` 管理。文件损坏时可删除或替换为 `{}` 后重启。
