# 直方图会话控制

MySQL 提供了会话级别的控制参数，允许在不删除直方图的情况下，临时控制优化器是否使用直方图统计信息。这在排查查询性能问题时非常有用——可以快速对比"使用直方图"和"不使用直方图"两种情况下的执行计划差异，判断直方图是帮助还是误导了优化器。

---

## optimizer_switch 中的 condition_fanout_filter

```sql
-- 优化器使用直方图的开关通过 optimizer_switch 的
-- condition_fanout_filter 标志控制

-- 查看当前设置：
SELECT @@optimizer_switch \G
-- 输出中包含：condition_fanout_filter=on

-- condition_fanout_filter 的作用：
-- ON（默认）：优化器使用直方图和其他过滤条件估算来优化 JOIN 顺序
-- OFF：禁用基于条件的过滤估算（包括直方图）

-- 会话级别禁用（只影响当前连接）：
SET SESSION optimizer_switch = 'condition_fanout_filter=off';

-- 查看禁用后的执行计划差异：
EXPLAIN SELECT * FROM orders o 
JOIN customers c ON o.customer_id = c.id
WHERE o.amount > 5000;
-- 与 condition_fanout_filter=on 时的执行计划对比
-- 观察 rows 和 filtered 列的估算值差异

-- 恢复默认：
SET SESSION optimizer_switch = 'condition_fanout_filter=on';
```

## 直接控制直方图使用

```sql
-- MySQL 8.0.33+ / 8.4 中可以通过 optimizer_switch 更精细地控制

-- 查看所有 optimizer_switch 标志：
SHOW VARIABLES LIKE 'optimizer_switch';

-- 与直方图相关的标志：
-- condition_fanout_filter：控制是否使用条件过滤估算（含直方图）

-- 如果怀疑直方图导致了错误的执行计划：
-- 步骤1：禁用 condition_fanout_filter，对比执行计划
SET SESSION optimizer_switch = 'condition_fanout_filter=off';
EXPLAIN FORMAT=TREE SELECT ...;

-- 步骤2：恢复 condition_fanout_filter，对比执行计划
SET SESSION optimizer_switch = 'condition_fanout_filter=on';
EXPLAIN FORMAT=TREE SELECT ...;

-- 步骤3：如果确认直方图误导了优化器
-- 可以删除有问题的直方图：
ANALYZE TABLE orders DROP HISTOGRAM ON amount;
-- 或者更新直方图（数据可能已变化导致直方图过时）：
ANALYZE TABLE orders UPDATE HISTOGRAM ON amount WITH 200 BUCKETS;
```

## EXPLAIN 中查看直方图的影响

```sql
-- 使用 EXPLAIN FORMAT=JSON 查看详细的过滤信息：
EXPLAIN FORMAT=JSON
SELECT * FROM orders WHERE amount > 5000 AND status = 'completed' \G

-- 在 JSON 输出中关注：
-- "rows_examined_per_scan": ...
-- "rows_produced_per_join": ...
-- "filtered": "30.00"  ← 基于直方图的过滤比例估算
-- "cost_info": { ... }

-- EXPLAIN ANALYZE（MySQL 8.0.18+）显示实际执行情况：
EXPLAIN ANALYZE
SELECT * FROM orders WHERE amount > 5000;
-- 对比估算行数 vs 实际行数
-- (cost=... rows=50000) (actual time=... rows=48523 loops=1)
-- estimated rows=50000 vs actual rows=48523 → 估算准确

-- 如果估算与实际差距很大（如估算 50000 实际 500000）：
-- 说明直方图可能过时了，需要更新
```

## 全局 vs 会话级别控制

```sql
-- 全局级别：影响所有新连接
SET GLOBAL optimizer_switch = 'condition_fanout_filter=off';
-- 注意：已有连接不受影响，只有新连接使用新设置
-- 不建议在生产环境全局禁用

-- 会话级别：只影响当前连接
SET SESSION optimizer_switch = 'condition_fanout_filter=off';
-- 适合排查问题时临时使用
-- 连接断开后自动恢复默认值

-- 持久化设置（my.cnf）：
-- [mysqld]
-- optimizer_switch = "condition_fanout_filter=off"
-- 不推荐持久化禁用，直方图在大多数场景下是有益的

-- 针对单条查询的控制（使用 Hint）：
SELECT /*+ SET_VAR(optimizer_switch='condition_fanout_filter=off') */
    * FROM orders WHERE amount > 5000;
-- 只在这条查询中禁用，不影响其他查询
```

## 排查直方图问题的流程

```
当怀疑直方图导致了次优执行计划时：

1. 查看当前直方图信息
   SELECT * FROM information_schema.COLUMN_STATISTICS
   WHERE TABLE_NAME = 'xxx';
   → 检查 last-updated 时间和 sampling-rate

2. 对比执行计划
   SET SESSION optimizer_switch = 'condition_fanout_filter=on';
   EXPLAIN ANALYZE SELECT ...;  → 记录估算和实际行数
   
   SET SESSION optimizer_switch = 'condition_fanout_filter=off';
   EXPLAIN ANALYZE SELECT ...;  → 记录估算和实际行数

3. 判断直方图是否有益
   - 如果 ON 时估算更接近实际 → 直方图有益，保留
   - 如果 OFF 时执行更快 → 直方图可能过时或误导

4. 采取行动
   - 直方图过时 → ANALYZE TABLE UPDATE HISTOGRAM
   - 直方图误导 → ANALYZE TABLE DROP HISTOGRAM
   - 需要更精确 → 增加桶数量或提高采样率
```

## 适用场景

- **查询性能回归的排查**：当某个查询突然变慢时，可以通过会话级别的 `condition_fanout_filter` 开关快速判断是否与直方图有关，无需修改全局配置
- **直方图效果的 A/B 对比测试**：在决定是否为某列创建直方图前，先创建直方图，然后通过会话控制对比有无直方图时的执行计划和查询性能

---

## 常见问题

**禁用 condition_fanout_filter 只影响直方图吗？**

不是。`condition_fanout_filter` 控制的是优化器的"条件过滤估算"功能，直方图只是其中一个数据来源。禁用后，优化器不仅不使用直方图，还会跳过基于 WHERE 条件的过滤比例估算（如根据等值条件估算过滤比例）。因此禁用 `condition_fanout_filter` 可能同时影响多个方面的优化决策，不仅仅是直方图。如果只想排除直方图的影响，更精确的方法是删除特定列的直方图（`ANALYZE TABLE t DROP HISTOGRAM ON col`），然后观察执行计划变化。

---

## 注意事项

- 使用 `SET_VAR` Hint 是最安全的单查询控制方式，不影响其他查询：`SELECT /*+ SET_VAR(optimizer_switch='condition_fanout_filter=off') */ ...`。在排查问题时推荐使用 Hint 而不是修改会话变量，避免忘记恢复设置。
- 直方图的会话控制是"排查工具"，不是"日常使用工具"。在绝大多数场景下，直方图对查询优化是有益的，不应该长期禁用。如果发现直方图持续误导优化器，应该更新或删除直方图，而不是禁用 `condition_fanout_filter`。

---

## 总结

直方图的会话控制通过 `optimizer_switch` 的 `condition_fanout_filter` 标志实现。`SET SESSION optimizer_switch='condition_fanout_filter=off'` 临时禁用条件过滤估算（含直方图），`=on` 恢复。单查询控制：`/*+ SET_VAR(optimizer_switch='condition_fanout_filter=off') */` Hint。排查流程：对比 ON/OFF 时的 `EXPLAIN ANALYZE` 结果（估算行数 vs 实际行数、执行时间），判断直方图是否有益。如果直方图过时则更新（`UPDATE HISTOGRAM`），如果误导则删除（`DROP HISTOGRAM`）。`condition_fanout_filter` 不仅控制直方图，还控制其他条件过滤估算。
