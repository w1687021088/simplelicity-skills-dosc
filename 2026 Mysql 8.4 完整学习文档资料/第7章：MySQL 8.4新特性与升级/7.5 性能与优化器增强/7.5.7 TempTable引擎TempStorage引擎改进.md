# TempTable 引擎 TempStorage 引擎改进

MySQL 8.0 引入了 TempTable 存储引擎，作为内部临时表的默认引擎，替代了旧版本中的 MEMORY 引擎。TempTable 引擎解决了 MEMORY 引擎的多个局限性：支持变长数据类型（VARCHAR、VARBINARY）的高效存储，减少内存浪费；支持更大的临时表（超出内存时自动溢写到磁盘的内存映射文件）；支持 BLOB 和 TEXT 类型。MySQL 8.4 LTS 中 TempTable 引擎进一步成熟稳定。

---

## 内部临时表引擎的演进

```
MySQL 5.7 及之前：
  内部临时表引擎 = MEMORY
  问题：
  1. VARCHAR(200) 固定分配 200 字节 → 内存浪费严重
  2. 不支持 BLOB/TEXT 类型 → 直接转为磁盘临时表
  3. 使用 HASH 索引 → 不支持范围查询
  4. 超出 tmp_table_size 后转为 MyISAM 磁盘临时表

MySQL 8.0+：
  内部临时表引擎 = TempTable（默认）
  改进：
  1. VARCHAR 按实际长度存储 → 节省内存
  2. 支持 BLOB/TEXT 类型 → 更少的磁盘临时表
  3. 超出内存后使用内存映射文件（mmap）→ 比 MyISAM 更快
  4. 内存管理更高效（使用内存池）
```

## TempTable 引擎的配置

```sql
-- 查看当前内部临时表引擎：
SHOW VARIABLES LIKE 'internal_tmp_mem_storage_engine';
-- internal_tmp_mem_storage_engine: TempTable（默认）
-- 可选值：TempTable | MEMORY

-- TempTable 内存池大小限制：
SHOW VARIABLES LIKE 'temptable_max_ram';
-- temptable_max_ram: 1073741824（默认 1GB）

-- 设置 TempTable 内存上限：
SET GLOBAL temptable_max_ram = 2147483648;  -- 2GB

-- 持久化配置（my.cnf）：
-- [mysqld]
-- internal_tmp_mem_storage_engine = TempTable
-- temptable_max_ram = 2G

-- 超出内存后的溢写方式：
SHOW VARIABLES LIKE 'temptable_max_mmap';
-- temptable_max_mmap: 1073741824（默认 1GB）
-- 0 表示不使用内存映射文件，直接转为 InnoDB 磁盘临时表

-- temptable_use_mmap（MySQL 8.0.16+，8.0.26 废弃）：
-- 已被 temptable_max_mmap 替代
```

## 溢写机制详解

```
TempTable 的三级存储策略：

第1级：内存（temptable_max_ram 以内）
  → 最快，纯内存操作
  → 默认上限 1GB（所有连接共享）

第2级：内存映射文件（mmap，temptable_max_mmap 以内）
  → 超出 temptable_max_ram 后使用
  → 通过 mmap 映射磁盘文件到内存地址空间
  → 性能介于内存和磁盘之间
  → 文件位置：tmpdir 指定的目录

第3级：InnoDB 磁盘临时表
  → 超出 temptable_max_mmap 后使用
  → 或 temptable_max_mmap = 0 时直接使用
  → 最慢，完全的磁盘 I/O
  → 使用 InnoDB 内部临时表空间（ibtmp1）

查询执行过程中，临时表可能在不同级别之间切换：
  小结果集 → 第1级（内存）
  中等结果集 → 第1级 → 溢写到第2级（mmap）
  大结果集 → 第1级 → 第2级 → 第3级（InnoDB 磁盘）
```

## 监控临时表使用情况

```sql
-- 查看临时表创建统计：
SHOW GLOBAL STATUS LIKE 'Created_tmp%';
-- Created_tmp_disk_tables: 1234  ← 磁盘临时表数量
-- Created_tmp_tables: 56789     ← 内存临时表数量（含磁盘）

-- 磁盘临时表比例：
-- ratio = Created_tmp_disk_tables / Created_tmp_tables
-- 理想值：< 10%
-- 如果比例过高 → 需要增大 temptable_max_ram 或优化查询

-- 查看 TempTable 内存使用量：
SELECT * FROM performance_schema.memory_summary_global_by_event_name
WHERE EVENT_NAME LIKE '%temptable%';

-- 查看当前连接的临时表使用情况（Performance Schema）：
SELECT THREAD_ID, EVENT_NAME, CURRENT_NUMBER_OF_BYTES_USED
FROM performance_schema.memory_summary_by_thread_by_event_name
WHERE EVENT_NAME LIKE '%temptable%'
ORDER BY CURRENT_NUMBER_OF_BYTES_USED DESC
LIMIT 10;
```

## TempTable vs MEMORY 引擎

| 对比维度 | TempTable | MEMORY |
|---------|:--------:|:------:|
| VARCHAR 存储 | 按实际长度 | 固定最大长度 |
| BLOB/TEXT | 支持 | 不支持 |
| 内存效率 | 高 | 低（固定长度浪费）|
| 溢写方式 | mmap → InnoDB | MyISAM 磁盘表 |
| 溢写性能 | 较好（mmap）| 较差（MyISAM）|
| 索引类型 | 无（顺序扫描）| HASH（不支持范围）|
| 最大内存 | temptable_max_ram | tmp_table_size |
| 默认引擎 | MySQL 8.0+ | MySQL 5.7 及之前 |

## 调优建议

```sql
-- 1. 根据工作负载调整 temptable_max_ram
-- OLTP 系统（大量短查询）：512MB ~ 1GB
-- OLAP 系统（少量复杂查询）：2GB ~ 4GB
SET GLOBAL temptable_max_ram = 2147483648;  -- 2GB

-- 2. 设置合理的 temptable_max_mmap
-- 如果磁盘是 SSD → 可以设置较大值（如 2GB~4GB）
-- 如果磁盘是 HDD → 设置较小值或为 0（直接用 InnoDB）
SET GLOBAL temptable_max_mmap = 2147483648;  -- 2GB

-- 3. 确保 tmpdir 指向高速存储
-- mmap 文件和 InnoDB 临时表空间都使用 tmpdir
SHOW VARIABLES LIKE 'tmpdir';
-- 建议指向 SSD 分区

-- 4. 优化查询以减少临时表使用
-- 避免 SELECT DISTINCT 在大结果集上
-- 避免 GROUP BY 没有索引的大表
-- 避免 ORDER BY 没有索引的大结果集
-- 避免 UNION（使用 UNION ALL 如果不需要去重）
```

## 适用场景

- **包含大量 GROUP BY、ORDER BY、DISTINCT 操作的分析型查询**：这些操作经常需要创建内部临时表。TempTable 引擎的变长存储和 mmap 溢写机制，相比旧的 MEMORY + MyISAM 组合，可以显著提升这类查询的性能
- **涉及 BLOB/TEXT 列的查询**：在 MEMORY 引擎时代，包含 BLOB/TEXT 列的查询直接使用磁盘临时表（MyISAM），性能很差。TempTable 引擎支持 BLOB/TEXT 在内存中处理，只在超出内存限制时才溢写

## 常见问题

**temptable_max_ram 是每个连接独占还是所有连接共享？**

`temptable_max_ram` 是**所有连接共享**的全局内存池上限。所有连接创建的 TempTable 临时表共享这个内存池。如果 100 个连接同时执行需要临时表的查询，它们共享 1GB（默认值）的内存。当内存池耗尽时，新的临时表分配会溢写到 mmap 文件。这意味着在高并发场景下，单个查询可能只能使用到 `temptable_max_ram` 的一小部分。如果需要确保单个大查询有足够的临时表内存，可以在会话级别调整（但注意 `temptable_max_ram` 是全局变量，不能会话级别设置）。

---

## 注意事项

- `temptable_max_ram` 是全局变量，不能在会话级别设置。所有连接共享这个内存池，设置过大可能与 InnoDB Buffer Pool 等竞争内存。建议 `temptable_max_ram` + `innodb_buffer_pool_size` + 其他内存需求不超过物理内存的 80%。
- 如果将 `temptable_max_mmap` 设为 0，TempTable 超出内存后会直接使用 InnoDB 内部临时表（on-disk），不经过 mmap 阶段。在某些场景下（如 tmpdir 所在磁盘空间有限），这可能是更安全的配置。

---

## 总结

TempTable 是 MySQL 8.0 默认的内部临时表引擎，替代 MEMORY 引擎。优势：VARCHAR 按实际长度存储（节省内存）、支持 BLOB/TEXT、溢写使用 mmap（比 MyISAM 快）。三级存储：内存（`temptable_max_ram`，默认 1GB，全局共享）→ mmap 文件（`temptable_max_mmap`，默认 1GB）→ InnoDB 磁盘临时表。监控：`Created_tmp_disk_tables` / `Created_tmp_tables` 比例应低于 10%。调优：根据工作负载调整 `temptable_max_ram`（OLTP 1GB / OLAP 2~4GB），确保 tmpdir 指向高速存储。
