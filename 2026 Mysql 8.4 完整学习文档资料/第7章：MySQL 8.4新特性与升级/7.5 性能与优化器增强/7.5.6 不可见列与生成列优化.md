# 不可见列与生成列优化

MySQL 8.0.23 引入了不可见列（Invisible Column）功能，允许将表中的某些列标记为"不可见"，使得 `SELECT *` 不会返回这些列，必须显式指定列名才能查询到。生成列（Generated Column）在 MySQL 5.7 中引入并在 8.0 中持续优化，可以基于其他列的表达式自动计算值。这两个特性结合使用，可以在不影响现有应用的情况下为表添加计算列和索引，提升查询性能。

---

## 不可见列（Invisible Column）

```sql
-- 创建表时定义不可见列：
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(200),
    internal_score INT INVISIBLE,  -- 不可见列
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 将已有列设为不可见：
ALTER TABLE users ALTER COLUMN internal_score SET INVISIBLE;

-- 将不可见列恢复为可见：
ALTER TABLE users ALTER COLUMN internal_score SET VISIBLE;

-- SELECT * 不包含不可见列：
SELECT * FROM users;
-- 结果只包含 id, name, email, created_at
-- 不包含 internal_score

-- 显式指定才能查询不可见列：
SELECT id, name, internal_score FROM users;
-- 可以查到 internal_score

-- INSERT 也不包含不可见列（使用默认值或 NULL）：
INSERT INTO users (name, email) VALUES ('张三', 'zhangsan@test.com');
-- internal_score 使用默认值

-- 显式插入不可见列：
INSERT INTO users (name, email, internal_score) VALUES ('李四', 'lisi@test.com', 85);

-- 查看列的可见性：
SELECT COLUMN_NAME, EXTRA
FROM information_schema.COLUMNS
WHERE TABLE_NAME = 'users' AND TABLE_SCHEMA = DATABASE();
-- EXTRA 列包含 INVISIBLE 标记
```

## 生成列（Generated Column）

```sql
-- 虚拟生成列（VIRTUAL）：不占存储空间，查询时计算
CREATE TABLE orders (
    id INT AUTO_INCREMENT PRIMARY KEY,
    quantity INT,
    unit_price DECIMAL(10,2),
    total_amount DECIMAL(10,2) GENERATED ALWAYS AS (quantity * unit_price) VIRTUAL,
    order_date DATETIME,
    order_year INT GENERATED ALWAYS AS (YEAR(order_date)) VIRTUAL
);

-- 存储生成列（STORED）：占存储空间，写入时计算并持久化
CREATE TABLE employees (
    id INT AUTO_INCREMENT PRIMARY KEY,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    full_name VARCHAR(101) GENERATED ALWAYS AS (CONCAT(first_name, ' ', last_name)) STORED
);

-- 在已有表上添加生成列：
ALTER TABLE users ADD COLUMN name_upper VARCHAR(100)
    GENERATED ALWAYS AS (UPPER(name)) VIRTUAL;

-- 在生成列上创建索引：
CREATE INDEX idx_total ON orders (total_amount);
CREATE INDEX idx_year ON orders (order_year);
CREATE INDEX idx_fullname ON employees (full_name);
```

## 虚拟生成列 vs 存储生成列

| 对比维度 | VIRTUAL | STORED |
|---------|:------:|:-----:|
| 存储空间 | 不占空间 | 占用存储 |
| 计算时机 | 查询时实时计算 | 写入时计算并存储 |
| 读取性能 | 需要计算（CPU 开销）| 直接读取（无计算开销）|
| 写入性能 | 无额外开销 | 写入时需要计算 |
| 可创建索引 | 可以（InnoDB）| 可以 |
| 适用场景 | 查询少、节省空间 | 查询频繁、需要高读性能 |
| 回表行为 | 需要计算（即使有索引）| 直接从行数据读取 |

## 不可见列 + 生成列的组合应用

```sql
-- 场景：为已有表添加优化索引，不影响现有应用

-- 原始表：
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(200),
    price DECIMAL(10,2),
    data JSON
);

-- 添加不可见的生成列 + 索引（不影响 SELECT * 和 INSERT）：
ALTER TABLE products ADD COLUMN name_lower VARCHAR(200)
    GENERATED ALWAYS AS (LOWER(name)) VIRTUAL INVISIBLE;

ALTER TABLE products ADD COLUMN sku VARCHAR(20)
    GENERATED ALWAYS AS (JSON_UNQUOTE(JSON_EXTRACT(data, '$.sku'))) VIRTUAL INVISIBLE;

CREATE INDEX idx_name_lower ON products (name_lower);
CREATE INDEX idx_sku ON products (sku);

-- 现有应用的 SELECT * 和 INSERT 不受影响
SELECT * FROM products;
-- 不包含 name_lower 和 sku 列

INSERT INTO products (name, price, data) VALUES 
    ('iPhone 15', 6999, '{"sku": "PHONE-001"}');
-- 正常插入，生成列自动计算

-- 但查询可以利用新索引：
SELECT * FROM products WHERE LOWER(name) = 'iphone 15';
-- 优化器可以使用 idx_name_lower（通过生成列匹配）

EXPLAIN SELECT * FROM products WHERE name_lower = 'iphone 15';
-- type: ref, key: idx_name_lower
```

## 生成列的限制

```sql
-- 1. 生成列的表达式只能引用同表的非生成列
-- 不能引用其他生成列（MySQL 8.0+ 部分放宽）
-- 不能引用其他表的列

-- 2. 不能在生成列上直接执行 INSERT 或 UPDATE
INSERT INTO orders (total_amount) VALUES (100);
-- ERROR: The value specified for generated column 'total_amount' is not allowed

UPDATE orders SET total_amount = 100 WHERE id = 1;
-- ERROR: The value specified for generated column 'total_amount' is not allowed

-- 3. 表达式必须是确定性的
-- 不能使用 NOW(), RAND(), UUID() 等非确定性函数

-- 4. VIRTUAL 生成列在 InnoDB 中不能作为主键
-- STORED 生成列可以作为主键

-- 5. VIRTUAL 生成列不支持外键约束
-- STORED 生成列可以参与外键

-- 6. 表达式中不能使用子查询、存储过程、用户变量
```

## 适用场景

- **无侵入式的查询优化**：通过不可见的生成列 + 索引，可以在不修改应用代码（`SELECT *` 和 `INSERT` 不受影响）的情况下为表添加函数索引，加速特定查询模式
- **数据模型中的计算字段**：如订单总金额（`quantity * price`）、用户全名（`CONCAT(first_name, ' ', last_name)`）等需要频繁计算的字段，使用存储生成列可以避免在每次查询时重复计算

## 常见问题

**不可见列在哪些操作中是真正"不可见"的？**

不可见列在以下操作中不可见：①`SELECT *` 不包含不可见列；②`INSERT INTO t VALUES (...)` 不需要为不可见列提供值（使用默认值）；③`CREATE TABLE ... LIKE` 会保留列的可见性属性。但在以下操作中不可见列仍然存在：①`SELECT invisible_col` 显式指定列名可以查询；②`INSERT INTO t (invisible_col) VALUES (...)` 显式指定列名可以插入；③`SHOW CREATE TABLE` 和 `DESCRIBE` 会显示不可见列（标记为 INVISIBLE）；④`information_schema.COLUMNS` 中包含不可见列信息。

---

## 注意事项

- 不可见列不能是表的唯一列——表至少需要一个可见列。也不能将主键列设为不可见（`ALTER TABLE t ALTER COLUMN id SET INVISIBLE` 如果 id 是主键会报错）。
- 生成列的表达式在修改基础列时会自动重新计算。例如 `total_amount = quantity * unit_price`，当 `UPDATE orders SET quantity = 10` 时，`total_amount` 会自动更新。VIRTUAL 列在下次查询时计算新值，STORED 列在 UPDATE 执行时立即更新。

---

## 总结

不可见列（MySQL 8.0.23+）：`ALTER COLUMN col SET INVISIBLE`，`SELECT *` 和 `INSERT INTO t VALUES()` 不包含该列，显式指定列名才可操作。生成列：`GENERATED ALWAYS AS (expr) VIRTUAL/STORED`，VIRTUAL 不占空间查询时计算，STORED 占空间写入时计算。组合应用：不可见生成列 + 索引，在不影响现有应用的前提下添加优化索引。生成列限制：表达式必须确定性、不能直接 INSERT/UPDATE、不能用子查询。VIRTUAL 列可在 InnoDB 上建索引（函数索引的底层实现）。
