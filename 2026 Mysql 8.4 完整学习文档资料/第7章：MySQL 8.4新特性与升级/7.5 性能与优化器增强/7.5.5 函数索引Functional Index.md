# 函数索引 Functional Index

函数索引（Functional Index，也称表达式索引）是 MySQL 8.0.13 引入的功能，允许在索引定义中使用表达式或函数，而不仅限于列名。传统索引只能建立在列的原始值上，如果查询条件中使用了函数（如 `UPPER(name)`、`YEAR(created_at)`），即使该列有索引也无法使用。函数索引通过在表达式的计算结果上建立索引，解决了这一问题。

---

## 基本语法

```sql
-- 在表达式上创建索引
-- 注意：表达式必须用圆括号包裹

-- 在 UPPER(name) 上创建索引：
CREATE INDEX idx_upper_name ON users ((UPPER(name)));

-- 在 YEAR(created_at) 上创建索引：
CREATE INDEX idx_year ON orders ((YEAR(created_at)));

-- 在数学表达式上创建索引：
CREATE INDEX idx_total ON order_items ((quantity * unit_price));

-- 在 JSON 路径上创建索引（配合 JSON_VALUE）：
CREATE INDEX idx_sku ON products ((JSON_VALUE(data, '$.sku' RETURNING CHAR(20))));

-- 在建表时创建函数索引：
CREATE TABLE logs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    message TEXT,
    created_at DATETIME,
    INDEX idx_date ((DATE(created_at))),
    INDEX idx_hour ((HOUR(created_at)))
);
```

---

## 使用函数索引的查询

```sql
-- 查询条件中的表达式必须与索引定义完全匹配

-- 匹配 idx_upper_name 的查询：
SELECT * FROM users WHERE UPPER(name) = 'ZHANG SAN';
-- 使用 idx_upper_name 索引 ✓

-- 不匹配的查询：
SELECT * FROM users WHERE LOWER(name) = 'zhang san';
-- 不使用 idx_upper_name ✗（函数不同）

SELECT * FROM users WHERE name = 'Zhang San';
-- 不使用 idx_upper_name ✗（没有使用 UPPER 函数）

-- 匹配 idx_year 的查询：
SELECT * FROM orders WHERE YEAR(created_at) = 2024;
-- 使用 idx_year 索引 ✓

-- 匹配 idx_total 的查询：
SELECT * FROM order_items WHERE quantity * unit_price > 1000;
-- 使用 idx_total 索引 ✓

-- 验证索引使用：
EXPLAIN SELECT * FROM users WHERE UPPER(name) = 'ZHANG SAN';
-- type: ref, key: idx_upper_name
```

## 函数索引的实现原理

```sql
-- MySQL 函数索引的底层实现是隐藏的虚拟生成列

-- 当创建函数索引时：
CREATE INDEX idx_upper_name ON users ((UPPER(name)));

-- MySQL 内部等效于：
-- 1. 创建一个隐藏的虚拟生成列（用户不可见）
-- ALTER TABLE users ADD COLUMN _hidden_col VARCHAR(255) 
--     GENERATED ALWAYS AS (UPPER(name)) VIRTUAL NOT VISIBLE;
-- 2. 在这个隐藏列上创建普通索引
-- CREATE INDEX idx_upper_name ON users (_hidden_col);

-- 可以通过 SHOW CREATE TABLE 看到隐藏列的痕迹：
SHOW CREATE TABLE users \G
-- 输出中不会显示隐藏列本身
-- 但索引定义中会显示表达式

-- 查看隐藏列：
SELECT COLUMN_NAME, GENERATION_EXPRESSION, EXTRA
FROM information_schema.COLUMNS
WHERE TABLE_NAME = 'users' AND GENERATION_EXPRESSION != '';
```

## 常用函数索引场景

```sql
-- 1. 大小写不敏感查询
CREATE INDEX idx_lower_email ON users ((LOWER(email)));
SELECT * FROM users WHERE LOWER(email) = 'user@example.com';

-- 2. 日期部分查询
CREATE INDEX idx_month ON orders ((MONTH(order_date)));
SELECT * FROM orders WHERE MONTH(order_date) = 12;

CREATE INDEX idx_date_only ON logs ((DATE(created_at)));
SELECT * FROM logs WHERE DATE(created_at) = '2024-06-15';

-- 3. 字符串前缀/后缀
CREATE INDEX idx_domain ON users ((SUBSTRING_INDEX(email, '@', -1)));
SELECT * FROM users WHERE SUBSTRING_INDEX(email, '@', -1) = 'gmail.com';

-- 4. JSON 字段索引
CREATE INDEX idx_city ON customers ((JSON_VALUE(address, '$.city' RETURNING CHAR(50))));
SELECT * FROM customers WHERE JSON_VALUE(address, '$.city' RETURNING CHAR(50)) = '上海';

-- 5. 计算列索引
CREATE INDEX idx_age ON employees ((TIMESTAMPDIFF(YEAR, birth_date, CURDATE())));
-- 注意：包含非确定性函数（如 CURDATE()）的表达式不能用于函数索引！
-- 上面的语句会报错！

-- 正确做法：使用确定性表达式
CREATE INDEX idx_birth_year ON employees ((YEAR(birth_date)));
SELECT * FROM employees WHERE YEAR(birth_date) = 1990;
```

## 函数索引的限制

```sql
-- 1. 表达式必须是确定性的（Deterministic）
-- 不能使用：NOW(), CURDATE(), RAND(), UUID() 等非确定性函数
-- 不能使用：用户自定义变量

-- 2. 不能引用其他表的列
-- 表达式只能使用当前表的列

-- 3. 表达式中不能使用子查询

-- 4. 不能在主键上使用函数索引
-- PRIMARY KEY 不支持表达式

-- 5. 表达式必须用双层括号包裹
CREATE INDEX idx ON t ((expr));  -- 正确
CREATE INDEX idx ON t (expr);    -- 错误（缺少外层括号）

-- 6. 复合索引中可以混合使用普通列和表达式
CREATE INDEX idx_mixed ON orders (
    customer_id,
    (YEAR(order_date)),
    (quantity * price)
);
```

## 函数索引 vs 生成列索引

| 对比维度 | 函数索引 | 生成列 + 普通索引 |
|---------|:------:|:---------------:|
| 语法简洁度 | 简洁（一行 SQL）| 需要两步（加列 + 建索引）|
| 表结构变化 | 隐藏列（不可见）| 显式列（可见）|
| 查询匹配 | 表达式精确匹配 | 可直接查询生成列 |
| 维护成本 | 低 | 中（多一个列定义）|
| 灵活性 | 一般 | 高（可以在多处引用）|
| 适用场景 | 简单表达式 | 复杂表达式或多处引用 |

---

## 适用场景

- **查询条件经常使用函数的列**：如 `WHERE UPPER(email) = ...`、`WHERE YEAR(date) = ...`、`WHERE DATE(datetime) = ...` 等模式，直接在函数表达式上创建索引，避免全表扫描
- **JSON 列的特定路径索引**：配合 `JSON_VALUE()` 函数，在 JSON 列的指定路径上创建索引，使 JSON 查询可以利用索引

## 常见问题

**函数索引对 INSERT/UPDATE 性能有影响吗？**

有，但通常影响很小。函数索引底层是虚拟生成列 + 索引，每次 INSERT 或 UPDATE 涉及索引列时，MySQL 需要计算表达式的值并更新索引。对于简单表达式（如 `UPPER(name)`、`YEAR(date)`），计算开销可以忽略。对于复杂表达式（如涉及字符串处理或 JSON 解析），可能有轻微的性能影响。总体来说，函数索引对写入性能的影响与普通二级索引类似。

---

## 注意事项

- 查询优化器匹配函数索引时要求 WHERE 条件中的表达式与索引定义**完全一致**（包括函数名、参数顺序、括号等）。例如索引是 `(UPPER(name))`，查询中写 `UCASE(name)`（UPPER 的别名）不会匹配。建议在应用代码中统一使用与索引定义一致的函数写法。
- 函数索引的表达式中使用的列如果被 `ALTER TABLE ... DROP COLUMN` 删除，索引也会被自动删除。但 `ALTER TABLE ... MODIFY COLUMN` 改变列的数据类型可能导致函数索引失效或报错，修改列类型前应检查是否有函数索引依赖该列。

---

## 总结

函数索引（MySQL 8.0.13+）允许在表达式或函数的计算结果上创建索引：`CREATE INDEX idx ON t ((expr))`（双层括号）。底层实现为隐藏虚拟生成列 + 普通索引。查询匹配要求 WHERE 条件中的表达式与索引定义完全一致。常见用途：大小写不敏感查询（`UPPER`/`LOWER`）、日期部分查询（`YEAR`/`MONTH`/`DATE`）、JSON 路径索引（`JSON_VALUE`）、计算表达式。限制：表达式必须是确定性的、不能用子查询、不能做主键。可与普通列混合组成复合索引。
