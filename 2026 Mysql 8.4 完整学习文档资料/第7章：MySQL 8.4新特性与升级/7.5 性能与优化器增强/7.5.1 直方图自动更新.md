# 直方图自动更新

MySQL 8.0 引入了列直方图（Histogram）统计信息，帮助优化器更准确地估算列值的分布情况，从而选择更优的执行计划。MySQL 8.0.31+ 进一步增强了直方图功能，支持在 `ANALYZE TABLE` 时自动更新已有的直方图统计信息。MySQL 8.4 LTS 中直方图功能更加成熟，配合 `histogram_generation_max_mem_size` 等参数可以精细控制直方图的生成行为。

---

## 直方图的基本概念

```
直方图记录了列值的分布信息：

假设 orders 表的 amount 列有以下值分布：
0~100:    30% 的行
100~500:  40% 的行
500~1000: 20% 的行
1000+:    10% 的行

没有直方图时，优化器假设值均匀分布：
WHERE amount > 500 → 估算选择性 = 50%（实际 30%）

有直方图时，优化器使用实际分布：
WHERE amount > 500 → 估算选择性 ≈ 30%（更接近实际）

更准确的选择性估算 → 更优的执行计划（是否走索引、JOIN 顺序等）

MySQL 支持两种直方图类型：
1. Singleton（单值直方图）：每个桶存一个精确值和频率
   适用于列的不同值数量（NDV）≤ 桶数量的情况
2. Equi-height（等高直方图）：每个桶存一个值范围
   适用于 NDV > 桶数量的情况（大多数场景）
```

## 创建与更新直方图

```sql
-- 创建直方图：
ANALYZE TABLE orders UPDATE HISTOGRAM ON amount;
-- 默认使用 100 个桶

-- 指定桶数量（最大 1024）：
ANALYZE TABLE orders UPDATE HISTOGRAM ON amount WITH 200 BUCKETS;

-- 同时为多列创建直方图：
ANALYZE TABLE orders UPDATE HISTOGRAM ON amount, status, created_at;

-- 更新已有直方图（MySQL 8.0.31+ 简化语法）：
ANALYZE TABLE orders UPDATE HISTOGRAM ON amount;
-- 如果 amount 列已有直方图，会自动更新（重新采样）
-- 不需要先删除再创建

-- 删除直方图：
ANALYZE TABLE orders DROP HISTOGRAM ON amount;

-- 查看直方图信息：
SELECT SCHEMA_NAME, TABLE_NAME, COLUMN_NAME,
       HISTOGRAM->>'$."histogram-type"' AS type,
       HISTOGRAM->>'$."number-of-buckets-specified"' AS buckets,
       HISTOGRAM->>'$."sampling-rate"' AS sampling_rate,
       HISTOGRAM->>'$."last-updated"' AS last_updated
FROM information_schema.COLUMN_STATISTICS
WHERE TABLE_NAME = 'orders';
```

## 自动更新机制

```sql
-- MySQL 8.0.31+ 中 ANALYZE TABLE UPDATE HISTOGRAM 的增强行为：

-- 1. 如果列已有直方图 → 自动更新（重新采样生成新的统计信息）
-- 2. 如果列没有直方图 → 创建新的直方图
-- 3. 无需手动 DROP HISTOGRAM 再重新创建

-- 更新策略：
-- 直方图不会随数据变化自动更新（非实时更新）
-- 需要手动或通过定时任务执行 ANALYZE TABLE UPDATE HISTOGRAM

-- 定时更新直方图的示例（通过 Event Scheduler）：
SET GLOBAL event_scheduler = ON;

CREATE EVENT update_order_histogram
ON SCHEDULE EVERY 1 DAY
STARTS CURRENT_TIMESTAMP + INTERVAL 2 HOUR
DO
    ANALYZE TABLE orders UPDATE HISTOGRAM ON amount, status WITH 200 BUCKETS;

-- 或者在业务低峰期更新：
CREATE EVENT update_histograms_nightly
ON SCHEDULE EVERY 1 DAY
STARTS '2024-01-01 03:00:00'
DO BEGIN
    ANALYZE TABLE orders UPDATE HISTOGRAM ON amount, status;
    ANALYZE TABLE products UPDATE HISTOGRAM ON price, category_id;
    ANALYZE TABLE users UPDATE HISTOGRAM ON age, city;
END;
```

## 采样率控制

```sql
-- histogram_generation_max_mem_size 控制直方图生成时的内存使用
SHOW VARIABLES LIKE 'histogram_generation_max_mem_size';
-- histogram_generation_max_mem_size: 20000000（默认 20MB）

-- 如果表数据超过内存限制，MySQL 会自动采样（而不是扫描所有行）
-- 采样率 = 内存限制 / 表数据大小
-- 采样率越高，直方图越精确

-- 增大内存限制以提高精确度：
SET GLOBAL histogram_generation_max_mem_size = 100000000; -- 100MB

-- 查看实际采样率：
SELECT COLUMN_NAME,
       HISTOGRAM->>'$."sampling-rate"' AS sampling_rate
FROM information_schema.COLUMN_STATISTICS
WHERE TABLE_NAME = 'orders';
-- sampling_rate: 1.0（全量扫描）
-- sampling_rate: 0.5（采样 50% 的行）
-- sampling_rate: 0.1（采样 10% 的行）
```

## 验证直方图对查询优化的影响

```sql
-- 对比有无直方图时优化器的估算差异：

-- 删除直方图：
ANALYZE TABLE orders DROP HISTOGRAM ON amount;

-- 无直方图时的执行计划：
EXPLAIN SELECT * FROM orders WHERE amount > 5000;
-- rows: 500000（假设均匀分布，估算不准确）

-- 创建直方图：
ANALYZE TABLE orders UPDATE HISTOGRAM ON amount WITH 200 BUCKETS;

-- 有直方图时的执行计划：
EXPLAIN SELECT * FROM orders WHERE amount > 5000;
-- rows: 50000（基于直方图分布估算，更准确）

-- 检查优化器是否使用了直方图：
EXPLAIN FORMAT=JSON SELECT * FROM orders WHERE amount > 5000;
-- 在 JSON 输出中查找 "filtering_effect" 相关信息
```

## 适用场景

- **数据分布不均匀的列**：当列的值分布严重不均匀（如订单金额集中在低金额区间、用户年龄集中在 20~40 岁）时，直方图可以帮助优化器更准确地估算查询选择性，避免错误地选择全表扫描或不必要的索引
- **没有索引但经常参与 WHERE 条件的列**：对于不适合创建索引的列（如低基数列 status、或不常更新但经常查询的列），直方图是一种低成本的替代方案，不占用索引空间但能改善查询计划

## 常见问题

**直方图和索引的关系是什么？有索引的列还需要创建直方图吗？**

直方图和索引解决的是不同的问题。索引用于加速数据访问（快速定位行），直方图用于帮助优化器估算选择性（决定是否使用索引、选择哪种 JOIN 算法等）。有索引的列通常不需要直方图——因为优化器可以通过索引的统计信息（如 `index dive`）获得选择性估算。直方图更适合没有索引的列，或者虽然有索引但优化器统计信息不够准确的场景。如果同时存在索引和直方图，优化器会优先使用索引统计信息。

---

## 注意事项

- 直方图的统计信息不会随数据变化自动更新。如果表的数据分布发生了显著变化（如大量新增数据导致值分布改变），旧的直方图可能反而误导优化器。建议通过 Event Scheduler 定期更新直方图，更新频率取决于数据变化速度（日更或周更）。
- `ANALYZE TABLE UPDATE HISTOGRAM` 需要扫描表数据（全量或采样），对大表可能需要几秒到几十秒。在业务高峰期执行可能影响查询性能。建议在低峰期执行，或通过 `histogram_generation_max_mem_size` 限制内存使用来控制扫描量。

## 总结

MySQL 直方图记录列值的分布信息，帮助优化器更准确地估算查询选择性。创建：`ANALYZE TABLE t UPDATE HISTOGRAM ON col WITH N BUCKETS`（默认 100 桶，最大 1024）。MySQL 8.0.31+ 更新已有直方图时无需先删除。两种类型：Singleton（离散值）和 Equi-height（连续值范围）。采样率由 `histogram_generation_max_mem_size`（默认 20MB）控制。直方图不会自动更新，需定期执行 `ANALYZE TABLE UPDATE HISTOGRAM`（推荐用 Event Scheduler）。适合数据分布不均匀且无索引的列。查看：`information_schema.COLUMN_STATISTICS`。
