# 窗口函数性能优化

MySQL 8.0 引入了窗口函数（Window Functions），支持 `ROW_NUMBER()`、`RANK()`、`DENSE_RANK()`、`NTILE()`、`LAG()`、`LEAD()`、`FIRST_VALUE()`、`LAST_VALUE()`、`NTH_VALUE()`、`CUME_DIST()`、`PERCENT_RANK()` 以及聚合函数的窗口版本（如 `SUM() OVER()`、`AVG() OVER()`）。MySQL 8.0 的后续版本（8.0.21+）和 8.4 LTS 对窗口函数的执行效率进行了多项优化，包括更好的帧缓存、减少重复计算、优化排序操作等。

---

## 窗口函数的基本语法

```sql
-- 窗口函数的通用语法：
-- function_name() OVER (
--     [PARTITION BY col1, col2, ...]
--     [ORDER BY col1 [ASC|DESC], ...]
--     [frame_clause]
-- )

-- frame_clause 定义窗口帧范围：
-- ROWS BETWEEN start AND end
-- RANGE BETWEEN start AND end
-- start/end 可以是：
--   UNBOUNDED PRECEDING（从分区起始）
--   N PRECEDING（前 N 行）
--   CURRENT ROW（当前行）
--   N FOLLOWING（后 N 行）
--   UNBOUNDED FOLLOWING（到分区末尾）

-- 常用窗口函数示例：
SELECT
    employee_id,
    department,
    salary,
    ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rank_in_dept,
    RANK() OVER (ORDER BY salary DESC) AS overall_rank,
    SUM(salary) OVER (PARTITION BY department) AS dept_total,
    AVG(salary) OVER () AS company_avg,
    LAG(salary, 1) OVER (PARTITION BY department ORDER BY salary) AS prev_salary,
    LEAD(salary, 1) OVER (PARTITION BY department ORDER BY salary) AS next_salary
FROM employees;
```

## 窗口函数的执行优化

```sql
-- MySQL 8.0 对窗口函数的多项优化：

-- 1. 窗口定义复用
-- 多个窗口函数使用相同的 PARTITION BY + ORDER BY 时
-- MySQL 只排序一次，多个函数共享排序结果

-- 优化前（需要 3 次排序）：
SELECT
    ROW_NUMBER() OVER (ORDER BY salary DESC),
    RANK() OVER (ORDER BY salary DESC),
    DENSE_RANK() OVER (ORDER BY salary DESC)
FROM employees;

-- 优化后（只需 1 次排序）：
-- 三个函数共享同一个排序结果

-- 使用命名窗口进一步简化（语法层面）：
SELECT
    ROW_NUMBER() OVER w,
    RANK() OVER w,
    DENSE_RANK() OVER w
FROM employees
WINDOW w AS (ORDER BY salary DESC);

-- 2. 帧缓存优化
-- 对于滑动窗口帧（如 ROWS BETWEEN 5 PRECEDING AND CURRENT ROW）
-- MySQL 优化了帧的增量计算
-- 不是每行都从头计算帧内的聚合值
-- 而是在前一行的结果基础上"滑入新行、滑出旧行"
-- 时间复杂度从 O(N×K) 降为 O(N)（K 为帧大小）

-- 3. 排序消除
-- 当窗口函数的 ORDER BY 与查询的 ORDER BY 一致时
-- 可以复用同一次排序
SELECT salary,
       SUM(salary) OVER (ORDER BY salary) AS running_total
FROM employees
ORDER BY salary;
-- 只需一次排序（窗口函数和最终输出共享）
```

## 性能关键：索引与排序

```sql
-- 窗口函数的主要性能开销在于排序（PARTITION BY + ORDER BY）

-- 如果有合适的索引，可以避免排序操作（filesort）：
-- 索引应覆盖 PARTITION BY 列 + ORDER BY 列

-- 示例：
CREATE INDEX idx_dept_salary ON employees (department, salary);

-- 以下查询可以利用 idx_dept_salary 避免排序：
SELECT department, salary,
       ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rn
FROM employees;

-- EXPLAIN 中查看是否有 filesort：
EXPLAIN FORMAT=TREE
SELECT department, salary,
       ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rn
FROM employees;
-- 如果有 "Sort" 节点 → 存在排序开销
-- 如果使用了索引顺序 → 无额外排序

-- 优化建议：
-- PARTITION BY (a) ORDER BY (b) → 创建索引 (a, b)
-- PARTITION BY (a, b) ORDER BY (c) → 创建索引 (a, b, c)
-- 仅 ORDER BY (a) → 创建索引 (a)
```

## 常见窗口函数的性能对比

| 窗口函数 | 计算复杂度 | 是否需要帧 | 性能特点 |
|---------|:--------:|:--------:|---------|
| ROW_NUMBER() | O(1)/行 | 不需要 | 最快，只需排序 |
| RANK() | O(1)/行 | 不需要 | 接近 ROW_NUMBER |
| DENSE_RANK() | O(1)/行 | 不需要 | 接近 ROW_NUMBER |
| LAG()/LEAD() | O(1)/行 | 不需要 | 快，直接偏移访问 |
| SUM() OVER (ORDER BY) | O(1)/行 | 需要（增量）| 累计和，增量计算 |
| AVG() OVER (ROWS N) | O(1)/行 | 需要（滑动）| 滑动平均，增量优化 |
| FIRST_VALUE() | O(1)/行 | 需要 | 快，缓存帧首值 |
| NTILE() | O(1)/行 | 不需要 | 快，预计算分组 |

## 窗口函数替代子查询的性能提升

```sql
-- 传统子查询方式（需要多次扫描表）：
-- 查找每个部门薪资排名前 3 的员工
SELECT * FROM employees e1
WHERE (SELECT COUNT(*) FROM employees e2
       WHERE e2.department = e1.department AND e2.salary > e1.salary) < 3;
-- 对外表每行执行一次子查询 → O(N²)

-- 窗口函数方式（只需一次扫描 + 排序）：
SELECT * FROM (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rn
    FROM employees
) ranked
WHERE rn <= 3;
-- 一次排序 + 一次扫描 → O(N log N)

-- 性能差距：
-- 1万行数据：子查询约 2 秒 vs 窗口函数约 0.05 秒
-- 100万行数据：子查询可能超时 vs 窗口函数约 3 秒

-- 累计求和的对比：
-- 子查询方式：
SELECT id, amount,
       (SELECT SUM(amount) FROM orders o2 WHERE o2.id <= o1.id) AS running_total
FROM orders o1;
-- O(N²)

-- 窗口函数方式：
SELECT id, amount,
       SUM(amount) OVER (ORDER BY id) AS running_total
FROM orders;
-- O(N log N)
```

## 适用场景

- **排名和分页查询**：使用 `ROW_NUMBER()` 进行精确分页或分组内排名，替代传统的子查询方式。如"每个部门薪资最高的 N 个员工"、"每个类别销量最高的商品"
- **时间序列分析和滑动计算**：使用 `SUM() OVER (ORDER BY date)`、`AVG() OVER (ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)` 进行累计求和、移动平均等时间序列分析，如财务报表的累计收入、库存的移动平均

## 常见问题

**窗口函数可以在 WHERE 子句中使用吗？**

不能。窗口函数在 SQL 执行顺序中位于 WHERE、GROUP BY、HAVING 之后执行，因此不能在 WHERE 中直接引用窗口函数的结果。如果需要基于窗口函数的结果进行过滤，必须将窗口函数包装在子查询或 CTE 中，然后在外层查询中过滤。例如：`SELECT * FROM (SELECT *, ROW_NUMBER() OVER (...) AS rn FROM t) sub WHERE rn <= 10`。这也是为什么"Top-N per group"查询需要嵌套一层子查询的原因。

## 注意事项

- 多个窗口函数如果使用不同的 `PARTITION BY` 或 `ORDER BY`，MySQL 需要进行多次排序操作。在复杂查询中（如同时需要按部门排名和按公司整体排名），排序次数可能成为性能瓶颈。建议尽量统一窗口定义，使用 `WINDOW` 子句命名窗口，让尽可能多的窗口函数共享同一个排序结果。
- 窗口函数的结果不能被索引加速（因为它是在查询执行时动态计算的）。如果窗口函数的计算结果需要频繁查询，考虑将结果物化到表中（如通过定期执行的存储过程或物化视图替代方案）。

## 总结

MySQL 8.0 引入窗口函数，8.0.21+ 和 8.4 对其进行了多项性能优化：窗口定义复用（相同 PARTITION BY + ORDER BY 只排序一次）、帧缓存增量计算（滑动窗口 O(1)/行）、排序消除（与查询 ORDER BY 一致时共享排序）。性能关键：为 PARTITION BY + ORDER BY 列创建复合索引避免 filesort。窗口函数替代相关子查询可从 O(N²) 优化到 O(N log N)。不能在 WHERE 中直接使用，需包装子查询或 CTE。建议使用 WINDOW 子句命名窗口，统一窗口定义减少排序次数。
