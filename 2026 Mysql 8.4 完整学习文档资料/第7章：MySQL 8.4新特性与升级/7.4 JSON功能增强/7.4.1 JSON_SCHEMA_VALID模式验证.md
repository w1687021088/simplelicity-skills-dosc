# JSON_SCHEMA_VALID 模式验证

`JSON_SCHEMA_VALID()` 是 MySQL 8.0.17 引入的 JSON Schema 验证函数，用于检查一个 JSON 文档是否符合指定的 JSON Schema 定义。JSON Schema 是一种描述 JSON 数据结构和约束的标准（MySQL 支持 Draft 4），可以定义字段类型、必填字段、值范围、字符串格式等约束。在数据库层面进行 JSON 文档的结构验证，可以替代或补充应用层的数据校验逻辑，确保存入数据库的 JSON 数据始终符合预期格式。

---

## 基本语法

```sql
-- JSON_SCHEMA_VALID(schema, document)
-- 参数：
--   schema：JSON Schema 定义（JSON 字符串）
--   document：待验证的 JSON 文档（JSON 字符串或 JSON 列）
-- 返回值：
--   1（TRUE）：文档符合 Schema
--   0（FALSE）：文档不符合 Schema
--   NULL：任一参数为 NULL

-- 基本示例：
SELECT JSON_SCHEMA_VALID(
    '{"type": "object", "properties": {"name": {"type": "string"}, "age": {"type": "integer"}}, "required": ["name"]}',
    '{"name": "张三", "age": 25}'
) AS is_valid;
-- is_valid: 1（文档符合 Schema）

SELECT JSON_SCHEMA_VALID(
    '{"type": "object", "properties": {"name": {"type": "string"}, "age": {"type": "integer"}}, "required": ["name"]}',
    '{"age": 25}'
) AS is_valid;
-- is_valid: 0（缺少必填字段 name）
```

## JSON Schema 常用关键字

```sql
-- 类型约束（type）
-- "type": "object"    → JSON 对象
-- "type": "array"     → JSON 数组
-- "type": "string"    → 字符串
-- "type": "integer"   → 整数
-- "type": "number"    → 数字（含小数）
-- "type": "boolean"   → 布尔值
-- "type": "null"      → null

-- 对象属性约束（properties + required）
SET @schema = '{
    "type": "object",
    "properties": {
        "id":    {"type": "integer"},
        "name":  {"type": "string", "minLength": 1, "maxLength": 50},
        "email": {"type": "string"},
        "age":   {"type": "integer", "minimum": 0, "maximum": 150}
    },
    "required": ["id", "name"]
}';

SELECT JSON_SCHEMA_VALID(@schema, '{"id": 1, "name": "张三", "age": 25}');
-- 1（通过）

SELECT JSON_SCHEMA_VALID(@schema, '{"id": 1, "name": "", "age": 25}');
-- 0（name 长度小于 minLength=1）

SELECT JSON_SCHEMA_VALID(@schema, '{"id": 1, "name": "张三", "age": 200}');
-- 0（age 超过 maximum=150）

-- 数组约束
SET @arr_schema = '{
    "type": "array",
    "items": {"type": "string"},
    "minItems": 1,
    "maxItems": 5,
    "uniqueItems": true
}';

SELECT JSON_SCHEMA_VALID(@arr_schema, '["apple", "banana", "cherry"]');
-- 1（通过）

SELECT JSON_SCHEMA_VALID(@arr_schema, '["apple", "apple"]');
-- 0（uniqueItems 约束：不允许重复）

SELECT JSON_SCHEMA_VALID(@arr_schema, '[]');
-- 0（minItems=1，不允许空数组）
```

## 在 CHECK 约束中使用

```sql
-- MySQL 8.0.16+ 支持 CHECK 约束
-- 结合 JSON_SCHEMA_VALID 可以在建表时强制 JSON 列的结构

CREATE TABLE user_profiles (
    id INT AUTO_INCREMENT PRIMARY KEY,
    profile JSON NOT NULL,
    CONSTRAINT chk_profile CHECK (
        JSON_SCHEMA_VALID('{
            "type": "object",
            "properties": {
                "nickname": {"type": "string", "minLength": 1},
                "avatar_url": {"type": "string"},
                "settings": {"type": "object"}
            },
            "required": ["nickname"]
        }', profile)
    )
);

-- 插入符合 Schema 的数据：
INSERT INTO user_profiles (profile) VALUES
    ('{"nickname": "test_user", "avatar_url": "https://example.com/avatar.jpg"}');
-- 成功

-- 插入不符合 Schema 的数据：
INSERT INTO user_profiles (profile) VALUES
    ('{"avatar_url": "https://example.com/avatar.jpg"}');
-- ERROR 3819 (HY000): Check constraint 'chk_profile' is violated.
-- 原因：缺少必填字段 nickname
```

## 嵌套对象验证

```sql
-- 验证嵌套的 JSON 结构
SET @order_schema = '{
    "type": "object",
    "properties": {
        "order_id": {"type": "integer"},
        "customer": {
            "type": "object",
            "properties": {
                "name": {"type": "string"},
                "phone": {"type": "string", "pattern": "^1[3-9][0-9]{9}$"}
            },
            "required": ["name", "phone"]
        },
        "items": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "product": {"type": "string"},
                    "quantity": {"type": "integer", "minimum": 1},
                    "price": {"type": "number", "minimum": 0}
                },
                "required": ["product", "quantity", "price"]
            },
            "minItems": 1
        }
    },
    "required": ["order_id", "customer", "items"]
}';

SELECT JSON_SCHEMA_VALID(@order_schema, '{
    "order_id": 1001,
    "customer": {"name": "张三", "phone": "13800138000"},
    "items": [
        {"product": "iPhone", "quantity": 1, "price": 6999.00}
    ]
}');
-- 1（通过）
```

## 适用场景

- **数据库层面的 JSON 数据质量保障**：在 CHECK 约束中使用 `JSON_SCHEMA_VALID`，确保写入数据库的 JSON 文档必须符合预定义的结构规范，防止格式错误的 JSON 数据进入系统
- **API 数据入库前的最后一道校验**：即使应用层已经做了 JSON 格式校验，在数据库层面再加一层 Schema 验证可以作为防御性编程措施，防止应用层校验被绕过

---

## 常见问题

**JSON_SCHEMA_VALID 支持哪些版本的 JSON Schema 标准？**

MySQL 实现的 JSON Schema 验证遵循 JSON Schema Draft 4 标准。不支持 Draft 6/7/2019-09/2020-12 中引入的新关键字。主要支持的关键字包括：`type`、`properties`、`required`、`items`、`minimum`/`maximum`、`minLength`/`maxLength`、`minItems`/`maxItems`、`uniqueItems`、`pattern`（正则表达式）、`enum`、`allOf`/`anyOf`/`oneOf`/`not` 等。不支持 `$ref`（外部引用）和 `format` 关键字的内置验证。

---

## 注意事项

- `JSON_SCHEMA_VALID()` 每次调用都会解析 Schema 字符串，对于频繁执行的 INSERT/UPDATE 操作，将 Schema 存储为用户变量或应用层常量可以减少解析开销，但 MySQL 内部仍会每次解析。如果 CHECK 约束中的 Schema 很复杂，可能对写入性能产生一定影响（通常在微秒级，可以忽略）。
- `JSON_SCHEMA_VALID()` 不支持 `$ref` 关键字，无法引用外部 Schema 或实现 Schema 的模块化组合。如果需要复杂的模块化 Schema 验证，建议在应用层完成。

---

## 总结

`JSON_SCHEMA_VALID(schema, document)` 用于验证 JSON 文档是否符合 JSON Schema（Draft 4 标准），返回 1（符合）或 0（不符合）。支持的约束：类型（`type`）、必填字段（`required`）、值范围（`minimum`/`maximum`）、字符串长度（`minLength`/`maxLength`）、正则匹配（`pattern`）、数组约束（`minItems`/`maxItems`/`uniqueItems`）、嵌套对象验证、逻辑组合（`allOf`/`anyOf`/`oneOf`/`not`）。最佳实践：在 CHECK 约束中使用，强制 JSON 列的结构规范。限制：不支持 `$ref` 外部引用和 `format` 内置验证。
