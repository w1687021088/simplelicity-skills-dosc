# JSON 聚合函数 JSON_ARRAYAGG

`JSON_ARRAYAGG()` 是 MySQL 8.0 引入的聚合函数，用于将多行数据的某列值聚合为一个 JSON 数组。它类似于 `GROUP_CONCAT()`，但输出的是标准的 JSON 数组格式，而不是逗号分隔的字符串。`JSON_ARRAYAGG()` 可以直接生成合法的 JSON 数据，无需额外的字符串处理，特别适合将关系型数据转换为 JSON 格式输出给前端 API。

---

## 基本语法

```sql
-- JSON_ARRAYAGG(column_or_expression)
-- 将多行值聚合为 JSON 数组

-- 基本用法：
SELECT JSON_ARRAYAGG(name) AS names
FROM employees;
-- names: ["张三", "李四", "王五"]

-- 聚合数字列：
SELECT JSON_ARRAYAGG(salary) AS salaries
FROM employees WHERE department = 'IT';
-- salaries: [15000, 18000, 22000, 12000]

-- NULL 值的处理：
-- JSON_ARRAYAGG 会跳过 NULL 值（不包含在结果数组中）
SELECT JSON_ARRAYAGG(phone) FROM contacts;
-- 如果某些行的 phone 为 NULL，结果数组中不包含 null
-- 注意：这与 JSON 标准中 null 值的行为不同
```

---

## 配合 GROUP BY 使用

```sql
-- 按部门分组，将每个部门的员工姓名聚合为数组
SELECT department,
       JSON_ARRAYAGG(name) AS members
FROM employees
GROUP BY department;

-- 结果：
-- department | members
-- IT         | ["张三", "李四", "王五"]
-- HR         | ["赵六", "孙七"]
-- Finance    | ["周八", "吴九", "郑十"]

-- 按订单聚合商品名称
SELECT order_id,
       JSON_ARRAYAGG(product_name) AS products
FROM order_items
GROUP BY order_id;

-- order_id | products
-- 1001     | ["iPhone 15", "AirPods Pro", "iPhone Case"]
-- 1002     | ["MacBook Pro"]
```

## 聚合 JSON 对象

```sql
-- 将每行构造为 JSON 对象，然后聚合为数组
-- 配合 JSON_OBJECT 使用，生成对象数组

SELECT department,
       JSON_ARRAYAGG(
           JSON_OBJECT('name', name, 'salary', salary, 'hire_date', hire_date)
       ) AS employees_info
FROM employees
GROUP BY department;

-- 结果示例（IT 部门）：
-- [
--   {"name": "张三", "salary": 15000, "hire_date": "2022-01-15"},
--   {"name": "李四", "salary": 18000, "hire_date": "2021-06-20"},
--   {"name": "王五", "salary": 22000, "hire_date": "2020-03-10"}
-- ]

-- 这种用法非常适合直接生成 API 响应格式的 JSON 数据
```

## 排序控制

```sql
-- JSON_ARRAYAGG 默认不保证元素顺序
-- 如果需要特定顺序，可以通过子查询或窗口函数控制

-- 方法1：通过子查询排序
SELECT department,
       JSON_ARRAYAGG(name) AS members
FROM (
    SELECT department, name FROM employees ORDER BY name
) AS sorted
GROUP BY department;

-- 方法2：MySQL 8.0.14+ 中 JSON_ARRAYAGG 内部不支持 ORDER BY
-- 不像 GROUP_CONCAT 有 ORDER BY 子句
-- GROUP_CONCAT(name ORDER BY name) ← 支持
-- JSON_ARRAYAGG(name ORDER BY name) ← 不支持！会报语法错误

-- 因此如果需要排序，只能通过子查询实现
```

## JSON_ARRAYAGG vs GROUP_CONCAT

| 对比维度 | JSON_ARRAYAGG | GROUP_CONCAT |
|---------|:------------:|:------------:|
| 返回类型 | JSON 数组 | 字符串 |
| 格式 | `["a", "b", "c"]` | `a,b,c` |
| 长度限制 | 无（受 max_allowed_packet 限制）| `group_concat_max_len`（默认 1024）|
| NULL 处理 | 跳过 NULL | 跳过 NULL |
| ORDER BY | 不支持内部 ORDER BY | 支持 |
| 分隔符 | 无需指定 | 可自定义（默认逗号）|
| 去重 | 不支持 DISTINCT | 支持 DISTINCT |
| 嵌套能力 | 可嵌套 JSON_OBJECT | 只能拼接字符串 |

## 适用场景

- **构建 API 响应的 JSON 数据**：在后端直接通过 SQL 生成符合 API 接口格式的 JSON 数据（如商品列表、用户标签列表），减少应用层的数据转换逻辑
- **将一对多关系转换为嵌套 JSON**：将父子表的关系数据（如订单→订单项）聚合为嵌套 JSON 结构，方便前端直接消费

---

## 常见问题

**JSON_ARRAYAGG 的结果有长度限制吗？**

`JSON_ARRAYAGG` 不像 `GROUP_CONCAT` 那样受 `group_concat_max_len` 限制（默认 1024 字节），它的结果长度受 `max_allowed_packet` 参数限制（默认 67MB）。在实际使用中，如果聚合的行数非常多（如数万行），生成的 JSON 数组可能非常大，需要注意内存消耗和网络传输开销。建议在业务层对聚合结果的大小进行合理控制（如通过 WHERE 或 LIMIT 限制参与聚合的行数）。

---

## 注意事项

- `JSON_ARRAYAGG` 不支持 `DISTINCT` 关键字来去重。如果需要去重，可以在子查询中使用 `SELECT DISTINCT` 后再聚合：`SELECT JSON_ARRAYAGG(col) FROM (SELECT DISTINCT col FROM t) sub`。
- `JSON_ARRAYAGG` 在没有匹配行时返回 NULL 而不是空数组 `[]`。如果需要在无数据时返回空数组，可以使用 `COALESCE(JSON_ARRAYAGG(col), JSON_ARRAY())` 或 `IFNULL(JSON_ARRAYAGG(col), CAST('[]' AS JSON))`。

---

## 总结

`JSON_ARRAYAGG(expr)` 将多行数据聚合为 JSON 数组，配合 `GROUP BY` 使用。可嵌套 `JSON_OBJECT()` 生成对象数组（适合 API 响应格式）。与 `GROUP_CONCAT` 相比：输出标准 JSON 格式、无 `group_concat_max_len` 限制、支持嵌套 JSON 对象，但不支持内部 `ORDER BY` 和 `DISTINCT`。排序需通过子查询实现，去重需通过 `SELECT DISTINCT` 子查询。无匹配行时返回 NULL（用 `COALESCE` 处理为空数组）。NULL 值会被跳过。
