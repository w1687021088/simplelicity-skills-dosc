# JSON 表函数 JSON_TABLE 展开

`JSON_TABLE()` 是 MySQL 8.0 引入的表函数，用于将 JSON 数据转换为关系型表格（行和列），可以在 `FROM` 子句中使用，就像查询一张普通的表一样。它是 JSON 数据与关系型查询之间的桥梁——将嵌套的 JSON 数组、对象"展开"为标准的行列结构，使得 JSON 数据可以参与 JOIN、WHERE、GROUP BY 等常规 SQL 操作。

---

## 基本语法

```sql
JSON_TABLE(
    json_expression,        -- JSON 数据源
    json_path               -- 根路径（通常是数组路径）
    COLUMNS (               -- 列定义
        column_name data_type PATH json_path [DEFAULT value ON EMPTY] [DEFAULT value ON ERROR],
        ...
    )
) AS alias

-- json_expression：JSON 数据（可以是列、变量、函数返回值）
-- json_path：用于遍历的根路径，通常指向一个 JSON 数组
-- COLUMNS：定义输出列的名称、类型和对应的 JSON 路径
-- alias：表别名（必须指定）
```

---

## 基础使用示例

```sql
-- 将 JSON 数组展开为多行
SELECT *
FROM JSON_TABLE(
    '[{"name": "张三", "age": 25}, {"name": "李四", "age": 30}, {"name": "王五", "age": 28}]',
    '$[*]' COLUMNS (
        name VARCHAR(50) PATH '$.name',
        age INT PATH '$.age'
    )
) AS jt;

-- 结果：
-- name | age
-- 张三 | 25
-- 李四 | 30
-- 王五 | 28

-- 带行号（FOR ORDINALITY）：
SELECT *
FROM JSON_TABLE(
    '[{"name": "张三"}, {"name": "李四"}, {"name": "王五"}]',
    '$[*]' COLUMNS (
        row_num FOR ORDINALITY,
        name VARCHAR(50) PATH '$.name'
    )
) AS jt;

-- row_num | name
-- 1       | 张三
-- 2       | 李四
-- 3       | 王五
```

## 从表列中提取 JSON 数据

```sql
-- 假设 orders 表有一个 JSON 列 items，存储订单项数组
-- orders 表：
-- id | customer | items (JSON)
-- 1  | 张三     | [{"product": "iPhone", "qty": 1, "price": 6999},
--                  {"product": "AirPods", "qty": 2, "price": 999}]

-- 使用 JSON_TABLE 展开订单项
SELECT o.id, o.customer, jt.product, jt.qty, jt.price, jt.qty * jt.price AS subtotal
FROM orders o,
JSON_TABLE(o.items, '$[*]' COLUMNS (
    product VARCHAR(100) PATH '$.product',
    qty INT PATH '$.qty',
    price DECIMAL(10,2) PATH '$.price'
)) AS jt;

-- 结果：
-- id | customer | product  | qty | price   | subtotal
-- 1  | 张三     | iPhone   | 1   | 6999.00 | 6999.00
-- 1  | 张三     | AirPods  | 2   | 999.00  | 1998.00
```

## 嵌套路径 NESTED PATH

```sql
-- 处理嵌套的 JSON 结构
-- 假设数据：
SET @data = '{
    "store": "旗舰店",
    "departments": [
        {
            "name": "电子产品",
            "products": [
                {"item": "手机", "price": 3999},
                {"item": "平板", "price": 2999}
            ]
        },
        {
            "name": "服装",
            "products": [
                {"item": "T恤", "price": 99},
                {"item": "牛仔裤", "price": 299}
            ]
        }
    ]
}';

SELECT *
FROM JSON_TABLE(@data, '$.departments[*]' COLUMNS (
    dept_name VARCHAR(50) PATH '$.name',
    NESTED PATH '$.products[*]' COLUMNS (
        item VARCHAR(50) PATH '$.item',
        price DECIMAL(10,2) PATH '$.price'
    )
)) AS jt;

-- 结果：
-- dept_name | item   | price
-- 电子产品  | 手机   | 3999.00
-- 电子产品  | 平板   | 2999.00
-- 服装      | T恤    | 99.00
-- 服装      | 牛仔裤 | 299.00
```

## 默认值与错误处理

```sql
-- DEFAULT ... ON EMPTY：路径不存在时使用默认值
-- DEFAULT ... ON ERROR：类型转换失败时使用默认值
-- NULL ON EMPTY / NULL ON ERROR：返回 NULL（默认行为）
-- ERROR ON EMPTY / ERROR ON ERROR：抛出错误

SELECT *
FROM JSON_TABLE(
    '[{"name": "张三", "age": 25}, {"name": "李四"}, {"name": "王五", "age": "unknown"}]',
    '$[*]' COLUMNS (
        name VARCHAR(50) PATH '$.name',
        age INT PATH '$.age'
            DEFAULT 0 ON EMPTY      -- age 字段不存在时返回 0
            DEFAULT -1 ON ERROR     -- age 类型转换失败时返回 -1
    )
) AS jt;

-- name | age
-- 张三 | 25
-- 李四 | 0      ← ON EMPTY（第二行没有 age 字段）
-- 王五 | -1     ← ON ERROR（"unknown" 无法转为 INT）

-- EXISTS PATH：检查路径是否存在
SELECT *
FROM JSON_TABLE(
    '[{"name": "张三", "email": "zhangsan@test.com"}, {"name": "李四"}]',
    '$[*]' COLUMNS (
        name VARCHAR(50) PATH '$.name',
        has_email INT EXISTS PATH '$.email'
    )
) AS jt;

-- name | has_email
-- 张三 | 1
-- 李四 | 0
```

## 适用场景

- **JSON 数组数据的关系型查询**：当 JSON 列中存储了数组数据（如订单项列表、标签数组），需要对数组中的元素进行过滤、排序、聚合等关系型操作时，`JSON_TABLE` 可以将数组展开为行，方便使用标准 SQL 处理
- **JSON 日志或事件数据的分析**：将 JSON 格式的日志数据（如审计日志、操作记录）通过 `JSON_TABLE` 展开为结构化表格，便于统计分析和报表生成

## 常见问题

**JSON_TABLE 的性能如何？在大数据量下是否可用？**

`JSON_TABLE` 对每行数据都需要解析 JSON 并提取路径，性能不如直接查询关系型列。对于少量数据（几千到几万行）或分析型查询，性能通常可以接受。对于高并发的 OLTP 查询（每秒数千次），如果每次都需要 `JSON_TABLE` 展开大量 JSON 数据，可能成为性能瓶颈。优化建议：①将频繁查询的 JSON 字段提取为生成列（Generated Column）并建索引；②考虑将 JSON 数组数据拆分到独立的关系型子表中；③在应用层完成 JSON 解析，减少数据库的解析负担。

---

## 注意事项

- `JSON_TABLE` 只能在 `FROM` 子句中使用，不能在 `WHERE`、`SELECT` 等其他子句中直接使用。它返回一个虚拟表，可以像普通表一样参与 JOIN、子查询等操作。
- 当 JSON 数据中的数组为空（`[]`）时，`JSON_TABLE` 不会产生任何行。如果需要在数组为空时仍保留父行数据，可以使用 `LEFT JOIN` 语法：`FROM orders o LEFT JOIN JSON_TABLE(o.items, '$[*]' COLUMNS (...)) AS jt ON TRUE`。

---

## 总结

`JSON_TABLE()` 将 JSON 数据转换为关系型表格（行和列），在 `FROM` 子句中使用。语法：`JSON_TABLE(json_expr, path COLUMNS (col_def, ...)) AS alias`。核心功能：`$[*]` 遍历数组元素、`PATH` 指定提取路径、`FOR ORDINALITY` 生成行号、`NESTED PATH` 处理嵌套结构、`DEFAULT ... ON EMPTY/ERROR` 处理缺失和错误、`EXISTS PATH` 检查路径存在性。适合将 JSON 数组展开为行进行 SQL 查询。空数组不产生行（用 LEFT JOIN 保留父行）。大数据量下注意性能，频繁查询的字段建议提取为生成列。
