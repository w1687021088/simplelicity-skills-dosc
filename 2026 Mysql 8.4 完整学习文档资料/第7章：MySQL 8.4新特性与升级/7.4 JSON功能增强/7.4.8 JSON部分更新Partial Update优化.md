# JSON 部分更新 Partial Update 优化

MySQL 8.0 引入了 JSON 部分更新（Partial Update）优化，允许在修改 JSON 文档中的某个字段时，只更新被修改的部分而不是重写整个 JSON 文档。在此之前，即使只修改 JSON 中的一个小字段，MySQL 也需要将整个 JSON 文档读出、修改、再写回，对于大型 JSON 文档来说存在明显的 I/O 浪费。部分更新优化在 InnoDB 存储层和 binlog 层面都有效，显著减少了 JSON 修改操作的磁盘 I/O 和复制传输量。

---

## 部分更新的触发条件

```sql
-- 部分更新并不是对所有 JSON 修改都生效
-- 需要满足以下条件才能触发 Partial Update：

-- 1. 使用 JSON_SET()、JSON_REPLACE() 或 JSON_REMOVE() 函数
-- 2. 更新的列必须与函数的第一个参数是同一列
-- 3. 修改后的值不能比原始值占用更多空间（对于 JSON_SET/JSON_REPLACE）
-- 4. 不能添加新的键（JSON_SET 添加不存在的键不触发部分更新）

-- 触发部分更新的语句：
UPDATE products SET data = JSON_SET(data, '$.price', 199.99)
WHERE id = 1;
-- 只修改 data 中的 price 字段 → 可以部分更新

UPDATE products SET data = JSON_REPLACE(data, '$.name', 'New Name')
WHERE id = 1;
-- 替换 data 中的 name 字段 → 可以部分更新（如果新值不超过旧值长度）

UPDATE products SET data = JSON_REMOVE(data, '$.temp_field')
WHERE id = 1;
-- 删除 data 中的 temp_field → 可以部分更新

-- 不触发部分更新的语句：
UPDATE products SET data = '{"completely": "new json"}'
WHERE id = 1;
-- 直接赋值整个 JSON → 不是部分更新

UPDATE products SET data = JSON_ARRAY_APPEND(data, '$.tags', 'new_tag')
WHERE id = 1;
-- JSON_ARRAY_APPEND 不在支持列表中 → 不触发部分更新
```

## binlog 层面的优化

```sql
-- 部分更新在 binlog 中也有优化
-- 通过 binlog_row_value_options 参数控制

-- 查看当前设置：
SHOW VARIABLES LIKE 'binlog_row_value_options';
-- binlog_row_value_options: PARTIAL_JSON（默认启用）

-- 启用 binlog 部分 JSON 记录：
SET GLOBAL binlog_row_value_options = 'PARTIAL_JSON';

-- 禁用（记录完整 JSON）：
SET GLOBAL binlog_row_value_options = '';

-- 启用后的效果：
-- binlog 中只记录 JSON 文档被修改的部分（差异/diff）
-- 而不是修改前后的完整 JSON 文档
-- 对于大型 JSON 文档（如 10MB），只修改一个字段时
-- binlog 可能只需要记录几十字节的差异，而不是 20MB（before + after）

-- 这对复制性能有重大影响：
-- 减少了 binlog 文件大小
-- 减少了主从复制的网络传输量
-- 从库的 relay log 也更小
```

## InnoDB 层面的优化

```sql
-- InnoDB 层面的部分更新优化是自动的，无需额外配置

-- 工作原理：
-- 1. 当 JSON 部分更新条件满足时
-- 2. InnoDB 不需要将整个 JSON 文档从数据页读到内存
-- 3. 只需要定位到被修改的字段在文档中的偏移量
-- 4. 直接在数据页上修改该位置的值
-- 5. redo log 也只记录被修改的部分

-- 性能对比（示例数据）：
-- 假设 JSON 文档大小 = 100KB
-- 修改其中一个 10 字节的字段

-- 不使用部分更新：
-- 读取：100KB（整个 JSON）
-- 写入：100KB（整个 JSON）
-- redo log：100KB+
-- binlog：200KB（before image + after image）

-- 使用部分更新：
-- 读取：定位偏移量 + 10 字节
-- 写入：10 字节
-- redo log：几十字节
-- binlog：几十字节（差异记录）
```

## 监控部分更新的使用情况

```sql
-- 通过状态变量监控部分更新的命中情况：

-- 暂未有直接的状态变量统计部分更新次数
-- 可以通过以下间接方式判断：

-- 1. 比较 binlog 文件大小
-- 启用 PARTIAL_JSON 前后，相同 UPDATE 操作产生的 binlog 大小差异

-- 2. 比较 InnoDB 的写入量
SHOW GLOBAL STATUS LIKE 'Innodb_data_written';
-- 在部分更新生效时，相同操作的写入量应显著减少

-- 3. 使用 mysqlbinlog 查看 binlog 事件
-- mysqlbinlog --verbose --base64-output=DECODE-ROWS binlog.000001
-- 部分更新的事件会标记为 partial JSON update
```

## 最佳实践

```sql
-- 1. 优先使用 JSON_SET 和 JSON_REPLACE 进行字段级修改
-- 而不是在应用层读取整个 JSON → 修改 → 写回整个 JSON

-- 推荐（触发部分更新）：
UPDATE orders SET data = JSON_SET(data, '$.status', 'shipped') WHERE id = 1;

-- 不推荐（不触发部分更新）：
-- 应用层代码：
-- json_data = SELECT data FROM orders WHERE id = 1
-- json_data['status'] = 'shipped'
-- UPDATE orders SET data = json_data WHERE id = 1

-- 2. 避免修改后值的长度显著增加
-- JSON_SET 修改值时，如果新值比旧值长很多
-- 可能需要重新分配空间 → 无法部分更新 → 退化为完整重写

-- 好的实践：
-- 预留足够的字段空间（如使用固定长度的状态码而不是可变长度的描述）
-- status: "P" (pending) → "S" (shipped)  ← 好（长度不变）
-- status: "pending" → "shipped_and_delivered"  ← 差（长度增加）

-- 3. 确保 binlog_row_value_options = 'PARTIAL_JSON'
-- MySQL 8.0 默认启用，但需要确认没有被修改
SHOW VARIABLES LIKE 'binlog_row_value_options';
```

## 适用场景

- **大型 JSON 文档的频繁小修改**：如用户画像（profile）、商品详情（detail）等存储在 JSON 列中的大型文档，业务中频繁更新其中的某个字段（如在线状态、最后活跃时间、库存数量），部分更新可以将 I/O 从 MB 级降低到 KB 级
- **高写入量的主从复制环境**：在主从复制环境中，JSON 部分更新可以显著减少 binlog 大小和网络传输量，降低复制延迟

## 常见问题

**如何确认某个 UPDATE 语句是否真正触发了部分更新？**

目前 MySQL 没有直接的状态变量或 EXPLAIN 输出来确认某条语句是否触发了部分更新。可以通过间接方法判断：①对大型 JSON 文档执行一次 `JSON_SET` 更新，观察 binlog 事件大小——如果事件远小于 JSON 文档本身的大小，说明部分更新生效了（`mysqlbinlog --verbose` 查看）；②比较 `Innodb_data_written` 在操作前后的增量——部分更新时增量应远小于 JSON 文档大小。确保语句满足触发条件：使用 `JSON_SET`/`JSON_REPLACE`/`JSON_REMOVE`、更新的列与函数第一参数是同一列、修改后不增加空间。

---

## 注意事项

- 部分更新只适用于 `JSON_SET()`、`JSON_REPLACE()` 和 `JSON_REMOVE()` 三个函数。其他 JSON 修改函数（如 `JSON_ARRAY_APPEND()`、`JSON_ARRAY_INSERT()`、`JSON_MERGE_PATCH()`、`JSON_MERGE_PRESERVE()`）不支持部分更新，使用这些函数时仍然会重写整个 JSON 文档。
- 当使用 `JSON_SET()` 向 JSON 文档添加一个之前不存在的键时（insert 语义而非 update 语义），由于需要扩展文档结构，通常无法触发部分更新。如果需要频繁添加新键，建议在文档初始化时预留所有可能的键（设为 null 或默认值），后续修改时使用 `JSON_REPLACE()` 更新已有键的值。

## 总结

JSON 部分更新（Partial Update）是 MySQL 8.0 的重要优化，允许修改 JSON 文档时只更新被修改的部分而不是重写整个文档。触发条件：使用 `JSON_SET()`/`JSON_REPLACE()`/`JSON_REMOVE()`，更新列与函数第一参数一致，修改后不增加空间。优化层面：InnoDB 层（减少 I/O 和 redo log）+ binlog 层（`binlog_row_value_options=PARTIAL_JSON`，减少 binlog 大小和复制传输量）。对大型 JSON 文档（KB~MB 级）的字段级修改效果显著。最佳实践：使用 SQL 层面的 JSON 函数直接修改而不是在应用层读取-修改-写回。
