# JSON 路径多值提取 JSON_MULTI_VALUE

MySQL 8.0.17 引入了多值索引（Multi-Valued Index）功能，允许在 JSON 数组元素上创建索引。与此配套的有两个关键特性：`MEMBER OF()` 运算符和 `JSON_OVERLAPS()` 函数，以及 `CAST(... AS ... ARRAY)` 语法。这些特性共同实现了"JSON 数组中的元素可以被索引和高效查询"的能力，解决了 JSON 数组数据无法被传统 B-Tree 索引覆盖的问题。

---

## 多值索引的创建

```sql
-- 多值索引通过 CAST(... AS ... ARRAY) 语法创建
-- 将 JSON 数组中的每个元素都建立索引条目

CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    data JSON
);

-- 在 data->'$.tags' 数组上创建多值索引
CREATE INDEX idx_tags ON products (
    (CAST(data->'$.tags' AS CHAR(20) ARRAY))
);

-- 在 data->'$.categories' 数组上创建多值索引（整数类型）
CREATE INDEX idx_categories ON products (
    (CAST(data->'$.categories' AS UNSIGNED ARRAY))
);

-- 插入测试数据
INSERT INTO products (name, data) VALUES
('iPhone 15', '{"tags": ["phone", "apple", "5G"], "categories": [1, 3, 5]}'),
('MacBook Pro', '{"tags": ["laptop", "apple", "M3"], "categories": [2, 3]}'),
('Galaxy S24', '{"tags": ["phone", "samsung", "5G"], "categories": [1, 4]}');
```

## MEMBER OF() 运算符

```sql
-- MEMBER OF() 检查一个值是否存在于 JSON 数组中
-- 语法：value MEMBER OF(json_array)

-- 查找包含 "apple" 标签的产品
SELECT * FROM products
WHERE 'apple' MEMBER OF(data->'$.tags');
-- iPhone 15, MacBook Pro

-- 查找类别包含 1 的产品
SELECT * FROM products
WHERE 1 MEMBER OF(data->'$.categories');
-- iPhone 15, Galaxy S24

-- MEMBER OF 可以利用多值索引（走 idx_tags 索引）
EXPLAIN SELECT * FROM products
WHERE 'apple' MEMBER OF(data->'$.tags');
-- type: ref, key: idx_tags

-- 注意 MEMBER OF 的语法：
-- 正确：'value' MEMBER OF(json_array_expression)
-- 错误：MEMBER OF('value', json_array_expression)  ← 不是函数调用
```

## JSON_OVERLAPS() 函数

```sql
-- JSON_OVERLAPS(json_doc1, json_doc2)
-- 检查两个 JSON 文档是否有共同元素
-- 返回 1（有交集）或 0（无交集）

-- 查找标签包含 "phone" 或 "laptop" 的产品
SELECT * FROM products
WHERE JSON_OVERLAPS(data->'$.tags', '["phone", "laptop"]');
-- iPhone 15, MacBook Pro, Galaxy S24

-- 查找类别包含 1 或 2 的产品
SELECT * FROM products
WHERE JSON_OVERLAPS(data->'$.categories', '[1, 2]');
-- iPhone 15, MacBook Pro, Galaxy S24

-- JSON_OVERLAPS 也可以利用多值索引
EXPLAIN SELECT * FROM products
WHERE JSON_OVERLAPS(data->'$.tags', '["phone", "laptop"]');

-- 两个标量值的比较：
SELECT JSON_OVERLAPS('"apple"', '"apple"');  -- 1
SELECT JSON_OVERLAPS('"apple"', '"banana"'); -- 0

-- 数组与标量的比较：
SELECT JSON_OVERLAPS('["a", "b", "c"]', '"b"');  -- 1
```

## JSON_CONTAINS() 与多值索引

```sql
-- JSON_CONTAINS 也可以利用多值索引

-- 查找标签包含 "phone" 且包含 "5G" 的产品（AND 语义）
SELECT * FROM products
WHERE JSON_CONTAINS(data->'$.tags', '"phone"')
  AND JSON_CONTAINS(data->'$.tags', '"5G"');
-- iPhone 15, Galaxy S24

-- 查找标签完全包含指定数组的产品
SELECT * FROM products
WHERE JSON_CONTAINS(data->'$.tags', '["phone", "5G"]');
-- iPhone 15, Galaxy S24（标签同时包含 phone 和 5G）
```

## 多值索引 vs 传统索引 vs 全文索引

| 对比维度 | 多值索引 | 传统 B-Tree 索引 | 全文索引 |
|---------|:------:|:-------------:|:------:|
| 数据结构 | JSON 数组 | 标量列 | 文本列 |
| 每行索引条目 | 多个（数组元素个数）| 1 个 | 多个（词语个数）|
| 查询运算符 | MEMBER OF / JSON_OVERLAPS / JSON_CONTAINS | = / > / < / BETWEEN | MATCH ... AGAINST |
| 索引创建 | CAST(... AS ... ARRAY) | 普通 CREATE INDEX | FULLTEXT |
| 适用引擎 | InnoDB | 所有 | InnoDB / MyISAM |
| 引入版本 | MySQL 8.0.17 | 早期版本 | 早期版本 |

## CAST ... AS ... ARRAY 支持的类型

```sql
-- 多值索引中 CAST 支持的 ARRAY 元素类型：

-- 字符串类型：
CAST(data->'$.tags' AS CHAR(N) ARRAY)
-- N 指定最大字符长度

-- 整数类型：
CAST(data->'$.ids' AS SIGNED ARRAY)
CAST(data->'$.ids' AS UNSIGNED ARRAY)

-- 日期时间类型：
CAST(data->'$.dates' AS DATE ARRAY)
CAST(data->'$.times' AS DATETIME ARRAY)
CAST(data->'$.times' AS TIME ARRAY)

-- 浮点/定点数类型：
CAST(data->'$.prices' AS DECIMAL(10,2) ARRAY)
CAST(data->'$.values' AS FLOAT ARRAY)
CAST(data->'$.values' AS DOUBLE ARRAY)

-- 二进制类型：
CAST(data->'$.bins' AS BINARY(N) ARRAY)
```

## 适用场景

- **标签系统的高效查询**：商品标签、文章标签、用户兴趣标签等场景，标签以 JSON 数组形式存储在 JSON 列中。通过多值索引 + `MEMBER OF`，可以高效查询"包含某个标签"的记录，性能接近传统的标签关联表
- **多选过滤条件的快速匹配**：电商平台的商品属性筛选（如颜色、尺寸、品牌），属性值以数组形式存储。用户选择多个筛选条件时，通过 `JSON_OVERLAPS` 判断是否有交集

## 常见问题

**多值索引的存储开销有多大？**

多值索引为 JSON 数组中的每个元素都创建一个索引条目。如果一个 JSON 列存储了平均 5 个标签的数组，那么多值索引的条目数大约是数据行数的 5 倍。索引的存储空间取决于元素类型和长度。例如 `CHAR(20) ARRAY` 每个条目约 20 字节 + 索引开销。100 万行数据、平均 5 个标签 → 约 500 万索引条目，索引文件大约 100~200MB。如果数组元素非常多（如每行数百个元素），索引可能非常大，需要评估存储和维护成本。

---

## 注意事项

- 多值索引只支持 InnoDB 引擎，且只能创建在 JSON 列的数组路径上。如果 JSON 路径指向的不是数组（如对象或标量），多值索引无法正常工作。
- 多值索引不能作为主键或唯一索引使用。它是二级索引（Secondary Index），用于加速包含 `MEMBER OF`、`JSON_OVERLAPS`、`JSON_CONTAINS` 的查询。复合索引中多值索引列只能是索引的最后一部分，且一个复合索引中最多只能有一个多值索引列。

---

## 总结

MySQL 8.0.17 引入多值索引，为 JSON 数组元素建立索引。创建：`CREATE INDEX idx ON t ((CAST(j->'$.arr' AS type ARRAY)))`，支持 `CHAR`/`SIGNED`/`UNSIGNED`/`DECIMAL`/`DATE`/`DATETIME` 等类型。查询运算符：`MEMBER OF()`（值是否在数组中）、`JSON_OVERLAPS()`（两个文档是否有交集）、`JSON_CONTAINS()`（数组是否包含指定值）。多值索引为每个数组元素创建索引条目，存储开销与数组元素数成正比。只支持 InnoDB，不能做主键/唯一索引。适合标签系统、多选过滤等 JSON 数组查询场景。
