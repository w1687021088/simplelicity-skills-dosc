# InnoDB ClusterSet 跨集群复制

InnoDB ClusterSet 是 MySQL 8.0.27 引入的跨地域灾备方案，允许将多个 InnoDB Cluster 通过异步复制链接在一起，形成一个跨数据中心的容灾架构。其中一个集群作为 Primary Cluster（主集群，负责读写），其余作为 Replica Cluster（副本集群，只读）。当主集群所在的数据中心发生灾难时，可以将某个副本集群提升为新的主集群，实现跨地域的灾难恢复。

---

## ClusterSet 架构

```
InnoDB ClusterSet 的跨数据中心架构：

┌─────────────────────────────────┐
│      数据中心 A（主站）          │
│  ┌──────────────────────────┐   │
│  │  Primary Cluster (R/W)   │   │
│  │  ┌────┐ ┌────┐ ┌────┐   │   │
│  │  │ P  │ │ S  │ │ S  │   │   │
│  │  └────┘ └────┘ └────┘   │   │
│  └────────────┬─────────────┘   │
└───────────────┼─────────────────┘
                │ 异步复制
┌───────────────┼─────────────────┐
│      数据中心 B（灾备站）        │
│  ┌────────────▼─────────────┐   │
│  │  Replica Cluster (R/O)   │   │
│  │  ┌────┐ ┌────┐ ┌────┐   │   │
│  │  │ P  │ │ S  │ │ S  │   │   │
│  │  └────┘ └────┘ └────┘   │   │
│  └──────────────────────────┘   │
└─────────────────────────────────┘

- Primary Cluster：唯一的读写集群（内部使用 MGR 同步复制）
- Replica Cluster：只读集群，通过异步复制从 Primary Cluster 接收数据
- 每个 Cluster 内部是完整的 InnoDB Cluster（MGR + Router）
- 集群间通过异步复制连接（ClusterSet Replication Channel）
```

## 创建 ClusterSet

```javascript
// 1. 先创建 Primary Cluster（如果还没有）
mysqlsh> \connect root@dc_a_host1:3306
mysqlsh> var cluster = dba.createCluster('primaryCluster')
mysqlsh> cluster.addInstance('root@dc_a_host2:3306')
mysqlsh> cluster.addInstance('root@dc_a_host3:3306')

// 2. 将 Primary Cluster 升级为 ClusterSet
mysqlsh> var cs = cluster.createClusterSet('myClusterSet')
// 返回 ClusterSet 对象

// 3. 在灾备数据中心创建 Replica Cluster
mysqlsh> var replicaCluster = cs.createReplicaCluster(
    'root@dc_b_host1:3306',    // Replica Cluster 的第一个实例
    'replicaCluster'            // Replica Cluster 名称
)

// 4. 向 Replica Cluster 添加更多成员
mysqlsh> replicaCluster.addInstance('root@dc_b_host2:3306')
mysqlsh> replicaCluster.addInstance('root@dc_b_host3:3306')

// 5. 查看 ClusterSet 状态
mysqlsh> cs.status()
// 显示所有集群的角色、成员状态、复制延迟等
mysqlsh> cs.status({extended: 1})
```

## 灾难恢复（Failover 与 Switchover）

```javascript
// 计划内切换（Switchover，优雅切换）
// 适用于：计划内维护、数据中心迁移
mysqlsh> cs.setPrimaryCluster('replicaCluster')
// 过程：
// 1. 停止 Primary Cluster 的写入
// 2. 等待 Replica Cluster 同步完所有数据
// 3. Replica Cluster 提升为新 Primary
// 4. 旧 Primary Cluster 降级为 Replica
// 零数据丢失

// 紧急切换（Emergency Failover，强制切换）
// 适用于：Primary Cluster 所在数据中心完全不可用
mysqlsh> cs.forcePrimaryCluster('replicaCluster')
// 过程：
// 1. 不等待旧 Primary（因为已不可达）
// 2. 强制将 Replica Cluster 提升为新 Primary
// 3. 可能有少量数据丢失（异步复制的延迟窗口）
// 4. 旧 Primary 恢复后需要手动处理（rejoin 或重建）

// 旧 Primary 恢复后重新加入 ClusterSet
mysqlsh> cs.rejoinCluster('primaryCluster')
// 如果数据差异过大，可能需要使用 Clone 重建
```

## ClusterSet vs 其他灾备方案

| 对比维度 | InnoDB ClusterSet | 单个跨地域 MGR | 异步复制+MHA |
|---------|:----------------:|:------------:|:-----------:|
| 本地一致性 | 强（MGR Paxos）| 强 | 弱（异步）|
| 跨地域复制 | 异步（可接受延迟）| 同步（延迟大）| 异步 |
| 跨地域延迟影响 | 仅影响灾备延迟 | 影响每个事务 | 仅影响灾备延迟 |
| 灾难切换 | AdminAPI 一键切换 | 无此能力 | 手动或 MHA |
| 管理复杂度 | 中（AdminAPI）| 高 | 高 |
| 数据丢失风险 | Switchover 零丢失 | 无 | 可能丢失 |
| 成员总数限制 | 每个集群 9 个 | 整体 9 个 | 无限制 |

## 适用场景

- **跨数据中心的灾难恢复**：当业务要求在数据中心级别的灾难（如机房断电、自然灾害）后能够快速恢复服务时，ClusterSet 提供了基于 AdminAPI 的一键灾难切换能力
- **同城双活或异地灾备架构**：主站在 A 城市提供读写服务，灾备站在 B 城市通过 ClusterSet 保持数据副本。正常情况下灾备站可以提供只读查询分担主站压力

---

## 常见问题

**ClusterSet 的 Replica Cluster 可以提供只读查询服务吗？**

可以。Replica Cluster 内部的所有成员（包括 Primary 和 Secondary）都是只读的（`super_read_only=ON`），但可以接受 SELECT 查询。可以在灾备数据中心部署 MySQL Router，将只读查询路由到 Replica Cluster 的成员，利用灾备站的计算资源分担主站的读负载。但需要注意 Replica Cluster 的数据可能有异步复制延迟（通常几秒），对实时性要求高的查询应路由到 Primary Cluster。

---

## 注意事项

- ClusterSet 的集群间复制使用**异步复制**（不是 MGR 的 Paxos 同步），因此存在复制延迟。在 Emergency Failover（强制切换）时，尚未同步到 Replica Cluster 的事务会丢失。丢失的数据量取决于异步复制的延迟大小。建议监控跨集群复制延迟（`Seconds_Behind_Source`），确保延迟在可接受范围内。
- ClusterSet 要求所有集群使用相同的 MySQL 版本（至少主版本号一致）。升级时应先升级 Replica Cluster，最后升级 Primary Cluster，确保兼容性。

---

## 总结

InnoDB ClusterSet 是 MySQL 8.0.27+ 的跨数据中心灾备方案，将多个 InnoDB Cluster 通过异步复制链接。架构：一个 Primary Cluster（读写）+ 多个 Replica Cluster（只读）。创建：`cluster.createClusterSet()` → `cs.createReplicaCluster()`。切换：计划内 `cs.setPrimaryCluster()`（零数据丢失）/ 紧急 `cs.forcePrimaryCluster()`（可能少量丢失）。监控：`cs.status({extended:1})`。集群内使用 MGR Paxos 同步（强一致），集群间使用异步复制（有延迟）。适合跨数据中心灾备和同城双活架构。Replica Cluster 可提供只读查询服务。
