# NOWAIT 不等待立即报错

`NOWAIT` 是 MySQL 8.0 引入的 `FOR UPDATE` 和 `FOR SHARE` 扩展选项，使 SELECT 在遇到无法立即获取的锁时，不进入等待状态，而是立即报错返回（ERROR 3572）。与默认的等待行为（等到 `innodb_lock_wait_timeout` 超时）相比，`NOWAIT` 的"快速失败"策略让调用方立即感知到冲突，可以迅速做出响应（报错给用户、重试或选择其他数据），而不是让请求长时间挂起。

---

## 基本语法

```sql
-- FOR UPDATE NOWAIT（排他锁，立即报错）
SELECT * FROM accounts WHERE id = 1 FOR UPDATE NOWAIT;

-- FOR SHARE NOWAIT（共享锁，立即报错）
SELECT * FROM accounts WHERE id = 1 FOR SHARE NOWAIT;

-- 报错信息：
-- ERROR 3572 (HY000): Statement aborted because lock(s) could not be acquired
-- immediately and NOWAIT is set.

-- NOWAIT 不能与 SKIP LOCKED 同时使用
-- SELECT * FROM t WHERE id = 1 FOR UPDATE NOWAIT SKIP LOCKED;  -- 语法错误
```

---

## 与默认等待行为的对比

```sql
-- 默认行为（等待锁，最长等待 innodb_lock_wait_timeout=50 秒）：
BEGIN;
SELECT * FROM accounts WHERE id = 1 FOR UPDATE;
-- 如果 id=1 有 X 锁 → 等待最多 50 秒
-- 50 秒后：ERROR 1205: Lock wait timeout exceeded

-- NOWAIT 行为（立即报错）：
BEGIN;
SELECT * FROM accounts WHERE id = 1 FOR UPDATE NOWAIT;
-- 如果 id=1 有 X 锁 → 立即报错（毫秒级）
-- 立即：ERROR 3572: Statement aborted because lock(s) could not be acquired immediately

-- NOWAIT 后事务仍然活跃（与锁等待超时一样，只回滚当前语句）
-- 应用层需要显式 ROLLBACK
ROLLBACK;
```

## NOWAIT 的适用场景

```sql
-- 场景1：用户交互界面的快速响应
-- 用户点击"编辑"按钮时，需要锁定某条记录用于编辑
BEGIN;
SELECT * FROM orders WHERE id = 1001 FOR UPDATE NOWAIT;
-- 如果成功：锁定记录，允许用户编辑
-- 如果 ERROR 3572：立即返回错误给前端
-- → 提示用户："当前记录正在被其他用户编辑，请稍后再试"
-- 比让用户等待 50 秒后超时体验好得多

-- 场景2：高并发的资源争抢（快速失败）
-- 多个请求争抢同一个资源（如限量商品、唯一优惠券）
BEGIN;
SELECT * FROM coupons WHERE id = 500 AND status = 'available' FOR UPDATE NOWAIT;
-- 如果成功：该优惠券未被锁，继续执行抢购
-- 如果 ERROR 3572：立即知道该优惠券被其他请求占用
-- → 立即返回"手慢了"，而不是让用户等待

-- 场景3：批量处理中的非阻塞任务获取
BEGIN;
SELECT * FROM tasks WHERE id = 1001 FOR UPDATE NOWAIT;
-- 如果成功：处理该任务
-- 如果 ERROR 3572：跳过该任务，处理其他任务（可以配合重试逻辑）
ROLLBACK;  -- 任务已被处理，继续下一个
```

## NOWAIT 对 innodb_lock_wait_timeout 的关系

```
NOWAIT 与 innodb_lock_wait_timeout 是不同的机制：

innodb_lock_wait_timeout：
  有锁冲突时等待指定秒数，然后报 ERROR 1205
  在等待期间，请求方的连接处于阻塞状态（不能执行其他操作）

NOWAIT：
  有锁冲突时立即报 ERROR 3572（毫秒级，不等待）
  在报错后，应用层可以立即处理（重试、报错给用户等）

两者不互斥：
  设置了 innodb_lock_wait_timeout 的系统，
  对特定语句使用 NOWAIT，该语句立即报错（不受 timeout 影响）
  其他没有 NOWAIT 的语句仍然等待 timeout 时间
```

## 适用场景

- **用户交互的快速反馈**：在需要立即反馈结果的场景（如 Web 界面的"编辑"操作），NOWAIT 让应用层立即知道锁冲突，可以返回友好提示（如"该记录正在被编辑"），而不是让请求挂起等待超时
- **高并发抢占式操作**：在多个请求争抢有限资源的场景，NOWAIT 让失败的请求立即感知并快速重试或放弃，减少系统资源的无效等待消耗

## 常见问题

**NOWAIT 和 SKIP LOCKED 如何选择？**

两者都是"不等待"，但处理方式不同：NOWAIT 遇到锁冲突时立即报错（整个 SELECT 失败，不返回任何行），适合"必须锁定这一行，否则就是冲突"的场景（如单个资源的独占获取）；SKIP LOCKED 遇到锁冲突时跳过该行（返回其他未锁定的行），适合"任意获取一个未锁定的行"的场景（如任务队列的消费者）。选择标准：只针对特定行、失败就是失败→NOWAIT；从多行中取一行、有替代选择→SKIP LOCKED。

---

## 注意事项

- NOWAIT 只作用于加锁操作（`FOR UPDATE`/`FOR SHARE`），不影响普通的 DML（UPDATE/DELETE）。如果需要在 DML 操作中也实现"立即失败不等待"，可以将 `innodb_lock_wait_timeout` 设置为 1（秒），这是 DML 的等待超时机制（但无法精确到毫秒级）。
- NOWAIT 报错后，当前事务还在活跃状态（只有 SELECT 语句被回滚，事务本身未回滚）。应用层必须在捕获 ERROR 3572 后明确执行 ROLLBACK，不能假设事务已自动回滚。

## 总结

`NOWAIT` 是 MySQL 8.0 为 `FOR UPDATE`/`FOR SHARE` 添加的扩展选项，遇到锁冲突时立即报 ERROR 3572（不等待），实现"快速失败"语义。与默认行为（等待 `innodb_lock_wait_timeout` 秒后超时报 ERROR 1205）相比，NOWAIT 毫秒级失败、允许应用层立即响应，适合用户交互场景（立即反馈"数据被占用"）和高并发抢占场景（快速放弃竞争）。NOWAIT 和 SKIP LOCKED 不可同时使用，两者各有适用场景（单行独占失败→NOWAIT，多行任取一个→SKIP LOCKED）。报错后事务仍活跃，需显式 ROLLBACK。
