# 谓词锁 Predicate Lock（spatial 索引）

谓词锁（Predicate Lock）是 InnoDB 专门为空间数据类型（`GEOMETRY`/`POINT`/`POLYGON` 等）的空间索引（`SPATIAL INDEX`）而设计的锁类型。普通的间隙锁（Gap Lock）依赖索引键值的线性有序性来定义锁定范围，但空间数据是多维的（二维地理坐标），无法用一维的区间来表示。谓词锁用"最小外接矩形（MBR，Minimum Bounding Rectangle）"来描述锁定的空间范围，是空间索引并发控制的专用锁。

---

## 谓词锁的设计背景

```
普通间隙锁的局限性：
  Gap Lock 依赖线性有序的索引键（如 id=5 到 id=10 之间的间隙）
  空间数据（地理坐标、多边形等）没有全局线性顺序
  无法用"(a, b] 区间"来表示空间范围

谓词锁的解决方案：
  用最小外接矩形（MBR）描述锁定的空间范围
  MBR = 包含所有查询匹配几何对象的最小矩形边界
  谓词锁锁定"与 MBR 相交的空间范围内的所有对象"

谓词锁的工作原理：
  1. 空间查询（如 ST_Contains, ST_Within, MBRContains）执行 FOR UPDATE
  2. InnoDB 计算查询 WHERE 条件的 MBR
  3. 加谓词锁：锁住与该 MBR 相交的所有对象的空间范围
  4. 其他事务向锁定范围内插入新的空间对象 → 等待
```

## 谓词锁的语法与使用

```sql
-- 空间索引的建立
CREATE TABLE locations (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    coord POINT NOT NULL SRID 4326,  -- 地理坐标（经纬度）
    SPATIAL INDEX idx_coord(coord)   -- 空间索引
);

-- 插入示例数据
INSERT INTO locations VALUES
(1, 'Beijing', ST_GeomFromText('POINT(116.4 39.9)', 4326)),
(2, 'Shanghai', ST_GeomFromText('POINT(121.5 31.2)', 4326)),
(3, 'Guangzhou', ST_GeomFromText('POINT(113.3 23.1)', 4326));

-- 空间查询（会产生谓词锁）：
BEGIN;
SELECT * FROM locations
WHERE ST_Within(
    coord,
    ST_GeomFromText('POLYGON((100 20, 130 20, 130 45, 100 45, 100 20))', 4326)
) FOR UPDATE;
-- 查询多边形（华中华南区域）内的所有地点，并加排他谓词锁
-- 锁定该多边形区域的 MBR，阻止其他事务在此区域内插入新地点
```

## 谓词锁与普通锁的对比

| 特征 | 普通间隙锁（Gap Lock）| 谓词锁（Predicate Lock）|
|------|:------------------:|:---------------------:|
| 适用索引类型 | B-Tree 索引 | Spatial 空间索引 |
| 锁定范围描述 | 线性区间 (a, b] | 最小外接矩形 MBR |
| 防止的操作 | 在区间内插入新行 | 在 MBR 范围内插入新空间对象 |
| 数据维度 | 一维（有序键值）| 二维（地理空间）|
| 出现隔离级别 | RR | RR |

## 查看谓词锁

```sql
-- 谓词锁在 performance_schema.data_locks 中的表示：
SELECT
    OBJECT_NAME,
    INDEX_NAME,
    LOCK_TYPE,
    LOCK_MODE,   -- 'P_S'（共享谓词锁）或 'P_X'（排他谓词锁）
    LOCK_DATA
FROM performance_schema.data_locks
WHERE LOCK_MODE IN ('P_S', 'P_X');

-- 谓词锁的特殊标识：
-- LOCK_MODE = 'P_S'：空间索引的共享谓词锁（对应 LOCK IN SHARE MODE）
-- LOCK_MODE = 'P_X'：空间索引的排他谓词锁（对应 FOR UPDATE）
-- LOCK_DATA：包含 MBR 的编码描述（内部格式）
```

## 谓词锁的实际意义

```sql
-- 谓词锁防止"空间幻读"：

-- 事务A（RR 级别）：
BEGIN;
SELECT * FROM locations
WHERE ST_Within(coord, ST_GeomFromText('POLYGON(...)'))
FOR UPDATE;
-- 查询特定区域内的餐厅，加谓词锁

-- 事务B（同时）：
BEGIN;
INSERT INTO locations VALUES (10, 'NewRestaurant',
    ST_GeomFromText('POINT(115.0 32.0)', 4326));  -- 在锁定区域内的新餐厅
-- 等待！事务A的谓词锁阻止在该 MBR 内插入新地点

-- 事务A再次查询：不会看到新餐厅（幻读被防止）
COMMIT;
-- 事务B的插入才能继续
```

## 适用场景

- **地理信息系统（GIS）**：配送范围查询、地理围栏检测等场景中，使用 `SPATIAL INDEX` 和谓词锁保证区域内数据的一致性
- **位置服务**：查询特定区域内的服务提供者（如外卖骑手、出租车）时，使用谓词锁防止并发插入新位置导致的幻读

## 常见问题

**一般应用不使用空间数据，谓词锁需要了解吗？**

对于不使用 `GEOMETRY`、`POINT`、`SPATIAL INDEX` 等空间功能的应用，谓词锁在实际中不会出现。了解谓词锁的价值在于：当应用使用了空间索引并且出现锁等待或死锁时，能识别出 `P_S`/`P_X` 类型的谓词锁，知道这与空间查询相关，而不是普通的行锁或间隙锁问题。

---

## 注意事项

- 谓词锁基于 MBR（最小外接矩形），而不是精确的几何形状。MBR 通常比实际的几何形状（如多边形）更大，因此谓词锁的范围可能比 WHERE 条件实际覆盖的范围更大，可能锁住更多不必要的对象，降低并发性。
- 在 MySQL 8.0+ 中，空间数据列建议指定 SRID（空间参考系统 ID），如 `SRID 4326`（WGS84 经纬度坐标），这样可以使用精确的地理计算函数（`ST_Distance_Sphere` 等）。

---

## 总结

谓词锁（Predicate Lock）是 InnoDB 为空间索引（`SPATIAL INDEX`）设计的专用锁类型，使用最小外接矩形（MBR）描述锁定的空间范围，防止在该范围内并发插入新空间对象（空间幻读）。在 `performance_schema.data_locks` 中以 `LOCK_MODE=P_S`（共享）或 `P_X`（排他）标识。谓词锁只在使用空间索引的 RR 级别查询中出现，对不使用空间数据的普通应用无影响。
