# 间隙锁 Gap Lock（范围锁）

间隙锁（Gap Lock）是 InnoDB 在 REPEATABLE READ（RR）隔离级别下特有的一种锁类型，锁定两个索引记录之间的"间隙"（gap），阻止其他事务在这个间隙内插入新记录。间隙锁的目的是防止幻读——通过锁定范围，保证在当前事务内多次范围查询的结果集行数一致。

---

## 间隙的定义

```
间隙是索引键值之间的空间（不包含键值本身）：

假设表中的主键值为：1, 5, 10, 20（其他值不存在）

索引上的间隙（用区间表示）：
  (-∞, 1)   ← 1 之前的间隙（开区间）
  (1, 5)    ← 1 和 5 之间的间隙
  (5, 10)   ← 5 和 10 之间的间隙
  (10, 20)  ← 10 和 20 之间的间隙
  (20, +∞)  ← 20 之后的间隙（向上无界）

Gap Lock 锁住的是间隙，不锁住任何具体记录（不含端点）
Record Lock 锁住具体记录
Next-Key Lock = 间隙（左开）+ 记录（右闭），即 (a, b]
```

---

## Gap Lock 的触发条件

```sql
-- Gap Lock 只在 REPEATABLE READ（RR）级别产生
-- READ COMMITTED 级别不产生 Gap Lock（这是 RC 和 RR 并发性差异的关键）

SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;

-- 场景1：精确查找不存在的记录（在间隙中）
BEGIN;
SELECT * FROM products WHERE id = 7 FOR UPDATE;
-- id=7 不存在，但 id=5 和 id=10 存在
-- 加间隙锁：(5, 10) 间隙被锁定
-- 其他事务无法在 id ∈ (5, 10) 范围内插入记录

-- 场景2：范围查询（产生多个间隙锁）
BEGIN;
SELECT * FROM products WHERE id BETWEEN 3 AND 15 FOR UPDATE;
-- 锁定范围内所有行和间隙：
-- (1, 5) 间隙锁 + id=5 记录锁
-- (5, 10) 间隙锁 + id=10 记录锁
-- (10, 20) 间隙锁
-- 实际上是多个 Next-Key Lock 的组合

-- 场景3：DELETE 不存在的记录（RR 级别）
BEGIN;
DELETE FROM products WHERE id = 7;
-- 加 (5, 10) 间隙锁（id=7 不存在，锁住它应该在的间隙）
```

## Gap Lock 的兼容性特殊性

```sql
-- Gap Lock 之间相互兼容（不同于 Record Lock）！
-- 两个事务可以同时持有相同间隙的 Gap Lock

-- 会话1：
BEGIN;
SELECT * FROM products WHERE id = 7 FOR UPDATE;
-- 加 (5, 10) Gap Lock

-- 会话2：
BEGIN;
SELECT * FROM products WHERE id = 8 FOR UPDATE;
-- 也加 (5, 10) Gap Lock → 成功！（Gap Lock 之间兼容）

-- 但两个会话都阻止插入：
-- INSERT INTO products VALUES (7, 'product7', 100);
-- 等待！被会话1和会话2的 Gap Lock 阻塞

-- Gap Lock 与 Insert Intention Lock 不兼容：
-- 插入意向锁 vs. Gap Lock → 插入等待（Gap Lock 阻止插入）
```

---

## RC 级别没有 Gap Lock

```sql
-- READ COMMITTED 级别下不加 Gap Lock

SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
BEGIN;
SELECT * FROM products WHERE id = 7 FOR UPDATE;
-- id=7 不存在，RC 级别不加任何锁（无记录可锁，无间隙锁）

SELECT * FROM products WHERE id BETWEEN 3 AND 15 FOR UPDATE;
-- 只锁已存在的行（id=5, id=10）的 Record Lock（X, REC_NOT_GAP）
-- 不锁间隙，其他事务可以在 (1,5)、(5,10)、(10,20) 间隙中自由插入

-- RC 级别的并发性优势：没有 Gap Lock，INSERT 不被阻塞，并发插入更自由
-- RC 级别的劣势：无法防止范围查询的幻读
```

## Gap Lock 与死锁

```sql
-- Gap Lock 增加了死锁概率（两个事务都持有间隙锁，再尝试插入）

-- 会话1（RR 级别）：
BEGIN;
SELECT * FROM products WHERE id = 7 FOR UPDATE;
-- 加 (5, 10) Gap Lock

-- 会话2（RR 级别）：
BEGIN;
SELECT * FROM products WHERE id = 8 FOR UPDATE;
-- 也加 (5, 10) Gap Lock（兼容，成功）

-- 会话1 尝试插入：
INSERT INTO products VALUES (9, 'p9', 100);
-- 需要插入意向锁 @ (5,10) 间隙
-- 等待！会话2的 Gap Lock 阻止

-- 会话2 尝试插入：
INSERT INTO products VALUES (6, 'p6', 80);
-- 需要插入意向锁 @ (5,10) 间隙
-- 等待！会话1的 Gap Lock 阻止

-- 会话1等会话2释放Gap Lock，会话2等会话1释放Gap Lock → 死锁！
```

## 查看 Gap Lock

```sql
-- performance_schema 查看 Gap Lock
SELECT
    OBJECT_NAME,
    INDEX_NAME,
    LOCK_TYPE,
    LOCK_MODE,      -- 'X,GAP' 表示间隙锁（X类型）
    LOCK_DATA       -- 锁定的间隙右端点键值
FROM performance_schema.data_locks
WHERE LOCK_MODE LIKE '%GAP%';

-- LOCK_MODE 的 Gap Lock 标识：
-- 'X,GAP'：排他间隙锁
-- 'S,GAP'：共享间隙锁
-- 'X'（Next-Key Lock = Record + Gap）：LOCK_MODE='X' 时包含间隙
-- 'X,REC_NOT_GAP'：纯记录锁（无间隙）
```

## 适用场景

- **理解 RR 级别的并发瓶颈**：分析为什么 RR 级别的并发插入比 RC 慢，通常是间隙锁阻塞了插入操作
- **防止幻读**：在需要保证范围查询行数一致的场景（如唯一性检查），利用 RR + Gap Lock 防止并发插入新行

---

## 常见问题

**如何知道某个操作是否会产生 Gap Lock？**

核心规则：在 RR 级别下，如果查询条件在索引上的查找范围覆盖了"不存在记录的间隙"（无论是 WHERE id = 不存在的值，还是范围条件），InnoDB 就会加 Gap Lock 保护这些间隙。RC 级别不加 Gap Lock。可以通过 `performance_schema.data_locks` 在事务执行后查看 `LOCK_MODE` 中是否有 `GAP` 标识来确认。

---

## 注意事项

- 如果希望完全禁用间隙锁（降低死锁概率，提升并发性，代价是 RR 级别允许幻读），可以设置 `innodb_locks_unsafe_for_binlog=1`（MySQL 5.x，已废弃）或将隔离级别调整为 RC。MySQL 8.0 推荐通过调整隔离级别为 RC 来禁用间隙锁，而不是使用已废弃的参数。
- 在唯一索引（UNIQUE INDEX）上的精确查找（查找已存在的记录）不会产生间隙锁，只有 Record Lock——因为唯一索引保证不会有相同值的插入，不需要间隙锁来防幻读。

---

## 总结

Gap Lock（间隙锁）是 InnoDB RR 级别下锁定两条索引记录之间"间隙"的锁，阻止其他事务在间隙内插入新记录，防止幻读。Gap Lock 之间相互兼容（可共存），但与 Insert Intention Lock（插入意向锁）不兼容（阻止插入）。RC 级别不产生 Gap Lock（并发性更高但允许幻读）。Gap Lock 与 Insert Intention Lock 之间的循环等待是 RR 级别死锁的常见原因之一。可通过 `performance_schema.data_locks` 的 `LOCK_MODE` 中的 `GAP` 标识查看。
