# 记录锁 Record Lock（行锁）

记录锁（Record Lock）是 InnoDB 最基本的行级锁类型，锁定索引记录（不是行数据本身，而是索引中对应的键值记录）上的单个记录。记录锁是精确的点锁——只锁定特定索引值对应的那一行，不锁定行前后的间隙。在 InnoDB 的锁系统输出中，记录锁的模式标识为 `REC_NOT_GAP`（只锁记录，不锁间隙）。

---

## 记录锁的基本特征

```
Record Lock（记录锁）：
  锁定对象：索引中的单条记录
  锁定粒度：精确到单行（不含间隙）
  锁类型：可以是 S（共享记录锁）或 X（排他记录锁）
  存在条件：表必须有索引（若无索引，InnoDB 使用隐藏 DB_ROW_ID 作为聚簇索引）
  适用级别：RC 和 RR 级别都有记录锁
  标识方式：LOCK_MODE = 'S,REC_NOT_GAP' 或 'X,REC_NOT_GAP'

与 Next-Key Lock 的区别：
  Next-Key Lock = Record Lock（记录锁）+ Gap Lock（间隙锁）
  纯 Record Lock 只锁该行本身，不锁间隙
  RR 级别的 FOR UPDATE 通常产生 Next-Key Lock（含间隙）
  RC 级别的 FOR UPDATE 通常产生 Record Lock（不含间隙）
```

---

## 记录锁的触发场景

```sql
-- RC 级别：FOR UPDATE 产生 Record Lock（无间隙锁）
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
BEGIN;
SELECT * FROM accounts WHERE id = 1 FOR UPDATE;
-- LOCK_TYPE=RECORD, LOCK_MODE=X,REC_NOT_GAP（纯记录锁）

-- RR 级别精确主键查找：也可能产生 Record Lock（而非 Next-Key Lock）
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
BEGIN;
SELECT * FROM accounts WHERE id = 1 FOR UPDATE;
-- id=1 是主键精确查找，InnoDB 优化为 Record Lock（X,REC_NOT_GAP）
-- 精确查找最小化锁范围，不需要间隙锁

-- RR 级别范围查找：产生 Next-Key Lock（含间隙）
BEGIN;
SELECT * FROM accounts WHERE id BETWEEN 1 AND 5 FOR UPDATE;
-- 对 id=1,2,3,4,5 各行加 Next-Key Lock（含 id 之间的间隙）
-- LOCK_MODE = 'X'（即 Next-Key Lock，含间隙）
```

## 记录锁的存储结构

```
InnoDB 记录锁的物理存储（lock_t 结构）：

每个锁对象（lock_t）：
  - 事务指针（trx_t*）：属于哪个事务
  - 锁类型（LOCK_REC | LOCK_TABLE | 锁模式）
  - 所在表空间和页号（定位到哪个数据页）
  - 位图（bitmap）：该页上哪些记录被此锁锁住

位图设计的优势：
  一个 lock_t 对象可以表示同一页上多条记录的锁
  减少了内存中锁对象的数量
  例：UPDATE scores WHERE class_id = 5（修改同一页上的 30 行）
    → 只创建一个 lock_t 对象，位图中第 1-30 位设为 1
    → 不是创建 30 个锁对象
```

## 查看记录锁

```sql
-- MySQL 8.0：通过 performance_schema 查看
SELECT
    OBJECT_NAME,
    INDEX_NAME,
    LOCK_TYPE,
    LOCK_MODE,
    LOCK_DATA,   -- 锁定的索引值（如主键值）
    LOCK_STATUS  -- GRANTED（已获得）或 WAITING（等待）
FROM performance_schema.data_locks
WHERE LOCK_TYPE = 'RECORD';

-- 典型输出（UPDATE accounts WHERE id=1）：
-- OBJECT_NAME=accounts
-- INDEX_NAME=PRIMARY
-- LOCK_TYPE=RECORD
-- LOCK_MODE=X,REC_NOT_GAP
-- LOCK_DATA=1          ← 锁定的主键值
-- LOCK_STATUS=GRANTED

-- LOCK_DATA 的含义：
-- 主键列：显示主键值（如 1, 100, 'abc'）
-- 二级索引：显示（索引列值, 主键值）
-- supremum pseudo-record：表示"大于所有现有值"的虚拟上界记录
```

## 记录锁与二级索引

```sql
-- 对二级索引加记录锁时，同时也会锁住主键记录

-- 场景：通过二级索引查询并加锁
CREATE TABLE employees (
    id INT PRIMARY KEY,
    dept_id INT,
    name VARCHAR(100),
    INDEX idx_dept(dept_id)
);

BEGIN;
SELECT * FROM employees WHERE dept_id = 10 FOR UPDATE;
-- InnoDB 的加锁行为：
-- 1. 对 idx_dept 上 dept_id=10 的所有记录加 X 锁（二级索引记录锁）
-- 2. 对主键上对应的行加 X 锁（聚簇索引记录锁）
-- 原因：防止通过主键的其他操作绕过二级索引的锁

-- 通过 data_locks 可以看到两层锁：
-- INDEX_NAME=idx_dept, LOCK_MODE=X（二级索引锁）
-- INDEX_NAME=PRIMARY, LOCK_MODE=X,REC_NOT_GAP（主键锁）
```

## 适用场景

- **精确主键的 DML**：通过主键的精确 UPDATE/DELETE 产生 Record Lock（REC_NOT_GAP），锁定范围最小，并发性最高，是 OLTP 系统推荐的写操作方式
- **RC 级别的范围操作**：RC 级别不加间隙锁，所有匹配行只加 Record Lock，相比 RR 级别减少了间隙锁带来的阻塞

---

## 常见问题

**InnoDB 对没有索引的列的 WHERE 条件如何加锁？**

如果 WHERE 条件列没有索引，InnoDB 无法使用记录锁（记录锁锁的是索引记录）。InnoDB 会进行全表扫描，对主键索引（聚簇索引）上扫描的每一行都加锁（X lock 或 Next-Key Lock）。在 RC 级别，扫描过程中判断不满足 WHERE 条件的行会立即释放锁（semi-consistent read 优化）；在 RR 级别，扫描过的所有行都会持锁直到事务结束。这就是为什么无索引的 UPDATE/DELETE 并发性极差，应建立合适的索引。

---

## 注意事项

- 记录锁锁定的是索引记录，不是行数据本身。这意味着如果同一行数据可以通过多个不同的索引访问，锁定一个索引的记录不会自动锁定其他索引上的对应项——但 InnoDB 在 DML 时会同时锁住所有相关索引（聚簇索引 + 使用的二级索引），保证一致性。
- 在 `SHOW ENGINE INNODB STATUS` 的锁等待信息中，记录锁会显示锁定的索引名和行的主键值（或最小堆大小），这些信息是排查具体哪行被锁住的关键。

---

## 总结

Record Lock（记录锁）是 InnoDB 最基础的行级锁，精确锁定索引上的单条记录，不含前后间隙（标识为 `REC_NOT_GAP`）。RC 级别 FOR UPDATE 通常产生纯记录锁，RR 级别精确主键查找也产生记录锁（优化），RR 级别范围查找产生 Next-Key Lock（记录锁+间隙锁）。InnoDB 通过位图结构高效表示同一页上多行的记录锁。二级索引加锁时同时锁住对应的主键行。无索引列的 WHERE 条件导致全表扫描所有行的记录锁，并发性极差，应建立索引。
