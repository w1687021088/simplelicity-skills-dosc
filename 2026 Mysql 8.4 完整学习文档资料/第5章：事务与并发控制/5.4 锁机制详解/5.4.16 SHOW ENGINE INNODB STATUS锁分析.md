# SHOW ENGINE INNODB STATUS 锁分析

`SHOW ENGINE INNODB STATUS` 是 InnoDB 提供的一个诊断命令，输出 InnoDB 引擎当前状态的详细快照，包括事务状态、锁等待、死锁历史、缓冲池使用、I/O 统计等关键信息。在锁分析方面，它提供了死锁历史（最后一次死锁的完整信息）和当前活跃事务的锁信息，是排查锁相关问题的重要工具。

---

## 基本用法

```sql
-- 执行命令（需要 PROCESS 权限或 SUPER 权限）
SHOW ENGINE INNODB STATUS \G
-- \G 使输出垂直排列，更易读

-- 将输出保存到表（MySQL 8.0+ 可以通过 Performance Schema 查看部分信息）
-- 或将结果保存到文件（通过 MySQL Shell 或重定向）

-- 输出的主要章节：
-- BACKGROUND THREAD：后台线程状态
-- SEMAPHORES：信号量等待
-- LATEST DETECTED DEADLOCK：最后检测到的死锁（如果有）
-- TRANSACTIONS：当前活跃事务列表
-- FILE I/O：文件 I/O 状态
-- INSERT BUFFER AND ADAPTIVE HASH INDEX：Insert Buffer 和 AHI
-- LOG：Redo Log 状态
-- BUFFER POOL AND MEMORY：Buffer Pool 内存使用
-- ROW OPERATIONS：行操作统计
```

## TRANSACTIONS 部分解读

```
TRANSACTIONS 输出示例：

---TRANSACTION 421934873650448, not started
0 lock struct(s), heap size 1136, 0 row lock(s)

---TRANSACTION 100, ACTIVE 25 sec
2 lock struct(s), heap size 1136, 2 row lock(s)
MySQL thread id 15, OS thread handle 140321649616640, query id 1234 localhost root
UPDATE accounts SET balance = 900 WHERE id = 1

---TRANSACTION 101, ACTIVE 5 sec starting index read
LOCK WAIT 2 lock struct(s), heap size 1136, 1 row lock(s)
MySQL thread id 16, OS thread handle 140321649616641, query id 1235 localhost app
SELECT * FROM accounts WHERE id = 1 FOR UPDATE

字段解读：
  TRANSACTION <ID>：事务 ID
  ACTIVE <N> sec：事务已活跃的秒数（越大说明事务越长）
  N lock struct(s)：持有的锁结构数量
  N row lock(s)：持有的行锁数量
  LOCK WAIT：事务正在等待锁
  query id <N>：当前执行的查询 ID
  后面跟着当前正在执行的 SQL（如果有）
```

## 锁信息的详细解读

```
锁信息格式：
RECORD LOCKS space id 123 page no 4 n bits 72 index PRIMARY of table `db`.`t`
trx id 200 lock_mode X locks rec but not gap

关键字段：
  space id 123：表空间 ID（标识哪个表空间）
  page no 4：数据页号（标识哪个数据页）
  n bits 72：位图大小（该页最多能表示 72 条行锁）
  index PRIMARY：锁在哪个索引上（PRIMARY = 聚簇索引）
  lock_mode X：锁类型（X=排他，S=共享）
  locks rec but not gap：只锁记录不锁间隙（=REC_NOT_GAP）
  locks gap before rec：只锁间隙（Gap Lock）
  locks rec and gap：锁记录和间隙（Next-Key Lock）
  waiting：等待状态

  Physical Record 后的十六进制数据：
  是索引键值的十六进制编码，如 80000001 = 整数 1（big-endian）
```

## 配合 innodb_status_output 输出更多锁信息

```sql
-- 默认情况下，SHOW ENGINE INNODB STATUS 只显示活跃事务中有锁等待的部分
-- 开启扩展输出以显示所有事务的锁信息：
SET GLOBAL innodb_status_output = ON;
SET GLOBAL innodb_status_output_locks = ON;
-- 这两个参数会让 InnoDB 在后台周期性将状态写入 error log
-- 也会让 SHOW ENGINE INNODB STATUS 显示更详细的锁信息

-- 显示所有活跃事务的完整锁信息（包括未发生等待的事务）
-- 注意：这会显著增加输出量，在锁数量多时输出可能很长

-- 查询完成后关闭，避免持续写入 error log：
SET GLOBAL innodb_status_output = OFF;
SET GLOBAL innodb_status_output_locks = OFF;
```

## 实用排查流程

```sql
-- 步骤1：发现系统响应变慢，怀疑有锁问题
-- 先查看当前锁等待情况（比 SHOW ENGINE INNODB STATUS 更直观）
SELECT * FROM sys.innodb_lock_waits;

-- 步骤2：如果有死锁记录，查看最后一次死锁
SHOW ENGINE INNODB STATUS \G
-- 找到 LATEST DETECTED DEADLOCK 部分，分析死锁的两个事务
-- 识别：哪两个 SQL 在相互等待？加锁顺序是什么？

-- 步骤3：如果是锁等待（非死锁），查看 TRANSACTIONS 部分
-- 找到 ACTIVE 时间最长的事务（它可能在阻塞其他事务）
-- 对应 thread id 可以通过 KILL 命令终止

-- 步骤4：开启死锁日志，收集更多信息
SET GLOBAL innodb_print_all_deadlocks = ON;
-- 之后的所有死锁都会写入 error log，便于长时间监控
```

## 适用场景

- **死锁排查**：发现系统出现 ERROR 1213 后，立即执行 `SHOW ENGINE INNODB STATUS` 查看 `LATEST DETECTED DEADLOCK` 部分，分析死锁的 SQL 和加锁顺序，找到死锁的根本原因
- **锁等待分析**：系统响应时间突然增大，通过 `TRANSACTIONS` 部分找到长时间活跃的事务（ACTIVE 时间长），确认是否有事务在长时间持有锁

## 常见问题

**SHOW ENGINE INNODB STATUS 输出中的锁信息只显示部分内容，如何获取完整信息？**

默认情况下，TRANSACTIONS 部分只显示等待状态的事务的锁信息（为了减少输出量）。要显示所有活跃事务的完整锁信息，需要开启 `innodb_status_output_locks=ON`。另外，MySQL 8.0 提供的 `performance_schema.data_locks` 和 `data_lock_waits` 视图可以实时查询所有当前锁信息（不依赖 STATUS 命令），是更现代的锁分析方式。

---

## 注意事项

- `SHOW ENGINE INNODB STATUS` 的 LATEST DETECTED DEADLOCK 部分只保留最后一次死锁信息，新的死锁会覆盖旧的。在频繁死锁的系统中，依赖此命令可能错过部分死锁信息——应开启 `innodb_print_all_deadlocks=ON` 将所有死锁写入 error log。
- STATUS 输出中的 History list length 是监控 Purge 积压的重要指标：正常 < 1000，超过 10000 需要关注，超过 100000 说明有严重的长事务阻塞 Purge。

---

## 总结

`SHOW ENGINE INNODB STATUS \G` 是 InnoDB 综合状态诊断命令，锁分析主要关注两个部分：TRANSACTIONS（当前活跃事务的锁信息和锁等待情况）和 LATEST DETECTED DEADLOCK（最后一次死锁的完整细节，包括每个事务持有的锁、等待的锁、被选为 victim 的事务）。通过 `lock_mode` 字段识别锁类型（X/S、rec but not gap/gap before rec/rec and gap）。开启 `innodb_status_output_locks=ON` 获取所有事务的完整锁信息。MySQL 8.0 的 `performance_schema.data_locks` 提供了更现代的实时锁查询方式。
