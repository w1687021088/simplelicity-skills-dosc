# 隐藏列 DB_ROW_ID 行 ID

`DB_ROW_ID` 是 InnoDB 在特定条件下为行记录自动生成的 6 字节隐藏列，作为聚簇索引的键。它不是 MVCC 机制的直接组成部分（不参与版本可见性判断），而是 InnoDB 在表没有显式主键时用于构建聚簇索引的内部标识符。了解 DB_ROW_ID 的存在条件和作用，有助于理解 InnoDB 的存储结构。

---

## DB_ROW_ID 的存在条件

```
InnoDB 为每个表添加隐藏列的规则：

条件1：表有显式主键（PRIMARY KEY）
  → 不添加 DB_ROW_ID
  → 聚簇索引使用主键

条件2：表没有主键，但有非 NULL 的 UNIQUE 索引
  → 不添加 DB_ROW_ID
  → 聚簇索引使用该 UNIQUE 索引

条件3：表既没有主键，也没有合适的 UNIQUE 索引
  → 自动添加 DB_ROW_ID（6字节，隐藏）
  → 聚簇索引使用 DB_ROW_ID

-- 示例：
-- 以下表会添加 DB_ROW_ID：
CREATE TABLE t1 (col1 VARCHAR(100));  -- 无主键，无 UNIQUE 索引
CREATE TABLE t2 (col1 INT, col2 INT, UNIQUE(col2));  -- UNIQUE 索引允许 NULL

-- 以下表不会添加 DB_ROW_ID：
CREATE TABLE t3 (id INT PRIMARY KEY, col1 VARCHAR(100));  -- 有主键
CREATE TABLE t4 (col1 INT NOT NULL UNIQUE, col2 VARCHAR(100));  -- NOT NULL + UNIQUE
```

---

## DB_ROW_ID 的物理特征

```
DB_ROW_ID 的属性：
- 大小：6 字节（48 位）
- 值范围：0 ~ 2^48 - 1（约 281 万亿，几乎不会耗尽）
- 分配方式：全局递增计数器（所有使用 DB_ROW_ID 的表共享同一个计数器！）
- 持久化：计数器持久化在 ibdata1（系统表空间）中
- 生成时机：INSERT 时自动分配

-- 全局共享计数器的含义：
-- 如果数据库中有多张表都没有主键（都使用 DB_ROW_ID），
-- 这些表的 DB_ROW_ID 值来自同一个全局计数器，
-- 不同表之间的 DB_ROW_ID 值可能交替出现
-- （表1的第1行 row_id=1，表2的第1行 row_id=2，表1的第2行 row_id=3，以此类推）
```

## 查看 DB_ROW_ID

```sql
-- DB_ROW_ID 不能直接通过列名查询（不是用户可见的列）
-- 可以通过以下方式间接观察：

-- 1. 查看表结构（是否有主键）
SHOW CREATE TABLE t1;
-- 如果 KEY 中有 PRIMARY KEY，则没有 DB_ROW_ID
-- 如果没有 PRIMARY KEY 且无合适 UNIQUE 索引，则有 DB_ROW_ID

-- 2. 通过 INFORMATION_SCHEMA 观察（无法直接查看 DB_ROW_ID 值）
SELECT TABLE_NAME, CREATE_OPTIONS
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_SCHEMA = 'db_name';

-- 3. 在 SQL 中引用（MySQL 允许用 _rowid 查询聚簇索引键）
SELECT _rowid, * FROM t1;
-- 如果 t1 有 PRIMARY KEY：_rowid 返回主键列的值
-- 如果 t1 没有主键但有 UNIQUE 索引：_rowid 返回 UNIQUE 索引列的值
-- 如果 t1 有 DB_ROW_ID：_rowid 返回 DB_ROW_ID 的值（隐藏列可见！）

-- 示例：
CREATE TABLE no_pk (name VARCHAR(50));
INSERT INTO no_pk VALUES ('Alice'), ('Bob'), ('Charlie');
SELECT _rowid, name FROM no_pk;
-- 可以看到 _rowid 的值（DB_ROW_ID）
```

## DB_ROW_ID 与聚簇索引

```sql
-- InnoDB 的聚簇索引键（决定行在磁盘上的物理存储顺序）

-- 有 PRIMARY KEY 的表：
CREATE TABLE with_pk (id INT PRIMARY KEY, name VARCHAR(50));
-- 聚簇索引键 = id（主键）
-- 行按 id 的顺序存储

-- 有 NOT NULL UNIQUE INDEX 的表：
CREATE TABLE with_uk (name VARCHAR(50) NOT NULL UNIQUE, age INT);
-- 聚簇索引键 = name（UNIQUE 索引）
-- 行按 name 的字母顺序存储

-- 无合适键的表（使用 DB_ROW_ID）：
CREATE TABLE no_key (name VARCHAR(50), age INT);
-- 聚簇索引键 = DB_ROW_ID（隐藏，自动分配的全局递增值）
-- 行按插入顺序存储（因为 DB_ROW_ID 全局递增）
```

## DB_ROW_ID 与 MVCC 的关系

```
DB_ROW_ID 不直接参与 MVCC 的可见性判断，
MVCC 的版本可见性主要依赖 DB_TRX_ID 和 DB_ROLL_PTR。

DB_ROW_ID 的作用是：
  在没有用户定义主键的情况下，为 InnoDB 提供行的唯一标识符
  使 InnoDB 可以构建聚簇索引（所有 InnoDB 表必须有聚簇索引）
  也用于行锁定（通过行的唯一标识加锁）

DB_TRX_ID 和 DB_ROLL_PTR 才是 MVCC 版本控制的核心隐藏列。
```

## 适用场景

- **了解存储结构**：在分析 InnoDB 表的磁盘存储时，理解 DB_ROW_ID 的存在条件，有助于解释为什么没有主键的表的行是按插入顺序物理存储的
- **性能优化依据**：DB_ROW_ID 的全局共享计数器可能在高并发多表无主键场景下形成轻微的竞争点，这是建议所有表都设置主键的原因之一

---

## 常见问题

**如果一个 UNIQUE 列允许 NULL，InnoDB 会用它做聚簇索引吗？**

不会。UNIQUE 索引列如果允许 NULL（没有 NOT NULL 约束），InnoDB 不会选择它作为聚簇索引键（因为 NULL 不是唯一的，多行可以都是 NULL）。在这种情况下，InnoDB 会继续查找其他 NOT NULL 的 UNIQUE 索引，如果都没有，则自动添加 DB_ROW_ID 隐藏列作为聚簇索引键。

---

## 注意事项

- 在生产环境中，强烈建议每张 InnoDB 表都定义显式主键（推荐 `AUTO_INCREMENT INT/BIGINT`）。使用 DB_ROW_ID 作为聚簇索引虽然功能上可以工作，但存在以下问题：DB_ROW_ID 全局共享，高并发多表时可能有竞争；DB_ROW_ID 不对外暴露（应用无法引用），不便于业务操作；没有主键的表在主从复制中（尤其 ROW 格式）可能有性能问题。
- 在 MySQL 8.0 中，对于没有主键的 InnoDB 表，`SHOW CREATE TABLE` 不会显示 DB_ROW_ID，但通过 `SELECT _rowid FROM table_name` 可以访问其值。

---

## 总结

`DB_ROW_ID` 是 InnoDB 在表没有主键且没有合适的 NOT NULL UNIQUE 索引时自动添加的 6 字节隐藏列，用作聚簇索引键。其值来自全局递增计数器（所有无主键表共享）。`DB_ROW_ID` 不参与 MVCC 的版本可见性判断（那是 `DB_TRX_ID` 的职责），其作用是为没有用户定义主键的表提供聚簇索引。可以通过 `SELECT _rowid FROM table_name` 访问其值。生产环境建议每张表都定义显式主键，避免依赖 `DB_ROW_ID`。
