# SAVEPOINT 保存点

SAVEPOINT（保存点）是在事务执行过程中设置的中间标记点，允许事务回滚到该标记点的状态，而不必回滚整个事务。通过 SAVEPOINT，可以实现事务内的"部分回滚"，在保留已完成部分工作的同时，撤销最近的一部分操作。SAVEPOINT 的实现依赖于 Undo Log：每次操作都有对应的 Undo Log 记录，`ROLLBACK TO SAVEPOINT` 只执行该保存点之后的 Undo Log 逆操作。

---

## 基本语法

```sql
-- 设置保存点
SAVEPOINT savepoint_name;

-- 回滚到保存点（撤销该保存点之后的所有操作）
ROLLBACK TO SAVEPOINT savepoint_name;
ROLLBACK TO savepoint_name;  -- 可以省略 SAVEPOINT 关键字

-- 删除保存点（不执行任何回滚）
RELEASE SAVEPOINT savepoint_name;

-- 完整事务示例
BEGIN;
-- 操作1
INSERT INTO orders VALUES (1, 100.00, 'pending');
SAVEPOINT after_order;          -- 保存点1

-- 操作2
INSERT INTO order_items VALUES (1, 1001, 2, 50.00);
INSERT INTO order_items VALUES (1, 1002, 1, 0.00);  -- 金额错误
SAVEPOINT after_items;          -- 保存点2

-- 发现操作2有问题，回滚到 after_order 点（撤销操作2）
ROLLBACK TO after_order;
-- 此时：orders(id=1) 还在，order_items 的插入全部撤销

-- 重新执行正确的操作2
INSERT INTO order_items VALUES (1, 1001, 2, 50.00);
INSERT INTO order_items VALUES (1, 1002, 1, 50.00);  -- 金额已修正
COMMIT;
```

## 保存点的嵌套与同名处理

```sql
-- 同名保存点的处理：
-- 设置同名保存点时，新保存点覆盖旧保存点
BEGIN;
INSERT INTO t VALUES (1);
SAVEPOINT sp;          -- 保存点1：id=1 已插入

INSERT INTO t VALUES (2);
SAVEPOINT sp;          -- 保存点2（同名！）：覆盖保存点1，此时 id=1 和 id=2 均插入

INSERT INTO t VALUES (3);
ROLLBACK TO sp;        -- 回滚到"最新的 sp"（即保存点2）
-- 结果：id=1 和 id=2 的插入被保留，id=3 的插入被撤销

COMMIT;
-- 最终提交：id=1 和 id=2 存在

-- 保存点是事务范围内的命名空间，不同事务的同名保存点互不影响
-- 保存点名称区分大小写（与表名规则一致）
```

## 存储过程中的保存点

```sql
-- SAVEPOINT 在存储过程和触发器中非常有用
-- 可以实现"条件性回滚"：如果某步失败，只回滚该步，不影响整个事务

DELIMITER //
CREATE PROCEDURE process_order(IN p_order_id INT)
BEGIN
    DECLARE v_error INT DEFAULT 0;
    DECLARE CONTINUE HANDLER FOR SQLEXCEPTION SET v_error = 1;
    
    START TRANSACTION;
    
    -- 步骤1：更新订单状态
    SAVEPOINT step1;
    UPDATE orders SET status = 'processing' WHERE id = p_order_id;
    IF v_error = 1 THEN
        ROLLBACK TO step1;
        SET v_error = 0;
    END IF;
    
    -- 步骤2：扣减库存
    SAVEPOINT step2;
    UPDATE inventory SET stock = stock - 1
    WHERE product_id = (SELECT product_id FROM orders WHERE id = p_order_id);
    IF v_error = 1 THEN
        ROLLBACK TO step2;
        SET v_error = 0;
        -- 可以在这里做其他补偿逻辑
    END IF;
    
    COMMIT;
END //
DELIMITER ;
```

## RELEASE SAVEPOINT 的使用

```sql
-- RELEASE SAVEPOINT 删除保存点（不回滚）
-- 通常在不再需要保存点时用于清理，避免保存点积累

BEGIN;
INSERT INTO t VALUES (1);
SAVEPOINT sp1;

INSERT INTO t VALUES (2);
SAVEPOINT sp2;

-- 操作2已完成且确认正确，不再需要回滚到 sp2 的能力
RELEASE SAVEPOINT sp2;  -- 删除 sp2 保存点（不影响 id=2 的数据）

INSERT INTO t VALUES (3);
-- 如果出错：
ROLLBACK TO sp1;    -- 只能回到 sp1（sp2 已被释放）
-- id=1 保留，id=2 和 id=3 回滚

COMMIT;
```

## 适用场景

- **复杂业务流程**：多步骤业务操作（如电商下单流程：创建订单→扣减库存→生成物流单），每步完成后设置保存点，某步失败只回滚该步，可以重试该步骤而不影响之前的步骤
- **存储过程错误处理**：在存储过程中使用 SAVEPOINT 实现精细化的错误恢复，而非遇错就回滚整个事务

---

## 常见问题

**ROLLBACK TO SAVEPOINT 之后，原保存点还存在吗？**

存在。`ROLLBACK TO SAVEPOINT sp1` 只是将数据状态回滚到 sp1 点，但 sp1 保存点本身仍然存在（没有被删除）。可以继续使用同一个保存点再次 `ROLLBACK TO sp1`（如果再次失败）或 `RELEASE SAVEPOINT sp1`（不再需要时删除）。如果想删除保存点，需要显式调用 `RELEASE SAVEPOINT sp1`。

---

## 注意事项

- `ROLLBACK TO SAVEPOINT` 不会释放该保存点之后加的行锁（MySQL InnoDB 中，行锁在整个事务内持有，不随部分回滚释放）。这与某些数据库（如 PostgreSQL）不同，在 PostgreSQL 中 `ROLLBACK TO SAVEPOINT` 会释放该点之后加的锁。在 MySQL 中，即使通过保存点回滚了操作，被锁定的行仍然被锁定，直到整个事务提交或回滚。
- 过多的 SAVEPOINT 会增加内存开销（每个保存点需要记录当前 Undo Log 位置），在非常长的事务中应合理控制保存点数量，不用的保存点及时 `RELEASE`。

---

## 总结

SAVEPOINT 在事务中设置中间标记点，支持部分回滚（`ROLLBACK TO SAVEPOINT`）而不影响保存点之前的操作。同名保存点后者覆盖前者。`RELEASE SAVEPOINT` 删除保存点但不回滚数据。`ROLLBACK TO SAVEPOINT` 执行该点之后的 Undo Log 逆操作，但不释放该点之后加的行锁（InnoDB 行锁整事务持有）。SAVEPOINT 在多步骤业务流程和存储过程错误处理中最为实用，可实现精细化的事务控制。
