# ROLLBACK TO SAVEPOINT 回滚到保存点

`ROLLBACK TO SAVEPOINT` 语句将当前事务的数据状态回退到指定保存点的位置，撤销该保存点之后的所有 DML 操作，但保留该保存点及之前的所有操作。执行时，InnoDB 按照 Undo Log 的逆序执行逆操作，直到回退到保存点时的 Undo Log 位置为止，实现事务内的"部分回滚"。

---

## 基本语法

```sql
-- 完整语法
ROLLBACK TO SAVEPOINT savepoint_name;

-- 简写语法（可以省略 SAVEPOINT 关键字）
ROLLBACK TO savepoint_name;

-- 示例：
BEGIN;
INSERT INTO orders VALUES (1, 100.00, 'pending');
SAVEPOINT sp1;                    -- 保存点1：id=1 已插入

INSERT INTO orders VALUES (2, 200.00, 'pending');
INSERT INTO orders VALUES (3, 300.00, 'pending');
SAVEPOINT sp2;                    -- 保存点2：id=1,2,3 均已插入

INSERT INTO orders VALUES (4, -50.00, 'error');  -- 金额为负，业务校验失败

-- 只回滚到 sp2（撤销 id=4 的插入）
ROLLBACK TO SAVEPOINT sp2;
-- 此时：id=1,2,3 的记录存在，id=4 的插入被撤销

-- 继续正确操作
INSERT INTO orders VALUES (4, 400.00, 'pending');
COMMIT;
-- 最终提交：id=1,2,3,4 均存在
```

## 回滚范围的精确控制

```sql
-- ROLLBACK TO SAVEPOINT 回滚的范围：
-- 撤销该保存点之后（不含）的所有操作
-- 保存点本身被保留（可以再次 ROLLBACK TO 同一个保存点）

BEGIN;
UPDATE accounts SET balance = 900 WHERE id = 1;  -- 原值 1000
SAVEPOINT before_transfer;

UPDATE accounts SET balance = 1100 WHERE id = 2;  -- 加钱
UPDATE accounts SET balance = 800 WHERE id = 1;   -- 再扣钱

-- 发现操作有误，回到 before_transfer 状态
ROLLBACK TO before_transfer;
-- 此时：id=1 的 balance = 900（before_transfer 时的状态）
-- id=2 的修改（1100）被撤销，恢复原值

-- before_transfer 保存点仍然存在，可以继续使用：
UPDATE accounts SET balance = 800 WHERE id = 1;  -- 正确的扣减
UPDATE accounts SET balance = 1200 WHERE id = 2; -- 正确的加款
COMMIT;
```

## 多级保存点的回滚顺序

```sql
-- 多级保存点场景：
BEGIN;
INSERT INTO t VALUES (1);
SAVEPOINT sp1;   -- 1 存在

INSERT INTO t VALUES (2);
SAVEPOINT sp2;   -- 1,2 存在

INSERT INTO t VALUES (3);
SAVEPOINT sp3;   -- 1,2,3 存在

INSERT INTO t VALUES (4);
-- 现在回滚到 sp2（跳过 sp3，直接回到 sp2）
ROLLBACK TO sp2;
-- 撤销 sp2 之后的所有操作（包括 id=3 和 id=4 的插入）
-- 此时：id=1 和 id=2 存在，sp3 保存点已不可用（不在 sp2 之后）
-- 注意：跨越 sp3 直接回到 sp2，sp3 自动失效

-- 再回滚到 sp1（sp2 之前的点，此时可以吗？）
ROLLBACK TO sp1;  -- 可以！sp1 仍然有效（sp1 在 sp2 之前设置）
-- 撤销 sp1 之后的所有操作：id=2 的插入也被撤销
-- 此时：只有 id=1 存在

COMMIT;
-- 最终只有 id=1
```

## ROLLBACK TO SAVEPOINT 与行锁

```sql
-- 重要：ROLLBACK TO SAVEPOINT 不释放该点之后加的行锁

BEGIN;
SELECT * FROM orders WHERE id IN (1,2) FOR UPDATE;  -- 加 X 锁 on id=1 and id=2
SAVEPOINT sp;

UPDATE orders SET status = 'done' WHERE id = 1;    -- 修改 id=1
ROLLBACK TO sp;  -- 撤销 id=1 的 UPDATE
-- 此时：id=1 的 status 恢复，但 id=1 和 id=2 的 X 锁仍然持有！

-- 其他事务尝试修改 id=1 仍然会被阻塞
-- 直到本事务 COMMIT 或 ROLLBACK 才释放锁
COMMIT;
```

## 适用场景

- **多步骤处理中的单步重试**：一个流程分多步执行，每步前设保存点，某步失败时回滚到该步之前的保存点，重试该步，而非回滚整个流程
- **存储过程异常隔离**：在存储过程中捕获异常后 `ROLLBACK TO SAVEPOINT`，只撤销出错的那部分操作

---

## 常见问题

**回滚到保存点后，保存点本身还有效吗？**

有效。`ROLLBACK TO SAVEPOINT sp1` 只是将数据状态回退到 sp1 点，但 sp1 保存点本身仍然存在，可以再次使用 `ROLLBACK TO SAVEPOINT sp1`（如果再次出现问题）或 `RELEASE SAVEPOINT sp1`（不再需要时删除）。位于 sp1 之后的保存点（如 sp2、sp3）在回滚到 sp1 后会自动失效（因为它们对应的 Undo Log 位置已经被回滚过了）。

---

## 注意事项

- `ROLLBACK TO SAVEPOINT` 执行后，跳过的保存点（位于目标保存点之后的保存点）全部失效，不能再 `ROLLBACK TO` 这些保存点。只有目标保存点之前（包括目标保存点本身）的保存点仍然有效。
- 从性能角度，`ROLLBACK TO SAVEPOINT` 的代价与保存点之后执行的操作量成正比（需要逆序执行那部分操作的 Undo Log），与整个事务的大小无关。

---

## 总结

`ROLLBACK TO SAVEPOINT savepoint_name` 将数据状态回退到指定保存点，撤销该点之后的所有 DML 修改（通过逆序执行 Undo Log 实现）。回滚不释放该点之后加的行锁（行锁整事务持有）。回滚后，目标保存点本身仍然有效，但其之后的保存点全部失效。`ROLLBACK TO` 可以简写（省略 SAVEPOINT 关键字）。多级保存点时，可以直接跳回任意之前的保存点，中间的保存点自动失效。
