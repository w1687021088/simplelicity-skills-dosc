# START TRANSACTION 开启事务

`START TRANSACTION` 是 MySQL 中显式开启事务的标准 SQL 语句，属于事务控制语言（TCL）。执行 `START TRANSACTION` 后，之后的 DML 语句（INSERT/UPDATE/DELETE/SELECT）都属于这个事务，直到显式 `COMMIT`（提交）或 `ROLLBACK`（回滚）为止。`START TRANSACTION` 还支持若干修饰符（如 `WITH CONSISTENT SNAPSHOT`、`READ ONLY`、`READ WRITE`），用于控制事务的行为。

---

## 基本语法

```sql
-- 标准语法
START TRANSACTION;
START TRANSACTION WITH CONSISTENT SNAPSHOT;  -- 立即创建快照
START TRANSACTION READ ONLY;                 -- 只读事务
START TRANSACTION READ WRITE;               -- 读写事务（默认）

-- 组合用法（MySQL 8.0 支持多个修饰符组合）
START TRANSACTION READ ONLY, WITH CONSISTENT SNAPSHOT;
```

---

## WITH CONSISTENT SNAPSHOT

```sql
-- 普通 START TRANSACTION（不带此修饰符）：
-- Read View 在第一次 SELECT 时才创建
-- 事务开始后、第一次 SELECT 前，其他事务的提交对当前事务可见

-- START TRANSACTION WITH CONSISTENT SNAPSHOT：
-- 立即在事务开始时创建 Read View（一致性快照）
-- 此后无论其他事务如何提交，当前事务的快照不变

-- 演示差异：
-- 会话1：
BEGIN;  -- 普通开始，尚未创建 Read View

-- 会话2：（此时插入一行）
INSERT INTO orders VALUES (100, 'new', 500.00);
COMMIT;

-- 会话1（继续）：
SELECT * FROM orders WHERE id = 100;
-- → 能看到！因为 Read View 是在这次 SELECT 时创建的，
--   此时会话2已提交，id=100 对当前事务可见。

-- ————————————————————————————————
-- 会话3：
START TRANSACTION WITH CONSISTENT SNAPSHOT;  -- 立即创建快照

-- 会话2：（同样插入 id=101）
INSERT INTO orders VALUES (101, 'new', 600.00);
COMMIT;

-- 会话3（继续）：
SELECT * FROM orders WHERE id = 101;
-- → 看不到！快照在 START TRANSACTION 时已固定，
--   id=101 是快照后插入的，对当前事务不可见。
```

## READ ONLY 只读事务

```sql
-- 只读事务：不允许执行 DML（INSERT/UPDATE/DELETE）
-- 好处：MySQL 优化器对只读事务有特殊优化
--   → 不分配真正的事务 ID（减少全局计数器争用）
--   → 不需要分配 Undo 段（省内存）

START TRANSACTION READ ONLY;
SELECT * FROM orders WHERE user_id = 123;
SELECT SUM(amount) FROM orders WHERE status = 'done';
-- UPDATE orders SET ... -- ERROR 1792: Cannot execute statement in a READ ONLY transaction.
COMMIT;

-- 适用场景：报表查询、数据导出等纯读取场景
-- MySQL 8.0 对 READ ONLY 事务的内部优化会自动提升性能
```

---

## READ WRITE 读写事务（默认）

```sql
-- START TRANSACTION READ WRITE 是默认行为（不指定修饰符时等效）
-- 允许执行所有 DML 和 SELECT 语句

START TRANSACTION READ WRITE;  -- 等价于 START TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
INSERT INTO audit_log VALUES (DEFAULT, 'debit', 100, NOW());
COMMIT;

-- 与 innodb_read_only 系统变量的区别：
-- innodb_read_only = ON：实例级别只读（通常用于只读副本）
-- START TRANSACTION READ ONLY：单个事务级别只读（会话级控制）
```

## START TRANSACTION 与 autocommit 的交互

```sql
-- autocommit = ON（默认）：
-- 每条单独的 SQL 自动提交（相当于每条 SQL 是一个独立事务）
-- 执行 START TRANSACTION 后，进入手动事务模式，直到 COMMIT/ROLLBACK

SHOW VARIABLES LIKE 'autocommit';  -- ON

-- 示例（autocommit=ON 情况下）：
-- 单条 SQL 自动提交：
INSERT INTO t VALUES (1);  -- 立即自动提交（相当于单独一个事务）

-- 使用 START TRANSACTION 开始手动事务：
START TRANSACTION;
INSERT INTO t VALUES (2);  -- 不自动提交
INSERT INTO t VALUES (3);  -- 不自动提交
COMMIT;  -- 显式提交，id=2 和 id=3 一起提交

-- autocommit = OFF 时：
SET SESSION autocommit = OFF;
-- 之后每条 DML 都需要显式 COMMIT 才持久化
-- 相当于每次操作都是隐式开启事务（不需要 START TRANSACTION）
```

## 适用场景

- **多步业务操作**：转账、下单等需要多个 DML 原子性的场景，用 `START TRANSACTION` 开启，最后 `COMMIT` 或 `ROLLBACK`
- **一致性报表读取**：`START TRANSACTION WITH CONSISTENT SNAPSHOT` 确保长时间运行的报表查询看到一个固定时间点的数据，不受查询期间其他事务修改的影响

---

## 常见问题

**START TRANSACTION 和 SET autocommit = 0 有什么区别？**

`SET autocommit = 0` 关闭当前会话的自动提交，之后所有 SQL 都在隐式事务中，必须显式 COMMIT 才提交，且不需要每次写 START TRANSACTION。`START TRANSACTION` 是在 autocommit 模式下显式开启一个事务，不改变 autocommit 设置本身，COMMIT/ROLLBACK 后自动提交模式恢复。两种方式都能实现手动事务控制，`START TRANSACTION` 更加明确（每次事务都清晰可见），推荐使用。

---

## 注意事项

- `START TRANSACTION` 会隐式提交当前任何活跃的事务（如果有的话）。如果当前已经在一个事务中，执行 `START TRANSACTION` 会先提交前一个事务，再开始新事务。这一行为在 MySQL 中被称为"隐式提交"（implicit commit）。
- 某些 DDL 语句（如 `CREATE TABLE`、`ALTER TABLE`）会触发隐式提交，将当前事务中的所有 DML 提交，然后执行 DDL，这是 MySQL 不支持 DDL 事务（部分数据库支持）的体现（虽然 MySQL 8.0 支持原子 DDL，但 DDL 本身仍然会触发隐式提交）。

---

## 总结

`START TRANSACTION` 是显式开启 InnoDB 事务的标准语句，支持修饰符：`WITH CONSISTENT SNAPSHOT`（立即创建 Read View 快照）、`READ ONLY`（只读事务，MySQL 优化器优化）、`READ WRITE`（默认，读写事务）。在 `autocommit=ON`（默认）的情况下，`START TRANSACTION` 开启手动提交模式，直到 `COMMIT` 或 `ROLLBACK` 为止。`START TRANSACTION WITH CONSISTENT SNAPSHOT` 适用于需要长时间一致性快照读的场景（如报表生成）。`START TRANSACTION` 本身会导致前一个未提交事务的隐式提交。
