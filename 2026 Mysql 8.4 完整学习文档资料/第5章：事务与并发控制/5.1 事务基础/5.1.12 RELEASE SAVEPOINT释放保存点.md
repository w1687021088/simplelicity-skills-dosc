# RELEASE SAVEPOINT 释放保存点

`RELEASE SAVEPOINT` 语句删除事务中指定的保存点，不执行任何数据回滚操作。当业务逻辑已经通过了某个保存点所保护的关键步骤，确认不再需要回滚到该点时，可以使用 `RELEASE SAVEPOINT` 将其释放，减少事务内存开销，同时也可以用于明确标记"此阶段工作已确认完成"。

---

## 基本语法

```sql
-- 释放保存点（删除保存点，不执行任何数据操作）
RELEASE SAVEPOINT savepoint_name;

-- 示例：明确释放不再需要的保存点
BEGIN;
INSERT INTO orders VALUES (1, 100.00, 'pending');
SAVEPOINT step1;               -- 步骤1完成，设置保存点

UPDATE inventory SET stock = stock - 1 WHERE product_id = 101;
-- 步骤2操作成功，step1 的保护不再需要
RELEASE SAVEPOINT step1;       -- 释放 step1，节省内存

INSERT INTO payments VALUES (1, 100.00, NOW());
SAVEPOINT step3;               -- 步骤3保存点

COMMIT;
-- step3 在 COMMIT 时自动清除（不需要手动 RELEASE）
```

---

## RELEASE SAVEPOINT 与 ROLLBACK TO SAVEPOINT 的区别

```sql
-- ROLLBACK TO SAVEPOINT：回滚数据 + 保留保存点
BEGIN;
INSERT INTO t VALUES (1);
SAVEPOINT sp;
INSERT INTO t VALUES (2);

ROLLBACK TO sp;
-- 结果：id=2 被撤销，id=1 存在；sp 保存点仍然存在
ROLLBACK TO sp;  -- 还可以再次使用 sp（因为 sp 未被删除）
COMMIT;

-- RELEASE SAVEPOINT：删除保存点 + 不回滚数据
BEGIN;
INSERT INTO t VALUES (3);
SAVEPOINT sp;
INSERT INTO t VALUES (4);

RELEASE SAVEPOINT sp;
-- 结果：id=3 和 id=4 都存在；sp 保存点已删除
-- 此后不能再 ROLLBACK TO sp（会报错）
ROLLBACK TO sp;  -- ERROR 1305: SAVEPOINT sp does not exist
COMMIT;
```

## 错误处理：保存点不存在时

```sql
-- 尝试 RELEASE 一个不存在的保存点会报错
BEGIN;
RELEASE SAVEPOINT nonexistent_sp;
-- ERROR 1305 (42000): SAVEPOINT nonexistent_sp does not exist

-- 同样，ROLLBACK TO 不存在的保存点也报错
BEGIN;
ROLLBACK TO SAVEPOINT nonexistent_sp;
-- ERROR 1305 (42000): SAVEPOINT nonexistent_sp does not exist

-- 在存储过程中使用 CONTINUE HANDLER 捕获错误：
DELIMITER //
CREATE PROCEDURE safe_release()
BEGIN
    DECLARE CONTINUE HANDLER FOR SQLSTATE '42000' BEGIN END;  -- 忽略保存点不存在的错误
    RELEASE SAVEPOINT maybe_exists;  -- 如果不存在，错误被忽略
END //
DELIMITER ;
```

## 内存优化意义

```sql
-- 事务内每个保存点占用少量内存（记录 Undo Log 位置等信息）
-- 对于长事务中大量使用保存点的场景，及时 RELEASE 可减少内存占用

-- 一般场景下保存点数量有限（通常几个到几十个），内存影响可忽略
-- 极端场景（循环中创建保存点，可能创建成百上千个）才需要手动管理

-- 示例：循环中使用保存点时需要及时释放
DELIMITER //
CREATE PROCEDURE batch_process()
BEGIN
    DECLARE i INT DEFAULT 1;
    START TRANSACTION;
    WHILE i <= 10000 DO
        SAVEPOINT current_row;
        -- 处理当前行
        INSERT INTO processed VALUES (i);
        IF /* 某条件 */ 1 = 0 THEN
            ROLLBACK TO current_row;  -- 出错时回滚
        ELSE
            RELEASE SAVEPOINT current_row;  -- 成功时释放，防止积累
        END IF;
        SET i = i + 1;
    END WHILE;
    COMMIT;
END //
DELIMITER ;
```

## 适用场景

- **长事务保存点管理**：在循环或多步骤处理中，每次迭代成功后 `RELEASE SAVEPOINT`，避免保存点在内存中无限积累
- **明确标记流程完成**：在业务代码中，`RELEASE SAVEPOINT` 可以作为"此阶段确认完成"的语义标记，提高代码可读性

---

## 常见问题

**COMMIT 时是否需要手动 RELEASE 所有保存点？**

不需要。事务正常提交（COMMIT）或整体回滚（ROLLBACK）时，该事务内所有保存点自动清除，无需手动 `RELEASE`。`RELEASE SAVEPOINT` 的主要用途是在事务仍然活跃时，提前释放不再需要的保存点（防止循环中积累，或明确标记阶段完成）。

---

## 注意事项

- `RELEASE SAVEPOINT` 不影响任何数据，它只是删除保存点本身（一个内存中的标记）。执行后，该保存点名称在当前事务内不再可用（再次 `ROLLBACK TO` 或 `RELEASE` 同名保存点会报错，除非重新 `SAVEPOINT`）。
- 如果保存点被释放后再想回滚到之前的某个状态，只有其他仍然存在的保存点可用，或者只能回滚整个事务（`ROLLBACK`）。因此在确认不需要回滚后再执行 `RELEASE SAVEPOINT`。

---

## 总结

`RELEASE SAVEPOINT savepoint_name` 删除事务中指定的保存点，不执行任何数据回滚，仅释放保存点占用的内存。与 `ROLLBACK TO SAVEPOINT`（回滚数据并保留保存点）形成对比：一个是操作数据，一个是清理标记。事务 COMMIT 或全量 ROLLBACK 后，所有保存点自动清除，无需手动释放。`RELEASE SAVEPOINT` 主要用于长事务中防止保存点积累，以及语义上明确某阶段工作已完成。
