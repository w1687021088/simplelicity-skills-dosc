# SAVEPOINT 保存点设置

`SAVEPOINT` 语句在当前事务中设置一个命名的中间标记点，记录当前的 Undo Log 位置。设置保存点后，可以通过 `ROLLBACK TO SAVEPOINT` 将数据状态回退到该点，而不必回滚整个事务。SAVEPOINT 是实现事务内"部分回滚"的核心机制，在多步骤业务流程中提供了细粒度的错误恢复能力。

---

## 基本语法

```sql
-- 设置保存点
SAVEPOINT savepoint_name;

-- 保存点名称规则：
-- 不区分大小写（MySQL 中保存点名称与标识符规则相同）
-- 可以包含字母、数字、下划线
-- 建议使用有意义的名称

-- 示例：
BEGIN;

INSERT INTO orders VALUES (1, 100.00, 'pending');
SAVEPOINT after_order_creation;    -- 保存点1：订单已创建

UPDATE inventory SET stock = stock - 1 WHERE product_id = 101;
SAVEPOINT after_inventory_update;  -- 保存点2：库存已扣减

INSERT INTO payments VALUES (1, 100.00, '2024-01-01');
-- 如果支付记录插入失败，回滚到 after_inventory_update 点
-- 再次尝试或做其他处理

COMMIT;
```

## 保存点覆盖行为

```sql
-- 同名保存点的覆盖规则：
BEGIN;
INSERT INTO t VALUES (1);
SAVEPOINT sp;           -- 保存点1（id=1已插入时设置）

INSERT INTO t VALUES (2);
SAVEPOINT sp;           -- 保存点2（同名！覆盖保存点1，此时id=1和2均插入）

INSERT INTO t VALUES (3);
ROLLBACK TO sp;         -- 回滚到"最新的 sp"（即保存点2）
-- 结果：id=1 和 id=2 的插入被保留，id=3 的插入被撤销

COMMIT;
-- 最终提交：id=1 和 id=2 存在
```

## 存储过程中的 SAVEPOINT

```sql
-- SAVEPOINT 在存储过程中实现精细化错误处理
DELIMITER //
CREATE PROCEDURE process_order(IN p_order_id INT)
BEGIN
    DECLARE v_error INT DEFAULT 0;
    DECLARE CONTINUE HANDLER FOR SQLEXCEPTION SET v_error = 1;

    START TRANSACTION;

    SAVEPOINT step1;
    UPDATE orders SET status = 'processing' WHERE id = p_order_id;
    IF v_error = 1 THEN
        ROLLBACK TO step1;
        SET v_error = 0;
    END IF;

    SAVEPOINT step2;
    UPDATE inventory SET stock = stock - 1 WHERE product_id = (
        SELECT product_id FROM orders WHERE id = p_order_id
    );
    IF v_error = 1 THEN
        ROLLBACK TO step2;
        SET v_error = 0;
    END IF;

    COMMIT;
END //
DELIMITER ;
```

## 保存点与锁的关系

```sql
-- 重要：ROLLBACK TO SAVEPOINT 不释放该点之后加的行锁
-- InnoDB 行锁在整个事务内持有，不随部分回滚释放

BEGIN;
SELECT * FROM orders WHERE id = 1 FOR UPDATE;  -- 加 X 锁
SAVEPOINT sp;

UPDATE orders SET status = 'done' WHERE id = 1;
ROLLBACK TO sp;  -- 撤销 UPDATE 操作
-- 但 id=1 的 X 锁仍然持有！（FOR UPDATE 加的锁未释放）

-- 直到整个事务 COMMIT 或 ROLLBACK，行锁才释放
COMMIT;  -- 此时 X 锁才释放
```

## 适用场景

- **复杂业务流程**：多步骤业务操作，每步完成后设置保存点，某步失败只回滚该步，可以重试该步骤而不影响之前的步骤
- **存储过程错误处理**：在存储过程中使用 SAVEPOINT 实现精细化错误恢复

---

## 常见问题

**事务 COMMIT 或 ROLLBACK 后，SAVEPOINT 还存在吗？**

不存在。事务结束（COMMIT 或整个事务 ROLLBACK）后，该事务内设置的所有 SAVEPOINT 全部消失。SAVEPOINT 是事务范围内的临时标记，仅在当前事务内有效，事务结束即清除。

---

## 注意事项

- 过多的 SAVEPOINT 会增加内存开销（每个保存点需要记录当前 Undo Log 位置），在非常长的事务中应合理控制保存点数量，不再需要的保存点及时使用 `RELEASE SAVEPOINT` 释放。
- `ROLLBACK TO SAVEPOINT` 不释放该点之后加的行锁——这是 InnoDB 与某些数据库（如 PostgreSQL）的区别。PostgreSQL 的 `ROLLBACK TO SAVEPOINT` 会释放该点之后加的锁，而 InnoDB 不会。

---

## 总结

`SAVEPOINT savepoint_name` 在事务中设置命名的中间标记点，记录 Undo Log 位置。同名保存点后者覆盖前者。SAVEPOINT 使事务支持"部分回滚"——回滚到指定点而不影响该点之前的操作。ROLLBACK TO SAVEPOINT 不释放该点之后加的行锁（锁整个事务持有）。事务结束后所有保存点自动清除。
