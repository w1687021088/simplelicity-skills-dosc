# SET TRANSACTION 设置隔离级别

`SET TRANSACTION` 是 MySQL 中设置事务隔离级别的 SQL 语句。隔离级别可以在三个作用范围内设置：全局（影响所有新建连接）、会话（影响当前连接的后续事务）、仅下一个事务。了解不同作用范围的差异和持久化方式，是正确配置隔离级别的基础。

---

## 基本语法

```sql
-- 语法格式：
SET [GLOBAL | SESSION] TRANSACTION ISOLATION LEVEL level;

-- 或：
SET @@[global. | session.]transaction_isolation = 'level_name';

-- level 的取值：
-- READ UNCOMMITTED
-- READ COMMITTED
-- REPEATABLE READ
-- SERIALIZABLE
```

---

## 三种作用范围

```sql
-- 1. 全局级别（影响所有新建连接，不影响已有连接）
SET GLOBAL TRANSACTION ISOLATION LEVEL READ COMMITTED;
SET @@global.transaction_isolation = 'READ-COMMITTED';

-- 2. 会话级别（影响当前连接的所有后续事务，直到连接断开或再次修改）
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
SET @@session.transaction_isolation = 'READ-COMMITTED';
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;  -- 不写 SESSION 关键字，效果见说明

-- 3. 仅下一个事务（在事务外设置，只对下一个事务有效，之后恢复）
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
-- 注意：在事务外执行且不加 SESSION/GLOBAL 时，只影响下一个事务
-- 下一个事务 COMMIT/ROLLBACK 后，隔离级别恢复为会话默认值

-- 注意：在事务内执行 SET TRANSACTION 会报错：
BEGIN;
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
-- ERROR 1568: Transaction characteristics can't be changed while a transaction is in progress
```

---

## 查看当前隔离级别

```sql
-- 查看当前会话的隔离级别
SELECT @@transaction_isolation;     -- MySQL 8.0 推荐
SELECT @@tx_isolation;              -- 旧版本（8.0 已废弃但仍可用）
SHOW VARIABLES LIKE 'transaction_isolation';

-- 查看全局隔离级别
SELECT @@global.transaction_isolation;
SHOW GLOBAL VARIABLES LIKE 'transaction_isolation';
```

---

## 持久化设置（配置文件）

```ini
# my.cnf / my.ini 永久修改（需重启 MySQL）
[mysqld]
transaction_isolation = READ-COMMITTED    # 注意格式：连字符，不是空格

# 可用值：
# READ-UNCOMMITTED
# READ-COMMITTED
# REPEATABLE-READ
# SERIALIZABLE
```

---

## 不同作用范围对比

| 设置方式 | 生效范围 | 持久性 | 示例 |
|---------|---------|--------|------|
| SET GLOBAL | 所有新建连接 | 重启后失效（除非写配置文件）| `SET GLOBAL TRANSACTION ISOLATION LEVEL RC` |
| SET SESSION | 当前连接后续事务 | 连接断开即失效 | `SET SESSION TRANSACTION ISOLATION LEVEL RC` |
| SET TRANSACTION（无限定词）| 仅下一个事务 | 该事务结束后恢复 | `SET TRANSACTION ISOLATION LEVEL RC` |
| my.cnf 配置 | 所有连接（全局默认）| 永久有效 | `transaction_isolation=READ-COMMITTED` |

## 适用场景

- **临时调整特定会话**：某些需要更高隔离性的操作（如财务对账），在单个会话中临时设置 SERIALIZABLE，操作完成后自动恢复
- **全局配置调整**：将生产环境默认隔离级别从 RR 调整为 RC（减少间隙锁、降低死锁概率），通过配置文件永久生效

---

## 常见问题

**SET TRANSACTION 在事务外不加 SESSION 时，到底影响"下一个事务"还是"当前会话"？**

MySQL 文档明确说明：在事务外执行且不带 SESSION/GLOBAL 修饰时，`SET TRANSACTION` 只影响紧接着下一个事务，下一个事务结束后隔离级别恢复为会话默认值。要影响整个会话后续所有事务，必须显式加 `SESSION` 关键字（`SET SESSION TRANSACTION ISOLATION LEVEL ...`）。

---

## 注意事项

- 在事务进行中（BEGIN 之后 COMMIT/ROLLBACK 之前）修改隔离级别会报错（ERROR 1568），只能在事务外修改。如果需要在一系列操作前修改，应在 `BEGIN` 之前执行 `SET TRANSACTION`。
- 通过连接池的连接（如 JDBC 连接池），修改隔离级别可能影响该连接归还后被其他请求复用时的行为。连接池通常会在归还连接时重置会话变量，但应确认所用连接池是否有此行为，避免隔离级别"泄漏"。

---

## 总结

`SET TRANSACTION ISOLATION LEVEL` 支持三个作用范围：全局（GLOBAL，影响新连接）、会话（SESSION，影响当前连接后续所有事务）、仅下一个事务（不带限定词）。查询当前隔离级别用 `SELECT @@transaction_isolation`。永久修改需写入 `my.cnf` 的 `transaction_isolation` 参数（格式为连字符，如 `READ-COMMITTED`）。不能在事务进行中修改隔离级别。
