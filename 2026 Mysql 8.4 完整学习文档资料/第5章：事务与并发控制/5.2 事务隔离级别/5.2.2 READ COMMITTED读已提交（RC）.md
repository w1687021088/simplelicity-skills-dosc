# READ COMMITTED 读已提交（RC）

READ COMMITTED（读已提交，简称 RC）是 SQL 标准定义的四个事务隔离级别中第二弱的级别，也是 Oracle、SQL Server 等数据库的默认隔离级别。在 RC 级别下，一个事务只能读取其他事务已经提交的修改，消除了脏读问题。InnoDB 通过 MVCC（每次 SELECT 时创建新的 Read View）实现 RC 级别的读已提交语义，使读操作不需要加锁，读写可以并发执行。

---

## 核心特征

```
READ COMMITTED 的行为特征：

读操作（快照读）：
  使用 MVCC，每次 SELECT 时创建新的 Read View
  Read View 代表当前时刻已提交的数据快照
  → 只能看到执行 SELECT 时已提交的事务的修改
  → 不能看到未提交的修改（消除脏读）
  → 每次 SELECT 可能看到不同的值（允许不可重复读）

写操作：
  与 RR 级别基本相同，DML 加 X 锁
  但 RC 级别下：锁只加在匹配的记录上，不加间隙锁（通常）
  → 并发插入不被间隙锁阻塞（比 RR 并发性更高）

可能出现的并发问题：
  脏读：不会（只读已提交数据）
  不可重复读：可能（每次 SELECT 看到新提交的数据）
  幻读：可能（范围查询行数可能变化）
```

---

## RC 级别的 Read View 行为

```sql
-- RC 级别：每次 SELECT 创建新 Read View（读取当时已提交的最新快照）

SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

BEGIN;
SELECT balance FROM accounts WHERE id = 1;
-- Read View 1 创建：看到 balance=1000（当时已提交状态）

-- 此时另一个事务提交了修改：balance 变为 900

SELECT balance FROM accounts WHERE id = 1;
-- Read View 2 创建：看到 balance=900（新提交的修改对本次 SELECT 可见）
-- 同一事务内两次读取结果不同 = 不可重复读（RC 允许）

COMMIT;

-- 对比 RR 级别（只创建一次 Read View）：
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
BEGIN;
SELECT balance FROM accounts WHERE id = 1;  -- Read View 固定：balance=1000
-- 另一个事务提交修改：balance 变为 900
SELECT balance FROM accounts WHERE id = 1;  -- 仍然是 balance=1000（固定快照）
COMMIT;
```

## RC 级别的锁行为

```sql
-- RC 级别下的锁更轻量，只锁匹配记录，不加间隙锁

-- 示例：DELETE 不存在的记录
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
BEGIN;
DELETE FROM orders WHERE user_id = 999;  -- user_id=999 不存在
-- RC 级别：不加间隙锁，其他事务可以插入 user_id=999 的记录
-- RR 级别：加间隙锁，阻止其他事务插入

-- RC 级别的锁优化（semi-consistent read）：
-- 在执行 UPDATE 时，如果访问到不匹配 WHERE 条件的记录，
-- RC 级别会读取已提交版本来判断是否匹配，不匹配则不加锁并立即释放
-- 减少了锁持有量，提高了并发性

-- RR 级别没有此优化，会持有所有扫描过的行锁（即使不匹配 WHERE）
```

---

## RC vs RR 的主要差异

| 特性 | READ COMMITTED | REPEATABLE READ |
|------|:-------------:|:---------------:|
| Read View 创建时机 | 每次 SELECT | 事务第一次读时 |
| 是否允许不可重复读 | 允许 | 不允许 |
| 间隙锁（Gap Lock）| 通常不加 | 加（防幻读）|
| 并发性 | 较高（无间隙锁）| 较低（有间隙锁）|
| 死锁概率 | 较低 | 较高（间隙锁增加等待）|
| 脏读防护 | 有（只读已提交）| 有 |
| 幻读防护 | 无 | 部分（MVCC+间隙锁）|

## 适用场景

- **高并发 OLTP 系统**：互联网电商、社交平台等对并发性要求高、允许非重复读（每次查询都读最新值）的场景，RC 比 RR 有更少的间隙锁，降低了死锁概率和并发阻塞
- **Oracle 迁移兼容**：将 Oracle 数据库迁移到 MySQL 时，由于 Oracle 默认就是 RC 级别，保持 RC 设置可以减少行为差异

## 常见问题

**RC 级别下会不会出现幻读？**

会。RC 级别每次 SELECT 创建新 Read View，如果范围查询期间有新行插入并提交，下次同样的范围查询就会看到新行，出现幻读。RC 级别不加间隙锁，无法防止其他事务在被查询的范围内插入。如果需要防止幻读，应升级到 RR 级别（配合 Next-Key Lock）。

---

## 注意事项

- 在启用 Binlog 的 MySQL 主从复制环境中，使用 RC 级别时必须将 `binlog_format` 设置为 `ROW`（行格式）或 `MIXED`（混合格式），不能使用 `STATEMENT`（语句格式）。因为 RC 级别下，相同 SQL 在不同时间执行可能产生不同结果（读已提交时效），使用语句格式会导致主从数据不一致。
- RC 级别虽然并发性更高，但在某些业务场景（如库存扣减、账户转账）中，不可重复读会导致业务逻辑错误（读到的值在后续操作前被修改）。这类场景应使用 RR 级别或显式加锁（`SELECT ... FOR UPDATE`）。

---

## 总结

READ COMMITTED 通过 MVCC（每次 SELECT 时创建新 Read View）消除脏读，同时允许不可重复读（每次 SELECT 看到当时最新的已提交数据）。RC 级别通常不加间隙锁，并发性更高，死锁风险更低，是互联网高并发系统的常用选择。与 RR 的核心差异是：RC 每次查询更新快照（读已提交），RR 整事务使用同一快照（可重复读）。在启用 Binlog 的 RC 环境中，必须使用 ROW 格式 Binlog。
