# 数据页 Page 结构（16KB）

InnoDB 以数据页（Page）为单位在磁盘和内存（Buffer Pool）之间传输和管理数据。每个数据页固定大小为 16KB（可通过 `innodb_page_size` 配置为 4KB/8KB/16KB/32KB/64KB，默认 16KB）。数据页是 InnoDB 最小的 I/O 单元，所有的数据行、索引记录、Undo Log 等都按页为单位组织。理解数据页的结构，是理解 InnoDB B+ Tree 存储、行记录布局和页分裂机制的基础。

---

## 数据页的整体布局

```
InnoDB 数据页（16KB = 16384 字节）的完整结构：

┌─────────────────────────────────────────────────────────────────────┐
│ File Header        (38 字节)  ← 文件头，跨页链表指针、校验和、LSN 等│
├─────────────────────────────────────────────────────────────────────┤
│ Page Header        (56 字节)  ← 页头，记录数量、槽数量、Free Space  │
│                               ← 位置、B+ Tree 层级等               │
├─────────────────────────────────────────────────────────────────────┤
│ Infimum + Supremum (26 字节)  ← 虚拟最小/最大记录（链表边界）        │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│ User Records (变长)           ← 实际存储的用户数据行（行记录）       │
│                               ← 按主键顺序单向链表排列               │
│                                                                     │
├─────────────────────────────────────────────────────────────────────┤
│ Free Space (变长)             ← 空闲空间（向两端压缩）               │
├─────────────────────────────────────────────────────────────────────┤
│ Page Directory (变长)         ← 槽（Slot）数组，用于二分查找          │
│                               ← 从页尾向上增长                      │
├─────────────────────────────────────────────────────────────────────┤
│ File Trailer       (8 字节)   ← 文件尾，包含校验和（验证完整性）     │
└─────────────────────────────────────────────────────────────────────┘

各区域大小：
Fixed 部分（File Header + Page Header + Infimum/Supremum + File Trailer）= 38+56+26+8 = 128 字节
可用区域：16384 - 128 = 16256 字节（User Records + Free Space + Page Directory）
```

## File Header（文件头）

```
File Header（38 字节）的关键字段：

FIL_PAGE_SPACE_OR_CHKSUM（4字节）：
  该页所在表空间的校验和（Checksum）
  崩溃恢复时用于验证页的完整性

FIL_PAGE_OFFSET（4字节）：
  该页在表空间中的页号（从 0 开始的序号）
  space_id + page_no 唯一标识一个页

FIL_PAGE_PREV（4字节）：
  前一页的页号（双向链表，叶子节点页之间的链接）
  B+ Tree 叶子节点的范围查询使用此链表顺序遍历

FIL_PAGE_NEXT（4字节）：
  后一页的页号

FIL_PAGE_LSN（8字节）：
  该页最后被修改时的 LSN（Log Sequence Number）
  崩溃恢复时通过比较此 LSN 决定是否重放 Redo Log

FIL_PAGE_TYPE（2字节）：
  页面类型，常见类型：
  FIL_PAGE_INDEX（17855）：B+ Tree 索引页（最常见）
  FIL_PAGE_UNDO_LOG（2）：Undo Log 页
  FIL_PAGE_INODE（3）：段管理页
  FIL_PAGE_IBUF_BITMAP（5）：Insert Buffer Bitmap 页
  FIL_PAGE_TYPE_SYS（6）：系统页
```

## 页类型与数据页的区别

```sql
-- 狭义的"数据页"通常指 B+ Tree 索引页（FIL_PAGE_INDEX）
-- 广义的"数据页"泛指 InnoDB 中所有 16KB 的页面

-- 查看 Buffer Pool 中不同类型页面的分布
SELECT PAGE_TYPE, COUNT(*) AS page_count
FROM information_schema.INNODB_BUFFER_PAGE
GROUP BY PAGE_TYPE
ORDER BY page_count DESC;
-- INDEX：最多（数据和索引页）
-- UNDO_LOG：Undo 页
-- INODE：段管理页
-- IBUF_BITMAP：Insert Buffer Bitmap 页
-- SYSTEM：系统内部页

-- 查看指定表的数据页信息
SELECT
    PAGE_NUMBER,
    PAGE_TYPE,
    SPACE,
    DATA_SIZE,
    COMPRESSED_SIZE,
    IS_OLD,
    ACCESS_TIME
FROM information_schema.INNODB_BUFFER_PAGE
WHERE TABLE_NAME = '`myapp`.`orders`'
ORDER BY PAGE_NUMBER
LIMIT 20;
```

## 数据页大小的配置

```sql
-- 查看当前页大小
SHOW VARIABLES LIKE 'innodb_page_size';
-- 默认：16384（16 KB）

-- 页大小对比：
-- 4 KB：适合 SSD 的原子写大小（减少部分写风险），但树高增加
-- 8 KB：折中
-- 16 KB（默认）：大多数场景的最优值
-- 32 KB：减少树高，但每页只能存更少的行（增加空间浪费）
-- 64 KB：适合极宽的表或 OLAP 大扫描场景

-- 注意：innodb_page_size 只能在初始化时配置（my.cnf），
-- 一旦数据库初始化后不能更改

-- 最大行大小限制（与页大小相关）：
-- 行大小 < 半页大小（约 8000 字节），否则需要行溢出存储
-- innodb_page_size = 16K → 最大行记录（内联部分）约 8000 字节
```

## 页分裂（Page Split）

```sql
-- 当一个数据页已满，再插入记录时发生页分裂：
-- 1. 分配一个新的空白页
-- 2. 将原页的约一半记录迁移到新页
-- 3. 调整父页的索引记录（指向两个子页）
-- 4. 如果父页也满了，递归向上分裂

-- 顺序插入（自增主键）：
-- 总是在最后一页末尾追加，只有最后一页会满后分裂
-- 新页利用率可以达到 100%

-- 随机插入（UUID 或随机主键）：
-- 插入位置随机，每次分裂后两个页都约 50% 利用率
-- 导致大量页分裂 + 低利用率（页碎片化）
-- 建议：对于写密集型表，使用自增主键而非 UUID/随机值

-- 监控页分裂次数（通过 performance_schema）
SELECT * FROM performance_schema.table_io_waits_summary_by_index_usage
WHERE OBJECT_SCHEMA = 'myapp' AND OBJECT_NAME = 'orders';
```

## 适用场景

- **表结构设计**：理解 16KB 页大小和行记录大小限制，有助于合理设计列类型，避免大字段导致行溢出（Off-page 存储）降低 I/O 效率
- **主键选择**：了解页分裂机制后，应优先选择单调递增的主键（如 AUTO_INCREMENT），避免 UUID 主键导致的随机插入和频繁页分裂

## 常见问题

**为什么 InnoDB 默认页大小是 16KB 而不是其他大小？**

16KB 是综合考虑内存效率、I/O 效率和行记录大小的经验值。太小（如 4KB）会导致 B+ Tree 树高增加（每页能放的记录少，需要更多层级），随机读的页数增多。太大（如 64KB）每页包含更多记录，但单个页的读取 I/O 成本更高，且容易浪费内存（Buffer Pool 中一个页占用更多内存但利用率低）。16KB 在行数量、树高、I/O 效率之间取得了较好的平衡。

---

## 注意事项

- 数据页的校验和机制（File Header 中的 checksum 与 File Trailer 中的 checksum 对应）是防止"部分写/撕裂页"损坏检测的基础。如果两端校验和不一致，InnoDB 会认为该页已损坏，尝试从 Doublewrite Buffer 恢复。
- `innodb_checksum_algorithm`（默认 `crc32`）控制校验和算法。MySQL 8.0 默认使用 CRC32，速度快且硬件加速支持好，一般不需要修改。

---

## 总结

InnoDB 数据页（16KB）由七个区域组成：File Header（38B，页元信息+链表指针+LSN）、Page Header（56B，记录统计）、Infimum/Supremum（26B，虚拟边界记录）、User Records（变长，实际行数据）、Free Space（变长，空闲区域）、Page Directory（变长，二分查找槽）、File Trailer（8B，校验和）。聚簇索引叶子节点页通过 FIL_PAGE_PREV/NEXT 双向链表连接，支持范围查询顺序遍历。自增主键减少页分裂，UUID 主键导致随机页分裂和碎片化。
