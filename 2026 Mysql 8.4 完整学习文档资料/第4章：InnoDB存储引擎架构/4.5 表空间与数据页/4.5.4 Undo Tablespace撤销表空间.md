# Undo Tablespace 撤销表空间

Undo Tablespace（撤销表空间）是 InnoDB 专门用于存储 Undo Log 的独立表空间，对应数据目录中的 `.ibu` 扩展名文件。MySQL 8.0 将 Undo Log 从系统表空间（ibdata1）中完全独立出来，默认创建 2 个 Undo 表空间（`undo_001`、`undo_002`），支持自动收缩（Truncate）和运行时动态管理，彻底解决了旧版本 ibdata1 因 Undo Log 积累而无限膨胀的历史问题。

（本节与 4.4.3 侧重点不同：4.4.3 偏重 Undo Log 的增删和收缩操作，本节侧重 Undo Tablespace 作为表空间的物理结构和内部组织。）

## Undo Tablespace 的物理结构

```
Undo Tablespace（.ibu 文件）内部组织：

┌──────────────────────────────────────────────────────────────────┐
│                  Undo Tablespace（undo_001.ibu）                  │
│                                                                  │
│  Page 0：表空间头（FSP Header）                                   │
│  ├── Rollback Segment 0（回滚段 0）                               │
│  │    ├── Undo Segment 0（Undo 段）                              │
│  │    │    ├── Undo Page 0（16KB）                               │
│  │    │    │    ├── INSERT Undo Record（事务A）                  │
│  │    │    │    └── UPDATE Undo Record（事务B）                  │
│  │    │    └── Undo Page 1（16KB）...                           │
│  │    └── Undo Segment 1 ... 1023                               │
│  ├── Rollback Segment 1 ... 127                                  │
│  └── ...共 128 个 Rollback Segment                              │
└──────────────────────────────────────────────────────────────────┘

每个 Undo Tablespace：
  → 最多 128 个 Rollback Segment（回滚段）
  → 每个 Rollback Segment 最多 1024 个 Undo Slot（Undo 段槽位）
  → 每个 Undo Slot 对应一个 Undo Segment（Undo 段）
  → 理论最大并发事务数 = 表空间数 × 128 × 1024
```

## Undo Tablespace 的配置

```sql
-- 查看 Undo Tablespace 相关配置
SHOW VARIABLES LIKE 'innodb_undo%';
-- innodb_undo_directory：Undo 文件目录（默认与 datadir 相同）
-- innodb_undo_log_encrypt：Undo Log 加密（MySQL 8.0.16+，默认 OFF）
-- innodb_undo_log_truncate：自动收缩（默认 ON）
-- innodb_undo_tablespaces：Undo 表空间数量（MySQL 8.0 默认 2）

-- 查看 Undo 表空间文件信息
SELECT
    ts.SPACE_ID,
    ts.NAME,
    ts.STATE,
    f.PATH,
    ts.SIZE / 1024 / 1024 AS size_mb
FROM information_schema.INNODB_TABLESPACES ts
JOIN information_schema.INNODB_DATAFILES f
    ON ts.SPACE_ID = f.SPACE
WHERE ts.NAME LIKE 'innodb_undo%';

-- 查看每个 Undo 表空间的 Rollback Segment 使用情况
SELECT
    TABLESPACE_NAME,
    FILE_ID,
    FILE_TYPE,
    TABLESPACE_TYPE
FROM information_schema.FILES
WHERE TABLESPACE_NAME LIKE '%undo%';
```

## Rollback Segment 的分配机制

```sql
-- 事务开始时分配 Rollback Segment 的规则：
-- MySQL 8.0 中 Rollback Segment 的总数：
-- = innodb_rollback_segments × (innodb_undo_tablespaces + 1)
-- 默认：128 × (2 + 1) = 384 个 Rollback Segments
-- （+1 是系统表空间中的那 1 个回滚段）

-- 查看 Rollback Segment 配置
SHOW VARIABLES LIKE 'innodb_rollback_segments';
-- 默认：128（每个 Undo 表空间包含 128 个 Rollback Segment）

-- 事务分配 Rollback Segment 的策略：
-- 轮询（Round-Robin）分配，避免多个事务竞争同一个回滚段
-- 查看当前活跃的 Rollback Segments 使用情况
SELECT
    COUNT
FROM information_schema.INNODB_METRICS
WHERE NAME = 'trx_active_transactions';

-- 监控每个 Rollback Segment 的使用情况
SHOW ENGINE INNODB STATUS \G
-- 在 TRANSACTIONS 部分：
-- "Trx id counter"：当前事务 ID 计数
-- "Purge done for trx's n:o < XXX"：Purge 进度
```

## Undo Tablespace 的磁盘位置优化

```sql
-- 将 Undo Tablespace 放到高速 SSD 以提升性能
-- my.cnf 配置（在 MySQL 初始化前设置）：
-- [mysqld]
-- innodb_undo_directory = /fast_nvme/mysql/undo

-- 运行时新增位于其他磁盘的 Undo Tablespace：
CREATE UNDO TABLESPACE undo_fast
    ADD DATAFILE '/fast_nvme/mysql/undo_fast.ibu';

-- 验证创建成功
SELECT SPACE_ID, NAME, STATE
FROM information_schema.INNODB_TABLESPACES
WHERE NAME = 'innodb_undo_fast';

-- Undo I/O 特点：
-- 写操作：随机写（各事务的 Undo Log 分散在 Undo Segment 中）
-- 读操作：MVCC 版本链遍历时随机读取 Undo 页
-- → Undo 对随机 I/O 要求较高，适合放在 SSD/NVMe
```

## Undo Tablespace 的自动收缩（Truncate）

```sql
-- 触发条件：
-- innodb_undo_log_truncate = ON（默认）
-- 且某个 Undo 表空间大小 > innodb_max_undo_log_size（默认 1GB）
SHOW VARIABLES LIKE 'innodb_max_undo_log_size';
-- 默认：1073741824（1 GB）

-- 收缩过程：
-- 1. 选择最大的 Undo 表空间（且所有其他表空间处于 active 状态）
-- 2. 将其标记为 inactive（新事务不再分配到此表空间）
-- 3. Purge 线程清空此表空间的所有 Undo 段
-- 4. 文件截断（Truncate）到初始大小
-- 5. 重新标记为 active

-- 监控收缩进度
SELECT NAME, STATE
FROM information_schema.INNODB_TABLESPACES
WHERE NAME LIKE 'innodb_undo%';
-- STATE 从 active → inactive → empty → active（Truncate 完成）
```

## 适用场景

- **高并发写入系统**：通过 `CREATE UNDO TABLESPACE` 增加 Undo 表空间数量（最多 127 个），增加可用 Rollback Segment 总数，减少事务间竞争
- **存储分层**：将 Undo 表空间放在高速 NVMe SSD（`innodb_undo_directory` 或创建时指定），利用 Undo 的随机 I/O 特性，与数据文件分离

---

## 常见问题

**2 个 Undo 表空间够用吗？是否需要增加？**

对于大多数系统，2 个 Undo 表空间（每个 128 个 Rollback Segment）共 256 个 Rollback Segment 已经足够。只有在极高并发（几千个并发写事务）且 Rollback Segment 竞争明显时（通过 `SHOW ENGINE INNODB STATUS` 观察 Rollback Segment 使用率），才需要增加 Undo 表空间数量。一般情况下，优先解决长事务问题（减少 Undo 积压）比增加 Undo 表空间更有效。

---

## 注意事项

- 在 MySQL 8.4 中，`innodb_undo_tablespaces` 的默认值仍为 2，但此参数被标注为 deprecated（将来版本可能移除），官方推荐通过 `CREATE UNDO TABLESPACE` 命令动态管理 Undo 表空间数量，而非依赖初始化参数。
- Undo Tablespace 文件（`.ibu`）与普通 InnoDB 表的 `.ibd` 文件格式类似，都以 16KB 数据页为单位，但内部页面的用途不同（Undo 专用的页面类型）。

---

## 总结

Undo Tablespace（`.ibu` 文件）是 MySQL 8.0 独立出来的 Undo Log 存储区域，默认 2 个（`undo_001/002`）。每个 Undo 表空间包含最多 128 个 Rollback Segment，每个 Rollback Segment 最多 1024 个 Undo Slot（Undo Segment）。通过 `innodb_undo_log_truncate=ON` 和 `innodb_max_undo_log_size=1G` 配置自动收缩。可以通过 `CREATE UNDO TABLESPACE` 在指定路径（如高速 SSD）创建新的 Undo 表空间，通过 `ALTER UNDO TABLESPACE ... SET INACTIVE` + `DROP UNDO TABLESPACE` 删除。
