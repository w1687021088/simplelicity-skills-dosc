# General Tablespace 通用表空间

General Tablespace（通用表空间）是 MySQL 5.7.6 引入的一种共享型表空间，允许将多张表的数据存储在同一个自定义表空间文件中，同时具备独立文件（file-per-table）的可管理性。它介于系统表空间（所有表共用 ibdata1）和独立表空间（每张表独立 .ibd）之间，适合需要对特定表组进行统一管理或放置在特定存储设备上的场景。

---

## 通用表空间与其他表空间的对比

| 特性 | 系统表空间（ibdata1）| 独立表空间（.ibd）| 通用表空间（.ibd）|
|------|-------------------|-----------------|-----------------|
| 文件数量 | 1-几个 | 每表 1 个 | 1 个包含多张表 |
| DROP TABLE 释放空间 | 否 | 是（立即）| 否（空间标记可复用）|
| 自定义存储位置 | 配置时固定 | DATA DIRECTORY | CREATE 时指定 |
| 支持多行格式 | 有限制 | 是 | 是 |
| 压缩表支持 | 否 | 是 | 是 |
| 可删除表空间 | 否 | DROP TABLE | DROP TABLESPACE |

---

## 创建和使用通用表空间

```sql
-- 创建通用表空间（在数据目录中）
CREATE TABLESPACE ts_orders
    ADD DATAFILE 'ts_orders.ibd'
    ENGINE = InnoDB;

-- 创建通用表空间（在自定义位置）
CREATE TABLESPACE ts_fast
    ADD DATAFILE '/fast_ssd/mysql/ts_fast.ibd'
    ENGINE = InnoDB;
-- 文件路径必须在 MySQL 有权访问的目录中

-- 查看已创建的通用表空间
SELECT SPACE_ID, NAME, STATE, ROW_FORMAT
FROM information_schema.INNODB_TABLESPACES
WHERE NAME NOT LIKE 'innodb_%'
  AND NAME NOT LIKE 'mysql%'
  AND NAME NOT LIKE 'sys%';

-- 在通用表空间中创建表
CREATE TABLE orders (
    id     BIGINT AUTO_INCREMENT PRIMARY KEY,
    amount DECIMAL(10, 2)
) ENGINE = InnoDB TABLESPACE = ts_orders;

-- 将已有表移动到通用表空间
ALTER TABLE orders TABLESPACE = ts_orders;

-- 将表从通用表空间移回 file-per-table（默认）
ALTER TABLE orders TABLESPACE = innodb_file_per_table;
```

## 通用表空间管理

```sql
-- 查看哪些表在通用表空间中
SELECT
    t.TABLE_SCHEMA,
    t.TABLE_NAME,
    ts.NAME AS tablespace_name
FROM information_schema.TABLES t
JOIN information_schema.INNODB_TABLES it
    ON CONCAT(t.TABLE_SCHEMA, '/', t.TABLE_NAME) = it.NAME
JOIN information_schema.INNODB_TABLESPACES ts
    ON it.SPACE = ts.SPACE_ID
WHERE ts.NAME NOT LIKE 'innodb_%'
  AND ts.NAME NOT LIKE '%undo%'
  AND ts.NAME NOT LIKE '#%';

-- 删除通用表空间（必须先将表移出）
-- 步骤1：将表移出
ALTER TABLE orders TABLESPACE = innodb_file_per_table;

-- 步骤2：确认表空间为空
SELECT COUNT(*) FROM information_schema.INNODB_TABLES
WHERE SPACE = (
    SELECT SPACE_ID FROM information_schema.INNODB_TABLESPACES
    WHERE NAME = 'ts_orders'
);

-- 步骤3：删除表空间
DROP TABLESPACE ts_orders;
```

## 通用表空间的行格式与压缩

```sql
-- 通用表空间支持指定行格式（DYNAMIC 或 COMPRESSED）
CREATE TABLESPACE ts_compressed
    ADD DATAFILE 'ts_compressed.ibd'
    FILE_BLOCK_SIZE = 8192  -- 使用 8KB 块大小支持压缩
    ENGINE = InnoDB;

-- 在压缩表空间中创建压缩表
CREATE TABLE orders_archive (
    id         BIGINT AUTO_INCREMENT PRIMARY KEY,
    order_data TEXT
) ENGINE = InnoDB
  ROW_FORMAT = COMPRESSED
  KEY_BLOCK_SIZE = 8          -- 压缩块大小（需与 FILE_BLOCK_SIZE 一致）
  TABLESPACE = ts_compressed;

-- 注意：通用表空间中的所有表必须使用相同的 FILE_BLOCK_SIZE
-- 混用不同 KEY_BLOCK_SIZE 的表不能放在同一个通用表空间中
```

## 适用场景

- **SSD 分层存储**：将热点表放到高速 NVMe SSD 的通用表空间，将冷数据表放到 SATA SSD，实现分层存储
- **同类表统一管理**：将同一业务模块的多张表放到一个通用表空间，方便按业务模块管理存储
- **压缩存储**：创建带有 `FILE_BLOCK_SIZE` 的通用表空间，将归档类大表统一存放并压缩

## 常见问题

**通用表空间和 innodb_file_per_table 可以共存吗？**

可以。`innodb_file_per_table=ON` 只是决定新建表的默认存储位置（独立 .ibd 文件）。通用表空间是显式指定的（`TABLESPACE = ts_name`），不受 `innodb_file_per_table` 参数影响。可以在同一数据库中同时存在独立表空间的表和通用表空间的表。

---

## 注意事项

- 通用表空间的文件路径（`ADD DATAFILE`）中，绝对路径或相对路径均可，相对路径是相对于 `datadir`。绝对路径必须指向 MySQL 用户有读写权限的目录，且该路径不能在 `datadir` 子目录内（会与 file-per-table 的命名空间冲突）。
- 通用表空间不支持 `DATA DIRECTORY` 子句（即在创建表时通过 `DATA DIRECTORY` 临时指定路径），它的路径在 `CREATE TABLESPACE` 时就固定了。

---

## 总结

General Tablespace（通用表空间）允许将多张表存储到同一个自定义 `.ibd` 文件中，通过 `CREATE TABLESPACE` 创建，`ENGINE=InnoDB TABLESPACE=ts_name` 指定。适用于需要将特定表放到特定磁盘（如高速 SSD）或统一管理一组表的场景。支持压缩（`FILE_BLOCK_SIZE`）和 DYNAMIC 行格式。DROP TABLE 不释放通用表空间文件的磁盘空间（与系统表空间类似），通过 `DROP TABLESPACE`（表全部移出后）删除并释放空间。
