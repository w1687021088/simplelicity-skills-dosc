# File-per-table 独立表空间（.ibd 文件）

File-per-table 是 InnoDB 将每张表的数据和索引单独存储在一个 `.ibd` 文件中的机制，通过 `innodb_file_per_table=ON`（MySQL 8.0 默认值）启用。相比将所有表数据存入系统表空间（ibdata1），独立表空间使每张表的存储更加独立可控，DROP TABLE 后立即释放磁盘空间，也支持表级别的传输（Transportable Tablespace）和独立备份恢复。

---

## 独立表空间的基本配置

```sql
-- 查看当前配置
SHOW VARIABLES LIKE 'innodb_file_per_table';
-- 默认：ON（MySQL 5.6.7+ 开始，MySQL 8.0 保持 ON）

-- 动态修改（只影响后续新建的表，不影响已有表）
SET GLOBAL innodb_file_per_table = ON;

-- my.cnf 持久化配置
-- [mysqld]
-- innodb_file_per_table = ON

-- 查看某张表的表空间信息
SELECT
    t.NAME AS table_name,
    ts.NAME AS tablespace_name,
    ts.STATE,
    ts.SIZE / 1024 / 1024 AS size_mb
FROM information_schema.INNODB_TABLES t
JOIN information_schema.INNODB_TABLESPACES ts
    ON t.SPACE = ts.SPACE_ID
WHERE t.NAME = 'myapp/orders';
```

## .ibd 文件结构

```
.ibd 文件（File-per-table 表空间文件）：

文件内部结构：
┌──────────────────────────────────────────────────────────┐
│ 数据段（Clustered Index Leaf Pages）                      │
│  B+ Tree 叶子节点 = 实际行数据（主键顺序存储）            │
├──────────────────────────────────────────────────────────┤
│ 索引段（Non-Leaf Index Pages）                           │
│  B+ Tree 非叶子节点 = 索引键值 + 指针                   │
├──────────────────────────────────────────────────────────┤
│ 二级索引段（Secondary Index Pages）                       │
│  每个 INDEX KEY 对应的 B+ Tree                          │
├──────────────────────────────────────────────────────────┤
│ 回滚段页（部分情况下）                                    │
├──────────────────────────────────────────────────────────┤
│ Page 0：Space Header（表空间头）                         │
│ Page 1：Insert Buffer Bitmap                            │
│ Page 2：Inode Page（段管理页）                          │
└──────────────────────────────────────────────────────────┘
所有内容均以 16KB 数据页（Page）为单位存储
```

## 查看和管理 .ibd 文件

```sql
-- 查看数据库中所有表的 .ibd 文件位置和大小
SELECT
    TABLE_SCHEMA,
    TABLE_NAME,
    DATA_LENGTH / 1024 / 1024 AS data_mb,
    INDEX_LENGTH / 1024 / 1024 AS index_mb,
    (DATA_LENGTH + INDEX_LENGTH) / 1024 / 1024 AS total_mb,
    DATA_FREE / 1024 / 1024 AS free_mb
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'myapp'
ORDER BY (DATA_LENGTH + INDEX_LENGTH) DESC;

-- DATA_FREE：已分配但未被使用的空间（删除数据后产生的碎片）
-- 如果 DATA_FREE 很大，考虑优化表回收空间：
-- ALTER TABLE myapp.orders ENGINE = InnoDB;  -- 重建表，回收碎片（会锁表）
-- 或用 pt-online-schema-change 工具在线重建（不锁表）

-- 查看表空间文件的物理路径
SELECT
    t.NAME,
    f.PATH
FROM information_schema.INNODB_TABLES t
JOIN information_schema.INNODB_DATAFILES f
    ON t.SPACE = f.SPACE
WHERE t.NAME LIKE 'myapp/%';
```

## DROP TABLE 与磁盘空间释放

```sql
-- file-per-table 模式下：
-- DROP TABLE orders;
-- → 直接删除 orders.ibd 文件
-- → 磁盘空间立即归还给操作系统

-- 系统表空间模式下（innodb_file_per_table = OFF）：
-- DROP TABLE orders;
-- → ibdata1 中的空间被标记为"可复用"，但不归还给 OS
-- → ibdata1 文件大小不变（甚至不减小）
-- → 这是 ibdata1 无法收缩的根本原因

-- 验证删除后文件消失
-- （操作前）ls -la /var/lib/mysql/myapp/orders.ibd
-- DROP TABLE orders;
-- （操作后）ls -la /var/lib/mysql/myapp/orders.ibd → No such file or directory
```

## Transportable Tablespace（表空间传输）

```sql
-- File-per-table 支持将 .ibd 文件在不同 MySQL 实例间迁移

-- 步骤1：在源实例上准备（锁定表，导出 .cfg 元数据文件）
FLUSH TABLE myapp.orders FOR EXPORT;
-- 生成 orders.cfg 文件（包含表结构元数据）

-- 步骤2：复制 .ibd 和 .cfg 文件到目标实例
-- （源：/var/lib/mysql/myapp/orders.ibd + orders.cfg）
-- → 复制到目标实例对应目录

-- 步骤3：在源实例上解锁
UNLOCK TABLES;

-- 步骤4：在目标实例上：
-- 先创建同结构的表
CREATE TABLE orders LIKE source_orders;
-- 丢弃目标表的表空间
ALTER TABLE orders DISCARD TABLESPACE;
-- 将复制来的 .ibd 文件放到目标目录
-- 导入表空间
ALTER TABLE orders IMPORT TABLESPACE;
-- 导入成功，数据可用

-- 用途：
-- → 物理备份单表（不需要全库备份）
-- → 快速迁移大表（比 mysqldump 快很多）
-- → 在读库上加载生产数据的只读副本
```

## 适用场景

- **生产环境标准配置**：`innodb_file_per_table=ON` 是生产环境的必选配置，确保 DROP TABLE 能立即释放磁盘空间
- **大表迁移**：通过 Transportable Tablespace 机制，可以在不停服的情况下将大表的物理文件复制到另一个实例
- **分盘存储**：将不同表的 `.ibd` 文件放到不同磁盘（通过 `CREATE TABLE ... DATA DIRECTORY = '/path/to/fast/disk'`）

---

## 常见问题

**表被删除后，磁盘空间没有减少，是什么原因？**

最常见的原因：`innodb_file_per_table = OFF`（在系统表空间模式下，DROP TABLE 不释放 ibdata1 的空间）。解决方法：确认使用了 file-per-table 模式（MySQL 8.0 默认 ON），对于已在系统表空间的旧表，可以通过 `ALTER TABLE t ENGINE=InnoDB` 重建到独立表空间后再删除。

---

## 注意事项

- 将 `innodb_file_per_table` 从 ON 改为 OFF 或反向更改，只影响之后新建的表，不自动迁移已有表的存储位置。如果需要将已有表从系统表空间迁移到独立文件，执行 `ALTER TABLE t ENGINE=InnoDB` 重建即可（生产环境用 pt-online-schema-change 避免锁表）。
- `DATA_FREE` 较大时（超过表数据量的 20%），说明有大量碎片，可以考虑重建表。对于频繁 DELETE 的表，碎片积累是正常的，重建后一段时间又会再次积累。

---

## 总结

File-per-table（`innodb_file_per_table=ON`，MySQL 8.0 默认）使每张表拥有独立的 `.ibd` 文件，DROP TABLE 后立即释放磁盘空间。`.ibd` 文件内部存储聚簇索引（B+ Tree 叶子节点为行数据）和二级索引，以 16KB 数据页为单位组织。支持 Transportable Tablespace（`FLUSH TABLE ... FOR EXPORT` + 文件复制 + `IMPORT TABLESPACE`）实现跨实例的表级物理迁移。通过 `information_schema.TABLES` 的 `DATA_FREE` 字段监控碎片情况。
