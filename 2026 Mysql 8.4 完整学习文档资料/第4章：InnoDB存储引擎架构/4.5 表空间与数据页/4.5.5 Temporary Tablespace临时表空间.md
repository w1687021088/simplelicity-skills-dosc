# Temporary Tablespace 临时表空间

Temporary Tablespace（临时表空间）是 InnoDB 专门用于存储临时表和临时操作数据的表空间，对应数据目录中的 `ibtmp1` 文件。MySQL 每次启动时自动创建，正常关闭时自动删除（不持久化），因此临时表空间中的数据在服务器重启后全部消失。MySQL 8.0 进一步引入了 Session Temporary Tablespace（会话临时表空间），专门为用户会话的临时表使用，与全局临时表空间分离。

---

## 临时表空间的分类

```
MySQL 8.0 的临时表空间分为两类：

1. Global Temporary Tablespace（全局临时表空间）
   文件：ibtmp1
   用途：内部临时表（如 GROUP BY 结果、ORDER BY 排序缓冲溢出时）
   生命周期：MySQL 启动时创建，正常关闭时删除

2. Session Temporary Tablespaces（会话临时表空间）
   文件：#innodb_temp/temp_1.ibt, temp_2.ibt ... （最多 400 个）
   用途：用户显式创建的临时表（CREATE TEMPORARY TABLE）
   生命周期：会话结束后，表空间内容清空（文件保留复用）
   目录：datadir/#innodb_temp/
```

## 全局临时表空间配置

```sql
-- 查看全局临时表空间配置
SHOW VARIABLES LIKE 'innodb_temp_data_file_path';
-- 默认：ibtmp1:12M:autoextend
-- 格式与 innodb_data_file_path 相同

-- 限制临时表空间最大大小（防止临时查询占用过多磁盘）
-- [mysqld]
-- innodb_temp_data_file_path = ibtmp1:12M:autoextend:max:2G
-- 超过 2G 后报错（通常是查询问题，如大排序/大 GROUP BY）

-- 查看临时表空间文件
-- （Linux）ls -la /var/lib/mysql/ibtmp1
-- ibtmp1 每次 MySQL 启动时从头创建，大小从初始值开始

-- 查看当前临时表空间使用情况
SELECT FILE_NAME, FILE_TYPE, TABLESPACE_NAME,
       ALLOCATED_SIZE / 1024 / 1024 AS allocated_mb,
       FILE_SIZE / 1024 / 1024 AS file_size_mb
FROM information_schema.FILES
WHERE TABLESPACE_NAME = 'innodb_temporary';
```

## 会话临时表空间（MySQL 8.0+）

```sql
-- 查看会话临时表空间目录
SHOW VARIABLES LIKE 'innodb_temp_tablespaces_dir';
-- 默认：#innodb_temp（相对于 datadir 的子目录）

-- 查看会话临时表空间池的大小
SHOW VARIABLES LIKE 'innodb_temp_tablespace%';
-- innodb_temp_tablespace_encrypt（默认 OFF）：是否加密临时表空间

-- 查看会话临时表空间使用情况
SELECT
    ID,
    SPACE,
    PATH,
    SIZE / 1024 AS size_kb,
    STATE,
    PURPOSE
FROM information_schema.INNODB_SESSION_TEMP_TABLESPACES;
-- STATE: ACTIVE（被会话使用中）或 INACTIVE（空闲可复用）
-- PURPOSE: INTRINSIC（内部临时表）或 USER（用户临时表）

-- 创建用户临时表（使用会话临时表空间）
CREATE TEMPORARY TABLE tmp_orders AS
SELECT * FROM orders WHERE status = 'pending';

-- 验证临时表使用了会话临时表空间
SELECT * FROM information_schema.INNODB_SESSION_TEMP_TABLESPACES
WHERE STATE = 'ACTIVE';
```

## 临时表与内存临时表

```sql
-- 临时表的存储位置决策：

-- 优先使用内存（TempTable 引擎，MySQL 8.0 默认）：
SHOW VARIABLES LIKE 'internal_tmp_mem_storage_engine';
-- MySQL 8.0：TempTable（取代旧的 MEMORY 引擎）
-- 内存临时表的大小限制：
SHOW VARIABLES LIKE 'temptable_max_ram';
-- 默认：1073741824（1 GB）

-- 当内存临时表超过 temptable_max_ram 时：
-- → 溢出到 ibtmp1 或会话临时表空间（磁盘）
SHOW VARIABLES LIKE 'temptable_max_mmap';
-- 默认：1073741824（1 GB）溢出到内存映射文件

-- 超过 temptable_max_mmap 后，再溢出到 InnoDB 临时表空间（ibtmp1）

-- 监控临时表使用
SHOW STATUS LIKE 'Created_tmp%';
-- Created_tmp_disk_tables：使用了磁盘临时表的次数（越低越好）
-- Created_tmp_tables：所有临时表次数
-- Created_tmp_files：创建的临时文件次数
-- 如果 Created_tmp_disk_tables / Created_tmp_tables 比例高，
-- 说明大量临时表溢出到磁盘，考虑增大 temptable_max_ram
```

## 临时表空间膨胀的处理

```sql
-- ibtmp1 异常增大的原因：
-- 1. 复杂查询产生大量临时结果（如大表 JOIN 后排序）
-- 2. 未优化的大 GROUP BY / ORDER BY
-- 3. 某个会话中有未关闭的临时表（持续占用空间）

-- 查看导致临时表膨胀的 SQL（通过 performance_schema）
SELECT
    st.sql_text,
    s.USER, s.HOST,
    s.COMMAND,
    s.TIME
FROM performance_schema.events_statements_current s
JOIN performance_schema.events_statements_history_long st
    ON s.THREAD_ID = st.THREAD_ID
WHERE s.CREATED_TMP_DISK_TABLES > 0
ORDER BY s.CREATED_TMP_DISK_TABLES DESC
LIMIT 10;

-- 临时解决 ibtmp1 过大（重启 MySQL 会自动清理）：
-- 不建议强制 kill，应先分析并优化查询

-- 限制最大临时表空间大小防止磁盘耗尽：
-- [mysqld]
-- innodb_temp_data_file_path = ibtmp1:12M:autoextend:max:8G
```

---

## 适用场景

- **复杂查询优化**：`Created_tmp_disk_tables` 过高时，增大 `temptable_max_ram`（调整为 2-4GB）减少磁盘临时表的使用
- **磁盘保护**：通过 `innodb_temp_data_file_path` 设置 `max` 上限，防止失控的查询将磁盘全部占满

## 常见问题

**MySQL 重启后磁盘多出来的空间是被 ibtmp1 占用了，如何处理？**

`ibtmp1` 是临时表空间，MySQL 正常关闭后会自动删除，下次启动重新创建。如果磁盘空间被 `ibtmp1` 大量占用，说明有查询或会话长期使用了大量临时表数据。解决方法：找到并终止使用大量临时表的会话（`SELECT * FROM information_schema.INNODB_SESSION_TEMP_TABLESPACES` 和 `processlist`），或正常重启 MySQL 让 `ibtmp1` 自动清理重建。

---

## 注意事项

- MySQL 重启后 `ibtmp1` 会从初始大小重新开始（12MB），历史积累的大小清零。这是临时表空间与系统表空间（ibdata1 只增不减）的重要区别。如果发现 `ibtmp1` 很大，等 MySQL 重启就会恢复，但这不是根本解决方案，应找到产生大量临时数据的 SQL 并优化。
- MySQL 8.0 引入的会话临时表空间（`#innodb_temp/temp_*.ibt`）不随会话结束而删除文件（文件留存在池中复用），只是内容被清空。这些文件的总数量最多 400 个，总文件数是固定的，单个文件大小会自动扩展。

---

## 总结

Temporary Tablespace 分为全局（`ibtmp1`，MySQL 启动创建，关闭删除）和会话级（`#innodb_temp/temp_*.ibt`，MySQL 8.0 引入，按会话管理）两类。临时表优先使用内存（TempTable 引擎，上限 `temptable_max_ram=1GB`），超出后溢出到磁盘临时表空间。通过 `Created_tmp_disk_tables` 监控磁盘临时表使用率，通过 `innodb_temp_data_file_path` 设置 `max` 防止磁盘被耗尽。
