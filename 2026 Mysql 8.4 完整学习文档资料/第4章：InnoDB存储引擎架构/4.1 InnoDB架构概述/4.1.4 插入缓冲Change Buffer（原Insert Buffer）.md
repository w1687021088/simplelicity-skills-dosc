# 插入缓冲 Change Buffer（原 Insert Buffer）

Change Buffer 是 InnoDB 针对**非唯一二级索引**的写入优化机制。当对二级索引页进行写操作（INSERT/UPDATE/DELETE）时，如果该索引页不在 Buffer Pool 中，InnoDB 不会立即将索引页读入内存再修改，而是将这次变更记录缓存在 Change Buffer 中，待后续该索引页被读入 Buffer Pool 时（合并时机），再统一将 Change Buffer 中的变更合并到对应页上。这避免了大量随机 I/O 读取索引页的开销。

---

## Change Buffer 的演变历史

- **MySQL 5.0 及之前**：只支持 INSERT 操作的缓冲，称为 Insert Buffer
- **MySQL 5.5+**：扩展为支持 INSERT、DELETE、UPDATE 操作，改名 Change Buffer
- **MySQL 8.0+**：Change Buffer 仍存储在系统表空间（ibdata1）的固定区域

---

## Change Buffer 工作原理

```
写操作流程（无 Change Buffer 优化）：
INSERT INTO orders (user_id, amount) VALUES (100, 99.99);
→ 修改聚簇索引页（通常在 Buffer Pool 中或顺序写）
→ 修改二级索引 idx_user_id 的对应页
  → 如果该页不在 Buffer Pool：从磁盘随机读入（慢）
  → 修改内存中的页
  → 脏页等待刷盘

写操作流程（有 Change Buffer 优化）：
INSERT INTO orders (user_id, amount) VALUES (100, 99.99);
→ 修改聚簇索引页（通常在 Buffer Pool 中）
→ 修改二级索引 idx_user_id 的对应页
  → 如果该页不在 Buffer Pool：不读磁盘！
  → 将此次变更记录到 Change Buffer（内存和 ibdata1）
  → 操作完成（避免了一次随机磁盘读）

合并时机：
① 后续有查询需要读取该二级索引页时（读合并）
② InnoDB 后台线程周期性合并（Master Thread）
③ MySQL 正常关闭时
```

## Change Buffer 的限制条件

```sql
-- Change Buffer 只对"非唯一二级索引"有效
-- 原因：唯一索引写入时必须立即读入索引页检查唯一性约束
-- 非唯一索引无需检查唯一性，可以延迟合并

-- 以下情况不使用 Change Buffer：
-- 1. 聚簇索引（主键索引）的修改
-- 2. 唯一二级索引的修改（UNIQUE KEY）
-- 3. 索引页已在 Buffer Pool 中（直接修改即可，不需要缓冲）
-- 4. innodb_change_buffering = NONE 时

-- 验证：创建表并观察 Change Buffer 使用情况
CREATE TABLE orders (
    id         BIGINT AUTO_INCREMENT PRIMARY KEY,          -- 聚簇索引，不用 Change Buffer
    user_id    INT NOT NULL,                               -- 非唯一二级索引，使用 Change Buffer
    order_no   VARCHAR(32) UNIQUE,                         -- 唯一索引，不用 Change Buffer
    amount     DECIMAL(10, 2),
    created_at DATETIME,
    INDEX idx_user_id (user_id)                            -- 非唯一索引 ✓ Change Buffer 有效
) ENGINE = InnoDB;
```

## Change Buffer 相关参数

```sql
-- 查看 Change Buffer 相关配置
SHOW VARIABLES LIKE 'innodb_change_buffer%';
-- +-------------------------------+---------+
-- | Variable_name                 | Value   |
-- +-------------------------------+---------+
-- | innodb_change_buffering       | all     | -- 缓冲类型：all/none/inserts/deletes/changes/purges
-- | innodb_change_buffer_max_size | 25      | -- 占 Buffer Pool 的最大比例（%）
-- +-------------------------------+---------+

-- innodb_change_buffering 选项：
-- all      (默认)：缓冲所有类型（inserts + deletes + purges）
-- none     ：禁用 Change Buffer
-- inserts  ：只缓冲 insert 操作
-- deletes  ：只缓冲 delete 标记操作
-- changes  ：缓冲 inserts + deletes
-- purges   ：只缓冲后台清理操作

-- innodb_change_buffer_max_size：Change Buffer 占 Buffer Pool 的最大比例
-- 默认 25%，范围 0-50
-- 对于写操作密集的系统，可以适当增大；对于读操作为主的系统，可以减小
SET GLOBAL innodb_change_buffer_max_size = 25;
```

## 监控 Change Buffer 状态

```sql
-- 查看 Change Buffer 当前状态（在 SHOW ENGINE INNODB STATUS 输出中）
SHOW ENGINE INNODB STATUS \G
-- 查找 INSERT BUFFER AND ADAPTIVE HASH INDEX 部分：
-- Ibuf: size 1, free list len 0, seg size 2, 0 merges
-- merged operations:
--  insert 0, delete mark 0, delete 0
-- discarded operations:
--  insert 0, delete mark 0, delete 0

-- 通过 information_schema 查看
SELECT * FROM information_schema.INNODB_METRICS
WHERE NAME LIKE 'ibuf%';
-- ibuf_merges：Change Buffer 合并次数
-- ibuf_merges_insert：插入合并次数
-- ibuf_size：Change Buffer 当前占用页数
-- ibuf_free_list：空闲链表长度

-- 查看 Buffer Pool 状态中的 Change Buffer 信息
SHOW STATUS LIKE 'Innodb_ibuf%';
-- 注意：STATUS 中 Innodb_ibuf_xxx 变量显示 Change Buffer 统计
```

## Change Buffer 对性能的影响

```sql
-- 适合使用 Change Buffer 的场景（收益大）：
-- 1. 批量 INSERT 操作（大量记录插入，二级索引页分散在磁盘各处）
-- 2. 写操作比读操作多
-- 3. Buffer Pool 较小，无法缓存大多数索引页
-- 4. 索引基数高（值分布均匀，索引页分散）

-- 不太需要 Change Buffer 的场景：
-- 1. 写入后立即读取（Change Buffer 来不及合并就被强制读合并）
-- 2. 大 Buffer Pool（大多数索引页都在内存中，无需 Change Buffer）
-- 3. SSD（随机读 I/O 很快，Change Buffer 的收益减小）
```

---

## 适用场景

- **批量数据导入**：大批量 INSERT 时，Change Buffer 大幅减少随机 I/O，加速导入速度
- **低峰期写入密集**：夜间批处理写入，Change Buffer 积累变更，减少实时 I/O 压力
- **日志类表**：只有普通二级索引（非唯一），高频写入时 Change Buffer 收益最大

## 常见问题

**Change Buffer 中的数据如果 MySQL 崩溃了，会丢失吗？**

不会丢失。Change Buffer 的内容会持久化到系统表空间（ibdata1），同时 Change Buffer 的修改也受 Redo Log 保护。MySQL 崩溃重启后，通过 Redo Log 恢复 Change Buffer 中的未完成操作，再在合适时机与索引页合并。

---

## 注意事项

- 如果 `innodb_change_buffer_max_size` 设置得过大，Change Buffer 会占用过多 Buffer Pool 空间，挤占数据页和索引页的缓存空间，反而可能降低查询性能。对于读多写少的系统，建议将此值调小（如 10-15%）。
- MySQL 8.4 中 Change Buffer 仍然存储在 `ibdata1` 系统表空间，这是 InnoDB 存储架构的历史遗留，尚未像 Doublewrite Buffer 那样迁移到独立文件。

---

## 总结

Change Buffer（原 Insert Buffer）缓冲对非唯一二级索引的写操作（INSERT/UPDATE/DELETE），避免在索引页不在 Buffer Pool 时产生随机磁盘读取，在写操作密集的场景下显著减少 I/O 开销。通过 `innodb_change_buffering = all`（默认）开启，`innodb_change_buffer_max_size`（默认 25%）控制其占 Buffer Pool 的比例。唯一索引和聚簇索引不能使用 Change Buffer，因为它们需要立即检查唯一性。
