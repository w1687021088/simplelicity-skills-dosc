# 存储引擎插件架构

MySQL 采用可插拔存储引擎（Pluggable Storage Engine）架构，将 SQL 解析、查询优化、缓存管理等上层逻辑与底层数据存储分离。不同存储引擎可以独立实现数据的读写、事务处理、索引结构、锁机制等，服务层通过统一的 Handler API 与任意引擎交互。这种设计使 MySQL 能够针对不同业务场景选择最合适的存储方式。

---

## 整体分层架构

```
┌─────────────────────────────────────────────────────────┐
│                    MySQL 服务层                          │
│  连接管理 │ 权限验证 │ SQL解析 │ 查询优化 │ 查询缓存     │
├─────────────────────────────────────────────────────────┤
│                   Handler API（存储引擎接口）             │
│   ha_write_row() │ ha_read_row() │ ha_index_read() ...  │
├──────────┬──────────┬───────────┬──────────────────────┤
│  InnoDB  │  MyISAM  │  MEMORY   │  ARCHIVE / CSV / ... │
│ （默认） │          │           │                      │
└──────────┴──────────┴───────────┴──────────────────────┘
```

- **服务层**：处理连接、认证、SQL 解析、查询优化，与具体存储引擎无关
- **Handler API**：存储引擎实现的统一接口，服务层通过它调用底层读写操作
- **存储引擎层**：各引擎独立管理数据文件、索引文件、事务日志

## 查看可用存储引擎

```sql
-- 查看当前 MySQL 实例支持的存储引擎
SHOW ENGINES;
-- +--------------------+---------+-----------------------------------------------------+
-- | Engine             | Support | Comment                                             |
-- +--------------------+---------+-----------------------------------------------------+
-- | InnoDB             | DEFAULT | Supports transactions, row-level locking, and ...  |
-- | MyISAM             | YES     | MyISAM storage engine                               |
-- | MEMORY             | YES     | Hash based, stored in memory, useful for temp tables|
-- | CSV                | YES     | CSV storage engine                                  |
-- | ARCHIVE            | YES     | Archive storage engine                              |
-- | BLACKHOLE          | YES     | /dev/null storage engine (anything written vanishes)|
-- | PERFORMANCE_SCHEMA | YES     | Performance Schema                                  |
-- | MRG_MYISAM         | YES     | Collection of identical MyISAM tables               |
-- | FEDERATED          | NO      | Federated MySQL storage engine                      |
-- +--------------------+---------+-----------------------------------------------------+

-- 查看当前默认存储引擎
SHOW VARIABLES LIKE 'default_storage_engine';
-- InnoDB

-- 查看表使用的存储引擎
SHOW CREATE TABLE orders;
-- ENGINE=InnoDB

SELECT TABLE_NAME, ENGINE FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'myapp';
```

## 存储引擎的指定方式

```sql
-- 创建表时指定存储引擎
CREATE TABLE log_archive (
    id       BIGINT AUTO_INCREMENT PRIMARY KEY,
    log_text TEXT,
    created  DATETIME
) ENGINE = ARCHIVE;

-- 修改表的存储引擎（会重建整张表，对大表有较大影响）
ALTER TABLE old_table ENGINE = InnoDB;

-- 修改默认存储引擎（会话级）
SET SESSION default_storage_engine = 'InnoDB';

-- 修改默认存储引擎（全局级，重启失效）
SET GLOBAL default_storage_engine = 'InnoDB';

-- 持久化到 my.cnf：
-- [mysqld]
-- default-storage-engine = InnoDB
```

## Handler API 核心接口

存储引擎插件通过继承 `handler` 基类并实现以下虚函数来接入 MySQL：

| 接口方法 | 功能 |
|---------|------|
| `ha_write_row()` | 插入一行数据 |
| `ha_update_row()` | 更新一行数据 |
| `ha_delete_row()` | 删除一行数据 |
| `ha_index_read()` | 通过索引读取记录 |
| `ha_rnd_next()` | 全表扫描下一行 |
| `ha_commit()` | 提交事务 |
| `ha_rollback()` | 回滚事务 |
| `ha_create()` | 创建表（创建底层文件）|
| `ha_drop_table()` | 删除表 |

服务层不关心底层是 InnoDB 的 B+ 树页面还是 MEMORY 的哈希表，统一通过这些接口操作。

## InnoDB 插件的加载机制

```sql
-- InnoDB 在 MySQL 8.0+ 作为内建插件编译进 mysqld，不能卸载
-- 查看插件信息
SELECT PLUGIN_NAME, PLUGIN_STATUS, PLUGIN_TYPE, PLUGIN_LIBRARY
FROM information_schema.PLUGINS
WHERE PLUGIN_NAME LIKE 'InnoDB%';

-- 尝试卸载 InnoDB 会失败：
-- UNINSTALL PLUGIN InnoDB;
-- ERROR 1721 (HY000): Plugin 'InnoDB' is a mandatory plugin and cannot be uninstalled

-- 第三方存储引擎（如 RocksDB、TokuDB）作为独立 .so 文件加载：
INSTALL PLUGIN RocksDB SONAME 'ha_rocksdb.so';
```

## 各存储引擎特性对比

| 特性 | InnoDB | MyISAM | MEMORY | ARCHIVE |
|------|--------|--------|--------|---------|
| 事务支持 | 是 | 否 | 否 | 否 |
| 行级锁 | 是 | 否（表锁）| 否（表锁）| 否 |
| 外键约束 | 是 | 否 | 否 | 否 |
| 崩溃恢复 | 是（Redo Log）| 部分 | 否（内存丢失）| 否 |
| 全文索引 | 是（5.6+）| 是 | 否 | 否 |
| 数据文件 | .ibd | .MYD + .MYI | 内存 | .ARZ |
| 适合场景 | 通用 OLTP | 读多写少 | 临时数据 | 日志归档 |

## 适用场景

- **InnoDB（默认选择）**：绝大多数业务场景，需要事务、行锁、崩溃安全的场景
- **MEMORY**：需要极高读写速度的临时数据（如会话缓存），但数据不需要持久化
- **ARCHIVE**：只写不改的日志、审计数据归档，压缩率高

---

## 常见问题

**混用不同存储引擎时，跨引擎事务如何处理？**

MySQL 不支持跨存储引擎的原子事务。如果在同一个事务中同时操作 InnoDB 表和 MyISAM 表，InnoDB 部分可以回滚，MyISAM 部分无法回滚（因为 MyISAM 不支持事务）。因此在需要事务的业务中，应避免混用不支持事务的存储引擎。

---

## 注意事项

- `ALTER TABLE ... ENGINE=InnoDB` 是重建整张表的操作，会在旧表上加 MDL 锁（元数据锁），在 MySQL 8.0+ 中使用 Online DDL 可以降低影响，但对超大表仍需在低峰期执行或使用 `pt-online-schema-change` 等工具。
- 使用第三方存储引擎时，需要确认其与当前 MySQL 版本的兼容性，不是所有第三方插件都支持最新版本的 Handler API。

---

## 总结

MySQL 的可插拔存储引擎架构通过 Handler API 将服务层与存储层解耦，InnoDB 作为默认引擎（DEFAULT）内建于 MySQL 8.4，支持事务、行级锁、MVCC 和崩溃恢复。`SHOW ENGINES` 查看所有可用引擎，`ENGINE=xxx` 子句指定表引擎，`ALTER TABLE ... ENGINE=InnoDB` 迁移引擎（会重建表）。生产环境中 InnoDB 是绝大多数场景的首选，其他引擎只在特定场景（归档、临时表等）使用。
