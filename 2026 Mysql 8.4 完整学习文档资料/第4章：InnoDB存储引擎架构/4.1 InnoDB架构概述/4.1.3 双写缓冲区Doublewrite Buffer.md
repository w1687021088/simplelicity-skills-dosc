# 双写缓冲区 Doublewrite Buffer

Doublewrite Buffer（双写缓冲区）是 InnoDB 防止"部分写（Partial Write / Torn Page）"问题的关键机制。数据页从 Buffer Pool 刷写到磁盘时，InnoDB 先将数据页写入 Doublewrite Buffer 区域，确认写入成功后再写到数据文件中的实际位置。即使在写入数据文件的过程中发生崩溃，InnoDB 在恢复时可以从 Doublewrite Buffer 中找到完整的页副本，避免数据页损坏。

---

## 部分写问题的背景

```
数据库页大小：16 KB（InnoDB 默认）
操作系统 I/O 原子单元：512 B（传统磁盘）或 4 KB（现代 SSD）

问题场景：
InnoDB 正在将一个 16 KB 的页写到磁盘，写入一半时（如写完 8 KB）系统崩溃
→ 磁盘上存储的是一个"半新半旧"的页（部分写/撕裂页）
→ Redo Log 记录的是"对完整旧页做的变更"，无法用来修复损坏的页
→ 因此仅有 Redo Log 无法解决部分写问题
```

---

## Doublewrite Buffer 的工作流程

```
Buffer Pool 脏页刷盘流程：

① 将多个脏页（通常 64 个一批）收集到内存中的 Doublewrite Buffer
② 将内存 Doublewrite Buffer 一次性顺序写到 Doublewrite 文件
   （顺序写，I/O 效率高）
③ 调用 fsync() 确保 Doublewrite 文件已持久化到磁盘
④ 将各数据页写到 .ibd 文件中对应的实际位置（随机写）

崩溃发生在步骤④（写 .ibd 时）：
→ 重启后，InnoDB 检查 .ibd 中的页是否有效
→ 发现损坏的页：从 Doublewrite 文件中读取完整副本
→ 将副本写回 .ibd 正确位置
→ 应用 Redo Log 追回提交的变更（如果有）
```

## MySQL 8.0.20+ 的变化：独立 Doublewrite 文件

```sql
-- MySQL 8.0.20 之前：Doublewrite Buffer 区域存储在系统表空间（ibdata1）中
-- MySQL 8.0.20+：Doublewrite Buffer 存储在独立的 .dblwr 文件中
-- 好处：
-- 1. 不再污染 ibdata1
-- 2. 可以配置存放在不同的磁盘（配合 innodb_doublewrite_dir）
-- 3. 支持更灵活的大小配置

-- 查看 Doublewrite 文件
SHOW VARIABLES LIKE 'innodb_doublewrite_dir';
-- 默认：与数据目录相同（datadir）

SHOW VARIABLES LIKE 'innodb_doublewrite_files';
-- 默认：2 * innodb_buffer_pool_instances（每个 Buffer Pool 实例 2 个文件）

-- 查看 Doublewrite 文件路径（数据目录中的 #ib_xxx.dblwr 文件）
-- 文件命名：#ib_<buffer_pool_instance_id>_<file_id>.dblwr
```

## Doublewrite Buffer 参数配置

```sql
-- 查看相关参数
SHOW VARIABLES LIKE 'innodb_doublewrite%';
-- +----------------------------------+-------+
-- | Variable_name                    | Value |
-- +----------------------------------+-------+
-- | innodb_doublewrite               | ON    | -- 是否开启（默认 ON）
-- | innodb_doublewrite_batch_size    | 0     | -- 批次大小（0=自动）
-- | innodb_doublewrite_dir           |       | -- 文件目录（默认 datadir）
-- | innodb_doublewrite_files         | 2     | -- 文件数量
-- | innodb_doublewrite_pages         | 4     | -- 每批次页数（MySQL 8.0.20+）
-- +----------------------------------+-------+

-- innodb_doublewrite 的四种模式（MySQL 8.0.20+）：
-- ON（默认）：完整 doublewrite 保护
-- OFF：关闭 doublewrite（性能更高，但无部分写保护，不推荐生产）
-- DETECT_AND_RECOVER：与 ON 相同（完整恢复）
-- DETECT_ONLY：仅检测部分写但不从 doublewrite 恢复
--   （适合底层文件系统/设备已保证原子写的场景，如 ZFS、Fusion-io）

-- 在 my.cnf 中配置：
-- [mysqld]
-- innodb_doublewrite = ON
-- innodb_doublewrite_dir = /fast_ssd/mysql_dblwr
```

## Doublewrite 的性能影响

```sql
-- 监控 Doublewrite 写入情况
SHOW STATUS LIKE 'Innodb_dblwr_%';
-- +----------------------------+---------+
-- | Variable_name              | Value   |
-- +----------------------------+---------+
-- | Innodb_dblwr_pages_written | 2847392 | -- 总共写入 Doublewrite 的页数
-- | Innodb_dblwr_writes        | 85623   | -- Doublewrite 写操作次数
-- +----------------------------+---------+

-- 写放大分析：
-- Innodb_dblwr_pages_written / Innodb_dblwr_writes ≈ 33
-- 平均每次 Doublewrite 写操作写约 33 个页
-- 理想状态：接近 64（批处理上限），说明 Doublewrite 效率高

-- 性能成本：
-- 额外写入量约为 2/64 * 数据量（约 3%），实际开销因顺序写而相对较小
-- 在 SSD 上，Doublewrite 的顺序写特性使其性能开销更低
```

## 何时可以关闭 Doublewrite

```sql
-- 以下情况可考虑关闭 innodb_doublewrite = OFF：
-- 1. 使用支持原子写的文件系统（ZFS 的 atomic write、Btrfs）
-- 2. 使用提供原子 4K/16K 写入的 SSD/NVMe 设备
-- 3. MySQL 在从库上作为备份副本，宕机后可以重新构建
-- 4. 开发/测试环境，追求最大 I/O 性能

-- 注意：关闭 Doublewrite 后，如果发生部分写，数据页会损坏
-- 且 Redo Log 无法修复损坏的页，需要从备份恢复
-- 生产主库不应关闭 Doublewrite
```

---

## 适用场景

- **生产环境（默认 ON）**：任何机械磁盘或不保证原子写的 SSD 环境都应保持开启
- **高 I/O 压力优化**：将 Doublewrite 文件（`innodb_doublewrite_dir`）移到高速 SSD，减少主数据目录的 I/O 竞争
- **ZFS/Btrfs 文件系统**：可设置为 `DETECT_ONLY` 或 `OFF`，利用文件系统的原子写保证

---

## 常见问题

**Doublewrite Buffer 和 Buffer Pool 的关系是什么？**

Doublewrite Buffer 不是 Buffer Pool 的一部分，两者相互独立。Buffer Pool 是数据页的内存缓存（用于加速读写操作），Doublewrite Buffer 是数据页刷盘时的中转站（保证写入安全性）。Buffer Pool 中的脏页在刷盘时，先经过 Doublewrite Buffer 写入磁盘，再写到数据文件的实际位置。

---

## 注意事项

- 在 MySQL 8.0.20+ 中，Doublewrite 文件（`.dblwr`）独立于 `ibdata1`，可以通过 `innodb_doublewrite_dir` 将其放在独立的高速磁盘上，以减少与数据文件的 I/O 竞争，这对高并发写入的系统有明显的性能提升。
- `innodb_doublewrite_pages` 参数（MySQL 8.0.20+）控制单批次 Doublewrite 写入的页数，默认为 0（自动根据 `innodb_write_io_threads` 计算），一般不需要手动调整。

---

## 总结

Doublewrite Buffer 解决了 InnoDB 数据页从内存（Buffer Pool）刷写到磁盘时，因操作系统页大小（4KB）与数据库页大小（16KB）不匹配而导致的"部分写/撕裂页"问题。写入流程：先批量顺序写到 Doublewrite 文件 → fsync 持久化 → 再写到 .ibd 数据文件。MySQL 8.0.20+ 将 Doublewrite 区域从 ibdata1 迁移到独立 `.dblwr` 文件。生产环境保持 `innodb_doublewrite=ON`，可将 .dblwr 文件移到独立 SSD 提升性能。
