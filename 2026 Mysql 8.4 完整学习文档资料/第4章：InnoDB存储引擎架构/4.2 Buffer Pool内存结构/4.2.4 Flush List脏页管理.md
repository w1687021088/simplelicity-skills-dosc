# Flush List 脏页管理

Flush List 是 Buffer Pool 中记录所有脏页（Dirty Page）的有序链表。当一个缓存页被修改后，它会被加入 Flush List，并记录修改时的 LSN（Log Sequence Number）。后台页清理线程（Page Cleaner Thread）按照 Flush List 中的 LSN 顺序将脏页刷写到磁盘，同时驱动 Checkpoint 推进，确保 Redo Log 可以被循环使用。

---

## Flush List 的结构与排序

```
Flush List 特点：
- 按照页首次被修改时的 LSN 从小到大排列（老 LSN 在尾部，新 LSN 在头部）
- 同一个页可能被多次修改，但在 Flush List 中只出现一次
  （以首次加入时的 LSN 为排序键，后续修改不更新其在 Flush List 中的位置）
- 每个 Buffer Pool 实例有自己独立的 Flush List

Flush List 链表：
[最新修改页(LSN=1000)] ↔ [LSN=900页] ↔ ... ↔ [最老修改页(LSN=100)]
        头部                                        尾部
                                                  ↑ Checkpoint 推进方向
```

## 脏页的产生与刷盘

```sql
-- 脏页产生：任何 DML 操作（INSERT/UPDATE/DELETE）都会产生脏页
-- 当缓存页被修改时：
-- 1. 修改内存中的页数据
-- 2. 写入 Redo Log（WAL：先写日志）
-- 3. 将该页标记为脏页，加入 Flush List（如果还未加入）
-- 4. 操作完成（不立即刷盘）

-- 脏页刷盘的触发条件：
-- 1. 后台 Page Cleaner 线程周期性刷盘（正常情况）
-- 2. 脏页比例超过 innodb_max_dirty_pages_pct（默认 90%）→ 强制刷盘
-- 3. Redo Log 空间不足（Checkpoint 压力）→ 强制刷盘
-- 4. LRU List 尾部需要驱逐一个脏页 → 立即刷盘
-- 5. MySQL 正常关闭时 → 全部脏页刷盘

-- 查看当前脏页状态
SHOW STATUS LIKE 'Innodb_buffer_pool_pages_dirty';
SHOW STATUS LIKE 'Innodb_buffer_pool_pages_flushed';
```

## Page Cleaner 线程

```sql
-- Page Cleaner 线程负责将 Flush List 中的脏页刷写到磁盘
-- MySQL 5.6：只有 1 个 Page Cleaner 线程
-- MySQL 5.7+：多个 Page Cleaner 线程（innodb_page_cleaners）

-- 查看 Page Cleaner 线程数
SHOW VARIABLES LIKE 'innodb_page_cleaners';
-- 默认：4（MySQL 8.0）
-- 建议等于 innodb_buffer_pool_instances

-- Page Cleaner 的工作：
-- 1. 从每个 Buffer Pool 实例的 Flush List 尾部取出最老的脏页
-- 2. 调用 Doublewrite Buffer 写入（见 4.1.3）
-- 3. 写入数据文件（.ibd）的实际位置
-- 4. 将页从 Flush List 移除，标记为干净页

-- 查看刷盘速率
SHOW STATUS LIKE 'Innodb_buffer_pool_pages_flushed';
-- 累计刷盘页数

-- 查看 Page Cleaner 线程状态
SELECT NAME, TYPE, STATE
FROM performance_schema.threads
WHERE NAME LIKE '%page_clean%';
```

## 自适应刷盘（Adaptive Flushing）

```sql
-- InnoDB 的自适应刷盘机制根据 Redo Log 的使用情况动态调整刷盘速率
-- 防止 Redo Log 被写满（写满后需要等待 Checkpoint，导致写入停顿）

-- 关键参数：
SHOW VARIABLES LIKE 'innodb_adaptive_flushing%';
-- innodb_adaptive_flushing：是否开启自适应刷盘（默认 ON）
-- innodb_adaptive_flushing_lwm：Redo Log 低水位（默认 10%）
--   低于此值：减慢刷盘速率
--   高于此值：自适应加速刷盘

-- 刷盘速率上限控制：
SHOW VARIABLES LIKE 'innodb_io_capacity%';
-- innodb_io_capacity：I/O 子系统的估计性能（默认 200，单位 IOPS）
-- innodb_io_capacity_max：最大 I/O 容量（默认 2000）
-- Page Cleaner 的刷盘速率不超过 innodb_io_capacity（正常）
-- 不超过 innodb_io_capacity_max（紧急情况）

-- SSD 优化配置建议：
-- SET PERSIST innodb_io_capacity = 2000;
-- SET PERSIST innodb_io_capacity_max = 4000;
```

## Flush List 与 LRU List 的关系

```sql
-- 一个脏页同时在两个链表中：
-- Flush List：按首次修改 LSN 排序（用于按顺序刷盘）
-- LRU List：按最近访问时间排序（用于决定驱逐顺序）
-- 两个链表服务于不同目的，互不干扰

-- 脏页的生命周期：
-- 从 Free List 取出 → 读入数据 → 在 LRU List 中（干净页）
-- 被修改 → 加入 Flush List（脏页）
-- 后台刷盘 → 从 Flush List 移除（干净页，仍在 LRU）
-- 被驱逐 → 从 LRU List 移除 → 回到 Free List

-- 特殊情况：LRU 需要驱逐一个脏页
-- → 立即刷盘（同步 I/O，影响当前操作的延迟！）
-- → 从 Flush List 和 LRU List 同时移除
-- → 回到 Free List
-- 这是 Innodb_buffer_pool_wait_free 增加的原因之一
```

## 监控脏页与刷盘情况

```sql
-- 完整的脏页监控 SQL
SELECT
    pool_id,
    pool_size,
    database_pages,
    free_buffers,
    modified_database_pages AS dirty_pages,
    ROUND(modified_database_pages * 100.0 / pool_size, 2) AS dirty_pct,
    pages_made_young,
    pages_made_not_young
FROM information_schema.INNODB_BUFFER_POOL_STATS;

-- 查看 SHOW ENGINE INNODB STATUS 中的刷盘信息
-- 在 BUFFER POOL AND MEMORY 部分：
-- Modified db pages XX：当前脏页数量
-- Pending reads XX：待读取的页数
-- Pending writes: LRU XX, flush list XX, single page XX：
--   LRU XX：因驱逐需要的写
--   flush list XX：Page Cleaner 正在写
--   single page XX：因单页立即刷盘的写
```

## 适用场景

- **写密集型系统**：Flush List 越长（脏页越多），意味着积压了大量未刷盘的变更，需要监控脏页比例和 Page Cleaner 速率
- **Redo Log 容量规划**：Flush List 的老端 LSN 决定了 Redo Log 可以复用的空间，Flush List 太长（老脏页积压）会限制 Redo Log 的可用空间

## 常见问题

**MySQL 有时候写入突然变慢（周期性停顿），可能是 Flush List 相关问题吗？**

是的。当 Redo Log 空间紧张时，InnoDB 会强制触发大量脏页刷盘（Checkpoint 压力），导致 I/O 写入突然增大，表现为周期性写入停顿。解决方向：增大 `innodb_log_file_size`（Redo Log 文件大小）、增加 `innodb_io_capacity` 以允许更高的后台刷盘速率、或减少并发写入量。

---

## 注意事项

- `innodb_max_dirty_pages_pct`（默认 90%）是脏页比例的上限，触发强制刷盘，不是正常刷盘的目标值。正常情况下，自适应刷盘机制会将脏页比例维持在一个平衡点（通常 20-60%），不会等到 90% 才刷盘。
- 增大 `innodb_io_capacity` 和 `innodb_io_capacity_max` 能让 Page Cleaner 更快地刷盘，但也意味着更多的磁盘写入压力。对于机械硬盘要谨慎调大（默认值 200 已较合理）；SSD 可以大幅提升（2000-10000）。

---

## 总结

Flush List 按首次修改 LSN 排序记录所有脏页，后台 Page Cleaner 线程（`innodb_page_cleaners`，默认 4 个）从 Flush List 尾部按 LSN 顺序刷盘，推进 Checkpoint。自适应刷盘（`innodb_adaptive_flushing=ON`）根据 Redo Log 使用率动态调整刷盘速率。脏页比例通过 `Innodb_buffer_pool_pages_dirty / pages_total` 计算，超过 `innodb_max_dirty_pages_pct`（90%）时强制加速刷盘。SSD 环境下应提高 `innodb_io_capacity` 以充分利用 SSD 的写入能力。
