# Free List 空闲页管理

Free List 是 Buffer Pool 中维护空闲缓存页的双向链表。Buffer Pool 初始化完成后，所有缓存页都挂载到 Free List 中，等待被使用。当需要将磁盘页读入 Buffer Pool 时，InnoDB 从 Free List 中取出一个空闲页，分配给该数据页使用；当一个缓存页被驱逐（evict）后，它会重新归还到 Free List 中。

---

## Free List 的位置与作用

```
Buffer Pool 启动时的初始状态：

Free List: [page_0] ↔ [page_1] ↔ [page_2] ↔ ... ↔ [page_N]
           所有页都是空闲页

LRU List: 空
Flush List: 空

随着数据被读取/写入：
Free List: 页数逐渐减少（空闲页被分配出去）
LRU List:  页数逐渐增多（分配出去的页挂载到 LRU）
Flush List: 有脏页时增多
```

---

## 空闲页的分配流程

```
需要从磁盘读入一个新页时：

步骤1：从 Free List 取出一个空闲页
       → 如果 Free List 不空，直接取走，成功

步骤2：如果 Free List 为空（没有空闲页）：
       → 扫描 LRU List 尾部，找一个可以驱逐的页
       → 如果该页是干净页（clean page，非脏页）：直接驱逐，将页地址放回 Free List
       → 如果该页是脏页（dirty page）：先刷写到磁盘，再驱逐
       → 如果以上都无法及时完成：等待（Innodb_buffer_pool_wait_free 计数+1）

步骤3：将分配到的空闲页用于存放新读入的数据
       → 将该页插入 LRU List 的 Old Sublist 头部（Midpoint）
```

## 监控 Free List 状态

```sql
-- 查看空闲页数量
SHOW STATUS LIKE 'Innodb_buffer_pool_pages_free';
-- 空闲页数越多，说明 Buffer Pool 还有余量
-- 接近 0 说明 Buffer Pool 几乎满了（不一定是问题，正常运行时应充分利用）

-- 查看 Buffer Pool 各部分页数
SHOW STATUS LIKE 'Innodb_buffer_pool_pages%';
-- Innodb_buffer_pool_pages_total：总页数（= innodb_buffer_pool_size / 16KB）
-- Innodb_buffer_pool_pages_data：被使用的页数（含干净页和脏页）
-- Innodb_buffer_pool_pages_free：空闲页数
-- Innodb_buffer_pool_pages_dirty：脏页数
-- 关系：pages_total = pages_data + pages_free + pages_misc
--      pages_misc：用于内部管理的页（自适应哈希索引、行锁信息等）

-- 关键告警指标：
-- Innodb_buffer_pool_wait_free > 0：说明有操作在等待空闲页
-- 这通常意味着 Buffer Pool 太小或后台刷盘跟不上写入速度
SHOW STATUS LIKE 'Innodb_buffer_pool_wait_free';
```

## Free List 与预读机制

```sql
-- InnoDB 的预读（Read-Ahead）机制会提前将磁盘页读入 Buffer Pool
-- 这会消耗 Free List 中的空闲页

-- 线性预读（Linear Read-Ahead）：
-- 顺序访问同一 extent（64页/1MB）中超过 innodb_read_ahead_threshold 个页时
-- 触发异步预读下一个 extent
SHOW VARIABLES LIKE 'innodb_read_ahead_threshold';
-- 默认：56（访问同一 extent 的 56 页后触发预读）

-- 随机预读（Random Read-Ahead）：
-- 当 Buffer Pool 中已有某个 extent 的 13 个以上连续页时触发
-- MySQL 5.5 之后默认关闭
SHOW VARIABLES LIKE 'innodb_random_read_ahead';
-- 默认：OFF

-- 预读消耗空闲页，但如果预读的页后续未被使用，它们会占用 LRU Old 区空间
-- 可以通过 Innodb_buffer_pool_read_ahead 和 Innodb_buffer_pool_read_ahead_evicted 评估预读效果
SHOW STATUS LIKE 'Innodb_buffer_pool_read_ahead%';
-- read_ahead：预读总页数
-- read_ahead_evicted：预读后未被访问就被驱逐的页数
-- evicted/read_ahead 比例高 → 预读效率低，考虑降低 innodb_read_ahead_threshold
```

## Buffer Pool 初始化与内存分配

```sql
-- MySQL 启动时，InnoDB 向操作系统申请 innodb_buffer_pool_size 大小的内存
-- 这是一次性的大块内存分配（mmap/VirtualAlloc）
-- 内存分配后，所有页都加入 Free List

-- 查看 Buffer Pool 初始化进度（大 Buffer Pool 启动较慢）
SHOW STATUS LIKE 'Innodb_buffer_pool_load_status';
-- 'Buffer pool(s) load completed at ...'

-- MySQL 8.0+ 支持启动时异步初始化（避免大 Buffer Pool 导致启动慢）
-- innodb_buffer_pool_load_at_startup=ON 时，异步加载上次的热点页
```

## 适用场景

- **Buffer Pool 使用率监控**：`pages_free / pages_total` 如果长期接近 0，说明 Buffer Pool 已被充分利用，这是正常现象；如果伴随 `wait_free > 0` 则需要扩容
- **内存压力评估**：定期检查 `Innodb_buffer_pool_wait_free`，发现大于 0 时需要分析是 Buffer Pool 太小还是脏页刷新太慢

---

## 常见问题

**Free List 为空是否意味着 Buffer Pool 不足？**

不一定。Free List 为空说明 Buffer Pool 已被完全使用，这在 Buffer Pool 充分利用的场景下是正常的（越空闲的内存越浪费）。判断 Buffer Pool 是否不足需要看 `Innodb_buffer_pool_wait_free`（等待空闲页的次数）和命中率（`Innodb_buffer_pool_reads` / `Innodb_buffer_pool_read_requests`）。只有当出现等待空闲页且命中率下降时，才需要考虑增大 Buffer Pool。

---

## 注意事项

- `Innodb_buffer_pool_pages_misc` 记录的是用于管理开销（自适应哈希索引、行锁信息、其他内部结构）的页数。这部分页不在 Free List 和 LRU List 中，属于 Buffer Pool 的固定开销，通常占 1-3%。
- 在 Buffer Pool 扩容（`SET GLOBAL innodb_buffer_pool_size`）期间，新分配的内存会被初始化为空闲页并加入 Free List，扩容过程是异步进行的，可以通过 `Innodb_buffer_pool_resize_status` 查看进度。

---

## 总结

Free List 是 Buffer Pool 中维护空闲缓存页的双向链表。Buffer Pool 初始化时所有页都在 Free List 中，随着数据被读入，空闲页逐渐被分配出去。当 Free List 为空时，InnoDB 通过驱逐 LRU 尾部的页来腾出空间。监控关键指标：`Innodb_buffer_pool_pages_free`（当前空闲页数）和 `Innodb_buffer_pool_wait_free`（等待空闲页次数，大于 0 需关注）。Free List 为空是正常运行状态，`wait_free > 0` 才是需要关注的信号。
