# Buffer Pool 预热与 Dump/Load

MySQL 重启后，Buffer Pool 是空的，所有数据需要重新从磁盘读入内存，这段时间内数据库响应时间会偏高（"冷启动"问题）。InnoDB 提供了 Buffer Pool Dump（转储）和 Load（加载）机制：在关闭前将 Buffer Pool 中的热点页信息（表空间 ID + 页号）保存到文件，重启后快速将这些热点页重新读入内存，大幅缩短热身时间。

---

## 冷启动问题

```
MySQL 重启后的 Buffer Pool 状态：

重启前：Buffer Pool 中缓存了大量热点数据（用户表、索引等）
重启后：Buffer Pool 完全为空（清空内存）

后果：
→ 前 N 分钟/小时，所有查询都需要从磁盘读取数据
→ 响应时间比正常时高出数倍甚至数十倍
→ 磁盘 I/O 突增，数据库陷入"预热期"

预热时间取决于：
→ Buffer Pool 大小
→ 磁盘读取速度
→ 热点数据量

典型场景：8GB Buffer Pool + 机械硬盘 → 预热可能需要数小时
```

---

## Dump/Load 机制的工作原理

```
Dump（转储热点页信息）：
1. 遍历每个 Buffer Pool 实例的 LRU List
2. 记录每个页的（表空间 ID, 页号）到 dump 文件
3. 不保存实际页数据（节省磁盘空间）
4. dump 文件大小很小（每条记录 8 字节）

Load（重启后加载）：
1. 读取 dump 文件中的（表空间 ID, 页号）列表
2. 异步地将这些页从磁盘批量读入 Buffer Pool
3. 读取完成后 Buffer Pool 恢复到关闭前的热点状态
4. 整个过程在后台异步进行，不阻塞数据库正常使用
```

## 配置参数

```sql
-- 查看 Buffer Pool Dump/Load 相关参数
SHOW VARIABLES LIKE 'innodb_buffer_pool_dump%';
SHOW VARIABLES LIKE 'innodb_buffer_pool_load%';
-- +------------------------------------------+----------------------------+
-- | Variable_name                            | Value                      |
-- +------------------------------------------+----------------------------+
-- | innodb_buffer_pool_dump_at_shutdown      | ON                         | -- 关闭时自动 dump
-- | innodb_buffer_pool_dump_now              | OFF                        | -- 立即触发 dump
-- | innodb_buffer_pool_dump_pct              | 25                         | -- dump 比例（%）
-- | innodb_buffer_pool_filename              | ib_buffer_pool             | -- dump 文件名
-- | innodb_buffer_pool_load_at_startup       | ON                         | -- 启动时自动 load
-- | innodb_buffer_pool_load_now              | OFF                        | -- 立即触发 load
-- | innodb_buffer_pool_load_abort            | OFF                        | -- 终止正在进行的 load
-- +------------------------------------------+----------------------------+

-- innodb_buffer_pool_dump_pct（默认 25%）：
-- dump LRU List 最热的前 25% 的页
-- 增大可以更完整地保存热点状态，但文件更大、load 时间更长
```

## 手动操作

```sql
-- 立即触发 Buffer Pool Dump（不需要重启）
SET GLOBAL innodb_buffer_pool_dump_now = ON;
-- 执行后自动重置为 OFF
-- dump 文件位于 datadir/ib_buffer_pool

-- 验证 dump 是否完成
SHOW STATUS LIKE 'Innodb_buffer_pool_dump_status';
-- 'Buffer pool(s) dump completed at 2026-03-15 10:30:00'

-- 立即触发 Buffer Pool Load（不需要重启，可以在运行中重新加载热点）
SET GLOBAL innodb_buffer_pool_load_now = ON;

-- 查看 load 进度
SHOW STATUS LIKE 'Innodb_buffer_pool_load_status';
-- 'Buffer pool(s) load completed at 2026-03-15 10:35:00'
-- 或 'Loading buffer pool(s) at XX%: completed XX of YY pages'

-- 如果 load 耗时过长，中止 load
SET GLOBAL innodb_buffer_pool_load_abort = ON;
```

## 持久化配置（my.cnf）

```ini
[mysqld]
# 关闭 MySQL 时自动将 Buffer Pool 热点页信息保存到文件
innodb_buffer_pool_dump_at_shutdown = ON

# 启动时自动从文件加载热点页
innodb_buffer_pool_load_at_startup = ON

# 保存 LRU 链表最热的前 25% 的页（可调整到 50% 获得更好预热效果）
innodb_buffer_pool_dump_pct = 25

# dump 文件名（相对于 datadir）
innodb_buffer_pool_filename = ib_buffer_pool
```

## Dump 文件内容示例

```bash
# dump 文件格式：每行一个条目，格式为 space_id,page_no
# 实际是二进制格式，可用以下命令查看
# cat /var/lib/mysql/ib_buffer_pool | head -20

# 文件内容示例（文本表示）：
# 0,7          → 系统表空间 (space_id=0)，第 7 页
# 23,456       → 表空间 23 的第 456 页（某个 .ibd 文件）
# 24,789       → 表空间 24 的第 789 页

# 文件大小估算：
# 假设 dump 25% 的 LRU 页，Buffer Pool = 8GB = 524288 页
# dump 25% = 131072 个条目
# 每条 8 字节 → 约 1 MB 的 dump 文件
```

## 监控预热进度

```sql
-- 查看 load 完成度
SHOW STATUS LIKE 'Innodb_buffer_pool_load_status';

-- 实时监控（每 5 秒查一次）
-- 可以结合 Buffer Pool 命中率监控
SELECT
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_buffer_pool_read_requests') AS read_req,
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_buffer_pool_reads') AS disk_reads,
    ROUND((1 - (SELECT VARIABLE_VALUE FROM performance_schema.global_status
                WHERE VARIABLE_NAME = 'Innodb_buffer_pool_reads') /
               (SELECT VARIABLE_VALUE FROM performance_schema.global_status
                WHERE VARIABLE_NAME = 'Innodb_buffer_pool_read_requests')) * 100, 2)
        AS hit_rate_pct;
-- Load 完成后，hit_rate_pct 应迅速提升到 99% 以上
```

## 适用场景

- **计划维护重启**：重启前 dump，重启后 load，将预热时间从数小时缩短到数分钟
- **主从切换**：主库故障后，从库晋升为主库时 Buffer Pool 为冷状态，可以手动触发 load（如果有之前的 dump 文件）
- **MySQL 版本升级**：大版本升级通常需要重启，通过 dump/load 加速恢复生产性能

---

## 常见问题

**innodb_buffer_pool_load_at_startup 会阻塞 MySQL 启动或影响 SQL 响应吗？**

不会阻塞。load 操作是异步后台进行的，MySQL 启动后立即可以接受连接和处理 SQL。load 进程在后台读取磁盘页，与正常 SQL 处理并行进行。在 load 未完成时，命中率相对较低，随着 load 进度推进命中率逐步提升。

---

## 注意事项

- dump 文件只保存（表空间 ID, 页号）这两个标识信息，不保存实际的页数据（16KB 的内容）。重启 load 时，还是需要从 .ibd 文件重新读取页数据到内存，因此 load 过程会有一定的磁盘 I/O 负载。
- 如果 dump 后数据库有大量写入（很多脏页），或者表结构发生了变化，load 时加载的可能是相对"过时"的热点分布，但这通常不是问题，因为 InnoDB 会正常读取需要的页。

---

## 总结

Buffer Pool Dump/Load 机制通过在关闭时将 LRU 热点页标识（表空间 ID + 页号）保存到 `ib_buffer_pool` 文件，重启后异步重新加载这些热点页，将冷启动预热时间大幅缩短。通过 `innodb_buffer_pool_dump_at_shutdown=ON` 和 `innodb_buffer_pool_load_at_startup=ON` 启用自动 dump/load。`innodb_buffer_pool_dump_pct`（默认 25%）控制保存的热点页比例，生产环境可调至 50%。手动触发用 `SET GLOBAL innodb_buffer_pool_dump_now=ON`。
