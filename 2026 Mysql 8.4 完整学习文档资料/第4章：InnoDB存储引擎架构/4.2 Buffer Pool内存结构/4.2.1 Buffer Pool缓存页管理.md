# Buffer Pool 缓存页管理

Buffer Pool 是 InnoDB 最重要的内存结构，用于缓存从磁盘读取的数据页和索引页。所有对数据的读写操作都先在 Buffer Pool 中进行，只有当缓存不够用时才会将部分页驱逐（刷写到磁盘）。Buffer Pool 的命中率直接决定了 InnoDB 的读写性能，命中率越高，需要的磁盘 I/O 越少，性能越好。

---

## Buffer Pool 基本概念

```
Buffer Pool 结构：

┌──────────────────────────────────────────────────────────────────┐
│                        Buffer Pool（内存）                        │
│                                                                  │
│  ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐    │
│  │ 数据页    │  │ 索引页    │  │ Undo页    │  │ 插入缓冲页│    │
│  │ (16KB)    │  │ (16KB)    │  │ (16KB)    │  │ (16KB)    │    │
│  └───────────┘  └───────────┘  └───────────┘  └───────────┘    │
│                                                                  │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  控制块（Control Block）：每页 ~800 字节                   │   │
│  │  存储：页类型 / 所属表空间 / 页号 / 链表指针 / LSN ...     │   │
│  └──────────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────────┘
```

- **缓存页（Page）**：Buffer Pool 以 16 KB 为单位管理内存，每个槽位存储一个数据页
- **控制块（Control Block）**：每个缓存页对应一个控制块（约 800 字节），存储页的元信息（表空间 ID、页号、脏页标记、访问时间等）
- **三条链表**：Free List（空闲页）、LRU List（活跃/非活跃页）、Flush List（脏页）

## Buffer Pool 大小配置

```sql
-- 查看当前 Buffer Pool 大小
SHOW VARIABLES LIKE 'innodb_buffer_pool_size';
-- 默认：128 MB（生产环境严重不足，需调整）

-- 查看 Buffer Pool 实例数量
SHOW VARIABLES LIKE 'innodb_buffer_pool_instances';
-- 默认：1（当 buffer pool size >= 1GB 时建议设置多个实例）

-- 动态修改 Buffer Pool 大小（MySQL 5.7+ 支持在线调整）
SET GLOBAL innodb_buffer_pool_size = 4 * 1024 * 1024 * 1024;  -- 4 GB
-- 调整是以 innodb_buffer_pool_chunk_size（默认 128MB）为单位逐步进行

-- my.cnf 持久化配置（推荐设置为物理内存的 50-70%）
-- [mysqld]
-- innodb_buffer_pool_size = 8G
-- innodb_buffer_pool_instances = 8  -- 每个实例 1GB

-- 查看 Buffer Pool chunk 大小
SHOW VARIABLES LIKE 'innodb_buffer_pool_chunk_size';
-- 默认：128 MB
-- 实际 Buffer Pool 大小 = N * chunk_size（自动向上取整）
```

## 缓存页的读取机制

```sql
-- 读操作流程：
-- 1. 计算要读取的页所在的表空间 ID 和页号
-- 2. 以 (space_id, page_no) 为 key 在 Buffer Pool 的哈希表中查找
-- 3. 命中 → 直接从内存返回（无磁盘 I/O）
-- 4. 未命中（缓存缺失）→ 从磁盘读取页，放入 Buffer Pool，再返回

-- 查看 Buffer Pool 命中率
SHOW STATUS LIKE 'Innodb_buffer_pool_read%';
-- +-----------------------------------+-----------+
-- | Variable_name                     | Value     |
-- +-----------------------------------+-----------+
-- | Innodb_buffer_pool_read_requests  | 987654321 | -- 总读取请求次数
-- | Innodb_buffer_pool_reads          | 12345     | -- 需要从磁盘读取的次数
-- +-----------------------------------+-----------+

-- 计算命中率
-- 命中率 = (read_requests - reads) / read_requests * 100%
-- 命中率 = (987654321 - 12345) / 987654321 * 100% ≈ 99.998%
-- 生产环境应保持 99% 以上，低于 95% 说明 Buffer Pool 严重不足

SELECT
    (1 - (SELECT VARIABLE_VALUE FROM performance_schema.global_status
          WHERE VARIABLE_NAME = 'Innodb_buffer_pool_reads') /
         (SELECT VARIABLE_VALUE FROM performance_schema.global_status
          WHERE VARIABLE_NAME = 'Innodb_buffer_pool_read_requests')
    ) * 100 AS buffer_pool_hit_rate_pct;
```

## Buffer Pool 状态监控

```sql
-- 查看 Buffer Pool 详细状态
SHOW STATUS LIKE 'Innodb_buffer_pool%';
-- Innodb_buffer_pool_pages_total    -- 总页数
-- Innodb_buffer_pool_pages_free     -- 空闲页数
-- Innodb_buffer_pool_pages_data     -- 存有数据的页数
-- Innodb_buffer_pool_pages_dirty    -- 脏页数
-- Innodb_buffer_pool_pages_flushed  -- 已刷盘的页数（累计）
-- Innodb_buffer_pool_wait_free      -- 因无空闲页需等待的次数（>0 说明 Buffer Pool 太小）
-- Innodb_buffer_pool_bytes_data     -- 数据占用字节数
-- Innodb_buffer_pool_bytes_dirty    -- 脏数据占用字节数

-- 通过 SHOW ENGINE INNODB STATUS 查看 Buffer Pool 详情
SHOW ENGINE INNODB STATUS \G
-- 查找 BUFFER POOL AND MEMORY 部分

-- 通过 performance_schema 查看每个 Buffer Pool 实例的状态
SELECT * FROM information_schema.INNODB_BUFFER_POOL_STATS;
-- POOL_ID, POOL_SIZE, FREE_BUFFERS, DATABASE_PAGES,
-- DIRTY_PAGES, DATA_PAGES, PAGE_MADE_YOUNG_RATE...
```

## 脏页（Dirty Page）管理

```sql
-- 脏页：已在 Buffer Pool 中被修改但尚未刷写到磁盘的页
-- 脏页标记：控制块中有一个 is_dirty 标志

-- 查看当前脏页数量和比例
SELECT
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_buffer_pool_pages_dirty') AS dirty_pages,
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_buffer_pool_pages_total') AS total_pages,
    ROUND(
        (SELECT VARIABLE_VALUE FROM performance_schema.global_status
         WHERE VARIABLE_NAME = 'Innodb_buffer_pool_pages_dirty') * 100.0 /
        (SELECT VARIABLE_VALUE FROM performance_schema.global_status
         WHERE VARIABLE_NAME = 'Innodb_buffer_pool_pages_total'),
        2
    ) AS dirty_page_pct;

-- 控制脏页刷盘比例的参数
SHOW VARIABLES LIKE 'innodb_max_dirty_pages_pct%';
-- innodb_max_dirty_pages_pct：脏页比例上限（默认 90%，超过触发强制刷盘）
-- innodb_max_dirty_pages_pct_lwm：低水位（默认 10%，低于此值减少刷盘）
```

## 适用场景

- **OLTP 系统**：Buffer Pool 应尽量大（物理内存的 50-70%），保证高频数据都在内存中
- **读密集系统**：Buffer Pool 命中率是最关键的性能指标，命中率低则首先扩大 Buffer Pool
- **写密集系统**：需要关注脏页比例，避免脏页比例过高时触发大量强制刷盘影响响应时间

## 常见问题

**Buffer Pool 调大后，`Innodb_buffer_pool_wait_free` 还是大于 0，怎么回事？**

`Innodb_buffer_pool_wait_free` 大于 0 说明所有空闲页都用完了，新页需要等待后台线程腾出空间。可能原因：Buffer Pool 仍然不够大；或者后台刷盘线程（`innodb_page_cleaners`）的工作速度跟不上写入速度。解决方向：继续增大 Buffer Pool，或增加 `innodb_page_cleaners` 的数量（默认等于 `innodb_buffer_pool_instances`）。

---

## 注意事项

- Buffer Pool 的大小调整（`SET GLOBAL innodb_buffer_pool_size`）在 MySQL 5.7+ 支持在线动态调整，调整过程中以 `innodb_buffer_pool_chunk_size`（默认 128MB）为单位逐步完成，期间不影响数据库服务。但调整大量时（如从 4GB 调到 64GB）需要一定时间。
- 实际可用的 Buffer Pool 大小略小于配置值，因为每个缓存页需要额外的控制块内存（约占 Buffer Pool 的 5%）。

---

## 总结

Buffer Pool 是 InnoDB 的核心内存缓存，以 16KB 为单位缓存数据页和索引页，通过哈希表快速定位（表空间 ID + 页号）。通过三条链表（Free List、LRU List、Flush List）管理空闲页、活跃页和脏页。Buffer Pool 命中率 = (read_requests - reads) / read_requests，应维持在 99% 以上。生产环境通过 `innodb_buffer_pool_size`（建议物理内存的 50-70%）和 `innodb_buffer_pool_instances` 配置，可在线动态调整。
