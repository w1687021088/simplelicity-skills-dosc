# Redo Log Buffer 内存缓冲

Redo Log Buffer 是 InnoDB 在内存中为 Redo Log 设置的写入缓冲区。事务执行过程中产生的 Redo Log 记录首先写入 Redo Log Buffer，而不是直接写到磁盘上的 Redo Log 文件。在合适的时机（事务提交、Buffer 满、后台线程定期刷新等），Redo Log Buffer 中的内容被批量刷写到磁盘，减少磁盘 I/O 次数，提高写入效率。

---

## Redo Log Buffer 的结构

```
Redo Log Buffer（内存）：

┌──────────────────────────────────────────────────────────────────────┐
│              Redo Log Buffer（默认 64 MB）                            │
│  ┌─────────────┬─────────────┬─────────────┬─────────────────────┐  │
│  │ Log Block 0 │ Log Block 1 │ Log Block 2 │ ...  (512字节/块)    │  │
│  └─────────────┴─────────────┴─────────────┴─────────────────────┘  │
│                                                                      │
│  buf_free：下一个写入位置（写指针）                                    │
│  buf_next_to_write：下一个刷盘位置（读指针）                           │
└──────────────────────────────────────────────────────────────────────┘
                          ↓ 刷盘
                   Redo Log File（磁盘）
```

## 相关配置参数

```sql
-- 查看 Redo Log Buffer 大小
SHOW VARIABLES LIKE 'innodb_log_buffer_size';
-- 默认：64 MB（MySQL 8.0，足够大多数场景）
-- MySQL 5.7 以前默认 8 MB，已提高

-- 调整 Redo Log Buffer 大小
-- 对于大事务（如批量 INSERT 大量数据），可适当增大
-- 对于小事务高并发，默认 64 MB 已足够
SET GLOBAL innodb_log_buffer_size = 128 * 1024 * 1024;  -- 128 MB
-- 注意：此参数修改需要重启 MySQL（不支持动态修改）
-- 或在 my.cnf 中：innodb_log_buffer_size = 128M

-- 查看 Redo Log Buffer 使用情况
-- 通过 SHOW ENGINE INNODB STATUS 查看
SHOW ENGINE INNODB STATUS \G
-- LOG 部分：
-- Log buffer assigned up to XXXXXXXX
-- Log buffer completed up to XXXXXXXX
-- Log written up to XXXXXXXX
-- Log flushed up to XXXXXXXX
```

## Redo Log Buffer 的刷盘时机

```sql
-- 触发 Redo Log Buffer 刷盘的条件：

-- 1. 事务提交（COMMIT）时
--    取决于 innodb_flush_log_at_trx_commit 参数设置
--    = 1（默认）：COMMIT 时立即刷盘（fsync）
--    = 2：COMMIT 时写入 OS 缓冲（不 fsync），每秒 fsync 一次
--    = 0：每秒写入并 fsync 一次（COMMIT 时不主动刷盘）

-- 2. Redo Log Buffer 写满时（超过 innodb_log_buffer_size 约一半）
--    InnoDB 自动刷盘，不等待 COMMIT
--    这对大事务很重要：事务执行过程中就会多次刷盘

-- 3. 后台线程每秒刷盘
--    InnoDB Master Thread 每秒将 Redo Log Buffer 刷到磁盘

-- 4. 检查点（Checkpoint）触发时
--    Checkpoint 推进时必须确保对应 LSN 之前的 Redo Log 已刷盘

-- 查看 Redo Log fsync 相关状态
SHOW STATUS LIKE 'Innodb_os_log%';
-- Innodb_os_log_fsyncs：总 fsync 次数
-- Innodb_os_log_written：总写入字节数
-- 计算每次提交平均写入量：os_log_written / Com_commit
```

## Redo Log Buffer 与并发写入

```sql
-- 多个事务并发写入 Redo Log Buffer 的机制：

-- MySQL 5.7 之前：
-- 使用 log_sys->mutex 互斥锁，一次只有一个线程可以写入
-- 高并发时成为瓶颈

-- MySQL 8.0 优化：Lock-Free Redo Log
-- 移除了 log_sys->mutex 大锁
-- 使用无锁的原子操作（CAS）分配 Buffer 中的写入位置
-- 多个事务可以并行写入 Redo Log Buffer 的不同位置
-- 显著提升高并发写入时的 Redo Log 写入吞吐量

-- 查看 Lock-Free Redo Log 相关状态（MySQL 8.0）
SELECT NAME, COUNT, SUM_TIMER_WAIT
FROM performance_schema.mutex_instances
WHERE NAME LIKE '%log%'
ORDER BY SUM_TIMER_WAIT DESC
LIMIT 10;
```

## Redo Log Buffer 大小对性能的影响

```sql
-- 场景1：大事务（如批量 INSERT 100 万行）
--    单个事务产生的 Redo Log 可能超过 Redo Log Buffer
--    → Buffer 满时自动刷盘（不等 COMMIT）
--    → 建议增大 Buffer 减少中途刷盘次数
--    → 参考：每行 100 字节 Redo Log × 100 万行 = 100 MB Redo Log
--    → 64 MB Buffer 不够，应设置 128 MB 或以上

-- 场景2：高并发小事务（每事务约 1-2 KB Redo Log）
--    → 64 MB Buffer 完全够用
--    → 每次 COMMIT 刷盘约 1-2 KB，fsync 的频率影响更大

-- 场景3：Redo Log Buffer 设置多大合适？
--    一般不需要超过 256 MB
--    Buffer 越大，崩溃丢失的 Redo Log 越多（未刷盘的部分）
--    但 innodb_flush_log_at_trx_commit=1 时 COMMIT 立即刷盘
--    Buffer 大小主要影响事务执行过程中（未提交时）的 Redo Log 管理

-- 监控是否需要增大 Buffer
-- 如果 Innodb_log_waits > 0，说明 Redo Log Buffer 太小
SHOW STATUS LIKE 'Innodb_log_waits';
-- 大于 0 说明有写操作因 Buffer 满而等待刷盘
```

## 适用场景

- **大批量导入**：执行大事务（INSERT SELECT 百万行）时，增大 `innodb_log_buffer_size` 减少事务中途的 Redo Log 刷盘次数
- **高并发 OLTP**：MySQL 8.0 的 Lock-Free Redo Log 机制已大幅优化并发写入，一般不需要特别调整 Buffer 大小

---

## 常见问题

**innodb_log_buffer_size 设置过大有什么风险？**

主要风险是崩溃时可能丢失更多的 Redo Log（Buffer 中未刷盘的部分）。但实际上，当 `innodb_flush_log_at_trx_commit=1` 时，每次 COMMIT 都会刷盘，Buffer 中只会保留未提交事务的 Redo Log。设置过大的 Buffer 对崩溃安全性的影响有限，只是内存占用增加。

---

## 注意事项

- `innodb_log_buffer_size` 的修改需要重启 MySQL 才能生效（不支持 `SET GLOBAL` 动态修改）。在评估是否需要增大时，先检查 `Innodb_log_waits` 状态变量，大于 0 才有必要增大。
- MySQL 8.0 的 Lock-Free Redo Log 优化（无锁写入 Redo Log Buffer）是 8.0 相对 5.7 在高并发写入场景下性能显著提升的原因之一，原有的 `log_sys->mutex` 瓶颈已被消除。

---

## 总结

Redo Log Buffer 是 Redo Log 在内存中的临时缓冲区（默认 64 MB），事务执行时产生的 Redo Log 先写入 Buffer，在 COMMIT 时（或 Buffer 满、后台定时、Checkpoint 时）批量刷到磁盘。通过 `Innodb_log_waits > 0` 判断 Buffer 是否不够大，大批量导入时可增大到 128-256 MB。MySQL 8.0 引入 Lock-Free Redo Log，多事务可并发写入 Buffer 不同位置，大幅减少高并发时的写入竞争。
