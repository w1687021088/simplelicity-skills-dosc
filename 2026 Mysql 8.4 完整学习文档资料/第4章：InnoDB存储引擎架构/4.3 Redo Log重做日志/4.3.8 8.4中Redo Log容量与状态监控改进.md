# 8.4 中 Redo Log 容量与状态监控改进

MySQL 8.4 继承并完善了 MySQL 8.0.30 引入的 Redo Log 容量管理机制。旧的 `innodb_log_file_size` 和 `innodb_log_files_in_group` 参数在 8.0.30 中被废弃，在 8.4 中已被移除。取而代之的是统一的 `innodb_redo_log_capacity` 参数，同时 Performance Schema 和状态变量提供了更细粒度的 Redo Log 监控手段。

---

## 参数变更对照

| 参数 | MySQL 8.0（8.0.30 之前） | MySQL 8.0.30 | MySQL 8.4 |
|------|------------------------|-------------|-----------|
| innodb_log_file_size | 正常使用，控制单个 Redo Log 文件大小 | 废弃（Deprecated） | 已移除 |
| innodb_log_files_in_group | 正常使用，控制 Redo Log 文件数量 | 废弃（Deprecated） | 已移除 |
| innodb_redo_log_capacity | 不存在 | 新增，控制 Redo Log 总容量 | 唯一的 Redo Log 容量配置参数 |

在 8.0.30 到 8.0.x 期间，如果同时设置了新旧参数，`innodb_redo_log_capacity` 优先，旧参数被忽略。到了 8.4，旧参数已经完全消失，如果 my.cnf 中还保留着 `innodb_log_file_size` 或 `innodb_log_files_in_group`，服务器启动时会报错。

---

## innodb_redo_log_capacity 参数详解

```sql
-- 查看当前 Redo Log 容量配置
SHOW VARIABLES LIKE 'innodb_redo_log_capacity';
-- +---------------------------+-----------+
-- | Variable_name             | Value     |
-- +---------------------------+-----------+
-- | innodb_redo_log_capacity  | 104857600 |
-- +---------------------------+-----------+
-- 默认值：104857600（100MB）

-- 在运行时动态调整 Redo Log 容量（不需要重启）
SET GLOBAL innodb_redo_log_capacity = 2147483648;  -- 设置为 2GB
-- 调整后立即生效，但底层文件的扩容或缩容需要一些时间

-- 在 my.cnf 中配置（启动时生效）
-- [mysqld]
-- innodb_redo_log_capacity = 2G
```

| 属性 | 值 |
|------|---|
| 作用域 | GLOBAL |
| 是否动态 | 是（运行时可修改，不需要重启） |
| 类型 | 整数（字节） |
| 默认值 | 104857600（100MB） |
| 最小值 | 8388608（8MB） |
| 最大值 | 549755813888（512GB） |

## Redo Log 文件的新管理方式

MySQL 8.4 中 Redo Log 文件不再是固定数量和固定大小的传统 `ib_logfile0`、`ib_logfile1` 形式，而是存放在数据目录下的 `#innodb_redo` 子目录中，由 InnoDB 自动管理。

```sql
-- 查看 Redo Log 文件所在目录
SHOW VARIABLES LIKE 'innodb_log_group_home_dir';
-- 默认指向 datadir
-- 实际文件位于 datadir/#innodb_redo/ 目录下

-- 文件命名规则：
-- #ib_redo582        普通（活跃）Redo Log 文件
-- #ib_redo603_tmp    备用（Spare）Redo Log 文件
```

InnoDB 会自动维护大约 32 个 Redo Log 文件，每个文件的大小约为 `innodb_redo_log_capacity / 32`。当容量调整后，InnoDB 会逐渐创建或删除文件，使总容量趋近新的设定值。

```sql
-- 查看当前活跃的 Redo Log 文件及其 LSN 范围
SELECT FILE_ID, FILE_NAME, START_LSN, END_LSN, SIZE_IN_BYTES, IS_FULL, CONSUMER_LEVEL
FROM performance_schema.innodb_redo_log_files;
-- +----------+-------------------------------+--------------+--------------+---------------+---------+----------------+
-- | FILE_ID  | FILE_NAME                     | START_LSN    | END_LSN      | SIZE_IN_BYTES | IS_FULL | CONSUMER_LEVEL |
-- +----------+-------------------------------+--------------+--------------+---------------+---------+----------------+
-- |      582 | ./#innodb_redo/#ib_redo582     | 117654982144 | 117658256896 |       3274752 |       1 |              0 |
-- |      583 | ./#innodb_redo/#ib_redo583     | 117658256896 | 117661531648 |       3274752 |       1 |              0 |
-- | ...      | ...                           | ...          | ...          | ...           | ...     | ...            |
-- +----------+-------------------------------+--------------+--------------+---------------+---------+----------------+
```

各列含义：

| 列名 | 说明 |
|------|------|
| FILE_ID | Redo Log 文件编号 |
| FILE_NAME | 文件路径（相对于 datadir） |
| START_LSN | 该文件存储的起始 LSN |
| END_LSN | 该文件存储的结束 LSN |
| SIZE_IN_BYTES | 文件大小（字节） |
| IS_FULL | 是否已写满（1=已满，0=未满） |
| CONSUMER_LEVEL | 消费者级别（用于 Redo Log 归档） |

## 状态变量监控

MySQL 8.4 提供了一组以 `Innodb_redo_log_` 为前缀的状态变量，用于实时监控 Redo Log 的运行状态。

```sql
-- 查看所有 Redo Log 相关状态变量
SHOW STATUS LIKE 'Innodb_redo_log%';
```

各状态变量详解：

| 状态变量 | 说明 |
|---------|------|
| Innodb_redo_log_capacity_resized | 当前实际生效的 Redo Log 总容量（字节） |
| Innodb_redo_log_resize_status | 容量调整操作的当前状态（OK 表示无调整或调整已完成） |
| Innodb_redo_log_checkpoint_lsn | 最近一次 Checkpoint 的 LSN 位置 |
| Innodb_redo_log_current_lsn | 当前正在写入的 LSN 位置 |
| Innodb_redo_log_flushed_to_disk_lsn | 已刷盘的最大 LSN 位置 |
| Innodb_redo_log_logical_size | Redo Log 的逻辑大小（当前 LSN 与 Checkpoint LSN 的差值） |
| Innodb_redo_log_physical_size | Redo Log 文件占用的物理磁盘空间 |
| Innodb_redo_log_read_only | Redo Log 是否处于只读模式（0=可写，1=只读） |
| Innodb_redo_log_uuid | 当前 Redo Log 的 UUID 标识 |
| Innodb_redo_log_enabled | Redo Log 是否启用（ON/OFF） |

```sql
-- 监控 Redo Log 使用率的实用查询
SELECT
    -- 当前 LSN 与 Checkpoint LSN 的差值，代表尚未 Checkpoint 的 Redo 数据量
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_redo_log_current_lsn') AS current_lsn,
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_redo_log_checkpoint_lsn') AS checkpoint_lsn,
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_redo_log_current_lsn') -
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_redo_log_checkpoint_lsn') AS redo_log_used_bytes,
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_redo_log_capacity_resized') AS total_capacity;
```

## 动态调整容量的过程

与旧版本需要停机修改 `innodb_log_file_size` 不同，`innodb_redo_log_capacity` 支持在线动态调整，整个过程不影响业务。

```sql
-- 第一步：查看当前容量
SHOW STATUS LIKE 'Innodb_redo_log_capacity_resized';
-- 假设当前是 104857600（100MB）

-- 第二步：调整为 2GB
SET GLOBAL innodb_redo_log_capacity = 2147483648;

-- 第三步：检查调整状态
SHOW STATUS LIKE 'Innodb_redo_log_resize_status';
-- +-------------------------------+----------+
-- | Variable_name                 | Value    |
-- +-------------------------------+----------+
-- | Innodb_redo_log_resize_status | OK       |
-- +-------------------------------+----------+
-- OK 表示调整已完成或没有正在进行的调整
-- 如果正在调整中，会显示其他状态

-- 第四步：确认新容量已生效
SHOW STATUS LIKE 'Innodb_redo_log_capacity_resized';
-- +----------------------------------+------------+
-- | Variable_name                    | Value      |
-- +----------------------------------+------------+
-- | Innodb_redo_log_capacity_resized | 2147483648 |
-- +----------------------------------+------------+
```

扩容时，InnoDB 会放缓脏页刷新速度，让 Redo Log 文件逐渐扩大到新容量。缩容时，InnoDB 会加速刷脏页，让 Redo Log 占用空间逐渐缩小。这两个过程都是渐进式的，不会导致性能突变。

## 与旧版本配置的迁移

如果从 MySQL 8.0（8.0.30 之前）升级到 8.4，需要将旧的 Redo Log 参数转换为新参数。

```ini
# 旧配置（MySQL 8.0.29 及之前）
[mysqld]
innodb_log_file_size = 256M
innodb_log_files_in_group = 4
# 总容量 = 256M * 4 = 1GB

# 等价的新配置（MySQL 8.4）
[mysqld]
innodb_redo_log_capacity = 1G
# 不再需要指定文件数量和单个文件大小
# InnoDB 自动管理约 32 个文件，每个约 32MB
```

| 旧配置组合 | 等价的 innodb_redo_log_capacity |
|-----------|-------------------------------|
| log_file_size=48M, files_in_group=2 | 96M |
| log_file_size=128M, files_in_group=2 | 256M |
| log_file_size=256M, files_in_group=4 | 1G |
| log_file_size=512M, files_in_group=4 | 2G |
| log_file_size=1G, files_in_group=4 | 4G |

## innodb_dedicated_server 的自动配置

当使用 `innodb_dedicated_server=ON` 时，MySQL 8.4 会根据系统可用内存自动计算 `innodb_redo_log_capacity` 的值。

```sql
-- 查看是否启用了专用服务器模式
SHOW VARIABLES LIKE 'innodb_dedicated_server';

-- 自动计算规则（基于检测到的服务器内存）：
-- 内存 < 1GB:   innodb_redo_log_capacity = 100MB
-- 1GB <= 内存 < 2GB:  innodb_redo_log_capacity = 100MB（即 round(0.5 * detected / 0.5) * 0.5）
-- 2GB <= 内存 < 4GB:  innodb_redo_log_capacity = round(detected * 0.5)GB 上限为 1GB
-- 4GB <= 内存 < 10.66GB: innodb_redo_log_capacity = round(detected * 0.5)GB 上限为 2GB  
-- 10.66GB <= 内存 < 170.66GB: innodb_redo_log_capacity = round(detected * 0.125)GB
-- 内存 >= 170.66GB: innodb_redo_log_capacity = 16GB（上限）
```

## 禁用 Redo Log（仅限数据加载场景）

MySQL 8.4 保留了临时禁用 Redo Log 的能力，用于加速大批量数据导入。这个功能仅适用于新实例的初始数据加载，绝不能在生产环境中使用。

```sql
-- 需要 INNODB_REDO_LOG_ENABLE 权限
GRANT INNODB_REDO_LOG_ENABLE ON *.* TO 'data_loader'@'localhost';

-- 禁用 Redo Log（加速数据导入）
ALTER INSTANCE DISABLE INNODB REDO_LOG;

-- 验证 Redo Log 已禁用
SHOW GLOBAL STATUS LIKE 'Innodb_redo_log_enabled';
-- +-------------------------+-------+
-- | Variable_name           | Value |
-- +-------------------------+-------+
-- | Innodb_redo_log_enabled | OFF   |
-- +-------------------------+-------+

-- 执行大批量数据导入操作...
-- LOAD DATA INFILE ...
-- INSERT INTO ... SELECT ...

-- 导入完成后，立即重新启用 Redo Log
ALTER INSTANCE ENABLE INNODB REDO_LOG;

-- 确认 Redo Log 已恢复
SHOW GLOBAL STATUS LIKE 'Innodb_redo_log_enabled';
-- Value: ON
```

## 容量规划建议

```sql
-- 监控 Redo Log 使用情况，帮助决定容量大小
-- 如果 Redo Log 经常接近写满（checkpoint 频繁），说明容量不够

-- 查看 checkpoint 相关的 InnoDB 指标
SHOW ENGINE INNODB STATUS\G
-- 在 LOG 部分查看：
-- Log sequence number:  当前 LSN
-- Log flushed up to:    已刷盘的 LSN
-- Pages flushed up to:  已刷页的 LSN
-- Last checkpoint at:   最后一次 Checkpoint 的 LSN
-- 如果 "Log sequence number" 与 "Last checkpoint at" 的差值
-- 经常接近 innodb_redo_log_capacity 的 80%，说明容量偏小

-- 也可以通过 Performance Schema 的状态变量计算
SELECT
    ROUND(
        ((SELECT VARIABLE_VALUE FROM performance_schema.global_status
          WHERE VARIABLE_NAME = 'Innodb_redo_log_current_lsn') -
         (SELECT VARIABLE_VALUE FROM performance_schema.global_status
          WHERE VARIABLE_NAME = 'Innodb_redo_log_checkpoint_lsn'))
        /
        (SELECT VARIABLE_VALUE FROM performance_schema.global_status
         WHERE VARIABLE_NAME = 'Innodb_redo_log_capacity_resized')
        * 100, 2
    ) AS redo_usage_percent;
-- 如果这个百分比经常超过 75%，建议增大容量
```

常见的容量配置参考：

| 业务场景 | 建议容量 | 说明 |
|---------|---------|------|
| 开发/测试环境 | 100MB~256MB | 写入量小，默认值即可 |
| 中小型生产环境 | 512MB~2GB | 一般 OLTP 业务 |
| 高写入量的生产环境 | 2GB~8GB | 大量 INSERT/UPDATE 操作 |
| 超大规模写入 | 8GB~16GB | 极端写入场景，如批量数据迁移 |

## 适用场景

- **版本升级**：从 MySQL 8.0（特别是 8.0.30 之前）升级到 8.4 时，需要将旧的 Redo Log 参数转换为 `innodb_redo_log_capacity`
- **性能调优**：通过监控 Redo Log 使用率，动态调整容量以平衡写入性能和磁盘占用
- **大批量数据导入**：临时禁用 Redo Log 加速数据加载，完成后立即重新启用
- **运维监控**：利用 Performance Schema 的 `innodb_redo_log_files` 表和 `Innodb_redo_log_*` 状态变量实时掌握 Redo Log 健康状态

## 常见问题

**升级到 8.4 后启动报错，提示 innodb_log_file_size 未知参数怎么办？**

这是因为 my.cnf 中还保留着已移除的旧参数。需要将 `innodb_log_file_size` 和 `innodb_log_files_in_group` 替换为 `innodb_redo_log_capacity`。计算方式：新容量 = innodb_log_file_size * innodb_log_files_in_group。

**动态调整 innodb_redo_log_capacity 后，磁盘空间变化不是立即发生的？**

对，这是正常行为。扩容时 InnoDB 逐渐减少脏页刷新频率，让 Redo Log 文件自然增长；缩容时加快刷脏页，让文件逐渐缩小。可以通过 `SHOW STATUS LIKE 'Innodb_redo_log_resize_status'` 查看调整进度，显示 OK 表示已完成。

**Redo Log 容量设置得太小会有什么后果？**

容量太小会导致 Checkpoint 频繁触发，InnoDB 需要不断将 Buffer Pool 中的脏页刷到磁盘，写入性能会明显下降。在极端情况下，如果写入速度超过 Checkpoint 的速度，用户线程会被迫等待（出现 "redo log not enough space" 的状况），导致查询延迟飙升。

**#innodb_redo 目录里的 _tmp 文件是什么？**

`_tmp` 后缀的文件是备用（Spare）Redo Log 文件。InnoDB 预先创建这些文件，当活跃文件写满时可以快速切换到备用文件，避免在运行时创建新文件带来的 I/O 延迟。这些备用文件不占用 Redo Log 容量预算，不需要手动管理。

---

## 注意事项

- 升级到 8.4 前，必须从 my.cnf 中移除 `innodb_log_file_size` 和 `innodb_log_files_in_group`，否则服务器无法启动。
- 动态调整 `innodb_redo_log_capacity` 虽然不需要重启，但在调整过程中可能会因为加速刷脏页或减缓刷脏页导致短暂的性能波动。建议在业务低峰期执行容量调整。
- 禁用 Redo Log（`ALTER INSTANCE DISABLE INNODB REDO_LOG`）后如果发生意外崩溃，数据将无法恢复。这个功能仅适用于全新实例的初始数据加载，绝不能在有业务数据的实例上使用。
- `#innodb_redo` 目录中的文件由 InnoDB 完全自动管理，不要手动删除、移动或修改这些文件。

---

## 总结

MySQL 8.4 在 Redo Log 管理方面的核心变更是：移除了旧的 `innodb_log_file_size` 和 `innodb_log_files_in_group` 参数，统一使用 `innodb_redo_log_capacity` 控制 Redo Log 总容量（默认 100MB，最大 512GB）。这个参数支持在线动态调整，不需要重启服务器。Redo Log 文件存放在 `#innodb_redo` 目录中，InnoDB 自动维护约 32 个文件。监控方面，Performance Schema 的 `innodb_redo_log_files` 表可以查看每个文件的 LSN 范围和状态，`Innodb_redo_log_*` 系列状态变量提供了 Checkpoint LSN、当前 LSN、刷盘 LSN、逻辑/物理大小等实时指标。升级到 8.4 时需要按照 "旧文件数 * 旧文件大小 = 新容量" 的公式转换配置参数。
