# REDUNDANT 行格式（5.0 前兼容）

REDUNDANT 是 InnoDB 最古老的行格式，MySQL 5.0 之前是唯一的选择（后被 COMPACT 取代）。其名字体现了它的特点——冗余（Redundant）：每条行记录都存储了所有列的末尾偏移量，无论列是否为 NULL，无论列是定长还是变长，都在记录头部有一个完整的偏移量条目。这种设计使得 REDUNDANT 行记录比 COMPACT 格式更大（尤其是列数多时），但保留是为了向后兼容旧版本 InnoDB 创建的表。

---

## REDUNDANT 行格式的结构

```
REDUNDANT 格式一条完整行记录的字节布局：

┌─────────────────────────────────────────────────────────────────────┐
│ 列偏移量列表（Field Start Offsets）                                   │
│ 每列的末尾偏移量（从记录开头算起）                                    │
│ 按列定义逆序排列                                                      │
│ 每个偏移量：1字节（列偏移 ≤ 127字节）或 2字节（列偏移 > 127字节）   │
│ 最高位（bit7 或 bit15）：1 = 该列为 NULL                            │
│ 次高位（bit6 或 bit14）：1 = 该列是 off-page 存储                   │
├─────────────────────────────────────────────────────────────────────┤
│ Record Header（6字节，比 COMPACT 多 1 字节）                          │
│ del | min_rec | n_owned | heap_no（12bit）| record_type | next      │
├─────────────────────────────────────────────────────────────────────┤
│ 隐藏列（仅聚簇索引行）                                                │
│ DB_ROW_ID（6字节，无显式主键时）                                     │
│ DB_TRX_ID（6字节）                                                   │
│ DB_ROLL_PTR（7字节）                                                 │
├─────────────────────────────────────────────────────────────────────┤
│ 实际列值（按列定义顺序）                                              │
│ NULL 列仍然占用固定字节：定长类型（INT等）存 0 值，VARCHAR 存 0 字节  │
│ （注：COMPACT 中 NULL 列不占空间，REDUNDANT 中有时会）                │
└─────────────────────────────────────────────────────────────────────┘
```

---

## REDUNDANT 与 COMPACT 的结构对比

| 对比维度 | REDUNDANT | COMPACT |
|---------|---------|--------|
| 头部信息 | 所有列的末尾偏移量（逆序）| 变长列长度 + NULL 位图（逆序）|
| Record Header 大小 | 6 字节 | 5 字节 |
| NULL 列存储 | 定长列 NULL 仍占固定空间 | NULL 列完全不占空间 |
| 变长列存储 | 偏移量包含在列表中 | 单独变长列长度列表 |
| 平均行大小 | 更大（尤其列多时）| 更小 |
| 兼容性 | MySQL 5.0 之前版本兼容 | MySQL 5.0+ |

## NULL 处理的差异

```sql
-- 举例：表有 4 列（id INT, name VARCHAR(50), score INT, note VARCHAR(100)）
-- 插入：INSERT INTO t VALUES (1, NULL, NULL, 'test');

-- REDUNDANT 格式：
-- 偏移量列表包含所有列（含 NULL 列）的偏移量
-- name = NULL：偏移量最高位置 1 标记，但在列值区域：
--   VARCHAR NULL → 0 字节（长度为 0）
-- score = NULL：偏移量最高位置 1 标记，在列值区域：
--   INT NULL → 存储 4 字节 0 值（定长列需要占位！）

-- COMPACT 格式：
-- NULL 位图：name(1) score(1) note(0) → bit=1 表示 NULL
-- 列值区域：name 和 score 完全不存储（节省空间）

-- 这就是 REDUNDANT 的"冗余"所在：
-- 定长列（INT, DATE, CHAR）即使为 NULL，REDUNDANT 仍然在偏移量中占用条目
-- 但实际列值的处理取决于列类型（VARCHAR NULL → 0字节；INT NULL → 0值占位）
```

## 如何查看和使用 REDUNDANT 格式

```sql
-- 查看表的行格式
SHOW TABLE STATUS LIKE 't' \G
-- Row_format: Redundant（旧表）

-- 在 MySQL 8.0 中显式创建 REDUNDANT 格式的表（通常只为兼容旧表，不推荐）
CREATE TABLE old_style (
    id   INT NOT NULL,
    name VARCHAR(50),
    PRIMARY KEY (id)
) ENGINE = InnoDB ROW_FORMAT = REDUNDANT;

-- 将 REDUNDANT 格式的旧表升级到 DYNAMIC 格式
ALTER TABLE old_style ROW_FORMAT = DYNAMIC;
-- 注意：这会重建整张表（类似 OPTIMIZE TABLE）

-- 查看数据库中所有使用 REDUNDANT 格式的表
SELECT TABLE_SCHEMA, TABLE_NAME, ROW_FORMAT
FROM information_schema.TABLES
WHERE ENGINE = 'InnoDB'
  AND ROW_FORMAT = 'Redundant'
  AND TABLE_SCHEMA NOT IN ('mysql', 'sys', 'information_schema', 'performance_schema');
-- 在 MySQL 8.0 环境中，这类表通常是从老版本迁移来的
```

## REDUNDANT 格式的历史地位

```
时间线：
  MySQL 5.0 之前：InnoDB 只有 REDUNDANT 格式
  MySQL 5.0：引入 COMPACT 格式（更节省空间）
  MySQL 5.7.9+：DEFAULT_ROW_FORMAT 参数（默认 DYNAMIC）
  MySQL 8.0：innodb_default_row_format = DYNAMIC（默认）

  REDUNDANT 格式从未被废弃（deprecated），但新表很少使用它
  主要存在于从 MySQL 4.x/5.0 迁移来的旧库中

实际影响：
  如果从 MySQL 5.6 以前的版本迁移数据，
  原来的表可能是 REDUNDANT 格式
  不迁移的话可以继续使用（功能完全兼容），
  但建议逐步迁移到 DYNAMIC 格式以利用现代行格式的特性
```

---

## 适用场景

- **旧库升级**：从 MySQL 4.x/5.0 迁移来的表可能是 REDUNDANT 格式，可以通过 `ALTER TABLE ... ROW_FORMAT = DYNAMIC` 批量迁移，释放额外空间并获得 DYNAMIC 格式的大字段优化
- **兼容性场景**：如果需要将数据迁回极旧的 MySQL 版本（4.x），REDUNDANT 是唯一兼容的格式（在实际中极少见）

## 常见问题

**现有 REDUNDANT 格式的表不修改行格式会有功能问题吗？**

功能上完全兼容，MySQL 8.0 完整支持 REDUNDANT 格式的读写。但 REDUNDANT 格式的行记录更大（尤其是有多个 INT 列且有 NULL 值时），占用更多磁盘空间和 Buffer Pool。另外，REDUNDANT 格式不支持大索引前缀（> 767 字节），对于包含长 VARCHAR 字段索引的表，如果需要更长的索引前缀，必须迁移到 DYNAMIC 或 COMPRESSED 格式。

---

## 注意事项

- REDUNDANT 格式的列偏移量条目数量等于该表的列数（含 NULL 列），而 COMPACT 的变长字段长度列表只包含有值的变长列。对于列数多（如几十列）且有大量 NULL 值的表，REDUNDANT 格式的行开销（偏移量列表）比 COMPACT/DYNAMIC 大很多。
- MySQL 8.0 的 `innodb_default_row_format = DYNAMIC` 只影响未显式指定行格式的新建表，`ROW_FORMAT = REDUNDANT` 明确指定时仍然生效。但不建议在新表中使用 REDUNDANT 格式，没有任何优势。

---

## 总结

REDUNDANT 是 InnoDB 最早的行格式（MySQL 5.0 之前唯一可用），行记录头部包含所有列的末尾偏移量（逆序，含 NULL 列）+ 6字节 Record Header + 隐藏列 + 实际列值。特点是"冗余"——无论列是否为 NULL、是否定长，都在偏移量列表中占条目，导致行记录比 COMPACT/DYNAMIC 更大。现代 MySQL 8.0 环境中不建议新表使用，对于旧版本迁移来的 REDUNDANT 格式表，建议通过 `ALTER TABLE ... ROW_FORMAT = DYNAMIC` 逐步迁移。
