# 变长字段长度列表

变长字段长度列表（Variable-Length Field Length List）是 COMPACT/DYNAMIC 格式行记录头部的第一个组成部分，逆序存储该行中每个有实际值（非 NULL）的变长列的字节长度。InnoDB 在读取行记录时，需要知道每个变长列在行中占用多少字节，才能正确解析列值。变长字段长度列表就承担了这个职责，其编码方式根据列长度的大小使用 1 字节或 2 字节来表示。

---

## 哪些列进入变长字段长度列表

```
参与变长字段长度列表的列类型：

需要记录长度的列（列值非 NULL 时进入列表）：
  → VARCHAR(N)：实际存储字节数（≤ N × 字符集最大字节数）
  → VARBINARY(N)：实际存储字节数（≤ N）
  → BLOB, TINYBLOB, MEDIUMBLOB, LONGBLOB：实际字节数
  → TEXT, TINYTEXT, MEDIUMTEXT, LONGTEXT：实际字节数
  → 多字节字符集（如 utf8mb4）下的 CHAR(N)：实际字节数可变，也进入列表

不进入变长字段长度列表的列：
  → INT, BIGINT, FLOAT, DOUBLE：定长，不需要记录长度
  → DECIMAL(M,D)：固定字节数
  → DATE, TIME, DATETIME, TIMESTAMP：固定字节数
  → 单字节字符集（latin1）下的 CHAR(N)：固定 N 字节，不进入列表
  → 值为 NULL 的列：不进入列表（NULL 信息在 NULL 位图中）
```

## 长度的编码规则

```
变长字段长度的存储规则：

规则1：列字节数 ≤ 127 字节 → 用 1 字节存储
  最高位（bit 7）= 0
  低 7 位存储长度值
  例如：25 字节 → [0x19]（十进制 25）

规则2：列字节数 > 127 字节 → 用 2 字节存储
  第一字节最高位（bit 7）= 1（标识这是 2 字节长度）
  实际长度用 15 位表示（最大 32767 字节）
  例如：500 字节 → 
    低字节：0x80 | (500 & 0x7F) = 0x80 | 0x74 = 0xF4
    高字节：500 >> 7 = 3 = 0x03
    存储为：[0xF4 0x03]（注意字节序）

规则3：如果是 off-page（行溢出）列
  最高 2 位 bit7 = 1, bit6 = 1（两位都是 1）
  表示该列是 off-page 存储
```

## 逆序存储的原因

```
变长字段长度列表按列定义逆序排列：

表定义（顺序）：
  col1 INT      （定长，不进入列表）
  col2 VARCHAR(50)（变长，进入列表）
  col3 INT      （定长，不进入列表）
  col4 VARCHAR(100)（变长，进入列表）

插入一行：(1, 'hello', 42, 'world')
  col2 = 'hello' → 5 字节
  col4 = 'world' → 5 字节

变长字段长度列表（逆序）：
  [col4的长度=5] [col2的长度=5]
  即：[0x05 0x05]
  注意：先存 col4（后面的列），再存 col2（前面的列）

逆序的设计意图：
  Record Header 在变长字段列表之后，紧跟列值区域
  从 Record Header 位置向前（低地址方向）读取变长字段列表
  逆序使得"第一列的长度"距离列值区域最近，便于顺序解析列值
```

## 举例解析完整的变长字段长度列表

```sql
-- 表结构
CREATE TABLE t (
    id     INT      NOT NULL,
    name   VARCHAR(50),         -- 变长，utf8mb4，最多 200 字节
    score  INT,
    note   VARCHAR(200),        -- 变长，utf8mb4，最多 800 字节
    tag    CHAR(10),             -- utf8mb4，变长（1-40字节），也进入列表
    PRIMARY KEY (id)
) ENGINE = InnoDB ROW_FORMAT = COMPACT;

-- 插入：INSERT INTO t VALUES (1, 'Alice', NULL, '备注信息', 'A');
-- 分析变长字段长度列表：
-- 涉及的变长列（非 NULL）：
--   name = 'Alice'（5字节 utf8mb4 ASCII）
--   note = '备注信息'（4个汉字 × 3字节/字(utf8) = 12字节）
--   tag = 'A'（1字节 utf8mb4 ASCII）
-- score = NULL → 不在变长字段列表（NULL 的列不算）

-- 逆序：tag → note → name（score 跳过，是 NULL；id 跳过，是定长）
-- 存储顺序：[tag=1字节] [note=12字节] [name=5字节]
-- 编码：1 ≤ 127 → 1字节: [0x01], 12 ≤ 127 → 1字节: [0x0C], 5 ≤ 127 → 1字节: [0x05]
-- 变长字段长度列表：[0x01 0x0C 0x05]（3字节）

-- 分析（正序读取）：
-- 倒着读：0x05=5（name），0x0C=12（note），0x01=1（tag）
```

## 变长字段长度列表的大小影响

```sql
-- 变长字段长度列表的大小 = 非 NULL 变长列的数量 × 1-2 字节
-- 对于大多数行，每个变长列占 1 字节（如果列值 ≤ 127 字节）
-- 对于较大的 VARCHAR 值（> 127 字节），占 2 字节

-- 举例：表有 10 个 VARCHAR 列，每列值 ≤ 127 字节且非 NULL：
-- 变长字段长度列表：10 × 1 = 10 字节
-- 对比 REDUNDANT 格式：10 个列的偏移量列表 ≈ 10 × 2 = 20 字节
-- → COMPACT/DYNAMIC 节省约 10 字节/行

-- 变长字段长度列表的上限：
-- 如果所有列都是大 VARCHAR（> 127 字节）且非 NULL：
-- N 个变长列 × 2 字节/列 = 2N 字节
-- N = 100 个列 → 200 字节（较大，但不影响性能）
```

## 适用场景

- **行大小计算**：理解变长字段长度列表的构成，有助于更准确地计算行记录的实际存储大小，从而估算每个数据页能存多少行，进而推算表的总页数和 B+ Tree 的层级
- **NULL 优化**：NULL 值的列不在变长字段长度列表中，也不占行内存储空间（NULL 位图中只占 1 bit），这是 InnoDB 设计中鼓励合理使用 NULL 值的存储层依据

## 常见问题

**如果一个 VARCHAR 列的实际值为空字符串（''），它在变长字段长度列表中如何存储？**

空字符串（''）不等于 NULL，它的长度是 0。在变长字段长度列表中存储 0（即 [0x00]，1 字节），在列值区域不存储任何字节（0 字节）。而 NULL 值则完全不在变长字段长度列表中出现（只在 NULL 位图中标记），也不在列值区域存储任何内容。因此空字符串（0字节值 + 1字节长度记录）比 NULL（0字节值 + 0字节长度记录 + 1 bit NULL 位图）稍微多占用一点空间。

## 注意事项

- 变长字段长度列表中的列顺序严格按照列定义的逆序排列，InnoDB 在解析行记录时依赖这个顺序。如果 `ALTER TABLE` 重排了列顺序（`ADD COLUMN ... AFTER`），InnoDB 会在重建表时重新调整变长字段列表的顺序，不会出现顺序错乱。
- utf8mb4 字符集下的 CHAR(N) 列也进入变长字段长度列表（因为每个字符占 1-4 字节，CHAR 实际字节数可变）。而在单字节字符集（如 latin1）下，CHAR(N) 固定占 N 字节，不进入变长字段列表。这是 utf8mb4 与 latin1 在行格式层面的细微差异之一。

## 总结

变长字段长度列表是 COMPACT/DYNAMIC 行记录头部的首要组成部分，逆序存储每个非 NULL 变长列（VARCHAR/TEXT/BLOB/多字节 CHAR）的实际字节长度。长度 ≤ 127 字节时用 1 字节编码，> 127 字节时用 2 字节编码（最高位置1区分）。NULL 列和定长列不进入此列表。逆序排列的设计使得从 Record Header 向前读取列表时，第一个读到的长度对应最后一个变长列，按列顺序正向解析列值时使用对应的长度值。正确理解变长字段长度列表是分析行大小、存储效率和 NULL 处理的基础。
