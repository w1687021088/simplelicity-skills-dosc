# COMPACT 行格式（5.0 后默认）

COMPACT 是 InnoDB 在 MySQL 5.0 引入的行格式，在 MySQL 8.0 之前是所有版本的默认行格式（8.0 之后默认改为 DYNAMIC）。COMPACT 格式相比早期的 REDUNDANT 格式，显著减少了行记录占用的存储空间，主要优化是不再重复存储每列的偏移量（REDUNDANT 中存储了每列末尾的绝对偏移量），改用更紧凑的变长字段长度列表 + NULL 位图的方式描述行结构。

---

## COMPACT 行格式的完整结构

```
COMPACT 格式一条完整行记录的字节布局：

┌───────────────────────────────────────────────────────────────────────┐
│ 变长字段长度列表                                                        │
│ （Variable-Length Field Length List）                                  │
│ 逆序存储每个 VARCHAR/VARBINARY/BLOB/TEXT 列的实际字节长度               │
│ 每个长度占 1 字节（≤127字节）或 2 字节（>127字节），NULL 列不包含        │
├───────────────────────────────────────────────────────────────────────┤
│ NULL 值位图                                                             │
│ （NULL Flags Bitmap）                                                  │
│ 对每个可为 NULL 的列占 1 bit（按列定义顺序逆序）                        │
│ 1 = 该列为 NULL，0 = 非 NULL                                           │
├───────────────────────────────────────────────────────────────────────┤
│ Record Header（5字节）                                                  │
│ delete_mask | min_rec | n_owned | heap_no | record_type | next_record │
├───────────────────────────────────────────────────────────────────────┤
│ 隐藏列（仅聚簇索引行）                                                   │
│ DB_ROW_ID（6字节，无显式主键时才有）                                    │
│ DB_TRX_ID（6字节，最后修改此行的事务 ID）                              │
│ DB_ROLL_PTR（7字节，指向 Undo Log 的回滚指针）                         │
├───────────────────────────────────────────────────────────────────────┤
│ 实际列值                                                                │
│ 按列定义顺序排列                                                        │
│ NULL 列不占存储空间（仅在 NULL 位图中标记）                             │
│ 定长列（INT, CHAR, DATE 等）按固定字节存储                              │
│ 变长列（VARCHAR, VARBINARY 等）按实际字节存储                           │
└───────────────────────────────────────────────────────────────────────┘
```

## 举例说明 COMPACT 行记录

```sql
-- 表定义
CREATE TABLE t (
    id      INT         NOT NULL,
    name    VARCHAR(50),
    score   INT,
    remark  VARCHAR(100),
    PRIMARY KEY (id)
) ROW_FORMAT = COMPACT;

-- 插入一行：INSERT INTO t VALUES (1, 'Alice', NULL, 'hello');
-- 分析行记录组成：

-- 变长字段（逆序）：remark='hello'(5字节) → name='Alice'(5字节)
-- → 变长字段长度列表：[05 05]（remark 在前逆序，所以先写 remark 的长度，再写 name 的长度）
-- 实际：因为列是 name, score, remark 顺序，逆序就是 remark length, name length
-- → [05 05]

-- NULL 位图：NULL 列有 name, score, remark（三个可为 NULL 的列）
-- score = NULL → score 对应 bit = 1
-- name = 'Alice' → 非 NULL，bit = 0
-- remark = 'hello' → 非 NULL，bit = 0
-- 逆序排列：remark(0) score(1) name(0) = 010 = 0x02
-- → [02]

-- Record Header（5字节）：包含 delete_mask, heap_no, next_record 等

-- 实际列值：
-- id = 1 → [00 00 00 01]（4字节，INT）
-- name = 'Alice' → [41 6C 69 63 65]（5字节，实际字节）
-- score = NULL → 不存储（已在 NULL 位图标记）
-- remark = 'hello' → [68 65 6C 6C 6F]（5字节）
```

## CHAR 类型在 COMPACT 格式中的处理

```sql
-- 与 VARCHAR 不同，CHAR 是定长的
-- 但对于多字节字符集（如 utf8mb4），CHAR(N) 的实际字节数是变长的
-- → COMPACT 格式中，CHAR 列的长度也会记录在变长字段列表中（如果字符集是多字节）

-- 示例：CHAR(10) UTF8MB4（每字符最多 4 字节）
-- 存储 '你好'（2个汉字，6字节）：
--   → COMPACT 格式：变长字段列表中记录 6，实际存储 6 字节
-- 存储 'ab'（2个 ASCII 字符，2字节）：
--   → 变长字段列表中记录 2，实际存储 2 字节
-- 但如果字符集是 latin1（单字节），CHAR(10) 固定存储 10 字节，
-- 不在变长字段列表中记录

-- 查看表的行格式
SHOW TABLE STATUS LIKE 'orders' \G
-- Row_format: Compact

-- 或查询
SELECT TABLE_NAME, ROW_FORMAT
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'myapp' AND TABLE_NAME = 'orders';
```

## COMPACT 与 REDUNDANT 的大小对比

```
举例（表有 10 列，其中 5 个 VARCHAR，3 个 INT，2 个 NULL）：

REDUNDANT 格式行记录：
  列偏移量列表：10 个列 × 2 字节 = 20 字节（或每列 1-2字节）
  Record Header：6 字节
  实际列值：N 字节

COMPACT 格式行记录：
  变长字段长度列表：5 个 VARCHAR × 1-2 字节 = 5-10 字节（仅变长列）
  NULL 位图：2 列可 NULL → 1 字节
  Record Header：5 字节（比 REDUNDANT 少 1 字节）
  实际列值：N 字节

节省空间：大约节省 10-15 字节/行
对于一个 1000 万行的表：节省约 100-150 MB

实际影响：
  Buffer Pool 中可以缓存更多行（每行更小）
  I/O 减少（同一页可以存更多行）
```

## COMPACT 格式的限制

```sql
-- 单行最大长度（不含 off-page 溢出列）：
-- 对于 16KB 页：约 8000 字节（小于半页）
-- 超过此限制的 VARCHAR/TEXT/BLOB 列会被存储为"行溢出"（off-page）

-- 查看表的最大行长度
SELECT
    TABLE_NAME,
    CREATE_OPTIONS,
    ROW_FORMAT,
    AVG_ROW_LENGTH,
    MAX_DATA_LENGTH
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'myapp' AND TABLE_NAME = 'orders';

-- 修改表的行格式（MySQL 8.0 之前的旧表可能是 COMPACT）
ALTER TABLE orders ROW_FORMAT = DYNAMIC;
-- 注意：修改行格式会重建整张表（全表锁）
-- 生产环境建议用 pt-online-schema-change 在线修改
```

## 适用场景

- **旧系统迁移**：MySQL 5.0-5.7 创建的表默认使用 COMPACT 格式，升级到 8.0 后仍保持 COMPACT，不会自动升级到 DYNAMIC。如果需要支持大字段索引前缀（> 767 字节，需要 DYNAMIC 格式 + innodb_large_prefix），需要手动 ALTER TABLE 修改行格式
- **行大小优化**：相比 REDUNDANT，COMPACT 减少了列偏移量的存储开销，适合列数多的宽表

## 常见问题

**COMPACT 格式和 DYNAMIC 格式的主要区别是什么？**

两种格式在行记录头部结构上基本相同，核心区别在于处理大字段（VARCHAR/BLOB/TEXT）超出行内存储阈值时的策略：COMPACT 格式将大字段的前 768 字节内联存储，剩余部分放到 off-page（行溢出页）；DYNAMIC 格式直接将整个大字段放到 off-page，行内只存储一个 20 字节的指针。DYNAMIC 格式对大字段更友好，避免了 COMPACT 的"前缀内联"导致的存储浪费，也是 MySQL 8.0 默认使用 DYNAMIC 的原因。

---

## 注意事项

- 在多字节字符集（utf8mb4）下，COMPACT 格式中 CHAR(N) 列也会在变长字段长度列表中记录实际长度（因为 utf8mb4 每字符 1-4 字节，CHAR(10) 的字节数是变长的）。这一点与 latin1 等单字节字符集不同（latin1 的 CHAR(N) 固定 N 字节，不在变长字段列表中）。
- COMPACT 格式的 NULL 位图只为"可为 NULL 的列"（NOT NULL 列不在位图中）分配 bit 位。如果所有列都是 NOT NULL，NULL 位图为空（0字节）。

---

## 总结

COMPACT 是 MySQL 5.0 引入、8.0 之前的默认行格式，行记录由变长字段长度列表（逆序存储变长列实际长度）+ NULL 位图（1bit/可NULL列）+ Record Header（5字节）+ 隐藏列（DB_TRX_ID、DB_ROLL_PTR）+ 实际列值组成。NULL 列不占实际存储空间（仅位图标记），变长列按实际长度存储。相比 REDUNDANT 节省约 10-15 字节/行。大字段超出阈值时内联前 768 字节 + off-page 剩余（区别于 DYNAMIC 的全量 off-page）。
