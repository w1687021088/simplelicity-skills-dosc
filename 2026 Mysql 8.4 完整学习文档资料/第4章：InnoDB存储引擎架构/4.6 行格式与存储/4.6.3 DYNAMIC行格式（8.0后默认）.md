# DYNAMIC 行格式（8.0 后默认）

DYNAMIC 是 MySQL 8.0 的默认行格式（通过 `innodb_default_row_format = DYNAMIC` 控制），在 MySQL 5.7.9 中已可以配置为默认。DYNAMIC 格式在 COMPACT 的基础上改进了大字段（VARCHAR/BLOB/TEXT）的处理方式：当一列的数据超过页内阈值时，整个字段的内容（不是只有前缀）存储到 off-page（行溢出页），行内只保留一个 20 字节的指针。这与 COMPACT 格式内联前 768 字节的策略不同，使得行内存储更紧凑。

---

## DYNAMIC 格式的核心特性

```
DYNAMIC 格式的行溢出策略：

情形1：列值较小（能放入页内）
  → 与 COMPACT 格式完全相同，整个列值内联存储在行内

情形2：列值较大（超出阈值）
  → COMPACT：内联存储前 768 字节 + off-page 指针存储剩余
  → DYNAMIC：行内完全不存储列值内容，只存储 20 字节的 off-page 指针

DYNAMIC 的溢出阈值：
  目标是每行至少有 2 条记录能放入 16KB 页（保证 B+ Tree 不退化）
  → 每行内联部分 <= 8000 字节
  当某一行的总内联大小接近 8000 字节时，
  最大的变长列被转为 off-page 存储（20 字节指针）
  重复此过程直到行内联部分 <= 8000 字节

优点：
  → 行内不浪费空间存储"前 768 字节前缀"
  → 对于大字段，行内实际上比 COMPACT 更小（只有指针）
  → 聚簇索引页可以存更多行（提高缓存效率）
```

## 如何查看和设置 DYNAMIC 格式

```sql
-- 查看默认行格式
SHOW VARIABLES LIKE 'innodb_default_row_format';
-- MySQL 8.0：DYNAMIC

-- 创建 DYNAMIC 格式的表（MySQL 8.0 默认，无需显式指定）
CREATE TABLE orders (
    id         BIGINT AUTO_INCREMENT PRIMARY KEY,
    amount     DECIMAL(10, 2),
    description TEXT
) ENGINE = InnoDB;  -- 默认就是 DYNAMIC

-- 显式指定（清晰表达意图）
CREATE TABLE orders_explicit (
    id         BIGINT AUTO_INCREMENT PRIMARY KEY,
    amount     DECIMAL(10, 2),
    description TEXT
) ENGINE = InnoDB ROW_FORMAT = DYNAMIC;

-- 查看表的行格式
SELECT TABLE_NAME, ROW_FORMAT
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'myapp' AND TABLE_NAME = 'orders';

-- 将旧的 COMPACT 表迁移到 DYNAMIC
ALTER TABLE old_compact_table ROW_FORMAT = DYNAMIC;
-- 这会重建整张表，生产环境建议用 pt-online-schema-change
```

## DYNAMIC 格式与大索引前缀支持

```sql
-- DYNAMIC 格式支持 innodb_large_prefix（大索引前缀）
-- innodb_large_prefix 在 MySQL 8.0 已废弃（行为始终开启）

-- COMPACT/REDUNDANT 格式：索引前缀最大 767 字节
-- DYNAMIC/COMPRESSED 格式：索引前缀最大 3072 字节

-- 举例：utf8mb4 字符集，VARCHAR(255) 最多 1020 字节
-- COMPACT 格式下：创建前 190 字符的索引（190 × 4 = 760 字节，不超 767）
-- DYNAMIC 格式下：可以创建前 768 字符的索引（768 × 4 = 3072 字节，恰好达到上限）

-- 在 DYNAMIC 格式下创建长索引前缀
CREATE TABLE products (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    title       VARCHAR(500),
    description TEXT,
    INDEX idx_title (title(255))  -- 255 × 4(utf8mb4) = 1020 字节，DYNAMIC 支持
) ENGINE = InnoDB ROW_FORMAT = DYNAMIC;

-- COMPACT 格式下同样的操作会报错或截断到 191 字符
```

## DYNAMIC 格式的行溢出 vs COMPACT

```
对比：存储一行含 16KB TEXT 字段的记录

COMPACT 格式：
  行内：... [前768字节内联] [off-page指针1（20字节）] ...
  off-page：剩余 16384 - 768 = 15616 字节（存储在独立溢出页）
  结果：行内占用 768 字节（巨大！影响行密度）

DYNAMIC 格式：
  行内：... [off-page指针（20字节）] ...
  off-page：全部 16384 字节（存储在独立溢出页）
  结果：行内只占 20 字节（非常紧凑！）

对于只有一个 TEXT 字段且其他列较少的情况：
  COMPACT：行内总大小可能接近 800+ 字节
  DYNAMIC：行内总大小可能只有 50-100 字节
  → DYNAMIC 可以在一个 16KB 页内存放多很多行（缓存效率高）
```

## 行格式对全文索引的影响

```sql
-- FULLTEXT 索引（全文索引）只支持 DYNAMIC 和 COMPRESSED 格式
-- 不支持 COMPACT 和 REDUNDANT

-- 如果表使用 COMPACT 格式且需要添加全文索引：
-- 先修改行格式：
ALTER TABLE articles ROW_FORMAT = DYNAMIC;
-- 再添加全文索引：
ALTER TABLE articles ADD FULLTEXT INDEX ft_content (content);

-- 或者在创建表时直接使用 DYNAMIC + 全文索引：
CREATE TABLE articles (
    id      INT AUTO_INCREMENT PRIMARY KEY,
    title   VARCHAR(200),
    content TEXT,
    FULLTEXT INDEX ft_content (content)
) ENGINE = InnoDB;  -- MySQL 8.0 默认 DYNAMIC，支持 FULLTEXT
```

## 适用场景

- **新建表的标准选择**：MySQL 8.0 中所有新表默认使用 DYNAMIC 格式，无需特别指定，是生产环境的标准行格式
- **包含大字段的表**：TEXT/BLOB 字段或较长的 VARCHAR，DYNAMIC 的 off-page 处理使行内更紧凑，提升聚簇索引页的行密度，减少磁盘 I/O

## 常见问题

**DYNAMIC 格式的 off-page 存储会影响查询性能吗？**

会有影响，但影响程度取决于查询是否实际读取溢出列。如果 SELECT 只查询非溢出列（如 `SELECT id, amount FROM orders`），InnoDB 不会读取 off-page 数据，性能无影响。只有当查询需要溢出列的值（如 `SELECT description FROM orders`）时，才需要额外读取 off-page 页（额外 1-2 次磁盘 I/O）。因此，对于只偶尔查询大字段的场景，DYNAMIC 格式实际上比 COMPACT 更高效（行更小，缓存更多非溢出数据）。

---

## 注意事项

- `innodb_default_row_format` 参数影响没有显式指定 `ROW_FORMAT` 的新建表，但通过 `CREATE TABLE ... ROW_FORMAT = COMPACT` 显式指定的表不受影响。将该参数从 COMPACT 改为 DYNAMIC，只影响此后创建的表，不自动迁移已有表。
- 从 COMPACT 格式迁移到 DYNAMIC 格式（通过 `ALTER TABLE`）时，包含大 TEXT/BLOB 的行的存储结构会改变（从前768字节内联变为完全 off-page），这一过程会重建整张表，对于大表需要较长时间。

---

## 总结

DYNAMIC 是 MySQL 8.0 的默认行格式（`innodb_default_row_format = DYNAMIC`），行记录头部结构与 COMPACT 相同（变长字段长度列表 + NULL 位图 + Record Header + 隐藏列）。核心差异是大字段溢出策略：超阈值的列完全存到 off-page，行内只保留 20 字节指针（而非 COMPACT 的前768字节内联）。支持最大 3072 字节的索引前缀（utf8mb4 下约 768 字符），支持 FULLTEXT 索引。对包含 TEXT/BLOB 字段的表，DYNAMIC 格式的行内更紧凑，聚簇索引页行密度更高。
