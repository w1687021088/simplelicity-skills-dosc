# 行溢出 Off-page 存储

Off-page（行溢出）是 InnoDB 在行记录过大时，将部分列的内容存储到独立的溢出页（Overflow Page）中，而在原行记录（Leaf Page）中保留一个指针指向溢出页的机制。触发行溢出的场景是：一行内所有列的内联内容总和超过 InnoDB 的单行内联限制（约 8000 字节，用于保证每个 16KB 页至少可以存放 2 条记录）。不同行格式（COMPACT vs DYNAMIC）对行溢出的处理策略不同。

---

## 行溢出的触发条件

```
触发条件：
  单行内联存储大小 > 8000 字节（16KB 页的约一半 - 固定开销）
  
  实际值（16384 - 128 字节固定开销 - 索引记录开销）≈ 8000 字节
  
  当一行的列值总和接近此阈值时：
  InnoDB 选择"最大的变长列"转为 off-page 存储
  重复直到行内联部分 ≤ 8000 字节

触发溢出的常见列类型：
  TEXT（最多 65535 字节）
  MEDIUMTEXT（最多 16777215 字节）
  LONGTEXT（最多 4294967295 字节）
  BLOB, MEDIUMBLOB, LONGBLOB
  VARCHAR(N)（N > 约 8000 字节时）
  
  注意：INT/DECIMAL/DATETIME 等定长类型不会溢出
        VARCHAR(255) utf8mb4 最多 1020 字节，通常不溢出
```

---

## COMPACT 格式的行溢出处理

```
COMPACT 格式溢出策略：
  当列需要溢出时：
    → 保留列的前 768 字节在行内（内联前缀）
    → 剩余内容存储到 off-page 溢出页
    → 行内存储：[768字节前缀] + [20字节 off-page 指针]

  off-page 指针结构（20字节）：
    [space_id (4字节)] [page_no (4字节)] [offset (4字节)] + [length info (8字节)]

  优点：行内有前缀数据，某些小范围操作（如 LEFT(column, 100)）可能无需读 off-page
  缺点：768 字节前缀浪费行内空间（哪怕不需要前缀）

溢出页的存储：
  溢出数据存储在 FIL_PAGE_TYPE_BLOB 类型的页（16KB 溢出页）
  每个溢出页包含一部分溢出数据 + 指向下一个溢出页的指针（溢出链）
  如果数据超过一个溢出页（16KB），则形成溢出页链表
```

---

## DYNAMIC 格式的行溢出处理

```
DYNAMIC 格式溢出策略：
  当列需要溢出时：
    → 行内完全不存储列值（不保留前缀）
    → 只存储 20 字节的 off-page 指针
    → 行内存储：[20字节 off-page 指针]

  优点：行内占用更小（只有指针，不有 768 字节前缀）
        对于有多个大字段的行，行内非常紧凑
  缺点：任何对溢出列的访问都需要读 off-page（哪怕只取前几字节）

  DYNAMIC 格式下溢出的触发更"激进"：
    只要一行超过内联阈值，大字段就被整体移到 off-page
    而不是 COMPACT 的先保留 768 字节前缀
```

## 溢出页的结构

```
溢出页（FIL_PAGE_TYPE_BLOB）：

┌────────────────────────────────────────────────────────┐
│ File Header（38字节）                                   │
│  - FIL_PAGE_TYPE = FIL_PAGE_TYPE_BLOB (10)             │
│  - FIL_PAGE_PREV / FIL_PAGE_NEXT（溢出链）            │
├────────────────────────────────────────────────────────┤
│ Blob 页头（8字节）                                      │
│  - 实际数据长度                                         │
│  - 下一个溢出页的指针（空间 ID + 页号 + 偏移量）        │
├────────────────────────────────────────────────────────┤
│ 溢出数据内容                                            │
│ （16384 - 38 - 8 = 约 16338 字节可用）                 │
└────────────────────────────────────────────────────────┘

如果数据超过一个溢出页：
  溢出页1 → 溢出页2 → 溢出页3 → ...（链表结构）
  每页存储约 16KB 数据
  一个 LONGBLOB（最大 4GB）需要约 4GB / 16KB ≈ 256K 个溢出页
```

## 查看行溢出信息

```sql
-- 查看表中溢出数据的情况
SELECT
    PAGE_NUMBER,
    PAGE_TYPE,
    TABLE_NAME,
    INDEX_NAME
FROM information_schema.INNODB_BUFFER_PAGE
WHERE PAGE_TYPE = 'BLOB'
  AND TABLE_NAME = '`myapp`.`orders`'
LIMIT 20;
-- BLOB 类型的页就是溢出页

-- 估算溢出列的实际大小
SELECT
    id,
    LENGTH(description) AS desc_len,
    LENGTH(attachment) AS attach_len
FROM orders
WHERE id BETWEEN 1 AND 100;
-- 如果 desc_len > 约 8000 字节，该行的 description 可能会溢出

-- 查看包含溢出数据的页数量
SELECT PAGE_TYPE, COUNT(*) AS page_count
FROM information_schema.INNODB_BUFFER_PAGE
WHERE TABLE_NAME = '`myapp`.`articles`'
GROUP BY PAGE_TYPE;
-- 如果 BLOB 页很多，说明有大量溢出数据
```

## 行溢出对性能的影响

```sql
-- 影响1：I/O 增加
-- 读取溢出列时，除了读取 Leaf Page（行记录页），
-- 还需要额外读取 off-page（溢出页）
-- 每个溢出列：至少 1 次额外 I/O（如果溢出页未在 Buffer Pool 中）
-- 大 BLOB：可能需要读取多个链式溢出页

-- 优化策略：
-- 1. 不在 SELECT * 中读取不需要的大字段
SELECT id, title, created_at FROM articles;  -- 不读 content
-- 而不是：SELECT * FROM articles;

-- 2. 对大字段单独查询（应用层分两步查询）
-- 第一步：获取元数据
SELECT id, title FROM articles WHERE id = 123;
-- 第二步：按需加载内容
SELECT content FROM articles WHERE id = 123;  -- 只在需要时读取溢出列

-- 3. 考虑将大字段存储到对象存储（OSS/S3），数据库只存 URL
-- 彻底避免行溢出问题
```

## 适用场景

- **大字段表设计**：理解行溢出机制，选择合适的行格式（DYNAMIC 优于 COMPACT）和查询模式（避免 SELECT * 读取不必要的溢出列）
- **性能问题排查**：如果某个表的查询异常慢，检查是否有大量溢出列被读取（通过 Buffer Pool 中 BLOB 类型页的数量判断）

## 常见问题

**VARCHAR(65535) 和 TEXT 有什么区别？溢出处理是否相同？**

VARCHAR(65535) 在 utf8mb4 字符集下实际最大字节数为 65535×4 = 262140 字节，远超页内阈值，绝大多数情况下会触发溢出存储，其处理方式与 TEXT 完全相同（DYNAMIC 格式下整体 off-page，COMPACT 格式下前768字节内联）。实际上，VARCHAR 列如果很短（通常小于 768 字节），建议使用 VARCHAR 而非 TEXT；如果确定会很长（如文章正文），TEXT 和 VARCHAR(65535) 的存储效果相同，但 TEXT 语义更清晰，且不受 MySQL 65535 字节单行大小限制的影响（TEXT 类型不计入行大小限制，因为它必然 off-page 存储）。

---

## 注意事项

- 行溢出只影响 VARCHAR/TEXT/BLOB 等变长大字段，INT/DECIMAL/CHAR 等定长类型不会溢出（CHAR 在 COMPACT/DYNAMIC 格式中虽然可变字节数，但受列定义的上限限制）。
- 在 DYNAMIC 格式下，如果一行中有多个 TEXT/BLOB 字段，InnoDB 会从最大的字段开始溢出，直到行内联部分 ≤ 8000 字节为止。并不是所有大字段都会溢出，只有让行大小超限的那些字段才会溢出。

---

## 总结

行溢出（Off-page）是行记录超过约 8000 字节内联限制时，将大字段内容移至独立溢出页的机制。COMPACT 格式保留列的前768字节在行内 + 20字节off-page指针；DYNAMIC 格式完全 off-page，只在行内留20字节指针（更紧凑）。溢出页为 FIL_PAGE_TYPE_BLOB 类型（16KB），多个溢出页形成链表。访问溢出列需要额外 I/O，优化策略是避免 `SELECT *` 读取不需要的大字段，或将大二进制数据存储到对象存储。
