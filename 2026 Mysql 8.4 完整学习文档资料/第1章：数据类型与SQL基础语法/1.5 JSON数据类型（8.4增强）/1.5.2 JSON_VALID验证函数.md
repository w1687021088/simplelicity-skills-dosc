## JSON_VALID 验证函数

`JSON_VALID()` 是 MySQL 中用于检查一个字符串是否是合法 JSON 格式的函数。它在处理从外部来源（用户输入、API 导入、历史存量数据）接收到的 JSON 字符串时特别有用，可以在写入 JSON 列之前或数据迁移时做格式验证。

---

### 函数语法

```sql
JSON_VALID(val)
```

返回值：
- `1`：val 是有效的 JSON 格式
- `0`：val 是无效的 JSON 格式
- `NULL`：val 为 NULL

---

### 基本用法示例

```sql
-- 有效的 JSON 值
SELECT JSON_VALID('{"name": "Alice", "age": 28}');  -- 1
SELECT JSON_VALID('[1, 2, 3]');                       -- 1
SELECT JSON_VALID('"hello"');                          -- 1（JSON 字符串）
SELECT JSON_VALID('true');                             -- 1（JSON 布尔值）
SELECT JSON_VALID('null');                             -- 1（JSON null）
SELECT JSON_VALID('42');                               -- 1（JSON 数字）

-- 无效的 JSON 值
SELECT JSON_VALID("{'name': 'Alice'}");               -- 0（单引号不合法）
SELECT JSON_VALID('{name: "Alice"}');                 -- 0（key 没有引号）
SELECT JSON_VALID('[1, 2, 3,]');                      -- 0（尾部多余逗号）
SELECT JSON_VALID('undefined');                        -- 0（undefined 不是合法 JSON 值）
SELECT JSON_VALID('{');                                -- 0（不完整）

-- NULL 输入
SELECT JSON_VALID(NULL);                              -- NULL
```

---

### 在插入前验证

```sql
-- 创建带 JSON 列的表
CREATE TABLE json_store (
    id      INT UNSIGNED NOT NULL AUTO_INCREMENT,
    data    JSON,
    raw     TEXT,   -- 原始字符串（可能无效）
    PRIMARY KEY (id)
);

-- 只有有效 JSON 才插入 data 列，否则插入 NULL
INSERT INTO json_store (data, raw)
SELECT 
    CASE WHEN JSON_VALID(raw_input) = 1 THEN raw_input ELSE NULL END,
    raw_input
FROM (
    SELECT '{"key": "value"}' AS raw_input UNION ALL
    SELECT '{bad json}'        AS raw_input
) AS t;

SELECT id, data, raw FROM json_store;
-- id=1: data={"key": "value"}, raw={"key": "value"}
-- id=2: data=NULL,             raw={bad json}
```

### 数据迁移中的应用

```sql
-- 将 TEXT 列中的 JSON 字符串迁移到 JSON 列
-- 先创建目标列
ALTER TABLE legacy_table ADD COLUMN data_json JSON;

-- 只将有效 JSON 迁移过来
UPDATE legacy_table 
SET data_json = data_text
WHERE JSON_VALID(data_text) = 1;

-- 找出无效的 JSON 行
SELECT id, data_text FROM legacy_table WHERE JSON_VALID(data_text) = 0;
-- 对这些行需要手动修复或标记处理
```

### JSON 类型列的自动验证

当列被声明为 JSON 类型时，MySQL 在写入时自动调用 JSON_VALID 逻辑。无效的 JSON 字符串会直接报错，无需手动调用 JSON_VALID：

```sql
CREATE TABLE strict_json (
    id   INT UNSIGNED NOT NULL AUTO_INCREMENT,
    data JSON NOT NULL,
    PRIMARY KEY (id)
);

-- 插入有效 JSON
INSERT INTO strict_json (data) VALUES ('{"key": "value"}');  -- 成功

-- 插入无效 JSON（自动报错）
INSERT INTO strict_json (data) VALUES ('{bad json}');
-- ERROR 3140 (22032): Invalid JSON text: "Invalid value." at position 1 in value for column
```

### JSON_VALID 与 JSON_SCHEMA_VALID 的区别

| 函数 | 功能 |
|------|------|
| `JSON_VALID(val)` | 只检查 JSON 格式合法性（是否是合法 JSON）|
| `JSON_SCHEMA_VALID(schema, doc)` | 检查 JSON 文档是否符合指定的 JSON Schema 规范 |

```sql
-- JSON_SCHEMA_VALID（MySQL 8.0.17+）
-- 验证文档是否包含必须的字段且字段类型正确
SELECT JSON_SCHEMA_VALID(
    '{"type": "object", "properties": {"name": {"type": "string"}, "age": {"type": "integer"}}, "required": ["name"]}',
    '{"name": "Alice", "age": 28}'
);
-- 返回 1（符合 schema）

SELECT JSON_SCHEMA_VALID(
    '{"type": "object", "required": ["name"]}',
    '{"age": 28}'
);
-- 返回 0（缺少 required 的 name 字段）
```

### 适用场景

- **数据迁移前的格式检查**：将旧系统 TEXT 列中的 JSON 迁移到 JSON 类型时，筛选出无效数据
- **外部数据导入**：接收用户上传的 JSON 文件或 API 数据时，在写入前做格式验证
- **数据质量检查**：定期检查 TEXT 列中存储的 JSON 数据是否有格式损坏

---

### 常见问题

**JSON_VALID 能检查 JSON 结构是否符合业务规则吗？**

不能，JSON_VALID 只检查 JSON 格式本身是否合法，不检查内容是否符合业务规则（如必须有某个字段、字段类型是否正确）。业务规则验证需要使用 JSON_SCHEMA_VALID 或在应用层实现。

**空字符串 `''` 通过 JSON_VALID 验证吗？**

不会，`JSON_VALID('')` 返回 0，因为空字符串不是合法的 JSON 值。

---

### 注意事项

- 对 JSON 列的 `INSERT` 或 `UPDATE` 操作，MySQL 自动进行 JSON 格式验证，无需显式调用 JSON_VALID。
- JSON_VALID 在 WHERE 子句中过滤 TEXT 列时，需要全表扫描（无索引支持），大表上应谨慎使用。

---

### 总结

`JSON_VALID(val)` 检查字符串是否是合法 JSON，返回 1/0/NULL。它在数据迁移（TEXT 到 JSON 列迁移前过滤无效数据）和外部数据导入时最为有用。JSON 类型列本身会自动拒绝无效 JSON，无需在业务代码中重复调用验证。需要结构验证（Schema 检查）时，使用 `JSON_SCHEMA_VALID()`。
