## JSON_TABLE 函数将 JSON 数组转为关系表

`JSON_TABLE()` 是 MySQL 8.0.4 引入的一个表函数，它能将 JSON 文档（通常是 JSON 数组）展开为标准的关系型表结构——行和列。这个函数在 FROM 子句中使用，就像查询一张普通的表一样。对于需要在 SQL 层面拆解、分析 JSON 数据的场景，JSON_TABLE 是目前最强大也最灵活的工具。

---

### 语法结构

```sql
JSON_TABLE(
    expr,                    -- JSON 数据源表达式（常量、列名、函数调用）
    path COLUMNS (           -- JSON 路径，定义"行源"（通常是数组路径 "$[*]"）
        column_definition    -- 一个或多个列定义
        [, column_definition ...]
    )
) [AS] alias                -- 必须指定别名
```

列定义支持以下几种形式：

```sql
-- 普通列：从 JSON 路径提取值
column_name type PATH json_path [DEFAULT val ON EMPTY] [DEFAULT val ON ERROR]

-- 存在性检测列：判断指定路径是否存在，返回 1 或 0
column_name type EXISTS PATH json_path

-- 行序号列：自动生成从 1 开始的递增序号
column_name FOR ORDINALITY

-- 嵌套路径列：处理 JSON 嵌套数组
NESTED PATH json_path COLUMNS (column_definition [, ...])
```

---

### 基本示例

```sql
-- 将 JSON 数组展开为多行
SELECT *
FROM JSON_TABLE(
    -- JSON 数据源：一个包含三个对象的数组
    '[{"name": "张三", "age": 28}, {"name": "李四", "age": 35}, {"name": "王五", "age": 22}]',
    -- "$[*]" 表示遍历数组的每个元素
    '$[*]' COLUMNS (
        row_num   FOR ORDINALITY,                    -- 自动行号，从 1 开始
        user_name VARCHAR(50) PATH '$.name',         -- 提取 name 字段
        user_age  INT         PATH '$.age'           -- 提取 age 字段
    )
) AS users;

-- 结果：
-- +---------+-----------+----------+
-- | row_num | user_name | user_age |
-- +---------+-----------+----------+
-- |       1 | 张三      |       28 |
-- |       2 | 李四      |       35 |
-- |       3 | 王五      |       22 |
-- +---------+-----------+----------+
```

### 从表的 JSON 列中提取数据

实际使用中，JSON 数据通常存储在表的 JSON 列中，而不是手写常量。

```sql
-- 创建订单表，items 列存储商品明细数组
CREATE TABLE orders (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    customer    VARCHAR(50) NOT NULL,
    items       JSON NOT NULL COMMENT '商品明细数组',
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id)
);

-- 插入测试数据
INSERT INTO orders (customer, items) VALUES
('张三', '[
    {"product": "键盘", "qty": 2, "price": 299.00},
    {"product": "鼠标", "qty": 1, "price": 159.00},
    {"product": "显示器", "qty": 1, "price": 2499.00}
]'),
('李四', '[
    {"product": "耳机", "qty": 1, "price": 899.00},
    {"product": "充电器", "qty": 3, "price": 69.00}
]');

-- 使用 JSON_TABLE 展开订单明细
SELECT
    o.id AS order_id,
    o.customer,
    jt.row_num,
    jt.product,
    jt.qty,
    jt.price,
    jt.qty * jt.price AS subtotal   -- 计算小计
FROM orders o,
-- 使用逗号 JOIN 或显式 CROSS JOIN 连接 JSON_TABLE
JSON_TABLE(
    o.items,           -- 引用 orders 表的 JSON 列
    '$[*]' COLUMNS (
        row_num  FOR ORDINALITY,
        product  VARCHAR(100) PATH '$.product',
        qty      INT          PATH '$.qty',
        price    DECIMAL(10,2) PATH '$.price'
    )
) AS jt;

-- 结果：
-- +----------+----------+---------+---------+-----+---------+----------+
-- | order_id | customer | row_num | product | qty | price   | subtotal |
-- +----------+----------+---------+---------+-----+---------+----------+
-- |        1 | 张三     |       1 | 键盘    |   2 |  299.00 |   598.00 |
-- |        1 | 张三     |       2 | 鼠标    |   1 |  159.00 |   159.00 |
-- |        1 | 张三     |       3 | 显示器  |   1 | 2499.00 |  2499.00 |
-- |        2 | 李四     |       1 | 耳机    |   1 |  899.00 |   899.00 |
-- |        2 | 李四     |       2 | 充电器  |   3 |   69.00 |   207.00 |
-- +----------+----------+---------+---------+-----+---------+----------+
```

### 聚合 JSON_TABLE 的结果

将 JSON 数组展开为行后，可以像普通表一样使用 GROUP BY、SUM 等聚合操作。

```sql
-- 统计每个订单的商品数量和总金额
SELECT
    o.id AS order_id,
    o.customer,
    COUNT(*)            AS item_count,
    SUM(jt.qty)         AS total_qty,
    SUM(jt.qty * jt.price) AS total_amount
FROM orders o,
JSON_TABLE(
    o.items,
    '$[*]' COLUMNS (
        qty   INT          PATH '$.qty',
        price DECIMAL(10,2) PATH '$.price'
    )
) AS jt
GROUP BY o.id, o.customer;

-- 结果：
-- +----------+----------+------------+-----------+--------------+
-- | order_id | customer | item_count | total_qty | total_amount |
-- +----------+----------+------------+-----------+--------------+
-- |        1 | 张三     |          3 |         4 |      3256.00 |
-- |        2 | 李四     |          2 |         4 |      1106.00 |
-- +----------+----------+------------+-----------+--------------+
```

### EXISTS PATH 检测字段是否存在

有些 JSON 对象中的字段不一定每个元素都有，可以用 EXISTS PATH 列来检测。

```sql
SELECT *
FROM JSON_TABLE(
    '[{"name": "A", "email": "a@test.com"}, {"name": "B"}, {"name": "C", "email": "c@test.com"}]',
    '$[*]' COLUMNS (
        user_name  VARCHAR(50) PATH '$.name',
        user_email VARCHAR(100) PATH '$.email'
            DEFAULT 'N/A' ON EMPTY,           -- 字段不存在时的默认值
        has_email  INT EXISTS PATH '$.email'   -- 1=存在，0=不存在
    )
) AS jt;

-- 结果：
-- +-----------+-------------+-----------+
-- | user_name | user_email  | has_email |
-- +-----------+-------------+-----------+
-- | A         | a@test.com  |         1 |
-- | B         | N/A         |         0 |
-- | C         | c@test.com  |         1 |
-- +-----------+-------------+-----------+
```

### DEFAULT ON EMPTY 与 DEFAULT ON ERROR

当 JSON 路径匹配不到值或者类型转换出错时，可以通过 DEFAULT 指定兜底值，避免查询失败。

```sql
SELECT *
FROM JSON_TABLE(
    '[{"val": 100}, {"val": "abc"}, {}]',
    '$[*]' COLUMNS (
        -- 正常提取，字段缺失时返回 -1
        num_val INT PATH '$.val'
            DEFAULT -1 ON EMPTY     -- 路径不存在时返回 -1
            DEFAULT 0  ON ERROR     -- 类型转换失败时返回 0（如 "abc" 转 INT）
    )
) AS jt;

-- 结果：
-- +---------+
-- | num_val |
-- +---------+
-- |     100 |   -- 正常提取
-- |       0 |   -- "abc" 转 INT 失败，ON ERROR 返回 0
-- |      -1 |   -- 字段不存在，ON EMPTY 返回 -1
-- +---------+
```

| 子句 | 触发条件 | 说明 |
|------|---------|------|
| DEFAULT val ON EMPTY | JSON 路径匹配结果为空（字段不存在） | 避免返回 NULL |
| DEFAULT val ON ERROR | 值存在但类型转换失败 | 避免查询报错 |
| ERROR ON EMPTY | 路径为空时抛出错误 | 严格模式，不允许缺失 |
| ERROR ON ERROR | 转换失败时抛出错误 | 严格模式，不允许类型错误 |
| NULL ON EMPTY | 路径为空时返回 NULL | 默认行为 |
| NULL ON ERROR | 转换失败时返回 NULL | 默认行为 |

### NESTED PATH 处理嵌套数组

当 JSON 结构中存在嵌套数组时，可以使用 NESTED PATH 进一步展开内层数组。

```sql
-- 数据结构：每个用户有多个标签（嵌套数组）
SELECT *
FROM JSON_TABLE(
    '[
        {"name": "张三", "tags": ["admin", "vip"]},
        {"name": "李四", "tags": ["user"]},
        {"name": "王五", "tags": ["user", "vip", "tester"]}
    ]',
    '$[*]' COLUMNS (
        user_name VARCHAR(50) PATH '$.name',
        -- NESTED PATH 展开内层 tags 数组
        NESTED PATH '$.tags[*]' COLUMNS (
            tag VARCHAR(50) PATH '$'
        )
    )
) AS jt;

-- 结果：每个标签展开为独立行（类似 CROSS JOIN 效果）
-- +-----------+--------+
-- | user_name | tag    |
-- +-----------+--------+
-- | 张三      | admin  |
-- | 张三      | vip    |
-- | 李四      | user   |
-- | 王五      | user   |
-- | 王五      | vip    |
-- | 王五      | tester |
-- +-----------+--------+
```

### 与 LATERAL JOIN 结合使用

在 MySQL 8.0.14+ 中，JSON_TABLE 本质上是一种 LATERAL 派生表，它可以引用前面的表列。这种关联形式让 JSON_TABLE 能逐行处理主表的 JSON 列。

```sql
-- 使用显式 JOIN ... ON TRUE 代替逗号连接（语义更清晰）
SELECT
    o.id,
    o.customer,
    jt.product,
    jt.price
FROM orders o
JOIN LATERAL JSON_TABLE(
    o.items,
    '$[*]' COLUMNS (
        product VARCHAR(100) PATH '$.product',
        price   DECIMAL(10,2) PATH '$.price'
    )
) AS jt ON TRUE;
-- 等价于前面的逗号写法，但 LATERAL 语义更明确
```

### 在 WHERE 和子查询中使用

JSON_TABLE 展开后的结果可以像普通表一样参与过滤和子查询。

```sql
-- 查找包含"显示器"的订单
SELECT DISTINCT o.id, o.customer
FROM orders o,
JSON_TABLE(
    o.items,
    '$[*]' COLUMNS (
        product VARCHAR(100) PATH '$.product'
    )
) AS jt
WHERE jt.product = '显示器';

-- 查找单价超过 500 的所有商品明细
SELECT
    o.customer,
    jt.product,
    jt.price
FROM orders o,
JSON_TABLE(
    o.items,
    '$[*]' COLUMNS (
        product VARCHAR(100) PATH '$.product',
        price   DECIMAL(10,2) PATH '$.price'
    )
) AS jt
WHERE jt.price > 500
ORDER BY jt.price DESC;
```

### JSON_TABLE 与手动解析的对比

| 对比维度 | JSON_TABLE | 手动解析（JSON_EXTRACT + 应用层循环） |
|---------|-----------|--------------------------------------|
| 展开方式 | SQL 层面直接展开为行 | 需要应用层遍历数组元素 |
| 聚合能力 | 展开后直接用 GROUP BY、SUM 等 | 需要应用层自己计算 |
| JOIN 能力 | 可以和其他表直接 JOIN | 需要多次查询或应用层关联 |
| 性能 | 大数据量时在数据库内完成，减少网络传输 | 大数组需要传输完整 JSON 到应用层 |
| 嵌套处理 | NESTED PATH 支持多层嵌套 | 需要多层循环 |
| 代码复杂度 | 一条 SQL 搞定 | 需要额外代码 |

### 适用场景

- **JSON 数组数据展开**：将存储在 JSON 列中的数组元素逐行展开为关系表行，方便 SQL 分析
- **报表统计**：对 JSON 数组中的数据做聚合计算（求和、计数、平均值等）
- **数据迁移**：将 JSON 格式数据批量转换为关系表结构，写入目标表
- **API 数据解析**：将第三方 API 返回的 JSON 数组在数据库层面解析为结构化数据
- **日志分析**：将 JSON 格式的日志字段展开，按字段过滤和统计

### 常见问题

**JSON_TABLE 的性能如何？**

JSON_TABLE 在处理中小规模 JSON 数组时性能良好。但如果 JSON 列中每行的数组都非常大（比如上千个元素），展开后的行数会急剧膨胀，可能导致查询变慢。对于这种场景，建议在应用层做分页处理，或者将 JSON 数组拆分为独立的关系表。

**JSON_TABLE 能用在 UPDATE 或 DELETE 语句中吗？**

可以在子查询中使用 JSON_TABLE 的结果作为条件，但不能直接更新 JSON_TABLE 产生的虚拟表。示例：

```sql
-- 删除包含某个特定商品的订单
DELETE FROM orders
WHERE id IN (
    SELECT o.id
    FROM orders o,
    JSON_TABLE(o.items, '$[*]' COLUMNS (
        product VARCHAR(100) PATH '$.product'
    )) AS jt
    WHERE jt.product = '过期商品'
);
```

**JSON_TABLE 返回的列能建索引吗？**

不能。JSON_TABLE 生成的是虚拟表，不是持久化的物理表，所以无法在其列上创建索引。如果需要频繁查询 JSON 数组中的特定元素，建议用生成列+索引或多值索引来代替。

### 注意事项

- JSON_TABLE 必须指定别名（AS alias），否则语法报错。
- 路径表达式 `$[*]` 中的 `[*]` 表示遍历数组所有元素。如果 JSON 数据不是数组（而是单个对象），应使用 `$` 作为路径。
- FOR ORDINALITY 列从 1 开始递增，每个 JSON_TABLE 调用独立编号，不受其他表的行号影响。
- NESTED PATH 展开多层嵌套数组时会产生笛卡尔积效果，行数可能快速增长，要注意控制数据规模。
- 在 MySQL 8.0 和 8.4 中 JSON_TABLE 的基本语法一致，8.4 没有对 JSON_TABLE 做破坏性变更。

---

### 总结

`JSON_TABLE()` 是 MySQL 中将 JSON 数组数据转换为关系型表结构的核心函数，在 FROM 子句中使用，支持 PATH 提取字段值、EXISTS PATH 检测字段存在性、FOR ORDINALITY 生成行序号、NESTED PATH 处理嵌套数组、DEFAULT ON EMPTY/ERROR 处理缺失和异常值。展开后的结果可以像普通表一样参与 WHERE 过滤、JOIN 关联、GROUP BY 聚合等操作。它替代了应用层手动遍历 JSON 数组的做法，在数据库层面完成 JSON 到关系数据的转换，减少了网络传输和应用层代码复杂度。
