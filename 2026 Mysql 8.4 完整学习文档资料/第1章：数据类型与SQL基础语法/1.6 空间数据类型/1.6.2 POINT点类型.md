# POINT 点类型

POINT 是 MySQL 空间数据类型中最基础、使用最广泛的类型，表示二维坐标系中的一个点。它在地理位置相关的业务（门店位置、用户坐标、骑手实时位置等）中应用极为普遍。

---

## 基本特性

| 属性 | 值 |
|------|---|
| 存储内容 | 一对坐标值 (X, Y) 或 (经度, 纬度) |
| WKT 格式 | `POINT(x y)` |
| 坐标顺序 | SRID 4326 下为 (longitude latitude)，即先经度后纬度 |
| 存储空间 | 25 字节（固定）|

---

## 语法与创建

```sql
column_name POINT
column_name POINT NOT NULL
column_name POINT NOT NULL SRID 4326  -- 推荐指定 SRID
```

```sql
-- 门店位置表
CREATE TABLE stores (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name        VARCHAR(200) NOT NULL,
    location    POINT NOT NULL SRID 4326 COMMENT '门店位置，WGS84坐标系',
    address     VARCHAR(500),
    PRIMARY KEY (id),
    SPATIAL INDEX idx_location (location)
);

-- 用户位置表
CREATE TABLE user_locations (
    user_id     INT UNSIGNED NOT NULL PRIMARY KEY,
    position    POINT NOT NULL SRID 4326,
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

## 插入 POINT 数据

```sql
-- 方式一：ST_GeomFromText（WKT 格式，推荐）
INSERT INTO stores (name, location, address) VALUES
('王府井店', ST_GeomFromText('POINT(116.4074 39.9042)', 4326), '北京市东城区王府井大街'),
('西单店',   ST_GeomFromText('POINT(116.3748 39.9131)', 4326), '北京市西城区西单北大街'),
('三里屯店', ST_GeomFromText('POINT(116.4550 39.9355)', 4326), '北京市朝阳区三里屯路');

-- 方式二：ST_PointFromText（专用函数，等效）
INSERT INTO stores (name, location) VALUES
('望京店', ST_PointFromText('POINT(116.4808 40.0044)', 4326));

-- 方式三：ST_GeomFromGeoJSON（GeoJSON 格式）
INSERT INTO stores (name, location) VALUES
('国贸店', ST_GeomFromGeoJSON('{"type":"Point","coordinates":[116.4601,39.9097]}'));

-- 方式四：POINT() 函数（MySQL 8.0+）
INSERT INTO user_locations (user_id, position)
VALUES (1001, ST_GeomFromText(CONCAT('POINT(', 116.3975, ' ', 39.9087, ')'), 4326));
```

## 查询 POINT 数据

```sql
-- 提取坐标值
SELECT name,
       ST_X(location) AS longitude,
       ST_Y(location) AS latitude,
       ST_AsText(location) AS wkt,
       ST_AsGeoJSON(location) AS geojson
FROM stores;

-- 按距离查询附近门店（最常见需求）
-- 用户位置：经度 116.4, 纬度 39.9
SET @user_location = ST_GeomFromText('POINT(116.4 39.9)', 4326);

-- 查询 5 公里内的门店（ST_Distance_Sphere 返回米）
SELECT 
    name,
    ST_Distance_Sphere(location, @user_location) AS distance_meters
FROM stores
WHERE ST_Distance_Sphere(location, @user_location) <= 5000
ORDER BY distance_meters;

-- 使用 MBR（最小外接矩形）配合空间索引的范围查询（更快）
-- 先用矩形快速过滤，再精确计算距离（两步查询法）
SELECT name, ST_Distance_Sphere(location, @user_location) AS dist
FROM stores
WHERE ST_Within(
    location,
    ST_GeomFromText(
        'POLYGON((116.35 39.86, 116.45 39.86, 116.45 39.95, 116.35 39.95, 116.35 39.86))',
        4326
    )
)
ORDER BY dist;
```

## 空间索引对 POINT 查询的作用

```sql
-- 不使用空间索引时（全表扫描）
EXPLAIN SELECT * FROM stores 
WHERE ST_Distance_Sphere(location, ST_GeomFromText('POINT(116.4 39.9)', 4326)) < 5000;
-- type: ALL（全表扫描，不走索引）

-- ST_Within + SPATIAL INDEX（走空间索引）
EXPLAIN SELECT * FROM stores
WHERE ST_Within(location, ST_MakeEnvelope(
    ST_GeomFromText('POINT(116.35 39.85)', 4326),
    ST_GeomFromText('POINT(116.46 39.96)', 4326)
));
-- type: range（使用 idx_location 空间索引）
```

## 适用场景

- **门店/地点位置**：存储地图上的点位坐标
- **骑手/用户实时位置**：配合定时更新，实现实时位置追踪
- **附近搜索**：查询指定位置周围一定半径内的对象
- **地理围栏**：判断某个 POINT 是否在指定区域（POLYGON）内
- **路程计算**：计算起点到终点的直线距离

## 常见问题

**为什么要指定 SRID 4326？**

SRID 4326 对应 WGS84 坐标系，是 GPS 和大多数地图 API（Google Maps、高德、百度等）使用的地理坐标系。不指定 SRID（默认 SRID 0）表示平面坐标系，使用 `ST_Distance_Sphere` 等函数计算地理距离时需要 SRID 4326 才能得到以米为单位的正确距离。

**SRID 4326 和百度/高德的坐标系一样吗？**

不完全一样。百度地图使用 BD-09 坐标系，高德/腾讯使用 GCJ-02（火星坐标系），WGS84（SRID 4326）是 GPS 原始坐标。三者之间有偏移，在中国境内差异约数十到数百米，需要在应用层做坐标系转换。

---

## 注意事项

- SRID 4326 中坐标顺序是 (经度 longitude, 纬度 latitude)，即 POINT(116.4 39.9)，不是 POINT(39.9 116.4)。这与很多人习惯的 (纬度, 经度) 顺序相反，容易写错。
- `ST_Distance_Sphere` 计算球面距离，适合地球表面的地理距离（单位：米）。`ST_Distance` 计算的是平面几何距离，在地理坐标系中没有直接的物理意义。
- 空间索引（SPATIAL INDEX）只支持 MBR（最小外接矩形）范围查询，不直接支持以某点为圆心的圆形范围查询。圆形查询通常先用矩形粗筛，再用距离函数精确过滤。

---

## 总结

POINT 是最常用的空间类型，表示二维坐标系中的一个点，存储空间固定 25 字节。在地理位置业务中，配合 SRID 4326（WGS84 坐标系）和 SPATIAL INDEX 使用，可以高效支持附近搜索和地理围栏等功能。SRID 4326 下坐标顺序是 (经度, 纬度)，`ST_Distance_Sphere` 返回球面距离（单位：米），圆形范围查询通常采用矩形粗筛+距离精确过滤的两步策略。
