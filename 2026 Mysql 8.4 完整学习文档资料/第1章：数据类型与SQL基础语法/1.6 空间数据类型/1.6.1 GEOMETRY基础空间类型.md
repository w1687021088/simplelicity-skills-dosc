# GEOMETRY 基础空间类型

GEOMETRY 是 MySQL 空间数据类型的基类，所有具体的空间类型（POINT、LINESTRING、POLYGON 等）都是它的子类型。GEOMETRY 列可以存储任意类型的空间对象，是实现地理信息系统（GIS）功能的基础。

---

## MySQL 空间类型体系

MySQL 遵循 OGC（Open Geospatial Consortium）标准，支持以下空间类型：

| 类型 | 描述 | 示例 |
|------|------|------|
| GEOMETRY | 所有空间类型的基类 | 可存储任意空间对象 |
| POINT | 单个坐标点 | (经度, 纬度) |
| LINESTRING | 由多个点连成的线 | 道路、轨迹 |
| POLYGON | 封闭的多边形 | 区域、地块 |
| MULTIPOINT | 多个点的集合 | 多个门店位置 |
| MULTILINESTRING | 多条线的集合 | 多段路线 |
| MULTIPOLYGON | 多个多边形的集合 | 行政区划（含飞地）|
| GEOMETRYCOLLECTION | 以上类型的混合集合 | 复杂地理数据 |

---

## 语法

```sql
column_name GEOMETRY
column_name GEOMETRY NOT NULL
column_name GEOMETRY SRID 4326  -- 指定空间参考系统
```

---

## 创建示例

```sql
-- 通用空间列（可存储任意类型的空间对象）
CREATE TABLE geo_objects (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name        VARCHAR(200) NOT NULL,
    shape       GEOMETRY NOT NULL SRID 4326,
    type_name   VARCHAR(20) NOT NULL COMMENT '对象类型说明',
    PRIMARY KEY (id),
    SPATIAL INDEX idx_shape (shape)
);

-- WKT（Well-Known Text）格式插入空间数据
INSERT INTO geo_objects (name, shape, type_name) VALUES
('天安门', ST_GeomFromText('POINT(116.3975 39.9087)', 4326), 'POINT'),
('长安街', ST_GeomFromText('LINESTRING(116.3 39.9, 116.4 39.9, 116.5 39.9)', 4326), 'LINESTRING'),
('二环区域', ST_GeomFromText('POLYGON((116.3 39.8, 116.5 39.8, 116.5 40.0, 116.3 40.0, 116.3 39.8))', 4326), 'POLYGON');
```

## 空间数据的输入/输出格式

MySQL 支持多种空间数据格式：

```sql
-- WKT（Well-Known Text）：人类可读的文本格式
SELECT ST_AsText(shape) FROM geo_objects WHERE id = 1;
-- 输出：POINT(116.3975 39.9087)

-- WKB（Well-Known Binary）：二进制格式（更紧凑）
SELECT ST_AsBinary(shape) FROM geo_objects WHERE id = 1;

-- GeoJSON：JSON 格式（Web 应用常用）
SELECT ST_AsGeoJSON(shape) FROM geo_objects WHERE id = 1;
-- 输出：{"type": "Point", "coordinates": [116.3975, 39.9087]}

-- 从 GeoJSON 创建空间对象
SELECT ST_GeomFromGeoJSON('{"type":"Point","coordinates":[116.3975,39.9087]}');

-- 从 WKT 创建（最常用）
SELECT ST_GeomFromText('POINT(116.3975 39.9087)', 4326);
```

## 空间类型的存储

```sql
-- 查看空间对象的类型
SELECT ST_GeometryType(shape) FROM geo_objects;
-- 输出：POINT / LINESTRING / POLYGON

-- 查看空间对象的 SRID
SELECT ST_SRID(shape) FROM geo_objects;
-- 输出：4326（WGS84 坐标系）

-- 检查空间对象是否有效
SELECT ST_IsValid(shape), ST_Validate(shape) FROM geo_objects;
```

## 常用空间函数概览

| 函数 | 功能 |
|------|------|
| ST_Distance(g1, g2) | 计算两个几何体之间的距离 |
| ST_Contains(g1, g2) | g1 是否包含 g2 |
| ST_Intersects(g1, g2) | 两个几何体是否相交 |
| ST_Within(g1, g2) | g1 是否在 g2 内 |
| ST_Buffer(g, d) | 以 g 为中心，半径 d 的缓冲区 |
| ST_Area(poly) | 多边形的面积 |
| ST_Length(line) | 线的长度 |
| ST_Centroid(g) | 几何体的重心/中心点 |

## 适用场景

- **地图应用**：存储地点坐标、道路轨迹、行政区划

## 常见问题

**MySQL 空间类型和 PostGIS 有什么区别？**

MySQL 的空间功能是内置的，支持 OGC 标准的基本空间运算。PostGIS 是 PostgreSQL 的空间扩展，功能更强大（更多空间分析函数、空间拓扑、三维支持等）。对于简单的地理位置查询（如附近搜索），MySQL 的空间类型已足够；对于复杂的 GIS 分析，PostGIS 更专业。

**GEOMETRY 列能存储不同类型的空间对象吗？**

可以，GEOMETRY 是基类，一个 GEOMETRY 列可以同时存储 POINT、LINESTRING、POLYGON 等不同类型的对象。如果需要限制只存储特定类型，应使用具体的子类型（如 POINT 列只接受点对象）。

---

## 注意事项

- MySQL 8.0 起，空间类型列应指定 SRID（空间参考系统 ID），`SRID 4326` 对应 WGS84 坐标系（GPS 通用标准），`SRID 0` 表示平面坐标系（笛卡尔坐标）。
- 空间索引（SPATIAL INDEX）只能在 NOT NULL 的空间类型列上建立。
- 在 SRID 4326 坐标系中，坐标顺序是 (经度, 纬度)，即 (longitude, latitude)，与直觉上的 (纬度, 经度) 顺序相反，写入时需注意。

---

## 总结

GEOMETRY 是 MySQL 空间类型体系的基类，其子类型包括 POINT、LINESTRING、POLYGON 等。空间数据支持 WKT、WKB、GeoJSON 等多种输入/输出格式，配合 `SPATIAL INDEX` 可以高效进行空间范围查询。MySQL 8.0 起，空间列建议指定 SRID，WGS84 坐标系（SRID=4326）是地理位置数据的通用标准。
