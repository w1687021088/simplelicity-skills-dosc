# JSON_EXTRACT 提取 JSON 字段

`JSON_EXTRACT()` 从 JSON 文档中按路径提取指定位置的值。MySQL 8.0+ 提供了简便的 `->` 和 `->>` 操作符作为等价简写，极大简化了 JSON 字段的读取操作。JSON 支持是 MySQL 5.7 引入并在 8.0 持续增强的重要特性。

---

## 语法

```sql
JSON_EXTRACT(json_doc, path [, path] ...)
json_col -> '$.path'      -- 等价于 JSON_EXTRACT，返回带引号的 JSON 值
json_col ->> '$.path'     -- 等价于 JSON_UNQUOTE(JSON_EXTRACT(...))，返回不带引号的文本
```

JSON 路径语法：
- `$`：整个 JSON 文档（根）
- `$.key`：对象的 key 字段
- `$.key1.key2`：嵌套对象
- `$[0]`：数组的第 0 个元素
- `$.key[1]`：对象中 key 对应的数组的第 1 个元素
- `$[*]`：数组的所有元素
- `$.*.field`：所有子对象的 field 字段

---

## 基本示例

```sql
-- 假设 profile 列存储 JSON：{"name":"张三","age":30,"tags":["java","mysql"]}

-- JSON_EXTRACT 基础用法
SELECT JSON_EXTRACT(profile, '$.name') FROM users;         -- "张三"（带引号）
SELECT JSON_EXTRACT(profile, '$.age')  FROM users;         -- 30（数字，无引号）
SELECT JSON_EXTRACT(profile, '$.tags[0]') FROM users;      -- "java"（带引号）

-- -> 操作符（等价于 JSON_EXTRACT）
SELECT profile -> '$.name'    FROM users;                  -- "张三"（带引号）
SELECT profile -> '$.tags[1]' FROM users;                  -- "mysql"

-- ->> 操作符（JSON_UNQUOTE + JSON_EXTRACT，去掉引号，返回普通文本）
SELECT profile ->> '$.name'   FROM users;                  -- 张三（无引号，可直接用于字符串比较）
SELECT profile ->> '$.age'    FROM users;                  -- 30（文本形式，无引号）
```

## 在 WHERE 中过滤 JSON 字段

```sql
-- 查找 age > 25 的用户（JSON 字段过滤）
SELECT id, profile ->> '$.name' AS name
FROM users
WHERE JSON_EXTRACT(profile, '$.age') > 25;
-- 等价写法：WHERE (profile -> '$.age') > 25

-- 查找 tags 包含 'mysql' 的用户（数组元素搜索）
SELECT id FROM users
WHERE JSON_CONTAINS(profile -> '$.tags', '"mysql"');
-- JSON_CONTAINS 的第二个参数是 JSON 值，字符串需要带引号

-- 查找有 phone 字段的用户（key 存在性检查）
SELECT id FROM users
WHERE JSON_EXTRACT(profile, '$.phone') IS NOT NULL;

-- 更精确的 key 存在检查
SELECT id FROM users
WHERE JSON_CONTAINS_PATH(profile, 'one', '$.phone');
-- 'one'：至少一个路径存在；'all'：所有路径都存在
```

## 提取嵌套 JSON

```sql
-- 假设 order_info 列：
-- {"customer":{"name":"李四","city":"上海"},"items":[{"id":1,"qty":2},{"id":2,"qty":1}]}

SELECT 
    order_info -> '$.customer.name'    AS customer_name,    -- "李四"
    order_info -> '$.customer.city'    AS customer_city,    -- "上海"
    order_info -> '$.items[0].id'      AS first_item_id,    -- 1
    order_info -> '$.items[0].qty'     AS first_item_qty,   -- 2
    JSON_LENGTH(order_info -> '$.items') AS item_count      -- 2（数组长度）
FROM orders;
```

## 多路径提取

```sql
-- 一次提取多个路径（返回 JSON 数组）
SELECT JSON_EXTRACT(profile, '$.name', '$.age') FROM users;
-- 返回：["张三", 30]

-- 常用 JSON 辅助函数
SELECT JSON_TYPE(profile);                    -- 返回 JSON 类型（OBJECT/ARRAY/STRING 等）
SELECT JSON_VALID(profile);                   -- 判断是否是合法 JSON（1 或 0）
SELECT JSON_LENGTH(profile -> '$.tags');      -- 返回数组/对象的元素数量
SELECT JSON_KEYS(profile);                    -- 返回 JSON 对象的所有 key（数组形式）
```

## JSON 字段的索引（生成列 + 索引）

```sql
-- JSON 列本身不能直接建索引，但可以通过生成列间接建立
ALTER TABLE users ADD COLUMN profile_age INT
    GENERATED ALWAYS AS (profile ->> '$.age') STORED;
CREATE INDEX idx_profile_age ON users (profile_age);

-- 之后对 age 的过滤就可以走索引
SELECT * FROM users WHERE profile_age > 25;
-- 或者（MySQL 8.0+ 优化器可以识别等价表达式）
SELECT * FROM users WHERE profile ->> '$.age' > 25;
-- MySQL 8.0 的函数索引特性也可以直接在虚拟列上建索引
```

## 适用场景

- **读取存储的配置/属性 JSON**：用户扩展属性、商品规格参数、订单附加信息
- **过滤 JSON 字段内容**：在不展开 JSON 列的情况下直接按 JSON 内字段查询
- **数据迁移准备**：将 JSON 列中的字段提取出来，准备迁移为独立列

---

## 常见问题

**`->` 和 `->>`  有什么区别？**

`->` 等价于 `JSON_EXTRACT()`，返回 JSON 格式的值，字符串会带双引号（如 `"张三"`），不能直接与普通字符串比较（`'张三' = "张三"` 不一定成立）。`->>` 等价于 `JSON_UNQUOTE(JSON_EXTRACT())`，将 JSON 值转为普通文本（去掉引号），可以直接与字符串字面量比较。

---

## 注意事项

- 对 JSON 列直接用 `JSON_EXTRACT` 或 `->` 过滤时，无法使用普通索引。高频 JSON 字段过滤必须通过生成列 + 索引来优化性能。
- JSON 路径中的 `*` 通配符（如 `$[*]` 或 `$.*.key`）会返回一个 JSON 数组，不是单个值，不能直接用于普通比较操作符。

---

## 总结

`JSON_EXTRACT(col, '$.path')` 或等价的 `->` 操作符从 JSON 文档中提取指定路径的值（返回 JSON 格式）；`->>` 进一步去掉引号返回普通文本，可直接用于字符串比较。支持嵌套路径、数组索引、通配符等丰富路径表达式。JSON 列的高频过滤需通过生成列 + 索引来获得良好性能。
