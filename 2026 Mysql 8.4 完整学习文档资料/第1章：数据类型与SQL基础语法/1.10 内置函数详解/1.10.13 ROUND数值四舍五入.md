# ROUND 数值四舍五入

`ROUND()` 函数将数值四舍五入到指定的小数位数。它是最常用的数值格式化函数，用于金额显示、统计数据的精度控制、评分计算等场景。

---

## 语法

```sql
ROUND(X)           -- 四舍五入到整数
ROUND(X, D)        -- 四舍五入到 D 位小数（D 可为负数）
```

- `X`：要舍入的数值
- `D`：保留的小数位数，默认 0；正数表示小数位，负数表示整数位（十位、百位等）

---

## 基本示例

```sql
-- 四舍五入到整数
SELECT ROUND(3.456);     -- 3
SELECT ROUND(3.567);     -- 4（四舍五入）
SELECT ROUND(-3.567);    -- -4

-- 四舍五入到指定小数位
SELECT ROUND(3.14159, 2);   -- 3.14
SELECT ROUND(3.14559, 2);   -- 3.15
SELECT ROUND(3.145, 2);     -- 3.15（注意浮点精度问题）

-- 负数 D（舍入到十位、百位等）
SELECT ROUND(1234.56, -1);  -- 1230（舍入到十位）
SELECT ROUND(1234.56, -2);  -- 1200（舍入到百位）
SELECT ROUND(1234.56, -3);  -- 1000（舍入到千位）
```

---

## 在业务计算中的应用

```sql
-- 计算平均评分（保留 1 位小数）
SELECT product_id,
    COUNT(*) AS review_count,
    ROUND(AVG(rating), 1) AS avg_rating
FROM reviews
GROUP BY product_id;

-- 计算折扣后价格（四舍五入到分）
SELECT product_id,
    price,
    discount_rate,
    ROUND(price * (1 - discount_rate), 2) AS discounted_price
FROM products;

-- 百分比显示（保留 2 位小数）
SELECT status,
    COUNT(*) AS cnt,
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 2) AS percentage
FROM orders
GROUP BY status;

-- 金额四舍五入到分（财务计算）
SELECT order_id,
    ROUND(subtotal * 1.13, 2) AS total_with_tax  -- 含13%增值税
FROM orders;
```

## ROUND 的舍入规则

```sql
-- MySQL 的 ROUND 使用"四舍五入"（Half-Away-From-Zero）
-- 即 0.5 向远离 0 的方向舍入
SELECT ROUND(2.5);   -- 3（而不是某些语言中"银行家舍入"的 2）
SELECT ROUND(-2.5);  -- -3（向远离 0 的方向）
SELECT ROUND(3.5);   -- 4
SELECT ROUND(-3.5);  -- -4

-- 注意：DECIMAL 类型的 ROUND 更精确，DOUBLE 类型有浮点精度问题
SELECT ROUND(2.445, 2);  -- 可能是 2.44（浮点精度问题）
-- 如果精度要求高，应该用 DECIMAL 类型而不是 DOUBLE
```

## ROUND vs TRUNCATE vs FLOOR vs CEIL

```sql
-- 对 3.7 的不同处理：
SELECT ROUND(3.7);      -- 4（四舍五入）
SELECT TRUNCATE(3.7, 0); -- 3（直接截断小数，不舍入）
SELECT FLOOR(3.7);      -- 3（向下取整到最大整数）
SELECT CEIL(3.7);       -- 4（向上取整到最小整数）

-- 对 -3.7 的不同处理：
SELECT ROUND(-3.7);      -- -4（四舍五入，远离 0）
SELECT TRUNCATE(-3.7, 0);-- -3（直接截断小数，向 0 的方向）
SELECT FLOOR(-3.7);      -- -4（向下取整，远离 0）
SELECT CEIL(-3.7);       -- -3（向上取整，向 0 的方向）
```

| 函数 | 3.7 | 3.2 | -3.7 | -3.2 |
|------|-----|-----|------|------|
| ROUND | 4 | 3 | -4 | -3 |
| TRUNCATE(x,0) | 3 | 3 | -3 | -3 |
| FLOOR | 3 | 3 | -4 | -4 |
| CEIL | 4 | 4 | -3 | -3 |

## 适用场景

- **金额计算**：价格折扣、含税金额、分摊费用（保留 2 位小数）
- **统计数据展示**：平均值、百分比的精度控制
- **评分系统**：将精确计算的评分四舍五入到 1 位或 0.5 精度
- **分页/批量计算**：`ROUND(total_rows / page_size)` 计算页数

---

## 常见问题

**为什么 ROUND(2.445, 2) 有时返回 2.44 而不是 2.45？**

这是浮点数精度问题。`2.445` 在 IEEE 754 双精度浮点中的实际存储值可能是 `2.44499999...`，所以 ROUND 到 2 位时得 `2.44`。解决方法：使用 `DECIMAL` 类型存储，或用 `ROUND(CAST(2.445 AS DECIMAL(10,3)), 2)`。

---

## 注意事项

- 涉及财务金额的计算，强烈建议列类型使用 `DECIMAL(M, D)` 而非 `FLOAT`/`DOUBLE`，DECIMAL 是精确的十进制存储，避免浮点精度问题。
- `ROUND` 和 `TRUNCATE` 的区别：ROUND 四舍五入，TRUNCATE 直接丢弃指定位数之后的部分（向 0 截断），不进行舍入。

---

## 总结

`ROUND(X, D)` 将数值 X 四舍五入到 D 位小数（D 默认为 0，负数 D 舍入到整数位）。MySQL 使用"四舍五入"规则（0.5 远离 0 舍入）。金额计算应使用 DECIMAL 类型避免浮点精度问题。ROUND 与 TRUNCATE（截断）、FLOOR（向下取整）、CEIL（向上取整）的区别在于对 0.5 及负数的处理方式。
