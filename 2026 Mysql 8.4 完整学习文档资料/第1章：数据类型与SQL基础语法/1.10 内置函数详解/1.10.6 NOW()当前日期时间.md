# NOW() 当前日期时间

`NOW()` 返回当前日期和时间，格式为 `YYYY-MM-DD HH:MM:SS`。它是 MySQL 中最常用的日期时间函数，广泛用于记录创建时间、更新时间，以及时间范围过滤。

---

## 语法

```sql
NOW()                    -- 返回 YYYY-MM-DD HH:MM:SS
NOW(fsp)                 -- 返回带小数秒的时间（fsp=0~6）
SYSDATE()                -- 与 NOW() 类似，但行为略有不同
CURRENT_TIMESTAMP        -- 等价于 NOW()，SQL 标准写法
CURRENT_TIMESTAMP()      -- 等价于 NOW()
LOCALTIME()              -- 等价于 NOW()（本地时间）
LOCALTIMESTAMP()         -- 等价于 NOW()
```

---

## 基本示例

```sql
-- 获取当前日期时间
SELECT NOW();                      -- 2026-03-15 14:30:25
SELECT NOW(3);                     -- 2026-03-15 14:30:25.123（精确到毫秒）
SELECT NOW(6);                     -- 2026-03-15 14:30:25.123456（精确到微秒）

-- 与日期时间类型的差异
SELECT NOW(), CURDATE(), CURTIME();
-- 2026-03-15 14:30:25 | 2026-03-15 | 14:30:25

-- 在 INSERT 中使用
INSERT INTO orders (user_id, amount, created_at)
VALUES (1, 99.00, NOW());

-- 在 UPDATE 中使用
UPDATE users SET last_login_at = NOW() WHERE id = 1;
```

---

## NOW() 与 SYSDATE() 的区别

```sql
-- NOW()：返回语句开始执行时的时间（整个语句中相同）
-- SYSDATE()：返回函数被调用时的实时时间（每次调用可能不同）

-- 在一个语句中，NOW() 总是相同的
SELECT NOW(), SLEEP(1), NOW();
-- 2026-03-15 14:30:25 | 0 | 2026-03-15 14:30:25（两个 NOW() 完全相同）

-- SYSDATE() 则不同
SELECT SYSDATE(), SLEEP(1), SYSDATE();
-- 2026-03-15 14:30:25 | 0 | 2026-03-15 14:30:26（相差 1 秒）

-- 实际使用中，绝大多数场景用 NOW()，它与事务的语义更一致
```

## 时间范围过滤

```sql
-- 查询今天的订单
SELECT * FROM orders
WHERE created_at >= CURDATE()   -- 今天 00:00:00
  AND created_at < CURDATE() + INTERVAL 1 DAY;  -- 明天 00:00:00
-- 推荐用半开区间 [今天, 明天) 而不是 BETWEEN（BETWEEN 包含右端点）

-- 查询最近 7 天的订单
SELECT * FROM orders
WHERE created_at >= NOW() - INTERVAL 7 DAY;

-- 查询最近 1 小时的记录
SELECT * FROM logs
WHERE created_at >= NOW() - INTERVAL 1 HOUR;

-- 查询 30 天内到期的合同
SELECT * FROM contracts
WHERE expire_at BETWEEN NOW() AND NOW() + INTERVAL 30 DAY;
```

## NOW() 与时区

```sql
-- NOW() 返回的是当前会话的时区时间（受 time_zone 变量控制）
SELECT @@time_zone;          -- 查看当前时区
SET time_zone = 'Asia/Shanghai';
SELECT NOW();                -- 返回上海时间

-- UTC_TIMESTAMP()：始终返回 UTC 时间，不受 time_zone 影响
SELECT UTC_TIMESTAMP();      -- 2026-03-15 06:30:25（UTC）
SELECT NOW();                -- 2026-03-15 14:30:25（Asia/Shanghai，UTC+8）

-- 在存储时间时，国际化应用应考虑使用 UTC_TIMESTAMP() 存储，
-- 查询时在应用层或 MySQL 中转换为目标时区
```

## 适用场景

- **记录创建/更新时间**：`created_at = NOW()`、`updated_at = NOW()`
- **时间范围过滤**：最近 N 天、今日、本月等时间段查询
- **TTL 过期判断**：`WHERE expire_at < NOW()`（已过期的记录）
- **时间戳生成**：生成基于当前时间的订单号、日志记录等

---

## 常见问题

**DEFAULT CURRENT_TIMESTAMP 和 NOW() 有区别吗？**

在 DDL 中，`DEFAULT CURRENT_TIMESTAMP` 是列的默认值，在 INSERT 时不提供该列值时自动填入当前时间。`NOW()` 是在 SQL 语句中显式调用的函数。两者的返回值相同，但使用场景不同。

---

## 注意事项

- `NOW()` 在同一语句中始终返回相同的时间（语句开始时刻）。如果需要精确的微秒时间戳（如日志排序），使用 `NOW(6)` 而不是 `NOW()`。
- 在 SELECT 中对 `created_at` 列直接用函数（如 `DATE(created_at) = CURDATE()`），会导致索引失效。更好的做法是用范围条件：`created_at >= CURDATE() AND created_at < CURDATE() + INTERVAL 1 DAY`，这样可以利用 `created_at` 上的索引。

---

## 总结

`NOW()` 返回当前日期时间（`YYYY-MM-DD HH:MM:SS`），`NOW(n)` 支持小数秒精度（n=0~6）。与 `SYSDATE()` 的区别是：`NOW()` 在同一语句中总是相同的（语句开始时刻），`SYSDATE()` 每次调用返回实时时间。时区由 `time_zone` 变量控制，UTC 时间用 `UTC_TIMESTAMP()`。时间范围过滤用范围条件而非对列加函数，保证索引可用。
