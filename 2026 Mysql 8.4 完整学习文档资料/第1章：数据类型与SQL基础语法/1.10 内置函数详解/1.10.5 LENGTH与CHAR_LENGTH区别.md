# LENGTH 与 CHAR_LENGTH 区别

`LENGTH()` 返回字符串的**字节数**，`CHAR_LENGTH()`（或 `CHARACTER_LENGTH()`）返回字符串的**字符数**。两者在处理纯 ASCII 字符时结果相同，但在处理多字节字符（如中文、日文、emoji 等）时结果不同。

---

## 语法

```sql
LENGTH(str)                   -- 返回字节数
CHAR_LENGTH(str)               -- 返回字符数（Unicode 字符算 1 个）
CHARACTER_LENGTH(str)          -- 等价于 CHAR_LENGTH
BIT_LENGTH(str)                -- 返回位数（字节数 × 8）
```

---

## 基本示例

```sql
-- ASCII 字符：字节数 = 字符数
SELECT LENGTH('Hello');       -- 5（5字节 = 5字符）
SELECT CHAR_LENGTH('Hello');  -- 5

-- UTF-8 中文（每个汉字 3 字节）
SELECT LENGTH('你好世界');       -- 12（4个汉字 × 3字节）
SELECT CHAR_LENGTH('你好世界');  -- 4（4个字符）

-- 混合字符串
SELECT LENGTH('Hello你好');      -- 11（5 ASCII字节 + 6 中文字节）
SELECT CHAR_LENGTH('Hello你好'); -- 7（5 ASCII字符 + 2 中文字符）

-- Emoji（UTF-8 中通常占 4 字节）
SELECT LENGTH('😊');        -- 4
SELECT CHAR_LENGTH('😊');   -- 1
```

---

## 在实际业务中的应用

```sql
-- 校验手机号长度（应用字符数，不是字节数）
SELECT * FROM users WHERE CHAR_LENGTH(phone) != 11;
-- 手机号应该是 11 位字符

-- 校验内容不超过字符限制
SELECT * FROM articles WHERE CHAR_LENGTH(title) > 100;
-- 标题超过 100 个字符的文章

-- 查找存储了多字节字符的行（字节数 > 字符数则含多字节字符）
SELECT * FROM products WHERE LENGTH(name) > CHAR_LENGTH(name);
-- 即找出名称中含有非 ASCII 字符（中文、特殊符号）的商品

-- 估算 VARCHAR 实际占用存储（字节）
SELECT name, CHAR_LENGTH(name) AS chars, LENGTH(name) AS bytes
FROM products
ORDER BY bytes DESC LIMIT 10;
```

---

## 与 VARCHAR 定义的关系

```sql
-- VARCHAR(n) 的 n 是字符数（不是字节数）
-- VARCHAR(100) 可以存储 100 个任意字符（ASCII 或 中文）
-- 但实际占用字节数 = CHAR_LENGTH × 每字符字节数

CREATE TABLE t (
    content VARCHAR(100)  -- 最多 100 个字符
);
INSERT INTO t VALUES ('你好世界');  -- 4 个字符，占 12 字节，没问题
INSERT INTO t VALUES (REPEAT('你', 100)); -- 100 个汉字，占 300 字节，也没问题

-- CHAR(n) 同理：固定 n 个字符的存储位置（字符数，不是字节数）
```

---

## 函数对比表

| 函数 | 返回值 | 中文"你好"的返回值 |
|------|--------|-----------------|
| `LENGTH('你好')` | 字节数 | 6（UTF-8，3字节/汉字）|
| `CHAR_LENGTH('你好')` | 字符数 | 2 |
| `BIT_LENGTH('你好')` | 位数 | 48（6字节 × 8位）|
| `OCTET_LENGTH('你好')` | 字节数（= LENGTH）| 6 |

---

## 适用场景

- **验证字段长度**：验证手机号位数、身份证号位数等必须用 `CHAR_LENGTH`（字符数）
- **估算存储空间**：用 `LENGTH` 了解实际字节占用，评估存储成本
- **发现数据问题**：找出含非 ASCII 字符的记录（可能是乱码或异常输入）
- **分页截断**：按字符数截断内容摘要用 `CHAR_LENGTH`，而不是 `LENGTH`

---

## 常见问题

**为什么 LENGTH('abc') = 3 但 LENGTH(123) 也是 3？**

MySQL 在字符串函数中会将数字隐式转换为字符串。`LENGTH(123)` 等效于 `LENGTH('123')`，返回字符串 '123' 的字节数 3。

---

## 注意事项

- 业务逻辑中涉及"字数限制"（如评论最多 500 字）时，必须用 `CHAR_LENGTH`，用 `LENGTH` 会让多字节字符被过度限制（中文每字 3 字节，本来 500 字的限制变成只能写约 167 个汉字）。
- `VARCHAR(n)` 中的 n 是字符数上限，MySQL 内部会根据字符集确定实际字节存储，不需要手动计算字节数来定义列。

---

## 总结

`LENGTH()` 返回字节数，`CHAR_LENGTH()` 返回字符数。对于纯 ASCII 字符两者相同；对于多字节字符集（UTF-8 中文 3 字节/字，emoji 4 字节/字），`LENGTH > CHAR_LENGTH`。业务中的字数限制、字段长度验证应使用 `CHAR_LENGTH`；估算存储占用时使用 `LENGTH`。
