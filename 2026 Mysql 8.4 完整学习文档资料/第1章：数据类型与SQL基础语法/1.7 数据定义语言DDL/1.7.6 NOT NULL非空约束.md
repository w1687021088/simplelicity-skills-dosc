# NOT NULL 非空约束

`NOT NULL` 约束要求列的值不能为 NULL，是最基础也是最重要的列约束之一。合理使用 NOT NULL 可以在数据库层面保证数据完整性，减少应用层处理 NULL 的复杂度。

---

## 语法

```sql
-- 列定义中直接声明
col_name data_type NOT NULL
col_name data_type NOT NULL DEFAULT default_value
col_name data_type NULL  -- 明确允许 NULL（默认行为）
```

---

## 示例

```sql
CREATE TABLE employees (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    emp_no      CHAR(10) NOT NULL COMMENT '工号',
    name        VARCHAR(100) NOT NULL COMMENT '姓名',
    email       VARCHAR(200) NOT NULL COMMENT '工作邮箱',
    department  VARCHAR(100),          -- 允许 NULL（部门可能未分配）
    hire_date   DATE NOT NULL,
    salary      DECIMAL(10, 2) NOT NULL DEFAULT 0.00,
    PRIMARY KEY (id),
    UNIQUE KEY uk_emp_no (emp_no)
);

-- 尝试插入 NULL 到 NOT NULL 列（报错）
INSERT INTO employees (emp_no, name, email, hire_date)
VALUES ('E001', '张三', NULL, '2026-03-15');
-- ERROR 1048 (23000): Column 'email' cannot be null

-- 正确插入
INSERT INTO employees (emp_no, name, email, hire_date)
VALUES ('E001', '张三', 'zhangsan@company.com', '2026-03-15');
```

---

## NULL 与 NOT NULL 的行为差异

| 行为 | NOT NULL 列 | NULL 列 |
|------|------------|---------|
| 插入时不提供值 | 使用 DEFAULT（无 DEFAULT 则报错）| 存储 NULL |
| 空字符串 '' | 合法值（存空串）| 合法值（存空串）|
| NULL 值 | 报错 | 合法值 |
| IS NULL 查询 | 永远是 false | 可以是 true |
| 索引行为 | 索引中不含 NULL | NULL 值不在 B-Tree 索引中 |
| 聚合函数（COUNT/SUM）| 正常计算 | COUNT(*) 计数，COUNT(col) 跳过 NULL |

## NULL 在比较中的特殊性

```sql
-- NULL 不等于任何值，包括 NULL 自身
SELECT NULL = NULL;    -- NULL（不是 true！）
SELECT NULL != NULL;   -- NULL
SELECT NULL IS NULL;   -- 1（TRUE）
SELECT NULL IS NOT NULL; -- 0（FALSE）

-- 以下查询不能找到 NULL 值
SELECT * FROM employees WHERE department = NULL;    -- 永远没有结果
-- 应该用 IS NULL
SELECT * FROM employees WHERE department IS NULL;  -- 正确

-- NULL 在 IN/NOT IN 中的陷阱
SELECT * FROM employees WHERE department NOT IN ('HR', 'IT', NULL);
-- 等效于 department != 'HR' AND department != 'IT' AND department != NULL
-- 最后一个条件永远是 NULL（非 true），导致整个 AND 链为 NULL，即没有结果
```

## NOT NULL 与性能

```sql
-- NULL 列在 InnoDB 中占用 NULL 位图空间（每8列占1字节）
-- NOT NULL 列不需要 NULL 位图，稍微节省空间

-- 对于频繁查询的列，NOT NULL 通常更高效
-- 索引建议：NOT NULL 列上的索引更简单有效

-- 检查现有表中哪些列允许 NULL（可能是设计遗漏）
SELECT column_name, is_nullable, data_type
FROM information_schema.COLUMNS
WHERE table_schema = DATABASE() AND table_name = 'employees'
ORDER BY ordinal_position;
```

## 适用场景

- **ID 字段**：主键、外键、业务主键，必须 NOT NULL
- **业务关键字段**：用户名、邮箱、状态等，通常应 NOT NULL
- **时间字段**：`created_at` NOT NULL DEFAULT CURRENT_TIMESTAMP
- **允许 NULL 的场景**：可选字段（如备注、可选的附加信息），或表示"未知/未填写"有明确业务含义时

---

## 常见问题

**NOT NULL 和 DEFAULT '' 搭配使用合适吗？**

对于字符串列，`NOT NULL DEFAULT ''` 表示"没有提供值时存空字符串"，这在业务层有时会造成混淆（空串和未填写应该区分吗？）。如果空字符串和 NULL 有不同的业务含义，应明确区分。如果两者无区别，统一用 NOT NULL DEFAULT '' 可以避免 NULL 带来的复杂性。

**AUTO_INCREMENT 列必须是 NOT NULL 吗？**

必须。AUTO_INCREMENT 列必须是 NOT NULL 的，MySQL 会自动为其添加 NOT NULL 约束。

---

## 注意事项

- 不要滥用 NULL——能明确设置 NOT NULL 的字段尽量设置，减少 NULL 在业务逻辑中传播的不确定性。
- 新增 NOT NULL 列到已有表时，如果没有 DEFAULT 值，MySQL 在严格模式下会报错（无法为已有行自动填充值）。需要先设置一个 DEFAULT 值，或者用 `ALTER TABLE ... ADD COLUMN ... DEFAULT '...'`。

---

## 总结

NOT NULL 约束在数据库层面保证列不能存储 NULL 值，是数据完整性的基础保障。NULL 在比较、聚合、索引中有特殊行为（NULL != NULL，COUNT 跳过 NULL，NOT IN 含 NULL 的陷阱等），理解这些差异对编写正确的 SQL 至关重要。能设 NOT NULL 的列尽量设 NOT NULL，配合合理的 DEFAULT 值使用。
