# TRUNCATE TABLE 清空表

`TRUNCATE TABLE` 快速删除表中的所有行，保留表结构（列定义、索引、约束）。与 `DELETE FROM` 不同，TRUNCATE 是 DDL 操作，速度极快，不会逐行记录 Undo Log，也不能回滚。

---

## 语法

```sql
TRUNCATE [TABLE] tbl_name;
```

---

## 与 DELETE 的对比

| 对比维度 | TRUNCATE TABLE | DELETE FROM |
|---------|---------------|------------|
| 操作类型 | DDL（非事务）| DML（支持事务）|
| 是否可回滚 | 不可回滚（隐式提交）| 可回滚（在事务内）|
| 速度 | 极快（重建表空间）| 逐行删除，慢 |
| Undo Log | 不记录 | 逐行记录 |
| WHERE 条件 | 不支持（全量清空）| 支持（可以过滤）|
| 触发器 | 不触发 DELETE 触发器 | 触发 DELETE 触发器 |
| AUTO_INCREMENT | 重置为 1（或初始值）| 不重置 |
| 外键约束 | 有外键引用时报错 | 有外键时逐行检查 |
| 返回影响行数 | 总是 0（不计数）| 返回实际删除行数 |

## 基本示例

```sql
-- 清空表（保留结构）
TRUNCATE TABLE temp_logs;
TRUNCATE TABLE session_cache;  -- TABLE 关键字可省略，但建议保留

-- 验证：表结构仍然存在，数据为空
DESCRIBE temp_logs;     -- 表结构还在
SELECT COUNT(*) FROM temp_logs;  -- 0 行

-- AUTO_INCREMENT 重置
CREATE TABLE test_counter (
    id   INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    data VARCHAR(100)
);
INSERT INTO test_counter (data) VALUES ('a'), ('b'), ('c');
SELECT MAX(id) FROM test_counter;  -- 3

TRUNCATE TABLE test_counter;
INSERT INTO test_counter (data) VALUES ('x');
SELECT id FROM test_counter;  -- id = 1（重置了）
```

## 外键约束下的 TRUNCATE

```sql
-- 如果有外键引用该表，TRUNCATE 会失败
CREATE TABLE parent (id INT PRIMARY KEY);
CREATE TABLE child (id INT, parent_id INT, FOREIGN KEY (parent_id) REFERENCES parent(id));

INSERT INTO parent VALUES (1), (2);
INSERT INTO child VALUES (1, 1), (2, 2);

TRUNCATE TABLE parent;
-- ERROR 1701: Cannot truncate a table referenced in a foreign key constraint

-- 处理方法：临时禁用外键检查
SET FOREIGN_KEY_CHECKS = 0;
TRUNCATE TABLE parent;
SET FOREIGN_KEY_CHECKS = 1;
-- 注意：这样做后 child 表中可能存在悬空的外键引用
```

## 适用场景

- **清空测试数据**：每次测试前快速清空测试表，比 DELETE 快得多
- **重置缓存表**：定期清空缓存/汇总表，重新计算
- **日志轮转**：清空旧日志表（保留结构，下次继续使用）
- **开发/测试环境初始化**：快速将数据库重置到干净状态

---

## 常见问题

**TRUNCATE 可以用在分区表上吗？**

可以，但 `TRUNCATE TABLE` 清空整张分区表的所有分区。如果只想清空特定分区，使用 `ALTER TABLE ... TRUNCATE PARTITION partition_name`。

---

## 注意事项

- TRUNCATE 不能回滚，执行后数据立即永久删除。如果在事务中执行 TRUNCATE，它会自动提交当前事务，然后执行 TRUNCATE。
- TRUNCATE 不触发 DELETE 触发器（`BEFORE DELETE`、`AFTER DELETE` 触发器都不会执行），如果业务逻辑依赖这些触发器，需要改用 DELETE。
- 在有外键引用的表上直接 TRUNCATE 会报错，需要先处理外键（禁用外键检查或先清空子表）。

---

## 总结

`TRUNCATE TABLE` 快速清空表中所有数据，保留表结构，同时重置 AUTO_INCREMENT 计数器。它比 DELETE FROM（无 WHERE）快得多，但不可回滚、不触发触发器、不支持外键保护。适用于需要快速清空整张表的场景（测试数据重置、缓存清理等）。
