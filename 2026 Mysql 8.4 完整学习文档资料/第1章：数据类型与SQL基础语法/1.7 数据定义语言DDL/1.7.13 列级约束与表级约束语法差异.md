# 列级约束与表级约束语法差异

MySQL 的约束可以在两个层面声明：列级约束（紧跟在列定义后面）和表级约束（独立声明在所有列定义之后）。理解两者的语法差异和适用情况，有助于编写清晰规范的建表语句。

---

## 两种约束声明方式对比

| 特性 | 列级约束 | 表级约束 |
|------|---------|---------|
| 位置 | 紧跟列定义 | 所有列之后，独立声明 |
| 可命名 | 部分支持（CHECK 支持）| 完全支持（通过 CONSTRAINT） |
| 复合支持 | 只能引用本列 | 可以引用多列 |
| 适用约束 | NOT NULL、DEFAULT、UNIQUE、PRIMARY KEY、CHECK | UNIQUE、PRIMARY KEY、FOREIGN KEY、CHECK |
| NOT NULL | 只能列级 | 不支持表级 NOT NULL |
| FOREIGN KEY | 语法支持但不推荐 | 推荐写法 |
| 可读性 | 适合单列约束（简洁）| 适合复合约束（清晰）|

---

## 语法示例对比

```sql
-- === 列级约束写法 ===
CREATE TABLE users_column_level (
    id       INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,  -- PRIMARY KEY 列级
    username VARCHAR(50) NOT NULL UNIQUE,                        -- UNIQUE 列级
    email    VARCHAR(200) NOT NULL UNIQUE,
    age      TINYINT UNSIGNED CHECK (age >= 0 AND age <= 150),  -- CHECK 列级
    salary   DECIMAL(10,2) DEFAULT 0.00
);

-- === 表级约束写法 ===
CREATE TABLE users_table_level (
    id       INT UNSIGNED NOT NULL AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL,
    email    VARCHAR(200) NOT NULL,
    age      TINYINT UNSIGNED,
    salary   DECIMAL(10,2) DEFAULT 0.00,
    -- 表级约束（独立声明）
    PRIMARY KEY (id),
    UNIQUE KEY uk_username (username),
    UNIQUE KEY uk_email (email),
    CONSTRAINT ck_age CHECK (age >= 0 AND age <= 150)
);
```

## 必须使用表级约束的情况

```sql
-- 1. 复合主键（多列联合主键只能表级声明）
CREATE TABLE order_items (
    order_id   BIGINT UNSIGNED NOT NULL,
    item_seq   SMALLINT UNSIGNED NOT NULL,
    product_id INT UNSIGNED NOT NULL,
    PRIMARY KEY (order_id, item_seq)   -- 必须表级
);

-- 2. 复合唯一约束（多列联合唯一只能表级声明）
CREATE TABLE product_tags (
    id         INT UNSIGNED NOT NULL AUTO_INCREMENT,
    product_id INT UNSIGNED NOT NULL,
    tag_name   VARCHAR(50) NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_product_tag (product_id, tag_name)   -- 必须表级
);

-- 3. 外键约束（强烈推荐表级声明，方便命名和管理）
CREATE TABLE orders (
    id      BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id INT UNSIGNED NOT NULL,
    PRIMARY KEY (id),
    CONSTRAINT fk_orders_user FOREIGN KEY (user_id) REFERENCES users(id)  -- 表级
);

-- 4. 跨列 CHECK 约束
CREATE TABLE events (
    start_at DATETIME NOT NULL,
    end_at   DATETIME NOT NULL,
    CONSTRAINT ck_event_time CHECK (end_at > start_at)  -- 必须表级（引用两列）
);
```

## 约束命名的重要性

```sql
-- 不命名的约束（MySQL 自动生成名称，如 products_chk_1）
CREATE TABLE t1 (
    price DECIMAL(10,2) CHECK (price > 0)  -- 自动命名为 t1_chk_1 或类似名
);

-- 命名的约束（推荐：便于管理和错误排查）
CREATE TABLE t2 (
    price    DECIMAL(10,2),
    cost     DECIMAL(10,2),
    CONSTRAINT ck_t2_price_positive CHECK (price > 0),
    CONSTRAINT ck_t2_price_above_cost CHECK (price >= cost)
);

-- 有命名时，错误信息更清晰
INSERT INTO t2 (price, cost) VALUES (-1, 0);
-- ERROR 3819: Check constraint 'ck_t2_price_positive' is violated.  ← 明确显示哪个约束

-- 无命名时，错误信息不直观
INSERT INTO t1 (price) VALUES (-1);
-- ERROR 3819: Check constraint 't1_chk_1' is violated.  ← 不直观
```

## 推荐的建表约束写法

```sql
-- 生产环境推荐的规范建表写法：
-- 1. NOT NULL 和 DEFAULT 用列级约束（只能列级）
-- 2. PRIMARY KEY、UNIQUE、FOREIGN KEY 用表级约束（便于命名和查看）
-- 3. CHECK 约束：单列的可列级，跨列的必须表级，都推荐命名

CREATE TABLE payments (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT       COMMENT '支付ID',
    order_id    BIGINT UNSIGNED NOT NULL                   COMMENT '订单ID',
    amount      DECIMAL(10, 2) NOT NULL DEFAULT 0.00       COMMENT '支付金额',
    method      VARCHAR(20) NOT NULL DEFAULT 'unknown'     COMMENT '支付方式',
    status      TINYINT UNSIGNED NOT NULL DEFAULT 0        COMMENT '状态',
    paid_at     DATETIME                                   COMMENT '支付时间',
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    -- 主键（表级）
    PRIMARY KEY (id),
    -- 索引（表级）
    INDEX idx_order_id (order_id),
    -- 外键（表级，命名）
    CONSTRAINT fk_payments_order FOREIGN KEY (order_id) REFERENCES orders(id),
    -- CHECK（表级，命名）
    CONSTRAINT ck_payment_amount CHECK (amount >= 0),
    CONSTRAINT ck_payment_method CHECK (method IN ('wechat', 'alipay', 'card', 'unknown'))
) ENGINE=InnoDB COMMENT='支付记录表';
```

## 适用场景

- 列级约束：`NOT NULL`、`DEFAULT`、单列的简单 CHECK 写法（代码简洁）
- 表级约束：复合键约束、外键约束、需要自定义名称的约束（便于维护）

---

## 常见问题

**同一个约束同时用列级和表级声明会怎样？**

会导致重复约束，MySQL 会创建两个约束，写入时会被检查两次（虽然效果一样）。在实际建表时应该只选一种方式，不要重复声明。

---

## 注意事项

- `NOT NULL` 约束无法在表级声明，必须在列定义中声明。
- 约束名称在同一个数据库内应该唯一（建议加表名前缀，如 `fk_orders_user`、`ck_orders_amount`），以便在 information_schema 中快速定位。

---

## 总结

列级约束写在列定义后面，语法简洁，适合 NOT NULL、DEFAULT 以及单列的简单约束。表级约束独立声明，可以命名，支持复合列，是 PRIMARY KEY、UNIQUE、FOREIGN KEY 和跨列 CHECK 的推荐写法。生产环境建表规范：NOT NULL/DEFAULT 用列级，其他约束用表级并命名，有助于错误排查和约束管理。
