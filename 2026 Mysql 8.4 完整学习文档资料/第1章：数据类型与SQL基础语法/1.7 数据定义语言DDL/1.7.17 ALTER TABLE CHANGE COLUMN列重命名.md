# ALTER TABLE CHANGE COLUMN 列重命名

`ALTER TABLE ... CHANGE COLUMN` 用于在修改列定义的同时重命名列，是 `MODIFY COLUMN` 的超集。MySQL 8.0 还引入了更简洁的 `RENAME COLUMN` 语法，可以在不修改列定义的情况下单独重命名列。

---

## 语法

```sql
-- CHANGE COLUMN：重命名同时可修改列定义
ALTER TABLE tbl_name
    CHANGE [COLUMN] old_col_name new_col_name col_definition [FIRST | AFTER col_name];

-- RENAME COLUMN（MySQL 8.0+）：只重命名，不修改定义
ALTER TABLE tbl_name RENAME COLUMN old_col_name TO new_col_name;
```

---

## CHANGE COLUMN 示例

```sql
-- 重命名列（同时保留原有定义，必须写完整的列定义）
ALTER TABLE users
    CHANGE COLUMN user_name username VARCHAR(50) NOT NULL COMMENT '用户名';
-- 将 user_name 改名为 username，同时完整写出新的列定义

-- 重命名并修改类型
ALTER TABLE orders
    CHANGE COLUMN order_amount amount DECIMAL(12, 2) NOT NULL DEFAULT 0.00 COMMENT '订单金额（元）';
-- 列名 order_amount → amount，同时精度从 DECIMAL(10,2) 升级为 DECIMAL(12,2)

-- 只修改注释（不改列名，使用 CHANGE 需要重复写列名）
ALTER TABLE products
    CHANGE COLUMN price price DECIMAL(10, 2) NOT NULL DEFAULT 0.00 COMMENT '零售价（元）';
-- 这种情况更推荐用 MODIFY COLUMN，不需要重复写列名
```

---

## RENAME COLUMN（MySQL 8.0+ 推荐）

```sql
-- 简洁的列重命名语法，不需要写完整的列定义
ALTER TABLE users RENAME COLUMN user_name TO username;

-- 多列同时重命名
ALTER TABLE products
    RENAME COLUMN product_name TO name,
    RENAME COLUMN product_price TO price;

-- RENAME COLUMN 支持 INSTANT 算法（只修改数据字典，不重建表）
ALTER TABLE users RENAME COLUMN user_name TO username, ALGORITHM=INSTANT;
```

---

## CHANGE vs RENAME vs MODIFY 对比

| 功能 | CHANGE COLUMN | RENAME COLUMN (8.0+) | MODIFY COLUMN |
|------|--------------|---------------------|---------------|
| 重命名列 | 支持 | 支持 | 不支持 |
| 修改列定义 | 支持 | 不支持（只改名）| 支持 |
| 需要写完整定义 | 是 | 否 | 是 |
| INSTANT 算法 | 取决于定义变更 | 支持 | 部分支持 |
| MySQL 版本 | 全版本 | 8.0+ | 全版本 |

## 注意事项（应用层影响）

列重命名后，所有引用旧列名的代码都需要更新：

```sql
-- 1. 代码中的 SQL 语句（ORM 映射、原生 SQL）
-- 2. 视图定义（引用了旧列名的视图需要重新创建）
SELECT table_name, view_definition FROM information_schema.VIEWS
WHERE view_definition LIKE '%old_column_name%';

-- 3. 存储过程和函数
SELECT routine_name, routine_definition FROM information_schema.ROUTINES
WHERE routine_definition LIKE '%old_column_name%';

-- 4. 触发器
SELECT trigger_name, action_statement FROM information_schema.TRIGGERS
WHERE action_statement LIKE '%old_column_name%';

-- 5. 生成列依赖（引用了旧列名的生成列需要重新定义）
-- 注意：RENAME COLUMN 不自动更新依赖该列的生成列定义
```

---

## 适用场景

- **规范化列名**：将不规范的列名（如 userName、UserName）统一为标准格式（user_name）
- **业务改名**：业务术语变化导致列名需要更新（如 amount → price）
- **遗留代码清理**：将历史遗留的模糊列名（如 col1、data1）改为有意义的名称

---

## 常见问题

**RENAME COLUMN 需要重建表吗？**

不需要，`RENAME COLUMN` 使用 INSTANT 算法，只修改数据字典中的列名元数据，不重建表数据，操作瞬间完成。

**CHANGE COLUMN 中新旧列名相同是什么效果？**

相当于只修改列的定义（等同于 MODIFY COLUMN），不改列名。语法上合法，但推荐用 MODIFY COLUMN 代替，更直观。

---

## 注意事项

- MySQL 8.0+ 优先使用 `RENAME COLUMN`，比 `CHANGE COLUMN` 更简洁，支持 INSTANT 算法，不需要写完整列定义（避免意外丢失 DEFAULT、NOT NULL、COMMENT 等属性）。
- 生产环境列重命名的风险主要来自应用层代码，而不是数据库层面。重命名前必须协调应用代码的同步更新，否则应用会因找不到旧列名而报错。

---

## 总结

`CHANGE COLUMN` 可以同时重命名列和修改列定义，但需要写完整的新列定义。MySQL 8.0+ 的 `RENAME COLUMN` 语法更简洁，只需指定新旧列名，支持 INSTANT 算法，适合单纯的列重命名场景。列重命名后需要同步更新所有引用旧列名的视图、存储过程、触发器和应用代码。
