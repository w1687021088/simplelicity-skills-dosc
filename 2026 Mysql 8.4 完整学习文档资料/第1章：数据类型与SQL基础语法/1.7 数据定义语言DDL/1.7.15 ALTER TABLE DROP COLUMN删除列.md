# ALTER TABLE DROP COLUMN 删除列

`ALTER TABLE ... DROP COLUMN` 从已有表中删除指定列，包括该列的所有数据和相关索引。这是不可逆的破坏性操作，执行前必须确认列已不再被任何业务代码或查询引用，且有完整备份。

---

## 语法

```sql
ALTER TABLE tbl_name DROP [COLUMN] col_name;

-- 同时删除多列
ALTER TABLE tbl_name
    DROP COLUMN col1,
    DROP COLUMN col2;
```

---

## 基本示例

```sql
-- 删除单列
ALTER TABLE users DROP COLUMN old_field;

-- 同时删除多列（推荐合并，减少 DDL 次数）
ALTER TABLE products
    DROP COLUMN legacy_code,
    DROP COLUMN deprecated_flag;

-- 验证删除结果
DESCRIBE users;
```

---

## 删除前的准备工作

```sql
-- 1. 确认列的当前使用情况
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.COLUMNS
WHERE table_schema = DATABASE() AND table_name = 'users' AND column_name = 'old_field';

-- 2. 检查该列是否有索引
SHOW INDEX FROM users;
-- 如果 old_field 在某个复合索引中，需要先删除索引

-- 3. 检查是否有依赖该列的视图
SELECT table_name, view_definition
FROM information_schema.VIEWS
WHERE table_schema = DATABASE() AND view_definition LIKE '%old_field%';

-- 4. 确认外键依赖
SELECT constraint_name, column_name
FROM information_schema.KEY_COLUMN_USAGE
WHERE table_schema = DATABASE() AND table_name = 'users' AND column_name = 'old_field';
```

## 删除列的限制

```sql
-- 1. 不能删除有外键约束的列（先删除外键，再删除列）
-- 假设 orders.user_id 被外键约束引用
ALTER TABLE orders DROP COLUMN user_id;
-- ERROR: Cannot drop column 'user_id': needed in a foreign key constraint

-- 正确做法：先删除外键约束，再删除列
ALTER TABLE orders DROP FOREIGN KEY fk_orders_user;
ALTER TABLE orders DROP COLUMN user_id;

-- 2. 不能删除被生成列依赖的列
-- 如果 profit = (price - cost) / cost，则不能先删除 price 或 cost
ALTER TABLE products DROP COLUMN price;
-- ERROR: Column 'price' has a generated column dependency.

-- 先删除生成列，再删除基础列
ALTER TABLE products DROP COLUMN profit, DROP COLUMN price;

-- 3. 不能删除表的唯一非空列（如果表只剩一列）
-- MySQL 不允许删除导致表没有列的操作
```

## DROP COLUMN 的算法

```sql
-- MySQL 8.0.29+ 支持 INSTANT DROP COLUMN（某些条件下）
-- 条件：列是通过 INSTANT ADD COLUMN 添加的，且满足一定要求

-- 一般情况下，DROP COLUMN 需要重建表（COPY 或 INPLACE）
ALTER TABLE t DROP COLUMN old_col, ALGORITHM=INPLACE, LOCK=NONE;
-- 如果不支持 INPLACE，会报错，需改为 COPY

-- 验证算法
EXPLAIN ALTER TABLE t DROP COLUMN old_col;  -- 不实际执行，只显示算法
```

## 数据恢复考量

```sql
-- 删除列后，如果需要恢复该列的数据：
-- 1. 从备份（mysqldump 等）恢复该列的数据
-- 2. 从 Binlog 中找到删除前的数据

-- 在生产环境操作前，先备份相关数据
-- 方法1：导出该列的数据到备份表
CREATE TABLE users_old_field_backup AS
SELECT id, old_field FROM users;  -- 备份该列数据

-- 然后再删除
ALTER TABLE users DROP COLUMN old_field;

-- 方法2：使用 mysqldump 备份整张表
-- mysqldump -u root -p mydb users > users_backup.sql
```

## 适用场景

- 清理废弃的业务字段（在代码已经不引用该字段后）
- 表结构重构时移除冗余列
- 数据库瘦身（删除历史遗留的无用字段）

---

## 常见问题

**DROP COLUMN 会删除该列上的索引吗？**

会。如果被删除的列是某个单列索引，该索引会被自动删除。如果该列是复合索引的一部分，整个复合索引都会被删除（不会自动调整为减少了一列的索引）。

**删除列后，该列的数据还在 .ibd 文件中吗？**

不在。DROP COLUMN 如果使用 COPY 算法（重建表），旧列的数据会被完全丢弃。INSTANT DROP COLUMN 的情况下，数据仍存储在磁盘但被标记为"幽灵列"，不会被 MySQL 读取，执行 OPTIMIZE TABLE 后才完全清除。

---

## 注意事项

- 生产环境删除大表的列应使用 pt-online-schema-change 等工具，避免长时间锁表。
- 删除前务必搜索代码库，确认没有任何 SQL、ORM 映射或视图引用该列，否则删除后会导致应用报错。
- **数据无法从 MySQL 层面直接恢复**，必须依赖 binlog 或备份。操作前备份数据是铁律。

---

## 总结

`ALTER TABLE DROP COLUMN` 删除列及其所有数据和相关索引，操作不可逆。删除前需检查外键依赖、生成列依赖、视图依赖，并做好数据备份。MySQL 8.0.29+ 在特定条件下支持 INSTANT DROP COLUMN；一般情况下需要重建表，大表应使用在线 Schema 变更工具。
