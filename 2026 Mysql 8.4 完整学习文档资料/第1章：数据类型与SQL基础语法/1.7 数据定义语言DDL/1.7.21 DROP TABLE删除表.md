# DROP TABLE 删除表

`DROP TABLE` 删除指定的表及其所有数据、索引和约束。这是不可逆的破坏性操作，执行后数据无法从 MySQL 层面直接恢复，必须依赖备份或 Binlog。

---

## 语法

```sql
DROP [TEMPORARY] TABLE [IF EXISTS] tbl_name [, tbl_name ...];
```

---

## 基本示例

```sql
-- 删除单张表
DROP TABLE old_logs;

-- 删除时不报错（即使表不存在）
DROP TABLE IF EXISTS old_logs;

-- 同时删除多张表
DROP TABLE IF EXISTS temp_analysis, old_cache, deprecated_data;

-- 删除临时表
DROP TEMPORARY TABLE IF EXISTS temp_result;
```

---

## DROP TABLE 与其他删除操作对比

| 操作 | 目标 | 是否删除结构 | 事务支持 | 性能 |
|------|------|------------|---------|------|
| DROP TABLE | 整张表 | 是（结构+数据）| 不支持（隐式提交）| 快 |
| TRUNCATE TABLE | 表内所有行 | 否（保留结构）| 不支持（隐式提交）| 快 |
| DELETE FROM | 表内符合条件的行 | 否 | 支持（可回滚）| 慢（记录 Undo Log）|

---

## 执行前的检查

```sql
-- 检查是否有外键约束引用该表
SELECT table_name, constraint_name
FROM information_schema.KEY_COLUMN_USAGE
WHERE referenced_table_schema = DATABASE()
  AND referenced_table_name = 'old_table';
-- 有结果时，需要先删除引用该表的外键约束，才能 DROP 该表

-- 检查是否有视图依赖该表
SELECT table_name FROM information_schema.VIEWS
WHERE view_definition LIKE '%old_table%';
```

-- MySQL 8.0 删除大表较快（O(1)，无需遍历所有行）

## 适用场景

- 清理测试数据、临时表、已下线功能的表
- 初始化脚本中 `DROP TABLE IF EXISTS` + `CREATE TABLE` 的幂等建表模式
- 数据迁移完成后清理旧表

---

## 常见问题

**DROP TABLE 可以回滚吗？**

不能。DROP TABLE 是 DDL 语句，在 MySQL 中会自动提交当前事务，且 DDL 操作本身不支持回滚。一旦执行，数据只能通过 Binlog 或备份恢复。

---

## 注意事项

- 生产环境执行 `DROP TABLE` 前，必须有完整备份，并确认代码库中没有对该表的任何引用。
- 有外键约束引用的表不能被直接删除，需要先删除引用它的外键约束（或先删除子表）。

---

## 总结

`DROP TABLE` 彻底删除表（结构+数据+索引），操作不可逆，执行时隐式提交事务。加上 `IF EXISTS` 可以避免表不存在时的错误。删除前需检查外键依赖和视图依赖。生产环境务必在有完整备份的前提下执行。
