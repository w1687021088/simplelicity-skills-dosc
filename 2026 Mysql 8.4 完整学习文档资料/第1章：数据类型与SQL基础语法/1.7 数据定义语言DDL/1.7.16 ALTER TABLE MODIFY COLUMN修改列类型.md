# ALTER TABLE MODIFY COLUMN 修改列类型

`ALTER TABLE ... MODIFY COLUMN` 用于修改列的数据类型、约束、默认值、注释等属性，但保留列名不变。它是日常表结构维护中最频繁的 DDL 操作之一，需要理解哪些改动是安全的，哪些可能导致数据截断或丢失。

---

## 语法

```sql
ALTER TABLE tbl_name
    MODIFY [COLUMN] col_name new_col_definition [FIRST | AFTER col_name];
```

与 `CHANGE COLUMN` 的区别：MODIFY 不能改列名；CHANGE 可以同时改列名和定义。

---

## 常见修改操作

```sql
-- 扩展 VARCHAR 长度（通常是安全的，不改变已有数据）
ALTER TABLE users MODIFY COLUMN username VARCHAR(100) NOT NULL COMMENT '用户名';

-- 修改列的默认值
ALTER TABLE orders MODIFY COLUMN status TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '状态';

-- 添加 COMMENT（不改类型，只加注释）
ALTER TABLE products MODIFY COLUMN price DECIMAL(10, 2) NOT NULL DEFAULT 0.00 COMMENT '售价（元）';

-- 修改 NOT NULL 约束（添加）
ALTER TABLE users MODIFY COLUMN phone VARCHAR(20) NOT NULL DEFAULT '';

-- 修改 NOT NULL 约束（允许 NULL）
ALTER TABLE users MODIFY COLUMN phone VARCHAR(20) DEFAULT NULL;

-- INT 升级为 BIGINT（扩大范围，数据不会丢失）
ALTER TABLE orders MODIFY COLUMN id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT;

-- 修改字符集（此操作会重建表）
ALTER TABLE articles MODIFY COLUMN title VARCHAR(200) NOT NULL
    CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

---

## 安全 vs 风险操作

| 操作类型 | 安全性 | 说明 |
|---------|--------|------|
| 扩大 VARCHAR 长度 | 安全 | 已有数据不受影响 |
| 缩小 VARCHAR 长度 | 有风险 | 可能截断已有数据，严格模式下报错 |
| INT → BIGINT | 安全 | 数值范围变大，不影响数据 |
| BIGINT → INT | 有风险 | 超出 INT 范围的值会被截断或报错 |
| 添加 DEFAULT 值 | 安全 | 只影响新插入行 |
| 添加 NOT NULL（无 DEFAULT）| 有风险 | 若有 NULL 值，会报错 |
| 修改字符集 | 需要重建 | 可能造成乱码（如数据本身不符合新字符集）|
| 增加 DECIMAL 精度 | 安全 | (10,2)→(12,2) 不影响已有数据 |
| 减少 DECIMAL 精度 | 有风险 | 整数部分长度变小会截断 |

## MODIFY 触发的 DDL 算法

```sql
-- 只修改默认值（INSTANT 算法，瞬间完成）
ALTER TABLE t MODIFY COLUMN col INT NOT NULL DEFAULT 10, ALGORITHM=INSTANT;

-- 扩大 VARCHAR（INPLACE 算法，不重建表）
ALTER TABLE t MODIFY COLUMN name VARCHAR(200), ALGORITHM=INPLACE, LOCK=NONE;

-- 修改字符集（COPY 算法，重建整张表）
ALTER TABLE t MODIFY COLUMN content TEXT CHARACTER SET utf8mb4, ALGORITHM=COPY;

-- 查看会使用哪种算法（不实际执行）
ALTER TABLE t MODIFY COLUMN name VARCHAR(200), ALGORITHM=INSTANT;
-- 如果返回 ERROR: ALGORITHM=INSTANT is not supported，说明需要 INPLACE 或 COPY
```

---

## 修改时处理已有数据的 NULL 情况

```sql
-- 当要把允许 NULL 的列改为 NOT NULL 时，先处理 NULL 值
-- 查看有多少 NULL 值
SELECT COUNT(*) FROM users WHERE phone IS NULL;

-- 将 NULL 替换为空字符串（或其他合适的默认值）
UPDATE users SET phone = '' WHERE phone IS NULL;

-- 确认没有 NULL 后，再修改为 NOT NULL
ALTER TABLE users MODIFY COLUMN phone VARCHAR(20) NOT NULL DEFAULT '';
```

## 适用场景

- **扩展存储空间**：业务增长后，VARCHAR 长度不够了，INT 主键快到上限了
- **添加/修改约束**：为列补充 NOT NULL、DEFAULT 或 COMMENT
- **字符集迁移**：将列的字符集从 utf8 改为 utf8mb4（支持 emoji）
- **精度调整**：金额字段增加整数位数（如 DECIMAL(10,2) → DECIMAL(12,2)）

## 常见问题

**MODIFY COLUMN 每次都需要重新指定完整的列定义吗？**

是的，MODIFY COLUMN 必须写出列的完整定义（类型、NOT NULL、DEFAULT、COMMENT 等）。如果只写新的类型而省略了原有的 NOT NULL 或 DEFAULT，这些约束会被移除。这是一个常见的疏漏，修改时要把所有属性都写全。

**MODIFY COLUMN 的位置参数（FIRST/AFTER）会触发重建吗？**

改变列的位置（逻辑顺序）通常需要重建表（COPY 算法），即使类型没有变化。如果不需要改位置，就不要加 FIRST/AFTER。

---

## 注意事项

- 修改列类型时，即使内容"兼容"，MySQL 在严格模式下仍会检查每一行数据是否符合新类型，不符合的会报错而不是静默截断。
- 大表的 MODIFY COLUMN 如果需要重建表（COPY 算法），时间可能很长。生产环境应先在测试库验证，并使用在线 DDL 工具（pt-online-schema-change、gh-ost）操作生产大表。
- 每次 MODIFY COLUMN 都要写完整的列定义，否则容易误删 DEFAULT 或 COMMENT 等属性。

---

## 总结

`MODIFY COLUMN` 修改列的类型、约束、默认值等属性，保留列名不变。扩大长度/类型通常安全；缩小长度/类型可能截断数据。仅修改 DEFAULT 值支持 INSTANT 算法（瞬间完成）；修改字符集需要 COPY 重建表。每次 MODIFY 必须写完整的列定义，避免意外丢失原有的 NOT NULL、DEFAULT 等属性。
