# ALTER TABLE DROP INDEX 删除索引

`ALTER TABLE ... DROP INDEX` 用于删除已有表上的索引。删除不再需要的索引可以减少写操作的额外开销（每次 DML 都需要维护索引），节省存储空间。删除索引在 MySQL 8.0 中是在线操作，通常不锁表。

---

## 语法

```sql
ALTER TABLE tbl_name DROP INDEX index_name;
ALTER TABLE tbl_name DROP KEY index_name;  -- DROP KEY 等价于 DROP INDEX

-- 等价的 DROP INDEX 语法
DROP INDEX index_name ON tbl_name;

-- 删除主键
ALTER TABLE tbl_name DROP PRIMARY KEY;

-- 同时删除多个索引
ALTER TABLE tbl_name
    DROP INDEX idx_old1,
    DROP INDEX idx_old2;
```

---

## 基本示例

```sql
-- 删除普通索引
ALTER TABLE orders DROP INDEX idx_amount;

-- 删除唯一索引
ALTER TABLE users DROP INDEX uk_phone;

-- 通过 DROP INDEX 语句删除
DROP INDEX idx_status ON orders;

-- 删除主键（需要特别注意：会将聚簇索引改变）
-- 如果没有 AUTO_INCREMENT，可以直接删除
ALTER TABLE t DROP PRIMARY KEY;
-- 如果有 AUTO_INCREMENT 列，需要先去掉 AUTO_INCREMENT，再删除主键
ALTER TABLE t MODIFY COLUMN id INT NOT NULL;  -- 去掉 AUTO_INCREMENT
ALTER TABLE t DROP PRIMARY KEY;               -- 再删除主键
```

---

## 删除前的确认步骤

```sql
-- 1. 查看现有索引
SHOW INDEX FROM orders;

-- 2. 确认索引是否真的没有在用（通过 performance_schema）
-- 查看索引的访问统计（MySQL 8.0）
SELECT object_schema, object_name, index_name, count_read, count_write
FROM performance_schema.table_io_waits_summary_by_index_usage
WHERE object_schema = DATABASE() AND object_name = 'orders'
ORDER BY count_read DESC;
-- count_read=0 AND count_write=0 说明该索引从未被使用过（可以考虑删除）

-- 3. 检查是否有查询依赖该索引（通过 EXPLAIN）
EXPLAIN SELECT * FROM orders WHERE amount > 100;
-- 如果 key 字段显示 idx_amount，说明有查询在用该索引，不应删除
```

## 在线删除索引

```sql
-- MySQL 8.0 中删除普通索引是在线操作（INPLACE + LOCK=NONE）
ALTER TABLE orders DROP INDEX idx_old_field, ALGORITHM=INPLACE, LOCK=NONE;
-- 删除索引期间 DML 正常进行

-- 显式验证算法支持
ALTER TABLE orders DROP INDEX idx_test, ALGORITHM=INSTANT;
-- 如果报错 "INSTANT is not supported"，改用 INPLACE
```

## 适用场景

- **性能调优**：发现某些索引从未被查询使用（通过 performance_schema 确认），删除无用索引减少写入开销
- **表结构清理**：历史遗留的废弃索引（对应已废弃的业务逻辑）
- **索引重建**：先删除旧索引，再创建优化后的新索引（通常合并为一条语句：`DROP INDEX + ADD INDEX`）

---

## 常见问题

**删除索引会影响现有数据吗？**

不会，索引只是数据的额外引用结构，删除索引不会改变表中的实际数据行。只会影响依赖该索引的查询性能——删除后这些查询会退化为全表扫描。

**能删除系统自动创建的索引吗？**

不能直接删除为外键约束自动创建的索引（需要先删除外键约束）。也不能用 `DROP INDEX` 删除主键，主键需要用 `DROP PRIMARY KEY`。

---

## 注意事项

- 删除索引前，务必通过 `performance_schema.table_io_waits_summary_by_index_usage` 确认该索引是否真的没有在使用中，避免删掉还在用的索引导致查询性能急剧下降。
- 删除后应监控相关查询的执行计划（`EXPLAIN`）和响应时间，确认没有意外的性能退化。

---

## 总结

`ALTER TABLE DROP INDEX`（或 `DROP INDEX ... ON`）删除指定索引，不影响表数据。MySQL 8.0 中删除普通索引是在线操作（INPLACE），不锁表。删除前应通过 performance_schema 确认索引是否有查询在使用，避免误删导致性能问题。删除后应验证相关查询的执行计划没有退化。
