# UNIQUE 唯一约束

UNIQUE 约束保证列（或列组合）中的值在整张表中唯一，不允许重复。与 PRIMARY KEY 的区别在于：UNIQUE 列可以包含 NULL 值（NULL 不与任何值相等，包括 NULL 自身，因此多个 NULL 不算重复），且一张表可以有多个 UNIQUE 约束。

---

## 语法

```sql
-- 列级声明
col_name data_type UNIQUE [KEY]

-- 表级声明（可以命名）
UNIQUE KEY uk_name (col_name [, col_name ...])
UNIQUE INDEX uk_name (col_name [, col_name ...])  -- KEY 和 INDEX 等价

-- 添加到已有表
ALTER TABLE tbl_name ADD UNIQUE KEY uk_name (col_name);
CREATE UNIQUE INDEX uk_name ON tbl_name (col_name);
```

---

## 创建示例

```sql
-- 用户表中多个唯一约束
CREATE TABLE users (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    username    VARCHAR(50) NOT NULL,
    email       VARCHAR(200) NOT NULL,
    phone       VARCHAR(20),           -- 允许 NULL（手机号可选）
    id_card     CHAR(18),              -- 允许 NULL（身份证可选）
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_username (username),  -- 用户名唯一
    UNIQUE KEY uk_email (email),        -- 邮箱唯一
    UNIQUE KEY uk_phone (phone),        -- 手机号唯一（允许多个 NULL）
    UNIQUE KEY uk_id_card (id_card)     -- 身份证唯一（允许多个 NULL）
);

-- 复合唯一约束（多列组合唯一）
CREATE TABLE user_roles (
    user_id INT UNSIGNED NOT NULL,
    role_id INT UNSIGNED NOT NULL,
    PRIMARY KEY (user_id, role_id)  -- 主键同时是唯一约束
);

-- 另一种复合唯一约束的场景（不用作主键的情况）
CREATE TABLE product_tags (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    product_id  INT UNSIGNED NOT NULL,
    tag_name    VARCHAR(50) NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_product_tag (product_id, tag_name)  -- 同一商品不能有重复标签
);
```

## NULL 与 UNIQUE 的行为

```sql
-- UNIQUE 列允许多个 NULL（NULL != NULL，不算重复）
INSERT INTO users (username, email, phone) VALUES ('alice', 'alice@example.com', NULL);
INSERT INTO users (username, email, phone) VALUES ('bob',   'bob@example.com',   NULL);
-- 两条记录的 phone 都是 NULL，不违反唯一约束，插入成功

-- 但两条相同的非 NULL 值会违反唯一约束
INSERT INTO users (username, email) VALUES ('alice', 'alice2@example.com');
-- ERROR 1062 (23000): Duplicate entry 'alice' for key 'uk_username'
```

## UNIQUE 与 PRIMARY KEY 的对比

| 对比维度 | PRIMARY KEY | UNIQUE KEY |
|---------|------------|-----------|
| 数量限制 | 每表只能一个 | 每表可以多个 |
| NULL 值 | 不允许 NULL | 允许多个 NULL |
| 索引类型 | 聚簇索引（InnoDB）| 二级索引 |
| 命名 | 固定名称 PRIMARY | 可自定义名称 |
| 复合支持 | 支持 | 支持 |

## 查看 UNIQUE 约束

```sql
-- 查看表的所有索引（包括 UNIQUE 索引）
SHOW INDEX FROM users;
-- Non_unique=0 表示是唯一索引

-- 通过 information_schema 查看
SELECT index_name, column_name, non_unique
FROM information_schema.STATISTICS
WHERE table_schema = DATABASE() AND table_name = 'users' AND non_unique = 0;
```

## 违反唯一约束的处理

```sql
-- 普通 INSERT 遇到重复值直接报错
INSERT INTO users (username, email) VALUES ('alice', 'new@example.com');
-- ERROR 1062 (23000): Duplicate entry 'alice' for key 'uk_username'

-- INSERT IGNORE：重复时静默忽略（不插入，不报错）
INSERT IGNORE INTO users (username, email) VALUES ('alice', 'new@example.com');
-- 不报错，但行数受影响为 0

-- INSERT ... ON DUPLICATE KEY UPDATE：重复时更新
INSERT INTO users (username, email) VALUES ('alice', 'updated@example.com')
ON DUPLICATE KEY UPDATE email = VALUES(email);
-- 找到重复的 username='alice'，更新其 email

-- REPLACE INTO：重复时先删除旧行，再插入新行（慎用，会改变主键）
REPLACE INTO users (id, username, email) VALUES (1, 'alice', 'replaced@example.com');
```

## 适用场景

- **用户名、邮箱、手机号**：账号唯一标识字段
- **业务编号**：订单号、商品 SKU、优惠券码等
- **关联关系约束**：中间表中防止重复关联（如用户-角色、商品-标签）
- **自然主键**：当业务主键有唯一性但不适合作聚簇索引时（仍建 UNIQUE，主键另设代理键）

---

## 常见问题

**UNIQUE 索引和普通 INDEX 的区别是什么？**

UNIQUE INDEX 在查询性能上和普通 INDEX 没有区别，都是 B-Tree 索引。区别在于 UNIQUE INDEX 在数据写入时额外检查唯一性，确保不存在重复值（NULL 除外）。

**复合 UNIQUE 约束中有 NULL 怎么处理？**

在复合唯一约束中，只要组合中有任意一列是 NULL，整个组合就不与其他任何行冲突（视为不相等），可以存在多个这样的行。

---

## 注意事项

- 在高并发写入场景中，UNIQUE 约束的检查是在事务内完成的，不同事务间有短暂的并发窗口。对于极高并发的写入（如秒杀），UNIQUE 约束仍然可靠，但需要正确处理 `ERROR 1062` 重复键错误。
- 不要为所有字段都加 UNIQUE 约束——多余的唯一索引会增加 INSERT/UPDATE/DELETE 的开销。

---

## 总结

UNIQUE 约束保证列或列组合的值在表中唯一（NULL 值例外，多个 NULL 不算重复）。一张表可以有多个 UNIQUE 约束，可以是单列或复合。与 PRIMARY KEY 的核心区别是：允许 NULL、每表可以多个、是二级索引（非聚簇）。遇到唯一键冲突时，可以用 `INSERT IGNORE` 或 `ON DUPLICATE KEY UPDATE` 处理。
