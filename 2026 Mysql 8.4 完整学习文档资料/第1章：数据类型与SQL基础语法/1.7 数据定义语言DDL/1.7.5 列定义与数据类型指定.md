# 列定义与数据类型指定

在 `CREATE TABLE` 或 `ALTER TABLE` 中，每一列的定义包含列名、数据类型、约束修饰符和列注释。合理的列定义是表设计质量的基础，类型选择不当会导致存储浪费或数据精度问题。

---

## 列定义完整语法

```sql
col_name data_type
    [NOT NULL | NULL]
    [DEFAULT {literal | expr}]
    [VISIBLE | INVISIBLE]
    [AUTO_INCREMENT]
    [UNIQUE [KEY]]
    [PRIMARY KEY]
    [COMMENT 'string']
    [COLLATE collation_name]
    [GENERATED ALWAYS AS (expr) [VIRTUAL | STORED]]
```

---

## 数据类型选择原则

| 数据特征 | 推荐类型 | 说明 |
|---------|---------|------|
| 整数 ID（小范围）| INT UNSIGNED | 支持 42 亿，大多数场景够用 |
| 整数 ID（大范围/雪花算法）| BIGINT UNSIGNED | 支持 1.8×10^19 |
| 布尔值 | TINYINT UNSIGNED | 0/1，1 字节 |
| 金融金额 | DECIMAL(M, D) | 精确计算，不用浮点 |
| 科学计数/统计 | DOUBLE | 精度要求不高的数值 |
| 短字符串（固定长度）| CHAR(M) | 如国家代码、MD5 哈希 |
| 短字符串（变长）| VARCHAR(M) | 用户名、邮箱、标题 |
| 长文本 | TEXT | 文章内容、描述 |
| 日期 | DATE | 只需年月日 |
| 日期时间 | DATETIME | 通用日期时间 |
| 二进制数据 | VARBINARY / BLOB | 加密数据、文件内容 |
| 枚举值 | ENUM | 固定几个选项，如状态 |
| JSON | JSON | 结构不固定的扩展属性 |

## 完整列定义示例

```sql
CREATE TABLE products (
    -- 整数主键（自增）
    id              INT UNSIGNED NOT NULL AUTO_INCREMENT       COMMENT '商品ID',
    
    -- 字符串类型
    sku             CHAR(20) NOT NULL                          COMMENT '商品编码（固定格式）',
    name            VARCHAR(200) NOT NULL                      COMMENT '商品名称',
    description     TEXT                                       COMMENT '商品描述',
    
    -- 数值类型
    price           DECIMAL(10, 2) NOT NULL DEFAULT 0.00       COMMENT '售价（元）',
    cost_price      DECIMAL(10, 2) NOT NULL DEFAULT 0.00       COMMENT '成本价（元）',
    weight_g        SMALLINT UNSIGNED NOT NULL DEFAULT 0       COMMENT '重量（克）',
    
    -- 枚举类型
    status          ENUM('active', 'inactive', 'deleted') NOT NULL DEFAULT 'active' COMMENT '商品状态',
    
    -- 布尔类型（TINYINT 模拟）
    is_featured     TINYINT UNSIGNED NOT NULL DEFAULT 0        COMMENT '是否推荐商品：0否1是',
    
    -- JSON 类型（扩展属性）
    attributes      JSON                                       COMMENT '商品属性（颜色、尺码等）',
    
    -- 日期时间
    on_sale_at      DATETIME                                   COMMENT '上架时间',
    off_sale_at     DATETIME                                   COMMENT '下架时间',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    
    -- 生成列（虚拟列，计算利润率）
    profit_rate     DECIMAL(5, 4) AS (
        CASE WHEN cost_price > 0 THEN (price - cost_price) / cost_price ELSE NULL END
    ) VIRTUAL                                                  COMMENT '利润率（虚拟列）',
    
    PRIMARY KEY (id),
    UNIQUE KEY uk_sku (sku),
    INDEX idx_status_created (status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品表';
```

## 不可见列（INVISIBLE，MySQL 8.0.23+）

```sql
-- INVISIBLE 列不出现在 SELECT * 的结果中，但可以显式指定
CREATE TABLE users (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    username    VARCHAR(50) NOT NULL,
    password    VARCHAR(255) NOT NULL INVISIBLE  COMMENT '密码（不可见列，防止被 SELECT * 意外泄露）',
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- SELECT * 不返回 password
SELECT * FROM users;  -- 只返回 id, username, created_at

-- 显式指定才能看到
SELECT id, username, password FROM users;
```

## 适用场景

列定义时的常见决策点：
- 状态字段用 `TINYINT UNSIGNED`（0/1/2）还是 `ENUM`：固定几个值时 ENUM 更有语义，值可能变多时 TINYINT 更灵活
- 金额字段必须用 `DECIMAL`，禁止使用 FLOAT/DOUBLE
- 创建时间/更新时间使用 `DATETIME DEFAULT CURRENT_TIMESTAMP`，简洁且时区安全

---

## 常见问题

**列定义中的 COMMENT 有长度限制吗？**

有，列注释最长 1024 个字符（MySQL 8.0），表注释最长 2048 个字符。

**生成列（Generated Column）可以更新吗？**

VIRTUAL 生成列不存储实际值，每次读取时计算，不能直接 UPDATE。STORED 生成列存储计算后的值，也不能直接 UPDATE（由引擎自动维护）。

---

## 注意事项

- 列名不要使用 MySQL 保留字（如 `index`、`status`、`order`），如必须使用，需用反引号包裹（``order``），但这会增加 SQL 书写的复杂度。
- 所有字符串列应明确设置 `NOT NULL DEFAULT ''`（空字符串）或 `NOT NULL DEFAULT NULL`，避免字段值语义不清晰（NULL 和空字符串在 MySQL 中有不同的语义）。

---

## 总结

列定义包含列名、数据类型、NULL/NOT NULL、DEFAULT、AUTO_INCREMENT、注释等修饰符。类型选择应精确匹配业务需求：整数用 INT/BIGINT、金额用 DECIMAL、枚举用 ENUM、时间用 DATETIME、扩展属性用 JSON。生成列（VIRTUAL/STORED）可以基于表达式自动计算值。不可见列（INVISIBLE）可以隐藏敏感字段不出现在 `SELECT *` 结果中。
