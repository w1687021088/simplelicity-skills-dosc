# ALTER DATABASE 修改数据库属性

`ALTER DATABASE` 用于修改已有数据库的属性，主要是字符集和排序规则。它是数据库字符集迁移（如从 latin1 迁移到 utf8mb4）的第一步，但需要注意修改数据库属性只影响新建表，已有表需要单独处理。

---

## 语法

```sql
ALTER DATABASE [db_name]
    [CHARACTER SET charset_name]
    [COLLATE collation_name]
    [ENCRYPTION {'Y' | 'N'}]
    [READ ONLY = {DEFAULT | 0 | 1}];  -- MySQL 8.0.22+

-- ALTER SCHEMA 等价于 ALTER DATABASE
ALTER SCHEMA db_name CHARACTER SET utf8mb4;
```

---

## 修改字符集示例

```sql
-- 修改数据库的字符集和排序规则
ALTER DATABASE my_app
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_ai_ci;

-- 只修改排序规则（字符集保持不变）
ALTER DATABASE my_app
    COLLATE utf8mb4_unicode_ci;

-- 验证修改结果
SHOW CREATE DATABASE my_app;
-- 或
SELECT schema_name, default_character_set_name, default_collation_name
FROM information_schema.SCHEMATA WHERE schema_name = 'my_app';
```

---

## 数据库只读模式（MySQL 8.0.22+）

```sql
-- 将数据库设为只读（常用于维护迁移窗口）
ALTER DATABASE my_app READ ONLY = 1;

-- 此时对 my_app 库的 DML 操作会报错：
-- ERROR 1290: The MySQL server is running with the --read-only option
-- 但 SELECT 和 SHOW 仍然可用

-- 解除只读
ALTER DATABASE my_app READ ONLY = 0;
-- 或
ALTER DATABASE my_app READ ONLY = DEFAULT;  -- DEFAULT 表示 0（关闭只读）
```

---

## 完整字符集迁移步骤

`ALTER DATABASE` 只修改数据库的默认字符集，不会改变已有表。完整的字符集迁移需要：

```sql
-- 第一步：修改数据库默认字符集
ALTER DATABASE old_db CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

-- 第二步：查看该库下所有表的字符集（找出需要迁移的表）
SELECT table_name, table_collation
FROM information_schema.TABLES
WHERE table_schema = 'old_db' AND table_collation != 'utf8mb4_0900_ai_ci';

-- 第三步：逐表修改字符集（会重建表数据）
-- 方式 A：只修改元数据，不转换数据（适合内容本身已是 utf8mb4 字节，只是元数据记录错误）
ALTER TABLE t1 DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

-- 方式 B：修改并转换所有字符类型列的数据（适合真正需要字符集转换）
ALTER TABLE t1 CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
-- CONVERT TO 会重建整张表，对大表有性能影响
```

## 适用场景

- **字符集升级**：将老项目的 latin1 或 utf8 数据库升级到 utf8mb4
- **维护窗口**：使用 `READ ONLY = 1` 临时锁定数据库，防止迁移期间有数据写入
- **统一标准**：在多个环境（开发、测试、生产）上统一字符集配置

---

## 常见问题

**ALTER DATABASE 修改字符集后，已有表的字符集会变吗？**

不会，`ALTER DATABASE` 只修改数据库的默认字符集（即新建表时的默认值），已有表的字符集不会改变，需要单独执行 `ALTER TABLE ... CONVERT TO CHARACTER SET` 才能修改已有表。

**可以对系统数据库（mysql、information_schema 等）执行 ALTER DATABASE 吗？**

不能，系统数据库受到保护，不允许修改。

---

## 注意事项

- `ALTER TABLE ... CONVERT TO CHARACTER SET utf8mb4` 会重建整张表，对大表（GB 级别）会持续很长时间，并且持有锁（非 INSTANT DDL），生产环境应在维护窗口或使用 pt-online-schema-change 等工具进行。
- 修改数据库字符集前，需要确认应用层的数据库连接字符集也设置为 `utf8mb4`（`SET NAMES utf8mb4` 或连接参数 `charset=utf8mb4`），否则仍然会乱码。

---

## 总结

`ALTER DATABASE` 主要用于修改数据库的默认字符集和排序规则，以及设置只读模式（MySQL 8.0.22+）。修改字符集只影响新建的表，已有表需要通过 `ALTER TABLE ... CONVERT TO CHARACTER SET` 单独迁移。完整的字符集迁移需要同步修改数据库、所有相关表、应用层连接配置三个层面。
