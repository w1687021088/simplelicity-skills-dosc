# ALTER TABLE ADD COLUMN 添加列

`ALTER TABLE ... ADD COLUMN` 是向已有表添加新列的 DDL 语句。MySQL 8.0 引入了 INSTANT DDL（即时 DDL），部分 ADD COLUMN 操作可以在毫秒级完成，而不需要重建整张表，大幅降低了对生产环境的影响。

---

## 语法

```sql
ALTER TABLE tbl_name
    ADD [COLUMN] col_name col_definition [FIRST | AFTER col_name];

-- 同时添加多列
ALTER TABLE tbl_name
    ADD COLUMN col1 def1 [FIRST | AFTER col],
    ADD COLUMN col2 def2 [FIRST | AFTER col];
```

- `FIRST`：新列成为表的第一列
- `AFTER col_name`：新列添加在指定列之后
- 不指定位置：默认添加为表的最后一列

---

## 基本示例

```sql
-- 在末尾添加列
ALTER TABLE users ADD COLUMN avatar_url VARCHAR(500) COMMENT '头像URL';

-- 在指定列之后添加
ALTER TABLE users ADD COLUMN phone VARCHAR(20) AFTER email;

-- 添加到第一列
ALTER TABLE users ADD COLUMN created_by INT UNSIGNED FIRST;

-- 同时添加多列（推荐合并为一条语句，减少 DDL 次数）
ALTER TABLE products
    ADD COLUMN brand VARCHAR(100) COMMENT '品牌' AFTER name,
    ADD COLUMN category_id INT UNSIGNED COMMENT '分类ID' AFTER brand,
    ADD COLUMN is_deleted TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '软删除标记';

-- 添加带约束的列
ALTER TABLE orders ADD COLUMN delivery_address_id INT UNSIGNED COMMENT '收货地址ID';
ALTER TABLE orders ADD CONSTRAINT fk_orders_address 
    FOREIGN KEY (delivery_address_id) REFERENCES addresses(id);
```

## INSTANT DDL（MySQL 8.0+）

MySQL 8.0 起，某些 `ADD COLUMN` 操作可以使用 INSTANT 算法——只修改数据字典中的元数据，不重建实际的表数据，操作几乎瞬间完成（不受表大小影响）：

```sql
-- 显式指定 ALGORITHM=INSTANT（MySQL 8.0+）
ALTER TABLE large_table
    ADD COLUMN new_col VARCHAR(200) DEFAULT NULL,
    ALGORITHM=INSTANT;

-- 查看操作的算法（INSTANT / INPLACE / COPY）
-- 如果操作不支持 INSTANT，可以改为 INPLACE 或 COPY
ALTER TABLE large_table
    ADD COLUMN new_col2 VARCHAR(100) NOT NULL DEFAULT '',
    ALGORITHM=INPLACE, LOCK=NONE;

-- 支持 INSTANT ADD COLUMN 的条件（MySQL 8.0）：
-- 1. 新列添加在所有列的末尾
-- 2. 表不是 ROW_FORMAT=COMPRESSED 格式
-- 3. 表没有全文索引
-- 4. 不是系统表

-- MySQL 8.4 进一步扩展了 INSTANT DDL 的支持范围
```

## 添加 NOT NULL 列到已有表

```sql
-- 向已有数据的表添加 NOT NULL 列，必须提供 DEFAULT 值
-- 否则在严格模式下报错（现有行无法自动填充值）

-- 错误写法（已有数据时）
ALTER TABLE users ADD COLUMN score TINYINT UNSIGNED NOT NULL;
-- ERROR 1364: Field 'score' doesn't have a default value

-- 正确写法：提供 DEFAULT 值
ALTER TABLE users ADD COLUMN score TINYINT UNSIGNED NOT NULL DEFAULT 0;
-- 成功：现有行的 score 自动填为 0

-- 添加后如果需要更新特定行的值
UPDATE users SET score = 100 WHERE id IN (1, 2, 3);
```

## 查看 INSTANT 操作的 DDL 信息

```sql
-- 查看最近的 DDL 操作信息（MySQL 8.0+）
SELECT * FROM performance_schema.events_statements_history
WHERE sql_text LIKE '%ALTER TABLE%' ORDER BY timer_start DESC LIMIT 5;

-- information_schema.INNODB_TABLES 查看表的行格式
SELECT name, row_format, instant_cols
FROM information_schema.INNODB_TABLES
WHERE name LIKE 'mydb/%';
-- instant_cols: 使用 INSTANT 添加的列数量（这些列有特殊的存储处理）
```

## 适用场景

- **新功能上线**：为现有表添加新业务字段
- **扩展属性**：添加标记字段（软删除标记、版本号等）
- **数据迁移过渡期**：先添加新列，再逐步迁移数据

---

## 常见问题

**大表添加列需要多长时间？**

如果支持 INSTANT 算法（MySQL 8.0+，新列在末尾，有 DEFAULT 值），添加列只修改元数据，时间与表大小无关，通常在毫秒级完成。如果不支持 INSTANT（如在列中间插入），需要使用 INPLACE 或 COPY 算法重建表，时间与表数据量成正比，几十 GB 的表可能需要数小时。

**FIRST 和 AFTER 的位置会影响物理存储顺序吗？**

在使用 INSTANT 算法添加的列，物理存储上新列始终在行的末尾（不管声明的 FIRST 还是 AFTER），逻辑顺序（查询返回的列顺序）按 FIRST/AFTER 指定。这个细节在存储层面有影响（涉及行格式），但对查询没有影响。

---

## 注意事项

- 生产环境对大表执行不支持 INSTANT 的 DDL，应使用 pt-online-schema-change 或 gh-ost 等工具，以避免长时间锁表。
- 一次 ALTER TABLE 合并多个 ADD COLUMN 操作（而不是分多次 ALTER），可以减少总体 DDL 开销（特别是需要重建表时只重建一次）。

---

## 总结

`ALTER TABLE ADD COLUMN` 向已有表添加列，默认加在末尾，可以用 FIRST/AFTER 指定位置。MySQL 8.0+ 的 INSTANT DDL 算法让向表末尾添加有 DEFAULT 值的列几乎瞬间完成，不受表大小影响。向已有数据的表添加 NOT NULL 列必须提供 DEFAULT 值。大表的非 INSTANT DDL 操作应使用在线 Schema 变更工具。
