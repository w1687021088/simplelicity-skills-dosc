# CREATE TABLE ... SELECT 复制表数据

`CREATE TABLE ... SELECT` 在创建新表的同时将查询结果作为初始数据写入，可以快速创建一张包含数据的表。它与 `CREATE TABLE ... LIKE` 的核心区别是：SELECT 方式不复制索引和约束，但会复制数据。

---

## 语法

```sql
CREATE [TEMPORARY] TABLE [IF NOT EXISTS] new_tbl_name
    [(col_defs)]           -- 可选：覆盖列定义
    [table_options]        -- 可选：ENGINE、CHARSET 等
    SELECT select_statement;
```

---

## 基本示例

```sql
-- 从已有表创建并复制全部数据
CREATE TABLE orders_backup AS SELECT * FROM orders;
-- 等价写法：
CREATE TABLE orders_backup SELECT * FROM orders;

-- 只复制部分列
CREATE TABLE orders_summary
SELECT order_id, user_id, amount, status, created_at FROM orders;

-- 带 WHERE 条件，只复制部分数据
CREATE TABLE orders_2025
SELECT * FROM orders WHERE YEAR(created_at) = 2025;

-- 复制聚合查询结果
CREATE TABLE user_stats AS
SELECT user_id, 
       COUNT(*) AS order_count,
       SUM(amount) AS total_amount,
       MIN(created_at) AS first_order_at,
       MAX(created_at) AS last_order_at
FROM orders
GROUP BY user_id;

-- 从多表 JOIN 创建
CREATE TABLE order_details_view AS
SELECT o.id AS order_id, u.username, o.amount, o.status, o.created_at
FROM orders o JOIN users u ON o.user_id = u.id
WHERE o.status = 1;
```

## 列定义的继承与自定义

```sql
-- SELECT 方式自动推断列类型
CREATE TABLE temp_data SELECT id, username, email FROM users;
-- id 继承 INT UNSIGNED，username 继承 VARCHAR(50)，email 继承 VARCHAR(200)
-- 但是：NOT NULL 约束、DEFAULT 值、AUTO_INCREMENT 不会被继承
-- 主键、唯一索引、普通索引也不会被继承

-- 通过在括号内定义列来覆盖推断的列属性
CREATE TABLE orders_archive (
    id          BIGINT UNSIGNED NOT NULL PRIMARY KEY,  -- 手动指定主键
    user_id     INT UNSIGNED NOT NULL,
    amount      DECIMAL(12, 2) NOT NULL DEFAULT 0.00,
    archived_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,  -- 额外添加归档时间
    INDEX idx_user_id (user_id)  -- 手动添加索引
)
SELECT id, user_id, amount FROM orders WHERE YEAR(created_at) < 2025;
-- 列定义中的列和 SELECT 结果列按顺序或名称匹配
-- archived_at 是新增列，不来自 SELECT，使用 DEFAULT
```

## 与 LIKE + INSERT 的对比

| 特性 | CREATE ... SELECT | CREATE ... LIKE + INSERT |
|------|------------------|------------------------|
| 复制索引约束 | 否（需要手动添加）| 是 |
| 复制外键 | 否 | 否 |
| 是否含数据 | 是 | 需要额外 INSERT |
| 灵活性 | 高（可以过滤、聚合）| 低（只能全量复制）|
| 执行步骤 | 一步完成 | 两步 |

## 注意事项（索引和约束的处理）

```sql
-- CREATE ... SELECT 创建的表没有索引和约束
-- 如果需要，必须事后手动添加

CREATE TABLE active_users AS 
SELECT id, username, email FROM users WHERE status = 'active';

-- 添加主键
ALTER TABLE active_users ADD PRIMARY KEY (id);

-- 添加索引
ALTER TABLE active_users ADD INDEX idx_username (username);

-- 或者结合列定义在创建时指定
CREATE TABLE active_users2 (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    username    VARCHAR(50) NOT NULL,
    email       VARCHAR(200) NOT NULL,
    UNIQUE KEY uk_email (email)
)
SELECT id, username, email FROM users WHERE status = 'active';
```

## 适用场景

- **快速数据快照**：将某个时间点的查询结果保存为快照表
- **汇总/报表表**：将复杂查询的结果持久化为独立表，加速后续查询
- **数据迁移过渡**：将关联查询的结果组合为新的宽表
- **临时分析表**：创建临时表存储中间分析结果

## 常见问题

**CREATE ... SELECT 中，源表和新表的字符集是否一致？**

新表的字符集默认继承数据库级别的字符集（不是源表的字符集），如果需要指定，在建表语句中添加 `DEFAULT CHARSET=utf8mb4`。

**CREATE ... SELECT 在事务中如何工作？**

在 MySQL 中，CREATE TABLE 是 DDL 语句，会隐式提交当前事务。但 `CREATE ... SELECT` 稍有特殊：MySQL 对 DDL 部分（建表）和 DML 部分（SELECT + INSERT 数据）分别处理，在某些情况下复制（Replication）行为需要注意。

---

## 注意事项

- `CREATE TABLE ... SELECT` 不复制 PRIMARY KEY、UNIQUE、INDEX 和外键约束，需要在建表时手动指定（通过括号内的列定义区块）或建表后执行 `ALTER TABLE` 添加。
- 如果源表很大，`SELECT *` 会导致大量数据被读取并写入新表，对磁盘 I/O 有较大影响，应在低峰期执行或限制 WHERE 范围。

---

## 总结

`CREATE TABLE ... SELECT` 同时创建表和写入数据，是最快速的数据复制方式，特别适合基于复杂查询（JOIN、GROUP BY、WHERE 过滤）创建汇总表或快照。但它不复制原表的索引和约束，需要在创建时手动指定列定义和索引，或者建表后用 `ALTER TABLE` 补充。
