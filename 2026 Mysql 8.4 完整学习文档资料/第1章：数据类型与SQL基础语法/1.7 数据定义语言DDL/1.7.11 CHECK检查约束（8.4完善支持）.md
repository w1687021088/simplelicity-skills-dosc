# CHECK 检查约束（8.4 完善支持）

CHECK 约束是 MySQL 8.0.16 正式引入并强制执行的约束类型，用于在列或表级别定义数据必须满足的条件表达式。MySQL 8.4 对 CHECK 约束的支持进一步完善，是生产环境中保证数据质量的有效手段。

---

## 语法

```sql
-- 列级 CHECK（约束表达式中只能引用本列）
col_name data_type CHECK (expr) [NOT ENFORCED]

-- 表级 CHECK（可引用多列，可命名）
[CONSTRAINT ck_name] CHECK (expr) [NOT ENFORCED]
```

`NOT ENFORCED`：定义约束但不实际检查（仅作文档用途，不强制执行）。默认是 ENFORCED（强制执行）。

---

## 创建示例

```sql
-- 单列 CHECK 约束
CREATE TABLE products (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name        VARCHAR(200) NOT NULL,
    price       DECIMAL(10, 2) NOT NULL CHECK (price >= 0),          -- 价格不能为负
    discount    DECIMAL(5, 2) NOT NULL DEFAULT 1.00 
                CHECK (discount > 0 AND discount <= 1),               -- 折扣在 0~1 之间
    stock       INT NOT NULL DEFAULT 0 CHECK (stock >= 0),            -- 库存不能为负
    PRIMARY KEY (id)
);

-- 跨列 CHECK 约束（表级，需要 CONSTRAINT 命名或直接写 CHECK）
CREATE TABLE events (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name        VARCHAR(200) NOT NULL,
    start_at    DATETIME NOT NULL,
    end_at      DATETIME NOT NULL,
    min_age     TINYINT UNSIGNED,
    max_age     TINYINT UNSIGNED,
    PRIMARY KEY (id),
    -- 结束时间必须晚于开始时间
    CONSTRAINT ck_event_time CHECK (end_at > start_at),
    -- 年龄区间合法性
    CONSTRAINT ck_age_range CHECK (
        min_age IS NULL OR max_age IS NULL OR min_age <= max_age
    )
);

-- 使用枚举形式的 CHECK（替代 ENUM 的另一种做法）
CREATE TABLE orders (
    id      INT UNSIGNED NOT NULL AUTO_INCREMENT,
    status  VARCHAR(20) NOT NULL 
            CHECK (status IN ('pending', 'paid', 'shipped', 'completed', 'cancelled')),
    PRIMARY KEY (id)
);
```

## CHECK 约束的强制执行

```sql
-- 违反 CHECK 约束时，INSERT/UPDATE 会报错
INSERT INTO products (name, price, stock) VALUES ('测试商品', -10.00, 100);
-- ERROR 3819 (HY000): Check constraint 'products_chk_1' is violated.

INSERT INTO events (name, start_at, end_at) VALUES ('测试活动', '2026-03-20', '2026-03-15');
-- ERROR 3819 (HY000): Check constraint 'ck_event_time' is violated.

-- 合法数据可以正常插入
INSERT INTO products (name, price, stock) VALUES ('测试商品', 99.00, 100);  -- 成功
```

## 查看与管理 CHECK 约束

```sql
-- 查看表的 CHECK 约束
SELECT constraint_name, check_clause, enforced
FROM information_schema.CHECK_CONSTRAINTS
WHERE constraint_schema = DATABASE();

-- SHOW CREATE TABLE 也会显示 CHECK 约束
SHOW CREATE TABLE products;

-- 添加 CHECK 约束到已有表
ALTER TABLE products ADD CONSTRAINT ck_price_positive CHECK (price > 0);

-- 删除 CHECK 约束
ALTER TABLE products DROP CHECK ck_price_positive;
-- 或
ALTER TABLE products DROP CONSTRAINT ck_price_positive;

-- 临时禁用 CHECK 约束（设为 NOT ENFORCED）
ALTER TABLE products ALTER CHECK ck_price_positive NOT ENFORCED;

-- 重新启用
ALTER TABLE products ALTER CHECK ck_price_positive ENFORCED;
```

## CHECK 约束的表达式限制

CHECK 约束的表达式有以下限制：

```sql
-- 不允许：
-- 1. 引用其他表的列（不支持子查询）
-- 2. 调用不确定的函数（如 RAND(), UUID(), NOW()）
-- 3. 引用 AUTO_INCREMENT 列的值
-- 4. 引用存储过程/函数

-- 允许：
-- 字面量比较：price > 0
-- 逻辑运算：status IN ('a', 'b') AND score BETWEEN 0 AND 100
-- 字符串函数：LENGTH(name) > 0
-- 数学函数：ABS(offset) < 100
-- 列之间的比较：end_date > start_date
-- IS NULL / IS NOT NULL
```

## 与 ENUM 的对比

```sql
-- ENUM 方式（集中存储枚举值）
CREATE TABLE t1 (status ENUM('active', 'inactive') NOT NULL);

-- CHECK IN 方式（更灵活，可随时 ALTER）
CREATE TABLE t2 (status VARCHAR(20) NOT NULL CHECK (status IN ('active', 'inactive')));

-- ENUM 添加新枚举值需要 ALTER TABLE（可能锁表）
ALTER TABLE t1 MODIFY COLUMN status ENUM('active', 'inactive', 'pending');

-- CHECK IN 添加新值只需修改 CHECK 约束（相对更灵活）
ALTER TABLE t2 DROP CHECK t2_chk_1;
ALTER TABLE t2 ADD CONSTRAINT ck_status CHECK (status IN ('active', 'inactive', 'pending'));
```

## 适用场景

- **数值范围验证**：价格 ≥ 0、数量 ≥ 0、评分 1~5、折扣 0~1
- **时间逻辑验证**：结束时间 > 开始时间
- **跨列业务规则**：最低价 ≤ 最高价、最小年龄 ≤ 最大年龄
- **字符串枚举替代**：status 只能取特定几个值（作为 ENUM 的补充）

## 常见问题

**MySQL 8.0.16 之前的 CHECK 约束是怎样的？**

MySQL 8.0.16 之前，CHECK 约束语法被接受但完全不执行（会被解析然后忽略），不起任何约束作用。8.0.16 起正式强制执行，这是一个重要的版本行为变化，升级时需要注意历史 DDL 中已有的 CHECK 约束。

**CHECK 约束和触发器（Trigger）哪个更适合做数据验证？**

CHECK 约束更简单、性能更好，仅在数据层面检查，不需要程序上下文。触发器功能更强（可以访问其他表、调用函数），但执行开销更大。优先使用 CHECK 约束，复杂的跨表验证逻辑才用触发器。

## 注意事项

- 大批量数据导入前，如果数据来源不保证符合 CHECK 约束，可以临时将约束设置为 `NOT ENFORCED`，导入完成并清洗数据后再重新 `ENFORCED`。
- CHECK 约束对 NULL 值的处理：如果表达式的结果是 NULL（因为涉及 NULL 的比较返回 NULL），MySQL 视为约束通过（NOT VIOLATED）。因此 `CHECK (price > 0)` 允许 price 为 NULL，如果要排除 NULL，需要组合：`CHECK (price IS NOT NULL AND price > 0)` 或者列本身就是 NOT NULL。

---

## 总结

CHECK 约束在 MySQL 8.0.16+ 正式强制执行，可以在列级或表级定义数据必须满足的条件表达式，是数据库层面保证数据合法性的有效工具。支持数值范围、逻辑条件、跨列比较等表达式，但不支持子查询和不确定函数。与应用层验证相比，CHECK 约束更靠近数据存储，即使绕过应用层的直接 SQL 操作也会被检查。
