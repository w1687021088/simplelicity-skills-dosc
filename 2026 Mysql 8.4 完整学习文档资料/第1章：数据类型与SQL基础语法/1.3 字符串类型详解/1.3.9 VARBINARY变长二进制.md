## VARBINARY 变长二进制

VARBINARY 是变长二进制字符串类型，对应 VARCHAR 在字符串中的地位。它按实际字节长度存储数据，不做字符集处理，适合存储长度可变的二进制数据，如加密后的密文、数字签名等。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 语法 | `VARBINARY(M)`，M 为最大字节数 |
| 存储空间 | 实际字节数 + 1或2字节长度前缀 |
| 长度前缀 | M ≤ 255 时 1 字节，M > 255 时 2 字节 |
| 最大长度 | 65535 字节（受行最大字节数限制）|
| 尾部填充 | 不填充（与 BINARY 的零字节填充不同）|
| 比较方式 | 按字节值比较，区分大小写 |

---

### BINARY 与 VARBINARY 的对比

| 对比维度 | BINARY(M) | VARBINARY(M) |
|---------|----------|------------|
| 存储方式 | 定长，不足用零字节填充 | 变长，按实际长度存储 |
| 最大字节 | 255 | 65535 |
| 尾部处理 | 填充零字节 | 不填充 |
| 适合内容 | 固定长度二进制 | 变长二进制 |

---

### 语法

```sql
column_name VARBINARY(M)
column_name VARBINARY(M) NOT NULL
```

---

### 创建示例

```sql
-- 存储变长加密数据（加密后长度可能不同）
CREATE TABLE encrypted_data (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id     INT UNSIGNED NOT NULL,
    ciphertext  VARBINARY(512) NOT NULL COMMENT '加密后的密文',
    iv          BINARY(16) NOT NULL COMMENT 'AES 初始化向量，固定16字节',
    PRIMARY KEY (id)
);

-- 存储数字签名（长度可变，如 RSA-2048 签名是 256 字节）
CREATE TABLE document_signatures (
    doc_id      INT UNSIGNED NOT NULL,
    signature   VARBINARY(512) NOT NULL COMMENT 'RSA 数字签名',
    signed_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (doc_id)
);

-- 存储压缩数据（压缩后长度不固定）
CREATE TABLE compressed_content (
    id            INT UNSIGNED NOT NULL AUTO_INCREMENT,
    original_size INT UNSIGNED NOT NULL,
    content       VARBINARY(8000) NOT NULL COMMENT '压缩后的内容',
    PRIMARY KEY (id)
);
```

### 适用场景

- **加密密文**：AES 加密后的数据长度取决于原始数据大小，使用 VARBINARY
- **数字签名**：签名长度相对固定但有时有变化
- **压缩数据**：ZLIB/GZIP 压缩后的二进制内容
- **网络协议数据包**：原始二进制协议数据
- **二进制凭证**：OAuth token 的原始字节形式

---

### 常见问题

**VARBINARY 和 BLOB 有什么区别？**

两者都是变长二进制类型，主要区别在容量和存储位置：VARBINARY 最大 65535 字节，存储在行内；BLOB 最大 65535 字节，可能离行存储。对于较短的二进制数据（几百字节），VARBINARY 的行内存储效率更高；内容较大时，BLOB 系列类型更合适。

---

### 注意事项

- VARBINARY 在比较时按字节值比较（区分大小写），行为与 BINARY 相同，但不填充尾部零字节。
- 不要用 VARBINARY 存储文本内容（用 VARCHAR），VARBINARY 不做任何字符集处理，读出的是原始字节。

---

### 总结

VARBINARY(M) 是变长二进制类型，按实际字节数加长度前缀存储，最大 65535 字节。适合存储加密密文、数字签名等长度可变的二进制数据。与 BINARY 的区别是变长存储且不填充尾部零字节；与 BLOB 的区别是行内存储且有明确的字节上限声明。
