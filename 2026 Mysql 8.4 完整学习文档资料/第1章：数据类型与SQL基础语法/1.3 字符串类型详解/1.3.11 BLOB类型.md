## BLOB 类型

BLOB（Binary Large Object）是存储二进制大数据的标准类型，最大支持 65535 字节（64KB）。它是 BLOB 家族中使用最广泛的成员，与 TEXT 对应，区别在于 BLOB 存储二进制字节，不做任何字符集处理。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 最大存储 | 65535 字节（64KB - 1字节）|
| 存储方式 | 变长，2 字节长度前缀 |
| 字符集 | binary（无字符集）|
| 排序/比较 | 按字节值比较，大小写敏感 |
| DEFAULT 值 | 不支持 |
| 完整索引 | 不支持，只能前缀索引 |

---

### BLOB 与 TEXT 的区别

| 对比维度 | BLOB | TEXT |
|---------|------|------|
| 存储内容 | 二进制字节 | 字符串（有字符集）|
| 字符集 | 无（binary）| 遵循列/表字符集 |
| 大小写比较 | 敏感（字节值）| 取决于排序规则 |
| 容量 | 65535 字节 | 65535 字节 |
| 使用场景 | 图片、文件、加密数据 | 文章、描述等文本 |

---

### 语法

```sql
column_name BLOB
column_name BLOB NOT NULL
```

### 创建示例

```sql
-- 存储小图片缩略图
CREATE TABLE thumbnails (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    product_id  INT UNSIGNED NOT NULL,
    image_data  BLOB NOT NULL COMMENT '图片二进制数据，最大 64KB',
    mime_type   VARCHAR(50) NOT NULL DEFAULT 'image/jpeg',
    width       SMALLINT UNSIGNED,
    height      SMALLINT UNSIGNED,
    PRIMARY KEY (id),
    INDEX idx_product (product_id)
);

-- 存储证书/密钥文件
CREATE TABLE certificates (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name        VARCHAR(200) NOT NULL,
    cert_data   BLOB NOT NULL COMMENT 'DER 格式证书，通常 < 4KB',
    cert_type   CHAR(10) NOT NULL COMMENT 'X509, PEM 等',
    expires_at  DATE,
    PRIMARY KEY (id)
);
```

### 是否应该在数据库中存储文件？

这是数据库设计中的经典争议，核心权衡如下：

| 方案 | 优点 | 缺点 |
|------|------|------|
| 数据库存 BLOB | 数据和元数据一体化，备份完整 | 数据库体积大，查询效率低，备份慢 |
| 文件系统存储，数据库记路径 | 数据库轻量，文件读取高效 | 文件和数据库数据可能不一致 |
| 对象存储（S3/OSS），数据库记URL | 可扩展，CDN 分发，高并发读取 | 需要外部存储服务 |

**主流实践**：文件存对象存储（S3/阿里云 OSS 等），数据库只记录 URL 和元数据。BLOB 存储仅用于极小文件或需要绝对一致性的场景（如证书、签名数据）。

---

### 适用场景

- **小型二进制文件**：数字证书、密钥文件（通常 < 4KB）
- **缩略图**：如果确定尺寸很小且不需要 CDN（内部系统）
- **二进制会话 token**：原始字节形式的 token
- **协议数据快照**：某些需要原样保存的网络协议数据

### 常见问题

**能对 BLOB 列建全文索引吗？**

不能。全文索引（FULLTEXT）只支持字符类型（CHAR、VARCHAR、TEXT），不支持 BLOB 类型。

**查询 BLOB 时能否只检索长度而不返回内容？**

可以，使用 `LENGTH()` 函数：

```sql
SELECT id, product_id, LENGTH(image_data) AS image_size FROM thumbnails;
-- 只返回图片大小（字节数），不传输图片内容
```

---

### 注意事项

- 查询中使用 `SELECT *` 会将 BLOB 内容完整传输，在列表查询中应明确排除 BLOB 列，只在需要时单独查询。
- BLOB 列在 GROUP BY、ORDER BY 中使用会消耗大量内存（临时表按最大长度分配），应避免对 BLOB 列排序或分组。
- 将大量 BLOB 数据存入 MySQL 会导致 ibdata 或独立表空间快速增大，影响备份和维护效率。

---

### 总结

BLOB 类型最大存储 64KB 二进制数据，适合存储证书、小图片、密钥等小型二进制文件。与 TEXT 的区别是不做字符集处理，按原始字节存储和比较。在现代系统设计中，大文件存储优先选择对象存储+数据库记 URL 的方案，BLOB 更适合小且需要与数据库事务保持一致的二进制数据。
