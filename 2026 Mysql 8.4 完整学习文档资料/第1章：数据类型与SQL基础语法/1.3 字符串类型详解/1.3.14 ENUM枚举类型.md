## ENUM 枚举类型

ENUM 是 MySQL 中的枚举类型，允许列只存储预定义集合中的某一个值。它在存储时将字符串枚举值映射为内部整数（1字节或2字节），兼顾了可读性和存储效率。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 最大枚举成员数 | 65535 个 |
| 内部存储 | 枚举值的整数下标（1~N），1字节（≤255个值）或2字节 |
| NULL 存储 | 存为 NULL（0 表示"空枚举"） |
| 比较方式 | 按枚举下标（数字顺序），非字母顺序 |
| 成员长度 | 每个枚举值最大 M 个字符 |

---

### 语法

```sql
column_name ENUM('值1', '值2', '值3', ...)
column_name ENUM('active', 'inactive', 'deleted') NOT NULL DEFAULT 'active'
```

---

### 创建示例

```sql
-- 用户状态
CREATE TABLE users (
    id      INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name    VARCHAR(100) NOT NULL,
    status  ENUM('active', 'inactive', 'banned', 'deleted') NOT NULL DEFAULT 'active',
    gender  ENUM('M', 'F', 'other') COMMENT '性别',
    PRIMARY KEY (id)
);

-- 订单状态
CREATE TABLE orders (
    id      BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    status  ENUM('pending', 'paid', 'shipped', 'delivered', 'cancelled', 'refunded')
            NOT NULL DEFAULT 'pending',
    PRIMARY KEY (id)
);

-- 日志级别
CREATE TABLE system_logs (
    id      BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    level   ENUM('DEBUG', 'INFO', 'WARN', 'ERROR', 'FATAL') NOT NULL DEFAULT 'INFO',
    message TEXT NOT NULL,
    PRIMARY KEY (id)
);

-- 插入和查询
INSERT INTO users (name, status, gender) VALUES ('Alice', 'active', 'F');
INSERT INTO orders (status) VALUES ('pending');

SELECT * FROM users WHERE status = 'active';
SELECT * FROM orders WHERE status IN ('pending', 'paid');

-- 按枚举定义顺序排序（不是字母顺序）
SELECT * FROM orders ORDER BY status;
-- 排序顺序：pending(1), paid(2), shipped(3), delivered(4), cancelled(5), refunded(6)
```

---

### 内部存储机制

ENUM 在内部将每个枚举值映射为整数：

```sql
-- 查看枚举值对应的整数
SELECT status + 0 AS status_num, status FROM orders LIMIT 5;
-- pending = 1, paid = 2, shipped = 3, delivered = 4, cancelled = 5, refunded = 6

-- 用整数插入（不推荐，可读性差）
INSERT INTO orders (status) VALUES (2);  -- 等同于插入 'paid'
```

---

### 排序行为

ENUM 排序按枚举值定义的顺序（内部整数顺序），不是字母顺序：

```sql
-- 枚举定义顺序：'pending', 'paid', 'shipped', 'delivered', 'cancelled', 'refunded'
SELECT status FROM orders ORDER BY status ASC;
-- 输出顺序：pending, paid, shipped, delivered, cancelled, refunded

-- 如果需要字母排序，转为字符串
SELECT status FROM orders ORDER BY CAST(status AS CHAR) ASC;
```

---

### 优缺点

| 维度 | ENUM | VARCHAR（替代方案）|
|------|------|----------------|
| 存储效率 | 高（1~2字节）| 低（字节数 = 字符串长度）|
| 可读性 | 好（显示字符串）| 好 |
| 枚举值变更 | 需要 ALTER TABLE（DDL）| 只需更新代码 |
| 添加新值 | ALTER TABLE，可能锁表 | 无需数据库变更 |
| 跨数据库兼容性 | MySQL 特有（部分兼容）| 标准 SQL |
| 误操作防护 | 好（只能存预定义值）| 差（需要应用层约束）|

---

### 适用场景

- **状态字段**：订单状态（pending/paid/shipped）、用户状态（active/banned）等，值域固定且在业务生命周期中不经常变化
- **类型字段**：性别（M/F/other）、支付方式（alipay/wechat/card）等
- **日志级别**：DEBUG/INFO/WARN/ERROR/FATAL 等标准枚举
- **布尔扩展**：当需要 yes/no/maybe 这样的三值枚举时

---

### 常见问题

**ENUM 新增枚举值需要 ALTER TABLE，会锁表吗？**

在 MySQL 8.0 中，对 ENUM 列在末尾追加新值（如 `ALTER TABLE t MODIFY status ENUM(..., '新值')`）是即时操作（INSTANT DDL），不会重建表，也不会锁表。但修改已有枚举值的位置或删除枚举值则需要重建表，会有锁表影响。

**插入了不在 ENUM 定义中的值会怎样？**

在严格 SQL 模式下会报错：`ERROR 1265: Data truncated for column`。在非严格模式下，会存储为空字符串（`''`），内部值为 0。

**ENUM 的 NULL 和空字符串（0）有什么区别？**

`NULL` 表示列没有赋值；空字符串（内部整数值 0）表示枚举集合之外的无效值（仅在非严格模式下会出现）。查询中需要分别处理：`WHERE col IS NULL` 和 `WHERE col = ''`。

---

### 注意事项

- ENUM 枚举值的变更（特别是修改已有值的顺序或删除值）是危险操作，会影响存量数据中存储的整数映射。不要随意更改枚举值的定义顺序。
- 在高度需要跨库兼容的系统中，ENUM 是 MySQL 特有特性，迁移到 PostgreSQL 等其他数据库时需要转换。
- 枚举值的业务含义应当在代码和文档中明确定义，不要让"字面值"成为唯一的含义来源——数据库迁移时可能需要理解每个枚举值的业务语义。

---

### 总结

ENUM 是 MySQL 的枚举类型，将预定义字符串集合映射为 1~2 字节整数存储，兼顾可读性和存储效率。适合存储值域固定、变化不频繁的状态/类型字段。主要注意点：ENUM 的排序是按定义顺序而非字母顺序；在 MySQL 8.0 中，末尾追加枚举值是即时操作，不锁表；修改已有枚举值位置或删除值则会重建表。
