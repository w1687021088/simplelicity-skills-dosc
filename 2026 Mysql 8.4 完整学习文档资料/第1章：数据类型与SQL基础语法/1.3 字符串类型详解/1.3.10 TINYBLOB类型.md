## TINYBLOB 类型

TINYBLOB 是 BLOB 家族中容量最小的类型，最大存储 255 字节的二进制数据。它与 TINYTEXT 对应，但存储的是原始字节而非字符，不受字符集影响。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 最大存储 | 255 字节 |
| 存储方式 | 变长，1 字节长度前缀 |
| 字符集 | 无（binary，按原始字节处理）|
| DEFAULT 值 | 不支持 |
| 完整索引 | 不支持，只能前缀索引 |

---

### BLOB 家族对比

| 类型 | 最大字节 | 长度前缀 |
|------|---------|--------|
| TINYBLOB | 255 B | 1 字节 |
| BLOB | 64 KB | 2 字节 |
| MEDIUMBLOB | 16 MB | 3 字节 |
| LONGBLOB | 4 GB | 4 字节 |

---

### 语法与示例

```sql
column_name TINYBLOB
column_name TINYBLOB NOT NULL
```

```sql
-- 存储小图标数据（favicon，通常几百字节）
CREATE TABLE site_favicons (
    site_id     INT UNSIGNED NOT NULL PRIMARY KEY,
    favicon     TINYBLOB COMMENT '网站图标，小于 255 字节'
);

-- 存储小缩略图（注意：255字节非常小，仅适合极小的图片）
-- 实际上，即使是最小的缩略图也往往超过 255 字节
-- 所以 TINYBLOB 在实践中很少用于图片存储
```

---

### 适用场景

TINYBLOB 适用场景极其有限，原因是 255 字节的容量对于大多数二进制数据都太小了。主要场景：
- 存储极小的图标或标志（< 255 字节，实际极少）
- 理解数据库设计时的类型完整性（知道它存在即可）

实践中，如果需要存储二进制数据，通常会选用 `BLOB`（64KB）或 `VARBINARY`（可指定精确上限）。

---

### 常见问题

**TINYBLOB 和 VARBINARY(255) 有什么区别？**

两者容量相同（最多 255 字节），主要区别是：VARBINARY 支持行内存储，对于短内容效率更高；TINYBLOB 有可能离行存储；VARBINARY 可以创建完整列索引（对于短列），TINYBLOB 只能前缀索引；VARBINARY 更灵活，实践中更推荐。

---

### 注意事项

- TINYBLOB 和 TEXT 家族一样，不支持 DEFAULT 值。
- 对于需要索引的二进制列（如哈希值查询），使用 `BINARY(M)` 或 `VARBINARY(M)` 而不是 TINYBLOB，前者支持完整索引。

---

### 总结

TINYBLOB 最大 255 字节，是 BLOB 家族中容量最小的类型。由于容量极小且不支持 DEFAULT 和完整索引，实践中很少主动使用。遇到需要存储几十字节到几百字节的二进制数据时，`VARBINARY` 是更合适的选择。
