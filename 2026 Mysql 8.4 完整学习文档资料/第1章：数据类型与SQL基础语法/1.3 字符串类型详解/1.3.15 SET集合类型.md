## SET 集合类型

SET 是 MySQL 中允许列存储多个预定义值组合的类型。与 ENUM 每次只能存一个值不同，SET 列可以同时存零个或多个预定义成员，在内部用位图（bitmask）表示。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 最大成员数 | 64 个 |
| 内部存储 | 位图（bitmask），1~8 字节 |
| 存储字节数 | 成员数 1~8 用 1字节，9~16 用 2字节，以此类推（每 8 个成员加 1 字节）|
| 显示格式 | 逗号分隔的字符串，如 `'read,write,delete'` |

---

### SET 的内部位图

每个 SET 成员对应一个二进制位：

| 成员 | 位值 |
|------|-----|
| 第 1 个成员 | 1（2^0）|
| 第 2 个成员 | 2（2^1）|
| 第 3 个成员 | 4（2^2）|
| 第 4 个成员 | 8（2^3）|
| ... | ... |

多个成员的组合就是各位值之和：`read(1) + write(2) = 3` 表示拥有 read 和 write。

---

### 语法

```sql
column_name SET('值1', '值2', '值3', ...)
column_name SET('read', 'write', 'delete', 'admin') NOT NULL DEFAULT ''
```

---

### 创建示例

```sql
-- 用户权限标志
CREATE TABLE user_permissions (
    user_id     INT UNSIGNED NOT NULL PRIMARY KEY,
    permissions SET('read', 'write', 'delete', 'admin', 'export') NOT NULL DEFAULT 'read'
);

-- 用户兴趣标签
CREATE TABLE user_profiles (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    username    VARCHAR(50) NOT NULL,
    interests   SET('sports', 'music', 'tech', 'travel', 'food', 'fashion') NOT NULL DEFAULT '',
    PRIMARY KEY (id)
);

-- 工作日设置
CREATE TABLE schedules (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name        VARCHAR(100) NOT NULL,
    work_days   SET('Mon', 'Tue', 'Wed', 'Thu', 'Fri', 'Sat', 'Sun') NOT NULL DEFAULT 'Mon,Tue,Wed,Thu,Fri',
    PRIMARY KEY (id)
);

-- 插入
INSERT INTO user_permissions VALUES (1, 'read,write');
INSERT INTO user_permissions VALUES (2, 'read,write,delete,admin');
INSERT INTO user_profiles (username, interests) VALUES ('Alice', 'sports,music,tech');
INSERT INTO schedules (name, work_days) VALUES ('标准工作制', 'Mon,Tue,Wed,Thu,Fri');
```

### 查询 SET 列

```sql
-- 精确匹配（完整集合值）
SELECT * FROM user_permissions WHERE permissions = 'read,write';

-- 查找包含某个成员（使用 FIND_IN_SET）
SELECT * FROM user_permissions WHERE FIND_IN_SET('admin', permissions) > 0;

-- 使用 & 位运算查询（更快）
-- 'admin' 是第 4 个成员，位值 = 8
SELECT * FROM user_permissions WHERE permissions & 8;  -- 包含 admin

-- 查找包含 read 且包含 write 的用户（位运算）
SELECT * FROM user_permissions WHERE (permissions & 1) AND (permissions & 2);

-- 查找所有拥有 write 权限的用户
SELECT * FROM user_permissions WHERE FIND_IN_SET('write', permissions);

-- 添加一个权限（字符串追加方式，不推荐）
UPDATE user_permissions SET permissions = CONCAT(permissions, ',export') WHERE user_id = 1;

-- 推荐：用位运算添加权限
UPDATE user_permissions SET permissions = permissions | 16 WHERE user_id = 1;  -- 添加 export(16)

-- 移除一个权限（位运算 AND NOT）
UPDATE user_permissions SET permissions = permissions & ~8 WHERE user_id = 2;  -- 移除 admin(8)
```

###  SET 与 ENUM 的对比

| 对比维度 | ENUM | SET |
|---------|------|-----|
| 存储值 | 只能存一个值 | 可以存多个值的组合 |
| 最大成员数 | 65535 | 64 |
| 内部存储 | 整数下标 | 位图 |
| 典型场景 | 单选状态（订单状态）| 多选标签（权限、兴趣）|

---

### SET 的局限性

- 最多 64 个成员，超过就无法使用 SET
- 修改 SET 成员定义同样需要 ALTER TABLE（类似 ENUM）
- FIND_IN_SET 函数不能使用索引，大量数据时查询较慢
- 与 ENUM 一样，跨数据库移植性较差

---

### 适用场景

- **权限标志**：用户具有多种权限组合的场景（但成员不超过 64 个）
- **多选标签**：兴趣爱好、喜好类别等多选字段
- **工作日/排班**：周一到周日的组合
- **功能开关**：多个独立开关标志（类似位标志/feature flag）

---

### 常见问题

**SET 和用中间表存多对多关系哪个更好？**

成员数不超过 64 且变化不频繁时，SET 更简单轻量；成员数多、需要单独管理每个标签（如标签有名称、描述等额外属性），或者需要按标签高效查询统计时，中间表（多对多关联表）更合适。大多数标签系统推荐中间表。

**SET 能建索引吗？**

可以创建普通索引，但对 SET 列的 FIND_IN_SET 查询不能用到这个索引。如果需要高效地按某个成员查询，考虑将 SET 转换为关联表或使用位运算。

**SET 的成员顺序会影响存储值吗？**

会。SET 成员的位值取决于它们在定义中的位置，修改成员顺序会改变位值映射，导致存量数据中的位图含义发生变化。修改 SET 定义时要格外谨慎。

---

### 注意事项

- SET 列存入多个成员时，顺序不影响存储结果（'read,write' 和 'write,read' 存储相同，检索时按定义顺序返回 'read,write'）。
- INSERT 或 UPDATE 时，如果提供的成员中有未在 SET 定义中的值，严格模式下会报错，非严格模式下该未定义值会被忽略。
- SET 类型的成员数限制 64 个是硬性限制，超出后必须改用关联表或 JSON 方案。

---

### 总结

SET 是 MySQL 特有的集合类型，允许列存储预定义成员中零个或多个值的组合，内部使用位图存储，最多 64 个成员。它适合权限标志、多选兴趣标签等多值组合场景。查询时 FIND_IN_SET 函数或位运算是常用方式。当成员数超过 64 或需要复杂的标签管理时，中间关联表是更好的设计选择。
