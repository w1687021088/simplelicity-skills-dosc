## MEDIUMBLOB 类型

MEDIUMBLOB 最大支持 16MB 的二进制数据存储，是 BLOB 家族中介于 BLOB（64KB）和 LONGBLOB（4GB）之间的类型，适合存储中等大小的图片、音频片段等二进制内容。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 最大存储 | 16777215 字节（16MB - 1字节）|
| 存储方式 | 变长，3 字节长度前缀 |
| 字符集 | binary（无字符集）|
| DEFAULT 值 | 不支持 |
| 完整索引 | 不支持 |

---

### 语法与示例

```sql
column_name MEDIUMBLOB
column_name MEDIUMBLOB NOT NULL
```

```sql
-- 存储压缩后的文件数据（最大 16MB）
CREATE TABLE file_storage (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    filename    VARCHAR(255) NOT NULL,
    content     MEDIUMBLOB NOT NULL COMMENT '文件内容，最大 16MB',
    file_size   INT UNSIGNED NOT NULL COMMENT '原始文件大小（字节）',
    mime_type   VARCHAR(100) NOT NULL,
    uploaded_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id)
);

-- 存储中等大小图片（如网站图片，通常 < 2MB）
CREATE TABLE product_images (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    product_id  INT UNSIGNED NOT NULL,
    image_data  MEDIUMBLOB NOT NULL COMMENT '图片二进制数据',
    PRIMARY KEY (id)
);
```

### 适用场景

- **中等大小图片**：分辨率适中的产品图片、用户头像原图（< 16MB）
- **PDF 文档**：普通 PDF 文件通常在几 MB 以内
- **压缩包**：小型 ZIP/RAR 文件
- **音频片段**：短音频剪辑（< 16MB）

---

### 常见问题

**16MB 限制够用吗？**

对于大多数网站图片（压缩后通常 < 2MB）和普通文档（< 5MB）来说足够。如果需要存储视频文件或高清图片原图，应使用对象存储而不是数据库 BLOB。

**`max_allowed_packet` 对 MEDIUMBLOB 有影响吗？**

有，与 LONGTEXT/LONGBLOB 一样，单次数据包传输受 `max_allowed_packet` 参数限制（默认 64MB）。存储 16MB 数据时，`max_allowed_packet` 必须大于 16MB。

---

### 注意事项

- 将 MB 级别的 MEDIUMBLOB 存入数据库会显著增加 InnoDB 表空间大小，影响备份时间和磁盘 I/O。生产系统中应优先考虑对象存储方案。
- 查询中避免在 SELECT 列表里包含 MEDIUMBLOB 列，每次加载完整图片数据会消耗大量内存和网络带宽。

---

### 总结

MEDIUMBLOB 最大存储 16MB 二进制数据，适合中等大小的图片、PDF 等文件。与 MEDIUMTEXT 对应，区别在于不做字符集处理。现代系统设计中，大于几十 KB 的文件通常存对象存储，数据库只记录元数据和 URL，MEDIUMBLOB 仅在特定场景（强一致性、内网小规模系统）下使用。
