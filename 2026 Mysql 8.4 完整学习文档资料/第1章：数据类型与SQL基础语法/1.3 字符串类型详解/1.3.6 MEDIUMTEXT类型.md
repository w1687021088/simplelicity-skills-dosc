## MEDIUMTEXT 类型

MEDIUMTEXT 是 TEXT 家族中的中等容量类型，最大支持 16MB 的文本存储。它在普通文本（TEXT 的 64KB）和超长文本（LONGTEXT 的 4GB）之间提供了一个合理的中间选项，适合存储长篇文章、HTML 内容、较长的 JSON 数据等。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 最大存储 | 16777215 字节（16MB - 1字节） |
| 最大字符数 | utf8mb4 下约 419 万字符 |
| 存储方式 | 变长，3 字节长度前缀 |
| 行外存储 | 大内容时离行存储 |
| DEFAULT 值 | 不支持 |
| 完整索引 | 不支持，只能前缀索引 |

---

### TEXT 家族容量对比

| 类型 | 最大字节 | 最大字符（utf8mb4）| 长度前缀 |
|------|---------|-----------------|--------|
| TINYTEXT | 255 B | 约 63 | 1 字节 |
| TEXT | 64 KB | 约 16383 | 2 字节 |
| MEDIUMTEXT | 16 MB | 约 419 万 | 3 字节 |
| LONGTEXT | 4 GB | 约 10 亿 | 4 字节 |

---

### 语法

```sql
column_name MEDIUMTEXT
column_name MEDIUMTEXT NOT NULL
column_name MEDIUMTEXT CHARACTER SET utf8mb4
```

### 创建示例

```sql
-- 长篇文章/文档内容
CREATE TABLE documents (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    title       VARCHAR(500) NOT NULL,
    content     MEDIUMTEXT COMMENT '文档正文，最大 16MB',
    doc_type    VARCHAR(50) NOT NULL DEFAULT 'article',
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    FULLTEXT INDEX ft_content (content)  -- 全文索引支持文本搜索
);

-- HTML 页面内容缓存
CREATE TABLE page_cache (
    page_id     VARCHAR(200) NOT NULL PRIMARY KEY,
    html_content MEDIUMTEXT COMMENT '渲染后的 HTML，可能较大',
    cached_at   DATETIME NOT NULL
);

-- 存储较大的 JSON 配置（非结构化配置数据）
CREATE TABLE app_configs (
    config_name VARCHAR(100) NOT NULL PRIMARY KEY,
    config_json MEDIUMTEXT COMMENT '较大的 JSON 配置内容'
);
```

### 适用场景

- **长篇小说、技术手册**：单篇内容可能超过 64KB 时，TEXT 不够，使用 MEDIUMTEXT
- **HTML 富文本内容**：包含大量 HTML 标签的富文本，内容可能较大
- **代码片段库**：存储完整的代码文件或较长的代码段
- **日志批量内容**：批量写入的日志文件片段
- **序列化对象**：较大的序列化数据（如复杂的业务对象序列化后的字符串）

---

### 常见问题

**什么时候应该用 MEDIUMTEXT 而不是 TEXT？**

当内容预计会超过 64KB 时。实际操作中，如果不确定内容大小，可以先用 MEDIUMTEXT 留有余量，因为从大类型改为小类型的风险（需要确认数据不超限）远大于用稍大类型的轻微存储浪费。

**MEDIUMTEXT 存储 JSON 数据和直接用 JSON 类型有什么区别？**

JSON 类型在存储时会验证 JSON 格式的合法性，提供 JSON 路径查询函数（JSON_EXTRACT 等）；MEDIUMTEXT 只是把 JSON 当作普通文本存储，不做格式验证，也不能用 JSON 函数直接操作。对于需要在数据库层面查询 JSON 内容的场景，应使用 JSON 类型；如果只是存储，MEDIUMTEXT 更灵活。

---

### 注意事项

- MEDIUMTEXT 的数据在读取时如果内容很大，会增加网络传输和内存使用。如果查询只需要文本的部分内容，应用 `SUBSTRING()` 或 `LEFT()` 截取必要部分，避免传输整个大文本。
- 不要在 SELECT * 中包含 MEDIUMTEXT 列，在列表查询中应明确指定字段，只在需要时才读取大文本字段。
- 在备份时，MEDIUMTEXT 大内容会显著增加 mysqldump 的输出大小和备份时间，设计时要考虑存储和备份成本。

---

### 总结

MEDIUMTEXT 最大支持 16MB 文本存储，是 TEXT（64KB）和 LONGTEXT（4GB）之间的过渡类型。适合存储长篇文章、HTML 富文本、代码文件等内容预计超过 64KB 但不需要 GB 级存储的场景。与所有 TEXT 类型一样，不支持 DEFAULT 值和完整列索引。
