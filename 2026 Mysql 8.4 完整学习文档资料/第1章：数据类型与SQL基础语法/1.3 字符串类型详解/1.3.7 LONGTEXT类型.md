## LONGTEXT 类型

LONGTEXT 是 TEXT 家族中容量最大的类型，理论上限是 4GB，但实际上受网络传输、内存配置、客户端缓冲区等多方面限制，单次读写的内容通常远小于这个上限。它适用于存储超大文本内容的场景，如完整的书稿、大规模爬虫抓取的网页原始内容等。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 最大存储 | 4294967295 字节（4GB - 1字节） |
| 最大字符数 | utf8mb4 下约 10 亿字符 |
| 存储方式 | 变长，4 字节长度前缀 |
| 实际限制 | `max_allowed_packet` 参数（默认 64MB）|
| DEFAULT 值 | 不支持 |
| 完整索引 | 不支持 |

---

### max_allowed_packet 的影响

LONGTEXT 的实际可用容量受 `max_allowed_packet` 参数约束，这个参数限制了 MySQL 单次传输包的最大大小：

```sql
-- 查看当前 max_allowed_packet
SHOW VARIABLES LIKE 'max_allowed_packet';
-- 默认：67108864（64MB）

-- 修改（如需存储更大的 LONGTEXT 内容）
SET GLOBAL max_allowed_packet = 268435456;   -- 设为 256MB
-- 也要在 my.cnf 中同步修改
-- [mysqld]
-- max_allowed_packet = 256M
```

### 语法与示例

```sql
column_name LONGTEXT
column_name LONGTEXT NOT NULL
column_name LONGTEXT CHARACTER SET utf8mb4
```

```sql
-- 书稿内容存储
CREATE TABLE book_manuscripts (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    book_title  VARCHAR(500) NOT NULL,
    author      VARCHAR(100) NOT NULL,
    content     LONGTEXT COMMENT '完整书稿内容',
    word_count  INT UNSIGNED COMMENT '字数',
    PRIMARY KEY (id)
);

-- 网页爬虫原始内容
CREATE TABLE crawled_pages (
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    url         VARCHAR(2048) NOT NULL,
    raw_html    LONGTEXT COMMENT '网页原始 HTML',
    crawled_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_url (url(1024))
);
```

### 适用场景

- **完整书稿、长篇小说**：内容可能达到数百万字
- **网页爬虫原始 HTML**：包含完整 HTML 标签的网页内容
- **数据库备份片段**：某些特殊的数据归档需求
- **大型 JSON 文档**：当 JSON 内容可能超过 16MB 时（MEDIUMTEXT 不够用）

### 常见问题

**LONGTEXT 能真的存 4GB 数据吗？**

理论上是，但受 `max_allowed_packet`、客户端内存、InnoDB 行格式等限制，实际中极少会存储 GB 级别的单列内容。如果真需要存储 GB 级别的内容，文件系统存储后在数据库中记录路径通常是更合理的方案。

**LONGTEXT 和 BLOB 有什么区别？**

两者容量相同（4GB），区别在于字符处理：LONGTEXT 是文本类型，会应用字符集和排序规则；LONGBLOB 是二进制类型，按字节存储，不做字符集转换。文本内容用 LONGTEXT，二进制内容（图片、视频等）用 LONGBLOB。

---

### 注意事项

- 存储和检索 LONGTEXT 内容会消耗大量内存和网络带宽。在查询中如果只需要部分内容，使用 `SUBSTRING(content, 1, 1000)` 等方式截取，避免传输全部大内容。
- 选择 LONGTEXT 应当是有充分理由的选择，而不是因为"保险起见"。不确定内容大小时，MEDIUMTEXT 是更合理的起点，真正需要时再迁移到 LONGTEXT。
- 备份包含 LONGTEXT 列的表时，dumping 速度会显著降低，要考虑对大内容列单独处理。

---

### 总结

LONGTEXT 理论最大 4GB，实际受 `max_allowed_packet` 限制（默认 64MB）。适合存储超长文本如完整书稿、爬虫 HTML 等。在大多数场景中，TEXT（64KB）或 MEDIUMTEXT（16MB）已足够，选择 LONGTEXT 时应当有明确的业务需求支撑，而非随意选用最大的类型。
