## LONGBLOB 类型

LONGBLOB 是 BLOB 家族中容量最大的类型，理论上限为 4GB。与 LONGTEXT 对应，区别在于存储的是二进制字节而不是字符文本，不受字符集约束。它适合存储超大二进制内容，如视频文件片段、完整数据库备份、大型文件快照等，但实际使用中受多个系统参数限制。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 最大存储 | 4294967295 字节（4GB - 1字节）|
| 存储方式 | 变长，4 字节长度前缀 |
| 字符集 | binary（无字符集）|
| 实际限制 | `max_allowed_packet`（默认 64MB）|
| DEFAULT 值 | 不支持 |
| 完整索引 | 不支持 |

---

### 语法与示例

```sql
column_name LONGBLOB
column_name LONGBLOB NOT NULL
```

```sql
-- 存储视频片段或大型二进制文件
CREATE TABLE video_segments (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    video_id    INT UNSIGNED NOT NULL,
    segment_no  SMALLINT UNSIGNED NOT NULL COMMENT '片段序号',
    data        LONGBLOB NOT NULL COMMENT '视频片段二进制数据',
    PRIMARY KEY (id),
    UNIQUE KEY uk_segment (video_id, segment_no)
);

-- 数据库备份片段存储（特殊归档场景）
CREATE TABLE backup_chunks (
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    backup_name VARCHAR(200) NOT NULL,
    chunk_no    INT UNSIGNED NOT NULL,
    chunk_data  LONGBLOB NOT NULL,
    PRIMARY KEY (id)
);
```

### BLOB 家族完整对比

| 类型 | 最大字节 | 适用场景 |
|------|---------|---------|
| TINYBLOB | 255 B | 极小二进制片段 |
| BLOB | 64 KB | 证书、密钥、小图片 |
| MEDIUMBLOB | 16 MB | 中等图片、PDF |
| LONGBLOB | 4 GB | 视频、大型文件（受限于 max_allowed_packet）|

---

### 适用场景

- **超大二进制文件**：视频文件、大型数据库备份文件（配合合理的 `max_allowed_packet` 设置）
- **完整文件快照**：需要在数据库事务中原子性保存的大型文件
- **分块存储**：将大文件分成多个块，每块存储为 LONGBLOB 行

---

### 常见问题

**LONGBLOB 和直接把文件存文件系统哪个更好？**

对于 MB 以上的文件，文件系统或对象存储（S3/OSS）几乎总是更好的选择：I/O 效率更高、不占用数据库事务日志、备份更灵活。LONGBLOB 的优势是与数据库事务保持强一致性，适合少量且必须与其他数据库操作原子一致的文件场景。

---

### 注意事项

- 存储大文件到 LONGBLOB 时，必须调整 `max_allowed_packet` 到足够大，否则会收到 `ERROR 1153: Got a packet bigger than 'max_allowed_packet' bytes` 错误。
- LONGBLOB 内容的读取会产生大量内存压力，务必在查询中只在必要时加载，使用 `LENGTH(col)` 检查大小，避免意外加载大数据。

---

### 总结

LONGBLOB 理论上限 4GB，实际受 `max_allowed_packet` 约束。适合需要在数据库中存储超大二进制数据且对一致性要求极高的场景。在大多数生产场景中，MB 级以上的二进制文件建议通过对象存储管理，数据库只存元数据和访问路径。
