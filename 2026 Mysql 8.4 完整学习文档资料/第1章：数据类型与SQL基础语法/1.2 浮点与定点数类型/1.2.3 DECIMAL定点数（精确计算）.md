## DECIMAL 定点数（精确计算）

DECIMAL 是 MySQL 中用于精确存储小数的数据类型，也叫定点数类型。与 FLOAT 和 DOUBLE 不同，DECIMAL 以字符串形式在内部存储每一位数字，不存在二进制近似误差，能保证每一位数字都精确无误。金融金额、税率、汇率等任何不允许有精度损失的场景，都应该使用 DECIMAL。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 存储方式 | 十进制定点数，每 9 位数字占 4 字节 |
| 精度类型 | 精确值（非近似） |
| 最大总位数 M | 65 |
| 最大小数位数 D | 30 |
| 别名 | `NUMERIC`（完全等价） |

**存储空间计算规则（每 9 位十进制数字占 4 字节）：**

| 有效位数范围 | 存储字节 |
|------------|---------|
| 1~9 位 | 4 字节 |
| 10~18 位 | 8 字节 |
| 19~27 位 | 12 字节 |
| 28~36 位 | 16 字节 |

实际上，DECIMAL(M, D) 的整数部分和小数部分分别计算存储：
- 整数部分 = M - D 位
- 小数部分 = D 位

---

### 语法

```sql
-- 标准语法：DECIMAL(总位数, 小数位数)
column_name DECIMAL(M, D)

-- 常用写法
amount      DECIMAL(10, 2)    -- 最多 10 位，其中 2 位小数，如 99999999.99
price       DECIMAL(12, 4)    -- 最多 12 位，其中 4 位小数
rate        DECIMAL(5, 4)     -- 最多 5 位，其中 4 位小数，如 0.9999
tax_rate    DECIMAL(6, 5)     -- 税率，如 0.13000（13%）

-- 默认值：DECIMAL 等价于 DECIMAL(10, 0)
```

### 创建示例

```sql
-- 金融交易表（核心金额字段使用 DECIMAL）
CREATE TABLE transactions (
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id     BIGINT UNSIGNED NOT NULL,
    amount      DECIMAL(15, 2) NOT NULL COMMENT '交易金额，最大 9999999999999.99',
    fee         DECIMAL(10, 2) NOT NULL DEFAULT 0.00 COMMENT '手续费',
    tax_rate    DECIMAL(5, 4) NOT NULL DEFAULT 0.0000 COMMENT '税率',
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id)
);

-- 商品价格表
CREATE TABLE products (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name        VARCHAR(200) NOT NULL,
    price       DECIMAL(10, 2) NOT NULL COMMENT '零售价',
    cost_price  DECIMAL(10, 2) COMMENT '成本价',
    discount    DECIMAL(3, 2) NOT NULL DEFAULT 1.00 COMMENT '折扣率，如0.85表示85折',
    PRIMARY KEY (id)
);

-- 汇率表
CREATE TABLE exchange_rates (
    from_currency   CHAR(3) NOT NULL,
    to_currency     CHAR(3) NOT NULL,
    rate            DECIMAL(18, 8) NOT NULL COMMENT '汇率，如1美元对人民币7.23456789',
    updated_at      DATETIME NOT NULL,
    PRIMARY KEY (from_currency, to_currency)
);

INSERT INTO products (name, price, cost_price, discount)

INSERT INTO exchange_rates (from_currency, to_currency, rate, updated_at)
VALUES ('USD', 'CNY', 7.23456789, NOW());
```

### 精确计算演示

```sql
CREATE TABLE decimal_demo (val DECIMAL(10, 2));
INSERT INTO decimal_demo VALUES (0.1), (0.2);

-- DECIMAL 的精确计算
SELECT 0.1 + 0.2;                     -- 结果：0.3（精确）
SELECT 1.0 / 3.0;                     -- 结果：0.3333（按 DECIMAL 精度截断）

-- 对比 FLOAT 的误差
SELECT CAST(0.1 AS FLOAT) + CAST(0.2 AS FLOAT);  -- 结果：0.3（看起来对，但内部近似）

-- DECIMAL 累加计算
SELECT SUM(val) FROM decimal_demo;    -- 精确结果：0.30

-- 计算带小数的金额
SELECT price * discount AS discounted_price FROM products WHERE id = 1;
-- 7999.00 * 0.95 = 7599.0500（DECIMAL 精确计算）
```

### DECIMAL 的精度规则

```sql
-- 超出精度时的处理
CREATE TABLE t (val DECIMAL(5, 2));

-- 正常插入（不超出范围）
INSERT INTO t VALUES (123.45);   -- 成功

-- 整数部分超出（5-2=3位整数，最大 999）
INSERT INTO t VALUES (9999.99);  -- ERROR: Out of range（严格模式）

-- 小数位超出时四舍五入
INSERT INTO t VALUES (1.555);    -- 实际存入 1.56（小数位只有2位，四舍五入）
INSERT INTO t VALUES (1.554);    -- 实际存入 1.55

-- 查看
SELECT val FROM t;
-- 123.45
-- 1.56
-- 1.55
```

### DECIMAL 在金融计算中的最佳实践

```sql
-- 计算订单总金额（含折扣和税）
SELECT 
    id,
    price,
    discount,
    price * discount AS discounted_price,
    ROUND(price * discount * 1.13, 2) AS price_with_tax
FROM products;

-- 计算平均值（SUM/COUNT 保持 DECIMAL 精度）
SELECT 
    AVG(amount)         AS avg_amount,      -- AVG 返回 DECIMAL
    SUM(amount)         AS total_amount,    -- SUM 返回 DECIMAL
    COUNT(*)            AS record_count
FROM transactions;

-- 货币转换
SELECT 
    100.00 * rate AS converted_amount
FROM exchange_rates 
WHERE from_currency = 'USD' AND to_currency = 'CNY';
```

### DECIMAL 的精度选择建议

| 场景 | 建议精度 | 说明 |
|------|---------|------|
| 人民币金额 | DECIMAL(15, 2) | 最大 9999999999999.99 元，13 位整数 2 位小数 |
| 美元金额 | DECIMAL(15, 2) | 同上 |
| 比特币等加密货币 | DECIMAL(20, 8) | 最多 8 位小数 |
| 商品单价 | DECIMAL(10, 2) | 最大 99999999.99 |
| 税率/折扣 | DECIMAL(5, 4) | 如 0.1300（13%）|
| 汇率 | DECIMAL(18, 8) | 保留 8 位精度 |
| 百分比 | DECIMAL(5, 2) | 如 99.99% |

### 常见问题

**DECIMAL 和 NUMERIC 有什么区别？**

没有区别，`NUMERIC` 是 `DECIMAL` 的标准 SQL 别名，两者完全等价。

**DECIMAL(10, 2) 能存多大的数？**

总位数 10，小数位 2，所以整数部分最多 10-2=8 位，即最大值是 `99999999.99`，最小值是 `-99999999.99`。

**DECIMAL 的加减法会不会超出精度范围？**

`SUM(DECIMAL(10,2))` 等聚合操作的返回类型精度会自动扩展，MySQL 内部会使用更高精度的中间结果。但如果手动拼接很多 DECIMAL 列相加，结果类型取决于参数中精度最高的那个，最终结果如果超出显示范围会有截断警告。

### 适用场景

- **金融系统**：账户余额、交易金额、手续费、汇率
- **电商系统**：商品价格、折扣率、税费计算
- **工资/薪酬系统**：工资、奖金、社保比例
- **库存系统**：库存数量（有小数，如液体按升）
- **任何不允许精度误差的数值字段**

---

### 注意事项

- DECIMAL 比 FLOAT 和 DOUBLE 占用更多存储空间，且计算稍慢（需要字符串运算），但对于金融场景，准确性远比性能重要。
- 在 Java 中，DECIMAL 对应 `java.math.BigDecimal` 类型，不要用 `double` 接收 DECIMAL 字段，否则会引入浮点误差。
- 使用 DECIMAL 时，确认 M 和 D 的设置足够容纳业务上可能出现的最大值，一旦数据库上线后修改精度是有风险的 DDL 操作。
- 不要将 DECIMAL 设置过大（如 DECIMAL(65, 30)）来"保险"，过大的精度会增加不必要的存储开销，根据实际业务需求设置合适的精度。

---

### 总结

DECIMAL 是 MySQL 中唯一能精确存储小数的数据类型，以字符串方式按位存储，不存在二进制近似误差。`DECIMAL(M, D)` 指定总位数 M 和小数位数 D，金融金额建议 `DECIMAL(15, 2)`，税率建议 `DECIMAL(5, 4)`。任何涉及金钱、税率、汇率的字段都应首选 DECIMAL，而非 FLOAT 或 DOUBLE。
