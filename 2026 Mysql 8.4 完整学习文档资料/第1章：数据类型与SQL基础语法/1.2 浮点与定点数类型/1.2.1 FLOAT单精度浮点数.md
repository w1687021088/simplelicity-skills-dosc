## FLOAT 单精度浮点数

FLOAT 是 MySQL 中的单精度浮点数类型，遵循 IEEE 754 标准的 32 位浮点表示，能存储非常大或非常小的小数，但这种存储方式本质上是近似值，存在精度限制。了解 FLOAT 的精度边界，是决定在什么场景下使用它、什么场景下必须避免它的关键。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 存储空间 | 4 字节（32 bits） |
| 精度 | 约 7 位十进制有效数字 |
| 数值范围 | ±1.175494351E-38 ~ ±3.402823466E+38 |
| 存储类型 | 近似值（IEEE 754 单精度） |

---

### 语法

```sql
column_name FLOAT
column_name FLOAT(M, D)      -- M 是总位数，D 是小数位数（已废弃，不推荐）
column_name FLOAT NOT NULL DEFAULT 0.0
```

`FLOAT(M, D)` 中的精度参数 M 和 D 在 MySQL 8.0.17 之后已废弃。

---

### 创建示例

```sql
-- 存储坐标（经纬度，精度要求不极高时可用 FLOAT）
CREATE TABLE locations (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name        VARCHAR(100) NOT NULL,
    latitude    FLOAT NOT NULL COMMENT '纬度',
    longitude   FLOAT NOT NULL COMMENT '经度',
    PRIMARY KEY (id)
);

-- 气象数据（温度/湿度，近似值足够）
CREATE TABLE weather_data (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    station_id  INT UNSIGNED NOT NULL,
    temperature FLOAT COMMENT '气温（摄氏度）',
    humidity    FLOAT COMMENT '湿度（%）',
    recorded_at DATETIME NOT NULL,
    PRIMARY KEY (id)
);

INSERT INTO locations (name, latitude, longitude) VALUES ('北京天安门', 39.9087, 116.3975);

VALUES (1001, 22.5, 65.3, NOW());
```

### 精度问题演示

```sql
-- FLOAT 的精度约为 7 位十进制有效数字
CREATE TABLE float_test (val FLOAT);
INSERT INTO float_test VALUES (1234567.89);
SELECT val FROM float_test;
-- 实际存储：1234568.0（超出 7 位精度的部分被截断）

INSERT INTO float_test VALUES (0.1);
INSERT INTO float_test VALUES (0.2);
SELECT val, val + val FROM float_test WHERE val < 0.2;
-- 可能输出：0.1, 0.2（但内部实际是近似值，不能用 = 0.1 安全比较）

-- FLOAT 的相等比较是危险的
SELECT * FROM float_test WHERE val = 0.1;  -- 可能返回空，因为存储的不是精确的 0.1
```

### FLOAT 与 DOUBLE 的比较

| 属性 | FLOAT | DOUBLE |
|------|-------|--------|
| 存储空间 | 4 字节 | 8 字节 |
| 有效位数 | 约 7 位 | 约 15 位 |
| 精度 | 单精度 | 双精度 |
| 适用场景 | 科学计算近似值，空间敏感 | 更高精度的近似值计算 |

---

### 适用场景

- **地理坐标**：经纬度通常需要 6 位小数，FLOAT 的 7 位有效数字勉强够用，但如果需要高精度地图应用（厘米级精度），应使用 DOUBLE 或 DECIMAL
- **物理传感器数据**：温度、湿度、气压等传感器数据本身就是近似值，FLOAT 的精度足够
- **科学计算的中间结果**：不需要精确比较的大量数据，节省存储空间
- **机器学习特征值**：训练数据中的特征列，通常使用 FLOAT 节省空间

### 常见问题

**FLOAT 能做精确的等值比较吗？**

不能。由于浮点数的近似存储特性，两个"看起来相同"的 FLOAT 值在内部可能有微小差异，导致等值比较失败。需要比较时，应使用范围比较：

```sql
-- 错误做法
SELECT * FROM weather WHERE temperature = 22.5;

-- 正确做法（设置合理的误差范围）
SELECT * FROM weather WHERE ABS(temperature - 22.5) < 0.001;
```

**FLOAT 的精度到底是多少？**

FLOAT 的有效十进制位数约为 7 位。意思是：对于一个 FLOAT 值，从最高有效数字开始数 7 位是精确的，第 7 位之后的数字是不可靠的（可能有舍入误差）。例如 `1234567.89` 存储为 FLOAT 后，第 8 位开始就不准确了。

---

### 注意事项

- 金融数据、订单金额、价格等需要精确计算的数值，绝对不能使用 FLOAT 或 DOUBLE，应使用 DECIMAL。一旦用浮点数存储金额，累计误差可能导致财务数据不平衡。
- `FLOAT(M, D)` 语法在 MySQL 8.0.17 后已废弃，不应在新代码中使用。
- 在 GROUP BY 或 ORDER BY 中对 FLOAT 列操作时，由于精度问题，相邻的近似值可能被分到不同的分组，或者排序结果不直观。

---

### 总结

FLOAT 是单精度 IEEE 754 浮点数，占用 4 字节，精度约 7 位有效数字。它适合存储本身就是近似值的科学数据（温度、传感器读数、地理坐标等）。任何需要精确计算或精确比较的场景——金融数据、计费金额、库存数量——都不应该使用 FLOAT，而应该选择 DECIMAL。
