## DOUBLE 双精度浮点数

DOUBLE 是 MySQL 中的双精度浮点数类型，遵循 IEEE 754 标准的 64 位浮点表示。相比 FLOAT，DOUBLE 有更大的数值范围和约两倍的有效精度，但本质上仍然是近似值，不能用于需要精确计算的场景。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 存储空间 | 8 字节（64 bits） |
| 精度 | 约 15~16 位十进制有效数字 |
| 数值范围 | ±2.2250738585072014E-308 ~ ±1.7976931348623157E+308 |
| 存储类型 | 近似值（IEEE 754 双精度） |
| 别名 | `DOUBLE PRECISION`、`REAL`（非严格模式下） |

---

### 语法

```sql
column_name DOUBLE
column_name DOUBLE PRECISION    -- 与 DOUBLE 完全等价
column_name REAL                -- 在 REAL_AS_FLOAT 未开启时等价于 DOUBLE
column_name DOUBLE NOT NULL DEFAULT 0.0
```

---

### 创建示例

```sql
-- 高精度地理坐标（DOUBLE 提供约 15 位精度，适合精确地图定位）
CREATE TABLE gps_points (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name        VARCHAR(100) NOT NULL,
    latitude    DOUBLE NOT NULL COMMENT '纬度，精度到 1 毫米级别',
    longitude   DOUBLE NOT NULL COMMENT '经度',
    altitude    DOUBLE COMMENT '海拔（米）',
    PRIMARY KEY (id)
);

-- 科学实验数据（需要高精度近似值）
CREATE TABLE experiment_results (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    sample_id   VARCHAR(50) NOT NULL,
    measurement DOUBLE NOT NULL COMMENT '测量值',
    std_dev     DOUBLE COMMENT '标准差',
    PRIMARY KEY (id)
);

INSERT INTO gps_points (name, latitude, longitude, altitude) 
VALUES ('珠穆朗玛峰', 27.988257, 86.924817, 8848.86);
```

### DOUBLE 与 FLOAT 的对比

| 属性 | FLOAT | DOUBLE |
|------|-------|--------|
| 存储 | 4 字节 | 8 字节 |
| 有效位数 | 约 7 位 | 约 15~16 位 |
| 精度 | 单精度 | 双精度 |
| 数值范围 | ±3.4E+38 | ±1.8E+308 |
| 精度误差量级 | 约 10^-7 | 约 10^-15 |
| 适用 | 低精度近似值、节省空间 | 更高精度近似值 |

---

### 精度演示

```sql
CREATE TABLE double_test (
    f FLOAT,
    d DOUBLE
);
INSERT INTO double_test VALUES (1.23456789012345, 1.23456789012345);
SELECT f, d FROM double_test;
-- FLOAT 输出：1.2345679（约 7 位有效数字）
-- DOUBLE 输出：1.23456789012345（约 15 位有效数字）

-- DOUBLE 的精度问题（IEEE 754 固有局限）
SELECT 0.1 + 0.2;
-- 结果：0.30000000000000004（不是精确的 0.3）
```

### 适用场景

- **高精度地理坐标**：GPS 坐标精确到厘米级需要 8~9 位小数，DOUBLE 的 15 位有效数字足够覆盖
- **科学计算**：物理、化学等领域的实验数据，需要比 FLOAT 更高精度的近似值
- **统计分析**：均值、方差、标准差等统计指标，DOUBLE 提供足够精度
- **金融中间计算（非最终存储）**：某些复杂金融模型的中间计算步骤可以用 DOUBLE，但最终结果落地存储应用 DECIMAL

---

### 常见问题

**DOUBLE 比 FLOAT 精确，但为什么还是不能存精确金额？**

DOUBLE 虽然有 15 位精度，但对于十进制小数（如 0.1、0.01），它的内部二进制表示仍然是近似的（0.1 在 IEEE 754 中是无限循环二进制小数）。经过多次运算后，精度误差会累积，最终结果可能与预期有微小偏差。金融场景不能接受任何误差，所以需要 DECIMAL。

**`REAL` 和 `DOUBLE` 一样吗？**

默认情况下（`REAL_AS_FLOAT` 未设置时），`REAL` 是 `DOUBLE` 的别名，两者等价。如果设置了 `REAL_AS_FLOAT`，则 `REAL` 变成 `FLOAT` 的别名。建议直接使用 `DOUBLE` 以避免歧义。

---

### 注意事项

- 不要对 DOUBLE 列使用 `=` 进行精确等值比较，应使用范围判断（如 `ABS(val - 目标值) < 容差`）
- DOUBLE 占用 8 字节，是 FLOAT 的两倍，存储大量行时会有明显的空间差异，根据精度需求合理选择
- `DOUBLE(M, D)` 的精度参数在 MySQL 8.0.17 后已废弃，新代码不应使用

---

### 总结

DOUBLE 是双精度 IEEE 754 浮点数，占用 8 字节，精度约 15~16 位有效数字。它比 FLOAT 精度更高，适合地理坐标、科学计算等需要更精确近似值的场景。但 DOUBLE 和 FLOAT 一样是近似值类型，金融、账务等需要精确小数计算的场景必须使用 DECIMAL。
