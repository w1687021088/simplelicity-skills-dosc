# SMALLINT 数据类型

SMALLINT 是 SQL 标准中定义的整数类型之一，占用 2 个字节，在存储空间和表示范围之间提供了比 TINYINT 更宽的覆盖，适合表示不太大但又超出 TINYINT 范围的整数值。

---

## 基本特性

| 属性 | 值 |
|------|---|
| 存储空间 | 2 字节（16 bits） |
| 有符号范围 | -32768 ~ 32767 |
| 无符号范围（UNSIGNED）| 0 ~ 65535 |
| SQL 标准 | ISO SQL 标准类型 |

---

## 语法

```sql
column_name SMALLINT
column_name SMALLINT UNSIGNED
column_name SMALLINT NOT NULL DEFAULT 0
```

---

## 创建示例

```sql
-- 端口号（0~65535 正好对应 SMALLINT UNSIGNED 范围）
CREATE TABLE service_config (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    service_name VARCHAR(100) NOT NULL,
    port        SMALLINT UNSIGNED NOT NULL DEFAULT 3306,
    PRIMARY KEY (id)
);

-- 年份差值（可能为负，有符号）
CREATE TABLE employee_records (
    id            INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name          VARCHAR(100) NOT NULL,
    years_service SMALLINT NOT NULL DEFAULT 0 COMMENT '工龄（年）',
    PRIMARY KEY (id)
);

-- 产品数量（库存）
CREATE TABLE inventory (
    product_id  INT UNSIGNED NOT NULL,
    quantity    SMALLINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '库存数量',
    PRIMARY KEY (product_id)
);

INSERT INTO service_config (service_name, port) VALUES ('MySQL', 3306), ('Redis', 6379), ('HTTP', 80);
INSERT INTO inventory (product_id, quantity) VALUES (1001, 500), (1002, 0), (1003, 1200);
```

## 与 TINYINT 的对比

| 类型 | 存储 | 有符号范围 | 无符号范围 | 适用场景 |
|------|------|-----------|----------|---------|
| TINYINT | 1 字节 | -128 ~ 127 | 0 ~ 255 | 状态枚举、布尔标志 |
| SMALLINT | 2 字节 | -32768 ~ 32767 | 0 ~ 65535 | 端口号、年龄、小范围计数 |

SMALLINT 比 TINYINT 多 1 个字节，但上限从 127/255 提升到了 32767/65535，覆盖了更多业务场景。

---

## 适用场景

- **网络端口号**：端口范围 0~65535，正好能用 `SMALLINT UNSIGNED` 精确表示，使用 INT 反而浪费空间
- **年龄字段**：理论上年龄不超过 200，用 TINYINT UNSIGNED 够用，但 SMALLINT 也常被使用
- **小范围计数**：如帖子的每天回复数（通常不超过 65535）、楼层号等
- **国家/地区代码**：ISO 3166 国家代码是数字时，最大值 999，SMALLINT 足够
- **HTTP 状态码**：200、404、500 等，SMALLINT UNSIGNED 适合

## 常见问题

**SMALLINT 能存储年份（如 2026）吗？**

可以，2026 在 SMALLINT 有符号范围（-32768~32767）内，可以正常存储。但 MySQL 有专门的 `YEAR` 类型用于年份，建议存储年份时使用专用类型。如果需要存储公元前年份（负数），SMALLINT 反而比 YEAR 类型更灵活。

**IP 端口 65535 能用 SMALLINT 存吗？**

不能用有符号 SMALLINT（上限 32767），但可以用 `SMALLINT UNSIGNED`（上限 65535），正好覆盖端口的完整范围（0~65535）。

**什么情况下用 SMALLINT 而不是 INT？**

当字段值确认不会超过 32767（有符号）或 65535（无符号），且需要节省存储空间时。在大量数据的宽表中，每个字段节省 2 字节（相比 INT）会有明显的总体收益。

---

## 注意事项

- 和所有整数类型一样，SMALLINT 的显示宽度（如 `SMALLINT(5)`）在 MySQL 8.0.17 后已废弃，不影响实际存储和范围。
- 存入超出范围的值时，在严格 SQL 模式下报错，非严格模式下截断为边界值。生产环境建议开启严格模式。
- 在算术运算中，SMALLINT 与其他整数类型做加减乘除时，MySQL 会自动提升结果类型，不会因为 SMALLINT 的范围限制而溢出（运算结果使用足够宽的类型）。

---

## 总结

SMALLINT 占用 2 字节，有符号范围 -32768~32767，无符号范围 0~65535。它是 SQL 标准类型，在需要比 TINYINT 更大范围、但又不需要 INT 那么宽的场景下使用。端口号、年龄、小范围计数是典型适用场景。在追求精确存储节省的系统设计中，根据字段的实际值域选择最小够用的整数类型是一个好习惯。
