## 整数类型自增属性 AUTO_INCREMENT

AUTO_INCREMENT 是 MySQL 用于自动生成递增整数值的列属性，最常用于主键列，让每条新插入的记录自动获得一个唯一的数字 ID，无需应用程序手动指定。

---

### 基本语法

```sql
-- 最常见写法：整数主键 + AUTO_INCREMENT
CREATE TABLE users (
    id      INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name    VARCHAR(100) NOT NULL,
    PRIMARY KEY (id)
);

-- 所有整数类型均支持 AUTO_INCREMENT
CREATE TABLE t1 (id TINYINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY);
CREATE TABLE t2 (id SMALLINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY);
CREATE TABLE t3 (id MEDIUMINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY);
CREATE TABLE t4 (id INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY);
CREATE TABLE t5 (id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY);
```

**使用限制：**
- 每张表只能有一个 AUTO_INCREMENT 列
- AUTO_INCREMENT 列必须有索引（通常是 PRIMARY KEY 或 UNIQUE KEY）
- AUTO_INCREMENT 列必须是 NOT NULL（即使不明写，也会隐式设为 NOT NULL）
- AUTO_INCREMENT 列必须是整数类型（TINYINT、SMALLINT、MEDIUMINT、INT、BIGINT）

---

### 自增值的工作机制

#### 插入行为

```sql
CREATE TABLE orders (
    id      INT UNSIGNED NOT NULL AUTO_INCREMENT,
    item    VARCHAR(100) NOT NULL,
    PRIMARY KEY (id)
);

-- 方法一：不指定 id，系统自动生成
INSERT INTO orders (item) VALUES ('商品A');    -- id = 1
INSERT INTO orders (item) VALUES ('商品B');    -- id = 2

-- 方法二：指定 id 为 NULL 或 0，系统自动生成
INSERT INTO orders (id, item) VALUES (NULL, '商品C');  -- id = 3
INSERT INTO orders (id, item) VALUES (0, '商品D');      -- id = 4

-- 方法三：显式指定 id
INSERT INTO orders (id, item) VALUES (100, '商品E');   -- id = 100

-- 之后自动生成的 id 会从 101 开始
INSERT INTO orders (item) VALUES ('商品F');    -- id = 101
```

#### 获取刚插入的自增 ID

```sql
-- 方法一：LAST_INSERT_ID()（推荐，连接级别，线程安全）
INSERT INTO orders (item) VALUES ('商品G');
SELECT LAST_INSERT_ID();    -- 返回刚刚插入的 id

-- 方法二：在同一条语句中使用
INSERT INTO orders (item) VALUES ('商品H');
SELECT LAST_INSERT_ID() AS new_id;

-- 批量插入时，LAST_INSERT_ID() 返回第一条插入记录的 id
INSERT INTO orders (item) VALUES ('商品I'), ('商品J'), ('商品K');
SELECT LAST_INSERT_ID();    -- 返回商品I的 id，不是商品K的
```

### 查看和修改 AUTO_INCREMENT 当前值

```sql
-- 方法一：查看表的 AUTO_INCREMENT 值
SHOW TABLE STATUS LIKE 'orders';
-- Auto_increment 列显示下一个自增值

-- 方法二：从 information_schema 查询
SELECT AUTO_INCREMENT 
FROM information_schema.TABLES 
WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'orders';

-- 修改 AUTO_INCREMENT 的起始值（只能增大，不能减小到已有值以下）
ALTER TABLE orders AUTO_INCREMENT = 1000;

-- 创建时指定起始值
CREATE TABLE products (
    id    INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name  VARCHAR(100) NOT NULL,
    PRIMARY KEY (id)
) AUTO_INCREMENT = 10000;
```

### InnoDB 中的 AUTO_INCREMENT 行为

#### 自增计数器

InnoDB 在内存中维护一个自增计数器。MySQL 8.0 之前，这个计数器在重启后会重置为"当前最大 ID + 1"，可能导致自增值"回退"（如果最大 ID 的行被删除后重启，新 ID 可能与已删除的 ID 重合）。

MySQL 8.0+ 修复了这个问题：InnoDB 将自增计数器的当前值持久化到 redo log，重启后能正确恢复，不再有回退问题。

```sql
-- 演示 8.0+ 的持久化行为
INSERT INTO orders (item) VALUES ('测试1');    -- id = 1
INSERT INTO orders (item) VALUES ('测试2');    -- id = 2
DELETE FROM orders WHERE id = 2;              -- 删除最大 id

-- 8.0 之前重启后：下一个 id 可能是 2（回退到删除前的最大+1）
-- 8.0+ 重启后：下一个 id 仍然是 3（持久化了计数器）
```

#### AUTO_INCREMENT 锁模式

InnoDB 有三种 AUTO_INCREMENT 锁模式（由 `innodb_autoinc_lock_mode` 控制），影响并发插入的性能：

| 锁模式 | 值 | 说明 |
|--------|---|------|
| 传统模式 | 0 | 每次 INSERT 持有表级 AUTO-INC 锁，并发低 |
| 连续模式 | 1 | 简单 INSERT 用轻量锁，批量 INSERT 持表锁（8.0 之前默认） |
| 交叉模式 | 2 | 所有 INSERT 都用轻量锁，并发最高，但批量 INSERT 的 ID 不连续（8.0 默认） |

MySQL 8.0 默认是锁模式 2（交叉模式），性能最好，但批量插入时多行的 ID 可能不连续（在并发场景下）。

```sql
-- 查看当前锁模式
SHOW VARIABLES LIKE 'innodb_autoinc_lock_mode';
```

### 自增 ID 的间隙问题

AUTO_INCREMENT 的值一旦分配就不会回收，即使对应的行被删除或者事务回滚：

```sql
-- 场景：插入失败后，自增 ID 被"消耗"但不会回收
BEGIN;
INSERT INTO orders (item) VALUES ('失败的订单');   -- 假设 id = 50
ROLLBACK;   -- 回滚，id = 50 的行不存在

INSERT INTO orders (item) VALUES ('新订单');   -- id = 51，不是 50
```

这意味着生产中看到的 AUTO_INCREMENT ID 往往不是连续的，这是正常现象，不代表数据缺失。**不要把 AUTO_INCREMENT ID 当作"第 N 条记录"的含义来使用**。

---

### 适用场景

- **单库单表的主键**：AUTO_INCREMENT 是最简单可靠的主键生成方式
- **不要求全局唯一的 ID**：在单一 MySQL 实例内唯一；分布式多写场景中不适合，应使用雪花算法或 UUID

---

### 常见问题

**为什么 ID 不连续（有跳号）？**

正常现象。原因：事务回滚、INSERT 失败、批量插入（锁模式 2 下并发分配）、服务重启（8.0 之前版本）等情况都会导致 ID 不连续。

**想重置自增 ID（比如清空表后从 1 开始）**

```sql
-- 方法一：TRUNCATE TABLE（清空并重置 AUTO_INCREMENT 为 1）
TRUNCATE TABLE orders;

-- 方法二：DELETE 后 ALTER
DELETE FROM orders;
ALTER TABLE orders AUTO_INCREMENT = 1;
```

`ALTER TABLE ... AUTO_INCREMENT = 1` 只有在表中没有比指定值更大的 ID 时才会生效，否则会被自动调整为当前最大 ID + 1。

**可以手动插入比当前自增值更大的 ID 吗？**

可以。手动插入更大的 ID 后，下次自动生成的 ID 会从手动插入的最大值 + 1 开始。

---

### 注意事项

- 分布式架构（多个 MySQL 写节点）中不能使用 AUTO_INCREMENT 作为全局主键，因为不同节点的自增值会冲突。此时应使用雪花算法、UUID 或数据库中间件的全局 ID 服务。
- 主键选择了 `INT`（非 UNSIGNED）时，上限约 21 亿；如果预期数据量较大，提前改为 `INT UNSIGNED`（约 43 亿）或 `BIGINT UNSIGNED`，避免临界时的紧急扩容。
- 不要依赖 AUTO_INCREMENT ID 的连续性做任何业务逻辑判断（如"最新一条是最大 ID"是正确的，但"ID 是 N 的记录一定是第 N 条"是错误的）。

---

### 总结

AUTO_INCREMENT 让整数主键列自动递增，是 MySQL 最常用的主键生成机制。InnoDB 在 MySQL 8.0 后将自增计数器持久化到 redo log，解决了重启后自增回退的历史问题。AUTO_INCREMENT 分配的值不会因为事务回滚或行删除而回收，ID 不连续是正常现象。分布式多写场景中，AUTO_INCREMENT 不适合作为全局唯一 ID，应改用分布式 ID 方案。
