# TINYINT 数据类型（范围、存储、有符号/无符号）

TINYINT 是 MySQL 整数类型家族中占用存储空间最小的一种，只需要 1 个字节。在列非常多的宽表设计中，或者存储大量状态标志字段时，选择合适的小类型能显著降低存储占用和内存压力。

---

## 基本特性

| 属性 | 值 |
|------|---|
| 存储空间 | 1 字节（8 bits） |
| 有符号范围 | -128 ~ 127 |
| 无符号范围（UNSIGNED）| 0 ~ 255 |
| SQL 标准支持 | MySQL 扩展，非标准 SQL |

---

## 语法

```sql
-- 有符号（默认）
column_name TINYINT

-- 无符号
column_name TINYINT UNSIGNED

-- 指定显示宽度（已废弃，不推荐使用）
column_name TINYINT(1)
```

---

## 创建示例

```sql
-- 状态字段（0/1，使用 TINYINT UNSIGNED）
CREATE TABLE orders (
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    status      TINYINT UNSIGNED NOT NULL DEFAULT 0
                COMMENT '0=待付款,1=已付款,2=已发货,3=已完成,4=已取消',
    is_deleted  TINYINT(1) NOT NULL DEFAULT 0
                COMMENT '逻辑删除：0=正常,1=已删除',
    PRIMARY KEY (id)
);

-- 温度记录（有符号，可能为负值）
CREATE TABLE temperature_records (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    celsius     TINYINT NOT NULL COMMENT '摄氏温度，-128 ~ 127',
    PRIMARY KEY (id)
);

-- 插入数据
INSERT INTO orders (status) VALUES (0), (1), (2);
INSERT INTO temperature_records (celsius) VALUES (-15), (0), (37), (100);

-- 查询
SELECT * FROM orders WHERE status = 1;
SELECT * FROM temperature_records WHERE celsius > 35;
```

---

## 有符号与无符号的选择

当字段的值确定不会出现负数时，使用 `UNSIGNED` 可以将正数的表示范围扩大一倍（0~255 vs -128~127）。

```sql
-- 有符号 TINYINT：适合可能有负值的场景（如温度、分差、偏移量）
age_difference TINYINT    -- -128 ~ 127，可以表示正负差值

-- 无符号 TINYINT：适合枚举状态、计数等非负场景
user_level TINYINT UNSIGNED   -- 0 ~ 255，状态级别
```

## TINYINT(1) 与 BOOLEAN

MySQL 中没有独立的 BOOLEAN 类型，`BOOL` 和 `BOOLEAN` 都是 `TINYINT(1)` 的别名。这里的 `(1)` 是历史遗留的"显示宽度"，在 MySQL 8.0.17 之后已被废弃，对实际存储和范围没有任何影响。

```sql
-- 以下三种定义完全等价
is_active BOOLEAN
is_active BOOL
is_active TINYINT(1)

-- 插入布尔值
INSERT INTO t (is_active) VALUES (TRUE), (FALSE);
-- TRUE = 1, FALSE = 0

-- 查询时可以用 TRUE/FALSE 或 1/0
SELECT * FROM t WHERE is_active = TRUE;
SELECT * FROM t WHERE is_active = 1;   -- 等价
```

注意：MySQL 实际上不严格区分 boolean，`TINYINT(1)` 可以存储 -128~127 中的任何值，不会限制为只存 0 和 1。

## 越界行为

```sql
-- 严格模式下（默认），插入超出范围的值会报错
SET sql_mode = 'STRICT_TRANS_TABLES';
INSERT INTO orders (status) VALUES (300);   -- ERROR 1264: Out of range value

-- 非严格模式下，超出范围的值会被截断为边界值
SET sql_mode = '';
INSERT INTO orders (status) VALUES (300);   -- 实际存入 255（无符号上限）
INSERT INTO orders (status) VALUES (-1);    -- 实际存入 0（无符号下限）
```

## 适用场景

- **状态/类型枚举字段**：如订单状态、用户类型、性别（0/1/2）等，值域在 0~127 或 0~255 之间
- **布尔标志字段**：is_deleted、is_active、is_vip 等 0/1 标志
- **小范围计数**：评分（1~5星）、优先级（1~10）等
- **需要节省存储的高频小值字段**：列数多的宽表，每个字段节省几个字节，整表可以节省可观的空间

## 常见问题

**TINYINT(1) 和 TINYINT 有什么实际区别？**

没有实际区别。括号中的数字是"显示宽度"，是一个历史遗留特性，在 MySQL 8.0.17 之后已被明确废弃，对存储空间和数值范围均无影响。建议新代码中不要使用 `TINYINT(1)` 这种写法，直接用 `TINYINT` 或 `TINYINT UNSIGNED`。

**为什么 ORM 框架将 TINYINT(1) 映射为 Boolean？**

Hibernate、MyBatis 等框架有约定：`TINYINT(1)` 映射为 Java 的 `boolean` 类型，其他 TINYINT 映射为 `byte` 或 `int`。这是框架层的约定，而非 MySQL 强制行为。如果不想让字段被映射为 boolean，可以用 `TINYINT(2)` 或 `TINYINT UNSIGNED` 代替（虽然显示宽度已废弃，但这些框架仍在检测括号中的数字）。

**TINYINT 插入了超出范围的值但没有报错**

检查 `sql_mode` 是否包含 `STRICT_TRANS_TABLES`。生产环境建议开启严格模式，避免数据被静默截断。

```sql
SHOW VARIABLES LIKE 'sql_mode';
-- 如果 STRICT_TRANS_TABLES 不在列表中，建议在 my.cnf 中添加
```

## 注意事项

- TINYINT 的范围有限，在设计时要确认业务上的值域不会超出范围。如果状态码未来可能超过 127 或 255，提前考虑使用 SMALLINT。
- `UNSIGNED` 属性在 MySQL 8.0 中不影响算术运算的结果类型，但在进行跨类型计算时要注意隐式转换可能导致的符号变化。
- 不要依赖显示宽度（如 `TINYINT(1)`）来控制实际存储或验证，这个特性已废弃，未来版本可能移除。

---

## 总结

TINYINT 是 MySQL 中最小的整数类型，占用 1 字节，有符号范围 -128~127，无符号范围 0~255。它适合存储状态码、布尔标志、小范围枚举等字段。`TINYINT(1)` 与 `BOOLEAN` 是等价的别名，显示宽度本身已废弃，不影响实际存储。在确定字段值不会为负数的情况下，使用 `TINYINT UNSIGNED` 能将上限提高到 255。
