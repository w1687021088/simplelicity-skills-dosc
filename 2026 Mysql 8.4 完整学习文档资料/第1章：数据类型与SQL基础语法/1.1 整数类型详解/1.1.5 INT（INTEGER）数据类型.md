## INT（INTEGER）数据类型

INT 是最常用的整数类型，也是 SQL 标准中最核心的整数类型之一。`INT` 和 `INTEGER` 是完全等价的同义词。它占用 4 个字节，能表示超过 20 亿的正负数范围，覆盖了绝大多数业务场景下的整数需求。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 存储空间 | 4 字节（32 bits） |
| 有符号范围 | -2147483648 ~ 2147483647（约 ±21 亿） |
| 无符号范围（UNSIGNED）| 0 ~ 4294967295（约 43 亿） |
| SQL 标准 | ISO SQL 标准核心类型 |
| 别名 | `INTEGER`（完全等价） |

---

### 语法

```sql
column_name INT
column_name INTEGER          -- 与 INT 完全等价
column_name INT UNSIGNED
column_name INT NOT NULL DEFAULT 0
column_name INT NOT NULL AUTO_INCREMENT PRIMARY KEY
```

---

### 创建示例

```sql
-- 最常见的用法：主键 + AUTO_INCREMENT
CREATE TABLE users (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    username    VARCHAR(50) NOT NULL UNIQUE,
    age         TINYINT UNSIGNED,
    score       INT NOT NULL DEFAULT 0 COMMENT '用户积分',
    PRIMARY KEY (id)
);

-- 外键关联
CREATE TABLE posts (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id     INT UNSIGNED NOT NULL COMMENT '作者ID',
    title       VARCHAR(200) NOT NULL,
    view_count  INT UNSIGNED NOT NULL DEFAULT 0,
    PRIMARY KEY (id),
    INDEX idx_user_id (user_id)
);

-- 金额（分为单位，避免浮点精度问题）
CREATE TABLE transactions (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    amount_fen  INT NOT NULL COMMENT '金额（分），可为负表示退款',
    PRIMARY KEY (id)
);

INSERT INTO users (username, age, score) VALUES ('alice', 28, 1500), ('bob', 32, 2300);
INSERT INTO posts (user_id, title) VALUES (1, 'MySQL 入门'), (1, 'Redis 进阶');
```

### INT 作为主键的上限问题

`INT UNSIGNED` 的上限约 43 亿，对于大多数业务表是足够的。但如果表是高并发写入的核心表（如订单表、日志表），需要评估是否会在业务生命周期内触及上限：

```sql
-- 查看某个 AUTO_INCREMENT 列当前的值
SELECT AUTO_INCREMENT 
FROM information_schema.TABLES 
WHERE TABLE_SCHEMA = 'myapp' AND TABLE_NAME = 'orders';

-- 理论计算：INT UNSIGNED 主键，即使每秒 1 万条记录，用完需要
-- 4294967295 / 10000 / 3600 / 24 / 365 ≈ 13.6 年
-- 对大多数系统来说足够，但高频写入系统应考虑 BIGINT
```

### INT 与其他整数类型的横向比较

| 类型 | 存储 | 无符号上限 | 适用场景 |
|------|------|----------|---------|
| TINYINT | 1B | 255 | 状态/枚举 |
| SMALLINT | 2B | 65535 | 端口号/小计数 |
| MEDIUMINT | 3B | 16777215 | 中等 ID/计数 |
| INT | 4B | 4294967295 | 通用 ID/计数/金额(分) |
| BIGINT | 8B | 约 1.8×10¹⁹ | 超大 ID/时间戳/全局 ID |

### 适用场景

- **表主键**：中小型业务表的标准主键类型，`INT UNSIGNED NOT NULL AUTO_INCREMENT`
- **外键**：引用其他表 INT 主键的外键列
- **计数字段**：点赞数、收藏数、订单量等，通常不超过 43 亿的计数
- **金额（分）**：将金额转为最小货币单位（分/分厘），存储为整数避免浮点精度问题
- **Unix 时间戳**：32 位 Unix 时间戳（但 2038 年问题后需改为 BIGINT 或使用 DATETIME）

### 常见问题

**INT 和 INTEGER 有区别吗？**

没有任何区别，两者是完全等价的同义词。`INTEGER` 是 SQL 标准写法，`INT` 是通用缩写形式，MySQL 都接受。

**INT(11) 里的 11 是什么意思？**

`INT(11)` 中的 11 是历史遗留的"显示宽度"特性，在 MySQL 8.0.17 之后已被废弃。它不影响存储空间（仍是 4 字节）、不影响数值范围（仍是 -21亿~21亿），只是在非常旧的 MySQL 客户端中用于格式化显示时的最小宽度提示。新代码中应避免使用这个写法，直接写 `INT` 即可。

**主键用 INT 还是 BIGINT？**

对于日常业务表，`INT UNSIGNED`（上限约 43 亿）通常已经足够。但对于分布式系统使用的全局 ID（如雪花算法生成的 19 位数字 ID）或预计数据量极大的核心表，应选择 BIGINT UNSIGNED。宁可一开始选大类型，也不要等到主键溢出后再做紧急扩容。

---

### 注意事项

- `INT` 的有符号上限是约 21 亿，如果用作 AUTO_INCREMENT 主键且预计行数接近这个上限，提前换用 `INT UNSIGNED`（约 43 亿）或 `BIGINT UNSIGNED`。
- 将金额存储为整数（分/厘）是推荐做法，避免了 FLOAT/DOUBLE 的精度问题，也便于整数运算。
- INT 主键用完时，AUTO_INCREMENT 会尝试获取下一个值，但下一个值已超出范围，导致插入失败报错。在业务高速增长期要定期监控主键使用比例。

---

### 总结

INT（INTEGER）是 MySQL 中最常用的整数类型，占用 4 字节，有符号范围约 ±21 亿，无符号上限约 43 亿。它是业务表主键、外键和通用整数字段的首选类型。`INT(11)` 中的显示宽度在 MySQL 8.0.17 后已废弃，新代码中直接使用 `INT` 即可。对于数据量极大的核心表，应评估是否需要 BIGINT 主键。
