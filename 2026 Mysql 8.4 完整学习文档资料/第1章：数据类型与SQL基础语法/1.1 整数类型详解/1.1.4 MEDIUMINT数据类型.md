# MEDIUMINT 数据类型

MEDIUMINT 是 MySQL 对 SQL 标准的扩展，占用 3 字节，介于 SMALLINT（2字节）和 INT（4字节）之间。它的存在填补了两者之间的空白，但在实际使用中，很多开发者会直接跳过它选择 INT，因为 4 字节在大多数场景下已经够用且没有歧义。

---

## 基本特性

| 属性 | 值 |
|------|---|
| 存储空间 | 3 字节（24 bits） |
| 有符号范围 | -8388608 ~ 8388607（约 ±838 万） |
| 无符号范围（UNSIGNED）| 0 ~ 16777215（约 1677 万） |
| SQL 标准 | MySQL 扩展，非标准 SQL |

---

## 语法

```sql
column_name MEDIUMINT
column_name MEDIUMINT UNSIGNED
column_name MEDIUMINT NOT NULL DEFAULT 0
```

---

## 创建示例

```sql
-- 城市人口（百万级别，MEDIUMINT UNSIGNED 适合中等城市人口）
CREATE TABLE cities (
    id          MEDIUMINT UNSIGNED NOT NULL AUTO_INCREMENT,
    city_name   VARCHAR(100) NOT NULL,
    population  MEDIUMINT UNSIGNED COMMENT '人口数量（万人）',
    PRIMARY KEY (id)
);

-- 文章浏览量（中等规模网站）
CREATE TABLE articles (
    id          MEDIUMINT UNSIGNED NOT NULL AUTO_INCREMENT,
    title       VARCHAR(200) NOT NULL,
    view_count  MEDIUMINT UNSIGNED NOT NULL DEFAULT 0,
    PRIMARY KEY (id)
);

INSERT INTO cities (city_name, population) VALUES ('成都', 2100), ('深圳', 1763), ('武汉', 1365);
INSERT INTO articles (title, view_count) VALUES ('MySQL 入门指南', 125000), ('Redis 实践', 88000);
```

## 与相邻类型的存储对比

| 类型 | 存储 | 有符号上限 | 无符号上限 |
|------|------|----------|----------|
| SMALLINT | 2 字节 | 32767 | 65535 |
| MEDIUMINT | 3 字节 | 8388607 | 16777215 |
| INT | 4 字节 | 2147483647 | 4294967295 |

MEDIUMINT 比 INT 少 1 个字节（25% 节省），但上限差了约 128 倍（1677 万 vs 21 亿）。

---

## 适用场景

- **中等规模的自增 ID**：如果业务表数据量在千万级别以内，MEDIUMINT UNSIGNED 作为主键比 INT 少 1 字节，在大表中有存储意义
- **人口统计**：城市人口（千级/万级），MEDIUMINT UNSIGNED 覆盖范围足够
- **网站浏览计数**：中小型网站的文章浏览量、点赞数等，通常不超过 1677 万
- **地区代码**：某些标准中的地区代码或邮政编码数值形式
- **MyISAM 引擎的行数限制**：早期 MySQL 的 MyISAM 表，三字节的行指针限制单表为 1677 万行，MEDIUMINT 与之对应

## 常见问题

**为什么生产中很少见到 MEDIUMINT？**

主要原因有两个：其一，INT 只多 1 字节，但范围从 1677 万增加到了 21 亿，这种范围扩展在大多数场景下值得付出 1 字节的代价；其二，很多开发者对类型选择没有精细计算习惯，直接用 INT/BIGINT 更省心。MEDIUMINT 的使用场景比较特定，在需要精确控制存储空间且数据量在千万级别以下的表中才有明显价值。

**MEDIUMINT 作为主键，表有多少行数据时会不够用？**

无符号 MEDIUMINT 上限是 16777215，约 1677 万。如果表的行数可能超过 1677 万，应该使用 INT UNSIGNED（约 42 亿上限）或 BIGINT UNSIGNED。

---

## 注意事项

- MEDIUMINT 是 MySQL 扩展类型，其他数据库（如 PostgreSQL、SQL Server）没有对应类型，如果将来需要数据库迁移，MEDIUMINT 类型可能需要转换为 INT。
- 在内存中，MySQL 通常将 MEDIUMINT 按 4 字节对齐处理（取决于操作系统和存储引擎实现），磁盘上存储节省 1 字节，但内存中的好处可能没有预期的那么大。

---

## 总结

MEDIUMINT 占用 3 字节，有符号范围约 ±838 万，无符号最大值约 1677 万。它在 SMALLINT 和 INT 之间提供了一个额外选择，在数据量在千万级别以内、对存储空间有精细要求的场景下有使用价值。但在大多数通用场景中，直接使用 INT 更为普遍，因为范围更大而代价只是多了 1 个字节。
