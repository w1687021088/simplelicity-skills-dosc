## DATE 日期类型

DATE 是 MySQL 中专门用于存储日期（年月日）的类型，不包含时间信息。它占用 3 字节，范围从 1000-01-01 到 9999-12-31，能满足绝大多数业务中的日期记录需求。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 存储空间 | 3 字节 |
| 日期范围 | 1000-01-01 ~ 9999-12-31 |
| 显示格式 | YYYY-MM-DD |
| 不含时间 | 没有时、分、秒信息 |
| 时区敏感 | 否（纯日期，不涉及时区）|

---

### 语法

```sql
column_name DATE
column_name DATE NOT NULL
column_name DATE DEFAULT '2026-01-01'
column_name DATE DEFAULT (CURRENT_DATE)  -- MySQL 8.0.13+ 支持表达式默认值
```

### 创建示例

```sql
-- 人员信息（出生日期）
CREATE TABLE persons (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name        VARCHAR(100) NOT NULL,
    birth_date  DATE NOT NULL COMMENT '出生日期',
    join_date   DATE NOT NULL DEFAULT (CURRENT_DATE) COMMENT '入职日期',
    PRIMARY KEY (id)
);

-- 节假日安排
CREATE TABLE holidays (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    holiday_date DATE NOT NULL,
    name        VARCHAR(100) NOT NULL COMMENT '节日名称',
    PRIMARY KEY (id),
    UNIQUE KEY uk_date (holiday_date)
);

-- 财务账期
CREATE TABLE accounting_periods (
    period_id   INT UNSIGNED NOT NULL AUTO_INCREMENT,
    start_date  DATE NOT NULL,
    end_date    DATE NOT NULL,
    is_closed   TINYINT UNSIGNED NOT NULL DEFAULT 0,
    PRIMARY KEY (period_id)
);

INSERT INTO persons (name, birth_date) VALUES ('张三', '1990-05-15');
INSERT INTO holidays (holiday_date, name) VALUES ('2026-01-01', '元旦'), ('2026-02-17', '春节');
```

### DATE 的输入格式

MySQL 接受多种日期输入格式：

```sql
-- 标准格式（推荐）
INSERT INTO persons (name, birth_date) VALUES ('李四', '1995-12-25');

-- 无分隔符格式
INSERT INTO persons (name, birth_date) VALUES ('王五', '19951225');

-- 其他分隔符（/ 或 .）
INSERT INTO persons (name, birth_date) VALUES ('赵六', '1995/12/25');
INSERT INTO persons (name, birth_date) VALUES ('孙七', '1995.12.25');

-- 两位年份（不推荐，70-99 映射到 1970-1999，00-69 映射到 2000-2069）
INSERT INTO persons (name, birth_date) VALUES ('周八', '95-12-25');  -- 解析为 1995-12-25
INSERT INTO persons (name, birth_date) VALUES ('吴九', '26-01-01');  -- 解析为 2026-01-01
```

###  DATE 的常用操作

```sql
-- 计算年龄
SELECT name, 
       birth_date,
       TIMESTAMPDIFF(YEAR, birth_date, CURDATE()) AS age
FROM persons;

-- 计算日期差（天数）
SELECT DATEDIFF('2026-12-31', '2026-01-01') AS days_in_year;  -- 364

-- 日期加减
SELECT DATE_ADD('2026-01-01', INTERVAL 30 DAY) AS plus_30_days;   -- 2026-01-31
SELECT DATE_SUB('2026-03-01', INTERVAL 1 MONTH) AS minus_1_month; -- 2026-02-01

-- 提取日期部分
SELECT birth_date,
       YEAR(birth_date)   AS year_part,
       MONTH(birth_date)  AS month_part,
       DAY(birth_date)    AS day_part,
       DAYOFWEEK(birth_date) AS weekday  -- 1=周日,2=周一,...,7=周六
FROM persons;

-- 日期格式化输出
SELECT DATE_FORMAT(birth_date, '%Y年%m月%d日') AS formatted FROM persons;
-- 输出：1990年05月15日

-- 范围查询
SELECT * FROM persons WHERE birth_date BETWEEN '1990-01-01' AND '1999-12-31';

-- 当月的所有记录
SELECT * FROM holidays 
WHERE YEAR(holiday_date) = 2026 AND MONTH(holiday_date) = 2;

-- 更高效的月份范围查询（避免在列上使用函数，允许走索引）
SELECT * FROM holidays 
WHERE holiday_date >= '2026-02-01' AND holiday_date < '2026-03-01';
```

### 适用场景

- **生日、入职日期、合同到期日**：只需要年月日，不需要时间
- **日历事件、节假日**：记录具体日期
- **财务账期**：会计期间的开始和结束日期
- **统计报表日期**：每日/每月/每年的汇总报表的日期维度
- **生效日期/失效日期**：优惠券有效期、政策生效日等

### 常见问题

**DATE 和 DATETIME 哪个更适合存生日？**

生日用 DATE，不需要时间部分，DATETIME 会多占用 5 字节（8字节 vs 3字节）且存储了无意义的时间信息（通常是 00:00:00）。

**为什么 DATE 列上用函数（如 YEAR(birth_date)=1990）会导致索引失效？**

在列上使用函数会让优化器无法直接用该列的索引，需要对每行计算函数值后再过滤。改为范围查询（`birth_date >= '1990-01-01' AND birth_date < '1991-01-01'`）可以让索引生效。

**DATE 是否会受时区设置影响？**

不会，DATE 只存储年月日，不涉及时间和时区。TIMESTAMP 列才受时区影响。

---

### 注意事项

- 两位年份输入（如 `26-01-01`）会被 MySQL 按规则解析（70~99→1970~1999，00~69→2000~2069），有歧义，应始终使用四位年份。
- 无效日期（如 `2026-02-30`、`2026-13-01`）在严格 SQL 模式下会报错，在非严格模式下会被存储为 `0000-00-00`（无效日期）。

---

### 总结

DATE 是纯日期类型，占用 3 字节，范围 1000-01-01 到 9999-12-31，格式为 YYYY-MM-DD。适合存储不需要时间部分的日期字段（生日、入职日、节假日等）。日期列上的索引在范围查询时效率最高，应避免在列上直接使用函数，改用等效的范围条件。
