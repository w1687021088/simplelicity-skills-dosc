## 日期时间字面量与自动初始化

日期时间字面量是 SQL 中表示日期时间值的写法，MySQL 接受多种格式的字面量输入。自动初始化和自动更新则是 DATETIME/TIMESTAMP 列的重要特性，让 `created_at` 和 `updated_at` 字段无需应用层干预就能自动维护。

---

### 日期时间字面量格式

MySQL 接受多种写法表示日期时间值：

```sql
-- 日期字面量（DATE）
'2026-03-15'          -- 标准格式，推荐
'2026/03/15'          -- 斜线分隔
'2026.03.15'          -- 点号分隔
'20260315'            -- 无分隔符
DATE '2026-03-15'     -- ODBC 风格（标准 SQL）

-- 时间字面量（TIME）
'14:30:00'            -- 标准格式，推荐
'14:30'               -- 省略秒，默认为 00
'143000'              -- 无分隔符（HHMMSS）
TIME '14:30:00'       -- ODBC 风格

-- 日期时间字面量（DATETIME/TIMESTAMP）
'2026-03-15 14:30:00'           -- 标准格式，推荐
'2026-03-15T14:30:00'           -- ISO 8601 格式（MySQL 8.0 支持 T 分隔符）
'20260315143000'                -- 无分隔符（YYYYMMDDHHMMSS）
'2026-03-15 14:30:00.123456'    -- 含小数秒
TIMESTAMP '2026-03-15 14:30:00' -- ODBC 风格
```

---

### 字面量的隐式类型转换

```sql
-- 字符串与日期比较时，字符串会被自动转换为日期
SELECT * FROM orders WHERE created_at >= '2026-03-01';
-- 等价于
SELECT * FROM orders WHERE created_at >= DATE '2026-03-01';

-- 注意：字符串格式错误时不会报错，而是被转为 0
SELECT '2026-99-99' + INTERVAL 0 DAY;  -- 结果：NULL（非法日期）

-- 用 STR_TO_DATE 明确指定格式（更安全）
SELECT STR_TO_DATE('15/03/2026', '%d/%m/%Y') AS parsed_date;
-- 输出：2026-03-15

SELECT STR_TO_DATE('2026年03月15日', '%Y年%m月%d日') AS parsed;
-- 输出：2026-03-15
```

### 自动初始化（DEFAULT CURRENT_TIMESTAMP）

```sql
-- 在 DATETIME 列上使用自动初始化
CREATE TABLE articles (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    title       VARCHAR(200) NOT NULL,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,  -- 插入时自动填入当前时间
    PRIMARY KEY (id)
);

-- 插入时不指定 created_at，自动填充
INSERT INTO articles (title) VALUES ('MySQL 8.4 入门');
SELECT id, title, created_at FROM articles;
-- created_at: 2026-03-15 14:30:00（自动填入）

-- 显式指定 DEFAULT 值
INSERT INTO articles (title, created_at) VALUES ('指定时间', '2026-01-01 00:00:00');
```

### 自动更新（ON UPDATE CURRENT_TIMESTAMP）

```sql
-- 创建带自动更新的表
CREATE TABLE posts (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    title       VARCHAR(200) NOT NULL,
    content     TEXT,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id)
);

-- 插入时两个时间字段均自动填充为当前时间
INSERT INTO posts (title) VALUES ('第一篇文章');

-- 更新时，updated_at 自动刷新为当前时间，created_at 不变
UPDATE posts SET title = '更新后的标题' WHERE id = 1;

-- 查看结果
SELECT id, title, created_at, updated_at FROM posts;
-- created_at: 2026-03-15 10:00:00（保持不变）
-- updated_at: 2026-03-15 10:05:30（自动更新）
```

###  同一表中多个自动时间列

在 MySQL 8.0.13 之后，一张表中可以有多个带 `DEFAULT CURRENT_TIMESTAMP` 或 `ON UPDATE CURRENT_TIMESTAMP` 的 DATETIME 列（之前版本只允许一个 TIMESTAMP 列有这个特性）：

```sql
-- MySQL 8.0.13+ 支持多个 DATETIME 列有自动时间特性
CREATE TABLE audit_table (
    id                  INT UNSIGNED NOT NULL AUTO_INCREMENT,
    data                VARCHAR(500),
    created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    first_modified_at   DATETIME,  -- 手动维护
    last_modified_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id)
);
```

### 使用表达式作为 DEFAULT 值（MySQL 8.0.13+）

```sql
-- MySQL 8.0.13 开始，DEFAULT 支持表达式（用括号包裹）
CREATE TABLE tasks (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    title       VARCHAR(200) NOT NULL,
    created_at  DATE NOT NULL DEFAULT (CURRENT_DATE),     -- 日期表达式默认值
    due_date    DATE NOT NULL DEFAULT (CURRENT_DATE + INTERVAL 7 DAY),  -- 7天后到期
    PRIMARY KEY (id)
);

-- 插入时自动计算默认值
INSERT INTO tasks (title) VALUES ('完成报告');
SELECT * FROM tasks;
-- created_at: 2026-03-15（今天）
-- due_date:   2026-03-22（7天后）
```

### 日期时间字面量的注意事项

```sql
-- 'YYYYMMDDHHMMSS' 格式的歧义风险
INSERT INTO events (event_at) VALUES ('20260315');
-- MySQL 将其解析为 DATE '2026-03-15'（14 位以下当日期）
-- 如果列是 DATETIME，会被解析为 '2026-03-15 00:00:00'

-- 建议始终使用标准格式 'YYYY-MM-DD HH:MM:SS'，避免歧义
```

### 常见问题

**`DEFAULT CURRENT_TIMESTAMP` 和 `DEFAULT NOW()` 有区别吗？**

在建表语句中，`CURRENT_TIMESTAMP`、`NOW()`、`CURRENT_TIMESTAMP()` 是等价的，都表示当前时间。在 MySQL 8.0.13+ 中，使用函数作为 DEFAULT 时需要用括号括起来：`DEFAULT (NOW())`。

**`ON UPDATE CURRENT_TIMESTAMP` 在 UPDATE 语句没有修改列值时会触发吗？**

不会。只有当 UPDATE 语句实际修改了行中至少一列的值时，`ON UPDATE` 才会触发刷新时间戳。如果 UPDATE 语句写了条件但没有匹配到任何行，或者赋的值和原值相同，`updated_at` 不会变化。

---

### 适用场景

- `created_at DATETIME DEFAULT CURRENT_TIMESTAMP`：所有需要记录创建时间的表都应该有这个字段
- `updated_at DATETIME ON UPDATE CURRENT_TIMESTAMP`：需要追踪最后修改时间的业务表
- 表达式默认值（MySQL 8.0.13+）：自动计算到期时间、截止日期等业务相关时间默认值

---

### 注意事项

- 在应用层不要同时手动维护 `updated_at`——如果数据库已经有 `ON UPDATE CURRENT_TIMESTAMP`，应用层的手动赋值和数据库的自动赋值可能产生冲突。
- 字面量格式不标准（如月份超出范围）在严格 SQL 模式下会报错，非严格模式下存为 `0000-00-00 00:00:00`。建议始终在严格模式下运行。

---

### 总结

MySQL 接受多种日期时间字面量格式，推荐标准格式 `'YYYY-MM-DD HH:MM:SS'`。自动初始化（`DEFAULT CURRENT_TIMESTAMP`）和自动更新（`ON UPDATE CURRENT_TIMESTAMP`）是 DATETIME/TIMESTAMP 列的核心便利特性，适合 `created_at` 和 `updated_at` 字段。MySQL 8.0.13+ 支持表达式类型的 DEFAULT 值，可以计算相对于当前时间的日期默认值。
