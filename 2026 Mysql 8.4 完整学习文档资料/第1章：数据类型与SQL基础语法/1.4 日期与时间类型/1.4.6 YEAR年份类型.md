## YEAR 年份类型

YEAR 是 MySQL 中专门存储年份的类型，占用 1 字节，只能存储 1901 到 2155 年的四位年份值。它是所有日期类型中存储空间最小的，适合只需要记录年份的场景。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 存储空间 | 1 字节 |
| 有效范围 | 1901 ~ 2155，以及 0000 |
| 显示格式 | YYYY（四位年份）|
| 两位输入 | 00~69 解析为 2000~2069，70~99 解析为 1970~1999 |

---

### 语法

```sql
column_name YEAR
column_name YEAR NOT NULL DEFAULT 2026
```

注意：`YEAR(4)` 在 MySQL 8.0.19 后已废弃，直接使用 `YEAR` 即可（只支持四位年份格式）。

---

### 创建示例

```sql
-- 版本发布年份
CREATE TABLE software_versions (
    id              INT UNSIGNED NOT NULL AUTO_INCREMENT,
    software_name   VARCHAR(100) NOT NULL,
    version         VARCHAR(50) NOT NULL,
    release_year    YEAR NOT NULL COMMENT '发布年份',
    PRIMARY KEY (id)
);

-- 电影年份
CREATE TABLE movies (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    title       VARCHAR(200) NOT NULL,
    release_year YEAR NOT NULL COMMENT '上映年份',
    PRIMARY KEY (id)
);

-- 学生入学年份
CREATE TABLE students (
    id              INT UNSIGNED NOT NULL AUTO_INCREMENT,
    name            VARCHAR(100) NOT NULL,
    enrollment_year YEAR NOT NULL COMMENT '入学年份',
    PRIMARY KEY (id)
);

INSERT INTO movies (title, release_year) VALUES ('阿凡达', 2009), ('流浪地球2', 2023);
INSERT INTO software_versions (software_name, version, release_year) 
VALUES ('MySQL', '8.4.0', 2024);
INSERT INTO students (name, enrollment_year) VALUES ('张三', 2026);
```

### 两位年份的解析规则

```sql
-- 输入 00~69 → 2000~2069
INSERT INTO movies (title, release_year) VALUES ('测试1', 26);   -- 存储为 2026
INSERT INTO movies (title, release_year) VALUES ('测试2', 69);   -- 存储为 2069

-- 输入 70~99 → 1970~1999
INSERT INTO movies (title, release_year) VALUES ('测试3', 70);   -- 存储为 1970
INSERT INTO movies (title, release_year) VALUES ('测试4', 99);   -- 存储为 1999

-- 0 或 '00' 存储为 0000
INSERT INTO movies (title, release_year) VALUES ('测试5', 0);    -- 存储为 0000
-- 字符串 '0' 也存储为 0000
```

### YEAR 的常用操作

```sql
-- 查询特定年份
SELECT * FROM movies WHERE release_year = 2023;

-- 查询某个年份范围
SELECT * FROM movies WHERE release_year BETWEEN 2010 AND 2023;

-- 按年份分组统计
SELECT release_year, COUNT(*) AS movie_count 
FROM movies 
GROUP BY release_year 
ORDER BY release_year DESC;

-- 查询今年的记录
SELECT * FROM software_versions WHERE release_year = YEAR(CURDATE());

-- 计算距今年数
SELECT title, release_year, YEAR(CURDATE()) - release_year AS years_since_release
FROM movies
ORDER BY release_year;
```

### YEAR 与 SMALLINT 的对比

有时会用 `SMALLINT UNSIGNED` 存储年份，两者各有优劣：

| 对比维度 | YEAR | SMALLINT UNSIGNED |
|---------|------|-----------------|
| 存储空间 | 1 字节 | 2 字节 |
| 有效范围 | 1901~2155 | 0~65535 |
| 输入验证 | MySQL 自动验证 | 需要应用层验证 |
| 两位年份解析 | 支持（有歧义）| 不支持 |
| 超出范围处理 | 严格模式下报错 | 只要在整数范围内就接受 |

对于严格记录年份（需要验证合法性）的场景，YEAR 更合适；对于需要存储超出 1901~2155 范围（如年龄计算中的辅助字段）或需要算术运算的场景，SMALLINT 更灵活。

### 适用场景

- **电影/书籍/音乐出版年份**：只关心年份，不需要月日
- **学年/入学年份**：高校学生、员工入职年份
- **软件版本年份**：记录发布的年份
- **数据分区键**：按年份分区的表（配合 RANGE 分区）
- **年龄层分析**：出生年份用于年龄段统计

### 常见问题

**YEAR 能直接和整数比较吗？**

可以。MySQL 会自动将 YEAR 值转为整数进行比较：

```sql
SELECT * FROM movies WHERE release_year > 2020;  -- 正常工作
SELECT * FROM movies WHERE release_year + 1 = 2024;  -- 也可以
```

**YEAR 列能建索引吗？**

可以，YEAR 列支持 B-Tree 索引，适合范围查询和等值查询。

---

### 注意事项

- 插入整数 `0` 或字符串 `'00'` 会存储为 `0000`（一个特殊的"零年份"），而不是 2000。如果需要存储 2000 年，应该明确传入整数 `2000` 或字符串 `'2000'`。
- `YEAR(4)` 已废弃（MySQL 8.0.19+），只需使用 `YEAR`。
- YEAR 的上限是 2155，对于需要存储 2156 年以后的场景，需改用 SMALLINT 或 INT。

---

### 总结

YEAR 是 MySQL 中最小的日期类型，仅占 1 字节，有效范围 1901~2155。它适合只需要记录年份的场景，如电影发行年、入学年份、出版年份等。使用时需注意两位年份的解析规则（00~69→2000~2069，70~99→1970~1999）以及整数 0 会被存储为 0000 而非 2000。
