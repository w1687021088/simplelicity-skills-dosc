## DATETIME 日期时间类型

DATETIME 是 MySQL 中存储完整日期和时间（年月日时分秒）的标准类型，占用 5 字节，支持微秒精度。它不受时区设置影响，写入什么就存什么，适合存储与时区无关或需要保持原始时间不变的场景。

---

### 基本特性

| 属性 | 值 |
|------|---|
| 存储空间 | 5 字节（不含小数秒）|
| 日期范围 | 1000-01-01 00:00:00 ~ 9999-12-31 23:59:59 |
| 显示格式 | YYYY-MM-DD HH:MM:SS |
| 小数秒 | 支持，DATETIME(fsp) 中 fsp=0~6 |
| 时区敏感 | 否（存储值不随时区设置变化）|

---

### 语法

```sql
column_name DATETIME
column_name DATETIME(fsp)   -- fsp: 0~6，小数秒精度
column_name DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
column_name DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

### 创建示例

```sql
-- 用户操作日志
CREATE TABLE user_actions (
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id     INT UNSIGNED NOT NULL,
    action      VARCHAR(100) NOT NULL,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    INDEX idx_user_time (user_id, created_at)
);

-- 订单表（带自动更新时间）
CREATE TABLE orders (
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id     INT UNSIGNED NOT NULL,
    amount      DECIMAL(10, 2) NOT NULL,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id)
);

-- 预约表（精确到分钟）
CREATE TABLE appointments (
    id              INT UNSIGNED NOT NULL AUTO_INCREMENT,
    patient_id      INT UNSIGNED NOT NULL,
    appointment_at  DATETIME NOT NULL COMMENT '预约时间',
    PRIMARY KEY (id)
);

-- 精确计时（微秒级）
CREATE TABLE performance_metrics (
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    metric_name VARCHAR(100) NOT NULL,
    recorded_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) COMMENT '微秒精度时间戳',
    value       DOUBLE NOT NULL,
    PRIMARY KEY (id)
);

INSERT INTO user_actions (user_id, action) VALUES (1001, 'login');
```

### 常用操作

```sql
-- 查询时间范围内的记录
SELECT * FROM orders 
WHERE created_at >= '2026-03-01 00:00:00' AND created_at < '2026-04-01 00:00:00';

-- 按日期分组统计（按天）
SELECT DATE(created_at) AS order_date, COUNT(*) AS order_count, SUM(amount) AS total
FROM orders
GROUP BY DATE(created_at)
ORDER BY order_date;

-- 按小时统计
SELECT HOUR(created_at) AS hour_of_day, COUNT(*) AS count
FROM user_actions
WHERE created_at >= NOW() - INTERVAL 24 HOUR
GROUP BY HOUR(created_at);

-- 计算时间差
SELECT TIMESTAMPDIFF(MINUTE, created_at, NOW()) AS minutes_ago FROM orders WHERE id = 1;
SELECT TIMESTAMPDIFF(DAY, '2026-01-01 00:00:00', '2026-12-31 23:59:59') AS days;

-- 格式化输出
SELECT DATE_FORMAT(created_at, '%Y-%m-%d %H:%i') AS formatted FROM orders LIMIT 5;
-- 输出：2026-03-14 10:30

-- 日期时间运算
SELECT NOW() + INTERVAL 7 DAY AS one_week_later;
SELECT NOW() - INTERVAL 30 MINUTE AS half_hour_ago;
```

### DEFAULT CURRENT_TIMESTAMP 与 ON UPDATE

```sql
-- 插入时自动填充当前时间，更新时自动更新时间
CREATE TABLE articles (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    title       VARCHAR(200) NOT NULL,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,           -- 创建时填充
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,  -- 更新时刷新
    PRIMARY KEY (id)
);

-- 插入：created_at 和 updated_at 都自动填充为当前时间
INSERT INTO articles (title) VALUES ('MySQL 8.4 新特性');

-- 更新：updated_at 自动刷新，created_at 不变
UPDATE articles SET title = '【更新】MySQL 8.4 新特性详解' WHERE id = 1;
```

### 适用场景

- **业务创建时间、修改时间**：`created_at`、`updated_at` 是最典型的使用场景
- **预约、排班时间**：需要记录具体日期和时间的业务节点
- **日志时间戳**：记录事件发生的精确时间
- **与时区无关的时间**：如"北京时间 2026-03-15 10:00 开始"这种时间，不应该因为查询的时区不同而显示不同值

### 常见问题

**DATETIME 和 TIMESTAMP 的最大区别是什么？**

最主要的区别是时区处理和存储范围：DATETIME 不受时区影响，存什么显示什么，范围到 9999 年；TIMESTAMP 在存储时自动转为 UTC，检索时自动转回当前时区，但范围只到 2038 年（32位 Unix 时间戳上限）。详见 1.4.5 文档。

**DATETIME 可以索引吗？**

可以，DATETIME 列支持 B-Tree 索引，范围查询（BETWEEN、>、<）能用到索引，效率良好。应避免在列上使用 DATE()、YEAR()、MONTH() 等函数后再比较，这会导致索引失效。

**能对 DATETIME 做毫秒/微秒精度操作吗？**

MySQL 8.0 起，`DATETIME(fsp)` 支持 0~6 位小数秒：`DATETIME(3)` 到毫秒，`DATETIME(6)` 到微秒。`CURRENT_TIMESTAMP(6)` 返回微秒精度的当前时间。

---

### 注意事项

- DATETIME 类型在 `DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` 行为中，只有真正发生更新（修改了行中至少一列的值）时才会刷新 `updated_at`，如果 UPDATE 语句没有改变任何值，`updated_at` 不会刷新。
- 在存储应用服务器时间还是数据库时间时，推荐用 `DEFAULT CURRENT_TIMESTAMP` 让数据库填充时间，而不是由应用层传入时间字符串，这样时间的一致性更可靠。
- 跨时区的分布式系统中，如果需要多地区统一的时间基准，TIMESTAMP（以 UTC 存储）比 DATETIME 更合适。

---

### 总结

DATETIME 是最常用的日期时间类型，占用 5 字节，范围 1000-01-01 到 9999-12-31。它存储写入时的原始时间值，不受时区影响。支持 `DEFAULT CURRENT_TIMESTAMP` 和 `ON UPDATE CURRENT_TIMESTAMP` 自动时间管理。业务表中的 `created_at`、`updated_at` 字段是 DATETIME 最典型的使用场景。
