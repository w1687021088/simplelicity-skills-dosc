# UNION ALL 结果集合并（保留重复）

`UNION ALL` 将多个 SELECT 的结果集直接合并，不进行任何去重处理，所有行原样保留（包括完全相同的重复行）。因为省去了去重的排序或哈希计算，UNION ALL 比 UNION 性能更好，是实际工作中更常用的选择。

---

## 语法

```sql
SELECT col1, col2 FROM tbl1
UNION ALL
SELECT col1, col2 FROM tbl2
[ORDER BY ...]
[LIMIT n];
```

---

## 基本示例

```sql
-- 合并当前订单和归档订单（两者没有重复行，用 UNION ALL 更高效）
SELECT id, user_id, amount, created_at FROM orders_current
UNION ALL
SELECT id, user_id, amount, created_at FROM orders_archive
ORDER BY created_at DESC
LIMIT 100;

-- 合并不同渠道的销售记录
SELECT 'online' AS channel, amount, created_at FROM online_orders
UNION ALL
SELECT 'offline' AS channel, amount, created_at FROM offline_orders
ORDER BY created_at;

-- 比较：UNION（去重）vs UNION ALL（保留重复）
SELECT val FROM t1 UNION SELECT val FROM t2;     -- 去重
SELECT val FROM t1 UNION ALL SELECT val FROM t2; -- 保留所有
```

---

## UNION ALL 用于统计汇总（WITH ROLLUP 效果）

```sql
-- 生成包含小计和总计行的报表
SELECT dept_id, SUM(salary) AS total
FROM employees GROUP BY dept_id
UNION ALL
SELECT NULL, SUM(salary) FROM employees;   -- 追加一行总计

-- 也可以通过 GROUP BY ... WITH ROLLUP 实现，但 UNION ALL 更灵活
```

---

## UNION ALL 作为 CTE 的输入（累计计算等）

```sql
-- UNION ALL 在递归 CTE 中是必须的（详见 1.9.18）
WITH RECURSIVE numbers AS (
    SELECT 1 AS n
    UNION ALL                        -- 必须用 UNION ALL，不能用 UNION
    SELECT n + 1 FROM numbers WHERE n < 10
)
SELECT * FROM numbers;
```

## UNION vs UNION ALL 对比

| 对比维度 | UNION | UNION ALL |
|---------|-------|-----------|
| 去重 | 是（自动）| 否（保留所有行）|
| 性能开销 | 高（需排序/哈希去重）| 低（直接合并）|
| 结果行数 | <= 各 SELECT 行数之和 | = 各 SELECT 行数之和 |
| 适用场景 | 需要去重时 | 确定无重复或需要保留重复时 |
| 推荐度 | 谨慎使用（有明确去重需求时）| 优先使用（明确不需要去重时）|

---

## 适用场景

- **分表合并查询**：按年/月分表后，将多个分表的数据合并为统一视图
- **报表汇总行**：在查询结果末尾追加合计行
- **日志流合并**：将多个来源的日志记录合并到一个时间线
- **递归 CTE 的递归部分**：递归 CTE 的语法要求必须使用 UNION ALL

---

## 常见问题

**什么时候必须用 UNION 而不是 UNION ALL？**

只有在两个或多个 SELECT 的结果集可能存在完全相同的行，并且业务上要求去除这些重复行时，才使用 UNION。如果设计上保证各部分数据无重复（如不同分表，主键不重叠），或者业务上允许/需要重复行，都应该用 UNION ALL。

---

## 注意事项

- 在不确定是否需要去重的情况下，先分析数据特征，确定后再决定用 UNION 还是 UNION ALL。使用 UNION 进行不必要的去重会浪费计算资源。
- 各个 SELECT 的列数必须一致，列类型应该兼容。如果某个 SELECT 缺少某列，用 `NULL AS col_name` 或字面量填充。

---

## 总结

`UNION ALL` 直接合并多个 SELECT 的结果，不去重，性能优于 `UNION`。在分表查询合并、报表追加汇总行、递归 CTE 等场景中是首选。只有确实需要去重时才使用 `UNION`。实际工作中，优先考虑 UNION ALL，在数据特征确认有重复且需要去除时再改为 UNION。
