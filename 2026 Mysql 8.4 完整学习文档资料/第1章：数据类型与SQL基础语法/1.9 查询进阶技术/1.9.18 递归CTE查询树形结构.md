# 递归 CTE 查询树形结构

递归 CTE（Recursive CTE）是 MySQL 8.0 引入的功能，通过 `WITH RECURSIVE` 语法实现自引用查询，特别适合处理层级结构数据（如组织架构、商品分类、评论回复树等）——这类数据的层级深度不固定，无法用普通的自连接处理。

---

## 语法

```sql
WITH RECURSIVE cte_name AS (
    -- 锚点成员（初始查询，不引用 CTE 自身）
    SELECT init_col FROM tbl WHERE init_condition
    
    UNION ALL  -- 必须是 UNION ALL，不能是 UNION
    
    -- 递归成员（引用 CTE 自身，每次迭代向下展开一层）
    SELECT t.col FROM tbl t
    INNER JOIN cte_name c ON t.parent_key = c.primary_key
    -- 可以加终止条件（WHERE depth < 最大深度）
)
SELECT * FROM cte_name;
```

递归执行过程：
1. 执行锚点成员，得到初始结果集
2. 将初始结果作为 CTE 的当前值，执行递归成员（以 CTE 自身为输入）
3. 递归成员的输出追加到结果集，再次作为 CTE 的当前值
4. 直到递归成员返回空集（没有新行），递归终止

## 场景1：查询组织架构（向下展开所有层级）

```sql
CREATE TABLE employees (
    id         INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    name       VARCHAR(100) NOT NULL,
    manager_id INT UNSIGNED DEFAULT NULL
);
INSERT INTO employees VALUES
    (1, '张总', NULL), (2, '李总监', 1), (3, '王总监', 1),
    (4, '张三', 2), (5, '李四', 2), (6, '王五', 3);

-- 查询张总（id=1）的所有下属（全部层级）
WITH RECURSIVE subordinates AS (
    -- 锚点：从 id=1 的张总开始
    SELECT id, name, manager_id, 0 AS depth
    FROM employees WHERE id = 1
    
    UNION ALL
    
    -- 递归：找到以当前结果为上级的员工
    SELECT e.id, e.name, e.manager_id, s.depth + 1
    FROM employees e
    INNER JOIN subordinates s ON e.manager_id = s.id
)
SELECT id, name, depth,
    REPEAT('  ', depth) || name AS hierarchy_display  -- 用缩进展示层级
FROM subordinates
ORDER BY depth, id;

-- 结果：
-- id | name   | depth | display
--  1 | 张总   |   0   | 张总
--  2 | 李总监 |   1   |   李总监
--  3 | 王总监 |   1   |   王总监
--  4 | 张三   |   2   |     张三
--  5 | 李四   |   2   |     李四
--  6 | 王五   |   2   |     王五
```

## 场景2：查询路径（从叶子节点向上追溯）

```sql
-- 查询某员工的完整上级路径（从叶子到根）
WITH RECURSIVE ancestors AS (
    SELECT id, name, manager_id, CAST(name AS CHAR(500)) AS path
    FROM employees WHERE id = 4  -- 从张三开始
    
    UNION ALL
    
    SELECT e.id, e.name, e.manager_id,
           CONCAT(e.name, ' > ', a.path) AS path  -- 每次往上追加一级
    FROM employees e
    INNER JOIN ancestors a ON e.id = a.manager_id
)
SELECT path FROM ancestors ORDER BY id DESC LIMIT 1;
-- 结果：张总 > 李总监 > 张三
```

## 场景3：生成数字序列

```sql
-- 生成 1~100 的整数序列（实用工具）
WITH RECURSIVE nums AS (
    SELECT 1 AS n
    UNION ALL
    SELECT n + 1 FROM nums WHERE n < 100
)
SELECT * FROM nums;

-- 生成日期序列（最近 30 天）
WITH RECURSIVE dates AS (
    SELECT CURDATE() - INTERVAL 29 DAY AS dt
    UNION ALL
    SELECT dt + INTERVAL 1 DAY FROM dates WHERE dt < CURDATE()
)
SELECT dt FROM dates;
-- 用途：与业务表 LEFT JOIN，生成完整的日期维度（没有数据的日期显示 0）
```

## 防止无限递归

```sql
-- 设置递归最大迭代次数（防止数据中有环导致无限递归）
SHOW VARIABLES LIKE 'cte_max_recursion_depth';
-- 默认值：1000

-- 修改当前会话的最大递归深度
SET SESSION cte_max_recursion_depth = 100;

-- 在递归成员中加深度限制（更安全）
WITH RECURSIVE tree AS (
    SELECT id, parent_id, 0 AS depth FROM categories WHERE parent_id IS NULL
    UNION ALL
    SELECT c.id, c.parent_id, t.depth + 1
    FROM categories c
    INNER JOIN tree t ON c.parent_id = t.id
    WHERE t.depth < 10  -- 最多展开 10 层，防止无限递归
)
SELECT * FROM tree;
```

## 适用场景

- **组织架构**：查询某人所有下属、某人完整上级路径
- **商品/内容分类树**：展开所有子分类、获取完整面包屑路径
- **评论回复树**：获取某评论的所有回复（多级嵌套）
- **生成序列**：数字序列、日期序列（填充缺失维度数据）

---

## 常见问题

**递归 CTE 的锚点和递归成员之间为什么必须用 UNION ALL？**

递归成员每次迭代只处理"上一次迭代的结果"，如果用 UNION 去重，会与之前所有迭代的结果进行去重，不仅性能极差，而且语义也不正确（树形结构中确实可能有相同内容的节点）。UNION ALL 直接追加，才是正确的递归语义。

---

## 注意事项

- 如果数据中存在循环引用（如 A 的上级是 B，B 的上级是 A），递归 CTE 会无限循环直到触发 `cte_max_recursion_depth` 限制。生产数据应在约束层面防止循环引用，或在递归成员中加入深度限制条件。
- 递归成员中不能使用聚合函数、GROUP BY、HAVING、DISTINCT、LIMIT 等，这些只能用在最外层的主查询中。

---

## 总结

递归 CTE 用 `WITH RECURSIVE` 声明，由锚点成员（初始集合）和递归成员（每次迭代）组成，两者用 UNION ALL 连接。递归在没有新行产生时自动终止。适合处理深度不固定的层级数据（组织架构、分类树、路径追溯）和生成序列数据。通过深度限制条件或 `cte_max_recursion_depth` 参数防止无限递归。
