# CTE 公用表表达式（WITH 子句）

公用表表达式（Common Table Expression，CTE）是用 `WITH` 关键字定义的命名临时结果集，可以在后续的主查询中像普通表一样引用。CTE 让复杂查询的结构更清晰，可以在同一个查询中多次引用，还支持递归查询（详见 1.9.18）。

---

## 语法

```sql
WITH cte_name [(col1, col2, ...)] AS (
    SELECT ...
),
cte_name2 AS (
    SELECT ... FROM cte_name ...  -- 后面的 CTE 可以引用前面的 CTE
)
SELECT ...
FROM cte_name
[JOIN cte_name2 ...]
[WHERE ...];
```

---

## 基本示例

```sql
-- 不用 CTE（嵌套子查询，难以阅读）
SELECT u.id, u.username, t.total_amount
FROM users u
INNER JOIN (
    SELECT user_id, SUM(amount) AS total_amount
    FROM orders
    WHERE status = 2
    GROUP BY user_id
) t ON u.id = t.user_id
WHERE t.total_amount > 5000
ORDER BY t.total_amount DESC;

-- 改用 CTE（逻辑清晰，分步描述）
WITH completed_orders AS (
    SELECT user_id, SUM(amount) AS total_amount
    FROM orders
    WHERE status = 2
    GROUP BY user_id
)
SELECT u.id, u.username, co.total_amount
FROM users u
INNER JOIN completed_orders co ON u.id = co.user_id
WHERE co.total_amount > 5000
ORDER BY co.total_amount DESC;
```

## 多个 CTE 的链式使用

```sql
-- 多个 CTE 用逗号分隔，后续 CTE 可以引用前面的 CTE
WITH 
-- 第一步：统计每个用户的订单情况
user_orders AS (
    SELECT user_id,
           COUNT(*) AS order_cnt,
           SUM(amount) AS total_spent,
           MAX(created_at) AS last_order_at
    FROM orders
    WHERE status = 2
    GROUP BY user_id
),
-- 第二步：筛选高价值用户（订单数>=3 且消费>=1000）
valuable_users AS (
    SELECT user_id, total_spent, order_cnt
    FROM user_orders
    WHERE order_cnt >= 3 AND total_spent >= 1000
)
-- 最终：获取这些高价值用户的详细信息
SELECT u.id, u.username, u.email, vu.total_spent, vu.order_cnt
FROM users u
INNER JOIN valuable_users vu ON u.id = vu.user_id
ORDER BY vu.total_spent DESC;
```

## CTE 在 UPDATE / DELETE 中的使用

```sql
-- CTE 也可以与 UPDATE、DELETE 配合使用（MySQL 8.0+）
WITH old_sessions AS (
    SELECT id FROM sessions WHERE expired_at < NOW() - INTERVAL 7 DAY
)
DELETE FROM sessions WHERE id IN (SELECT id FROM old_sessions);

-- 更新 CTE 结果对应的行
WITH top_earners AS (
    SELECT id FROM employees WHERE salary > 20000
)
UPDATE employees
SET bonus = salary * 0.2
WHERE id IN (SELECT id FROM top_earners);
```

## CTE 与派生表的对比

| 对比维度 | CTE（WITH）| 派生表（FROM 子查询）|
|---------|-----------|------------------|
| 可读性 | 高（顶部定义，主查询简洁）| 较低（嵌套在 FROM 内，层层嵌套）|
| 复用性 | 同一查询内可多次引用 | 不可复用（需要重复写）|
| 递归支持 | 支持（RECURSIVE 关键字）| 不支持 |
| 性能 | MySQL 8.0+ 优化器处理相同 | 相同 |
| 调试友好性 | 高（可以单独测试每个 CTE）| 低（嵌套查询难以逐步调试）|

## CTE 在同一查询中多次引用

```sql
-- CTE 可以在同一主查询中被多次引用（派生表做不到）
WITH monthly_stats AS (
    SELECT DATE_FORMAT(created_at, '%Y-%m') AS month,
           SUM(amount) AS total
    FROM orders
    GROUP BY month
)
SELECT 
    current.month,
    current.total AS 当月销售额,
    COALESCE(prev.total, 0) AS 上月销售额,
    current.total - COALESCE(prev.total, 0) AS 环比差值
FROM monthly_stats current
LEFT JOIN monthly_stats prev   -- 同一 CTE 引用两次：current 和 prev
    ON prev.month = DATE_FORMAT(DATE_SUB(
        STR_TO_DATE(CONCAT(current.month, '-01'), '%Y-%m-%d'),
        INTERVAL 1 MONTH), '%Y-%m')
ORDER BY current.month;
```

## 适用场景

- **分步复杂查询**：将多步计算分解为可读的命名步骤
- **复用中间结果**：同一查询中多次引用同一中间结果
- **窗口函数结果过滤**：窗口函数结果不能直接用 WHERE，用 CTE 包一层再过滤
- **递归查询**：处理层级结构（见 1.9.18）

---

## 常见问题

**CTE 会被物化（缓存）还是每次都重新计算？**

MySQL 8.0 的优化器会自动决定：简单的 CTE 会被"内联"（合并到主查询中优化），复杂的 CTE（含 DISTINCT、GROUP BY 等）或被多次引用的 CTE 会被物化（结果存入临时表）。`WITH ... AS (...)` 加上 `MATERIALIZE` hint 可以强制物化。

---

## 注意事项

- CTE 只在定义它的单条语句中有效，不像视图那样持久化。每次执行该语句时 CTE 都会重新计算。
- 多个 CTE 之间用逗号分隔，只需写一个 `WITH` 关键字，不要每个 CTE 前都写 `WITH`。

---

## 总结

CTE（WITH 子句）定义命名的临时结果集，在同一查询中像表一样被引用，可以多次使用。与嵌套派生表相比，CTE 代码更清晰、可读性更高、支持递归（RECURSIVE 关键字）。适合将复杂的多步查询逻辑分解为清晰的命名步骤，是现代 SQL 编写的推荐方式。
