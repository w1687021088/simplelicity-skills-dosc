# 表子查询（返回多行多列）

表子查询是返回**多行多列**结果集的子查询，其结果可以被当作一张虚拟表（派生表）使用。在 MySQL 中，表子查询最常见的用法是作为 FROM 子句中的派生表（Derived Table），或者用于 IN / EXISTS 操作符的条件判断。

---

## 派生表（FROM 子句中的表子查询）

```sql
-- 语法：FROM 中的子查询必须有别名
SELECT alias.col1, alias.col2
FROM (SELECT ... FROM tbl WHERE ...) AS alias
[JOIN ...]
[WHERE ...];
```

```sql
-- 基础示例：查询各部门中薪资排名前 3 的员工
-- 先用子查询计算每个员工在其部门内的薪资排名
SELECT dept_id, name, salary
FROM (
    SELECT 
        dept_id, 
        name, 
        salary,
        RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rnk
    FROM employees
) ranked
WHERE rnk <= 3;

-- 先聚合再过滤（HAVING 的等价写法，有时用派生表更清晰）
SELECT dept_id, avg_salary
FROM (
    SELECT dept_id, ROUND(AVG(salary), 2) AS avg_salary
    FROM employees
    GROUP BY dept_id
) dept_stats
WHERE avg_salary > 12000;
```

## 用于 IN 的表子查询

```sql
-- IN 子查询返回多行单列（最常见形式）
SELECT name FROM employees
WHERE dept_id IN (
    SELECT id FROM departments WHERE name LIKE '%技术%'
);

-- 实践中，IN 子查询对于大数据集性能较差
-- 改用 INNER JOIN 通常更高效：
SELECT e.name FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
WHERE d.name LIKE '%技术%';
```

---

## 派生表作为聚合中间层

```sql
-- 经典场景：查询消费最多的前 10 名用户，并显示其信息
SELECT u.id, u.username, t.total_amount, t.order_count
FROM users u
INNER JOIN (
    SELECT user_id, 
           SUM(amount) AS total_amount,
           COUNT(*) AS order_count
    FROM orders
    WHERE status = 2   -- 已完成的订单
    GROUP BY user_id
) t ON u.id = t.user_id
ORDER BY t.total_amount DESC
LIMIT 10;
-- 派生表先聚合，再与 users JOIN，效率远好于每行都计算聚合
```

## MySQL 8.0+ 派生表的侧向引用（LATERAL）

```sql
-- MySQL 8.0.14+ 支持 LATERAL 关键字，允许派生表引用前面表的列
SELECT e.name, e.dept_id, dept_avg.avg_sal
FROM employees e
JOIN LATERAL (
    SELECT AVG(salary) AS avg_sal
    FROM employees e2
    WHERE e2.dept_id = e.dept_id  -- 引用外层的 e.dept_id
) dept_avg ON 1=1;
-- 每行 e 都对应一次 dept_avg 的计算
-- 等价于相关标量子查询，但更灵活（可以返回多列）
```

## 派生表的优化特性（MySQL 8.0）

```sql
-- MySQL 8.0 对简单的派生表会自动"合并"（Derived Table Merging）
-- 优化器将派生表内联到外层查询中，就像直接写了 JOIN 一样
-- 这意味着派生表不一定会产生临时表

-- 验证是否合并（EXPLAIN 中查看是否有 <derived> 行）
EXPLAIN SELECT * FROM (
    SELECT id, name FROM employees WHERE salary > 10000
) t WHERE t.dept_id = 1;
-- MySQL 8.0 可能将此优化为直接过滤 salary > 10000 AND dept_id = 1

-- 复杂的派生表（含 DISTINCT、GROUP BY、LIMIT 等）不能被合并，会物化为临时表
```

---

## 适用场景

- **分组聚合 + 过滤**：先 GROUP BY 聚合，再对聚合结果进行条件过滤
- **窗口函数的结果过滤**：窗口函数结果不能直接用 WHERE 过滤，必须通过派生表包一层
- **复杂的中间计算**：将多步计算分解为派生表，提高可读性

---

## 常见问题

**派生表的列能用别名直接引用吗？**

是的，派生表内部 SELECT 定义的别名，在外层查询中可以直接引用，如 `SELECT t.avg_salary FROM (...) t`。但派生表内部不能引用外层查询的列（除非使用 LATERAL）。

---

## 注意事项

- 派生表必须有别名（`AS t`），否则 MySQL 报语法错误。
- 含 GROUP BY、DISTINCT、LIMIT 的派生表会被物化为临时表，而不是被优化器内联合并。如果派生表结果集很大，临时表可能占用大量内存。可以通过 `EXPLAIN` 中是否有 `Using temporary` 来判断。

---

## 总结

表子查询返回多行多列结果集，最常见的用法是作为 FROM 中的派生表（加别名）。派生表可以将复杂的聚合或窗口函数结果包装为虚拟表，供外层查询进一步过滤或连接。MySQL 8.0 会对简单派生表自动合并优化；含 GROUP BY 等操作的派生表会物化为临时表。LATERAL 关键字允许派生表引用外层表的列。
