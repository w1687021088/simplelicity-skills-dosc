# 标量子查询（返回单行单列）

标量子查询是指返回**单行单列**（即单个值）的子查询。它可以出现在 SQL 中任何允许单个值出现的位置，包括 SELECT 列表、WHERE 条件、SET 赋值、HAVING 过滤等。如果子查询实际返回多行，MySQL 会报错；如果返回 0 行，结果为 NULL。

---

## 基本语法与使用位置

```sql
-- 在 SELECT 列表中使用（每行都执行一次子查询）
SELECT 
    e.name AS 员工,
    e.salary AS 薪资,
    (SELECT AVG(salary) FROM employees) AS 全公司平均薪资
FROM employees e;

-- 在 WHERE 中使用（与聚合值比较）
SELECT name, salary FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
-- 找出薪资高于平均的员工

-- 在 HAVING 中使用
SELECT dept_id, AVG(salary) AS 部门平均
FROM employees
GROUP BY dept_id
HAVING AVG(salary) > (SELECT AVG(salary) FROM employees);
-- 找出平均薪资高于全公司均值的部门
```

---

## 常见使用场景

```sql
-- 场景1：获取最新记录的关联信息
SELECT o.id, o.amount, o.created_at,
    (SELECT name FROM users WHERE id = o.user_id) AS 用户名
FROM orders o
ORDER BY o.created_at DESC
LIMIT 20;
-- 通常改写为 JOIN 性能更好，但在 SELECT 列表中标量子查询语义清晰

-- 场景2：与聚合统计比较
-- 查询薪资排名第二的员工（标量子查询嵌套）
SELECT name, salary FROM employees
WHERE salary = (
    SELECT MAX(salary) FROM employees
    WHERE salary < (SELECT MAX(salary) FROM employees)
);

-- 场景3：计算百分比（相对比例）
SELECT 
    status,
    COUNT(*) AS 数量,
    ROUND(COUNT(*) * 100 / (SELECT COUNT(*) FROM orders), 2) AS 占比百分比
FROM orders
GROUP BY status;

-- 场景4：UPDATE 中使用标量子查询
UPDATE products p
SET p.avg_rating = (
    SELECT ROUND(AVG(rating), 2) FROM reviews r WHERE r.product_id = p.id
);
```

## 标量子查询返回 NULL 的处理

```sql
-- 子查询没有匹配行时，结果为 NULL
SELECT name,
    (SELECT manager_id FROM employees WHERE name = '一个不存在的人') AS mgr
FROM employees;
-- mgr 列全为 NULL（子查询无结果）

-- 用 COALESCE 处理 NULL
SELECT name,
    COALESCE(
        (SELECT name FROM employees WHERE id = e.manager_id),
        '无直接上级'
    ) AS 上级名称
FROM employees e;
```

## 标量子查询与 JOIN 的对比

```sql
-- 标量子查询方式（在 SELECT 列表中逐行执行，适合偶尔使用）
SELECT e.name, (SELECT name FROM departments WHERE id = e.dept_id) AS 部门
FROM employees e;

-- JOIN 方式（更高效，推荐）
SELECT e.name, d.name AS 部门
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id;

-- 标量子查询的性能劣势：
-- 在 SELECT 列表中的标量子查询，对每一行结果都执行一次
-- 如果主查询返回 10000 行，子查询就执行 10000 次（N+1 问题）
-- 改写为 JOIN 通常只需要一次数据集合并，性能好得多
```

---

## 适用场景

- **与全局聚合值比较**：`WHERE salary > (SELECT AVG(...))`，这种场景子查询只执行一次，性能可接受
- **UPDATE / DELETE 中的辅助计算**：使用子查询计算目标值，作为 SET 的赋值来源
- **计算百分比等相对指标**：需要引用全局汇总值时

---

## 常见问题

**标量子查询返回多行时会怎样？**

MySQL 会报错：`ERROR 1242: Subquery returns more than 1 row`。解决方法是确保子查询有唯一条件（如按主键查询），或者加 `LIMIT 1`，或者改用 `MIN()`、`MAX()` 等聚合函数将多行归结为单值。

---

## 注意事项

- 在 SELECT 列表中使用相关标量子查询（子查询中引用外层表的列，如 `WHERE r.product_id = p.id`）会对每行主查询结果单独执行一次，形成 N+1 查询问题，性能差。对于大数据量的查询，应改写为 JOIN 或使用派生表。
- 标量子查询使用 `(SELECT ...)` 包裹，如果子查询会返回多行，必须通过聚合函数（MAX、MIN、AVG、COUNT）或 LIMIT 1 保证只返回一行。

---

## 总结

标量子查询返回单行单列，可用于 SELECT 列表、WHERE、HAVING、SET 等任意需要单值的位置。子查询无匹配行时返回 NULL，返回多行时报错。在 SELECT 列表中引用外层表列的相关标量子查询性能较差（N+1 问题），大数据量场景应改写为 JOIN。
