# 自连接（Self Join）场景

自连接是指一张表与自身进行连接查询，通过给表取不同的别名来区分两个不同角色的行。自连接本质上与普通的多表连接没有区别，只是连接的两边都来自同一张表。它最典型的应用场景是处理层次结构数据（如组织架构、商品分类树）和行间比较（同表中行与行之间的比较）。

---

## 语法

```sql
SELECT a.col, b.col
FROM tbl_name a
[INNER | LEFT] JOIN tbl_name b ON a.key = b.key
[WHERE condition];
-- 必须给表起不同的别名（如 a 和 b）
```

## 场景1：组织架构（上下级关系）

```sql
-- 员工表，包含 manager_id 自引用列
CREATE TABLE employees (
    id         INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    name       VARCHAR(100) NOT NULL,
    manager_id INT UNSIGNED DEFAULT NULL COMMENT 'NULL表示顶级（如CEO）',
    department VARCHAR(100) NOT NULL
);

INSERT INTO employees VALUES
    (1, '张总', NULL, '管理层'),
    (2, '李总监', 1, '技术部'),
    (3, '王总监', 1, '市场部'),
    (4, '张三', 2, '技术部'),
    (5, '李四', 2, '技术部'),
    (6, '王五', 3, '市场部');

-- 查询员工及其直接上级
SELECT e.name AS 员工, m.name AS 直接上级
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;
-- 张总的上级为 NULL（无上级）

-- 查询某员工的所有下属
SELECT e.name AS 下属
FROM employees e
INNER JOIN employees m ON e.manager_id = m.id
WHERE m.name = '李总监';
-- 返回：张三、李四

-- 查询直接管辖超过 1 人的管理者
SELECT m.name AS 管理者, COUNT(e.id) AS 直接下属数
FROM employees m
INNER JOIN employees e ON e.manager_id = m.id
GROUP BY m.id, m.name
HAVING COUNT(e.id) > 1;
```

## 场景2：商品分类树（多级分类）

```sql
CREATE TABLE categories (
    id        INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    name      VARCHAR(100) NOT NULL,
    parent_id INT UNSIGNED DEFAULT NULL COMMENT 'NULL为一级分类'
);

INSERT INTO categories VALUES
    (1, '电子产品', NULL),
    (2, '手机', 1),
    (3, '笔记本', 1),
    (4, '苹果手机', 2),
    (5, '华为手机', 2);

-- 查询所有子分类及其父分类名
SELECT c.name AS 子分类, p.name AS 父分类
FROM categories c
LEFT JOIN categories p ON c.parent_id = p.id
ORDER BY p.id, c.id;
```

## 场景3：行间比较（同表中不同行的比较）

```sql
-- 查询薪资比直接上级更高的员工
SELECT e.name AS 员工, e.salary AS 员工薪资,
       m.name AS 上级, m.salary AS 上级薪资
FROM employees e
INNER JOIN employees m ON e.manager_id = m.id
WHERE e.salary > m.salary;

-- 查询同一部门内薪资差距超过 5000 的员工对
SELECT a.name AS 员工A, a.salary AS 薪资A,
       b.name AS 员工B, b.salary AS 薪资B
FROM employees a
INNER JOIN employees b ON a.department = b.department AND a.id < b.id
WHERE ABS(a.salary - b.salary) > 5000;
-- a.id < b.id 防止同一对出现两次（如 (A,B) 和 (B,A)）
```

## 自连接的深度限制

```sql
-- 自连接只能处理已知深度（如只有 2 级、3 级）
-- 对于深度不固定的树形结构，应使用递归 CTE（见 1.9.18）

-- 两级深度（祖父-父-子）
SELECT g.name AS 祖父, p.name AS 父, c.name AS 子
FROM employees c
LEFT JOIN employees p ON c.manager_id = p.id
LEFT JOIN employees g ON p.manager_id = g.id;
```

## 适用场景

- **组织架构查询**：查找上下级关系、直接下属、所有下属
- **商品/内容分类树**：获取父分类名、面包屑路径
- **行间数据比较**：同一表中不同行的对比分析（如同组最高薪资）
- **相邻记录比较**：日志分析中比较相邻两行的值变化

---

## 常见问题

**自连接和普通 JOIN 的性能有什么区别？**

自连接和普通 JOIN 的性能规律完全相同。关键是连接列（如 `manager_id`、`parent_id`）必须有索引，否则会触发全表扫描。通常这类自引用列是外键，应确保有索引。

---

## 注意事项

- 自连接时必须给表起不同的别名（如 `employees e` 和 `employees m`），否则 MySQL 无法区分两个表实例的列引用。
- 自连接只适合处理已知有限深度的层级结构（如 2~3 级）。对于深度不固定的无限层级树，必须改用递归 CTE（MySQL 8.0+ 支持），参见 1.9.18 节。

---

## 总结

自连接是表与自身的连接，通过不同别名区分角色。最常用于处理自引用的层级数据（组织架构、分类树），以及同表不同行之间的比较。连接列必须有索引。深度不固定的树形结构不适合用自连接，应改用递归 CTE。
