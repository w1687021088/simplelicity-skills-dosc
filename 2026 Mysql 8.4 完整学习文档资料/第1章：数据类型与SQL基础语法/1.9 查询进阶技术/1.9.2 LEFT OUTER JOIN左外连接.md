# LEFT OUTER JOIN 左外连接

LEFT OUTER JOIN（通常简写为 LEFT JOIN）以左表为基准，返回左表中的所有行。对于左表中每一行，如果在右表中能找到满足连接条件的行，则输出匹配的列值；如果找不到，则右表对应的列以 NULL 填充。

---

## 语法

```sql
SELECT t1.col, t2.col
FROM t1
LEFT [OUTER] JOIN t2 ON t1.key = t2.key
[WHERE condition];
-- OUTER 关键字可省略，LEFT JOIN 即为 LEFT OUTER JOIN
```

---

## 基本示例

```sql
-- 查询所有部门及其员工（包括没有员工的部门）
SELECT d.name AS 部门, e.name AS 员工, e.salary
FROM departments d
LEFT JOIN employees e ON d.id = e.dept_id
ORDER BY d.id;

-- 结果（与 INNER JOIN 对比）：
-- 财务部（id=3）没有员工，但仍然出现，员工列为 NULL
-- +--------+--------+----------+
-- | 部门   | 员工   | salary   |
-- +--------+--------+----------+
-- | 技术部  | 张三   | 15000.00 |
-- | 技术部  | 李四   | 12000.00 |
-- | 市场部  | 王五   | 10000.00 |
-- | 财务部  | NULL   | NULL     |  ← 没有员工的部门
-- +--------+--------+----------+
```

---

## 查找"仅在左表中"的行（NOT EXISTS 效果）

```sql
-- 找出没有任何员工的部门（经典 LEFT JOIN + IS NULL 用法）
SELECT d.name AS 无员工部门
FROM departments d
LEFT JOIN employees e ON d.id = e.dept_id
WHERE e.id IS NULL;
-- 返回：财务部（因为 employees 中没有 dept_id=3 的行，右表 id 为 NULL）

-- 找出没有下过订单的用户
SELECT u.id, u.username
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE o.id IS NULL;
```

---

## LEFT JOIN 与 NULL 填充

```sql
-- LEFT JOIN 后对 NULL 列做聚合（IFNULL 处理）
SELECT d.name AS 部门,
       COUNT(e.id) AS 员工数,         -- COUNT(e.id) 不计 NULL，正确统计员工数
       COALESCE(SUM(e.salary), 0) AS 薪资总额  -- NULL 的 SUM 也是 NULL，用 COALESCE 转为 0
FROM departments d
LEFT JOIN employees e ON d.id = e.dept_id
GROUP BY d.id, d.name;

-- +--------+--------+----------+
-- | 部门   | 员工数 | 薪资总额 |
-- +--------+--------+----------+
-- | 技术部  |   2    | 27000.00 |
-- | 市场部  |   1    | 10000.00 |
-- | 财务部  |   0    | 0.00     |  ← COUNT 和 SUM 正确处理了 NULL
-- +--------+--------+----------+
```

## 多表 LEFT JOIN

```sql
-- 连续左连接（每次以前一个结果集为左表）
SELECT u.username, o.id AS 订单ID, p.name AS 商品名
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
LEFT JOIN products p ON o.product_id = p.id
-- 没有订单的用户：o 列全 NULL，p 列也全 NULL
-- 有订单但商品已删除的用户：o 有值，p 列为 NULL
ORDER BY u.id;
```

## LEFT JOIN 与 WHERE 的交互

```sql
-- 注意：在 LEFT JOIN 之后加 WHERE 对右表的 NOT NULL 条件，会把 LEFT JOIN 变成 INNER JOIN
SELECT d.name, e.name
FROM departments d
LEFT JOIN employees e ON d.id = e.dept_id
WHERE e.salary > 10000;  -- WHERE 过滤掉了 e.salary IS NULL 的行（即无员工的部门）
-- 效果等同于 INNER JOIN！财务部的 NULL 行被过滤掉了

-- 如果要在 LEFT JOIN 后过滤右表数据（保留左表无匹配行），
-- 条件应该放在 ON 子句中，而不是 WHERE
SELECT d.name, e.name
FROM departments d
LEFT JOIN employees e ON d.id = e.dept_id AND e.salary > 10000;
-- 财务部仍然出现（e 列为 NULL），只是连接时只匹配 salary > 10000 的员工
```

---

## 适用场景

- **主表查询 + 可选关联数据**：查询用户信息及其最新订单（用户可能没有订单）
- **统计缺失数据**：找出没有关联数据的主表行（如没有评论的文章）
- **全量主表统计**：统计包含零值的聚合（如部门员工数，包括 0 员工的部门）

---

## 常见问题

**LEFT JOIN 和 LEFT OUTER JOIN 有什么区别？**

没有区别，是同一个语法的两种写法，`OUTER` 关键字可以省略。

---

## 注意事项

- `ON` 子句中的条件用于控制连接逻辑（哪些行算匹配），`WHERE` 子句用于过滤结果。对右表的过滤条件如果放在 `WHERE` 而不是 `ON`，会意外地把 LEFT JOIN 退化为 INNER JOIN。
- 右表的连接列有索引时，LEFT JOIN 性能与 INNER JOIN 相近；没有索引时会导致全表扫描。

---

## 总结

LEFT JOIN 返回左表的所有行，右表无匹配时以 NULL 填充。通过 `WHERE 右表列 IS NULL` 可以找到"仅存在于左表"的行。过滤条件要分清应放在 `ON`（控制连接匹配范围）还是 `WHERE`（过滤最终结果）——放错位置会改变 LEFT JOIN 的语义。
