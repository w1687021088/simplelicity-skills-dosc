# EXISTS 存在性子查询

`EXISTS` 操作符用于检查子查询是否返回至少一行结果。如果子查询返回至少一行（不论具体值是什么），EXISTS 为 TRUE；如果子查询返回空集，EXISTS 为 FALSE。EXISTS 是一种"相关子查询"，它对外层查询的每一行都执行一次子查询。

---

## 语法

```sql
-- EXISTS
SELECT col1 FROM tbl1
WHERE EXISTS (
    SELECT 1 FROM tbl2 WHERE tbl2.fk = tbl1.pk [AND ...]
);

-- NOT EXISTS
SELECT col1 FROM tbl1
WHERE NOT EXISTS (
    SELECT 1 FROM tbl2 WHERE tbl2.fk = tbl1.pk [AND ...]
);
```

子查询中通常写 `SELECT 1` 或 `SELECT *`，因为 EXISTS 只关心是否有行返回，不关心具体值。

---

## 基本示例

```sql
-- 查找有下属的管理者（employees 中有 manager_id 指向此人）
SELECT e.id, e.name
FROM employees e
WHERE EXISTS (
    SELECT 1 FROM employees sub WHERE sub.manager_id = e.id
);

-- 查找有已完成订单的用户
SELECT u.id, u.username
FROM users u
WHERE EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.id AND o.status = 2
);

-- NOT EXISTS：查找没有任何订单的用户（推荐替代 NOT IN，安全处理 NULL）
SELECT u.id, u.username
FROM users u
WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.id
);
```

---

## EXISTS 与 IN 的对比

```sql
-- 功能上，以下两种写法通常等价
-- IN 方式
SELECT name FROM employees
WHERE dept_id IN (SELECT id FROM departments WHERE location = 'Beijing');

-- EXISTS 方式
SELECT e.name FROM employees e
WHERE EXISTS (
    SELECT 1 FROM departments d WHERE d.id = e.dept_id AND d.location = 'Beijing'
);

-- 性能差异（历史上）：
-- 外层表小、内层表大 → EXISTS 性能更好（早返回优化：找到一行即停止）
-- 外层表大、内层表小 → IN 性能更好（IN 的列表较小，直接比较快）
-- MySQL 8.0+ 优化器对两种写法都能做 semi-join 优化，实际差距已很小
```

---

## NOT EXISTS 处理 NULL（推荐替代 NOT IN）

```sql
-- NOT IN 有 NULL 陷阱，NOT EXISTS 没有
-- 即使子查询中包含 NULL 行，NOT EXISTS 也能正确工作

-- NULL 陷阱演示：
-- CREATE TABLE temp_vals (v INT); INSERT INTO temp_vals VALUES (1), (2), (NULL);
-- SELECT * FROM employees WHERE dept_id NOT IN (SELECT v FROM temp_vals);
-- 结果：空集（因为 NOT IN (1, 2, NULL) 永远不为 TRUE）

-- NOT EXISTS 版本（安全）：
SELECT e.* FROM employees e
WHERE NOT EXISTS (
    SELECT 1 FROM temp_vals t WHERE t.v = e.dept_id
);
-- 即使 temp_vals 中有 NULL，也不影响结果
-- NULL != NULL 在 EXISTS 中不会导致整体失败（子查询行 v IS NULL 与 e.dept_id 比较不匹配，继续查找其他行）
```

## 半连接（Semi-Join）优化

```sql
-- MySQL 8.0+ 对 EXISTS 子查询自动做 semi-join 优化
-- semi-join：对于外层每一行，只要在内层找到一个匹配就立即返回 TRUE，不再继续扫描
-- 这与 INNER JOIN 的区别在于：semi-join 不会因内层有多行匹配而产生重复的外层行

-- 验证优化器使用的是 semi-join
EXPLAIN SELECT u.* FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);
-- Extra 中可能看到 "Using where; FirstMatch(u)" 或 "Using index"
```

## 适用场景

- **存在性检查**：只需知道"是否有记录"，不需要关联数据本身
- **替代 NOT IN（防 NULL 陷阱）**：任何 NOT IN 的场景都可以安全地用 NOT EXISTS 替代
- **过滤主表行（半连接效果）**：根据关联表的条件过滤主表，但不需要关联表的列

---

## 常见问题

**EXISTS 子查询中 SELECT 什么不影响结果吗？**

对。EXISTS 只判断子查询是否返回至少一行，完全不看子查询 SELECT 出来的值。写 `SELECT 1`、`SELECT NULL`、`SELECT *` 都完全等价，通常写 `SELECT 1` 是惯例，表达意图最清晰。

---

## 注意事项

- NOT EXISTS 中的子查询是相关子查询（引用了外层表的列），对外层表每一行都执行一次。如果外层表行数很多而内层子查询没有合适的索引，性能会很差。确保子查询中外键列（如 `o.user_id`）有索引。
- 在 MySQL 8.0+ 中，EXISTS 和 IN 的性能差异已经由优化器自动平衡，通常不需要手动选择。主要选择依据是语义清晰度和是否有 NULL 处理需求。

---

## 总结

`EXISTS` 检查子查询是否返回至少一行，只关心存在性不关心值。`NOT EXISTS` 是替代 `NOT IN` 的安全写法，不受 NULL 值影响。EXISTS 是相关子查询，内层子查询的连接列必须有索引。MySQL 8.0+ 对 EXISTS/IN 都做 semi-join 优化，性能差距已很小，选择依据主要是语义清晰性。
