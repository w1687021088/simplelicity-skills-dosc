# IN 操作符与子查询

`IN` 操作符用于判断某列的值是否在一个指定的列表或子查询结果集中。它是 `= 值1 OR = 值2 OR ...` 的简洁写法，支持字面量列表和子查询两种形式。

---

## 语法

```sql
-- 字面量列表
expr IN (val1, val2, val3, ...)

-- 子查询
expr IN (SELECT col FROM tbl WHERE ...)

-- NOT IN：不在列表或子查询结果中
expr NOT IN (val1, val2, ...)
expr NOT IN (SELECT col FROM tbl WHERE ...)
```

---

## 基本示例

```sql
-- 字面量列表形式（等价于多个 OR）
SELECT * FROM orders WHERE status IN (1, 2, 3);
-- 等价于：WHERE status = 1 OR status = 2 OR status = 3

SELECT * FROM employees WHERE dept_id NOT IN (1, 3);

-- 子查询形式
SELECT name FROM employees
WHERE dept_id IN (
    SELECT id FROM departments WHERE name LIKE '%技术%'
);
-- 找出属于"技术"相关部门的员工

-- NOT IN 子查询
SELECT name FROM employees
WHERE dept_id NOT IN (
    SELECT id FROM departments WHERE name LIKE '%管理%'
);
-- 找出不属于管理类部门的员工
```

---

## IN 子查询与 JOIN 的对比

```sql
-- IN 子查询方式（语义清晰）
SELECT e.name FROM employees e
WHERE e.dept_id IN (SELECT id FROM departments WHERE location = 'Beijing');

-- 等价 JOIN 方式（通常更高效，优化器可以更好地利用索引）
SELECT e.name FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
WHERE d.location = 'Beijing';

-- MySQL 8.0+ 优化器会自动将 IN 子查询转换为 semi-join（半连接）
-- 性能上与 JOIN 相近，不需要手动改写
```

## NOT IN 与 NULL 的陷阱

```sql
-- NOT IN 的 NULL 陷阱（非常重要）
-- 如果子查询结果集中包含 NULL 值，NOT IN 会返回空集（没有任何行匹配）

CREATE TABLE test_null (val INT);
INSERT INTO test_null VALUES (1), (2), (NULL);

SELECT * FROM employees WHERE id NOT IN (SELECT val FROM test_null);
-- 结果：空集（没有任何行！）
-- 原因：id NOT IN (1, 2, NULL) 等价于 id != 1 AND id != 2 AND id != NULL
-- NULL != NULL 的结果是 NULL（不是 TRUE），使整个表达式永远不为 TRUE

-- 正确写法：过滤掉子查询中的 NULL
SELECT * FROM employees
WHERE id NOT IN (
    SELECT val FROM test_null WHERE val IS NOT NULL
);

-- 或者改用 NOT EXISTS（天然处理 NULL，更安全）
SELECT * FROM employees e
WHERE NOT EXISTS (
    SELECT 1 FROM test_null t WHERE t.val = e.id
);
```

---

## 大量值的 IN 列表性能

```sql
-- IN 列表中值非常多时（如几百个 ID），性能可能变差
-- 方法1：使用临时表
CREATE TEMPORARY TABLE temp_ids (id INT UNSIGNED NOT NULL PRIMARY KEY);
INSERT INTO temp_ids VALUES (1),(2),(3), ... -- 大量 ID

SELECT e.* FROM employees e
INNER JOIN temp_ids t ON e.id = t.id;

-- 方法2：使用 FIND_IN_SET（字符串形式，不推荐大量值）
SELECT * FROM employees WHERE FIND_IN_SET(dept_id, '1,2,3');
-- 会导致全表扫描，性能差

-- IN 子查询中，子查询结果集不应过大
-- 如果子查询返回数万行，考虑改写为 EXISTS 或 JOIN
```

---

## 适用场景

- **枚举状态过滤**：`WHERE status IN (0, 1, 2)`（对已知枚举值列表的过滤）
- **批量 ID 查询**：`WHERE id IN (101, 102, 103)`（批量按 ID 查找记录）
- **子集匹配**：`WHERE dept_id IN (SELECT id FROM departments WHERE ...)`

---

## 常见问题

**IN 和 = ANY 是否等价？**

是的，`IN (subquery)` 等价于 `= ANY (subquery)`。`NOT IN (subquery)` 等价于 `!= ALL (subquery)`，但 NOT IN 存在 NULL 陷阱，而 NOT EXISTS 更安全。

---

## 注意事项

- **NOT IN 中的 NULL 是最常见的逻辑 bug**：只要子查询结果集中有一个 NULL，NOT IN 整个条件就永远是 FALSE，导致结果集为空。生产代码中使用 NOT IN 时，务必在子查询中过滤掉 NULL，或者改用 NOT EXISTS。
- MySQL 8.0+ 优化器可以将 IN 子查询转换为 semi-join（半连接），自动利用索引。但对于非常大的 IN 列表（几千个值），性能可能不如临时表 JOIN。

---

## 总结

`IN` 操作符检查值是否在列表或子查询结果中，是多 OR 条件的简写。IN 子查询在 MySQL 8.0+ 中被优化器自动转换为 semi-join，性能接近 JOIN。`NOT IN` 存在 NULL 陷阱——子查询结果中有 NULL 时整个 NOT IN 条件失效，建议改用 `NOT EXISTS`。大量值的 IN 列表可以通过临时表 + JOIN 来优化。
