# HAVING 分组后过滤

`HAVING` 子句用于对 `GROUP BY` 分组后的聚合结果进行过滤，它的作用类似于 WHERE，但 WHERE 在分组前过滤原始行，HAVING 在分组后过滤聚合结果。HAVING 中可以引用聚合函数（如 `COUNT(*) > 5`），而 WHERE 中不能。

---

## 语法

```sql
SELECT col1, AGG_FUNC(col2) AS agg_val
FROM tbl_name
[WHERE condition]      -- 分组前过滤原始行
GROUP BY col1
HAVING agg_val > val   -- 分组后过滤聚合结果
[ORDER BY ...]
[LIMIT n];
```

---

## 基本示例

```sql
-- 找出员工数超过 2 人的部门
SELECT dept_id, COUNT(*) AS emp_count
FROM employees
GROUP BY dept_id
HAVING emp_count > 2;  -- 对聚合结果过滤（employee_count > 2）

-- 或者直接在 HAVING 中写聚合函数（不用别名）
SELECT dept_id, COUNT(*) AS emp_count
FROM employees
GROUP BY dept_id
HAVING COUNT(*) > 2;

-- 找出平均薪资超过全公司均值的部门
SELECT dept_id, ROUND(AVG(salary), 2) AS avg_sal
FROM employees
GROUP BY dept_id
HAVING avg_sal > (SELECT AVG(salary) FROM employees);

-- 查找有重复 email 的用户记录（数据质量检查）
SELECT email, COUNT(*) AS cnt
FROM users
GROUP BY email
HAVING cnt > 1
ORDER BY cnt DESC;
```

---

## HAVING 与 WHERE 的组合使用

```sql
-- WHERE 先过滤原始数据，GROUP BY 再分组，HAVING 最后过滤分组结果
-- 三者配合是最常见的聚合查询模式

-- 统计 2026 年每月已完成订单数，只显示月订单超过 100 的月份
SELECT 
    DATE_FORMAT(created_at, '%Y-%m') AS 月份,
    COUNT(*) AS 订单数,
    SUM(amount) AS 销售额
FROM orders
WHERE status = 2                      -- WHERE：先过滤，只看已完成订单
  AND YEAR(created_at) = 2026
GROUP BY DATE_FORMAT(created_at, '%Y-%m')  -- GROUP BY：按月分组
HAVING 订单数 > 100                   -- HAVING：只保留订单数超过 100 的月份
ORDER BY 月份;
```

---

## HAVING 中引用别名（MySQL 特性）

```sql
-- MySQL 允许在 HAVING 中引用 SELECT 中定义的别名（标准 SQL 不允许这样）
SELECT dept_id, ROUND(AVG(salary), 2) AS avg_salary
FROM employees
GROUP BY dept_id
HAVING avg_salary > 12000;  -- MySQL 允许：avg_salary 是 SELECT 中的别名
-- 等价于：HAVING ROUND(AVG(salary), 2) > 12000

-- 注意：在 WHERE 中不能引用 SELECT 别名（WHERE 在 SELECT 之前执行）
SELECT dept_id, ROUND(AVG(salary), 2) AS avg_salary
FROM employees
WHERE avg_salary > 12000  -- 报错：Unknown column 'avg_salary'
GROUP BY dept_id;
```

## HAVING 中过滤 GROUP_CONCAT

```sql
-- 找出有超过 3 种商品的订单
SELECT order_id, GROUP_CONCAT(product_id ORDER BY product_id) AS 商品列表
FROM order_items
GROUP BY order_id
HAVING COUNT(DISTINCT product_id) >= 3;
```

## 适用场景

- **数据质量检查**：找出重复数据（`HAVING COUNT(*) > 1`）
- **维度过滤**：只显示满足聚合条件的组（如订单数超过阈值的用户）
- **异常检测**：找出均值/总量超出正常范围的分组
- **分层统计**：统计满足特定聚合条件的维度数量

---

## 常见问题

**HAVING 中能引用原始列吗？**

可以。HAVING 子句可以引用 GROUP BY 中的列、SELECT 中的列和聚合表达式。但应尽量将非聚合的行级过滤放在 WHERE 中，因为 WHERE 在分组前执行，可以减少参与聚合的数据量，性能更好。

---

## 注意事项

- 能在 WHERE 中过滤的条件，尽量放 WHERE，不要放 HAVING。WHERE 先执行，可以减少进入分组的数据量，提升性能。HAVING 过滤的是已经聚合完的分组，此时行数已经大幅减少，过滤成本低。
- 没有 GROUP BY 时，HAVING 也可以使用，此时整张表作为一个组，HAVING 对这唯一一组的聚合结果进行过滤。

---

## 总结

`HAVING` 在 GROUP BY 分组聚合之后对每个分组的聚合结果进行条件过滤，可以使用聚合函数（WHERE 不能）。与 WHERE 的区别是执行时机：WHERE 在分组前过滤行，HAVING 在分组后过滤组。非聚合条件优先放 WHERE，聚合条件才放 HAVING，这样性能最优。
