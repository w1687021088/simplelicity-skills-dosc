# LEAD() 与 LAG() 偏移函数

`LEAD()` 和 `LAG()` 是窗口函数中的偏移函数，允许在同一行中访问同一分区内其他行的值，而不需要自连接。`LAG()` 访问当前行之**前**的某行值，`LEAD()` 访问当前行之**后**的某行值。这两个函数非常适合计算相邻行之间的差值、环比增长、状态变化等。

---

## 语法

```sql
LAG(expr [, offset [, default_val]]) OVER (
    [PARTITION BY col1, ...]
    ORDER BY col2 [ASC|DESC]
)

LEAD(expr [, offset [, default_val]]) OVER (
    [PARTITION BY col1, ...]
    ORDER BY col2 [ASC|DESC]
)
```

- `expr`：要获取的列或表达式
- `offset`：偏移行数，默认 1（前/后 1 行）
- `default_val`：当偏移行不存在时的返回值，默认 NULL

---

## 基本示例

```sql
-- 计算每日订单金额与前一天的差值（环比）
SELECT 
    order_date,
    daily_amount,
    LAG(daily_amount, 1) OVER (ORDER BY order_date) AS prev_day_amount,
    daily_amount - LAG(daily_amount, 1, 0) OVER (ORDER BY order_date) AS diff,
    ROUND(
        (daily_amount - LAG(daily_amount, 1) OVER (ORDER BY order_date)) 
        / LAG(daily_amount, 1) OVER (ORDER BY order_date) * 100, 2
    ) AS growth_pct
FROM (
    SELECT DATE(created_at) AS order_date, SUM(amount) AS daily_amount
    FROM orders WHERE status = 2
    GROUP BY DATE(created_at)
) daily_stats
ORDER BY order_date;

-- 简单示例：序列中获取前后值
SELECT 
    id, value,
    LAG(value)  OVER (ORDER BY id) AS prev_value,  -- 上一行
    LEAD(value) OVER (ORDER BY id) AS next_value   -- 下一行
FROM test_series;
```

## LEAD/LAG 在分区内使用

```sql
-- 按用户分区，查看每个用户的相邻订单
SELECT 
    user_id,
    order_id,
    amount,
    created_at,
    LAG(amount) OVER (PARTITION BY user_id ORDER BY created_at) AS prev_order_amount,
    LEAD(amount) OVER (PARTITION BY user_id ORDER BY created_at) AS next_order_amount,
    amount - LAG(amount, 1, amount) OVER (PARTITION BY user_id ORDER BY created_at) AS diff_from_prev
FROM orders
WHERE status = 2
ORDER BY user_id, created_at;
-- LAG/LEAD 在遇到分区边界时（第一行的 LAG 或最后一行的 LEAD），
-- 返回 default_val（这里设为 amount 本身，所以 diff 为 0）
```

## 检测状态变化

```sql
-- 检测用户登录状态的变化（如何时从"活跃"变为"不活跃"）
SELECT 
    user_id,
    event_date,
    status,
    LAG(status) OVER (PARTITION BY user_id ORDER BY event_date) AS prev_status,
    CASE 
        WHEN status != LAG(status) OVER (PARTITION BY user_id ORDER BY event_date)
        THEN '状态变化'
        ELSE ''
    END AS change_flag
FROM user_status_log
ORDER BY user_id, event_date;
```

## 多步偏移

```sql
-- offset=2：获取当前行之前第 2 行的值
SELECT 
    month,
    revenue,
    LAG(revenue, 1) OVER (ORDER BY month) AS prev_month,  -- 上个月
    LAG(revenue, 2) OVER (ORDER BY month) AS two_months_ago,  -- 上上个月
    LAG(revenue, 3) OVER (ORDER BY month) AS three_months_ago  -- 3个月前
FROM monthly_revenue;
-- 可用于计算 3 个月移动平均的对比等
```

## LAG/LEAD 与自连接的对比

```sql
-- 自连接方式（获取前一行，繁琐且性能差）
SELECT t1.order_date, t1.amount,
    t2.amount AS prev_amount
FROM daily_orders t1
LEFT JOIN daily_orders t2 
    ON t2.order_date = t1.order_date - INTERVAL 1 DAY;
-- 自连接需要确保日期连续，有日期缺口时无法处理

-- LAG 方式（简洁，处理所有情况）
SELECT order_date, amount,
    LAG(amount) OVER (ORDER BY order_date) AS prev_amount
FROM daily_orders;
-- 自动处理：按排序的上一行，不要求日期连续
```

## 适用场景

- **环比计算**：本期与上一期的差值、增长率
- **相邻行比较**：价格变化、状态转换检测
- **时间序列分析**：识别趋势变化（连续上涨/下跌）
- **计算间隔时间**：用 LEAD 获取下次事件时间，计算两次事件的时间差

---

## 常见问题

**LAG/LEAD 的默认值应该设什么？**

视计算需求而定：
- 计算差值时，设 `default_val = 0` 或 `default_val = expr`（当前值），使第一行/最后一行的差为 0 而不是 NULL
- 状态变化检测时，不设默认值（返回 NULL），在外层用 IS NOT NULL 过滤掉无前置状态的行

---

## 注意事项

- `LAG` 和 `LEAD` 必须配合 `ORDER BY` 使用，否则偏移方向不确定。`PARTITION BY` 决定了偏移的范围边界（跨分区不偏移）。
- 在分区的第一行使用 `LAG`，或分区的最后一行使用 `LEAD` 时，没有对应的偏移行，结果返回 `default_val`（未设时为 NULL）。

---

## 总结

`LAG(expr, n)` 返回当前行前第 n 行的值，`LEAD(expr, n)` 返回后第 n 行的值，n 默认为 1。两者都需要 `ORDER BY` 来确定行的顺序。分区边界时返回可指定的默认值（默认 NULL）。适合环比计算、相邻行比较、状态变化检测等时间序列分析场景，比自连接更简洁高效。
