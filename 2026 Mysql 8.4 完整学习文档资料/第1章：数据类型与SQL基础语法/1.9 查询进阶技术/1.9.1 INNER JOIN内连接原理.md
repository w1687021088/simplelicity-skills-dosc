# INNER JOIN 内连接原理

INNER JOIN 是 SQL 中最常用的表连接方式，返回两张（或多张）表中满足连接条件的所有匹配行。只有在两张表中都能找到匹配记录的行才会出现在结果集中，不满足连接条件的行不包含在内。

---

## 语法

```sql
-- 显式 INNER JOIN（推荐写法）
SELECT t1.col, t2.col
FROM t1
INNER JOIN t2 ON t1.key = t2.key
[WHERE condition]
[ORDER BY ...]
[LIMIT n];

-- JOIN 等价写法（省略 INNER，效果完全相同）
SELECT t1.col, t2.col
FROM t1
JOIN t2 ON t1.key = t2.key;

-- 旧式隐式写法（不推荐，可读性差）
SELECT t1.col, t2.col
FROM t1, t2
WHERE t1.key = t2.key;
```

## 基本示例

```sql
-- 创建示例表
CREATE TABLE departments (
    id   INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);

CREATE TABLE employees (
    id      INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    name    VARCHAR(100) NOT NULL,
    dept_id INT UNSIGNED NOT NULL,
    salary  DECIMAL(10,2) NOT NULL
);

INSERT INTO departments VALUES (1,'技术部'), (2,'市场部'), (3,'财务部');
INSERT INTO employees VALUES
    (1,'张三',1,15000),
    (2,'李四',1,12000),
    (3,'王五',2,10000),
    (4,'赵六',4,8000);  -- dept_id=4 在 departments 中不存在

-- INNER JOIN：只返回两表都有匹配的行
SELECT e.name AS 员工, d.name AS 部门, e.salary
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id;

-- 结果：赵六（dept_id=4）不出现（departments 中没有 id=4 的部门）
-- 财务部（id=3）不出现（employees 中没有 dept_id=3 的员工）
-- +--------+--------+----------+
-- | 员工   | 部门   | salary   |
-- +--------+--------+----------+
-- | 张三   | 技术部  | 15000.00 |
-- | 李四   | 技术部  | 12000.00 |
-- | 王五   | 市场部  | 10000.00 |
-- +--------+--------+----------+
```

## 多表 INNER JOIN

```sql
-- 三表连接
CREATE TABLE salaries (
    emp_id    INT UNSIGNED NOT NULL,
    month     DATE NOT NULL,
    amount    DECIMAL(10,2) NOT NULL
);

SELECT e.name, d.name AS dept, s.amount
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
INNER JOIN salaries s ON e.id = s.emp_id AND s.month = '2026-03-01';

-- 结合聚合
SELECT d.name AS 部门, COUNT(e.id) AS 员工数, AVG(e.salary) AS 平均薪资
FROM departments d
INNER JOIN employees e ON d.id = e.dept_id
GROUP BY d.id, d.name
ORDER BY 平均薪资 DESC;
```

## INNER JOIN 的执行原理

```sql
-- MySQL 优化器选择 JOIN 驱动表：
-- 小表（结果集小）作为驱动表（outer loop），大表作为被驱动表（inner loop）
-- 被驱动表的连接列有索引时，可以用 eq_ref/ref 方式查找，效率极高

-- 查看执行计划
EXPLAIN SELECT e.name, d.name
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id;

-- 关注：
-- type: eq_ref（被驱动表用主键连接）或 ref（被驱动表用普通索引连接）
-- rows: 每步预计扫描行数，越小越好
-- Extra: 是否有 Using join buffer（表示被驱动表没有合适的索引，用了 BNL/Hash Join）
```

## 等值连接与非等值连接

```sql
-- 等值连接（最常见）
SELECT * FROM t1 INNER JOIN t2 ON t1.id = t2.fk_id;

-- 非等值连接（按范围匹配）
-- 场景：根据薪资区间匹配薪资等级
CREATE TABLE salary_grade (
    grade   VARCHAR(10) NOT NULL,
    low_val DECIMAL(10,2) NOT NULL,
    high_val DECIMAL(10,2) NOT NULL
);
INSERT INTO salary_grade VALUES ('A', 15000, 99999), ('B', 10000, 14999), ('C', 0, 9999);

SELECT e.name, e.salary, g.grade
FROM employees e
INNER JOIN salary_grade g ON e.salary BETWEEN g.low_val AND g.high_val;
```

## 适用场景

- **获取完整的关联数据**：查询员工及其所属部门（双方都必须存在）
- **多表聚合查询**：统计各部门的员工数、薪资总额等
- **数据验证**：检查两表中都有记录的关联数据的一致性

---

## 常见问题

**INNER JOIN 和 WHERE 条件放一起效果相同吗？**

当使用隐式写法（`FROM t1, t2 WHERE t1.id = t2.fk_id`）时，WHERE 里的连接条件与 INNER JOIN 效果相同。但 INNER JOIN 的显式写法更清晰，将连接条件（ON）和过滤条件（WHERE）分开，可读性更好，推荐使用。

---

## 注意事项

- 在 JOIN 的被驱动表（内循环表）的连接列上**必须有索引**，否则每次外循环都要全表扫描被驱动表，性能极差（N×M 的复杂度）。连接列通常是外键列，应确保它有索引。
- 多表连接时，避免使用 `SELECT *`，只选取需要的列，减少数据传输量。

---

## 总结

INNER JOIN 返回两表中满足连接条件的匹配行，不满足条件的行（无论在哪张表）都不会出现在结果中。推荐使用显式的 `INNER JOIN ... ON` 语法，将连接条件和过滤条件分开写，增强可读性。被驱动表的连接列必须有索引，否则会导致严重的性能问题。
