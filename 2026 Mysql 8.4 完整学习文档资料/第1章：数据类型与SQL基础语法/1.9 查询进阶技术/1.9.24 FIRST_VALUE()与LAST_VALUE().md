# FIRST_VALUE() 与 LAST_VALUE()

`FIRST_VALUE()` 返回窗口帧内第一行的指定列值，`LAST_VALUE()` 返回窗口帧内最后一行的指定列值。它们常用于在每一行中附加分区的边界值（如分区内最早/最晚记录的某个字段），而不需要自连接或子查询。

---

## 语法

```sql
FIRST_VALUE(expr) OVER (
    [PARTITION BY col1, ...]
    ORDER BY col2
    [frame_clause]
)

LAST_VALUE(expr) OVER (
    [PARTITION BY col1, ...]
    ORDER BY col2
    [frame_clause]
)
```

---

## FIRST_VALUE 基本示例

```sql
-- 查询每个员工的薪资，以及其所在部门薪资最高的员工名字
SELECT 
    name,
    dept_id,
    salary,
    FIRST_VALUE(name) OVER (
        PARTITION BY dept_id 
        ORDER BY salary DESC
    ) AS top_earner_in_dept
FROM employees;
-- 每行都显示本部门薪资最高的那个人的名字
-- FIRST_VALUE + ORDER BY salary DESC = 分区内薪资最高的第一行

-- 查询每个用户的第一笔订单金额
SELECT 
    user_id,
    order_id,
    amount,
    created_at,
    FIRST_VALUE(amount) OVER (
        PARTITION BY user_id 
        ORDER BY created_at ASC
    ) AS first_order_amount
FROM orders;
```

## LAST_VALUE 与帧子句

```sql
-- LAST_VALUE 的关键注意点：
-- 默认帧子句是 RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
-- 这意味着帧的结束是"当前行"，不是分区结束
-- 所以默认情况下 LAST_VALUE 返回的是"到当前行为止的最后一行"（即当前行自己），而不是分区末尾

-- 错误示例（通常不是想要的结果）：
SELECT name, salary,
    LAST_VALUE(name) OVER (
        PARTITION BY dept_id ORDER BY salary DESC
        -- 默认帧：RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS last_name_wrong
FROM employees;
-- last_name_wrong 永远等于当前行的 name（因为帧的最后一行就是当前行）

-- 正确示例：扩展帧到分区末尾
SELECT name, salary,
    LAST_VALUE(name) OVER (
        PARTITION BY dept_id 
        ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING  -- 帧扩展到分区末尾
    ) AS lowest_earner_in_dept
FROM employees;
-- 现在 LAST_VALUE 返回部门内薪资最低的那个人的名字（ORDER BY DESC 时，最后一行薪资最低）
```

## FIRST_VALUE 替代 MIN/MAX 的场景

```sql
-- 通常情况下，取分区最大/最小值可以直接用 MAX/MIN 窗口函数
-- FIRST_VALUE 的优势是可以获取与最大/最小值同行的其他列的值

-- 场景：获取每个部门薪资最高员工的 id 和入职日期
SELECT 
    dept_id,
    name,
    salary,
    FIRST_VALUE(id) OVER (PARTITION BY dept_id ORDER BY salary DESC) AS top_emp_id,
    FIRST_VALUE(hire_date) OVER (PARTITION BY dept_id ORDER BY salary DESC) AS top_emp_hire_date
FROM employees;
-- MAX(salary) 只能得到最高薪资值，无法获取同行的 id 或 hire_date
-- FIRST_VALUE 可以在每行旁边展示分区第一行（薪资最高者）的任意列
```

## NTH_VALUE（获取第 N 行的值）

```sql
-- NTH_VALUE(expr, n)：获取窗口帧内第 n 行的值
-- 是 FIRST_VALUE（第1行）的泛化版本

SELECT name, salary,
    NTH_VALUE(name, 1) OVER (PARTITION BY dept_id ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS top1,
    NTH_VALUE(name, 2) OVER (PARTITION BY dept_id ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS top2,
    NTH_VALUE(name, 3) OVER (PARTITION BY dept_id ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS top3
FROM employees;
-- 在每行旁边同时显示本部门薪资排名第1、2、3的员工名字
```

## 适用场景

- **每行展示分区边界行的属性**：每个员工行显示其部门薪资最高/最低者的名字
- **获取与极值同行的关联列**：薪资最高者的入职日期、部门等（MAX 做不到）
- **时间序列中的首末值**：每行显示分区内最早/最晚的时间点的某个字段值

---

## 常见问题

**FIRST_VALUE 和 MIN/MAX 的区别是什么？**

`MIN(col)` 和 `MAX(col)` 返回分区内 col 列的最小/最大值本身。`FIRST_VALUE(col)` 返回按 ORDER BY 排序后第一行的 col 值（可以是任意列）。当你需要"薪资最高者的名字"时，只有 FIRST_VALUE（配合 ORDER BY salary DESC）能做到，MIN/MAX 做不到这种跨列取值。

---

## 注意事项

- `LAST_VALUE` 使用时几乎总是需要显式指定帧子句为 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`，才能正确获取分区末尾的值。不加帧子句时，默认帧结束于当前行，LAST_VALUE 的结果通常是当前行自己的值，毫无意义。
- `FIRST_VALUE` 不需要修改帧子句（默认帧包含分区起点到当前行，第一行永远在范围内）。

---

## 总结

`FIRST_VALUE(col)` 返回窗口帧内第一行（按 ORDER BY 排序）的 col 值，`LAST_VALUE(col)` 返回帧内最后一行的值。使用 LAST_VALUE 时几乎必须把帧扩展到 `UNBOUNDED FOLLOWING`，才能获得分区末尾的值而不是当前行的值。适合在每行中附加"分区内排名第一/最后的行"的任意属性值。
