# 窗口函数 OVER 子句基础

窗口函数（Window Function）是 MySQL 8.0 引入的功能，通过 `OVER()` 子句定义一个"窗口"（数据分区和排序范围），在每一行的基础上计算聚合或排名值，而**不减少结果集的行数**。这与普通 GROUP BY 聚合的根本区别在于：窗口函数保留每一行，同时在旁边附加一个基于窗口计算的值。

---

## 语法

```sql
窗口函数名([args]) OVER (
    [PARTITION BY col1, col2, ...]   -- 分区（可选）
    [ORDER BY col3 [ASC|DESC], ...]  -- 排序（可选）
    [frame_clause]                   -- 帧子句（可选，详见 1.9.25）
) AS alias
```

`OVER()` 括号内可以为空（表示整张表作为一个窗口），也可以含分区、排序、帧子句的任意组合。

---

## 窗口函数与 GROUP BY 的核心区别

```sql
-- GROUP BY 聚合：行数变少，每组只有一行
SELECT dept_id, AVG(salary) AS avg_sal
FROM employees
GROUP BY dept_id;
-- 结果：N 个部门 = N 行

-- 窗口函数：行数不变，每行附加聚合值
SELECT id, name, dept_id, salary,
       AVG(salary) OVER (PARTITION BY dept_id) AS dept_avg_sal
FROM employees;
-- 结果：所有员工行都保留，每行多一列"本部门平均薪资"
-- 技术部的每个员工行都显示技术部的平均薪资
-- 市场部的每个员工行都显示市场部的平均薪资
```

---

## OVER() 的三个组成部分

```sql
-- 1. PARTITION BY：类似 GROUP BY，将行分成不同的分区
--    窗口函数在每个分区内独立计算
SELECT name, dept_id, salary,
    SUM(salary) OVER (PARTITION BY dept_id) AS 部门薪资总和
FROM employees;
-- 每行显示其所在部门的薪资总和（不同部门显示不同值）

-- 2. ORDER BY：定义分区内行的排序，影响排名函数和滑动帧
SELECT name, dept_id, salary,
    RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS 部门内薪资排名
FROM employees;

-- 3. 两者都有：先分区，再在分区内按指定顺序排名/聚合
SELECT name, dept_id, salary,
    ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rn
FROM employees;
-- 每个部门内按薪资降序编号，各部门从 1 开始重新编号
```

---

## 无 PARTITION BY（整表作为一个窗口）

```sql
-- 不分区：整张表作为一个窗口
SELECT name, salary,
    RANK() OVER (ORDER BY salary DESC) AS 全公司薪资排名,
    SUM(salary) OVER () AS 全公司薪资总和
FROM employees;
-- 每行都显示在全公司中的薪资排名和全公司薪资总和
```

---

## 常用窗口函数一览

| 函数名 | 用途 |
|-------|------|
| `ROW_NUMBER()` | 分区内唯一行号（1, 2, 3...）|
| `RANK()` | 排名（相同值同名次，之后跳号）|
| `DENSE_RANK()` | 排名（相同值同名次，不跳号）|
| `LEAD(col, n)` | 获取当前行之后第 n 行的值 |
| `LAG(col, n)` | 获取当前行之前第 n 行的值 |
| `FIRST_VALUE(col)` | 窗口帧内第一行的值 |
| `LAST_VALUE(col)` | 窗口帧内最后一行的值 |
| `SUM(col)` | 窗口内累计求和 |
| `AVG(col)` | 窗口内均值 |
| `COUNT(col)` | 窗口内计数 |
| `NTILE(n)` | 将分区内行平均分为 n 个桶，返回桶号 |

## WINDOW 子句（复用窗口定义）

```sql
-- 当多个窗口函数使用相同的 OVER 定义时，可以用 WINDOW 子句命名窗口
SELECT name, dept_id, salary,
    ROW_NUMBER() OVER w AS rn,
    RANK() OVER w AS rnk,
    DENSE_RANK() OVER w AS drnk,
    SUM(salary) OVER w AS cumulative_salary
FROM employees
WINDOW w AS (PARTITION BY dept_id ORDER BY salary DESC);
-- 在 SELECT 后、ORDER BY 前用 WINDOW 子句定义命名窗口
```

## 适用场景

- **排名和分位**：各部门薪资排名、各渠道销售额前 N 名
- **累计汇总**：滚动累计销售额、环比增长
- **前后行比较**：通过 LAG/LEAD 访问上一行/下一行数据，计算变化量
- **分组内取 Top-N**：利用 ROW_NUMBER 取每组的前 N 条记录

---

## 常见问题

**窗口函数能在 WHERE 中使用吗？**

不能直接在 WHERE 中使用，因为窗口函数在 WHERE 之后才执行。必须把窗口函数放在 CTE 或派生表中，外层查询再用 WHERE 过滤：

```sql
-- 错误
SELECT * FROM employees WHERE RANK() OVER (ORDER BY salary DESC) <= 3;

-- 正确：通过 CTE 包一层
WITH ranked AS (
    SELECT *, RANK() OVER (ORDER BY salary DESC) AS rnk FROM employees
)
SELECT * FROM ranked WHERE rnk <= 3;
```

---

## 注意事项

- 窗口函数只能在 SELECT 列表和 ORDER BY 子句中使用，不能在 WHERE、GROUP BY、HAVING 中直接使用。
- 窗口函数在 GROUP BY 之后执行——如果查询同时有 GROUP BY 和窗口函数，窗口函数作用在分组聚合的结果上（每个分组一行），而不是原始行上。

---

## 总结

窗口函数通过 `OVER()` 子句定义计算窗口，在保留所有行的同时为每行附加计算值，是 GROUP BY 聚合的重要补充。`PARTITION BY` 分区，`ORDER BY` 排序，共同定义计算范围。MySQL 8.0+ 支持完整的窗口函数特性，包括排名函数、偏移函数、聚合函数、帧子句等。
