# ROW_NUMBER() 窗口函数

`ROW_NUMBER()` 为查询结果集（或分区）内的每一行分配一个唯一的、连续的整数序号，从 1 开始，在同一分区内不会出现重复编号。它是最常用的窗口函数之一，尤其擅长实现"取每组前 N 条"和分页查询。

---

## 语法

```sql
ROW_NUMBER() OVER (
    [PARTITION BY col1, col2, ...]
    ORDER BY col3 [ASC|DESC]
)
```

`ROW_NUMBER()` 必须配合 `ORDER BY` 使用（否则每次执行的编号顺序不确定）。`PARTITION BY` 可选，有则按分区重置编号。

---

## 基本示例

```sql
-- 对全部员工按薪资降序编号
SELECT id, name, dept_id, salary,
    ROW_NUMBER() OVER (ORDER BY salary DESC) AS rn
FROM employees;
-- rn: 1, 2, 3, 4, 5, 6（全局唯一，即使薪资相同也会给不同编号）

-- 按部门分区，各部门内按薪资降序编号
SELECT id, name, dept_id, salary,
    ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS dept_rn
FROM employees;
-- 每个部门内从 1 重新开始编号
```

---

## 最经典用法：取每组 Top-N

```sql
-- 取每个部门薪资最高的 2 名员工（Top-2）
WITH ranked AS (
    SELECT id, name, dept_id, salary,
        ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rn
    FROM employees
)
SELECT id, name, dept_id, salary
FROM ranked
WHERE rn <= 2;
-- 每个部门取前 2 名，与 RANK() 的区别：相同薪资时 ROW_NUMBER 仍给不同编号

-- 取每个用户最新的 1 条订单
WITH latest_orders AS (
    SELECT *,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at DESC) AS rn
    FROM orders
)
SELECT id, user_id, amount, created_at
FROM latest_orders
WHERE rn = 1;
```

## 用于分页查询（大数据量分页）

```sql
-- 传统 LIMIT OFFSET 分页（深翻页时性能差）
SELECT * FROM products ORDER BY id LIMIT 20 OFFSET 10000;
-- OFFSET 很大时，MySQL 需要扫描并丢弃前 10000 行

-- ROW_NUMBER 分页（"键集分页"的辅助方式）
WITH numbered AS (
    SELECT *,
        ROW_NUMBER() OVER (ORDER BY id) AS rn
    FROM products
)
SELECT * FROM numbered WHERE rn BETWEEN 10001 AND 10020;
-- 但这种方式同样需要计算所有 rn，对大表也慢

-- 更推荐的深翻页方案：游标分页（记住上次的 id）
SELECT * FROM products WHERE id > 10000 ORDER BY id LIMIT 20;
```

## 去除重复数据（保留每组第一条）

```sql
-- 场景：emails 表中有重复 email，保留 id 最小的那条，删除其余
WITH dedup AS (
    SELECT id,
        ROW_NUMBER() OVER (PARTITION BY email ORDER BY id ASC) AS rn
    FROM emails
)
DELETE FROM emails WHERE id IN (
    SELECT id FROM dedup WHERE rn > 1
);
-- rn=1 的是每组 id 最小的（保留），rn>1 的是重复的（删除）
```

## ROW_NUMBER vs RANK vs DENSE_RANK

```sql
-- 三个函数的对比（薪资相同时的行为差异）
SELECT name, salary,
    ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num,
    RANK()       OVER (ORDER BY salary DESC) AS rnk,
    DENSE_RANK() OVER (ORDER BY salary DESC) AS d_rnk
FROM employees;

-- 假设数据：Alice=15000, Bob=15000, Carol=12000
-- row_num: 1, 2, 3     （总是唯一，相同薪资随机分配 1 和 2）
-- rnk:     1, 1, 3     （相同薪资同名次，下一个名次跳过 2）
-- d_rnk:   1, 1, 2     （相同薪资同名次，下一个名次不跳号）
```

## 适用场景

- **取每组 Top-N 记录**：每个分类最热门的 N 个商品、每个用户最近的 N 条行为
- **数据去重**：在重复数据中标记保留第一条，删除其余
- **有序分页**：在结果集中生成行号，用于定位或展示
- **数据对比**：将结果集编号后与另一组编号数据做行级对比

---

## 常见问题

**ROW_NUMBER() 相同 ORDER BY 值的编号顺序是固定的吗？**

不固定。当 ORDER BY 列有相同值时，ROW_NUMBER() 对这些行的编号顺序是不确定的（MySQL 可能在不同执行中给不同顺序）。如果需要确定性的编号，在 ORDER BY 中加入额外的唯一列（如 id）来打破平局：`ORDER BY salary DESC, id ASC`。

---

## 注意事项

- ROW_NUMBER() 的结果不能直接在 WHERE 中过滤，必须通过 CTE 或派生表包一层才能过滤。
- 当需要处理平局（相同 ORDER BY 值应该给相同排名）时，改用 RANK() 或 DENSE_RANK()，而不是 ROW_NUMBER()。

---

## 总结

`ROW_NUMBER()` 为分区内每行分配唯一连续编号，即使 ORDER BY 值相同也给不同编号。最核心的用途是配合 CTE + `WHERE rn <= N` 实现"取每组前 N 条"。与 RANK() 的区别是不会给相同值相同编号，与 DENSE_RANK() 的区别同理。编号不确定时，ORDER BY 中加唯一列确保稳定性。
