# 窗口函数帧子句 ROWS / RANGE

帧子句（Frame Clause）是 `OVER` 子句的可选部分，用于在已排序的分区内进一步限定每行计算所使用的行的范围（即"帧"）。通过帧子句，可以实现滑动平均、累计求和、移动窗口统计等时间序列分析。

---

## 语法

```sql
window_function() OVER (
    [PARTITION BY ...]
    ORDER BY col
    frame_clause
)

-- frame_clause 格式：
frame_type BETWEEN frame_start AND frame_end

-- frame_type：
--   ROWS    ：按物理行数计算偏移
--   RANGE   ：按排序列的值范围计算偏移

-- frame_start / frame_end 可取值：
--   UNBOUNDED PRECEDING  ：分区的第一行
--   n PRECEDING          ：当前行往前 n 行（ROWS）或值差 n（RANGE）
--   CURRENT ROW          ：当前行
--   n FOLLOWING          ：当前行往后 n 行（ROWS）或值差 n（RANGE）
--   UNBOUNDED FOLLOWING  ：分区的最后一行
```

---

## 默认帧子句

```sql
-- 当 OVER 中有 ORDER BY 时，默认帧是：
-- RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
-- 即：从分区起点到当前行（按值范围，相同排序值的行都算"当前行"）

-- 当 OVER 中没有 ORDER BY 时，默认帧是：
-- ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
-- 即：整个分区

-- 这是 LAST_VALUE 陷阱的根源：有 ORDER BY 时默认帧不包含"当前行之后"的行
```

---

## ROWS 帧（按物理行数）

```sql
-- ROWS：严格按行数偏移，与列值无关

-- 滑动 3 行平均（当前行 + 前 2 行）
SELECT 
    order_date,
    daily_amount,
    ROUND(AVG(daily_amount) OVER (
        ORDER BY order_date
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW  -- 窗口：前2行 + 当前行（共3行）
    ), 2) AS moving_avg_3d
FROM daily_sales
ORDER BY order_date;

-- 累计求和（从分区起点到当前行）
SELECT 
    order_date,
    daily_amount,
    SUM(daily_amount) OVER (
        ORDER BY order_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS cumulative_sum
FROM daily_sales;

-- 向后滑动窗口（当前行 + 后 2 行，用于预测）
SELECT 
    order_date,
    daily_amount,
    SUM(daily_amount) OVER (
        ORDER BY order_date
        ROWS BETWEEN CURRENT ROW AND 2 FOLLOWING
    ) AS next_3d_sum
FROM daily_sales;
```

---

## RANGE 帧（按值范围）

```sql
-- RANGE：按排序列的值差（不是行数）计算边界
-- 适用于日期间隔、数值范围等

-- 最近 7 天的滑动销售额（日期类型列的范围）
SELECT 
    order_date,
    daily_amount,
    SUM(daily_amount) OVER (
        ORDER BY order_date
        RANGE BETWEEN INTERVAL 6 DAY PRECEDING AND CURRENT ROW
        -- 帧包含：order_date - 6 天 到 order_date 的所有行
    ) AS rolling_7d_sum
FROM daily_sales;

-- RANGE CURRENT ROW（默认行为）：
-- 所有与当前行 ORDER BY 列值相同的行都属于"CURRENT ROW"帧
SELECT score, 
    SUM(score) OVER (ORDER BY score RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
FROM scores;
-- 相同 score 值的行，SUM 值相同（因为 RANGE CURRENT ROW 把相同值的行算作一组）
```

---

## ROWS vs RANGE 对比

| 对比维度 | ROWS | RANGE |
|---------|------|-------|
| 偏移单位 | 物理行数 | 排序列的值差 |
| 相同排序值的处理 | 每行独立，按位置偏移 | 相同值视为同一帧边界 |
| 日期/时间范围 | 不直接支持（需要行数）| 支持 INTERVAL 语法 |
| 精确控制行数 | 是 | 否 |
| 适用场景 | 滑动 N 行平均 | 时间窗口（最近 N 天）|

---

## 常用帧子句模式

```sql
-- 模式1：累计到当前行（运行总计）
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW

-- 模式2：整个分区（无滑动，等同于不加帧子句且无 ORDER BY）
ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING

-- 模式3：滑动 N 行窗口
ROWS BETWEEN N PRECEDING AND CURRENT ROW          -- 往前 N 行到当前行
ROWS BETWEEN N PRECEDING AND N FOLLOWING           -- 前后各 N 行（中心对称）

-- 模式4：最近 N 天（时间窗口）
RANGE BETWEEN INTERVAL N DAY PRECEDING AND CURRENT ROW
```

---

## 适用场景

- **移动平均**：最近 N 天/N 行的均值（平滑时间序列波动）
- **累计求和**：从起点到当前行的累计金额
- **滑动窗口统计**：任意时间窗口内的 SUM、COUNT、MAX/MIN
- **LAST_VALUE 正确使用**：需要扩展帧到 `UNBOUNDED FOLLOWING` 才能获取分区末尾值

---

## 常见问题

**ROWS 和 RANGE 在没有重复排序值时有区别吗？**

没有区别。当 ORDER BY 列的值完全唯一时，ROWS 和 RANGE 的帧边界是完全相同的。区别只在 ORDER BY 列有重复值时才体现。

---

## 注意事项

- 使用 `RANGE` 时，`ORDER BY` 只能指定**一列**（因为范围是基于单一值的差计算的）。`ROWS` 可以有多列 ORDER BY。
- 帧子句的 `FOLLOWING` 端不能出现在 `PRECEDING` 端之前（如 `ROWS BETWEEN 2 FOLLOWING AND 1 PRECEDING` 是非法的）。

---

## 总结

帧子句定义窗口函数计算时所使用的行范围。`ROWS` 按物理行数偏移，`RANGE` 按排序列的值差偏移。有 ORDER BY 时默认帧是 `RANGE ... CURRENT ROW`（到当前行为止），`LAST_VALUE` 使用时必须扩展到 `UNBOUNDED FOLLOWING`。滑动平均用 `ROWS BETWEEN N PRECEDING AND CURRENT ROW`，时间窗口用 `RANGE BETWEEN INTERVAL N DAY PRECEDING AND CURRENT ROW`。
