# INSERT ... SELECT 批量插入

`INSERT ... SELECT` 将 SELECT 查询的结果集直接插入到目标表中，是跨表数据复制和批量数据迁移的标准方式。与多行 `VALUES` 插入相比，它可以从已有数据中筛选、转换后再写入，表达能力更强。

---

## 语法

```sql
INSERT INTO target_tbl [(col1, col2, ...)]
SELECT col_a, col_b, ...
FROM source_tbl
[WHERE condition]
[GROUP BY ...]
[ORDER BY ...]
[LIMIT n];
```

---

## 基本示例

```sql
-- 将一张表的数据全量复制到另一张表
INSERT INTO users_backup SELECT * FROM users;

-- 指定列映射（只复制部分列）
INSERT INTO users_summary (id, username, email)
SELECT id, username, email FROM users WHERE status = 'active';

-- 数据归档：将旧数据从主表复制到归档表
INSERT INTO orders_archive
SELECT * FROM orders WHERE created_at < '2025-01-01';

-- 从多表 JOIN 的结果插入
INSERT INTO order_reports (user_id, username, order_count, total_amount)
SELECT u.id, u.username, COUNT(o.id), SUM(o.amount)
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE u.status = 'active'
GROUP BY u.id, u.username;
```

## 带数据转换的批量插入

```sql
-- 插入时对数据进行转换（格式化、计算等）
INSERT INTO products_new (id, name, price_cents, created_at)
SELECT 
    id,
    UPPER(name),                      -- 转大写
    ROUND(price * 100),               -- 元转分
    NOW()                             -- 使用当前时间
FROM products_old;

-- 将字符串状态转为数字状态（枚举映射）
INSERT INTO orders_v2 (id, user_id, status_code, amount)
SELECT 
    id,
    user_id,
    CASE status
        WHEN 'pending'   THEN 0
        WHEN 'paid'      THEN 1
        WHEN 'shipped'   THEN 2
        WHEN 'completed' THEN 3
        ELSE 99
    END,
    amount
FROM orders_v1;
```

## 大批量数据的分批插入

对于超大表的数据迁移，一次性 `INSERT ... SELECT` 会生成一个巨大的事务，持有大量 undo log，影响其他业务。应采用分批插入：

```sql
-- 分批迁移数据（每次 1000 行）
-- 方法：按主键范围分批

-- 查找需要迁移的 ID 范围
SELECT MIN(id), MAX(id) FROM orders WHERE created_at < '2025-01-01';
-- 假设是 1 ~ 500000

-- 循环分批执行（在应用层或存储过程中实现）
-- 批次1：id 1 ~ 1000
INSERT INTO orders_archive SELECT * FROM orders WHERE id BETWEEN 1 AND 1000 AND created_at < '2025-01-01';
-- 批次2：id 1001 ~ 2000
INSERT INTO orders_archive SELECT * FROM orders WHERE id BETWEEN 1001 AND 2000 AND created_at < '2025-01-01';
-- ... 依此类推

-- 每批之间可以 COMMIT（分批提交），避免大事务
```

## 避免插入重复数据

```sql
-- 目标表有 UNIQUE 约束时，重复数据会报错
-- 方法1：INSERT IGNORE（跳过重复行）
INSERT IGNORE INTO users_backup
SELECT * FROM users;

-- 方法2：先检查再插入（使用 NOT EXISTS）
INSERT INTO users_backup (id, username, email)
SELECT id, username, email FROM users
WHERE NOT EXISTS (
    SELECT 1 FROM users_backup b WHERE b.id = users.id
);

-- 方法3：ON DUPLICATE KEY UPDATE（重复时更新）
INSERT INTO users_backup (id, username, email)
SELECT id, username, email FROM users
ON DUPLICATE KEY UPDATE
    username = VALUES(username),
    email    = VALUES(email);
```

## 适用场景

- **数据归档**：将主表历史数据批量迁移到归档表
- **汇总报表**：将聚合查询结果写入报表表（预计算）
- **数据迁移**：从旧表迁移到新表（可以同时做数据转换）
- **初始化数据**：将基础数据从种子表复制到业务表

## 常见问题

**INSERT ... SELECT 会锁定源表吗？**

在 InnoDB 的默认隔离级别（REPEATABLE READ）下，SELECT 使用一致性读（快照读），不会锁定源表的行，因此不会阻塞源表上的并发 DML。目标表在写入时持有行锁，但不影响源表。

**INSERT ... SELECT 的 LAST_INSERT_ID() 返回什么？**

返回批量插入中第一行的 AUTO_INCREMENT ID（与多行 VALUES 的行为一致）。

---

## 注意事项

- 执行大量数据的 `INSERT ... SELECT` 时，binlog_format=ROW 模式下会将每行数据记录到 binlog，可能导致 binlog 文件急速增大。如果是一次性迁移，可以考虑临时关闭 binlog（`SET sql_log_bin=0`），但这会导致从库无法同步。
- 超大批量数据迁移应分批执行，避免单事务过大。

---

## 总结

`INSERT ... SELECT` 将查询结果批量写入目标表，支持过滤（WHERE）、聚合（GROUP BY）、连接（JOIN）等完整的 SELECT 功能，同时可以在插入时做数据转换（CASE、计算、函数调用）。大批量迁移应分批执行避免大事务。与 `INSERT IGNORE`、`ON DUPLICATE KEY UPDATE` 配合可以安全地处理重复数据。
