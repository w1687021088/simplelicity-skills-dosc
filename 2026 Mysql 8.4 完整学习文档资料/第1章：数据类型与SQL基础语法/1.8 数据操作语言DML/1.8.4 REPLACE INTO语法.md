# REPLACE INTO 语法

`REPLACE INTO` 是 MySQL 特有的语句，当插入的数据与已有行存在主键或唯一键冲突时，先删除旧行再插入新行。它的语义是"替换"而非"更新"，这一细微区别导致它的行为与 `ON DUPLICATE KEY UPDATE` 有本质不同。

---

## 语法

```sql
REPLACE INTO tbl_name (col1, col2, ...) VALUES (val1, val2, ...);
REPLACE INTO tbl_name SET col1 = val1, col2 = val2;
REPLACE INTO tbl_name (col1, col2) SELECT ...;
```

---

## 基本行为演示

```sql
CREATE TABLE settings (
    key_name  VARCHAR(100) NOT NULL PRIMARY KEY,
    value     VARCHAR(500) NOT NULL,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 初始插入
INSERT INTO settings (key_name, value) VALUES ('max_retry', '3');

-- REPLACE INTO：key_name 重复时，删除旧行，插入新行
REPLACE INTO settings (key_name, value) VALUES ('max_retry', '5');
-- 等效于：DELETE FROM settings WHERE key_name='max_retry'; INSERT INTO settings ...
-- 结果：max_retry 的值变为 '5'，updated_at 是新时间（因为是新插入的行）
SELECT * FROM settings WHERE key_name = 'max_retry';
-- key_name='max_retry', value='5', updated_at=当前时间

-- ROW_COUNT()：
-- 插入新行（无冲突）：= 1
-- 替换旧行（有冲突）：= 2（1 次 DELETE + 1 次 INSERT）
```

---

## REPLACE 与 ON DUPLICATE KEY UPDATE 的关键区别

| 对比维度 | REPLACE INTO | ON DUPLICATE KEY UPDATE |
|---------|-------------|------------------------|
| 操作语义 | DELETE + INSERT | UPDATE |
| 主键/ID 变化 | AUTO_INCREMENT 会重新生成（如果 ID 由系统生成）| 主键不变 |
| 外键子表 | 子表中引用该行的外键数据会被级联处理 | 主键不变，子表不受影响 |
| 未指定的列 | 使用 DEFAULT 值（不保留旧值）| 只更新指定列，其他列保留旧值 |
| ON DELETE 触发器 | 触发 | 不触发 |
| ROW_COUNT | 替换时返回 2 | 更新时返回 2 |

## REPLACE 的"未指定列使用默认值"陷阱

```sql
CREATE TABLE user_profile (
    id          INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    username    VARCHAR(50) NOT NULL,
    bio         TEXT DEFAULT NULL,
    avatar_url  VARCHAR(500) DEFAULT NULL,
    score       INT UNSIGNED NOT NULL DEFAULT 0,
    UNIQUE KEY uk_username (username)
);

INSERT INTO user_profile (username, bio, avatar_url, score) 
VALUES ('alice', '这是个人简介', 'https://cdn.example.com/avatar.jpg', 500);

-- 用 REPLACE 只更新 bio，但 avatar_url 和 score 的旧值会丢失！
REPLACE INTO user_profile (username, bio)
VALUES ('alice', '新的个人简介');
-- 结果：id 变为新值，bio 更新，但 avatar_url = NULL，score = 0（默认值）
-- 旧的 avatar_url 和 score 值被丢弃！

-- 对比：ON DUPLICATE KEY UPDATE 不会丢失其他列的值
INSERT INTO user_profile (username, bio) VALUES ('alice', '新的个人简介')
ON DUPLICATE KEY UPDATE bio = VALUES(bio);
-- 结果：只更新 bio，id、avatar_url、score 全部保留原值
```

## REPLACE 的适用场景

REPLACE INTO 适合以下条件同时满足的场景：
- 操作的是全量数据（每次都提供所有列的值）
- 表没有被外键引用的子表
- 表没有 AUTO_INCREMENT 主键（或主键不参与业务逻辑）
- 没有 ON DELETE 触发器

```sql
-- 典型适用：配置键值对表（primary key 是业务键，不是自增ID）
CREATE TABLE app_config (
    cfg_key     VARCHAR(100) NOT NULL PRIMARY KEY,
    cfg_value   TEXT NOT NULL,
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 每次都是完整设置，用 REPLACE 简洁
REPLACE INTO app_config (cfg_key, cfg_value) VALUES
    ('site_name', 'My Website'),
    ('max_upload_size', '10485760'),
    ('maintenance_mode', 'false');
```

## 常见问题

**REPLACE INTO 后 AUTO_INCREMENT 为什么跳了？**

因为 REPLACE 是 DELETE + INSERT，新插入行会分配一个新的 AUTO_INCREMENT 值。如果表有 AUTO_INCREMENT 主键，每次 REPLACE 触发替换时，旧行被删除后，新行的 ID 是下一个自增值，不是原来的 ID。如果下游系统有缓存或关联了旧 ID，这会造成数据不一致。

---

## 注意事项

- 在有外键引用的父表上使用 REPLACE INTO，其 DELETE 部分会触发外键的 ON DELETE 动作（可能级联删除子表数据）。这个风险非常大，生产环境要特别注意。
- REPLACE INTO 不保留未指定列的旧值，全部重置为默认值，容易造成数据丢失。日常开发中，`ON DUPLICATE KEY UPDATE` 通常是更安全的选择。

---

## 总结

`REPLACE INTO` 通过"先删除再插入"来处理重复键冲突，语义上是"替换"而非"更新"。它不保留未指定列的旧值（使用 DEFAULT），并且会改变 AUTO_INCREMENT 生成的 ID。在有外键引用或自增主键的表上使用需特别谨慎。配置键值对表（以业务键为主键）是 REPLACE INTO 最安全的应用场景；其他情况优先考虑 `ON DUPLICATE KEY UPDATE`。
