# INSERT IGNORE 与 ON DUPLICATE KEY UPDATE

当 INSERT 语句遇到违反唯一约束（PRIMARY KEY 或 UNIQUE KEY）的重复数据时，MySQL 提供了两种处理方式：`INSERT IGNORE`（静默跳过）和 `INSERT ... ON DUPLICATE KEY UPDATE`（更新已存在的行）。这两种方式在日常开发中大量使用，适合处理"存在则更新，不存在则插入"（Upsert）的业务场景。

---

## INSERT IGNORE

遇到重复键（以及部分其他错误）时，直接跳过该行，不报错，也不更新已有数据。

```sql
-- 创建测试表
CREATE TABLE products (
    id       INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    sku      VARCHAR(50) NOT NULL,
    name     VARCHAR(200) NOT NULL,
    price    DECIMAL(10, 2) NOT NULL,
    UNIQUE KEY uk_sku (sku)
);

-- 正常插入
INSERT INTO products (sku, name, price) VALUES ('SKU001', '商品A', 99.00);

-- INSERT IGNORE：sku 重复时跳过，不报错
INSERT IGNORE INTO products (sku, name, price) VALUES
    ('SKU001', '商品A修改版', 88.00),  -- 重复，跳过
    ('SKU002', '商品B', 199.00);       -- 不重复，正常插入

SELECT ROW_COUNT();  -- 1（只有 SKU002 插入成功）

-- INSERT IGNORE 也会跳过其他类型的错误（如 NOT NULL 违反）
-- 跳过后，原有数据不变，只有新数据被插入
```

`INSERT IGNORE` 适用于：导入数据时只关心新数据，不需要更新已有数据。

---

## ON DUPLICATE KEY UPDATE

遇到重复键时，执行 UPDATE 子句更新已有行，而不是插入新行。

```sql
-- Upsert 示例（存在则更新，不存在则插入）
INSERT INTO products (sku, name, price)
VALUES ('SKU001', '商品A Pro', 120.00)
ON DUPLICATE KEY UPDATE
    name  = VALUES(name),   -- VALUES(name) 引用 INSERT 语句中的 name 值
    price = VALUES(price);

-- 或者使用 MySQL 8.0.20+ 的新语法（别名替代 VALUES()）
INSERT INTO products (sku, name, price)
VALUES ('SKU001', '商品A Pro', 120.00) AS new_vals
ON DUPLICATE KEY UPDATE
    name  = new_vals.name,
    price = new_vals.price;

-- 查看影响的行数：
-- 插入新行：ROW_COUNT() = 1
-- 更新已有行（值有变化）：ROW_COUNT() = 2
-- 更新已有行（值相同）：ROW_COUNT() = 0
SELECT ROW_COUNT();
```

## 批量 Upsert

```sql
-- 多行批量 Upsert
INSERT INTO products (sku, name, price) VALUES
    ('SKU001', '商品A', 99.00),
    ('SKU002', '商品B', 199.00),
    ('SKU003', '商品C', 299.00)
ON DUPLICATE KEY UPDATE
    name  = VALUES(name),
    price = VALUES(price);
-- 已存在的 sku 会被更新，不存在的会被插入
```

## 计数器更新（+1 操作）

```sql
-- ON DUPLICATE KEY UPDATE 可以用于实现原子计数器
CREATE TABLE page_views (
    page_key  VARCHAR(100) NOT NULL PRIMARY KEY,
    view_cnt  INT UNSIGNED NOT NULL DEFAULT 0,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 不存在则插入（view_cnt=1），存在则 +1
INSERT INTO page_views (page_key, view_cnt)
VALUES ('home_page', 1)
ON DUPLICATE KEY UPDATE view_cnt = view_cnt + 1;
```

## INSERT IGNORE vs ON DUPLICATE KEY UPDATE 对比

| 对比维度 | INSERT IGNORE | ON DUPLICATE KEY UPDATE |
|---------|--------------|------------------------|
| 重复键处理 | 跳过（不插入，不更新）| 执行 UPDATE 更新已有行 |
| 是否修改已有数据 | 否 | 是 |
| ROW_COUNT 返回 | 跳过的行计为 0 | 更新的行计为 2 |
| AUTO_INCREMENT 消耗 | 会消耗（即使跳过）| 会消耗（即使更新）|
| 其他错误处理 | 跳过部分错误（如 NOT NULL）| 只处理重复键错误 |
| 适用场景 | 幂等导入，忽略重复 | Upsert，需要更新已有数据 |

---

## 适用场景

- **INSERT IGNORE**：数据同步时忽略已存在的记录，只插入新增数据（如增量同步）
- **ON DUPLICATE KEY UPDATE**：计数器自增、配置项的"设置或更新"操作、商品库存同步

---

## 常见问题

**ON DUPLICATE KEY UPDATE 触发的是哪个唯一键冲突？**

当 INSERT 语句同时违反多个唯一约束时，MySQL 使用最先找到冲突的索引来触发 UPDATE 操作，其结果可能不确定（取决于索引扫描顺序）。在设计上应该避免一条 INSERT 语句同时违反多个唯一约束。

**INSERT IGNORE 和 REPLACE INTO 有什么区别？**

INSERT IGNORE 跳过重复行（原数据不变）；REPLACE INTO 删除重复的旧行，然后插入新行（AUTO_INCREMENT 会重新生成，旧行上的关联外键数据可能受影响）。参见 1.8.4 节。

---

## 注意事项

- `ON DUPLICATE KEY UPDATE` 中使用 `VALUES(col)` 引用 INSERT 中的新值，但在 MySQL 8.0.20 后这种写法已被标记为弃用（deprecated），推荐使用行别名（`AS new_vals`）语法。
- 两种语句都会消耗 AUTO_INCREMENT 值，即使最终没有插入新行。在高并发环境中，频繁触发重复键操作可能导致 AUTO_INCREMENT 快速增长（不连续）。

---

## 总结

`INSERT IGNORE` 在遇到重复键时静默跳过，适合只需要保留已有数据的幂等导入场景。`ON DUPLICATE KEY UPDATE` 在遇到重复键时执行更新操作，是实现 Upsert（存在则更新，不存在则插入）的标准方式，广泛用于计数器、配置同步等场景。两者都不中断批量操作，只对违反唯一约束的行做特殊处理。
