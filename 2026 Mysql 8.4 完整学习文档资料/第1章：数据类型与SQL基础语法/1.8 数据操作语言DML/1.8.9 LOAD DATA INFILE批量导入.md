# LOAD DATA INFILE 批量导入

`LOAD DATA INFILE` 是 MySQL 中将文本文件（CSV、TSV 等）批量导入表的最高效方式，其速度远超逐行 INSERT，是大规模数据导入的首选工具。

---

## 语法

```sql
LOAD DATA [LOCAL] INFILE 'file_path'
    [REPLACE | IGNORE]
    INTO TABLE tbl_name
    [FIELDS
        [TERMINATED BY 'str']          -- 字段分隔符，默认 '\t'
        [[OPTIONALLY] ENCLOSED BY 'char']  -- 字段引用字符，默认无
        [ESCAPED BY 'char']            -- 转义字符，默认 '\\'
    ]
    [LINES
        [STARTING BY 'str']            -- 行开始标记
        [TERMINATED BY 'str']          -- 行结束符，默认 '\n'
    ]
    [IGNORE number LINES]              -- 跳过前 N 行（如 CSV 表头）
    [(col_name_or_user_var, ...)]      -- 列映射
    [SET col_name = expr, ...]         -- 列赋值表达式
;
```

- `LOCAL`：从客户端本地读文件（需要 `LOCAL_INFILE=ON`）；不加 LOCAL 则从服务器端读文件
- `REPLACE`：遇到重复键时替换旧行
- `IGNORE`：遇到重复键时跳过

## CSV 文件导入示例

```sql
-- 准备 CSV 文件（users.csv）：
-- id,username,email,score
-- 1,alice,alice@example.com,100
-- 2,bob,bob@example.com,200
-- 3,carol,carol@example.com,150

-- 启用 LOCAL_INFILE（如果使用 LOCAL 方式）
SET GLOBAL local_infile = ON;

-- 导入 CSV（跳过第一行表头）
LOAD DATA LOCAL INFILE 'C:/data/users.csv'
INTO TABLE users
FIELDS TERMINATED BY ',' ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 LINES
(id, username, email, score);

-- 服务端文件导入（文件在 MySQL 服务器上）
LOAD DATA INFILE '/var/lib/mysql-files/users.csv'
INTO TABLE users
FIELDS TERMINATED BY ',' ENCLOSED BY '"'
LINES TERMINATED BY '\r\n'   -- Windows 换行符
IGNORE 1 LINES;
```

## 常用选项示例

```sql
-- TAB 分隔的文件（TSV）
LOAD DATA INFILE '/data/products.tsv'
INTO TABLE products
FIELDS TERMINATED BY '\t'
LINES TERMINATED BY '\n'
IGNORE 1 LINES;

-- 带字段映射（CSV 列顺序与表列顺序不同）
-- CSV: email,username,created_at
LOAD DATA LOCAL INFILE '/data/users2.csv'
INTO TABLE users
FIELDS TERMINATED BY ','
LINES TERMINATED BY '\n'
IGNORE 1 LINES
(email, username, @dummy_col)   -- @dummy_col 是用户变量，丢弃该列
SET created_at = NOW();          -- created_at 不来自文件，设为当前时间

-- 用户变量进行数据转换
LOAD DATA LOCAL INFILE '/data/prices.csv'
INTO TABLE products
FIELDS TERMINATED BY ','
IGNORE 1 LINES
(@id, @name, @price_str)
SET id = @id,
    name = @name,
    price = CAST(@price_str AS DECIMAL(10,2));
```

## 性能对比

```sql
-- LOAD DATA INFILE 与 INSERT 的速度差异（百万行数据量级）
-- INSERT VALUES（逐行）：约 10~20 分钟
-- INSERT VALUES（批量多行，1000行/批）：约 2~5 分钟
-- LOAD DATA INFILE：约 30~60 秒

-- LOAD DATA 速度快的原因：
-- 1. 绕过大部分 SQL 解析开销
-- 2. 直接批量写入，减少索引维护中间开销
-- 3. 使用二进制协议传输（LOCAL 方式）

-- 导入大量数据前可以暂时禁用部分索引
-- 方法1：先 DISABLE KEYS（仅 MyISAM，InnoDB 不支持）
-- 方法2：导入前删除非唯一索引，导入后重建（INPLACE）
-- 方法3：设置 innodb_autoinc_lock_mode=2，减少自增锁竞争
```

## 文件安全限制

```sql
-- 查看允许的安全文件路径（服务器端导入）
SHOW VARIABLES LIKE 'secure_file_priv';
-- 如果为 NULL，禁止文件操作
-- 如果为空字符串，允许任意路径
-- 如果指定路径（如 /var/lib/mysql-files/），只能从该目录读写

-- 修改 secure_file_priv（需要重启 MySQL）
-- 在 my.cnf 中：
-- [mysqld]
-- secure_file_priv = /var/lib/mysql-files
```

## 适用场景

- **大规模数据初始化**：系统上线时一次性导入百万级别的基础数据
- **数据迁移**：从其他数据库导出 CSV，再导入到 MySQL
- **定期数据同步**：每天凌晨通过 CSV 文件批量同步外部系统数据
- **数据恢复**：从备份 CSV 文件恢复数据

## 常见问题

**LOAD DATA 导入后，AUTO_INCREMENT 的值是什么？**

如果 CSV 中包含 id 列（指定了 AUTO_INCREMENT 列的值），导入后 AUTO_INCREMENT 的下一个值会自动更新为已有最大 id + 1。如果 CSV 不包含 id 列（让 MySQL 自动生成），AUTO_INCREMENT 正常递增。

**Windows 和 Linux 的换行符不同怎么处理？**

Windows 文件的换行符是 `\r\n`（CRLF），Linux 是 `\n`（LF）。导入时通过 `LINES TERMINATED BY '\r\n'` 指定 Windows 换行符。如果不确定，可以预先用工具（如 dos2unix）统一转换。

---

## 注意事项

- MySQL 8.0 默认禁用 `local_infile`（`local_infile=OFF`），使用 LOCAL 方式前需要在服务器和客户端都开启：服务端 `SET GLOBAL local_infile=ON`，客户端连接时加 `--local-infile=1`。
- 导入前确认目标表的字符集与 CSV 文件的编码一致（通常都用 UTF-8），否则中文等多字节字符会乱码。

## 总结

`LOAD DATA INFILE` 是 MySQL 最快的批量数据导入方式，速度远超 INSERT，适合百万级以上的数据导入。支持 CSV、TSV 等格式，支持跳过表头行、列映射、数据转换。服务端导入受 `secure_file_priv` 路径限制，客户端导入（LOCAL）需要启用 `local_infile`。大规模数据迁移和初始化时是首选工具。
