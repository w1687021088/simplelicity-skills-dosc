# 自增主键与 INSERT 的关系

AUTO_INCREMENT 是 MySQL 中为整数列自动生成递增值的机制，通常用于主键列。理解 AUTO_INCREMENT 的分配方式、与 INSERT 各种变体的交互行为，以及在高并发和回滚场景中的特性，是正确设计和使用自增主键的基础。

---

## AUTO_INCREMENT 基本行为

```sql
CREATE TABLE test_auto (
    id   INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL
);

-- 插入时不提供 id（让 MySQL 自动生成）
INSERT INTO test_auto (name) VALUES ('Alice');  -- id = 1
INSERT INTO test_auto (name) VALUES ('Bob');    -- id = 2
INSERT INTO test_auto (name) VALUES ('Carol');  -- id = 3

-- 插入时提供 id（手动指定，使用指定值）
INSERT INTO test_auto (id, name) VALUES (10, 'Dave');  -- id = 10
INSERT INTO test_auto (name) VALUES ('Eve');            -- id = 11（从最大值+1继续）

-- AUTO_INCREMENT 列传 NULL 或 0，等同于不提供（自动生成）
INSERT INTO test_auto (id, name) VALUES (NULL, 'Frank');  -- id = 12
INSERT INTO test_auto (id, name) VALUES (0, 'Grace');      -- id = 13
```

---

## 获取最后插入的 AUTO_INCREMENT 值

```sql
-- LAST_INSERT_ID() 返回本次会话最近一次 INSERT 成功生成的自增 ID
INSERT INTO test_auto (name) VALUES ('Henry');
SELECT LAST_INSERT_ID();  -- 返回 Henry 的 id

-- 多行插入时，LAST_INSERT_ID() 返回第一行的 id
INSERT INTO test_auto (name) VALUES ('Iris'), ('Jack'), ('Kate');
SELECT LAST_INSERT_ID();  -- 返回 Iris 的 id（批量中第一行）

-- LAST_INSERT_ID() 是会话级别的，不受其他并发会话影响
-- 即使其他用户同时插入，本会话的 LAST_INSERT_ID() 只返回自己的插入结果
```

## AUTO_INCREMENT 的不连续性

```sql
-- AUTO_INCREMENT 在以下情况下会不连续（这是正常行为）：

-- 1. 事务回滚（分配的 ID 不回退）
START TRANSACTION;
INSERT INTO test_auto (name) VALUES ('Transaction Test');  -- 分配 id = 100（假设）
ROLLBACK;  -- 事务回滚，行不存在，但 id=100 已被消耗，下次从 101 开始

-- 2. INSERT IGNORE 跳过了行
INSERT IGNORE INTO test_auto (id, name) VALUES (5, 'Duplicate');
-- id=5 已存在，跳过。如果有其他自增操作，计数器可能已经推进

-- 3. INSERT ... ON DUPLICATE KEY UPDATE 触发了更新
INSERT INTO test_auto (id, name) VALUES (1, 'Updated')
ON DUPLICATE KEY UPDATE name = VALUES(name);
-- 未插入新行，但自增计数器可能已推进

-- 4. 服务器重启（MySQL 5.x 中 AUTO_INCREMENT 从内存中的最大值重新算，
--    MySQL 8.0+ 将 AUTO_INCREMENT 持久化到 redo log，重启后不重置）
```

## AUTO_INCREMENT 的锁模式

```sql
-- innodb_autoinc_lock_mode 控制自增锁的类型
SHOW VARIABLES LIKE 'innodb_autoinc_lock_mode';

-- 值说明：
-- 0 (Traditional)：每次 INSERT 都加表级 AUTO-INC 锁（最慢，最严格）
-- 1 (Consecutive)：批量插入时加表级锁，简单插入用轻量级锁（MySQL 5.x 默认）
-- 2 (Interleaved)：所有 INSERT 都用轻量级互斥量，无表级锁（MySQL 8.0 默认，最快）
-- MySQL 8.4 默认值为 2

-- 在 innodb_autoinc_lock_mode=2 时：
-- 多行插入的 id 可能不连续（并发插入时各批次的 id 可能交叉）
-- 但单次插入（一条 INSERT 一行）的 id 一定是连续的
```

## 查看和修改 AUTO_INCREMENT 值

```sql
-- 查看表当前的 AUTO_INCREMENT 值
SELECT AUTO_INCREMENT FROM information_schema.TABLES
WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'test_auto';

-- 也可以通过 SHOW CREATE TABLE 看
SHOW CREATE TABLE test_auto;

-- 手动修改 AUTO_INCREMENT 起始值（只能增大，不能减小到已有最大值以下）
ALTER TABLE test_auto AUTO_INCREMENT = 1000;
-- 下次 INSERT 时，id 从 1000 开始
-- 如果表中已有 id > 1000 的行，ALTER 无效（会自动设为 max(id)+1）
```

## 适用场景

- 所有需要唯一行标识的业务表（最常见的主键形式）
- 通过 `LAST_INSERT_ID()` 获取刚插入行的 ID，用于后续关联插入（如先插入主表，再插入子表）

## 常见问题

**自增 ID 用完了怎么办？**

当 INT UNSIGNED（最大约 42 亿）用完后，再 INSERT 会报"超出范围"错误。应提前将列类型升级为 BIGINT UNSIGNED（最大约 1.84×10¹⁹）。对于普通业务，几十年内 BIGINT UNSIGNED 几乎不会用完。

**在主从复制中，自增 ID 在从库上是否一致？**

在 Statement-Based Replication（SBR）下，从库重放 INSERT 语句，自增 ID 由从库自己生成，可能与主库不一致。MySQL 8.0 默认使用 Row-Based Replication（RBR），主库将实际 ID 值写入 binlog，从库直接使用主库的 ID，保持一致。

---

## 注意事项

- 不要依赖自增 ID 的连续性——事务回滚、INSERT IGNORE、服务器重启等情况都可能导致 ID 不连续，这是正常的，业务逻辑不应依赖 ID 无间隙连续。
- MySQL 8.0+ 将 AUTO_INCREMENT 的当前值持久化到 redo log，服务器重启后不会重置（这修复了 MySQL 5.x 中重启后自增值可能"倒退"的 bug）。

---

## 总结

AUTO_INCREMENT 在 INSERT 时自动生成递增整数，通过 `LAST_INSERT_ID()` 获取最新生成的 ID。自增 ID 在回滚、ON DUPLICATE KEY UPDATE、INSERT IGNORE 等场景下可能不连续，这是正常行为。MySQL 8.4 默认 `innodb_autoinc_lock_mode=2`，使用轻量级锁，并发写入性能最好。MySQL 8.0+ 将自增值持久化，重启后不再重置。
