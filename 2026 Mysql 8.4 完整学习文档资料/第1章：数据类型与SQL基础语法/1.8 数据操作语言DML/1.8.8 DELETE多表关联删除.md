# DELETE 多表关联删除

MySQL 支持在 DELETE 语句中通过 JOIN 关联多张表，可以同时从多张表中删除匹配的行，或者根据关联表的条件来删除主表中的数据。这种方式比应用层循环多次 DELETE 更高效。

---

## 语法

```sql
-- 从单表删除，但通过 JOIN 关联表来过滤条件
DELETE t1 FROM t1
JOIN t2 ON t1.col = t2.col
[WHERE condition];

-- 同时从多张表删除
DELETE t1, t2 FROM t1
JOIN t2 ON t1.col = t2.col
[WHERE condition];
```

删除目标表在 `DELETE` 关键字后指定（`DELETE t1`），可以列出多个表（`DELETE t1, t2`），未列出的表中的数据不会被删除。

---

## 基本示例

```sql
-- 场景1：删除没有订单的用户（通过 LEFT JOIN + IS NULL 过滤）
DELETE u FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE o.id IS NULL AND u.created_at < NOW() - INTERVAL 365 DAY;

-- 场景2：删除已过期的 VIP 用户的所有未完成订单
DELETE o FROM orders o
JOIN users u ON o.user_id = u.id
WHERE u.vip_expired_at < NOW() AND o.status = 0;

-- 场景3：删除重复数据（保留 id 最小的行）
DELETE d FROM products d
JOIN (
    SELECT MIN(id) AS keep_id, sku
    FROM products
    GROUP BY sku
    HAVING COUNT(*) > 1
) dup ON d.sku = dup.sku AND d.id != dup.keep_id;
-- 找出重复 sku 的行，删除 id 不是最小的那些
```

## 同时从多张表删除

```sql
-- 同时删除用户及其所有订单（手动级联删除）
DELETE u, o FROM users u
JOIN orders o ON u.id = o.user_id
WHERE u.id = 100;
-- u 表中 id=100 的行被删除
-- o 表中 user_id=100 的所有行也被删除

-- 同时删除用户、订单和订单详情（三表关联）
DELETE u, o, oi FROM users u
JOIN orders o ON u.id = o.user_id
JOIN order_items oi ON o.id = oi.order_id
WHERE u.id = 100;
```

## 子查询方式（替代多表 DELETE）

```sql
-- 子查询方式（语义更清晰，但 MySQL 不能在子查询中引用被删除的表）
-- 正确写法（用派生表包一层）
DELETE FROM orders
WHERE user_id IN (
    SELECT id FROM (
        SELECT id FROM users WHERE status = 'banned'
    ) AS banned_users
);

-- 错误写法（直接在子查询中引用被删除的表）
DELETE FROM orders WHERE user_id IN (SELECT id FROM users WHERE ...);
-- 如果 orders 和 users 没有名字冲突，这通常没问题
-- 但 DELETE FROM users WHERE id IN (SELECT id FROM users WHERE ...) 会报错
-- ERROR: You can't specify target table 'users' for update in FROM clause
```

## 清理重复数据的完整示例

```sql
-- 假设 emails 表中有重复的 email 值，保留每个 email 中 id 最小的行
-- 第一步：查看重复数据
SELECT email, COUNT(*), MIN(id) AS keep_id
FROM emails GROUP BY email HAVING COUNT(*) > 1;

-- 第二步：删除重复行（保留 id 最小的）
DELETE e FROM emails e
JOIN (
    SELECT MIN(id) AS keep_id, email
    FROM emails
    GROUP BY email
    HAVING COUNT(*) > 1
) dup ON e.email = dup.email AND e.id > dup.keep_id;

-- 第三步：验证无重复
SELECT email, COUNT(*) FROM emails GROUP BY email HAVING COUNT(*) > 1;
-- 无结果表示成功
```

## 适用场景

- **级联删除（无外键约束）**：手动删除父表和所有关联子表的数据
- **重复数据清理**：保留每组重复数据中符合条件的那一行，删除其余
- **条件关联删除**：根据另一张表的状态批量删除本表数据

---

## 常见问题

**多表 DELETE 支持 LIMIT 吗？**

不支持，`LIMIT` 只在单表 DELETE 中有效，多表 JOIN DELETE 不能使用 LIMIT。如需分批删除，需要通过主键范围来控制（`WHERE id BETWEEN ... AND ...`）。

---

## 注意事项

- 多表 DELETE 执行前，先用 `SELECT` 语句替换 `DELETE t1` 来验证 JOIN 条件和 WHERE 过滤的结果是否符合预期。
- 同时删除多张表的数据时，删除顺序和锁定顺序由 MySQL 内部决定，在高并发场景下可能产生死锁，需要注意事务设计。

---

## 总结

多表 DELETE 通过 JOIN 语法实现根据关联表条件删除数据，或同时从多张表删除匹配行。`DELETE t1, t2 FROM t1 JOIN t2` 可以一次删除两张表中的关联数据。子查询中不能引用被删除的表（需要用派生表包一层）。执行前务必用 SELECT 验证命中的数据范围。
