# UPDATE 基础语法

`UPDATE` 修改表中已有行的数据，是 DML 中使用最频繁的语句之一。正确使用 WHERE 条件、理解 UPDATE 的执行顺序和 LIMIT 的作用，是编写安全可靠的数据更新逻辑的基础。

---

## 语法

```sql
UPDATE [LOW_PRIORITY] [IGNORE] tbl_name
SET col1 = expr1 [, col2 = expr2 ...]
[WHERE condition]
[ORDER BY ...]
[LIMIT row_count];
```

`IGNORE`：遇到错误（如违反唯一约束）时跳过该行，继续更新其他行。
`ORDER BY + LIMIT`：按指定顺序更新前 N 行（单表 UPDATE 才支持）。

---

## 基本示例

```sql
-- 更新单列
UPDATE users SET status = 'inactive' WHERE id = 42;

-- 更新多列
UPDATE users
SET email = 'new@example.com',
    updated_at = NOW()
WHERE id = 42;

-- 基于当前值计算新值
UPDATE products SET price = price * 0.9 WHERE category_id = 5;   -- 9折
UPDATE users SET score = score + 10 WHERE id IN (1, 2, 3, 4, 5); -- 加分

-- 使用表达式
UPDATE orders SET status = 1, paid_at = NOW() WHERE id = 1001 AND status = 0;

-- 批量按条件更新（使用 CASE）
UPDATE products
SET price = CASE category_id
    WHEN 1 THEN price * 0.95  -- 分类1打95折
    WHEN 2 THEN price * 0.90  -- 分类2打9折
    WHEN 3 THEN price * 0.85  -- 分类3打85折
    ELSE price                -- 其他分类不变
END
WHERE category_id IN (1, 2, 3);
```

## ORDER BY + LIMIT（有序分批更新）

```sql
-- 更新最早的 100 条未处理记录
UPDATE tasks
SET status = 'processing', processor = 'worker-01'
WHERE status = 'pending'
ORDER BY created_at ASC
LIMIT 100;

-- 逐批更新大表（避免长时间持锁）
-- 循环执行，每次更新 1000 行，直到没有更多行
UPDATE old_orders SET archived = 1
WHERE archived = 0 AND created_at < '2024-01-01'
ORDER BY id
LIMIT 1000;
-- 在应用层循环执行，直到 affected rows = 0
```

## UPDATE IGNORE

```sql
-- 当更新会导致唯一键冲突时，跳过该行（不报错）
-- 例如：将 email 更新为已存在的值
UPDATE IGNORE users SET email = 'existing@example.com' WHERE id = 10;
-- 如果 'existing@example.com' 已存在，跳过 id=10 的行，不报错
```

---

## 避免意外全表更新

```sql
-- 危险操作（忘记 WHERE 条件会全表更新）
UPDATE users SET status = 'banned';  -- 所有用户都被封禁！

-- MySQL 的安全模式可以防止无 WHERE 条件的 UPDATE
-- 开启安全模式：
SET SQL_SAFE_UPDATES = 1;
-- 开启后，UPDATE 必须有 WHERE 条件，且 WHERE 中必须包含主键列
UPDATE users SET status = 'banned';  -- 报错：Error Code: 1175
UPDATE users SET status = 'banned' WHERE id = 0; -- 合法（有主键条件）

-- 关闭安全模式：
SET SQL_SAFE_UPDATES = 0;
```

## 查看 UPDATE 的影响行数

```sql
-- 执行 UPDATE 后：
-- ROW_COUNT()：实际被修改的行数（值有实际变化的行）
-- 注意：WHERE 命中但值未变化的行，ROW_COUNT() 不计入

UPDATE users SET score = 100 WHERE id = 1;  -- 假设原来 score 就是 100
SELECT ROW_COUNT();  -- 0（值没有变化，不计入）

UPDATE users SET score = 200 WHERE id = 1;  -- 从 100 改为 200
SELECT ROW_COUNT();  -- 1（值发生了变化）
```

## 适用场景

- **状态变更**：订单状态流转、账号启用/禁用
- **批量修正**：批量更新历史数据中的错误或格式
- **计数器更新**：积分增加、库存扣减、点赞数+1
- **逻辑删除**：将 `is_deleted` 标记从 0 更新为 1

---

## 常见问题

**UPDATE 中可以引用其他列的当前值吗？**

可以，`SET score = score + 10` 就是引用了 score 的当前值进行计算。MySQL 在 UPDATE 中，SET 语句从左到右顺序执行，前面列的新值可以被后面的 SET 表达式引用：

```sql
UPDATE t SET a = 10, b = a + 1;
-- b = 10 + 1 = 11（b 用的是 a 的新值，不是旧值）
```

---

## 注意事项

- **务必检查 WHERE 条件**：在编写 UPDATE 语句前，先用 SELECT 替换 SET ... WHERE，确认命中的行是否符合预期。这是防止意外全表更新的最有效习惯。
- 对于高并发的计数器更新（如库存扣减），`UPDATE products SET stock = stock - 1 WHERE id = 1 AND stock > 0` 是比先 SELECT 再 UPDATE 更安全的写法（避免超卖）。

---

## 总结

UPDATE 修改表中符合 WHERE 条件的行，支持多列同时更新、表达式计算新值、CASE 批量按条件更新。`ORDER BY + LIMIT` 可以实现有序的分批更新，适合大表的分批处理。`SQL_SAFE_UPDATES=1` 可以防止意外的无条件全表更新。执行前用 SELECT 验证 WHERE 条件命中的行是写 UPDATE 语句的最基本安全习惯。
