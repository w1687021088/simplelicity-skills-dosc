# UPDATE 多表关联更新

MySQL 支持在 UPDATE 语句中通过 JOIN 引用多张表，使得可以根据关联表的数据来更新目标表，或者同时更新多张关联表中的数据。这种写法避免了先 SELECT 再循环 UPDATE 的低效模式。

---

## 语法

```sql
-- 多表 UPDATE（通过 JOIN 关联）
UPDATE tbl1
JOIN tbl2 ON tbl1.col = tbl2.col
[JOIN tbl3 ON ...]
SET tbl1.col_a = expr1 [, tbl2.col_b = expr2, ...]
[WHERE condition];

-- 子查询方式（等效，但通常 JOIN 方式性能更好）
UPDATE tbl1
SET col_a = (SELECT ... FROM tbl2 WHERE ...)
WHERE ...;
```

---

## 基本示例

```sql
-- 场景1：根据用户表的 VIP 状态，更新订单表中订单的折扣
UPDATE orders o
JOIN users u ON o.user_id = u.id
SET o.discount_rate = 0.9
WHERE u.is_vip = 1 AND o.status = 0;

-- 场景2：将用户名同步到订单的冗余字段
UPDATE orders o
JOIN users u ON o.user_id = u.id
SET o.username = u.username
WHERE o.username != u.username;  -- 只更新不一致的行

-- 场景3：根据商品分类表，批量更新商品价格
UPDATE products p
JOIN categories c ON p.category_id = c.id
SET p.price = p.price * c.discount_factor
WHERE c.discount_factor IS NOT NULL AND c.discount_factor != 1.0;
```

## 同时更新多张表

```sql
-- 同时更新 orders 和 users 两张表
UPDATE orders o
JOIN users u ON o.user_id = u.id
SET 
    o.status = 2,              -- 更新订单状态
    u.order_count = u.order_count + 1  -- 更新用户订单计数
WHERE o.id = 1001 AND o.status = 1;
```

---

## LEFT JOIN 方式（处理没有匹配行的情况）

```sql
-- 使用 LEFT JOIN，即使关联表中没有匹配行也可以更新主表
-- 场景：将没有下过订单的用户标记为不活跃
UPDATE users u
LEFT JOIN orders o ON u.id = o.user_id
SET u.status = 'inactive'
WHERE o.id IS NULL AND u.created_at < NOW() - INTERVAL 90 DAY;
-- LEFT JOIN + IS NULL：找到 users 中没有关联 orders 的行
```

## 使用子查询的等效写法

```sql
-- 子查询方式（某些情况下更易读）
UPDATE orders
SET discount_rate = 0.9
WHERE user_id IN (
    SELECT id FROM users WHERE is_vip = 1
) AND status = 0;

-- 注意：MySQL 不允许在 UPDATE/DELETE 的子查询中引用被更新的表
-- 以下会报错：
UPDATE users SET score = score + 1 WHERE id IN (SELECT id FROM users WHERE ...);
-- ERROR: You can't specify target table 'users' for update in FROM clause
-- 解决方案：使用派生表包装一层
UPDATE users SET score = score + 1
WHERE id IN (
    SELECT id FROM (SELECT id FROM users WHERE ...) AS sub
);
```

## 性能对比

```sql
-- 低效写法（应用层循环，多次网络往返）
-- PHP/Python 循环：
-- foreach ($vip_user_ids as $uid) {
--     $pdo->exec("UPDATE orders SET discount_rate=0.9 WHERE user_id=$uid AND status=0");
-- }

-- 高效写法（一条 SQL 完成，一次网络往返）
UPDATE orders o JOIN users u ON o.user_id = u.id
SET o.discount_rate = 0.9
WHERE u.is_vip = 1 AND o.status = 0;
-- 对 orders 和 users 都能走索引（user_id, is_vip, status 都有索引时）
```

## 适用场景

- **数据同步**：将一张表的字段同步到另一张表的冗余字段
- **批量状态变更**：根据关联表的状态批量更新主表
- **数据修正**：根据参照表批量修正数据
- **统计字段维护**：根据明细表更新汇总表的计数或金额

---

## 常见问题

**多表 UPDATE 中 WHERE 条件应该放哪里？**

WHERE 条件放在所有 JOIN 和 SET 之后，可以引用任何 JOIN 涉及的表的列。建议将最能缩小数据范围的条件放在 WHERE 中，充分利用索引。

**多表 UPDATE 支持 ORDER BY 和 LIMIT 吗？**

不支持，`ORDER BY` 和 `LIMIT` 只在单表 UPDATE 中有效，多表 JOIN 的 UPDATE 不能使用这两个子句。

---

## 注意事项

- 多表 UPDATE 中，被更新的表（SET 涉及的表）不能在子查询中再次引用（MySQL 限制），需要用派生表（子查询包一层）来绕过。
- 在更新之前，先用 `SELECT ... WHERE ...` 验证 JOIN 条件和 WHERE 条件命中的行，确认逻辑正确，避免意外批量更新错误数据。

---

## 总结

多表 UPDATE 通过 JOIN 语法让一条 SQL 可以根据关联表的数据来更新目标表，或者同时更新多张表。这种方式比应用层循环 UPDATE 效率高很多。LEFT JOIN 配合 IS NULL 可以处理"关联表中没有匹配行"的场景。执行前务必先用 SELECT 验证命中数据的正确性。
