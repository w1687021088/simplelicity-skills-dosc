# 事务中的 DML（BEGIN / COMMIT / ROLLBACK）

MySQL 的 InnoDB 存储引擎支持完整的 ACID 事务。将 DML 语句（INSERT、UPDATE、DELETE）包裹在事务中，可以保证一组操作要么全部成功提交，要么全部回滚撤销，避免数据进入中间状态。

---

## 基本事务语法

```sql
-- 开启事务（三种等价写法）
BEGIN;
START TRANSACTION;
START TRANSACTION WITH CONSISTENT SNAPSHOT;  -- 立即建立一致性快照读视图

-- 提交事务（将修改持久化）
COMMIT;

-- 回滚事务（撤销所有未提交的修改）
ROLLBACK;
```

---

## 事务的基本使用

```sql
-- 场景：转账操作（必须保证两个 UPDATE 同时成功或同时失败）
START TRANSACTION;

UPDATE accounts SET balance = balance - 500 WHERE user_id = 1;
-- 检查是否成功，balance 不能为负
SELECT balance FROM accounts WHERE user_id = 1;
-- 假设 balance = 300（转账后余额合理）

UPDATE accounts SET balance = balance + 500 WHERE user_id = 2;

-- 两步都成功，提交
COMMIT;

-- 如果任意步骤失败，回滚
-- ROLLBACK;
```

## autocommit 模式

```sql
-- MySQL 默认 autocommit = ON（每条 DML 自动提交）
SHOW VARIABLES LIKE 'autocommit';
-- Value: ON

-- autocommit=ON 时，每条 DML 语句执行后自动提交，无法回滚
-- 这是为什么直接执行 DELETE FROM t 后不能回滚的原因

-- 临时关闭 autocommit（当前会话有效）
SET autocommit = 0;
-- 关闭后，DML 需要手动 COMMIT 才能持久化

-- 恢复 autocommit
SET autocommit = 1;

-- 无论 autocommit 是否开启，显式 BEGIN 都会开启新事务
-- 在 BEGIN 之后，autocommit 的设置对本事务内的 DML 无效
-- 直到 COMMIT 或 ROLLBACK 结束事务
```

## SAVEPOINT（保存点）

```sql
-- SAVEPOINT 允许在事务内设置中间检查点，可以部分回滚
START TRANSACTION;

INSERT INTO orders (user_id, amount) VALUES (100, 500.00);
SAVEPOINT sp_order;  -- 设置保存点

INSERT INTO order_items (order_id, product_id, qty) VALUES (LAST_INSERT_ID(), 1, 2);
-- 假设这步失败（如 product_id 不存在）

-- 回滚到保存点（订单主行保留，只撤销订单详情的插入）
ROLLBACK TO SAVEPOINT sp_order;
-- 现在可以修正数据后重新插入订单详情

INSERT INTO order_items (order_id, product_id, qty) VALUES (LAST_INSERT_ID(), 2, 2);  -- 改用 product_id=2

-- 全部成功后提交
COMMIT;

-- 删除保存点（不再需要时）
RELEASE SAVEPOINT sp_order;
```

## DDL 语句的隐式提交

```sql
-- DDL 语句（CREATE, ALTER, DROP, TRUNCATE 等）会隐式提交当前事务
START TRANSACTION;
INSERT INTO t VALUES (1, 'test');
-- 还未提交

ALTER TABLE t ADD COLUMN new_col INT;
-- 这条 DDL 语句自动提交了上面的 INSERT，然后执行 ALTER
-- 此时即使 ROLLBACK 也无法撤销 INSERT

-- 结论：不要在事务中混用 DDL 和 DML（DDL 会打断事务）
```

## 常见的事务使用模式

```sql
-- 模式1：标准的错误处理事务（在存储过程中）
DELIMITER //
CREATE PROCEDURE create_order(IN p_user_id INT, IN p_amount DECIMAL(10,2))
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '订单创建失败，已回滚';
    END;
    
    START TRANSACTION;
    
    INSERT INTO orders (user_id, amount) VALUES (p_user_id, p_amount);
    UPDATE users SET order_count = order_count + 1 WHERE id = p_user_id;
    
    COMMIT;
END //
DELIMITER ;

-- 模式2：应用层事务（在应用代码中管理事务，最常见）
```

## 适用场景

- **金融转账**：借方扣款和贷方入账必须原子完成
- **订单创建**：插入订单主表 + 订单详情表 + 扣减库存，必须全部成功或全部失败
- **批量数据操作**：在事务内包裹多条 INSERT/UPDATE，减少自动提交的频率，提升性能
- **数据修正**：手动执行高风险 DML 时，用事务保护，执行前先验证再提交

---

## 常见问题

**事务占用了锁，会影响其他查询吗？**

是的，InnoDB 的行锁在事务提交或回滚前一直持有。长时间不提交的事务会持续持锁，导致其他事务等待。生产环境要避免"开了事务但长时间不提交"的情况（如事务内有网络调用或用户等待）。

---

## 注意事项

- DDL 语句（CREATE、ALTER、DROP、TRUNCATE）会隐式提交当前事务，不要在事务内混用 DDL。
- 长事务会持续占用 undo log 空间（用于 MVCC 历史版本），影响整个 InnoDB 的性能。避免长时间不提交的事务。
- `ROLLBACK TO SAVEPOINT` 不结束事务，只回滚到保存点。完整结束事务仍需 COMMIT 或 ROLLBACK。

---

## 总结

`BEGIN / START TRANSACTION` 开启事务，`COMMIT` 提交，`ROLLBACK` 回滚。MySQL 默认 `autocommit=ON`，每条 DML 自动提交；显式 `BEGIN` 可以开启手动控制的事务。SAVEPOINT 允许事务内部分回滚。DDL 语句会隐式提交当前事务。长事务持锁影响并发性能，应尽量保持事务短小、及时提交。
