# DELETE 基础语法

`DELETE` 从表中删除符合条件的行，是 DML 中不可逆（但在事务中可回滚）的删除操作。与 TRUNCATE 不同，DELETE 支持 WHERE 条件、ORDER BY + LIMIT 分批删除，并且记录 Undo Log，可以在事务内回滚。

---

## 语法

```sql
DELETE [LOW_PRIORITY] [QUICK] [IGNORE] FROM tbl_name
[WHERE condition]
[ORDER BY ...]
[LIMIT row_count];
```

- `IGNORE`：遇到错误（如外键约束）时跳过该行，继续删除其他行
- `ORDER BY + LIMIT`：按指定顺序删除前 N 行（仅单表 DELETE）

---

## 基本示例

```sql
-- 删除单行（按主键）
DELETE FROM users WHERE id = 42;

-- 删除多行（按条件）
DELETE FROM sessions WHERE expired_at < NOW();

-- 删除特定状态的数据
DELETE FROM orders WHERE status = 'cancelled' AND created_at < NOW() - INTERVAL 30 DAY;

-- 使用 IN 批量删除
DELETE FROM products WHERE id IN (101, 102, 103, 104);

-- 删除所有行（等同 TRUNCATE，但更慢，可回滚）
DELETE FROM temp_logs;  -- 不推荐，用 TRUNCATE 替代
```

---

## ORDER BY + LIMIT（分批删除）

```sql
-- 按时间顺序删除最旧的 1000 条记录
DELETE FROM audit_logs
WHERE created_at < '2024-01-01'
ORDER BY created_at ASC
LIMIT 1000;

-- 循环分批删除大量数据（避免长时间持锁）
-- 在应用层循环执行，直到 ROW_COUNT() = 0
-- 每批删 1000 行，每批间可以 COMMIT 释放锁
DELETE FROM old_data WHERE created_at < '2023-01-01' LIMIT 1000;
-- ... repeat until ROW_COUNT() = 0
```

---

## 事务内的 DELETE（可回滚）

```sql
-- DELETE 在事务内是可回滚的
START TRANSACTION;
DELETE FROM orders WHERE user_id = 100;  -- 删除用户 100 的所有订单
-- 此时可以检查影响行数
SELECT ROW_COUNT();  -- 查看删了多少行

-- 如果确认正确，提交
COMMIT;

-- 如果发现删错了，回滚
ROLLBACK;  -- 数据恢复，删除操作撤销
```

---

## DELETE IGNORE

```sql
-- 当 DELETE 会触发外键约束报错时，IGNORE 可跳过该行
-- 例如：试图删除有子表引用的父行
DELETE IGNORE FROM departments WHERE id IN (1, 2, 3);
-- id=1 有员工关联（外键），跳过
-- id=2 没有关联，删除成功
-- id=3 没有关联，删除成功
-- 不会因为 id=1 报错而中断整个操作
```

---

## 查看删除行数

```sql
DELETE FROM expired_tokens WHERE expired_at < NOW();
SELECT ROW_COUNT();  -- 实际删除的行数
-- ROW_COUNT() 只在当前语句执行后立即有效，后续查询会重置
```

---

## 防止意外全表删除

```sql
-- 危险：没有 WHERE 条件，删除所有行
DELETE FROM users;  -- 全表删除！

-- 同 UPDATE 一样，SQL_SAFE_UPDATES 可以防止无 WHERE 的 DELETE
SET SQL_SAFE_UPDATES = 1;
DELETE FROM users;  -- 报错：Error Code: 1175 (You are using safe update mode)
```

## 适用场景

- **定期清理**：删除过期会话、历史日志、已取消订单
- **数据纠错**：删除重复数据或错误录入的数据
- **级联清理**：删除用户时同步清理相关数据（如无外键约束时手动级联）
- **分批大量删除**：配合 LIMIT 避免一次删除大量数据导致锁等待

---

## 常见问题

**DELETE 后磁盘空间释放了吗？**

InnoDB 的 DELETE 不立即释放磁盘空间——删除的行被标记为"可重用"，`.ibd` 文件大小不减少。执行 `OPTIMIZE TABLE` 可以真正释放空间（但会重建表，对大表影响较大）。

**DELETE 比 TRUNCATE 慢多少？**

DELETE 需要为每一行记录 Undo Log（支持回滚）和 Binlog，时间与删除行数成正比。TRUNCATE 直接重建表空间，速度与表大小无关。对于清空整张表，TRUNCATE 比 DELETE 快几个数量级。

---

## 注意事项

- 执行 DELETE 前，先用 `SELECT COUNT(*) WHERE ...` 确认会命中多少行。特别是在生产环境，务必验证 WHERE 条件的正确性。
- 大量数据的 DELETE 应分批执行（配合 LIMIT），每批操作间可以 COMMIT，避免单个大事务持有大量行锁影响其他业务。

---

## 总结

DELETE 支持 WHERE 过滤、ORDER BY + LIMIT 分批删除，记录 Undo Log，在事务内可回滚。不加 WHERE 会删除所有行（比 TRUNCATE 慢且可回滚）。对大量数据的删除应分批进行，避免长时间持锁和大事务 Undo Log 问题。生产环境删除前必须用 SELECT 验证 WHERE 条件的命中范围。
