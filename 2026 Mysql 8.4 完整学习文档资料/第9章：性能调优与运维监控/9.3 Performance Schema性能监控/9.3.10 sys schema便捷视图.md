# sys schema 便捷视图

sys schema 是 MySQL 5.7.7+ 内置的一组视图、存储过程和函数，建立在 Performance Schema 和 INFORMATION_SCHEMA 之上。它的核心价值在于将 Performance Schema 中需要复杂 SQL 才能获取的数据，包装成简单直观的视图，并自动将皮秒转换为可读时间格式（如 1.23 s、45.6 ms）、字节转换为可读单位（如 1.5 GiB、256 MiB）。DBA 不再需要记住 Performance Schema 表的复杂列名和单位换算，直接查询 sys schema 即可获得关键的性能诊断信息。

---

## 语句分析视图

```sql
-- statement_analysis：按语句指纹聚合统计（最常用的视图之一）
-- 等价于查询 events_statements_summary_by_digest 但格式更友好
SELECT
    query,
    db,
    exec_count,
    total_latency,
    avg_latency,
    max_latency,
    rows_sent,
    rows_examined,
    rows_sent_avg,
    rows_examined_avg,
    tmp_disk_tables,
    full_scans
FROM sys.statement_analysis
ORDER BY total_latency DESC
LIMIT 10;

-- statements_with_full_table_scans：使用全表扫描的语句
SELECT
    query,
    db,
    exec_count,
    total_latency,
    no_index_used_count,
    rows_examined_avg,
    rows_sent_avg
FROM sys.statements_with_full_table_scans
ORDER BY no_index_used_count DESC
LIMIT 10;

-- statements_with_temp_tables：使用临时表的语句
SELECT
    query,
    db,
    exec_count,
    total_latency,
    tmp_tables,
    tmp_disk_tables,
    tmp_tables_to_disk_pct
FROM sys.statements_with_temp_tables
ORDER BY tmp_disk_tables DESC
LIMIT 10;

-- statements_with_sorting：使用排序的语句
SELECT
    query,
    db,
    exec_count,
    total_latency,
    sort_merge_passes,
    avg_sort_merges,
    sorts_using_scans
FROM sys.statements_with_sorting
ORDER BY sort_merge_passes DESC
LIMIT 10;

-- statements_with_errors_or_warnings：有错误或警告的语句
SELECT * FROM sys.statements_with_errors_or_warnings
ORDER BY errors DESC
LIMIT 10;
```

## I/O 和表统计视图

```sql
-- io_global_by_file_by_bytes：按文件查看 I/O（字节）
SELECT * FROM sys.io_global_by_file_by_bytes
LIMIT 10;

-- io_global_by_file_by_latency：按文件查看 I/O（延迟）
SELECT * FROM sys.io_global_by_file_by_latency
LIMIT 10;

-- io_global_by_wait_by_bytes：按等待类型查看 I/O
SELECT * FROM sys.io_global_by_wait_by_bytes
LIMIT 10;

-- schema_table_statistics：按表查看操作统计
SELECT
    table_schema,
    table_name,
    rows_fetched,
    fetch_latency,
    rows_inserted,
    insert_latency,
    rows_updated,
    update_latency,
    rows_deleted,
    delete_latency,
    io_read,
    io_write
FROM sys.schema_table_statistics
WHERE table_schema NOT IN ('mysql', 'sys', 'performance_schema')
ORDER BY fetch_latency DESC
LIMIT 10;

-- schema_table_statistics_with_buffer：包含 Buffer Pool 信息
SELECT
    table_schema,
    table_name,
    innodb_buffer_allocated,
    innodb_buffer_data,
    innodb_buffer_pages
FROM sys.schema_table_statistics_with_buffer
WHERE table_schema NOT IN ('mysql', 'sys', 'performance_schema')
ORDER BY innodb_buffer_allocated DESC
LIMIT 10;
```

## 索引分析视图

```sql
-- schema_unused_indexes：未使用的索引
SELECT
    object_schema,
    object_name,
    index_name
FROM sys.schema_unused_indexes
WHERE object_schema NOT IN ('mysql', 'sys', 'performance_schema');
-- 这些索引可能是冗余的，可以考虑删除
-- 但要确保统计数据覆盖了足够长的业务周期

-- schema_redundant_indexes：冗余索引
SELECT
    table_schema,
    table_name,
    redundant_index_name,
    redundant_index_columns,
    dominant_index_name,
    dominant_index_columns
FROM sys.schema_redundant_indexes
WHERE table_schema NOT IN ('mysql', 'sys', 'performance_schema');
-- 冗余索引：一个索引是另一个索引的前缀
-- 例如 INDEX(a) 被 INDEX(a, b) 覆盖
-- 删除冗余索引可以减少写入开销和磁盘占用

-- schema_index_statistics：索引使用统计
SELECT
    table_schema,
    table_name,
    index_name,
    rows_selected,
    select_latency,
    rows_inserted,
    insert_latency,
    rows_updated,
    update_latency,
    rows_deleted,
    delete_latency
FROM sys.schema_index_statistics
WHERE table_schema NOT IN ('mysql', 'sys', 'performance_schema')
ORDER BY select_latency DESC
LIMIT 10;
```

## 实用工具视图和存储过程

```sql
-- innodb_buffer_stats_by_schema：按 Schema 查看 Buffer Pool 使用
SELECT * FROM sys.innodb_buffer_stats_by_schema;

-- innodb_buffer_stats_by_table：按表查看 Buffer Pool 使用
SELECT * FROM sys.innodb_buffer_stats_by_table
ORDER BY allocated DESC
LIMIT 10;

-- processlist：增强版 SHOW PROCESSLIST
SELECT * FROM sys.processlist
WHERE conn_id IS NOT NULL
LIMIT 20;
-- 比 SHOW PROCESSLIST 多：完整 SQL、执行进度、锁等信息

-- session：当前会话信息
SELECT * FROM sys.session;

-- metrics：综合指标视图（合并 global_status 和 innodb_metrics）
SELECT * FROM sys.metrics
WHERE Variable_name LIKE 'innodb_buffer_pool%'
LIMIT 10;

-- 常用存储过程：
-- 创建语句的 EXPLAIN 分析：
CALL sys.ps_trace_statement_digest('DIGEST_HASH', 10, 0.1, TRUE, TRUE);

-- 启用/禁用探针和消费者：
CALL sys.ps_setup_enable_instrument('wait');
CALL sys.ps_setup_disable_instrument('wait');
CALL sys.ps_setup_enable_consumer('history_long');

-- 重置所有 Performance Schema 统计：
CALL sys.ps_truncate_all_tables(FALSE);
```

## x$ 视图

```sql
-- sys schema 中每个视图都有一个 x$ 前缀的对应版本
-- 普通视图：格式化输出（如 1.23 GiB、45.6 ms）
-- x$ 视图：原始数值（如 1320702443520 字节、45600000000 皮秒）

-- 普通视图适合人工查看：
SELECT * FROM sys.statement_analysis LIMIT 5;

SELECT * FROM sys.x$statement_analysis LIMIT 5;
```

## 适用场景

- **日常性能巡检**：DBA 每天查看 `statement_analysis`（TOP SQL）、`schema_unused_indexes`（冗余索引）、`memory_global_by_current_bytes`（内存分布），快速了解数据库健康状态
- **快速定位性能问题**：收到告警后，通过 `processlist`（当前活动）、`statements_with_full_table_scans`（全表扫描）、`waits_global_by_latency`（等待瓶颈）快速定位问题原因

## 常见问题

**查询 sys schema 视图很慢，有时候要几秒甚至更久，为什么？**

sys schema 的视图底层是对 Performance Schema 表的查询，某些视图涉及多表 JOIN 和聚合操作。特别是 `schema_table_statistics_with_buffer` 视图需要查询 `INFORMATION_SCHEMA.INNODB_BUFFER_PAGE`（InnoDB Buffer Pool 中所有页面的信息），在 Buffer Pool 很大（如 64GB+）时可能包含数百万行，查询耗时较长。建议：①避免频繁查询包含 buffer 信息的视图；②对于监控系统，使用 x$ 视图并限制查询频率（如每 5 分钟一次）；③对于简单的 TOP SQL 分析，直接查 `statement_analysis` 通常很快。

---

## 注意事项

- sys schema 依赖 Performance Schema 启用，如果 `performance_schema=OFF`，sys schema 的视图会返回空结果或报错。同时，sys schema 的部分视图依赖特定的探针和消费者启用。例如 `waits_global_by_latency` 需要 wait 探针启用，`statements_with_full_table_scans` 需要 statement 探针启用。如果查询结果为空，先检查相关的探针和消费者是否已启用。
- sys schema 的 `schema_unused_indexes` 视图不包含主键。因为主键在 InnoDB 中是聚簇索引，即使不被 SELECT 查询直接使用，也承载着数据存储本身，不能删除。该视图只列出未被使用的二级索引。

## 总结

sys schema 是 Performance Schema 的"友好界面"，提供格式化的视图和便捷的存储过程。核心视图：`statement_analysis`（TOP SQL）、`schema_table_statistics`（表统计）、`schema_unused_indexes`/`schema_redundant_indexes`（索引分析）、`memory_global_by_current_bytes`（内存分布）、`io_global_by_file_by_latency`（文件 I/O）、`processlist`（增强进程列表）、`waits_global_by_latency`（等待分析）。每个视图有 x$ 对应版本（原始数值）。依赖 Performance Schema 启用。部分视图（含 buffer）查询较慢。
