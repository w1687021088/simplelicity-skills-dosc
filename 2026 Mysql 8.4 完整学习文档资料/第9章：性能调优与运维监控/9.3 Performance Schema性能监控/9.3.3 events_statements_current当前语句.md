# events_statements_current 当前语句

`events_statements_current` 表记录每个线程当前正在执行（或最近一次执行完成）的 SQL 语句信息。每个线程在该表中最多只有一行记录，反映该线程此刻的语句执行状态。这是实时分析"MySQL 现在正在做什么"的核心工具，类似于 `SHOW PROCESSLIST` 但提供更详细的执行统计数据（如扫描行数、返回行数、执行时间、错误码等）。

---

## 基本查询

```sql
-- 查看所有线程当前正在执行的语句：
SELECT
    THREAD_ID,
    EVENT_ID,
    SQL_TEXT,
    DIGEST_TEXT,
    CURRENT_SCHEMA,
    TIMER_WAIT / 1000000000000 AS exec_time_sec,
    ROWS_SENT,
    ROWS_EXAMINED,
    ROWS_AFFECTED,
    CREATED_TMP_TABLES,
    CREATED_TMP_DISK_TABLES,
    NO_INDEX_USED,
    NO_GOOD_INDEX_USED
FROM performance_schema.events_statements_current
WHERE SQL_TEXT IS NOT NULL
ORDER BY TIMER_WAIT DESC;

-- 查看正在执行的慢查询（执行时间 > 1秒）：
SELECT
    t.PROCESSLIST_USER AS user,
    t.PROCESSLIST_HOST AS host,
    t.PROCESSLIST_DB AS db,
    esc.SQL_TEXT,
    esc.TIMER_WAIT / 1000000000000 AS exec_time_sec,
    esc.ROWS_EXAMINED,
    esc.ROWS_SENT
FROM performance_schema.events_statements_current esc
JOIN performance_schema.threads t ON esc.THREAD_ID = t.THREAD_ID
WHERE esc.TIMER_WAIT > 1000000000000  -- 1 秒 = 1e12 皮秒
  AND esc.END_EVENT_ID IS NULL         -- 仍在执行中
  AND t.TYPE = 'FOREGROUND'
ORDER BY esc.TIMER_WAIT DESC;
```

## 关键列说明

```sql
-- events_statements_current 表的重要列：

-- 标识列：
-- THREAD_ID：线程 ID（内部 ID，不同于 PROCESSLIST_ID）
-- EVENT_ID：事件 ID（递增）
-- END_EVENT_ID：事件结束时的 ID（NULL 表示仍在执行）

-- SQL 内容：
-- SQL_TEXT：完整的 SQL 语句文本（可能被截断）
-- DIGEST：语句指纹的哈希值
-- DIGEST_TEXT：参数化后的语句模板
-- CURRENT_SCHEMA：执行时的默认数据库

-- 执行时间（单位：皮秒，1秒 = 1e12 皮秒）：
-- TIMER_START：开始执行的时间戳
-- TIMER_END：结束执行的时间戳（执行中为当前时间）
-- TIMER_WAIT：总执行时间 = TIMER_END - TIMER_START
-- LOCK_TIME：等待表锁的时间

-- 行统计：
-- ROWS_SENT：返回给客户端的行数
-- ROWS_EXAMINED：扫描的行数
-- ROWS_AFFECTED：INSERT/UPDATE/DELETE 影响的行数

-- 临时表：
-- CREATED_TMP_TABLES：创建的内存临时表数
-- CREATED_TMP_DISK_TABLES：创建的磁盘临时表数（性能差）

-- 排序：
-- SORT_ROWS：排序的行数
-- SORT_MERGE_PASSES：排序合并的趟数

-- 索引使用：
-- NO_INDEX_USED：1 表示没有使用索引
-- NO_GOOD_INDEX_USED：1 表示没有使用好的索引

-- 错误和警告：
-- ERRORS：错误数
-- WARNINGS：警告数
-- MESSAGE_TEXT：错误或状态信息

-- 嵌套信息（存储过程中的语句）：
-- NESTING_EVENT_ID：父事件 ID
-- NESTING_EVENT_TYPE：父事件类型
-- NESTING_LEVEL：嵌套层级
```

## 与 SHOW PROCESSLIST 的对比

| 对比维度 | SHOW PROCESSLIST | events_statements_current |
|---------|:---------------:|:-----------------------:|
| 获取方式 | SQL 命令 | 查询 performance_schema 表 |
| SQL 文本长度 | 截断到 100 字符 | 截断到 1024 字符（可配置）|
| 执行时间 | 秒级 | 皮秒级（精确到微秒）|
| 行统计 | 无 | 有（ROWS_SENT/EXAMINED/AFFECTED）|
| 临时表信息 | 无 | 有 |
| 索引使用 | 无 | 有 |
| 语句指纹 | 无 | 有（DIGEST/DIGEST_TEXT）|
| 历史记录 | 无 | 有（配合 history 表）|
| 性能影响 | 获取全局锁 | 无锁读取 |

## 实用查询示例

```sql
-- 找出当前扫描行数最多的查询（可能缺少索引）：
SELECT
    t.PROCESSLIST_USER,
    t.PROCESSLIST_DB,
    esc.SQL_TEXT,
    esc.ROWS_EXAMINED,
    esc.ROWS_SENT,
    esc.ROWS_EXAMINED / GREATEST(esc.ROWS_SENT, 1) AS scan_ratio
FROM performance_schema.events_statements_current esc
JOIN performance_schema.threads t ON esc.THREAD_ID = t.THREAD_ID
WHERE esc.SQL_TEXT IS NOT NULL
  AND esc.ROWS_EXAMINED > 10000
ORDER BY esc.ROWS_EXAMINED DESC
LIMIT 10;

-- 找出创建了磁盘临时表的查询（性能差）：
SELECT
    t.PROCESSLIST_USER,
    esc.SQL_TEXT,
    esc.CREATED_TMP_TABLES,
    esc.CREATED_TMP_DISK_TABLES,
    esc.TIMER_WAIT / 1000000000000 AS exec_time_sec
FROM performance_schema.events_statements_current esc
JOIN performance_schema.threads t ON esc.THREAD_ID = t.THREAD_ID
WHERE esc.CREATED_TMP_DISK_TABLES > 0;

-- 将 THREAD_ID 转换为 PROCESSLIST_ID（用于 KILL）：
SELECT
    t.PROCESSLIST_ID,
    t.PROCESSLIST_USER,
    esc.SQL_TEXT,
    esc.TIMER_WAIT / 1000000000000 AS exec_time_sec
FROM performance_schema.events_statements_current esc
JOIN performance_schema.threads t ON esc.THREAD_ID = t.THREAD_ID
WHERE esc.END_EVENT_ID IS NULL
  AND t.TYPE = 'FOREGROUND'
ORDER BY esc.TIMER_WAIT DESC;
-- 如果需要终止查询：KILL <PROCESSLIST_ID>
```

## 适用场景

- **实时监控当前数据库活动**：查看每个线程正在执行的 SQL，比 `SHOW PROCESSLIST` 提供更详细的执行指标
- **定位长时间运行的查询**：找出执行时间长、扫描行数多、创建磁盘临时表的问题查询，配合 EXPLAIN 优化

## 常见问题

**events_statements_current 表中看到的 SQL_TEXT 被截断了，如何看到完整 SQL？**

`SQL_TEXT` 列的最大长度由 `performance_schema_max_sql_text_length` 参数控制，默认值为 1024 字节。超过此长度的 SQL 会被截断。如果需要查看更长的 SQL，需要在 my.cnf 中增大该参数（如 `performance_schema_max_sql_text_length = 4096`）并重启 MySQL。该参数只能在启动时设置。注意增大此值会增加 Performance Schema 的内存使用。

---

## 注意事项

- `events_statements_current` 表的 `END_EVENT_ID` 列用于判断语句是否仍在执行中。`END_EVENT_ID IS NULL` 表示语句正在执行；非 NULL 表示已完成。已完成的语句在该表中保留到线程开始执行下一条语句时才被替换。因此即使线程处于空闲状态（Sleep），表中仍可能有该线程上一条已完成语句的记录。
- `TIMER_WAIT` 的单位是皮秒（picoseconds，10^-12 秒）。将其转换为秒需要除以 10^12（即 1000000000000）。转换为毫秒除以 10^9，转换为微秒除以 10^6。在写查询时注意单位换算。

---

## 总结

`events_statements_current` 记录每个线程当前/最近执行的 SQL 语句及详细统计。每线程一行。提供 SQL_TEXT、执行时间、ROWS_EXAMINED/SENT/AFFECTED、临时表、索引使用、错误等信息。比 `SHOW PROCESSLIST` 更详细。`END_EVENT_ID IS NULL` 判断是否正在执行。时间单位为皮秒。`SQL_TEXT` 最大长度由 `performance_schema_max_sql_text_length` 控制（默认 1024）。通过 JOIN `threads` 表获取用户和主机信息。
