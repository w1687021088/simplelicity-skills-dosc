# memory_summary 内存统计

Performance Schema 的内存统计表（`memory_summary_*`）记录了 MySQL 服务器各个组件的内存分配和使用情况。通过这些表可以了解 MySQL 的内存到底花在了哪里：Buffer Pool 占了多少、排序缓冲区用了多少、连接线程消耗了多少、临时表占了多少等。这是诊断内存问题（如 OOM、内存泄漏、内存使用过高）的关键工具。

---

## 内存统计表

```sql
-- Performance Schema 提供多个维度的内存统计表：

-- 按事件名全局统计（最常用）：
SELECT * FROM performance_schema.memory_summary_global_by_event_name
WHERE CURRENT_NUMBER_OF_BYTES_USED > 0
LIMIT 10;

-- 按线程统计：
SELECT * FROM performance_schema.memory_summary_by_thread_by_event_name
WHERE CURRENT_NUMBER_OF_BYTES_USED > 0
LIMIT 10;

-- 按用户统计：
SELECT * FROM performance_schema.memory_summary_by_user_by_event_name
WHERE CURRENT_NUMBER_OF_BYTES_USED > 0
LIMIT 10;

-- 按主机统计：
SELECT * FROM performance_schema.memory_summary_by_host_by_event_name
WHERE CURRENT_NUMBER_OF_BYTES_USED > 0
LIMIT 10;

-- 按账号（用户@主机）统计：
SELECT * FROM performance_schema.memory_summary_by_account_by_event_name
WHERE CURRENT_NUMBER_OF_BYTES_USED > 0
LIMIT 10;
```

## 关键列含义

```
memory_summary 表的列说明：

EVENT_NAME：内存分配的事件名（探针名）
  例如：memory/innodb/buf_buf_pool（InnoDB Buffer Pool）
  例如：memory/sql/TABLE（表定义缓存）
  例如：memory/sql/THD::main_mem_root（线程主内存）
  例如：memory/innodb/mem0mem（InnoDB 通用内存）
  例如：memory/sql/Filesort（排序操作）

统计列：
  COUNT_ALLOC：分配次数
  COUNT_FREE：释放次数
  SUM_NUMBER_OF_BYTES_ALLOC：分配的总字节数
  SUM_NUMBER_OF_BYTES_FREE：释放的总字节数
  CURRENT_COUNT_USED：当前未释放的分配次数 = COUNT_ALLOC - COUNT_FREE
  CURRENT_NUMBER_OF_BYTES_USED：当前占用的字节数 = SUM_ALLOC - SUM_FREE
  LOW_COUNT_USED / HIGH_COUNT_USED：历史最低/最高分配次数
  LOW_NUMBER_OF_BYTES_USED / HIGH_NUMBER_OF_BYTES_USED：历史最低/最高字节数

最核心的列：
  CURRENT_NUMBER_OF_BYTES_USED = 当前该组件实际使用的内存
```

## 常用内存分析查询

```sql
-- 查看当前内存使用 TOP 20（按组件）：
SELECT
    EVENT_NAME,
    CURRENT_NUMBER_OF_BYTES_USED / 1024 / 1024 AS current_mb,
    HIGH_NUMBER_OF_BYTES_USED / 1024 / 1024 AS peak_mb,
    COUNT_ALLOC,
    COUNT_FREE,
    CURRENT_COUNT_USED AS current_alloc_count
FROM performance_schema.memory_summary_global_by_event_name
WHERE CURRENT_NUMBER_OF_BYTES_USED > 0
ORDER BY CURRENT_NUMBER_OF_BYTES_USED DESC
LIMIT 20;

-- 按大类汇总内存使用：
SELECT
    SUBSTRING_INDEX(EVENT_NAME, '/', 2) AS category,
    SUM(CURRENT_NUMBER_OF_BYTES_USED) / 1024 / 1024 AS current_mb,
    SUM(HIGH_NUMBER_OF_BYTES_USED) / 1024 / 1024 AS peak_mb
FROM performance_schema.memory_summary_global_by_event_name
WHERE CURRENT_NUMBER_OF_BYTES_USED > 0
GROUP BY category
ORDER BY current_mb DESC;

-- 常见的大类：
-- memory/innodb    InnoDB 存储引擎
-- memory/sql       SQL 层（解析、优化、临时表等）
-- memory/mysys     MySQL 系统库（字符串、文件缓冲等）
-- memory/performance_schema  Performance Schema 自身

-- 查看 InnoDB 的内存分布：
SELECT
    EVENT_NAME,
    CURRENT_NUMBER_OF_BYTES_USED / 1024 / 1024 AS current_mb
FROM performance_schema.memory_summary_global_by_event_name
WHERE EVENT_NAME LIKE 'memory/innodb/%'
  AND CURRENT_NUMBER_OF_BYTES_USED > 1024 * 1024  -- > 1MB
ORDER BY CURRENT_NUMBER_OF_BYTES_USED DESC;

-- 查看每个连接的内存使用：
SELECT
    t.PROCESSLIST_USER,
    t.PROCESSLIST_HOST,
    t.PROCESSLIST_DB,
    SUM(m.CURRENT_NUMBER_OF_BYTES_USED) / 1024 / 1024 AS mem_mb
FROM performance_schema.memory_summary_by_thread_by_event_name m
JOIN performance_schema.threads t ON m.THREAD_ID = t.THREAD_ID
WHERE t.TYPE = 'FOREGROUND'
GROUP BY t.THREAD_ID, t.PROCESSLIST_USER, t.PROCESSLIST_HOST, t.PROCESSLIST_DB
ORDER BY mem_mb DESC
LIMIT 20;
```

## 使用 sys schema 简化查询

```sql
-- sys schema 提供了格式化的内存视图：

-- 全局内存分配（按组件，自动格式化单位）：
SELECT * FROM sys.memory_global_by_current_bytes
LIMIT 20;
-- 输出示例：
-- event_name                          | current_count | current_alloc | current_avg_alloc
-- memory/innodb/buf_buf_pool          | 1             | 8.00 GiB      | 8.00 GiB
-- memory/innodb/log0log               | 1             | 64.00 MiB     | 64.00 MiB

-- 全局内存总量：
SELECT * FROM sys.memory_global_total;
-- 显示 MySQL 服务器总的内存分配量

-- 按用户查看内存使用：
SELECT * FROM sys.memory_by_user_by_current_bytes;

-- 按主机查看内存使用：
SELECT * FROM sys.memory_by_host_by_current_bytes;

-- 按线程查看内存使用：
SELECT * FROM sys.memory_by_thread_by_current_bytes
LIMIT 10;
```

## 内存探针的启用

```sql
-- MySQL 8.0.16+ 默认启用了大部分 memory 探针
-- 检查 memory 探针的启用状态：
SELECT
    SUBSTRING_INDEX(NAME, '/', 2) AS category,
    COUNT(*) AS total,
    SUM(ENABLED = 'YES') AS enabled_count
FROM performance_schema.setup_instruments
WHERE NAME LIKE 'memory/%'
GROUP BY category;

-- 如果某些 memory 探针未启用，手动启用：
UPDATE performance_schema.setup_instruments
SET ENABLED = 'YES'
WHERE NAME LIKE 'memory/%';

-- 在 my.cnf 中启动时启用（确保启动阶段的内存也被记录）：
-- [mysqld]
-- performance-schema-instrument = 'memory/%=COUNTED'
```

## 适用场景

- **诊断 MySQL 内存使用过高**：当 MySQL 进程占用的内存远超预期时，通过内存统计表定位是哪个组件消耗了最多内存（Buffer Pool 配置过大、临时表过多、连接数过多等）
- **排查内存泄漏**：监控 `CURRENT_NUMBER_OF_BYTES_USED` 是否持续增长且 `COUNT_FREE` 远小于 `COUNT_ALLOC`，可能存在内存泄漏

---

## 常见问题

**memory_summary 中显示的内存总量和操作系统 top/ps 看到的 MySQL 进程内存不一致，为什么？**

Performance Schema 的内存统计只记录通过 MySQL 内存分配器（`my_malloc`、`my_realloc` 等）分配的内存。某些内存分配不经过这个路径：①glibc 的内存分配器碎片（已释放但未归还操作系统的内存）；②第三方插件或 UDF 的内存分配；③线程栈内存（`thread_stack`）；④操作系统为 MySQL 进程预留的内存映射。因此 Performance Schema 显示的内存总量通常小于 `top` 看到的 RSS（常驻内存集）。差距通常在 10%~30%，如果差距过大需要排查是否有内存碎片问题（可以通过 `malloc_trim` 或使用 jemalloc 替代 glibc 的分配器）。

---

## 注意事项

- 内存统计的 `HIGH_NUMBER_OF_BYTES_USED` 记录了某个组件历史上的最高内存使用量。如果该值远大于 `CURRENT_NUMBER_OF_BYTES_USED`，说明该组件曾经使用过大量内存但后来释放了。这种情况在排序大结果集、创建大临时表的场景中很常见。虽然内存已释放，但 glibc 的分配器可能不会立即将内存归还操作系统，导致 RSS 看起来偏高。
- 在 MySQL 启动时通过 `performance-schema-instrument='memory/%=COUNTED'` 启用内存探针，可以捕获启动阶段的内存分配（如 Buffer Pool 初始化）。如果只在运行时通过 UPDATE 启用，启动阶段已分配的内存不会被计入统计，导致统计数据不完整。

---

## 总结

`memory_summary_global_by_event_name` 是分析 MySQL 内存分布的核心表。`CURRENT_NUMBER_OF_BYTES_USED` 显示当前实际使用的内存。按 `memory/innodb`、`memory/sql`、`memory/mysys` 等大类分析内存分布。sys schema 提供 `memory_global_by_current_bytes`、`memory_global_total` 等友好视图。MySQL 8.0.16+ 默认启用大部分 memory 探针。统计的内存可能小于 OS 看到的 RSS（因 glibc 碎片和未跟踪的分配）。`HIGH_NUMBER_OF_BYTES_USED` 显示历史峰值。启动时配置 `memory/%=COUNTED` 确保启动阶段的分配被记录。
