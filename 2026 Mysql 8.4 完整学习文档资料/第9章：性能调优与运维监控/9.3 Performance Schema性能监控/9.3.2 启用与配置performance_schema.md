# 启用与配置 performance_schema

Performance Schema 在 MySQL 8.0/8.4 中默认启用，但并非所有的探针（Instruments）和消费者（Consumers）都默认开启。合理配置 Performance Schema 的关键是在监控需求和性能开销之间找到平衡：启用需要的探针和消费者，关闭不需要的，调整历史表大小以控制内存占用。

---

## 启用与禁用

```sql
-- 查看 Performance Schema 是否启用：
SHOW VARIABLES LIKE 'performance_schema';
-- 默认值：ON

-- Performance Schema 只能在启动时开启或关闭，不能在线修改
-- 在 my.cnf 中配置：
-- [mysqld]
-- performance_schema = ON    -- 启用（默认）
-- performance_schema = OFF   -- 禁用

-- 命令行方式：
-- mysqld --performance-schema=ON
-- mysqld --performance-schema=OFF

-- 禁用后的影响：
-- performance_schema 数据库仍然存在，但所有表为空
-- 不采集任何性能数据
-- 节省内存和少量 CPU 开销
-- 不推荐禁用，除非在极端性能敏感的场景

-- 查看 Performance Schema 的内存使用：
SHOW ENGINE PERFORMANCE_SCHEMA STATUS;
-- 输出各子系统的内存使用情况
-- 最后一行 performance_schema.memory 是总内存
```

## 探针（Instruments）配置

```sql
-- 查看所有探针及其状态：
SELECT NAME, ENABLED, TIMED
FROM performance_schema.setup_instruments
LIMIT 20;

-- 探针总数：
SELECT COUNT(*) FROM performance_schema.setup_instruments;
-- MySQL 8.0 中通常有 1200+ 个探针

-- 查看各类探针的数量：
SELECT SUBSTRING_INDEX(NAME, '/', 1) AS category, COUNT(*) AS cnt
FROM performance_schema.setup_instruments
GROUP BY category
ORDER BY cnt DESC;

-- 默认启用情况：
-- statement/* 探针：大部分默认启用
-- wait/* 探针：大部分默认禁用
-- stage/* 探针：大部分默认禁用
-- memory/* 探针：大部分默认启用（MySQL 8.0.16+）
-- transaction/* 探针：默认启用

-- 启用特定类别的探针：
UPDATE performance_schema.setup_instruments
SET ENABLED = 'YES', TIMED = 'YES'
WHERE NAME LIKE 'wait/io/file/%';

-- 禁用特定类别的探针：
UPDATE performance_schema.setup_instruments
SET ENABLED = 'NO', TIMED = 'NO'
WHERE NAME LIKE 'wait/synch/mutex/%';

-- 启用所有探针（开销较大，排查问题时临时使用）：
UPDATE performance_schema.setup_instruments
SET ENABLED = 'YES', TIMED = 'YES';

-- 使用 sys schema 的便捷存储过程：
CALL sys.ps_setup_enable_instrument('wait');
CALL sys.ps_setup_enable_instrument('stage');
CALL sys.ps_setup_enable_instrument('statement');

-- 在 my.cnf 中启动时配置探针（持久化）：
-- [mysqld]
-- performance-schema-instrument = 'wait/io/file/%=ON'
-- performance-schema-instrument = 'wait/synch/mutex/%=OFF'
```

## 消费者（Consumers）配置

```sql
-- 查看所有消费者及其状态：
SELECT NAME, ENABLED
FROM performance_schema.setup_consumers;

-- 输出示例：
-- events_stages_current          NO
-- events_stages_history          NO
-- events_stages_history_long     NO
-- events_statements_current      YES
-- events_statements_history      YES
-- events_statements_history_long NO
-- events_transactions_current    YES
-- events_transactions_history    YES
-- events_transactions_history_long NO
-- events_waits_current           NO
-- events_waits_history           NO
-- events_waits_history_long      NO
-- global_instrumentation         YES
-- thread_instrumentation         YES
-- statements_digest              YES

-- 启用消费者：
UPDATE performance_schema.setup_consumers
SET ENABLED = 'YES'
WHERE NAME = 'events_waits_current';

-- 启用所有消费者（排查问题时临时使用）：
UPDATE performance_schema.setup_consumers
SET ENABLED = 'YES';

-- 使用 sys schema 的存储过程：
CALL sys.ps_setup_enable_consumer('current');
CALL sys.ps_setup_enable_consumer('history_long');

-- 在 my.cnf 中启动时配置消费者（持久化）：
-- [mysqld]
-- performance-schema-consumer-events-waits-current = ON
-- performance-schema-consumer-events-waits-history = ON
-- performance-schema-consumer-events-statements-history-long = ON
```

## 历史表大小配置

```sql
-- 历史表大小影响内存使用和可查看的历史数据量

-- 语句历史（每线程）：
SHOW VARIABLES LIKE 'performance_schema_events_statements_history_size';
-- 默认值：10（每个线程保留最近 10 条语句）

-- 语句长历史（全局）：
SHOW VARIABLES LIKE 'performance_schema_events_statements_history_long_size';
-- 默认值：10000（全局保留最近 10000 条语句）

-- 等待事件历史：
SHOW VARIABLES LIKE 'performance_schema_events_waits_history_size';
SHOW VARIABLES LIKE 'performance_schema_events_waits_history_long_size';

-- 这些参数只能在启动时设置，不能在线修改
-- 在 my.cnf 中配置：
-- [mysqld]
-- performance_schema_events_statements_history_size = 20
-- performance_schema_events_statements_history_long_size = 50000
-- performance_schema_events_waits_history_size = 20
-- performance_schema_events_waits_history_long_size = 50000

-- 语句摘要表的最大条数：
SHOW VARIABLES LIKE 'performance_schema_digests_size';
-- 默认值：10000
-- 超过此数量后新的语句指纹无法记录
```

## 监控对象过滤

```sql
-- setup_actors 控制对哪些用户/主机的线程进行监控：
SELECT * FROM performance_schema.setup_actors;
-- 默认配置：HOST='%', USER='%', ROLE='%', ENABLED='YES', HISTORY='YES'
-- 表示监控所有用户的所有线程

-- 只监控特定用户：
TRUNCATE performance_schema.setup_actors;
INSERT INTO performance_schema.setup_actors
    (HOST, USER, ROLE, ENABLED, HISTORY)
VALUES ('%', 'app_user', '%', 'YES', 'YES');

-- setup_objects 控制对哪些数据库对象进行监控：
SELECT * FROM performance_schema.setup_objects;

-- 排除特定数据库的监控（减少开销）：
UPDATE performance_schema.setup_objects
SET ENABLED = 'NO'
WHERE OBJECT_SCHEMA = 'test';
```

## 推荐的生产配置

```ini
# my.cnf 中的 Performance Schema 推荐配置

[mysqld]
performance_schema = ON

# 启用语句和事务监控（默认已启用）
performance-schema-consumer-events-statements-current = ON
performance-schema-consumer-events-statements-history = ON
performance-schema-consumer-statements-digest = ON
performance-schema-consumer-events-transactions-current = ON

# 排查问题时可额外启用
# performance-schema-consumer-events-waits-current = ON
# performance-schema-consumer-events-stages-current = ON

# 历史表大小
performance_schema_events_statements_history_size = 20
performance_schema_events_statements_history_long_size = 20000
performance_schema_digests_size = 25000
```

## 适用场景

- **生产环境的默认监控**：保持默认配置即可满足基本的 SQL 语句分析需求（statements_digest 表），无需额外调整
- **深度性能诊断**：排查锁竞争时启用 wait/synch 探针，排查 I/O 瓶颈时启用 wait/io 探针，排查执行阶段时启用 stage 探针

## 常见问题

**运行时修改探针和消费者的配置重启后会丢失吗？**

会丢失。通过 UPDATE `setup_instruments` 或 `setup_consumers` 进行的运行时修改不会持久化。MySQL 重启后恢复为默认值（或 my.cnf 中的配置）。如果需要持久化配置，必须在 my.cnf 中使用 `performance-schema-instrument` 和 `performance-schema-consumer-*` 参数。MySQL 8.0.27+ 支持 `SET PERSIST` 持久化部分 Performance Schema 变量，但探针和消费者的启用状态仍需通过 my.cnf 配置。

---

## 注意事项

- 启用所有探针（特别是 `wait/synch/mutex` 类）会显著增加 CPU 开销（可能 5%~15%），因为每次获取和释放互斥锁都需要记录事件。生产环境中建议只在排查问题时临时启用这类探针，排查完成后关闭。
- `performance_schema_digests_size` 控制语句摘要表的最大条数。如果应用有大量不同的 SQL 模板（如动态生成的 SQL），可能超出默认的 10000 条限制。超出后新的 SQL 指纹无法被记录，统计数据不完整。可以通过 `SHOW STATUS LIKE 'Performance_schema_digest_lost'` 查看是否有丢失。如果有，增大 `performance_schema_digests_size`。

---

## 总结

Performance Schema 默认启用，通过 `setup_instruments`（探针）和 `setup_consumers`（消费者）控制数据采集。探针控制"监控什么"，消费者控制"存到哪"。默认配置满足基本监控，深度诊断时临时启用更多探针。运行时修改不持久化，需在 my.cnf 中配置。历史表大小（如 `history_size`、`history_long_size`）在启动时设置。`setup_actors` 过滤监控的用户，`setup_objects` 过滤监控的对象。sys schema 提供便捷的启用存储过程。
