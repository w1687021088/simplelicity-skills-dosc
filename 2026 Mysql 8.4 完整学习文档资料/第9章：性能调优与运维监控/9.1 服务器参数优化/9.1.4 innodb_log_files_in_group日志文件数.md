# innodb_log_files_in_group 日志文件数

`innodb_log_files_in_group` 控制 InnoDB 重做日志（Redo Log）文件的数量。InnoDB 使用循环写入的方式将事务日志写入多个 Redo Log 文件，当最后一个文件写满后，回到第一个文件继续写入。该参数与 `innodb_log_file_size` 一起决定了 Redo Log 的总容量。从 MySQL 8.0.30 起，该参数已被 `innodb_redo_log_capacity` 替代并标记为废弃，在 MySQL 8.4 中不再推荐使用。

---

## 参数说明

```sql
-- 查看当前日志文件数量：
SHOW VARIABLES LIKE 'innodb_log_files_in_group';
-- 默认值：2
-- 取值范围：1 ~ 100（早期版本）

-- 总 Redo Log 容量计算：
-- 总容量 = innodb_log_file_size × innodb_log_files_in_group

-- 常见配置示例：
-- innodb_log_file_size = 256M, innodb_log_files_in_group = 2 → 总容量 512MB
-- innodb_log_file_size = 512M, innodb_log_files_in_group = 4 → 总容量 2GB
-- innodb_log_file_size = 1G,   innodb_log_files_in_group = 2 → 总容量 2GB

-- 该参数只能在启动时设置，不能在线修改
-- 修改后需要重启 MySQL
```

---

## 废弃与替代

```sql
-- MySQL 8.0.30+ 和 MySQL 8.4 的新方式：

-- 旧方式（8.0.30 之前）：
-- [mysqld]
-- innodb_log_file_size = 512M
-- innodb_log_files_in_group = 4
-- 总容量 = 512M × 4 = 2GB
-- 文件：datadir/ib_logfile0, ib_logfile1, ib_logfile2, ib_logfile3

-- 新方式（8.0.30+ / 8.4 推荐）：
-- [mysqld]
-- innodb_redo_log_capacity = 2G
-- InnoDB 自动维护 32 个 Redo Log 文件
-- 每个文件 = 2G / 32 = 64MB
-- 文件：datadir/#innodb_redo/redo_log_0, redo_log_1, ... redo_log_31

-- 兼容性规则：
-- 如果设置了 innodb_redo_log_capacity：
--   innodb_log_file_size 和 innodb_log_files_in_group 被忽略
-- 如果没有设置 innodb_redo_log_capacity：
--   等效容量 = innodb_log_file_size × innodb_log_files_in_group
--   Error Log 会输出废弃警告

-- 查看当前实际使用的方式：
SHOW VARIABLES LIKE 'innodb_redo_log_capacity';
-- 如果返回非零值，说明使用的是新方式
```

## 旧版本中文件数量的选择

```
在 MySQL 8.0.30 之前，文件数量的选择：

默认 2 个文件：
  最常见的配置
  足以满足大多数场景
  调整总容量时通常只需改 innodb_log_file_size

增加文件数量（3~4 个）：
  某些操作系统对单文件大小有限制
  （如 FAT32 最大 4GB 单文件 — 但 MySQL 服务器几乎不运行在 FAT32 上）
  通过增加文件数来增大总容量而不增加单文件大小

不建议过多文件：
  文件过多增加文件系统管理开销
  循环切换更频繁，增加元数据操作
  2~4 个通常足够
```

```ini
# innodb_log_files_in_group = 4
# 总容量 = 2GB

# [mysqld]
# innodb_redo_log_capacity = 2G
# 删除或注释掉旧的两个参数

# 升级步骤：
# 1. 修改 my.cnf
# 2. 重启 MySQL
# 3. 旧的 ib_logfile* 文件会被自动迁移
#    新文件位于 datadir/#innodb_redo/ 目录下
# 4. 确认迁移成功后，旧文件可以删除（MySQL 会自动处理）
```

## 适用场景

- **旧版本 MySQL 的 Redo Log 调优**：在 MySQL 8.0.29 及更早版本中，通过 `innodb_log_files_in_group` 和 `innodb_log_file_size` 配合调整总 Redo Log 容量
- **版本升级时的配置迁移**：从旧版本升级到 MySQL 8.4 时，将旧的两个参数替换为 `innodb_redo_log_capacity`

---

## 常见问题

**升级到 MySQL 8.4 后不修改旧参数会怎样？**

如果 my.cnf 中仍然保留了 `innodb_log_file_size` 和 `innodb_log_files_in_group`，且没有设置 `innodb_redo_log_capacity`，MySQL 8.4 会用旧参数的值计算等效容量（`file_size × files_in_group`），作为 `innodb_redo_log_capacity` 的值。同时在 Error Log 中输出废弃警告：`Warning: innodb_log_file_size is deprecated and will be removed in a future release`。MySQL 可以正常运行，但建议尽快修改配置文件以避免未来版本中参数被完全移除后启动失败。

---

## 注意事项

- 在旧版本中修改 `innodb_log_files_in_group` 需要重启 MySQL。MySQL 会在重启过程中检测配置变化，自动执行 checkpoint 将脏页刷盘，然后删除旧的 Redo Log 文件并创建新的文件。这个过程通常很快，但如果 Buffer Pool 中有大量脏页，可能需要较长时间完成 shutdown。
- 在升级到 MySQL 8.4 之前，建议先记录旧的 Redo Log 配置（`SHOW VARIABLES LIKE 'innodb_log%'`），计算总容量，然后在新配置中设置等效的 `innodb_redo_log_capacity` 值。避免升级后因为参数不匹配导致 Redo Log 容量意外变小。

---

## 总结

`innodb_log_files_in_group` 控制 Redo Log 文件数量，默认为 2，取值 1~100。总容量 = `file_size × files_in_group`。MySQL 8.0.30 起被 `innodb_redo_log_capacity` 替代，在 MySQL 8.4 中已废弃。新方式由 InnoDB 自动管理 32 个文件。升级到 8.4 后应将旧参数替换为 `innodb_redo_log_capacity = 总容量`。未修改旧参数时 MySQL 会兼容计算但输出废弃警告。旧版本中修改该参数需要重启。
