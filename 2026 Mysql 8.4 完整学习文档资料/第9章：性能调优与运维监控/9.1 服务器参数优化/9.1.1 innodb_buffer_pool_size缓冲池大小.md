# innodb_buffer_pool_size 缓冲池大小

`innodb_buffer_pool_size` 是 MySQL InnoDB 存储引擎中最重要的性能参数，没有之一。Buffer Pool（缓冲池）是 InnoDB 在内存中缓存表数据和索引数据的区域，所有对 InnoDB 表的读写操作都会先经过 Buffer Pool。合理设置 Buffer Pool 的大小，可以让更多的数据在内存中被命中，大幅减少磁盘 I/O，是 MySQL 性能调优的第一步。

---

## 参数说明

```sql
-- 查看当前 Buffer Pool 大小：
SHOW VARIABLES LIKE 'innodb_buffer_pool_size';
-- 默认值：134217728（128MB）
-- MySQL 8.4 默认值仍为 128MB

-- 查看实际生效的大小（可能被自动调整）：
SELECT @@innodb_buffer_pool_size / 1024 / 1024 AS buffer_pool_mb;
-- 或以 GB 为单位：
SELECT @@innodb_buffer_pool_size / 1024 / 1024 / 1024 AS buffer_pool_gb;

-- 在线动态调整（MySQL 5.7.5+ 支持，无需重启）：
SET GLOBAL innodb_buffer_pool_size = 4 * 1024 * 1024 * 1024;  -- 设置为 4GB
-- 调整过程是分 chunk 进行的，不会导致服务完全中断
-- 但调整期间可能有短暂的性能波动

-- 在 my.cnf 中配置（持久化）：
-- [mysqld]
-- innodb_buffer_pool_size = 4G
```

## 大小设置原则

```
Buffer Pool 大小的通用建议：

专用数据库服务器（只运行 MySQL）：
  设置为物理内存的 70%~80%
  例如 64GB 内存 → innodb_buffer_pool_size = 48G ~ 50G

共享服务器（还运行其他服务）：
  设置为物理内存的 50%~60%
  为操作系统和其他进程留足内存

小型服务器（<= 4GB 内存）：
  设置为物理内存的 50%~60%
  过大会导致操作系统使用 swap，反而降低性能

需要预留内存的部分：
  操作系统本身：1~2 GB
  MySQL 连接线程（每个连接约 4~10 MB）：
    max_connections=200 → 预留 800MB~2GB
  InnoDB 其他内存结构：
    innodb_log_buffer_size、tmp_table_size 等
  其他 MySQL 组件：Performance Schema、binlog cache 等

计算公式（粗略）：
  buffer_pool_size = 总内存 - OS预留(2G) - 连接内存(max_connections×10MB) - 其他缓冲(1G)

示例（64GB 服务器，max_connections=500）：
  64G - 2G - 500×10MB(≈5G) - 1G = 56G
  实际设置：50G~56G（取整到 chunk_size 的倍数）
```

## Buffer Pool 的命中率

```sql
-- Buffer Pool 命中率是衡量 Buffer Pool 大小是否合适的核心指标

-- 查看 Buffer Pool 状态：
SHOW STATUS LIKE 'Innodb_buffer_pool%';

-- 计算命中率：
SELECT
    (1 - Innodb_buffer_pool_reads / Innodb_buffer_pool_read_requests) * 100
    AS hit_rate_pct
FROM (
    SELECT
        VARIABLE_VALUE AS Innodb_buffer_pool_reads
    FROM performance_schema.global_status
    WHERE VARIABLE_NAME = 'Innodb_buffer_pool_reads'
) a,
(
    SELECT
        VARIABLE_VALUE AS Innodb_buffer_pool_read_requests
    FROM performance_schema.global_status
    WHERE VARIABLE_NAME = 'Innodb_buffer_pool_read_requests'
) b;

-- Innodb_buffer_pool_read_requests：从 Buffer Pool 读取的逻辑请求数
-- Innodb_buffer_pool_reads：必须从磁盘读取的物理请求数

-- 命中率参考标准：
-- > 99%：非常好，Buffer Pool 足够大
-- 95%~99%：正常，可以适当增大
-- < 95%：需要增大 Buffer Pool
-- < 90%：严重不足，立即增大

-- 查看 Buffer Pool 中的页信息：
SHOW STATUS LIKE 'Innodb_buffer_pool_pages%';
-- Innodb_buffer_pool_pages_total：Buffer Pool 总页数
-- Innodb_buffer_pool_pages_data：存有数据的页数
-- Innodb_buffer_pool_pages_free：空闲页数
-- Innodb_buffer_pool_pages_dirty：脏页数

-- 如果 pages_free 长期为 0，说明 Buffer Pool 太小
-- 如果 pages_free 占总量 > 50%，说明 Buffer Pool 可能偏大
```

## Buffer Pool 大小与 Chunk Size 的关系

```sql
-- Buffer Pool 的调整是以 chunk 为单位的
SHOW VARIABLES LIKE 'innodb_buffer_pool_chunk_size';
-- 默认值：134217728（128MB）

-- Buffer Pool 大小必须是 chunk_size × instances 的倍数
-- 如果设置的值不满足，MySQL 会自动调整

-- 示例：
-- innodb_buffer_pool_instances = 8
-- innodb_buffer_pool_chunk_size = 128M
-- 最小单位 = 128M × 8 = 1GB
-- buffer_pool_size 必须是 1GB 的倍数

-- 设置 3G → 不是 1GB 的倍数 → 自动调整为 3GB（向上取整到 3*1GB）
-- 设置 3.5G → 自动调整为 4GB

-- 查看自动调整后的实际值：
SELECT @@innodb_buffer_pool_size / 1024 / 1024 / 1024 AS actual_gb;
```

## 在线动态调整

```sql
-- MySQL 5.7.5+ 支持在线调整 Buffer Pool 大小

-- 增大 Buffer Pool（从 4G 到 8G）：
SET GLOBAL innodb_buffer_pool_size = 8 * 1024 * 1024 * 1024;
-- 增大操作：分 chunk 分配新内存
-- 通常很快完成，对服务影响较小

-- 缩小 Buffer Pool（从 8G 到 4G）：
SET GLOBAL innodb_buffer_pool_size = 4 * 1024 * 1024 * 1024;
-- 缩小操作：需要先将多余的数据页逐出
-- 过程可能较慢，取决于脏页数量
-- 脏页需要先刷盘再释放

-- 监控调整进度：
SHOW STATUS LIKE 'Innodb_buffer_pool_resize_status';
-- 显示当前调整的状态信息
-- 例如：Resizing also other hash tables... done.

-- 查看调整过程的日志（Error Log）：
-- [Note] InnoDB: Resizing buffer pool from 4294967296 to 8589934592.
-- [Note] InnoDB: Buffer pool 0 : hash tables were resized.
-- ...
-- [Note] InnoDB: Completed resizing buffer pool at ...
```

## 适用场景

- **新部署的 MySQL 服务器**：根据服务器内存大小和是否为专用数据库服务器，设定初始的 Buffer Pool 大小（专用服务器 70%~80%，共享服务器 50%~60%）
- **性能瓶颈在磁盘 I/O 的场景**：如果 `iostat` 显示磁盘读 I/O 持续很高，同时 Buffer Pool 命中率低于 95%，增大 Buffer Pool 可以有效减少物理读

## 常见问题

**设置了很大的 innodb_buffer_pool_size，但 MySQL 启动后实际使用的内存远超这个值，为什么？**

`innodb_buffer_pool_size` 只是 InnoDB 缓冲池的大小，MySQL 还需要额外的内存用于其他用途：①每个连接的线程栈、排序缓冲、连接缓冲（`sort_buffer_size`、`join_buffer_size`、`read_buffer_size` 等，每个连接独立分配）；②InnoDB 的自适应哈希索引、Change Buffer、Log Buffer；③Performance Schema 数据收集；④临时表（`tmp_table_size`、`max_heap_table_size`）；⑤binlog cache。MySQL 进程的总内存使用 = buffer_pool_size + 连接数 × 每连接内存 + 其他结构。如果总使用超过物理内存，系统会使用 swap，导致严重性能下降。建议在设置 buffer_pool_size 时预留足够的内存给其他部分。

---

## 注意事项

- 在线调整 Buffer Pool 大小期间（特别是缩小操作），可能会有短暂的性能波动。缩小操作需要将多余的数据页逐出并将脏页刷盘，如果脏页比例较高，flush 操作可能造成额外的 I/O 负载。建议在业务低峰期执行调整，并监控调整过程中的 I/O 和查询延迟。
- 不要将 Buffer Pool 设置得过大导致操作系统使用 swap。一旦 MySQL 的内存被 swap 到磁盘，Buffer Pool 的意义就丧失了——从 swap 读数据比直接从磁盘读 InnoDB 数据文件还慢。建议设置 `vm.swappiness=1`（Linux）减少 swap 使用倾向，并通过监控确保 MySQL 的 RSS（Resident Set Size）不超过物理内存。

---

## 总结

`innodb_buffer_pool_size` 是 InnoDB 最重要的性能参数，控制数据和索引的内存缓存大小。默认 128MB，生产环境远远不够。专用服务器设置为物理内存的 70%~80%，共享服务器 50%~60%。通过命中率指标（>99% 为佳，<95% 需增大）判断大小是否合适。支持在线动态调整（`SET GLOBAL`），按 `chunk_size × instances` 的倍数生效。设置时预留内存给 OS、连接线程和其他 MySQL 组件。避免过大导致 swap。缩小操作在低峰期执行。
