# innodb_io_capacity_max 最大 IO 容量

`innodb_io_capacity_max` 定义了 InnoDB 后台任务在紧急刷新（Aggressive Flushing）时允许使用的最大 IOPS。当脏页比例过高或 Redo Log 即将写满时，InnoDB 会突破 `innodb_io_capacity` 的限制，以更高的速率刷新脏页，但不会超过 `innodb_io_capacity_max` 的上限。该参数是 InnoDB I/O 预算体系中的"安全阀"，防止紧急刷新时过度占用 I/O 资源。

---

## 参数说明

```sql
-- 查看当前值：
SHOW VARIABLES LIKE 'innodb_io_capacity_max';
-- 默认值：MAX(2 × innodb_io_capacity, 2000)
-- 即默认至少为 2000

-- 在线动态修改：
SET GLOBAL innodb_io_capacity_max = 4000;

-- 在 my.cnf 中配置：
-- [mysqld]
-- innodb_io_capacity = 2000
-- innodb_io_capacity_max = 4000

-- 约束条件：
-- innodb_io_capacity_max 不能小于 innodb_io_capacity
-- 最小值：100
```

---

## 与 innodb_io_capacity 的关系

```
InnoDB 的 I/O 调度逻辑：

正常状态（脏页比例正常，Redo Log 空间充足）：
  后台刷新速度 ≤ innodb_io_capacity
  刷新速度根据脏页比例动态调整
  
紧急状态（脏页比例高或 Redo Log 接近写满）：
  后台刷新速度可以超过 innodb_io_capacity
  但不会超过 innodb_io_capacity_max
  
超紧急状态（innodb_flush_sync=ON，checkpoint 刷新）：
  刷新速度不受 innodb_io_capacity_max 限制
  全力刷盘，可能导致前台查询延迟
  
两个参数的配合：
  innodb_io_capacity = 日常刷新的 IOPS 预算
  innodb_io_capacity_max = 紧急刷新的 IOPS 上限
  
推荐比例：
  innodb_io_capacity_max = 2 × innodb_io_capacity（默认比例）
  或根据存储设备的最大能力设置
```

## 紧急刷新的触发条件

```sql
-- InnoDB 紧急刷新的触发取决于两个因素：

-- 因素1：脏页比例超过 innodb_max_dirty_pages_pct
SHOW VARIABLES LIKE 'innodb_max_dirty_pages_pct';
-- 默认值：90（MySQL 8.4 中为 90）
-- 当脏页比例超过此值，触发紧急刷新

SHOW VARIABLES LIKE 'innodb_max_dirty_pages_pct_lwm';
-- 默认值：10
-- 低水位标记：脏页比例低于此值时，预刷新停止

-- 查看当前脏页比例：
SELECT
    VARIABLE_VALUE AS dirty_pages
FROM performance_schema.global_status
WHERE VARIABLE_NAME = 'Innodb_buffer_pool_pages_dirty';

SELECT
    VARIABLE_VALUE AS total_pages
FROM performance_schema.global_status
WHERE VARIABLE_NAME = 'Innodb_buffer_pool_pages_total';

-- 因素2：Redo Log 空间使用率
-- 当 Redo Log 使用率超过约 75% 时
-- InnoDB 开始 Adaptive Flushing（自适应刷新）
-- Redo Log 使用率越高，刷新速度越快
-- 接近 100% 时以 innodb_io_capacity_max 速度全力刷新
```

## 适用场景

- **写入突发的业务**：业务有写入高峰（如每天定时批量导入、促销活动），高峰期产生大量脏页，`innodb_io_capacity_max` 确保在脏页堆积时能以更高速率刷盘，避免 Buffer Pool 被脏页填满
- **存储设备有突发 I/O 能力**：某些 SSD 和云磁盘支持突发 IOPS（如 AWS gp3 的 burst），`innodb_io_capacity_max` 可以设置为突发 IOPS 的值，在紧急刷新时利用存储的突发能力

## 常见问题

**innodb_io_capacity_max 和 innodb_flush_sync 有什么关系？**

`innodb_flush_sync` 控制 checkpoint 时的刷新是否受 `innodb_io_capacity_max` 限制。当 `innodb_flush_sync=ON`（默认），checkpoint 刷新时 InnoDB 会无视 `innodb_io_capacity_max` 的限制，全力刷盘。这可能导致前台查询出现延迟抖动。设置 `innodb_flush_sync=OFF` 后，即使在 checkpoint 刷新时，刷盘速度也不会超过 `innodb_io_capacity_max`，前台查询延迟更平稳，但可能导致 Redo Log 空间不足。大多数生产环境保持默认 `ON`。

---

## 注意事项

- `innodb_io_capacity_max` 的值不能小于 `innodb_io_capacity`。如果先修改了 `innodb_io_capacity` 使其大于当前的 `innodb_io_capacity_max`，MySQL 会自动将 `innodb_io_capacity_max` 调整为 `2 × innodb_io_capacity`。建议修改时先调整 `innodb_io_capacity_max`，再调整 `innodb_io_capacity`，避免意外的自动调整。
- 在 HDD 存储上不要设置过高的 `innodb_io_capacity_max`。HDD 的随机写 IOPS 非常有限（约 75~150），设置过高的值会导致紧急刷新时产生大量 I/O 排队，严重影响前台查询性能。

---

## 总结

`innodb_io_capacity_max` 是 InnoDB 紧急刷新时的最大 IOPS 限制，默认值为 `MAX(2 × innodb_io_capacity, 2000)`。正常刷新受 `innodb_io_capacity` 限制，紧急刷新（脏页过多/Redo Log 接近写满）可以突破到 `innodb_io_capacity_max`。推荐设为 `innodb_io_capacity` 的 2 倍或存储设备最大 IOPS 的 80%。不能小于 `innodb_io_capacity`。`innodb_flush_sync=ON` 时 checkpoint 不受此限制。支持在线修改。根据存储类型合理设置，HDD 不要过高。
