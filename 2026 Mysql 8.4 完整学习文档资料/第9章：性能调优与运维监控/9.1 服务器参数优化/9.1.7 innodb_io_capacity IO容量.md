# innodb_io_capacity IO 容量

`innodb_io_capacity` 告诉 InnoDB 后台任务每秒可以执行多少次 I/O 操作（IOPS）。InnoDB 的后台任务包括从 Buffer Pool 刷新脏页（Flushing）、合并 Change Buffer 中的操作、预读等。该参数的值应该与底层存储设备的 I/O 能力匹配：HDD 设置较低值，SSD 设置较高值。设置不当会导致脏页刷新过慢（值太低）或后台 I/O 抢占前台查询资源（值太高）。

---

## 参数说明

```sql
-- 查看当前值：
SHOW VARIABLES LIKE 'innodb_io_capacity';
-- 默认值：200
-- 取值范围：100 ~ 2^64-1（实际不要设太大）

-- 在线动态修改：
SET GLOBAL innodb_io_capacity = 2000;

-- 在 my.cnf 中配置：
-- [mysqld]
-- innodb_io_capacity = 2000
```

## 不同存储设备的推荐值

| 存储类型 | 推荐 innodb_io_capacity | 说明 |
|---------|:----------------------:|:----:|
| 单块 7200RPM HDD | 100~200 | HDD 随机 IOPS 约 75~150 |
| RAID 10（4块 HDD）| 400~800 | RAID 带来 IOPS 叠加 |
| 单块 SATA SSD | 1000~2000 | SATA SSD IOPS 约 5000~50000 |
| 单块 NVMe SSD | 2000~5000 | NVMe IOPS 可达 100000+ |
| 高端 NVMe（企业级）| 5000~10000 | 高端存储性能充裕 |
| 云磁盘（按规格）| 按云厂商 IOPS 规格设置 | 如 AWS gp3 默认 3000 IOPS |

## innodb_io_capacity 影响的后台操作

```
InnoDB 后台任务使用 innodb_io_capacity 作为 I/O 预算：

1. 脏页刷新（Page Flushing）
   从 Buffer Pool 中将修改过的脏页写回磁盘
   是 innodb_io_capacity 控制的最主要操作
   
2. Change Buffer 合并（Merge）
   将 Change Buffer 中缓存的二级索引修改合并到索引页
   在空闲时或读取到目标页时触发

3. Purge 操作
   清理被标记为删除的 MVCC 旧版本数据
   innodb_io_capacity 间接影响 purge 的速度

innodb_io_capacity 的作用方式：
  InnoDB 根据脏页比例和 Redo Log 使用率
  动态计算当前需要的刷新速度
  innodb_io_capacity 是"正常情况下"的刷新速度上限
  innodb_io_capacity_max 是"紧急情况下"的刷新速度上限
```

## 判断 innodb_io_capacity 是否合适

```sql
-- 方法1：观察脏页比例
SELECT
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_buffer_pool_pages_dirty') /
    (SELECT VARIABLE_VALUE FROM performance_schema.global_status
     WHERE VARIABLE_NAME = 'Innodb_buffer_pool_pages_total') * 100
    AS dirty_pct;

-- 脏页比例参考：
-- < 10%：正常，innodb_io_capacity 足够
-- 10%~25%：可以接受
-- 25%~75%：偏高，考虑增大 innodb_io_capacity
-- > 75%：过高，需要立即增大

-- 方法2：检查 Redo Log 是否接近写满
SHOW ENGINE INNODB STATUS\G
-- 在 LOG 部分观察：
-- Log sequence number 和 Last checkpoint at 的差距
-- 如果差距接近 Redo Log 总容量的 75%，说明刷新速度不够

-- 方法3：观察 Adaptive Flushing 状态
SHOW STATUS LIKE 'Innodb_buffer_pool_wait_free';
-- 如果该值持续增加，说明 Buffer Pool 没有空闲页
-- InnoDB 必须等待脏页刷盘后才能使用新页
-- 需要增大 innodb_io_capacity
```

## 适用场景

- **SSD 存储的性能调优**：使用 SSD 存储时，默认值 200 远低于 SSD 的实际 IOPS 能力，导致脏页刷新过慢、Buffer Pool 利用率降低。应根据 SSD 性能设置 1000~5000
- **写密集型业务**：大量 INSERT/UPDATE 操作产生大量脏页，需要较高的 `innodb_io_capacity` 确保脏页及时刷盘，避免 Buffer Pool 被脏页填满

## 常见问题

**innodb_io_capacity 设置得越大越好吗？**

不是。设置过大会导致 InnoDB 后台任务占用过多的磁盘 I/O 带宽，挤压前台查询的 I/O 资源，反而导致用户查询变慢。比如在 HDD 上设置 `innodb_io_capacity=10000`，后台刷新会尝试以 10000 IOPS 的速度工作，但 HDD 最多只能提供 150 IOPS，结果后台任务产生大量 I/O 排队，前台查询的 I/O 延迟显著增加。建议将该参数设置在存储设备实际 IOPS 能力的 50%~80%。

---

## 注意事项

- `innodb_io_capacity` 是所有 Buffer Pool 实例共享的全局值，不是每个实例独立的。如果有 8 个 Buffer Pool 实例，总的后台 I/O 预算仍然是 `innodb_io_capacity` 指定的值，不会乘以 8。
- 在使用云服务器（如 AWS EC2、阿里云 ECS）时，磁盘的 IOPS 是按规格配置的（如 AWS gp3 默认 3000 IOPS）。`innodb_io_capacity` 不应超过购买的 IOPS 配额，否则后台任务可能触发 I/O 限流（throttling），导致不可预测的延迟。

## 总结

`innodb_io_capacity` 告诉 InnoDB 后台任务每秒可执行的 IOPS 数量，默认 200。主要影响脏页刷新和 Change Buffer 合并速度。应根据存储设备能力设置：HDD 100~200，SATA SSD 1000~2000，NVMe 2000~5000。过低导致脏页积累、Buffer Pool 效率下降；过高导致后台 I/O 抢占前台资源。通过脏页比例和 `Innodb_buffer_pool_wait_free` 状态判断是否合适。支持在线动态调整。是所有 Buffer Pool 实例的全局值。云服务器不要超过购买的 IOPS 配额。
