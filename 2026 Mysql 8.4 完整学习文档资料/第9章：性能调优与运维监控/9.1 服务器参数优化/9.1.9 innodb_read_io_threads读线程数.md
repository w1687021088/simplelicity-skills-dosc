# innodb_read_io_threads 读线程数

`innodb_read_io_threads` 控制 InnoDB 后台用于处理读 I/O 请求的线程数量。这些线程负责从磁盘读取数据页到 Buffer Pool（如预读操作、Page Fault 时的页面加载等）。增加读线程数可以提升并行读取能力，特别是在使用 SSD 或 RAID 阵列等高 IOPS 存储设备时效果更明显。

---

## 参数说明

```sql
-- 查看当前读线程数：
SHOW VARIABLES LIKE 'innodb_read_io_threads';
-- 默认值：4
-- 取值范围：1 ~ 64

-- 该参数不能在线动态修改，需要在 my.cnf 中设置并重启：
-- [mysqld]
-- innodb_read_io_threads = 8

-- 查看当前 I/O 线程的状态：
SHOW ENGINE INNODB STATUS\G
-- 在 FILE I/O 部分可以看到每个 I/O 线程的状态：
-- I/O thread 0 state: waiting for completed aio requests (insert buffer thread)
-- I/O thread 1 state: waiting for completed aio requests (log thread)
-- I/O thread 2 state: waiting for completed aio requests (read thread)
-- I/O thread 3 state: waiting for completed aio requests (read thread)
-- I/O thread 4 state: waiting for completed aio requests (read thread)
-- I/O thread 5 state: waiting for completed aio requests (read thread)
-- I/O thread 6 state: waiting for completed aio requests (write thread)
-- ...
```

## 线程分配

```
InnoDB 的后台 I/O 线程分配：

固定线程（不受参数控制）：
  1 个 Insert Buffer 线程（负责 Change Buffer 合并）
  1 个 Log 线程（负责 Redo Log 的 I/O）

可配置线程：
  innodb_read_io_threads 个读线程（默认 4 个）
  innodb_write_io_threads 个写线程（默认 4 个）

总 I/O 线程数 = 2 + innodb_read_io_threads + innodb_write_io_threads
默认：2 + 4 + 4 = 10 个线程

每个读线程可以同时处理一个异步 I/O 请求
Linux 上使用 Native AIO（异步 I/O）
每个线程可以排队多个 I/O 请求
```

## 设置建议

```
根据存储设备和负载特征设置：

读密集型业务（读多写少）：
  增加读线程，减少写线程
  innodb_read_io_threads = 8 ~ 16
  innodb_write_io_threads = 4

写密集型业务（写多读少）：
  增加写线程，读线程保持默认
  innodb_read_io_threads = 4
  innodb_write_io_threads = 8 ~ 16

均衡型业务：
  读写线程各设置相同
  innodb_read_io_threads = 8
  innodb_write_io_threads = 8

存储设备因素：
  HDD：默认 4 个读线程通常足够（HDD 的并行 I/O 能力有限）
  SATA SSD：8 个读线程
  NVMe SSD：8 ~ 16 个读线程（NVMe 支持更多并行 I/O 队列）
  
Linux 上的限制：
  多个 MySQL 实例共享同一服务器时
  总的 AIO 请求数不能超过 Linux 内核的 aio-max-nr 限制
  默认 aio-max-nr = 65536
  如果运行多个实例，可能需要增大：
  echo 1048576 > /proc/sys/fs/aio-max-nr
```

## 监控 I/O 线程状态

```sql
-- 通过 SHOW ENGINE INNODB STATUS 监控：
SHOW ENGINE INNODB STATUS\G

-- FILE I/O 部分输出示例：
-- Pending normal aio reads: [0, 0, 0, 0]  ← 4 个读线程的待处理请求
-- Pending normal aio writes: [0, 0, 0, 0] ← 4 个写线程的待处理请求
-- Pending ibuf aio reads: 0               ← Change Buffer 读请求
-- Pending log writes: 0                   ← 日志写请求

-- 如果 Pending reads 持续 > 0，说明读线程处理不过来
-- 可能需要：
-- 1. 增大 innodb_read_io_threads
-- 2. 增大 innodb_buffer_pool_size（减少磁盘读取）
-- 3. 升级存储设备

-- 通过 performance_schema 监控 I/O 等待：
SELECT EVENT_NAME, COUNT_STAR, SUM_TIMER_WAIT/1000000000 AS total_wait_ms
FROM performance_schema.file_summary_by_event_name
WHERE EVENT_NAME LIKE '%innodb%'
ORDER BY SUM_TIMER_WAIT DESC
LIMIT 10;
```

## 适用场景

- **全表扫描或大范围查询频繁的场景**：报表查询、数据分析等需要读取大量数据页的操作，增加读线程可以提升并行读取效率
- **NVMe SSD 存储的性能挖掘**：NVMe SSD 支持大量并行 I/O 队列（通常 32~64 队列），默认 4 个读线程无法充分利用 NVMe 的并行能力

---

## 常见问题

**增加 innodb_read_io_threads 一定能提升读取性能吗？**

不一定。如果性能瓶颈不在磁盘读取而在其他环节（如 CPU 解析 SQL、锁等待、网络延迟），增加读线程不会有改善。另外，如果 Buffer Pool 足够大（命中率 > 99%），绝大部分读取都在内存中完成，增加读线程也没有意义。增加读线程只在以下情况有效：①Buffer Pool 命中率较低，有大量物理读取；②存储设备支持高并行 I/O（SSD/NVMe）；③`SHOW ENGINE INNODB STATUS` 中 Pending reads 持续 > 0。

---

## 注意事项

- `innodb_read_io_threads` 不能在线修改，修改后需要重启 MySQL。在生产环境中修改该参数需要安排维护窗口。建议在初始部署时根据硬件配置一次性设置好。
- 在 Linux 系统上运行多个 MySQL 实例时，每个实例的 I/O 线程都会消耗 AIO 资源。如果总的 I/O 线程数超过系统的 `aio-max-nr` 限制（默认 65536），MySQL 启动时可能报错。需要通过 `sysctl -w fs.aio-max-nr=1048576` 增大系统限制。

---

## 总结

`innodb_read_io_threads` 控制 InnoDB 后台读 I/O 线程数量，默认 4，取值 1~64。不能在线修改。读密集型业务可增至 8~16，配合高 IOPS 存储设备效果更好。总 I/O 线程 = 2（固定）+ 读线程 + 写线程。通过 `SHOW ENGINE INNODB STATUS` 观察 Pending reads 判断是否需要增加。Buffer Pool 命中率高时增加读线程无意义。Linux 多实例需注意 `aio-max-nr` 系统限制。
