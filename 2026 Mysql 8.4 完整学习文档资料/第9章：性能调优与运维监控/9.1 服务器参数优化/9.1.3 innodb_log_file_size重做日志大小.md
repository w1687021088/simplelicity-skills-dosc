# innodb_log_file_size 重做日志大小

`innodb_log_file_size` 控制单个 InnoDB 重做日志（Redo Log）文件的大小。Redo Log 记录了所有对 InnoDB 数据页的修改操作，是 InnoDB 事务持久性（Durability）和崩溃恢复的核心机制。在 MySQL 8.0.30 之前，Redo Log 的总容量由 `innodb_log_file_size × innodb_log_files_in_group` 决定。从 MySQL 8.0.30 起，该参数已被 `innodb_redo_log_capacity` 替代。在 MySQL 8.4 中，`innodb_log_file_size` 已标记为废弃。

---

## 参数演进

| 版本范围 | 配置方式 | 状态 |
|---------|:------:|:----:|
| MySQL 5.x ~ 8.0.29 | `innodb_log_file_size` + `innodb_log_files_in_group` | 正常使用 |
| MySQL 8.0.30 ~ 8.0.x | 新增 `innodb_redo_log_capacity`，旧参数降为备选 | 旧参数废弃 |
| MySQL 8.4 LTS | `innodb_redo_log_capacity` 为唯一推荐方式 | 旧参数移除或忽略 |

---

## 参数说明（旧版方式）

```sql
-- 查看当前 Redo Log 文件大小：
SHOW VARIABLES LIKE 'innodb_log_file_size';
-- 默认值：50331648（48MB）

-- 查看日志文件数量：
SHOW VARIABLES LIKE 'innodb_log_files_in_group';
-- 默认值：2

-- 总 Redo Log 容量 = innodb_log_file_size × innodb_log_files_in_group
-- 默认：48MB × 2 = 96MB

-- 在 my.cnf 中配置（旧版方式，8.0.30 之前）：
-- [mysqld]
-- innodb_log_file_size = 256M
-- innodb_log_files_in_group = 2
-- 总容量 = 256M × 2 = 512MB
```

---

## 新版配置方式（innodb_redo_log_capacity）

```sql
-- MySQL 8.0.30+ 和 MySQL 8.4 推荐使用 innodb_redo_log_capacity

-- 查看当前 Redo Log 容量：
SHOW VARIABLES LIKE 'innodb_redo_log_capacity';
-- 默认值：104857600（100MB）

-- 在线动态调整（不需要重启）：
SET GLOBAL innodb_redo_log_capacity = 2 * 1024 * 1024 * 1024;  -- 2GB

-- 在 my.cnf 中配置：
-- [mysqld]
-- innodb_redo_log_capacity = 2G

-- innodb_redo_log_capacity 设置后：
-- InnoDB 自动维护 32 个 Redo Log 文件
-- 每个文件大小 = innodb_redo_log_capacity / 32
-- 文件位于 datadir/#innodb_redo/ 目录下
-- innodb_log_file_size 和 innodb_log_files_in_group 被忽略
```

## Redo Log 大小的影响

```
Redo Log 大小对性能和恢复的影响：

Redo Log 太小的问题：
  1. 频繁触发 checkpoint
     Redo Log 写满后，InnoDB 必须将脏页刷盘（checkpoint）
     频繁的 checkpoint 导致大量随机 I/O
     性能下降，特别是写密集型场景
  
  2. 写入阻塞
     极端情况下 Redo Log 空间用尽
     InnoDB 必须暂停所有写入等待 checkpoint 完成
     Error Log 中出现：InnoDB: Redo log is too small

  3. 慢查询增多
     checkpoint 期间，脏页刷盘抢占 I/O 带宽
     导致其他查询的 I/O 延迟增加

Redo Log 太大的问题：
  1. 崩溃恢复时间长
     MySQL 崩溃后重启，需要重放 Redo Log
     Redo Log 越大，可能需要重放的数据越多
     恢复时间从秒级变成分钟级
  
  2. 占用更多磁盘空间
     但相比数据文件通常可以忽略

权衡建议：
  小型数据库（< 10GB）：256MB ~ 512MB
  中型数据库（10~100GB）：1GB ~ 2GB
  大型数据库（> 100GB）：2GB ~ 4GB
  写密集型高负载：4GB ~ 8GB（甚至更大）
```

## 判断 Redo Log 大小是否合适

```sql
-- 方法1：观察 checkpoint 频率
SHOW ENGINE INNODB STATUS\G
-- 在 LOG 部分查看：
-- Log sequence number    12345678900
-- Log flushed up to      12345678800
-- Pages flushed up to    12345678000
-- Last checkpoint at     12345677000
-- 
-- 如果 Log sequence number 和 Last checkpoint 差距接近 Redo Log 总容量
-- 说明 Redo Log 即将写满，需要增大

-- 方法2：查看 Redo Log 相关状态变量
SHOW STATUS LIKE 'Innodb_redo_log%';
-- Innodb_redo_log_capacity_resized：当前生效的 Redo Log 容量

-- 方法3：观察 InnoDB 的等待事件
-- 如果 Error Log 中出现以下消息说明 Redo Log 太小：
-- InnoDB: Redo log writer is waiting for a new log file...
-- InnoDB: Waiting for checkpoint...

-- 方法4：按写入量估算
-- 查看每小时的 Redo Log 写入量：
SELECT
    VARIABLE_VALUE AS redo_log_written_bytes
FROM performance_schema.global_status
WHERE VARIABLE_NAME = 'Innodb_os_log_written';
-- 间隔一小时再查一次，差值就是一小时的写入量
-- Redo Log 容量建议至少能容纳 1~2 小时的写入量
```

## 适用场景

- **写密集型业务的性能优化**：高频 INSERT、UPDATE、DELETE 操作产生大量 Redo Log，Redo Log 过小会频繁触发 checkpoint，增大 Redo Log 可以积累更多脏页再一次性 checkpoint，减少随机 I/O
- **MySQL 8.4 新部署**：在 MySQL 8.4 中应直接使用 `innodb_redo_log_capacity` 配置 Redo Log 容量，不再使用旧的 `innodb_log_file_size` 参数

---

## 常见问题

**从旧版本升级到 MySQL 8.4 后，innodb_log_file_size 的配置还有效吗？**

在 MySQL 8.4 中，如果同时设置了 `innodb_redo_log_capacity` 和旧的 `innodb_log_file_size`/`innodb_log_files_in_group`，旧参数会被忽略，以 `innodb_redo_log_capacity` 为准。如果没有设置 `innodb_redo_log_capacity`，MySQL 会使用旧参数的值来计算等效的容量（`innodb_log_file_size × innodb_log_files_in_group`），并在 Error Log 中给出废弃警告。建议升级后尽快将 my.cnf 中的旧参数替换为 `innodb_redo_log_capacity`。

---

## 注意事项

- 在 MySQL 8.0.30 之前修改 `innodb_log_file_size` 需要重启 MySQL，且旧的 Redo Log 文件会被自动删除和重新创建。这个过程在正常情况下很快，但如果 Buffer Pool 中有大量脏页，shutdown 时的 flush 操作可能耗时较长。建议修改前先执行 `SET GLOBAL innodb_fast_shutdown=0` 确保干净关闭。
- `innodb_redo_log_capacity` 支持在线动态调整，这是相比旧参数的巨大改进。调整后 InnoDB 会自动管理 Redo Log 文件的数量和大小（始终维护 32 个文件），不需要手动处理文件。

---

## 总结

`innodb_log_file_size` 控制单个 Redo Log 文件大小，在 MySQL 8.4 中已废弃，被 `innodb_redo_log_capacity` 替代。Redo Log 太小导致频繁 checkpoint 和 I/O 瓶颈，太大导致崩溃恢复时间长。建议 Redo Log 容量：小型库 256MB~512MB，中型库 1G~2G，大型写密集型 4G~8G。通过 checkpoint 差距和写入量判断大小是否合适。MySQL 8.4 使用 `innodb_redo_log_capacity` 直接设置总容量，支持在线动态调整，InnoDB 自动维护 32 个日志文件。升级后应将旧参数替换为新参数。
