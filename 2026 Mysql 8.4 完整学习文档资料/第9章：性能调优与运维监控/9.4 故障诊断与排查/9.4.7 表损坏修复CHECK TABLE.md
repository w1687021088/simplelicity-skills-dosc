# 表损坏修复 CHECK TABLE

`CHECK TABLE` 是 MySQL 内置的表完整性检查语句，用于检测表和索引是否存在损坏。它支持 InnoDB 和 MyISAM 等多种存储引擎。表损坏虽然不常见，但在以下情况可能发生：MySQL 异常崩溃（断电、OOM Kill）、磁盘故障（坏道、控制器故障）、文件系统错误、MySQL Bug 等。及时发现并修复损坏的表可以避免数据丢失和查询异常。

---

## CHECK TABLE 基本用法

```sql
-- 检查单张表：
CHECK TABLE db_name.table_name;

-- 检查多张表：
CHECK TABLE db1.t1, db1.t2, db2.t3;

-- 输出示例：
-- +----------------+-------+----------+----------+
-- | Table          | Op    | Msg_type | Msg_text |
-- +----------------+-------+----------+----------+
-- | mydb.orders    | check | status   | OK       |
-- +----------------+-------+----------+----------+

-- Msg_type 的值：
-- status：正常状态信息
-- error：发现错误
-- warning：警告信息
-- info：额外的信息
-- note：备注

-- Msg_text 为 OK 表示表没有问题
-- 如果有问题，会显示具体的错误描述
```

---

## CHECK TABLE 的检查选项

```sql
-- CHECK TABLE 支持不同级别的检查（主要用于 MyISAM）：

-- QUICK：不扫描数据行，只检查索引
-- 速度最快，但检查不完整
CHECK TABLE mydb.orders QUICK;

-- FAST：只检查没有正确关闭的表
-- 如果表被正常关闭过，跳过检查
CHECK TABLE mydb.orders FAST;

-- CHANGED：只检查上次检查后有过修改的表
CHECK TABLE mydb.orders CHANGED;

-- MEDIUM：检查行数据和索引的一致性（默认级别）
-- 验证删除链接的完整性，计算行校验和
CHECK TABLE mydb.orders MEDIUM;

-- EXTENDED：完整检查，包括对每行的所有索引进行查找
-- 最慢但最彻底
CHECK TABLE mydb.orders EXTENDED;

-- InnoDB 的 CHECK TABLE 行为：
-- InnoDB 不区分上述检查级别
-- 执行的检查包括：
-- 1. 表空间的页面校验和（checksum）验证
-- 2. 索引结构的完整性验证
-- 3. 自适应哈希索引（AHI）的完整性
-- 4. 二级索引与聚簇索引的一致性
```

---

## InnoDB 表的损坏检测

```sql
-- InnoDB 表损坏的表现：
-- 1. 查询报错：InnoDB: Database page corruption on disk or a failed file read
-- 2. MySQL 错误日志中出现：
--    [ERROR] InnoDB: Page [page_id] checksum mismatch
-- 3. 查询返回不正确的结果
-- 4. MySQL 崩溃后重启失败

-- 检查 InnoDB 表：
CHECK TABLE mydb.orders;
-- InnoDB 的 CHECK TABLE 会验证：
-- 聚簇索引和二级索引的结构完整性
-- 索引间的一致性（二级索引指向正确的聚簇索引记录）

-- 如果 CHECK TABLE 报告 InnoDB 表损坏：
-- InnoDB 表不支持 REPAIR TABLE
-- 需要使用其他方法修复（见下文）

-- innodb_force_recovery 参数（紧急恢复用）：
-- 当 InnoDB 因损坏无法正常启动时
-- 在 my.cnf 中设置：
-- [mysqld]
-- innodb_force_recovery = 1
-- 然后重启 MySQL

-- innodb_force_recovery 的级别：
-- 1 (SRV_FORCE_IGNORE_CORRUPT)：跳过损坏的页面继续启动
-- 2 (SRV_FORCE_NO_BACKGROUND)：不启动后台线程
-- 3 (SRV_FORCE_NO_TRX_UNDO)：不执行事务回滚
-- 4 (SRV_FORCE_NO_IBUF_MERGE)：不执行 Insert Buffer 合并
-- 5 (SRV_FORCE_NO_UNDO_LOG_SCAN)：不查看 Undo Log
-- 6 (SRV_FORCE_NO_LOG_REDO)：不执行 Redo Log 恢复

-- 使用建议：
-- 从 1 开始逐级尝试，直到能启动
-- 启动后立即用 mysqldump 导出所有数据
-- 重建数据库实例，导入数据
-- 完成后务必移除 innodb_force_recovery 参数
```

## MyISAM 表的检查

```sql
-- MyISAM 表更容易损坏（不支持事务，崩溃不安全）

-- 使用 CHECK TABLE：
CHECK TABLE mydb.legacy_table;

-- 使用命令行工具 myisamchk（MySQL 未运行时）：
-- myisamchk /var/lib/mysql/mydb/legacy_table.MYI
-- myisamchk --check --force /var/lib/mysql/mydb/*.MYI

-- myisamchk 的检查级别：
-- myisamchk table.MYI               -- 默认检查
-- myisamchk --medium-check table.MYI -- 中等检查
-- myisamchk --extend-check table.MYI -- 完整检查
-- myisamchk --check-only-changed table.MYI  -- 只检查有变更的
```

## 批量检查所有表

```sql
-- 使用 mysqlcheck 工具批量检查（MySQL 运行时使用）：

-- 检查单个数据库的所有表：
-- mysqlcheck -u root -p --check mydb

-- 检查所有数据库的所有表：
-- mysqlcheck -u root -p --check --all-databases

-- 快速检查所有数据库：
-- mysqlcheck -u root -p --quick --all-databases

-- 使用 SQL 生成批量 CHECK TABLE 语句：
SELECT CONCAT('CHECK TABLE `', TABLE_SCHEMA, '`.`', TABLE_NAME, '`;')
FROM information_schema.TABLES
WHERE TABLE_SCHEMA NOT IN ('information_schema', 'performance_schema', 'sys', 'mysql')
  AND TABLE_TYPE = 'BASE TABLE';
```

## CHECK TABLE 对生产环境的影响

```
CHECK TABLE 对不同引擎的影响：

InnoDB 表：
  CHECK TABLE 需要获取表的共享锁（读锁）
  检查期间 SELECT 正常，INSERT/UPDATE/DELETE 被阻塞
  大表的检查可能需要几分钟到几十分钟
  建议在低峰期执行

MyISAM 表：
  CHECK TABLE 也需要锁定表
  在线检查会阻塞写操作
  使用 myisamchk 时必须先停止 MySQL

建议的执行策略：
  不要对所有表定期执行 CHECK TABLE
  只在以下情况执行：
  1. MySQL 异常崩溃后
  2. 磁盘故障修复后
  3. 查询结果出现异常时
  4. 错误日志中出现 checksum 相关警告时
```

## 适用场景

- **MySQL 异常崩溃后的数据完整性验证**：服务器断电、MySQL 被 OOM Kill 后，对关键表执行 CHECK TABLE 确认数据完整性
- **磁盘故障后的损坏检测**：磁盘出现坏道或控制器故障后，用 CHECK TABLE 找出哪些表受到了影响

## 常见问题

**InnoDB 表 CHECK TABLE 报告损坏了，但 REPAIR TABLE 不支持 InnoDB，怎么修复？**

InnoDB 表的修复步骤：①尝试 `ALTER TABLE t ENGINE=InnoDB`，这会重建表（本质上是导出数据 → 创建新表 → 导入数据 → 替换旧表），可以修复索引层面的损坏。②如果 ALTER TABLE 失败（数据页损坏严重），尝试用 `SELECT ... INTO OUTFILE` 或 `mysqldump` 导出能读取的数据，然后 DROP 旧表，CREATE 新表，重新导入。③如果 MySQL 无法启动，使用 `innodb_force_recovery`（从 1 到 6 逐级尝试），启动后立即 `mysqldump` 导出所有可用数据，然后重建实例。④如果以上都失败，只能从备份恢复。

---

## 注意事项

- `CHECK TABLE` 对 InnoDB 表执行时会加共享锁（读锁），阻塞 DML 操作（INSERT/UPDATE/DELETE）。对于大表（几十 GB），检查可能持续很长时间。在生产环境中执行前需要评估对业务的影响，建议在维护窗口或低峰期执行。
- `innodb_force_recovery` 是紧急恢复手段，在设置大于 0 的值时，MySQL 会禁止某些正常操作（如写入操作在 recovery >= 3 时被禁止）。使用完 `innodb_force_recovery` 并导出数据后，必须移除该参数并重启 MySQL，否则数据库处于不正常的运行状态。

---

## 总结

`CHECK TABLE` 用于检测表和索引的完整性。InnoDB 表的检查包括页面校验和验证和索引一致性检查。MyISAM 表支持 QUICK/FAST/MEDIUM/EXTENDED 等检查级别。`mysqlcheck` 工具可批量检查。InnoDB 表不支持 REPAIR TABLE，修复方法：`ALTER TABLE ... ENGINE=InnoDB`（重建表）、导出再导入、`innodb_force_recovery`（紧急恢复）、从备份恢复。CHECK TABLE 会加读锁阻塞写操作，大表检查耗时长。建议在异常崩溃或磁盘故障后执行，不需要定期执行。
