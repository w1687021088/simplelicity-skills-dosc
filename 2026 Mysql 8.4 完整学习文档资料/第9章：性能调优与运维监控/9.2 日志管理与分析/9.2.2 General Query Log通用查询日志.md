# General Query Log 通用查询日志

General Query Log（通用查询日志）记录 MySQL 服务器接收到的所有 SQL 语句，包括 SELECT、INSERT、UPDATE、DELETE、DDL、管理命令等。与慢查询日志只记录超过阈值的查询不同，General Log 记录一切操作，不论执行时间。由于记录量巨大，对性能影响较大，通常只在排查问题时临时开启，不建议在生产环境长期启用。

---

## 参数配置

```sql
-- 查看是否启用：
SHOW VARIABLES LIKE 'general_log';
-- 默认值：OFF

-- 查看日志文件路径：
SHOW VARIABLES LIKE 'general_log_file';
-- 默认值：hostname.log（数据目录下）

-- 查看日志输出方式：
SHOW VARIABLES LIKE 'log_output';
-- 默认值：FILE
-- 可选值：FILE、TABLE、NONE
-- 可以同时指定多个：FILE,TABLE

-- 在线开启（动态生效，不需要重启）：
SET GLOBAL general_log = ON;

-- 在线关闭：
SET GLOBAL general_log = OFF;

-- 修改日志文件路径：
SET GLOBAL general_log_file = '/var/log/mysql/general.log';

-- 在 my.cnf 中配置：
-- [mysqld]
-- general_log = OFF
-- general_log_file = /var/log/mysql/general.log
-- log_output = FILE
```

## 日志内容格式

```
General Query Log 文件的内容示例：

2024-06-15T10:30:01.123456Z	   12 Connect	root@localhost on mydb using TCP/IP
2024-06-15T10:30:01.234567Z	   12 Query	SELECT * FROM users WHERE id = 1
2024-06-15T10:30:01.345678Z	   12 Query	UPDATE users SET name='Tom' WHERE id = 1
2024-06-15T10:30:02.456789Z	   12 Query	COMMIT
2024-06-15T10:30:05.567890Z	   12 Quit

各字段含义：
  时间戳：精确到微秒
  线程 ID：12（对应 SHOW PROCESSLIST 的 Id）
  操作类型：Connect/Query/Quit/Init DB 等
  SQL 语句或操作详情

注意：General Log 记录的是 MySQL 接收到的原始 SQL
      不包含执行时间、扫描行数等性能信息
      这些信息在慢查询日志中才有
```

## 输出到表

```sql
-- 将 General Log 输出到 mysql.general_log 表：
SET GLOBAL log_output = 'TABLE';
SET GLOBAL general_log = ON;

-- 查询 general_log 表：
SELECT event_time, user_host, thread_id, command_type, argument
FROM mysql.general_log
ORDER BY event_time DESC
LIMIT 20;

-- 表结构：
-- event_time：事件时间
-- user_host：用户@主机
-- thread_id：线程 ID
-- server_id：服务器 ID
-- command_type：命令类型（Connect/Query/Quit 等）
-- argument：SQL 语句

-- 输出到表的优势：
-- 可以用 SQL 查询和过滤日志（比 grep 方便）
-- 例如查找某个用户的所有操作：
SELECT event_time, command_type, argument
FROM mysql.general_log
WHERE user_host LIKE '%app_user%'
ORDER BY event_time DESC
LIMIT 50;

-- 输出到表的劣势：
-- 写表操作本身有开销（INSERT）
-- 表可能快速增长，占用大量空间
-- 需要定期清理：TRUNCATE TABLE mysql.general_log;

-- 同时输出到文件和表：
SET GLOBAL log_output = 'FILE,TABLE';
```

## 会话级控制

```sql
-- 可以通过 sql_log_off 变量控制单个会话是否记录到 General Log

-- 关闭当前会话的日志记录：
SET SESSION sql_log_off = ON;
-- 后续该会话的 SQL 不会被记录到 General Log

-- 重新开启：
SET SESSION sql_log_off = OFF;

-- 使用场景：
-- 批量导入数据时关闭日志，避免日志文件暴涨
-- 执行敏感操作时关闭日志，避免记录明文密码等
```

## 性能影响

```
General Query Log 的性能开销：

FILE 模式：
  每条 SQL 都需要写入磁盘文件
  高并发时产生大量磁盘 I/O
  TPS 可能下降 10%~30%（取决于负载类型）

TABLE 模式：
  每条 SQL 都执行 INSERT INTO mysql.general_log
  比 FILE 模式开销更大
  TPS 可能下降 20%~50%

开启 General Log 的建议：
  仅在排查问题时临时开启（几分钟到几小时）
  排查完成后立即关闭
  不要在生产环境长期启用
  如果需要审计功能，使用 MySQL Enterprise Audit 或审计插件
```

## 适用场景

- **排查应用程序发送了什么 SQL**：当怀疑应用程序有异常查询或不正确的 SQL 时，临时开启 General Log 可以看到所有发送到 MySQL 的 SQL 语句
- **安全审计和合规**：在需要记录所有数据库操作的合规场景中，可以短期使用 General Log 或使用专门的审计插件替代

## 常见问题

**General Log 文件增长很快，如何清理？**

如果使用 FILE 模式，可以通过以下步骤清理：①先关闭 General Log（`SET GLOBAL general_log = OFF`）；②删除或重命名旧的日志文件（`mv general.log general.log.bak`）；③重新开启 General Log（`SET GLOBAL general_log = ON`），MySQL 会自动创建新文件。也可以使用 `FLUSH GENERAL LOGS` 命令让 MySQL 关闭并重新打开日志文件（配合 logrotate 使用）。如果使用 TABLE 模式，直接 `TRUNCATE TABLE mysql.general_log` 即可清空。

---

## 注意事项

- General Log 记录的 SQL 语句包含明文的参数值，如果 SQL 中包含密码、身份证号等敏感信息，这些信息会以明文形式出现在日志文件中。在安全敏感的环境中，需要严格控制 General Log 文件的访问权限，或者使用 `sql_log_off` 在执行敏感操作前关闭日志。
- 如果使用 TABLE 模式输出，`mysql.general_log` 表默认使用 CSV 存储引擎。CSV 引擎不支持索引，查询效率较低。如果需要对日志表进行复杂查询，可以将其转换为 MyISAM 引擎（但需要先关闭 General Log）：`ALTER TABLE mysql.general_log ENGINE = MyISAM`。

## 总结

General Query Log 记录 MySQL 接收到的所有 SQL 语句。默认关闭。通过 `general_log=ON` 开启，`log_output` 控制输出到 FILE 或 TABLE。对性能影响较大（10%~50%），仅在排查问题时临时开启。支持会话级控制（`sql_log_off`）。FILE 模式用 `FLUSH GENERAL LOGS` 配合 logrotate 清理，TABLE 模式用 `TRUNCATE` 清理。日志包含明文参数，注意敏感信息保护。不适合长期生产使用，审计需求推荐使用专门的审计插件。
