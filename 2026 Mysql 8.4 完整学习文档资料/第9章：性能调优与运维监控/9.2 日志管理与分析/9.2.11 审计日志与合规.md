# 审计日志与合规

审计日志（Audit Log）记录数据库的所有操作行为，包括谁在什么时间通过什么方式对哪些数据执行了什么操作。审计日志的目的不是性能优化，而是满足安全合规要求（如 GDPR、PCI DSS、等保 2.0 等），实现操作可追溯。MySQL 提供了 Enterprise Audit（商业版）和多种社区审计插件方案。本文介绍 MySQL 审计日志的整体方案和实践。

---

## MySQL Enterprise Audit（商业版）

```sql
-- MySQL Enterprise Audit 是 MySQL 商业版（Enterprise Edition）的功能
-- 基于 audit_log 插件实现

-- 安装审计插件：
INSTALL PLUGIN audit_log SONAME 'audit_log.so';

-- 验证安装：
SHOW PLUGINS;
-- 应该看到 audit_log 插件状态为 ACTIVE

-- 查看审计日志文件路径：
SHOW VARIABLES LIKE 'audit_log_file';
-- 默认值：audit.log（数据目录下）

-- 查看审计日志格式：
SHOW VARIABLES LIKE 'audit_log_format';
-- 可选值：OLD（旧 XML）、NEW（新 XML）、JSON
-- 推荐使用 JSON 格式，便于后续解析

-- 配置审计策略（基于规则的过滤）：
-- 创建过滤器（记录所有事件）：
SELECT audit_log_filter_set_filter('log_all', '{ "filter": { "log": true } }');

-- 将过滤器应用到所有用户：
SELECT audit_log_filter_set_user('%', 'log_all');

-- 只记录特定用户的操作：
SELECT audit_log_filter_set_filter('log_admin', '{ "filter": { "log": true } }');
SELECT audit_log_filter_set_user('admin@%', 'log_admin');

-- 只记录 DML 操作（不记录 SELECT）：
SELECT audit_log_filter_set_filter('log_writes',
    '{ "filter": { "class": [
        { "name": "table_access",
          "event": [
            { "name": "insert", "log": true },
            { "name": "update", "log": true },
            { "name": "delete", "log": true }
          ]
        }
    ]}}');
```

## 社区审计方案

```
MySQL 社区版没有 Enterprise Audit 插件
但有以下替代方案：

1. MariaDB Audit Plugin（兼容 MySQL）
   MariaDB 开发的审计插件，可以在 MySQL 上使用
   支持记录连接、查询、表访问等事件
   输出到文件或 syslog
   
   安装方式（需要编译或下载对应版本）：
   INSTALL PLUGIN server_audit SONAME 'server_audit.so';
   
   配置：
   SET GLOBAL server_audit_logging = ON;
   SET GLOBAL server_audit_events = 'CONNECT,QUERY,TABLE';
   SET GLOBAL server_audit_file_path = '/var/log/mysql/audit.log';
   SET GLOBAL server_audit_file_rotate_size = 1000000;
   SET GLOBAL server_audit_file_rotations = 10;

2. Percona Audit Log Plugin
   Percona Server 内置的审计插件
   API 兼容 MySQL Enterprise Audit
   支持 JSON/XML/CSV 格式
   免费使用

3. MySQL General Log 作为简易审计
   记录所有 SQL 操作
   缺点：性能影响大、不支持过滤、格式简单
   只适合短期临时使用

4. 基于触发器的审计
   为关键表创建 AFTER INSERT/UPDATE/DELETE 触发器
   将变更记录写入审计表
   优点：可精确控制审计范围
   缺点：影响 DML 性能、无法审计 SELECT 和 DDL

5. 基于 binlog 的审计
   解析 binlog 获取所有数据变更
   使用 Canal、Maxwell 等工具实时解析
   只能审计数据变更，不能审计 SELECT
```

## 合规要求与审计策略

```
常见合规标准对数据库审计的要求：

PCI DSS（支付卡行业）：
  必须记录所有对持卡人数据的访问
  记录管理员的所有操作
  审计日志保留至少 1 年
  审计日志必须防篡改

等保 2.0（中国信息安全等级保护）：
  三级及以上系统必须开启数据库审计
  记录所有用户的登录和操作
  审计日志保留至少 6 个月
  审计日志与被审计对象分离存储

GDPR（欧盟通用数据保护条例）：
  记录对个人数据的所有访问
  支持数据访问记录的追溯
  确保审计日志本身的安全性

审计策略设计建议：
  核心数据表：记录所有 CRUD 操作
  管理员操作：记录所有 DDL 和权限变更
  敏感操作：记录 GRANT、CREATE USER、DROP TABLE 等
  登录行为：记录所有连接和断开事件
  失败事件：记录登录失败和权限拒绝
```

## 审计日志管理

```sql
-- 审计日志的存储和管理：

-- 日志轮转（Enterprise Audit）：
-- 手动轮转：
SELECT audit_log_rotate();
-- 关闭当前审计日志，创建新文件

-- 自动轮转配置：
-- audit_log_rotate_on_size = 1073741824  -- 1GB 时自动轮转
-- audit_log_max_size = 10737418240       -- 总大小限制 10GB

-- 日志加密（MySQL 8.0.17+）：
-- SET GLOBAL audit_log_encryption = 'AES';
-- 加密后只有拥有密钥的人才能读取审计日志

-- 审计日志的安全保护：
-- 1. 审计日志文件权限设为 600（仅 MySQL 用户可读写）
-- 2. 定期将审计日志传输到独立的日志服务器（Filebeat + ELK）
-- 3. 使用只追加文件系统（chattr +a）防止删改
-- 4. 对审计日志做完整性校验（SHA256 哈希）

-- 审计日志分析（使用 ELK Stack）：
-- Filebeat → Logstash → Elasticsearch → Kibana
-- 可以实现：
--   实时查看所有数据库操作
--   按用户、时间、操作类型检索
--   异常行为告警（如非工作时间的大量 DELETE）
--   定期生成合规报告
```

## 适用场景

- **金融、医疗等强合规行业**：必须满足 PCI DSS、HIPAA 等标准对数据库操作审计的要求，需要完整记录所有数据访问和变更
- **敏感数据保护**：对包含用户个人信息、财务数据的表进行精细化审计，追踪谁在什么时间访问了什么数据

## 常见问题

**开启审计日志对 MySQL 性能影响大吗？**

取决于审计的范围和输出方式。如果审计所有用户的所有 SQL（包括 SELECT），性能开销可能在 5%~15%（异步写入文件时）。如果只审计特定用户或特定操作（如 DDL 和写操作），开销可以控制在 2%~5%。使用异步写入（`audit_log_strategy=ASYNCHRONOUS`）比同步写入开销小得多。审计日志写入 JSON 格式比 XML 格式略快（序列化开销更小）。建议在上线前做压测评估实际的性能影响。

## 注意事项

- MySQL Enterprise Audit 是商业版功能，需要购买 MySQL Enterprise Edition 许可证。社区版用户可以使用 MariaDB Audit Plugin 或 Percona Audit Plugin 作为替代，但功能和稳定性可能略有差异。在选择方案前需要评估合规要求的完整性和插件的兼容性。
- 审计日志应当与 MySQL 数据文件分开存储。如果审计日志和数据文件在同一块磁盘上，审计日志增长过快可能导致磁盘空间不足影响数据库正常运行。同时，审计日志存储在独立位置也是合规标准（如等保 2.0）的要求——审计日志不能被数据库管理员轻易删除或篡改。

## 总结

审计日志记录数据库的所有操作行为，满足安全合规要求。MySQL Enterprise Audit（商业版）提供完整的审计功能，支持 JSON/XML 格式和基于规则的过滤。社区替代方案：MariaDB Audit Plugin、Percona Audit Plugin、binlog 解析、触发器审计。合规标准（PCI DSS、等保 2.0、GDPR）对审计有明确要求。审计日志需要独立存储、防篡改、定期轮转。性能影响：全量审计 5%~15%，精细审计 2%~5%。建议配合 ELK Stack 进行日志分析和告警。
