# Relay Log 中继日志

Relay Log（中继日志）是 MySQL 复制架构中从库（Replica）端特有的日志文件。从库的 I/O 线程从主库读取 binlog 事件后，先将其写入本地的 Relay Log 文件中，然后由 SQL 线程（Applier 线程）读取 Relay Log 并逐条执行，从而实现数据同步。Relay Log 在格式上与 binlog 完全相同，可以使用 `mysqlbinlog` 工具解析查看。

---

## 工作原理

```
MySQL 主从复制中 Relay Log 的位置：

主库（Source）                    从库（Replica）
    |                                |
    | binlog                         |
    |-----> I/O Thread 读取 -------> Relay Log
    |                                |
    |                           SQL Thread 读取
    |                                |
    |                           应用到从库数据
    |                                |

详细流程：
  1. 主库执行 DML/DDL 操作，写入 binlog
  2. 从库的 I/O 线程连接到主库
  3. I/O 线程读取主库的 binlog 事件
  4. 将事件写入从库本地的 Relay Log 文件
  5. 从库的 SQL 线程读取 Relay Log
  6. SQL 线程逐条执行事件，修改从库数据
  7. SQL 线程执行完一个 Relay Log 文件后自动删除该文件

Relay Log 的意义：
  解耦网络接收和数据应用两个过程
  I/O 线程可以快速接收 binlog（网络速度快）
  SQL 线程可以按自己的速度应用（受限于从库性能）
  两者速度不同时，Relay Log 起到缓冲作用
```

## 参数配置

```sql
-- 查看 Relay Log 文件名前缀：
SHOW VARIABLES LIKE 'relay_log';
-- 默认值：hostname-relay-bin
-- 建议显式设置，避免主机名变更后找不到 Relay Log

-- 查看 Relay Log 索引文件：
SHOW VARIABLES LIKE 'relay_log_index';
-- 默认值：hostname-relay-bin.index

-- 查看 Relay Log 所在目录：
SHOW VARIABLES LIKE 'relay_log_basename';

-- 查看是否自动清理已执行的 Relay Log：
SHOW VARIABLES LIKE 'relay_log_purge';
-- 默认值：ON
-- SQL 线程执行完一个 Relay Log 文件后自动删除

-- 查看 Relay Log 空间限制：
SHOW VARIABLES LIKE 'relay_log_space_limit';
-- 默认值：0（不限制）
-- 设为非零值时，Relay Log 总大小不超过此值
-- 如果达到限制，I/O 线程会暂停直到 SQL 线程释放空间

-- 在 my.cnf 中配置（从库）：
-- [mysqld]
-- relay_log = /var/lib/mysql/relay-bin
-- relay_log_purge = ON
-- relay_log_space_limit = 0
-- max_relay_log_size = 0   -- 0 表示使用 max_binlog_size 的值
```

## 监控 Relay Log 状态

```sql
-- 查看从库复制状态中的 Relay Log 信息：
SHOW REPLICA STATUS\G

-- 关键字段：
-- Relay_Log_File：当前 SQL 线程正在读取的 Relay Log 文件
-- Relay_Log_Pos：SQL 线程在当前 Relay Log 中的位置
-- Relay_Log_Space：所有 Relay Log 文件占用的总磁盘空间（字节）

-- 查看从库的 Relay Log 文件列表：
SHOW RELAYLOG EVENTS IN 'relay-bin.000005' LIMIT 20;

-- 查看 Relay Log 中的具体事件：
SHOW RELAYLOG EVENTS IN 'relay-bin.000005' FROM 1234 LIMIT 10;

-- 使用 mysqlbinlog 查看 Relay Log 内容：
-- mysqlbinlog -v /var/lib/mysql/relay-bin.000005
-- Relay Log 格式与 binlog 相同，解析方法一致
```

## Relay Log 恢复机制

```sql
-- relay_log_recovery 控制从库崩溃后的 Relay Log 恢复行为：
SHOW VARIABLES LIKE 'relay_log_recovery';
-- 默认值：OFF

-- 开启 relay_log_recovery（推荐从库设置）：
-- [mysqld]
-- relay_log_recovery = ON

-- 工作原理：
-- 从库崩溃重启后：
-- 如果 relay_log_recovery = OFF：
--   SQL 线程从崩溃前的位置继续读取 Relay Log
--   如果 Relay Log 文件损坏，复制会中断

-- 如果 relay_log_recovery = ON：
--   丢弃所有未执行的 Relay Log
--   I/O 线程从 SQL 线程最后执行完的位置重新从主库拉取 binlog
--   重新生成 Relay Log
--   更安全，避免损坏的 Relay Log 导致数据不一致

-- 注意：relay_log_recovery = ON 时不要关闭 relay_log_purge
-- 否则不是 crash-safe 的
```

## Relay Log 信息持久化

```sql
-- relay_log_info_repository 控制 Relay Log 位置信息的存储方式：
SHOW VARIABLES LIKE 'relay_log_info_repository';
-- MySQL 8.0+ 默认值：TABLE（存储在 mysql.slave_relay_log_info 表中）
-- 旧版默认值：FILE（存储在 relay-log.info 文件中）

-- TABLE 方式的优势：
-- 位置信息存在 InnoDB 表中，支持事务
-- SQL 线程每执行一个事务，同时更新位置信息
-- 两者在同一个事务中，保证原子性
-- 崩溃恢复时位置信息与已执行的数据一致

-- 查看位置信息表：
SELECT * FROM mysql.slave_relay_log_info\G
```

## 适用场景

- **MySQL 主从复制架构的从库管理**：Relay Log 是从库的核心组件，理解其工作原理有助于排查复制延迟和复制中断问题
- **从库磁盘空间管理**：当复制延迟很大时，Relay Log 可能占用大量磁盘空间，需要通过 `relay_log_space_limit` 限制或优化复制速度来控制

---

## 常见问题

**复制延迟很大时 Relay Log 占满了磁盘空间怎么办？**

当 SQL 线程执行速度远慢于 I/O 线程接收速度时，Relay Log 会持续增长。处理方法：①设置 `relay_log_space_limit` 限制总大小（如 10GB），达到限制时 I/O 线程自动暂停，但这会导致从库进一步落后；②优化 SQL 线程的执行速度（开启多线程复制 `replica_parallel_workers`）；③临时跳过一些非关键操作（不推荐）；④检查是否有大事务（一个事务修改 100 万行）阻塞了 SQL 线程。根本解决方案是优化复制速度而非限制 Relay Log 大小。

---

## 注意事项

- 不要手动删除 Relay Log 文件（使用 `rm` 命令），必须让 MySQL 通过 `relay_log_purge=ON` 自动管理。手动删除会导致 Relay Log 索引文件（`relay-bin.index`）与实际文件不一致，从库的 SQL 线程找不到文件而中断。如果已经手动删除，需要停止从库复制，手动编辑索引文件或使用 `RESET REPLICA` 重新初始化复制。
- 建议在从库配置中显式设置 `relay_log` 的文件名前缀（如 `relay_log=relay-bin`），不要依赖默认值（基于主机名）。如果从库的主机名发生变化（如虚拟机迁移、容器重建），默认的 Relay Log 文件名会变化，MySQL 找不到旧的 Relay Log 文件，复制会中断。

---

## 总结

Relay Log 是从库端的中继日志，在 I/O 线程接收 binlog 和 SQL 线程应用数据之间起缓冲作用。格式与 binlog 相同。`relay_log_purge=ON`（默认）自动清理已执行的文件。`relay_log_recovery=ON` 保证崩溃安全（丢弃损坏的 Relay Log 重新拉取）。`relay_log_info_repository=TABLE`（MySQL 8.0+ 默认）保证位置信息与数据的事务一致性。`relay_log_space_limit` 可限制总大小。不要手动删除 Relay Log 文件。显式设置 `relay_log` 前缀避免主机名变更问题。
