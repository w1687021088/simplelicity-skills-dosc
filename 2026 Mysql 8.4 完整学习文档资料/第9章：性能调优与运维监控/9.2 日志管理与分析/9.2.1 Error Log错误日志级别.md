# Error Log 错误日志级别

Error Log（错误日志）是 MySQL 最重要的日志文件，记录了 MySQL 服务器的启动和关闭过程、运行期间的错误信息、警告信息和重要的通知信息。MySQL 8.0 引入了基于组件架构的错误日志系统，通过 `log_error_services` 配置日志过滤器和输出目标，通过 `log_error_verbosity` 控制日志的详细程度（级别）。错误日志是数据库故障排查的第一手资料，DBA 日常运维中需要频繁查看。

---

## 日志级别（log_error_verbosity）

```sql
-- 查看当前日志级别：
SHOW VARIABLES LIKE 'log_error_verbosity';
-- 默认值：2
-- 取值范围：1 ~ 3

-- 在线动态修改：
SET GLOBAL log_error_verbosity = 3;

-- 各级别记录的内容：
-- 级别 1：仅记录 ERROR（错误）
--   示例：mysqld: Table './test/t1' is marked as crashed and should be repaired
--   示例：InnoDB: Unable to lock ./ibdata1
-- 
-- 级别 2：记录 ERROR + WARNING（错误 + 警告）
--   示例：[Warning] Aborted connection 1234 to db: 'mydb' user: 'root'
--   示例：[Warning] innodb_log_file_size is deprecated
-- 
-- 级别 3：记录 ERROR + WARNING + NOTE/INFO（全部信息）
--   示例：[Note] mysqld: ready for connections
--   示例：[Note] InnoDB: Buffer pool(s) load completed

-- 在 my.cnf 中配置：
-- [mysqld]
-- log_error_verbosity = 2
```

## 错误日志文件位置

```sql
-- 查看错误日志文件路径：
SHOW VARIABLES LIKE 'log_error';
-- 常见值：
-- /var/log/mysqld.log（RPM 安装）
-- /var/log/mysql/error.log（APT 安装）
-- stderr（标准错误输出，某些 Docker 容器）

-- 在 my.cnf 中配置日志路径：
-- [mysqld]
-- log_error = /var/log/mysql/error.log

-- 如果不指定 log_error：
-- MySQL 将错误日志输出到控制台（stderr）
-- 通过 systemd 启动时，日志会被 journal 捕获
-- 可以用 journalctl -u mysqld 查看
```

## 组件化日志架构（MySQL 8.0+）

```sql
-- MySQL 8.0 引入组件化的错误日志系统

-- 查看当前日志组件配置：
SHOW VARIABLES LIKE 'log_error_services';
-- 默认值：log_filter_internal; log_sink_internal

-- 日志组件分两类：
-- 过滤器（Filter）：控制哪些日志事件被记录
--   log_filter_internal：内置过滤器（基于 verbosity 和 suppression_list）
--   log_filter_dragnet：规则过滤器（高级，自定义规则）
--
-- 输出器（Sink）：控制日志输出到哪里
--   log_sink_internal：内置输出（写文件，默认格式）
--   log_sink_json：JSON 格式输出
--   log_sink_syseventlog：系统日志（syslog/Windows Event Log）

-- 配置多个输出目标（同时写文件和 JSON）：
-- INSTALL COMPONENT 'file://component_log_sink_json';
-- SET GLOBAL log_error_services = 'log_filter_internal; log_sink_internal; log_sink_json';
-- 结果：错误日志同时写入默认格式文件和 JSON 格式文件

-- 配置输出到系统日志：
-- INSTALL COMPONENT 'file://component_log_sink_syseventlog';
-- SET GLOBAL log_error_services = 'log_filter_internal; log_sink_syseventlog';
```

## 日志抑制（log_error_suppression_list）

```sql
-- MySQL 8.0.13+ 支持抑制特定错误码的日志
SHOW VARIABLES LIKE 'log_error_suppression_list';

-- 抑制特定警告（不再记录到日志）：
SET GLOBAL log_error_suppression_list = 'MY-010914,MY-013360';

-- 注意：只能抑制 WARNING 和 NOTE 级别的消息
-- ERROR 级别不能被抑制（防止错过严重问题）

-- 查看 MySQL 错误码格式：
-- MySQL 8.0+ 使用 MY-NNNNNN 格式
-- 例如：MY-010914 对应 Aborted connection
-- 可以在错误日志中看到具体的错误码
```

崩溃信息：
  mysqld got signal 11

## 适用场景

- **日常运维监控**：将 `log_error_verbosity` 设为 2（默认），记录错误和警告。配合日志监控工具（如 Filebeat + ELK）实时告警关键错误
- **故障排查时增加详细度**：遇到问题时临时设为 3，记录全部信息（包括 NOTE），排查完成后恢复为 2

## 常见问题

**错误日志中大量出现 Aborted connection 警告，是否需要关注？**

`Aborted connection` 表示客户端异常断开连接（没有正常关闭）。少量出现是正常的（网络抖动、应用重启等）。但如果大量出现，可能的原因有：①应用层没有正确关闭数据库连接（连接泄漏）；②`wait_timeout` 设置过短导致空闲连接被服务器主动断开；③网络不稳定导致连接中断；④应用异常退出。可以通过 `log_error_suppression_list` 抑制该警告（`MY-010914`），但建议先排查根因。

## 注意事项

- 生产环境建议将 `log_error_verbosity` 保持在 2（默认值）。设为 1 会遗漏重要的警告信息（如废弃参数警告、复制相关警告），可能导致问题被忽视。设为 3 会产生大量的 NOTE 信息，增加日志体积和解析负担，仅在排查问题时临时使用。
- 错误日志文件没有自动轮转机制（不像 binlog 会自动清理）。长时间运行后日志文件可能变得很大。建议配置 logrotate（Linux）定期轮转错误日志，或者使用 `FLUSH ERROR LOGS` 命令关闭并重新打开日志文件（配合 logrotate 的 postrotate 脚本）。

## 总结

Error Log 是 MySQL 最重要的日志，记录启动/关闭、错误、警告和通知。`log_error_verbosity` 控制级别：1=仅错误，2=错误+警告（默认），3=全部。MySQL 8.0+ 使用组件架构，通过 `log_error_services` 配置过滤器和输出目标。支持同时输出到文件、JSON、syslog。`log_error_suppression_list` 可抑制特定警告码。生产环境保持 verbosity=2。排查问题时临时设为 3。需要配合 logrotate 管理日志文件大小。
