# mysqldump 基础语法

`mysqldump` 是 MySQL 官方提供的逻辑备份工具，将数据库的表结构和数据导出为 SQL 语句文件。导出的文件包含 `CREATE TABLE`、`INSERT INTO` 等 SQL 语句，恢复时通过执行这些 SQL 语句重建数据库。`mysqldump` 是 MySQL 安装包自带的命令行工具，无需额外安装，是中小型数据库备份最常用的工具。

---

## 基本语法格式

```bash
# 语法格式：
mysqldump [选项] 数据库名 [表名...] > 输出文件

# 三种使用模式：

# 模式1：备份指定数据库中的指定表
mysqldump -u root -p mydb table1 table2 > backup.sql

# 模式2：备份一个或多个完整数据库
mysqldump -u root -p --databases mydb1 mydb2 > backup.sql

# 模式3：备份所有数据库
mysqldump -u root -p --all-databases > backup.sql
```

## 常用连接参数

```bash
# 用户名和密码：
mysqldump -u root -p mydb > backup.sql
# -u root：指定用户名
# -p：交互式输入密码（推荐，不在命令行暴露密码）
# -pMyPassword：直接指定密码（不安全，会被 history 记录）

# 指定主机和端口：
mysqldump -h 192.168.1.100 -P 3306 -u root -p mydb > backup.sql
# -h：指定 MySQL 服务器地址（默认 localhost）
# -P：指定端口号（默认 3306）

# 使用 Socket 连接（本地）：
mysqldump -S /var/lib/mysql/mysql.sock -u root -p mydb > backup.sql

# 使用 SSL 连接：
mysqldump --ssl-mode=REQUIRED -u root -p mydb > backup.sql

# 使用配置文件中的凭据（推荐）：
mysqldump --defaults-file=/etc/mysql/backup.cnf mydb > backup.sql
# backup.cnf 内容：
# [mysqldump]
# user=backup_user
# password=backup_password
# host=localhost
```

## 常用备份参数

```bash
# 结构和数据相关：
# --no-data（-d）：只导出表结构，不导出数据
mysqldump -u root -p --no-data mydb > schema_only.sql

# --no-create-info（-t）：只导出数据，不导出表结构
mysqldump -u root -p --no-create-info mydb > data_only.sql

# --no-create-db（-n）：不生成 CREATE DATABASE 语句
mysqldump -u root -p --no-create-db --databases mydb > backup.sql

# 一致性相关：
# --single-transaction：使用一致性快照（InnoDB）
mysqldump -u root -p --single-transaction mydb > backup.sql

# --lock-tables（-l）：逐库加读锁（默认开启）
# --lock-all-tables（-x）：全局读锁

# 输出格式相关：
# --compact：精简输出（省略注释和 SET 语句）
# --complete-insert：使用完整的 INSERT 语句（包含列名）
mysqldump -u root -p --complete-insert mydb > backup.sql
# INSERT INTO `users` (`id`,`name`,`email`) VALUES (1,'张三','a@b.com');

# --extended-insert（默认开启）：多行合并为一条 INSERT
# INSERT INTO `users` VALUES (1,'张三'),(2,'李四'),(3,'王五');

# --skip-extended-insert：每行一条 INSERT（恢复更安全但更慢）
# INSERT INTO `users` VALUES (1,'张三');
# INSERT INTO `users` VALUES (2,'李四');

# 对象相关：
# --routines（-R）：包含存储过程和函数
# --triggers：包含触发器（默认开启）
# --events（-E）：包含事件调度器的事件

# 综合示例（生产环境推荐）：
mysqldump -u root -p \
    --single-transaction \
    --routines \
    --triggers \
    --events \
    --source-data=2 \
    --set-gtid-purged=AUTO \
    --all-databases > full_backup.sql
```

## 输出文件内容结构

```sql
-- mysqldump 输出文件的典型结构：

-- MySQL dump 10.13  Distrib 8.4.0, for Linux (x86_64)
-- Host: localhost    Database: mydb
-- Server version	8.4.0

SET NAMES utf8mb4;
SET @OLD_CHARACTER_SET_CLIENT=@@CHARACTER_SET_CLIENT;
-- ... 其他 SET 语句（保存和恢复会话变量）

-- 表结构：
DROP TABLE IF EXISTS `users`;
CREATE TABLE `users` (
  `id` int NOT NULL AUTO_INCREMENT,
  `name` varchar(100) DEFAULT NULL,
  `email` varchar(200) DEFAULT NULL,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB AUTO_INCREMENT=4 DEFAULT CHARSET=utf8mb4;

-- 表数据：
LOCK TABLES `users` WRITE;
INSERT INTO `users` VALUES (1,'张三','zhang@test.com'),
    (2,'李四','li@test.com'),(3,'王五','wang@test.com');
UNLOCK TABLES;

-- ... 其他表的结构和数据

-- Dump completed on 2024-06-15 03:00:00
```

## 备份所需的权限

```sql
-- mysqldump 需要的最小权限：
-- SELECT：读取表数据
-- SHOW VIEW：导出视图定义
-- TRIGGER：导出触发器
-- LOCK TABLES：加表锁（如果不使用 --single-transaction）
-- PROCESS：使用 --single-transaction 时需要
-- EVENT：导出事件
-- EXECUTE：导出存储过程和函数
-- SHOW DATABASES：使用 --all-databases 时需要

-- 创建专用备份用户：
CREATE USER 'backup'@'localhost' IDENTIFIED BY 'BackupPass123!';
GRANT SELECT, SHOW VIEW, TRIGGER, LOCK TABLES, PROCESS,
      EVENT, EXECUTE, SHOW DATABASES, RELOAD
ON *.* TO 'backup'@'localhost';

-- MySQL 8.4 中可以使用 BACKUP_ADMIN 权限：
GRANT BACKUP_ADMIN ON *.* TO 'backup'@'localhost';
```

## 适用场景

- **中小型数据库的日常备份**：数据量在 50GB 以下的数据库，mysqldump 的备份和恢复速度可以接受，操作简单，是最常用的备份方式
- **数据库迁移和版本升级**：mysqldump 导出的 SQL 文件可以跨平台、跨版本使用，是从旧版本 MySQL 迁移到新版本的标准方式

## 常见问题

**mysqldump 备份大型数据库时特别慢怎么办？**

mysqldump 是单线程工具，对于大型数据库（>50GB）确实会很慢。优化方法：①使用 `--single-transaction` 避免锁表等待；②使用 `--quick`（默认开启）逐行读取数据而不是全部加载到内存；③备份时压缩输出（`mysqldump ... | gzip > backup.sql.gz`）减少 I/O；④考虑使用 `mysqlpump`（多线程逻辑备份）或 `mydumper`（社区多线程工具）替代；⑤对于超大数据库（>100GB），建议使用物理备份工具（XtraBackup）。

## 注意事项

- mysqldump 默认使用 `--extended-insert`（多行合并为一条 INSERT），这样恢复速度更快但单条 INSERT 语句可能非常长。如果备份文件需要手动编辑或部分恢复，可以使用 `--skip-extended-insert` 让每行数据一条 INSERT 语句。
- 在使用 `-p` 参数时，如果直接在命令行指定密码（`-pMyPassword`），密码会被记录在 shell 的历史记录中（`~/.bash_history`），存在安全风险。推荐使用 `--defaults-file` 指定配置文件或使用 `-p` 交互输入密码。

## 总结

mysqldump 是 MySQL 官方的逻辑备份工具，将数据库导出为 SQL 文件。三种模式：单表/多表、指定数据库（`--databases`）、全库（`--all-databases`）。关键参数：`--single-transaction`（InnoDB 一致性快照）、`--routines`（存储过程）、`--triggers`（触发器）、`--events`（事件）、`--source-data`（binlog 位置）。输出为 CREATE TABLE + INSERT INTO 的 SQL 文件。适合中小型数据库（<50GB）。大型数据库考虑 mysqlpump 或物理备份。建议创建专用备份用户并使用配置文件存储凭据。
