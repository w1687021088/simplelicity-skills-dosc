# --databases 指定数据库

`--databases`（简写 `-B`）是 mysqldump 的参数，用于指定要备份的一个或多个数据库。与直接指定数据库名不同，`--databases` 会在备份文件中生成 `CREATE DATABASE` 和 `USE` 语句，恢复时会自动创建数据库。这是备份指定数据库的推荐方式，在数据库迁移、部分备份等场景中广泛使用。

---

## 基本用法

```bash
# 备份单个数据库：
mysqldump -u root -p --databases mydb > mydb_backup.sql

# 备份多个数据库：
mysqldump -u root -p --databases mydb1 mydb2 mydb3 > multi_db_backup.sql

# 配合其他参数：
mysqldump -u root -p \
    --databases mydb1 mydb2 \
    --single-transaction \
    --routines \
    --triggers \
    --events \
    --source-data=2 \
    > selected_dbs_backup.sql
```

## --databases 与不使用 --databases 的区别

```bash
# 方式1：不使用 --databases（直接指定库名）
mysqldump -u root -p mydb > backup1.sql

# 备份文件中的内容：
# 不包含 CREATE DATABASE 语句
# 不包含 USE 语句
# 只有 CREATE TABLE 和 INSERT INTO 语句

# 恢复时必须手动创建数据库并指定：
# mysql -u root -p mydb < backup1.sql
# 如果 mydb 不存在，需要先手动创建

# 方式2：使用 --databases
mysqldump -u root -p --databases mydb > backup2.sql

# 备份文件中的内容：
# CREATE DATABASE /*!32312 IF NOT EXISTS*/ `mydb` ...;
# USE `mydb`;
# CREATE TABLE ...
# INSERT INTO ...

# 恢复时不需要手动创建数据库：
# mysql -u root -p < backup2.sql
# 自动创建 mydb 并恢复数据
```

| 对比维度 | 不使用 --databases | 使用 --databases |
|---------|:----------------:|:---------------:|
| CREATE DATABASE | 不包含 | 包含 |
| USE 语句 | 不包含 | 包含 |
| 恢复时指定库名 | 必须指定 | 不需要 |
| 可恢复到不同库名 | 可以 | 需要编辑文件 |
| 多库备份 | 不支持 | 支持 |
| 包含表 | 可指定部分表 | 整个数据库 |

## 备份到不同数据库名

```bash
# 不使用 --databases 的一个优势：可以恢复到不同的数据库名

# 备份 mydb（不包含 CREATE DATABASE）：
mysqldump -u root -p mydb > mydb_backup.sql

# 恢复到名为 mydb_test 的新数据库：
mysql -u root -p -e "CREATE DATABASE mydb_test"
mysql -u root -p mydb_test < mydb_backup.sql
# 数据被恢复到 mydb_test 而不是 mydb

# 如果使用了 --databases：
mysqldump -u root -p --databases mydb > mydb_backup.sql
# 恢复时会自动使用 USE mydb
# 数据只能恢复到 mydb

# 如果需要恢复到不同库名，需要编辑备份文件：
# 将文件中的 `mydb` 替换为 `mydb_test`
# sed -i 's/`mydb`/`mydb_test`/g' mydb_backup.sql
```

## 多数据库备份策略

```bash
# 策略1：一次命令备份多个库到一个文件
mysqldump -u root -p --databases db1 db2 db3 > multi_db.sql
# 优点：简单，一个文件包含所有库
# 缺点：不能单独恢复某个库（需要 --one-database）

# 策略2：每个库分别备份到独立文件
mysqldump -u root -p --databases db1 > db1_backup.sql
mysqldump -u root -p --databases db2 > db2_backup.sql
mysqldump -u root -p --databases db3 > db3_backup.sql
# 优点：可以单独恢复任意库
# 缺点：多次执行，时间点可能不同
```

## 适用场景

- **部分数据库的备份与迁移**：当只需要备份或迁移服务器上的部分数据库时，使用 `--databases` 指定目标数据库，避免备份不需要的数据
- **多租户环境的独立备份**：在多租户架构中每个租户有独立的数据库，使用 `--databases` 为每个租户的数据库创建独立的备份文件，便于单独恢复

## 常见问题

**使用 --databases 时可以同时指定特定的表吗？**

不可以。`--databases` 参数后面的所有参数都被视为数据库名，不能再指定表名。如果需要备份特定数据库中的特定表，应该不使用 `--databases`，直接使用 `mysqldump -u root -p dbname table1 table2` 的格式。`--databases` 的设计目的是备份完整的数据库，包括数据库中的所有表。如果需要"多个数据库各自的部分表"，需要分多次执行 mysqldump。

---

## 注意事项

- 使用 `--databases` 时，备份文件中的 `CREATE DATABASE` 语句包含 `IF NOT EXISTS`，恢复时如果目标数据库已存在不会报错。但 `DROP TABLE IF EXISTS` 会删除同名表再重建。如果目标服务器上同名数据库中有额外的表（备份中不包含的），这些表不会被删除，但同名表的数据会被覆盖。
- `--databases` 参数必须放在数据库名之前。如果放在数据库名之后，可能导致参数解析错误。正确格式：`mysqldump --databases db1 db2`，错误格式：`mysqldump db1 db2 --databases`。

---

## 总结

`--databases`（`-B`）指定要备份的数据库列表，备份文件包含 `CREATE DATABASE` 和 `USE` 语句，恢复时自动创建数据库。与不使用 `--databases` 的区别：包含库创建语句、支持多库、恢复无需手动指定库名。不使用 `--databases` 时可以灵活恢复到不同库名。不能与表名同时使用。多库备份策略：一个文件包含多库（简单）或每库独立文件（灵活）。适合部分库备份、数据库迁移和多租户独立备份。
