# --where 条件备份

`--where`（简写 `-w`）是 mysqldump 的参数，用于在备份指定表时添加 WHERE 条件，只导出满足条件的数据行。这是 mysqldump 提供的最细粒度的数据筛选方式，可以按时间范围、状态值、ID 范围等条件导出部分数据。在数据归档、部分迁移、开发环境数据采样等场景中非常实用。

---

## 基本用法

```bash
# 基本语法：
mysqldump -u root -p dbname tablename --where="条件表达式" > output.sql

# 按时间范围导出：
mysqldump -u root -p mydb orders \
    --where="created_at >= '2024-01-01' AND created_at < '2024-07-01'" \
    > orders_2024h1.sql
# 只导出 2024 年上半年的订单

# 按 ID 范围导出：
mysqldump -u root -p mydb users \
    --where="id BETWEEN 1 AND 10000" \
    > users_1_10000.sql

# 按状态导出：
mysqldump -u root -p mydb orders \
    --where="status = 'completed'" \
    > completed_orders.sql

# 按条件组合导出：
mysqldump -u root -p mydb logs \
    --where="log_level = 'ERROR' AND created_at > '2024-06-01'" \
    > error_logs_june.sql

# 使用 LIMIT 限制导出行数（采样数据）：
mysqldump -u root -p mydb users \
    --where="1=1 LIMIT 1000" \
    > users_sample.sql
# 导出前 1000 行数据
```

---

## 使用注意事项

```bash
# 1. --where 只对数据行有效，不影响表结构导出
# 表的 CREATE TABLE 语句始终完整导出
# 只有 INSERT INTO 语句受 WHERE 条件过滤

# 2. --where 只能用于指定表，不能与 --databases 或 --all-databases 组合
# 正确：
mysqldump -u root -p mydb orders --where="id > 100" > backup.sql
# 错误：
# mysqldump -u root -p --databases mydb --where="id > 100"
# --databases 后的参数都被视为数据库名

# 3. --where 应用于所有指定的表
# 如果指定多张表，WHERE 条件应用于每张表
mysqldump -u root -p mydb users orders \
    --where="id > 100" > backup.sql
# WHERE id > 100 同时应用于 users 表和 orders 表
# 两张表都只导出 id > 100 的数据

# 4. WHERE 条件中的引号处理
# Linux 中使用双引号包裹条件，内部用单引号：
mysqldump -u root -p mydb orders \
    --where="status = 'active'" > backup.sql

# Windows 中引号处理可能不同：
# mysqldump -u root -p mydb orders --where="status = 'active'" > backup.sql

# 5. 复杂条件使用括号：
mysqldump -u root -p mydb orders \
    --where="(status = 'pending' OR status = 'processing') AND amount > 100" \
    > filtered_orders.sql
```

## 常见应用场景

```bash
# 场景1：数据归档（导出并删除旧数据）
# 步骤1：导出旧数据
mysqldump -u root -p mydb access_logs \
    --where="log_date < '2023-01-01'" \
    > archive_logs_before_2023.sql

# 步骤2：确认备份完整后删除旧数据
# mysql -u root -p mydb -e \
#     "DELETE FROM access_logs WHERE log_date < '2023-01-01' LIMIT 10000"
# 分批删除避免长事务

# 场景2：开发环境数据采样
mysqldump -u root -p production_db users \
    --where="1=1 ORDER BY RAND() LIMIT 5000" \
    --single-transaction > dev_users_sample.sql
# 随机抽样 5000 条用户数据用于开发环境

# 场景3：按租户导出数据（多租户架构）
mysqldump -u root -p saas_db \
    orders products customers \
    --where="tenant_id = 42" \
    > tenant_42_data.sql
# 导出租户 42 的所有相关数据

# 场景4：导出最近的数据用于分析
mysqldump -u root -p mydb transactions \
    --where="transaction_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)" \
    --single-transaction > recent_transactions.sql
# 导出最近 30 天的交易数据
```

## 配合其他参数使用

```bash
# 只导出数据不导出结构（用于数据迁移）：
mysqldump -u root -p mydb users \
    --no-create-info \
    --where="status = 'active'" \
    --complete-insert \
    > active_users_data.sql
# --complete-insert 生成包含列名的 INSERT 语句
# 方便导入到结构不完全相同的目标表

# 配合 --single-transaction：
mysqldump -u root -p mydb orders \
    --single-transaction \
    --where="created_at >= '2024-01-01'" \
    > orders_2024.sql

# 条件备份 + 压缩：
mysqldump -u root -p mydb large_table \
    --where="is_archived = 0" \
    --single-transaction \
    | gzip > active_data.sql.gz
```

## 适用场景

- **历史数据归档**：按时间条件导出旧数据（如一年前的日志），备份后从生产表中删除，减少表体积提升查询性能
- **开发测试环境的数据准备**：从生产环境按条件或采样导出部分数据到开发测试环境，避免导出全量生产数据（数据量大且可能涉及隐私）

## 常见问题

**--where 条件中可以使用子查询吗？**

可以，但需要注意性能和语法。例如 `--where="user_id IN (SELECT id FROM users WHERE status='vip')"` 在语法上是合法的，mysqldump 会将整个 WHERE 条件传递给 SELECT 查询。但子查询可能导致性能问题（特别是在大表上），因为 mysqldump 对每张表执行 `SELECT * FROM tablename WHERE 条件`，如果子查询扫描大量数据会很慢。建议将复杂条件的结果先存入临时表，再用简单的 IN 条件导出。或者先查询出 ID 列表，拼接为 `--where="id IN (1,2,3,...)"` 的形式。

---

## 注意事项

- `--where` 条件应用于 mysqldump 指定的所有表。如果同时备份 users 和 orders 两张表，`--where="id > 100"` 会同时过滤两张表。如果两张表需要不同的过滤条件，应该分两次执行 mysqldump，每次指定不同的表和条件。
- `--where` 生成的 SQL 会在表的 SELECT 查询中添加 WHERE 子句。如果条件列上没有索引，可能导致全表扫描，在大表上执行时间会很长。建议确保 WHERE 条件中的列有合适的索引，并在备份前通过 `EXPLAIN` 验证查询计划。

---

## 总结

`--where`（`-w`）在 mysqldump 中添加行级过滤条件，只导出满足条件的数据。语法：`mysqldump dbname tablename --where="条件"`。条件应用于所有指定的表。不能与 `--databases` 或 `--all-databases` 同时使用。表结构始终完整导出，只有数据行受过滤。支持标准 SQL WHERE 语法（比较、范围、IN、子查询、LIMIT 等）。适合数据归档、条件迁移、开发环境采样。注意条件列的索引性能和多表使用时条件的适用性。
