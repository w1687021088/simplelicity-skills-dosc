# --tables 指定表

`--tables` 是 mysqldump 的参数，用于在指定数据库中只备份特定的表。当数据库中包含大量表，但只需要备份其中几张时，使用 `--tables` 可以精确控制备份范围，减少备份时间和文件大小。这在数据迁移、单表恢复、开发环境数据准备等场景中非常实用。

---

## 基本用法

```bash
# 方式1：直接在数据库名后列出表名（最常用）
mysqldump -u root -p mydb users orders products > tables_backup.sql
# 备份 mydb 数据库中的 users、orders、products 三张表

# 方式2：使用 --tables 参数显式指定
mysqldump -u root -p mydb --tables users orders products > tables_backup.sql
# 效果与方式1相同

# 配合其他参数：
mysqldump -u root -p mydb \
    --tables users orders \
    --single-transaction \
    --hex-blob \
    > selected_tables.sql

# 注意：使用 --tables 时不能同时使用 --databases
# 以下命令会报错：
# mysqldump --databases mydb --tables users  ← 错误
# --databases 后面的参数都被视为数据库名
```

---

## 排除特定表（--ignore-table）

```bash
# 如果要备份数据库中除某些表之外的所有表
# 使用 --ignore-table 参数

# 排除单张表：
mysqldump -u root -p mydb \
    --ignore-table=mydb.large_log_table > backup.sql
# 备份 mydb 中除 large_log_table 外的所有表

# 排除多张表：
mysqldump -u root -p mydb \
    --ignore-table=mydb.log_table \
    --ignore-table=mydb.tmp_table \
    --ignore-table=mydb.session_table \
    > backup.sql
# 注意：--ignore-table 的格式是 数据库名.表名

# 全库备份时排除特定表：
mysqldump -u root -p --all-databases \
    --ignore-table=mydb.huge_table \
    --ignore-table=logs.access_log \
    --single-transaction > backup.sql

# --tables 与 --ignore-table 不能同时使用
# 两者是互斥的
```

## 只备份表结构或只备份数据

```bash
# 只备份指定表的结构（不含数据）：
mysqldump -u root -p mydb users orders --no-data > schema.sql
# 输出只包含 CREATE TABLE 语句

# 只备份指定表的数据（不含结构）：
mysqldump -u root -p mydb users orders --no-create-info > data.sql
# 输出只包含 INSERT INTO 语句
# 恢复前需要确保目标表已存在

# 组合使用：先导出结构，再导出数据
# 适用于需要修改表结构后再导入数据的场景
mysqldump -u root -p mydb users --no-data > users_schema.sql
# 修改 users_schema.sql 中的表结构
mysqldump -u root -p mydb users --no-create-info > users_data.sql
# 先恢复修改后的结构，再恢复数据
```

## 备份文件的内容

```sql
-- 指定表备份的输出文件结构：

-- 注意：不包含 CREATE DATABASE 和 USE 语句
-- （因为没有使用 --databases）

-- 表1的结构和数据：
DROP TABLE IF EXISTS `users`;
CREATE TABLE `users` (
  `id` int NOT NULL AUTO_INCREMENT,
  `name` varchar(100) DEFAULT NULL,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

INSERT INTO `users` VALUES (1,'张三'),(2,'李四');

-- 表2的结构和数据：
DROP TABLE IF EXISTS `orders`;
CREATE TABLE `orders` (
  `id` int NOT NULL AUTO_INCREMENT,
  `user_id` int DEFAULT NULL,
  `amount` decimal(10,2) DEFAULT NULL,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

INSERT INTO `orders` VALUES (1,1,99.50),(2,2,199.00);

-- 恢复时需要指定数据库：
-- mysql -u root -p mydb < tables_backup.sql
```

## 单表备份与恢复的完整流程

```bash
# 场景：需要恢复被误删除的 users 表

# 前提：之前有包含 users 表的备份

# 步骤1：从备份中恢复 users 表
# 如果备份是单表备份：
mysql -u root -p mydb < users_backup.sql

# 如果备份是全库备份，需要提取 users 表的部分：
# 方法1：使用 sed 提取（不推荐，容易出错）
# 方法2：恢复到临时数据库，再复制表
mysql -u root -p -e "CREATE DATABASE temp_restore"
mysql -u root -p temp_restore < full_backup.sql
# 注意：这会恢复整个备份的所有表

# 然后只复制需要的表：
mysql -u root -p -e "
    CREATE TABLE mydb.users LIKE temp_restore.users;
    INSERT INTO mydb.users SELECT * FROM temp_restore.users;
    DROP DATABASE temp_restore;
"

# 更好的做法：日常备份时为重要表单独备份
mysqldump -u root -p mydb users --single-transaction > users_daily.sql
```

## 适用场景

- **单表数据迁移**：只需要将某张表的数据从一个数据库迁移到另一个数据库时，使用指定表备份可以精确控制迁移范围，避免导出不需要的数据
- **大表排除备份**：数据库中某些日志表或临时表非常大但不重要，使用 `--ignore-table` 排除这些表可以显著减少备份时间和文件大小

## 常见问题

**如何从全库备份中只恢复一张表？**

有几种方法：①如果全库备份使用了 `--databases` 或 `--all-databases`，可以在恢复命令中使用 `mysql --one-database mydb < backup.sql`，但这仍然会恢复 mydb 中的所有表。②更精确的方法是恢复到临时数据库，再通过 `CREATE TABLE ... LIKE` 和 `INSERT INTO ... SELECT` 复制需要的表。③最佳做法是在日常备份策略中，为重要的表单独创建备份文件，这样恢复时可以直接使用单表备份文件。④使用 `mysqlpump` 工具可以在导入时通过 `--include-tables` 筛选特定表。

---

## 注意事项

- 指定表备份不包含 `CREATE DATABASE` 和 `USE` 语句（除非同时使用 `--databases`，但 `--databases` 和 `--tables` 不能同时使用）。恢复时必须手动指定目标数据库：`mysql -u root -p target_db < backup.sql`。如果目标数据库不存在，需要先手动创建。
- 如果备份的表之间有外键依赖关系，恢复时需要注意顺序。默认情况下 mysqldump 会在备份文件开头添加 `SET FOREIGN_KEY_CHECKS=0`，在恢复结束时恢复为 `SET FOREIGN_KEY_CHECKS=1`，所以通常不需要担心外键顺序问题。但如果手动从备份文件中提取部分表的 SQL 恢复，需要自行处理外键依赖。

---

## 总结

指定表备份：`mysqldump dbname table1 table2` 或 `mysqldump dbname --tables table1 table2`。排除表：`--ignore-table=dbname.tablename`（可多次使用）。不能与 `--databases` 同时使用。备份文件不含 `CREATE DATABASE`，恢复需指定库名。配合 `--no-data`（只结构）或 `--no-create-info`（只数据）实现更精细的控制。日常备份建议为重要表单独创建备份文件，便于单表恢复。适合数据迁移、开发环境数据准备和排除大型日志表的场景。
