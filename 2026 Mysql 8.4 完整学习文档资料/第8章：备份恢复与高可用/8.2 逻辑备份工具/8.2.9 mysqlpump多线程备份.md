# mysqlpump 多线程备份

`mysqlpump` 是 MySQL 5.7.8 引入的逻辑备份工具，作为 `mysqldump` 的增强替代方案。与 mysqldump 最大的区别在于 mysqlpump 支持多线程并行备份，可以同时导出多个数据库或多张表的数据，显著提升大型数据库的备份速度。此外 mysqlpump 还支持对象级别的并行控制、进度显示、压缩输出等特性。

---

## mysqlpump vs mysqldump

| 对比维度 | mysqldump | mysqlpump |
|---------|:---------:|:---------:|
| 并行能力 | 单线程 | 多线程并行 |
| 备份速度 | 慢（大库） | 快（多线程加速）|
| 进度显示 | 无 | 支持（--watch-progress）|
| 压缩输出 | 需要管道（\| gzip）| 内置压缩（--compress-output）|
| 对象过滤 | --ignore-table | 更丰富的包含/排除选项 |
| 输出顺序 | 确定的 | 不确定（多线程）|
| 成熟度 | 非常成熟 | 较新，部分场景有限制 |
| --single-transaction | 支持 | 支持 |
| 恢复速度 | 一般 | 一般（输出格式类似）|

## 基本用法

```bash
# 基本全库备份（默认并行）：
mysqlpump -u root -p --all-databases > backup.sql

# 指定数据库备份：
mysqlpump -u root -p --databases mydb1 mydb2 > backup.sql

# 使用一致性快照（InnoDB 热备）：
mysqlpump -u root -p --single-transaction --all-databases > backup.sql

# 显示备份进度：
mysqlpump -u root -p --watch-progress --all-databases > backup.sql
# 实时显示备份进度（已完成的表数、行数等）

# 内置压缩输出：
mysqlpump -u root -p --compress-output=zlib --all-databases > backup.zlib
# 支持的压缩算法：zlib, lz4
# 恢复时需要先解压：
# zlib_decompress backup.zlib backup.sql
# lz4_decompress backup.lz4 backup.sql

# 包含存储过程、函数、事件、触发器：
mysqlpump -u root -p \
    --include-routines \
    --include-events \
    --include-triggers \
    --all-databases > backup.sql
```

## 并行控制

```bash
# mysqlpump 的并行是基于"队列"（queue）和"线程"（threads）的

# 默认并行设置：
# 默认有一个队列，包含 2 个线程

# 自定义并行度：
mysqlpump -u root -p \
    --default-parallelism=4 \
    --all-databases > backup.sql
# 默认队列使用 4 个线程

# 高级并行控制（多个队列，不同并行度）：
mysqlpump -u root -p \
    --parallel-schemas=4:mydb1,mydb2 \
    --parallel-schemas=2:mydb3 \
    --default-parallelism=1 \
    --all-databases > backup.sql
# mydb1 和 mydb2 使用 4 个线程并行导出
# mydb3 使用 2 个线程并行导出
# 其他数据库使用 1 个线程（default-parallelism）

# 禁用并行（等效于 mysqldump 的单线程模式）：
mysqlpump -u root -p --default-parallelism=0 --all-databases > backup.sql
```

## 对象过滤

```bash
# mysqlpump 提供了丰富的包含/排除选项：

# 包含指定数据库：
mysqlpump -u root -p --include-databases=mydb1,mydb2 > backup.sql

# 排除指定数据库：
mysqlpump -u root -p --exclude-databases=test,tmp > backup.sql

# 包含指定表：
mysqlpump -u root -p --include-tables=users,orders mydb > backup.sql

# 排除指定表：
mysqlpump -u root -p --exclude-tables=logs,sessions mydb > backup.sql

# 排除系统数据库：
mysqlpump -u root -p \
    --exclude-databases=mysql,sys,information_schema,performance_schema \
    > user_databases.sql

# 只备份用户和权限（不备份数据）：
mysqlpump -u root -p --exclude-databases=% --users > users_backup.sql
# --users 导出所有用户的 CREATE USER 和 GRANT 语句
# --exclude-databases=% 排除所有数据库

# 包含/排除存储过程：
mysqlpump -u root -p \
    --include-routines \
    --exclude-routines=debug_%  \
    mydb > backup.sql
```

## 用户备份功能

```bash
# mysqlpump 特有的用户备份功能（mysqldump 不直接支持）：

# 备份所有用户和权限：
mysqlpump -u root -p --exclude-databases=% --users > all_users.sql

# 备份文件中会生成：
# CREATE USER 'app_user'@'%' IDENTIFIED WITH caching_sha2_password AS '...';
# GRANT SELECT, INSERT, UPDATE ON `mydb`.* TO 'app_user'@'%';
# CREATE ROLE 'read_only_role';
# GRANT SELECT ON *.* TO 'read_only_role';

# 包含特定用户：
mysqlpump -u root -p --exclude-databases=% \
    --include-users=app_user,monitor_user > selected_users.sql

# 排除特定用户：
mysqlpump -u root -p --exclude-databases=% \
    --exclude-users=root,mysql.sys > non_system_users.sql
```

## 输出格式的差异

```sql
-- mysqlpump 的输出与 mysqldump 有一些差异：

-- 1. mysqlpump 使用 CREATE TABLE ... 后跟 INSERT 语句
-- 但 INSERT 语句的顺序在多线程下不保证

-- 2. mysqlpump 默认生成 CREATE TABLE IF NOT EXISTS
-- 而 mysqldump 默认生成 DROP TABLE IF EXISTS + CREATE TABLE

-- 3. mysqlpump 对视图的处理
-- 先创建临时表代替视图 → 创建所有基表 → 创建真正的视图 → 删除临时表
-- 这避免了视图依赖其他视图时的创建顺序问题

-- 4. 恢复方式与 mysqldump 相同：
-- mysql -u root -p < backup.sql
```

## 适用场景

- **大型数据库的加速备份**：数据量在 50GB 以上、包含多个数据库或大量表的环境，mysqlpump 的多线程并行可以显著减少备份时间（通常比 mysqldump 快 2~5 倍）
- **用户和权限的独立备份**：需要单独备份所有用户账户和权限定义时，mysqlpump 的 `--users` 功能比 mysqldump 备份 mysql 库更方便和准确

## 常见问题

**mysqlpump 的多线程备份是否保证数据一致性？**

在使用 `--single-transaction` 参数时，mysqlpump 的多线程备份可以保证 InnoDB 表的数据一致性。每个线程都在同一个一致性快照下读取数据，所以多线程不影响数据的一致性。但需要注意：多线程导出的 INSERT 语句在输出文件中的顺序是不确定的——不同表的数据可能交错排列。这不影响恢复的正确性（每条 INSERT 语句都是独立的），但如果需要手动检查或编辑备份文件，可能不太方便。

## 注意事项

- mysqlpump 在 MySQL 8.0.34 中被标记为废弃（deprecated），MySQL 官方推荐使用 MySQL Shell 的 dump utilities（`util.dumpInstance()`、`util.dumpSchemas()`）作为替代。MySQL Shell 的 dump 工具同样支持多线程并行，而且功能更强大、性能更好。如果使用 MySQL 8.4，建议评估 MySQL Shell dump utilities 作为 mysqlpump 的替代方案。
- mysqlpump 的压缩输出（`--compress-output`）使用自定义格式，恢复时需要先用对应的解压工具（`zlib_decompress` 或 `lz4_decompress`）解压为 SQL 文件，再用 `mysql` 命令恢复。不能直接用 `gunzip` 解压。如果需要通用的压缩格式，建议使用管道压缩：`mysqlpump ... | gzip > backup.sql.gz`。

---

## 总结

mysqlpump 是 MySQL 5.7.8+ 的多线程逻辑备份工具，通过并行队列和线程加速备份。关键参数：`--default-parallelism=N`（默认并行度）、`--parallel-schemas=N:db1,db2`（按库指定并行度）、`--watch-progress`（进度显示）、`--compress-output`（内置压缩）。特有功能：`--users`（用户和权限独立备份）、丰富的 `--include/exclude` 过滤选项。使用 `--single-transaction` 保证 InnoDB 一致性。在 MySQL 8.0.34 中被标记为废弃，推荐使用 MySQL Shell dump utilities 替代。适合大型多库环境的加速备份。
