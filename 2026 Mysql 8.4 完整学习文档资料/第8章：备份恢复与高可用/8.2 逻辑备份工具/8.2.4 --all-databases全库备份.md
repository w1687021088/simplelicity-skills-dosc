# --all-databases 全库备份

`--all-databases`（简写 `-A`）是 mysqldump 的参数，用于备份 MySQL 服务器上的所有数据库，包括用户数据库和系统数据库（`mysql`、`sys`、`performance_schema`、`information_schema`）。全库备份是灾难恢复的基础，确保在服务器完全损坏时可以恢复所有数据、用户、权限、存储过程等。

---

## 基本用法

```bash
# 备份所有数据库：
mysqldump -u root -p --all-databases > all_databases_backup.sql

# 生产环境推荐的完整命令：
mysqldump -u root -p \
    --all-databases \
    --single-transaction \
    --routines \
    --triggers \
    --events \
    --source-data=2 \
    --set-gtid-purged=AUTO \
    --hex-blob \
    > all_db_$(date +%Y%m%d_%H%M%S).sql

# 压缩备份（减少磁盘占用）：
mysqldump -u root -p --all-databases --single-transaction \
    | gzip > all_db_$(date +%Y%m%d).sql.gz

# 使用配置文件简化命令：
mysqldump --defaults-file=/etc/mysql/backup.cnf \
    --all-databases > all_db_backup.sql
```

## --all-databases 备份的内容

```sql
-- --all-databases 会备份以下数据库：

-- 1. 用户数据库（如 mydb、testdb 等）
--    包含所有表结构和数据

-- 2. mysql 系统数据库
--    包含用户账户、权限、密码等信息
--    user 表、db 表、global_grants 表等
--    恢复后用户和权限自动恢复

-- 3. sys 数据库
--    Performance Schema 的视图和存储过程
--    通常不需要手动恢复（MySQL 启动时自动创建）

-- 4. performance_schema
--    运行时性能数据（通常不备份实际数据）
--    mysqldump 只导出结构

-- 5. information_schema
--    虚拟数据库（MySQL 自动生成）
--    mysqldump 通常跳过

-- 备份文件中会包含：
-- CREATE DATABASE IF NOT EXISTS `mydb`;
-- USE `mydb`;
-- CREATE TABLE ...
-- INSERT INTO ...
-- CREATE DATABASE IF NOT EXISTS `mysql`;
-- USE `mysql`;
-- ...
```

## 排除特定数据库

```bash
# --all-databases 会备份所有数据库
# 如果需要排除某些数据库，使用 --ignore-table 排除表
# 或者改用 --databases 明确指定要备份的数据库

# 方法1：使用 --databases 代替（指定需要备份的库）
mysqldump -u root -p --databases mydb1 mydb2 mydb3 \
    --single-transaction > selected_dbs.sql

# 方法2：使用脚本动态生成数据库列表（排除系统库）

#      FROM information_schema.SCHEMATA \

#      ('information_schema','performance_schema','sys','mysql')")

# 全库备份包含所有库，恢复时可以只恢复需要的库
```

## --all-databases vs --databases

| 对比维度 | --all-databases | --databases db1 db2 |
|---------|:--------------:|:------------------:|
| 备份范围 | 所有数据库 | 指定的数据库 |
| 系统库 | 包含 | 需要手动指定 |
| 用户权限 | 包含（mysql 库）| 不包含（除非指定 mysql）|
| CREATE DATABASE | 包含 | 包含 |
| 灵活性 | 低（全部备份）| 高（可选择）|
| 备份大小 | 最大 | 较小 |
| 适用场景 | 灾难恢复 | 部分库备份/迁移 |

## 全库备份的恢复

```bash
# 恢复全库备份到新服务器：
mysql -u root -p < all_databases_backup.sql

# 恢复压缩的备份：
gunzip < all_db_backup.sql.gz | mysql -u root -p

# 恢复后刷新权限（确保 mysql 系统库的权限生效）：
mysql -u root -p -e "FLUSH PRIVILEGES;"

# 只从全库备份中恢复特定数据库：
# 方法1：使用 mysql 的 --one-database 参数
mysql -u root -p --one-database mydb < all_databases_backup.sql
# 只恢复 mydb 数据库的内容

# 方法2：使用 sed/grep 从备份文件中提取特定库
# 不推荐（容易出错），建议直接恢复全部或使用 --one-database
```

## 适用场景

- **完整的灾难恢复备份**：全库备份包含所有数据库、用户、权限、存储过程等，是服务器完全损坏后恢复的基础。建议每天至少执行一次全库备份
- **服务器迁移**：将整个 MySQL 实例迁移到新服务器时，`--all-databases` 一次性导出所有内容，在新服务器上恢复即可完成迁移

## 常见问题

**恢复全库备份会覆盖目标服务器上已有的数据吗？**

会。全库备份文件中包含 `DROP TABLE IF EXISTS` 语句，恢复时会先删除同名的表再重新创建和导入数据。如果目标服务器上有备份文件中不包含的数据库或表，这些不会被删除（只影响备份文件中包含的对象）。但如果目标服务器上同名表中有新数据，这些数据会被覆盖。因此在非空服务器上恢复全库备份前，应确认是否需要保留现有数据。如果只需要恢复特定数据库，使用 `mysql --one-database` 参数。

---

## 注意事项

- `--all-databases` 会备份 `mysql` 系统数据库中的用户和权限表。在跨版本恢复时（如从 8.0 恢复到 8.4），系统表结构可能不兼容，恢复 `mysql` 库可能导致问题。跨版本迁移时建议只恢复用户数据库，用户和权限通过 `CREATE USER` 和 `GRANT` 语句手动重建。
- 全库备份文件可能非常大。对于 TB 级数据库，备份文件可能也是 TB 级别。确保备份目标路径有足够的磁盘空间。可以使用管道压缩（`| gzip`）减少约 60%~80% 的空间占用。

## 总结

`--all-databases`（`-A`）备份 MySQL 服务器上的所有数据库，包括用户库和系统库（mysql、sys 等）。是灾难恢复和服务器迁移的标准方式。配合 `--single-transaction`、`--routines`、`--events`、`--source-data=2` 使用。恢复：`mysql < backup.sql`，恢复后执行 `FLUSH PRIVILEGES`。只恢复特定库：`mysql --one-database dbname < backup.sql`。跨版本恢复时注意系统表兼容性。建议管道压缩减少空间占用。
