# 导出 CSV 文本文件 SELECT ... INTO OUTFILE

`SELECT ... INTO OUTFILE` 是 MySQL 的 SQL 语句，用于将查询结果直接导出为服务器本地的文本文件（如 CSV、TSV 等格式）。与 mysqldump 导出 SQL 语句不同，`INTO OUTFILE` 导出的是纯数据文本，每行一条记录，字段之间使用指定的分隔符。这种方式导出速度快、文件体积小，适合与外部系统交换数据、数据分析导入、批量数据迁移等场景。

---

## 基本语法

```sql
-- 基本语法：
SELECT * FROM table_name
INTO OUTFILE '/path/to/output.csv'
FIELDS TERMINATED BY ','
ENCLOSED BY '"'
LINES TERMINATED BY '\n';

-- 导出 users 表为 CSV 格式：
SELECT * FROM users
INTO OUTFILE '/var/lib/mysql-files/users.csv'
FIELDS TERMINATED BY ','      -- 字段分隔符：逗号
OPTIONALLY ENCLOSED BY '"'    -- 字符串字段用双引号包裹
LINES TERMINATED BY '\n';     -- 行分隔符：换行

-- 导出为 TSV 格式（Tab 分隔）：
SELECT * FROM users
INTO OUTFILE '/var/lib/mysql-files/users.tsv'
FIELDS TERMINATED BY '\t'
LINES TERMINATED BY '\n';

-- 导出指定列和条件：
SELECT id, name, email, created_at FROM users
WHERE status = 'active'
INTO OUTFILE '/var/lib/mysql-files/active_users.csv'
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n';

-- 添加 CSV 表头（MySQL 不直接支持，需要 UNION）：
SELECT 'id', 'name', 'email', 'created_at'
UNION ALL
SELECT id, name, email, created_at FROM users
INTO OUTFILE '/var/lib/mysql-files/users_with_header.csv'
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n';
```

## 文件路径与权限

```sql
-- INTO OUTFILE 的文件路径限制：

-- 1. 文件由 MySQL 服务器进程（mysqld）写入
-- 路径必须是服务器可写的路径
-- 不是客户端的路径

-- 2. secure_file_priv 限制
SHOW VARIABLES LIKE 'secure_file_priv';
-- 可能的值：
-- '/var/lib/mysql-files/'：只能导出到该目录
-- ''（空字符串）：可以导出到任何目录
-- NULL：禁止 INTO OUTFILE 操作

-- 如果 secure_file_priv = '/var/lib/mysql-files/'：
-- 正确：
SELECT * FROM users
INTO OUTFILE '/var/lib/mysql-files/users.csv' ...;
-- 错误：
SELECT * FROM users
INTO OUTFILE '/tmp/users.csv' ...;
-- ERROR 1290: --secure-file-priv 限制

-- 3. 文件不能已存在
-- INTO OUTFILE 不会覆盖已有文件
-- 如果文件已存在，会报错：
-- ERROR 1086: File '/path/users.csv' already exists
-- 需要先删除旧文件再导出

-- 4. 权限要求
-- 需要 FILE 权限：
GRANT FILE ON *.* TO 'export_user'@'localhost';

-- Windows 路径写法：
-- SELECT * FROM users
-- INTO OUTFILE 'C:/ProgramData/MySQL/MySQL Server 8.4/Uploads/users.csv'
-- FIELDS TERMINATED BY ',' LINES TERMINATED BY '\r\n';
```

## 格式化选项详解

```sql
-- FIELDS 子句选项：

-- TERMINATED BY：字段分隔符
FIELDS TERMINATED BY ','       -- CSV（逗号分隔）
FIELDS TERMINATED BY '\t'      -- TSV（Tab 分隔）
FIELDS TERMINATED BY '|'       -- 管道符分隔
FIELDS TERMINATED BY ';'       -- 分号分隔（欧洲 CSV 常用）

-- ENCLOSED BY：字段包裹字符
ENCLOSED BY '"'                -- 所有字段用双引号包裹
OPTIONALLY ENCLOSED BY '"'     -- 只有字符串字段用双引号包裹
                               -- 数字不包裹

-- ESCAPED BY：转义字符
ESCAPED BY '\\'                -- 默认，反斜杠转义
ESCAPED BY ''                  -- 不使用转义

-- LINES 子句选项：

-- TERMINATED BY：行分隔符
LINES TERMINATED BY '\n'       -- Unix 换行（LF）
LINES TERMINATED BY '\r\n'     -- Windows 换行（CRLF）

-- STARTING BY：行前缀（少用）
LINES STARTING BY 'ROW:'       -- 每行以 'ROW:' 开头

-- 完整示例（标准 CSV）：
SELECT * FROM orders
INTO OUTFILE '/var/lib/mysql-files/orders.csv'
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
ESCAPED BY '\\'
LINES TERMINATED BY '\n';

-- 输出示例：
-- 1,"张三","zhang@test.com","2024-06-15 10:30:00"
-- 2,"李四","li@test.com","2024-06-15 11:00:00"
-- 3,"王五,Jr.","wang@test.com","2024-06-15 11:30:00"
-- 注意：第3行 name 中包含逗号，被双引号包裹保护
```

## 导入 CSV 文件（LOAD DATA INFILE）

```sql
-- 使用 LOAD DATA INFILE 导入之前导出的 CSV 文件：

LOAD DATA INFILE '/var/lib/mysql-files/users.csv'
INTO TABLE users
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n';

-- 导入时跳过表头行：
LOAD DATA INFILE '/var/lib/mysql-files/users_with_header.csv'
INTO TABLE users
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 LINES;              -- 跳过第一行（表头）

-- 导入时指定列的映射：
LOAD DATA INFILE '/var/lib/mysql-files/partial_data.csv'
INTO TABLE users (name, email)
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n';

-- 从客户端本地文件导入（不受 secure_file_priv 限制）：
LOAD DATA LOCAL INFILE 'C:/data/users.csv'
INTO TABLE users
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n';
-- 需要启用 local_infile：
-- SET GLOBAL local_infile = ON;
-- 客户端也需要启用：mysql --local-infile=1
```

## 与 mysqldump 的对比

| 对比维度 | SELECT INTO OUTFILE | mysqldump |
|---------|:------------------:|:---------:|
| 输出格式 | CSV/TSV 文本 | SQL 语句 |
| 导出速度 | 快 | 中等 |
| 文件大小 | 小（纯数据）| 大（含 SQL 语法）|
| 包含结构 | 不包含 | 包含 CREATE TABLE |
| 恢复方式 | LOAD DATA INFILE | mysql < file.sql |
| 恢复速度 | 快 | 慢 |
| 跨平台交换 | 好（通用 CSV）| 差（MySQL 专用）|
| 选择性导出 | 支持（WHERE/列选择）| 支持 |
| 文件写入位置 | 服务器端 | 客户端 |
| 权限要求 | FILE 权限 | SELECT 权限 |

## 适用场景

- **与外部系统交换数据**：将 MySQL 数据导出为 CSV 格式，供 Excel、Python（pandas）、R、Spark 等工具处理或分析。CSV 是最通用的数据交换格式
- **大数据量的快速导出/导入**：`LOAD DATA INFILE` 的导入速度比执行 INSERT SQL 语句快 10~20 倍，适合大数据量的批量加载

## 常见问题

**INTO OUTFILE 导出的文件为什么只能在服务器本地？能否直接导出到客户端？**

`SELECT ... INTO OUTFILE` 是由 MySQL 服务器进程（mysqld）执行文件写入的，因此文件只能写到服务器本地文件系统。如果需要将数据导出到客户端机器，有几种替代方案：①使用 `mysql -e "SELECT ..." > file.csv` 命令行重定向（但格式控制不如 INTO OUTFILE 灵活）；②先用 INTO OUTFILE 导出到服务器，再通过 scp/sftp 传输到客户端；③使用 mysqldump 的 `--tab` 选项（在服务器端生成数据文件，同时在客户端生成结构文件）。

## 注意事项

- `INTO OUTFILE` 不会覆盖已存在的文件。如果目标文件已存在，会报错 `File already exists`。在自动化脚本中，导出前应先检查并删除旧文件。由于文件由 mysqld 进程创建，删除文件需要有服务器文件系统的权限（不能通过 SQL 删除）。
- `NULL` 值在导出时默认显示为 `\N`（反斜杠 + N）。导入时 `LOAD DATA INFILE` 会自动将 `\N` 识别为 NULL。如果导出的 CSV 需要被非 MySQL 工具处理，NULL 的表示方式可能导致混淆。可以在 SELECT 中使用 `IFNULL(column, '')` 将 NULL 转换为空字符串。

## 总结

`SELECT ... INTO OUTFILE` 将查询结果导出为服务器本地的 CSV/TSV 文本文件。关键子句：`FIELDS TERMINATED BY`（字段分隔符）、`ENCLOSED BY`（包裹字符）、`LINES TERMINATED BY`（行分隔符）。文件受 `secure_file_priv` 路径限制，不能覆盖已有文件，需要 FILE 权限。对应的导入命令：`LOAD DATA INFILE`（速度比 INSERT 快 10~20 倍）。适合与外部系统交换数据和大数据量的快速导出/导入。文件只能写在服务器本地，不能直接导出到客户端。NULL 默认显示为 `\N`。
