# 差异备份 Differential Backup

差异备份（Differential Backup）是指每次备份都包含自最近一次**全量备份**以来所有发生变化的数据。与增量备份不同，差异备份的基准始终是最近的全量备份，而不是上一次备份。这意味着差异备份的大小会随时间递增（距离全量备份越远，变化的数据越多），但恢复时只需要全量备份 + 最新的差异备份，恢复过程比增量备份简单得多。

---

## 差异备份的原理

```
差异备份与增量备份的区别（以一周为例）：

全量备份（周日）：备份全部数据 → F0（50GB）

增量备份方式：
  周一增量 I1：周日→周一的变化（2GB）
  周二增量 I2：周一→周二的变化（3GB）
  周三增量 I3：周二→周三的变化（1.5GB）
  恢复周三：F0 + I1 + I2 + I3（需要4个备份集）

差异备份方式：
  周一差异 D1：周日→周一的变化（2GB）
  周二差异 D2：周日→周二的变化（5GB）← 包含周一和周二的变化
  周三差异 D3：周日→周三的变化（6.5GB）← 包含周一到周三的变化
  恢复周三：F0 + D3（只需要2个备份集）

对比：
  增量备份大小：2 + 3 + 1.5 = 6.5GB（总计）
  差异备份大小：2 + 5 + 6.5 = 13.5GB（总计）
  增量备份更省空间，但恢复需要所有增量
  差异备份占空间更大，但恢复只需全量+最新差异
```

## 使用 XtraBackup 实现差异备份

```bash
# XtraBackup 本身没有"差异备份"模式
# 但可以通过始终指定全量备份作为 incremental-basedir 来实现

# 步骤1：全量备份
xtrabackup --backup --target-dir=/backup/full \
    --user=root --password=xxx

# 步骤2：差异备份1（基准始终是全量备份）
xtrabackup --backup --target-dir=/backup/diff1 \
    --incremental-basedir=/backup/full \
    --user=root --password=xxx
# 注意：--incremental-basedir 指向 /backup/full（全量备份）
# 不是指向上一个差异备份

# 步骤3：差异备份2（基准仍然是全量备份）
xtrabackup --backup --target-dir=/backup/diff2 \
    --incremental-basedir=/backup/full \
    --user=root --password=xxx

# 步骤4：差异备份3（基准仍然是全量备份）
xtrabackup --backup --target-dir=/backup/diff3 \
    --incremental-basedir=/backup/full \
    --user=root --password=xxx

# 恢复（只需全量 + 最新差异）：
# 1. Prepare 全量备份
xtrabackup --prepare --apply-log-only --target-dir=/backup/full

# 2. 应用最新的差异备份（不需要 diff1 和 diff2）
xtrabackup --prepare --target-dir=/backup/full \
    --incremental-dir=/backup/diff3

# 3. 恢复
# systemctl stop mysqld
# rm -rf /var/lib/mysql/*
xtrabackup --copy-back --target-dir=/backup/full
# chown -R mysql:mysql /var/lib/mysql
# systemctl start mysqld
```

## 三种备份策略对比

| 对比维度 | 全量备份 | 增量备份 | 差异备份 |
|---------|:------:|:------:|:------:|
| 每次备份内容 | 全部数据 | 上次备份后的变化 | 全量后的所有变化 |
| 备份速度 | 最慢 | 最快 | 快（随时间变慢）|
| 备份大小 | 最大 | 最小 | 中等（随时间增大）|
| 存储总量 | 最大 | 最小 | 中等 |
| 恢复复杂度 | 最简单 | 最复杂（链式）| 简单（2步）|
| 恢复速度 | 最快 | 最慢 | 较快 |
| 容错性 | 最高 | 最低（链式依赖）| 较高 |
| 恢复所需备份集 | 1个 | 全量+所有增量 | 全量+最新差异 |

## 差异备份的存储空间变化

```
差异备份大小随时间的变化趋势：

假设每天数据变更量约为总量的 2%：

全量备份后第1天：差异 ≈ 2% × 50GB = 1GB
全量备份后第2天：差异 ≈ 4% × 50GB = 2GB
全量备份后第3天：差异 ≈ 6% × 50GB = 3GB
全量备份后第4天：差异 ≈ 8% × 50GB = 4GB
全量备份后第5天：差异 ≈ 10% × 50GB = 5GB
全量备份后第6天：差异 ≈ 12% × 50GB = 6GB

注意：实际大小取决于数据的修改模式
如果同一批数据被反复修改（热点数据）：差异备份增长慢
如果每天修改的是不同数据：差异备份线性增长

当差异备份的大小接近全量备份时
应该执行新的全量备份重新作为基准
```

## 实际备份策略选择

```
根据业务需求选择备份策略：

策略1：每天全量（最简单）
  适用：小型数据库（< 10GB）
  优点：恢复最简单，无依赖
  缺点：每天备份量大

策略2：每周全量 + 每天增量（最省空间）
  适用：大型数据库，存储空间有限
  优点：备份量最小
  缺点：恢复复杂，依赖链长

策略3：每周全量 + 每天差异（平衡方案）
  适用：中大型数据库，对恢复速度有要求
  优点：恢复只需2步，容错性好
  缺点：存储空间比增量大

策略4：每天全量 + 每小时增量（高可用）
  适用：关键业务，RTO/RPO 要求严格
  优点：数据丢失风险最小
  缺点：管理复杂，存储成本高

推荐：大多数生产环境选择策略3（每周全量 + 每天差异）
平衡了备份效率、存储成本和恢复速度
```

## 适用场景

- **对恢复速度有较高要求的生产环境**：差异备份恢复只需要全量备份 + 最新差异备份两步操作，比增量备份（需要依次应用所有增量）快得多，适合 RTO 要求较严格的场景
- **需要在备份空间和恢复效率之间取得平衡**：差异备份比每天全量备份节省空间，又比增量备份恢复更简单更快速

## 常见问题

**差异备份和增量备份在 XtraBackup 中的命令有什么区别？**

在 XtraBackup 中，差异备份和增量备份使用相同的 `--backup --incremental-basedir` 参数，区别仅在于 `--incremental-basedir` 指向的目录不同。增量备份的 `--incremental-basedir` 指向上一次备份（可以是全量或增量），差异备份的 `--incremental-basedir` 始终指向最近的全量备份。XtraBackup 本身不区分"增量"和"差异"——它只知道"备份 LSN 大于指定基准的数据页"。差异与增量的区别完全取决于你指定的基准目录。

## 注意事项

- 差异备份的大小会随时间增长。如果距离上一次全量备份的时间太长（如超过一周），差异备份可能接近甚至超过全量备份的大小。此时应及时执行新的全量备份重置基准。一般建议每周执行一次全量备份作为差异备份的基准。
- 差异备份虽然恢复比增量备份简单（只需全量 + 最新差异），但仍然需要全量备份作为基础。如果全量备份损坏或丢失，所有差异备份都无法使用。因此全量备份应存储多份副本，且定期验证其完整性。

---

## 总结

差异备份每次备份自最近全量备份以来的所有变化数据，基准始终是全量备份。恢复只需全量 + 最新差异（2步），比增量备份（链式多步）简单。大小随时间增长，当接近全量大小时应重新做全量备份。XtraBackup 实现：`--incremental-basedir` 始终指向全量备份目录。推荐策略：每周全量 + 每天差异（平衡备份效率和恢复速度）。容错性优于增量备份（单个差异备份损坏不影响其他差异备份）。全量备份是差异备份的基础，必须确保全量备份的安全。
