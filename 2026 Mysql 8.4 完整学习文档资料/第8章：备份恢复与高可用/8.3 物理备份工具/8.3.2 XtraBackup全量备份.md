# XtraBackup 全量备份

XtraBackup 全量备份是将 MySQL 数据库的所有 InnoDB 数据文件、系统表空间、undo 表空间、redo log 以及 non-InnoDB 数据完整复制到指定目录的过程。全量备份是增量备份的基础，也是灾难恢复最直接的数据来源。本文详细介绍 XtraBackup 全量备份的完整操作流程、参数配置和生产环境最佳实践。

## 执行全量备份

```bash
# 基本全量备份命令：
xtrabackup --backup \
    --target-dir=/backup/full_20240615 \
    --user=bkpuser \
    --password=BackupPass123!

# 参数说明：
# --backup：执行备份操作
# --target-dir：备份文件的存储目录（必须不存在或为空）
# --user：MySQL 用户名
# --password：MySQL 密码

# 使用配置文件存储凭据（推荐）：
xtrabackup --backup \
    --defaults-file=/etc/my.cnf \
    --target-dir=/backup/full_20240615 \
    --user=bkpuser \
    --password=BackupPass123!

# 限制 I/O 速率（减少对生产的影响）：
xtrabackup --backup \
    --target-dir=/backup/full_20240615 \
    --user=bkpuser \
    --password=BackupPass123! \
    --throttle=40
# --throttle=40：每秒最多读取 40 个 I/O 操作

# 并行备份（加速大库备份）：
xtrabackup --backup \
    --target-dir=/backup/full_20240615 \
    --user=bkpuser \
    --password=BackupPass123! \
    --parallel=4
# --parallel=4：使用 4 个线程并行复制数据文件

# 压缩备份（减少存储空间）：
xtrabackup --backup \
    --target-dir=/backup/full_20240615 \
    --user=bkpuser \
    --password=BackupPass123! \
    --compress \
    --compress-threads=4
# --compress：启用 qpress 压缩
# --compress-threads=4：使用 4 个压缩线程
```

## 生产环境备份脚本

```bash
#!/bin/bash
# XtraBackup 全量备份脚本

BACKUP_BASE="/backup"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="${BACKUP_BASE}/full_${DATE}"
LOG_FILE="${BACKUP_BASE}/backup_${DATE}.log"
MYSQL_USER="bkpuser"
MYSQL_PASS="BackupPass123!"
RETENTION_DAYS=7

echo "$(date): 开始全量备份..." | tee -a $LOG_FILE

# 执行备份
xtrabackup --backup \
    --target-dir=$BACKUP_DIR \
    --user=$MYSQL_USER \
    --password=$MYSQL_PASS \
    --parallel=4 \
    --throttle=40 \
    2>> $LOG_FILE

# 检查备份结果
if tail -1 $LOG_FILE | grep -q "completed OK"; then
    echo "$(date): 备份成功: $BACKUP_DIR" | tee -a $LOG_FILE
    
    # 执行 prepare
    xtrabackup --prepare --target-dir=$BACKUP_DIR 2>> $LOG_FILE
    
    if tail -1 $LOG_FILE | grep -q "completed OK"; then
        echo "$(date): Prepare 完成" | tee -a $LOG_FILE
    else
        echo "$(date): Prepare 失败！" | tee -a $LOG_FILE
    fi
else
    echo "$(date): 备份失败！" | tee -a $LOG_FILE
    # 发送告警通知
fi

# 清理过期备份
find $BACKUP_BASE -maxdepth 1 -name "full_*" -type d \
    -mtime +$RETENTION_DAYS -exec rm -rf {} \;
echo "$(date): 已清理 ${RETENTION_DAYS} 天前的备份" | tee -a $LOG_FILE
```

## 适用场景

- **大型 InnoDB 数据库的日常全量备份**：数据量在 100GB 以上的数据库，XtraBackup 的物理复制速度远超 mysqldump，且支持并行和限速，对生产影响可控
- **增量备份策略的基础**：每周执行一次 XtraBackup 全量备份作为基础，每天执行增量备份，形成完整的备份恢复链

## 常见问题

**XtraBackup 全量备份可以只备份指定的数据库或表吗？**

XtraBackup 支持部分备份（partial backup），可以通过 `--databases="mydb1 mydb2"` 指定数据库，或通过 `--tables-file=/path/to/tables.txt` 指定表列表。但部分备份有一些限制：①恢复时不能直接恢复到运行中的实例，需要先恢复整个备份再导入需要的表；②部分备份不包含系统表空间中的数据（如果使用共享表空间 `innodb_file_per_table=OFF`）；③部分备份的增量备份管理更复杂。大多数场景下推荐全量备份所有数据库，需要部分恢复时再从全量备份中提取。

---

## 注意事项

- XtraBackup 的 `--target-dir` 必须是一个不存在或为空的目录。如果目录已存在且不为空，XtraBackup 会报错拒绝执行。在自动化脚本中应使用日期时间戳命名目录（如 `full_20240615_030000`），避免目录冲突。
- 备份完成后建议立即执行 `--prepare`（如果不需要后续的增量备份应用）。Prepare 后的备份可以直接用于恢复，减少恢复时的等待时间。但如果计划在全量备份上应用增量备份，应在应用增量前不执行 prepare（或使用 `--apply-log-only` 参数 prepare）。

## 总结

XtraBackup 全量备份通过物理复制 InnoDB 数据文件 + redo log 实现热备份。命令：`xtrabackup --backup --target-dir=/path`。关键参数：`--parallel`（并行线程）、`--throttle`（I/O 限速）、`--compress`（压缩）。备份后通过 `xtrabackup --prepare` 实现数据一致性。验证：检查日志中的 "completed OK!"、xtrabackup_checkpoints 文件、备份大小。生产脚本应包含备份验证、prepare、过期清理和告警通知。全量备份是增量备份的基础。推荐每周全量 + 每天增量的策略。
