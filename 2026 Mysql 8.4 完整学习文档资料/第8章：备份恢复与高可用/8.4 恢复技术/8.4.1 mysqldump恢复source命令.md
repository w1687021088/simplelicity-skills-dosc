# mysqldump 恢复 source 命令

`source` 是 MySQL 客户端（mysql 命令行工具）的内置命令，用于在交互式会话中执行 SQL 文件。通过 `source` 命令可以恢复 mysqldump 导出的备份文件，将备份中的 CREATE TABLE 和 INSERT INTO 语句逐条执行，重建数据库的表结构和数据。`source` 是 DBA 手动恢复备份时最常用的方式之一。

---

## 基本用法

```sql
-- 在 mysql 命令行中使用 source 恢复备份：

-- 步骤1：登录 MySQL
-- mysql -u root -p

-- 步骤2：选择目标数据库（如果备份不包含 CREATE DATABASE）
USE mydb;

-- 步骤3：执行 source 命令
source /path/to/backup.sql;
-- 或使用简写形式：
\. /path/to/backup.sql

-- Windows 路径示例：
source D:/backup/mydb_backup.sql;
-- 或
source D:\\backup\\mydb_backup.sql;

-- 恢复全库备份（包含 CREATE DATABASE 语句）：
-- 不需要先 USE 某个数据库
source /backup/all_databases_backup.sql;
```

---

## source 命令的执行过程

```sql
-- source 命令的内部行为：

-- 1. 逐行读取 SQL 文件
-- 2. 将每条 SQL 语句发送给 MySQL 服务器执行
-- 3. 显示每条语句的执行结果（或错误信息）
-- 4. 文件中的所有语句执行完毕后返回 mysql 提示符

-- 典型的备份文件执行顺序：
-- SET NAMES utf8mb4;                          ← 设置字符集
-- SET @OLD_...=@@...;                         ← 保存当前环境变量
-- SET FOREIGN_KEY_CHECKS=0;                   ← 关闭外键检查
-- DROP TABLE IF EXISTS `users`;               ← 删除旧表
-- CREATE TABLE `users` (...);                 ← 创建表
-- LOCK TABLES `users` WRITE;                  ← 锁表
-- INSERT INTO `users` VALUES (...);           ← 插入数据
-- UNLOCK TABLES;                              ← 解锁
-- ...（其他表的结构和数据）
-- SET FOREIGN_KEY_CHECKS=1;                   ← 恢复外键检查
-- SET @...=@OLD_...;                          ← 恢复环境变量
```

## 恢复前的准备工作

```sql
-- 在恢复之前建议进行以下准备：

-- 1. 确认备份文件完整性
-- 检查文件末尾是否有 "Dump completed" 字样
-- Linux: tail -5 /backup/backup.sql
-- Windows: Get-Content D:\backup\backup.sql -Tail 5

-- 2. 如果恢复到非空数据库，了解覆盖影响
-- 备份文件中的 DROP TABLE IF EXISTS 会删除同名表
-- 已有的同名表数据会被覆盖

-- 3. 临时调整参数提升恢复速度
SET GLOBAL innodb_flush_log_at_trx_commit = 0;
-- 减少磁盘刷新频率（恢复完成后改回 1）

SET GLOBAL sync_binlog = 0;
-- 减少 binlog 同步频率（恢复完成后改回 1）

SET GLOBAL foreign_key_checks = 0;
-- 关闭外键检查（加速导入）

SET GLOBAL unique_checks = 0;
-- 关闭唯一性检查（加速导入）

-- 4. 如果不需要记录恢复操作到 binlog
SET SESSION sql_log_bin = 0;
-- 避免恢复操作产生大量 binlog
-- 适用于非复制环境或手动同步的场景
```

## 恢复速度优化

```sql
-- source 恢复的速度受多个因素影响：

-- 1. innodb_buffer_pool_size
-- 确保有足够的缓冲池容纳索引和数据
SHOW VARIABLES LIKE 'innodb_buffer_pool_size';

-- 2. max_allowed_packet
-- 备份文件中的 INSERT 语句可能很长（extended insert）
-- 如果 max_allowed_packet 太小会导致语句被截断
SET GLOBAL max_allowed_packet = 1073741824;  -- 1GB

-- 3. bulk_insert_buffer_size
SET GLOBAL bulk_insert_buffer_size = 268435456;  -- 256MB

-- 4. innodb_log_file_size / innodb_redo_log_capacity
-- 较大的 redo log 可以减少频繁的 checkpoint
-- 但这是只读变量，需要在 my.cnf 中设置

-- 恢复完成后恢复安全参数：
SET GLOBAL innodb_flush_log_at_trx_commit = 1;
SET GLOBAL sync_binlog = 1;
SET GLOBAL foreign_key_checks = 1;
SET GLOBAL unique_checks = 1;
```

## source 与管道恢复的对比

| 对比维度 | source 命令 | 管道恢复（mysql < file） |
|---------|:-----------:|:---------------------:|
| 使用方式 | 交互式 mysql 会话 | 命令行直接执行 |
| 进度可见 | 可见每条语句执行 | 无输出（直到完成或报错）|
| 错误处理 | 实时看到错误 | 错误输出到终端 |
| 中断恢复 | Ctrl+C 中断 | Ctrl+C 中断 |
| 脚本化 | 不方便 | 方便（可在脚本中使用）|
| 适用场景 | 手动恢复、调试 | 自动化恢复 |

## 适用场景

- **DBA 手动恢复备份**：在交互式 mysql 会话中使用 source 命令恢复，可以实时观察恢复进度和错误信息，适合手动操作和排查问题
- **恢复到不同数据库名**：先 `USE target_db` 切换到目标数据库，再 source 不含 CREATE DATABASE 的备份文件，可以将数据恢复到不同的数据库名下

---

## 常见问题

**source 恢复过程中遇到错误会停止吗？**

默认情况下，source 遇到错误会显示错误信息但继续执行后续语句。这意味着如果中间某条 INSERT 失败，后续的语句仍会执行。如果希望遇到错误时立即停止，可以在启动 mysql 客户端时使用 `--force` 的反向操作——默认就是不停止。要实现遇错停止，可以在 mysql 客户端中设置：`\W`（启用警告显示），但 mysql 客户端本身没有"遇错停止"的选项。在自动化场景中，建议使用管道方式（`mysql < file.sql`）并检查退出码来判断是否有错误。

---

## 注意事项

- `source` 是 mysql 客户端的内置命令，不是 SQL 语句。它不能通过 JDBC、Python Connector 等编程接口执行。在应用程序中恢复备份，应该读取 SQL 文件内容，逐条执行 SQL 语句，或使用命令行调用 `mysql < file.sql`。
- 恢复大型备份文件时，`source` 命令会持续执行很长时间（可能数小时）。期间如果 mysql 客户端连接断开（如 SSH 超时），恢复会中断。建议使用 `screen` 或 `tmux` 等终端复用工具保持会话，或使用 `nohup mysql < file.sql &` 在后台执行。

---

## 总结

`source` 是 mysql 客户端的内置命令，用于在交互式会话中执行 SQL 文件恢复备份。语法：`source /path/to/backup.sql` 或 `\. /path/to/backup.sql`。恢复前建议临时调整参数（`innodb_flush_log_at_trx_commit=0`、`sync_binlog=0`）提升速度，恢复后恢复安全参数。适合手动恢复和调试。大型备份恢复时使用终端复用工具防止连接断开。不是 SQL 语句，不能在编程接口中使用。与管道恢复（`mysql < file`）互为替代。
