# 物理备份恢复拷贝文件

物理备份恢复是将备份的数据库文件直接拷贝回 MySQL 数据目录的过程。与逻辑恢复（执行 SQL 语句）不同，物理恢复是文件级别的操作，速度远快于逻辑恢复，特别适合大型数据库的快速恢复。物理恢复的核心步骤是：停止 MySQL → 清空数据目录 → 拷贝备份文件 → 修复权限 → 启动 MySQL。

---

## 冷备份的恢复

```bash
# 冷备份恢复是最简单的物理恢复方式
# 前提：冷备份时直接复制了 MySQL 数据目录下的所有文件

# 步骤1：停止 MySQL 服务
systemctl stop mysqld
# Windows: net stop mysql84

# 确认 MySQL 完全停止：
# ps aux | grep mysqld     (Linux)
# tasklist | findstr mysqld (Windows)

# 步骤2：备份当前数据目录（安全措施）
mv /var/lib/mysql /var/lib/mysql_damaged
# Windows: Rename-Item "C:\ProgramData\MySQL\MySQL Server 8.4\Data" "Data_damaged"

# 步骤3：创建新的数据目录
mkdir /var/lib/mysql
# Windows: New-Item -ItemType Directory -Path "C:\ProgramData\MySQL\MySQL Server 8.4\Data"

# 步骤4：拷贝备份文件到数据目录
cp -a /backup/cold_backup_20240615/* /var/lib/mysql/
# -a 参数保留文件属性（权限、时间戳等）
# Windows: Copy-Item "D:\backup\cold_backup_20240615\*" -Destination "C:\...\Data\" -Recurse

# 步骤5：修复文件权限（Linux）
chown -R mysql:mysql /var/lib/mysql
chmod 750 /var/lib/mysql

# 步骤6：处理 SELinux 上下文（如果启用了 SELinux）
# restorecon -Rv /var/lib/mysql

# 步骤7：启动 MySQL
systemctl start mysqld
# Windows: net start mysql84

# 步骤8：验证恢复结果
mysql -u root -p -e "SHOW DATABASES;"
mysql -u root -p -e "SELECT COUNT(*) FROM mydb.users;"
```

## XtraBackup 备份的恢复

```bash
# XtraBackup 恢复使用 --copy-back 或 --move-back 命令

# 前提：备份已经完成 prepare
# xtrabackup --prepare --target-dir=/backup/full

# 步骤1：停止 MySQL
systemctl stop mysqld

# 步骤2：清空数据目录
rm -rf /var/lib/mysql/*
# 注意：不要删除 /var/lib/mysql 目录本身
# 只删除目录下的内容

# 步骤3：使用 --copy-back 恢复
xtrabackup --copy-back --target-dir=/backup/full
# 数据文件从 /backup/full 复制到 my.cnf 中的 datadir 路径
# 默认读取 /etc/my.cnf 中的 datadir 配置

# 如果 datadir 不在默认位置，需要指定配置文件：
xtrabackup --copy-back \
    --defaults-file=/etc/my.cnf \
    --target-dir=/backup/full

# 或使用 --move-back（移动文件，速度更快）：
# xtrabackup --move-back --target-dir=/backup/full
# 注意：move-back 后备份目录被清空

# 步骤4：修复权限
chown -R mysql:mysql /var/lib/mysql

# 步骤5：启动 MySQL
systemctl start mysqld
```

## 恢复到不同服务器的注意事项

```bash
# 当备份来自服务器 A，恢复到服务器 B 时需要注意：

# 1. datadir 路径可能不同
# 确认目标服务器的 datadir 路径：
# mysql -u root -p -e "SHOW VARIABLES LIKE 'datadir'"
# 确保将文件拷贝到正确的路径

# 2. server_uuid 冲突
# 备份中的 auto.cnf 包含源服务器的 server_uuid
# 如果两台服务器在同一复制拓扑中，UUID 不能重复
# 解决：恢复后删除 auto.cnf，MySQL 启动时会生成新的 UUID
rm -f /var/lib/mysql/auto.cnf

# 3. innodb_data_home_dir 和 innodb_log_group_home_dir
# 如果源服务器使用了非默认的 InnoDB 目录配置
# 目标服务器的 my.cnf 需要匹配，或调整文件位置

# 4. innodb_page_size
# 源和目标的 innodb_page_size 必须相同
# 默认都是 16K，但如果修改过需要确认

# 5. 操作系统差异
# 大小写敏感性：Linux 区分大小写，Windows 不区分
# 如果从 Linux 恢复到 Windows，检查 lower_case_table_names

# 6. MySQL 版本
# 物理备份不能跨大版本恢复
# 8.0 的备份 → 只能恢复到 8.0
# 8.4 的备份 → 只能恢复到 8.4
```

## 恢复后的验证步骤

```sql
-- 恢复并启动 MySQL 后执行以下验证：

-- 1. 检查 Error Log
-- tail -50 /var/log/mysqld.log
-- 查看是否有 ERROR 或 WARNING

-- 2. 检查数据库列表
SHOW DATABASES;

-- 3. 检查 InnoDB 引擎状态
SHOW ENGINE INNODB STATUS\G
-- 确认没有崩溃恢复错误

-- 4. 检查表的完整性
-- 对关键表执行 CHECK TABLE
CHECK TABLE mydb.users;
CHECK TABLE mydb.orders;

-- 5. 检查行数是否正确
SELECT TABLE_SCHEMA, TABLE_NAME, TABLE_ROWS
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'mydb';

-- 6. 执行业务查询验证数据正确性
SELECT * FROM mydb.users LIMIT 10;

-- 7. 如果是复制环境，检查复制状态
SHOW REPLICA STATUS\G
```

## 适用场景

- **大型数据库的快速恢复**：物理恢复是直接拷贝文件，恢复速度取决于磁盘 I/O 速度而非 SQL 执行速度。100GB 的数据库，物理恢复可能只需 10~30 分钟，而逻辑恢复可能需要数小时
- **灾难恢复和服务器替换**：服务器硬件故障后，将物理备份恢复到新服务器，是最快恢复服务的方式

## 常见问题

**恢复后 MySQL 启动失败，Error Log 中显示 "InnoDB: Page size mismatch" 怎么办？**

这表示备份数据的 `innodb_page_size` 与当前 MySQL 配置的 `innodb_page_size` 不一致。MySQL 默认的 page_size 是 16K，但某些环境可能配置为 4K、8K 或 32K。解决方法：查看备份来源服务器的 `innodb_page_size` 配置，在目标服务器的 my.cnf 中设置相同的值（`innodb_page_size=16384`）。注意：`innodb_page_size` 是在初始化数据库时确定的，之后不能修改。如果目标服务器已有数据且 page_size 不同，需要先清空数据目录再恢复。

## 注意事项

- 物理恢复前必须完全停止 MySQL 服务。如果在 MySQL 运行时直接覆盖数据文件，会导致数据损坏。使用 `systemctl stop mysqld` 停止后，还应通过进程检查（`ps aux | grep mysqld`）确认 mysqld 进程已完全退出。某些情况下 mysqld 可能需要较长时间完成关闭（如有大事务需要回滚）。
- 拷贝文件时务必使用保留属性的复制命令（如 `cp -a` 或 `rsync -a`），确保文件的权限、所有者等属性正确。即使使用了 `cp -a`，如果源和目标的 UID/GID 不同（如跨服务器恢复），仍需执行 `chown -R mysql:mysql /var/lib/mysql` 修复权限。

## 总结

物理备份恢复通过直接拷贝数据文件实现，速度远快于逻辑恢复。核心流程：停止 MySQL → 清空 datadir → 拷贝文件（`cp -a` 或 `xtrabackup --copy-back`）→ 修复权限（`chown -R mysql:mysql`）→ 启动 MySQL。XtraBackup 备份需要先 prepare 再恢复。跨服务器恢复注意：datadir 路径、server_uuid（删除 auto.cnf）、innodb_page_size、MySQL 版本一致性。恢复后检查 Error Log、表完整性、行数。不能跨大版本恢复。适合大型数据库的快速恢复和灾难恢复。
