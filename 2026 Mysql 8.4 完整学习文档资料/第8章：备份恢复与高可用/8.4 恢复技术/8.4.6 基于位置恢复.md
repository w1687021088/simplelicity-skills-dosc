# 基于位置恢复

基于位置恢复（Position-Based Recovery）是通过指定 Binary Log 文件名和偏移量（Position）来精确控制 binlog 重放范围的恢复方式。与基于时间的恢复相比，基于位置的恢复更加精确——它可以精确到单个 SQL 语句级别，而时间恢复只能精确到秒。在同一秒内有多条语句执行的场景中，基于位置恢复是唯一能实现语句级精确恢复的方式。

---

## Binlog 位置的概念

```
Binary Log 的位置（Position）是一个整数值，表示 binlog 文件中的字节偏移量。

每个 binlog 文件：
  起始位置：4（前 4 字节是 binlog 魔数标识）
  每个事件（Event）：
    4字节 时间戳
    1字节 事件类型
    4字节 server_id
    4字节 事件长度
    4字节 下一个事件的位置（end_log_pos）
    ...事件具体数据

查看 binlog 事件和位置：
  SHOW BINLOG EVENTS IN 'mysql-bin.000020';
  
  Log_name           | Pos  | Event_type | Server_id | End_log_pos | Info
  mysql-bin.000020   | 4    | Format_desc| 1         | 125         | Server ver: 8.4.0
  mysql-bin.000020   | 125  | Previous_gtids| 1      | 156         |
  mysql-bin.000020   | 156  | Gtid       | 1         | 235         | SET @@SESSION.GTID_NEXT= ...
  mysql-bin.000020   | 235  | Query      | 1         | 345         | BEGIN
  mysql-bin.000020   | 345  | Table_map  | 1         | 400         | table_id: 123 (mydb.orders)
  mysql-bin.000020   | 400  | Write_rows | 1         | 460         | table_id: 123
  mysql-bin.000020   | 460  | Xid        | 1         | 491         | COMMIT /* xid=100 */
  ...
  
关键位置点：
  事务开始（BEGIN）的位置 → 起始位置
  事务提交（Commit/Xid）的结束位置 → 结束位置
  --start-position 和 --stop-position 应指向事务边界
```

## 定位目标 Position

```bash
# 步骤1：确定大致时间范围
# 先用时间过滤缩小范围，再找精确位置

# 方法1：SHOW BINLOG EVENTS（适合小量事件）
SHOW BINLOG EVENTS IN 'mysql-bin.000020'
    FROM 1 LIMIT 100;
-- 查看前 100 个事件的位置信息

-- 从指定位置开始查看：
SHOW BINLOG EVENTS IN 'mysql-bin.000020'
    FROM 156 LIMIT 50;

# 方法2：mysqlbinlog 输出到文件后搜索
mysqlbinlog --no-defaults \
    --start-datetime="2024-06-15 15:25:00" \
    --stop-datetime="2024-06-15 15:35:00" \
    --verbose \
    /var/log/mysql/mysql-bin.000020 > /tmp/binlog_analysis.txt

# 在输出文件中搜索目标操作：
# Linux:
grep -n "DELETE FROM orders" /tmp/binlog_analysis.txt
grep -B5 "DELETE FROM orders" /tmp/binlog_analysis.txt  # 显示前5行（包含 at 行）

# 找到类似以下内容：
# # at 12345                 ← 这就是事件的开始位置
# #240615 15:30:00 server id 1  end_log_pos 12500 CRC32 0x12345678
# # Delete_rows: table id 123
# ### DELETE FROM `mydb`.`orders`
# ### WHERE

# 关键位置信息：
# Position 12345 = 误操作事务的开始（BEGIN）
# Position 12500 = 误操作事务的结束（Commit）
# 恢复目标：重放到 12344（误操作 BEGIN 之前）
```

## 基于位置的 PITR 操作

```bash
# 场景：发现 mysql-bin.000020 Position 12345 是误操作（DELETE FROM orders）
# 全量备份时的 binlog 位置：mysql-bin.000020 Position 157

# 策略1：停在误操作之前
# 重放从备份位置到误操作位置之前的所有 binlog

mysqlbinlog --no-defaults \
    --start-position=157 \
    --stop-position=12345 \
    /var/log/mysql/mysql-bin.000020 \
    | mysql -u root -p
# --stop-position=12345：在位置 12345 处停止（不包含该位置的事件）
# 即恢复到误操作 BEGIN 之前

# 策略2：跳过误操作后继续重放（恢复误操作之后的正常数据）
# 先执行策略1，然后继续重放误操作之后的内容

# 重放误操作之后的正常 binlog：
mysqlbinlog --no-defaults \
    --start-position=12500 \
    /var/log/mysql/mysql-bin.000020 \
    /var/log/mysql/mysql-bin.000021 \
    | mysql -u root -p
# --start-position=12500：从误操作事务结束后开始重放
# 跳过了位置 12345~12500 的误操作事务
```

## --start-position 与 --stop-position 参数详解

```bash
# 参数规则：

# 1. --start-position 和 --stop-position 是针对第一个 binlog 文件的
# 当有多个 binlog 文件时，--start-position 只对第一个文件有效
# 后续文件从文件开头开始读取

# 示例：
mysqlbinlog \
    --start-position=157 \
    --stop-position=5000 \
    mysql-bin.000020 mysql-bin.000021
# mysql-bin.000020：从 Position 157 开始读到 Position 5000
# mysql-bin.000021：从文件开头读（如果 mysql-bin.000020 未到 5000 就结束，mysql-bin.000021 不会读）
# 如果 Position 5000 在 mysql-bin.000021 中，则读完 mysql-bin.000020 后继续读 mysql-bin.000021 直到 5000

# 2. 位置必须指向事务边界（BEGIN 或 Commit/XID 之后）
# 不要在事务中间切断，否则会导致数据不一致

# 正确的位置选择：
# 找到目标事务的 BEGIN 位置或上一个 Commit 的 end_log_pos
SHOW BINLOG EVENTS IN 'mysql-bin.000020' FROM 12000 LIMIT 20;
# 找到目标事务之前的最后一个 Commit/Xid 的 End_log_pos
# 将该值作为 --stop-position
```

## 与基于时间恢复的对比

| 对比维度 | 基于时间点（--stop-datetime）| 基于位置（--stop-position）|
|---------|:------------------------:|:------------------------:|
| 精度 | 秒级 | 语句级 |
| 使用难度 | 简单 | 中等（需找到 Position）|
| 同一秒多语句 | 无法区分 | 可精确区分 |
| 依赖时区 | 依赖（需注意时区）| 不依赖 |
| 适用场景 | 明确时间点的误操作 | 需要精确跳过特定语句 |
| 风险 | 可能包含或遗漏边界操作 | 精确控制 |

---

## 适用场景

- **同一秒内有多个操作需要区分**：当误操作和正常操作发生在同一秒内，基于时间恢复无法区分两者，必须使用基于位置恢复来精确跳过误操作语句
- **需要跳过特定操作继续重放后续数据**：先停在误操作之前（`--stop-position`），再从误操作之后继续重放（`--start-position`），实现"跳过特定事务"的精确恢复

## 常见问题

**如何快速找到某个 DDL（如 DROP TABLE）在 binlog 中的 Position？**

效率最高的方法是使用 `mysqlbinlog --verbose` 解析 binlog 并用文本搜索工具定位。步骤：①`mysqlbinlog --verbose mysql-bin.000020 > /tmp/analyze.txt`；②`grep -n "DROP TABLE" /tmp/analyze.txt` 找到行号；③在该行上方找到 `# at NNNN` 格式的位置信息，NNNN 就是事件的 Position。也可以使用 MySQL 8.0+ 的 binlog 查询语句：`SELECT * FROM performance_schema.events_statements_history WHERE sql_text LIKE '%DROP TABLE%'`（仅在语句执行后立即查看有效，历史记录有限）。最可靠的还是解析 binlog 文件。

## 注意事项

- `--stop-position` 指定的位置是"在该位置处停止"，即不包含该位置的事件。如果误操作的 Position 是 12345，使用 `--stop-position=12345` 会在读取到 12345 之前停止，即最后执行 12345 之前的那个事务提交。确保 Position 指向事务的起始点（BEGIN），而非中间某个事件。
- 当操作涉及多个 binlog 文件时，需要将所有相关文件都传给 mysqlbinlog，让它按顺序处理。不要分多次执行 mysqlbinlog，因为每次执行都是独立的会话，中间可能有事务被截断。应该一次性传入所有文件：`mysqlbinlog --start-position=N file1 file2 file3 | mysql`。

## 总结

基于位置恢复使用 binlog 的字节偏移量（Position）精确控制重放范围，精度达到语句级别，优于时间点恢复。关键命令：`mysqlbinlog --start-position=N --stop-position=M binlog_file`。定位 Position：`SHOW BINLOG EVENTS IN 'file' FROM N LIMIT K` 或 `mysqlbinlog --verbose > file.txt` 后文本搜索。`--stop-position` 不包含该位置的事件。跳过特定操作：先 `--stop-position=误操作前`，再 `--start-position=误操作后`。多文件操作一次传入所有文件。适合同一秒多操作的精确区分和跳过特定事务的场景。
