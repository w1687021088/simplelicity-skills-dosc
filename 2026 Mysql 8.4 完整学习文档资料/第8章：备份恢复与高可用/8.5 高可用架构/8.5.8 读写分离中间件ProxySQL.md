# 读写分离中间件 ProxySQL

ProxySQL 是高性能的开源 MySQL 代理中间件，支持读写分离、连接池、查询路由、查询缓存、流量镜像等功能。应用程序连接 ProxySQL 的端口，ProxySQL 根据配置的规则将请求路由到主库（写操作）或从库（读操作）。ProxySQL 支持在线动态配置（不需要重启），并内置管理界面（通过 MySQL 协议连接），是生产环境中最常用的 MySQL 读写分离方案之一。

---

## ProxySQL 的架构

```
应用程序连接 ProxySQL 的流程：

应用程序 → ProxySQL (端口 6033) → 根据规则路由
                                    ├─ 写请求 → 主库 (3306)
                                    └─ 读请求 → 从库1/从库2 (3306)

ProxySQL 内部架构：

[前端监听端口: 6033]
    ↓
[查询处理器]
    ├─ 解析 SQL
    ├─ 匹配查询规则（query_rules）
    ├─ 决定路由到哪个 HostGroup
    └─ 从连接池获取连接
    
[主机组 HostGroup]
    ├─ HG 10：写组（主库）
    └─ HG 20：读组（从库1、从库2）

[管理端口: 6032]
    └─ 使用 MySQL 协议连接
       管理所有配置

[内部配置数据库]
    └─ 三层配置：MEMORY → RUNTIME → DISK
```

## 安装与基本配置

```bash
# 安装 ProxySQL（RHEL/CentOS）：
# cat > /etc/yum.repos.d/proxysql.repo << EOF
# [proxysql_repo]
# name=ProxySQL YUM repository
# baseurl=https://repo.proxysql.com/ProxySQL/proxysql-2.x.x/centos/\$releasever
# EOF
# yum install proxysql
# systemctl start proxysql

# 连接 ProxySQL 管理端（端口 6032，默认用户 admin/admin）：
mysql -u admin -padmin -h 127.0.0.1 -P 6032 --prompt='ProxySQL Admin> '

# 配置后端 MySQL 服务器：
INSERT INTO mysql_servers (hostgroup_id, hostname, port, weight, comment)
VALUES
    (10, '192.168.1.100', 3306, 1000, 'Master'),   -- 写组
    (20, '192.168.1.101', 3306, 1000, 'Slave1'),   -- 读组
    (20, '192.168.1.102', 3306, 500,  'Slave2');   -- 读组（权重较低）

-- 配置 MySQL 用户（应用程序连接的账号）：
INSERT INTO mysql_users (username, password, default_hostgroup, transaction_persistent)
VALUES ('app_user', 'AppPass123!', 10, 1);
-- default_hostgroup=10：默认路由到写组
-- transaction_persistent=1：同一事务内的所有请求路由到同一节点

-- 配置查询规则（读写分离的核心）：
INSERT INTO mysql_query_rules (rule_id, active, match_digest, destination_hostgroup, apply)
VALUES
    (1, 1, '^SELECT.*FOR UPDATE', 10, 1),  -- SELECT FOR UPDATE 路由到主库
    (2, 1, '^SELECT', 20, 1);              -- 普通 SELECT 路由到读组
-- match_digest：正则表达式匹配 SQL 语句
-- destination_hostgroup：路由目标主机组

-- 将配置从内存加载到运行时：
LOAD MYSQL SERVERS TO RUNTIME;
LOAD MYSQL USERS TO RUNTIME;
LOAD MYSQL QUERY RULES TO RUNTIME;

-- 将配置持久化到磁盘（重启后不丢失）：
SAVE MYSQL SERVERS TO DISK;
SAVE MYSQL USERS TO DISK;
SAVE MYSQL QUERY RULES TO DISK;
```

## 三层配置体系

```sql
-- ProxySQL 的配置分三层：

-- MEMORY 层（当前会话的修改）：
-- 所有 INSERT/UPDATE/DELETE 操作默认写到 MEMORY
INSERT INTO mysql_servers ...;  -- 写到 MEMORY

-- RUNTIME 层（当前生效的配置）：
-- LOAD ... TO RUNTIME 将 MEMORY 的修改应用到运行时
LOAD MYSQL SERVERS TO RUNTIME;
-- 立即生效，不需要重启 ProxySQL

-- DISK 层（持久化存储）：
-- SAVE ... TO DISK 将 RUNTIME 的配置写到磁盘
SAVE MYSQL SERVERS TO DISK;
-- 重启 ProxySQL 后，从 DISK 加载配置

-- 查看各层的配置：
SELECT * FROM mysql_servers;              -- 查看 MEMORY 层
SELECT * FROM runtime_mysql_servers;      -- 查看 RUNTIME 层

-- 恢复到上次保存的配置：
LOAD MYSQL SERVERS FROM DISK;  -- 从磁盘加载到 MEMORY
LOAD MYSQL SERVERS TO RUNTIME; -- 应用到运行时
```

## 高级查询路由

```sql
-- ProxySQL 支持复杂的查询路由规则

-- 按数据库路由（不同库到不同实例）：
INSERT INTO mysql_query_rules (rule_id, active, schemaname, destination_hostgroup, apply)
VALUES (3, 1, 'analytics_db', 30, 1);
-- analytics_db 的所有查询路由到 HG 30（专用分析从库）

-- 按用户路由（不同用户到不同实例）：
INSERT INTO mysql_users (username, password, default_hostgroup)
VALUES ('report_user', 'ReportPass!', 30);
-- report_user 的所有查询默认路由到 HG 30

-- 按 SQL 注释路由（应用层显式指定路由）：
INSERT INTO mysql_query_rules (rule_id, active, match_digest, destination_hostgroup, apply)
VALUES (4, 1, '/\*master\*/', 10, 1);
-- SQL 中包含 /* master */ 注释的查询路由到主库
-- 应用层可以在需要强一致读时使用：
-- SELECT /* master */ * FROM orders WHERE id=123;

-- 查询延迟统计（分析哪些查询慢）：
SELECT digest_text, count_star, sum_time/count_star avg_us
FROM stats_mysql_query_digest
ORDER BY sum_time DESC
LIMIT 10;
```

## 监控与健康检查

```sql
-- ProxySQL 内置了对后端 MySQL 的健康检查

-- 查看后端服务器状态：
SELECT hostgroup, srv_host, srv_port, status, ConnUsed, ConnFree, Latency_us
FROM stats_mysql_connection_pool;
-- status: ONLINE / SHUNNED（临时隔离）/ OFFLINE_SOFT / OFFLINE_HARD
-- Latency_us：到该服务器的延迟（微秒）

-- 配置健康检查：
UPDATE global_variables SET variable_value='3' WHERE variable_name='mysql-monitor_connect_timeout';
UPDATE global_variables SET variable_value='2000' WHERE variable_name='mysql-monitor_ping_interval';
LOAD MYSQL VARIABLES TO RUNTIME;

-- 配置 ProxySQL 监控 MySQL 复制延迟：
-- 当从库延迟超过阈值时，自动将其移出读组（SHUNNED）
UPDATE mysql_servers SET max_replication_lag=30
WHERE hostgroup_id=20;
-- max_replication_lag=30：从库延迟超过 30 秒时临时隔离

LOAD MYSQL SERVERS TO RUNTIME;
SAVE MYSQL SERVERS TO DISK;
```

## 与 Orchestrator 的集成

```bash
# ProxySQL + Orchestrator 的典型高可用方案：

# 故障转移流程：
# 1. Orchestrator 检测到主库故障
# 2. Orchestrator 提升从库为新主库
# 3. Orchestrator 执行 PostMasterFailoverProcesses 钩子
# 4. 钩子脚本调用 ProxySQL API 更新路由配置：

# 故障转移钩子脚本示例：
#!/bin/bash
NEW_MASTER=$1
OLD_MASTER=$2

# 更新 ProxySQL 的主库（写组）
mysql -u admin -padmin -h proxysql_host -P 6032 << EOF
UPDATE mysql_servers SET status='OFFLINE_SOFT'
WHERE hostname='$OLD_MASTER' AND hostgroup_id=10;
INSERT INTO mysql_servers (hostgroup_id, hostname, port)
VALUES (10, '$NEW_MASTER', 3306)
ON DUPLICATE KEY UPDATE status='ONLINE';
LOAD MYSQL SERVERS TO RUNTIME;
SAVE MYSQL SERVERS TO DISK;
EOF
```

## 适用场景

- **读写分离架构**：应用程序通过 ProxySQL 连接数据库，无需在应用代码中处理读写路由逻辑，由 ProxySQL 统一管理，简化应用层实现
- **连接池管理**：大量应用服务器（如 K8s 中的数百个 Pod）连接 MySQL 时，通过 ProxySQL 的连接池统一管理数据库连接，减少 MySQL 的连接数压力（将数百个前端连接复用到少量的后端连接）

## 常见问题

**使用 ProxySQL 后事务中有读操作被路由到从库，导致读到旧数据怎么解决？**

ProxySQL 的 `transaction_persistent=1` 参数可以保证同一事务内的所有 SQL 路由到同一个 MySQL 节点（默认是写组的主库）。确保在 `mysql_users` 表中为应用用户设置 `transaction_persistent=1`，这样事务内的 SELECT 也会路由到主库，而非从库。对于事务外的 SELECT，如果有强一致性要求，可以在 SQL 中添加 `/* master */` 注释，配合相应的路由规则强制路由到主库。

## 注意事项

- ProxySQL 本身也需要高可用部署。单节点 ProxySQL 是架构的单点。通常的做法是部署两个 ProxySQL 节点，通过 Keepalived 实现 VIP 漂移，或者直接在每台应用服务器上部署 ProxySQL（本机连接，无需网络跳转，同时也不存在单点）。
- ProxySQL 在解析和路由 SQL 时会有少量额外延迟（通常 < 1ms）。在对延迟极度敏感的场景（如 HFT 量化交易）可能不适合引入代理层。但在大多数互联网业务中，这个延迟完全可以接受。

## 总结

ProxySQL 是高性能 MySQL 代理，实现读写分离、连接池、查询路由。管理端口 6033（业务），6032（管理，MySQL 协议）。三层配置：MEMORY → `LOAD TO RUNTIME`（生效）→ `SAVE TO DISK`（持久化）。读写分离：写请求路由到 HG 10（主库），SELECT 路由到 HG 20（从库）。高级路由：按数据库、用户、SQL 注释路由。健康检查：`max_replication_lag` 超阈值自动隔离从库。与 Orchestrator 集成实现故障转移时自动更新路由。`transaction_persistent=1` 保证事务内路由一致性。需要高可用部署（Keepalived 或本机部署）。
