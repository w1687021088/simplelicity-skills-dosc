# SET ROLE 激活角色

`SET ROLE` 在当前会话中激活或停用已授予的角色。角色被 `GRANT` 给用户后，不会自动在会话中生效，需要通过 `SET ROLE` 手动激活，或者通过 `SET DEFAULT ROLE` / `activate_all_roles_on_login` 配置让其在登录时自动激活。

---

## 语法

```sql
SET ROLE
    DEFAULT                       -- 激活该用户的默认角色
  | NONE                          -- 停用所有角色
  | ALL                           -- 激活所有已授予的角色
  | ALL EXCEPT role [, role] ...  -- 激活除指定角色外的所有角色
  | role [, role] ...             -- 激活指定角色
```

---

## 基本示例

```sql
-- 假设用户 alice 已被授予 read_role 和 write_role
GRANT 'read_role', 'write_role' TO 'alice'@'%';

-- alice 登录后，查看当前激活的角色
SELECT CURRENT_ROLE();
-- 如果没有设置默认角色，结果为 NONE

-- 激活指定角色
SET ROLE 'read_role';
SELECT CURRENT_ROLE();
-- 'read_role'@'%'

-- 激活多个角色
SET ROLE 'read_role', 'write_role';
SELECT CURRENT_ROLE();
-- 'read_role'@'%','write_role'@'%'

-- 激活所有已授予的角色
SET ROLE ALL;

-- 恢复到默认角色（使用 SET DEFAULT ROLE 设置的默认值）
SET ROLE DEFAULT;

-- 停用所有角色（会话中无任何角色权限）
SET ROLE NONE;
```

## SET ROLE 与权限检查

```sql
-- 演示激活/停用角色对权限的即时影响

-- 前提：alice 被授予 write_role（含 INSERT, UPDATE 权限），但无默认角色
-- alice 登录后默认没有 INSERT 权限：
INSERT INTO myapp.orders (user_id, amount) VALUES (1, 100);
-- ERROR 1142 (42000): INSERT command denied to user 'alice'@'%' for table 'orders'

-- 激活角色后，立即拥有 INSERT 权限
SET ROLE 'write_role';
INSERT INTO myapp.orders (user_id, amount) VALUES (1, 100);
-- Query OK, 1 row affected

-- 再次停用角色
SET ROLE NONE;
INSERT INTO myapp.orders (user_id, amount) VALUES (2, 200);
-- ERROR 1142：INSERT 权限消失
```

## ALL EXCEPT 排除特定角色

```sql
-- 激活除高危角色外的所有角色（临时降权操作）
-- 假设用户有 read_role, write_role, admin_role
SET ROLE ALL EXCEPT 'admin_role';
-- 激活了 read_role 和 write_role，但 admin_role 不激活

-- 这样可以在执行一些不需要管理员权限的操作时，避免意外操作（如误删数据）
```

---

## SET ROLE DEFAULT

```sql
-- SET ROLE DEFAULT 恢复到 SET DEFAULT ROLE 配置的默认角色集合
-- 与 SET DEFAULT ROLE 的区别：
-- SET DEFAULT ROLE：持久设置（存储在 mysql.default_roles），登录时自动应用
-- SET ROLE DEFAULT：当前会话临时恢复到默认角色（不改变存储的配置）

-- 用户调整过 SET ROLE 后，想恢复默认配置：
SET ROLE ALL;           -- 临时全权
-- ...执行需要全权的操作...
SET ROLE DEFAULT;       -- 恢复到默认角色（如果默认只有 read_role，则恢复为只读）
```

## activate_all_roles_on_login 系统变量

```sql
-- 控制是否在每次登录时自动激活所有已授予的角色
SHOW VARIABLES LIKE 'activate_all_roles_on_login';
-- 默认：OFF（不自动激活）

-- 全局开启（所有用户登录后自动激活所有角色）
SET GLOBAL activate_all_roles_on_login = ON;
-- 或在 my.cnf 中：activate_all_roles_on_login=ON

-- 开启后，SET DEFAULT ROLE 的配置会被忽略（因为所有角色都自动激活）
```

## 适用场景

- **按任务切换权限**：DBA 日常只使用 read_role（只读），需要做 DDL 时切换到 admin_role
- **最小权限原则**：默认激活只读角色，只在需要写操作时临时激活 write_role
- **安全上下文切换**：在代码审查、数据分析等场景中，仅激活当前任务需要的最小权限

---

## 常见问题

**SET ROLE 的变更在会话结束后是否保留？**

不保留，`SET ROLE` 是会话级的临时变更，连接断开后恢复到 `SET DEFAULT ROLE` 配置的默认值。下次登录时激活的角色取决于 `DEFAULT ROLE` 配置和 `activate_all_roles_on_login` 设置。

---

## 注意事项

- `SET ROLE` 只能激活已被 `GRANT` 授予给当前用户的角色。如果尝试激活一个未被授予的角色，会报错：`ERROR 3530 (HY000): 'role_name'@'%' is not granted to 'user'@'%'`。
- 通过 `mandatory_roles` 全局变量设置的强制角色始终处于激活状态，无法通过 `SET ROLE NONE` 停用。

---

## 总结

`SET ROLE` 在当前会话中激活/停用角色，立即影响该会话的权限。`SET ROLE ALL` 激活所有已授角色；`SET ROLE NONE` 停用所有角色；`SET ROLE DEFAULT` 恢复到默认角色配置；`SET ROLE ALL EXCEPT role` 排除指定角色后全部激活。会话结束后恢复默认状态。`activate_all_roles_on_login = ON` 可以全局简化为登录时自动激活所有角色。
