# SET DEFAULT ROLE 默认角色

`SET DEFAULT ROLE` 为用户配置登录时自动激活的角色。设置后，用户每次登录都会自动激活指定的角色，无需手动执行 `SET ROLE`。这是角色管理中"开箱即用"体验的关键配置。

---

## 语法

```sql
SET DEFAULT ROLE
    NONE                   -- 取消默认角色（登录后无角色激活）
  | ALL                    -- 设置所有已授予的角色为默认
  | role [, role] ...      -- 设置指定角色为默认
  TO user [, user] ...;   -- 为哪些用户设置
```

---

## 基本示例

```sql
-- 假设 alice 已被授予 read_role 和 write_role
GRANT 'read_role', 'write_role' TO 'alice'@'%';

-- 设置 alice 登录时自动激活 read_role
SET DEFAULT ROLE 'read_role' TO 'alice'@'%';

-- alice 下次登录后，SELECT CURRENT_ROLE() 返回 'read_role'@'%'

-- 设置激活所有已授予的角色
SET DEFAULT ROLE ALL TO 'alice'@'%';

-- 取消默认角色（登录后需要手动 SET ROLE）
SET DEFAULT ROLE NONE TO 'alice'@'%';

-- 为多个用户设置相同的默认角色
SET DEFAULT ROLE 'app_read_role' TO 'user1'@'%', 'user2'@'%', 'user3'@'%';
```

---

## 验证默认角色配置

```sql
-- 查看用户的默认角色配置（存储在 mysql.default_roles 表）
SELECT USER, HOST, DEFAULT_ROLE_USER, DEFAULT_ROLE_HOST
FROM mysql.default_roles
WHERE USER = 'alice';

-- 模拟 alice 登录后的状态（在 alice 的会话中执行）
SELECT CURRENT_ROLE();
-- 返回 alice 的默认角色（如果已配置）

-- 查看当前会话中有效的权限（包含默认角色带来的权限）
SHOW GRANTS FOR CURRENT_USER();
SHOW GRANTS FOR CURRENT_USER() USING 'read_role';  -- 明确包含角色权限
```

## 默认角色与 SET ROLE 的关系

```sql
-- SET DEFAULT ROLE 是持久配置（存储在 mysql.default_roles）
-- SET ROLE 是会话级临时操作

-- 例如：alice 的默认角色是 read_role
SET DEFAULT ROLE 'read_role' TO 'alice'@'%';

-- alice 登录后，默认激活 read_role
-- 如果 alice 需要临时获得更多权限：
SET ROLE 'write_role';   -- 临时激活 write_role（同时保留 read_role 需重新设置）
-- 或
SET ROLE ALL;            -- 激活所有已授予的角色

-- 会话结束后，下次登录自动恢复为只有 read_role 激活
```

## CREATE USER 时设置默认角色

```sql
-- MySQL 8.0.11+ 支持在 CREATE USER 时直接指定默认角色
CREATE USER 'new_employee'@'%'
    IDENTIFIED BY 'EmpP@ss123'
    DEFAULT ROLE 'read_role', 'write_role';
-- 等价于：
-- CREATE USER 'new_employee'@'%' IDENTIFIED BY 'EmpP@ss123';
-- GRANT 'read_role', 'write_role' TO 'new_employee'@'%';
-- SET DEFAULT ROLE 'read_role', 'write_role' TO 'new_employee'@'%';
-- 注意：需要先确保角色已存在，且已授予给该用户
```

## 批量设置默认角色

```sql
-- 为所有已被授予 app_role 的用户设置默认角色
SELECT CONCAT(
    'SET DEFAULT ROLE ''app_role'' TO ''',
    TO_USER, '''@''', TO_HOST, ''';'
) AS set_default_sql
FROM mysql.role_edges
WHERE FROM_USER = 'app_role';

-- 生成后批量执行
```

## mandatory_roles 与 DEFAULT ROLE 的交互

```sql
-- mandatory_roles 配置的角色对所有用户强制激活，不需要 SET DEFAULT ROLE
SET GLOBAL mandatory_roles = 'base_read_role';
-- 所有用户登录后自动拥有 base_read_role 的权限
-- 不需要 GRANT base_read_role TO user，也不需要 SET DEFAULT ROLE

-- 当 mandatory_roles 和 DEFAULT ROLE 同时配置时：
-- 用户的默认激活角色 = mandatory_roles + DEFAULT ROLE 配置的角色
```

## 适用场景

- **应用账号**：设置 `SET DEFAULT ROLE ALL`，确保应用登录后所有角色权限立即可用
- **人工账号**：只设置日常最需要的角色为默认（如 read_role），需要更高权限时手动激活
- **批量用户初始化**：创建用户后统一执行 SET DEFAULT ROLE 配置默认角色

---

## 常见问题

**为用户设置了 DEFAULT ROLE，但用户登录后 CURRENT_ROLE() 仍然返回 NONE，怎么回事？**

可能是 `activate_all_roles_on_login` 的设置覆盖了 DEFAULT ROLE，但这不是 NONE 的原因。更常见的原因是角色没有被正式 GRANT 给用户。`SET DEFAULT ROLE` 只能设置"已经被 GRANT 给用户的角色"为默认角色，如果还没有 GRANT，设置时会报错。确认流程：先 `GRANT role TO user`，再 `SET DEFAULT ROLE role TO user`。

---

## 注意事项

- `SET DEFAULT ROLE` 对**下次登录**才生效，已建立的当前会话不受影响（当前会话需手动 `SET ROLE`）。
- 设置了 `SET DEFAULT ROLE` 的用户，如果对应角色后来被 `REVOKE` 撤销，则 `mysql.default_roles` 中的记录不会自动清理，但实际上该角色已无法激活（REVOKE 后无法激活已被撤销的角色）。

---

## 总结

`SET DEFAULT ROLE {NONE|ALL|role_list} TO user` 配置用户登录时自动激活的角色，存储在 `mysql.default_roles`，对下次登录生效。必须先 `GRANT role TO user` 再设置默认角色。`SET DEFAULT ROLE ALL` 让用户激活所有已授予的角色，适合应用账号。`activate_all_roles_on_login = ON` 是全局替代方案，对所有用户有效，但粒度较粗。
