# GRANT 角色授予用户

将角色授予用户（`GRANT role TO user`）是角色管理的核心步骤，完成后用户获得了持有该角色的资格，但角色中的权限需要被"激活"后才能在会话中实际生效。同一用户可以持有多个角色，角色也可以被授予另一个角色（形成角色嵌套）。

---

## 语法

```sql
-- 将角色授予用户
GRANT role [, role] ... TO user [, user] ...
    [WITH ADMIN OPTION];

-- WITH ADMIN OPTION：允许被授权人将该角色再授予他人（类似权限的 WITH GRANT OPTION）
```

---

## 基本示例

```sql
-- 创建角色和用户
CREATE ROLE 'read_role', 'write_role';
GRANT SELECT ON myapp.* TO 'read_role';
GRANT SELECT, INSERT, UPDATE, DELETE ON myapp.* TO 'write_role';

CREATE USER 'alice'@'%' IDENTIFIED BY 'AliceP@ss1';
CREATE USER 'bob'@'%'   IDENTIFIED BY 'BobP@ss1';

-- 将角色授予用户
GRANT 'read_role' TO 'alice'@'%';
GRANT 'write_role' TO 'bob'@'%';

-- 授予多个角色给同一用户
GRANT 'read_role', 'write_role' TO 'charlie'@'%';

-- 同时授予角色给多个用户
GRANT 'read_role' TO 'alice'@'%', 'eve'@'%', 'frank'@'localhost';
```

---

## WITH ADMIN OPTION

```sql
-- 允许用户将角色再授予其他用户
GRANT 'team_role' TO 'team_lead'@'%' WITH ADMIN OPTION;

-- team_lead 现在可以将 team_role 授予其他用户
-- （使用 team_lead 账号执行）
GRANT 'team_role' TO 'team_member1'@'%';
GRANT 'team_role' TO 'team_member2'@'%';
-- 如果没有 WITH ADMIN OPTION，以上操作会报错
```

---

## 角色授予后的激活要求

```sql
-- 将角色授予用户后，角色不会自动激活
-- 需要以下任一方式使角色权限生效：

-- 方式1：设置默认角色（用户每次登录自动激活）
SET DEFAULT ROLE 'read_role' TO 'alice'@'%';
SET DEFAULT ROLE ALL TO 'charlie'@'%';   -- 激活所有已授予的角色

-- 方式2：用户登录后手动激活（仅当前会话）
SET ROLE 'read_role';

-- 方式3：全局自动激活（所有用户、所有已授角色）
SET GLOBAL activate_all_roles_on_login = ON;

-- 验证：角色授予但未激活前
SHOW GRANTS FOR 'alice'@'%';
-- GRANT USAGE ON *.* TO `alice`@`%`
-- GRANT `read_role`@`%` TO `alice`@`%`    ← 角色已授予但未激活
-- alice 此时无法执行 SELECT（角色权限未激活）

-- 设置默认角色后
SET DEFAULT ROLE 'read_role' TO 'alice'@'%';
-- alice 下次登录后可以使用 SELECT 权限
```

## 查看角色授予关系

```sql
-- 查看某用户被授予了哪些角色
SELECT FROM_USER AS role_name, FROM_HOST, TO_USER AS user_name, TO_HOST, WITH_ADMIN_OPTION
FROM mysql.role_edges
WHERE TO_USER = 'alice';

-- 查看某角色被授予给了哪些用户
SELECT FROM_USER AS role_name, TO_USER AS user_name, TO_HOST
FROM mysql.role_edges
WHERE FROM_USER = 'read_role';

-- 查看用户的权限（包含通过角色获得的权限）
SHOW GRANTS FOR 'alice'@'%' USING 'read_role';
```

---

## 撤销角色授予

```sql
-- 从用户身上撤销角色
REVOKE 'read_role' FROM 'alice'@'%';
-- alice 不再持有 read_role，角色中的权限随之失效

-- 从多个用户撤销角色
REVOKE 'read_role' FROM 'alice'@'%', 'eve'@'%';

-- 撤销角色不会删除角色本身（角色定义和权限仍然存在）
SHOW GRANTS FOR 'read_role';  -- 角色的权限仍然存在
```

---

## 角色授予角色（嵌套）

```sql
-- 角色也可以被授予给另一个角色（权限继承）
CREATE ROLE 'base_role', 'extended_role';
GRANT SELECT ON myapp.* TO 'base_role';
GRANT INSERT, UPDATE ON myapp.* TO 'extended_role';

-- 将 base_role 的权限嵌套到 extended_role
GRANT 'base_role' TO 'extended_role';
-- extended_role 现在包含：SELECT（从 base_role）+ INSERT + UPDATE

-- 将 extended_role 授予用户
GRANT 'extended_role' TO 'alice'@'%';
SET DEFAULT ROLE 'extended_role' TO 'alice'@'%';
-- alice 激活 extended_role 后，通过嵌套拥有 SELECT + INSERT + UPDATE
```

---

## 适用场景

- **批量权限分配**：同一角色授予多个用户，权限统一管理
- **分层权限设计**：不同职能分配不同角色（read_role, write_role, admin_role）
- **临时权限**：为某用户临时 GRANT 一个角色，事后 REVOKE，不影响其他权限

---

## 常见问题

**角色 GRANT 给用户后，用户是否立即拥有角色中的权限？**

不一定。角色被 GRANT 后，用户持有角色资格，但需要"激活"才能在当前会话中使用角色权限。使用 `SET DEFAULT ROLE` 或 `activate_all_roles_on_login = ON` 可以让角色在每次登录时自动激活。

---

## 注意事项

- 将角色授予用户后，需要用户重新登录（或执行 `SET ROLE`）才能使角色权限生效于当前会话；对于已经连接的会话，已有连接不会自动感知角色变化。
- `WITH ADMIN OPTION` 与 `GRANT OPTION` 类似，存在权限扩散风险，应谨慎使用，建议仅在需要委托角色管理的场景（如部门 DBA）中授予。

---

## 总结

`GRANT role TO user` 将角色授予用户，使用户获得角色持有资格。角色授予后默认不激活，需通过 `SET DEFAULT ROLE` 或 `activate_all_roles_on_login` 使角色权限在会话中生效。可以同时授予多个角色，也可以将角色授予角色（嵌套）构建权限层级。`REVOKE role FROM user` 撤销角色授予，角色本身不受影响。
