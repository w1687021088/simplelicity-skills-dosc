# DROP ROLE 删除角色

`DROP ROLE` 语句永久删除一个或多个角色。删除角色后，所有被授予该角色的用户将自动失去通过该角色获得的权限（下次权限检查时生效）。角色本质上是一种特殊账户，`DROP ROLE` 与 `DROP USER` 在内部使用相同的机制。

---

## 语法

```sql
DROP ROLE [IF EXISTS] role [, role] ...
```

---

## 基本示例

```sql
-- 删除单个角色
DROP ROLE 'app_read_role';

-- IF EXISTS：角色不存在时不报错（只发出警告）
DROP ROLE IF EXISTS 'app_read_role';

-- 删除多个角色
DROP ROLE 'read_role', 'write_role', 'admin_role';

-- 验证角色已被删除
SELECT User FROM mysql.user WHERE User = 'app_read_role';
-- 空结果集
```

---

## 删除前的检查

```sql
-- 检查哪些用户持有该角色（删除后这些用户将失去角色权限）
SELECT TO_USER AS affected_user, TO_HOST
FROM mysql.role_edges
WHERE FROM_USER = 'app_read_role';

-- 检查是否有其他角色嵌套了该角色
SELECT FROM_USER AS parent_role
FROM mysql.role_edges
WHERE TO_USER = 'app_read_role';

-- 查看角色的权限（便于在删除前记录或迁移）
SHOW GRANTS FOR 'app_read_role';
```

---

## 删除角色对用户的影响

```sql
-- 假设 alice 持有 app_read_role（已设置为默认角色）
GRANT 'app_read_role' TO 'alice'@'%';
SET DEFAULT ROLE 'app_read_role' TO 'alice'@'%';

-- 删除角色
DROP ROLE 'app_read_role';

-- alice 下次登录时：
-- mysql.role_edges 中 alice -> app_read_role 的记录已删除
-- alice 无法再激活 app_read_role（角色不存在）
-- alice 通过该角色获得的权限（SELECT 等）自动失效
-- alice 的 mysql.default_roles 记录也会被清理（或变为无效引用）

-- alice 的当前已有连接不受立即影响，但下次权限检查时会发现角色已删除
```

---

## DROP ROLE vs REVOKE 角色

```sql
-- REVOKE 角色：从特定用户身上撤销角色授予，角色本身仍然存在
REVOKE 'app_read_role' FROM 'alice'@'%';
-- app_read_role 角色仍然存在，可以重新 GRANT 给其他用户

-- DROP ROLE：永久删除角色定义
DROP ROLE 'app_read_role';
-- 角色不再存在，所有持有该角色的用户自动失去权限

-- 操作对比：
-- 不再需要某用户有该角色权限 → REVOKE role FROM user
-- 角色整体废弃不再使用 → DROP ROLE（所有持有者一并失去权限）
```

---

## 所需权限

```sql
-- 需要 DROP ROLE 权限（或 CREATE USER 权限）
-- 拥有 CREATE USER 权限的用户可以删除任何角色
-- 拥有 DROP ROLE 权限的用户只能删除由自己创建的角色（8.0.16+ 细化规则）

SHOW GRANTS FOR CURRENT_USER();

-- 权限不足时：
-- ERROR 1396 (HY000): Operation DROP ROLE failed for 'app_read_role'@'%'
```

---

## 角色迁移（修改角色权限）

```sql
-- MySQL 没有 ALTER ROLE 语句，但可以通过 REVOKE + GRANT 修改角色权限

-- 从角色中移除某个权限
REVOKE DELETE ON myapp.* FROM 'app_write_role';

-- 向角色添加新权限
GRANT SELECT ON audit_db.* TO 'app_write_role';

-- 角色已有的授权者（用户）自动获得新权限/失去被撤销的权限
-- 不需要删除角色重建
```

---

## 适用场景

- **废弃角色**：某个角色所代表的职能不再存在时，彻底删除该角色
- **角色重构**：重新规划 RBAC 权限体系时，删除旧角色并创建新角色
- **环境清理**：测试环境重置时，删除所有测试用角色

---

## 常见问题

**删除角色后，持有该角色的用户会立即掉权吗？**

已建立的连接在会话内权限检查时会发现角色已不存在，但不会立即断开。新建立的连接无法激活已删除的角色。实际上，下一次访问受控资源时才会发现权限消失（报错 1142 权限拒绝）。

---

## 注意事项

- `DROP ROLE` 删除的是角色定义本身（相当于从 `mysql.user` 删除该角色账户，并清理 `mysql.role_edges` 和 `mysql.global_grants` 中的相关记录）。一旦删除无法恢复，需要重新 `CREATE ROLE` 并重新配置权限和授予关系。
- `DROP ROLE` 与 `DROP USER` 在 MySQL 内部使用相同的实现，两者都可以用于删除角色（角色本质上是锁定的用户账户）。但推荐使用语义更明确的 `DROP ROLE`。

---

## 总结

`DROP ROLE [IF EXISTS] role_name` 永久删除角色，所有持有该角色的用户自动失去通过该角色获得的权限。删除前建议检查受影响的用户（`mysql.role_edges`）并做好权限迁移规划。仅需要撤销特定用户的角色时，用 `REVOKE role FROM user` 而非 DROP ROLE。修改角色权限无需删除重建，用 REVOKE + GRANT 直接修改即可。
