# CREATE ROLE 创建角色

角色（Role）是 MySQL 8.0 引入的权限管理机制，本质上是一个命名的权限集合。创建角色后，可以向角色授予权限，再将角色授予多个用户，实现权限的统一管理。当权限需求变化时，只需修改角色的权限，所有持有该角色的用户自动获得变更，无需逐一修改用户权限。

---

## 语法

```sql
CREATE ROLE [IF NOT EXISTS] role [, role] ...
-- role 格式：'role_name'@'host'（host 通常省略，默认为 %）
-- 或直接写不带 host 的角色名：role_name
```

---

## 基本示例

```sql
-- 创建单个角色
CREATE ROLE 'app_read_role';
CREATE ROLE 'app_write_role';
CREATE ROLE 'app_admin_role';

-- 带主机名的角色（通常不需要，直接用角色名即可）
CREATE ROLE 'dba_role'@'%';

-- 一次创建多个角色
CREATE ROLE 'order_reader', 'order_writer', 'order_admin';

-- IF NOT EXISTS：角色已存在时不报错
CREATE ROLE IF NOT EXISTS 'report_role';
```

---

## 向角色授予权限

```sql
-- 创建角色后，为角色授予权限（与给用户授权语法相同）
-- 只读角色
GRANT SELECT ON myapp.* TO 'app_read_role';

-- 读写角色
GRANT SELECT, INSERT, UPDATE, DELETE ON myapp.* TO 'app_write_role';

-- 管理员角色（包含 DDL 权限）
GRANT SELECT, INSERT, UPDATE, DELETE,
      CREATE, DROP, ALTER, INDEX,
      CREATE VIEW, SHOW VIEW,
      CREATE ROUTINE, ALTER ROUTINE, EXECUTE,
      TRIGGER, EVENT
ON myapp.* TO 'app_admin_role';
```

---

## 将角色授予用户

```sql
-- 创建用户并授予角色
CREATE USER 'alice'@'%' IDENTIFIED BY 'AliceP@ss1';
GRANT 'app_read_role' TO 'alice'@'%';

CREATE USER 'bob'@'%' IDENTIFIED BY 'BobP@ss1';
GRANT 'app_write_role' TO 'bob'@'%';

-- 授予多个角色
GRANT 'app_read_role', 'app_write_role' TO 'charlie'@'%';

-- 设置默认角色（用户登录后自动激活）
SET DEFAULT ROLE 'app_read_role' TO 'alice'@'%';
SET DEFAULT ROLE ALL TO 'charlie'@'%';  -- 激活所有已授予的角色
```

## 查看角色

```sql
-- 查看已创建的角色（角色本质上存储在 mysql.user 表中，plugin 为空）
SELECT User AS role_name, Host
FROM mysql.user
WHERE authentication_string = '' AND password_expired = 'N' AND account_locked = 'Y';
-- 角色的特征：无密码、账户锁定（不能直接登录）

-- 查看角色拥有的权限
SHOW GRANTS FOR 'app_read_role';

-- 查看哪些用户被授予了某个角色
SELECT FROM_USER, FROM_HOST, TO_USER, TO_HOST
FROM mysql.role_edges
WHERE FROM_USER = 'app_read_role';
```

## 完整的角色管理流程

```sql
-- 第一步：规划角色结构
-- 第二步：创建角色
CREATE ROLE 'readonly_role', 'readwrite_role', 'ddl_admin_role';

-- 第三步：向角色授权
GRANT SELECT ON myapp.* TO 'readonly_role';
GRANT SELECT, INSERT, UPDATE, DELETE ON myapp.* TO 'readwrite_role';
GRANT ALL PRIVILEGES ON myapp.* TO 'ddl_admin_role';

-- 第四步：创建用户并分配角色
CREATE USER 'read_user'@'%' IDENTIFIED BY 'ReadP@ss1';
GRANT 'readonly_role' TO 'read_user'@'%';
SET DEFAULT ROLE 'readonly_role' TO 'read_user'@'%';

-- 第五步：验证
SHOW GRANTS FOR 'read_user'@'%';
```

## 适用场景

- **团队权限管理**：为不同职能（开发、测试、DBA、只读）创建角色，按职能分配
- **多应用共享角色**：多个应用实例使用同一套权限（同一个角色），权限变更时只改角色
- **最小权限实践**：创建细粒度角色（如 `order_reader`, `order_writer`），按需组合授权

---

## 常见问题

**角色和用户在 MySQL 内部有什么区别？**

从实现上看，角色和用户都存储在 `mysql.user` 表中，本质上角色是一个特殊的账户（账户被锁定、无密码）。角色不能直接用于登录，只能被授予给其他账户，激活后提供相应的权限。

---

## 注意事项

- 创建角色需要 `CREATE ROLE` 权限（或 `CREATE USER` 权限）。在 MySQL 8.0 中，`CREATE ROLE` 权限是一个独立的系统权限，可以授予只负责角色管理的账号。
- 角色名中也可以包含主机名（如 `'role'@'host'`），但通常无实际意义（角色不用于登录），建议使用不带主机名的简单角色名。

---

## 总结

`CREATE ROLE role_name` 创建一个命名的权限集合。创建后，用 `GRANT privilege ON scope TO role_name` 向角色授权，再用 `GRANT role_name TO user` 将角色分配给用户，最后用 `SET DEFAULT ROLE` 设置默认激活。角色使权限管理集中化，修改角色权限时所有持有该角色的用户自动受益，是比逐用户授权更高效的权限管理方式。
