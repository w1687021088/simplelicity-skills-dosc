# 8.4 默认认证插件 caching_sha2_password

`caching_sha2_password` 是 MySQL 8.0 引入并在 8.4 中作为唯一默认认证插件的强哈希认证机制。它使用 SHA-256 算法对密码进行哈希，并在服务器端维护一个内存缓存，对重复连接的同一用户使用缓存加速认证，兼顾了安全性和性能。

---

## 认证流程

```
客户端连接请求
     ↓
服务端发送随机盐值（nonce）
     ↓
客户端用 SHA-256 计算：hash = SHA256(SHA256(password)) XOR SHA256(nonce + SHA256(SHA256(password)))
     ↓
服务端验证：
  1. 先查内存缓存（fast_auth_cache）→ 有缓存则直接验证 → 快速认证成功
  2. 缓存未命中 → 执行完整 RSA 公钥加密交换 → 验证成功后写入缓存
     ↓
认证完成
```

## 查看和确认当前默认认证插件

```sql
-- 查看系统默认认证插件
SHOW VARIABLES LIKE 'default_authentication_plugin';
-- MySQL 8.0：default_authentication_plugin = caching_sha2_password
-- MySQL 8.4：该变量已废弃，由 authentication_policy 替代

-- 查看 authentication_policy（8.4 新变量）
SHOW VARIABLES LIKE 'authentication_policy';
-- 默认值：caching_sha2_password（只有一个因素认证）

-- 查看某用户使用的认证插件
SELECT User, Host, plugin FROM mysql.user WHERE User = 'alice';
```

## 创建使用 caching_sha2_password 的用户

```sql
-- 默认即使用 caching_sha2_password（可以省略 WITH 子句）
CREATE USER 'alice'@'%' IDENTIFIED BY 'SecureP@ss123';

-- 显式指定（效果相同）
CREATE USER 'alice'@'%'
    IDENTIFIED WITH caching_sha2_password BY 'SecureP@ss123';

-- 将已有用户切换到 caching_sha2_password
ALTER USER 'legacy_user'@'%'
    IDENTIFIED WITH caching_sha2_password BY 'NewSecureP@ss123';
```

## 与 mysql_native_password 的对比

| 对比维度 | caching_sha2_password | mysql_native_password |
|---------|----------------------|----------------------|
| 哈希算法 | SHA-256（更强）| SHA-1（已不推荐）|
| 密码缓存 | 有（内存缓存加速重复认证）| 无 |
| 安全性 | 高 | 中等（SHA-1 已被破解）|
| 首次连接 | 需要 SSL 或 RSA 公钥交换 | 无此要求 |
| 兼容性 | 需要较新驱动 | 兼容所有旧版驱动 |
| MySQL 8.4 状态 | 默认，推荐 | 默认禁用，需手动启用 |

## 客户端连接要求

```sql
-- caching_sha2_password 要求以下之一：
-- 1. SSL/TLS 加密连接（推荐）
-- 2. 使用 RSA 公钥加密交换（非 SSL 时）

-- 使用 RSA 公钥文件连接（不启用 SSL 时）：
-- mysql -u alice -p --get-server-public-key

-- 在 Java JDBC 中配置 RSA 公钥交换：
-- jdbc:mysql://host/db?allowPublicKeyRetrieval=true&useSSL=false
-- 注意：allowPublicKeyRetrieval=true 在不受信任网络中有安全风险

-- 检查服务器是否有 RSA 公钥文件
SHOW VARIABLES LIKE 'caching_sha2_password_private_key_path';
SHOW VARIABLES LIKE 'caching_sha2_password_public_key_path';
```

## 缓存机制说明

```sql
-- caching_sha2_password 维护一个内存缓存（fast_auth_cache）：
-- - 首次认证成功后，服务器将用户的认证信息写入缓存
-- - 后续连接时，直接用缓存验证，无需 RSA 密钥交换（更快）
-- - 缓存在以下情况会失效：
--   * 用户密码被修改（ALTER USER）
--   * MySQL 服务重启
--   * FLUSH PRIVILEGES（会清空缓存）

-- 缓存统计
SELECT * FROM performance_schema.global_status
WHERE VARIABLE_NAME LIKE 'Caching_sha2_password%';
-- Caching_sha2_password_rsa_public_key：RSA 公钥请求次数（= 未命中缓存次数）
```

## 适用场景

- **所有新建系统**：MySQL 8.0+ 的新项目应默认使用 caching_sha2_password
- **安全审计要求**：金融、医疗等对认证安全有严格要求的环境
- **使用新版驱动的项目**：JDBC 8.x、pymysql 1.0+、PHP mysqlnd 等已支持此插件

## 常见问题

**客户端连接报错 `Authentication plugin 'caching_sha2_password' cannot be loaded`，怎么解决？**

这是客户端驱动版本过旧导致的。解决方案按优先级：
1. 升级客户端驱动到支持 caching_sha2_password 的版本（推荐）
2. 将该账户的认证插件改为 mysql_native_password（兼容方案，但 8.4 中需先启用该插件）
3. 修改 my.cnf 恢复 mysql_native_password 作为默认插件（不推荐，降低安全性）

---

## 注意事项

- MySQL 8.4 中 `mysql_native_password` 插件默认被禁用（`--mysql-native-password=OFF`）。如果需要兼容旧应用，需要在 my.cnf 中添加 `mysql_native_password=ON` 并重启 MySQL。
- 如果应用和数据库之间没有 SSL 连接，客户端必须配置 `allowPublicKeyRetrieval=true` 或提前获取服务器 RSA 公钥文件，否则首次连接无法通过 caching_sha2_password 认证。

---

## 总结

`caching_sha2_password` 使用 SHA-256 哈希加服务端内存缓存，是 MySQL 8.4 的唯一默认认证插件（`mysql_native_password` 在 8.4 中默认禁用）。首次连接需要 SSL 或 RSA 公钥交换；缓存命中后的重复连接速度与 `mysql_native_password` 相当。旧版驱动不兼容时应升级驱动而非降级认证插件。
