# 用户锁定与解锁 ACCOUNT LOCK / UNLOCK

账户锁定（`ACCOUNT LOCK`）是 MySQL 提供的一种"软禁用"机制，被锁定的账户无法建立新连接，但账户的定义、权限记录和密码信息完整保留，随时可以解锁恢复使用。这比 `DROP USER` 更灵活，适合临时暂停账户访问权限的场景。

---

## 语法

```sql
-- 创建时直接锁定
CREATE USER 'user'@'host' IDENTIFIED BY 'password' ACCOUNT LOCK;

-- 锁定已有账户
ALTER USER 'user'@'host' ACCOUNT LOCK;

-- 解锁账户
ALTER USER 'user'@'host' ACCOUNT UNLOCK;
```

---

## 基本示例

```sql
-- 创建一个处于锁定状态的账户（如新员工账号，待配置完成后再解锁）
CREATE USER 'new_employee'@'%'
    IDENTIFIED BY 'TempP@ss123'
    ACCOUNT LOCK
    COMMENT '新员工账号，待入职手续完成后解锁';

-- 锁定离职员工账号
ALTER USER 'alice'@'%' ACCOUNT LOCK;

-- 员工重新入职，解锁账号
ALTER USER 'alice'@'%' ACCOUNT UNLOCK;

-- 查看账户锁定状态
SELECT User, Host, account_locked, password_expired
FROM mysql.user
WHERE User = 'alice';
-- account_locked: Y（已锁定）/ N（未锁定）
```

---

## 锁定后的连接尝试

```sql
-- 当被锁定的账户尝试连接时，MySQL 返回：
-- ERROR 3118 (HY000): Access denied for user 'alice'@'%'.
-- Account is locked.

-- 注意：这个错误信息明确说明账户被锁定
-- 攻击者可以通过此错误信息判断账户存在但被锁定
-- 如果安全策略要求不泄露账户状态，需要在应用层统一处理错误信息
```

## 自动锁定（连续登录失败）

```sql
-- MySQL 8.0.19+ 支持连续登录失败后自动锁定账户
-- 通过 FAILED_LOGIN_ATTEMPTS 和 PASSWORD_LOCK_TIME 配置

-- 创建有失败尝试锁定策略的账户
CREATE USER 'secure_user'@'%'
    IDENTIFIED BY 'SecureP@ss123'
    FAILED_LOGIN_ATTEMPTS 5    -- 连续5次登录失败后锁定
    PASSWORD_LOCK_TIME 2;      -- 锁定2天（或 PASSWORD_LOCK_TIME UNBOUNDED 永久锁定）

-- 修改已有账户的失败锁定策略
ALTER USER 'alice'@'%'
    FAILED_LOGIN_ATTEMPTS 3
    PASSWORD_LOCK_TIME 1;       -- 1天后自动解锁

-- 手动解除失败登录导致的临时锁定
ALTER USER 'alice'@'%' ACCOUNT UNLOCK;
-- ACCOUNT UNLOCK 同时重置失败登录计数器
```

## 批量锁定/解锁

```sql
-- 生成批量锁定所有非系统账户的脚本（如系统维护期间）
SELECT CONCAT('ALTER USER ''', User, '''@''', Host, ''' ACCOUNT LOCK;') AS lock_sql
FROM mysql.user
WHERE User NOT IN ('root', 'mysql.sys', 'mysql.infoschema', 'mysql.session')
  AND account_locked = 'N';

-- 生成批量解锁脚本（维护结束后）
SELECT CONCAT('ALTER USER ''', User, '''@''', Host, ''' ACCOUNT UNLOCK;') AS unlock_sql
FROM mysql.user
WHERE User NOT IN ('root', 'mysql.sys', 'mysql.infoschema', 'mysql.session')
  AND account_locked = 'Y';
```

## ACCOUNT LOCK 与 DROP USER 对比

| 对比维度 | ACCOUNT LOCK | DROP USER |
|---------|-------------|-----------|
| 账户定义 | 保留 | 删除 |
| 权限记录 | 保留 | 删除 |
| 密码 | 保留 | 删除 |
| 是否可逆 | 可以（ACCOUNT UNLOCK）| 不可逆 |
| 审计痕迹 | 保留完整的账户历史 | 丢失 |
| 适用情况 | 临时禁用、员工离职（需保留审计）| 彻底清理账户 |

---

## 适用场景

- **员工离职**：锁定离职员工的数据库账户（保留审计记录，而非直接删除）
- **系统维护**：维护期间锁定所有业务账户，防止期间有业务写入
- **安全事件响应**：发现异常账户活动时立即锁定，防止进一步操作
- **账户预创建**：提前创建账户但暂不启用（ACCOUNT LOCK），到达启用时间再解锁

---

## 常见问题

**锁定账户会影响其已经建立的现有连接吗？**

不会，`ACCOUNT LOCK` 只阻止新建连接，已经建立的会话不受影响，继续正常运行。如果需要立即断开已有连接，需要用 `KILL <connection_id>` 手动终止。

---

## 注意事项

- `ACCOUNT LOCK` 状态存储在 `mysql.user` 表的 `account_locked` 列中（值为 `Y` 或 `N`）。可以通过 `SELECT User, Host, account_locked FROM mysql.user` 查看所有账户的锁定状态。
- 通过 `FAILED_LOGIN_ATTEMPTS` 和 `PASSWORD_LOCK_TIME` 配置的自动锁定是一种独立的机制（`USER_ATTRIBUTES` 中记录失败次数），与手动 `ACCOUNT LOCK` 存储在不同字段，两者都通过 `ACCOUNT UNLOCK` 解除。

---

## 总结

`ACCOUNT LOCK` 禁止账户建立新连接，但保留账户定义和权限，是比 DROP USER 更安全的临时禁用方式。`ACCOUNT UNLOCK` 恢复访问。MySQL 8.0.19+ 还支持 `FAILED_LOGIN_ATTEMPTS + PASSWORD_LOCK_TIME` 自动锁定连续登录失败的账户。已有会话不受锁定影响，如需立即断开需手动 KILL 连接。
