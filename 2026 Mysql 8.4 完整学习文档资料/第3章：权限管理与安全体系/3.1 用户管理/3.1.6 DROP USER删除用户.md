# DROP USER 删除用户

`DROP USER` 语句从 MySQL 中永久删除一个或多个账户，同时自动删除该账户在各权限表中的所有权限记录。删除账户不会影响其曾经创建的数据库对象（表、存储过程等），但与该账户相关的权限授予关系会被同步清理。

---

## 语法

```sql
DROP USER [IF EXISTS] user [, user] ...
-- user 格式：'username'@'host'
```

---

## 基本示例

```sql
-- 删除单个用户
DROP USER 'alice'@'%';

-- IF EXISTS：用户不存在时不报错（只发出警告）
DROP USER IF EXISTS 'alice'@'%';

-- 删除多个用户（一条语句）
DROP USER 'alice'@'%', 'bob'@'localhost', 'charlie'@'192.168.1.%';

-- 查看剩余用户
SELECT User, Host FROM mysql.user ORDER BY User, Host;
```

---

## 删除前检查

```sql
-- 检查用户是否存在
SELECT User, Host, account_locked FROM mysql.user
WHERE User = 'alice';

-- 检查用户有哪些权限（确认删除的影响范围）
SHOW GRANTS FOR 'alice'@'%';

-- 检查用户是否有活跃连接（删除有活跃连接的用户时，已有连接不会立即断开）
SELECT ID, USER, HOST, DB, COMMAND, TIME, STATE
FROM information_schema.PROCESSLIST
WHERE USER = 'alice';

-- 如果有活跃连接，可以先 KILL 连接
KILL <connection_id>;
```

---

## DROP USER 与账户锁定的对比

```sql
-- 临时禁用账户（保留账户和权限，随时可以重新启用）
ALTER USER 'alice'@'%' ACCOUNT LOCK;
-- 之后恢复：
ALTER USER 'alice'@'%' ACCOUNT UNLOCK;

-- 永久删除账户（不可逆，权限一并删除）
DROP USER 'alice'@'%';

-- 选择建议：
-- 员工离职但账号历史数据仍需查阅 → ACCOUNT LOCK（保留审计痕迹）
-- 测试账号、临时账号彻底清理 → DROP USER
```

---

## 删除用户对数据库对象的影响

```sql
-- 删除用户不会删除该用户创建的数据库对象
-- 以 'alice'@'%' 创建了 mydb.my_procedure 存储过程为例：

DROP USER 'alice'@'%';

-- my_procedure 仍然存在
SHOW CREATE PROCEDURE mydb.my_procedure\G
-- 但 DEFINER 已经变为一个不存在的账户

-- 查询依赖已删除账户的对象
SELECT ROUTINE_SCHEMA, ROUTINE_NAME, ROUTINE_TYPE, DEFINER
FROM information_schema.ROUTINES
WHERE DEFINER = 'alice@%';

-- 视图也有同样的问题
SELECT TABLE_SCHEMA, TABLE_NAME, DEFINER
FROM information_schema.VIEWS
WHERE DEFINER = 'alice@%';
-- 这些对象需要修改 DEFINER 或重建
```

## 批量删除测试账户

```sql
-- 生成删除所有测试账户的 SQL（用户名以 test_ 开头）
SELECT CONCAT('DROP USER IF EXISTS ''', User, '''@''', Host, ''';') AS drop_sql
FROM mysql.user
WHERE User LIKE 'test_%';

-- 生成后手动确认并执行
```

## 所需权限

```sql
-- 删除用户需要 CREATE USER 权限
SHOW GRANTS FOR CURRENT_USER();

-- 没有权限时报错：
-- ERROR 1227 (42000): Access denied; you need (at least one of) the CREATE USER privilege(s)
-- for this operation
```

## 适用场景

- **账户清理**：删除测试账号、临时账号、已离职员工账号
- **安全审计**：清理长期不活跃的账户（通过 `information_schema.PROCESSLIST` 统计）
- **环境重置**：开发/测试环境初始化时删除所有非必要账户

---

## 常见问题

**删除用户后，该用户拥有的存储过程还能被其他用户调用吗？**

这取决于存储过程的 `SQL SECURITY` 设置。如果是 `SQL SECURITY DEFINER`（默认），调用时会以被删除用户的身份执行，由于用户已不存在，会报 `ERROR 1449: The user specified as a definer ('alice'@'%') does not exist`。需要修改存储过程的 DEFINER 为现存用户：`ALTER DEFINER = 'newuser'@'%' PROCEDURE mydb.my_procedure ...`（实际需要 DROP + CREATE 重建）。

---

## 注意事项

- 删除用户后，如果该用户有活跃的数据库连接，已有连接**不会立即断开**——正在执行的会话继续运行，直到会话主动断开或超时。如果需要立即断开，应先用 `KILL <connection_id>` 终止连接。
- 删除 `root` 账户时要格外谨慎，确保有其他具有 SUPER 权限的账户可以管理数据库。

---

## 总结

`DROP USER [IF EXISTS] 'user'@'host'` 永久删除账户及其所有权限记录。删除账户不影响其创建的数据库对象（存储过程、视图等），但这些对象的 DEFINER 变为无效用户，调用时会报错，需要及时处理。临时禁用推荐用 `ACCOUNT LOCK` 而非 DROP。删除有活跃连接的账户时，已有会话不会立即中断。
