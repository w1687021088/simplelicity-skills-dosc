# IDENTIFIED BY 密码设置

`IDENTIFIED BY` 子句用于在 `CREATE USER` 或 `ALTER USER` 语句中设置账户的认证密码。MySQL 会根据账户使用的认证插件对密码进行哈希处理后存储，不会以明文形式保存密码。

---

## 语法

```sql
-- 创建用户时设置密码
CREATE USER 'user'@'host' IDENTIFIED BY 'plaintext_password';

-- 修改用户密码
ALTER USER 'user'@'host' IDENTIFIED BY 'new_password';

-- 指定认证插件同时设置密码
CREATE USER 'user'@'host'
    IDENTIFIED WITH caching_sha2_password BY 'plaintext_password';

-- 直接提供哈希后的密码（AS 而非 BY）
CREATE USER 'user'@'host'
    IDENTIFIED WITH mysql_native_password AS '*哈希字符串';
```

---

## 密码哈希存储机制

```sql
-- MySQL 不以明文存储密码，BY 子句中的明文密码会被哈希后存储
CREATE USER 'alice'@'localhost' IDENTIFIED BY 'MySecret123!';

-- 查看密码存储（只能看到哈希值，看不到原始密码）
SELECT User, Host, plugin, authentication_string
FROM mysql.user WHERE User = 'alice';
-- authentication_string 列存储的是哈希字符串，不是明文密码
-- caching_sha2_password：$A$005$加密后的哈希
-- mysql_native_password：*加41位十六进制字符

-- 修改当前登录用户的密码
ALTER USER CURRENT_USER() IDENTIFIED BY 'NewSecret456!';
-- 或
ALTER USER USER() IDENTIFIED BY 'NewSecret456!';
```

---

## IDENTIFIED BY 与 IDENTIFIED WITH ... BY 的区别

```sql
-- IDENTIFIED BY：使用账户当前的认证插件（默认 caching_sha2_password）
ALTER USER 'alice'@'localhost' IDENTIFIED BY 'Password123!';

-- IDENTIFIED WITH plugin：切换认证插件，不设密码
ALTER USER 'alice'@'localhost'
    IDENTIFIED WITH caching_sha2_password;  -- 切换插件，密码清空

-- IDENTIFIED WITH plugin BY 'password'：切换插件并设置新密码
ALTER USER 'alice'@'localhost'
    IDENTIFIED WITH caching_sha2_password BY 'Password123!';

-- IDENTIFIED WITH plugin AS 'hash'：使用已知哈希值直接设置
-- 用于从其他 MySQL 实例迁移账户时（已知哈希值）
ALTER USER 'alice'@'localhost'
    IDENTIFIED WITH mysql_native_password
    AS '*2470C0C06DEE42FD1618BB99005ADCA2EC9D1E19';
```

## 密码修改的验证选项（MySQL 8.0.13+）

```sql
-- REPLACE 选项：修改密码时需要验证旧密码（防止他人在你临时离开时改密码）
ALTER USER 'alice'@'localhost'
    IDENTIFIED BY 'NewPassword456!'
    REPLACE 'OldPassword123!';  -- 必须提供当前密码才能修改

-- 普通用户修改自己的密码时，建议强制使用 REPLACE
-- DBA 修改其他用户密码不需要 REPLACE（有足够权限直接修改）
```

## 密码过期设置

```sql
-- 立即使密码过期（用户下次登录后必须修改密码）
ALTER USER 'alice'@'localhost' PASSWORD EXPIRE;

-- 设置密码过期间隔
ALTER USER 'alice'@'localhost' PASSWORD EXPIRE INTERVAL 90 DAY;

-- 密码永不过期
ALTER USER 'alice'@'localhost' PASSWORD EXPIRE NEVER;

-- 使用全局默认过期策略
ALTER USER 'alice'@'localhost' PASSWORD EXPIRE DEFAULT;

-- 查看全局默认过期天数
SHOW VARIABLES LIKE 'default_password_lifetime';
-- 0 表示永不过期（默认值）
```

## 密码的明文传输安全性

```sql
-- IDENTIFIED BY 中的密码在客户端和服务器之间传输时是明文的
-- 因此强烈建议使用 SSL/TLS 加密连接，防止网络抓包

-- 验证当前连接是否使用 SSL
SHOW STATUS LIKE 'Ssl_cipher';
-- 如果 Value 非空（如 TLS_AES_256_GCM_SHA384），说明使用了 SSL

-- 如果没有 SSL，创建用户时可以用哈希值（AS 而非 BY）避免明文传输
-- 但首先需要在安全环境中获取密码的哈希值
SELECT PASSWORD('MySecret123!');  -- 8.0+ 中此函数已废弃
```

## 适用场景

- **初始账号创建**：`CREATE USER ... IDENTIFIED BY` 设置初始密码
- **密码轮换**：`ALTER USER ... IDENTIFIED BY` 定期更新密码（配合 REPLACE 验证旧密码）
- **账号迁移**：用 `IDENTIFIED WITH ... AS` 直接导入已知哈希值，避免重置密码
- **密码过期管理**：`PASSWORD EXPIRE INTERVAL` 配合企业密码政策

## 常见问题

**密码策略（validate_password 组件）对 IDENTIFIED BY 有影响吗？**

有。如果安装了 `validate_password` 组件并启用了密码复杂度检查，`IDENTIFIED BY` 的密码必须满足长度、大小写、数字和特殊字符的要求，否则报错 `ERROR 1819 (HY000): Your password does not satisfy the current policy requirements`。

---

## 注意事项

- `IDENTIFIED BY` 中的密码是明文输入，MySQL 内部会自动哈希。在命令行输入时，密码可能出现在 shell 历史记录或审计日志中，生产环境应注意清除命令历史（`history -c`）。
- 在 MySQL 8.4 中，`caching_sha2_password` 是默认认证插件，其哈希算法（SHA-256）比 `mysql_native_password` 的 SHA-1 更安全。对安全性要求高的场景，避免使用 `mysql_native_password`。

---

## 总结

`IDENTIFIED BY 'password'` 以明文密码设置账户认证，MySQL 自动哈希存储。`IDENTIFIED WITH plugin BY 'password'` 可以同时指定认证插件。修改密码时可以加 `REPLACE 'old_password'` 验证旧密码。`PASSWORD EXPIRE INTERVAL N DAY` 配置密码过期策略。密码在网络传输中是明文，应使用 SSL/TLS 连接保护传输安全。
