# ALTER USER 修改用户

`ALTER USER` 语句修改已存在的 MySQL 账户的属性，包括密码、认证插件、资源限制、密码过期策略和账户锁定状态等。它是管理账户生命周期的核心语句。普通用户可以修改自己的密码，DBA 可以修改任何账户。

---

## 语法

```sql
ALTER USER [IF EXISTS]
    user [auth_option] [, user [auth_option]] ...
    [REQUIRE {NONE | tls_option [[AND] tls_option] ...}]
    [WITH resource_option [resource_option] ...]
    [password_option | lock_option] ...
    [COMMENT 'string' | ATTRIBUTE 'json']
```

---

## 修改密码

```sql
-- DBA 修改其他用户密码
ALTER USER 'alice'@'%' IDENTIFIED BY 'NewSecureP@ss123';

-- 用户修改自己的密码（需提供旧密码验证）
ALTER USER CURRENT_USER()
    IDENTIFIED BY 'NewP@ss456'
    REPLACE 'OldP@ss123';   -- REPLACE 子句：验证当前密码

-- 切换认证插件的同时修改密码
ALTER USER 'alice'@'%'
    IDENTIFIED WITH caching_sha2_password BY 'NewP@ss456';

-- 修改多个用户的密码（一条语句）
ALTER USER
    'alice'@'%' IDENTIFIED BY 'AliceNewPass!',
    'bob'@'localhost' IDENTIFIED BY 'BobNewPass!';
```

## 密码过期管理

```sql
-- 立即使账户密码过期（用户下次登录必须修改密码）
ALTER USER 'alice'@'%' PASSWORD EXPIRE;

-- 设置密码 90 天后过期
ALTER USER 'alice'@'%' PASSWORD EXPIRE INTERVAL 90 DAY;

-- 密码永不过期（适合服务账号）
ALTER USER 'service_account'@'localhost' PASSWORD EXPIRE NEVER;

-- 恢复使用全局默认策略
ALTER USER 'alice'@'%' PASSWORD EXPIRE DEFAULT;

-- 批量设置所有普通用户密码90天过期
SELECT CONCAT('ALTER USER ''', User, '''@''', Host, ''' PASSWORD EXPIRE INTERVAL 90 DAY;')
FROM mysql.user
WHERE User NOT IN ('root', 'mysql.sys', 'mysql.infoschema', 'mysql.session')
  AND account_locked = 'N';
```

## 资源限制修改

```sql
-- 修改连接和查询资源上限
ALTER USER 'limited_user'@'%'
    WITH
        MAX_QUERIES_PER_HOUR    2000
        MAX_UPDATES_PER_HOUR    500
        MAX_CONNECTIONS_PER_HOUR 100
        MAX_USER_CONNECTIONS    10;

-- 重置所有资源限制（设为0表示无限制）
ALTER USER 'limited_user'@'%'
    WITH
        MAX_QUERIES_PER_HOUR    0
        MAX_UPDATES_PER_HOUR    0
        MAX_CONNECTIONS_PER_HOUR 0
        MAX_USER_CONNECTIONS    0;
```

## 账户锁定与解锁

```sql
-- 锁定账户（禁止登录）
ALTER USER 'alice'@'%' ACCOUNT LOCK;

-- 解锁账户
ALTER USER 'alice'@'%' ACCOUNT UNLOCK;

-- 查看账户锁定状态
SELECT User, Host, account_locked FROM mysql.user WHERE User = 'alice';
-- account_locked: Y（已锁定）/ N（未锁定）
```

## 修改账户注释和属性

```sql
-- 修改注释
ALTER USER 'alice'@'%' COMMENT '已迁移到新项目团队';

-- 修改 JSON 属性（会替换整个属性对象）
ALTER USER 'alice'@'%'
    ATTRIBUTE '{"team": "platform", "owner": "李四", "updated": "2026-03"}';

-- 查看用户属性
SELECT User, Host, USER_ATTRIBUTES
FROM information_schema.USER_ATTRIBUTES
WHERE User = 'alice';
```

## IF EXISTS 选项

```sql
-- 不加 IF EXISTS：用户不存在时报错
ALTER USER 'nonexistent'@'%' IDENTIFIED BY 'Pass123!';
-- ERROR 1396 (HY000): Operation ALTER USER failed for 'nonexistent'@'%'

-- 加 IF EXISTS：用户不存在时只发出警告，不报错
ALTER USER IF EXISTS 'nonexistent'@'%' IDENTIFIED BY 'Pass123!';
-- Query OK, 0 rows affected, 1 warning
```

## 密码历史与重用限制

```sql
-- 禁止重用最近5次使用过的密码
ALTER USER 'alice'@'%' PASSWORD HISTORY 5;

-- 禁止重用180天内使用过的密码
ALTER USER 'alice'@'%' PASSWORD REUSE INTERVAL 180 DAY;

-- 同时设置两个限制（取更严格的那个）
ALTER USER 'alice'@'%'
    PASSWORD HISTORY 5
    PASSWORD REUSE INTERVAL 180 DAY;
```

## 适用场景

- **定期密码轮换**：强制某些账户重新设置密码（`PASSWORD EXPIRE`）
- **账户临时禁用**：维护或离职时锁定账户（`ACCOUNT LOCK`），无需删除账户
- **权限调整**：在不重建账户的情况下调整资源配额
- **安全审计**：通过注释记录账户用途和责任人

## 常见问题

**ALTER USER 修改密码后是否需要 FLUSH PRIVILEGES？**

不需要。`ALTER USER` 是标准的 SQL DDL 语句，会自动刷新权限缓存。只有直接修改 `mysql.user` 表（`UPDATE mysql.user SET ...`）后才需要 `FLUSH PRIVILEGES`。

---

## 注意事项

- `ALTER USER` 执行后，对已建立的现有连接没有影响（已登录的会话继续有效），密码修改对下次登录才生效。但账户锁定（`ACCOUNT LOCK`）对新建连接立即生效，已有连接不受影响。
- 普通用户只能修改自己的账户属性，且修改密码时必须通过 `REPLACE 'old_password'` 提供旧密码验证。修改其他用户的账户需要 `CREATE USER` 权限或 `SUPER` 权限。

---

## 总结

`ALTER USER` 是账户生命周期管理的核心语句，可以修改密码（含验证旧密码的 REPLACE）、切换认证插件、设置密码过期策略（PASSWORD EXPIRE）、调整资源限制（MAX_CONNECTIONS 等）和锁定/解锁账户（ACCOUNT LOCK/UNLOCK）。修改立即生效，无需 FLUSH PRIVILEGES，但对已有连接无影响。
