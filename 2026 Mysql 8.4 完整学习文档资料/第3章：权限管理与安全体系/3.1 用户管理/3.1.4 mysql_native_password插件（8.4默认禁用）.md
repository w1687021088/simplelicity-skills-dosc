# mysql_native_password 插件（8.4 默认禁用）

`mysql_native_password` 是 MySQL 5.x 时代的默认认证插件，使用 SHA-1 算法对密码进行双重哈希（`SHA1(SHA1(password))`）后存储。由于 SHA-1 已不被视为安全的哈希算法，MySQL 8.0 开始引入 `caching_sha2_password` 作为新默认，并在 **MySQL 8.4 中将 `mysql_native_password` 默认禁用**，需要显式配置才能使用。

---

## 8.4 中的状态变化

```sql
-- 检查 mysql_native_password 插件状态
SELECT PLUGIN_NAME, PLUGIN_STATUS
FROM information_schema.PLUGINS
WHERE PLUGIN_NAME = 'mysql_native_password';
-- MySQL 8.0：PLUGIN_STATUS = ACTIVE
-- MySQL 8.4：PLUGIN_STATUS = DISABLED（默认禁用）

-- 查看插件相关变量
SHOW VARIABLES LIKE 'mysql_native_password';
-- MySQL 8.4 中该变量值为 OFF（禁用状态）
```

## 在 8.4 中重新启用 mysql_native_password

```sql
-- 方法1：在 my.cnf（my.ini）配置文件中启用（需要重启 MySQL）
-- [mysqld]
-- mysql_native_password=ON
-- 或
-- loose-mysql-native-password=ON   （兼容写法，插件不存在时不报错）

-- 方法2：通过命令行参数启动
-- mysqld --mysql-native-password=ON

-- 启用后验证
SHOW VARIABLES LIKE 'mysql_native_password';
-- Value: ON（已启用）

SELECT PLUGIN_NAME, PLUGIN_STATUS
FROM information_schema.PLUGINS
WHERE PLUGIN_NAME = 'mysql_native_password';
-- PLUGIN_STATUS: ACTIVE
```

## 创建使用 mysql_native_password 的用户

```sql
-- 首先确保插件已启用，再创建使用该插件的用户
CREATE USER 'legacy_app'@'%'
    IDENTIFIED WITH mysql_native_password BY 'LegacyP@ss123';

-- 将现有用户切换为 mysql_native_password（兼容旧驱动）
ALTER USER 'app_user'@'%'
    IDENTIFIED WITH mysql_native_password BY 'ExistingP@ss123';

-- 查看用户使用的认证插件
SELECT User, Host, plugin FROM mysql.user WHERE User = 'legacy_app';
-- plugin: mysql_native_password
```

## 批量排查哪些用户仍在使用旧插件

```sql
-- 列出所有仍使用 mysql_native_password 的账户
SELECT User, Host, plugin
FROM mysql.user
WHERE plugin = 'mysql_native_password'
ORDER BY User, Host;

-- 批量生成迁移脚本（将旧插件用户迁移到新插件）
SELECT CONCAT(
    'ALTER USER ''', User, '''@''', Host, ''' ',
    'IDENTIFIED WITH caching_sha2_password BY ''<请手动设置新密码>'';'
) AS migration_sql
FROM mysql.user
WHERE plugin = 'mysql_native_password';
```

## mysql_native_password 存储格式

```sql
-- mysql_native_password 的密码哈希格式（41字符）
-- *后接40位十六进制字符，是 SHA1(SHA1(plaintext)) 的结果

SELECT User, Host, authentication_string
FROM mysql.user WHERE User = 'legacy_app';
-- authentication_string: *2470C0C06DEE42FD1618BB99005ADCA2EC9D1E19
-- 注：SHA-1 已被破解，已知哈希数据库可以反向查询对应的明文密码

-- caching_sha2_password 的哈希格式（更安全）
-- $A$005$加密盐值加密结果（基于 SHA-256，更长更安全）
```

## 适用场景（不得不用时）

- **遗留应用**：应用程序使用的 MySQL 驱动版本过旧（如 PHP 5.x 的 mysql/mysqli 扩展），无法升级驱动
- **某些连接工具**：部分 GUI 工具或 ETL 工具尚未更新支持 caching_sha2_password
- **短期过渡**：在驱动升级前作为临时兼容方案

---

## 常见问题

**在 MySQL 8.4 中，如果配置文件没有启用 mysql_native_password，执行 `IDENTIFIED WITH mysql_native_password` 会怎样？**

会报错：`ERROR 1524 (HY000): Plugin 'mysql_native_password' is not loaded`。必须在配置文件中添加 `mysql_native_password=ON` 并重启 MySQL 服务后，才能使用该插件。

---

## 注意事项

- SHA-1 在密码学上已被认为不安全（存在碰撞攻击），国内外安全标准（如等保 2.0）越来越多地要求禁止使用 SHA-1 进行密码哈希。在可以升级驱动的情况下，应优先迁移到 `caching_sha2_password`。
- 在主从复制环境中，如果主库有 `mysql_native_password` 账户，从库的配置也需要启用该插件，否则复制 DDL（ALTER USER）时可能在从库报错。

---

## 总结

`mysql_native_password` 使用 SHA-1 双重哈希，在 MySQL 8.4 中默认禁用。要使用需在配置文件加 `mysql_native_password=ON` 并重启。应优先升级应用层驱动以支持 `caching_sha2_password`，仅在无法升级驱动时才将 `mysql_native_password` 作为临时兼容方案。应定期排查并迁移使用旧插件的账户。
