# CREATE USER 创建用户

`CREATE USER` 语句在 MySQL 中创建新的数据库账户。每个账户由用户名和主机名组成（`'username'@'host'`），同一用户名在不同主机下是不同的账户。MySQL 8.4 中默认认证插件已从 `mysql_native_password` 改为 `caching_sha2_password`，这对创建用户时的行为有直接影响。

---

## 语法

```sql
CREATE USER [IF NOT EXISTS]
    user [auth_option] [, user [auth_option]] ...
    [REQUIRE {NONE | tls_option [[AND] tls_option] ...}]
    [WITH resource_option [resource_option] ...]
    [password_option | lock_option] ...
    [COMMENT 'comment_string' | ATTRIBUTE 'json_object']

user:
    'user_name'@'host_name'   -- 标准格式
    'user_name'               -- 等价于 'user_name'@'%'

auth_option:
    IDENTIFIED BY 'auth_string'                 -- 密码
  | IDENTIFIED WITH auth_plugin                 -- 指定插件（不设密码）
  | IDENTIFIED WITH auth_plugin BY 'auth_string' -- 指定插件和密码
```

---

## 主机名（host）的含义

```sql
-- 'user'@'localhost'：只能从本机登录（通过 Unix socket 或 127.0.0.1）
CREATE USER 'localapp'@'localhost' IDENTIFIED BY 'Passw0rd!';

-- 'user'@'%'：可以从任意主机登录（通配符）
CREATE USER 'remoteapp'@'%' IDENTIFIED BY 'Passw0rd!';

-- 'user'@'192.168.1.%'：只能从 192.168.1.0/24 网段登录
CREATE USER 'intranet_user'@'192.168.1.%' IDENTIFIED BY 'Passw0rd!';

-- 'user'@'192.168.1.100'：只能从特定 IP 登录
CREATE USER 'specific_ip'@'192.168.1.100' IDENTIFIED BY 'Passw0rd!';

-- 'user'@'app.example.com'：只能从指定域名主机登录
CREATE USER 'named_host'@'app.example.com' IDENTIFIED BY 'Passw0rd!';
```

## 基本创建示例

```sql
-- 最简单的创建（使用默认认证插件 caching_sha2_password）
CREATE USER 'alice'@'localhost' IDENTIFIED BY 'SecureP@ss1';

-- IF NOT EXISTS：用户已存在时不报错
CREATE USER IF NOT EXISTS 'bob'@'%' IDENTIFIED BY 'SecureP@ss2';

-- 明确指定认证插件
CREATE USER 'charlie'@'localhost'
    IDENTIFIED WITH caching_sha2_password BY 'SecureP@ss3';

-- 使用 mysql_native_password（兼容旧客户端，8.4 已默认禁用此插件需先启用）
CREATE USER 'legacy_app'@'%'
    IDENTIFIED WITH mysql_native_password BY 'SecureP@ss4';
```

## 资源限制（连接控制）

```sql
-- 限制用户的连接和查询资源
CREATE USER 'limited_user'@'%'
    IDENTIFIED BY 'Passw0rd!'
    WITH
        MAX_QUERIES_PER_HOUR    1000    -- 每小时最多 1000 次查询
        MAX_UPDATES_PER_HOUR    200     -- 每小时最多 200 次更新
        MAX_CONNECTIONS_PER_HOUR 50     -- 每小时最多 50 次连接
        MAX_USER_CONNECTIONS    5;      -- 同时最多 5 个并发连接
```

## 密码策略选项

```sql
-- 密码永不过期
CREATE USER 'service_account'@'localhost'
    IDENTIFIED BY 'Passw0rd!'
    PASSWORD EXPIRE NEVER;

-- 密码默认过期策略（使用全局设置）
CREATE USER 'regular_user'@'%'
    IDENTIFIED BY 'Passw0rd!'
    PASSWORD EXPIRE DEFAULT;

-- 密码 90 天后过期
CREATE USER 'staff'@'%'
    IDENTIFIED BY 'Passw0rd!'
    PASSWORD EXPIRE INTERVAL 90 DAY;
```

## 账户注释和属性（MySQL 8.0.21+）

```sql
-- 添加注释（便于管理）
CREATE USER 'app_read'@'%'
    IDENTIFIED BY 'Passw0rd!'
    COMMENT '应用层只读账号，负责查询订单数据';

-- 添加 JSON 属性（存储额外元数据）
CREATE USER 'dev_user'@'%'
    IDENTIFIED BY 'Passw0rd!'
    ATTRIBUTE '{"team": "backend", "owner": "张三", "expires": "2026-12-31"}';
```

## 验证创建结果

```sql
-- 查看已创建的用户
SELECT User, Host, plugin, account_locked, password_expired
FROM mysql.user
WHERE User IN ('alice', 'bob', 'charlie');

-- 查看用户属性
SELECT User, Host, USER_ATTRIBUTES
FROM information_schema.USER_ATTRIBUTES
WHERE User = 'dev_user';
```

## 适用场景

- **应用账号**：为每个应用或服务创建独立账号（最小权限原则），限制访问来源 IP
- **DBA 账号**：限制只能从内网 IP 登录，配置强密码策略
- **只读账号**：报表查询、BI 工具专用账号
- **服务账号**：密码永不过期的机器对机器服务账号

## 常见问题

**创建用户后为什么无法登录？**

刚创建的用户默认没有任何权限，即使能连接到 MySQL 服务器也几乎什么都做不了。需要用 `GRANT` 为其授予所需权限后，才能执行具体的数据库操作。

---

## 注意事项

- MySQL 8.4 将 `mysql_native_password` 认证插件默认禁用（在 8.0 中是默认值）。如果应用程序使用不支持 `caching_sha2_password` 的旧版 MySQL 驱动，需要在创建用户时显式指定 `IDENTIFIED WITH mysql_native_password`，并确认配置文件中已启用该插件。
- `'user'@'%'` 与 `'user'@'localhost'` 是两个不同的账户，各自有独立的密码和权限。在本机连接时，MySQL 会优先匹配更具体的主机（localhost 优先于 %）。

---

## 总结

`CREATE USER 'name'@'host' IDENTIFIED BY 'password'` 创建 MySQL 账户，账户由用户名和主机名共同标识。MySQL 8.4 默认认证插件为 `caching_sha2_password`，旧客户端需显式指定 `mysql_native_password`。创建时可配置资源限制（MAX_QUERIES_PER_HOUR 等）、密码策略（PASSWORD EXPIRE）、锁定状态（ACCOUNT LOCK）。新账户没有任何权限，需配合 GRANT 语句授权。
