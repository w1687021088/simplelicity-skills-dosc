# GRANT 列级权限

列级权限（Column-level Privilege）是 MySQL 权限体系中最细粒度的授权方式，将 SELECT、INSERT 或 UPDATE 权限精确限定到表的某几列。适用于需要隐藏敏感列（如密码、身份证号、薪资）但允许访问同一表中其他列的场景。

---

## 语法

```sql
GRANT privilege_type (col1, col2, ...)
    ON database_name.table_name
    TO 'user'@'host';
```

支持列级控制的权限类型：
- `SELECT (col1, col2, ...)`：只允许查询指定列
- `INSERT (col1, col2, ...)`：只允许插入指定列的值
- `UPDATE (col1, col2, ...)`：只允许更新指定列

---

## 基本示例

```sql
-- 只允许查询用户表的非敏感列
GRANT SELECT (id, username, department, created_at)
    ON myapp.users
    TO 'partial_read'@'%';
-- partial_read 无法查询 email、phone、salary 等敏感列

-- 只允许更新非关键字段
GRANT UPDATE (profile_bio, avatar_url, settings_json)
    ON myapp.users
    TO 'profile_editor'@'%';
-- profile_editor 不能修改 status、role、password_hash 等关键字段

-- 组合列级 SELECT 和 UPDATE
GRANT SELECT (id, product_name, stock, category_id),
      UPDATE (stock)
    ON myapp.products
    TO 'stock_manager'@'%';
-- stock_manager 只能看到指定列，且只能修改库存数量
```

---

## 列级权限的行为

```sql
-- 只有列级 SELECT 时，SELECT * 会报错
-- 必须显式指定有权限的列

-- 假设 partial_read 只有 SELECT (id, username)
SELECT id, username FROM myapp.users;       -- 合法
SELECT id, username, email FROM myapp.users; -- 报错
-- ERROR 1143 (42000): SELECT command denied to user 'partial_read'@'%'
-- for column 'email' in table 'users'

SELECT * FROM myapp.users;  -- 报错（* 包含了无权限的列）
-- 如果用户同时有表级 SELECT 权限，则 SELECT * 不受列级限制
```

---

## 查看列级权限

```sql
-- 查看列级权限
SHOW GRANTS FOR 'partial_read'@'%';
-- GRANT SELECT (id, username, department, created_at)
-- ON `myapp`.`users` TO 'partial_read'@'%'

-- 从 information_schema 查询列级权限
SELECT GRANTEE, TABLE_SCHEMA, TABLE_NAME, COLUMN_NAME, PRIVILEGE_TYPE
FROM information_schema.COLUMN_PRIVILEGES
WHERE GRANTEE = "'partial_read'@'%'"
ORDER BY TABLE_NAME, COLUMN_NAME;
```

## 列级权限与视图的对比

```sql
-- 列级权限方式：
GRANT SELECT (id, username, department) ON myapp.users TO 'hr_read'@'%';

-- 视图方式（更推荐）：
CREATE VIEW myapp.v_users_hr AS
    SELECT id, username, department FROM myapp.users;
GRANT SELECT ON myapp.v_users_hr TO 'hr_read'@'%';

-- 对比：
-- 列级权限：简单直接，但 SELECT * 不能用，需要应用层显式写列名
-- 视图方式：更灵活（可以加 WHERE 过滤行、可以计算列），应用层可以 SELECT *
-- 列级权限无法限制 WHERE 子句（只限列，不限行）
-- 视图可以同时限制行和列（WHERE + 指定列）
```

## 列级 INSERT 控制

```sql
-- 只允许插入部分列（其他列必须有默认值或允许 NULL）
GRANT INSERT (username, email, created_at)
    ON myapp.users
    TO 'registration_svc'@'%';

-- 尝试插入未授权的列：
INSERT INTO myapp.users (username, email, role, created_at)
VALUES ('alice', 'alice@example.com', 'admin', NOW());
-- ERROR 1143: INSERT command denied to user 'registration_svc'@'%'
-- for column 'role' in table 'users'

-- 只插入有权限的列：
INSERT INTO myapp.users (username, email, created_at)
VALUES ('alice', 'alice@example.com', NOW());
-- 成功，role 使用默认值
```

## 适用场景

- **隐藏薪资/评级列**：HR 系统中，基层人员只能看员工姓名和部门，不能看薪资
- **限制关键字段修改**：允许用户更新个人资料，但不允许修改状态、角色等关键字段
- **数据脱敏**：结合视图或列级权限，避免将手机号、身份证号暴露给非必要人员

---

## 常见问题

**列级 SELECT 权限能配合 WHERE 子句过滤行吗？**

列级权限只控制能访问哪些列，不控制能访问哪些行。即使只有列级 SELECT 权限，仍然可以用 WHERE 子句过滤，可以看到满足条件的所有行（只是只能看到被授权的列）。如果需要行级限制，应使用视图（在视图中加 WHERE 子句）。

---

## 注意事项

- 列级权限存储在 `mysql.columns_priv` 系统表中。在数据库迁移或 mysqldump 时，需要确保列级权限也被导出（`mysqldump --all-databases` 包含 `mysql.columns_priv`）。
- 列级权限的管理比较繁琐（每次表结构调整时，需要检查列级权限是否需要相应更新）。在实际工程中，视图方式通常比列级权限更易于长期维护。

---

## 总结

列级权限通过 `GRANT SELECT/INSERT/UPDATE (col1, col2) ON db.table TO user` 授予，是 MySQL 最细粒度的权限控制，将访问限制到具体列。有列级 SELECT 权限但无表级 SELECT 时，`SELECT *` 会报错，必须显式列举列名。与视图相比，列级权限更简单但功能有限（无法限制行）；视图更灵活（可同时控制行和列）。列级权限存储在 `mysql.columns_priv`。
