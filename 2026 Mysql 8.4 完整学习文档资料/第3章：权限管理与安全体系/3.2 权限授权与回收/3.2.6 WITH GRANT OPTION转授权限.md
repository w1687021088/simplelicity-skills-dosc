# WITH GRANT OPTION 转授权限

`WITH GRANT OPTION` 是 `GRANT` 语句的一个子句，允许被授权用户将其拥有的权限（在该级别和范围内）转授给其他用户。这实现了权限的委托管理模式，但也引入了权限扩散的风险，需要谨慎使用。

---

## 语法

```sql
GRANT privilege_type [, ...] ON scope TO 'user'@'host'
    WITH GRANT OPTION;
```

---

## 基本示例

```sql
-- 授予数据库管理权限，并允许他将这些权限转授给他人
GRANT SELECT, INSERT, UPDATE, DELETE ON myapp.*
    TO 'team_lead'@'%'
    WITH GRANT OPTION;

-- team_lead 现在可以把这些权限授予其他用户
-- （使用 team_lead 账号执行）
GRANT SELECT, INSERT ON myapp.* TO 'team_member'@'%';
-- team_lead 可以授予不超过自己权限范围的权限
-- 如果 team_lead 尝试授予 DELETE（自己有），也可以
-- 如果尝试授予 CREATE（自己没有），会报错
```

---

## GRANT OPTION 的独立性

```sql
-- GRANT OPTION 是一个独立的权限元标记，可以单独撤销
-- 撤销 GRANT OPTION 不会撤销已授予的数据权限

-- 只撤销转授权（保留数据操作权限）
REVOKE GRANT OPTION ON myapp.* FROM 'team_lead'@'%';
-- team_lead 仍然有 SELECT, INSERT, UPDATE, DELETE 权限
-- 但不能再将这些权限转授给别人

-- 查看是否有 GRANT OPTION
SHOW GRANTS FOR 'team_lead'@'%';
-- 如果有 GRANT OPTION，权限字符串末尾会显示 WITH GRANT OPTION
-- GRANT SELECT, INSERT, UPDATE, DELETE ON `myapp`.* TO 'team_lead'@'%' WITH GRANT OPTION
```

---

## 权限转授的边界

```sql
-- 规则：被授权用户只能转授"自己已有的"权限（不能超出自己的权限范围）

-- 示例：
-- root 授予 team_lead：SELECT, INSERT, UPDATE + GRANT OPTION
GRANT SELECT, INSERT, UPDATE ON myapp.* TO 'team_lead'@'%' WITH GRANT OPTION;

-- team_lead 尝试：
GRANT SELECT ON myapp.* TO 'junior'@'%';            -- 合法（自己有 SELECT）
GRANT INSERT, UPDATE ON myapp.* TO 'junior'@'%';    -- 合法（自己有 INSERT, UPDATE）
GRANT DELETE ON myapp.* TO 'junior'@'%';            -- 报错（自己没有 DELETE）
-- ERROR 1044 (42000): Access denied for user 'team_lead'@'%' to database 'myapp'

-- team_lead 转授 WITH GRANT OPTION：
GRANT SELECT ON myapp.* TO 'junior'@'%' WITH GRANT OPTION;  -- 也合法
-- junior 也可以继续转授 SELECT 给更多人（权限链传递）
```

---

## GRANT OPTION 的安全风险

```sql
-- 权限链问题：如果 A 有 GRANT OPTION，A 可以授权给 B
-- 如果 A 的权限后来被缩小，B 已有的权限不会自动减少
-- B 甚至可以将权限授权给 C，形成权限扩散链

-- 撤销问题：
-- REVOKE 只能撤销目标用户的权限，无法级联撤销其已经转授出去的权限
-- 例如：team_lead 把权限授给了 junior，
-- 撤销 team_lead 的权限后，junior 的权限依然有效

-- 查找通过 GRANT OPTION 可能形成权限链的账户
SELECT User, Host FROM mysql.user WHERE Grant_priv = 'Y';
```

---

## 收回 WITH GRANT OPTION 授权

```sql
-- 方式1：只收回转授权，保留数据权限
REVOKE GRANT OPTION ON myapp.* FROM 'team_lead'@'%';

-- 方式2：同时收回数据权限和转授权（一次性）
REVOKE ALL PRIVILEGES, GRANT OPTION ON myapp.* FROM 'team_lead'@'%';

-- 方式3：收回全局转授权
REVOKE ALL PRIVILEGES, GRANT OPTION ON *.* FROM 'super_user'@'%';
```

## 适用场景

- **部门 DBA 委托**：将某业务库的管理权委托给部门技术负责人，由其为团队成员授权
- **多租户架构**：为每个租户的管理员授予该租户数据库的权限 + GRANT OPTION，让租户自行管理其用户

---

## 常见问题

**撤销一个有 GRANT OPTION 的用户的权限后，他已经授予出去的权限会被级联撤销吗？**

不会。MySQL 的 REVOKE 不会级联撤销。如果 team_lead 已经将权限授给了 junior，撤销 team_lead 的权限不会影响 junior 已有的权限。需要手动 `REVOKE ... FROM 'junior'@'%'` 单独处理。

---

## 注意事项

- `WITH GRANT OPTION` 应该非常谨慎地授予，特别是对全局权限（`ON *.*`）。一旦某个账号有了全局权限 + GRANT OPTION，他就可以将任意全局权限授予任意账号，甚至包括创建新的 `root` 级别用户。
- 在 MySQL 8.0+ 中，角色（Role）是比 GRANT OPTION 更安全、更可控的权限委托方式。建议优先使用角色管理权限，而非通过 GRANT OPTION 链式传递权限。

---

## 总结

`WITH GRANT OPTION` 允许用户将自己已有的权限转授给他人，适用于权限委托管理场景。被授权人只能转授自己已有的权限，不能超出自己的权限范围。权限撤销不级联，已转授出去的权限需要手动单独撤销。由于存在权限扩散风险，生产环境中应优先使用角色（Role）替代 GRANT OPTION 链式授权。
