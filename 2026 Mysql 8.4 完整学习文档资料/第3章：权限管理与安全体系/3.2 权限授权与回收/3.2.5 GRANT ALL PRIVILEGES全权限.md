# GRANT ALL PRIVILEGES 全权限

`GRANT ALL PRIVILEGES` 一次性授予指定作用范围内的所有静态权限，避免逐一列举权限名称。根据 `ON` 子句的不同，它覆盖全局、数据库级或表级的所有权限。需要注意它不包含动态权限（如 `SYSTEM_VARIABLES_ADMIN`），也不包含 `GRANT OPTION`（除非显式加 `WITH GRANT OPTION`）。

---

## 语法

```sql
-- 全局全权限
GRANT ALL [PRIVILEGES] ON *.* TO 'user'@'host';

-- 数据库级全权限
GRANT ALL [PRIVILEGES] ON dbname.* TO 'user'@'host';

-- 表级全权限
GRANT ALL [PRIVILEGES] ON dbname.tablename TO 'user'@'host';
```

---

## 全局 ALL PRIVILEGES

```sql
-- 授予全局所有静态权限（DBA 账号）
GRANT ALL PRIVILEGES ON *.* TO 'dba_user'@'localhost';

-- 同时授予 GRANT OPTION（可以将自己的权限转授给他人）
GRANT ALL PRIVILEGES ON *.* TO 'super_dba'@'localhost'
    WITH GRANT OPTION;

-- 验证
SHOW GRANTS FOR 'dba_user'@'localhost';
-- GRANT ALL PRIVILEGES ON *.* TO 'dba_user'@'localhost'

-- 注意：PRIVILEGES 关键字是可选的
-- GRANT ALL ON *.* TO 'dba_user'@'%';  -- 等价写法
```

---

## 数据库级 ALL PRIVILEGES

```sql
-- 授予对指定数据库的所有权限（最常用的场景）
GRANT ALL PRIVILEGES ON myapp.* TO 'app_dba'@'%';

-- 生产环境推荐方式（限制连接来源）
GRANT ALL PRIVILEGES ON myapp.* TO 'app_dba'@'192.168.1.%';

-- 开发环境快速授权
GRANT ALL PRIVILEGES ON development.* TO 'dev_user'@'localhost';
```

---

## ALL PRIVILEGES 包含的权限范围

```sql
-- ALL PRIVILEGES ON *.* 包含的静态权限（不含动态权限）：
-- ALTER, ALTER ROUTINE, CREATE, CREATE ROLE, CREATE ROUTINE,
-- CREATE TABLESPACE, CREATE TEMPORARY TABLES, CREATE USER,
-- CREATE VIEW, DELETE, DROP, DROP ROLE, EVENT, EXECUTE, FILE,
-- INDEX, INSERT, LOCK TABLES, PROCESS, REFERENCES, RELOAD,
-- REPLICATION CLIENT, REPLICATION SLAVE, SELECT, SHOW DATABASES,
-- SHOW VIEW, SHUTDOWN, SUPER, TRIGGER, UPDATE

-- 不包含的动态权限（需要单独授予）：
-- SYSTEM_VARIABLES_ADMIN, BINLOG_ADMIN, REPLICATION_SLAVE_ADMIN,
-- GROUP_REPLICATION_ADMIN, CONNECTION_ADMIN, PERSIST_RO_VARIABLES_ADMIN,
-- INNODB_REDO_LOG_ENABLE 等

-- 查看当前用户拥有的权限（包含动态权限）
SHOW GRANTS FOR CURRENT_USER();
```

## 与逐一授权的对比

```sql
-- 逐一授权（精确控制，推荐用于生产业务账号）
GRANT SELECT, INSERT, UPDATE, DELETE,
      CREATE, DROP, ALTER, INDEX,
      CREATE VIEW, SHOW VIEW,
      CREATE ROUTINE, ALTER ROUTINE, EXECUTE,
      TRIGGER, EVENT
ON myapp.* TO 'precise_user'@'%';

-- ALL PRIVILEGES（简便，推荐用于 DBA 账号或开发环境）
GRANT ALL PRIVILEGES ON myapp.* TO 'all_user'@'%';

-- 两者的区别：
-- 逐一授权：只授予明确需要的权限，更安全（最小权限原则）
-- ALL PRIVILEGES：包含所有权限（含 SHUTDOWN, FILE 等危险权限，如果是 *.*）
-- 对于数据库级 ALL（ON dbname.*），危险权限（FILE, SHUTDOWN 等）是全局权限，不在数据库级范围内，相对安全
```

---

## 撤销 ALL PRIVILEGES

```sql
-- 撤销所有数据库级权限
REVOKE ALL PRIVILEGES ON myapp.* FROM 'app_dba'@'%';

-- 撤销全局权限
REVOKE ALL PRIVILEGES ON *.* FROM 'dba_user'@'localhost';

-- 注意：REVOKE ALL PRIVILEGES 不会撤销 GRANT OPTION
-- 需要单独撤销
REVOKE ALL PRIVILEGES, GRANT OPTION ON *.* FROM 'super_dba'@'localhost';
-- 或
REVOKE GRANT OPTION ON *.* FROM 'super_dba'@'localhost';
```

## 适用场景

- **DBA 账号**：`ALL PRIVILEGES ON *.*`（全局权限，通常限制只能从 localhost 登录）
- **局部 DBA**：`ALL PRIVILEGES ON specific_db.*`（指定数据库管理员）
- **开发环境**：为开发者快速授予开发库的全权限，省去逐一授权的麻烦
- **测试环境**：快速重建账号时，`ALL PRIVILEGES` 确保不会因为遗漏某个权限而影响测试

---

## 常见问题

**GRANT ALL ON *.* 之后为什么还是无法修改全局系统变量？**

因为 `ALL PRIVILEGES ON *.*` 只包含静态权限，不包含动态权限。修改全局变量（`SET GLOBAL`）需要 `SYSTEM_VARIABLES_ADMIN` 动态权限，必须单独授予：
```sql
GRANT SYSTEM_VARIABLES_ADMIN ON *.* TO 'dba_user'@'localhost';
```

---

## 注意事项

- 在生产环境中，对业务账号（应用程序使用的账号）应避免使用 `ALL PRIVILEGES ON *.*`，这会给予过多危险权限（FILE, SHUTDOWN, SUPER 等）。业务账号应只授予实际需要的权限。
- `REVOKE ALL PRIVILEGES ON *.* FROM user` 不会删除账户（账户的 USAGE 权限保留），账户依然存在。如果要彻底删除账户，需要使用 `DROP USER`。

---

## 总结

`GRANT ALL [PRIVILEGES] ON scope TO user` 一次性授予指定范围内的所有静态权限。全局 `ALL ON *.*` 包含所有静态权限但不含动态权限（SYSTEM_VARIABLES_ADMIN 等需单独授予）。数据库级 `ALL ON db.*` 不包含 FILE、SHUTDOWN 等全局危险权限，相对安全。`WITH GRANT OPTION` 允许被授权人转授权限。REVOKE ALL PRIVILEGES 不会撤销 GRANT OPTION，需单独 REVOKE。
