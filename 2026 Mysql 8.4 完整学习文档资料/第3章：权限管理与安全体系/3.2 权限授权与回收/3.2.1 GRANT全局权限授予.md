# GRANT 全局权限授予

全局权限（Global Privilege）使用 `GRANT privilege ON *.* TO user` 语法授予，作用于 MySQL 实例上的所有数据库和所有表。全局权限存储在 `mysql.user` 系统表中，是 MySQL 权限层级中最高的一层，影响范围最广，授予时应遵循最小权限原则。

---

## 语法

```sql
GRANT privilege_type [, privilege_type] ...
    ON *.*
    TO 'user'@'host'
    [WITH GRANT OPTION];
```

---

## 常用全局权限说明

| 权限名称 | 说明 |
|---------|------|
| ALL PRIVILEGES | 所有权限（不含 GRANT OPTION）|
| SUPER | 超级管理权限（8.0+ 细化为多个动态权限）|
| CREATE USER | 创建、修改、删除、重命名用户 |
| REPLICATION SLAVE | 允许作为主库的从库连接 |
| REPLICATION CLIENT | 查看主从状态（SHOW MASTER/SLAVE STATUS）|
| FILE | 读写服务器上的文件（LOAD DATA, SELECT INTO OUTFILE）|
| PROCESS | 查看所有用户的进程（SHOW PROCESSLIST）|
| RELOAD | FLUSH 操作（FLUSH PRIVILEGES, FLUSH LOGS 等）|
| SHUTDOWN | 关闭 MySQL 服务器 |
| SHOW DATABASES | 查看所有数据库列表 |
| SYSTEM_VARIABLES_ADMIN | 修改全局系统变量（SET GLOBAL）|
| BINLOG_ADMIN | 管理二进制日志 |

---

## 基本示例

```sql
-- 授予 DBA 全部权限（不含 GRANT OPTION）
GRANT ALL PRIVILEGES ON *.* TO 'dba_user'@'%';

-- 授予复制账号所需的最小全局权限
GRANT REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'repl'@'192.168.1.%'
    IDENTIFIED BY 'ReplP@ss123';

-- 授予监控账号查看进程和状态的权限
GRANT PROCESS, REPLICATION CLIENT, SHOW DATABASES ON *.* TO 'monitor'@'localhost';

-- 授予能修改全局变量的权限
GRANT SYSTEM_VARIABLES_ADMIN ON *.* TO 'ops_user'@'%';
```

---

## WITH GRANT OPTION

```sql
-- 授予权限的同时允许被授权人将这些权限转授给他人
GRANT SELECT, INSERT ON *.* TO 'team_lead'@'%' WITH GRANT OPTION;

-- team_lead 可以把自己有的权限授予其他用户
-- （但不能授予自己没有的权限）
```

## 查看全局权限

```sql
-- 查看某用户的全局权限
SHOW GRANTS FOR 'dba_user'@'%';

-- 从系统表查询（更详细）
SELECT User, Host,
    Select_priv, Insert_priv, Update_priv, Delete_priv,
    Create_priv, Drop_priv, Grant_priv, Super_priv
FROM mysql.user
WHERE User = 'dba_user';
```

## MySQL 8.0+ 动态权限（代替部分 SUPER）

```sql
-- 8.0+ 中 SUPER 权限被细化为多个动态权限，更精细地控制管理操作
-- 动态权限存储在 mysql.global_grants 中（而非 mysql.user）

-- 查看可用的动态权限
SELECT * FROM information_schema.USER_PRIVILEGES;

-- 常用动态权限授予
GRANT SYSTEM_VARIABLES_ADMIN ON *.* TO 'ops'@'%';    -- 修改全局变量
GRANT BINLOG_ADMIN ON *.* TO 'ops'@'%';              -- 管理 binlog
GRANT REPLICATION_SLAVE_ADMIN ON *.* TO 'repl'@'%'; -- 管理复制
GRANT INNODB_REDO_LOG_ENABLE ON *.* TO 'ops'@'%';   -- 8.4 新增：管理 redo log

-- 查看动态权限授予情况
SELECT * FROM mysql.global_grants WHERE USER = 'ops';
```

## 立即生效与 FLUSH PRIVILEGES

```sql
-- GRANT 语句直接修改内存权限缓存，立即生效，无需 FLUSH PRIVILEGES
GRANT SELECT ON *.* TO 'read_user'@'%';
-- 立即生效，read_user 下次连接后即可执行 SELECT

-- 只有直接修改 mysql.user 等权限表后才需要 FLUSH PRIVILEGES
-- UPDATE mysql.user SET Select_priv = 'Y' WHERE User = 'read_user';
-- FLUSH PRIVILEGES;  -- 这种方式不推荐
```

## 适用场景

- **DBA 账户**：授予 ALL PRIVILEGES（通常不授予 WITH GRANT OPTION 防止权限扩散）
- **复制账户**：授予 REPLICATION SLAVE（主从复制必需）
- **监控账户**：授予 PROCESS, REPLICATION CLIENT（最小权限监控）
- **运维账户**：授予特定动态权限（SYSTEM_VARIABLES_ADMIN 等）而非 SUPER

---

## 常见问题

**GRANT ALL PRIVILEGES ON *.* 和 GRANT SUPER ON *.* 有什么区别？**

`ALL PRIVILEGES` 包含所有静态权限（包括 SELECT, INSERT, CREATE 等），但不包含动态权限（如 SYSTEM_VARIABLES_ADMIN）。`SUPER` 是一个权限，在 MySQL 8.0 中已逐步被更细粒度的动态权限取代，但为了兼容性仍然存在。新系统应优先使用动态权限而非 SUPER。

---

## 注意事项

- 全局权限是最高级别权限，授予时应格外谨慎。实际业务账号通常不需要全局权限，应使用数据库级或表级权限。
- `FILE` 全局权限允许读写服务器文件系统上的文件，存在严重安全风险，应只在必要时授予受信任的账号，且必须确保 `secure_file_priv` 参数限制了可读写的目录。

---

## 总结

全局权限通过 `GRANT privilege ON *.* TO user` 授予，作用于所有数据库。常见的全局权限包括 ALL PRIVILEGES（全部静态权限）、REPLICATION SLAVE（复制账号）、PROCESS（监控账号）等。MySQL 8.0+ 将 SUPER 细化为动态权限，应优先使用动态权限做精细控制。GRANT 语句立即生效，无需 FLUSH PRIVILEGES。
