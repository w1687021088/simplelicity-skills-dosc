# GRANT 数据库级权限

数据库级权限（Database-level Privilege）使用 `GRANT privilege ON dbname.* TO user` 语法授予，作用于指定数据库内的所有对象（表、视图、存储过程等）。这是业务账号中最常用的权限级别，既能给予足够的操作空间，又将影响范围限制在特定数据库内。

---

## 语法

```sql
GRANT privilege_type [, privilege_type] ...
    ON database_name.*
    TO 'user'@'host';
```

---

## 常用数据库级权限

| 权限名称 | 说明 |
|---------|------|
| SELECT | 查询表和视图 |
| INSERT | 向表中插入数据 |
| UPDATE | 更新表中的数据 |
| DELETE | 删除表中的数据 |
| CREATE | 创建表和索引 |
| DROP | 删除表、视图、索引等 |
| ALTER | 修改表结构（ALTER TABLE）|
| INDEX | 创建和删除索引 |
| CREATE VIEW | 创建视图 |
| SHOW VIEW | 查看视图定义（SHOW CREATE VIEW）|
| CREATE ROUTINE | 创建存储过程和函数 |
| ALTER ROUTINE | 修改和删除存储过程和函数 |
| EXECUTE | 执行存储过程和函数 |
| TRIGGER | 创建和删除触发器 |
| EVENT | 创建和管理事件 |
| REFERENCES | 创建外键引用 |
| LOCK TABLES | 对有 SELECT 权限的表执行 LOCK TABLES |

---

## 基本示例

```sql
-- 授予应用程序账号对指定数据库的读写权限
GRANT SELECT, INSERT, UPDATE, DELETE ON myapp.* TO 'app_user'@'%';

-- 授予开发账号完整的数据库操作权限
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, ALTER, INDEX,
      CREATE VIEW, SHOW VIEW, CREATE ROUTINE, ALTER ROUTINE, EXECUTE,
      TRIGGER, EVENT
ON development_db.* TO 'dev_team'@'192.168.1.%';

-- 授予只读账号（报表查询）
GRANT SELECT ON reporting_db.* TO 'report_user'@'%';

-- 授予存储过程执行权限（不允许查询底层表）
GRANT EXECUTE ON myapp.* TO 'proc_runner'@'localhost';
```

## 多数据库授权

```sql
-- 同一语句无法对多个数据库授权，需要多条语句
GRANT SELECT, INSERT, UPDATE ON db1.* TO 'multi_db_user'@'%';
GRANT SELECT ON db2.* TO 'multi_db_user'@'%';
GRANT SELECT ON db3.* TO 'multi_db_user'@'%';

-- 使用通配符（% 匹配任意字符，_ 匹配单个字符）
-- 注意：数据库名中的通配符会匹配所有符合模式的数据库名
GRANT SELECT ON `app\_%`.* TO 'multi_app_user'@'%';
-- 授予所有以 app_ 开头的数据库的 SELECT 权限（\ 转义 _ 让其作为字面量匹配）
```

## 查看数据库级权限

```sql
-- 查看某用户的权限（包含各级别）
SHOW GRANTS FOR 'app_user'@'%';
-- 输出示例：
-- GRANT USAGE ON *.* TO 'app_user'@'%'
-- GRANT SELECT, INSERT, UPDATE, DELETE ON 'myapp'.* TO 'app_user'@'%'

-- 从 information_schema 查询数据库级权限
SELECT GRANTEE, TABLE_CATALOG, TABLE_SCHEMA, PRIVILEGE_TYPE, IS_GRANTABLE
FROM information_schema.SCHEMA_PRIVILEGES
WHERE GRANTEE = "'app_user'@'%'";
```

## 数据库级权限与全局权限的叠加

```sql
-- 权限的有效集合是全局权限 + 数据库级权限 + 表级权限 + 列级权限的并集
-- 例如：全局有 SELECT，数据库级有 INSERT，则对该数据库有 SELECT + INSERT

-- 全局只读账号，对特定数据库有读写权
GRANT SELECT ON *.* TO 'mostly_read'@'%';          -- 全局只读
GRANT INSERT, UPDATE ON operational_db.* TO 'mostly_read'@'%';  -- 特定库读写
-- mostly_read 对 operational_db 有 SELECT + INSERT + UPDATE
-- 对其他数据库只有 SELECT
```

## 适用场景

- **业务应用账号**：授予 SELECT, INSERT, UPDATE, DELETE，限制在业务数据库内
- **数据库管理员（局部 DBA）**：授予某数据库的完整权限，但不影响其他数据库
- **只读报表账号**：只授予 SELECT，对数据库内所有表只读
- **存储过程服务账号**：只授予 EXECUTE，通过存储过程操作数据，不直接访问表

---

## 常见问题

**授予数据库级权限后，新建的表也会自动继承这些权限吗？**

是的，数据库级权限是对该数据库下所有当前和未来对象生效的，之后在该数据库内新建的表不需要单独授权，账号自动对其有相应的权限。

---

## 注意事项

- 数据库级权限中的 `DROP` 权限允许删除该数据库内的任意表，是一个破坏性权限，对普通业务账号应谨慎授予。`ALTER` 权限可以修改表结构（包括删除列），同样需要谨慎。
- 数据库名在 `GRANT` 语句中默认区分大小写（取决于 `lower_case_table_names` 设置）。在不区分大小写的系统上，`myapp.*` 和 `MyApp.*` 会被当成同一个数据库；在区分大小写的系统上，它们是不同的授权记录。

---

## 总结

数据库级权限通过 `GRANT privilege ON dbname.* TO user` 授予，是业务账号最常用的权限粒度。常用权限：SELECT/INSERT/UPDATE/DELETE（DML）、CREATE/DROP/ALTER（DDL）、EXECUTE（存储过程）。权限对该数据库内现有和未来的所有对象有效。多数据库授权需要多条 GRANT 语句；数据库名支持通配符（但需谨慎使用）。
