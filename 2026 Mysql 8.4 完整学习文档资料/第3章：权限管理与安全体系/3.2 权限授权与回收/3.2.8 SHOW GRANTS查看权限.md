# SHOW GRANTS 查看权限

`SHOW GRANTS` 语句显示指定账户或角色拥有的所有权限，以可执行的 `GRANT` 语句形式输出。配合 `information_schema` 中的权限视图，可以对权限进行更复杂的查询和审计。

---

## 语法

```sql
-- 查看指定用户的权限
SHOW GRANTS FOR 'user'@'host';

-- 查看当前登录用户的权限
SHOW GRANTS;
SHOW GRANTS FOR CURRENT_USER();
SHOW GRANTS FOR USER();

-- 查看用户通过某个角色获得的有效权限（MySQL 8.0+）
SHOW GRANTS FOR 'user'@'host' USING 'role_name';
```

---

## 基本示例

```sql
-- 查看某用户的权限
SHOW GRANTS FOR 'app_user'@'%';
-- 输出示例：
-- +--------------------------------------------------------------+
-- | Grants for app_user@%                                       |
-- +--------------------------------------------------------------+
-- | GRANT USAGE ON *.* TO `app_user`@`%`                       |
-- | GRANT SELECT, INSERT, UPDATE, DELETE ON `myapp`.* TO ...   |
-- +--------------------------------------------------------------+

-- USAGE 是一个"基础占位权限"，表示账户存在但没有全局权限
-- 所有账户都有 USAGE，它本身不代表任何操作权限

-- 查看角色的权限
SHOW GRANTS FOR 'app_developer_role';
```

---

## 理解输出中的权限层级

```sql
-- 示例账号有多个层级的权限
SHOW GRANTS FOR 'mixed_user'@'%';
-- 全局权限（ON *.*）：
-- GRANT PROCESS, SHOW DATABASES ON *.* TO 'mixed_user'@'%'
-- 数据库级权限（ON db.*）：
-- GRANT SELECT, INSERT, UPDATE, DELETE ON `myapp`.* TO 'mixed_user'@'%'
-- 表级权限（ON db.table）：
-- GRANT SELECT ON `finance_db`.`exchange_rates` TO 'mixed_user'@'%'
-- 角色授予：
-- GRANT `read_role`@`%` TO `mixed_user`@`%`
```

## 使用 information_schema 查询权限

```sql
-- 查询全局权限（来自 mysql.user 表）
SELECT GRANTEE, PRIVILEGE_TYPE, IS_GRANTABLE
FROM information_schema.USER_PRIVILEGES
WHERE GRANTEE = "'app_user'@'%'";

-- 查询数据库级权限（来自 mysql.db 表）
SELECT GRANTEE, TABLE_SCHEMA, PRIVILEGE_TYPE, IS_GRANTABLE
FROM information_schema.SCHEMA_PRIVILEGES
WHERE GRANTEE = "'app_user'@'%'";

-- 查询表级权限（来自 mysql.tables_priv 表）
SELECT GRANTEE, TABLE_SCHEMA, TABLE_NAME, PRIVILEGE_TYPE
FROM information_schema.TABLE_PRIVILEGES
WHERE GRANTEE = "'app_user'@'%'";

-- 查询列级权限（来自 mysql.columns_priv 表）
SELECT GRANTEE, TABLE_SCHEMA, TABLE_NAME, COLUMN_NAME, PRIVILEGE_TYPE
FROM information_schema.COLUMN_PRIVILEGES
WHERE GRANTEE = "'app_user'@'%'";
```

## 权限审计查询

```sql
-- 审计：找出拥有 SUPER 或高危权限的账户
SELECT User, Host
FROM mysql.user
WHERE Super_priv = 'Y' OR Grant_priv = 'Y' OR File_priv = 'Y' OR Shutdown_priv = 'Y';

-- 审计：找出对敏感数据库有访问权限的账户
SELECT DISTINCT GRANTEE, TABLE_SCHEMA
FROM information_schema.SCHEMA_PRIVILEGES
WHERE TABLE_SCHEMA IN ('finance_db', 'hr_db', 'payment_db')
ORDER BY TABLE_SCHEMA, GRANTEE;

-- 审计：找出有转授权限（GRANT OPTION）的账户
SELECT User, Host
FROM mysql.user
WHERE Grant_priv = 'Y'
UNION
SELECT GRANTEE, '' AS Host
FROM information_schema.SCHEMA_PRIVILEGES
WHERE IS_GRANTABLE = 'YES';

-- 审计：查看动态权限授予情况
SELECT USER, HOST, PRIV, WITH_GRANT_OPTION
FROM mysql.global_grants
ORDER BY USER, HOST, PRIV;
```

## 查看通过角色获得的有效权限

```sql
-- 查看用户激活了某角色后的有效权限
SHOW GRANTS FOR 'alice'@'%' USING 'read_role', 'write_role';
-- 输出包含 alice 自身的权限 + read_role 的权限 + write_role 的权限

-- 查看当前会话中激活的角色
SELECT CURRENT_ROLE();

-- 查看当前会话的所有有效权限（包含激活的角色权限）
SHOW GRANTS FOR CURRENT_USER() USING <current_roles>;
```

## 适用场景

- **权限审计**：定期检查账户权限是否符合最小权限原则
- **安全检查**：排查拥有高危权限（SUPER、FILE、GRANT OPTION）的账户
- **账户交接**：了解账户的完整权限配置，便于迁移或重建
- **问题排查**：应用连接报权限错误时，用 SHOW GRANTS 验证实际权限

---

## 常见问题

**SHOW GRANTS 输出的权限与实际有效权限一致吗？**

基本一致，但有一个细节：如果用户有角色但当前会话没有激活该角色（没有设置默认角色或执行 SET ROLE），角色中的权限不会在 SHOW GRANTS 的基础输出中体现。使用 `SHOW GRANTS FOR user USING role` 才能看到包含角色权限的完整有效权限。

---

## 注意事项

- 普通用户只能执行 `SHOW GRANTS FOR CURRENT_USER()`（查看自己的权限）。查看其他用户的权限需要 `SELECT` 权限访问 `mysql` 系统数据库，或拥有 `CREATE USER` / `SUPER` 权限。
- `SHOW GRANTS` 的输出是可执行的 GRANT 语句，可以直接用于在其他 MySQL 实例上重建相同的权限配置。这也是 mysqldump 生成用户权限脚本时使用的格式。

---

## 总结

`SHOW GRANTS FOR 'user'@'host'` 显示账户所有权限（以可执行 GRANT 语句的形式），包含全局、数据库、表、列各级权限及角色授予。`information_schema.USER_PRIVILEGES` / `SCHEMA_PRIVILEGES` / `TABLE_PRIVILEGES` / `COLUMN_PRIVILEGES` 提供结构化的权限数据，适合权限审计查询。`SHOW GRANTS FOR user USING role` 显示包含角色权限的完整有效权限。
