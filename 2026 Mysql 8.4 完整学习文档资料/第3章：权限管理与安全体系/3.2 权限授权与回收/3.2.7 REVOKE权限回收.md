# REVOKE 权限回收

`REVOKE` 语句从用户账号中撤销已授予的权限。撤销后，权限在下一次新建连接时生效；已建立的会话中，撤销的权限对正在执行的操作不立即中断，但下次权限检查时会发现权限已被撤销。

---

## 语法

```sql
-- 撤销特定权限
REVOKE privilege_type [, ...] ON scope FROM 'user'@'host' [, ...];

-- 撤销所有权限和转授权
REVOKE ALL [PRIVILEGES], GRANT OPTION FROM 'user'@'host' [, ...];

-- 撤销角色
REVOKE role [, role] ... FROM 'user'@'host' [, ...];
```

---

## 基本示例

```sql
-- 撤销数据库级权限
REVOKE DELETE ON myapp.* FROM 'app_user'@'%';

-- 撤销全局权限
REVOKE SHUTDOWN ON *.* FROM 'dba_user'@'%';

-- 撤销表级权限
REVOKE INSERT ON myapp.orders FROM 'limited_user'@'%';

-- 同时撤销多个权限
REVOKE INSERT, UPDATE, DELETE ON myapp.* FROM 'read_only_user'@'%';

-- 撤销多个用户的权限（一条语句）
REVOKE SELECT ON myapp.* FROM 'user1'@'%', 'user2'@'localhost';
```

---

## 撤销所有权限

```sql
-- 撤销用户的所有权限（但不删除账户）
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'dismissed_employee'@'%';

-- 验证：撤销后只剩 USAGE（无任何权限）
SHOW GRANTS FOR 'dismissed_employee'@'%';
-- GRANT USAGE ON *.* TO 'dismissed_employee'@'%'
-- （USAGE 是一个特殊"权限"，表示账户存在但无任何操作权限）

-- 撤销 ALL PRIVILEGES 之后，账户依然存在（只是没有任何权限了）
-- 如果想彻底删除，还需要 DROP USER
DROP USER 'dismissed_employee'@'%';
```

---

## 撤销列级权限

```sql
-- 撤销列级 SELECT 权限中的特定列
REVOKE SELECT (salary, ssn) ON myapp.employees FROM 'hr_read'@'%';

-- 查看撤销后剩余的列级权限
SELECT TABLE_NAME, COLUMN_NAME, PRIVILEGE_TYPE
FROM information_schema.COLUMN_PRIVILEGES
WHERE GRANTEE = "'hr_read'@'%'";
```

## 权限撤销后的实时影响

```sql
-- 当前 app_user 有 SELECT, INSERT 权限，并且有一个活跃连接
-- 撤销 INSERT 权限
REVOKE INSERT ON myapp.* FROM 'app_user'@'%';

-- 对于已建立的连接（已在 session 内的）：
-- 正在执行的 INSERT 语句继续执行（不中断当前操作）
-- 下一次执行 INSERT 时，MySQL 检查权限，发现已撤销，报错
-- ERROR 1142 (42000): INSERT command denied to user 'app_user'@'%' for table 'orders'

-- 对于新建立的连接：
-- 权限缓存已更新，连接后立即发现没有 INSERT 权限

-- 如果需要立即断开已有连接：
SELECT ID FROM information_schema.PROCESSLIST WHERE USER = 'app_user';
KILL <connection_id>;
```

---

## 检查撤销前的权限状态

```sql
-- 先查看当前权限
SHOW GRANTS FOR 'app_user'@'%';
-- GRANT SELECT, INSERT, UPDATE, DELETE ON `myapp`.* TO 'app_user'@'%'

-- 执行撤销
REVOKE UPDATE, DELETE ON myapp.* FROM 'app_user'@'%';

-- 验证撤销结果
SHOW GRANTS FOR 'app_user'@'%';
-- GRANT SELECT, INSERT ON `myapp`.* TO 'app_user'@'%'
```

## REVOKE 与 FLUSH PRIVILEGES

```sql
-- 与 GRANT 一样，REVOKE 直接更新内存权限缓存，无需 FLUSH PRIVILEGES
REVOKE SELECT ON myapp.* FROM 'app_user'@'%';
-- 立即生效，不需要执行 FLUSH PRIVILEGES

-- 只有直接修改 mysql.db 等权限表后才需要 FLUSH PRIVILEGES（不推荐直接修改权限表）
```

---

## 动态权限的撤销

```sql
-- 动态权限也可以用 REVOKE 撤销
REVOKE SYSTEM_VARIABLES_ADMIN ON *.* FROM 'ops_user'@'%';
REVOKE BINLOG_ADMIN ON *.* FROM 'ops_user'@'%';

-- 动态权限存储在 mysql.global_grants，REVOKE 后记录被删除
SELECT * FROM mysql.global_grants WHERE USER = 'ops_user';
```

## 适用场景

- **权限缩减**：应用需求变化后，收回不再需要的权限（遵循最小权限原则）
- **人员变动**：员工调岗或离职时，撤销不再需要的数据库访问权限
- **安全响应**：发现账号异常操作时，立即撤销相关权限
- **权限清理**：定期审计和清理过时的授权

---

## 常见问题

**REVOKE 能级联撤销通过 GRANT OPTION 转授出去的权限吗？**

不能。REVOKE 只影响指定的目标用户，不会级联撤销该用户已经转授给他人的权限。例如撤销 team_lead 的权限后，team_lead 已授予 junior 的权限仍然有效，需要单独 REVOKE。

---

## 注意事项

- `REVOKE` 只能由具有 `CREATE USER` 权限或 `SUPER` 权限的用户执行，或者具有该权限并有 `GRANT OPTION` 的用户执行（只能撤销自己授予出去的权限）。
- 如果 REVOKE 的权限在目标用户身上不存在，MySQL 会报警告而非错误（在严格模式下会报错），执行结果是 0 rows affected。

---

## 总结

`REVOKE privilege ON scope FROM user` 撤销指定权限，立即更新权限缓存（无需 FLUSH PRIVILEGES）。对已有连接不立即中断，但下次权限检查时生效。`REVOKE ALL PRIVILEGES, GRANT OPTION FROM user` 撤销所有权限但不删除账户。撤销不级联——已通过 GRANT OPTION 转授给他人的权限，需要单独 REVOKE。
