# REQUIRE SSL 强制 SSL

`REQUIRE SSL` 是账户级别的 TLS 连接强制要求，设置后该账户只能通过 SSL/TLS 加密连接访问 MySQL，使用未加密连接时将被拒绝。MySQL 8.4 默认会生成 SSL 证书和密钥文件，服务端 SSL 支持默认开启，但账户是否强制使用 SSL 取决于账户配置。

---

## SSL/TLS 在 MySQL 中的工作方式

```
客户端发起连接
    ↓
MySQL 检查是否使用 TLS（ssl_cipher 非空）
    ↓
检查账户的 REQUIRE 子句
    ↓
REQUIRE NONE（默认）：允许 SSL 和非 SSL 连接
REQUIRE SSL：只允许 SSL 连接（任何有效的 SSL 连接）
REQUIRE X509：只允许有客户端证书的 SSL 连接
REQUIRE CIPHER/ISSUER/SUBJECT：更精细的 SSL 要求
```

## 服务端 SSL 状态确认

```sql
-- 确认服务端 SSL 已启用
SHOW VARIABLES LIKE 'have_ssl';
-- have_ssl: YES（SSL 可用）/ NO（未编译 SSL 支持）/ DISABLED（禁用）

-- 查看 SSL 相关文件路径
SHOW VARIABLES LIKE '%ssl%';
-- ssl_ca, ssl_cert, ssl_key: 服务端证书路径
-- ssl_cipher: 允许的加密算法列表

-- 查看当前连接的 SSL 状态
SHOW STATUS LIKE 'Ssl_cipher';
-- 非空值（如 TLS_AES_256_GCM_SHA384）= 使用了 SSL
-- 空值 = 未使用 SSL
```

## 为账户设置 REQUIRE SSL

```sql
-- 创建用户时强制 SSL
CREATE USER 'secure_user'@'%'
    IDENTIFIED BY 'SecureP@ss1'
    REQUIRE SSL;

-- 修改已有账户为强制 SSL
ALTER USER 'existing_user'@'%' REQUIRE SSL;

-- 取消 SSL 要求（恢复允许非 SSL 连接）
ALTER USER 'secure_user'@'%' REQUIRE NONE;

-- 验证账户 SSL 要求
SELECT User, Host, ssl_type, ssl_cipher, x509_issuer, x509_subject
FROM mysql.user
WHERE User = 'secure_user';
-- ssl_type: SSL（已设置 REQUIRE SSL）/ ''（未设置）
```

## REQUIRE SSL 连接验证

```sql
-- 使用非 SSL 连接（被 REQUIRE SSL 账户拒绝）
-- mysql -u secure_user -p --ssl-mode=DISABLED
-- ERROR 1045 (28000): Access denied for user 'secure_user'@'localhost'
-- (using password: YES)
-- 注意：错误信息是 "Access denied"，不直接说明是 SSL 问题

-- 使用 SSL 连接（成功）
-- mysql -u secure_user -p --ssl-mode=REQUIRED
-- 或
-- mysql -u secure_user -p  （默认尝试 SSL）

-- 连接后确认 SSL 状态
SHOW STATUS LIKE 'Ssl_cipher';
-- TLS_AES_256_GCM_SHA384（确认使用了 SSL）
```

## 全局强制所有连接使用 SSL

```sql
-- 方法1：修改 my.cnf 配置，全局要求 SSL
-- [mysqld]
-- require_secure_transport = ON

-- 方法2：动态设置（MySQL 8.0+）
SET GLOBAL require_secure_transport = ON;
SET PERSIST require_secure_transport = ON;  -- 持久化

-- 开启后，所有客户端连接必须使用 SSL（包括 localhost 通过 socket 的连接）
-- 注意：Unix socket 连接默认被视为安全传输，不会被 require_secure_transport 阻断
-- 但 TCP 连接（包括 127.0.0.1）必须使用 SSL

-- 查看当前设置
SHOW VARIABLES LIKE 'require_secure_transport';
```

## MySQL 8.4 自动生成的 SSL 证书

```sql
-- MySQL 8.0+ 在首次启动时（或执行 mysql_ssl_rsa_setup）自动生成 SSL 证书
-- 生成的文件位于 MySQL 数据目录（datadir）：

-- 查看数据目录
SHOW VARIABLES LIKE 'datadir';

-- 默认生成的证书文件：
-- ca.pem          - CA 证书（根证书）
-- ca-key.pem      - CA 私钥（保密！）
-- server-cert.pem - 服务器证书（公钥）
-- server-key.pem  - 服务器私钥（保密！）
-- client-cert.pem - 客户端证书（用于 X509 认证）
-- client-key.pem  - 客户端私钥（保密！）

-- 查看 SSL 文件路径变量
SHOW VARIABLES LIKE 'ssl_%';
```

## 适用场景

- **数据传输加密**：网络中有明文传输风险（如公共网络、跨数据中心）时，强制 SSL 防止数据被截获
- **密码传输保护**：`IDENTIFIED BY` 的密码在非 SSL 连接中以明文传输，`caching_sha2_password` 的 RSA 加密可以缓解，但 SSL 更彻底
- **合规要求**：GDPR、等保 2.0 等要求数据库连接加密传输

## 常见问题

**已设置 REQUIRE SSL 的账户从 localhost 连接是否需要 SSL？**

取决于连接方式。通过 Unix socket（`mysql -u user`，不指定 `-h`）的连接不经过 TCP 栈，不受 SSL 要求影响，可以连接成功。但通过 TCP 连接（`mysql -h 127.0.0.1`）则必须使用 SSL。这是一个常见的混淆点。

---

## 注意事项

- MySQL 8.4 自动生成的 SSL 证书使用的是自签名证书（Self-Signed），客户端通常需要使用 `--ssl-mode=REQUIRED`（验证加密但不验证证书有效性）而非 `--ssl-mode=VERIFY_CA`（需要验证 CA 证书是否受信任）。在生产环境中，推荐使用由受信任 CA 签发的证书。
- `REQUIRE SSL` 只验证连接是否使用了 SSL，不验证客户端证书。如果需要双向认证（验证客户端身份），应使用 `REQUIRE X509`。

---

## 总结

`REQUIRE SSL` 要求账户只能通过 SSL/TLS 加密连接访问 MySQL，非 SSL 连接将被拒绝（报 Access Denied）。设置方式：`CREATE/ALTER USER ... REQUIRE SSL`，取消：`REQUIRE NONE`。`require_secure_transport = ON` 可以全局强制所有 TCP 连接使用 SSL。MySQL 8.4 自动生成自签名 SSL 证书，服务端 SSL 默认已启用。
