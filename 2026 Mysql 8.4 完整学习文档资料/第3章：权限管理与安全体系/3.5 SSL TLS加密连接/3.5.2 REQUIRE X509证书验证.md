# REQUIRE X509 证书验证

`REQUIRE X509` 在 `REQUIRE SSL` 的基础上进一步要求客户端在连接时提供有效的 X.509 客户端证书，并且该证书必须由服务端信任的 CA（证书颁发机构）签发。这实现了双向 TLS 认证（Mutual TLS），既验证服务端身份（客户端验证服务端证书），也验证客户端身份（服务端验证客户端证书）。

---

## REQUIRE 子句的几个层级

| 子句 | 要求 | 验证内容 |
|------|------|---------|
| `REQUIRE NONE` | 不要求 SSL | 无 |
| `REQUIRE SSL` | 必须使用 SSL | 连接必须加密 |
| `REQUIRE X509` | 必须有有效客户端证书 | 证书有效且由信任 CA 签发 |
| `REQUIRE ISSUER 'issuer'` | 指定证书颁发者 | 证书颁发者必须匹配 |
| `REQUIRE SUBJECT 'subject'` | 指定证书主体 | 证书主体必须匹配 |
| `REQUIRE CIPHER 'cipher'` | 指定加密算法 | 必须使用指定算法 |

## 为账户设置 REQUIRE X509

```sql
-- 创建用户时要求客户端证书（最基本的 X509 验证）
CREATE USER 'x509_user'@'%'
    IDENTIFIED BY 'X509P@ss1'
    REQUIRE X509;

-- 修改已有账户
ALTER USER 'api_gateway'@'%' REQUIRE X509;

-- 更精细：要求特定 CA 颁发的证书
ALTER USER 'api_gateway'@'%'
    REQUIRE ISSUER '/C=CN/ST=Beijing/L=Beijing/O=MyCompany/CN=MyCA';

-- 要求特定证书主体（只有这张证书才能连接）
ALTER USER 'dedicated_app'@'%'
    REQUIRE SUBJECT '/C=CN/O=MyCompany/CN=app-server-01';

-- 组合多个条件（AND 连接）
ALTER USER 'secure_app'@'%'
    REQUIRE ISSUER '/C=CN/O=MyCompany/CN=MyCA'
    AND SUBJECT '/C=CN/O=MyCompany/CN=app-server-01';
```

## 查看账户的 X509 要求配置

```sql
-- 查看账户的 SSL 要求设置
SELECT User, Host, ssl_type, ssl_cipher, x509_issuer, x509_subject
FROM mysql.user
WHERE User = 'x509_user';
-- ssl_type:
--   ''      = REQUIRE NONE（无要求）
--   'ANY'   = REQUIRE SSL（任何有效 SSL）
--   'X509'  = REQUIRE X509（需要客户端证书）
--   'SPECIFIED' = REQUIRE CIPHER/ISSUER/SUBJECT
-- x509_issuer：ISSUER 配置的颁发者字符串
-- x509_subject：SUBJECT 配置的主体字符串
```

-- openssl req -new -x509 -nodes -days 3650 -key ca-key.pem -out ca-cert.pem
-- openssl req -newkey rsa:2048 -days 3650 -nodes -keyout client-key.pem -out client-req.pem
-- openssl x509 -req -in client-req.pem -days 3650 -CA ca-cert.pem -CAkey ca-key.pem -CAcreateserial -out client-cert.pem

## 客户端连接时提供证书

```bash
# 命令行客户端提供客户端证书
mysql -u x509_user -p \
    --ssl-ca=/path/to/ca.pem \
    --ssl-cert=/path/to/client-cert.pem \
    --ssl-key=/path/to/client-key.pem \
    --ssl-mode=VERIFY_CA \
    -h mysql-server.example.com

# 不提供客户端证书时的错误：
# ERROR 1045 (28000): Access denied for user 'x509_user'@'...'
# (using password: YES)
```

```python
# Python（PyMySQL）使用客户端证书连接
import pymysql

conn = pymysql.connect(
    host='mysql-server.example.com',
    user='x509_user',
    password='X509P@ss1',
    database='myapp',
    ssl={
        'ca': '/path/to/ca.pem',
        'cert': '/path/to/client-cert.pem',
        'key': '/path/to/client-key.pem'
    }
)
```

## 适用场景

- **机器对机器认证**：应用服务器到数据库的服务账号，用客户端证书取代密码作为认证手段（或双因素认证）
- **零信任架构**：每个服务都有独立的客户端证书，服务端通过 SUBJECT 精确识别连接来源
- **监管合规**：金融、医疗等行业要求传输层双向认证

## 常见问题

**REQUIRE X509 和 REQUIRE SSL 有什么区别？**

`REQUIRE SSL` 只要求连接必须加密（TLS 握手成功），不验证客户端身份。`REQUIRE X509` 在加密基础上额外要求客户端提供由信任 CA 签发的证书，服务端会验证客户端证书的有效性（未过期、CA 签名有效）。这是单向认证 vs 双向认证的区别。

---

## 注意事项

- 客户端证书私钥（`client-key.pem`）必须严格保密，只存在于需要连接的客户端服务器上。一旦私钥泄露，需要立即撤销该证书（更换新的客户端证书和密钥对），并更新对应账户的 SUBJECT/ISSUER 配置。
- `REQUIRE X509` 只验证证书的有效性（CA 签名正确、未过期），不验证证书是否被吊销（CRL/OCSP）。如果需要证书吊销检查，需要在应用层或网络层实现。

---

## 总结

`REQUIRE X509` 要求客户端在 SSL 连接时提供有效的 X.509 证书（由服务端信任 CA 签发），实现双向 TLS 认证。可以用 `REQUIRE ISSUER` 限制证书颁发者，`REQUIRE SUBJECT` 限制证书主体，精确控制哪个客户端证书可以连接。客户端连接时通过 `--ssl-cert/--ssl-key/--ssl-ca` 参数提供证书。适用于服务间高安全认证场景。
