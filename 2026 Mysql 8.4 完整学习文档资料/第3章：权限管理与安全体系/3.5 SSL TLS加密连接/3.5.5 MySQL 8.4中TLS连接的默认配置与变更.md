# MySQL 8.4 中 TLS 连接的默认配置与变更

MySQL 8.4 在 TLS/SSL 加密连接方面做了多项调整，主要方向是移除不安全的旧协议、收紧默认加密套件、废弃旧式参数。如果你从 MySQL 8.0 升级到 8.4，或者在 8.4 上全新部署，需要了解这些变更对现有客户端连接和复制拓扑的影响。

---

## 8.0 到 8.4 TLS 相关变更概览

| 变更项 | MySQL 8.0 | MySQL 8.4 |
|--------|-----------|-----------|
| 支持的 TLS 协议 | TLSv1、TLSv1.1（8.0.28 移除）、TLSv1.2、TLSv1.3 | 仅 TLSv1.2 和 TLSv1.3 |
| tls_version 默认值 | TLSv1.2,TLSv1.3 | TLSv1.2,TLSv1.3 |
| TLSv1.3 支持 | 8.0.16 起支持（需 OpenSSL 1.1.1+） | 完全支持 |
| --ssl / --skip-ssl 参数 | 8.0.26 起废弃 | 已移除 |
| ssl_cipher 默认列表 | 较宽松，包含部分旧套件 | 收紧，大量旧套件标记为废弃 |
| TLS_AES_128_CCM_8_SHA256 | 可用 | 使用时产生废弃警告 |
| 自动生成证书 | 支持（mysql_ssl_rsa_setup 或自动） | 支持（mysql_ssl_rsa_setup 已移除，改用服务器自动生成） |
| ALTER INSTANCE RELOAD TLS | 支持 | 支持（推荐方式） |

---

## TLS 协议支持变更

MySQL 8.4 彻底移除了 TLSv1 和 TLSv1.1 协议的支持。这两个协议在 RFC 8996 中被正式废弃，存在已知的安全漏洞。

```sql
-- 查看当前服务器支持的 TLS 协议版本
SHOW GLOBAL VARIABLES LIKE 'tls_version';
-- +---------------+--------------------+
-- | Variable_name | Value              |
-- +---------------+--------------------+
-- | tls_version   | TLSv1.2,TLSv1.3   |
-- +---------------+--------------------+

-- 8.4 中只能设置 TLSv1.2 和/或 TLSv1.3
-- 尝试设置 TLSv1 或 TLSv1.1 会被忽略或报错
```

如果你的客户端程序或驱动版本较老，只支持 TLSv1 或 TLSv1.1，连接 MySQL 8.4 时会失败。需要升级客户端或驱动到支持 TLSv1.2 以上的版本。

---

## --ssl 和 --skip-ssl 参数的移除

在 MySQL 8.0.26 中 `--ssl` 参数被标记为废弃，MySQL 8.4 中已完全移除。如果 my.cnf 中仍有 `--ssl` 或 `--skip-ssl` 配置，启动时会报错。

```ini
# 8.0 的旧写法（8.4 中不再有效）
# [mysqld]
# --skip-ssl              # 已移除，不能使用

# 8.4 中禁用 SSL 的正确方式：将 tls_version 设为空字符串
[mysqld]
tls_version=''
# 这样服务器不允许加密连接（不推荐在生产环境中使用）
```

---

## mysql_ssl_rsa_setup 工具的移除

MySQL 8.0 中有一个独立的命令行工具 `mysql_ssl_rsa_setup`，用于手动生成 SSL 证书和 RSA 密钥。在 8.4 中这个工具已被移除。

```sql
-- 8.4 的替代方案：服务器自动生成证书
-- MySQL 8.4 在首次启动时，如果 datadir 中没有 SSL 证书文件，
-- 服务器会自动生成自签名 CA 证书、服务端证书和客户端证书
-- 文件名与之前相同：
-- ca.pem / ca-key.pem
-- server-cert.pem / server-key.pem
-- client-cert.pem / client-key.pem

-- 查看自动生成的证书路径
SHOW VARIABLES LIKE 'ssl_ca';
SHOW VARIABLES LIKE 'ssl_cert';
SHOW VARIABLES LIKE 'ssl_key';

-- 查看证书有效期
SHOW STATUS LIKE 'Ssl_server_not_after';
-- 自动生成的证书默认有效期为 10 年
```

## 默认加密套件的收紧

MySQL 8.4 对 TLSv1.2 的默认 cipher 列表做了大幅度清理，许多旧的加密套件被标记为废弃（使用时会产生警告），部分被永久禁止。

**8.4 中 TLSv1.2 推荐使用的加密套件：**

```ini
# 这些是 8.4 默认启用且不产生警告的 TLSv1.2 加密套件
ECDHE-ECDSA-AES128-GCM-SHA256
ECDHE-ECDSA-AES256-GCM-SHA384
ECDHE-RSA-AES128-GCM-SHA256
ECDHE-RSA-AES256-GCM-SHA384
ECDHE-ECDSA-CHACHA20-POLY1305
ECDHE-RSA-CHACHA20-POLY1305
ECDHE-ECDSA-AES256-CCM
ECDHE-ECDSA-AES128-CCM
DHE-RSA-AES128-GCM-SHA256
DHE-RSA-AES256-GCM-SHA384
DHE-RSA-AES256-CCM
DHE-RSA-AES128-CCM
DHE-RSA-CHACHA20-POLY1305
```

**8.4 中 TLSv1.3 默认支持的 ciphersuite：**

```ini
# TLSv1.3 使用独立的 ciphersuite 参数（tls_ciphersuites）
TLS_AES_128_GCM_SHA256
TLS_AES_256_GCM_SHA384
TLS_CHACHA20_POLY1305_SHA256
TLS_AES_128_CCM_SHA256
# 注意：TLS_AES_128_CCM_8_SHA256 在 8.4 中使用时会产生废弃警告
```

## 推荐的 8.4 TLS 配置

```ini
[mysqld]
# 只允许 TLSv1.2 和 TLSv1.3（默认值，通常不需要显式设置）
tls_version=TLSv1.2,TLSv1.3

# 如果所有客户端都支持 TLSv1.3，可以限制为仅 TLSv1.3
# tls_version=TLSv1.3

# SSL 证书配置（生产环境应使用 CA 签发的正式证书）
ssl_ca=/etc/mysql/ssl/ca-cert.pem
ssl_cert=/etc/mysql/ssl/server-cert.pem
ssl_key=/etc/mysql/ssl/server-key.pem

# 强制所有连接使用加密（可选但推荐）
require_secure_transport=ON

# 限制 TLSv1.3 的 ciphersuite（可选）
tls_ciphersuites=TLS_AES_256_GCM_SHA384:TLS_AES_128_GCM_SHA256:TLS_CHACHA20_POLY1305_SHA256

# 管理接口的 TLS 配置（如果开启了管理端口）
# admin_tls_version=TLSv1.3
# admin_ssl_ca=/etc/mysql/ssl/ca-cert.pem
# admin_ssl_cert=/etc/mysql/ssl/admin-cert.pem
# admin_ssl_key=/etc/mysql/ssl/admin-key.pem
```

## 验证当前连接的 TLS 状态

```sql
-- 查看当前连接使用的 TLS 版本和加密套件
SELECT * FROM performance_schema.session_status
WHERE VARIABLE_NAME IN ('Ssl_version', 'Ssl_cipher');
-- +---------------+-------------------------------+
-- | VARIABLE_NAME | VARIABLE_VALUE                |
-- +---------------+-------------------------------+
-- | Ssl_cipher    | TLS_AES_256_GCM_SHA384        |
-- | Ssl_version   | TLSv1.3                       |
-- +---------------+-------------------------------+
-- 如果连接未加密，两个值都是空字符串

-- 查看服务器端 SSL 状态概览
SHOW STATUS LIKE 'Ssl%';
-- 重要的状态变量：
-- Ssl_accepts:        服务器接受的 SSL 连接总次数
-- Ssl_finished_accepts: 成功完成 SSL 握手的次数
-- Ssl_cipher:         当前会话使用的加密套件
-- Ssl_version:        当前会话使用的 TLS 版本

-- 查看服务器支持的完整 cipher 列表
SHOW SESSION STATUS LIKE 'Ssl_cipher_list';
-- 返回当前服务器支持的所有 cipher（非常长的列表）

-- 查看某个用户是否要求 SSL
SELECT user, host, ssl_type FROM mysql.user WHERE ssl_type != '';
-- ssl_type 可能的值：ANY（REQUIRE SSL）、X509、SPECIFIED
```

## 热更新 TLS 证书（不重启服务器）

MySQL 8.0.16+ 支持运行时重新加载 TLS 配置，8.4 中继续支持。更换证书后无需重启服务器。

```sql
-- 更换证书文件后，执行以下命令热加载
ALTER INSTANCE RELOAD TLS;
-- 新的连接会使用新证书
-- 已经建立的连接继续使用旧证书（直到断开重连）

-- 如果需要同时更新管理接口的 TLS（MySQL 8.4）
ALTER INSTANCE RELOAD TLS FOR CHANNEL mysql_admin;

-- 验证新证书已生效
SHOW STATUS LIKE 'Ssl_server_not_after';
-- 应显示新证书的过期时间
```

## 复制连接的 TLS 变更

MySQL 8.4 中复制相关的 TLS 参数名称也随着复制命令的重命名而变更。

| 8.0 参数名 | 8.4 参数名 | 说明 |
|-----------|-----------|------|
| MASTER_SSL | SOURCE_SSL | 启用复制 SSL |
| MASTER_SSL_CA | SOURCE_SSL_CA | CA 证书路径 |
| MASTER_SSL_CERT | SOURCE_SSL_CERT | 客户端证书路径 |
| MASTER_SSL_KEY | SOURCE_SSL_KEY | 客户端私钥路径 |
| MASTER_TLS_VERSION | SOURCE_TLS_VERSION | 允许的 TLS 版本 |
| MASTER_TLS_CIPHERSUITES | SOURCE_TLS_CIPHERSUITES | TLSv1.3 ciphersuite |

```sql
-- 8.4 中配置从库到主库的加密复制连接
CHANGE REPLICATION SOURCE TO
    SOURCE_HOST = 'primary.example.com',
    SOURCE_PORT = 3306,
    SOURCE_USER = 'repl_user',
    SOURCE_PASSWORD = 'repl_pass',
    SOURCE_SSL = 1,
    SOURCE_SSL_CA = '/etc/mysql/ssl/ca-cert.pem',
    SOURCE_SSL_CERT = '/etc/mysql/ssl/client-cert.pem',
    SOURCE_SSL_KEY = '/etc/mysql/ssl/client-key.pem',
    SOURCE_TLS_VERSION = 'TLSv1.3';
-- 注意：CHANGE MASTER TO 在 8.4 中已被完全移除
```

## 升级到 8.4 前的 TLS 检查清单

```sql
-- 1. 检查当前 tls_version 设置，确认没有依赖 TLSv1/TLSv1.1
SHOW GLOBAL VARIABLES LIKE 'tls_version';

-- 2. 检查 my.cnf 中是否有 --ssl 或 --skip-ssl（需要移除）
-- 如果有，替换为 tls_version 参数

-- 3. 检查是否使用了被废弃的 cipher
SHOW GLOBAL VARIABLES LIKE 'ssl_cipher';
-- 如果值中包含旧 cipher，升级后会产生废弃警告

-- 4. 检查复制配置中的 MASTER_SSL 等参数
-- 需要在升级后改为 SOURCE_SSL 等新名称

-- 5. 检查客户端和驱动版本是否支持 TLSv1.2+
-- 常见的不支持 TLSv1.2 的旧版驱动：
-- MySQL Connector/J 5.1.38 之前
-- PyMySQL 0.9.0 之前
-- PHP mysqlnd 7.1 之前

-- 6. 验证证书的 RSA 密钥长度（建议至少 2048 位）
-- 在服务器上用 openssl 检查：
-- openssl x509 -in server-cert.pem -noout -text | grep "Public-Key"
```

## 适用场景

- **新部署 MySQL 8.4**：直接使用默认 TLS 配置（TLSv1.2 + TLSv1.3），如果所有客户端都较新，可以限制为仅 TLSv1.3
- **从 8.0 升级到 8.4**：需要检查并移除 --ssl/--skip-ssl 参数、更新复制配置中的参数名、确认客户端支持 TLSv1.2+
- **合规要求**：PCI DSS、HIPAA 等合规标准要求禁用 TLSv1 和 TLSv1.1，8.4 天然满足这个要求
- **跨数据中心复制**：使用 SOURCE_SSL 和 SOURCE_TLS_VERSION 配置加密的复制连接

## 常见问题

**升级到 8.4 后客户端连接失败，报 SSL 相关错误怎么办？**

最常见的原因是客户端只支持 TLSv1 或 TLSv1.1。解决方法是升级客户端驱动到支持 TLSv1.2 的版本。如果暂时无法升级客户端，可以在 8.4 中将 `tls_version` 设为空字符串临时禁用 SSL（仅在内网且不影响安全的情况下），但这不是推荐做法。

**8.4 中 require_secure_transport 默认是什么值？**

默认是 OFF，即允许非加密连接。如果要强制所有连接都使用 TLS，需要显式设置为 ON。开启后，不使用 SSL 的客户端连接会被拒绝。

**已有的自签名证书在升级到 8.4 后还能用吗？**

可以继续使用，只要证书使用的是 TLSv1.2 或 TLSv1.3 兼容的加密算法，且 RSA 密钥长度足够（建议 2048 位以上）。8.4 不会强制你更换证书，但生产环境建议使用 CA 签发的正式证书。

---

## 注意事项

- 移除 TLSv1 和 TLSv1.1 是不可逆的。如果你的环境中有依赖旧 TLS 版本的老旧客户端或中间件，必须在升级前完成客户端升级。
- `ALTER INSTANCE RELOAD TLS` 只影响新建连接，已有连接使用旧证书直到断开。如果需要强制所有连接使用新证书，需要在热更新后主动断开旧连接（通过 KILL 命令或等待连接自然超时）。
- Group Replication 的 TLS 配置有独立的参数（`group_replication_recovery_tls_version` 等），升级时也需要同步检查和更新。
- 在容器化环境中，证书文件应通过 Kubernetes Secret 或 Docker Secret 挂载，不要打包进镜像。

---

## 总结

MySQL 8.4 在 TLS 方面的核心变更包括：彻底移除 TLSv1 和 TLSv1.1 协议支持（仅保留 TLSv1.2 和 TLSv1.3）、移除 --ssl/--skip-ssl 参数（用 tls_version 替代）、移除 mysql_ssl_rsa_setup 工具（改由服务器自动生成证书）、收紧默认加密套件列表（大量旧 cipher 标记为废弃）、复制相关的 SSL 参数名从 MASTER_ 前缀改为 SOURCE_ 前缀。升级前需要确认所有客户端和驱动支持 TLSv1.2+，清理 my.cnf 中的废弃参数，更新复制配置中的参数名称。生产环境建议设置 `require_secure_transport=ON` 强制所有连接使用加密传输。
