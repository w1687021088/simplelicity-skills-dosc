# 客户端证书配置

客户端证书配置涵盖了 MySQL 客户端（命令行工具、各语言驱动）在连接时提供 SSL/TLS 证书的完整设置方式。正确配置客户端证书是实现 `REQUIRE X509` 双向 TLS 认证的必要条件，也是在不信任网络上安全连接 MySQL 的重要手段。

---

## 客户端需要的证书文件

```
ca.pem          - CA 根证书（用于验证服务端证书是否由受信任 CA 签发）
client-cert.pem - 客户端证书（发给服务端，证明客户端身份）
client-key.pem  - 客户端私钥（配合客户端证书使用，保密！）
```

## MySQL 自动生成的证书文件

```sql
-- MySQL 8.0+ 在数据目录中自动生成测试用证书
SHOW VARIABLES LIKE 'datadir';
-- 找到 datadir 后，查看以下文件：
-- ca.pem / ca-key.pem
-- server-cert.pem / server-key.pem
-- client-cert.pem / client-key.pem

-- 查看服务端当前使用的证书配置
SHOW VARIABLES LIKE 'ssl_%';
-- ssl_ca: CA 证书路径
-- ssl_cert: 服务端证书路径
-- ssl_key: 服务端私钥路径

-- 查看证书有效期（通过 Ssl_server_not_after）
SHOW STATUS LIKE 'Ssl_server_not%';
-- Ssl_server_not_before: 证书有效期起始时间
-- Ssl_server_not_after:  证书有效期截止时间
```

## 用 OpenSSL 生成生产级客户端证书

```bash
# 第一步：创建 CA 私钥和根证书（如果尚未有 CA）
openssl genrsa 4096 > ca-key.pem
openssl req -new -x509 -nodes -days 3650 -key ca-key.pem \
    -out ca-cert.pem \
    -subj "/C=CN/ST=Beijing/O=MyCompany/CN=MySQL-CA"

# 第二步：创建客户端私钥和证书请求（CSR）
openssl genrsa 2048 > client-key.pem
openssl req -new -key client-key.pem \
    -out client-req.pem \
    -subj "/C=CN/O=MyCompany/CN=app-server-01"

# 第三步：用 CA 签发客户端证书
openssl x509 -req -in client-req.pem \
    -CA ca-cert.pem -CAkey ca-key.pem \
    -CAcreateserial \
    -days 3650 \
    -out client-cert.pem

# 验证证书信息
openssl verify -CAfile ca-cert.pem client-cert.pem
# 输出：client-cert.pem: OK

# 查看证书主体（Subject）
openssl x509 -in client-cert.pem -noout -subject
# subject=C=CN, O=MyCompany, CN=app-server-01
# 这个字符串可用于 REQUIRE SUBJECT 配置
```

## 命令行客户端配置

```bash
# 基本 SSL 连接（验证服务端证书，不需要客户端证书）
mysql -u alice -p \
    --ssl-ca=/etc/mysql/ssl/ca-cert.pem \
    --ssl-mode=VERIFY_CA \
    -h mysql.example.com

# 双向认证（提供客户端证书，用于 REQUIRE X509 账户）
mysql -u x509_user -p \
    --ssl-ca=/etc/mysql/ssl/ca-cert.pem \
    --ssl-cert=/etc/mysql/ssl/client-cert.pem \
    --ssl-key=/etc/mysql/ssl/client-key.pem \
    --ssl-mode=VERIFY_CA \
    -h mysql.example.com

# ssl-mode 选项说明：
# DISABLED     - 禁用 SSL
# PREFERRED    - 优先 SSL（默认）
# REQUIRED     - 必须 SSL，但不验证证书有效性
# VERIFY_CA    - 必须 SSL 且验证 CA 证书
# VERIFY_IDENTITY - 必须 SSL，验证 CA 且验证主机名

# 写入 ~/.my.cnf 避免每次命令行指定
# [client]
# ssl-ca=/etc/mysql/ssl/ca-cert.pem
# ssl-cert=/etc/mysql/ssl/client-cert.pem
# ssl-key=/etc/mysql/ssl/client-key.pem
# ssl-mode=VERIFY_CA
```

## Python（PyMySQL / mysql-connector-python）

```python
# PyMySQL
import pymysql

connection = pymysql.connect(
    host='mysql.example.com',
    port=3306,
    user='x509_user',
    password='X509P@ss1',
    database='myapp',
    ssl={
        'ca': '/etc/mysql/ssl/ca-cert.pem',
        'cert': '/etc/mysql/ssl/client-cert.pem',
        'key': '/etc/mysql/ssl/client-key.pem',
        'check_hostname': True,
    }
)

# mysql-connector-python
import mysql.connector

connection = mysql.connector.connect(
    host='mysql.example.com',
    user='x509_user',
    password='X509P@ss1',
    database='myapp',
    ssl_ca='/etc/mysql/ssl/ca-cert.pem',
    ssl_cert='/etc/mysql/ssl/client-cert.pem',
    ssl_key='/etc/mysql/ssl/client-key.pem',
    ssl_verify_cert=True,
    ssl_verify_identity=True,
)
```

## 服务端 SSL 证书配置（my.cnf）

```ini
[mysqld]
# SSL 证书文件路径（服务端）
ssl_ca=/etc/mysql/ssl/ca-cert.pem
ssl_cert=/etc/mysql/ssl/server-cert.pem
ssl_key=/etc/mysql/ssl/server-key.pem

# 只允许 TLS 1.3（推荐 MySQL 8.4）
tls_version=TLSv1.3

# 只允许强加密套件
tls_ciphersuites=TLS_AES_256_GCM_SHA384:TLS_AES_128_GCM_SHA256

# 全局强制所有连接使用 SSL（可选）
require_secure_transport=ON
```

## 证书到期管理

```sql
-- 检查服务端证书到期时间
SHOW STATUS LIKE 'Ssl_server_not_after';
-- Ssl_server_not_after: Apr 18 00:00:00 2028 GMT

-- 自动生成的证书默认有效期为 10 年（3650天）
-- 生产环境推荐使用 1-2 年有效期，建立证书轮换机制

-- 更换服务端证书后，无需重启即可热加载
ALTER INSTANCE RELOAD TLS;
-- 新连接使用新证书，已有连接不受影响（使用旧证书直到断开）
```

## 适用场景

- **跨数据中心连接**：应用服务器和 MySQL 不在同一内网，需要 SSL 防止传输过程中数据被截获
- **云数据库连接**：连接 RDS 或云上 MySQL 时，通常需要提供 CA 证书验证服务端身份
- **服务网格中的 mTLS**：在 Kubernetes 等容器环境中，服务与 MySQL 之间用 mTLS（双向 TLS）实现零信任认证

## 常见问题

**`SSL connection error: error:0200100D:system library:fopen:Permission denied` 错误怎么解决？**

这是证书文件权限问题。MySQL 客户端进程需要能读取证书文件，检查文件权限：
```bash
chmod 600 client-key.pem   # 私钥只有所有者可读
chmod 644 client-cert.pem  # 证书可以让其他用户读
chmod 644 ca-cert.pem      # CA 证书可以让其他用户读
chown mysql:mysql *.pem    # 确保 MySQL 进程有权访问
```

---

## 注意事项

- 客户端私钥（`client-key.pem`）必须严格保护，不能被其他用户读取（权限应设为 600 或 400）。如果私钥泄露，应立即撤销对应的客户端证书，重新生成密钥对和证书，并更新 MySQL 账户的 REQUIRE 配置。
- 在 Docker/Kubernetes 环境中，证书文件应通过 Kubernetes Secret 或 Docker Secret 挂载到容器，而不是直接打包进镜像，避免证书随镜像泄露。

## 总结

客户端证书配置需要三个文件：CA 根证书（ca.pem）、客户端证书（client-cert.pem）、客户端私钥（client-key.pem）。命令行通过 `--ssl-ca/--ssl-cert/--ssl-key` 指定，各语言驱动有对应的参数（PyMySQL 用 ssl 字典，JDBC 用 KeyStore）。服务端通过 my.cnf 的 `ssl_ca/ssl_cert/ssl_key` 配置，`ALTER INSTANCE RELOAD TLS` 可不重启热更新证书。私钥文件需严格保护权限（600），生产环境应通过 Secret 管理系统管理证书。
