# CIPHER 指定加密算法

`REQUIRE CIPHER 'cipher_name'` 在账户级别限制该账户连接时必须使用指定的 TLS 加密套件（Cipher Suite）。这允许 DBA 为特定高安全账户强制使用更强的加密算法，即使服务端默认允许多种算法也不例外。

---

## TLS 加密套件基础知识

TLS 握手时，客户端和服务端协商使用哪种加密套件（Cipher Suite）。一个加密套件由多个算法组合而成：

```
TLS_AES_256_GCM_SHA384
│   │   │   │   │
│   │   │   │   └── 消息认证算法（MAC）：SHA384
│   │   │   └────── 对称加密模式：GCM
│   │   └────────── 对称加密密钥长度：256
│   └────────────── 对称加密算法：AES
└────────────────── 协议版本：TLS 1.3
```

## 为账户设置 REQUIRE CIPHER

```sql
-- 强制账户只能使用指定的加密套件
CREATE USER 'cipher_user'@'%'
    IDENTIFIED BY 'CipherP@ss1'
    REQUIRE CIPHER 'TLS_AES_256_GCM_SHA384';

-- 修改已有账户
ALTER USER 'finance_app'@'%'
    REQUIRE CIPHER 'TLS_AES_256_GCM_SHA384';

-- CIPHER 可以与 ISSUER/SUBJECT 组合使用
ALTER USER 'high_security'@'%'
    REQUIRE CIPHER 'TLS_AES_256_GCM_SHA384'
    AND ISSUER '/C=CN/O=MyCompany/CN=MyCA'
    AND SUBJECT '/C=CN/O=MyCompany/CN=app-server-01';

-- 查看账户的加密算法要求
SELECT User, Host, ssl_type, ssl_cipher
FROM mysql.user WHERE User = 'cipher_user';
-- ssl_cipher 字段存储要求的加密套件名称
```

## MySQL 8.4 支持的加密套件

```sql
-- 查看当前 MySQL 支持的 TLS 版本
SHOW VARIABLES LIKE 'tls_version';
-- 默认：TLSv1.2,TLSv1.3（MySQL 8.4 已移除 TLSv1 和 TLSv1.1 支持）

-- 查看 TLS 1.3 的可用加密套件
SHOW VARIABLES LIKE 'tls_ciphersuites';
-- 默认：TLS_AES_128_GCM_SHA256:TLS_AES_256_GCM_SHA384:TLS_CHACHA20_POLY1305_SHA256

-- 查看 TLS 1.2 的可用加密套件
SHOW VARIABLES LIKE 'ssl_cipher';
-- 默认：大量允许的 TLS 1.2 算法列表
```

## TLS 1.3 vs TLS 1.2 加密套件对比

| TLS 版本 | 典型加密套件 | 特点 |
|---------|------------|------|
| TLS 1.3 | TLS_AES_256_GCM_SHA384 | 最新版本，性能好，算法精简，推荐 |
| TLS 1.3 | TLS_AES_128_GCM_SHA128 | 128位，稍弱，兼容性好 |
| TLS 1.3 | TLS_CHACHA20_POLY1305_SHA256 | 适合低性能设备（移动端）|
| TLS 1.2 | ECDHE-RSA-AES256-GCM-SHA384 | 传统套件，广泛支持 |
| TLS 1.2 | ECDHE-RSA-AES128-GCM-SHA256 | 128位，老版本驱动兼容 |

## 限制 MySQL 服务端只使用强算法

```sql
-- 服务端级别：限制只允许 TLS 1.3（最强安全性）
SET GLOBAL tls_version = 'TLSv1.3';
-- 修改 my.cnf（持久化）：
-- [mysqld]
-- tls_version=TLSv1.3

-- 服务端级别：限制 TLS 1.3 可用的加密套件
SET GLOBAL tls_ciphersuites = 'TLS_AES_256_GCM_SHA384';
-- 只允许最强的 256 位 AES-GCM 套件

-- 注意：更改 tls_version 和 tls_ciphersuites 后需要重新加载 SSL 配置
-- MySQL 8.0.16+ 支持不重启热更新：
ALTER INSTANCE RELOAD TLS;
-- 执行后新连接使用更新后的 TLS 配置，已有连接不受影响
```

## 查看当前连接的加密信息

```sql
-- 查看当前连接使用的加密套件
SHOW STATUS LIKE 'Ssl_cipher';
-- 例如：TLS_AES_256_GCM_SHA384

-- 查看 TLS 版本
SHOW STATUS LIKE 'Ssl_version';
-- 例如：TLSv1.3

-- 查看更多 SSL 状态信息
SHOW STATUS LIKE 'Ssl%';
-- Ssl_cipher：当前加密套件
-- Ssl_version：TLS 版本
-- Ssl_cipher_list：服务端支持的加密套件列表
-- Ssl_server_not_before：服务端证书有效期起始
-- Ssl_server_not_after：服务端证书有效期截止
```

## 配置客户端使用指定加密套件

```bash
# 命令行客户端指定使用特定加密套件
mysql -u cipher_user -p \
    --ssl-mode=REQUIRED \
    --tls-version=TLSv1.3 \
    --tls-ciphersuites=TLS_AES_256_GCM_SHA384 \
    -h mysql-server.example.com

# 如果客户端不支持服务端/账户要求的算法，连接失败：
# ERROR 2026 (HY000): SSL connection error: error:1409442E:SSL routines...
```

## 适用场景

- **高安全业务账号**：要求金融、支付类账号只能使用 AES-256 级别的加密套件
- **合规要求**：某些安全标准（FIPS 140-2 等）要求使用经过认证的特定加密算法
- **逐步升级**：过渡期内，对新账号强制 TLS 1.3，老账号仍使用 TLS 1.2，便于管理

## 常见问题

**设置了 REQUIRE CIPHER 后，客户端不支持该加密套件怎么办？**

客户端会收到 TLS 握手失败的错误（`SSL connection error`），无法连接。需要确认客户端使用的 MySQL 驱动版本是否支持该套件，以及操作系统的 OpenSSL 版本是否支持。对于 TLS 1.3 的套件，需要 OpenSSL 1.1.1+ 版本。

---

## 注意事项

- `REQUIRE CIPHER` 对账户生效的前提是服务端的 `ssl_cipher` 或 `tls_ciphersuites` 也支持该套件。如果服务端已通过 `tls_ciphersuites` 禁用了该套件，账户层面的 REQUIRE CIPHER 设置也无法生效（协商阶段就会失败）。
- 在 MySQL 8.4 中，TLSv1 和 TLSv1.1 已被完全移除（不只是默认禁用），任何基于这些版本的连接都无法建立，不需要也无法通过 CIPHER 配置使用旧版本算法。

---

## 总结

`REQUIRE CIPHER 'suite_name'` 限制账户连接必须使用指定的 TLS 加密套件。MySQL 8.4 支持 TLS 1.2 和 TLS 1.3（TLS 1.0/1.1 已移除），推荐使用 TLS 1.3 套件（`TLS_AES_256_GCM_SHA384` 等）。服务端通过 `tls_ciphersuites`（TLS 1.3）和 `ssl_cipher`（TLS 1.2）变量控制全局允许的算法范围。`ALTER INSTANCE RELOAD TLS` 可以不重启 MySQL 热更新 TLS 配置。
