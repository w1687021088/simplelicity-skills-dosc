# 密码复杂度策略（长度、大小写、数字、特殊字符）

`validate_password` 组件安装后，通过一组系统变量控制密码复杂度要求。每次设置或修改密码时，MySQL 自动检查密码是否满足这些要求，不满足则拒绝操作并提示具体原因。合理配置这些策略是账户安全的第一道防线。

---

## 复杂度控制变量详解

```sql
-- 查看所有密码复杂度相关变量
SHOW VARIABLES LIKE 'validate_password%';
```

| 变量名 | 默认值 | 说明 |
|-------|--------|------|
| `validate_password.policy` | MEDIUM | 策略级别：LOW/MEDIUM/STRONG |
| `validate_password.length` | 8 | 密码最小长度（字符数）|
| `validate_password.mixed_case_count` | 1 | 大写字母 + 小写字母各至少几个 |
| `validate_password.number_count` | 1 | 数字（0-9）至少几个 |
| `validate_password.special_char_count` | 1 | 特殊字符至少几个 |
| `validate_password.check_user_name` | ON | 禁止密码中包含用户名 |
| `validate_password.dictionary_file` | （空）| 字典文件路径（STRONG 级别使用）|

## 密码长度要求

```sql
-- 查看当前最小长度
SHOW VARIABLES LIKE 'validate_password.length';
-- 默认：8

-- 修改为 12 位
SET GLOBAL validate_password.length = 12;
SET PERSIST validate_password.length = 12;  -- 持久化

-- 测试：密码太短时
CREATE USER 'test'@'%' IDENTIFIED BY 'Short1!';
-- ERROR 1819 (HY000): Your password does not satisfy the current policy requirements

-- 注意：validate_password.length 的实际最小值受其他规则约束：
-- length >= mixed_case_count * 2 + number_count + special_char_count
-- 默认情况下：2*1 + 1 + 1 = 4，小于默认 length=8，所以实际最小长度为 8
-- 如果设置 length=6 但 mixed_case*2+number+special=4，实际允许 length=6
```

## 大小写字母要求

```sql
-- 当前要求：大写字母至少1个，小写字母至少1个
SHOW VARIABLES LIKE 'validate_password.mixed_case_count';
-- 默认：1

-- 修改为：大写至少2个，小写至少2个
SET GLOBAL validate_password.mixed_case_count = 2;
SET PERSIST validate_password.mixed_case_count = 2;

-- 测试：全小写密码被拒绝
CREATE USER 'test'@'%' IDENTIFIED BY 'password123!';
-- ERROR 1819: 没有大写字母，不满足策略

-- 满足要求的密码
CREATE USER 'test'@'%' IDENTIFIED BY 'Password123!';  -- 合法
```

## 数字要求

```sql
-- 当前要求：至少1个数字
SHOW VARIABLES LIKE 'validate_password.number_count';
-- 默认：1

-- 修改为至少2个数字
SET GLOBAL validate_password.number_count = 2;
SET PERSIST validate_password.number_count = 2;

-- 测试
CREATE USER 'test'@'%' IDENTIFIED BY 'Password!@';  -- 没有数字，被拒绝
CREATE USER 'test'@'%' IDENTIFIED BY 'Password1!';  -- 1个数字，被拒绝（要求2个）
CREATE USER 'test'@'%' IDENTIFIED BY 'Password12!'; -- 2个数字，合法
```

## 特殊字符要求

```sql
-- 当前要求：至少1个特殊字符
SHOW VARIABLES LIKE 'validate_password.special_char_count';
-- 默认：1

-- 特殊字符指非字母、非数字的字符，如：! @ # $ % ^ & * ( ) - _ = + [ ] { } | ; : ' " , . < > / ?

-- 修改为至少2个特殊字符
SET GLOBAL validate_password.special_char_count = 2;
SET PERSIST validate_password.special_char_count = 2;

-- 测试
ALTER USER 'alice'@'%' IDENTIFIED BY 'Password1a';   -- 无特殊字符，被拒绝
ALTER USER 'alice'@'%' IDENTIFIED BY 'Password1!';   -- 1个特殊字符，被拒绝（要求2个）
ALTER USER 'alice'@'%' IDENTIFIED BY 'Password1!@';  -- 2个特殊字符，合法
```

## 禁止密码包含用户名

```sql
-- validate_password.check_user_name = ON（默认）
-- 禁止密码中包含账户的用户名部分（大小写不敏感）

SHOW VARIABLES LIKE 'validate_password.check_user_name';

-- 测试
CREATE USER 'alice'@'%' IDENTIFIED BY 'alice123!A';
-- ERROR 1819：密码包含用户名 'alice'

CREATE USER 'alice'@'%' IDENTIFIED BY 'AlIcE123!X';
-- ERROR 1819：大小写不敏感匹配，包含 alice

CREATE USER 'alice'@'%' IDENTIFIED BY 'SecureP@ss1';
-- 合法，不包含用户名
```

## 字典文件（STRONG 策略）

```sql
-- STRONG 级别会检查密码是否包含字典文件中的单词
SET GLOBAL validate_password.policy = STRONG;

-- 指定字典文件路径（文本文件，每行一个词）
SET GLOBAL validate_password.dictionary_file = '/etc/mysql/password_dictionary.txt';
-- 字典文件内容示例：
-- password
-- iloveyou
-- sunshine
-- mysql

-- 测试（STRONG 级别）
CREATE USER 'test'@'%' IDENTIFIED BY 'Password1!';
-- ERROR 1819：密码包含字典词汇 'password'

CREATE USER 'test'@'%' IDENTIFIED BY 'SecureP@ss1#';
-- 合法（不包含字典词汇且满足其他策略）
```

## 企业推荐配置

```sql
-- 平衡安全与可用性的推荐配置：
SET PERSIST validate_password.policy = 'MEDIUM';
SET PERSIST validate_password.length = 12;
SET PERSIST validate_password.mixed_case_count = 1;
SET PERSIST validate_password.number_count = 1;
SET PERSIST validate_password.special_char_count = 1;
SET PERSIST validate_password.check_user_name = ON;

SET PERSIST validate_password.length = 16;
SET PERSIST validate_password.mixed_case_count = 2;
SET PERSIST validate_password.number_count = 2;

```

## 适用场景

- **合规要求**：等保 2.0、HIPAA 等标准要求密码复杂度
- **防暴力破解**：复杂密码大幅提升暴力破解的难度和时间成本
- **防弱密码**：防止用户设置容易猜测的密码（"company2026!"）

## 常见问题

**如何让临时账号或测试账号绕过密码策略？**

不建议绕过，但如果必须（如 CI/CD 测试环境），可以临时降低策略：
```sql
SET GLOBAL validate_password.policy = LOW;
SET GLOBAL validate_password.length = 4;
-- 创建测试账号...
-- 然后恢复
SET GLOBAL validate_password.policy = MEDIUM;
SET GLOBAL validate_password.length = 12;
```

---

## 注意事项

- 修改复杂度策略只影响之后的密码设置操作，不会导致已有密码失效或要求用户立即修改密码（除非配合 `PASSWORD EXPIRE` 强制过期）。
- 当 `validate_password.length` 设置的值小于 `mixed_case_count * 2 + number_count + special_char_count` 时，MySQL 会自动将有效长度提升到这个计算值，不会低于各部分要求的字符总数。

---

## 总结

密码复杂度通过 `validate_password.*` 系统变量控制，主要维度：最小长度（length）、大小写字母数量（mixed_case_count）、数字数量（number_count）、特殊字符数量（special_char_count），以及禁止包含用户名（check_user_name）。策略级别 LOW 只检查长度，MEDIUM 检查全部复杂度，STRONG 额外检查字典文件。用 `SET PERSIST` 持久化配置。
