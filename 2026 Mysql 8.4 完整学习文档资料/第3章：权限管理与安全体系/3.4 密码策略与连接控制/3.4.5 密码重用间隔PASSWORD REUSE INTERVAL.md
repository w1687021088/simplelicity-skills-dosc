# 密码重用间隔 PASSWORD REUSE INTERVAL

`PASSWORD REUSE INTERVAL` 以时间为维度限制密码重用，规定在指定天数内不允许重复使用旧密码。与 `PASSWORD HISTORY`（以次数为维度）不同，它关注的是时间窗口：无论密码在这段时间内修改了多少次，只要在这个时间范围内用过的密码都不能重复使用。

---

## 语法

```sql
-- 创建用户时设置
CREATE USER 'user'@'host' IDENTIFIED BY 'password'
    PASSWORD REUSE INTERVAL N DAY;

-- 修改已有用户
ALTER USER 'user'@'host' PASSWORD REUSE INTERVAL N DAY;

-- 不限制（0 = 无时间间隔限制）
ALTER USER 'user'@'host' PASSWORD REUSE INTERVAL 0 DAY;

-- 恢复使用全局设置
ALTER USER 'user'@'host' PASSWORD REUSE INTERVAL DEFAULT;
```

---

## 全局默认设置

```sql
-- 查看全局密码重用间隔
SHOW VARIABLES LIKE 'password_reuse_interval';
-- 默认：0（无限制，可以立即重用旧密码）

-- 设置全局重用间隔为365天
SET GLOBAL password_reuse_interval = 365;
SET PERSIST password_reuse_interval = 365;  -- 持久化

-- 设置后，所有使用 DEFAULT 重用策略的账户的旧密码在365天内不可重用
```

---

## 账户级重用间隔设置

```sql
-- 配置人工账号：180天内不能重用旧密码
CREATE USER 'staff_user'@'%'
    IDENTIFIED BY 'StaffP@ss001'
    PASSWORD EXPIRE INTERVAL 90 DAY
    PASSWORD REUSE INTERVAL 180 DAY;
-- 90天后强制修改，新密码不能是180天内用过的任何密码

-- 修改已有账户
ALTER USER 'alice'@'%' PASSWORD REUSE INTERVAL 365 DAY;

-- 取消账户级限制（不受任何时间间隔限制）
ALTER USER 'alice'@'%' PASSWORD REUSE INTERVAL 0 DAY;
-- 注意：0 DAY 是明确不限制，与 DEFAULT 不同
-- DEFAULT 是跟随全局 password_reuse_interval 设置

-- 恢复使用全局设置
ALTER USER 'alice'@'%' PASSWORD REUSE INTERVAL DEFAULT;
```

---

## PASSWORD HISTORY 与 PASSWORD REUSE INTERVAL 的区别

| 维度 | PASSWORD HISTORY N | PASSWORD REUSE INTERVAL N DAY |
|------|-------------------|-------------------------------|
| 限制基准 | 最近 N 次修改的密码 | 过去 N 天内使用过的密码 |
| 全局变量 | `password_history` | `password_reuse_interval` |
| 适合场景 | 频繁修改密码的账号 | 按时间周期管理密码的账号 |
| 例子 | 不能用最近5次中的任何一个 | 不能用365天内用过的任何一个 |

---

## 两者同时设置时的交互

```sql
-- 同时设置时，两个条件都必须满足（取更严格的）
ALTER USER 'alice'@'%'
    PASSWORD HISTORY 5
    PASSWORD REUSE INTERVAL 180 DAY;

-- 密码拒绝条件（满足任一即拒绝）：
-- 1. 该密码在最近5次修改记录中存在
-- 2. 该密码在过去180天内曾被使用

-- 场景示例：
-- alice 今天修改了密码（第1次）
-- 3天后又改了密码（第2次）
-- 再过3天又改了密码（第3次）
-- 此时尝试改回第1次的密码：
--   HISTORY 检查：第1次密码在最近3次修改中，被拒绝 ✗
-- 即使6天内不在180天内的时间限制范围：
--   INTERVAL 检查：6天 < 180天，也被拒绝 ✗
-- 两个条件都拒绝
```

## 历史记录与时间间隔的存储

```sql
-- 两个策略都依赖 mysql.password_history 表
-- 该表存储历史密码的哈希值和修改时间戳

SELECT User, Host, Password_timestamp
FROM mysql.password_history
WHERE User = 'alice'
ORDER BY Password_timestamp DESC;

-- MySQL 根据时间戳判断哪些历史密码在 REUSE INTERVAL 范围内
-- 根据行数判断哪些在 HISTORY 范围内

-- 历史表的清理：
-- 当账户没有 HISTORY 限制且没有 INTERVAL 限制时，历史记录不会自动清理
-- DBA 可以手动清理（如账户离职后清理其历史）：
DELETE FROM mysql.password_history WHERE User = 'former_employee' AND Host = '%';
```

## 适用场景

- **年度安全审计**：设置 365 天重用间隔，确保用户每年都在使用全新的密码
- **高频修改环境**：在高安全环境中，配合 90 天过期 + 365 天重用间隔，防止快速循环修改密码
- **合规要求**：PCI DSS 要求密码不能重用最近12次使用的密码（可用 HISTORY 12 或 INTERVAL 365 DAY 实现）

---

## 常见问题

**用户90天后密码过期，要求修改，但是设置了365天重用间隔，用户拿不到新密码怎么办？**

这是策略配置冲突的问题。正常来说，用户的密码在90天的使用周期内只被记录一次，365天内不能重用这一次旧密码，所以用户只需要设置一个新密码（不同于旧密码）即可。密码重用间隔不是"不能用之前365天内的任何字符串"，而是"不能用这段时间内在该账号上实际使用过的密码哈希"。只要新密码与旧密码不同，就可以通过。

---

## 注意事项

- `PASSWORD REUSE INTERVAL 0 DAY` 与 `PASSWORD REUSE INTERVAL DEFAULT` 含义不同：前者明确表示不限制（即使全局设置了间隔也不受影响），后者表示跟随全局 `password_reuse_interval` 变量。
- 密码历史表（`mysql.password_history`）在主从复制时会被复制到从库，确保密码策略在整个集群中一致。

---

## 总结

`PASSWORD REUSE INTERVAL N DAY` 限制 N 天内使用过的密码不能重复设置，全局变量为 `password_reuse_interval`（默认 0 = 不限制）。与 `PASSWORD HISTORY`（按次数）同时设置时两者都须满足。历史记录存储在 `mysql.password_history` 表（含时间戳）。账户级 `INTERVAL 0 DAY` 明确不限制（覆盖全局），`INTERVAL DEFAULT` 跟随全局设置。
