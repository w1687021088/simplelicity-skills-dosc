# 密码过期策略 PASSWORD EXPIRE

密码过期（Password Expiration）是强制用户定期更新密码的机制。密码过期后，用户仍然可以连接到 MySQL，但只能执行 `SET PASSWORD` / `ALTER USER` 修改密码的操作，其他所有操作（包括 SELECT）都会报错，直到设置新密码为止。

---

## 过期策略的三种配置层次

```
全局策略（default_password_lifetime）
    ↓ 被账户级策略覆盖
账户级策略（ALTER USER ... PASSWORD EXPIRE INTERVAL）
    ↓ 影响
账户实际过期时间（mysql.user.password_last_changed + 策略天数）
```

---

## 全局过期策略

```sql
-- 查看全局默认密码过期天数
SHOW VARIABLES LIKE 'default_password_lifetime';
-- 默认：0（永不过期）

-- 设置全局默认：90天过期
SET GLOBAL default_password_lifetime = 90;
SET PERSIST default_password_lifetime = 90;  -- 持久化

-- 设置后，所有使用 DEFAULT 过期策略的账户都会在90天后过期
-- 已存在的账户需要确认其账户级策略
```

---

## 账户级过期策略

```sql
-- 创建时设置密码过期策略
-- 永不过期（适合服务账号、应用账号）
CREATE USER 'service_app'@'%'
    IDENTIFIED BY 'ServiceP@ss123'
    PASSWORD EXPIRE NEVER;

-- 指定间隔天数过期（覆盖全局设置）
CREATE USER 'staff_user'@'%'
    IDENTIFIED BY 'StaffP@ss123'
    PASSWORD EXPIRE INTERVAL 90 DAY;

-- 使用全局策略（明确声明使用全局设置）
CREATE USER 'regular_user'@'%'
    IDENTIFIED BY 'RegularP@ss123'
    PASSWORD EXPIRE DEFAULT;

-- 修改已有账户的过期策略
ALTER USER 'alice'@'%' PASSWORD EXPIRE NEVER;
ALTER USER 'alice'@'%' PASSWORD EXPIRE INTERVAL 180 DAY;
ALTER USER 'alice'@'%' PASSWORD EXPIRE DEFAULT;
```

---

## 立即使密码过期

```sql
-- 立即使账户密码过期（用户下次登录必须修改密码）
ALTER USER 'alice'@'%' PASSWORD EXPIRE;

-- 批量使所有非系统账号立即过期（如强制密码轮换事件后）
SELECT CONCAT('ALTER USER ''', User, '''@''', Host, ''' PASSWORD EXPIRE;') AS sql_stmt
FROM mysql.user
WHERE User NOT IN ('root', 'mysql.sys', 'mysql.infoschema', 'mysql.session')
  AND User NOT LIKE 'mysql.%';
-- 生成 SQL 后执行

-- 查看账户密码过期状态
SELECT User, Host, password_expired, password_last_changed, password_lifetime
FROM mysql.user
WHERE User NOT LIKE 'mysql.%';
-- password_expired: Y（已过期）/ N（未过期）
-- password_last_changed：最近一次修改密码的时间
-- password_lifetime：账户级过期天数（NULL = 使用全局 default_password_lifetime）
```

## 密码过期后的连接行为

```sql
-- 密码过期后，用户依然可以连接到 MySQL，但连接后处于"沙盒模式"（sandbox mode）
-- 在沙盒模式下，只能执行修改密码的语句，其他任何操作都报错

-- 过期用户登录后执行 SELECT：
SELECT 1;
-- ERROR 1820 (HY000): You must reset your password using ALTER USER statement
-- before executing this statement.

-- 在沙盒模式下修改密码
ALTER USER CURRENT_USER() IDENTIFIED BY 'NewSecureP@ss1';
-- 修改成功后，连接恢复正常（不需要断开重连）
```

## 查看账户过期状态

```sql
-- 查看哪些账户密码已过期
SELECT User, Host, password_expired, password_last_changed,
       CASE
           WHEN password_lifetime IS NULL AND @@global.default_password_lifetime > 0
               THEN DATE_ADD(password_last_changed, INTERVAL @@global.default_password_lifetime DAY)
           WHEN password_lifetime IS NOT NULL AND password_lifetime > 0
               THEN DATE_ADD(password_last_changed, INTERVAL password_lifetime DAY)
           ELSE NULL
       END AS estimated_expire_date
FROM mysql.user
WHERE User NOT LIKE 'mysql.%' AND User != 'root';
```

## 适用场景

- **人工账号**：配置90-180天的密码过期策略，定期强制更新密码
- **安全事件响应**：发现可疑活动后，立即使相关账户密码过期（`PASSWORD EXPIRE`）
- **服务账号**：设置 `PASSWORD EXPIRE NEVER`，避免应用因密码过期而无法连接

---

## 常见问题

**密码过期后，应用程序使用该账号连接会如何？**

应用程序会收到 MySQL 错误码 `1820`（`ER_MUST_CHANGE_PASSWORD`）或连接建立后的第一条 SQL 报错。大多数连接池不会自动处理这种情况，导致应用无法访问数据库。因此服务账号应设置 `PASSWORD EXPIRE NEVER`，只对人工账号设置过期策略。

---

## 注意事项

- 使用 `PASSWORD EXPIRE NEVER` 的服务账号，应通过其他手段（如定期安全审计、限制 IP 来源）确保账号安全，而不是单纯依赖密码过期来驱动安全更新。
- 密码过期策略与密码历史限制（PASSWORD HISTORY）配合使用效果更佳——过期后强制修改密码，历史限制防止修改回旧密码。

---

## 总结

密码过期通过三种方式控制：全局 `default_password_lifetime`（默认 0 表示不过期）、账户级 `PASSWORD EXPIRE INTERVAL N DAY`、立即过期 `PASSWORD EXPIRE`。密码过期后账户进入沙盒模式，只能执行密码修改操作，执行 `ALTER USER CURRENT_USER() IDENTIFIED BY 'new_pass'` 后恢复正常。服务账号应设置 `PASSWORD EXPIRE NEVER`，人工账号推荐配置 90-180 天过期。
