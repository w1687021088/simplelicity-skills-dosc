# 连接失败锁定 FAILED_LOGIN_ATTEMPTS

`FAILED_LOGIN_ATTEMPTS` 是 MySQL 8.0.19 引入的账户安全特性，设置连续登录失败多少次后自动锁定账户。这是防范暴力破解密码攻击的重要机制，锁定后需要 `ACCOUNT UNLOCK` 或等待 `PASSWORD_LOCK_TIME` 设定的时间自动解锁。

---

## 语法

```sql
-- 创建用户时设置
CREATE USER 'user'@'host' IDENTIFIED BY 'password'
    FAILED_LOGIN_ATTEMPTS N;

-- 修改已有用户
ALTER USER 'user'@'host' FAILED_LOGIN_ATTEMPTS N;

-- 取消失败尝试锁定策略（0 = 不限制）
ALTER USER 'user'@'host' FAILED_LOGIN_ATTEMPTS 0;
```

---

## 基本示例

```sql
-- 创建一个连续3次登录失败后锁定的账户
CREATE USER 'alice'@'%'
    IDENTIFIED BY 'AliceP@ss123'
    FAILED_LOGIN_ATTEMPTS 3
    PASSWORD_LOCK_TIME 1;  -- 锁定1天后自动解锁

-- 修改已有账户（常见实际配置）
ALTER USER 'staff_user'@'%'
    FAILED_LOGIN_ATTEMPTS 5
    PASSWORD_LOCK_TIME 2;  -- 5次失败后锁定，2天后自动解锁

-- 高安全配置：3次失败后永久锁定（需手动解锁）
ALTER USER 'admin_user'@'%'
    FAILED_LOGIN_ATTEMPTS 3
    PASSWORD_LOCK_TIME UNBOUNDED;
```

## 连续失败的计数机制

```sql
-- 失败计数存储在 USER_ATTRIBUTES JSON 中
SELECT User, Host, USER_ATTRIBUTES
FROM information_schema.USER_ATTRIBUTES
WHERE User = 'alice';
-- USER_ATTRIBUTES 示例：
-- {"Password_locking": {"failed_login_attempts": 2, "password_lock_days": 1}}
-- failed_login_attempts: 当前已失败次数（会累积到触发锁定）

-- 重要：只有"连续失败"才计数
-- 只要有一次成功登录，计数器重置为 0
-- 例如：失败2次后成功登录1次，计数器归零，再失败需要重新从1开始
```

## 失败锁定与手动锁定的区别

```sql
-- ACCOUNT LOCK（手动锁定）：
-- 存储在 mysql.user.account_locked = 'Y'
-- 连接时报错：ERROR 3118: Account is locked.

-- FAILED_LOGIN_ATTEMPTS 触发的锁定：
-- 存储在 USER_ATTRIBUTES 的 Password_locking 字段
-- 连接时报错：ERROR 3955: Access denied for user 'alice'@'%'.
-- Account is blocked for N day(s) (N day(s) remaining)
-- because of N consecutive failed logins.

-- 两种锁定都通过 ACCOUNT UNLOCK 解除
ALTER USER 'alice'@'%' ACCOUNT UNLOCK;
-- ACCOUNT UNLOCK 同时清除失败登录计数器
```

## 查看账户锁定状态

```sql
-- 查看账户是否因失败次数被锁定
SELECT User, Host, account_locked, USER_ATTRIBUTES
FROM information_schema.USER_ATTRIBUTES
WHERE User = 'alice';

-- 或通过 mysql.user 和 USER_ATTRIBUTES 联合查询
SELECT u.User, u.Host, u.account_locked,
       JSON_EXTRACT(ua.USER_ATTRIBUTES, '$.Password_locking.failed_login_attempts')
           AS failed_attempts,
       JSON_EXTRACT(ua.USER_ATTRIBUTES, '$.Password_locking.password_lock_days')
           AS lock_days
FROM mysql.user u
JOIN information_schema.USER_ATTRIBUTES ua USING(User, Host)
WHERE u.User = 'alice';
```

## 失败锁定后的解锁

```sql
-- 方法1：手动解锁（清除锁定状态和失败计数）
ALTER USER 'alice'@'%' ACCOUNT UNLOCK;

-- 方法2：等待 PASSWORD_LOCK_TIME 设定的时间自动解锁
-- 如果设置了 PASSWORD_LOCK_TIME 1（1天），1天后自动恢复
-- 如果设置了 PASSWORD_LOCK_TIME UNBOUNDED，必须手动解锁

-- 解锁后验证
SELECT User, HOST, account_locked, USER_ATTRIBUTES
FROM information_schema.USER_ATTRIBUTES
WHERE User = 'alice';
-- account_locked 应为 N，USER_ATTRIBUTES 中失败计数清零
```

## 与 connection_control 插件的区别

```sql
-- MySQL 还有一个 connection_control 插件（单独安装）提供类似功能
-- INSTALL PLUGIN CONNECTION_CONTROL SONAME 'connection_control.so';

-- connection_control 插件：
-- 在失败 N 次后增加连接延迟（不直接锁定账户）
-- 通过时间惩罚减缓暴力破解

-- FAILED_LOGIN_ATTEMPTS：
-- 在失败 N 次后直接锁定账户

-- 两者可以同时使用（互补）：
-- connection_control：减缓攻击速度
-- FAILED_LOGIN_ATTEMPTS：最终锁定账户
```

## 适用场景

- **互联网暴露账户**：面向公网的 MySQL 账户应配置失败锁定，防止暴力破解
- **人工账号**：DBA、开发人员的个人账号配置适当的失败次数限制
- **高价值账户**：对访问核心业务数据的账户设置更严格的失败限制（如3次）

---

## 常见问题

**应用程序配置了错误密码，频繁连接导致账户被锁定，怎么处理？**

立即执行 `ALTER USER 'app_user'@'%' ACCOUNT UNLOCK` 解锁。然后检查并修正应用程序的数据库连接配置，确保密码正确。对于应用程序账号，可以适当提高 `FAILED_LOGIN_ATTEMPTS` 的值（如设置20次），因为连接池的重试机制可能在短时间内产生多次失败尝试。

---

## 注意事项

- `FAILED_LOGIN_ATTEMPTS` 需要与 `PASSWORD_LOCK_TIME` 配合使用才有意义：如果只设置 FAILED_LOGIN_ATTEMPTS 但不设置 PASSWORD_LOCK_TIME，达到失败次数后不会触发锁定（没有设定锁定时长）。
- 在主从复制环境中，失败登录计数（`USER_ATTRIBUTES`）的变更是通过账户修改语句复制到从库的，但实时的"当前失败次数"状态只在发生登录的主库上更新，从库不会同步登录失败事件本身。

---

## 总结

`FAILED_LOGIN_ATTEMPTS N` 设置连续登录失败 N 次后触发账户锁定，需配合 `PASSWORD_LOCK_TIME` 使用。失败计数在一次成功登录后自动重置。锁定状态存储在 `USER_ATTRIBUTES` 的 `Password_locking` 字段。`ACCOUNT UNLOCK` 解除锁定并清零计数。应用程序账号应设置较高的失败次数（防止连接池触发误锁），人工账号应设置较低值（增强安全性）。
