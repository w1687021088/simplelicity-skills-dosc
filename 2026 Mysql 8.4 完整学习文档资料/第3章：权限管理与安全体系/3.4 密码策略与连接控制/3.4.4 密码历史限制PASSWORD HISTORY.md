# 密码历史限制 PASSWORD HISTORY

`PASSWORD HISTORY` 限制用户在修改密码时不能重复使用最近 N 次使用过的密码。这个机制配合密码过期策略使用，防止用户在密码到期后把新密码改回旧密码（循环使用），从而真正实现密码的定期更新。

---

## 语法

```sql
-- 创建用户时设置历史限制
CREATE USER 'user'@'host' IDENTIFIED BY 'password'
    PASSWORD HISTORY N;

-- 修改已有用户的历史限制
ALTER USER 'user'@'host' PASSWORD HISTORY N;

-- 恢复使用全局默认设置
ALTER USER 'user'@'host' PASSWORD HISTORY DEFAULT;
```

---

## 全局默认历史限制

```sql
-- 查看全局密码历史数量限制
SHOW VARIABLES LIKE 'password_history';
-- 默认：0（不限制，可以重复使用任何旧密码）

-- 设置全局历史限制（不能重复使用最近5次的密码）
SET GLOBAL password_history = 5;
SET PERSIST password_history = 5;  -- 持久化

-- 设置后，所有使用 DEFAULT 历史策略的账户都受此限制
```

---

## 账户级历史限制

```sql
-- 限制不能重复使用最近3次密码
CREATE USER 'alice'@'%'
    IDENTIFIED BY 'AliceP@ss001'
    PASSWORD HISTORY 3;

-- 修改为不限制（覆盖全局限制）
ALTER USER 'alice'@'%' PASSWORD HISTORY 0;

-- 修改为限制最近6次
ALTER USER 'alice'@'%' PASSWORD HISTORY 6;

-- 使用全局设置
ALTER USER 'alice'@'%' PASSWORD HISTORY DEFAULT;
```

---

## 历史限制的工作机制

```sql
-- 密码历史存储在 mysql.password_history 表中
-- 每次成功修改密码时，旧密码的哈希值被记录到历史表

-- 查看某账户的密码历史记录
SELECT User, Host, Password_timestamp
FROM mysql.password_history
WHERE User = 'alice'
ORDER BY Password_timestamp DESC;
-- 每行代表一次密码修改记录（存储的是哈希值）

-- 当 alice 尝试将密码改为历史中的旧密码时：
ALTER USER 'alice'@'%' IDENTIFIED BY 'AliceP@ss001' REPLACE 'AliceP@ss004';
-- ERROR 3638 (HY000): Cannot use these credentials for 'alice@%' because
-- they contradict the password history policy.
```

## 结合密码过期策略使用

```sql
-- 完整的密码策略配置示例（防止密码循环）：
CREATE USER 'staff_member'@'%'
    IDENTIFIED BY 'InitialP@ss123'
    PASSWORD EXPIRE INTERVAL 90 DAY  -- 90天后过期
    PASSWORD HISTORY 5               -- 不能重复使用最近5次密码
    PASSWORD REUSE INTERVAL 365 DAY; -- 或365天内的密码不能重复使用
-- PASSWORD HISTORY 和 PASSWORD REUSE INTERVAL 同时设置时，取更严格的那个

-- 效果：
-- 每90天必须修改一次密码
-- 不能使用过去5次内的任何密码
-- 也不能使用365天内使用过的任何密码
-- 两者都满足才允许设置新密码
```

## 查看账户的历史策略配置

```sql
-- 查看账户历史策略配置
SELECT User, Host, password_history, password_reuse_interval
FROM mysql.user
WHERE User = 'staff_member';
-- password_history: NULL（使用全局设置）或 具体数字（账户级设置）
-- password_reuse_interval: NULL（使用全局设置）或 具体天数（账户级设置）

-- 查看全局设置
SHOW VARIABLES LIKE 'password_history';
SHOW VARIABLES LIKE 'password_reuse_interval';
```

## 管理员重置密码是否受历史限制影响

```sql
-- 有 CREATE USER 权限的管理员修改其他用户密码时，默认也受历史限制
-- 但可以通过以下方式绕过（紧急情况）：

-- 方法1：临时将账户历史限制设为0
ALTER USER 'alice'@'%' PASSWORD HISTORY 0;
ALTER USER 'alice'@'%' IDENTIFIED BY 'OldPassword123!';
ALTER USER 'alice'@'%' PASSWORD HISTORY 5;  -- 恢复原设置

-- 方法2：清空密码历史记录
DELETE FROM mysql.password_history WHERE User = 'alice' AND Host = '%';
FLUSH PRIVILEGES;  -- 清空历史表后需要刷新
-- 然后正常修改密码（无历史可检查）
```

## 适用场景

- **人工账号密码管理**：配合 PASSWORD EXPIRE，防止用户循环使用同一组密码
- **高安全环境**：金融、政务系统要求密码历史限制（如限制最近12次）
- **合规要求**：满足 PCI DSS、HIPAA 等标准对密码不重用的要求

---

## 常见问题

**PASSWORD HISTORY 5 和 PASSWORD REUSE INTERVAL 365 DAY 同时设置，哪个生效？**

两者同时生效，取更严格的交集。密码被拒绝只要满足以下任一条件：该密码在最近 5 次密码变更中使用过，或者该密码在过去 365 天内使用过。两个限制都通过才允许设置新密码。

---

## 注意事项

- `mysql.password_history` 表存储历史密码的哈希值（不是明文），旧哈希与新密码的哈希比对时使用相同的算法（`caching_sha2_password` 或 `mysql_native_password`）。如果账户切换了认证插件，历史哈希格式不同，可能无法检查旧密码——建议维持统一的认证插件。
- 历史记录的数量会持续增长（每次修改密码新增一条记录）。当账户级历史限制为 N 时，MySQL 会自动清理超出 N 条的历史记录，但全局 `password_history = 0` 时不会自动清理，需要 DBA 定期维护。

---

## 总结

`PASSWORD HISTORY N` 限制用户不能重复使用最近 N 次的密码，历史记录存储在 `mysql.password_history` 表（存哈希值，非明文）。全局控制变量为 `password_history`（默认 0 不限制）。账户级设置优先于全局设置，`PASSWORD HISTORY DEFAULT` 恢复使用全局值。与 `PASSWORD REUSE INTERVAL` 同时设置时两者都须满足，取更严格的。
