# 锁定时间 PASSWORD_LOCK_TIME

`PASSWORD_LOCK_TIME` 指定账户因连续登录失败（达到 `FAILED_LOGIN_ATTEMPTS` 设定的次数）后，自动锁定多长时间。可以设定为具体天数（到期自动解锁）或 `UNBOUNDED`（永久锁定，必须手动解锁）。该特性在 MySQL 8.0.19 中引入，与 `FAILED_LOGIN_ATTEMPTS` 配合构成完整的登录失败锁定机制。

---

## 语法

```sql
-- 创建用户时设置
CREATE USER 'user'@'host' IDENTIFIED BY 'password'
    FAILED_LOGIN_ATTEMPTS N
    PASSWORD_LOCK_TIME {N | UNBOUNDED};

-- 修改已有用户
ALTER USER 'user'@'host'
    FAILED_LOGIN_ATTEMPTS N
    PASSWORD_LOCK_TIME {N | UNBOUNDED};

-- 取消锁定时间设置
ALTER USER 'user'@'host' PASSWORD_LOCK_TIME 0;
```

---

## 锁定时间选项

| 设置值 | 说明 |
|-------|------|
| `PASSWORD_LOCK_TIME 0` | 不锁定（即使设置了 FAILED_LOGIN_ATTEMPTS，达到次数也不锁）|
| `PASSWORD_LOCK_TIME N`（N > 0）| 锁定 N 天后自动解锁 |
| `PASSWORD_LOCK_TIME UNBOUNDED` | 永久锁定，只能通过 ACCOUNT UNLOCK 手动解锁 |

---

## 基本示例

```sql
-- 配置1：5次失败后锁定1天，1天后自动解锁（适合普通员工账号）
CREATE USER 'staff'@'%'
    IDENTIFIED BY 'StaffP@ss1'
    FAILED_LOGIN_ATTEMPTS 5
    PASSWORD_LOCK_TIME 1;

-- 配置2：3次失败后永久锁定（适合高权限账号，需人工解锁）
CREATE USER 'dba_user'@'localhost'
    IDENTIFIED BY 'DBAP@ss1'
    FAILED_LOGIN_ATTEMPTS 3
    PASSWORD_LOCK_TIME UNBOUNDED;

-- 配置3：10次失败后锁定2天（适合应用程序账号，容错空间大）
ALTER USER 'app_user'@'%'
    FAILED_LOGIN_ATTEMPTS 10
    PASSWORD_LOCK_TIME 2;

-- 验证配置
SELECT User, Host, USER_ATTRIBUTES
FROM information_schema.USER_ATTRIBUTES
WHERE User IN ('staff', 'dba_user', 'app_user');
```

## 锁定时间的自动倒计时

```sql
-- 账户被锁定后，连接时会看到锁定剩余时间：
-- ERROR 3955 (HY000): Access denied for user 'staff'@'%'.
-- Account is blocked for 1 day(s) (1 day(s) remaining) because of 5 consecutive failed logins.

-- 锁定状态存储在 USER_ATTRIBUTES 中，记录锁定的时间戳
-- MySQL 通过比较当前时间与锁定时间戳 + LOCK_TIME 计算剩余时间

-- 查看锁定详情
SELECT User, Host,
    JSON_PRETTY(USER_ATTRIBUTES) AS attributes
FROM information_schema.USER_ATTRIBUTES
WHERE User = 'staff';
-- Password_locking 字段中包含：
-- failed_login_count: 5（已失败次数）
-- password_lock_days: 1（锁定天数配置）
-- auto_unlock_at: 2026-03-15 10:30:00（预计自动解锁时间）
```

## 手动解锁（提前解除锁定）

```sql
-- 无论 PASSWORD_LOCK_TIME 是具体天数还是 UNBOUNDED，都可以手动解锁
ALTER USER 'staff'@'%' ACCOUNT UNLOCK;

-- ACCOUNT UNLOCK 的效果：
-- 1. 清除账户锁定状态
-- 2. 重置失败登录计数器（从0开始重新计数）
-- 3. 清除 USER_ATTRIBUTES 中的 Password_locking 锁定记录

-- 解锁后验证
SELECT User, Host, account_locked, USER_ATTRIBUTES
FROM information_schema.USER_ATTRIBUTES
WHERE User = 'staff';
-- account_locked: N（已解锁）
-- USER_ATTRIBUTES 的 Password_locking 记录已清除
```

## 不同场景的推荐配置

```sql
-- 场景1：面向互联网的管理账号（高安全）
ALTER USER 'admin'@'%'
    FAILED_LOGIN_ATTEMPTS 3
    PASSWORD_LOCK_TIME UNBOUNDED;
-- 3次失败永久锁定，需人工干预解锁，防止远程暴力破解

-- 场景2：内网员工账号（平衡安全与便利）
ALTER USER 'employee'@'192.168.%.%'
    FAILED_LOGIN_ATTEMPTS 5
    PASSWORD_LOCK_TIME 1;
-- 5次失败锁定1天，1天后自动恢复，不会因忘记密码长期被锁

-- 场景3：应用程序账号（宽松，防止误触发）
ALTER USER 'webapp'@'10.0.0.%'
    FAILED_LOGIN_ATTEMPTS 20
    PASSWORD_LOCK_TIME 0;
-- 20次失败（连接池重试），但 LOCK_TIME=0 实际上不锁定
-- 仅用于监控（通过 USER_ATTRIBUTES 记录异常失败）

-- 场景4：需要防暴力破解但不想永久锁定
ALTER USER 'service'@'%'
    FAILED_LOGIN_ATTEMPTS 5
    PASSWORD_LOCK_TIME 7;  -- 7天后自动解锁
```

## PASSWORD_LOCK_TIME 与 ACCOUNT LOCK 的区别

| 维度 | PASSWORD_LOCK_TIME 触发的锁定 | ACCOUNT LOCK 手动锁定 |
|------|------------------------------|----------------------|
| 触发方式 | 连续登录失败自动触发 | 手动 ALTER USER ... ACCOUNT LOCK |
| 自动解锁 | 支持（设置天数时）| 不支持（必须手动 ACCOUNT UNLOCK）|
| 解锁方式 | 自动到期 或 ACCOUNT UNLOCK | 只能 ACCOUNT UNLOCK |
| 错误信息 | 包含剩余锁定时间 | "Account is locked" |

---

## 适用场景

- **暴力破解防护**：所有对外开放的账户都应配置 FAILED_LOGIN_ATTEMPTS + PASSWORD_LOCK_TIME
- **安全审计**：UNBOUNDED 配置确保异常登录事件必须经过安全审计才能恢复
- **自动恢复**：内网账号使用短时间锁定（1天），自动恢复避免影响工作效率

---

## 常见问题

**PASSWORD_LOCK_TIME 设置为 0，但 FAILED_LOGIN_ATTEMPTS 也设置了，有什么效果？**

实际上不会触发锁定。`PASSWORD_LOCK_TIME 0` 相当于"失败 N 次后锁定 0 天"，因为锁定时长为 0，所以达到失败次数时不会实际执行锁定。这种配置没有实际的锁定保护效果，通常不建议这样设置。如果要完全取消失败锁定策略，应将 `FAILED_LOGIN_ATTEMPTS` 也设置为 0。

---

## 注意事项

- 如果只设置了 `FAILED_LOGIN_ATTEMPTS` 而没有设置 `PASSWORD_LOCK_TIME`，MySQL 的默认 `PASSWORD_LOCK_TIME` 是 0，即达到失败次数后不锁定。必须两个参数都设置才能让自动锁定机制生效。
- `UNBOUNDED` 锁定在高安全场景下很有价值，但需要有完善的账户解锁流程（谁有权解锁、如何申请解锁），否则可能导致账户长期无法使用影响业务。

---

## 总结

`PASSWORD_LOCK_TIME N` 设置因登录失败被锁定后的持续时间：N 天后自动解锁，`UNBOUNDED` 永久锁定（只能手动解锁）。必须与 `FAILED_LOGIN_ATTEMPTS` 配合才能触发自动锁定。锁定状态通过 `ALTER USER ... ACCOUNT UNLOCK` 手动提前解除。高权限账号推荐 `UNBOUNDED`（防暴力破解），普通员工账号推荐 1-7 天（平衡安全与可用性），应用账号需适当放宽 FAILED_LOGIN_ATTEMPTS 值。
