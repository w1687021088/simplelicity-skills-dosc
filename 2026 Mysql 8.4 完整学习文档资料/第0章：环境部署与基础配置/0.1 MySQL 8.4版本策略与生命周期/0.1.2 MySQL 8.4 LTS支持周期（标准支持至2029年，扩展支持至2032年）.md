# MySQL 8.4 LTS 支持周期

选择数据库版本不只是当下能不能用的问题，更要考虑未来几年内这个版本还能不能得到官方支持、安全补丁和 bug 修复。MySQL 8.4 作为第一个正式的 LTS 版本，其支持周期是做中长期技术规划的重要依据。

---

## 支持周期的两个阶段

Oracle 对 MySQL 的官方支持分为两个阶段：

**标准支持（Premier Support）**

在标准支持阶段，Oracle 提供：
- 新 bug 修复（Patch Set Update）
- 安全漏洞修复（Security Patch Update）
- 产品文档更新
- 24/7 技术支持服务（企业版订阅用户）

**扩展支持（Extended Support）**

标准支持结束后，可以付费购买扩展支持，获得：
- 重大安全漏洞修复（Critical Patch Update）
- 有限度的 bug 修复
- 技术支持持续可用

扩展支持通常需要额外付费，适合还没有完成下一代系统迁移、需要更多缓冲时间的用户。

---

## MySQL 8.4 的具体时间节点

| 阶段 | 截止日期 | 说明 |
|------|---------|------|
| GA 发布（General Availability） | 2024-04-30 | 正式可用于生产环境 |
| 标准支持结束 | 2029-04-30 | 约 5 年标准支持 |
| 扩展支持结束 | 2032-04-30 | 约 3 年额外扩展支持 |
| 持续支持（Sustained Support） | 2032 年后按需 | 仅限企业合同用户 |

从 2024 年 4 月发布到 2032 年 4 月扩展支持结束，MySQL 8.4 LTS 拥有完整的 8 年官方保障周期。

## 与其他版本的支持周期对比

| MySQL 版本 | 类型 | GA 日期 | EOL 日期 | 支持年限 |
|-----------|------|---------|---------|---------|
| MySQL 5.7 | 普通 GA | 2015-10 | 2023-10 | 8 年 |
| MySQL 8.0 | 普通 GA（后变为 bugfix 系列）| 2018-04 | 2026-04 | 8 年 |
| MySQL 8.4 | LTS | 2024-04 | 2032-04 | 8 年 |
| MySQL 8.1~8.3 | Innovation | 2023-07 ~ 2024-01 | 短期 | < 1 年 |

MySQL 8.0 和 8.4 的支持周期在总年限上相近，但 8.0 的 EOL 已经逼近（2026 年 4 月），而 8.4 的标准支持刚开始不久。

## 支持周期对技术决策的影响

**新系统选型**

2026 年及以后启动的新项目，应当直接以 MySQL 8.4 LTS 为基线，无需考虑 8.0。8.4 的标准支持到 2029 年，意味着一个 2026 年上线的系统，至少有 3 年不需要考虑数据库版本迁移问题，且有额外 3 年扩展支持兜底。

**已有 8.0 系统的迁移窗口**

8.0 EOL 是 2026 年 4 月 30 日，到期后不再有安全补丁。对于金融、医疗等有合规要求的系统，使用 EOL 版本可能违反安全审计要求。迁移窗口实际上已经在倒计时，2026 年上半年前完成迁移是合理目标。

**扩展支持的使用场景**

2029 年标准支持结束后，如果因为某些特殊原因无法立即迁移到下一个 LTS 版本，扩展支持提供了 3 年的缓冲期。但扩展支持需要额外费用，社区版用户（Community Edition）通常不能享受，这是选择企业版（Enterprise Edition）的理由之一。

## 常见问题

**社区版（Community Edition）和企业版（Enterprise Edition）的支持周期一样吗？**

版本发布节奏和 EOL 日期是一样的，但服务内容不同。社区版用户的支持主要依靠官方 bug 追踪系统和社区论坛，不享有 Oracle 官方 24/7 技术支持和某些扩展支持服务。企业版用户可以在扩展支持阶段获得更完整的官方保障。

**补丁版本（如 8.4.1、8.4.2）多久发布一次？**

LTS 系列的补丁版本通常每季度发布一次，包含 bug 修复和安全补丁。建议关注官方 Release Notes，在测试环境验证后跟进升级，不要因为"怕升级出问题"就一直停留在初始 GA 版本上。

**如果标准支持期内发现了严重安全漏洞，Oracle 一定会修复吗？**

是的，在标准支持期内，安全漏洞属于高优先级修复项目。Oracle 每季度发布 CPU（Critical Patch Update），覆盖已知安全漏洞。高危漏洞有时会在季度更新之间发布紧急补丁。

## 注意事项

- 支持周期的截止日期以 Oracle 官方发布的信息为准，可以在 Oracle Lifetime Support Policy 文档中查到最新数据，本文档中的日期基于 2024 年发布时的官方声明。
- 使用 EOL 版本不代表数据库立刻停止工作，只是不再有官方安全更新。实际风险取决于业务对安全漏洞的暴露程度，公网可访问的数据库风险更高。
- 从 8.4 升级到未来的下一个 LTS 版本时，同样需要规划迁移时间窗口，提前测试兼容性，不要等到 EOL 前才开始。

## 总结

MySQL 8.4 LTS 的支持周期从 2024 年 4 月 GA 开始，标准支持覆盖到 2029 年 4 月，扩展支持延伸至 2032 年 4 月，总计 8 年的官方保障。这个周期足以支撑一个系统从建设到下一个迭代周期的完整生命周期。对于 2026 年的数据库技术规划，MySQL 8.4 是唯一一个能同时满足"当前可用"和"长期有保障"两个条件的版本选择。
