# my.cnf 配置文件结构（全局、服务端、客户端段）

MySQL 的配置文件是整个数据库实例行为的基础控制文件。理解它的结构和各段的作用，是正确配置 MySQL 的前提。配置写错位置会导致参数不生效，甚至服务无法启动，这是新手常见的坑。

---

## 配置文件的位置

MySQL 启动时会按固定顺序依次读取多个配置文件，后读取的文件中同名参数会覆盖前面的值：

**Linux 系统读取顺序（从先到后）：**

| 优先级 | 文件路径 | 说明 |
|--------|---------|------|
| 1（最低）| `/etc/my.cnf` | 系统全局配置 |
| 2 | `/etc/mysql/my.cnf` | 部分发行版使用 |
| 3 | `/usr/etc/my.cnf` | 编译时默认路径 |
| 4 | `~/.my.cnf` | 当前用户的个人配置（注意安全性） |
| 5（最高）| 命令行 `--defaults-file=` 指定的文件 | 明确指定时完全替代前面所有 |

**Windows 系统读取顺序：**

| 优先级 | 文件路径 | 说明 |
|--------|---------|------|
| 1（最低）| `C:\Windows\my.ini` | |
| 2 | `C:\Windows\my.cnf` | |
| 3 | `C:\my.ini` | |
| 4 | `C:\my.cnf` | |
| 5 | `安装目录\my.ini` | 如 `C:\Program Files\MySQL\MySQL Server 8.4\my.ini` |
| 6（最高）| `--defaults-file=` 指定路径 | |

```bash
# 查看 MySQL 实际读取了哪些配置文件
mysqld --verbose --help 2>/dev/null | grep -A 1 "Default options"
# 输出示例：
# Default options are read from the following files in the given order:
# /etc/my.cnf /etc/mysql/my.cnf ~/.my.cnf
```

## 配置文件的段（Section）结构

配置文件使用 INI 格式，每个段用 `[段名]` 标识，段内的配置只对对应的程序生效。常见段如下：

```ini
# ======================================================
# [mysqld] 段：mysqld 服务端进程读取
# ======================================================
[mysqld]
port = 3306
datadir = /var/lib/mysql
socket = /var/lib/mysql/mysql.sock
character-set-server = utf8mb4
collation-server = utf8mb4_0900_ai_ci
innodb_buffer_pool_size = 2G
max_connections = 500
slow_query_log = ON
slow_query_log_file = /var/log/mysql/slow.log
long_query_time = 1

# ======================================================
# [client] 段：所有 MySQL 客户端程序读取（mysql、mysqldump 等）
# ======================================================
[client]
port = 3306
socket = /var/lib/mysql/mysql.sock
default-character-set = utf8mb4

# ======================================================
# [mysql] 段：仅 mysql 命令行客户端读取
# ======================================================
[mysql]
default-character-set = utf8mb4
prompt = "MySQL [\\d]> "   # 命令行提示符显示当前数据库名

# ======================================================
# [mysqldump] 段：仅 mysqldump 工具读取
# ======================================================
[mysqldump]
single-transaction
max_allowed_packet = 256M

# ======================================================
# [mysqld_safe] 段：mysqld_safe 启动脚本读取（传统 init.d 方式）
# ======================================================
[mysqld_safe]
log-error = /var/log/mysql/error.log
pid-file = /var/run/mysqld/mysqld.pid
```

---

## 各段的读取关系

| 段名 | 谁读取它 |
|------|---------|
| `[mysqld]` | MySQL 服务端进程（mysqld） |
| `[server]` | `[mysqld]` 的别名，效果相同 |
| `[client]` | 所有客户端工具：mysql、mysqldump、mysqladmin 等 |
| `[mysql]` | 仅 mysql 命令行客户端 |
| `[mysqldump]` | 仅 mysqldump 备份工具 |
| `[mysqladmin]` | 仅 mysqladmin 管理工具 |
| `[mysqlcheck]` | 仅 mysqlcheck 检查工具 |
| `[mysqld_safe]` | 老式 mysqld_safe 启动脚本（systemd 环境下已基本不用） |

## 参数的格式规则

```ini
# 布尔型参数（开启）
slow_query_log = ON
slow_query_log = 1
slow_query_log         # 不加值，相当于 ON/1

# 布尔型参数（关闭）
slow_query_log = OFF
slow_query_log = 0

# 字符串参数
character-set-server = utf8mb4

# 数值参数（支持单位后缀）
innodb_buffer_pool_size = 2G    # 2GB
innodb_buffer_pool_size = 2048M # 2048MB，等价
max_allowed_packet = 64M

# 注意：参数名中的 "-" 和 "_" 是等价的
# max-connections 和 max_connections 效果相同
```

## include 引入其他配置文件

对于复杂的配置，可以拆分成多个文件，通过 `include` 指令引入：

```ini
# 引入单个文件
!include /etc/mysql/conf.d/innodb.cnf

# 引入目录下所有 .cnf 文件
!includedir /etc/mysql/conf.d/
```

Ubuntu/Debian 系统的 MySQL 包通常会把 `/etc/mysql/conf.d/` 目录里的所有 `.cnf` 文件自动 include 进去，所以可以在该目录下创建独立的配置文件，而不需要修改主 `my.cnf`。

## 常见问题

**修改了 my.cnf，参数没有生效怎么办？**

首先确认参数写在了正确的段（如 `[mysqld]`），而不是 `[client]` 或其他段；其次确认服务已重启（`systemctl restart mysqld`）；最后用以下命令确认 MySQL 读取了哪个配置文件，以及参数是否被后续文件覆盖：

```bash
# 查看当前生效的参数值
mysql -u root -p -e "SHOW VARIABLES LIKE 'slow_query_log';"

# 查看参数来源
mysqld --verbose --help 2>/dev/null | grep "slow.query.log"
```

**my.cnf 和 mysqld-auto.cnf 哪个优先级更高？**

`mysqld-auto.cnf`（由 `SET PERSIST` 写入）优先级高于 `my.cnf`。如果发现 my.cnf 改了但参数不生效，检查是否有 `mysqld-auto.cnf` 在覆盖。

```sql
-- 查看所有持久化的参数
SELECT * FROM performance_schema.persisted_variables;
-- 清除某个持久化参数
RESET PERSIST parameter_name;
```

**Windows 下配置文件用 my.ini 还是 my.cnf？**

两者都可以，MySQL 都能识别。Windows 下习惯用 `.ini`，Linux 下用 `.cnf`。如果通过 MySQL Installer 安装，默认会生成 `my.ini`。

**如何验证配置文件语法正确？**

```bash
# 启动前验证配置
mysqld --validate-config
# 如果有语法错误会输出错误信息；无输出表示配置正确
```

## 适用场景

- **新实例部署**：安装完成后立即配置合理的 my.cnf，包括字符集、InnoDB 参数、日志路径等基础项
- **多实例管理**：同一台服务器上运行多个 MySQL 实例时，每个实例使用独立的配置文件（通过 `--defaults-file` 指定）
- **配置版本管理**：将 my.cnf 纳入 Git 管理，记录每次配置变更的历史，方便回滚和审计
- **参数调优记录**：参数调整后在注释中记录调整时间和原因，方便后续维护

## 注意事项

- `~/.my.cnf` 中可以存放用户名和密码（`[client]` 段的 `user=` 和 `password=`），方便免密码登录。但这个文件权限必须设置为 `600`，否则 MySQL 会拒绝读取（安全保护机制）。
- `[client]` 段的配置会被所有客户端工具读取，包括 `mysqldump`，如果在 `[client]` 里设置了不适合 mysqldump 的参数（如某些连接超时），可能影响备份。对特定工具的参数放在对应的专用段更安全。
- 不要在注释中写敏感信息（如密码），即使是在服务器本地的配置文件。
- 修改 `[mysqld]` 段的参数通常需要重启服务才能生效，但部分参数支持动态修改（`SET GLOBAL`），可以通过 `SHOW VARIABLES` 确认当前值。

---

## 总结

my.cnf 文件按段组织配置，不同段由不同程序读取。`[mysqld]` 是最核心的段，控制服务端行为；`[client]` 影响所有客户端工具。文件的读取顺序决定了参数优先级，`mysqld-auto.cnf`（SET PERSIST 写入的文件）的优先级最高。配置文件修改后要重启服务才能生效，同时通过 `SHOW VARIABLES` 验证参数是否已按预期设置。
