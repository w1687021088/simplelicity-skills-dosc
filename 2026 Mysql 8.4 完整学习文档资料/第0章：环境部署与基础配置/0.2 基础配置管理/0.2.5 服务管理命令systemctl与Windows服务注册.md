# 服务管理命令 systemctl 与 Windows 服务注册

MySQL 以系统服务方式运行时，启动、停止、重启以及开机自启都依赖操作系统的服务管理机制。Linux 上主要用 systemctl，Windows 上通过服务管理器或 sc 命令。了解这些命令和配置是日常运维的基础，在排查启动失败、配置变更后重启等场景中会频繁用到。

---

## Linux：systemctl 服务管理

### 常用操作命令

```bash
# 启动 MySQL 服务
systemctl start mysqld

# 停止 MySQL 服务
systemctl stop mysqld

# 重启 MySQL 服务（先停止再启动，会断开所有连接）
systemctl restart mysqld

# 重载配置（不断开连接，仅重新读取配置文件中支持动态加载的部分）
# MySQL 不支持 reload，所以这个命令实际会执行 restart
systemctl reload mysqld

# 查看服务运行状态
systemctl status mysqld

# 设置开机自启
systemctl enable mysqld

# 取消开机自启
systemctl disable mysqld

# 查看是否设置了开机自启
systemctl is-enabled mysqld
```

不同 Linux 发行版的 MySQL 服务名可能有差异：

| 发行版 | 默认服务名 |
|--------|---------|
| RHEL / CentOS / Rocky Linux | `mysqld` |
| Ubuntu / Debian | `mysql` |
| 通过二进制包手动安装 | 取决于安装时的配置 |

### systemctl status 的输出解读

```bash
systemctl status mysqld
```

典型输出：

```
● mysqld.service - MySQL Server
     Loaded: loaded (/usr/lib/systemd/system/mysqld.service; enabled; vendor preset: disabled)
     Active: active (running) since Sat 2026-03-14 10:00:00 CST; 2h 30min ago
       Docs: man:mysqld(8)
             http://dev.mysql.com/doc/refman/en/using-systemd.html
    Process: 1234 ExecStartPre=/usr/bin/mysqld_pre_systemd (code=exited, status=0/SUCCESS)
   Main PID: 1235 (mysqld)
     Status: "Server is operational"
      Tasks: 38 (limit: 23695)
     Memory: 512.0M
        CPU: 3min 45.678s
     CGroup: /system.slice/mysqld.service
             └─1235 /usr/sbin/mysqld

Mar 14 10:00:01 server01 systemd[1]: Starting MySQL Server...
Mar 14 10:00:02 server01 systemd[1]: Started MySQL Server.
```

关键字段：
- `Active: active (running)`：服务正常运行
- `Active: failed`：服务启动失败，查看错误日志排查
- `enabled`：已设置开机自启
- `Main PID`：MySQL 进程 ID

### 查看 systemd 服务日志

```bash
# 查看 MySQL 服务的 systemd 日志（最近 50 行）
journalctl -u mysqld -n 50

# 查看最近 1 小时的日志
journalctl -u mysqld --since "1 hour ago"

# 实时跟踪日志输出
journalctl -u mysqld -f
```

### MySQL 的 systemd 服务文件

```bash
# 查看服务文件位置
systemctl cat mysqld

# 典型内容（/usr/lib/systemd/system/mysqld.service）
# [Unit]
# Description=MySQL Server
# After=network.target
#
# [Service]
# User=mysql
# Group=mysql
# ExecStart=/usr/sbin/mysqld
# LimitNOFILE=10000
# Restart=on-failure
# RestartPreventExitStatus=1
# TimeoutStartSec=0
#
# [Install]
# WantedBy=multi-user.target
```

**注意**：不要直接修改 `/usr/lib/systemd/system/mysqld.service`，这个文件可能在软件更新时被覆盖。如果需要自定义参数（如修改文件描述符限制），使用 override 文件：

```bash
# 创建 override 文件
systemctl edit mysqld
# 会打开编辑器，在其中添加需要覆盖的配置
# 保存后自动创建 /etc/systemd/system/mysqld.service.d/override.conf

# 重载 systemd 配置
systemctl daemon-reload
systemctl restart mysqld
```

## Windows：服务管理

### 图形界面方式

1. 按 `Win + R`，输入 `services.msc`，打开服务管理器
2. 找到 MySQL 服务（名称通常是 `MySQL84` 或 `MySQL`）
3. 右键可以选择启动、停止、重启、属性设置等

### 命令行方式（推荐）

```cmd
:: 启动 MySQL 服务（管理员权限）
net start MySQL84

:: 停止 MySQL 服务
net stop MySQL84

:: 查看服务状态
sc query MySQL84

:: 设置开机自启（自动启动）
sc config MySQL84 start= auto

:: 设置手动启动（不自动启动）
sc config MySQL84 start= demand

:: 禁用服务
sc config MySQL84 start= disabled
```

**PowerShell 方式（Windows 10/11）：**

```powershell
# 启动服务
Start-Service -Name MySQL84

# 停止服务
Stop-Service -Name MySQL84

# 重启服务
Restart-Service -Name MySQL84

# 查看服务状态
Get-Service -Name MySQL84

# 查看所有 MySQL 相关服务
Get-Service | Where-Object {$_.Name -like "*MySQL*"}
```

### 手动注册 MySQL 服务（非 Installer 安装时）

如果是解压安装（ZIP 方式）而不是通过 MySQL Installer，需要手动注册服务：

```cmd
:: 注册服务（以管理员权限运行）
"C:\Program Files\MySQL\MySQL Server 8.4\bin\mysqld" --install MySQL84 --defaults-file="C:\ProgramData\MySQL\MySQL Server 8.4\my.ini"

:: 注册后启动服务
net start MySQL84

:: 删除服务（删除前先停止）
net stop MySQL84
"C:\Program Files\MySQL\MySQL Server 8.4\bin\mysqld" --remove MySQL84
```

## 两个平台的操作对比

| 操作 | Linux (systemctl) | Windows (net/sc) |
|------|-----------------|----------------|
| 启动服务 | `systemctl start mysqld` | `net start MySQL84` |
| 停止服务 | `systemctl stop mysqld` | `net stop MySQL84` |
| 重启服务 | `systemctl restart mysqld` | `net stop MySQL84 && net start MySQL84` |
| 查看状态 | `systemctl status mysqld` | `sc query MySQL84` |
| 开机自启 | `systemctl enable mysqld` | `sc config MySQL84 start= auto` |
| 取消自启 | `systemctl disable mysqld` | `sc config MySQL84 start= demand` |
| 查看日志 | `journalctl -u mysqld` | 事件查看器（Event Viewer） |

## 常见问题

**systemctl restart mysqld 后 MySQL 没有起来，怎么排查？**

```bash
# 1. 查看 systemd 日志
journalctl -u mysqld -n 30

# 2. 查看 MySQL 错误日志
tail -50 /var/log/mysql/error.log
# 或者
tail -50 $(mysql -u root -p -e "SHOW VARIABLES LIKE 'log_error';" 2>/dev/null | awk 'NR==2{print $2}')

# 3. 尝试手动启动查看详细错误
mysqld --user=mysql --console
```

**MySQL 服务启动失败，提示 "Can't create PID file"**

通常是 pid 文件目录不存在或权限不对：

```bash
# 检查 pid 文件路径
grep pid /etc/my.cnf

# 确保目录存在且 mysql 用户有写权限
mkdir -p /var/run/mysqld
chown mysql:mysql /var/run/mysqld
```

**Windows 下 net start MySQL84 提示 "服务没有响应控制功能"**

可能是 my.ini 配置有问题导致启动失败。查看 Windows 事件查看器（Event Viewer）中的应用程序日志，以及 MySQL 错误日志文件（通常在 `C:\ProgramData\MySQL\MySQL Server 8.4\Data\` 目录下）。

## 适用场景

- **日常运维**：配置变更后重启服务，使新配置生效
- **故障处理**：服务崩溃后快速重启，配合日志定位崩溃原因
- **系统维护**：计划维护时停止服务，维护完成后启动并验证
- **多实例管理**：每个 MySQL 实例对应一个独立的 systemd 服务或 Windows 服务

## 注意事项

- `systemctl restart` 会立即断开所有客户端连接，如果有未提交的事务，InnoDB 会自动回滚。生产环境重启前应通知相关业务方，选择低峰期操作。
- 修改了 my.cnf 中静态参数（如 `innodb_buffer_pool_instances`）后，只有重启服务才能生效；动态参数（如 `max_connections`）可以通过 `SET GLOBAL` 立即修改，无需重启。
- Linux 上 `systemctl stop mysqld` 后，MySQL 会等待所有事务完成（正常关闭），而不是强制杀进程。如果有长事务，stop 可能需要等待较长时间。如果需要强制停止，用 `kill -9 <pid>`，但这种方式下次启动会触发崩溃恢复。
- Windows 下不要直接在任务管理器中结束 mysqld.exe 进程，应使用服务停止命令。强制结束进程会导致 InnoDB 崩溃恢复。

---

## 总结

Linux 下用 systemctl 管理 MySQL 服务是标准做法，核心命令是 start/stop/restart/status/enable/disable；Windows 下用 net start/stop 或 PowerShell 的 Start-Service/Stop-Service。两个平台都需要以管理员/root 权限执行服务管理命令。遇到服务启动失败时，优先查看 systemd 日志（journalctl）和 MySQL 错误日志，这两个来源通常能直接定位问题。
