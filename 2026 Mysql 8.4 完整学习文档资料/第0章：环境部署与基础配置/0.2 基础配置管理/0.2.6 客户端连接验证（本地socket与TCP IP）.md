# 客户端连接验证（本地 socket 与 TCP/IP）

MySQL 支持两种连接方式：本地 Unix socket 连接和 TCP/IP 网络连接。理解两者的区别，知道什么时候会走哪种连接，是排查连接失败问题的基础知识。

---

## 两种连接方式的原理

### Unix Socket 连接

Unix socket 是一种进程间通信（IPC）机制，通过文件系统上的 socket 文件实现同一台机器上两个进程的通信。当客户端和服务端在同一台服务器上时，使用 socket 连接比 TCP/IP 更快，因为不经过网络协议栈。

socket 文件路径由 MySQL 配置控制：

```ini
[mysqld]
socket = /var/lib/mysql/mysql.sock

[client]
socket = /var/lib/mysql/mysql.sock
```

```sql
-- 查看 socket 文件路径
SHOW VARIABLES LIKE 'socket';
```

### TCP/IP 连接

TCP/IP 连接通过网络套接字进行，无论是本机还是远程服务器都可以使用。它监听在一个端口（默认 3306）上，所有经过网络的连接请求都通过这个端口处理。

```ini
[mysqld]
port = 3306
bind-address = 0.0.0.0    # 监听所有网卡，允许远程连接
# bind-address = 127.0.0.1  # 只监听本地回环，禁止远程连接
```

```sql
-- 查看 MySQL 监听的端口
SHOW VARIABLES LIKE 'port';

-- 查看绑定的地址
SHOW VARIABLES LIKE 'bind_address';
```

## 连接方式的自动选择规则

当用 `mysql` 命令行客户端连接时，MySQL 会根据 `--host` 参数决定连接方式：

| 命令 | 连接方式 | 说明 |
|------|---------|------|
| `mysql -u root -p` | Unix socket | 不指定 host 时，默认用 socket |
| `mysql -u root -p -h localhost` | Unix socket | `localhost` 触发 socket 连接 |
| `mysql -u root -p -h 127.0.0.1` | TCP/IP | IP 地址触发 TCP 连接 |
| `mysql -u root -p -h 192.168.1.10` | TCP/IP | 远程地址，必须用 TCP |
| `mysql -u root -p --protocol=tcp` | TCP/IP | 强制指定 TCP |
| `mysql -u root -p --socket=/tmp/mysql.sock` | Unix socket | 显式指定 socket 文件 |

**关键区别**：`localhost` 和 `127.0.0.1` 在 MySQL 中不等价。`localhost` 触发 socket 连接，`127.0.0.1` 触发 TCP 连接。这也影响用户账号的匹配：`'root'@'localhost'` 和 `'root'@'127.0.0.1'` 是两个不同的账号。

## 连接验证实操

### 基本连接测试

```bash
# 本地 socket 连接（最常用的本地登录方式）
mysql -u root -p

# 显式指定 socket 文件
mysql -u root -p --socket=/var/lib/mysql/mysql.sock

# 通过 TCP/IP 连接本机（需要 root@127.0.0.1 账号存在且有权限）
mysql -u root -p -h 127.0.0.1 -P 3306

# 连接远程服务器
mysql -u app_user -p -h 192.168.1.10 -P 3306 myapp_db

# 执行单条 SQL 后退出
mysql -u root -p -e "SELECT VERSION();"

# 免密码连接（使用 ~/.my.cnf 中的凭据）
# ~/.my.cnf 内容示例：
# [client]
# user = root
# password = your_password
mysql
```

### 验证连接成功

```sql
-- 连接成功后确认当前状态
SELECT VERSION();                  -- 确认版本
SELECT CURRENT_USER();             -- 确认实际匹配的账号
SELECT USER();                     -- 确认连接时使用的用户名和主机
SHOW DATABASES;                    -- 确认有权限查看数据库列表

-- 查看当前连接信息
SHOW STATUS LIKE 'Threads_connected';  -- 当前连接数
STATUS;                                -- mysql 客户端内置命令，显示连接详情
```

### 查看当前所有连接

```sql
-- 查看所有活跃连接
SHOW PROCESSLIST;

-- 或使用 information_schema（包含更多字段）
SELECT 
    ID, USER, HOST, DB, COMMAND, TIME, STATE
FROM information_schema.PROCESSLIST
ORDER BY TIME DESC;

-- 查看连接的实际使用情况
SHOW STATUS LIKE 'Threads_%';
```

## TCP/IP 连接的网络配置

### bind-address 配置

`bind-address` 控制 MySQL 监听哪个网络接口：

```ini
# 监听所有网卡（允许任何 IP 连接，需要配合用户权限控制）
bind-address = 0.0.0.0

# 只监听本地回环（只允许本机连接，最安全）
bind-address = 127.0.0.1

# 监听特定 IP（只允许通过该 IP 的连接，适合多网卡服务器）
bind-address = 192.168.1.10

# MySQL 8.0.13+ 支持多个绑定地址
bind-address = 127.0.0.1,192.168.1.10
```

### 防火墙配置

```bash
# Linux (firewalld) 开放 MySQL 端口
firewall-cmd --permanent --add-port=3306/tcp
firewall-cmd --reload

# Linux (iptables) 开放 MySQL 端口
iptables -A INPUT -p tcp --dport 3306 -j ACCEPT
iptables-save > /etc/iptables/rules.v4

# 验证端口是否在监听
ss -tlnp | grep 3306
# 或
netstat -tlnp | grep 3306
```

### 禁用 TCP/IP（仅允许 socket 连接）

如果 MySQL 只供本机使用，可以完全禁用 TCP 监听：

```ini
[mysqld]
skip-networking    # 禁用所有 TCP/IP 连接
# 或
bind-address = 127.0.0.1  # 更温和，仍可用 127.0.0.1 连接
```

## Windows 下的连接

Windows 没有 Unix socket，默认使用 TCP/IP 或命名管道（Named Pipe）：

```cmd
:: TCP/IP 连接（最常用）
mysql -u root -p -h 127.0.0.1 -P 3306

:: 命名管道连接（需要在 my.ini 中启用 named_pipe）
mysql -u root -p --protocol=pipe
```

在 Windows 的 my.ini 中，可以配置命名管道：

```ini
[mysqld]
named_pipe = ON
socket = MySQL                     # 命名管道的名称
enable-named-pipe
```

## 连接字符串格式

不同驱动和框架的连接字符串格式各有不同：

```
# 标准 JDBC URL（Java）
jdbc:mysql://192.168.1.10:3306/myapp?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8mb4

# Python（mysql-connector-python）
connection = mysql.connector.connect(
    host="192.168.1.10",
    port=3306,
    user="app_user",
    password="password",
    database="myapp",
    charset="utf8mb4"
)

# PHP (PDO)
$dsn = "mysql:host=192.168.1.10;port=3306;dbname=myapp;charset=utf8mb4";
$pdo = new PDO($dsn, 'app_user', 'password');

# Node.js (mysql2)
const connection = mysql.createConnection({
  host: '192.168.1.10',
  port: 3306,
  user: 'app_user',
  password: 'password',
  database: 'myapp',
  charset: 'utf8mb4'
});
```

## 常见问题

**连接报错 "Can't connect to local MySQL server through socket"**

socket 文件不存在或路径不对。检查步骤：

```bash
# 1. 确认 MySQL 是否在运行
systemctl status mysqld

# 2. 确认 socket 文件位置
mysql -u root -p --verbose --help 2>/dev/null | grep socket

# 3. 确认 socket 文件是否存在
ls -la /var/lib/mysql/mysql.sock

# 4. 如果文件不存在但 MySQL 在运行，查看错误日志
tail -20 /var/log/mysql/error.log
```

**连接报错 "ERROR 1130: Host '192.168.1.100' is not allowed to connect"**

用户账号的 host 不匹配。需要创建允许该 IP 连接的账号：

```sql
-- 查看用户的 host 配置
SELECT user, host FROM mysql.user WHERE user = 'app_user';

-- 创建或修改允许特定 IP 的账号
CREATE USER 'app_user'@'192.168.1.%' IDENTIFIED BY 'password';
GRANT SELECT, INSERT, UPDATE, DELETE ON myapp.* TO 'app_user'@'192.168.1.%';
```

**连接报错 "ERROR 2003: Can't connect to MySQL server on '192.168.1.10' (111)"**

TCP 连接被拒绝。检查：
1. MySQL 的 `bind-address` 是否允许该 IP（是否为 0.0.0.0）
2. 防火墙是否开放了 3306 端口
3. MySQL 是否在运行

## 适用场景

- **本地开发**：使用 socket 连接，更快且不需要网络配置
- **生产应用服务器**：应用服务器通过 TCP/IP 连接数据库服务器，需要配合防火墙只开放应用服务器 IP 的访问
- **DBA 本地维护**：通过 socket 连接本机，无需网络
- **监控服务**：监控程序通常使用 TCP/IP 连接，因为监控服务器和数据库可能不在同一台机器上

---

## 注意事项

- `bind-address = 0.0.0.0` 意味着 MySQL 监听所有网络接口，包括公网 IP（如果服务器有公网 IP）。生产环境要配合防火墙规则严格限制能访问 3306 端口的 IP。
- socket 文件的权限应为 mysql 用户所有，普通 Linux 用户直接用 socket 连接可能会被权限拒绝。解决方案是使用 sudo 或在 `/etc/my.cnf` 中配置 `[client]` 段的 socket 路径，同时确保用户在 mysql 组中。
- 连接时的 `--host` 参数值会影响用户权限匹配，`localhost` 匹配 `'user'@'localhost'`，`127.0.0.1` 匹配 `'user'@'127.0.0.1'` 或 `'user'@'%'`，两者可能是不同的账号，有不同的权限。
- 在 Docker 容器中运行 MySQL 时，socket 文件在容器内部，宿主机无法通过 socket 连接，只能通过 TCP/IP 连接（需要映射端口 `-p 3306:3306`）。

## 总结

MySQL 支持 socket 和 TCP/IP 两种连接方式，前者用于同机进程间通信，更快更安全；后者用于跨网络连接，是应用服务器访问数据库的标准方式。`localhost` 触发 socket 连接，`127.0.0.1` 触发 TCP 连接，这个区别在权限配置和连接排查时非常重要。生产环境应当通过 `bind-address` 和防火墙规则严格控制 TCP 连接的来源，避免数据库端口暴露在不必要的网络中。
