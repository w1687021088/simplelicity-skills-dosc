# 慢查询日志 Slow Query Log 配置

慢查询日志（Slow Query Log）是 MySQL 内置的查询性能诊断工具，记录执行时间超过 `long_query_time` 阈值的 SQL 语句（以及满足其他条件的语句），是定位慢查询和优化数据库性能的基础手段之一。慢查询日志可以写入文件或数据表（`mysql.slow_log`）。在生产环境中，慢查询日志通常持续开启，配合分析工具（`mysqldumpslow`、`pt-query-digest`）定期分析，形成性能监控闭环。

---

## 开启慢查询日志

```sql
-- 查看当前慢查询日志配置
SHOW VARIABLES LIKE 'slow_query%' \G
-- slow_query_log: OFF（默认关闭）
-- slow_query_log_file: /var/lib/mysql/hostname-slow.log（默认路径）

SHOW VARIABLES LIKE 'long_query_time';
-- long_query_time: 10.000000（默认 10 秒，通常需要调低）

-- 动态开启（无需重启，Session 级或 Global 级）
SET GLOBAL slow_query_log = ON;

-- 设置日志文件路径（也可在配置文件中设置）
SET GLOBAL slow_query_log_file = '/var/log/mysql/slow.log';

-- 设置阈值（通常设置为 1 秒）
SET GLOBAL long_query_time = 1;

-- 验证配置
SHOW VARIABLES LIKE 'slow_query_log' \G
-- slow_query_log: ON
SHOW VARIABLES LIKE 'long_query_time' \G
-- long_query_time: 1.000000
```

---

## my.cnf 配置文件方式（持久化）

```ini
[mysqld]
# 开启慢查询日志
slow_query_log = ON

# 慢查询日志文件路径（需确保 MySQL 用户有写入权限）
slow_query_log_file = /var/log/mysql/slow.log

# 执行时间超过 1 秒的查询记录到慢查询日志
long_query_time = 1

# 记录没有使用索引的查询（即使执行时间未超过 long_query_time）
log_queries_not_using_indexes = ON

# 限制每分钟记录"未使用索引"查询的次数（防止日志文件过快增长）
log_throttle_queries_not_using_indexes = 10

# 记录管理语句（ANALYZE TABLE、ALTER TABLE 等）的慢查询
log_slow_admin_statements = ON

# 记录从库慢查询（主从复制环境中，从库 SQL 线程的慢查询）
log_slow_replica_statements = ON
```

## 记录到数据表（log_output）

```sql
-- log_output 控制慢查询日志的输出目标
SHOW VARIABLES LIKE 'log_output';
-- log_output: FILE（默认输出到文件）

-- 同时输出到文件和表：
SET GLOBAL log_output = 'FILE,TABLE';

-- 只输出到表（便于 SQL 查询）：
SET GLOBAL log_output = 'TABLE';

-- 查询慢查询表（mysql.slow_log）：
SELECT * FROM mysql.slow_log
ORDER BY start_time DESC LIMIT 10 \G
-- 字段：start_time, user_host, query_time, lock_time, rows_sent,
--        rows_examined, db, sql_text, thread_id 等

-- 清空慢查询表（谨慎操作）：
TRUNCATE TABLE mysql.slow_log;
-- 注意：TRUNCATE 是 DDL，会产生一次全表锁

-- 对比文件 vs 表的优缺点：
-- 文件：I/O 效率高，不占用 MySQL 表空间，配合 logrotate 管理
-- 表：可以用 SQL 分析查询（但写入有锁竞争，高并发下有少量开销）
```

## 慢查询日志文件的内容格式

```
# 每条慢查询记录的格式：

# Time: 2025-01-15T10:30:45.123456Z
# User@Host: app_user[app_user] @ 10.0.0.1 [10.0.0.1]  Id: 12345
# Query_time: 2.567890  Lock_time: 0.000123  Rows_sent: 100  Rows_examined: 50000
# Set timestamp=1736937045;
SELECT o.id, o.amount, u.name
FROM orders o JOIN users u ON o.user_id = u.id
WHERE o.status = 1 ORDER BY o.created_at LIMIT 100;

字段含义：
- Query_time：查询总执行时间（秒）
- Lock_time：等待锁的时间（秒）
- Rows_sent：返回给客户端的行数
- Rows_examined：扫描的行数（越大说明效率越低）
- Rows_examined/Rows_sent 的比值：
  - 比值 = 1：索引精确命中，效率极高
  - 比值 = 100：扫描了 100 行才返回 1 行，需要优化
  - 比值 > 1000：严重的全表扫描，优先优化
```

## 动态管理慢查询日志文件

```sql
-- 日志轮转（轮转后通知 MySQL 使用新文件）
-- 方法1：FLUSH SLOW LOGS（关闭并重新打开慢查询日志文件）
FLUSH SLOW LOGS;

-- 方法2：通过操作系统 logrotate 工具（配合 postrotate 脚本）
-- /etc/logrotate.d/mysql-slow 示例：
-- /var/log/mysql/slow.log {
--     daily
--     rotate 7
--     compress
--     missingok
--     notifempty
--     postrotate
--         /usr/bin/mysqladmin flush-slow-logs
--     endscript
-- }

-- 临时关闭慢查询日志（高负载时减少 I/O）
SET GLOBAL slow_query_log = OFF;
-- 处理完高负载后重新开启
SET GLOBAL slow_query_log = ON;

-- 查看慢查询统计（不需要读日志文件）
SHOW GLOBAL STATUS LIKE 'Slow_queries';
-- Slow_queries: 1234（自 MySQL 启动以来的慢查询总数）
-- 监控这个值的增长速率，可以快速判断慢查询是否增多
```

## 适用场景

- **生产环境的持续性能监控**：在生产环境中，慢查询日志是持续性能监控的基础，设置合理的 `long_query_time`（通常 1 秒，高要求场景可以设置 0.5 秒甚至 0.1 秒），持续记录慢查询，定期用 `mysqldumpslow` 或 `pt-query-digest` 分析，发现新出现的慢查询模式
- **新版本发布后的回归检测**：在应用新版本上线后，临时将 `long_query_time` 降低（如从 1 秒降到 0.5 秒），增加 `log_queries_not_using_indexes=ON`，通过慢查询日志快速发现新代码引入的低效查询

## 常见问题

**开启慢查询日志对生产环境性能有多大影响？**

影响很小。慢查询日志的写入是异步的（MySQL 不会因为写日志而阻塞查询），实际性能开销通常在 1%~3% 以内，远低于不监控慢查询可能带来的业务损失。`log_queries_not_using_indexes=ON` 会稍微多记录一些内容，但配合 `log_throttle_queries_not_using_indexes`（限制每分钟记录次数）后，对性能的额外影响可以忽略。在高 QPS（每秒查询数万次）的环境中，可以设置更高的 `long_query_time`（如 3~5 秒）只记录真正严重的慢查询，减少日志量。

## 注意事项

- 慢查询日志文件会持续增长，需要配置日志轮转（logrotate）防止磁盘被占满。建议每天轮转一次，保留最近 7~14 天的日志文件，并压缩旧日志文件。
- `long_query_time` 支持微秒精度（如 `0.5` 表示 500 毫秒，`0.001` 表示 1 毫秒），不只是整秒。对于高性能要求的 OLTP 系统，可以将阈值设为 `0.1`（100 毫秒）或更低，更早发现潜在的性能问题。

## 总结

慢查询日志通过 `slow_query_log=ON` + `slow_query_log_file` + `long_query_time` 配置。重要参数：`log_queries_not_using_indexes=ON`（记录无索引查询）、`log_throttle_queries_not_using_indexes`（限频）、`log_slow_admin_statements=ON`（记录管理语句）。输出目标：`log_output=FILE`（文件，默认高效）或 `TABLE`（写入 `mysql.slow_log`，可 SQL 查询）。日志内容关键字段：`Query_time`（执行时间）、`Rows_examined/Rows_sent`（扫描效率比）。通过 `SHOW GLOBAL STATUS LIKE 'Slow_queries'` 监控慢查询累计数量；通过 `mysqldumpslow` 或 `pt-query-digest` 分析日志文件内容。
