# partitions 分区信息

EXPLAIN 输出的 `partitions` 列显示查询访问了哪些分区（Partition Pruning 分区裁剪的结果）。对于未分区的表，`partitions` 值为 `NULL`。对于分区表，如果查询条件能让优化器排除不相关的分区（只扫描部分分区），则 `partitions` 列只显示实际需要访问的分区列表；如果无法裁剪，则显示所有分区。分区裁剪的效果直接体现在 `partitions` 列——访问的分区数越少，性能越好。

---

## 分区表与 partitions 列

```sql
-- 创建 RANGE 分区表（按年份分区）
CREATE TABLE orders_partitioned (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,
    amount DECIMAL(10,2),
    created_at DATETIME NOT NULL
)
PARTITION BY RANGE (YEAR(created_at)) (
    PARTITION p2022 VALUES LESS THAN (2023),
    PARTITION p2023 VALUES LESS THAN (2024),
    PARTITION p2024 VALUES LESS THAN (2025),
    PARTITION p2025 VALUES LESS THAN (2026),
    PARTITION p_future VALUES LESS THAN MAXVALUE
);

-- 插入测试数据：
INSERT INTO orders_partitioned (user_id, amount, created_at)
VALUES (1, 99.99, '2023-06-15 10:00:00');

-- 查询所有分区（无分区裁剪）：
EXPLAIN SELECT * FROM orders_partitioned WHERE user_id = 100 \G
-- partitions: p2022,p2023,p2024,p2025,p_future  ← 扫描所有分区
-- 因为 WHERE user_id = 100 不涉及分区键（created_at），无法裁剪

-- 查询指定分区范围（分区裁剪生效）：
EXPLAIN SELECT * FROM orders_partitioned WHERE created_at >= '2023-01-01' AND created_at < '2024-01-01' \G
-- partitions: p2023  ← 只扫描 2023 年的分区
-- 分区裁剪将扫描范围从 5 个分区缩小为 1 个！
```

## 分区裁剪的条件

```sql
-- 分区裁剪需要 WHERE 条件包含分区键（或分区表达式）的比较
-- 这样优化器才能确定哪些分区可能包含目标数据

-- RANGE 分区：
EXPLAIN SELECT * FROM orders_partitioned WHERE YEAR(created_at) = 2024 \G
-- partitions: p2024  ← 裁剪到 2024 分区（分区键表达式匹配）

EXPLAIN SELECT * FROM orders_partitioned WHERE created_at BETWEEN '2023-06-01' AND '2024-01-31' \G
-- partitions: p2023,p2024  ← 跨两个分区

-- LIST 分区示例：
CREATE TABLE orders_by_region (
    id INT PRIMARY KEY AUTO_INCREMENT,
    region_id INT NOT NULL,
    amount DECIMAL(10,2)
)
PARTITION BY LIST (region_id) (
    PARTITION p_north VALUES IN (1, 2, 3),
    PARTITION p_south VALUES IN (4, 5, 6),
    PARTITION p_east  VALUES IN (7, 8, 9),
    PARTITION p_west  VALUES IN (10, 11, 12)
);

EXPLAIN SELECT * FROM orders_by_region WHERE region_id = 5 \G
-- partitions: p_south  ← 直接定位到 p_south 分区

EXPLAIN SELECT * FROM orders_by_region WHERE region_id IN (1, 7) \G
-- partitions: p_north, p_east  ← 两个分区

EXPLAIN SELECT * FROM orders_by_region WHERE region_id > 5 \G
-- partitions: p_south,p_east,p_west  ← 范围条件，无法精确到 p_north
```

## 分区裁剪失效的场景

```sql
-- 失效场景1：WHERE 条件不包含分区键
EXPLAIN SELECT * FROM orders_partitioned WHERE user_id = 100 \G
-- partitions: p2022,p2023,p2024,p2025,p_future  ← 所有分区都扫描

-- 失效场景2：对分区键使用函数（类似索引失效）
EXPLAIN SELECT * FROM orders_partitioned WHERE MONTH(created_at) = 6 \G
-- partitions: p2022,p2023,p2024,p2025,p_future  ← 所有分区，无法裁剪
-- MONTH() 函数破坏了分区裁剪的条件（分区是按 YEAR 定义的）

-- 失效场景3：分区键与 OR 连接非分区键
EXPLAIN SELECT * FROM orders_partitioned
WHERE (created_at >= '2023-01-01' AND created_at < '2024-01-01')
   OR user_id = 100 \G
-- partitions: p2022,p2023,p2024,p2025,p_future  ← OR 连接了非分区键，所有分区
```

## 直接指定分区查询

```sql
-- 通过 PARTITION 子句直接指定访问的分区（绕过优化器）
EXPLAIN SELECT * FROM orders_partitioned PARTITION (p2023, p2024) WHERE user_id = 100 \G
-- partitions: p2023,p2024  ← 直接指定，无论 WHERE 条件如何

-- 用于确认某个分区内的数据（维护场景）
SELECT COUNT(*) FROM orders_partitioned PARTITION (p2022);
```

## partitions 列与 NULL 的含义

```sql
-- 非分区表：partitions 为 NULL
EXPLAIN SELECT * FROM orders WHERE user_id = 100 \G
-- partitions: NULL  ← 普通表，无分区信息

-- 分区表但所有分区都被访问：
EXPLAIN SELECT * FROM orders_partitioned WHERE user_id = 100 \G
-- partitions: p2022,p2023,p2024,p2025,p_future  ← 所有分区（非 NULL）
-- 对比 NULL 与所有分区，可以区分是非分区表还是分区裁剪失败
```

## 适用场景

- **分区裁剪效果验证**：在分区表上执行查询时，通过 `partitions` 列确认分区裁剪是否生效。如果 `partitions` 显示的分区数比总分区数少，说明裁剪生效；如果显示全部分区，说明 WHERE 条件不足以裁剪，需要在查询中添加分区键的条件
- **分区维护查询**：使用 `PARTITION(pname)` 语法直接指定分区进行操作（如清理旧分区数据），通过 EXPLAIN 验证操作只作用于指定分区，避免误操作其他分区

## 常见问题

**为什么 EXPLAIN 显示 `partitions: NULL` 但表明明是分区表？**

这不会发生。对于分区表，`partitions` 列总是会显示实际访问的分区名称（至少一个分区）或所有分区——不会显示 `NULL`。只有非分区表才显示 `NULL`。如果对分区表做 EXPLAIN 时看到了 `NULL`，需要确认：①表是否真的是分区表（通过 `SHOW CREATE TABLE` 确认）；②是否指定了 `PARTITION()` 子句导致输出格式变化；③是否存在查看的是另一个非分区的表。

---

## 注意事项

- 分区裁剪只能发生在分区键（或分区表达式）上的比较操作，不能跨分区键列进行裁剪。设计分区方案时，应将最常作为查询条件的列（如时间戳列）作为分区键，以确保大多数查询都能利用分区裁剪。
- 即使分区裁剪生效（只访问部分分区），每个被访问的分区内仍然需要进行全扫描或索引扫描。分区裁剪和索引是两个不同维度的优化：分区裁剪减少了需要访问的分区数量，索引在分区内加速行定位，两者结合使用效果最好。

---

## 总结

`partitions` 列显示分区表查询涉及的分区列表（非分区表为 NULL）。分区裁剪（Partition Pruning）：WHERE 条件包含分区键的比较时，优化器自动排除不相关的分区，`partitions` 只显示实际访问的分区（越少越好）。裁剪失效原因：WHERE 条件不含分区键、对分区键用函数、OR 连接非分区键条件。可以通过 `PARTITION(pname)` 语法强制指定分区。分区裁剪与索引是互补的优化：裁剪减少分区访问数量，索引在分区内加速行定位。
