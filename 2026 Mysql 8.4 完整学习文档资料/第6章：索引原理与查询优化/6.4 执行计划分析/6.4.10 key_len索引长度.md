# key_len 索引长度

EXPLAIN 输出的 `key_len` 列显示 MySQL 实际使用索引时的字节长度。这是判断联合索引使用了几列的唯一直接途径——`key_len` 越大，说明使用了索引中更多的列。此外，`key_len` 的计算规则涉及数据类型的字节宽度、字符集的字节系数、以及 NULL 标记位，理解这些规则有助于准确解读执行计划。

---

## key_len 计算规则

```
各数据类型的 key_len 计算：

整数类型（定长）：
  TINYINT    → 1 字节
  SMALLINT   → 2 字节
  MEDIUMINT  → 3 字节
  INT        → 4 字节
  BIGINT     → 8 字节

浮点/定点类型：
  FLOAT      → 4 字节
  DOUBLE     → 8 字节
  DECIMAL(M,D) → ceil(M/9)*4 + ceil(D/9)*4（实际以字节数计，具体依 MySQL 的实现）

字符串类型（依字符集）：
  CHAR(N) utf8mb4    → N * 4 字节（utf8mb4 最大 4 字节/字符）
  CHAR(N) utf8       → N * 3 字节
  CHAR(N) latin1     → N * 1 字节
  VARCHAR(N) utf8mb4 → N * 4 + 2 字节（前缀 2 字节存储实际长度）
  VARCHAR(N) utf8    → N * 3 + 2 字节

日期时间类型：
  DATE       → 3 字节
  TIME       → 3 字节（MySQL 5.6.4+）
  DATETIME   → 5 字节（MySQL 5.6.4+ 无精度）
  TIMESTAMP  → 4 字节（MySQL 5.6.4+ 无精度）

NULL 标记：
  允许 NULL 的列 (+1 字节)：MySQL 用 1 字节记录是否为 NULL
  NOT NULL 的列：不额外占用字节
```

## 通过 key_len 推算联合索引使用的列数

```sql
CREATE TABLE orders (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,       -- INT, NOT NULL → 4 字节
    status TINYINT NOT NULL,    -- TINYINT, NOT NULL → 1 字节
    dept_id INT NULL,           -- INT, NULL → 4+1=5 字节
    name VARCHAR(50),           -- VARCHAR(50) utf8mb4, NULL → 50*4+2+1=203 字节
    INDEX idx_user_status_dept (user_id, status, dept_id)
);

-- 只用 user_id：
EXPLAIN SELECT * FROM orders WHERE user_id = 100 \G
-- key: idx_user_status_dept
-- key_len: 4  ← 只用了 user_id（INT NOT NULL = 4 字节）

-- 用 user_id + status：
EXPLAIN SELECT * FROM orders WHERE user_id = 100 AND status = 1 \G
-- key_len: 5  ← user_id(4) + status(1) = 5 字节

-- 用 user_id + status + dept_id：
EXPLAIN SELECT * FROM orders WHERE user_id = 100 AND status = 1 AND dept_id = 3 \G
-- key_len: 10  ← user_id(4) + status(1) + dept_id(4+1) = 10 字节
-- dept_id 允许 NULL，所以多 1 字节

-- 通过 key_len 验证联合索引是否全部生效：
-- 期望用 3 列 → key_len 应为 10
-- 如果 key_len = 5，说明只用了前 2 列（最左前缀中断）
```

## VARCHAR 类型的 key_len 计算

```sql
-- VARCHAR(50) 字段，utf8mb4 字符集，允许 NULL
-- key_len = 50 * 4 + 2（变长前缀）+ 1（NULL 标记）= 203 字节

-- VARCHAR(50) utf8mb4 NOT NULL（不允许 NULL）
-- key_len = 50 * 4 + 2 = 202 字节

-- 实际验证：
CREATE TABLE t (
    id INT PRIMARY KEY,
    name VARCHAR(50) CHARACTER SET utf8mb4 NOT NULL,
    INDEX idx_name (name)
);

EXPLAIN SELECT * FROM t WHERE name = 'test' \G
-- key: idx_name
-- key_len: 202  ← 50*4 + 2 = 202（VARCHAR NOT NULL）

-- 如果 name 允许 NULL：
-- key_len: 203  ← 50*4 + 2 + 1 = 203
```

## DATETIME 和 TIMESTAMP 的 key_len

```sql
CREATE TABLE logs (
    id BIGINT PRIMARY KEY,
    created_at DATETIME(3) NOT NULL,   -- 精度 3（毫秒）
    updated_at TIMESTAMP NULL,         -- 无精度
    INDEX idx_created (created_at),
    INDEX idx_updated (updated_at)
);

-- DATETIME(3) NOT NULL：5 字节（基础）+ 2 字节（3位精度）= 7 字节
-- TIMESTAMP NULL：4 字节 + 1 字节（NULL）= 5 字节

EXPLAIN SELECT * FROM logs WHERE created_at = '2025-01-15 10:00:00.000' \G
-- key_len: 7

EXPLAIN SELECT * FROM logs WHERE updated_at IS NULL \G
-- key_len: 5
```

## key_len 与前缀索引

```sql
-- 前缀索引（字符串的前 N 个字符）的 key_len 与前缀长度对应
CREATE TABLE users (
    id INT PRIMARY KEY,
    email VARCHAR(100) CHARACTER SET utf8mb4,
    INDEX idx_email_prefix (email(20))  -- 前 20 个字符
);

EXPLAIN SELECT * FROM users WHERE email = 'alice@example.com' \G
-- key: idx_email_prefix
-- key_len: 82  ← 20 * 4 + 2 = 82（前缀 20 字符，VARCHAR 前缀标记）
-- 不是 100*4+2=402（全列索引的长度）

-- 通过 key_len 可以确认走的是前缀索引还是全列索引
```

## 适用场景

- **联合索引使用列数的快速验证**：通过 `key_len` 的值与每列字节数的累加对比，可以精确确认联合索引使用了几列。当 `key_len` 比预期小（说明最左前缀中断了）时，检查 WHERE 条件是否满足最左前缀原则
- **索引设计验证**：在设计完联合索引后，通过实际查询的 EXPLAIN 检查 `key_len` 是否等于所有列的总字节数，确认查询完整利用了联合索引

## 常见问题

**`key_len` 很大（如 1000+ 字节）是否会影响性能？**

`key_len` 大意味着每个索引记录占用的字节数多，索引本身更大（同等行数占用更多 B+树页面），进而影响 Buffer Pool 中索引页的命中率和索引扫描的 I/O 效率。对于前缀索引，适当减小前缀长度（降低 `key_len`）可以减小索引体积，但要注意选择性损失。对于多列联合索引，`key_len` 大通常意味着查询使用了更多的列，过滤效果更好，这是正面的——不应为了减小 `key_len` 而放弃使用更多列的索引。

---

## 注意事项

- `key_len` 是索引字节长度的上限，不是实际扫描的字节数（实际扫描的行数由 `rows` 决定）。`key_len` 只反映索引定义的宽度，不直接代表 I/O 开销的大小。
- 计算 `key_len` 时，字符集的影响很重要：utf8mb4 的 VARCHAR(N) 按 N×4 字节算（最大宽度），即使实际存储的字符都是 ASCII（每个 1 字节）。这意味着对于 utf8mb4 字符集的宽 VARCHAR 索引，key_len 可能远大于实际存储的字节数。

---

## 总结

`key_len` 是实际使用索引的字节长度，通过计算联合索引各列的字节数累加，可以精确判断用了几列（`key_len` 等于前 N 列的总字节数，就是用了 N 列）。字节数计算规则：整数类型固定字节数（INT=4）；VARCHAR(N)=N×字符集宽度+2（变长标记）；NULL 允许额外+1字节。`key_len` 是验证联合索引使用完整度的唯一直接依据。通过 `key_len` 可以区分全列索引和前缀索引，发现最左前缀中断的位置。
