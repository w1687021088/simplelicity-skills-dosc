# 多值索引 Multi-Valued Index（JSON 数组索引）

多值索引（Multi-Valued Index，也称 MVIndex）是 MySQL 8.0.17 引入的特殊索引类型，专门用于对 JSON 类型列中的数组元素建立索引。与普通索引（一行 → 一条索引记录）不同，多值索引允许一行数据对应多条索引记录（一个 JSON 数组中有多少元素，就在索引中生成多少条记录）。这使得 `MEMBER OF()`、`JSON_CONTAINS()`、`JSON_OVERLAPS()` 等 JSON 数组操作可以利用索引加速，而不必全表扫描。

---

## 多值索引的创建语法

```sql
-- 建表时创建多值索引
CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100),
    tags JSON,       -- 存储标签数组，如 ["mysql", "database", "backend"]
    scores JSON,     -- 存储分数数组，如 [85, 92, 78]
    INDEX idx_tags ((CAST(tags->'$[*]' AS CHAR(50) ARRAY))),    -- 字符串数组多值索引
    INDEX idx_scores ((CAST(scores->'$[*]' AS UNSIGNED ARRAY))) -- 数字数组多值索引
);

-- 建表后添加多值索引
ALTER TABLE users ADD INDEX idx_tags ((CAST(tags->'$[*]' AS CHAR(50) ARRAY)));

-- 语法说明：
-- CAST(json_column->'$[*]' AS type ARRAY) 是多值索引的固定写法
-- json_column->'$[*]'：JSON Path 提取数组所有元素
-- CAST(... AS type ARRAY)：将 JSON 数组元素转为指定类型的数组
-- 支持的 type：CHAR(N)、UNSIGNED、SIGNED、DECIMAL、DATE、DATETIME 等

-- 查看多值索引
SHOW INDEX FROM users \G
-- Index_type: BTREE（多值索引仍是 B+树结构）
-- Expression: (cast(json_unquote(json_extract(`tags`,'$[*]')) as char(50) array))
```

## 插入 JSON 数组数据

```sql
-- 插入包含数组的 JSON 数据
INSERT INTO users (name, tags, scores) VALUES
    ('Alice', '["mysql","redis","python"]', '[85, 92, 78]'),
    ('Bob', '["mysql","java","spring"]', '[90, 88, 95]'),
    ('Carol', '["redis","mongodb","nosql"]', '[70, 85, 80]'),
    ('Dave', '["python","django","backend"]', '[88, 76, 92]');

-- 多值索引内部对应的索引记录（以 idx_tags 为例）：
-- Alice 行 → 3 条索引记录：["mysql", id=1], ["redis", id=1], ["python", id=1]
-- Bob 行   → 3 条索引记录：["mysql", id=2], ["java", id=2], ["spring", id=2]
-- Carol 行 → 3 条索引记录：["redis", id=3], ["mongodb", id=3], ["nosql", id=3]
-- Dave 行  → 3 条索引记录：["python", id=4], ["django", id=4], ["backend", id=4]

-- 索引按 tag 值排序：
-- "backend" → [id=4]
-- "django"  → [id=4]
-- "java"    → [id=2]
-- "mongodb" → [id=3]
-- "mysql"   → [id=1, id=2]  ← 同一个 tag 对应多个 id
-- "nosql"   → [id=3]
-- ...
```

## 多值索引支持的查询操作

```sql
-- 1. MEMBER OF()：检查某值是否在 JSON 数组中（利用多值索引）
EXPLAIN SELECT * FROM users WHERE 'mysql' MEMBER OF (tags) \G
-- key: idx_tags  ← 走多值索引
-- Extra: Using where

-- 查询包含 mysql 标签的用户
SELECT id, name FROM users WHERE 'mysql' MEMBER OF (tags);
-- 结果：Alice(id=1), Bob(id=2)

-- 2. JSON_CONTAINS()：检查 JSON 数组是否包含某个子 JSON
EXPLAIN SELECT * FROM users
WHERE JSON_CONTAINS(tags, '"mysql"') \G
-- key: idx_tags  ← 走多值索引（MySQL 8.0.17+）

-- 3. JSON_OVERLAPS()：检查两个 JSON 数组是否有交集
EXPLAIN SELECT * FROM users
WHERE JSON_OVERLAPS(tags, '["mysql","redis"]') \G
-- key: idx_tags  ← 走多值索引
-- 返回 tags 数组中包含 "mysql" 或 "redis" 的用户

-- 4. 组合条件查询
SELECT id, name FROM users
WHERE 'mysql' MEMBER OF (tags) AND 90 MEMBER OF (scores);
-- 使用两个多值索引分别过滤
```

## 多值索引的约束和限制

```sql
-- 限制1：多值索引列必须是 JSON 类型
-- ALTER TABLE t ADD INDEX ((CAST(varchar_col->'$[*]' AS CHAR(10) ARRAY)));
-- 普通 VARCHAR 列不支持多值索引

-- 限制2：JSON 数组元素类型必须一致（CAST 时指定）
-- 混合类型数组（如 ["mysql", 123, true]）在 CAST 为 CHAR(50) 时，数字和布尔会被转为字符串

-- 限制3：不能与函数索引混用（一个索引定义只能是多值索引或普通索引）
-- 正确：INDEX idx_tags ((CAST(tags->'$[*]' AS CHAR(50) ARRAY)))
-- 错误：INDEX idx_wrong (name, (CAST(tags->'$[*]' AS CHAR(50) ARRAY)))
-- ERROR: 多值索引不能与普通列组合成联合索引

-- 限制4：多值索引不支持降序（不能写 DESC）
-- ALTER TABLE t ADD INDEX ((CAST(tags->'$[*]' AS CHAR(50) ARRAY) DESC));
-- ERROR

-- 限制5：一个多值索引只能基于一个数组路径
-- 不能同时索引 tags 和 scores 在同一个多值索引中

-- 限制6：多值索引不支持 NULL 值的数组元素（NULL 元素不被索引）
INSERT INTO users (name, tags) VALUES ('Eve', '[null, "mysql"]');
-- "mysql" 被索引，null 不被索引
```

## 多值索引的性能影响

```sql
-- 写入性能：
-- 一行包含 N 个元素的数组 → N 条索引记录
-- 数组越大，写入时索引维护开销越高
-- 建议控制 JSON 数组的长度（如不超过 10~20 个元素）

-- 查询性能：
-- 没有多值索引时：
EXPLAIN SELECT * FROM users WHERE 'mysql' MEMBER OF (tags) \G
-- type: ALL, Extra: Using where  ← 全表扫描，逐行解析 JSON

-- 有多值索引时：
EXPLAIN SELECT * FROM users WHERE 'mysql' MEMBER OF (tags) \G
-- type: ref, key: idx_tags       ← 走索引，效率高

-- 索引大小：
-- 如果每行平均有 5 个 tag，多值索引的记录数 = 表行数 × 5
-- 比普通索引大 5 倍，Buffer Pool 和磁盘压力更大
```

## 适用场景

- **用户标签/权限/分类的 JSON 存储**：当业务需要存储每个用户的多个标签（如技能标签、兴趣标签），且需要按标签过滤用户时，多值索引可以避免为每种标签建立单独的关联表，用更简洁的 JSON 数组存储，同时保持查询性能
- **产品属性多值查询**：电商系统中商品的多个属性值（如可选颜色 `["红","蓝","绿"]`）需要按属性值过滤时，多值索引是比额外关联表更轻量的解决方案

## 常见问题

**多值索引和普通关联表相比哪个更好？**

这取决于具体需求。关联表（如 `user_tags(user_id, tag)`）在以下情况更好：①需要对标签做复杂查询（COUNT、JOIN 等）；②标签有自己的属性（如标签创建时间）；③需要外键约束。多值索引在以下情况更好：①标签只用于过滤（`MEMBER OF`），不需要复杂聚合；②数组长度适中（10~20 个元素内）；③希望减少表的数量，简化数据模型；④JSON 数组的查询性能可以接受（通过多值索引保证）。两种方案并不互斥，可以根据查询模式选择。

---

## 注意事项

- 多值索引目前（MySQL 8.0.17+/8.4）不支持作为联合索引的一部分（不能与普通列组合），每个多值索引必须是独立的索引定义。这限制了多值索引的覆盖索引能力。
- 建立多值索引前，要合理评估 JSON 数组的最大长度。如果数组元素数量不可控（如用户标签可以有 100+ 个），多值索引会导致索引记录数远大于表行数，索引维护开销和存储空间可能超过其带来的查询收益，此时考虑改用关联表设计。

---

## 总结

多值索引（Multi-Valued Index）是 MySQL 8.0.17 引入的 JSON 数组专用索引，一行对应多条索引记录（每个数组元素一条）。语法：`INDEX ((CAST(json_col->'$[*]' AS type ARRAY)))`。支持 `MEMBER OF()`、`JSON_CONTAINS()`、`JSON_OVERLAPS()` 操作走索引加速。限制：只支持 JSON 类型列、不能与普通列组合联合索引、不支持降序、NULL 元素不被索引。适用于标签系统、多属性值过滤等场景，数组元素数量应控制在合理范围内（避免索引膨胀）。写入时每个数组元素都生成一条索引记录，数组越大写入开销越高。
