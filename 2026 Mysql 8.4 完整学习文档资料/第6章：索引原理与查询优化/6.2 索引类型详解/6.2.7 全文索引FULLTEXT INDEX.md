# 全文索引 FULLTEXT INDEX

全文索引（FULLTEXT INDEX）是 MySQL 专门为全文搜索设计的特殊索引，支持在 `CHAR`、`VARCHAR`、`TEXT` 等字符串类型列上进行自然语言搜索（词语匹配）和布尔模式搜索。与 B+树索引的前缀匹配不同，全文索引通过倒排索引（Inverted Index）记录每个词语在哪些行中出现，支持 `LIKE '%word%'` 无法实现的词级别全文搜索能力。MySQL 5.6+ 起 InnoDB 支持全文索引（之前只有 MyISAM 支持）。

---

## 创建与使用全文索引

```sql
-- 建表时创建全文索引
CREATE TABLE articles (
    id INT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(200) NOT NULL,
    content TEXT NOT NULL,
    author VARCHAR(100),
    FULLTEXT INDEX ft_content (content),                    -- 单列全文索引
    FULLTEXT INDEX ft_title_content (title, content)        -- 多列全文索引
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 建表后添加全文索引
ALTER TABLE articles ADD FULLTEXT INDEX ft_title (title);

-- 删除全文索引
ALTER TABLE articles DROP INDEX ft_title;

-- 查看全文索引（Index_type = FULLTEXT）
SHOW INDEX FROM articles \G
-- Index_type: FULLTEXT
```

## 全文搜索的三种模式

```sql
-- 模式1：自然语言模式（默认）
-- 按相关性评分排序，高频词（出现在超过 50% 行中）被忽略
SELECT id, title,
       MATCH(content) AGAINST ('MySQL 索引优化' IN NATURAL LANGUAGE MODE) AS score
FROM articles
WHERE MATCH(content) AGAINST ('MySQL 索引优化' IN NATURAL LANGUAGE MODE)
ORDER BY score DESC
LIMIT 10;
-- score：相关性得分，越高越相关
-- 包含这些词的行会被返回（不需要包含所有词）

-- 模式2：布尔模式
-- 支持 + - * "" 等操作符，精确控制搜索
SELECT * FROM articles
WHERE MATCH(title, content) AGAINST (
    '+MySQL +索引 -DELETE "全文搜索"'  -- 必须含MySQL、必须含索引、不含DELETE、精确短语"全文搜索"
    IN BOOLEAN MODE
);

-- 布尔模式操作符：
-- +word：必须包含此词
-- -word：不能包含此词
-- word*：通配符（以word开头的任意词）
-- "phrase"：精确短语匹配
-- (word1 word2)：分组
-- >word：提高此词的相关性权重
-- <word：降低此词的相关性权重

-- 模式3：查询扩展模式
-- 先找到最相关的行，再用这些行的词语扩展搜索
SELECT * FROM articles
WHERE MATCH(content) AGAINST ('数据库' WITH QUERY EXPANSION);
-- 先搜索"数据库"，找到最相关文章
-- 再提取这些文章的关键词（如 MySQL、PostgreSQL、索引）
-- 用扩展词重新搜索，返回更多相关结果
```

## 全文索引的内部结构

```
倒排索引（Inverted Index）工作原理：

文章1：content = "MySQL 索引是数据库性能的关键"
文章2：content = "B+树是 MySQL 索引的底层结构"
文章3：content = "索引优化可以提升数据库查询速度"

倒排索引（词 → 文章列表）：
  "MySQL"    → [文章1(位置1), 文章2(位置3)]
  "索引"     → [文章1(位置2), 文章2(位置4), 文章3(位置1)]
  "数据库"   → [文章1(位置4), 文章3(位置4)]
  "B+树"     → [文章2(位置1)]
  "性能"     → [文章1(位置5)]

搜索 "MySQL 索引"：
  找到包含 "MySQL" 的文章：{文章1, 文章2}
  找到包含 "索引" 的文章：{文章1, 文章2, 文章3}
  两者取并集（自然语言模式）→ {文章1, 文章2, 文章3}
  按相关性得分排序返回
```

## 中文全文搜索配置

```sql
-- MySQL 8.0 内置 ngram 分词器（支持中文）
-- ngram 将文本分割为连续的 N 个字符的 token

-- 建表时使用 ngram 分词器
CREATE TABLE articles_cn (
    id INT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(200),
    content TEXT,
    FULLTEXT INDEX ft_content (content) WITH PARSER ngram    -- 指定 ngram 分词器
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 查看 ngram 分词的 token 大小（默认 2）
SHOW VARIABLES LIKE 'ngram_token_size';
-- ngram_token_size = 2 表示每个 token 是 2 个字符
-- "数据库性能" → ["数据", "据库", "库性", "性能"]

-- 修改 ngram token 大小（需要修改配置文件）
-- my.cnf: ngram_token_size=2（值越小，索引越大，但支持更短的搜索词）

-- 中文全文搜索（使用布尔模式效果更可控）
SELECT * FROM articles_cn
WHERE MATCH(content) AGAINST ('数据库' IN BOOLEAN MODE);
-- 搜索包含 "数据库" 的文章（ngram 分词后："数据"、"据库"）
```

## 全文索引的最小词长度配置

```sql
-- 控制最小索引词长度
SHOW VARIABLES LIKE 'innodb_ft_min_token_size';
-- 默认：3（3个字符以上才建立索引）
-- 单字或双字词不会被索引（如 "a"、"is"、"to"）

-- 中文搜索通常需要设置为 1 或 2
-- 在 my.cnf 中设置：
-- innodb_ft_min_token_size=2

-- 修改后需要重建全文索引：
ALTER TABLE articles DROP INDEX ft_content, ADD FULLTEXT INDEX ft_content (content);
-- 或：OPTIMIZE TABLE articles;（重建索引）

-- 停用词（stopwords）：过于常见的词不被索引
SHOW VARIABLES LIKE 'innodb_ft_enable_stopword';
-- 默认 ON，MySQL 内置英文停用词
-- 自定义停用词（创建停用词表）：
CREATE TABLE my_stopwords (value VARCHAR(30));
INSERT INTO my_stopwords VALUES ('the'), ('and'), ('is');
SET GLOBAL innodb_ft_server_stopword_table = 'mydb/my_stopwords';
```

## 全文索引 vs LIKE 搜索

| 对比维度 | LIKE '%keyword%' | FULLTEXT 全文索引 |
|---------|:---------------:|:----------------:|
| 索引使用 | 不走索引（全表扫描）| 走全文倒排索引 |
| 性能 | O(N)（行数）| O(log N) + 倒排查找 |
| 相关性排序 | 不支持 | 支持（score）|
| 词语匹配 | 字符串子串匹配 | 词级别匹配 |
| 布尔操作 | 不支持 | 支持（+、-、*、""）|
| 中文支持 | 支持（字符层面）| 需要 ngram 分词器 |
| 功能复杂度 | 简单 | 较复杂（需要分词）|
| 适合场景 | 简单前后缀搜索 | 全文内容搜索 |

## 适用场景

- **文章、博客、商品描述的全文检索**：数据量较大的文本内容搜索，通过 `FULLTEXT` + `MATCH AGAINST` 可以实现较好的搜索性能和相关性排序
- **替代 `LIKE '%keyword%'` 的全文搜索**：当 `LIKE '%keyword%'` 导致全表扫描、性能无法接受时，可以为相关列建立 FULLTEXT 索引，利用倒排索引快速定位包含目标词的行

## 常见问题

**MySQL 全文索引和 Elasticsearch 相比如何？**

MySQL 全文索引适合轻量级搜索需求（数百万行以内的内容搜索）：配置简单、无额外依赖、与业务数据在同一数据库。但在以下方面弱于 Elasticsearch：①大数据量（亿级）性能；②分词能力（MySQL ngram 是固定 N 字符分割，不是语义分词）；③搜索功能丰富度（同义词、模糊匹配、拼写纠错）；④分布式横向扩展能力。如果搜索是核心业务功能且数据量大，Elasticsearch 是更合适的选择；MySQL 全文索引适合搜索是辅助功能的中小型系统。

---

## 注意事项

- 全文索引对 INSERT/UPDATE/DELETE 的影响比 B+树索引更大：每次写入都需要更新倒排索引（将行中的词语加入/删除索引），对于高写入频率的表，全文索引可能成为性能瓶颈。
- 全文索引不参与事务优化（如 Change Buffer），每次修改都是同步更新倒排索引。在大批量写入时（如数据初始化），建议先不建全文索引，数据导入完成后再建，速度更快。
- 中文全文搜索的 ngram 分词方式（2字符滑动窗口）会产生大量 token，索引大小远超 B+树索引，需要为全文索引预留足够的 Buffer Pool 和磁盘空间。

---

## 总结

全文索引（FULLTEXT INDEX）通过倒排索引支持词级别的全文搜索，避免了 `LIKE '%keyword%'` 的全表扫描。支持三种搜索模式：自然语言（默认，相关性排序）、布尔模式（精确控制+/-/*/"" 操作符）、查询扩展（自动扩展相关词）。InnoDB 从 MySQL 5.6 开始支持 FULLTEXT；MySQL 8.0 内置 ngram 分词器支持中文（`WITH PARSER ngram`）。通过 `MATCH(col) AGAINST('keyword')` 使用全文索引。注意事项：写密集表会增加全文索引维护开销；中文 ngram 索引较大；轻量搜索适合 MySQL FULLTEXT，大规模复杂搜索考虑 Elasticsearch。
