# 空间索引 SPATIAL INDEX

空间索引（SPATIAL INDEX）是 MySQL 为地理空间数据类型（`GEOMETRY`、`POINT`、`LINESTRING`、`POLYGON` 等）设计的特殊索引，使用 R-Tree（矩形树）数据结构。与 B+树不同，R-Tree 能够高效地处理多维空间数据的范围查询（如"找出在某个矩形区域内的所有点"）。MySQL 5.7+ 起 InnoDB 支持空间索引（之前只有 MyISAM 支持）。空间索引适用于地图应用、地理信息系统（GIS）、位置服务等场景。

---

## 空间数据类型与创建空间索引

```sql
-- 空间数据类型（Geometry Types）
-- GEOMETRY：所有空间类型的父类型
-- POINT：单个坐标点（经度, 纬度）
-- LINESTRING：折线（多个点组成的线段）
-- POLYGON：多边形区域

-- 建表时创建空间索引（列必须是 NOT NULL）
CREATE TABLE stores (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    location POINT NOT NULL,          -- 地理坐标（不能为 NULL）
    boundary POLYGON,
    SPATIAL INDEX idx_location (location),   -- 空间索引
    SPATIAL INDEX idx_boundary (boundary)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 建表后添加空间索引
ALTER TABLE stores ADD SPATIAL INDEX idx_location (location);

-- 插入空间数据（需要使用 ST_ 函数构造几何对象）
INSERT INTO stores (name, location) VALUES
    ('店铺A', ST_GeomFromText('POINT(116.397128 39.916527)')),  -- 经度 纬度
    ('店铺B', ST_GeomFromText('POINT(121.473701 31.230416)')),
    ('店铺C', ST_GeomFromText('POINT(113.264385 23.128994)'));

-- 或使用 POINT() 函数：
INSERT INTO stores (name, location) VALUES
    ('店铺D', ST_GeomFromText('POINT(114.0579 22.5431)'));
```

## 空间索引的常用查询函数

```sql
-- 1. MBRContains：判断一个几何形状是否包含另一个（基于最小边界矩形）
-- 查找在指定矩形区域内的所有店铺
SELECT name, ST_AsText(location)
FROM stores
WHERE MBRContains(
    ST_GeomFromText('POLYGON((116.3 39.85, 116.5 39.85, 116.5 40.0, 116.3 40.0, 116.3 39.85))'),
    location
);
-- 利用空间索引，只检查矩形区域内的记录

-- 2. ST_Distance：计算两点之间的距离（单位：度，需转换）
-- 注意：ST_Distance 返回的是度数距离，不是公里距离
-- 对于地球上的点，需要使用 ST_Distance_Sphere 或手动换算

-- 找距目标点最近的 5 家店铺（直接比较经纬度距离）
SELECT name,
       ST_Distance(location, ST_GeomFromText('POINT(116.4 39.9)')) AS dist
FROM stores
ORDER BY dist
LIMIT 5;
-- 注意：ORDER BY ST_Distance() 无法使用空间索引，是全表扫描
-- 先用 MBRContains 在矩形范围内筛选，再在结果集内排序

-- 3. MBRWithin：MBRContains 的反向操作（判断是否在范围内）
SELECT name FROM stores
WHERE MBRWithin(location,
    ST_GeomFromText('POLYGON((...))')
);

-- 4. ST_Contains：更精确的包含关系（考虑实际几何形状，而不是 MBR）
SELECT name FROM stores
WHERE ST_Contains(
    ST_GeomFromText('POLYGON((116.3 39.85, ...))'),
    location
);
-- ST_Contains 更精确但比 MBRContains 慢（MBRContains 可以用空间索引）
```

## R-Tree 与 B+树的对比

| 对比维度 | B+树 | R-Tree（空间索引）|
|---------|:----:|:----------------:|
| 数据类型 | 1维有序数据（数字、字符串）| 多维空间数据（坐标、几何形状）|
| 排序方式 | 按键值线性排序 | 按空间区域（MBR）分层组织 |
| 等值查询 | 高效（O(log N)）| 不适用 |
| 范围查询 | 高效（线性范围）| 高效（空间范围/矩形区域）|
| 最近邻查询 | 不支持 | 可支持（结合过滤）|
| 使用场景 | 通用索引 | 地理坐标、几何图形 |

## SRID（空间参考系统标识符）

```sql
-- MySQL 8.0+ 支持 SRID（Spatial Reference System ID）
-- SRID 4326 = WGS 84（GPS 使用的经纬度坐标系）
-- SRID 0 = 平面坐标系（默认，不考虑地球曲率）

-- 建议明确指定 SRID 4326（地理坐标）
CREATE TABLE locations (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100),
    point POINT NOT NULL SRID 4326,     -- 使用 WGS84 坐标系
    SPATIAL INDEX idx_point (point)
);

-- 使用 SRID 4326 时，ST_Distance_Sphere 和 ST_Distance 返回米（更准确）
SELECT name,
       ST_Distance_Sphere(
           point,
           ST_GeomFromText('POINT(116.4 39.9)', 4326)
       ) AS distance_meters
FROM locations
ORDER BY distance_meters
LIMIT 10;
-- ST_Distance_Sphere 计算球面距离，结果单位为米
-- 适合实际的 LBS（基于位置的服务）距离计算
```

## 适用场景

- **LBS（基于位置的服务）**：查找附近的店铺、餐厅、用户，通过空间索引快速定位在指定矩形范围内的记录，比逐行计算经纬度距离高效得多
- **地图和 GIS 应用**：存储和查询地理区域（多边形）、路线（折线）等空间数据，通过 `ST_Contains`、`ST_Intersects` 等函数进行空间关系判断

---

## 常见问题

**为什么 `ORDER BY ST_Distance()` 不走空间索引？**

空间索引（R-Tree）只支持空间范围过滤（如 `MBRContains`），不支持按距离排序。`ORDER BY ST_Distance()` 需要计算每行到目标点的距离后排序，这个过程必须逐行计算，无法利用 R-Tree 的空间分区特性。实际的"查找最近 N 个"查询的正确做法：先用 `MBRContains` 在一个合理大小的矩形范围内筛选（利用空间索引），然后在结果集上计算精确距离并排序。矩形范围的大小根据业务需求设定（如 5 公里），避免扫描全表。

---

## 注意事项

- 空间索引要求列为 `NOT NULL`（InnoDB 空间索引不支持 NULL 值列）。如果需要允许空值，必须处理为将空值替换为特殊坐标或用其他列标记"无位置"状态。
- InnoDB 的空间索引在精确的空间关系判断（如 `ST_Contains` 的精确几何计算）上会比 `MBRContains`（基于最小边界矩形的近似计算）慢，但精度更高。在不需要精确几何判断时，优先使用 `MBRContains` 以利用空间索引。

---

## 总结

空间索引（SPATIAL INDEX）使用 R-Tree 数据结构，专为地理坐标和几何形状数据设计，支持空间范围查询（`MBRContains`、`MBRWithin`、`ST_Contains`）。只支持 `GEOMETRY` 及其子类型列（`POINT`、`LINESTRING`、`POLYGON`），要求列为 `NOT NULL`。MySQL 5.7+ InnoDB 开始支持空间索引。常用场景：附近店铺查询（先 MBRContains 矩形过滤 + 再精确距离计算排序）、地理围栏判断。MySQL 8.0+ 建议明确指定 SRID（如 `SRID 4326` WGS84）以获得正确的距离计算（米为单位）。
