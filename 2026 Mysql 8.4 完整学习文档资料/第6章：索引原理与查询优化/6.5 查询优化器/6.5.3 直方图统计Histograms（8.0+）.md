# 直方图统计 Histograms（8.0+）

直方图（Histogram）是 MySQL 8.0 引入的列级统计信息，用于描述列的数据分布情况。与传统的索引基数（Cardinality）统计不同，直方图针对的是**没有索引的列**，帮助优化器更准确地估算 WHERE 条件的过滤比例（filtered 值）。在数据分布不均匀（如某个 status 值占 80% 行，另一个只占 1% 行）时，直方图能显著提高优化器的成本估算精度，从而做出更好的 JOIN 顺序和索引选择决策。

---

## 直方图的核心价值

```sql
-- 传统统计信息（Cardinality）的局限：
-- 只记录"有多少个不同值"，不记录"每个值有多少行"
-- 对于均匀分布：Cardinality=4（4个不同值），每个值约 25% 的行 → 估算准确
-- 对于不均匀分布：status=0（80%），status=1（15%），status=2（4%），status=3（1%）
-- → Cardinality=4，优化器认为每个值约 25% → 严重高估 status=3 的行数！

-- 直方图的改进：
-- 记录每个值（或每个区间）的实际比例
-- WHERE status = 3 → 优化器知道只有 1% 的行，而不是 25%
-- 更准确的 filtered 估算 → 更好的 JOIN 顺序决策

-- 直方图特别适合：
-- 没有索引的过滤列（有索引的列，优化器通过索引的 Cardinality 估算）
-- 数据分布极不均匀的列（如 status、type、gender 等低基数列）
-- 用于 JOIN 驱动表选择的 WHERE 条件列
```

---

## 创建与管理直方图

```sql
-- 语法：ANALYZE TABLE t UPDATE HISTOGRAM ON col [WITH N BUCKETS]
-- 为 orders.status 列创建直方图（默认 100 个桶）
ANALYZE TABLE orders UPDATE HISTOGRAM ON status;

-- 指定桶数（Bucket 数量）：
ANALYZE TABLE orders UPDATE HISTOGRAM ON status WITH 20 BUCKETS;
-- 桶数越多，精度越高；桶数越少，存储越小
-- 对于低基数列（如 status 只有 4 个值），桶数设为不同值数量即可

-- 同时为多列创建直方图：
ANALYZE TABLE orders UPDATE HISTOGRAM ON status, region_id, category;

-- 删除直方图：
ANALYZE TABLE orders DROP HISTOGRAM ON status;

-- 查看所有直方图：
SELECT * FROM information_schema.COLUMN_STATISTICS
WHERE SCHEMA_NAME = 'mydb' AND TABLE_NAME = 'orders' \G
-- SCHEMA_NAME: mydb
-- TABLE_NAME: orders
-- COLUMN_NAME: status
-- HISTOGRAM: JSON 格式的直方图数据
```

## 查看直方图的详细内容

```sql
-- 直方图以 JSON 格式存储在 information_schema.COLUMN_STATISTICS 中
SELECT
    COLUMN_NAME,
    JSON_UNQUOTE(JSON_EXTRACT(HISTOGRAM, '$.histogram-type')) AS hist_type,
    JSON_UNQUOTE(JSON_EXTRACT(HISTOGRAM, '$.number-of-buckets-specified')) AS buckets,
    JSON_UNQUOTE(JSON_EXTRACT(HISTOGRAM, '$.null-values')) AS null_frac,
    HISTOGRAM
FROM information_schema.COLUMN_STATISTICS
WHERE SCHEMA_NAME = 'mydb' AND TABLE_NAME = 'orders' AND COLUMN_NAME = 'status' \G

-- 直方图类型：
-- singleton（单值直方图）：每个桶代表一个特定值，适合低基数列
-- equi-height（等高直方图）：每个桶包含相等比例的数据，适合高基数列

-- 单值直方图示例（status 列只有 4 个值）：
-- histogram-type: singleton
-- buckets: [
--   [0, 0.80],  ← status=0 占 80%
--   [1, 0.15],  ← status=1 占累计 95%（15%）
--   [2, 0.04],  ← status=2 占累计 99%（4%）
--   [3, 0.01]   ← status=3 占累计 100%（1%）
-- ]
-- 优化器看到 WHERE status=3，立即知道 filtered ≈ 1%
```

## 直方图对执行计划的影响

```sql
-- 验证直方图对 filtered 估算的改善

-- 建直方图之前：
SET SESSION histogram_generation_max_mem_size = 0;  -- 临时模拟无直方图
EXPLAIN SELECT * FROM orders o JOIN users u ON o.user_id = u.id
WHERE o.status = 3 \G
-- table: o, rows: 1000000, filtered: 25.00  ← 错误估算 25%（4个值各25%）
-- 传递给 users 的行数估算：1000000 × 0.25 = 250000 行

-- 建直方图之后：
ANALYZE TABLE orders UPDATE HISTOGRAM ON status WITH 4 BUCKETS;
EXPLAIN SELECT * FROM orders o JOIN users u ON o.user_id = u.id
WHERE o.status = 3 \G
-- table: o, rows: 1000000, filtered: 1.00   ← 正确估算 1%（直方图的精确数据）
-- 传递给 users 的行数估算：1000000 × 0.01 = 10000 行
-- 估算更准确，JOIN 顺序决策更合理！

-- 注意：直方图不影响索引的 Cardinality，只改善 filtered 估算
-- 如果 status 有索引，直方图的改善效果有限（索引已提供精确统计）
-- 直方图主要对"无索引列的过滤"有帮助
```

## 直方图的存储与刷新

```sql
-- 直方图存储在 mysql.column_stats 表（通过 information_schema.COLUMN_STATISTICS 查看）
-- 在服务器重启后仍然有效（持久化）

-- 刷新直方图（数据变化后需要重新建立）
ANALYZE TABLE orders UPDATE HISTOGRAM ON status;
-- 直方图不会自动更新！与索引统计（innodb_stats_auto_recalc）不同
-- 需要手动执行 ANALYZE TABLE ... UPDATE HISTOGRAM

-- 批量更新多张表的直方图：
SELECT CONCAT('ANALYZE TABLE `', TABLE_SCHEMA, '`.`', TABLE_NAME,
              '` UPDATE HISTOGRAM ON `', COLUMN_NAME, '`;') AS sql_text
FROM information_schema.COLUMN_STATISTICS
WHERE SCHEMA_NAME = 'mydb';
-- 生成所有已建直方图的更新语句，批量执行

-- 直方图的最大桶数限制：
SHOW VARIABLES LIKE 'histogram_generation_max_mem_size';
-- 默认: 20971520（20MB）
-- 控制生成直方图时的最大内存使用，影响精度（更多内存 = 更多桶）
```

## 适用场景

- **无索引低基数列的过滤优化**：对于 `status`、`type`、`category` 等枚举型列，通常因选择性太低不适合建索引，但 WHERE 中频繁用这些列过滤。直方图可以让优化器知道每个枚举值的真实比例，改善 JOIN 驱动表选择
- **多表 JOIN 的驱动表选择优化**：在 WHERE 条件涉及多张表的过滤列时，直方图帮助优化器准确估算每张表过滤后的行数，从而选择正确的 JOIN 驱动顺序（行数少的表先驱动）

## 常见问题

**有了直方图，还需要定期 `ANALYZE TABLE` 更新索引统计吗？**

两者相互独立，都需要维护。`ANALYZE TABLE 表名`（不带 `UPDATE HISTOGRAM`）只更新索引的 Cardinality 统计，不更新直方图；`ANALYZE TABLE 表名 UPDATE HISTOGRAM ON 列名` 只更新直方图，不更新索引统计。如果数据分布发生显著变化，需要同时执行两个操作：先 `ANALYZE TABLE 表名` 更新索引统计，再 `ANALYZE TABLE 表名 UPDATE HISTOGRAM ON 列名` 更新直方图。

---

## 注意事项

- 直方图只对没有索引的列（或有索引但优化器不走索引的情况）有直接帮助。如果一个列已经有高选择性的索引，优化器通过索引的 Cardinality 统计已经能做出准确估算，直方图的额外价值有限。
- 直方图不会自动更新（不像索引统计有 `innodb_stats_auto_recalc` 机制）。在大量数据变化（如每天的批量导入/归档）后，如果不主动更新直方图，直方图的数据可能反映的是旧的分布情况。建议将 `ANALYZE TABLE ... UPDATE HISTOGRAM` 加入定期维护脚本。

---

## 总结

直方图（Histogram）是 MySQL 8.0 新增的列级数据分布统计，通过 `ANALYZE TABLE t UPDATE HISTOGRAM ON col [WITH N BUCKETS]` 创建，存储在 `information_schema.COLUMN_STATISTICS`。分两种类型：单值直方图（singleton，每个桶代表一个具体值，适合低基数列）和等高直方图（equi-height，每个桶包含等比例数据，适合高基数列）。核心价值：改善无索引列过滤的 `filtered` 估算精度，特别是数据分布不均匀（如 status=3 只占 1%）的情况。直方图不会自动更新，需要数据变化后手动执行更新。与索引统计相互独立，两者都需要维护。
