# 直方图单值与等高模式

MySQL 8.0 的直方图支持两种存储模式：**单值直方图（singleton）**和**等高直方图（equi-height）**。MySQL 会根据列的数据分布特征自动选择合适的模式，不需要手动指定。理解这两种模式的工作机制，有助于准确解读直方图的内容，以及在 EXPLAIN 中分析 `filtered` 估算为何会有差异。

---

## 两种模式的适用条件

```sql
-- MySQL 根据列的不同值数量（基数）自动选择模式：

-- 单值模式（singleton）：不同值数量 ≤ 指定桶数
-- 等高模式（equi-height）：不同值数量 > 指定桶数

-- 示例：
-- status 列有 4 个不同值，指定 20 个桶
-- → 4 ≤ 20 → 自动选择 singleton 模式（每个值独占一个桶）

-- user_id 列有 100000 个不同值，指定 100 个桶
-- → 100000 > 100 → 自动选择 equi-height 模式（每个桶覆盖约 1000 个值）

-- 验证：查看生成的直方图类型
SELECT COLUMN_NAME,
    JSON_UNQUOTE(JSON_EXTRACT(HISTOGRAM, '$.histogram-type')) AS hist_type,
    JSON_EXTRACT(HISTOGRAM, '$.buckets') AS buckets
FROM information_schema.COLUMN_STATISTICS
WHERE SCHEMA_NAME = 'mydb' AND TABLE_NAME = 'orders'
ORDER BY COLUMN_NAME \G
```

---

## 单值直方图（singleton）详解

```sql
-- 单值直方图：每个桶存储一个特定值及其累计频率
-- 适合低基数列（枚举型：status、type、category 等）

-- 示例：orders.status 列（4个值）
ANALYZE TABLE orders UPDATE HISTOGRAM ON status WITH 4 BUCKETS;

-- 查看生成的直方图 JSON：
SELECT JSON_PRETTY(HISTOGRAM) AS pretty_histogram
FROM information_schema.COLUMN_STATISTICS
WHERE SCHEMA_NAME = 'mydb' AND TABLE_NAME = 'orders' AND COLUMN_NAME = 'status' \G

-- 单值直方图的桶格式：[value, cumulative_frequency]
-- 输出示例：
-- {
--   "buckets": [
--     [0, 0.8000],    ← status=0 的行占 80%，累计频率 0.80
--     [1, 0.9500],    ← status=1 的行占 15%，累计频率 0.95
--     [2, 0.9900],    ← status=2 的行占  4%，累计频率 0.99
--     [3, 1.0000]     ← status=3 的行占  1%，累计频率 1.00
--   ],
--   "histogram-type": "singleton",
--   "null-values": 0.00,           ← NULL 值占比
--   "number-of-buckets-specified": 4,
--   "sampling-rate": 1.0,          ← 采样率（1.0 表示全表扫描建立）
--   "last-updated": "2025-01-15 10:00:00.000000"
-- }

-- 优化器如何使用单值直方图：
-- WHERE status = 3 → 累计(3) - 累计(2) = 1.00 - 0.99 = 0.01 → filtered=1%
-- WHERE status > 1 → 1.00 - 0.95 = 0.05 → filtered=5%（status=2和3共5%）
-- WHERE status IN (0,1) → 0.95 → filtered=95%
```

---

## 等高直方图（equi-height）详解

```sql
-- 等高直方图：每个桶包含约等比例的数据，桶的边界是实际数据值
-- 适合高基数列（连续值或大量不同值：amount、created_at、score 等）

-- 示例：orders.amount 列（有大量不同金额值）
ANALYZE TABLE orders UPDATE HISTOGRAM ON amount WITH 50 BUCKETS;

-- 等高直方图的桶格式：[lower_bound, upper_bound, cumulative_frequency, ndv]
-- ndv = number of distinct values in this bucket（桶内不同值数量）
-- 输出示例：
-- {
--   "buckets": [
--     [0.01, 99.99, 0.02, 234],       ← 第1桶：0.01~99.99，累计 2%，234个不同值
--     [100.00, 299.99, 0.04, 412],    ← 第2桶：100~299.99，累计 4%
--     ...
--     [5000.00, 9999.99, 0.98, 89],   ← 第49桶
--     [10000.00, 99999.99, 1.0, 12]   ← 第50桶（最大金额范围）
--   ],
--   "histogram-type": "equi-height",
--   "number-of-buckets-specified": 50,
--   ...
-- }

-- 优化器如何使用等高直方图：
-- WHERE amount > 5000 → 找到 5000 在哪个桶，计算右侧的比例
-- 如果 amount=5000 在第 49 桶（累计 0.98），则 > 5000 约占 1 - 0.98 = 2%
-- filtered ≈ 2%（远比均匀分布估算的更准确）
```

## 两种模式的对比

| 对比维度 | 单值直方图（singleton）| 等高直方图（equi-height）|
|---------|:--------------------:|:---------------------:|
| 适用列类型 | 低基数枚举列 | 高基数连续值列 |
| 桶的含义 | 每桶=一个具体值 | 每桶=一个值范围 |
| 精度 | 高（每个值精确频率）| 中（范围内均匀分布假设）|
| 存储格式 | `[value, cumfreq]` | `[min, max, cumfreq, ndv]` |
| 等值查询 | 非常准确 | 线性插值估算 |
| 范围查询 | 准确（累计频率差）| 较准确（桶间插值）|
| 自动选择条件 | 不同值数 ≤ 桶数 | 不同值数 > 桶数 |

## 桶数的选择对精度的影响

```sql
-- 桶数越多，精度越高，但存储开销也越大
-- MySQL 8.0 默认最大桶数：1024

-- 低基数列：桶数 = 不同值数量即可
-- status 有 4 个值 → 4 桶就能完全精确（singleton）
ANALYZE TABLE orders UPDATE HISTOGRAM ON status WITH 4 BUCKETS;

-- 高基数列：桶数越大，估算越精确
-- amount 有 10000 个不同值，100 桶 → 每桶约 100 个值（合理精度）
ANALYZE TABLE orders UPDATE HISTOGRAM ON amount WITH 100 BUCKETS;

-- 极高精度需求（宽范围连续值）：
ANALYZE TABLE orders UPDATE HISTOGRAM ON amount WITH 500 BUCKETS;
-- 代价：JSON 体积更大，存储和加载开销增加（通常影响可以忽略）

-- 查看生成的桶数（指定 100 桶但不同值只有 30 个 → 只生成 30 桶的 singleton）
SELECT JSON_ARRAY_LENGTH(JSON_EXTRACT(HISTOGRAM, '$.buckets')) AS actual_buckets,
       JSON_EXTRACT(HISTOGRAM, '$.number-of-buckets-specified') AS specified_buckets,
       JSON_UNQUOTE(JSON_EXTRACT(HISTOGRAM, '$.histogram-type')) AS hist_type
FROM information_schema.COLUMN_STATISTICS
WHERE SCHEMA_NAME = 'mydb' AND TABLE_NAME = 'orders';
```

## NULL 值的处理

```sql
-- 直方图中记录了 NULL 值的比例（null-values 字段）
-- 优化器在估算 WHERE col IS NULL 或 WHERE col IS NOT NULL 时使用

-- 示例：department_id 列有 10% 的 NULL 值
ANALYZE TABLE employees UPDATE HISTOGRAM ON department_id WITH 50 BUCKETS;

-- 查看 NULL 比例：
SELECT JSON_EXTRACT(HISTOGRAM, '$.null-values') AS null_fraction
FROM information_schema.COLUMN_STATISTICS
WHERE COLUMN_NAME = 'department_id';
-- null-values: 0.10  ← 10% 的行 department_id 为 NULL

-- 优化器估算：
-- WHERE department_id IS NULL     → filtered ≈ 10%
-- WHERE department_id IS NOT NULL → filtered ≈ 90%
-- WHERE department_id = 5         → 在非 NULL 的 90% 中查找，再乘以该值的比例
```

## 适用场景

- **枚举型列的优化（singleton 模式）**：订单状态（status）、支付类型（pay_type）、地区编码（region）等低基数列，建立 singleton 直方图后，优化器能精确知道每个枚举值的行数比例，大幅改善涉及这些列的 JOIN 驱动顺序决策
- **金额/时间范围查询的过滤估算（equi-height 模式）**：对 `amount`、`score`、`created_at` 等连续值列建立等高直方图，优化器可以更准确地估算范围条件（如 `amount > 1000`）的 filtered 值，避免因均匀分布假设造成的估算偏差

## 常见问题

**MySQL 自动选择 singleton 还是 equi-height，是否可以手动指定？**

不能手动指定，MySQL 根据"列的不同值数量是否超过指定桶数"自动决定。如果希望强制使用 equi-height（即使不同值数量不多），可以减小桶数（如 `WITH 2 BUCKETS`，使得不同值数量超过桶数，触发 equi-height）。但通常情况下，让 MySQL 自动选择是最佳实践——低基数列用 singleton 更精确，高基数列用 equi-height 更合适，MySQL 的自动选择逻辑本身就是最优的。

---

## 注意事项

- 等高直方图对于**桶内均匀分布**有一个内在假设，当桶内数据分布不均匀时，等值查询（`WHERE amount = 1500`）的 filtered 估算仍可能偏差较大。增加桶数可以减小每个桶的范围，降低不均匀分布的影响。
- 直方图的 `sampling-rate`（采样率）字段反映了建立直方图时的数据采样比例。当表很大（超过 `histogram_generation_max_mem_size` 限制时），MySQL 会对数据进行采样（采样率 < 1.0）而不是全表扫描。采样率越低，直方图的精度越低，特别是稀有值的频率估算会更不准确。

---

## 总结

直方图有两种模式：单值直方图（singleton）针对低基数列，每个桶精确记录一个值的累计频率，等值查询估算精度高；等高直方图（equi-height）针对高基数列，每个桶覆盖一个值范围，用线性插值估算范围条件的 filtered。MySQL 根据"不同值数量 vs 桶数"自动选择模式。桶格式：singleton 为 `[value, cumfreq]`；equi-height 为 `[min, max, cumfreq, ndv]`。两种模式都记录 NULL 值比例。增加桶数提高精度但增大存储；实践中低基数列桶数=不同值数，高基数列桶数建议 100~500 范围内根据精度需求选择。
